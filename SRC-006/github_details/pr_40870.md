## Motivation

Decoder layers repeat the same sequence around the FFN: ask the communicator whether the next layer fuses the all-reduce and whether a reduce-scatter follows, publish both flags around the MLP call, then either mark the output for the next layer or call `postprocess_layer`. The exit protocol belongs to the communicator; the FFN call and its model-specific arguments belong to the model.

## Modifications

- `LayerCommunicator.ffn_exit(forward_batch)` returns an `FfnExit`. It takes the decision once with the existing `should_fuse_mlp_allreduce_with_next_layer` / `should_use_reduce_scatter` (subclass overrides still apply). Used as a context manager around the FFN call, it publishes the two flags through `get_forward().scoped`; `finish(hidden_states, residual)` applies the same decision to the FFN output (mark for fusion or `postprocess_layer`). The communicator does not call the FFN.
- Qwen3-MoE (and Mellum, which inherits it), the non-TBO DeepSeek-V2 decoder forward and GLM4-MoE use it. DeepSeek keeps `moe_output_buffer_ctx` inside the flag scope, as before.
- New `test/registered/unit/layers/test_communicator_ffn_exit.py`, including a `torch.compile(fullgraph=True)` check of a function using `ffn_exit` / `finish`.

No behavior change.

## Accuracy Tests

Parent vs this PR on H200, four greedy prompts, 32 new tokens, text / token ids / every logprob / top-5 compared bit-exactly, with a per-rank log of the decisions actually taken:

| Configuration | Result | Decisions exercised |
|---|---|---|
| Qwen3-30B-A3B TP2 | identical | fuse true and false in decode and extend |
| Qwen3-30B-A3B TP2 × EP2 | identical | same |
| Qwen3-30B-A3B TP2, DP attention 2 | identical | reduce-scatter in decode and extend |
| DeepSeek-V2-Lite TP2 | identical (requests submitted one at a time) | fuse true and false |
| GLM-4.5-Air-FP8 TP4 | identical | fuse true and false |
| DeepSeek-V2-Lite TP2, `--enable-torch-compile` | identical; same graph breaks and recompiles (340 / 340 on rank 0, same functions and guards) | — |

With all prompts submitted as one batch, DeepSeek-V2-Lite's second prompt varies between runs of the parent itself (prefill batch composition depends on arrival timing); submitted one at a time, parent and this PR are identical.

A CPU dispatch comparison runs each real decoder forward with stubbed attention / FFN / communicator methods over fuse × reduce-scatter (20 cases): call order, flags seen inside the FFN, MoE buffer context, outputs and marker are identical. `unit/layers` + `unit/models`: every existing case keeps its status.

## Speed Tests and Profiling

Eager Python overhead measured with stubbed decisions / FFN / postprocess: 2.34 → 2.75 µs (no fusion) and 2.28 → 2.69 µs (fusion) per layer per forward, about +0.4 µs. CUDA graph replay does not run this code.
