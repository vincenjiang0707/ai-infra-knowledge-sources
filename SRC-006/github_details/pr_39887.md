# [PR #39887] [Bugfix] Keep chat stream IDs and timestamps consistent

## 正文

## Motivation

For `POST /v1/chat/completions` with `stream=true`, all chunks of one response should have the same `id` and `created` values. The Python server can return different values within the same response:

- With `n > 1`, each candidate has its own engine ID. The response ID changes as chunks arrive from different candidates.
- If the stream crosses a second boundary, `created` changes as well. This also affects `n = 1`.

Fixes #39864.

## Modifications

Read the timestamp once at the start of the stream. Use the ID from the first engine result for all response chunks. Each candidate still has its own `choices[].index`.

Pass these two values through the response helpers. This also covers tool calls, final tool arguments, usage, hidden states, and `sglext` data.

## Accuracy Tests

The change affects response metadata only. No model accuracy test was run.

- All 142 tests in `test/registered/unit/entrypoints/openai/test_serving_chat.py` passed on CPU with the repository's macOS platform adapter.
- The regression tests cover one or two candidates, either candidate first, plain and named `sglext` events, and tool calls with final argument deltas. Both tests fail with the original response code and pass with this fix.
- The existing helper tests also check the ID and timestamp on reasoning content, logprobs, and tool arguments.
- Pre-commit checks passed for both changed files.

These tests use mock engine output. No live GPU server was tested.

Not run. This change does not alter model execution.
