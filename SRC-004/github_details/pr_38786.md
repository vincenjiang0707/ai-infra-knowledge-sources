## 正文

A revival of PR #19774  (which, surprisingly, still seems relevant).

This splits _fwd_grouped_kernel_stage1 operation in two parts, using a temporary buffer.

## Rationale
_fwd_grouped_kernel_stage1 becomes a significant bottleneck with large context lengths due to severe GPU under-utilization (very small grid size). This patch breaks it into two kernels:
- _fwd_grouped_kernel_stage1_part1: launched with larger grid, writes into temporary buffer
- _fwd_grouped_kernel_stage1_part2: smaller grid but much lighter operation

## Affected Models
At least on ROCm, this optimization benefits GLM-4.7-Flash, DeepSeek-V3 (when AITER is off), and potentially other GLM models. (DeepSeek can handle longer contexts when AITER is on, but AITER MLA does not support the head size of GLM-4.7-Flash.)

## Code Review

This pull request refactors the MLA decoding attention mechanism by splitting the first stage kernel into two parts and introducing a temporary accumulation buffer to improve GPU utilization. However, several critical issues were identified: the kpe loading logic in the first kernel part lacks necessary FP8 dequantization, the fixed allocation size of the temporary buffer poses a high risk of out-of-memory (OOM) errors at large batch sizes, and the second kernel part requires a safety check to prevent NaN values when handling empty KV splits.
