## 正文

The Kimi-K3 unit tests only run on the B200 job today, which means the AMD-specific tests in tests/models/kimi_k3/ never execute on AMD:

  test_amd_kda_chunk.py        66 tests   skipped on NVIDIA
  test_amd_latent_moe_runner.py 14 tests  skipped on NVIDIA
  test_amd_kda_decode.py       12 tests   skipped on NVIDIA
  test_amd_attn_res.py          9 tests   skipped on NVIDIA

Add an `amd` mirror of the existing job so they run on MI355.

Measured on an MI355X (gfx950), `pytest -v -s models/kimi_k3` gives 242 passed, 45 skipped, 0 failed in 451s. For comparison, the B200 job runs 180 of the same directory's tests and skips 111, so this is not duplicate coverage: 101 of these tests have no other home.

MI355 rather than MI300 because the fused KDA chunk and decode kernels are gated on gfx950 (tests/models/kimi_k3/test_amd_kda_chunk.py:23-27); on gfx942 those 66 tests would stay skipped.

The mirror overrides `commands` to drop the two kernels/ files the NVIDIA job runs. Both are CUDA-only -- they transitively import cuda.bindings.driver and error on ROCm. `source_file_dependencies` is inherited from the parent step, which already covers vllm/models/kimi_k3/, csrc/libtorch_stable/kimi_k3/ and tests/models/kimi_k3/.

Three tests in test_amd_latent_moe_runner.py are decorated @multi_gpu_test(num_gpus=4|8) and will skip on mi355_1; moving the job to mi355_4 would pick up the two tp4 cases if that is worth the slots.
