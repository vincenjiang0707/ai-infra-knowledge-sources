## 正文

## Purpose

Fix flaky Hugging Face reference generation on XPU in model comparison tests.

`HfRunner.generate_greedy_logprobs_limit()` can produce different greedy-decoding outputs across repeated runs with identical model inputs. This PR enables `torch.use_deterministic_algorithms(True)` only during the XPU HF reference `generate()` call, then restores the original setting afterward.

## Test Plan

Run the following ut repeatedly on XPU:

```bash
pytest -v -s \
  'tests/models/language/generation/test_common.py::test_models[False-False-5-32-openai-community/gpt2]'
```

## Test Result

Before this PR, the test was flaky across six runs:

```text
3 passed
1 failed at Test1
2 failed at Test7
```

The failures were caused by nondeterministic HF reference generation. For the same input, HF output varied between runs while vLLM output remained stable. eg: 

```text
# run_1
Test1 token_idx=10 hf_token=2099 vllm_token=318

# run_2
Test1 token_idx=10 hf_token=318  vllm_token=318
```

After this PR:
- Repeated runs produced consistent HF generated tokens and top-k logprobs.
- The ut passed.
- `pre-commit run --all-files`: passes.
