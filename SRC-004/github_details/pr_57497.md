# [PR #57497] [Qwen4Exp][ROCm] PLE n-gram table CPU offload

## 正文



## Purpose
- Enable `VLLM_PLE_CPU_OFFLOAD` on the AMD/ROCm path: keep the Qwen4Exp PLE n-gram table in pinned host memory, read through a UVA view on the GPU.
- Free VRAM so `Qwen/Qwen3.8-Flash-Next-FP8` (FP8 table ~51 GiB) / `Inferact/Qwen3.8-Flash-Next-NVFP4` (bf16 table ~102 GiB) serve on one MI300X with the table entirely in host RAM.
- Keep the pinned lookup behind a custom op (`qwen4_exp_amd_ple_ngram_embedding_pinned`) with `mutates_args=["output"]` so the large embedding weight is never materialized by `torch.compile` (Inductor autotuning builds a bf16 copy of the table during compile, which OOMs on AMD setups without enough VRAM) and the op survives aot_autograd/Inductor.
- Move the PLE embedding storage classes to `qwen4_exp/common` so the AMD and NVIDIA paths share one implementation (NVIDIA re-exports).
- Relax the PLE enable gate to `is_cuda_alike()` so ROCm is accepted, matching the existing NVIDIA default (`VLLM_PLE_CPU_OFFLOAD` defaults on for both; `=0` opts out). Also, my local testing shows little to no performance loss for PLE offload while saving a good chunk of VRAM for more KV cache.
- Why this is not duplicating existing PRs: 
  - #54371 (merged — source of the UVA offload code, ported here)
  - #55040 (AMD FP8 PLE, different approach: FP8 storage + forward dequant vs load-time bf16 fold; no offload/prefetch)
  - #55334 / #54070 / #54129 (nvidia + mmap — complementary).
- AI assistance: developed with opencode+deepseek-v4-flash+vllm; the submitting human reviewed every changed line and ran the tests/evals.

## Test Plan
- `uvx --from ruff==0.14.0 ruff check <changed files>`; `pre-commit run --files <changed files>` (incl. mypy).
- `python -m pytest tests/models/qwen4_exp/test_ple.py -q` on ROCm (MI300X) — 52 passed, including compile and cudagraph-capture regression tests for the pinned lookup op.
- Offload-vs-device correctness: same prompt with `VLLM_PLE_CPU_OFFLOAD=0/1`, top-8 logprobs bit-identical (max diff 0.0).
- Eval: 1× MI300X, `Qwen/Qwen3.8-Flash-Next-FP8`, `--max-model-len 262144`, table pinned (weight_device=cpu), CPU KV offload tier.
- Offload ON vs OFF head-to-head (8192 ctx, identical engine): prefill TTFT, decode, and burst are equal within noise; the offload's value is VRAM, not speed.
- An async side-stream prefetch variant was prototyped and measured on the clean config (64k-token non-repeating prefill, default cudagraphs): TTFT difference was a wash vs the synchronous lookup and decode was identical, so this PR ships the synchronous version.

## Test Result
- 52/52 PLE tests pass on ROCm; offload-vs-device logprobs max diff 0.0; "17*23" → 391.
- Needle-in-haystack at 105k and 209k tokens recalled exactly; GPU KV pool 1.57M tokens (6.0× for 262144) on one MI300X.
- Perf: offload ON vs OFF at 8192 — TTFT (6144-token prefill) 0.33s vs 0.33s, decode 8.8 vs 8.9 tok/s (eager) / 87 vs 86 tok/s (default cudagraphs at 262144), 8-way burst 2.4s vs 2.4s. No measurable offload cost.
