## Summary

ROCm MI355 GPUs in DPX mode use NPS2 partitioning — each physical GPU is split into 2 logical partitions (~144 GiB each). When multiple test pods run on the same physical node simultaneously (bin-packing scheduler), tests encounter GPU memory and hardware-specific failures. This PR fixes 3 categories of failures validated by a 400-job DPX stress test.

## Changes

### 1. GPU memory teardown — `tests/basic_correctness/`

**Problem:** On DPX nodes with bin-packing, a prior test leaves ~11 GiB residual GPU memory. The next `test_deep_sleep_*` test tries to initialize with `gpu_memory_utilization=0.92` × 144 GiB = 132.48 GiB but only 132.47 GiB is free — failing by 10 MB.

**Fix:** New `gpu_memory_cleared` opt-in fixture in `conftest.py`. Only activates on `gfx950`, waits for GPU to drop below 8% usage. Tests that need clean state explicitly request it via parameter — **no overhead on other tests** (not `autouse`).

```python
# conftest.py
@pytest.fixture()
def gpu_memory_cleared():
    if current_platform.is_rocm() and "gfx950" in (current_platform.get_device_name() or ""):
        wait_for_gpu_memory_to_clear(devices=[0], threshold_ratio=0.08, timeout_s=30)
    yield

# test_mem.py — 4 tests opt in
def test_deep_sleep(gpu_memory_cleared): ...
def test_deep_sleep_lora(gpu_memory_cleared): ...
def test_deep_sleep_async(gpu_memory_cleared): ...
def test_deep_sleep_fp8_kvcache_mrv1(monkeypatch, gpu_memory_cleared): ...
```

Same fixture added to `tests/models/language/generation/conftest.py` for hybrid model tests (`mamba-130m` Engine OOM on MI355).

### 2. GPTQ kernel not compiled for gfx950 — `tests/quantization/test_auto_gptq.py`

**Problem:** The GPTQ kernel (exllama/marlin) is not compiled for gfx950. At model load time, `qweight` key is missing from `RowParallelLinear`, causing `ValueError`.

**Fix:** Skip `test_auto_gptq_quantization_method` on gfx950.

### 3. Tensorizer numerical mismatch — `tests/model_executor/.../test_tensorizer.py`

**Problem:** After tensorizer serialization/deserialization, `test_deserialized_encrypted_vllm_model_has_same_outputs` asserts exact output match. gfx950 produces a valid but lexically different output due to attention numerical precision differences from gfx942/NVIDIA.

**Fix:** `xfail(strict=False)` for gfx950 — test still runs and counts as expected failure.
