# [PR #58261] [Bugfix][Logging] Fix three logging calls whose message is swallowed at runtime

state: closed | updated: 2026-09-23T04:59:03Z

## 正文

## Purpose

`logging` interpolates with `msg % args` inside `LogRecord.getMessage()`. When the format string and the argument count disagree it raises, the handler prints `--- Logging error ---` plus a traceback to stderr, and **the intended message never appears**. Three call sites in the tree do this.

**1. `vllm/v1/engine/tensor_ipc.py:149`**

```python
while tensors and (mid := next(iter(tensors))) < message_id:
    if sender.tensors.pop(mid):
        logger.warning(
            "Discarding %d stale tensors from sender %s",
            sender_id,          # one argument, two specs
        )
```

`%d` also receives the sender id, which is a `str`, so this raises `TypeError: %d format: a real number is required, not str`. The count the message wants is the size of the dict that `pop(mid)` returned, which is currently discarded by the `if`.

**2. `vllm/distributed/device_communicators/quick_all_reduce.py:175`**

```python
logger.warning(
    "Custom quick allreduce:",                       # format string, no %-spec
    f"Invalid quantization level: {regime_str}. "    # ...but here is an argument
    "Supported levels: "
    f"{list(QuickReduceRegime.__members__.keys())}",
)
return
```

Someone who sets an invalid `VLLM_ROCM_QUICK_REDUCE_QUANTIZATION` gets a logging traceback instead of the list of supported levels, and quick allreduce then silently stays off — exactly the case the warning exists for.

**3. `vllm/distributed/kv_transfer/kv_connector/v1/moriio/moriio_connector.py:1987`**

```python
logger.debug(
    "MoRIIO handshake listener received done recv for req",
    req_id.decode(),
)
```

Same shape: an argument with nothing to interpolate it into.

## Changes

- All three rewritten in the lazy `%s` form. For `tensor_ipc.py` the popped dict is bound to `stale` so its length can be logged, which is what the message has always claimed to report.
- `pyproject.toml`: add `PLE1205` and `PLE1206` to `[tool.ruff.lint] select`. The `G` (flake8-logging-format) rules already selected do **not** cover argument-count mismatches — `ruff check --select=G` passes on all three files above. `PLE1205`/`PLE1206` are report-only (no autofix), and the tree is clean for them after this change:

  ```
  $ ruff check --select=PLE1205,PLE1206 .
  All checks passed!
  ```

  `ruff check .` reports the same 133 pre-existing findings before and after this PR, so enabling the rules adds no new failures.

## Test

`tests/v1/test_tensor_ipc_queue.py` gains `test_receiver_reports_how_many_stale_tensors_it_discards`. It primes a `TensorIpcReceiver` with two tensors buffered under a stale `message_id`, asks for a tensor from a newer message, and asserts the rendered warning names the count and the sender. No GPU, no subprocess.

On current `main` it fails:

```
E   TypeError: %d format: a real number is required, not str
FAILED tests/v1/test_tensor_ipc_queue.py::test_receiver_reports_how_many_stale_tensors_it_discards
```

With this PR the whole file passes:

```
$ pytest tests/v1/test_tensor_ipc_queue.py
10 passed, 3 skipped in 24.93s
```

(3 skips are the CUDA-only cases; I ran this on a CPU-only host. `ruff check` and `ruff format --check` are clean on every changed file.)

I do not have AMD or MoRIIO hardware, so 2 and 3 are verified by reading plus the standalone stdlib repro below; 1 is covered by the new test.

```
>>> log.warning("Custom quick allreduce:", "Invalid quantization level: FP8")

    msg = msg % self.args

```
