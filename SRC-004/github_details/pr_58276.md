## Purpose

Fixes #57955

`decorate_logs()` rewrites `stdout`/`stderr` to prepend `(Worker_DP0 pid=12345) ` to every line. A configured JSON formatter (see `examples/features/logging_configuration.md`) then emits lines that are not valid NDJSON:

```text
(Worker_DP0 pid=12345) {"message": "Engine started"}
```

This change keeps structured-log output parseable while retaining the familiar console prefix for human-readable logs:

- JSON object lines are passed through **unprefixed**, so one `LogRecord` stays one valid JSON object.
- Every `LogRecord` now carries `vllm_process_name` and `vllm_pid`, so process identity (including rank-aware names like `Worker_DP0_TP1`) remains available to structured-log consumers.
- Default human-readable console logging and `print()` keep the `(name pid=N) ` prefix.

## Test Plan

```bash
pytest tests/test_logger.py -k decorate
```

## Test Result

**Before** — the same JSON-formatted write was prefixed and no longer parsed:

```text
(Worker_DP0 pid=12345) {"message": "Engine started"}
```

**After** — the JSON line is untouched and parses as a JSON object; text lines are unchanged:

```text
{"message": "Engine started"}
(Worker_DP0 pid=12345) INFO hello
```

Standalone check of the prefix logic:

```text
OUT: '{"message": "Engine started"}\n(Worker_DP0 pid=12345) INFO hello\n'
SMOKE_OK
```

New tests in `tests/test_logger.py`:

- `test_decorate_logs_keeps_json_lines_parseable`
- `test_decorate_logs_still_prefixes_text_lines`
- `test_decorate_logs_exposes_process_identity_on_records`
