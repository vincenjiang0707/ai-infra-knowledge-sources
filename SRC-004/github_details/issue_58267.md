### 🐛 Describe the bug

### Summary

Loading a compressed-tensors **W4A16 Whisper** checkpoint on **CPU** (`CPUWNA16LinearKernel` / `cpu_gemm_wna16`) fails at runtime. The Whisper encoder feeds **3-D** activations `[B, T, D]` into quantized Linear layers, but the C++ kernel treats the input as 2-D `[M, K]` and reads `K` from `input.size(1)`. For encoder time `T=28` that is not a multiple of 32, so the kernel aborts.

Separately, packed checkpoints expose `.k_proj.weight_packed` and omit `.k_proj.bias`. `_create_fake_bias_for_k_proj` only matches `.k_proj.weight` and sizes the fake bias from `weight.size(0)`, which is wrong for packed AWQ/Marlin layouts (`d_model` is required). After the crash is avoided, that produces garbage transcripts (WER 100 on LibriSpeech in our runs).

### Repro

Model: https://huggingface.co/RedHatAI/whisper-large-v3-turbo-quantized.w4a16

```python
from vllm import LLM
from vllm.assets.audio import AudioAsset

llm = LLM(
    model="RedHatAI/whisper-large-v3-turbo-quantized.w4a16",
    device="cpu",
    dtype="bfloat16",
    max_model_len=448,
    enforce_eager=True,
    limit_mm_per_prompt={"audio": 1},
)

prompt = "<|startoftranscript|><|en|><|transcribe|><|notimestamps|>"
audio, sr = AudioAsset("mary_had_lamb").audio_and_sample_rate
outputs = llm.generate(
    {
        "prompt": prompt,
        "multi_modal_data": {"audio": (audio, sr)},
    }
)
print(outputs[0].outputs[0].text)
```

### Expected
The request completes. BF16 openai/whisper-large-v3-turbo on the same CPU path is around 2.x WER on LibriSpeech; W4A16 should be in the same ballpark, not crash.

### Actual
```RuntimeError: Check failed: a_k_size % 32 == 0 (28 vs. 0)```

### Root cause
- 3-D activations. ops.cpu_gemm_wna16 does not flatten leading dims the way int4_scaled_mm_cpu already does (x.reshape(-1, x_shape[-1]), then reshape the output back). Whisper encoder Linear layers therefore pass [B, T, D] straight into the C++ op.
- Packed k_proj bias. WhisperForConditionalGeneration.load_weights only walks .k_proj.weight. Compressed-tensors W4A16 checkpoints use .k_proj.weight_packed and have no real .k_proj.bias. The fused qkv_proj/kv_proj path still needs a d_model-sized zeros bias; using packed dim0 is wrong.

### Suggested fix (native vLLM)
- Flatten/reshape in cpu_gemm_wna16 to match int4_scaled_mm_cpu.
- In _create_fake_bias_for_k_proj, also match .k_proj.weight_packed, size the fake bias from config.d_model, and do not override a real .k_proj.bias.

### hclsys · 2026-09-23

Checked both halves against current `main`. They hold, and there are a few details worth having before someone writes the patch.

**The 3-D gap is a two-line asymmetry, in one `if/else`.** `mixed_precision/cpu.py:190-204` passes `x` straight through in *both* branches. The `use_w4a8` branch survives 3-D only because `int4_scaled_mm_cpu`'s wrapper flattens internally (`_custom_ops.py:3436`); the `else` branch calls `cpu_gemm_wna16`, which flattens nowhere — not in the wrapper, not in the caller.

**One part isn't the C++ op.** The wrapper pre-allocates the output itself:

```python
# _custom_ops.py:4417
output = torch.empty((input.size(0), scales.size(1)), dtype=input.dtype)
```

For `[B, T, D]` that's `(B, N)` — wrong rank *and* wrong size, independently of the `a_k_size % 32` check. So relaxing the C++ assert alone wouldn't fix it; the flatten/reshape has to happen on the Python side (or the wrapper has to stop allocating).

**Scope, so nobody has to re-check the neighbours.** Of the CPU linear GEMM wrappers, `weight_packed_linear_cpu` and `int4_scaled_mm_cpu` flatten in the wrapper. `fp8_scaled_mm_cpu` doesn't — but its caller does, at `scaled_mm/cpu.py:320-330` (`x_2d = x.reshape(...)`, reshape back after). So `cpu_gemm_wna16` is the only one with no flatten on either side.

**On the fake-bias fix — `str.replace` will bite.** `_create_fake_bias_for_k_proj` derives the name with:

```python
bias_name = name.replace("weight", "bias")
```

Extend the match to `.k_proj.weight_packed` as you suggest and that yields `...k_proj.bias_packed`, not `...k_proj.bias`. The name needs to be built from the matched suffix rather than substring-replaced.

Also note the helper is shared: `whisper.py:1037`, `glmasr.py:508`, and `moss_transcribe_diarize.py` all call it with `".k_proj.weight"`. Sizing from `config.d_model` is right, but it wants to be right for all three.

I don't have the hardware you're on and haven't run the repro — this is all read against `main`, so treat the WER half as unverified by me.
