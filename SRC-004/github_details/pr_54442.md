## Purpose

Part of #54437.

`StructuredOutputManager.grammar_bitmask` constrains a row only while
`apply_bitmask` holds, and a `-1` placeholder in the scheduled draft window sets
`seen_padding`, so every row after it is filled with `_full_mask` — every token
in the vocabulary allowed:

```python
# vllm/v1/structured_output/__init__.py
for i, token in enumerate(req_tokens):
    apply_bitmask = not failed and not seen_padding and i >= constraint_start
    self._fill_bitmasks(((grammar, cumulative_index, apply_bitmask),))
    if token == -1:
        seen_padding = True
```

That is sound when the `-1` means "`validate_tokens` rejected this draft": the
first `-1` then sits at exactly the draft the grammar rejected, that draft's own
row is still masked, so it is rejected and acceptance never reaches the
permissive rows. It is not sound when the `-1` means "the drafts never reached
the scheduler", which happens because the draft hand-off carries no identity —
`DraftTokensHandler` keeps one slot that every `execute_model` overwrites
(`vllm/v1/worker/gpu/spec_decode/utils.py`), and it also clears the payload
entirely for a batch with no structured-output requests. The worker meanwhile
verifies the genuine drafts from its own GPU-resident `req_states.draft_tokens`,
so acceptance can walk straight into rows that constrain nothing and the request
emits tokens the grammar never allowed.

#54437 has the full chain, a model-free reproduction on `main`, and field
measurements. This PR is the fail-closed half: it makes the permissive rows
unreachable regardless of why the drafts went missing. The identity fix for the
hand-off is a separate change.

**Not a duplicate of #56802.** That PR implements the other half of #54437 —
identity for the hand-off, so the drafts are not lost in the first place. It is
complementary: its lookup miss path falls back to exactly the invalidation this
PR adds, so on a miss without this PR the bitmask still fails open.

## Change

Carry, per structured-output request, how many leading drafts the bitmask
actually constrained, and invalidate the drafts from that index on, so
`is_valid_draft = draft_sampled >= 0` pins the accepted length before sampling
can reach a permissive row.

- `vllm/v1/core/sched/scheduler.py`: `get_grammar_bitmask` fills
  `num_acceptable_drafts` with `len(strip_speculative_padding(window))`, reusing
  the helper #48200 introduced.
- `vllm/v1/core/sched/output.py`: `GrammarOutput.num_acceptable_drafts`, a
  defaulted field, so existing constructors keep working.
- `vllm/v1/worker/gpu/model_runner.py`: `grammar_invalid_draft_positions`
  translates that into indices of the gathered draft vector.
- `vllm/v1/worker/gpu/spec_decode/rejection_sampler.py`: verification runs
  against a copy with those entries set to `-1`. `apply_sampling_params` and the
  watermarking context still receive the real draft ids, so penalties and
  bad-words are unaffected.
- `vllm/v1/worker/gpu/sample/batch_shard.py`: shard the new per-request list the
  same way as the bitmask.

No kernel change: `rejection_sampler_utils` already resamples a `-1` position
straight from the target distribution rather than from the residual. That
matters — `max(p - q, 0)` is the residual of a *genuine* rejection, and forcing
one where `p ≈ q` collapses it across the vocabulary.

When the drafts are fully back-filled nothing is invalidated and behaviour is
unchanged. Absent the field — an older scheduler, or warmup — the whole window is
invalidated, which is the conservative choice.

Production diff is 79 added / 2 removed lines across those five files.
