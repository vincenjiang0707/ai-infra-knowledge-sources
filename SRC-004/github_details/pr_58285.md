## 正文

## Purpose

`get_lock` flattens the whole model path into the lock file name:

```python
# vllm/model_executor/model_loader/weight_utils.py
model_name = model_name_or_path.replace("/", "-")
hash_name = hashlib.sha256(model_name.encode()).hexdigest()
# add hash to avoid conflict with old users' lock files
lock_file_name = hash_name + model_name + ".lock"
lock = filelock.FileLock(os.path.join(lock_dir, lock_file_name), mode=0o666)
```

The digest is 64 characters, so any `--model` path longer than roughly 186 characters produces a file **name** over the 255-byte cap that ext4, xfs, btrfs and APFS all put on a single path component. The full *path* may be far longer than 255 bytes, which is why this is easy to miss — the limit is per component.

It only bites on local checkpoint paths, but it bites before a single weight is read:

```
OSError: [Errno 36] File name too long
```

Reproduced on a 221-character local checkpoint path, which lands the lock name at 290 bytes:

```python
>>> path = ("/mnt/shared-storage/models/team-inference/experiments/"
...         "2026-02-long-context-run-17/checkpoints/global_step_120000/"
...         "hf_export/Qwen3-235B-A22B-Instruct-FP8-blockwise/snapshot/"
...         "revision-2026-02-14-rc3-merged-lora-adapters/final")
>>> get_lock(path, cache_dir=tmpdir)
OSError errno=63: File name too long          # ENAMETOOLONG, macOS numbering
```

`get_lock` guards the weight download, the config download and the tokenizer download — 8 call sites in `weight_utils.py` and `tokenizers/registry.py` — so this takes out model loading entirely for anyone serving from a deep shared-storage or multi-revision export path.

## Changes

Fall back to the digest alone when the composed name is too long:

```python
if len(os.fsencode(lock_file_name)) > 255:
    lock_file_name = hash_name + ".lock"
```

The digest is already collision-resistant and is derived from the same string, so the lock stays per-model. Ordinary Hugging Face model ids keep their existing lock file name — that matters, because the file name is what makes the lock shared between processes, and changing it unconditionally would let two concurrent vLLM processes download the same model at once.

This is the same fix that already shipped in SGLang's fork of this function (`python/sglang/multimodal_gen/runtime/loader/weight_utils.py`), which is where I noticed the divergence.
