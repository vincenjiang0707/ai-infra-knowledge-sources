# [PR #57309] [KVConnector] Share KV cache spec-type classification across connectors

## 正文

## Purpose

Cross-engine KV transfer has to classify each cache group's spec type (attention / SSM / other) before it can plan anything. In tree there are three implementations of that step: NIXL keeps `_is_attention_spec` / `_is_ssm_spec` private in `nixl/tp_mapping.py` and `get_representative_spec_type` in `nixl/utils.py`, MooncakeConnector calls `isinstance(...)` inline at three sites, and MoRIIO unwraps the group spec on its own. The same classification therefore gets fixed per connector.

This PR moves those three helpers to the connector framework layer as `v1/transfer_planning.py`: `is_attention_spec`, `is_ssm_spec`, `get_representative_spec_type`. NIXL and MooncakeConnector import them, and `nixl/tp_mapping.py` no longer defines a private copy.

The shared surface is deliberately only the classification vocabulary. `TPMapping`, `compute_tp_mapping` and `ReadSpec` stay in the `nixl` package, because `rank_to_attention_slot`, `rank_offset_factor` and `local_consumers` encode NIXL's read path and its completion-notification accounting. Extracting the peer shard relation and the transfer plan comes later, once the primitive list in #57373 is settled.

No behavior change: the three helpers are moved verbatim (`get_representative_spec_type` gains a one-line docstring), the Mooncake call sites keep identical semantics (`isinstance(inst, Cls)` → `is_*(type(inst))`), and the NIXL transfer paths and wire formats are untouched.
