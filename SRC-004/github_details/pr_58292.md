# [PR #58292] [Bugfix][KV Connector] Reap expired NIXL leases behind a heartbeated head

## 正文

## Purpose

The NIXL send-side lease reaper treated `_reqs_to_send` as expiry-ordered and stopped at the first still-live entry. Heartbeats update that map **in place**, so a request that keeps getting renewed can sit at the head forever and block reclaim of every expired entry behind it. That is the case in #58222: A is heartbeated, B and C expire, and neither is ever released.

Delete+reinsert on heartbeat is not enough either — `max(old, now + extension)` can still leave a later-inserted longer TTL in front of an already-expired entry. The reaper now scans the whole map. `_reqs_to_process.remove()` is also `discard()`, so reaping IDs the old early-exit never reached cannot KeyError.

Fixes #58222.

**Not a duplicate of [#50789](https://github.com/vllm-project/vllm/pull/50789):** that is a stale draft from August against an older `get_finished()` layout, and it does not target this issue. This change is against current `main`, extracts a testable helper, and pins the issue's stdlib repro as a unit test.
