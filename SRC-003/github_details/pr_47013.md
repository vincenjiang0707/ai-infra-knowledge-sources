### ErenAta16 · 2026-07-10 · APPROVED

Checked this against the pattern #46908 established for the same problem (`get_attention_context()` / `mla_attention.py`) — the `if isinstance(slot_mapping, list): slot_mapping = slot_mapping[0]` fix here matches that precedent exactly, including the "[0] is the base model" comment convention and the test structure (constructing a `ForwardContext` with `slot_mapping=[{...}]` and asserting the unwrapped dict is what reaches `do_kv_cache_update`).

Also went looking for any other `forward_context.slot_mapping` consumer this PR (and #46908/#46830 before it) might have missed. There are 8 references repo-wide; the only one not covered by either PR is `whisper_causal.py`, but that one's deliberately not affected — it explicitly builds its own transformed `slot_mapping` off `attn_metadata` instead and has a comment saying exactly why it avoids `forward_context.slot_mapping`. So this PR's two additions (`extract_hidden_states.py`, `deepseek_v32/nvidia/attention.py`) look like the complete remaining set, not a partial fix.
