## Purpose

**Depends on U-model PR [#58239](https://github.com/vllm-project/vllm/pull/58239), which depends on Q-model PR [#58046](https://github.com/vllm-project/vllm/pull/58046). Merge order: Q → U → V.** This branch starts at U's `1b14e30aa7`. Its diff against upstream `main` includes the pending Q and U changes; after those merge, rebasing onto `main` will leave only the V-specific changes.

Continue the incremental mypy rollout tracked by [#26533](https://github.com/vllm-project/vllm/issues/26533) by removing `r"vllm/model_executor/models/[vV]"` from the mypy exclusions. All four selected files are now checked: `vision.py`, `voxtral.py`, `voxtral_realtime.py`, and `voyage.py`. Voyage already passes without code changes.

The V-specific changes touch five files. They correct read-only vision configuration protocols, narrow optional normalization values, and type Voxtral's encoder factory and mixed string/integer weight shard IDs. Quantization remapping is only called when a quantization configuration exists. Realtime processing explicitly requires audio data and a causal encoder. No new casts or typing suppressions are added; the existing `cast(WhisperConfig, ...)` in `voxtral.py` is unchanged.

Voxtral's realtime buffer now yields raw `TokensPrompt` values directly. The serving path already renders those prompts before wrapping the resulting engine inputs in `StreamingInput`. The generation test is updated to follow that same contract, and three CPU regression cases check audio overlap, token feedback, and stream termination across different chunk sizes. Model computations and the prompts yielded by `buffer_realtime_audio` are unchanged for valid inputs.
