# [PR #54874] [XPU] Preserve non-contiguous strides when pinning CPU tensors for UVA view

source: https://github.com/vllm-project/vllm/pull/54874
state: open | updated: 2026-09-23T03:31:12Z
labels: bug, intel-gpu, ci/build

## 正文

## Purpose

When obtaining an XPU accelerator view from an unpinned CPU tensor, the previous implementation invoked `cpu_tensor.contiguous()` before pinning the memory. This operation converted non‑contiguous strided views (e.g., the transposed weight‑scale tensor `scale_kn.t()`) into contiguous ones, discarding their original stride patterns. Later, applying `.t()` on these contiguous copies produced non‑contiguous tensors again, which triggered extra implicit `.contiguous()` copies during GEMM execution and degraded performance.

## Changes

- Modify the XPU‑specific `get_accelerator_view_from_cpu_tensor` to allocate pinned memory via `torch.empty_strided` using the original tensor's size and stride, instead of first making the tensor contiguous.
- Add a new test `test_non_contiguous_strided_view` under `tests/kernels/core/test_uva.py` to validate both pinned and unpinned non‑contiguous strided views.
