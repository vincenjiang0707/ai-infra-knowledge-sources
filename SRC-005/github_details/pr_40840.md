# [PR #40840] fix(attention): drop duplicate method definitions that shadow the newer ones

## 正文

## Motivation

Two attention wrappers define the same method twice inside one class body. Python keeps the **last** definition, so in both cases a newer implementation is silently replaced by an older one and the behavior it added never runs.

**1. `HybridLinearAttnBackend.get_indexer_metadata`** (`hybrid_linear_attn_backend.py`)

| line | added by | body |
|---|---|---|
| 1236 | #37500 `support qwen 3.8 flash next` (2026-09-08) | `if layer_id in self.full_attn_layers: return self.full_attn_backend.get_indexer_metadata(...)` else `None` |
| 1279 | #36507 `GLM-5.3-Flash support` (2026-09-06) | unconditional `return self.full_attn_backend.get_indexer_metadata(...)` |

The two PRs landed two days apart and each added its own copy. The one at line 1279 wins, so the `full_attn_layers` guard added by #37500 is dead code: on a hybrid model every `layer_id`, including the linear / Mamba layers, is forwarded to the full-attention backend instead of returning `None`.

**2. `HybridAttnBackend.forward`** (`hybrid_attn_backend.py`)

| line | added by | body |
|---|---|---|
| 161 | `73d272bddb6` (2026-03-05) | accepts `mixed_qkv` / `a` / `b` and routes linear-attention calls |
| 231 | `5b2e2750b55` (2026-03-04) | plain `q, k, v` delegation |

Same pattern. The plain version at line 231 wins, so a caller that passes `mixed_qkv=...` has it absorbed into `**kwargs` while the wrapper still forwards `q=None, k=None, v=None` to the child backend. The linear-attention support added at line 161 never executes.

Both are caught by `ruff check --select=F811`, which is not currently enabled in this repo's pre-commit config.

## Modifications

- `hybrid_linear_attn_backend.py`: delete the unguarded `get_indexer_metadata` at line 1279, keep the guarded one.
- `hybrid_attn_backend.py`: delete the plain `forward` at line 231, keep the one that handles linear attention.
  To keep the diff behavior-preserving for the non-linear path, the surviving `forward` now delegates with keyword arguments (`q=q, k=k, ...`), exactly as the definition that was live before this change did, instead of positionally.

In both files the surviving definition is a strict superset of the deleted one, so this only restores the branches that were unreachable.

## Accuracy Tests

No kernel or model forward math is changed. The change restores two branches that could not be reached:
- `get_indexer_metadata` now returns `None` for a non-full-attention `layer_id` instead of querying the full-attention backend.
- `HybridAttnBackend.forward` now routes `mixed_qkv` / `a` / `b` to the child backend instead of dropping them into `**kwargs` alongside `q=None, k=None, v=None`.

I do not have hybrid-model hardware to run an end-to-end accuracy sweep. Happy to add one if a maintainer points me at the right CI job (`qwen3.5`/`GLM-5.3-Flash` hybrid + DSA indexer looks like the relevant coverage).
