## Motivation

`Qwen3_5ForCausalLM.set_dflash_layers_to_capture` is defined twice in `python/sglang/srt/models/qwen3_5_text.py`:

| line | added by | shift |
|---|---|---|
| 114 | #35758 `qwen 3.8 rebase` (2026-08-28) | `[layer_id + 1 for layer_id in layer_ids]` |
| 149 | #34771 `[Spec] Wire DFLASH aux-hidden capture into the Qwen3.5 text-only wrapper` (2026-08-14) | no shift |

Python keeps the last definition in the class body, so the one at line 149 is what runs and the one at line 114 is dead code. `ruff check --select=F811` flags it (that rule is not in this repo's pre-commit `--select` list).

**The live one is missing the `+1` shift.** The backbone sets the flag on the layer object:

```python
# qwen3_5.py
def set_dflash_layers_to_capture(self, layers_to_capture: list[int]):
    self.layers_to_capture = layers_to_capture
    for layer_id in self.layers_to_capture:
        setattr(self.layers[layer_id], "_is_layer_to_capture", True)
```

and the forward pass passes `captured_last_layer_outputs` to the flagged layer (`qwen3_5.py:1940`), so layer `i` captures the output of layer `i - 1`. Every other model wrapper in the tree shifts by one before calling the backbone:

- `llama.py:912` — `self.model.layers_to_capture = [val + 1 for val in layer_ids]`, with the comment *"we plus 1 here because in sglang, for the ith layer, it takes the output of the (i-1)th layer as aux hidden state"*
- `qwen3_moe.py:1177` — `self.model.set_dflash_layers_to_capture([val + 1 for val in layer_ids])`
- `gemma4_causal.py:1150` — `self.model.layers_to_capture = [val + 1 for val in layer_ids]`

`Qwen3MoeModel.set_dflash_layers_to_capture` and `Qwen3_5*.set_dflash_layers_to_capture` have identical bodies, so the wrappers should agree on the shift and today they do not.

Effect: Qwen3.5 + DFLASH captures the output of layer `val - 1` instead of layer `val`. It does not crash. The draft model simply consumes hidden states from the wrong layers, which shows up as a lower acceptance rate.

## Modifications

- Delete the shadowed definition at line 114.
- Add `[val + 1 for val in layers_to_capture]` to the live definition, with the same comment used in `llama.py`.

The deleted definition also carried input validation (unique / strictly increasing ids, range check, explicit `NotImplementedError` for PP > 1). None of that has ever executed. This PR keeps the live definition's `if not self.pp_group.is_last_rank: return`, which is what `llama.py` and `qwen3_moe.py` do. If maintainers want the stricter validation back, that is worth a separate change so this one stays a pure off-by-one fix.

## Accuracy Tests

No kernel math changes. The behavioral change is which decoder layers set `_is_layer_to_capture`, and the new value matches `llama.py` / `qwen3_moe.py` / `gemma4_causal.py`.

I do not have the hardware to run a Qwen3.5 + DFLASH acceptance-rate comparison. The check that would confirm it: run spec decode with the same `--speculative-*` config before and after and compare the reported accept length. Happy to add the run if a maintainer can point me at the CI job.

## Speed Tests and Profiling

Indirect: this is expected to raise the DFLASH acceptance rate for Qwen3.5 back to where the other models sit. No hot-path code changes.
