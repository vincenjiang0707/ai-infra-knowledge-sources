## Motivation

`ModelOptMixedPrecisionConfig` dispatches both `FP8_PB_WO` and `FP8_BLOCK_SCALES` for Linear layers, but only `FP8_BLOCK_SCALES` for FusedMoE, and it hard-codes the block-FP8 block size to `[128, 128]` in two field-identical sub-configs.

`nvidia/Qwen3.8-Flash-Next-NVFP4` labels its MTP experts (`mtp.layers.0.mlp.experts`) `FP8_PB_WO` (`group_size` 128) in the inline `config.json` and `FP8_BLOCK_SCALES` in `hf_quant_config.json`. Today the file copy wins only because the inline copy carries no KV-cache key and is discarded as incomplete (`weight_utils.py`). If the inline copy became authoritative, the FusedMoE branch would fall through to `return None`, FusedMoE would install the unquantized method, and the fp8 expert weights would be cast to bf16 with `weight_scale_inv` silently dropped — no error.

Mirrors vllm-project/vllm#55513 (`_BLOCK_FP8_MOE_ALGOS`, block size from `group_size`, conflicting sizes rejected).

## Modifications

- `_BLOCK_FP8_ALGOS = ("FP8_PB_WO", "FP8_BLOCK_SCALES")`; the Linear and FusedMoE branches both dispatch on it to the single block-FP8 sub-config `fp8_block_config`. The field-identical `fp8_pb_wo_config` that sat next to it is removed (constructor parameter, attribute, construction, kwarg).
- That sub-config's `weight_block_size` is derived from the checkpoint's block-FP8 `group_size` (default 128) instead of being hard-coded; a MIXED_PRECISION map whose block-FP8 layers disagree on it raises.
