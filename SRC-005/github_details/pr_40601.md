## 正文

## Motivation

Shared KV-event consumers reject SGLang `BlockStored` messages because the required nullable `lora_name` field is missing. Consumers that derive salted cache keys from `extra_keys` also cannot find SGLang's salt there.

This draft contains an implementation of **proposed Phase 1 of #39991**. Replay framing and LoRA adapter-name/hash propagation remain separate follow-ups, so this PR does not close the RFC.

## Modifications

- Always serialize nullable `medium` and `lora_name`; producers emit `lora_name=None`.
- Emit the cache salt in `extra_keys` only for block zero of a full prefix. Keep entries aligned with `block_hashes` when stores coalesce, including padding absent entries. Preserve the named `cache_salt` and `session_id` fields.
- Apply the same metadata rule to the Rust adapter using its existing parent hash, block count, and salt. No Rust binding tuple or native implementation change is needed.
- Document the wire metadata and add registered CPU regression tests for required nulls, legacy decoders, coalescing, prefix continuations, and Python/Rust parity after extension and node splitting.

A separate commit relocates the unchanged MXFP8 reserved-slot test added by #35351 from `test/registered/kernel/quantization/` to `test/registered/kernels/ops/quantization/`. The latest upstream commit otherwise fails the repository's registered-test taxonomy check; the failure was reproduced on unmodified `main`. This is a path-only correction with no test-content changes.

Block hashes, storage-tier names, batch layout, and transport framing are unchanged.

  test/registered/unit/disaggregation/test_kv_events.py \
