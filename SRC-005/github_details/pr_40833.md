# [PR #40833] [Bugfix] Harden DeepSeek V4 reasoning and DSML tool-call parsing 

source: https://github.com/sgl-project/sglang/pull/40833
state: open | updated: 2026-09-23T03:46:39Z
labels: dependencies, deepseek, npu

## 正文

DeepSeek V4 reasoning and tool-call outputs can expose several parser correctness issues, especially under streaming:

• Parsing and reserializing incomplete non-string parameters can change previously emitted values. For example, the intermediate value of  12345e-3  may change from  12345  to  12.345 , violating the append-only contract of streamed tool arguments.
• Template-prefilled reasoning delimiters, repeated closing tags, and malformed DSML boundaries can leave protocol fragments in assistant content or reasoning.
• A completed generation does not necessarily contain valid tool arguments. Malformed JSON, duplicate parameters, or schema violations should fail explicitly rather than become apparently successful tool calls.
• Raw model-output tracing needs an explicit opt-in because decoded outputs may contain sensitive information.

This PR improves parsing correctness and adds optional validation policies. It does not attempt to repair arbitrary model-generated content or infer missing tool arguments.

Modifications

• Preserve append-only argument streaming
• Wait for non-string DSML parameters to close before serializing their values.
• Preserve incremental string-parameter handling.
• Reject incomplete non-string parameters at EOF instead of emitting guessed values.
• Cover the shared DeepSeek V3.2/V4 parsing path.
• Improve reasoning and DSML boundary handling
• Handle bare reasoning-end tokens for internally thinking models.
• Recognize tool boundaries while protecting quoted and code-literal regions.
• Remove redundant, unquoted reasoning closers only at confirmed tool boundaries.
• Handle orphan reasoning-tail closers only at an explicit reasoning-end boundary, preserving paired markup, quoted content, and unconfirmed EOF cases.
• Add explicit validation
• Validate parameter boundaries, duplicate names, string flags, completed JSON, and append-only argument prefixes.
• Reject duplicate JSON keys and non-finite JSON constants.
• Add optional JSON Schema validation without value coercion, missing-field insertion, or external reference retrieval.
• Add optional protocol-marker rejection for assistant content and tool arguments.
• Make raw output tracing explicitly opt-in
• Require  SGLANG_ENABLE_MODEL_OUTPUT_LOGGING=1  together with  SGLANG_MODEL_OUTPUT_TRACE_DIR .
• Configuring a directory alone no longer enables tracing.
• Preserve append/replace output deltas for parser diagnostics without directly copying request bodies or authentication headers.
• Raw output is not redacted; enabling this feature remains an explicit diagnostic choice.

The additional strict/schema/marker policies and raw-output logging gate are disabled by default. Marker rejection is a policy restriction: when enabled, it can also reject legitimate protocol examples.

Accuracy Tests

No kernels, model forward code, checkpoint weights, or quantization implementations are changed. Validation focuses on parsed outputs and tool-call semantics.

Coverage includes different chunk boundaries, streaming/non-streaming behavior, incomplete EOF, quoted/fenced/heredoc content, argument validation, and enabled/disabled logging configurations.

Recorded-output replay

• Reproduced previously captured invalid arguments with the old parser, then verified that the updated parser rejects those generations explicitly.
• Verified that a recorded reasoning-tail case removes only the targeted orphan closer while preserving ordinary content and tool arguments.
• Replays used recorded decoded output; they did not invoke the model again or execute generated commands.

End-to-end observations

A custom 100-task agent regression using the preceding parser revision, with strict/schema/marker policies enabled, completed 92/100 tasks with 0 terminal protocol failures. There were 142 intermediate source-side rejections, reported separately rather than counted as repaired generations.

One orphan  </parameter>  in the middle of reasoning remains. Cleanup is intentionally limited to confirmed boundaries; this PR does not claim universal zero-marker output.

These cases were used during regression development, not as an untouched holdout. The final logging-only commit was covered by the CPU tests above; the full model evaluation was not repeated after that commit.

Speed Tests and Profiling

No isolated TTFT, TPOT, throughput benchmark, or profiler run was performed for this PR. No inference-speed improvement is claimed.

Strict validation, buffering, and enabled raw tracing can add CPU, memory, or I/O overhead. Raw tracing is disabled by default.

For reference, the recorded end-to-end agent evaluation averaged 333.6 seconds per task, compared with 323.6 seconds in the preceding evaluation. These are not controlled engine-performance measurements: generation trajectories differed, seeds were not fixed, and execution resources were shared during part of the run. The difference should not be attributed solely to this patch.
