# [PR #40820] [Perf] Shard Kimi K3 latent front projection for TP8 decode

source: https://github.com/sgl-project/sglang/pull/40820
state: open | updated: 2026-09-23T03:14:36Z
labels: jit-kernel

## 正文

## Motivation

Kimi K3's merged MoE front computes the full latent down-projection on every TP rank. For small decode batches, sharding its output columns reduces redundant weight reads and compute.

## Modifications

- Add an opt-in TP8 front for M8/M16: compute the shared/router outputs plus 448 local latent columns, then assemble the FP32 latent tensor through multicast.
- Reuse the existing communication workspace and extend its gather consumer to support FP32 payloads.
- Enable with `SGLANG_ENABLE_K3_SHARDED_FRONT=1`; retain the existing path for other shapes or unsupported configurations. The local weight copy adds approximately 3.54 GiB/GPU for the 92 MoE layers; full weights remain available for fallback.

## Accuracy Tests

- Eight-rank exact FP32 assembly checks with positive, negative and zero payloads, alternating M8/M16 gathers with push all-reduce; six CUDA Graph replays exercise all three payload types in both mailbox phases.
- Exact M8/M16 projection checks against an independent FP32 matmul under CUDA Graph replay, including rank-specific shared-expert weights.
- Misaligned input rejection before kernel launch.
- Existing BF16 GEMM all-gather and push all-reduce regression tests.
- Pre-commit checks on all changed files.

Model-quality evaluation is pending; the performance experiment uses dummy weights.

## Speed Tests and Profiling

Preliminary full-model A/B measured before the upstream port; E2E revalidation on this PR base is pending.

8×B300, Kimi K3 NVFP4, TP8/DCP8, BS1, 61,440 input / 1,024 output tokens, 95% prefix-cache hit rate, DSPARK block 7 with simulated acceptance 5.5. Both target and draft use deterministic dummy weights. Both arms use TRT-LLM MoE, CuTe DSL BF16 GEMM, FP8 E4M3 KV, BF16 Mamba state, and identical cache capacities.

| Unprofiled decode throughput | Baseline | Sharded front |
|---|---:|---:|
| Median of three requests | 387.67 tok/s | **395.55 tok/s (+2.03%)** |
| Range | 385.80–387.72 tok/s | 393.77–395.58 tok/s |

One server launch per arm. Acceptance matched sample-by-sample at 5.49 / 5.49 / 5.52, and every request generated 1,024 tokens at a 95% cache hit rate. No prefill speedup is claimed. Profile traces will be added separately.
