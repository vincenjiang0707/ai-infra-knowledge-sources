### Describe the bug

When `--spec-capture-aux-layer-ids` contains the **last decoder layer** (`num_hidden_layers - 1`), the DFlash aux-hidden-state capture crashes at server startup on the Qwen3.5 model path:

```
File ".../sglang/srt/model_executor/model_runner.py", line 1034, in init_aux_hidden_state_capture
    self.model.set_dflash_layers_to_capture(self.dflash_target_layer_ids)
  File ".../sglang/srt/models/qwen3_vl.py", line 1309, in set_dflash_layers_to_capture
    self.model.set_dflash_layers_to_capture([val + 1 for val in layer_ids])
  File ".../sglang/srt/models/qwen3_5.py", line 1210, in set_dflash_layers_to_capture
    setattr(self.layers[layer_id], "_is_layer_to_capture", True)
IndexError: index 32 is out of range
```

**Root cause.** The CLI layer ids are HF-style "capture the *output* of layer k". SGLang captures "before layer i", so the wrapper shifts every id by +1 to capture the hidden state entering layer k+1 (= output of layer k). This convention is intentional and documented in #30204.

The problem: for `k = num_layers - 1` (the last decoder layer), the shifted id is `num_layers`, which does not exist as a module:

- `qwen3_5.py` / `qwen3_vl.py`: `set_dflash_layers_to_capture` does `setattr(self.layers[num_layers], ...)` → **IndexError** (crash at startup).
- `qwen2.py` / `qwen3.py` use a `layers_to_capture` list checked inside the forward loop (`for i in range(start_layer, end_layer)`), so the id `num_layers` **silently never matches** — the server starts but the last layer's output is never captured, producing fewer aux hidden states than the draft config expects. This silent variant is arguably worse: training/serving proceeds with a mismatched feature set.

This is triggered by any DFlash/Domino draft config whose `dflash_config.target_layer_ids` includes the final layer. Existing published configs never hit it (e.g. Qwen3-8B has 36 layers and uses `[3, 11, 19, 27, 31]`), but the Qwen3.5-4B Domino/DFlash draft configs (32 layers, `target_layer_ids=[3, 11, 19, 27, 31]`) require the output of layer 31 and crash on startup. Found while running SpecForge online disaggregated training (server-capture mode) for Qwen3.5-4B on Ascend NPU; the code path is device-independent and reproduces identically on current `main`.


(Qwen3.5-4B has 32 decoder layers; id 31 + the internal +1 shift = index 32 → IndexError. Any 32-layer Qwen3.5/VL target with id 31 in the list reproduces it; `--attention-backend` is irrelevant to the crash.)

### Expected behavior

Capturing the last decoder layer's output should work: `num_layers` in the shifted list is a valid capture position meaning "the hidden state entering the final norm" (= output of the last decoder layer), consistent with the documented "capture before layer i" convention in `qwen3.py` ("SGLang captures 'before layer i'. To capture the hidden state after target layer `k` (HF-style), we capture before layer `k + 1`").

### Suggested fix

In the model forward pass, treat a capture id of `num_layers` as "append the pre-final-norm hidden state after the decoder loop", e.g. for `qwen3_5.py`:

```python
def set_dflash_layers_to_capture(self, layers_to_capture: list[int]):
    self.layers_to_capture = layers_to_capture
    self._capture_after_last_layer = False
    for layer_id in self.layers_to_capture:
        if layer_id >= len(self.layers):
            self._capture_after_last_layer = True  # capture output of the last decoder layer
            continue
        setattr(self.layers[layer_id], "_is_layer_to_capture", True)

# in forward(), after the decoder loop and before the final norm:
if getattr(self, "_capture_after_last_layer", False):
    aux_hidden_states.append(
        hidden_states + residual if residual is not None else hidden_states
    )
```

This matches the value captured by `layer_communicator.prepare_attn_and_capture_last_layer_outputs` for in-range layers (residual-stream input of the next layer) and keeps `aux_hidden_states` ordered by layer id. The `qwen2.py`/`qwen3.py` list-based implementations additionally need the same after-loop capture so the `num_layers` id stops being silently dropped. Happy to open a PR with this change plus a boundary test if the approach looks right.
