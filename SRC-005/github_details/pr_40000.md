## 正文

## Motivation

The Kimi-K3 LatentMoE tail, after the MoE all-reduce, is fully **replicated**:
every rank runs the latent RMSNorm, the `routed_expert_up_proj` GEMM and the
`_add3` over all `T` tokens and keeps the same full result. At TP8 that means
7/8 of the GEMM is computed and thrown away on every rank, on every one of the
91 MoE layers.

The tail is **token-local** — there is no cross-token reduction anywhere in it
(RMSNorm reduces over the row; the up-projection is a per-row matmul; the adds
are elementwise). So each rank can compute its own `T/w` rows and the ranks can
exchange what they uniquely computed, instead of all of them recomputing the
same thing:

```
AR(buf) -> norm(full T) -> up_proj(full T) -> add3(full T)      before
AR(buf) -> norm(T/w)    -> up_proj(T/w)    -> add3(T/w) -> AG   after
```

This is the same idea as the existing SP-MoE family in `k3_sp_collective.py`,
applied one call-site over: that shards the attention-residual aggregation,
this shards the MoE tail. It deliberately leaves the all-reduce alone.

## Modifications

| file | change |
|---|---|
| `python/sglang/srt/layers/k3_sp.py` | **new**, 108 lines — the tail-shard closure only |
| `python/sglang/srt/environ.py` | `SGLANG_K3_TAIL_SHARD` + `SGLANG_K3_TAIL_SHARD_MIN_TOKENS` |
| `python/sglang/srt/models/kimi_k3.py` | one import + a 9-line branch in `_forward_fused` |
| `test/registered/unit/models/test_kimi_k3_tail_shard.py` | **new** correctness gates |

`k3_sp.py` is trimmed to what this feature uses — `tail_shard_enabled`,
`_tail_shard_armed`, `tail_shard_eligible`, `tail_shard_rows`,
`front_shard`/`qkva_shard` reuse `tail_shard_rows` and `tail_shard_all_gather`,
so a later PR adds them on top with no rework.

**No new kernel and no rebuild.** The only collective added is
`torch.distributed.all_gather_into_tensor` on the TP group.

**Off by default**, and gated three ways so an existing deployment is
bit-for-bit unaffected:

1. `SGLANG_K3_TAIL_SHARD = EnvBool(False)`.
2. A token floor, `SGLANG_K3_TAIL_SHARD_MIN_TOKENS = 4096` — below the
   crossover the all-gather's fixed cost exceeds the saving.
3. `num_tokens % world_size == 0` — a ragged batch has no row slice.

It is additionally skipped under `fused_norm`, where the fused AR+norm kernel
has already consumed the latent. The restructure is layer-local — every layer
still enters and leaves on the full batch — so the bank, the attention-side
aggregation, dspark capture and the PP wire are unaffected.

## Accuracy Tests

The all-reduce is untouched and the all-gather is unquantized bf16, so no value
passes through a codec the replicated path does not already use. RMSNorm and
both adds are strictly row-local, so they are exact by construction. **The only
step that can move a value is the up-projection GEMM, whose `M` drops from `T`
to `T/w`.**

### Where a difference comes from

That GEMM is the same arithmetic on a subset of rows. But bf16 accumulation is
order-sensitive, and the BLAS kernel selects its K-loop split from `M`, so the
last bit can round differently at one row count than at another. On a single
fixed tensor — every point a slice of the same data, so only the row count
varies — the disagreement appears in **eight disjoint bands of `T`, not a clean
threshold**. As a function of rows-per-rank:

```
M/rank   513-544  737-832  1153-1280  1345-1408  1537-1600  1633-1664  1825-1856  2081-2112
         differ   differ   differ     differ     differ     differ     differ     differ
```

Everywhere else in the gated range it is exact. **The two sizes this deployment
actually runs are outside all eight bands and are bit-exact.**

### Measured error

8x MI325X (gfx942), TP8, latent 3584, hidden 7168, bf16. Two independent runs.
Through the layer's own `ReplicatedLinear`:

| `T` | `M/rank` | differing | max ulp |
|--:|--:|--:|--:|
| **19456** (tuned chunk) | 2432 | **0 of 139,460,608** | 0.00 |
| **16384** (`max_prefill_tokens`) | 2048 | **0 of 117,440,512** | 0.00 |
| 8192 | 1024 | **0 of 58,720,256** | 0.00 |
| 4096 (the gate floor) | 512 | **0 of 29,360,128** | 0.00 |

Where it does differ, the error is bounded and tiny. At `T=6144`
(`M/rank=768`), over the differing elements:

| | |
|---|--:|
| differing elements | 1862 of 5,505,024 (0.0338%) |
| **max ulp distance** | **1.00** bf16 ulp (mean 0.57) |
| **RMS(diff) / RMS(ref)** | **4.43e-05** |

That is last-bit rounding — one ulp, on 0.03% of elements, a relative error ~89x
below bf16's own resolution (2^-8 = 3.9e-3). It is the same magnitude everywhere
the disagreement appears: across all 480 differing points, `max ulp` is 1.00 and
`RMS(diff)/RMS(ref)` spans only 4.23e-05 … 4.57e-05.

**So:** bit-exact at the sizes this deployment runs; at most one bf16 ulp from
GEMM accumulation order anywhere else in the gated range. The new test asserts
the reference-shape comparison rather than assuming it, so a kernel-selection
change that widens one of these bands shows up there.

`SGLANG_K3_TAIL_SHARD_MIN_TOKENS` is a **performance** gate, not a numeric one:
it sits at the measured crossover where the all-gather stops paying for itself.
Lowering it changes speed, not correctness.

## Speed Tests and Profiling

Per MoE layer, at the real shapes, through the layer's own `ReplicatedLinear`
(8x MI325X, gfx942; mean of 30 iterations after 8 warmup:

| `T` | replicated | row-parallel | delta | speedup |
|--:|--:|--:|--:|--:|
| **19456** (tuned chunk) | 2.3098 ms | **1.1814 ms** | **-1.1283 ms** | **1.96x** |
| **16384** (`max_prefill_tokens`) | 1.9217 ms | **0.9921 ms** | -0.9296 ms | 1.94x |
| 8192  | 1.0093 ms | **0.5443 ms** | -0.4649 ms | 1.85x |
| 4096 (the gate floor) | 0.5446 ms | **0.3174 ms** | -0.2271 ms | 1.72x |
| 128  | 0.0970 ms | 0.1157 ms | +0.0186 ms | **0.84x** |
| 64  | 0.0921 ms | 0.1614 ms | +0.0693 ms | **0.57x** |

Every row above is bit-exact through the layer.

Component breakdown at T=19456: latent norm 0.578 -> 0.099 ms, `up_proj` GEMM
1.934 -> 0.279 ms, bf16 all-gather of `[T, H]` costs 1.152 ms.

The token floor sits at the measured crossover; chunked prefill takes the path
and decode keeps the replicated one (the 0.57x and 0.84x decode rows are exactly
what the floor is preventing).

SGLANG_K3_TAIL_SHARD_MIN_TOKENS is not a workgroup-size knob, it is just where the change (less compute, more communication) starts to pay off.
