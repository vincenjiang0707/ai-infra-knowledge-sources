## Motivation

Deterministic inference with Triton GDN prefill can produce different logprobs when scheduling changes the intermediate chunk lengths. This is reproducible on main `1d59ce7c9063edec20fd3f5a49a504b8c12acd23` with the public `Qwen/Qwen3.5-35B-A3B` model, FA3 full attention, and FP32 recurrent state.

Setting the configured chunk budget to a multiple of 64 is insufficient: concurrent requests consume part of the budget. With a 1024-token budget, observed first chunks were 1017 tokens in normal admission and 889 tokens in the cache-disabled `ignore_eos` path. The subsequent chunks preserve this displaced boundary. Serial repeats were exact, but concurrent responses could differ from their serial reference.

The constraint belongs to the dispatched Triton GDN prefill implementation, whose FLA chunk size is 64. It does not require imposing 4096-token chunks on every FA3 model.

## Modifications

- Expose an optional deterministic prefill chunk alignment on attention backends. Hybrid wrappers propagate the prefill/linear backend's requirement. GDN advertises the FLA chunk size when its actual extend implementation is Triton, including the CuTe DSL fallback on Hopper.
- Combine this requirement with existing FlashInfer/Triton full-attention alignment using LCM. Apply it only in deterministic mode, leaving dLLM outside this new constraint.
- Align intermediate chunks in normal admission, cache-disabled `ignore_eos`, and continuation admission. Preserve complete short tails and page allocation constraints. If the remaining budget cannot fit a legal chunk, defer without charging tokens or announcing a successful prefill.
- Keep a deferred continuation out of another request's batch accounting. Preserve the single unfinished-chunk slot while allowing a complete short request to run.
- Reject enabled fixed chunk budgets below the smallest legal chunk. Clamp dynamic predictions to that minimum so the same prediction cannot indefinitely park a continuation; memory admission can still defer it.

Related context: #10645 / #10694 introduced the existing full-attention constraints; #13309 discussed GDN chunk sensitivity; #35632 restricts deterministic GDN prefill to Triton. This change addresses scheduler chunk lengths, not the separate radix-prefix FA3 layout proposals in #25479 / #25481.

### Warm prefix cache

With `extra_buffer`, each serial request and each concurrent round was preceded by a cache flush and a 4097-token seed request. Normal admission was tested at budgets `-1` and `1000`; logprob scoring started after the seed prefix. On the candidate, all 24 measured requests had `cached_tokens=4096` and an observed prefill start of 4096. All signatures matched main's unchunked warm reference exactly. At budget 1000, the 6151-token request used 960-token continuation chunks; one concurrent schedule began with 832 tokens, followed by 960, and still matched.

Main's unchunked warm case also matched throughout. Its 1000-budget case differed, but its actual cache hits changed from 960 in serial execution to several different lengths under concurrency. Those main results therefore do **not** isolate continuation splitting from changes in the cached prefix state. The candidate's fixed-prefix result is the controlled warm comparison; it does not establish equivalence for arbitrary cold/warm transitions.

### Kernel scope and limitations

A direct FLA test compared single splits and periodic splits at 1000 / 1024 / 1088 / 4096, lengths 4127 / 4224, and three seeds. With FP32 recurrent state, all 36 aligned cases matched the unsplit output and final state exactly; all 12 unaligned cases differed. Unsplit repeat controls were exact. With BF16 recurrent state, aligned splits still did not consistently match: this scheduler change is not a complete determinism guarantee for reduced-precision recurrent state and adds no dtype restriction.

The service evidence covers these inputs and configurations. It is not an exhaustive numerical proof or a claim that changing the cached prefix state is equivalent to starting cold.

```python
"""Save cold-cache serial/concurrent signatures from a running SGLang server."""

import argparse
from concurrent.futures import ThreadPoolExecutor
import json
from pathlib import Path
from threading import Barrier

import requests
from transformers import AutoTokenizer

parser = argparse.ArgumentParser(description=__doc__)
parser.add_argument("--model", default="Qwen/Qwen3.5-35B-A3B")
parser.add_argument("--url", default="http://127.0.0.1:30000")
parser.add_argument("--output", type=Path, required=True)
args = parser.parse_args()
tokenizer = AutoTokenizer.from_pretrained(args.model)
lengths = [4127, 4224, 6151]
pattern = tokenizer.encode(
    "Record 17: the blue box contains 23 pencils. Record 18: the green box contains 31 pencils.\n",
    add_special_tokens=False,
)
full = (pattern * (max(lengths) // len(pattern) + 1))[: max(lengths)]
inputs = {
    length: full[:4097]
    + tokenizer.encode(str(i + 1), add_special_tokens=False)[:1]
    + full[4098:length]
    for i, length in enumerate(lengths)
}
keys = (
    "input_token_logprobs", "output_token_logprobs",
    "input_top_logprobs", "output_top_logprobs",
)


def generate(length, ignore_eos, barrier=None):
    if barrier is not None:
        barrier.wait(timeout=30)
    response = requests.post(
        args.url + "/generate",
        json=dict(
            input_ids=inputs[length],
            sampling_params=dict(temperature=0, max_new_tokens=8, ignore_eos=ignore_eos),
            return_logprob=True, logprob_start_len=length - 128, top_logprobs_num=5,
        ),
        timeout=600,
    )
    response.raise_for_status()
    data = response.json()
    assert data["meta_info"].get("cached_tokens", 0) == 0
    return dict(text=data["text"], **{key: data["meta_info"][key] for key in keys})


results = {}
for ignore_eos in (False, True):
    for execution in ("serial", "concurrent"):
        for repeat in range(2):
            if execution == "serial":
                values = [generate(length, ignore_eos) for length in lengths]
            else:
                barrier = Barrier(len(lengths))
                with ThreadPoolExecutor(max_workers=len(lengths)) as pool:
                    futures = [pool.submit(generate, length, ignore_eos, barrier) for length in lengths]
                    values = [future.result() for future in futures]
            for length, value in zip(lengths, values):
                results[f"{ignore_eos}/{execution}/{repeat}/{length}"] = value
args.output.write_text(json.dumps(results, indent=2) + "\n")
```
