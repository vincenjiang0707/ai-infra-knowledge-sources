### Describe the bug

`marlin` is accepted as a value for `--quantization` (it is listed in `QUANTIZATION_CHOICES`), but it is not a direct key in `QUANTIZATION_METHODS`.

Argument parsing therefore accepts the value, while direct quantization-config resolution later rejects it. The value currently appears to be interpreted only through checkpoint-specific `override_quantization_method` paths (e.g. in `marlin_utils.py`, `gptq/gptq.py`, `awq/awq.py`), so it does not resolve on its own.

This makes the public CLI and the quantization registry inconsistent: a value the CLI advertises as valid cannot be resolved unless the checkpoint metadata happens to select it.

### Reproduction

Reproduced against `upstream/main` at:

```text
a2ddf92e616c6b47f8a166aece71d3c0bc5976af
```

```python
from sglang.srt.layers.quantization import (
    QUANTIZATION_METHODS,
    get_quantization_config,
)
from sglang.srt.server_args import QUANTIZATION_CHOICES

print("marlin in QUANTIZATION_CHOICES:", "marlin" in QUANTIZATION_CHOICES)
print("marlin in QUANTIZATION_METHODS:", "marlin" in QUANTIZATION_METHODS)

get_quantization_config("marlin")
```

Actual output:

```text
marlin in QUANTIZATION_CHOICES: True
marlin in QUANTIZATION_METHODS: False
exception type: ValueError
exception message: Invalid quantization method: marlin. Available methods: ['fp8', 'mxfp8', 'blockwise_int8', 'modelopt', 'modelopt_fp8', 'modelopt_fp4', 'nvfp4_online', 'modelopt_mixed', 'w8a8_int8', 'w8a8_fp8', 'awq', 'awq_marlin', 'bitsandbytes', 'gguf', 'gptq', 'gptq_marlin', 'moe_wna16', 'compressed-tensors', 'w4afp8', 'petit_nvfp4', 'quark', 'quark_mxfp4', 'auto-round', 'auto-round-int8', 'modelslim', 'quark_int4fp8_moe', 'humming', 'mxfp_w4a8', 'mxfp4']
```

The advertised "Available methods" list does not contain `marlin`.

### Expected behavior

A value accepted by `--quantization` should resolve deterministically. Either:

- `marlin` should resolve to a supported registered configuration, or
- it should not be exposed as a direct CLI choice when it is only intended for checkpoint-conditional detection.
