## 正文

## Motivation

`VocabParallelEmbedding.weight_loader_v2` picks the packing factor with a branch whose two arms are identical:

```python
# python/sglang/srt/layers/vocab_parallel_embedding.py:487
packed_factor = (
    param.packed_factor
    if isinstance(param, BasevLLMParameter)
    else param.packed_factor          # <- same expression on both sides
)
assert loaded_weight.shape[output_dim] == (
    self.org_vocab_size // param.packed_factor
)
start_idx = start_idx // packed_factor
shard_size = shard_size // packed_factor
```

The `isinstance` check exists because the two parameter families spell the attribute differently:

| parameter family | attribute | where |
|---|---|---|
| `BasevLLMParameter` | `packed_factor` | `layers/parameter.py:468` |
| legacy packed params | `pack_factor` | `layers/linear.py:659`, `:692`, `:1280`, `:1337` |

The [upstream vLLM version of this function](https://github.com/vllm-project/vllm/blob/main/vllm/model_executor/layers/vocab_parallel_embedding.py) has `else param.pack_factor`. This copy lost it in #3790, which ported the function over for GPTQ `lm_head` quantization.

The branch is entered through the legacy attribute:

```python
packed_dim = getattr(param, "packed_dim", None)
if packed_dim is not None and packed_dim == output_dim:
```

`packed_dim` / `pack_factor` are exactly the pair that `ColumnParallelLinear.weight_loader` uses for legacy packed parameters, so a legacy packed parameter does reach this branch, and then hits:

```
AttributeError: 'Parameter' object has no attribute 'packed_factor'
```

while loading a quantized embedding or `lm_head`.

The `assert` on the next line has the same defect from the other direction: it reads `param.packed_factor` instead of the `packed_factor` that was just computed, so it would raise for the same parameters even after the first line is corrected.

I do not have a GPTQ/AWQ `lm_head` checkpoint on hand to post a traceback from a real run, so I am reporting this as a read-and-compare finding against the upstream function and the sibling loaders, not as a reproduced crash.

## Modifications

Two lines:

- `else param.packed_factor` -> `else param.pack_factor`, matching upstream and the other loaders.
- the assert divides by the local `packed_factor` instead of `param.packed_factor`.

`BasevLLMParameter` behavior is unchanged: for those parameters the ternary already returned `param.packed_factor` and still does.

## Accuracy Tests

No numerics change for any parameter that loads successfully today. The change only affects legacy packed parameters, which currently raise `AttributeError` on this path.

## Speed Tests and Profiling

Not applicable, weight loading only.

### haosenwang1018 · 2026-09-23

Adding the concrete configuration this breaks, which I should have led with.

**Who hits it:** a checkpoint whose `lm_head` / embedding is packed-quantized and whose parameter goes through the *legacy* packed-parameter path rather than `BasevLLMParameter` — i.e. GPTQ / AWQ style weights where the loader reads `param.packed_dim` and `param.pack_factor`. `VocabParallelEmbedding.weight_loader_v2` enters the branch on the legacy attribute:

```python
packed_dim = getattr(param, "packed_dim", None)
if packed_dim is not None and packed_dim == output_dim:
```

and then reads `param.packed_factor`, which those parameters do not have. Every other loader in the tree pairs `packed_dim` with `pack_factor` (`layers/linear.py:659, :692, :1280, :1337`).

**What the failure looks like:** `AttributeError: 'Parameter' object has no attribute 'packed_factor'` during weight loading, before the server comes up.

I do not have a GPTQ `lm_head` checkpoint to post a real traceback from, so I am not claiming a reproduced crash — the evidence here is that the two arms of the conditional are identical, that the upstream vLLM copy of the same function reads `param.pack_factor` in the else arm, and that the attribute name is consistent across the other loaders. If a maintainer with such a checkpoint can confirm, I will add the traceback.
