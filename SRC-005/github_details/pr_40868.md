# [PR #40868] [Fix] Stop deferring the last layer's FFN all-reduce in five models

state: open | updated: 2026-09-23T07:28:41Z

## 正文

> Based on `cheng/refactor/nemotron-dp-attn-communicator` (which includes #40799 → #40800 → #40801). Review only the top commit.

## Motivation

With FlashInfer all-reduce fusion enabled, `LayerCommunicator` leaves a layer's FFN all-reduce to be fused into the next layer's residual add + RMSNorm, unless the layer is marked as the model's last one (`is_last_layer`). Five decoder layers were not marked, so their last layer handed its reduction to a layer that does not exist, and the final norm ran on TP-partial sums.

Qwen3-Next is on the list of architectures that auto-enable this fusion (SM90 / SM100, TP > 1, no DP attention), so its default configuration is affected. Outputs stay fluent, which hides the problem; the error only shows up numerically (see Accuracy Tests).

## Modifications

- `qwen3_next.py`: both decoder layer types pass `is_last_layer`. The MTP draft model builds a single layer with `num_hidden_layers = 1`, so it is covered by the same expression.
- `minimax_m3.py`: passes `is_last_layer`.
- `bailing_moe_linear.py`: passes `is_last_layer=(is_nextn or layer_id == num_hidden_layers - 1)`, which also covers the hybrid NextN draft layer (built with `layer_id=0`).
- `bailing_moe.py` / `bailing_moe_nextn.py` and `step3p5.py` / `step3p5_mtp.py`: the draft layers are built with `layer_id` 0 and `num_hidden_layers` respectively, so the existing `layer_id == num_hidden_layers - 1` check marked them as not last. Both decoder layers now take `is_nextn`, as the DeepSeek, GLM and Dots3 layers already do, and their NextN / MTP models pass it.
- New `test/registered/unit/models/test_last_layer_communicator.py`: builds each affected decoder layer class through its real `__init__` (submodules stubbed) and checks the `is_last_layer` handed to `LayerCommunicator`, for every layer id and for the draft layer. On current main, exactly the 9 affected cases fail (last layer of Qwen3-Next ×2, Bailing-MoE-linear, MiniMax-M3; draft layer of Qwen3-Next ×2, Bailing-MoE-linear, Bailing-MoE, Step-3.5); all 29 pass with this change.

`is_last_layer` also keeps the last layer from reduce-scattering in input-scattered mode, so that path is corrected for these models as well.

## Accuracy Tests

Qwen3-Next-80B-A3B-Instruct-FP8, TP2 on H200, default fusion (auto-enabled). Four greedy prompts, 32 new tokens, top-5 logprobs, requests submitted one at a time. Reference: the same model at TP1. `SGLANG_ENABLE_JIT_DEEPGEMM=0` for every arm, because DeepGEMM's FP8 GEMM hits an unrelated CUDA-graph-capture assert in this environment on both main and this branch.

| TP2 configuration | First token diverging from TP1 (4 prompts) | Step-0 max \|Δlogp\| over top-5 | Decode steps with \|Δlogp\| < 0.05 before divergence |
|---|---|---|---|
| Fusion disabled (`--enforce-disable-flashinfer-allreduce-fusion`) | 32 / 11 / 32 / 32 | 0.24 / 0.43 / 0.24 / 0.65 | 94 / 103 |
| Fusion on, main | 26 / 5 / 17 / 32 | 0.42 / 0.93 / **2.20** / 1.19 | 62 / 76 |
| Fusion on, this PR | 32 / 11 / 32 / 32 | 0.24 / 0.18 / 0.23 / 0.89 | 94 / 103 |

Step 0 depends on prefill only. With this change, fusion-on accuracy matches fusion-off. A per-rank decision log shows the last layer now decides not to fuse, which it never did on main.

The other four models are not on the fusion auto-enable list, so their default outputs are unchanged; the fix matters only when fusion is enabled explicitly.

## Speed Tests and Profiling

No kernel change. The last layer now completes the all-reduce it used to drop.
