## Motivation

Piecewise CUDA Graph (PCG) was disabled on NPU, so NPU prefill could not use the
torch.compile-driven piecewise capture/replay path. Enabling it also requires the NPU
MoE, fused QKV/RMSNorm/RoPE, elementwise, and FLA layernorm-gated helpers to be visible
to Dynamo as traceable custom ops instead of unsupported Python or external-kernel code.

This PR enables NPU PCG behind the opt-in
`SGLANG_NPU_ENABLE_PIECEWISE_CUDA_GRAPH=1` environment variable and adds the
torch.compile compatibility needed by Qwen3/Qwen3-MoE/Qwen3.5 prefill.

## Modifications

Three commits:

**1. `[NPU] Make MoE helper ops torch.compile friendly.`**
- Register NPU weight-prefetch and CMO/shared-stream synchronization helpers as custom
  ops, separating list and single-tensor cache paths.
- Run the shared expert serially while compiling, avoiding Dynamo tracing of NPU stream
  management.
- Wrap the NPU MoE `l1_norm` helper as a custom op.
- Use a torch implementation of `fused_sigmoid_mul` during NPU compilation.
- Register the NPU fused split-QKV/RMSNorm/RoPE kernel, including its fake implementation,
  as a custom op for Qwen3 and Qwen3-MoE.
- Pass tensors through the registered stream-wait ops in Qwen2-MoE and Qwen3.

**2. `[NPU] Wrap FLA layernorm-gated op for torch.compile.`**
- Register the NPU `layer_norm_fwd` path as a custom op and declare `out` as the
  mutated argument.
- Preserve the existing `(y, mean, rstd)` return contract; the unused NPU mean/rstd
  values remain `None`.

**3. `[PCG] Enable NPU piecewise CUDA graph support.`**
- Add the `SGLANG_NPU_ENABLE_PIECEWISE_CUDA_GRAPH` opt-in and allow PCG on NPU only
  when it is enabled.
- During torch.compile warmup, execute the compiled general-shape graph directly; also
  use that path for pieces without symbolic shape inputs.
- Capture NPU graphs on the PCG capture stream with `auto_dispatch_capture=True`.
- Skip Qwen3.5 expert-distribution-recorder layer contexts only for TC-piecewise
  prefill.
- Add a registered NPU TP=2 PCG serving test for `Qwen/Qwen3.5-35B-A3B`. The test
  runs 128 requests with 4096 input tokens, concurrency 32, chunk size 2048, and
  requires all requests to complete with input throughput above 8500 tok/s.

## Accuracy Tests

The change adds the registered NPU test
`test_npu_piecewise_graph_prefill_tp2.py` for the PCG serving path. It checks request
completion, concurrency, and a minimum input-throughput threshold on
Qwen3.5-35B-A3B (NPU, TP=2, Ascend attention backend).

No model-quality/accuracy benchmark is included in `result_0803.md`; the file contains
serving performance results only.

## Speed Tests and Profiling

Prefill-heavy serving benchmark on Qwen3.5-35B-A3B, NPU, TP=2, Ascend attention
backend.

- Backend: sglang
- Requests: 200
- Warmup requests: 20
- Max request concurrency: 32
- Chunked prefill size: 2048
- Output length: 1 token per request
- Traffic request rate: inf

## Code Review

This pull request enables and optimizes piecewise CUDA graph execution on NPU hardware, registers several custom operations to support torch.compile, and adds NPU-specific compilation paths and Mamba state resets. The review feedback highlights critical issues to address: establishing data dependencies for stream synchronization custom ops (wait_cmo_stream and wait_share_stream) to prevent torch.compile from reordering them, fixing missing imports (Backend and is_npu) that would cause runtime NameErrors, recursively marking nested tensors dynamic in compile.py, and adding element-count checks before reshaping the gate tensor in fused_sigmoid_mul to avoid potential runtime crashes.
