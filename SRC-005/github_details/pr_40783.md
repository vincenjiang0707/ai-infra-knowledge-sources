# [PR #40783] [HiSparse] Plan ROCm misses and reuse KV copy plans

## 正文

On qualified ROCm gfx95 AITER paths, record cache misses first and perform the real KV transfer with a copy-only kernel. Use sixteen copy blocks for that transfer. When shared-index prefetch is disabled, follower layers reuse the anchor miss plan and copy synchronously on the current stream. Prefetched copies retain their existing stream and event ordering; unsupported configurations keep the fused swap-in path.

The planned-copy path rejects the debug skip-I/O setting because it requires real KV transfer. Focused protocol tests cover capability gates, fallback behavior, plan/copy ordering, the copy grid, shared-index reuse, and the prefetch kill switch.

## C1 steady-state decode

Measured on GLM-5.2 FP8 with BF16 KV, TP4 MI355X, a 32,768-token input and 256-token output, using 64 warmup tokens and the next 192 decode intervals. Measured source commit: `38876dd01b81`. Runtime: stock SGLang v0.5.20 on ROCm 7.2.4. Parent: `87c1754`. Lower is faster.

| Prefetch | Parent median (ms/token) | This PR median (ms/token) | Latency reduction |
|---|---:|---:|---:|
| Off | 19.918 | 17.249 | +13.40% |
| On | 18.201 | 17.751 | +2.48% |

One trial per source and prefetch mode was run on the same TP4 allocation. These results are descriptive, not independent restart replications.
