## 正文

## Motivation

Support semantic decisions with candidate tokens through the existing scoring API. Keep the infrastructure model-agnostic, with SemIf as the first example.

## Modifications

- Accept per-item candidate token IDs in `/v1/score` and Engine scoring, including the packed MIS path.
- Add temperature scaling and optional unscaled, full-vocabulary token logprobs in candidate order.
- Add a SemIf direct-scoring client and cookbook covering setup, JSONL inputs, HTTP usage, calibration, and limitations. Reuse its official prompt encoder and preserve prompt hashes and option IDs.

Single-token candidates only. Scheduler and cache behavior are unchanged; explicit shared-prefix prefill/fan-out is out of scope.

## Accuracy Tests

Added coverage for per-item candidates, temperature scaling, logprob output, input validation, and HTTP/Engine scoring, including MIS.

## Speed Tests and Profiling

No performance claims. This PR extends the scoring interface, not model execution.
