# [PR #40859] [HiCache] Unify the linker mode entry under --hicache-host-memory-mode

## 正文

## Motivation

HiCache has two host-memory modes (`cache`, `buffer_only`), while the direct external linker (Mooncake / MORI direct L3) is a separate feature behind `--enable-unified-cache-external-linker` + `--unified-cache-external-linker-backend`, mutually exclusive with `--enable-hierarchical-cache`. This PR unifies the entry so HiCache has exactly three modes selected on one axis:

| mode | host tier | storage |
|---|---|---|
| `cache` | persistent host pool | optional `--hicache-storage-backend` |
| `buffer_only` | transient staging | required `--hicache-storage-backend` |
| `linker` | none, device pools link directly to storage | required `--hicache-storage-backend {mooncake,mori}` |

```bash
# before
--enable-unified-cache-external-linker --unified-cache-external-linker-backend mori
# after
--enable-hierarchical-cache --hicache-host-memory-mode linker --hicache-storage-backend mori
```

**Breaking change:** `--enable-unified-cache-external-linker` and `--unified-cache-external-linker-backend` are removed with no alias. `--hicache-storage-backend-extra-config` and `--enable-linker-mla-dedup` keep working as before (both linkers already read the extra config through the HiCache field).

## Modifications

- `arg_groups/fields/memory.py`: `linker` added to `--hicache-host-memory-mode`; the two linker flags removed (`field_order.py` follows).
- `arg_groups/hicache_mode.py` (new): `hicache_uses_linker(cfg)` / `hicache_has_host_tier(cfg)`, usable on both a resolving view and the published `memory` bag. It is a separate module because `overrides.py` and `hicache_hook.py` would otherwise import each other.
- `arg_groups/hicache_hook.py`: linker mode validates the backend (`mooncake`/`mori`) and skips the host-tier normalization (layout/io/DCP), which keeps today's linker behavior; `--enable-linker-mla-dedup` now requires linker mode with Mooncake.
- `enable_hierarchical_cache` is now true in linker mode, so every reader was classified:
  - any mode (unchanged or simplified): scheduler HiCache event drain / admission `batch_is_full` / `ready_to_load_host_cache`, DSA `index_k` retention, spec draft plan, `--disable-radix-cache` exclusivity, int8 Mamba / MiniCPM / beam-search rejections.
  - host tier only (switched to `hicache_has_host_tier`): `kv_cache_builder` staging + auto-sizing + draft sidecars + backup-only ratio, `registry.init_hicache`, scheduler `enable_hicache_storage` / decode HiCache / attach-detach-clear / `is_fully_idle` / host-pool metrics, piecewise CUDA graph gate, optimistic-prefill gate, Step3p5 SWA override, SM100 NVFP4 gate, Mooncake TE reuse.
- `mem_cache/registry.py`: the linker branch is selected by `hicache_uses_linker` before the host-tier branch, backend from `hicache_storage_backend`.
- Scheduler exposes `enable_hicache_host_tier`; unit fixtures that build a bare `Scheduler` set it where the tested path reads it.
- Existing tests moved to the new flags (unit + the two linker KL e2e tests). Docs: DeepSeek-V4 cookbook UMBP section and the Playground UMBP/HiCache axes emit and detect the linker recipe.

## Accuracy Tests

No model forward change. Verified:

- Unit suites `test/registered/unit/{managers,disaggregation,server_args,mem_cache}`: identical pass/fail set to `main` on the same machine (the remaining failures need the Rust workspace or the `parameterized` package and fail identically on `main`).
- Config resolution: linker+mooncake / linker+mori accepted; linker without backend, linker+`file`, `--enable-linker-mla-dedup` in cache mode rejected with clear messages; the old flag is an argparse error; cache and buffer_only recipes unchanged.
- E2E Mooncake direct linker via the new flags on a 5-layer DeepSeek-V3.2 checkpoint (single GPU): cold prompt 0 cached tokens, `/flush_cache`, replay hits 1984/2040 tokens with `Mooncake direct linker offload` / `lookup hit` in the log; server healthy throughout.
- Not run here: `test_unified_cache_linker_kl_dsv4.py` / `test_unified_cache_linker_kl_glm52.py` (multi-GPU), MORI backend, Playground JS.
