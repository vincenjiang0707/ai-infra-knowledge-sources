## Motivation

Two halves of one proposal: a host page layout whose axis order makes an L3 chunk a single byte run, and a key scheme that names those chunks without naming who wrote them. Library only -- no server arg and no transfer arm yet, so nothing here is reachable from the CLI; the integration PR adds both at once rather than shipping a flag that does nothing.

The layout, page_unified:

```
  MHA: (page, head_group, layer, 2, page_size, head_in_group, dim)   K=0, V=1
  MLA: (page, layer, page_size, dim)
```

matching the write-back kernel in #39606 and the load-back kernel this stack already landed, so a page is byte-identical whether it arrived from the device or from L3.

A PARTITION AXIS MUST BE OUTER. The grid cuts a page along the kv-head axis and then along the layer axis, so both sit outside page_size and a chunk becomes an offset and a length. The K/V axis sits INSIDE the layer axis rather than outside the pool, which is what lets one object carry both components: hoisting it out -- as layer_first and page_first_direct do -- makes a chunk two objects whose runs interleave at token granularity. The result is that every chunk is exactly one run, a ragged final layer window included, so the transport never has to switch descriptor forms mid-plan.

The key scheme replaces the rank suffixes (_{tp_rank}_{tp_size}, _{pp_size}_{pp_rank}, _cp{r}_{s}) with

```
  {page_hash}_{digest}_L{start}-{end}[_H{head_group}]
```

The coordinate names what an object holds -- a layer-range x head-range rectangle of one page, K and V together -- so a TP2 rank's objects are exactly the union of two TP4 ranks', and a PP1 rank's the union of the stages'. Both union properties are tested, because nothing else in the stack checks them and the failure mode is a silent 0% hit rate rather than an error.

head_group and layer_partition are fleet-wide agreements, not local tuning: they fix chunk boundaries, and the boundaries are namespace identity. Unset, each falls back to this rank's own shard and shares only with its own topology; the head case logs a warning, since the symptom is again a silent miss.

head_group_num is a constructor argument on MHATokenToKVPoolHost because it sizes the buffer. Under page_unified, k_buffer and v_buffer raise: the components are interleaved inside a page block, so kv_buffer[0] is a page there, not the K half-pool.

Tested: 23 CPU unit cases. The layout side pins that the declared strides equal the allocated tensor's, that chunks tile a page exactly once with no gap or overlap, that a 61-layer/30-partition tail is still one run, and that the head-group count permutes a page without resizing it. The key side pins the two union properties, that every identity field reaches the digest (a field that does not would let different bytes collide on one key), and each rejection. Separately smoke-tested on B200 that the pools allocate the declared shapes for head_group_num in {1, 2, 8} and for MLA.
