## What this changes

Names `docs/cookbook/` as the entry point for "how should this model be served", and says what the configs under `test/` are instead.

- **`.claude/rules/cookbook-first.md`** (new) — repo-wide. The cookbook is not diffusion-only: `autoregressive` carries ~100 pages to diffusion's ~26. Rules load for every session, so this reaches LLM work too. It also states the reverse obligation: a change that alters a model's recommended deployment updates that page in the same PR.
- **`multimodal_gen/.claude/CLAUDE.md`** — same pointer, with the diffusion family list, since that file never mentioned the cookbook at all.
- **`sglang-diffusion-performance/SKILL.md`** — tuning should start from the deployment we recommend rather than from scratch. The MOVA / Helios / LingBot World row no longer says to use "the benchmark/profile presets or **server test cases first**", and now carries the documented GPU counts inline.

## Why — with the evidence, including what it does *not* show

The motivating incident: measuring LingBot-World realtime throughput, I took the configuration from `test/server/gpu_cases.py` (single GPU, `--text-encoder-cpu-offload true`) because I wanted a pinned reproducible setup. `docs/cookbook/diffusion/LingBot-World/LingBot-World.mdx` pins `--num-gpus 4 --ulysses-degree 4` with different offload flags. Single GPU cannot keep up with realtime playback at all, so the numbers characterised a deployment nobody runs, and the analysis built on them was wrong until it got redone at the documented GPU count.

I then checked whether this generalises, by giving a fresh agent only a user's question — "I want to run Wan2.2 T2V on my 4-GPU H200 box, what command should I run? Also MiniMax-H3" — with no hint about docs layout. **It found the cookbook in 7 tool calls and answered from it correctly.** So this PR is *not* fixing "agents cannot find the cookbook" for deployment questions; that path already works.

The gap it does fix is narrower: **measurement, benchmarking and tuning tasks anchor on `test/` configs**, which are pinned for CI reproducibility rather than chosen as good deployments — and results then get reported as if they described the recommended setup. The performance skill actively pointed that way for the realtime families. Hence the framing here: cookbook is the baseline, `test/` is for exact reproducibility, and say which cookbook flags you diverged from.

No runtime code, no behavior change. Family and section names checked against `docs/cookbook/`.
