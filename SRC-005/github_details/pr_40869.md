## Motivation

`LayerCommunicator` picks the collective for each boundary (gather, scatter, all-reduce or nothing) from three tables keyed by the source and target `ScatterMode`. Whether a transition is the identity was decided by comparing process-group sizes. A group size is only the product of axis sizes, so two different token layouts can have the same size, and the tables hide the mapping from modes to functions inside chains of conditions.

## Modifications

- New `python/sglang/srt/layers/boundary_layout.py`: `TokenAxis` (`ATTN_DP`, `ATTN_CP`, `ATTN_TP_SCATTER`) and `Layout`, the set of token axes a rank's rows are sharded over.
- `communicator.py`: `scatter_mode_layouts(...)` derives each `ScatterMode`'s layout from the attention DP / CP / TP sizes. `CommunicateContext.layouts` is computed from the context's own size fields (its constructor is unchanged), and `is_same_layout` compares two modes' layouts. The base communicator's three `get_fn` tables use it for the identity check, and the mode-to-function mappings are written as explicit tables.
- The DSA context-parallel communicator, whose `SCATTERED` mode shards tokens over CP, keeps its size-based checks (`process_group_sizes` / `is_same_group_size` stay).
- New `test/registered/unit/layers/test_communicator_layout.py` (builds contexts from `scatter_mode_layouts` directly, without process-wide parallel state).

## Accuracy Tests

Selection happens at construction time; the runtime path is unchanged. An exhaustive comparison against main covers 27 topologies (attention DP / CP / TP ∈ {1, 2, 4}) × `SGLANG_USE_AG_AFTER_QLORA` on / off and every mode pair of the three tables: 18,144 selections, 0 differences. `test/registered/unit/layers` + `unit/models`: every existing case keeps its status; the 6 new cases pass.

N/A: the selection runs once per layer at construction.
