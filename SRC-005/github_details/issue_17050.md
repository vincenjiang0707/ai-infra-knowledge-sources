## LoRA Overlap Loading Test Investigation Update

Investigation of the `test_lora_overlap_loading.py` failure revealed two separate issues:

### 1. Adapter Contamination (Attempt at #18133)
- **Root cause**: HFRunner was calling `PeftModel.from_pretrained()` multiple times on the same base model, causing adapter contamination
- **Symptom**: Warning "Already found a `peft_config` attribute in the model"
- **Fix**: Track `self.peft_model` instance and use `load_adapter()`/`set_adapter()` for subsequent adapters

### 2. SRT vs HF Output Differences (Separate Issue)
- **Finding**: Even with pristine base model (no LoRA adapters), SRT and HF produce different outputs for the same prompt
- **Example**:
  - SRT: "building smart machines capable of performing tasks..."
  - HF: "the creation of intelligent machines that work and react like humans..."
- **Impact**: `test_ci_lora_models_multi_batch` fails with ROUGE-L tolerance of 1.0 (exact match)
- **Status**: This is a known flakiness issue (see #17683, #18047)

The fix in #18133 addresses the adapter contamination issue. The SRT vs HF output difference is a separate issue that may require adjusting test tolerances or investigating model implementation differences.

### Incomplete summaries can incorrectly mark tests as passed

[Relevant code: lines 502–513](https://github.com/sgl-project/sglang/blob/978cc228caabaaaab19fa5ca88f50d6170cb4326/scripts/ci_monitor/ci_failures_analysis.py#L502-L513)

When the test summary is **incomplete**, a previously failing test is still marked as passed if its `test_file` is absent from `failed_test_files` (line 503), despite the lack of a confirmed passing result:

I propose recording its outcome as **`None` (unknown)** and preserving its failure streak. Replace **lines 502–513** with:

```python
for test_file in test_failures.keys():
    if test_file not in failed_test_files:
        if not is_incomplete:  # Reset the streak only when the summary is complete.
            test_failures[test_file]["current_streak"] = 0
        test_failures[test_file]["recent_runs"].append(
            {
                "run_number": run_info.get("run_number"),
                "job_url": run_info.get("job_url"),
                "status": "\u26aa" if is_incomplete else "\u2705",
                "failed": None if is_incomplete else False,  # Record unknown when the summary is incomplete.
            }
        )
```

### Adjust the existing failure check to handle unknown outcomes

[Relevant code: lines 566–576](https://github.com/sgl-project/sglang/blob/978cc228caabaaaab19fa5ca88f50d6170cb4326/scripts/ci_monitor/ci_failures_analysis.py#L566-L576)

After recording incomplete outcomes as None, the existing failure check should skip these unknown entries before selecting the checking window. The original run history remains unchanged. Replace lines 566–576 with:

```python
            if current_streak > 0:
                known_runs = []

                for run in recent_runs:
                    # Keep failed (True) and passed (False) outcomes.
                    # Skip unknown outcomes (None).
                    if run.get("failed") is not None:
                        known_runs.append(run)

                # Select the last N known outcomes, where N = current_streak.
                # Check if any of them are actual failures (not just cancelled/skipped)
                streak_runs = known_runs[-current_streak:]

                has_actual_failure = any(
                    run.get("failed") is True for run in streak_runs
                )

                # Exclude the test if no actual failure is found.
                if not has_actual_failure:
                    continue
```

This preserves the original history and **does not count unknown outcomes as failures**.
