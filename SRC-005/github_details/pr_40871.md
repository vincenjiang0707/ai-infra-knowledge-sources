## 正文

## Motivation

Follow-up to #40870: eleven more MoE decoder layers repeat the same FFN-exit sequence that `LayerCommunicator.ffn_exit` now owns.

## Modifications

Bailing (MoE, MoE-linear, V3), GLM4-MoE-Lite, GPT-OSS, Laguna, MiMo-V2, MiniMax-M2, Qwen3-Next, Sarvam-MoE and SDAR-MoE wrap their FFN call in `ffn_exit` and finish with `ffn_exit.finish`, instead of calling the two decision methods, publishing the flags and marking or postprocessing the output themselves. The now-unused `get_forward` imports and the comments that described the removed calls are dropped.

- Sarvam-MoE's dense layers keep their manual all-reduce between the FFN and the exit; it reads the decision from `ffn_exit`.
- Qwen3-Next used to ask for reduce-scatter before fusion. Both are side-effect-free reads and `should_use_reduce_scatter` does not read the token count, so `ffn_exit`'s order changes neither result nor the fusion check's short-circuit order under torch.compile.

No behavior change.

## Accuracy Tests

Parent vs this PR on H200, four greedy prompts submitted one at a time, 32 new tokens, bit-exact comparison of text / token ids / every logprob / top-5, with a per-rank decision log:

| Configuration | Result | Decisions exercised |
|---|---|---|
| Ling-3.0-tiny (Bailing-V3) TP2 | identical | fuse true and false |
| GLM-4.7-Flash TP2 | identical | fuse true and false |
| GLM-4.7-Flash TP2, DP attention 2 | identical | reduce-scatter in decode and extend |
| gpt-oss-20b TP2 | identical | fuse true and false |
| MiniMax-M2.5 (FP8) TP4 | identical | fuse true and false |
| Qwen3-Next-80B-A3B-Instruct-FP8 TP2 (`SGLANG_ENABLE_JIT_DEEPGEMM=0`) | identical | fuse true and false |

A CPU dispatch comparison runs the real decoder forward of all 12 decoder classes with stubbed submodules, communicator methods and collectives over fuse × reduce-scatter (60 cases): identical except Qwen3-Next's decision call order, and identical after swapping those two calls. `unit/layers` + `unit/models`: every existing case keeps its status.

## Speed Tests and Profiling

Same per-layer eager overhead as #40870 (about +0.4 µs); CUDA graph replay does not run this code.
