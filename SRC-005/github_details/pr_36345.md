## Motivation

`--hicache-host-memory-mode buffer_only` was fenced to FULL and FULL+SWA trees:

```
--hicache-host-memory-mode buffer_only supports only FULL/SWA unified trees
```

Buffer mode publishes a fetched span with a plain insert at prefill admission,
and a hybrid model's tail node cannot be published without the recurrent state
that ends it — so the mode was unavailable on Mamba/GDN models, which are
exactly the ones that benefit most from L3: their state is one small slot per
checkpoint, and their prefixes are expensive to recompute.

This lifts the fence and adds the state handoff the read path was missing.
Part of the coverage roadmap in #34899.

## Design

The write path was already generic — `build_backup_spec` collects each
component's transfers and `finish_backup_ack` keys every aux pool by the
trailing KV page hashes it covers. Mamba needed the gating around it, and a read
path.

**Write path**
- `_build_aux_staging_transfers` reports the state (one key: the node's last KV
  page hash) so the per-pool oversize and staging-headroom gates size it.
- `_aux_loads_margin` becomes per-pool. It used to reserve
  `swa_window_pages * page_size` for *every* aux pool; applied to the Mamba pool
  that reads as "one SWA window of Mamba slots", which is not a quantity that
  means anything. SWA now reserves a trailing window, Mamba a single slot.

**Read path** — `_prepare_mamba_handoff` binds one staged host bounce to the two
device destinations it has to reach:

- the tree node's slot, auto-allocated by `cc.load`, which becomes the published
  node's `mamba_value`;
- the consuming request's own slot.

The request gets its **own H2D** rather than the match path's deferred D2D copy.
That copy runs at `model_runner.py:1725`, at the top of the forward:

```python
# Deferred mamba COW/clear on the forward stream, before the extend
# dispatch below reads the pool.
self._maybe_execute_deferred_mamba_cow_and_clear(forward_batch)
```

— i.e. before any `mamba2_layer_index()` -> `layer_transfer_counter.wait_until()`
gate, so it would read the node's slot while the H2D filling it is still in
flight. The H2D into the request's slot is gated like the rest of the load, so
that is the one that is safe. A called-off load-back returns the slot it
allocated and leaves any pending copy the match staged intact.

**Admission** — `staged_prefetch_mamba_slots` surfaces the hold as
`req.mamba_host_hit_length`, so the state a consumption will bind is visible to
the adder the way the SWA window already is. The budget half of this is the
second commit of #36415.

**Fences** — `validate_buffer_only_stack` now rejects a Mamba host pool under
two slots (one staging a write, one in the loads-priority reserve — the same
argument as the existing SWA two-window rule) and int8 Mamba checkpoints, where
the tree value would be a checkpoint slot while a load-back restores a raw state
slot.

## Tests

**New: `TestUnifiedHybridBufferOnlyBitExact`** (Inkling, one GPU, per-commit).
Seeds a 512-token prefix into L3, flushes the device tree, then measures a
768-token prompt over it. The flush is what makes this a storage test rather
than a device-tree test: the radix tree is gone, L3 is not, so every hit came
back through the buffer-mode read path.

The seeded prefix has to end **strictly inside** the measured prompt. Storage
keys one recurrent state per checkpoint node, the hit query accepts only a
prefix ending on one, and a request can never ask for its own last token back
(`max_prefix_len` is `input_len - 1`) — so seeding and measuring the *same*
prompt reads as a total miss however much KV is stored. Measured directly:
re-sending the seeded prompt gives `cached_tokens` 0 for 8/8 while storage holds
48 KV + 48 SWA + 8 mamba objects; seeding `P[:512]` and measuring `P[:768]`
gives 512 for 8/8.

**Unit** — the buffer-only suite now runs on the FULL+MAMBA configs it used to
skip, and `test_buffer_only_read_path_roundtrip` asserts the restored state's
bytes match the producer's on both the published node and the consuming request.
Those assertions are only meaningful on top of the marker-write fix in #36415.

## Results

H200, one GPU, `thinkingmachines/Inkling@test`:

```
TestUnifiedHybridBufferOnlyBitExact::test_prefill_cache_hit_from_storage
buffer_only storage hits: [512, 512, 512, 512, 512, 512, 512, 512]
avg_kl_div=0.0
1 passed in 365.78s
```

Every sample restores its full seeded span from L3 and scores the generation
bit-for-bit identically to a recomputed prefix. Per #34899, any nonzero KL here
is a state-reuse bug.

Unit suite (`-k 'buffer or hicache'`), same box, against a pristine baseline of
the parent commit:

| | passed | skipped | failed |
|---|---|---|---|
| baseline | 418 | 403 | 0 |
| this stack | 434 | 387 | 0 |

The +16 / -16 are exactly the FULL+MAMBA buffer-only cases that used to skip.

## Notes for reviewers

- The KL class asks for a longer `flush_cache` deadline than the 30s the helpers
  default to. `flush_cache` waits for a fully idle scheduler, which in buffer
  mode includes draining staged storage writes, and the `file` backend is not in
  the zero-copy list so it goes through `_generic_page_set` at a few MB/s for
  this model (the disk itself benchmarks at 419 MB/s on the same box). That
  throughput is pre-existing and out of scope here, but it is why the class is
  sized the way it is.
- The class raises `--swa-full-tokens-ratio` to 0.5. A span is only readable
  back from storage if its trailing SWA window was still resident when the
  backup staged — the hit query folds the window's boundary into the KV hit, so
  an SWA-evicted span reads as a total miss. At the 0.1 the sibling classes run,
  the seeding set's own windows evict each other and the earliest samples go
  cold.
- FULL+SWA+MAMBA is covered end to end by the KL class; the unit fixture still
  skips SWA+Mamba stacks, which is a pre-existing fixture limitation unrelated
  to this change.
- A follow-up makes buffer-mode existence beliefs per-pool instead of KV-only,
  so a checkpoint landing on an already-written node still reaches storage. That
  is a coverage gap, not a correctness one, and it ships separately with its own
  number.
