## Logs

```console
- kv  43:               tokenizer.ggml.mask_token_id u32      = 128799
```

But the speculative implementation resolves it to -1 and fails on every draft decode:

```console
I common_speculative_impl_draft_dflash: - n_max=5, n_min=0, p_min=0.00

W draft: llama_decode returned -1

```
## Root cause

**`src/llama-vocab.cpp`** — the `no_vocab` branch sets `special_mask_id = LLAMA_TOKEN_NULL` and returns before any metadata is read (~line 1933):

```cpp
if (tokenizer_model == "no_vocab" || tokenizer_model == "none") {
    type = LLAMA_VOCAB_TYPE_NONE;
    special_bos_id  = LLAMA_TOKEN_NULL;
    ...
    special_mask_id = LLAMA_TOKEN_NULL;   // hardcoded; metadata never consulted
    ...
    return;                               // skips the metadata read below
}
```

**`common/speculative.cpp`** (~line 970) trusts the vocab API with no fallback:

```cpp
mask_token_id = llama_vocab_mask(llama_model_get_vocab(model_dft));   // returns -1
```

That `-1` is then injected into the draft batch (~line 1153):

```cpp
common_batch_add(batch, i == 0 ? dp.id_last : mask_token_id, n + i, { seq_id }, true);
```

→ `invalid token[1] = -1` → `llama_decode` returns -1.

The metadata key is valid and correctly mapped in `src/llama-arch.cpp:345`:

```cpp
{ LLM_KV_TOKENIZER_MASK_ID, "tokenizer.ggml.mask_token_id" },
```

It's simply unreachable on the `no_vocab` path.

## Suggested fix

`common/speculative.cpp` already reads another drafter field (`dflash.block_size`) directly from metadata via `llama_model_meta_val_str` for exactly this reason (~line 962). Applying the same pattern to the mask token is the smallest, most contained fix:

```diff
         mask_token_id = llama_vocab_mask(llama_model_get_vocab(model_dft));
+
+        // no_vocab drafters (DSpark/DFlash) nullify the mask token in the vocab, so
+        // fall back to the GGUF metadata key when the vocab API returns nothing.
+        // Mirrors the dflash.block_size metadata read above.
+        if (mask_token_id < 0) {
+            char buf[32] = {};
+            if (llama_model_meta_val_str(model_dft, "tokenizer.ggml.mask_token_id", buf, sizeof(buf)) >= 0) {
+                mask_token_id = (llama_token) std::atoi(buf);
+            }
+        }
```

With this change, the log line flips from `mask_token_id=-1` to `mask_token_id=128799` and the `invalid token` / decode failures stop. No new includes needed — `llama_model_meta_val_str` and `std::atoi` are already used a few lines above for `dflash.block_size`.

(An alternative, broader fix would be to read `LLM_KV_TOKENIZER_MASK_ID` inside the `no_vocab` branch of `src/llama-vocab.cpp` so `llama_vocab_mask()` returns the right value for any caller — but the change above is sufficient for the speculative path and carries no risk to other vocab consumers.)
