### Feature Description

I've seen it mentioned in https://github.com/ggml-org/llama.cpp/discussions/16938#discussioncomment-16737780 and https://github.com/ggml-org/llama.cpp/discussions/19223 but I don't think anyone has created an issue yet or at least my searches did not result in anything, so here it is. Pinging @apellaman and @Maykeye as you were interested in this. Also ping @allozaur for feedback.

At the moment, once the WebUI is used for more than quick one-off chats, the chat history can become difficult to navigate. Different conversations often belong to different work contexts, for example in my case:
- coding/debugging
- writing/research
- model testing
- personal stuff
- focused specific projects

A lightweight "Projects" or "Folders" feature would allow users to group related chats together.

The first version could be intentionally simple:
1. Add a project/folder list in the chat sidebar.
2. Allow creating, renaming, and deleting projects/folders.
3. Allow moving conversations into a project/folder.
4. Keep an "Uncategorized" or "Conversations" view for the existing chats without project/folder assignment.
5. Show the current project/folder name in the conversation and/or sidebar.

### Motivation

llama-server is becoming a very good lightweight WebUI for local model use. It is fast, small, easy to run, and does not require a separate stack with a database, accounts, background services, etc.

However, as soon as the WebUI becomes the main interface for day-to-day local LLM use, the number of chats grows quickly. A flat chat list works fine for casual testing, but it becomes harder to use when conversations are part of separate ongoing contexts. Without folders/projects, the user has to rely on conversation titles alone scrolling or searching for the one needed at the moment, or manually clean up old conversations. This adds friction and makes me more likely to reach for another WebUI for more serious usage.

### Possible Implementation

The idea is rather well-explored and widely available in both many commercial and some open source UIs. Below is what I think what definitely needs to be done (maybe in some other form though, I'm not a UI/UX expert), but it's not complete and definitely needs more planning.

1. Update sidebar UI:
```
Projects
  Coding
  Experiments
  Writing
  ...

Conversations
  Write a story about a frog
  Write a story about a fox
  Write a story about a rabbit
  ...
```

2. Add conversation actions:
Move to project...
Remove from project

3. Deleting a project could offer two options:
[ ] Delete chats inside this project
[x] Keep chats and move them to Uncategorized/Conversations list

The safer default should probably be to keep chats and only remove the project assignment.

To avoid making the first implementation too complex, nested folders could be left out initially. A single-level project/folder system is probably enough for a first version.

Optional ideas for the future:
- project/folder-level settings e.g. system prompt
- project/folder-level enabled MCP servers/tools
- search/filter chats within the current project/folder

Those extensions could also interact nicely with the presets idea from #22523, but they are not required for the basic version. The core request is simply: give users a lightweight way to group related chats together.
