## 正文

Allow `llama serve -hf` to use llama-server in router mode

Behavior:
- `llama serve -hf` will run a new llama-server in router mode if one doesn't yet exist
- if there was already a server, then reuse it
- models that don't yet exist in cache should be downloaded automatically

Some considerations (TBD):
- server should run on which port? --> port 9931 == "ggml"
- maybe add a "model name resolve" API; for example, input `user/model` without tag resolve to `user/model:Q4_K_M`

### stevecs · 2026-08-23

Just a comment here as I just started using llama.cpp directly, but saw the note on the default port change from 8080 -> 9931 but doing a quick search did NOT see any hits/lookups at IANA that this new port number was going through the registration process.   Any port < 49152 should be registered if used on a project and is for a unique application/service/function.   This helps identification and management of flows through application aware firewalls (so custom service checks, etc can be assigned or excluded for particular ports).   Since this *seems* to be just http traffic but on a different port would argue *against* changing this from 80/8080 normal web ports or if needed to a port > 49152 as otherwise if unregistered will just be laying a future land-mine when that port *IS* registered via the correct channels.  

### ngxson · 2026-08-23

To clarify:

`llama-server` will work as-is, the only thing change is `llama serve` command, as the title of this issue suggested

The change from 8080 to 9931 is because 8080 is a generic port that might be used by other apps. This is mostly for better UX, not just a technical change. That being said, (1) many other apps also use ports not registered on IANA and (2) even if there are conflict, usually with too obscure app that less than 1% users gonna use, and (3) user can always set explicit `--port`, that option is not going anywhere

So I don't see any other blocking issues for this feature.
