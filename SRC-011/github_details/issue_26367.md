# [Issue #26367] ggml-backend-meta: `axis <= GGML_MAX_DIMS` off-by-one (inconsistent with ~21 other sites)

source: https://github.com/ggml-org/llama.cpp/issues/26367
state: open | updated: 2026-09-23T01:11:35Z
labels: stale

## 正文

`ggml/src/ggml-backend-meta.cpp:793` bounds-checks a dimension index with `<=`:

```c
if (ret.axis <= GGML_MAX_DIMS) { ... }   // accepts axis == GGML_MAX_DIMS
```

`ne[]` has `GGML_MAX_DIMS` elements, so `axis == GGML_MAX_DIMS` indexes one past the end. Roughly 21 other sites in the tree use `<` for the same comparison, so this one looks like a typo rather than intent.

**Not attacker-reachable as far as I can tell**, which is why I'm filing it as a plain bug rather than a security report: `ret.axis` comes from the host application's `get_split_state` callback, not from any GGUF file contents. So it requires an embedder to pass a bad axis, not a malicious model.

Suggested fix: change `<=` to `<` for consistency with the rest of the codebase.

Found while sweeping `GGML_MAX_*` uses for inconsistent comparison operators.
