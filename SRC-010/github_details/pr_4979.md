# [PR #4979] fix(disagg): prevent Mooncake async migration from hanging forever

## 正文

## Motivation

Fixes #4971.

Mooncake `p2p_migrate()` under `LMDEPLOY_USE_ASYNC_MIGRATION` created an `asyncio.Future`, ran `_migrate()` in an executor, then `await`ed that Future. Nothing ever called `set_result()` / `set_exception()`, so Decode migration hung after `_migrate()` returned and the node went unhealthy.

This is the unused-Future bug in `lmdeploy/pytorch/disagg/backend/mooncake.py`, not a Mooncake Store + PD feature gap.

## Modification

- Await `loop.run_in_executor(None, self._migrate, assignment)` directly, matching the DLSlime backend.
- Drop the orphan Future. `_migrate()` already raises on a failed transfer, so executor exceptions surface without a separate result check.
- Add a unit test that the async path returns (and that `_migrate` errors propagate) instead of hanging.
