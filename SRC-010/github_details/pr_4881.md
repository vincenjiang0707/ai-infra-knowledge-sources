### 🟡 Changes recommended

`work_num` is incorrectly derived from only `tp` in eval tests, breaking layouts that set `dp`/`ep` (e.g. `tp2dp4ep8`) and potentially causing invalid worker/GPU mappings.

<details>
<summary>Pull request overview</summary>

This PR refactors the `autotest` pytest suite to consolidate layout-based parametrization by introducing standardized “layout marks” (e.g., `tp1`, `dp16ep16`) and helper builders, then updates tests and CI workflows to select cases using these marks instead of the older `gpu_num_*` markers.

**Changes:**
- Add `utils.pytest_layout_utils` to centralize known layouts, derive layout mark names, and build parametrized `pytest.param` rows with consistent marks/ids.
- Refactor many autotest modules (chat/pipeline/restful/evaluate/benchmark/interface) to use shared layout-param builders and `@layout_mark(...)`.
- Update GitHub Actions workflows to filter test runs by layout marks (`tp1/tp2/tp4/tp8`) and adjust one E2E timeout.
</details>
