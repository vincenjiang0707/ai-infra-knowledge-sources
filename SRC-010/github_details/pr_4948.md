## 正文

## Motivation

This PR adds Mooncake Store support for MTP (Multi-Token Prediction) KV caches in LMDeploy. Previously, the Mooncake Store KV connector only handled target-model caches. With MTP enabled (e.g., speculative decoding with models like GLM), the draft-model KV rows were not registered with the connector, so they could not be offloaded to or loaded from Mooncake Store. This PR enables full cache offloading for MTP-enabled inference by registering both target and MTP cache rows and coordinating their save/load lifecycle.

## TODO

- [ ] **MTP-aware cache key and local deduplication**: The MTP KV dependency can extend beyond the range covered by the target-token block key. In a race, a reused MTP KV state may be incorrect, which can reduce the MTP acceptance rate and the resulting performance benefit. This should not affect final model accuracy under the normal verification path, since the target model still verifies the drafted tokens. The long-term fix is to include the required lookahead token(s) in the Mooncake Store key and make local deduplication MTP-aware. I will follow up with a separate PR to address this.
