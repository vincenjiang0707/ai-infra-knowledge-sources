## 正文

## Motivation

Add an opt-in BF16 symmetric-memory LM-head all-gather for supported single-node NVLink/multicast TP2/TP4/TP8 deployments. Each rank writes its local logits directly into the final last-dimension layout using `multimem.st`, then returns an owning output. NCCL remains the default.

This is V1 (native local GEMM followed by all-gather), not a fused CuTeDSL/TileLang GEMM epilogue and not Transformer all-reduce.

## Configuration and dispatch

Only two public settings are exposed:

- `LMDEPLOY_ENABLE_SYMM_MEM_LMHEAD=1`: explicit opt-in; defaults to disabled.
- `LMDEPLOY_SYMM_MEM_LMHEAD_MAX_MB=64`: symmetric arena budget per rank, in MiB. Owning output tensors are additional allocations.

```bash
# Default: NCCL
lmdeploy serve api_server ... --backend pytorch --tp 8

# Optional symmetric-memory LM-head
LMDEPLOY_ENABLE_SYMM_MEM_LMHEAD=1 \
LMDEPLOY_SYMM_MEM_LMHEAD_MAX_MB=64 \
lmdeploy serve api_server ... --backend pytorch --tp 8
```

Block/thread counts, barrier mode and the conservative M=1 NCCL policy are internal. M is the flattened number of token rows presented to the LM head, not the prompt length. Calls above the arena capacity also use NCCL. A shape must be warmed eagerly before using the custom path inside CUDA Graph capture; otherwise capture uses NCCL.

Preparation collectively agrees on enable/dtype, capability/width, arena configuration, optional implementation availability, local allocation success and handle validity. These setup failures disable the optional path consistently across TP ranks. Once ranks commit to rendezvous, communication errors propagate rather than attempting an unsafe rank-local fallback. After admission, an unexpected input-contract change raises; coordinated model device/dtype changes rebuild or disable the provider through `_apply`.

## Changes following review

- Move configuration, capacity, TP agreement/admission and arena lifecycle into `MultimemAllGatherer`; keep `ParallelLMHead` integration and its `_apply` notification thin.
- Remove lazy initialization, `_UNINIT`, `admit_static`, `fast_call`, and the unused `_graph_ready` flag. A single checked `__call__` never initializes/rebuilds resources. Keep only the used warmed-shape set for capture safety.
- Separate the optional Triton kernels from the import-safe provider. Provider plus kernels total 734 lines, down from the previous 1,220-line combined implementation.
- Keep entry/completion synchronization and owning outputs; no borrowed-buffer lifetime contract is introduced.
- Add attribution to [SGLang's implementation](https://github.com/sgl-project/sglang/blob/main/python/sglang/srt/distributed/device_communicators/triton_symm_mem_ag.py).
- Merge current main (`7bbc312c`) and resolve the typed `BuildSpec` integration conflict.
- Preserve Ray peer-device visibility/binding support.
- Keep test and benchmark changes out of this PR. The added LM-head regression file was removed, and the two upstream parser/core test files were restored unchanged at the author's request.

## Final three-way performance comparison: NCCL vs PyTorch native vs custom multimem

Results for the refactored implementation at `68cf6287`: H200 × 8, TP8, BF16, GLM5.2 LM-head shape V=154880 and H=6144, PyTorch 2.13.0+cu129. M is the flattened number of token rows processed by this LM-head call, **not input sequence length**. These are synthetic LM-head benchmarks, not a full GLM5.2 serving run.

The three alternatives use the same local logits / LM-head weights:

- **NCCL:** `dist.all_gather_into_tensor`, followed by the layout reconstruction used by `ParallelLMHead`.
- **PyTorch native:** `torch.ops.symm_mem.multimem_all_gather_out`, followed by the required layout conversion and independent output copy.
- **Custom multimem:** this PR's implementation adapted from SGLang, writing the final last-dimension layout directly and including its owning output clone. This is not an unmodified upstream SGLang benchmark.

For PyTorch native, the measured operation includes:

```python
torch.ops.symm_mem.multimem_all_gather_out(local_logits, group.group_name, symmetric_out)
logits = (symmetric_out.view(tp, M, V // tp).permute(1, 0, 2)
          .clone(memory_format=torch.contiguous_format).view(M, V))
```

**Timing:** microseconds, lower is better. Median of 21 samples after 3 discarded samples; each sample replays 8 calls in a CUDA Graph. Backend order rotates, and each sample takes the maximum latency across ranks. Both multimem alternatives include owning outputs. Bitwise equality, output ownership and captured-output equality after replay all passed. This is not a comparison against the raw native collective without layout conversion.

### Takeaways

- **Against NCCL:** custom all-gather achieves **1.23–1.68×** speedup; GEMM+AG achieves **1.15–1.23×** across the measured shapes.
- **M=6/8:** the two multimem alternatives have nearly equal GEMM+AG medians, differing by less than 1%; native is slightly lower. These small differences are not evidence of a decisive performance win.
- **M=128/512:** custom GEMM+AG achieves **1.112× / 1.163×** speedup over native. For AG alone, the speedups are **1.173× / 1.218×**.
- Retain the custom kernel in this revision because of the measured larger-M benefit, while keeping NCCL as the default. This is not a claim that custom wins for every shape, GPU or topology.
- **These speedups are not end-to-end TTFT/TPOT improvements.** No full-model serving benchmark was rerun for this revision.
