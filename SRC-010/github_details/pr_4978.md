# [PR #4978] Decouple GEMM workspace from Linear handle

source: https://github.com/InternLM/lmdeploy/pull/4978
state: closed | updated: 2026-09-17T07:59:51Z
labels: improvement

## 正文

## Motivation

`LlamaLinear` owned its GEMM workspace privately, which tied scratch memory (barriers/partials/tensormaps) to every linear instance and prevented sharing a workspace across components. This change makes the workspace an explicit, caller-supplied resource bound at scope, so different non-overlapping components — including ones running on different streams — can share the same workspace, and concurrent GEMMs can use distinct ones.

## Design

- **`gemm::Workspace`** is now self-contained RAII: constructing with a stream allocates and initializes everything on that stream; destruction frees it. The stream is used at construction only and never retained, so a workspace is usable from any stream. Non-copyable, move-constructible, not move-assignable. Workspace sizing constants moved here from `Gemm`.
- **`LlamaLinear`** owns nothing. `LlamaLinear::With(workspace)` returns a non-copyable, non-movable scope token (RAII, LIFO restore) that binds the workspace for the duration of a scope. `Forward`/`Tune`/`GetExecPlan` signatures are unchanged; an unbound call fails a `TM_CHECK` instead of dereferencing null.
- **No per-component wiring** — binding happens at the two outer-most scopes only:
  - *Engine:* `ModelExecutor`'s internal thread creates the workspace on the executor stream and binds it for the entire work loop. At thread exit it calls `Workspace::Release(stream)`, which frees with `cudaFreeAsync` — stream-ordered after the last batch's kernels.
  - *Python:* a per-stream workspace pool lives in `lmdeploy.turbomind.linear.Linear` (keyed by stream, like per-stream cuBLAS workspaces). The four workspace-bound bindings (`get_exec_plan`, `forward_dense`, `forward_moe`, `tune`) take the workspace as an argument and hold the GIL across With → run → restore, keeping the per-device `get_linear()` singleton consistent under multi-threaded use. `get_exec_plan` needs no live native context, only a device guard.
- **Teardown contract:** the destructor uses plain `cudaFree` (no implicit sync for `cudaMallocAsync` memory) as a fallback for already-synced or exception paths; owners on a live stream use `Release()`. Python `close()` synchronizes the device before dropping the pool.

## Also fixed along the way

- Tensormaps were allocated at `partials_size` (32 MiB) instead of their actual size (8192 × 128 B = 1 MiB) — saves 31 MiB per workspace.

## Compatibility

- C++ `LlamaLinear` API: `Forward`/`Tune`/`GetExecPlan` signatures unchanged; new `With()` is additive.
- Python: `Linear`'s public API (`__call__`, `forward_moe`, `tune`, `get_exec_plan`) is unchanged; the pool is internal. Note: `tune()` now blocks the interpreter during measurement (GIL held for thread safety).

**lmdeploy/turbomind/linear.py:181**
* This cache retains one roughly 34 MiB workspace for every distinct raw CUDA stream handle until `Linear.close()`. Because `get_linear()` returns a long-lived per-device singleton, applications that create ephemeral streams can accumulate these allocations and exhaust GPU memory; the raw integer key also provides no stream-lifetime eviction. Please add a lifecycle-aware eviction or bounded-pool policy that preserves in-flight work before releasing a workspace.
```
        ws = self._workspaces.get(stream.cuda_stream)
        if ws is None:
            ws = _tm.GemmWorkspace(stream.cuda_stream)
            self._workspaces[stream.cuda_stream] = ws
```

Add a CUDA regression test that runs a plan on two streams and closes the executor while work is in flight, so workspace keying and lifetime regressions are caught automatically.

* `Gemm::Arguments::workspace` now defaults to null, but `Gemm::Run` remains public and this path dereferences it unconditionally. A direct caller that omits the required workspace now gets undefined behavior rather than a diagnostic; validate the pointer before dereferencing, consistent with the `LlamaLinear` `TM_CHECK` contract.

**src/turbomind/kernels/gemm/types.h:256**
* A default-constructed workspace has null device pointers and zero capacities, but `With()` only checks the workspace pointer itself. A named `gemm::Workspace workspace;` therefore passes the check and can reach dispatch or a kernel with an invalid scratch buffer. Since no caller needs an empty workspace and move assignment is deleted, remove the default constructor or reject uninitialized workspaces in `With()`.
```

```
