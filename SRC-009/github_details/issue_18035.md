# [Issue #18035] [Performance]: Deduplicate shared RoPE SMEM staging in fused DiT QK norm

## 正文

### Proposal to improve performance

#### Problem

The full-dimension fused DiT QK-norm/RoPE kernel stages Q, K, cosine, and sine values in dynamic shared memory. For the shared-FP32 RoPE layout (`per_head_cos=false`, `cos_is_bf16=false`), every head consumes the same `head_dim` cosine/sine row, but the current implementation stages that row once per head.

For the Wan A14B shape (`num_heads_q=num_heads_k=40`, `head_dim=128`), this inflates the cosine/sine staging volume and dynamic shared-memory allocation. The duplicated shared-memory footprint limits CTA residency on SM100.

#### Proposed change

- Stage one FP32 cosine row and one FP32 sine row per token/CTA row when the embeddings are shared across heads.
- Index that shared row with `elem % head_dim` during RoPE application.
- Leave the BF16 cosine/sine layout and all per-head layouts unchanged.
- Compute dynamic shared-memory size from `head_dim` for the shared-FP32 case and retain the existing `num_heads * head_dim` size elsewhere.
- Keep the existing generic full-dimension kernel entry point and dispatch. Do not impose an architecture- or shape-specific launch bound.
- Add bitwise shared-vs-expanded-layout tests for both interleaved and rotate-half RoPE at `(24, 64)`, `(24, 128)`, and `(40, 128)`.

There is no public API or numerical algorithm change. Unsupported layouts continue through their existing implementations.

#### Why this version

An earlier single-row-QK experiment changed more of the kernel schedule and did not produce reliable end-to-end evidence. A later `__launch_bounds__(256, 3)` candidate reduced registers but produced a 48-byte per-thread stack frame in the exact SM100 build. This proposal keeps the existing two-row Q/K schedule, removes only redundant shared-FP32 RoPE staging, and leaves register allocation to the generic kernel.

#### Related work

- #13052 introduced a separate cross-head/full-dimension QK-norm/RoPE path for Wan.
- #13985 introduced the current two-row full-dimension kernel family.
- #14529 unified dispatch, removed the cross-head op, and routed Wan through the full-dimension implementation.

This proposal narrowly optimizes the current #13985/#14529 shared-FP32 path: it removes replication only when `PER_HEAD_COS=false` and the embedding type is FP32.

#### Research evidence (directional, not final-candidate validation)

The following B200 measurements came from an earlier research prototype by @chang-l. They motivate this proposal, but they were **not** collected from the final upstream-ready diff and must not be read as final PR results.

| Measurement | Baseline | Research prototype | Change |
| --- | ---: | ---: | ---: |
| Standalone fused QK-norm/RoPE kernel | 975.0 us | 486.98 us | 2.00x faster |
| In-model fused QK-norm/RoPE kernel | 1303.7 us | 681 us | 1.91x faster |
| Wan 480x832x81-frame denoise | 107.118 s | 106.629 s | -0.46% |
| Dynamic shared memory, A14B dispatch | 122,944 B | 43,072 B | -65.0% |
| Requested cosine/sine staging bytes per call | 2.684 GB | 67.1 MB | -97.5% |

The physical shared cosine/sine table is 33.5 MB for 32,760 tokens in each CFG branch; 67.1 MB is the per-call requested staging volume because both CFG branches reuse that table. The research prototype produced a bitwise-identical full QKV output in its parity check.

The research launch-bound sweep measured 504 us at LB2 and 486.98 us at LB3; LB4/LB5 regressed to 542/611 us. Those results are directional only. The final candidate does not carry a launch bound, and its own binary resources and performance must be measured independently.

A superseded research prototype also changed shared-BF16 staging and imposed
SM100 launch bounds. The proposed candidate is FP32-only, preserves the BF16
layout, and carries no launch bound.

Before a ready PR, the exact upstream candidate will be built and tested on B200, profiled to confirm the intended symbol and shared-memory size, benchmarked against its unmodified base, and run through the VisualGen end-to-end quality gate. Those candidate-specific results are intentionally not claimed here yet.

### Report of performance regression

This is not a regression report. It is a proposal to remove redundant memory movement in an existing fused kernel.

### Misc discussion on performance

The generic optimization is deliberately restricted to shared FP32 embeddings because that is the layout with measured redundant staging. The BF16 and per-head paths retain their prior layout and dispatch. There is no SM100-only entry point or launch-bound specialization, so an occupancy choice measured for one Wan A14B experiment is not imposed on other architectures or shapes.
