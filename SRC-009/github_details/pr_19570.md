## Background

Agent Flow currently directs Nsight Compute at the full `trtllm-serve`
process. A kernel-name filter limits captured launches, but it does not reduce
the CUDA context that kernel replay must save. Large model and KV-cache
processes can therefore fail with `ContextSaveFailed` before the target kernel
is captured.

## Summary

- Use Nsight Systems first to identify dominant non-collective hotspot kernels
  and recover representative shapes, dtypes, layouts, launch configuration,
  and relevant runtime state.
- Direct the analyzer to build or reuse a minimal faithful microbenchmark for
  each selected hotspot, complete JIT compilation and autotuning during
  warmup, and bracket only steady-state launches with
  `cudaProfilerStart`/`cudaProfilerStop`.
- Run Nsight Compute against those microbenchmarks instead of wrapping the
  full model server, with a bounded launch count and focused metric sections.
- Recognize both `.ncu-rep` and `.ncu-repz` reports and update workflow prompts,
  documentation, and tests consistently.

## Impact

This changes only Agent Flow profiling guidance and report discovery. It does
not modify TensorRT-LLM runtime or kernel behavior. Nsight Systems remains the
source of whole-model hotspot evidence; Nsight Compute is scoped to faithful
standalone reproductions of selected kernels.
