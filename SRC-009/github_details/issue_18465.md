# [Issue #18465] Expose KV-cache hit metrics by storage tier

source: https://github.com/NVIDIA/TensorRT-LLM/issues/18465
state: closed | updated: 2026-09-17T10:05:17Z
labels: Disaggregated serving

## 正文

### Problem

TensorRT-LLM exposes aggregate KV-cache metrics such as `kv_cache_hit_rate` and `prompt_cached_tokens_total`, plus host-cache utilization and onboard/offload byte counters.

When KV-cache offloading is enabled, these metrics do not identify whether reused tokens were served from GPU memory, host memory, disk, or another tier. Transfer counters cannot reliably reconstruct cache-hit attribution.

### Request

Please expose monotonic Prometheus counters attributing reused tokens or blocks to their source tier, for example:

```text
trtllm_prompt_cached_tokens_total{cache_tier="gpu"}
trtllm_prompt_cached_tokens_total{cache_tier="host"}
trtllm_prompt_cached_tokens_total{cache_tier="disk"}
trtllm_prompt_cached_tokens_total{cache_tier="remote"}
```

An equivalent tier-labeled cache-hit counter would also work. Ideally:

- Every cache hit is attributed to exactly one tier.
- Tier totals sum to the existing aggregate value.
- Host-cache hits are distinguishable from GPU-resident prefix-cache hits.
- Metrics work with disaggregated serving and supported KV-cache managers.
- Existing aggregate metrics remain available for compatibility.
- Counter and reset semantics are documented.

### Motivation

This would allow users to measure whether CPU offloading is actually serving requests, evaluate each cache tier, and correctly visualize token sources. Host utilization and transfer volume show data movement, but not whether requests benefited from host-cache hits.

Related work: #11243, #12132, and #12854.
