## Description

The embedded DSpark worker shares a reserved slot among CUDA graph padding and attention-DP idle requests. Its decode position currently accumulates across generation steps for the lifetime of the worker. Eventually, RoPE gathers can index past their fixed table even though the dummy rows are subsequently masked.

Reset the scratch slot's previous position to zero inside `_advance_generation_state()` using tensor operations, so the reset executes on every CUDA graph replay without host synchronization. Real-request position bootstrap and advancement retain their existing behavior. This adds one tensor comparison/selection to the generation path; full-serving performance has not been measured for this upstream adaptation.

## Test Coverage

Added `test_dspark_generation_state.py` under the existing `hw_agnostic` directory, already included by the CPU and H100 CI lists:

- CPU: initialized and uninitialized scratch positions at/beyond the RoPE boundary, duplicate scratch rows with different accepted-token counts, repeated advancement, real-request bootstrap, and recycled real-slot state.
- CUDA: capture/replay with changing real/scratch mappings and accepted-token counts for batches 16, 32, 48, 64, 96, and 128, followed by 1,000 all-padding replays.

Validation performed locally on macOS with PyTorch 2.8.0:
- Invoked the two CPU regression cases using the actual `_advance_generation_state` method extracted from upstream source via AST, isolating it from unavailable TensorRT-LLM runtime dependencies. Both fail with out-of-bounds indexing on unpatched main and pass with the fix.
- Ruff 0.9.4 lint and formatting checks pass for both changed files.
- `git diff --check` passes.

The full upstream pytest suite, pre-commit suite, and CUDA replay tests have not been run in this environment. GPU CI validation is pending.
