## 正文

## Background

Perf Optimize computed the integration acceptance threshold in Python, but also required the Integrator agent to recompute and report the same floating-point value. Normal output rounding could make those values differ and abort an otherwise successful integration.

## Summary

- Use the orchestrator-computed expected gain directly for integration acceptance.
- Remove the redundant required_gain_pct field from the Integrator tool schema and progress records.
- Simplify the Integrator prompt so it reports measured results while Python owns the acceptance threshold.
- Update the affected workflow and progress tests.

## Impact

This prevents harmless LLM-side numeric formatting from terminating Perf Optimize. Acceptance semantics are unchanged: measured integration gain must still meet the same Python-computed threshold. Existing progress entries with the removed field remain readable because the orchestrator ignores extra persisted fields.
