## 正文

## Summary

`--mm-encoder-only` already skips building the language model (#30242), but the default loader still iterates every safetensors shard. This PR filters **pure LM shards** out of `hf_weights_files` using the HF weight index before any weights iterator runs: under `--mm-encoder-only`, shards are classified via `_language_model_names` plus the model’s existing `hf_to_vllm_mapper`, pure-LM shards are dropped, and resolve fail-closes (full file list) when an LM module prefix is also an HF ancestor of non-LM mapper entries. Encoder-only EPD cold start therefore avoids reading the full VLM checkpoint on prefix-match families (e.g. Kimi top-level `language_model.` / MiniCPM `llm.`, Qwen nested/flat via the mapper).

**When this helps:** Encoder-only cold start under `--mm-encoder-only` — e.g. EPD Encoder scale-out / restart, or single-Encoder bring-up & testing — by skipping LM-only safetensors I/O when the Encoder never builds the LM.

## Motivation

1. **Finding:** On **[Kimi-K3 pruned75](https://huggingface.co/mgoin/Kimi-K3-pruned75)**, even the Encoder node under `--mm-encoder-only` still had to walk/load the **full** safetensors shard set — very slow and wasteful for cold start / Encoder restart.
2. **Fix:** Index-based **LM-shard skipping** on the default loader (filter pure LM shards before iterators). Confirmed on that finding: pruned75 **96→2** shards, `Loading weights took` **683.36s → 0.31s**.
3. **Broader check:** Same mechanism validated on **original Kimi-K3**, same-series **Kimi-K2.6**, and **Qwen** (Qwen3 nested + Qwen2.5 flat, classified via `hf_to_vllm_mapper`), including `safetensors` / `instanttensor` / `fastsafetensors` where measured.
4. **Out of scope this PR (extendable):** Families whose LM module prefix is a shared HF root with non-LM weights (e.g. Molmo / Phi-4-MM / Muse with bare `model.`) are **not covered** by whole-shard skip here — fail-closed, full file list (safe). They can use the **same** mechanism later with finer non-overlapping HF prefixes or key-level filtering.

Steady GPU memory was already small under Encoder-only; the waste is **startup I/O**, not steady VRAM.

## Addressing review: hard-coded HF prefixes

Review asked to avoid a model-specific hard-coded HF nest list and a magic bare-`model.` deny set in the loader.

**Current design (this PR):**

1. **Prefix source:** `_language_model_names` only → vLLM *module* prefixes (fallback `language_model.`). No per-model override attr.
2. **HF key classification:** map each index key through the model’s existing `hf_to_vllm_mapper`, then test the *vLLM* name against those module prefixes — Qwen nested (`model.language_model.*`) and flat (`model.layers.*` via the catch-all `model.`→`language_model.model.` mapping) need no nest list in `weight_utils`.
3. **Shared-root guard:** if a module prefix (e.g. `model.`) is also an HF ancestor of non-LM mapper entries (vision under `model.vision_*`), resolve returns `None` and the file list is left unchanged (Molmo / Phi-4-MM / Muse). Detected from `WeightsMapper.orig_to_new_prefix`, not a name allow/deny set.

No global HF-prefix tuple; no magic `{"model."}` set; no `mm_encoder_only_lm_prefixes` escape hatch.

**Regression pointers:** unit 9/9 PASS; K3 safetensors 94/96 + Tier-2 HTTP 200 (pt 113 vs 95); Qwen3-VL 12/13; K3 instanttensor / fastsafetensors PASS (load Δ within noise). Live log prefixes=`('language_model.',)` confirms the mapper path.

## Approach

- Applies on `DefaultModelLoader` safetensors-file+index path (also `fastsafetensors` / `instanttensor` / `mistral` via the shared file list); other loaders untouched.
- Under `--mm-encoder-only`, derive LM *module* prefixes from `_language_model_names` (fallback `language_model.`) and capture the model’s existing `hf_to_vllm_mapper`.
- `resolve_mm_encoder_only_lm_prefixes()` returns those module prefixes, or `None` (fail-closed → full file list) when a prefix is a shared HF root with non-LM `WeightsMapper` entries (Molmo / Phi-4-MM / Muse).
- `filter_mm_encoder_only_safetensors_files()` reads the index `weight_map`, maps each HF key through the optional mapper, and drops shards whose keys are all LM-module-prefix.
- In `DefaultModelLoader.load_weights`, when multimodal `mm_encoder_only` is set, resolve prefixes + capture mapper, then apply the filter in `_get_weights_iterator` **after** `_prepare_weights` and **before** choosing `safetensors` / `fastsafetensors` / `instanttensor` iterators.
- Missing index / shared-root fail-closed / no key match → unchanged file list (safe).

### gty111 · 2026-09-23 · COMMENTED

One non-blocking suggestion: the filter duck-types the private `WeightsMapper._map_name` via `getattr(weights_mapper, "_map_name", None)`. If that method is ever renamed, classification silently degrades to identity matching and the shard skip just stops happening (safe direction, but invisible). Consider adding a small public `map_name()` wrapper on `WeightsMapper` and typing the parameter as `WeightsMapper | None`.

Minor: an empty `_language_model_names` currently falls back to `("language_model.",)` (fail-open); returning `None` there would match the fail-closed design used elsewhere in this PR.
