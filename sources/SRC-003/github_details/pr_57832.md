## Summary

Adds context-parallel decode scoring for MiniMax-M3's sparse lightning indexer on ROCm (TP>1, opt-in).

### Problem
With TP>1, every rank independently scores the entire KV cache for the sparse indexer — redundant work scaling linearly with world_size.

### Solution
- Each rank scores only its 1/world_size shard of global KV blocks (round-robin: block = local * world + rank)
- Scores scattered into a global-shape `[heads, tokens, max_block]` tensor pre-filled with `-inf`
- MAX allreduce across TP group fills all positions from their owning rank
- `minimax_m3_index_decode(precomputed_score=...)` skips internal re-scoring and runs top-k directly

**Activation:** `VLLM_ROCM_MINIMAX_INDEXER_CP=1` — off by default. ROCm + TP>1 only.

At concurrency 20: TTFT p50 improves (−8%); p90 slightly worse — CP overhead vs savings near break-even at lower load.

### Architecture Concerns

**`minimal-fix-over-parallel-class-proliferation`**
`MiniMaxM3IndexerTritonCPImpl` overrides `forward()` but the CP-vs-non-CP distinction is a single branch (round-robin shard + allreduce vs. full scoring). Consider whether the base `MiniMaxM3IndexerTritonImpl.forward()` should host an `if self.cp_enabled:` branch instead of a subclass, eliminating the separate class and the selector branch. If the subclass is kept, extract a `_score_decode()` hook to avoid duplicating the buffer-allocation and metadata-unpacking scaffolding.

**`gate-feature-on-upstream-kernel-readiness`**
The MAX-allreduce-over-`-inf` pattern is a manual emulation of what a CP-aware sparse-indexer primitive would do. The `global_score` allocation, `owned_cols` scatter, and `dist.all_reduce(op=MAX)` dance waste bandwidth (allreduces a full-width tensor where each rank contributes only `1/world_size`). Consider gating this clearly as experimental and tracking the upstream CP primitive as a prerequisite.

**`reuse-existing-internal-api-over-reimplementation`**
`dist.all_reduce(..., group=get_tp_group().device_group)` reimplements a TP-group collective that vLLM exposes via `tensor_model_parallel_all_reduce`. Use the canonical API to stay consistent with vLLM's custom-allreduce and coordinator handling.
