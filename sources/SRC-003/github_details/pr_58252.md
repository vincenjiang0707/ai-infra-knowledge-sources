## 正文

## Problem

`test_rms_norm` group-64 int8/fp8 cases fail on main roughly daily (`scales_close(rtol=1e-5)` assert) — dashboard alerts #1414/#1481/#1719/#1746/#1942 family, ~9 occurrences in the past week, on multiple H200 hosts.

The groupwise scale comparison between the fused kernel and the reference can flip by one ULP on isolated groups (reduction order), identical to the pattern the existing `relax_block_rocm` accommodation covers — but that relaxation only applied on ROCm.

## Fix

Extend the per-block scale relaxation to CUDA as well (`relax_block_rocm` → `relax_block`). Strict per-token/fp32 paths unchanged.

NOTE: I have no GPU on this box — needs CI on H200 to confirm the relaxation actually covers the observed mismatch magnitude. If the fused path's deviation exceeds rtol=1e-2, the real fix is in the kernel, not the test; the alerts' evidence so far (isolated groups, passes on retry) points to ULP-scale.
