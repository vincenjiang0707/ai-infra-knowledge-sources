# [PR #52927] [Bugfix] Scan the final window in ASR audio split-point search

source: https://github.com/vllm-project/vllm/pull/52927
state: open | updated: 2026-09-23T06:05:26Z
labels: bug, multi-modality

## 正文

## Purpose

`find_split_point` (used by `split_audio` for ASR long-audio chunking) scans non-overlapping RMS-energy windows to pick a low-energy split point. The loop bound

```python
for i in range(0, len(segment) - min_energy_window, min_energy_window):
```

uses an exclusive stop of `len - min_energy_window`, which drops the final full window `[len - min_energy_window, len)` whenever `len(segment)` is an exact multiple of `min_energy_window`. When the quietest region lies in that final window, it is never scanned, so the search falls back to a louder point and the chunk boundary can cut through speech.

Fix: use `len - min_energy_window + 1` as the exclusive stop so the last full window is scanned.

```diff
-    for i in range(0, len(segment) - min_energy_window, min_energy_window):
+    for i in range(0, len(segment) - min_energy_window + 1, min_energy_window):
```

## Not a duplicate

Open audio PRs (#48225, #45115, #45063, #35159, #34375, #33564) all address cumulative Whisper **timestamp** drift/offset compensation, and #49414 is docs-only. None modify `find_split_point`'s window-scanning loop / silence detection.

## Test Plan

- New regression test `tests/multimodal/test_audio.py::TestAudioChunking::test_find_split_point_scans_final_window`: search region spanning exactly three windows with silence only in the final window; asserts the split lands in that window.
- `pytest tests/multimodal/test_audio.py::TestAudioChunking`

## Test Result

- Before the fix, the new test **fails** (`assert 0 == 3200` — the silent final window is missed). After the fix it **passes**.
- Full `TestAudioChunking` class: **13 passed**.
- `ruff check` and `ruff format --check` (v0.14.0) clean on both changed files.

## Model evaluation

This change affects only *where* audio is chunked, not model numerics: the split point moves by at most one `min_energy_window` (0.1s under the default 16 kHz / 1600-sample window) and always stays within the existing search region, so transcription text can differ only slightly at chunk boundaries. A full end-to-end ASR accuracy (WER) eval has not been run yet; I'm happy to add one (e.g. Whisper on long-form audio) if maintainers would like it before merge.
