### TheEpicDolphin · 2026-06-19

@benchislett One challenge I see from reusing `AutoRegressiveSpeculator` is that the vanilla draft model cannot reuse the attention metadata & slot mappings from the target model prefill. EAGLE & MTP were able to because they shift the input tokens by one (first token is dropped, bonus token is added), so any position-based metadata is consistent between target and draft model prefills. However, that's not the case for a vanilla draft model because it actually prefills with N + 1 tokens, which includes the N target model prefill tokens + the bonus token.

The logic for decoding the last K - 1 draft tokens is mostly the same as `AutoRegressiveSpeculator`, though we'd have to handle threading the hidden states through. We could potentially add a similar property to `advance_draft_positions`, but for hidden states called `consumes_hidden_states`, and this class would override to True.

### tomasruizt · 2026-09-18

@wxsIcey About PCP & code reuse: 

Currently, `prepare_attn()` is only implicit in this PR, but is explicit in [#53660](https://github.com/vllm-project/vllm/pull/53660), and [#55990](https://github.com/vllm-project/vllm/pull/55990). The method is used in `draft_model` because it cannot reuse the target attn metadata for prefill (1 token more). EAGLE3/MTP normally reuse the target attn metadata, except in specific cases, e.g. PCP: The target prefill is split among multiple ranks, and the drafter can be replicated in each rank, so the attn metadata no longer matches.

Foreseeing the PCP compatibility, we could factor out `prepare_attn()` into a separate function in this PR (or a method, follwing [#53660](https://github.com/vllm-project/vllm/pull/53660)). A follow-up PR can then extend that function to support EAGLE3/MTP for the PCP setting if needed.

Do you agree? @TheEpicDolphin

This pull request implements the DraftModelSpeculator for the v1 worker, enabling speculative decoding using a separate draft model. The implementation includes a custom Triton kernel for step-0 input preparation and logic for iterative draft token generation. Review feedback highlighted critical bugs in sequence length calculations within both the Triton kernel and the decode loop, noting that incorrect lengths would cause the attention mechanism to read from invalid KV cache slots, potentially leading to accuracy issues or crashes.
