## 正文

## What

Organize correlated Model Executor tests into content folders and assign whole units to four named jobs. Keep singleton loader, routed-expert, and sleep-mode files in their natural parents.

## Old

```text
tests/model_executor/
├── test_*.py                 # loose feature tests
├── model_loader/test_*.py
└── existing loader/layer folders
# one filtered job
```

## New

```text
tests/model_executor/
├── test_routed_experts_capture.py
├── test_sleep_mode_tensor_ownership.py
├── warmup/  mrope/  quantization/  models/  custom_ops/  utils/
├── layers/  kernels/  offloader/
└── model_loader/
    ├── test_model_load_with_params.py
    ├── test_reload.py
    ├── test_sharded_state_loader.py
    └── weights/  registry/  existing loader folders
# four named jobs, one replica each; no partition marker, no case routing
#
# model-executor-tensorizer                     tensorizer_loader + entrypoints tensorizer file
# model-executor-sharded-state-weights-registry test_sharded_state_loader.py + weights/ + registry/
# model-executor-reload                         test_reload.py
# model-executor-core                           layers/ mrope/ kernels/ utils/ models/ custom_ops/
#                                               warmup/ quantization/ offloader/ + singletons
#                                               + params + fastsafetensors/instanttensor/runai loaders
```

## Notes

- The singleton files replace the former `moe/`, `sleep_mode/`, `params/`, `reload/`, and `sharded_state/` wrappers. Unit assignments and process boundaries are preserved; the slow-test cases stay included.
- The old `model-executor` key (one job, `parallelism: 4`, `case` routing) is replaced by the four keys above; nothing outside the area YAML referenced the old key. Timings are routing-invariant, so the build 89155 per-unit measurements carry over.
- The existing state-cleanup fixes and distributed sharded-state selection remain part of this PR. Every pipeline reference to a moved singleton follows its new path.
- This updates the existing Model Executor effort rather than adding a parallel PR. The generated primary/mirror jobs and the separate legacy pipeline require validation.
- Validation: all five flattened files preserve test ASTs/import destinations; real-area coverage, Python syntax, YAML parsing, and Ruff pass. Fresh CI evidence will be reported against the new head. AI assistance was used.
