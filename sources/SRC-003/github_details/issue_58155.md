### 🐛 Describe the bug

Summary
According to the official DeepSeek API documentation, the DeepSeek V4 series thinking mode does not support the temperature, presence_penalty, and frequency_penalty parameters. For backward compatibility, passing these parameters does not raise an error, but they have no effect.

However, vLLM does not behave consistently with the DeepSeek API. When serving DeepSeek V4 series models in thinking mode, these parameters are still applied to sampling instead of being ignored.

Expected behavior
For DeepSeek V4 series thinking mode, vLLM should accept temperature, presence_penalty, and frequency_penalty without raising an error, but silently ignore them — matching the official DeepSeek API behavior.

Actual behavior
These parameters are still honored by the sampler, which can lead to different (and unexpected) outputs compared to the official API.

Impact
Users migrating from the official DeepSeek API to vLLM may get inconsistent results.

Clients that rely on the documented "accepted but ignored" behavior may unintentionally change model output.

Reproducibility across the official API and vLLM is broken for these models.

Steps to reproduce
Serve a DeepSeek V4 series model in thinking mode with vLLM.

Send a request with different values of temperature (or presence_penalty / frequency_penalty).

Observe that the output changes, whereas the official DeepSeek API would produce identical sampling behavior regardless of these values.

Suggested fix
Detect DeepSeek V4 series thinking mode and skip applying temperature, presence_penalty, and frequency_penalty in the sampling path, while still accepting them in the request schema for compatibility.
