# [PR #57629] [Bugfix][Core] Release pinned host cache before discarded wake remap

## Purpose

Fixes #50011.

On unified-memory systems such as DGX Spark / GB10, PyTorch's pinned-host allocator can retain a freed CPU backup in its cache after `wake_up()` restores it to device memory.

Because host and device allocations compete for the same physical memory on these systems, that cached pinned memory can contribute to the wake-time memory spike.

This PR keeps the existing `wake_up()` flow unchanged and makes the smallest possible modification after restoring a CPU-backed allocation:

1. drop the remaining local reference to the backup tensor;
2. call `torch.accelerator.empty_host_cache()` so the freed pinned-host memory can be returned before wake continues.

No public API or C++ allocator changes are introduced.
