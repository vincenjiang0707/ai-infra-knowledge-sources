### 🐛 Describe the bug

#57289 installs vLLM's nested-RoPE validator patch only when the model type being loaded is in `_PATCH_HF_NESTED_ROPE_VALIDATION` (`laguna`, `gemma4_text`), the "surgical" scoping asked for in its review. The installed wrapper replaces `PretrainedConfig.validate_rope` for the rest of the process, and it drops shared `rope_parameters` entries for any config it validates, without looking at that config's `model_type`. So after a `laguna` or `gemma4_text` config has been parsed, every later config of any other model type with the same malformed shape is accepted with a warning instead of failing transformers' validation.

Reproduction, config loading only (no weights, no GPU; `poolside/Laguna-XS-2.1-NVFP4` is public):

```python
from transformers import Gemma3TextConfig


def gemma3_with_shared_entry():
    # gemma3_text is not in vLLM's allowlist. The shared "rope_theta" beside the
    # per-layer dicts is the shape transformers 5.17 rejects.
    return Gemma3TextConfig(
        num_hidden_layers=2,
        layer_types=["sliding_attention", "full_attention"],
        rope_parameters={
            "sliding_attention": {"rope_type": "default", "rope_theta": 10000.0},
            "full_attention": {"rope_type": "default", "rope_theta": 1000000.0},
            "rope_theta": 1000000.0,
        },
    )


try:
    gemma3_with_shared_entry()
    print("before: built")
except AttributeError as e:
    print(f"before: {type(e).__name__}: {e}")

# Parse an allowlisted model's config (laguna). This installs the patch.
from vllm.transformers_utils.config import get_config

get_config("poolside/Laguna-XS-2.1-NVFP4", trust_remote_code=True)

try:
    c = gemma3_with_shared_entry()
    print(f"after:  built, rope_parameters keys = {sorted(c.rope_parameters)}")
except AttributeError as e:
    print(f"after:  {type(e).__name__}: {e}")
```

Observed on `main` at 63d9ad0a3 (transformers 5.17.0, huggingface_hub 1.31.0; vLLM built from source, the collect_env version string reflects the venv build):

```text
before: AttributeError: 'float' object has no attribute 'get'
WARNING [config.py:311] Dropping ['rope_theta'] from rope_parameters; entries shared across layer types are not supported
WARNING [config.py:311] Dropping ['rope_theta'] from rope_parameters; entries shared across layer types are not supported
after:  built, rope_parameters keys = ['full_attention', 'sliding_attention']
```

The first warning is laguna's own, expected. The second is the `gemma3_text` config being repaired. Same result when the allowlisted model is parsed through `vllm.config.ModelConfig(...)` instead of `get_config`.

Expected: the second construction raises the same `AttributeError` as the first. The allowlist decides which model types get the accommodation; parsing one of them should not change what happens to every other config in the process.

Where: `vllm/transformers_utils/config.py`. The allowlist is consulted in `get_config` (`if model_type in _PATCH_HF_NESTED_ROPE_VALIDATION: _patch_hf_transformers_nested_rope_validation()`); the wrapper defined inside `_patch_hf_transformers_nested_rope_validation` drops shared keys whenever `rope_parameters` carries layer-type keys. This is the nested-map sibling of #57188 (the same wrapper mutating later flat `rope_parameters`), which #57189 fixed with the layer-type gate.

Fix in the linked PR.
