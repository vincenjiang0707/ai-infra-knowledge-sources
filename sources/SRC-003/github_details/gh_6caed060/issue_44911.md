## Still reproducible in v0.23.0 — Mistral Large 3 675B NVFP4, different error variant

Confirming the bug persists in **vLLM v0.23.0** (which should include the #45180 fix) with **Mistral Large 3 675B** (sparse MoE, Pixtral vision encoder, NVFP4 weights) on **4× H200 (Hopper/sm_90a)**.

The error is slightly different from the `fetch_images` AttributeError that #45180 targeted — we hit a `ValueError` wrapping an underlying exception during vLLM's dummy warmup profiling:


The `return_tensors=None` being passed to the HF processor during dummy profiling looks like the root cause — the processor expects `'pt'` but receives `None`. This may be a separate regression from the `fetch_images` fix, or the `fetch_images` fix surfaced this next crash.

**Reproduction config:**
- vLLM: `v0.23.0`
- Model: `registry.redhat.io/rhai/modelcar-mistral-large-3-675b-instruct-2512-nvfp4:3.0` (Mistral Large 3, 675B total / 41B active MoE, Pixtral vision)
- Hardware: 4× H200 NVL (Hopper sm_90a), `--tensor-parallel-size=4`
- Relevant args: `--load_format=mistral --config_format=mistral --tokenizer_mode=mistral --limit-mm-per-prompt={"image": 1} --kv-cache-dtype=fp8`

**Workaround:** `--limit-mm-per-prompt={"image": 0}` (disables vision, model loads and serves text normally).
