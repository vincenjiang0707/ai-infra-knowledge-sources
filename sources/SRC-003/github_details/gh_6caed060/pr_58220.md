## Purpose

Add opt-in logical expert-routing statistics that work with or without Expert Parallel Load Balancing (EPLB). Users can inspect which experts receive assignments without enabling expert rearrangement or changing the routing policy.

Rebased on September 23, 2026 onto public `main` at `f9ad9dd6b495f7492fa975e0ac48164b090d99ad`.

## User experience

Use one collection configuration in either mode:

```bash
# Observe without balancing.
vllm serve MODEL --data-parallel-size 2 --enable-expert-parallel \
    --expert-load-stats-config '{"enabled":true,"log_interval":1000,"output_dir":"./expert-load"}'

# Collect the same statistics while balancing.
vllm serve MODEL --data-parallel-size 2 --enable-expert-parallel --enable-eplb \
    --expert-load-stats-config '{"enabled":true,"log_interval":1000,"output_dir":"./expert-load"}'
```

The JSONL schema and logical expert identity do not change with EPLB. Dotted CLI options and the equivalent Python configuration are supported. Existing `--eplb-config` policy, recording windows, and balancedness logging keep their current meaning.

```
- Interval summaries: per-layer expert counts, assignment totals, maximum/mean, and unused experts.
- Optional bounded per-layer/per-iteration JSONL traces, with sampling and layer selection.
- Rank-local source-token ownership; no observability all-reduce/all-gather or Prometheus expert-label expansion.
- Logical routing skew is distinct from physical EP-rank balance. Replication can improve physical balance without changing logical selections.
```

## Implementation and scope

Instrument non-monolithic `BaseRouter` target-model routing. Without EPLB, use a histogram kernel; with EPLB, fuse logical counting into the existing mapping traversal while retaining separate logical counters and preserving physical counters/sampling. Persistent buffers support graph replay; two asynchronous export slots bound buffering and keep writer waits off the inference thread. Slow exports drop trace samples with an explicit counter, not summary counts.

Disabled collection allocates no tracker or device/export resources. Enabled collection has instrumentation and export costs; no performance result is claimed.

Iteration IDs are local target-forward counters, not synchronized DP steps. Target verification tokens are included even if subsequently rejected; draft forwards, warmup, dummy calls, padding, and shared experts are excluded. Initial support is CUDA/non-monolithic routing; unsupported paths such as custom/monolithic routers, LoRA, DBO/ubatching, CP, and elastic EP fail closed. See the feature documentation for the complete scope and ownership semantics.

## Rebase compatibility

Preserve main's new pipeline-parallel warmup broadcast guard alongside expert-statistics warmup suppression: neither synthetic token broadcasts nor warmup expert counts are enabled during startup. Update the existing MRV2 EPLB test fixture with the disabled-by-default collection configuration and assert that enabling EPLB alone does not create a statistics tracker. Collection options, output schema, and kernels are unchanged by this rebase.
