## 正文

## What

Splits the `(L4) Pipeline + Context Parallelism` job (~40 min of pytest in one serial job, 8 recent `main` runs at 41–43 min wall against a 55 min timeout) into three named jobs: a 3-way hash-sharded `Pipeline Parallelism Models` job over a new `tests/distributed/pipeline_parallel/` folder, plus one-replica `CUDAGraph` and `DP V2` jobs. Existing NVIDIA test selection is unchanged: the monolith `test_pipeline_parallel.py` is split into per-family wrappers with the same 29 cases and the same params, and the split applies no `-k`/`-m`/`--ignore` filters.

## Old

One job per lane ran three pytest commands serially:

```
- `:nvidia: (L4) Pipeline + Context Parallelism` (`pipeline-context-parallelism-4-gpus`): `test_pp_cudagraph.py` (1 case), `test_pipeline_parallel.py` (29 cases, ~82% of the runtime), `v1/distributed/test_pp_dp_v2.py` (6 cases)
- `:amd: (MI250) Pipeline + Context Parallelism` (mirror of the above; the DP V2 file skips entirely on ROCm)
```

## New

| label | key | contents |
|---|---|---|
| :nvidia: (L4) Pipeline Parallelism Models Shard %N | `pipeline-parallelism-models-4-gpus`, `parallelism: 3` | `tests/distributed/pipeline_parallel/` (29 cases, pytest-shard) |
| :nvidia: (L4) Pipeline Parallelism CUDAGraph | `pipeline-parallelism-cudagraph-4-gpus` | `distributed/test_pp_cudagraph.py` (unchanged) |
| :nvidia: (L4) Pipeline Parallelism DP V2 | `pipeline-parallelism-dp-v2-4-gpus` | `v1/distributed/test_pp_dp_v2.py` (same six scenarios) |
| :amd: (MI250) Pipeline Parallelism Models Shard %N | generated `amd-pipeline-parallelism-models-4-gpus` | mirror, `parallelism: 4`, inherits the shard flags |
| :amd: (MI250) Pipeline Parallelism CUDAGraph | generated `amd-pipeline-parallelism-cudagraph-4-gpus` | mirror, one replica |
| :amd: (MI355) Pipeline Parallelism DP V2 | generated `amd-pipeline-parallelism-dp-v2-4-gpus` | mirror, all six cases with V2 and AITER enabled |

All three jobs created by the split now have AMD mirrors. The DP V2 shared suite accepts CUDA and ROCm; its engine arguments, assertions, and six scenarios remain unchanged. Only the AMD CI command sets `VLLM_USE_V2_MODEL_RUNNER=1 VLLM_ROCM_USE_AITER=1`. Its four-GPU MI355 job runs the original PP=2, DP=2, TP=1 configuration with expert parallelism disabled.

This does not add inline mirrors to the existing Distributed 2-Node or RayExecutorV2 jobs updated by the file move. RayExecutorV2 retains its separate legacy MI300 job.

Monolith split (`tests/distributed/test_pipeline_parallel.py` deleted):

```text
tests/distributed/pipeline_parallel/
├── __init__.py
├── _common.py                        # settings machinery, model catalog, _compare_tp — not collected
├── test_llama_mp.py                  # Llama-3.2-1B-Instruct detailed, mp backend (5)
├── test_llama_ray.py                 # Llama-3.2-1B-Instruct detailed, ray backend (5)
├── test_phi3_5_moe.py                # Phi-3.5-MoE detailed, multi_node_only (10)
├── test_language_generation.py       # Ilama / PowerLM / DeepSeek-V2-Lite / Jamba (4)
├── test_language_embedding.py        # e5-mistral / bge-multilingual-gemma2 (2)
└── test_multimodal_generation.py     # InternVL3 / Phi-3.5-vision / ultravox (3)
```

Forced consumers of the shared file move with it:

- `(L4) Distributed 2-Node` now runs `VLLM_MULTI_NODE=1 pytest -v -s distributed/pipeline_parallel/` (whole folder; same cases run/skip as before).
- `(L4) RayExecutorV2` replaces `pytest distributed/test_pipeline_parallel.py -k "ray"` with `pytest -v -s distributed/pipeline_parallel/test_llama_ray.py`. The only ray-backend cases that actually run on a single node are Llama's (the Phi-3.5-MoE ray cases are `multi_node_only` and skip), so effective coverage is unchanged and the `-k` filter is gone.
- Legacy `test-amd.yaml` (`amd-ci` pipeline): the MI250 Pipeline + Context Parallelism step runs the whole folder unsharded (fits its 90 min timeout), and the MI300 RayExecutorV2 step runs `test_llama_ray.py`. DP V2 moves from the skip-only MI250 command to a dedicated MI355 four-GPU job with the same AMD settings as the inline mirror.
- CODEOWNERS entry updated to the folder.

## AMD DP V2 validation

The follow-up was validated on four local MI355 GPUs at the PR head:

```bash
HIP_VISIBLE_DEVICES=0,1,2,3 VLLM_USE_V2_MODEL_RUNNER=1 VLLM_ROCM_USE_AITER=1 \
  .venv/bin/python -m pytest -v -s tests/v1/distributed/test_pp_dp_v2.py \
  --timeout=900 --durations=6
```

Result: **6 passed** on four MI355 GPUs in 261.07 seconds (0:04:21), using the original test scenarios and assertions. Logs confirm V2 Model Runner and ROCm AITER Unquantized MoE selection. The 32 reported warnings are dependency deprecations.

Pre-commit passed for all three follow-up files, including YAML, Buildkite keys, test tethering, and Python checks. Structural comparison against the preceding PR commit confirms that all shared test scenarios and NVIDIA job definitions are unchanged apart from the added mirror. No production code or model outputs changed, so a separate accuracy evaluation was not required. This follow-up extends the same PR; #57735 concerns dependency metadata rather than enabling AMD execution. OpenAI Codex assisted with the AMD follow-up and validation.

- Before: ~40.5 min pytest in one job (~42 min wall) on the primary lane; the mirror ran ~44 min pytest (~46-54 min wall) with the DP V2 file skipped.
- After: NVIDIA model coverage uses three shards and the MI250 mirror uses four shards, alongside separate CUDAGraph and DP V2 jobs. All three split jobs have AMD coverage.
- The earlier aggregate-cost estimate assumed three AMD model shards and excluded an executing AMD DP V2 job. Aggregate cost and end-to-end timing for the final topology need confirmation in the validation build. Local MI355 timing above covers the DP V2 payload only.
