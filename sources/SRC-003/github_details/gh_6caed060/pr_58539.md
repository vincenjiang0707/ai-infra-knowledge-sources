# [PR #58539] [ROCm][DSv4.1][Perf] Use the shared prefill chunk plan in the ROCm sparse prefill

## 正文

## Purpose

`DeepseekV41ROCMAiterMLAAttention._forward_prefill` splits prefill requests into fixed groups of `PREFILL_CHUNK_SIZE = 4` and sizes the bf16 gather workspace from the static worst case (`N = ceil(max_model_len / compress_ratio)`, `M = N + window_size + max_num_batched_tokens`). The NVIDIA V4.1 paths already use `DeepseekSparseSWAMetadata.get_prefill_chunk_plan()`, which packs requests by workspace area and returns each chunk's real widths.

This PR drives the ROCm V4.1 prefill loop from the same plan. As on NVIDIA, it passes `has_compressed=not swa_only`, because ratio-1 layers carry a compressed region. Each chunk's KV is a `(chunk_size, chunk_M, head_dim)` view of the single prefill workspace, which also holds the MXFP8 staging rows, and `chunk_N` / `chunk_M` go to the SWA gather and `combine_topk_swa_indices`.

The ROCm V4.1 combine runs two `torch.repeat_interleave` calls per chunk, each forcing a host sync, so steps with more than 4 prefill requests gain the most. Peak memory is unchanged: the plan's area bound equals the worst case that `forward_mqa()` already reserves during warmup. Decode is unchanged, and steps with at most 4 prefills still run as a single chunk.

The same change for DeepSeek-V4 is #58405. #56720 touches this loop and composes with it.
