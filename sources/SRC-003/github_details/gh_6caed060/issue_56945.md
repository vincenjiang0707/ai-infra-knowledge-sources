### 🐛 Describe the bug

I've been benchmarking single-user (batch 1) decode of Qwen3.5-122B-A10B-FP8 on rented AMD cards, mostly out of curiosity. The numbers I got from the official ROCm 10 image were a long way below what the same card does with two switches, and neither switch is discoverable from the image or the startup log, so I wanted to write it up with the measurements.

**The bug:** the `rocm/vllm` image doesn't set `VLLM_ROCM_USE_AITER`, so out of the box a gfx942 or gfx950 card runs the Triton FP8 MoE and `ROCM_ATTN`. On this model that is 57 / 49 / 26 tok/s at ~200 / ~2k / ~12k prompt tokens on an MI325X — it loses half its speed across that context range — against **98 / 98 / 97** with `VLLM_ROCM_USE_AITER=1 --attention-backend ROCM_AITER_UNIFIED_ATTN`: 1.7× at short prompts, 3.7× at 12k. Same on an MI300X and an MI355X.

Common flags:

```
vllm serve Qwen/Qwen3.5-122B-A10B-FP8 --port 8000 --gpu-memory-utilization 0.85 --max-model-len 32768 \
  --kv-cache-dtype fp8 --max-num-seqs 64 --no-enable-prefix-caching
```
(`--max-num-seqs 64` because the default 1024 exceeds the Mamba block budget on the 192 GB card.)

| cell | env / extra flags | attention (from the log) | MoE (from the log) |
|---|---|---|---|
| stock | — | `Overriding with ROCM_ATTN out of ['ROCM_ATTN', 'ROCM_AITER_UNIFIED_ATTN', 'TRITON_ATTN']` | `TRITON Fp8 MoE` |
| aiter | `VLLM_ROCM_USE_AITER=1` | `Overriding with ROCM_ATTN out of ['ROCM_ATTN', 'ROCM_AITER_FA', 'ROCM_AITER_UNIFIED_ATTN', 'TRITON_ATTN']` | `AITER Fp8 MoE` |
| aiter-ua | `VLLM_ROCM_USE_AITER=1 --attention-backend ROCM_AITER_UNIFIED_ATTN` | `ROCM_AITER_UNIFIED_ATTN` | `AITER Fp8 MoE` |
| aiter-mtp | `VLLM_ROCM_USE_AITER=1 --speculative-config '{"method":"mtp","num_speculative_tokens":1}'` | `ROCM_ATTN` | `AITER Fp8 MoE` |
| aiter-ua-mtp | as aiter-ua + the speculative config | target: `ROCM_AITER_UNIFIED_ATTN`; **drafter: `Overriding with ROCM_ATTN`** (logged right after "Loading drafter model...") | `AITER Fp8 MoE` |

The AITER MoE alone is worth 1.7× at short prompts with no other change; the attention backend decides the shape over context. Both attention backends end up with the same ~4,200-token attention block after the Mamba page-size alignment (`Setting attention block size to 4176/4224 tokens to ensure that attention page size is >= mamba page size`), so it isn't the block size — it's `ROCM_ATTN`'s decode at that block size with a long KV. MTP acceptance is the same on either backend (mean acceptance length 1.76–1.81 in `SpecDecoding metrics`). A few `Autotuning failed with out of resource: shared memory` lines show up on the unified backend at startup (Triton autotune candidates over 64 KB); harmless for the result as far as I can see.

Two related things that I think are already tracked — numbers here in case they help:

```
- With AITER on, attention is still auto-assigned `ROCM_ATTN`. Every override line is preceded by `Found incompatible backend(s) [TURBOQUANT] with AttentionType.DECODER.`, and `ROCM_ATTN` is first in the candidate list — that looks like #46596's priority order. For this hybrid GDN model the difference is the whole context-length shape: `ROCM_ATTN` decays (96.6 → 32.4) and the unified backend is flat (97.9 → 97.4).
- With MTP, `--attention-backend` reaches the target but the drafter logs the override again and runs `ROCM_ATTN` — the silent version of #55312 (the draft autoselects independently of the target). I think that's why the last row still loses 17–22 % from 200 to 12k while the non-speculative unified row loses nothing; I haven't found a way to set the drafter's backend to check.
```

**What I'd hope for:** the `rocm/vllm` image (or its docs) defaulting `VLLM_ROCM_USE_AITER=1` on gfx942 / gfx950, or at least a startup hint when AITER is available and off — it's 1.7× on this model with no other change, and nothing in the log suggests it exists. The backend priority and the drafter are #46596 and #55312.

**Workaround** for anyone landing here: `VLLM_ROCM_USE_AITER=1 vllm serve ... --attention-backend ROCM_AITER_UNIFIED_ATTN`.

I have the full server logs for every cell on all three cards (backend-selection lines, block-size lines, the drafter override) — happy to attach or re-run.
