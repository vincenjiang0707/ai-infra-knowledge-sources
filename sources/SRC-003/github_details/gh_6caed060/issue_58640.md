### 🐛 Describe the bug

vLLM does not ship a dedicated parser for DeepSeek V4.1 Flash, and reuses the existing V4 parser to process model outputs generated by V4.1 Flash.
DeepSeek V4.1 Flash introduces an extra leading space inside DSML tags compared to the V4 specification. This difference triggers multiple failures in the legacy V4 parser:

1. The state machine for DSML tag matching fails to recognize tags due to the unexpected leading space.
2. The hardcoded regular expressions used in `_dsml_arg_converter` cannot match the parameter content, as the regex patterns do not account for the leading space.
3. The argument delta filtering logic with `arg_structural_chars=frozenset(">")` buffers all delta content that does not contain the `>` character and suppresses incremental streaming delivery.

As a combined result, tool call arguments cannot be streamed back to the caller.
The proposed fix is to implement a new V4.1-specific parser inheriting from the V4 parser class: adjust tag definitions and regular expressions to accommodate the leading space, disable the arg delta filtering logic, and register the parser under an independent name.
