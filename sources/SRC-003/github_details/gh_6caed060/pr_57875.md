## Purpose

Implement the Part D frontend/API split from #56542 on top of #57460.

`POST /start_profile` now accepts three optional per-session controls in both Python and Rust frontends:

- `profile_prefix`
- `delay_iterations`
- `max_iterations`

The same options are available through the Python `LLM` and `AsyncLLM` APIs. Worker profiler wrappers remain reusable across sessions while each session can select its own output name and iteration bounds.

For reviewer, main behavioral/logic changes are in
- `wrapper.py`: per-session overrides, output names, duplicate start handling
- `async_llm.py`: frontend CPU-profiler handling
- `api_router.py`: request parsing/validation and backwards compatible dispatch
- `gpu_worker.py`: validation + applying overrides
- `routes/profiles.rs, state.rs`: rust side equivalent of API/session handling

## Reviewed behavior and compatibility

- Unknown request fields are ignored so `vllm bench serve --profile` completion-shaped payloads remain compatible.
- A second start before an explicit stop returns HTTP 409 instead of silently discarding the new options. Notably this is different from previous behavior (allows duplicate start, 2nd start is ignored if profiler is running). I think once we introduce per-session overrides, this convention makes more sense.
- Iteration bounds apply to worker profiling. The frontend CPU profiler runs until `/stop_profile`, which remains required after worker auto-stop.
- New worker RPC arguments are keyword-only and sent only when supplied, preserving ordinary calls to out-of-tree workers.
- `ProfilerConfig.should_profile_frontend` centralizes frontend eligibility for Torch CPU activity.
- Profile prefixes are validated consistently by the Python and Rust frontends.
- the summary table `profiler_out_{i}.txt` also uses the prefix so output from later sessions doesn't override previous ones.

verify per-session overrides produce expected traces
```
run_session() {
  prefix=$1
  delay=$2
  max=$3

  curl -fsS -X POST http://localhost:8000/start_profile \
    -H 'Content-Type: application/json' \
    -d "{\"profile_prefix\":\"$prefix\",
         \"delay_iterations\":$delay,
         \"max_iterations\":$max}"

  curl -fsS http://localhost:8000/v1/completions \
    -H 'Content-Type: application/json' \
    -d "{\"model\":\"$MODEL\",
         \"prompt\":\"Profile this request\",
         \"max_tokens\":16,
         \"ignore_eos\":true}" >/dev/null

  curl -fsS -X POST http://localhost:8000/stop_profile
}

run_session short 0 2
run_session long 2 5

# requests successful and generated 2 different traces + summary with the expected names
/tmp/vllm-profile-rust# ls
long_rank0.1790014672781277722.pt.trace.json.gz  long_rank0.profiler_out.txt  short_rank0.1790014671642916536.pt.trace.json.gz  short_rank0.profiler_out.txt
```
