## Overview

(DISCLAIMER: I USED THE NEW SKILL TO HAVE GPT-6 AUTHOR THE PR DESCRIPTION BELOW, COMMIT THE CHANGES AND OPEN THIS PR. TREAT IT AS A REVIEWABLE EXAMPLE ARTIFACT. ALL CODE CHANGES WERE HAND WRITTEN WITH CARE BY ME.)

Add a `pr-checklist` skill for coding agents preparing, reviewing, or revising
vLLM pull requests. Integrate it with the agent contribution instructions and
the PR template.

## Claims

- Provide a structured review workflow covering design fit, compatibility,
  complexity, tradeoffs, validation, test quality, code clarity, and PR evidence.
- Distinguish validation performed for a contribution from tests maintained in
  the repository, emphasizing meaningful coverage rather than test volume.
- Include guidance for human-in-the-loop review and responding to prior feedback.
- Require agents to use the skill before submission through `AGENTS.md`.
- Restructure the PR template around Overview, Claims, Validation, and Details,
  with checklist and AI-assistance disclosure fields.

The intended benefit is better-prepared contributions and less avoidable
maintainer follow-up. This PR does not claim a measured reduction in review
rounds or review time.

## Validation

model, kernel, dependency, or runtime behavior is modified; runtime tests,
model evaluations, and performance benchmarks are not applicable.

## Details

### Motivation and research

The drafting process examined the latest 50 vLLM PRs reviewed by each of
`benchislett` and `mgoin`, ordered by the reviewer's latest submitted review.
The samples contain 97 distinct PRs and 342 nonempty authored review/comment
messages. Recurring themes included compatibility across execution paths,
appropriate ownership and reuse, concise implementations, meaningful rather
than excessive tests, and claims supported by evidence.

A separate exploratory analysis measured additions and deletions under
`vllm/` and compared them with description-based complexity grades. It
reinforced that LOC is a coarse review aid, not a reliable standalone semantic
complexity classification. The skill's 50/250 bands are judgment-based
guidance, not validated predictive cutoffs.

The research artifacts are local preparation material and are not included
in this PR. The proposed skill was handwritten and iteratively refined by
the human author with AI-assisted research and review.

### Duplicate-work checks

Open-PR searches were run on September 15, 2026:

```bash

  --search '"pr-checklist"' --limit 30 --json number,title,url,headRefName

  --search '"skill" "review"' --limit 30 --json number,title,url,headRefName

  --search 'checklist in:title' --limit 30 --json number,title,url

gh pr list --repo vllm-project/vllm --state open \
  --head 'benchislett:skill-pr-checklist' --json number,title,url
```

The broad searches returned unrelated PRs mentioning review or checklist
usage. Targeted title searches found checklists for tool-calling models and
server hardening, and skills for CI and installation; none appeared to
duplicate this general contribution-review workflow. No existing open PR
was found for this branch. No associated issue was supplied, so issue-specific
duplicate checks were not applicable.
