# [PR #58546] [Perf][MoE] Tile pack_bitmatrix by 32 rows instead of 512

source: https://github.com/vllm-project/vllm/pull/58546
state: open | updated: 2026-09-25T01:46:29Z

## 正文

## Purpose

`make_routing_data` launches `pack_bitmatrix` with `BLOCK_SIZE_M = 512`. The kernel masks its row tail on both the load and the store, so the packed bitmatrix is bit-identical for any tile width; the tile width is purely a launch-config choice. It is a bad one: the cost of each program is dominated by the `[BLOCK_SIZE_M, BLOCK_SIZE_K]` one-hot `tl.where` / `tl.reduce_or`, which Triton emits at full tile width whether or not those rows exist. A 512-row tile therefore pays for padding rows at every batch size, and for any batch of up to 512 tokens (every decode step at realistic concurrency) it collapses the grid to a single workgroup. This PR changes the tile to 32 rows, matching `BLOCK_SIZE_K`.

**Who reaches this.** `make_routing_data` runs once per MoE layer per step wherever the OAI Triton experts rebuild routing from top-k ids on triton_kernels 3.5.1/3.6:

```
- **DeepSeek-V4 on MI300X/MI325X (gfx942), with the recommended `VLLM_ROCM_USE_AITER=1`.** `AiterExperts` rejects MXFP4 weights off gfx950, so DeepSeek-V4's ROCm candidate list (`[AITER_MXFP4_BF16, TRITON_UNFUSED]`) falls through to `TRITON_UNFUSED`, and `UnfusedOAITritonExperts` calls `make_routing_data` unconditionally. With AITER off, gfx942 cannot run DeepSeek-V4 at all (the sparse-attention indexer requires AITER there), so this is the only configuration.
- gpt-oss on the OAI Triton path under expert parallelism (TP=1 bypasses it since #45457), and anything that explicitly selects `--moe-backend triton` / `triton_unfused`.
```

**Not affected:** gfx950 with AITER on (DeepSeek-V4 and gpt-oss both select AITER MoE backends there); triton_kernels 3.8 (the `Dockerfile.rock` image), whose `make_routing_data` builds routing in torch and never launches `pack_bitmatrix`; and eager mode / prefill, where the call is host-bound.

**Related:** #43159 rewrites `pack_bitmatrix` itself and adds a runtime-compiled (`load_inline`) HIP fast path. It leaves `BLOCK_SIZE_M = 512` in `make_routing_data`, and its Triton fallback still defaults to 512, so the two compose: this PR is the one-constant change on its own and is useful whether or not #43159 lands.
