## Bug: `Expected slot_mapping to be a dict, got <class 'list'>`

### Environment
- vLLM nightly `0.23.1rc1.dev471+ge312c5cb2`
- NVIDIA H200 GPUs, EP16 (2 nodes × 8 GPUs)
- Model: GLM-5.2-FP8 (753B MoE) with MLA (DEEPSEEK_V32_INDEXER / FLASHMLA_SPARSE)
- MTP speculative decoding: `--speculative-config '{"method":"mtp","num_speculative_tokens":1}'`
- All2all backend: `deepep_low_latency`

### Description

During KV cache initialization, MTP creates ubatch slices that cause `slot_mapping` to be returned as `list[dict[str, torch.Tensor]]` instead of `dict[str, torch.Tensor]`. Both `mla_attention.py` and `attention.py` assert that `slot_mapping` is a dict, causing a crash.

The `attn_metadata` handling 10 lines above already handles this exact pattern correctly (list vs dict), but the same handling was not applied to `slot_mapping`.

```
RuntimeError: Worker failed with error 'Expected slot_mapping to be a dict, got <class 'list'>. '
```

### Root Cause

Introduced in commit b4a6f26c (`[ROCm][perf] Use workspace manager for sparse indexer allocations`, PR #41002) which created `mla_attention.py` as shared code with the strict assert, without accounting for the MTP ubatch `list[dict]` case.

### Affected Files

```
- `vllm/model_executor/layers/attention/mla_attention.py` (line 583)
- `vllm/model_executor/layers/attention/attention.py` (line 706)
```

### Suggested Fix

Apply the same pattern already used for `attn_metadata` (lines 572-577 in `mla_attention.py`, lines 695-700 in `attention.py`):

```python
# mla_attention.py, after line 581:
slot_mapping = forward_context.slot_mapping
if isinstance(slot_mapping, list):
    slot_mapping = slot_mapping[0]

# attention.py, after line 705:
slot_mapping = forward_context.slot_mapping
if isinstance(slot_mapping, list):
    slot_mapping = slot_mapping[0]
```
