# [PR #58287] [Bugfix] Disable prefix caching for encoder-only before model config hooks

source: https://github.com/vllm-project/vllm/pull/58287
state: open | updated: 2026-09-23T07:14:07Z
labels: bug

## 正文

## Summary

An `--mm-encoder-only` instance runs no language model and holds no KV cache, so `VllmConfig.__post_init__` forcibly disables prefix caching for it. That override ran **after** `try_verify_and_update_config()`, where any `is_hybrid` (attention+mamba) model sets `mamba_cache_mode="align"` / `mamba_block_size=block_size` based on the stale "prefix caching on" value (`HybridAttentionMambaModelConfig` → `MambaModelConfig`). The later `validate_mamba_block_size()` then rejects the derived state:

```
Value error, --mamba-block-size can only be set with --enable-prefix-caching
```

So every hybrid VLM crashes on startup under `--mm-encoder-only` with default flags; the only workaround is explicitly passing `--no-enable-prefix-caching`.

**Fix:** move the encoder-only prefix-caching disable to right after `_resolve_mm_encoder_only()`, before any model config hook runs. One block moved, no logic change.

```
Reproduced with `--mm-encoder-only` + default flags:
- Kimi-K3-pruned75: `ValueError` at startup
- Qwen3.5-VL (Qwen3_5ForConditionalGeneration): `ValueError` at startup
```

After the fix, both start cleanly with default flags; `mamba_cache_mode` resolves to `none` and `mamba_block_size` to `max_model_len`, matching the intended "prefix caching off" state.

## Test Plan

```
- `VllmConfig` construction with a hybrid model + `mm_encoder_only=True` + default prefix caching: previously `ValueError`, now passes (`enable_prefix_caching=False`, `mamba_cache_mode='none'`).
- End-to-end `vllm serve --mm-encoder-only` on Qwen3.5-VL and Kimi-K3 with default flags: previously crashed at config validation, now reaches "Application startup complete".
```
