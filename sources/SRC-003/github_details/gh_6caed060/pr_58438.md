## 正文

## Purpose

The current `structured_diffusion.py` server sends four identical requests in sampling mode and this works only because the engine itself is non-deterministic. If the upstream kernels end up becoming deterministic, the sampler will silently degrade.

How it works now: the current approach to sampling requires 1+N requests in auto mode (N=3), and N requests when explicitly specified. We can instead dispatch N requests in the server which can skip extra tokenization, prefix lookup, etc and individual response serialization. Then, the pinned positions are the noise template for multiple requests, and the children come back as k choices of one response.

The random draws are reproducible: a request seed reaches the children as seed + index, as it does for n, and a child with a seed draws its noise from a generator seeded with it.

The example structured server sends a fixed sample count this way with the schema seed, and keeps the auto policy on separate requests; --no-engine-samples restores the old behaviour for comparison. The diagnostics report the number of upstream requests beside the number of reads.

## Test Plan

Run the existing `structured_server.py`, test performance of "auto" and explicit "N" samples parameters.

## Test Results

With no additional load, timing is identical as requests are scheduled in parallel:

| test | time |
|--|--|
| 1 draw, cold prefix	| 112 ms |
| 4 draws as 4 concurrent requests, warm prefix	| 143 ms |
| 4 draws as one request, warm prefix	| 144 ms |
| 4 draws as 4 requests, cold prefix	| 188 ms |
| 4 draws as one request, cold prefix	| 187 ms |

This yields _slightly_ higher throughput near max server concurrency:

```
32 requests x 4 draws (diffusion_samples)    wall median   1215 ms (rounds [1298, 1215, 1174])  per-request median   765 ms  p90  1202 ms    26.3 answers/s   105.3 draws/s
128 requests x 1 draw (32 prompts x 4)       wall median   1292 ms (rounds [1314, 1217, 1292])  per-request median   785 ms  p90  1249 ms    24.8 answers/s    99.0 draws/s
```
