# [PR #57648] [Bugfix][DP] add_dp_placement_groups does not require ray[default]

## 正文



## Purpose

Follow-up to #23822.

That PR removed the `ray.util.state.list_nodes()` call from `CoreEngineActorManager.create_dp_placement_groups()` because `list_nodes()` is a developer API backed by the Ray dashboard HTTP server (`127.0.0.1:8265/api/v0/nodes`), which only exists when Ray is installed as `ray[default]` and started with the dashboard. vLLM does not depend on `ray[default]`.

The sibling `add_dp_placement_groups()` (used by `scale_up_elastic_ep()` for elastic EP scale-up) still called `list_nodes()`, so `/scale_elastic_ep` fails with `Failed to connect to API server` on any Ray cluster started without the dashboard, e.g. `ray` core only or `ray start --include-dashboard=False`. Downstream projects have had to monkeypatch `ray.util.state.list_nodes` around the call to work around this (NVIDIA Dynamo, `components/src/dynamo/vllm/handlers.py`, `TODO(upstream-vllm)` block in `scale_elastic_ep`).

This PR applies the same fix as #23822 to `add_dp_placement_groups()`:

- Drop the `ray.util.state.list_nodes` import.
- Use `available_resources_per_node()` (already imported there, keyed by node id, live nodes only) to enumerate nodes, and locate the DP master node via its `node:<dp_master_ip>` resource key, exactly as `create_dp_placement_groups()` does today.
- Read each node's IP with the existing `_node_ip_from_resources()` helper.

Placement group bundles, names (`dp_rank_{rank}`), strategy (`STRICT_PACK`), and the local DP rank computation are unchanged. The old "there can only be one head node" check is kept.
