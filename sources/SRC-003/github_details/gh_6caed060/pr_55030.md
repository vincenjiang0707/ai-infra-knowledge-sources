# [PR #55030] [Bugfix] Account for PCP when validating DCP for GQA/MQA models

## 正文

## Purpose

Fixes #51429.

`ParallelConfig` accepts `decode_context_parallel_size in (1, pcp, tp * pcp)` when prefill context parallelism is enabled, and `initialize_model_parallel` lays the DCP groups out over the PCP axis first. `ModelConfig.verify_with_parallel_config` then rejects that same topology for GQA/MQA models whenever `tensor_parallel_size <= total_num_kv_heads`, because it only counts TP-induced KV head replication as duplication for DCP to reclaim. So a topology one layer documents as valid cannot be started, and the error message (`Increase --tensor-parallel-size`) points at the wrong knob.

PCP replicates the full KV cache on every PCP rank (K/V are all-gathered across the PCP group), so a DCP group that spans the PCP axis always has duplication to reclaim. This PR:

```
- computes the DCP ceiling as `max(1, tp // num_kv_heads) * pcp` instead of `tp // num_kv_heads`, and only raises the "no duplication source" error when both TP and PCP contribute nothing;
- applies the query-heads-per-KV-head divisibility check to the TP-spanning part of DCP (`dcp // pcp`) rather than the whole DCP size, since ranks along the PCP axis hold identical query heads (the attention backends all-gather queries across the DCP group and run them against the local KV heads, which are the same on every PCP rank);
- mentions `--prefill-context-parallel-size` in the error messages.
```

Behaviour with `pcp == 1` is unchanged: the ceiling collapses to `tp // num_kv_heads` and the divisibility check to `num_q_per_kv % dcp`.

Note on reachability: in-tree PCP is currently MLA-only (`pcp_manager.py` raises for non-MLA models and no non-MLA backend sets `supports_pcp`), and this guard is skipped for MLA. So today the relaxed path is exercised by out-of-tree backends (we hit it on TPU, where PCP shards the KV cache and `dcp == pcp` is how the block accounting is kept consistent). The fix is still worthwhile as platform-independent config validation: `ParallelConfig` already accepts the topology, and the old message pointed at the wrong knob.

### Relationship to #51490

#51490 (by @mayuriphad) addresses the same issue and I'd be glad for either to land. This PR differs in that it:

1. also generalises the query-head divisibility check, which #51490 leaves keyed on the full DCP size. With that check unchanged, a model with 3 query heads per KV head still fails at `pcp = dcp = 2` even though no query heads are split along the DCP group.
2. adds the regression tests to `tests/test_config.py` next to the existing DCP config tests, and builds a real `ParallelConfig` in them so the test asserts that both validation layers accept the same topology.

I wrote the original issue and am the human submitter for this change; I have reviewed every changed line. AI assistance was used for this PR.
