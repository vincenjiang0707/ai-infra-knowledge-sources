# [Issue #58158] [Bug]: v0.30 dependencies raise the effective compiler floor above GCC 11.3

state: open | updated: 2026-09-22T15:06:37Z

## 正文

## Summary

vLLM v0.30.0's declared source-build floor remains GCC/G++ >= 11.3, but multiple pinned dependencies now require C++20 `<format>` / `std::format`. With libstdc++, that raises the effective GCC floor to GCC 13.

This is broader than the first observed DeepSelect failure: the DeepGEMM revision pinned by v0.30.0 independently uses `<format>` in host code that is included unconditionally when building its Python extension.

## Declared vLLM contract

vLLM both enforces GCC >= 11.3 and recommends installing GCC 11 on Ubuntu 22.04:

```
- https://github.com/vllm-project/vllm/blob/v0.30.0/CMakeLists.txt#L23-L29
- https://github.com/vllm-project/vllm/blob/v0.30.0/docs/getting_started/installation/gpu.cuda.inc.md#L140-L149
```

## DeepSelect: first observed failure

vLLM pins DeepSelect commit `d96d33afe1fab0d6066da49cdc91e64c2bee65ea`:

- https://github.com/vllm-project/vllm/blob/v0.30.0/cmake/external_projects/deepselect.cmake#L19-L22

That revision includes `<format>` and uses `std::format` once to construct a stride-validation error message:

```
- https://github.com/vllm-project/DeepSelect/blob/d96d33afe1fab0d6066da49cdc91e64c2bee65ea/csrc/api.cpp#L15-L19
- https://github.com/vllm-project/DeepSelect/blob/d96d33afe1fab0d6066da49cdc91e64c2bee65ea/csrc/api.cpp#L89-L97
```

With GCC 11.4 and `-std=c++20`, compilation stops at:

```text
csrc/api.cpp:17:10: fatal error: format: No such file or directory
   17 | #include <format>
      |          ^~~~~~~~
```

Root-upstream tracking and the proposed portable replacement are available here:

```
- https://github.com/deepseek-ai/DeepSelect/issues/21
- https://github.com/deepseek-ai/DeepSelect/pull/22
```

## DeepGEMM: independent compiler-floor drift

vLLM v0.30.0 pins `vllm-project/DeepGEMM` commit `e1f418c2a4f20818221f6b0e578b4c2f634d4c3f`:

- https://github.com/vllm-project/vllm/blob/v0.30.0/cmake/external_projects/deepgemm.cmake#L30-L36

That exact pinned tree also requires `<format>`:

```
- `csrc/apis/attention.hpp` includes `<format>`, includes the SM100 sparse-MQA implementation, and uses `std::format`:
  - https://github.com/vllm-project/DeepGEMM/blob/e1f418c2a4f20818221f6b0e578b4c2f634d4c3f/csrc/apis/attention.hpp#L1-L15
  - https://github.com/vllm-project/DeepGEMM/blob/e1f418c2a4f20818221f6b0e578b4c2f634d4c3f/csrc/apis/attention.hpp#L64-L67
- `csrc/jit_kernels/impls/sm100_sparse_mqa_logits.hpp` includes `<format>` and uses `std::format` repeatedly to construct JIT source:
  - https://github.com/vllm-project/DeepGEMM/blob/e1f418c2a4f20818221f6b0e578b4c2f634d4c3f/csrc/jit_kernels/impls/sm100_sparse_mqa_logits.hpp#L1-L9
  - https://github.com/vllm-project/DeepGEMM/blob/e1f418c2a4f20818221f6b0e578b4c2f634d4c3f/csrc/jit_kernels/impls/sm100_sparse_mqa_logits.hpp#L82-L109
- `csrc/python_api.cpp` includes `apis/attention.hpp` unconditionally, so runtime architecture gating does not prevent the host compiler from parsing this code:
  - https://github.com/vllm-project/DeepGEMM/blob/e1f418c2a4f20818221f6b0e578b4c2f634d4c3f/csrc/python_api.cpp#L1-L15
```

DeepGEMM's own current requirements explicitly call for "Compilers and standard libraries with C++20 `<format>` support":

- https://github.com/vllm-project/DeepGEMM/blob/e1f418c2a4f20818221f6b0e578b4c2f634d4c3f/README.md#L24-L33

This source path did not produce the observed CI failure only because Ninja stopped after the earlier DeepSelect error. The pinned source and unconditional include chain show that fixing DeepSelect alone is insufficient for a GCC 11 build.

## What changed from v0.29.0

The known-good v0.29.0 build used GCC 11.4. Its DeepGEMM integration pinned the older `deepseek-ai/DeepGEMM` revision `8b1392b978f5a03c828dd1711090d7fb50958b8a`, before the linked sparse-MQA `<format>` code was present. DeepSelect was introduced in v0.30.0 as a new extension.

```
- v0.29.0 DeepGEMM pin: https://github.com/vllm-project/vllm/blob/v0.29.0/cmake/external_projects/deepgemm.cmake#L30-L34
- Known-good GCC 11.4 build: https://github.com/neuralmagic/nm-cicd/actions/runs/34346952915
- Failing v0.30.0 build: https://github.com/neuralmagic/nm-cicd/actions/runs/35729206971
```

## Compatibility decision needed

vLLM should make the declared and effective build contracts agree. The main options are:

```
1. Preserve GCC 11.3 compatibility by replacing or conditionally excluding incompatible `<format>` usage in all pinned host dependencies, then validate the minimum compiler in CI.
2. Intentionally raise the source-build requirement to a compiler and standard library with C++20 `<format>` support (GCC 13 for libstdc++), update the CMake guard and installation documentation, and validate that new floor in CI.
```

The DeepSelect PR above is still a useful portability fix, but it addresses only the first failure and does not resolve DeepGEMM's independent requirement.
