## 正文

### Your current environment

Image `vllm/vllm-openai:cu129-nightly` as published on 2026-09-14 (tag `cu129-nightly-dc36fcce902a63eab06c1b93a5c4a5ee178a0c56`, digest `sha256:e756ef831f09b7486420005c5bce7a028df9b6b68d77ed7b5e9020ac7aea7e01`, buildkite release-v2 build 6550). Host: Ubuntu, driver 615.71.09, 2x RTX PRO 6000 Blackwell (sm_120). Inside the image:

```
vllm        0.29.1rc1.dev47+gdc36fcce9
torch       2.14.0+cu130
torchvision 0.28.0+cu129
torchaudio  2.11.0+cu129
triton      3.8.0
CUDA_VERSION=12.9.1 (image env)
```

### 🐛 Describe the bug

`vllm serve` (any model) dies at import in the `cu129-nightly` image because torch is a **cu130** wheel while torchvision and torchaudio are **cu129** wheels built against torch 2.13:

```
  File "/usr/local/lib/python3.12/dist-packages/torch/library.py", line 496, in impl
    @torch.library.register_fake("torchvision::nms")
RuntimeError: operator torchvision::nms does not exist
```

`python3 -c "import torchvision.ops"` fails the same way; `import torchaudio` then reports "PyTorch has CUDA version 13.0 whereas TorchAudio has CUDA version 12.9".

Workaround that makes the image serve (verified with Qwen3.8-Flash-Next NVFP4, TP=2):

```
pip install --no-deps torchvision==0.29.0+cu130 torchaudio==2.11.0+cu130 --index-url https://download.pytorch.org/whl/cu130
```

So either the cu129 nightly picked up a cu130 torch by mistake, or torchvision/torchaudio were not bumped with it. Expected: the `cu129-nightly` tag ships a consistent cu129 torch/torchvision/torchaudio set (or, if cu130 is intended, matching vision/audio wheels).
