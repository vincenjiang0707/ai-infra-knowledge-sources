## 正文

## Purpose

- Fix #27894: SP + PP force-enabled `+rms_norm` since native rms_norm broke tracing
- Obsolete now: RMSNorm always traces as an opaque vLLM IR op
- IR lowering picks the impl after the SP pass, so shapes always match
- The append was also dead: fusion defaults resolve before it runs

## Test

```
- New regression test: SP + PP generation with `custom_ops=["-rms_norm"]`
- Manual repro from #27894 on 4x L4 (nightly wheel, TP2 x PP2): runs clean
- `+rms_norm` vs `-rms_norm` outputs bit-identical; matches TP-only baseline
```
