# [PR #58643] [Bugfix] Fix Rust frontend startup with config-only model

## 正文

## Purpose

Fix Rust frontend startup when the model is provided through `--config`.

When running:

```bash
VLLM_USE_RUST_FRONTEND=1 vllm serve --config config.yml
```

the resolved model is stored in `args.model`, while `args.model_tag` remains unset. The Rust frontend bootstrap requires `model_tag` in `--args-json`, causing startup to fail with:

```text
invalid JSON arguments: missing field `model_tag`
```

This was reproduced with `Qwen/Qwen3.5-35B-A3B` through the vLLM Recipes flow.

## Changes

- Fall back to `args.model` when `args.model_tag` is not set.
- Explicitly pass the resolved model as `model_tag` to the Rust frontend.
- Add a regression test for config-only model selection.

This keeps positional model behavior unchanged.

## Test Plan

```bash
python3 -m pytest -v \
  tests/entrypoints/launchers/api_server/test_api_server_process_manager.py \
  -k "rust_frontend"
```

Manual validation:

```bash
VLLM_USE_RUST_FRONTEND=1 \
vllm serve --config config.yml
```

Verify the Rust frontend `--args-json` includes:

```json
"model_tag": "Qwen/Qwen3.5-35B-A3B"
```

and the server starts without the `missing field model_tag` error.
