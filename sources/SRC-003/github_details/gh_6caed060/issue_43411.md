## 正文

### Your current environment

Since v0.18.0 (#36483), `OpenAIServingChat.__init__` requires a new keyword-only argument `openai_serving_render: OpenAIServingRender`. This is a silent breaking change for anyone constructing `OpenAIServingChat` directly. We are using KubeRay + Ray Serve + FastAPI encounter this issue.

### Code that worked on v0.17.0:

  ```python
  from vllm.engine.async_llm_engine import AsyncLLMEngine
  from vllm.engine.arg_utils import AsyncEngineArgs
  from vllm.entrypoints.openai.chat_completion.serving import OpenAIServingChat
  from vllm.entrypoints.openai.models.serving import OpenAIServingModels
  from vllm.entrypoints.openai.models.protocol import BaseModelPath

  engine = AsyncLLMEngine.from_engine_args(AsyncEngineArgs(model="Qwen/Qwen3-4B-Instruct-2507"))
  serving_models = OpenAIServingModels(
      engine_client=engine,
      base_model_paths=[BaseModelPath(name="my-model", model_path="Qwen/Qwen3-4B-Instruct-2507")],
      lora_modules=[],
  )

  OpenAIServingChat(
      engine,
      models=serving_models,
      response_role="assistant",
      request_logger=None,
      chat_template=None,
      chat_template_content_format="auto",
  )
  ```


 ### Error on v0.18.0+

  ```
  TypeError: OpenAIServingChat.__init__() missing 1 required keyword-only argument: 'openai_serving_render'
  ```

  ## Expected behavior

`openai_serving_render` should default to `None` with an internal auto-construction fallback so existing call sites keep working.

## Proposed Solution: OpenAIServingChat Silent Breaking Change

### Root Cause
PR #36483 added `openai_serving_render: OpenAIServingRender` as a required keyword-only argument to `OpenAIServingChat.__init__`, but did NOT provide a default value. This silently breaks all direct instantiation users (KubeRay + Ray Serve + FastAPI).

### Proposed Fix
**File**: `vllm/entrypoints/openai/chat_completion/serving.py`

```python
class OpenAIServingChat:
    def __init__(
        self,
        # ... existing params ...
        openai_serving_render: Optional[OpenAIServingRender] = None,  # ADD default
    ):
        if openai_serving_render is None:
            openai_serving_render = OpenAIServingRender()
        self.openai_serving_render = openai_serving_render
        # ... rest unchanged
```

### Key Changes
- `vllm/entrypoints/openai/chat_completion/serving.py`: Add `= None` default + auto-construction
- Add deprecation warning for future removal of default

Full solution: `solutions/vllm-43411-openaiservingchat-silent-breaking-change-fix.md`

I think the internal server path always constructs and passes `openai_serving_render` through `init_generate_state` so making it required made sense there. The users who got caught by this are exactly the ones building on top of these classes directly, they never go through that init path.
