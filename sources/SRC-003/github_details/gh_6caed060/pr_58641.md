## 正文

## Purpose

Harden the JIT build directory of the NCCL allocator wrapper (`vllm/distributed/device_communicators/pynccl_allocator.py`). Today the torch extension is compiled under a fixed name (`nccl_allocator`) directly in `tempfile.gettempdir()` and the resulting `.so` is dlopened without any checks. On multi-user machines the shared temp directory is world-traversable, so another local user can pre-create content at that fixed location; ninja then sees fresh-looking outputs and skips recompilation, and the victim process can end up loading a library it did not build — with the full authority of the vLLM process (GPU access, model weights) — or be permanently denied the feature. The build directory should be private to the user running vLLM.

This PR adds two layers, mirroring the existing weight-cache protocol pattern (`vllm/model_executor/model_loader/weight_cache/protocol.py`):

```python
1. **Per-user private build dir.** The extension is built under `<VLLM_CACHE_ROOT>/nccl_allocator/<key>/`, where `key = sha256(source, libname, ldflags, include paths, torch version)`. The directory is created `0700` and lstat-verified (no symlink, current-uid owner, no group/world bits on POSIX); when the cache root is unusable the code falls back to `tempfile.mkdtemp()`.
2. **Ownership check before dlopen.** Before `CUDAPluggableAllocator` loads the `.so`, the parent directory and the file are re-verified (regular file, no symlink, current-uid owner). Any failure takes the existing disable-with-warning path.
```

No public API change; compile timing and failure semantics are unchanged.
