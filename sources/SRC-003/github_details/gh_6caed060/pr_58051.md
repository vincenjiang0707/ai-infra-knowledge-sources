## Purpose

Under EP with a full routing table on every rank (`MoEPrepareAndFinalizeNoDPEPModular`, DeepEP high-throughput), `TritonExperts.apply` aligns with `ignore_invalid_experts=False`: slots whose expert lives on another rank still get M-blocks in both `fused_moe_kernel` launches (the `off_experts == -1` branch writes zeros), and `moe_sum` adds the zeros back. At EP degree `ep`, `(ep-1)/ep` of the launched M-blocks do no useful work.

This PR aligns with `ignore_invalid_experts=True` when an `expert_map` is set and no LoRA context is active, and reduces with the existing pad-aware `moe_sum(input, output, topk_ids, expert_map)` (#48385) whenever `expert_map` is set. `fused_marlin_moe` already pairs the two.

Scope: dropped slots leave their workspace rows unwritten, so the skip requires a row-local activation quantization for the second GEMM (unquantized, static `a2_scale`, block-wise, or native dynamic per-token). Dynamic per-tensor activation scales (e.g. non-blocked online `--quantization fp8`) and LoRA keep the dense path. `TritonWNA16Experts` is unchanged.
