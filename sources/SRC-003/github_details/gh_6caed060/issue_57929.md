### 🐛 Describe the bug

The non-streaming scale-out completions pipeline drops prompt log probabilities at the final derender step.

For the same request with `prompt_logprobs=1`:

- `/v1/completions` returns prompt log probabilities;
- `/v1/completions/render` requests them from the engine;
- `/inference/v1/generate` returns them in
  `GenerateResponse.prompt_logprobs`;
- `/v1/completions/derender` returns HTTP 200, but
  `choices[0].prompt_logprobs` is `null`.

The generated text and usage are otherwise correct, so the missing data can go unnoticed.

## Environment

- vLLM: `0.29.0`
- Model: `Qwen/Qwen2.5-0.5B-Instruct`
- GPU: NVIDIA L40S
- Request mode: non-streaming

The issue is also present in the current `main` implementation of `OnlineDerenderer._derender_completion`.

## Reproduction

Start a vLLM server with the scale-out endpoints enabled:

```bash
CUDA_VISIBLE_DEVICES=0 \
VLLM_USE_FLASHINFER_SAMPLER=0 \
vllm serve Qwen/Qwen2.5-0.5B-Instruct \
  --port 8029 \
  --gpu-memory-utilization 0.25 \
  --max-model-len 1024 \
  --enforce-eager \
  2>&1 | tee server.log
```

Run the reproducer [probe_vllm_0290_derender_prompt_logprobs.py](https://github.com/user-attachments/files/32463597/probe_vllm_0290_derender_prompt_logprobs.py):

```bash
python probe_vllm_0290_derender_prompt_logprobs.py \
  --base-url http://127.0.0.1:8029 \
  2>&1 | tee reproducer.log
```

The reproducer sends this request both through `/v1/completions` and through the split render/generate/derender pipeline:

```json
{
  "model": "Qwen/Qwen2.5-0.5B-Instruct",
  "prompt": "The capital of France is",
  "max_tokens": 1,
  "temperature": 0,
  "prompt_logprobs": 1
}
```

The split request flow is:

```text
/v1/completions/render
  -> /inference/v1/generate
  -> /v1/completions/derender
```

## Actual result

All requests return HTTP 200 and generate the same text, `" Paris"`.

```text
/v1/completions:
  choices[0].prompt_logprobs: 5 entries

/inference/v1/generate:
  prompt_logprobs: 5 entries

/v1/completions/derender:
  choices[0].prompt_logprobs: null
```

The prompt-logprob arrays returned by the direct endpoint and the generate endpoint are identical. Only the final derendered response loses them.

Full log are here: 
```
[logprobs_server.log](https://github.com/user-attachments/files/32463567/logprobs_server.log)
[reproducer.log](https://github.com/user-attachments/files/32463572/reproducer.log)
```

## Expected result

The derendered response should preserve the prompt log probabilities already present in each `GenerateResponse`:

```text
direct choice.prompt_logprobs
  == generate_response.prompt_logprobs
  == derendered choice.prompt_logprobs
```

## Root cause

`OnlineDerenderer._derender_completion()` builds each `CompletionResponseChoice` with `index`, `text`, `finish_reason`, and generated token `logprobs`, but it never copies `gen.prompt_logprobs` into the choice.

The field therefore falls back to its default value of `null`, even though the engine has already computed and returned it.

Clients using the scale-out pipeline for scoring, evaluation, ranking, or perplexity calculations silently receive an incomplete response. The engine still pays the cost of computing and serializing the requested prompt log probabilities.
