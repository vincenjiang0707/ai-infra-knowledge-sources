# [PR #58451] [CI] Shard (H200 MIG 35GB) PyTorch Compilation + (MI300) mirror into whole coverage units

## 正文

## What

Splits the `(H200 MIG 35GB) PyTorch Compilation` job into four named jobs — one per heavy test file plus the original job running the rest — and gives each of the four jobs its own `(MI300)` mirror. No test selection changes: every file still runs exactly once per lane, with no `-k`/`-m`/`--ignore` anywhere, and each file keeps its own pytest process (see #28965).

## Old

One job per lane ran all 13 flat `tests/compile/test_*.py` files serially via `find compile/ -maxdepth 1 ... | xargs -n1 pytest`:

```
- `:nvidia: (H200 MIG 35GB) PyTorch Compilation` (`pytorch-compilation-unit-tests`)
- `:amd: (MI300) PyTorch Compilation` (mirror of the above)
```

## New

| label | key | contents |
|---|---|---|
| :nvidia: (H200 MIG 35GB) PyTorch Compilation | `pytorch-compilation-unit-tests` (unchanged) | the 10 light files, one pytest command each |
| :nvidia: (H200 MIG 35GB) PyTorch Compilation / Dynamic Shapes | `pytorch-compilation-dynamic-shapes` | `test_dynamic_shapes_compilation.py` |
| :nvidia: (H200 MIG 35GB) PyTorch Compilation / Config | `pytorch-compilation-config` | `test_config.py` |
| :nvidia: (H200 MIG 35GB) PyTorch Compilation / AOT Compile | `pytorch-compilation-aot-compile` | `test_aot_compile.py` |
| :amd: (MI300) PyTorch Compilation (+ `/ Dynamic Shapes`, `/ Config`, `/ AOT Compile`) | `amd-<key>` of each job above (`mirror.amd`, unchanged key for the remainder) | same files as the NVIDIA job it mirrors |

The legacy `test-amd.yaml` copy of the MI300 job (separate `amd-ci` pipeline) is untouched.

## Notes

```
- Coverage is verified statically: the union of the new per-lane commands is exactly the 13 files the old `find` command collected, each claimed once. New files added at `compile/` root must now be listed in exactly one job (noted in a YAML comment) — this replaces the future-proofing the `find` glob used to provide.
- The MI300 lane stays as `mirror.amd` blocks (one per split job) so it remains tracked in the dashboard alongside its NVIDIA job; an earlier revision used two standalone AMD steps.
- Timeouts tightened to match measured runtimes (60→30 min NVIDIA, 90→45 min AMD).
- AI assistance was used for this change (evidence gathering, YAML edit, local render check). No duplicate PR exists: open-PR search for this job/area found only unrelated torch.compile work.
```

## Expected runtime and overhead

Predictions from the job's own recent CI history (three consecutive runs, per-file pytest times parsed from logs):

| job | predicted pytest | predicted running wall | main overhead cause |
|---|---|---|---|
| PyTorch Compilation / Dynamic Shapes | ~18 min | ~22 min | checkout + image pull + env setup |
| PyTorch Compilation / Config | ~16 min | ~20 min | same |
| PyTorch Compilation / AOT Compile | ~12 min | ~17 min | same |
| PyTorch Compilation (remainder) | ~1.5 min | ~6 min | same |

```
- Before: ~47 min pytest in one job (~51 min wall). After: slowest job ~18 min pytest — under the 20-minute target; both lanes' slowest jobs stay well under target.
- Predicted aggregate cost: the split adds 3 job setups per lane. On the primary lane that is ≈ +13 worker-minutes against the same coverage, within the 20 extra worker-minute budget (measured ≈ +1 in build 90781). The mirror lane's aggregate is re-measured in the new validation build, since it now follows the 4-way split.
```

Local verification: `yaml.safe_load` passes; the pipeline generator renders all six jobs with the expected keys/commands (run with the ECR lookup stubbed; full render needs CI credentials).
