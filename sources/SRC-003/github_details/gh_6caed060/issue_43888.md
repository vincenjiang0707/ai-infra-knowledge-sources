# [Issue #43888] MLA: kv_b_proj.weight.dtype AttributeError on quantized ColumnParallelLinear in chunked prefill

state: open | updated: 2026-09-25T01:45:42Z

## 正文

## Description

When using a quantized (AWQ/GPTQ/compressed-tensors) model with MLA attention, vLLM crashes with an `AttributeError` during chunked prefill because `kv_b_proj` is a `ColumnParallelLinear` that lacks a `.weight` attribute after quantization.

## Error

```
AttributeError: 'ColumnParallelLinear' object has no attribute 'weight'
```

at `vllm/model_executor/layers/attention/mla_attention.py:2094` in `_compute_prefill_context`:

```python
kv_c_normed = kv_c_normed.to(self.kv_b_proj.weight.dtype)
```

## Root Cause

Lines 2084-2087 already correctly handle quantized layers:

```python
_kv_b_proj_w_dtype = (
    self.kv_b_proj.weight.dtype
    if hasattr(self.kv_b_proj, "weight")
    else self.kv_b_proj.params_dtype
)
```

But line 2094 ignores `_kv_b_proj_w_dtype` and directly accesses `self.kv_b_proj.weight.dtype` without the `hasattr` guard.

## Fix

On line 2094, replace:

```python
kv_c_normed = kv_c_normed.to(self.kv_b_proj.weight.dtype)
```

with:

```python
kv_c_normed = kv_c_normed.to(_kv_b_proj_w_dtype)
```

The variable `_kv_b_proj_w_dtype` is already computed with the correct `hasattr` guard immediately above.

## Impact

vLLM EngineCore crashes with a fatal error, forcing a full restart (service enters crash loop under load). All inflight requests fail with HTTP 500.

## Environment

- vLLM version: v0.21.1rc1.dev384 (nightly, also present in current main)
- Model: GLM-4.7-Flash-AWQ-4bit (quantized with compressed-tensors)
- GPU: NVIDIA RTX 3090 (CUDA 12.9)
- Quantization: compressed-tensors (AWQ group_size=32, num_bits=4)
- CUDA graphs: enabled
- MLA: enabled (model uses Multi-head Latent Attention)

### cipherfoxie · 2026-06-26

Confirming this on different hardware and a newer nightly, in case the second data point helps land #43889:

```
- **Hardware:** NVIDIA DGX Spark, GB10 (Blackwell), compute capability sm_121a, CUDA 13, 128 GB unified memory.
- **Model:** `cyankiwi/GLM-4.7-Flash-AWQ-4bit` (GLM-4.7-Flash, 30B-A3B MoE, MLA attention, packaged as compressed-tensors W4A16 despite the "AWQ" name).
- **vLLM:** reproduced on both `0.20.2rc1.dev196` and `0.23.1rc1.dev309`. On the newer nightly the crash moves *earlier*: it fires during the KV-cache profiling run at engine init rather than on the first request, but it is the same unguarded `kv_b_proj.weight.dtype` read in `_compute_prefill_context`. So upgrading does not help.
```

The guard in #43889 (reusing the already-computed `_kv_b_proj_w_dtype`) is the right fix. I applied the equivalent `hasattr(self.kv_b_proj, "weight")` guard locally, after which GLM-4.7-Flash boots clean and decodes at ~53.7 tok/s single-stream on the Spark.

Full write-up and repro: https://sovgrid.org/blog/glm-47-flash-on-a-single-dgx-spark/
