# [Issue #58171] [Feature]: Add a built-in JSON logging formatter

source: https://github.com/vllm-project/vllm/issues/58171
state: open | updated: 2026-09-22T15:17:32Z
labels: 

## 正文

## Problem

vLLM can emit structured JSON logs today, but users must author and mount a
complete Python `logging.config.dictConfig` file and pass it with
`--logging-config.pylogging_config_file`. That is disproportionate when the
only desired change is to replace vLLM's default human-readable formatter with
JSON.

The typed `LoggingConfig` introduced by #57200 and #57205 provides the right
configuration surface, and #57955/#57957 make worker process metadata
compatible with valid JSON output. A simple built-in JSON choice is still
missing.

## Proposed solution

Add a `formatter` field to `LoggingConfig` with two initial values:

```
- `text` (default): retain the existing newline/color-aware formatters.
- `json`: replace the built-in text formatters with the bundled
  `python-json-logger` formatter.
```

Users could enable it through the existing configuration forms:

```bash
vllm serve MODEL --logging-config.formatter json
vllm serve MODEL --logging-config '{"formatter":"json"}'
```

The same field would work through serve YAML and Python configuration. The JSON
profile should include `asctime`, `levelname`, `name`, `vllm_process_name`,
`process`, and `message`. A user-supplied `pylogging_config_file` remains
authoritative and replaces the built-in configuration rather than being merged
with it.

This profile covers records emitted through vLLM's Python loggers. It does not
define an OpenTelemetry Logs Data Model schema, reconfigure Uvicorn, or convert
direct third-party/native writes to `stdout` or `stderr`.

## Prior efforts and non-duplication

- #32761 is the closest prior implementation of plain JSON logging. It predates
  `LoggingConfig`, uses an environment-variable switch and a custom formatter
  and exception hook, and is currently stale/conflicted. This proposal is
  materially different: it extends the typed configuration model and reuses
  the already bundled and documented `python-json-logger` formatter.
- #54769 proposes an OpenTelemetry-aligned JSON schema, trace/span correlation,
  and `VLLM_LOGGING_FORMAT`. That is a distinct profile and broader scope than
  the plain Python `LogRecord` JSON profile proposed here.
- #57200 defines the typed console-logging model and identifies a built-in JSON
  format as follow-up work; #57205 implements the initial model.
- #57955 and #57957 ensure process decoration does not corrupt JSON and expose
  the logical process name as structured metadata, but users still need to
  provide a complete logging configuration.
- #2397, #2432, and #13920 are earlier requests or implementations in this
  space.

## Acceptance criteria

- Existing users retain the current text output by default.
- `--logging-config.formatter json` emits one parseable JSON object per vLLM
  `LogRecord` with logical process name and PID fields.
- The selection propagates through `LoggingConfig` to child processes.
- A custom `pylogging_config_file` remains authoritative.
- CLI parsing, formatter output, default behavior, and documentation are
  covered by tests.
