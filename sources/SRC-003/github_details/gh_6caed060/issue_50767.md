### 🐛 Describe the bug

`--override-generation-config` is intended to set server-side default sampling parameters that apply when the client does not send a value for that parameter. It works for `temperature`, `top_p`, `top_k`, `min_p`, `repetition_penalty` and `max_new_tokens`, but **silently ignores `presence_penalty` and `frequency_penalty`** — both are missing from the `available_params` whitelist in `ModelConfig.get_diff_sampling_param()` (`vllm/config/model.py`). No warning is emitted, and the sampler always falls back to `0.0`.

This is the same class of silent-drop bug as #45591 (where `eos_token_id` was dropped by the same whitelist mechanism and later fixed).

```bash
# Server-side default sampling params:
vllm serve /path/to/model \
  --generation-config vllm \
  --override-generation-config '{"presence_penalty":1.5,"temperature":0.6,"top_p":0.95}' \
  --enable-log-requests

# Client request that does NOT send presence_penalty:
curl -X POST http://localhost:8000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"<model>","messages":[{"role":"user","content":"hi"}],"max_tokens":8}'
```

Observed server log (`--enable-log-requests`):

```text
SamplingParams(... presence_penalty=0.0, ..., temperature=0.6, top_p=0.95, ...)
#                       ^^ configured default 1.5 never applied
```

`temperature`/`top_p` from `--override-generation-config` are applied, but `presence_penalty` is not.

Expected behavior: `presence_penalty` (and `frequency_penalty`) configured in `--override-generation-config` should be applied as server-side defaults, exactly like `temperature`/`top_p`. They are standard sampling parameters of both `/v1/chat/completions` and `/v1/responses`, and the only sampling parameters in this whitelist that accept a client value but have no server-default path.

Root cause location: `vllm/config/model.py`, `ModelConfig.get_diff_sampling_param()`:

```python
available_params = [
    "repetition_penalty",
    "temperature",
    "top_k",
    "top_p",
    "min_p",
    "max_new_tokens",
]
```

Verified present on `v0.24.0` (this env), still present on `v0.26.0` and on `main`.

Impact: deployments that rely on server-side default penalties (e.g. an LLM gateway in front of vLLM that does not forward penalty fields) cannot get presence/frequency penalty applied, causing output repetition / tool-call loops that are very hard to diagnose.

### wuhangxian · 2026-08-25

I reproduced this on current main (commit on 2025-08-25). The root cause is confirmed: `ModelConfig.get_diff_sampling_param()` in `vllm/config/model.py` builds an `available_params` whitelist that omits `presence_penalty` and `frequency_penalty`, so any values set via `--override-generation-config` for those two parameters are silently dropped.

```python
# vllm/config/model.py, line ~1737
available_params = [
    "repetition_penalty",
    # <-- presence_penalty and frequency_penalty are missing here
    "temperature",
    "top_k",
    "top_p",
    "min_p",
    "max_new_tokens",
]
```

Both `presence_penalty` and `frequency_penalty` are first-class fields on `SamplingParams` (lines 240, 244) with the same `-2.0` to `2.0` range, and they are accepted by both `/v1/chat/completions` and `/v1/responses`. They are the only two client-sendable sampling parameters that have no server-default path — every other parameter in the whitelist works.

**Fix** is a two-line addition to the whitelist:

```diff
         available_params = [
             "repetition_penalty",
+            "presence_penalty",
+            "frequency_penalty",
             "temperature",
             "top_k",
             "top_p",
             "min_p",
             "max_new_tokens",
         ]
```

Verified locally: after the fix, `--override-generation-config '{"presence_penalty":1.5,"temperature":0.6}\`` correctly propagates `presence_penalty=1.5` into the default `SamplingParams`, matching the behavior of `temperature` and the other whitelisted params.
