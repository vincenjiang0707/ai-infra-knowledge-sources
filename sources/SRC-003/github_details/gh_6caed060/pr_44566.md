# [PR #44566] [Bugfix][Spec Decode] Derive num_speculative_tokens from a speculators draft config

source: https://github.com/vllm-project/vllm/pull/44566
state: open | updated: 2026-09-23T03:03:17Z
labels: bug

## 正文

## Purpose

Refs #40382. The primary issue there, no Ampere attention backend for a non-causal `head_dim=256` draft, is already resolved on current main by #40394. This PR fixes the remaining `num_speculative_tokens` auto-detect gap.

Serving a speculators-format draft (Eagle3, DFlash, PEAGLE, ...) through `--speculative-config` with the target as the top-level `--model` fails to start unless the user also restates `num_speculative_tokens`, even though the draft config already declares it under `speculators_config.proposal_methods[0].speculative_tokens`.

The existing auto-detect path only runs when the speculator repo itself is the top-level `--model` and `maybe_override_with_speculators` handles it. With the target as `--model` and the draft supplied via `--speculative-config`, `SpeculativeConfig.__post_init__` loads the draft as a `SpeculatorsConfig` built from `transformer_layer_config`, so the proposal-method `speculative_tokens` count is dropped before `num_speculative_tokens` can default from it.

This carries the speculators proposal count into the draft config and defaults `num_speculative_tokens` from that count when the user did not provide an explicit value. A user-provided value still takes precedence, and the behavior is generic across speculators algorithms.

## Test Plan

Validated `EngineArgs.create_engine_config()`, the shared config-build path used by `vllm serve` and offline `LLM(...)` before engine startup. The repro uses target model `unsloth/Llama-3.2-1B-Instruct`, speculators draft `nm-testing/Llama3_2_1B_speculator.eagle3`, and omits `num_speculative_tokens`.

## Test Result
