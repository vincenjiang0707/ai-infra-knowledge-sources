## 正文

## Problem and change

Online NVFP4 reuses its MoE kernel and quantization config across weight reloads. Conversion installs new weight-scale tensors on the layer, but the reused config still references the previous alpha storage. Expert post-processing can therefore rebuild derived scales (for example TRTLLM's `g1_scale_c`) using the previous weights' scales. Restoring graph-visible parameter storage afterward is too late to correct those derived values.

Copy the converted `w13_scale_2` and `w2_scale_2` values into the persistent config alphas before expert post-processing. Preserve the kernel, config, and alpha storage identities. This follows up the kernel reuse introduced by #50074; it does not rebuild the kernel or change quantization policy.

Extend the existing lifecycle test with changed scales over three processing calls. Check the values visible during expert post-processing and stable config/alpha storage.

## Related work

Checked open reload/scale work, including #49789, #50521, #50538 and #53741. Those address broader reload arenas, CUTLASS/B12x runtime storage, or ModelOpt reload. None modifies `online/nvfp4.py` to refresh an already-reused config before expert post-processing. This is the narrow online-NVFP4 refresh; broader storage work may eventually subsume it.
