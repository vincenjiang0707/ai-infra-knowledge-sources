## 正文

## Purpose

#54016 fixed this in `flashinfer_nvlink_one_sided.py`: with expert parallelism but no data parallelism — it was hit with `TP=1, PCP=4, EP` — `ForwardContext.dp_metadata` is None, and `get_local_sizes()` asserted that it is not.

`flashinfer_nvlink_two_sided.py` still carries the unfixed copy of the same function:

```python
def get_local_sizes():
    dp_metadata = get_forward_context().dp_metadata
    assert dp_metadata is not None
    return dp_metadata.get_chunk_sizes_across_dp_rank()
```

The consumer in the same file is already written for the None case:

```python
# flashinfer_alltoall_dispatch
max_num_token = (
    max(global_num_tokens_cpu) if global_num_tokens_cpu is not None else x.shape[0]
)
```

so that fallback branch is unreachable today — the assert fires first. `flashinfer_nvlink_two_sided` is a currently selectable `all2all_backend`; only the older `flashinfer_all2allv` spelling of it is deprecated (`cuda_communicator.py:231`).

Reproduced without a GPU:

```python
>>> with patch.object(two_sided, "get_forward_context",
...                   lambda: SimpleNamespace(dp_metadata=None)):
...     two_sided.get_local_sizes()
AssertionError
>>> # same call on one_sided, after #54016
None
```

## Changes

- `get_local_sizes()` returns `None` when there is no DP metadata, exactly as #54016 did for the one-sided module.
- Widen `flashinfer_alltoall_dispatch`'s `global_num_tokens_cpu` annotation to `list[int] | None`, matching what its body already accepts.

I checked the other prepare/finalize backends that read `dp_metadata` — `deepep_v2.py:201`, `moonep.py:360`, `experts/batched_deep_gemm_moe.py:393` — and they all already guard for None. This was the last one that did not.

## Test

`tests/kernels/moe/test_flashinfer_nvlink_local_sizes.py`, CPU-only (`cpu_test`), pins **both** modules to the same contract with and without DP metadata, so the two copies cannot drift apart again.
