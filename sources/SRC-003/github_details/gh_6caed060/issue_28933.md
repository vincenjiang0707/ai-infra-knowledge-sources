# Structured request_id in logs and inclusion in error logs

When sending a request with the `x-request-id` header, vLLM logs an entry like:

```
[2025-11-14 13:57:07] [INFO] [vllm.v1.engine.async_llm] Added request cmpl-833171a7b8c84e5eb20408b3e4fe2377
```

This is quite useful for traceability, but it currently has two limitations.

## 1. `request_id` is not available as a structured logging field

The `request_id` appears only inside the log message text, not as a dedicated log record field.
This prevents using it in structured logging formats such as:

```json
{
    "formatters": {
        "vllm": {
            "class": "vllm.logging_utils.NewLineFormatter",
            "datefmt": "%m-%d %H:%M:%S",
            "format": "%(levelname)s %(asctime)s %(filename)s:%(lineno)d %(request_id)s %(message)s"
        }
    }
}
```

Since `request_id` is not part of the log record, any formatter referencing it fails.

Adding `request_id` as an optional field in the logger would enable proper log correlation and integration with observability tools.

## 2. Error logs do not include the `request_id`

If the request is valid, vLLM logs the “Added request …” line containing the `request_id`, as stated above. 

However, if the request fails before being accepted—e.g., invalid JSON, exceeding max context length, or other early validation errors—**the error logs do not include the `request_id`**, even when the header is present.

Example:

```
[2025-11-18 11:37:57] [ERROR] [vllm.entrypoints.openai.serving_chat] ValueError: This model's maximum context length is 8192 tokens. However, your request has 54732 input tokens. Please reduce the length of the input messages.
```

This makes end-to-end tracing difficult precisely in the cases where correlation is most needed.

# Summary:

* Expose `request_id` as a structured logging attribute.
* Include `request_id` in error logs, even when the request fails early.
* Maintain backward compatibility.

These changes would improve observability and make vLLM easier to operate in production environments.

Thank you for the great work on vLLM. It’s an outstanding project!
