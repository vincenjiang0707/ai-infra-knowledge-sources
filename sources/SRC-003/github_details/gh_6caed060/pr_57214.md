# [PR #57214] [Perf][Pooling] Avoid blocking seq_lens GPU-to-CPU copy for pooling in FlashInfer metadata builder

## Purpose
FlashInfer's metadata builder needs per-request sequence lengths on the CPU to plan paged KV metadata. For V2 model runner, `seq_lens` live on the GPU, so the builder fetches them with `common_attn_metadata.seq_lens.cpu()`. For pooling models this copy is avoidable; pooling models have no speculative tokens, so `seq_lens_cpu_upper_bound` maintained by the model runner is exact, not optimistic. The pooling runner already relies on this (`pooling_runner.py`: ["Pooling has no speculative tokens, so this CPU upper bound is exact"](https://github.com/vllm-project/vllm/blob/v0.29.0/vllm/v1/worker/gpu/pool/pooling_runner.py#L142)). 

This results in a measured performance boost of about 1.35%.

AI assistance (locally hosted GLM 5.3 and Kimi K3 as well as GPT-6 Astra) was used for implementation and analysis. All changed lines were reviewed and validated end-to-end.

## Test Plan

E2E benchmarking:

```bash
vllm serve Qwen/Qwen3-Embedding-0.6B \
    --runner pooling --max-num-seqs 512 --max-num-batched-tokens 4096 \
    --enable-chunked-prefill --async-scheduling \
    --attention-backend FLASHINFER

vllm bench serve --backend openai-embeddings --endpoint /v1/embeddings \
    --base-url http://127.0.0.1:8000 --model Qwen/Qwen3-Embedding-0.6B \
    --tokenizer Qwen/Qwen3-Embedding-0.6B --dataset-name random \
    --random-input-len 1300 --random-output-len 1 --num-prompts 8192 \
    --num-warmups 50 --request-rate inf --seed 42 \
    --percentile-metrics e2el
```

Also, manual verification that embeddings are almost numerically identical was done.
