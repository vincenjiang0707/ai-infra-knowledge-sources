# [PR #56473] [Bugfix][Perf][KV Connector] Keep DecodeBenchConnector's dummy fill out of its own measurements

source: https://github.com/vllm-project/vllm/pull/56473
state: open | updated: 2026-09-25T00:55:01Z
labels: bug, needs-rebase, kv-connector

## 正文

## What

`DecodeBenchConnector` fills the KV cache with dummy values so a decode instance can be benchmarked without running prefill. The fill is expensive enough to distort that measurement, and it runs synchronously inside the scheduler step.

The clearest symptom is that skipping prefill can make a model slower. On 4x B200 at TP=4, `Qwen/Qwen3-32B` reaches 84.9 req/s at concurrency 256 behind this connector, against 117.7 req/s when it actually runs prefill.

This PR makes the fill cheap. No written value changes.

```
- `_fill_block_tensor` no longer builds a full-size `torch.full` temporary and scatters it with advanced indexing, which cost one allocation plus two kernels per layer per request. A contiguous run of block ids is now written with a slice `fill_` or `normal_`; gaps use `index_fill_`, or one reused scratch buffer for the random path.
- `_fill_state_tensor` no longer runs per request. Linear-attention state buffers have no `num_blocks` dimension, so one buffer is shared by every slot and there is nothing to fill per request; repeating it cost time proportional to `max_num_seqs` and overwrote the state of the other in-flight sequences. They are filled once in `register_kv_caches`.
```

## Why this is not a duplicate

Searched open work on this connector: nothing addresses the cost of the fill, and every change this file has taken since it landed is a correctness fix that this PR preserves.

## Performance (4x B200, TP=4, input 1024 / output 128, 3 repetitions per cell)

Throughput in req/s, `before / after`. The baseline column is the same model on the same GPUs actually running prefill, which is what this connector stands in for:

| model | c8 | c32 | c128 | c256 | baseline at c256 |
|---|---|---|---|---|---|
| Qwen3-32B, 64 block-indexed KV layers | 9.1 / 9.5 | 28.8 / 32.5 | 63.2 / 84.5 | **84.9 / 122.0** | 117.7 |
| hybrid MoE, 12 block-indexed + 36 linear | 6.5 / 6.7 | 19.9 / 21.2 | 51.1 / 55.8 | 69.9 / 85.3 | 38.2 |

Every cell now exceeds that baseline; before the change, Qwen3-32B did not at any concurrency, which cannot happen if the fill is free.

| metric | Qwen3-32B | hybrid MoE |
|---|---|---|
| ITL p99 | 1.4x to **7.8x** better | 1.2x to **4.8x** better |
| ITL p50 | +0.0% to +1.9% | +0.0% to +0.3% |
| repetition spread | 0.2-2.2% | 0.5-1.7%, one cell at 21.8% |

ITL p50 barely moves, which is the check that the step itself is untouched. The gain tracks the number of block-indexed KV layers rather than concurrency, which points at the per-layer temporary as the dominant cost.

## Tests

```
- `pytest tests/v1/kv_connector/unit/test_decode_bench_connector.py` — **21 passed / 3 failed before the change, 24 passed after**. The three failures are exactly the cases that encode the new behaviour, and the 15 pre-existing cases pass in both states.
- Four cases added, nine with parameters, each driving a real worker-role connector through `register_kv_caches`, `bind_connector_metadata` and `start_load_kv`: requested blocks only (contiguous run, gaps, single block, out-of-range id, empty list), random fill staying inside the requested rows, scratch buffer reuse (contiguous expecting none, scattered expecting one), and one-time state tensor fill over a `MambaSpec` group.
- `ruff check` and `ruff format --diff` on both changed files — clean.
- End-to-end: `vllm bench serve --dataset-name random --random-input-len 1024 --random-output-len 128`, against both this connector and a plain server, producing the table above.
```

## Notes / open questions

- The fill is still synchronous and once per request, so a residual tail cost remains. Returning `is_async=True` from `get_num_new_matched_tokens` would remove it and is the obvious follow-up; it was left out here to keep the change to the fill itself.
- The two causes were not toggled independently, so the attribution between the per-layer temporary and the state tensor fill is directional only.
- The hybrid MoE c128 patched cell has a 21.8% repetition spread where every other cell is under 2.2%, so that one figure is loose.
