## 正文

### 📚 The doc issue

In data parallel deployments, it is not well documented that vllm-router is capable to route requests to specific data-parallel engines within a vllm deployment via `--intra-node-data-parallel-size`.

This can effectively leverage session-affinity routing with data-parallel deployments in the presence of a conversational or agentic workload where a request's context is reused by the same client over and over.

### Suggest a potential alternative/fix

It does not fit well with the current load balancing classification (internal, hybrid, external) because it looks like this is specific to vllm-router, but it would be handy to explicitly mention that it is possible to route requests to specific engines within a single HTTP endpoint and demonstrate it with an example using `vllm-router --intra-node-data-parallel-size N`.
