## Purpose

Kimi K2.5/K3 passes contiguous `[patches, 3, 14, 14]` inputs to its shared vision tower. Each Conv2d call produces one output per patch, so use the existing `Conv2dLayer.forward_native` GEMM path. Checkpoint keys and output shape stay the same; the explicit output width also handles zero patches.

**Alternative considered**:  We decide not to add GEMM dispatch to `Conv2dLayer.forward_cuda` because it serves many other models with different input layouts, which might not guarantee speedup by switching to GEMM. For example, GLM5Next forms a channels-last NCHW view with `view(..., 2, 2, C).permute(0, 3, 1, 2)` before its 2×2 feature merger. A
GB300 BF16 microbenchmark of a representative 1024→4096 merger shows GEMM regression.

| Input and layout | Conv2d | GEMM |
| --- | ---: | ---: |
| `[256, 1024, 2, 2]`, channels-last view | 58.7 µs | 72.3 µs

Hence, the dispatch should be considered carefully for each model implementation.
