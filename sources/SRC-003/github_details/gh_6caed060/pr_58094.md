## 正文

Fixes #58080

`--hf-overrides` as a dict (the YaRN / rope CLI path) was dropped when building the speculative draft `ModelConfig`. The target ran extended RoPE, the MTP draft stayed on native encodings, and acceptance went to 0% past the draft's native `max_position_embeddings`.

This forwards rope-relevant mapping-style overrides (`rope_parameters`, `rope_scaling`, `max_position_embeddings`, including nested `text_config`) onto the draft before architecture mapping. Callable overrides are unchanged.

#37443 targets the same bug (#37435) but is conflicted against current `compose_draft_hf_overrides` and would drop callable composition from #45352, so this is not a duplicate of that PR.

### Rotary Position Embedding Invariant Alignment

1. **Context Window Scale Parity**:
   When the target base model applies RoPE scaling overrides (e.g. `rope_theta`, `yarn_scaling_factor`, or extended position factor mappings via `hf_overrides`), failing to forward these overrides to the MTP draft worker causes frequency misalignment in relative position embeddings.

2. **Draft Verification Stability**:
   Forwarding `hf_overrides` to the draft runner ensures the speculative proposal heads match the target model's positional representation exactly across long-context sequences (>32k tokens), preventing false speculative rejection rates.

```python
# Verification of draft config propagation
draft_hf_config = copy.deepcopy(target_hf_config)
if hasattr(target_config, "hf_overrides") and target_config.hf_overrides:
    draft_hf_config.update(target_config.hf_overrides.get("rope_scaling", {}))
```
