# [PR #57754] [Bugfix] Apply structured output on /v1/completions when the prompt never opens reasoning

## 正文

## Purpose

Fixes #57726.

With a reasoning parser configured, a `/v1/completions` request carrying a
structured-output constraint comes back **unconstrained**, with a 200 and no
warning. The same request on the same model without `--reasoning-parser` is
constrained. `/v1/chat/completions` is unaffected.

## Root cause

```python
`StructuredOutputManager._get_constraint_start()` infers the initial reasoning
state from the prompt with a single question:
```

```python
if reasoner.is_reasoning_end(request.prompt_token_ids or []):
    return 0
structured_req.reasoning_ended = False
```

`BaseThinkingReasoningParser.is_reasoning_end()` scans backwards and returns
`False` on the start token, `True` on the end token, and falls through to
`return False` when it finds neither. That final line conflates two opposite
states:

| prompt | `is_reasoning_end` | meaning | current behaviour |
|---|---|---|---|
| ends with `<think>` | `False` | inside reasoning | wait for `</think>` — correct |
| contains `<think></think>` | `True` | reasoning closed | constrain now — correct |
| contains **neither** | `False` | never entered reasoning | wait forever — **bug** |

A raw completions prompt renders no chat template, so it is the third row. No
reasoning-end token will ever arrive, so the bitmask is never applied and the
model is unconstrained for the whole completion.

The same holds for the engine parser family: `ParserEngineReasoningAdapter`
inherits `ReasoningParser` and proxies the same properties, so both families
reach the gate through this one inference.

## The change

Ask the second question at the same place: does the prompt contain a reasoning
**start** marker at all? `ReasoningParser.reasoning_start_str` already exists
for this and the manager never consulted it.

A parser that exposes no start marker, or whose marker is absent from the
vocabulary, keeps today's behaviour — the helper returns `False` for "cannot
tell", so only a provable never-entered-reasoning prompt changes.

## Verification

Behaviour of the gate before and after, driven through the repo's own
`is_reasoning_end` source:

| prompt shape | main | this PR |
|---|---|---|
| chat, thinking on (ends `<think>`) | waits | waits |
| chat, thinking off (`<think></think>`) | constrained | constrained |
| chat mid-reasoning, long prompt | waits | waits |
| reasoning closed then reopened | waits | waits |
| reasoning closed, trailing content | constrained | constrained |
| **raw completions, no reasoning tokens** | **waits** | **constrained** |
| **raw completions, empty prompt** | **waits** | **constrained** |

Exactly the two raw-completions rows change; the five chat rows are untouched.
Parsers without a start marker are identical on all seven.

Tests added to `tests/v1/structured_output/test_structured_output_manager.py`,
parametrized over both backends:

- `test_constraint_applies_when_prompt_never_opens_reasoning` — a prompt that
  opens reasoning still waits, one that closes it is constrained, and one with
  no reasoning tokens is now constrained rather than free.
- `test_parser_without_start_marker_keeps_waiting` — the fallback stays on the
  previous behaviour.

Both fail on `main` for the no-reasoning-tokens case and pass with this change.
