# [PR #56781] [XPU][UT] Fix OverflowError when storing embeds.data_ptr()

source: https://github.com/vllm-project/vllm/pull/56781
state: closed | updated: 2026-09-23T06:55:43Z
labels: intel-gpu, mrv2

## 正文

## Purpose

On XPU, USM device pointers returned by `embeds.data_ptr()` can exceed the positive range of a signed 64-bit integer.

`PromptEmbedsState.add_request()` stores the prompt embedding pointer in a NumPy-backed `torch.int64` buffer. Assigning a high-bit XPU pointer directly to this buffer raises the following error (similar to the issue described in #48059):

```text
OverflowError: Python int too large to convert to C long
```

The error occurs when processing a request with prompt embeddings:

```text
File "vllm/v1/worker/gpu/model_states/prompt_embeds.py", line 58, in add_request
  self.embeds_ptrs.np[req_index] = embeds.data_ptr()
```

This PR reinterprets the unsigned 64-bit embedding pointer as a signed `int64` value before storing it in the existing pointer buffer. The reinterpretation uses the same code as the existing `_reinterpret_u64_as_i64` in `mamba_utils.py`, which has been verified.

Duplicate-work check: no open PR currently matches the PromptEmbedsState & overflow keywords.
