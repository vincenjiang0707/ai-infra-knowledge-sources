## 正文

## Purpose

Reduce DeepSeek-V4.1-Flash MXFP4 expert padding on SM90 Marlin. At TP8,
each 288-channel partition uses **320 instead of 384** channels, saving
**7.77 GiB of model-loading memory per H20 GPU** at a fixed KV budget.

The change applies to regular CUDA SM90 Marlin with BF16 activations and
no A8 quantization. Hidden alignment remains 256. This storage-alignment
change is separate from #56744's batched tile selection and #56493's
SM89 block-FP8 tile grouping.

## Test Plan

Rebase validation (`b05a5ca710a9` on `7b942936276d`): the original
patch is unchanged apart from upstream context. **142 MXFP4 tests passed**
on H20 with the prepared native Marlin runtime; changed-file lint and
mypy 3.12 passed. Performance and quality results below retain their
original frozen source versions.

## Test Result

Frozen upstream **`bb5507741155`**, PR **`238e1c21f478`**; identical native
binaries across layouts. H20×8, TP8, BF16, dense emulation, Python API1,
default modalities/Engram, max sequences 64, batch tokens 8192, DSpark 5
adaptive, `fp8_ds_mla`. GPU KV is fixed at 22,191,197,696 bytes/rank;
native SimpleCPUOffloadConnector uses 64 GiB total. The service limit is
1M; the performance inputs below are 8K/32K.

EvalScope 1.11.1, matched random inputs, streaming and exactly 1024 output
tokens. Two complete boots per layout in C→D / D→C order, with separate
priming. Model-loading memory is **51.09 → 43.32 GiB/GPU**.

| Input/concurrency | Round | Baseline tok/s | +PR tok/s | Throughput | E2E p95 |
|---|---:|---:|---:|---:|---:|
| 8K/C64 | 1 | 861.71 | 916.19 | +6.3% | -9.1% |
| 8K/C64 | 2 | 850.94 | 916.65 | +7.7% | -7.2% |
| 32K/C4 | 1 | 221.78 | 239.05 | +7.8% | -7.3% |
| 32K/C4 | 2 | 218.73 | 232.51 | +6.3% | -3.2% |

832 measured requests succeeded, plus 384 priming requests. 8K/C4 was
inconsistent, including p95 regressions. C16 and one C4 run overlap JIT
warnings and are excluded from the performance claim above. CPU prefix
hits were zero in these random-input runs; these are PR gains with
offload enabled, not an offload-benefit measurement.

One baseline boot stopped at priming validation after an empty-text
stream had unavailable TTFT. Its 64 completed measurements are retained
separately; the entire boot was repeated with unchanged EvalScope commands
and seeds after correcting only the priming validator.

**Quality:** full GSM8K, three independent boots per layout:

| Layout | Original | Repeat 1 | Repeat 2 |
|---|---:|---:|---:|
| Baseline | 1277/1319 | 1280/1319 | 1278/1319 |
| +PR | 1275/1319 | 1280/1319 | 1277/1319 |

Zero-shot chat, C16, greedy, thinking=false, max_tokens=1024, request
seed=20260915, server seed=0. Prompt and grading logic were unchanged;
truncations and missing final answers count as incorrect. The differences
remain **−2, 0, −1 answers**. Within-layout repeats change 7–12 final answers;
targeted C1 replays also vary. This does **not** establish quality equivalence
or prove that the negative difference is entirely runtime variation.

An additional 90-case numerical comparison passed the same dequantized
BF16 reference tolerance (`atol=rtol=0.03`) for both padding extents.
Mean relative L2 error was 0.00499137 / 0.00499136. Both layouts also pass
three image, two streamed-tool and 16 controlled KV-retrieval checks.

AI assistance was used; the original patch was reviewed and tested by the submitter.
