## 正文

### Which component has the problem?

CuTe DSL

### Bug Report

**Describe the bug**
In CuTeDSL, if you define a variable as a constant like `zero = Int32(0)`, `inline_ptx` lowers `Int32(0)` to the immediate operand 0. This causes ptxas to reject instructions whose operand grammar requires a register, such as `max.xorsign.abs.bf16x2`. There is currently no apparent way to request register materialization for a constant passed through `read_only_args`.


**Steps/Code to reproduce bug**
```python
import cutlass
from cutlass import cute
from cutlass import Int32


@cute.kernel
def kernel():
    value = cute.arch.thread_idx()[0]
    zero = Int32(0)
    cute.arch.inline_ptx(
        "max.xorsign.abs.bf16x2 {$w0}, {$r0}, {$r1};",
        write_only_types=[Int32],
        read_only_args=[zero, value],
    )

@cute.jit
def launch():
    kernel().launch(grid=(1, 1, 1), block=(32, 1, 1))

if __name__ == "__main__":
    cute.compile(launch)
```

**Expected behavior**
It should be 
```
  .reg .b32 %r0;
  mov.b32 %r0, 0;
  max.xorsign.abs.bf16x2 %r1, %r0, %r2;
```
where zero is not a literal zero.

### 0z5a · 2026-09-18

Opened #3642 for this.

`inline_ptx(..., force_register_args=(0,))` moves the named read-only operands into a register before the instruction runs, so the target operand is produced by an instruction instead of by a constant op:

```ptx
mov.b32 %r2, 0;
max.xorsign.abs.bf16x2 %r1, %r2, %r3;
```

The constraint itself is chosen in the NVVM to LLVM conversion (`BasicPtxBuilderInterface::getRegisterType(Value)` returns `n` for any constant without consulting the instruction), so this is an opt-in per call site and the existing immediate behavior is left untouched. Verified end to end on an L20 (sm_89) with bit-exact readback, plus a regression matrix and a CPU-only test.

Two unrelated failures I hit while testing are written up in the PR and deliberately left unfixed: `predicate=` emits `@0` instead of the predicate's operand index, and a float read-only constant fails with `constraint 'n' expects an integer constant expression`.
