## 正文

## Problem (#3643)

`examples/python/CuTeDSL/experimental/primitives/tcgen05/2cta_mma_blockscale_m128.py` produces wrong results for larger problem sizes and hits `CUDA_ERROR_LAUNCH_FAILED` for larger K. Reproduced on B200 (sm_100, CUDA 13.0, nvidia-cutlass-dsl 4.8.0) with the reporter's `check_blockscale_sync.py`: 29/200 iterations mismatch at 4096x256x2048, launch failure at 8192x256x4096. `compute-sanitizer --tool synccheck` on the unmodified example reports `Barrier error detected. Missing wait` from the SFB TMA warp in the non-leader CTA on `sfb_smem_full`.

## Root cause

1. **The peer CTA's SFB completion is never observed.** Each CTA loads its own SFB half with a `cta_group::1` TMA tracked by its *local* `sfb_smem_full`. Only the leader's MMA warp waits, and only on the *leader's* barrier, before issuing the `cta_group::2` UTCCP that also reads the peer's sSFB. There is no path from the peer's `sfb_smem_full` to the leader.

2. **Cross-CTA arrives use `MemScope.CTA`.** `mbarrier_arrive(remote, scope=CTA)` lowers to `mbarrier.arrive.release.cta.shared::cluster.b64`, so the peer's SFA `cp.async` writes are not released at cluster scope before the leader's UTCCP reads them. (The default for a shared::cluster address is already `.cluster`; the example explicitly downgraded it.)

3. **No cross-proxy fence.** SFA is written through the generic proxy (`cp.async`) and read through the async proxy (`tcgen05.cp`).

## Fix

- Warp 7 (sync relay) also waits on `sfb_smem_full[stage]` before arriving on the leader's `ab_full[stage]`.
- Both cross-CTA `mbarrier_arrive` calls (the `ab_full` relay and the `tmem_dealloc` handshake) use `MemScope.CLUSTER`.
- `fence.proxy.async.shared::cta` after the `a_local` wait, before the relay arrive.
- Updated the warp-7 comment, which said SFB "does not participate here".

## Verification (B200)

Using the reproducer from #3643 (`--repeats 300` per shape):

| variant | 4096x256x2048 | 8192x256x4096 | 16384x256x8192 |
|---|---|---|---|
| upstream main | 29/200 FAIL | launch failure | — |
| only `ab_full` relay arrive → CLUSTER | 0/300 | — | — |
| only `tmem_dealloc` arrive → CLUSTER | 11/300 FAIL | — | — |
| only SFB wait added | 0/300 | 0/300 | 0/300 |
| this PR | 0/300 | 0/300 | 0/300 |

`compute-sanitizer --tool synccheck` on this PR: 0 errors (8 before). The example's own `python 2cta_mma_blockscale_m128.py` and `--mnk 4096,256,2048` runs pass.

Isolating the two scope changes shows the `ab_full` relay arrive is what removes the mismatches on B200; adding only the SFB wait also passes here, but that is timing (SFB is small and normally lands before A/B), and synccheck still needs the wait to go clean. All three changes are kept.

Fixes #3643
