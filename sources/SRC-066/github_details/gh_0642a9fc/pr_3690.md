# [PR #3690] [CuTeDSL] Work around lost D when MMA C is a separate register tensor

source: https://github.com/NVIDIA/cutlass/pull/3690
state: open | updated: 2026-09-27T06:20:47Z
labels: 

## 正文

**Fixes #3689.** When the MMA `C` accumulator is a register tensor separate from `D`, `D` is never written, and the kernel can be eliminated entirely. The defect is in the MMA lowering, which is not in this repository; this PR works around it in the Python layer until it is fixed there. Verified on a B200 with DSL 4.8.0.

## Cause

`cute.mma_atom_call` and `cute.gemm` compute `D = A * B + C`, and the `cute.gemm` docs allow `C` and `D` to be different tensors ("where C and D can alias"). The DSL passes both to the IR correctly (`cute.mma_atom_call(atom, %D, %A, %B, %C)`), but the lowering writes the result to **`C`** and never writes `D`. `D` is then undefined, so the store of `D` can be dropped, and everything feeding it becomes dead code: the #3689 reproducer compiles to a bare `ret`.

This is not specific to `mma.sync`. The universal FMA atom and `cute.gemm` with a `TiledMma` behave the same way. Every example in the repo passes the same tensor as `C` and `D`, which is likely why this went unnoticed.

Note on the reproducer in #3689: removing `rD.store(rC.load())` as described leaves `mma_atom_call(atom, rD, rA, rB, rD)`, which reads uninitialized `rD` and does not use `rC`. The failing form is `mma_atom_call(atom, rD, rA, rB, rC)`.

## Fix

A small helper, `_accumulator_in_place`, is called by both `mma_atom_call` and `cute.gemm`. When `C` and `D` are distinct register tensors with the same element type, it copies `C` into `D` and passes `D` as the accumulator, so the MMA runs in place. This computes the same `D = A * B + C` and leaves `C` unchanged.

Everything else is passed through as before: same-tensor calls, accumulators in TMEM or shared memory (tcgen05 and warpgroup MMAs), and tensors that differ in element type.

## Cost / open question

None measurable: the copy folds away, and the PTX of the separate-`D`/`C` reproducer is identical, instruction for instruction, to the in-place form.

This is a workaround. The lowering itself should honour a separate `C`; once it does, the helper can be removed. If you would rather keep the Python layer untouched and fix only the lowering, feel free to take just the test.

## Verification

B200, DSL 4.8.0. `D` pre-filled with `7.0`, `C = 0`, `A = B = 1`, `K = 16`, so the expected value is `16.0`:

| Case (separate `D` / `C`) | before | after |
|---|---|---|
| `mma_atom_call`, `mma.sync` m16n8k16 (#3689) | kernel eliminated / `7.0` | `16.0` |
| `cute.gemm`, 2x2 `TiledMma` of m16n8k16 | `7.0` | `16.0` |
| `mma_atom_call`, universal FMA atom | `7.0` | `16.0` |
| any of the above with `C` = `D` | correct | unchanged |

- New `test/python/CuTeDSL/test_mma_separate_accumulator.py` covers the three cases above, each in the separate and in-place form, and checks both `D` against a reference and that `C` is left unchanged. The `TiledMma` case uses per-thread fragments of shape `((2,2),2,2)`, so it spans two M, N and K blocks. The separate cases fail on 4.8.0 and pass with this change.
- The other tests in `test/python/CuTeDSL`, and the Ampere `tensorop_gemm.py` / `sgemm.py` and Blackwell `fp16_gemm_0.py` examples, give the same results with and without it.
