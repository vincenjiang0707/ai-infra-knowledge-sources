# [PR #3679] Fix EVT testbed host/device argument size mismatch for DAG nodes

source: https://github.com/NVIDIA/cutlass/pull/3679
state: open | updated: 2026-09-25T15:41:08Z
labels: 

## 正文

Fixes #2862

`Testbed3xEVT::run()` copies the host reference's EVT arguments into the device epilogue arguments with
`std::memcpy(&arguments.epilogue.thread, &epilogue_args.arg, sizeof(epilogue_args.arg))`. This only
works if the host argument structs have the same layout as the device ones. For the EVTDAG tests they
don't:

- `HostCompute::Arguments` was `struct { struct OpArgs {} op; }`, a 1-byte non-empty type.
- The default `Sm90Compute::Arguments` is empty (`Sm90VisitorImpl<>::Arguments`, i.e. `cute::tuple<>`).
- Nodes with more than 4 ops use `cute::tuple` arguments on both sides, and `cute::tuple` stores
  nothing for empty element types.
- So the three `HostCompute` arguments in the 6-op DAG node of `HostEVTDAG` take space the device
  tuple doesn't have. The node's arguments are 64 bytes on the host and 56 on the device.
- As a result, the host arguments are 104 bytes but `CollectiveEpilogue::Arguments::thread` is 96
  bytes. The memcpy writes 8 uninitialized bytes into `ptr_C`, which follows `thread`.

This is the overwritten C pointer reported in the issue. It also affects the upstream
`..._cooperative_dag.cu` and `..._pingpong_dag.cu` EVTDAG tests. Whether it shows up depends on the
build, because the copied bytes are uninitialized.

The change makes `HostCompute::Arguments` empty, the same as `HostAccumulator::Arguments`. Nothing
reads the `op` member. For nodes with 4 or fewer ops (`ArgumentPack`), an empty member still takes
1 byte, so their layouts do not change.

Fixes #2862.

### Verification

No SM90 GPU was available, so the GPU unit tests were **not** run. All checks below are host-side.
They compile the real sources with clang in CUDA host-only mode against the CUDA 12.8 headers.

Command:
```
hostcc = clang++ -x cuda --cuda-host-only --cuda-path=<cuda-12.8> -nocudalib -std=c++17 -DNDEBUG \
         -D__CUDACC_VER_MAJOR__=12 -D__CUDACC_VER_MINOR__=8 \
         -I include -I tools/util/include -isystem <googletest-1.14.0>/googletest/include
         (plus local macOS-only header workarounds, not part of this change)

# 1) with a temporary size report and
#    static_assert(sizeof(epilogue_args.arg) <= sizeof(arguments.epilogue.thread))
#    added before the memcpy in Testbed3xEVT::run():
for f in $(grep -l "gemm_testbed_3x_evt.hpp\|sm90_evt_operations.hpp" test/unit/gemm/device/*.cu); do
  hostcc -fsyntax-only "$f"
done

# 2) host replay of the argument setup in Testbed3xEVT::run() for the EVTDAG Gemm
hostcc -I test/unit/gemm/device -O0 -c evt_args_check.cu && clang++ evt_args_check.o cudart_stub.o -o evt_args_check && ./evt_args_check
```

Result:
1. Sweep over the 12 sm90 test sources that use this testbed (28 `TestAllEVT` instantiations):
   - Before: 2 of 28 overflow. These are the EVTDAG tests in `..._cooperative_dag.cu:114` and
     `..._pingpong_dag.cu:114`, with host 104 B and device 96 B. Both files fail the static_assert.
     The other 26 have equal sizes.
   - After: 28 of 28 have equal sizes. EVTDAG is now 96 B = 96 B, the other 26 are unchanged,
     and all 12 files compile.
   - The DAG node's arguments go from 64 B on the host (device: 56 B) to 56 B.
2. The replay builds the `Gemm` of `SM90_..._cooperative_epilogue.256x128x64_2x2x1_EVTDAG`, and also
   the issue's float C/D, 128x128x64, 1x1x1 variant. It stamps known beta, alpha and aux
   ptr/null_default/stride values into the host arguments, sets `ptr_C = 0xc0c0c000`, does the memcpy,
   and reads back the device fields. I built it for both arm64 and x86-64.

   Before:
   ```
   sizeof(host EVT args)          = 104
   sizeof(epilogue.thread)        = 96
   offsetof(epilogue args, ptr_C) = 96
   device beta / alpha / aux ptr / aux null_default / aux stride   ok
   ptr_C before memcpy = 0xc0c0c000, after = 0x16ee42100
   ptr_C preserved                    MISMATCH
   FAIL
   ```
   After:
   ```
   sizeof(host EVT args)          = 96
   sizeof(epilogue.thread)        = 96
   offsetof(epilogue args, ptr_C) = 96
   device beta / alpha / aux ptr / aux null_default / aux stride   ok
   ptr_C before memcpy = 0xc0c0c000, after = 0xc0c0c000
   ptr_C preserved                    ok
   PASS
   ```
   In an -O2 build of the unfixed code, `ptr_C` survived for one configuration and was overwritten
   for the other. That fits the corruption depending on the build and optimization level.
