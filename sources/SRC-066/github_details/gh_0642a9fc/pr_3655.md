## Summary

Document how callers should interpret and report non-zero return codes from the exported CuTe DSL AOT C API, as requested in #3562.

## Changes

- Added an AOT error-handling section describing `cudaSuccess` and `cudaError_t` status values.
- Documented `cudaGetErrorName()` and `cudaGetErrorString()` for symbolic and human-readable diagnostics.
- Clarified the distinction between `CuteDSLRT_Error_t` loader errors and the CUDA status returned by the exported wrapper.
- Added a C++ example that checks the wrapper result.

## Testing

- `git diff --check` ✅
- Verified the documented return-code and error-helper behavior against the AOT C header generator and the maintainer's issue guidance.
- A full documentation build was not run locally because the repository's documentation tooling is not installed in this checkout.

## Notes

This is a documentation-only change. The implementation follows the maintainer's clarification that non-zero AOT return codes are `cudaError_t` values handled through the CUDA Runtime API. AI assistance was used in preparing this contribution; the submitted change has been reviewed for correctness.
