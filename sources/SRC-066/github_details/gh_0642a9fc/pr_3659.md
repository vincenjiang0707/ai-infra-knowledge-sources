## 正文

## Motivation

#3646: `make cutlass_profiler` fails for `CUTLASS_NVCC_ARCHS=120a`:

```
sm90_common.inl(321): error: static assertion failed with "BLK_K0 must be a multiple of size<1>(GMMA::Layout_K_INTER_Atom<ElementType>{})"
  ... ss_smem_selector<K, float_e5m2_t, _128, _8> ... sm120_get_epilogue_smem_swizzle_layout_atom ...
  ... cutlass3x_sm120_bstensorop_gemm_ue8m0xe4m3_ue8m0xe2m3_f32_void_e5m2_128x8x128_1x1x1_0_tnt_align128_cooperative_q.cu
```

## Root cause

This is a regression from #3176 ("Small Tile N BlockScaled GEMM"). That PR added N = 8/16/32/64 CTA tiles to `GenerateSM120_TensorOp_mixed_8bits_UMMA_gemm_with_block_scaled` and `GenerateSM120_TensorOp_fp4_UMMA_gemm_with_block_scaled`. There are two problems:

1. **The small tiles were put first.** Without a kernel filter, `CreateGemmUniversal3xOperator` instantiates only `tile_descriptions[0]` ("by default, only generate the largest tile"). Before #3176 that was `[128, 128, 128]`. Now it is `[128, 8, 128]` (cooperative) or `[128, 16, 128]` (ping-pong). A default `120a` configure of current `main` emits 286 non-grouped SM120 blockscaled GEMMs: 172 at N=8, 114 at N=16, and **none** at N=128.
2. **Every small tile is combined with every data type,** but for row-major C/D with `EpilogueTileAuto` the collective builders only accept some combinations:
   - **R1:** the epilogue tile N (`min(CTA_N, 32)`, from `sm120_compute_tile_shape_or_override`) must span a multiple of 128 bits for C and D. This comes from the swizzle atom in `ss_smem_selector` (`sm90_common.inl:321`). FP6 is stored in 8-bit containers.
   - **R2:** FP6 D needs `CTA_N % 128 == 0` (`sm120_builder.inl:158`).
   - **R3:** block-scaled D needs epilogue tile N / SFD vector size in {1, 2, 4, 8} (`Sm120BlockScaleFactorRowStore`, `sm120_visitor_store_tma_warpspecialized.hpp:72`).
   - **R4:** 6-bit B needs `CTA_N >= 32`. `sm120_rr_smem_copy_selector_B` (`sm120_common.inl:81`) always picks `SM100_SU6_DU8x16_x4_LDSM_N` for 6-bit B, so smaller N fails with "TiledCopy uses too few vals for selected CopyAtom". #3176 added x1/x2 variants only for 4-bit and 8-bit B.

**How many kernels fail (CUDA 12.8, `sm_120a`, the 286 kernels of a default build of current `main`):**

| | N=8 | N=16 | total |
|---|---|---|---|
| fail to compile | 155 / 172 | 78 / 114 | **233 / 286** |

The first error in each failed compile:

| error | count | constraint |
|---|---|---|
| `BLK_K0 must be a multiple of size<1>(GMMA::Layout_K_INTER_Atom...)` | 103 | R1 |
| `CTA tile for FP6 ElementD must have a contiguous extent that is a multiple of 128.` | 75 | R2 |
| `TiledCopy uses too few vals for selected CopyAtom` | 30 | R4 |
| `EpilogueTileN should be divisible by SFVecSize` | 25 | R3 |

I spot-checked each error class with CUDA 13.0 and got the same results.

## Modifications

`python/cutlass_library/generator.py`, SM120 blockscaled dense generators only:

- Put the original large tiles back at the front of `tile_sizes_cooperative` / `tile_sizes_pingpong`, followed by the small-N tiles in decreasing N. A default build instantiates `[128, 128, 128]` again, as it did before #3176.
- Add `sm120_blockscaled_supports_tile_n(tile_n, data_type)`, which encodes R1–R4. Each data type is generated only with the tile N values the builders accept, so filtered builds (for example `CUTLASS_LIBRARY_KERNELS=cutlass3x_sm120*`) no longer contain kernels that cannot compile. The small tiles remain wherever they are valid, for example f32/f16 output at N=8, e5m2 output at N=16, and FP4 output at N=32/64.

No C++ changes. The x1/x2 variants of `SM100_SU6_DU8x16_*_LDSM_N` exist, so an alternative for R4 would be to extend `sm120_rr_smem_copy_selector_B` the way #3176 did for 4-bit and 8-bit B. That would add new FP6-B small-tile kernels, and I can't validate them without SM120 hardware, so I left the selector as is.

## Testing

I ran compile-only checks, because I have no SM120 GPU (`-DCUTLASS_NVCC_ARCHS=120a`).

**The filter agrees with nvcc on every kernel of the default build.** Of the 286 compile outcomes above, `sm120_blockscaled_supports_tile_n` accepts exactly the 53 that compile and rejects exactly the 233 that fail (286/286 agree).

**Results with this PR:**

| build | result |
|---|---|
| default `120a` configure, CUDA 13.0: `ninja cutlass_profiler` | **builds and links**: 1981 objects, 0 failures. The 350 library shards contain 500 SM120 blockscaled GEMMs (286 + 214 grouped), all `128x128x128` |
| default `120a` configure, CUDA 12.8: `ninja cutlass_profiler` | all 500 SM120 blockscaled GEMMs compile. 5 profiler/reference objects (`gemm_int4.cu`, `conv2d.cu`, `conv3d.cu`, `gemm_int8_interleaved_64.cu`, `device_allocation.cu`) still fail with `subbyte_reference.h(459): error: too few arguments in function call` (`__nv_atomic_load_n`). That is a separate CUDA 12.8 issue, fixed by #3301, and unrelated to this change |
| `CUTLASS_LIBRARY_KERNELS=cutlass3x_sm120_bstensorop_gemm*_128x{8,16,32,64}x*`, CUDA 12.8: every generated kernel | **1042 / 1042 compile** (597 non-grouped + 445 grouped) |

The generator has no unit-test harness in-tree, so I did not add a test.

Closes #3646
