## Summary

Adds a CuTeDSL port of CUTLASS Example 67's groupwise variant (`67_hopper_fp8_warp_specialized_gemm_with_groupwise_scaling.cu`) at `examples/python/CuTeDSL/hopper/dense_gemm_fp8_groupwise.py`.

The kernel computes

```
D = scale_d * relu(alpha * scale_a * scale_b * accum)
accum[m, n] = sum_k SFA[m, k] * SFB[n // 128, k]
                    * (A[m, k*128:(k+1)*128] @ B[k*128:(k+1)*128, n])
```

`ScaleGranularityM = 1`: one Float32 scale per M row per K-tile for A (SFA) and one per 128-column block of B per K-tile (SFB). Per-row SFA is applied per accumulator element via a coordinate tensor that maps every WGMMA register fragment to its absolute M row, so the scale lookup does not depend on the WGMMA register layout.

Cooperative pipeline: one DMA warpgroup feeds two MMA warpgroups via a multi-stage SMEM ring. Tile shape is fixed at (256, 128, 128); output D is BFloat16 N-major.

## Performance optimizations on top of the baseline

Four small commits stacked on the initial port. Each delta is measured against the prior commit at H100, `cluster=(1,2)`, 200 iter + 10 warmup. Cumulative delta is +10 to +15% depending on shape.

| Commit | Optimization | Δ on 4096³ | Notes |
|---|---|---|---|
| `f1387583` | Register split 24/240 (was 40/232) | **+9%** | DMA warpgroup only holds TMA descriptors + barrier addrs — 24 regs is plenty. Shifting 8 regs to the math warpgroups eliminates the spill on FP32 accumulator + per-row SFA registers. Same change as PR1 (where it gave +26%); smaller win here because PR2's gap mix is more memory-bound. |
| `125c322c` | Programmatic Dependent Launch | 0% large / +6% (1024³) | `griddepcontrol.wait` at entry + `use_pdl=True` on launch. Lets the runtime overlap this kernel's prologue with the prior kernel's tail on the same stream. Visible only on launch-bound shapes. |
| `9edc9a9e` | Cluster-aware rasterization swizzle | +0.5% | `--swizzle_size` default switches to a cluster-aware optimum (1 for any multicast cluster, 2 for `(1,1)`); user can still override. |
| `4117b0c6` | Lazy `tma_store` producer_acquire | ~0% | Acquire moved to immediately *before* the next TMA store instead of trailing the commit. Structurally aligned with DeepGEMM; near-zero perf delta because the existing `epi_stage=4` already provided enough slack. |

C++: `examples/67_..._gemm_with_groupwise_scaling --m=M --n=N --k=K --iterations=200 --verify=false`. CuTeDSL: `--iterations 200 --warmup_iterations 10`. A further perf opportunity left as a follow-up: staging the per-row SFA tile through SMEM (TMA-loaded alongside A/B) rather than reading from GMEM per accumulator element — see DeepGEMM `sm90_fp8_gemm_1d2d.cuh:192-200`. The implementation is still meant as a CuTeDSL learning example and not a drop-in replacement for the C++ collective builders.
