## Summary

Adds a CuTeDSL port of CUTLASS Example 67's blockwise variant (`67_hopper_fp8_warp_specialized_gemm_with_blockwise_scaling.cu`) at `examples/python/CuTeDSL/hopper/dense_gemm_fp8_blockwise.py`.

The kernel computes

```
D = scale_d * relu(alpha * scale_a * scale_b * accum + beta * scale_c * C)
accum[m, n] = sum_k SFA[m // 128, k // 128] * SFB[n // 128, k // 128]
                    * (A[m, k*128:(k+1)*128] @ B[k*128:(k+1)*128, n])
```

with one Float32 scale factor per 128-row block of A (SFA) and per 128-column block of B (SFB), indexed by K-tile. Pipeline: a DMA warpgroup feeds the MMA warpgroup over a multi-stage SMEM ring; the MMA warpgroup runs WGMMA per K-tile, multiplies the partial accumulator by SFA*SFB before adding it to the running accumulator, applies the alpha/beta/scale_c/scale_d + ReLU epilogue, then R2S + TMA store of D.

Tile (128, 256) is intentionally not exposed — with the cooperative atom layout (2, 1, 1) it would span two SFB entries per tile, which the blockwise mainloop doesn't handle. This is documented in the parser and the kernel class.

## Performance optimizations on top of the baseline

Five small commits stacked on the initial port, each measured independently against the prior commit on H100 at `cluster=(1,2)`, 200 iter + 10 warmup. Cumulative delta is +15 to +29% depending on shape.

| Commit | Optimization | Δ on 4096³ | Notes |
|---|---|---|---|
| `a1dad1d3` | BF16 D output | 0% | Matches the FP8-GEMM family convention; halves SMEM-D and unblocks `ab_stage` 5 → 6, though pipeline depth was not the binding constraint here. |
| `472f3f76` | Programmatic Dependent Launch | 0% large / +7% (1024³) | `griddepcontrol.wait` at entry + `use_pdl=True` on launch. Lets the runtime overlap the kernel's prologue with the prior kernel's tail on the same stream. Visible only on launch-bound shapes. |
| `74f5221a` | Cluster-aware rasterization swizzle | +1% | `--swizzle_size` default switches to a cluster-aware optimum (1 for any multicast cluster, 2 for `(1,1)`); user can still override. Sweep showed `sz=1` consistently beats `sz=2` on the three multicast configs. |
| `ef58af70` | Lazy `tma_store` producer_acquire | +1% | Acquire moved to immediately *before* the next TMA store instead of trailing the commit, matching DeepGEMM's `tma_store_wait<0>` pattern at the start of the next tile's epilogue. |
| `34a82c45` | Register split 24/240 (was 40/232) | **+26%** | DMA warpgroup only holds TMA descriptors + barrier addrs — 24 regs is enough. Shifting 8 regs to the math warpgroups eliminates the spill on the FP32 accumulator + scale registers in the inner loop. Dominant single trick. |

## Notes

- C must be passed with `is_dynamic_layout=False` so that `thr_mma.partition_C` sees static strides; with dynamic strides the per-thread offsets collapse to zero and `beta != 0` produces wrong results.
- Scale-factor indexing uses `(tile_coord * tile_size) // 128` so the small-tile (64×64, 128×64) configurations index SFA/SFB correctly.
- D output is BF16 (the FP8-GEMM family convention, matching the groupwise and grouped-blockwise ports); C input remains Float32 to keep the per-element `beta * scale_c * C` path in full precision.
- `--swizzle_size` defaults to a cluster-aware optimum (1 for any multicast cluster, 2 for the single-CTA case); pass an explicit value to override.
- Programmatic Dependent Launch (`griddepcontrol.wait` + `use_pdl=True`) is enabled at kernel entry; lets the runtime overlap this kernel's prologue with the prior kernel's tail on the same stream.
