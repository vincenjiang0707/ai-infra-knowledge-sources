# [PR #3678] [CuTeDSL] Raise on unsupported tma_desc_ptr types in TMA copies

## 正文

Fixes #3670

In each of those seven `unpack()` methods, the guard is now `if tma_desc_ptr is not None:`.
Its first statement raises a `ValueError` when the value is not a `cute.Pointer`:

```
ValueError: expects a `cute.Pointer` to be provided via the tma_desc_ptr kw argument, but got cutlass.base_dsl.typing.Pointer
```

This copies the structure of the `cache_policy` check a few lines below in the same methods
(`if cache_policy is not None: if not isinstance(cache_policy, Int64): raise ValueError(...)`).
It also makes `tma_desc_ptr` consistent with `tma_bar_ptr`, which already raises a
`ValueError` when handed a `cutlass.Pointer`. The error includes the received type's module
because both classes are named `Pointer`.

Nothing changes for `None` or a `cute.Pointer`: the body that sets the field is untouched.
The change does not decide whether `cute.copy` should accept a `cutlass.Pointer` in the future.
It only stops such a value from being dropped silently.

I also added `test/python/CuTeDSL/test_tma_desc_ptr_type.py`, a compile-only test that needs no
GPU. Using fake tensors and `--gpu-arch sm_90a`, it checks:
- For a tile TMA load and a tile TMA store, `tma_desc_ptr=TensorMap.get_ptr()` raises
  `ValueError`.
- `tma_desc_ptr=None` and a `cute.Pointer` from
  `TensorMapManager.get_tensormap_ptr(..., AddressSpace.generic)` still compile.

### Verification

Environment: Linux aarch64 (Ubuntu 26.04 VM), Python 3.12.14, no GPU, so everything is
compile-only.
- `nvidia-cutlass-dsl==4.8.0` came from PyPI with the cu12 libs.
- The installed Python front end is identical to `main` except for the `__version__`
  placeholder and `_mlir_helpers/{vector,math}.py`.
- I linked those two helpers and `cute/nvgpu/cpasync/copy.py` to this branch's files.
- "Before" runs used `main`'s `copy.py`.

1. Reproducer from the issue, adapted to fake tensors and compile-only with `--keep-ptx` at sm_90a:

   Command: `CUTE_DSL_ARCH=sm_90a python repro_3670.py`

   Result before the fix, same as the issue:
   ```
   [baked]    ptx md5 (name-normalised): 2188b31bd5f3
   [get_ptr]  get_ptr() -> cutlass.base_dsl.typing.Pointer, isinstance(p, cute.Pointer) = False
              ptx md5 (name-normalised): 2188b31bd5f3
   [retyped]  ptx md5 (name-normalised): e1f8606e0507
   get_ptr PTX identical to baked PTX: True
   ```

   Result after the fix:
   ```
   [baked]    ptx md5 (name-normalised): 2188b31bd5f3
   [get_ptr]  cute.compile raised ValueError: expects a `cute.Pointer` to be provided via the tma_desc_ptr kw argument, but got cutlass.base_dsl.typing.Pointer
   [retyped]  ptx md5 (name-normalised): e1f8606e0507
   ```

   The PTX for the supported paths is byte-identical before and after.

2. CuTe DSL unit tests, with the JIT cache disabled:

   Command: `CUTE_DSL_NO_CACHE=1 python -m pytest -p no:cacheprovider -q test/python/CuTeDSL`

   Result after the fix:
   ```
   35 passed, 92 warnings, 418 subtests passed in 3.52s
   ```

   Result before the fix (new test only fails):
   ```
   SUBFAILED(is_load=True) test/python/CuTeDSL/test_tma_desc_ptr_type.py::TestTmaDescPtrType::test_non_cute_pointer_raises
   SUBFAILED(is_load=False) test/python/CuTeDSL/test_tma_desc_ptr_type.py::TestTmaDescPtrType::test_non_cute_pointer_raises
   2 failed, 35 passed, 92 warnings, 416 subtests passed in 4.07s
   ```
   (`AssertionError: ValueError not raised`)

3. Changed methods: I compiled four of the seven changed `unpack()` methods with `None`, a
   `cute.Pointer`, and `TensorMap.get_ptr()` as `tma_desc_ptr`. The four ops were
   `CopyBulkTensorTileG2SOp`, `CopyBulkTensorTileG2SMulticastOp`, `CopyBulkTensorTileS2GOp`
   and `CopyReduceBulkTensorTileS2GOp`.
   - Before: all three compiled for every op. The `cutlass.Pointer` case was silently dropped.
   - After: `None` and `cute.Pointer` compile, and `cutlass.Pointer` raises the `ValueError`.

4. In-tree callers: every in-tree `tma_desc_ptr=` caller in `examples/python/CuTeDSL` passes one
   of two things:
   - `TensorMapManager.get_tensormap_ptr(..., AddressSpace.generic)`, in the grouped GEMM examples
   - the MoE examples' `moe_utils.tensormap_ptr_for_copy(...)`, or `None`

   I compiled both helpers into a load and a store with the patch applied. Both return
   `cutlass.cute.core._Pointer` (`isinstance(p, cute.Pointer)` is True), change the PTX relative
   to `None`, and produce the same PTX hashes before and after the fix.

5. `ruff format --check` and `ruff check --select E,F,W` report nothing new for either file. The
   pre-existing findings in `copy.py` are unchanged.
