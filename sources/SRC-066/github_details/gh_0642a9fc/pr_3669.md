# [PR #3669] [CuTeDSL] Add non-TMA bulk FP32 reduction CopyOp

## 正文

FlashAttention's dQ path currently issues `cp.reduce.async.bulk.global.shared` through a local PTX wrapper ([consumer example](https://github.com/Dao-AILab/flash-attention/blob/c4d8b0630eb81cf88206e0cc9e9bff4e7806d88f/flash_attn/cute/flash_bwd_sm100.py#L2563)). Add `CopyReduceBulkS2GOp` so callers can construct a CuTe CopyAtom, partition a tile, and call `cute.copy` for the non tensor-map `add.f32` reduction. Related: #3029.

The existing bulk S2G atom supplies the partition layout. A Python `cute.copy` dispatch emits the reduction PTX because the current compiler binding has no dedicated non tensor-map reduction atom type. The supported first pass is one contiguous, 16-byte-aligned FP32 tile per call, with a byte count divisible by 16. The caller elects one issuing thread, fences shared writes, and commits/waits on the bulk group, consistent with other non tensor-map bulk operations. The tensor-map reduction path is unchanged.

RTX 5090 / SM120, CUDA 13.0.88, driver 580.82.07: eight cases (16, 128, 512, 4096 bytes × 1/4 CTAs) matched a direct PTX reference bit for bit, including nonzero destination initialization and competing CTA additions. Noncontiguous, misaligned, non-FP32, and non-16-byte-granular inputs are rejected before code generation. The PTX for all eight cases contains `cp.reduce.async.bulk.global.shared::cta.bulk_group.add.f32`; all corresponding cubins contain `UBLKRED.G.S.ADD.F32.RN`.

| Bytes | CTAs | Direct PTX (µs) | CopyOp (µs) | Speedup |
|---:|---:|---:|---:|---:|
| 16 | 1 | 8.437 | 8.452 | 0.998× |
| 16 | 4 | 8.012 | 7.992 | 1.003× |
| 4096 | 1 | 8.235 | 8.325 | 0.989× |
| 4096 | 4 | 8.168 | 8.225 | 0.993× |

These are launch-level CUDA-event timings, four samples per arm in balanced ABBA/BAAB order, 128 calls per sample, on one GPU. They show no measurable acceleration; the change provides a reusable API. The correctness test covers all eight sizes/CTA cases and the rejection tests cover the supported contract.

A consumer-level dQ check also passed. PyTorch SDPA supplied the reference gradient; its softmax backward was split across two key/value ranges, then the CopyOp accumulated both dQ tiles into one output. Max absolute error was `9.54e-7` for `(batch, heads, seq, dim)=(1,2,64,32)` and `1.79e-6` for `(2,3,96,64)`. This validates the reduction in an attention backward calculation; it is not a pretrained-model or full FlashAttention performance result.

**Draft validation boundary:** tests ran against an isolated Python source copy of CuTeDSL 4.6.2 with the same three changes transplanted from this PR. Current `main` does not import with those installed binaries (`NumericCast` missing); a matching-current-main compiler run remains outstanding. No installed packages were changed.
