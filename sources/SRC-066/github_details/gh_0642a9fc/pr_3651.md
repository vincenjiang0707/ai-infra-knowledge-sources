## 正文

## Motivation

#3496: `EpilogueDirectStore` computes the warp's (m, n) position in the threadblock tile with

```cpp
int warp_id_mn = warp_idx % (WarpCount::kM * WarpShape::kN);   // WarpShape::kN is the warp tile's N extent
```

`EpilogueBase` uses `WarpCount::kM * WarpCount::kN`, the number of warps in the MN plane.

I tried to build a failing config for the case described in the issue, `WarpCount::kN > WarpShape::kN`, and could not make a valid one. An 8-wide warp tile (for example 128x128x32 CTA with 128x8x32 warps) also fails with the **default** epilogue, so that config is not supported by the SM80 mainloop/epilogue in general. An N=16 warp tile would need at least 17 warps along N, which exceeds the register file. So that path is latent, as the issue says.

The typo **is** reachable through sliced-K (`kPartitionsK > 1`), which `EpilogueDirectStore` does not reject. For a 64x64x64 threadblock with 64x64x32 warps, WarpCount = (1, 1, 2). The second K-partition warp gets `warp_id_mn = 1 % (1 * 64) = 1`, so `warp_n = 1`, and it stores its partial sums into columns 64..127, the **neighbouring threadblock's output tile**. Those writes stay inside D, so compute-sanitizer reports nothing and the results are silently wrong. Even with the correct modulo, sliced-K cannot work with this epilogue: it stores accumulators straight from registers and has no cross-warp reduction over K partitions, so both K-partition warps would write different partial sums to the same elements.

## Modifications

`include/cutlass/epilogue/threadblock/epilogue_direct_store.h`:
- Use `WarpCount::kM * WarpCount::kN` for the MN-plane warp decomposition, matching `EpilogueBase`.
- Add `static_assert(kPartitionsK == 1, ...)` so that sliced-K configurations fail at compile time with a clear message, instead of producing wrong results.

## Testing

Built with CUDA 12.8, `-DCUTLASS_NVCC_ARCHS="80;90"`; run on NVIDIA H200 (SM90) and A800 (SM80).

- Existing test `SM80_Device_GemmUniversal_DirectStore_f16n_f16t_f32n_tensor_op_f32.128x128x32_64x64x32` (`cutlass_test_unit_gemm_device_tensorop_f32_sm80`): **passes** on both GPUs with this change.
- Sliced-K diagnostic (not included in the PR): 64x64x64 threadblock / 64x64x32 warps / `DefaultEpilogueDirectStore`, run through `TestAllGemmUniversal`:
  - Same mainloop with the default epilogue: passes.
  - Direct store, original header: **fails** (memcheck: 0 errors, i.e. wrong values written inside D).
  - Direct store, modulo fix only: **fails** (no K-partition reduction).
  - Direct store, this PR: **compile error**:
    ```
    epilogue_direct_store.h(145): error: static assertion failed with "The direct store epilogue does not reduce
    accumulators across K partitions (sliced-K). Use a warp shape whose K extent equals the threadblock shape's K extent."
    ```

I did not add a runtime test for the `WarpCount::kN > WarpShape::kN` case, because I could not construct a supported configuration that reaches it (see above).

Closes #3496
