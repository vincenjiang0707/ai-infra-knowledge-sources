# [PR #3676] [CuTeDSL] Convert gmem TMA descriptor pointers to generic in tma_desc_ptr

## 正文

**Fixes #3671.** Verified on hardware: the reported libNVVM failure reproduces before this change and is gone after.

> Stacked on #3675 (which adds the `_to_tma_desc_ptr` helper) — only the second commit is new here. I'll rebase once #3675 lands.

## Cause

`TensorMapManager.get_tensormap_ptr()` defaults to a gmem-space `!cute.ptr<tma_descriptor_tiled, gmem, align<128>>` — also the form `copy_tensormap` needs for a global-memory workspace. Passed as `tma_desc_ptr=`, it got past the type check, was lowered as `ptr addrspace(1)`, and was handed to `llvm.nvvm.cp.async.bulk.tensor.*`, whose descriptor operand is a generic `ptr`. libNVVM then failed with `Call parameter type does not match function signature!` and a suggestion pointing at `CUDA_TOOLKIT_PATH`. A shared-memory pointer failed later still, with an internal IR verification error.

## Fix

The TMA instructions take the descriptor as a generic address, and the generic address of a global location equals its global address. `_to_tma_desc_ptr` now converts a gmem cute pointer to a generic one (keeping its alignment, at least 64B) — the same conversion `get_tensormap_ptr(ptr, AddressSpace.generic)` and the grouped GEMM examples already do by hand. Pointers in any other address space raise a `ValueError` that names the address space.

## Verification

B200 (`sm_100a`), CUDA 13.2, DSL 4.8.0 — the #3671 reproducer (TMA load through a global-memory copy of the atom's descriptor):

| `tma_desc_ptr` | before | after |
|---|---|---|
| generic (converted by hand) | `y == x` | `y == x` |
| gmem (`get_tensormap_ptr` default) | **libNVVM signature mismatch** | `y == x` |
| smem | internal IR verification error | `ValueError` |

Generic pointers are passed through unchanged, so existing callers are unaffected — the Blackwell `grouped_gemm.py` and `grouped_blockscaled_gemm.py` examples pass before and after.
