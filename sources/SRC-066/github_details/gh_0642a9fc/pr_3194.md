## Summary

Adds a CuTeDSL port of CUTLASS Example 68's grouped blockwise GEMM (`68_hopper_fp8_warp_specialized_grouped_gemm_with_blockwise_scaling.cu`) at `examples/python/CuTeDSL/hopper/dense_gemm_fp8_grouped_blockwise.py`.

For each non-empty group g the kernel computes

```
D_g = alpha_g * sum_k SFA_g[m, k] * SFB_g[n // 128, k]
                    * (A_g[:, k*128:(k+1)*128] @ B_g[k*128:(k+1)*128, :])
```

with per-row A scaling (`ScaleGranularityM = 1`) and blockwise B scaling (`ScaleGranularityN = 128`). Output D and inputs A/B are FP8 E4M3FN; SFA, SFB, and the accumulator are Float32. Only beta = 0 is currently supported.

Kernel design:

- Cooperative warp-specialized schedule with one DMA + two MMA warpgroups; tile shape (128, 128, 128).
- Persistent group tile scheduler (`StaticPersistentGroupTileScheduler`) drives per-group iteration; A/B/D TMA descriptors are updated in GMEM at each group boundary via `utils.TensorMapManager`.
- Per-row SFA is applied via a coordinate tensor partitioned by the MMA layout, so the scale lookup does not depend on the WGMMA register layout.

Per-group GMEM tensors are allocated through `cutlass_torch.cute_tensor_like` so device pointers come from PyTorch's standard CUDA caching allocator (canonical 0x7f… VA), which is what the TMA hardware expects when those pointers are patched into the descriptor at runtime.

## Performance optimizations on top of the baseline

Three small commits stacked on the initial port. Each delta is measured against the prior commit. Cumulative delta is modest (PR3 had little headroom to begin with) but each is a structural improvement matching upstream conventions.

| Commit | Optimization | Δ (largest case) | Notes |
|---|---|---|---|
| `af27955b` | Register split 24/240 (was 40/232) | +2.6% (64 groups) | DMA warps only hold TMA descriptors + barrier addrs. Shifting 8 regs to math warpgroups helps the math side's larger live set (per-group pointer/stride state + tensormap workspace + accumulator). Smaller win than on PR1 because PR3 was already near the C++ ratio. |
| `19115bfc` | Programmatic Dependent Launch | +2.4% (4 groups) | `griddepcontrol.wait` at entry + `use_pdl=True`. Largest win on the smallest-group case where launch overhead is the biggest fraction of total runtime. |
| `0df0c4f9` | Lazy `tma_store` producer_acquire | +0.6% | Acquire moved to immediately *before* the next TMA store instead of trailing the commit. Structural alignment with DeepGEMM. |

Cluster-aware swizzle skipped on PR3 — the grouped tile scheduler does not take a swizzle parameter. SF→SMEM (TMA-loaded per-row SFA) is a known further opportunity left as a follow-up; see DeepGEMM `sm90_fp8_gemm_1d2d.cuh:192-200`.

Per the #3202 examples-tree reorganization, the file now sits at `examples/python/CuTeDSL/cute/hopper/kernel/grouped_gemm/grouped_gemm_fp8_blockwise.py`, alongside the existing `grouped_gemm.py` rather than under `dense_gemm/`.

**NVVM TMA binding port.** The previous revision no longer imported on DSL >= 4.7: `CpAsyncBulkTensorLoadMode` was removed from `_nvvm_enum_gen`, and `elect_sync` became keyword-only. Folded into the baseline port commit so that commit still builds and validates standalone.
