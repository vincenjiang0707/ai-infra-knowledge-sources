## 正文

## Summary

The running example in [Partitioning Tensors](https://docs.nvidia.com/cutlass/latest/media/docs/pythonDSL/guides/mma/wmma_programming.html#partitioning-tensors) (GEMM 512×512×256, `cta_tiler = (128, 128, 32)`, `atom_layout_mnk = (2, 2, 1)`, F16 `m16n8k16`, `permutation_mnk = (32, 32, 16)`) gives `MMA_N = BN/perm_N = 4`. CuTe DSL returns `MMA_N = 8` for both B and C.

`MMA_N` is not `BN/perm_N`. The N doubling in `permutation_mnk` makes each warp repeat its atom twice inside one `perm_N = 32` block, and `partition_B` / `partition_C` count those repeats together with the 4 blocks: `MMA_N = BN / (atom_layout_N × inst_N) = 128 / 16 = 8`. The same rule gives `MMA_M = 4`, and the doc has that one right, but only because `perm_M` equals the atom coverage (2 × 16).

A second check is to count values per thread. Each thread must hold `128 × 128 / 128 = 128` accumulators. `((2,2), 4, 8)` gives 128. The documented `((2,2), 4, 4)` gives only 64, which is half the CTA tile.

## Changes (`media/docs/pythonDSL/guides/mma/wmma_programming.rst` only)

- The sA/sB partition diagram: `MMA_N = BN/perm_N = 4` → `MMA_N = 2 x BN/perm_N = 8`.
- The "After partition" bullets: `tCsB (MMA, 8, 2, 4)` and `tCgC (MMA, 4, 8)` with `MMA_N = 2 × BN/perm_N`, plus one sentence on where the factor 2 comes from.
- Making Fragments: `tCsB MMA_N=8`, `tCrB (MMA, 8, 2)`, `tCgC MMA_N=8`, `tCrC (MMA, 4, 8)`.

## Verification

Checked with `nvidia-cutlass-dsl` 4.7.1 and 4.8.0. Both give the same output:

```python
import cutlass
import cutlass.cute as cute

@cute.jit
def run():
    op = cute.nvgpu.warp.MmaF16BF16Op(cutlass.Float16, cutlass.Float32, (16, 8, 16))
    tiled_mma = cute.make_tiled_mma(op, cute.make_layout((2, 2, 1)), permutation_mnk=(32, 32, 16))
    thr = tiled_mma.get_slice(0)
    print("tCsA:", thr.partition_A(cute.make_identity_tensor((128, 32, 4))).layout)
    print("tCsB:", thr.partition_B(cute.make_identity_tensor((128, 32, 4))).layout)
    print("tCgC:", thr.partition_C(cute.make_identity_tensor((128, 128))).layout)
    print("tCrB:", tiled_mma.make_fragment_B(tiled_mma.partition_shape_B((128, 32))).layout)
    print("tCrC:", tiled_mma.make_fragment_C(tiled_mma.partition_shape_C((128, 128))).layout)

run()
```

```
tCsA: ((2,2,2),4,2,4):((1@1,8@0,8@1),32@0,16@1,1@2)
tCsB: ((2,2),8,2,4):((1@1,8@1),16@0,16@1,1@2)
tCgC: ((2,2),4,8):((1@1,8@0),32@0,16@1)
tCrB: ((2,2),8,2):((1,2),4,32)
tCrC: ((2,2),4,8):((1,2),4,16)
```

The stride `16@1` on the `MMA_N` mode of `tCgC` shows each step is one 16-wide atom placement (2 warps × 8), not one 32-wide `perm_N` block. The page's other `MMA_M` / `MMA_K` values (4 and 2) match this output and are left unchanged. Running `docutils` on the file gives the same warnings before and after the change.
