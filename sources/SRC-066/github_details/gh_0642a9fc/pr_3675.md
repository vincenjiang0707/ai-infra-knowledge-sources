# [PR #3675] [CuTeDSL] Honour cutlass.Pointer TMA descriptors passed via tma_desc_ptr

source: https://github.com/NVIDIA/cutlass/pull/3675
state: open | updated: 2026-09-24T20:08:11Z
labels: 

## 正文

**Fixes #3670.** Verified on hardware: the reported silent fallback reproduces before this change and is gone after.

## Cause

Every TMA trait's `unpack` in `cute/nvgpu/cpasync/copy.py` sets the `tma_descriptor_ptr` field only `if isinstance(tma_desc_ptr, cute.typing.Pointer)`. `TensorMap.get_ptr()` returns a `cutlass.Pointer` (`base_dsl.typing.Pointer`), which is not a cute pointer, so it was dropped without an error — the copy compiled, ran, and used the descriptor baked into the atom by `make_tiled_tma_atom`. Any other non-pointer value (e.g. an `Int64`) was dropped the same way.

## Fix

Route all seven `tma_desc_ptr` sites (tiled / gather4 / im2col G2S, their multicast variants, S2G store and S2G reduce) through one helper, `_to_tma_desc_ptr`:
- cute pointers pass through unchanged;
- a gmem or generic `cutlass.Pointer` is converted to `!cute.ptr<tma_descriptor_tiled, generic, align<64>>` — the same form `TensorMapManager.get_tensormap_ptr(..., AddressSpace.generic)` produces (`CUtensorMap` is 64B aligned);
- anything that is not a pointer raises `TypeError`, and a `cutlass.Pointer` outside generic/gmem raises `ValueError`.

## Verification

B200 (`sm_100a`), CUDA 13.2, DSL 4.8.0 — the #3670 reproducer (one CTA TMA-loads a 64x64 fp32 tile of `x`; the override map is based at `z`, so an honoured override gives `y == z`):

| `tma_desc_ptr` | before | after |
|---|---|---|
| none (baked) | `y == x` | `y == x` |
| `TensorMap.get_ptr()` | **`y == x` (silently ignored)** | `y == z` |
| `get_ptr()` re-typed by hand | `y == z` | `y == z` |
| `Int64(0)` | **`y == x` (silently ignored)** | `TypeError` |

With the fix, the `get_ptr()` PTX is identical to the hand re-typed workaround. This also makes the #3672 workaround of passing a `create_tensor_map_tiled_from_view(..., l2_promotion=l2_256b)` map work directly through `get_ptr()` (verified: `y == z`).

Existing cute-pointer callers are unaffected — the Blackwell `grouped_gemm.py` example passes before and after. The gmem-pointer failure in #3671 is fixed separately in a follow-up PR.
