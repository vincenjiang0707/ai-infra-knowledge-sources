## 正文

## Summary

- Track completed CLC work tiles locally in the epilogue warps.
- Rotate TMA-store shared-memory stages using the epilogue's actual tile count.
- Prevent short-K dynamic persistent GEMMs from reusing an SMEM stage while its previous TMA store is still in flight.

## Root cause

`ClcDynamicPersistentTileScheduler` is instantiated independently in each specialized warp. Only the scheduler warp calls `advance_to_next_work()`, which increments that instance's `num_tiles_executed`. The TMA, MMA, and epilogue warps consume the CLC response through `get_current_work()`, so their scheduler-local counters remain zero.

The TMA-store epilogue uses `num_tiles_executed` to select its C-SMEM stage:

```text
c_buffer =
    (num_tiles_executed * subtile_count + subtile_idx)
    % num_c_stages
```

For the reproducer below, each M64xN256 output tile has four M64xN64 epilogue subtiles and a three-stage C-SMEM ring. A counter permanently equal to zero restarts every output tile at stage zero and can overwrite a stage still owned by an earlier asynchronous TMA store. Large K hides the race behind mainloop latency; short K exposes it.

## Fix

Initialize a local epilogue tile counter before the persistent loop and increment it after each completed tile. This keeps all epilogue threads in lockstep and avoids changing the public CLC scheduler semantics.

## Reproduction

Environment:

- GPU: NVIDIA B30Z, compute capability 10.3
- A/B/C: FP16/FP16/FP16, FP32 accumulation
- CTA tile: M64xN256
- CTA group: 1
- Cluster: `(1,1)`
- CLC raster/swizzle: M/1
- TMA store: enabled

Before this change:

```text
MNK: 8256x8448x128
Mismatched elements: 755401 / 69746688 (1.1%)
Greatest absolute difference: 158.0
```

After this change:

```text
MNK: 8256x8448x128
FP32 reference check: PASS
```

## Validation

- `python -m py_compile .../dense_gemm_persistent_dynamic.py`: PASS
- FP16 `8256x8448x128`, CTA M64xN256, cluster `(1,1)`, TMA store: PASS
- FP16 `8192x8192x8192`, CTA M64xN256, cluster `(1,1)`, TMA store: PASS
  - Smoke runtime: 976.69 us
- FP16 `4096x4096x128`, CTA M64xN256, cluster `(1,2)`, TMA multicast + TMA store: PASS
- FP16 `4096x4096x128`, CTA M64xN256, cluster `(1,1)`, direct non-TMA epilogue: PASS

The full-K target remains performance-neutral; this change only corrects C-SMEM ring indexing in fast tile-turnover cases.

## Scope

This PR intentionally does not change CLC swizzle-domain padding behavior. That is a separate issue and should be handled independently.
