# [PR #3656] [CuTe] Reject Copy_Atom copies whose src/dst size does not match the CopyOp (#3488)

## 正文

## Motivation

#3488: `copy_if(Copy_Atom<...>, prd, src, dst)` with a smaller `dst` silently writes out of bounds. I reproduced it host-only with g++ 13 and ASan, using the issue's example (`UniversalCopy<uint128_t>` over `float`, `src` (4,3), `dst` (2,3)):

```
ERROR: AddressSanitizer: stack-buffer-overflow ... WRITE of size 16
    #3 cute::copy_unpack<...>        include/cute/atom/copy_traits.hpp:133
    #4 cute::Copy_Atom<...>::call    include/cute/atom/copy_atom.hpp:149
```

One correction to the issue: the sibling `copy(Copy_Atom<...>{}, src, dst)` is **not** safe either. The same repro through `copy` gives the same 16-byte out-of-bounds write (`copy_atom.hpp:103`). Only the atom-less `copy(src, dst)` avoids the instruction.

## Root cause

`Copy_Atom::call()` dispatches to `copy_unpack()` as soon as **either** slice has the instruction's element count (`is_constant<NumValSrc, size(src)> || is_constant<NumValDst, size(dst)>`). `copy_unpack()` then recasts both slices to the CopyOp's register type and only checks the **register count**:

```cpp
Tensor rD = recast<RegTypeDst>(dst);
CUTE_STATIC_ASSERT_V(size(rD) == Int<RegNumDst>{}, ...);
```

`recast<>` rounds a partial register up to a whole one. A 2-float (64-bit) slice recast to `uint128_t` therefore still has size 1, the assertion passes, and the 128-bit instruction writes past the slice.

## Modifications

- `include/cute/atom/copy_traits.hpp`: the generic `copy_unpack()` now also requires that `src` and `dst` hold **exactly** as many bits as the CopyOp's registers (`size(t) * sizeof_bits_v<value_type> == RegNum * sizeof_bits_v<RegType>`). The check is done per side, so converting ops whose src and dst registers differ are unaffected. A mismatch now fails to compile:
  ```
  error: static assertion failed: Copy_Traits: dst tensor size does not match this CopyOp.
         The copy would access memory outside the dst tensor.
  ```
  The `copy_unpack` overloads for the SM80/SM90/SM100 TMA, im2col and async ops are not changed.
- `include/cute/algorithm/copy.hpp`: the elementwise `copy_if(pred, src, dst)` loops over `size(dst)` while indexing `pred` and `src`. It now statically rejects `src`/`dst` of different static sizes. Dynamic sizes are left alone, because there is no device-side error channel.
- `test/unit/cute/core/tensor_algs.cpp`: host tests for `copy(Copy_Atom)`, `copy_if(Copy_Atom)` with one rest-slice masked off, and the elementwise `copy_if`. The rejection itself is a `static_assert` in a function body, so it cannot be a runtime or SFINAE test. It is shown by the repro below.

**SM100 (compile-only; I have no SM100 hardware).** *Correction:* an earlier version of this description said the Blackwell tests were compiled, but `test/unit/cute` has no SM100-specific tests, so that claim was wrong. I then compiled these SM100 GEMM targets with the new asserts (CUDA 12.8, `100a`): `cutlass_test_unit_gemm_device_tensorop_sm100_f16xf16`, `_tensorop_sm100_f8xf8`, and `_bstensorop_sm100_nvf4xnvf4`. They cover the TMEM-load epilogues, TMA stores and the UTCCP scale-factor copies.

- **9 of 13 objects compile, and the new asserts do not fire in any of them.**
- **4 objects fail with `include/cutlass/subbyte_reference.h(459): error: too few arguments in function call`** (`__nv_atomic_load_n` under CUDA 12.8). This is unrelated to this PR. I compiled one of the failing objects (`f16_f16_f16_f16_fusion.cu`) with `main`'s unmodified CuTe headers and got the same error. It is addressed by #3301.

The TMA, TMEM (load/store/UTCCP) and im2col copies have their own `copy_unpack` overloads, so they do not go through the changed generic function. That includes the new SM107 collectives. I could not compile SM107 (it needs CUDA 13.4).

Not covered: `cutlass_test_unit_cute_volta` contains 0 tests for these architectures. I did not build `cutlass_profiler` or the full kernel library.

## Performance

None. The changes are `static_assert`s only, and no code generation changes.

Closes #3488
