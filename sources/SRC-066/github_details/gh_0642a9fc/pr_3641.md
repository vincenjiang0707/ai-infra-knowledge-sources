# [PR #3641] CuTeDSL: preserve outer comprehension generator_targets across nested comprehensions (#3499)

## 正文

Fixes #3499.

## Problem
A nested comprehension inside the element of an outer comprehension broke staged control flow later in the outer comprehension. E.g.:

```python
vals = [(len([0 for _ in range(2)]), (y if flag else -y)) for y in range(4)]
```

failed at runtime with `name 'y' is not defined`, even though `y` is the comprehension variable.

## Root cause
`DSLPreprocessor._visit_Comprehension` (`python/CuTeDSL/cutlass/base_dsl/ast_preprocessor.py`) set `session_data.generator_targets` for the comprehension being visited and then unconditionally reset it to `[]` afterwards. When the element contained a nested comprehension, the inner visit overwrote the targets and reset them to empty on exit. The outer comprehension's remaining element processing then ran with no generator targets, so `visit_IfExp` synthesized its then/else branch blocks without the outer generator variable as an argument, treating it as a free/global name.

## Fix
Save the previous `generator_targets` before visiting the element and restore it afterwards in a `try/finally` (which also protects session state on exception paths), instead of resetting to `[]`:

```python
previous_targets = self.session_data.generator_targets
self.session_data.generator_targets = targets
try:
    ele_visitor(node)
finally:
    self.session_data.generator_targets = previous_targets
```

This mirrors the existing save/restore idiom used elsewhere in the session data (`SessionData._set_attr`).

## Testing
- Unit repro driving the real `_visit_Comprehension` on the issue's AST shape (nested `ListComp` + `IfExp` on the outer generator variable), spying on the `generator_targets` observed by the `IfExp` transform: **failed before the fix** (observed `[]`, want `['y']`), **passes after**.
- Extended sanity suite (8 checks, all green after the fix): triple nesting, two sequential nested comprehensions, `DictComp`/`SetComp`/`GeneratorExp` nesting, sibling-comprehension isolation, top-level reset-to-`[]` behavior unchanged, and state restoration when the element visitor raises.
- End-to-end `@cute.jit` compilation from the issue needs a CUDA GPU, which isn't available in this environment; that leg is left to CI.
