## 正文

ResMLP inference runs separate LayerScale multiply, residual add, and Affine kernels in each block. Add an opt-in FP32 CuTe DSL example that combines residual + Affine in one launch and the final scaled residual in another. The native transpose views, GEMMs, parameter storage, and output strides are preserved.

Small PTX wrappers keep `mul.rn.f32` and `add.rn.f32` separate for the residual, then use `fma.rn.f32` for the Affine operation matching `torch.addcmul`. TVM FFI passes tensors and the current stream directly after compilation. The example rejects autograd use and does not change CUTLASS core dispatch or add a timm dependency to the package.

The included `resmlp_inference.py` runs a complete pretrained ResMLP-12 with a local checkpoint, checks logits against the native forward, and benchmarks eager or CUDA Graph execution. This is independent of #3667 and #3668.

Validation at `56959d7f7181257f225364cffded01d5759a8965` on RTX 5090 SM120, CUDA 13.0.88, driver 580.82.07, Python 3.12.13, CuTeDSL 4.8.0, cuda-python/cuda-bindings 13.0.3, TVM FFI 0.1.11, torch 2.13.0+cu130, timm 1.0.29:

- Four unittest methods pass: eight shape/layout pairs (including tails and mixed layouts), cancellation-sensitive residual rounding, a non-default stream and graph replay, and the autograd guard. Compute Sanitizer memcheck: **0 errors**.
- Full-model outputs and all 12 block outputs are bit exact for batch 1/2/8, FP32, 224×224, TF32 disabled. Parameter storage/version fingerprints are unchanged. Every fused forward executes the two new kernels in each block.
- Exported SASS contains separate `FMUL` / `FADD`, followed by `FFMA` only for the Affine variant. A separate screening trace reduces full-forward GPU launches from 174 to 138.

These are geometric means of process medians from eight fresh processes, ordered APPA then PAAP, with four processes per arm. Each process runs all three batches in both modes; each measurement has six observations, each with 10 warmups and 30 complete forwards/replays. Allocation and Python invocation are included in eager time; JIT, model loading, and graph capture are excluded. CUDA Graph actually replays captured forwards. Seeds are 303601 and 303602, one per quartet.

Batch-2 eager speedups in the two independent quartets are 1.0880× and 1.1023×; CUDA Graph speedups are 1.04786× and 1.04789×. Maximum within-quartet baseline drift is 1.68%, below the predeclared 5% guard. There are only two independent quartets, so these are results for the tested inference workload, not a general significance or cross-platform claim. No training, mixed precision, dataset accuracy, or `torch.compile` comparison is included.

Batch-2 eager peak allocated PyTorch memory is 100.88 MiB native versus 101.46 MiB fused (+0.58 MiB); this is not a memory-reduction claim.

Final validation used GPU UUID `GPU-c9f0f22e-3db5-252c-d294-a47b05b1f904`; 101 process samples found only the corresponding validation process. The host was shared with work on another GPU. An earlier GPU-7 series with unexpected processes is retained separately and excluded from this table. Main environment and system CUDA were unchanged; task-owned checkpoint copies were removed after all runs.

Model: `timm/resmlp_12_224.fb_in1k`, revision `59a4112ca93db165fd828bef7d47d758ad84295b`, checkpoint SHA256 `2ed399f6a787a30925f49bd3e8040e6b0f0a620ed68d56758c703e98bb7c0fbe`.

Reproduce using the matching CuTe DSL runtime and the optional timm/safetensors dependencies:

```bash
python test/python/CuTeDSL/test_residual_affine.py -v
python examples/python/CuTeDSL/cute/ampere/kernel/elementwise/resmlp_inference.py --weights model.safetensors --arm native --batch 2
python examples/python/CuTeDSL/cute/ampere/kernel/elementwise/resmlp_inference.py --weights model.safetensors --arm fused --batch 2
# Add --graph to both arms for the CUDA Graph comparison.
```
