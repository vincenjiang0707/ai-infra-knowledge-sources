## Pull Request Description

The Redis write-through for session-key pinning shares one unconditional `SET` across three cases with different concurrency-safety needs: the initial claim, TTL-only refreshes, and failover repins. That leaves the initial claim racy: two gateway replicas that both miss Redis and resolve different pods for the same session can overwrite each other's pinning (last writer wins), and an unconfirmed sync-pass retry can replace a pinning that another replica already owns.

This makes the claim atomic instead: `persistSessionKeyToRedis` now takes the caller's write intent, and the claim persists with `SET NX EX`:

```go
if mode == writeClaim {
	claimed, err := r.redisClient.SetNX(ctx, sessionAffinityRedisKey(cacheKey), addr, sessionAffinityTTL).Result()
	if err != nil {
		klog.V(4).ErrorS(err, "failed to persist session key pinning to redis", "cache_key", cacheKey)
		return false
	}
	if !claimed {
		return false
	}
	r.markSessionKeyConfirmed(cacheKey, addr)
	return true
}
```

A fresh rendezvous pick on the route path, the sync-pass retry, an unconfirmed local-cache hit, and the post-route commit (the single-ready-pod fast path and blended commits) all use this claim mode. A lost claim reads the winner back and converges the local entry on it, so the losing replica follows the winner on its next request instead of waiting for the sync pass. Refresh and repin intentionally keep the unconditional write for now. Gating a refresh on the stored value still matching `addr` (so a delayed refresh cannot revert a newer repin) and a compare-and-swap for repins are the follow-ups recorded in the TODO at the call site, and the write-intent plumbing added here is what those build on. Say the word if you would rather see those folded into a single larger change instead.

Verified by reverting each part of the fix locally: the added specs fail with the losing replica's address replacing the existing pinning (`10.0.0.2:8000` landing over `10.0.0.1:8000`), and pass with the fix. `go test -race ./pkg/plugins/gateway/algorithms/`, `go vet ./pkg/plugins/gateway/algorithms/`, and `go test ./pkg/plugins/gateway/... ./pkg/cache/...` all pass.

## Code Review

This pull request introduces a sessionAffinityWrite enum (writeClaim, writeRefresh, writeRepin) to represent the write intent when persisting session keys to Redis, and updates persistSessionKeyToRedis to use SetNX for initial claims to prevent concurrent replicas from overwriting each other's pins. It also adds corresponding regression tests. A critical concurrency bug was identified where a replica that loses a claim fails to immediately evict the unconfirmed entry from its local cache, which can lead to a subsequent request overwriting the winner's claim in Redis via a writeRefresh unconditional Set.
