**development/app/app.py:633**
* Returning `None` for every ConfigMap read error makes an API outage or RBAC denial indistinguishable from 'no prefill failure'. The decode handler then proceeds to contract validation and may return HTTP 200, masking the failed prefill; this lookup should fail closed or propagate a dedicated handoff error instead of silently continuing.
```
    try:
        return _get_sglang_handoff_store().get_failure(request_id, room)
    except Exception:
        logger.warning("Unable to read SGLang prefill failure", exc_info=True)
        return None
```
**development/app/app.py:831**
* When the decode request carries the `prefill` fault header but the ConfigMap write/read never yields a failure (for example, an API or RBAC outage), this condition is false and execution falls through to normal contract handling, returning HTTP 200 after a failed prefill. Fail closed when the header is present and the handoff state is unavailable (or propagate the store error) so an infrastructure failure cannot become a successful decode.
```
                    if prefill_failure:
```
