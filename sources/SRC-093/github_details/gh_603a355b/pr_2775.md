## Pull Request Description
HTTP/2 :path includes the query string (RFC 7540), so a request like /v1/messages?beta=true was falling through path-matching switches that compared against the bare literal /v1/messages, e.g. in the prefix cache router and the trtllm prompt-token-ids merge. Centralize the strip-on-'?' logic in utils.PathWithoutQuery and use it everywhere a request path is matched.
