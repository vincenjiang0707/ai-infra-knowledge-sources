## 正文

## Pull Request Description

#1961 asks for the gateway plugin configuration to move onto routing profiles, split into what needs backward compatibility and what does not. This PR moves the per-request routing thresholds a model config profile (`model.aibrix.ai/config`) can select for its own requests into `routingConfig` (plus the model-level `ttftThresholdS`), with the environment as the fallback default: a deployment without these fields routes exactly as before.

**Review guide**

- One funnel: `ResolveRoutingOverrides` in `pkg/plugins/gateway/algorithms/profile_knobs.go` runs once per request inside `Server.selectTargetPod` (`pkg/plugins/gateway/gateway.go`), so every strategy downstream reads the same resolved values from the routing context.
- Core logic beyond the resolver: `pkg/plugins/gateway/configprofiles/configprofiles.go` (profile loading). Consumers: `algorithms/pd/*`, `algorithms/vtc/*`, `load_balance.go`, `router.go`, `prefix_cache*.go`, `gateway_rsp_body.go`.
- Fallback: environment values stay the process default (`algorithms/pd/env_overrides.go`, `algorithms/vtc/env_overrides.go`); a profile field wins only when the profile sets it.
- Mechanical: type definitions in `pkg/types/*`, plus tests (24 of the 51 files) and docs (three `.rst` files and `ENV_VARS.md`).

**What moves into the profile**

- `ttftThresholdS` (top level, next to `routingStrategy`): overrides `AIBRIX_TTFT_THRESHOLD_S` for the profile's first-token-delay classification.
- `routingConfig.pd.*`: the decode abort timeout and retry delay, the four imbalance spread thresholds, the decode load-balance weights, the token-load charge knobs, `hybridCacheLoadFactor`, `minMatchPct` and `prefillRequestTimeout`.
- `routingConfig.promptLengthBucketing` (flat, next to `promptLenBucket*`), `routingConfig.loadBalance.*`, `routingConfig.prefixCache.standardDeviationFactor`, `routingConfig.preble.targetGPU` and `decodingLength`, `routingConfig.vtc.*`, and `routingConfig.autoBlend.*`.

**Compatibility and semantics**

- Every knob keeps its matching `AIBRIX_*` variable as the default. A knob the profile leaves unset, or sets to a value the variable would reject (a negative factor, a percentage outside its range, an unknown GPU name), is dropped at the profile boundary, so a profile can only narrow or sharpen routing behavior and a deployment without these fields routes exactly as before.
- Knobs that configure process-wide state stay environment-only on purpose, because all models of one gateway process share that state: the preble histogram window and eviction loop, the VTC token tracker window, time unit and token floors plus its input/output token weights, the session-affinity local cache capacity, and the router string cache bound. The docs list them explicitly.
- Deployment-level settings (tokenizer endpoints, Redis and statesync settings, the rate limiting switches, `AIBRIX_KV_CONNECTOR_TYPE`) also stay environment-only, as before.
- The knobs are resolved once per request. The non-PD path parks them on the `RoutingContext`, and `reset` clears them so a pooled context cannot leak the previous request's thresholds into a request whose profile sets none. The PD path parks them on the `PDLegState`, because the async prefill goroutine and the decode abort outlive the client stream and must not read a recycled routing context.

**Docs**

`gateway-plugins.rst` gains a per-request routing knobs table (field, overridden variable, description) and the environment-only list; `ENV_VARS.md` gains a variable-to-field mapping section; the PD and model-deployment pages point at the new section.

## Test Plan

- `go build ./...`, `go vet ./pkg/types/... ./pkg/plugins/gateway/...`, `gofmt` clean.
- `go test ./pkg/types/... ./pkg/plugins/gateway/... -count=1`: the new tests cover the environment default without a profile, the profile value reaching every scoring, charge and filter site when set, invalid values keeping the environment default, and `RoutingContext.reset` clearing the knobs.
- `sphinx-build -b html -W --keep-going docs/source docs/_build/html` clean for the docs changes.

## Design feedback: simplify the shape

The direction is right — per-request overrides with env as default, process-wide knobs stay env-only, PD values parked on the leg. The cost is mostly structural: the same idea is implemented twice, and `routingConfig` is still a bag of `json.RawMessage`.

### 1. Resolve once into concrete values

Today: pointer fields + `*OrDefault(env)` at every read site + env still read at each site.

Simpler: at profile attach / request start, merge profile over env into a **concrete** struct (no pointers). Call sites become `knobs.ImbalanceFactor`, not `RoutingKnobs().LoadBalanceImbalanceFactorOrDefault(envFactor)`.

That removes ~30 near-identical accessors and the “pass the env default again” tax.

### 2. One override bag, not two

`RoutingKnobs` and `PDRuntimeKnobs` are the same pattern with different park points. Prefer one `RequestRoutingOverrides` (or nest `PD` inside it). Keep **one** storage rule: park on `RoutingContext` for sync path; copy/reference onto `PDLegState` only when the PD route starts (the longevity constraint is real — the dual type system is not required by it).

### 3. Parse `routingConfig` once

Same raw blob is unmarshaled separately for auto-hints, PD algorithm config, PD knobs, and non-PD knobs. That duplicates structs, validators (`positiveFloat` etc. appear in both files), and failure modes.

Simpler: typed `RoutingConfig` parsed when the profile is resolved, stored on `ResolvedConfigProfile`, then knobs are just field projections. No per-strategy re-parse.

### 4. One resolve call site

Non-PD: `ResolveRoutingKnobs` on the gateway path.
PD: `SetPDKnobs(effectivePDKnobs)` again inside `Route`.

Fold into one “materialize overrides for this request” step next to profile resolution. PD `Route` should only attach already-resolved knobs to the leg.

### 5. Shrink the first cut

~2.5k lines moving every knob at once makes the mechanism hard to review. Issue #1961 asked to list and split. Suggested slice:

1. Mechanism + 2–3 knobs (e.g. TTFT + one load-balance + one PD timeout)
2. Rest of the catalog as follow-ups

Prove park/reset/PD-leg rules before expanding the schema.

### 6. Flatten the profile schema a bit

`routingConfig.pd.abort.timeout` + many sub-structs is neat on paper, costly in code. Flat keys under `routingConfig` (or one `pd` object without `abort`/`spreads`/`tokenLoad` nesting) would cut parse types roughly in half with little UX loss. TTFT on the profile root while everything else is under `routingConfig` is another split to reconsider.

### 7. Drop `atomic.Pointer` where it isn’t needed

Atomic on `PDLegState` is justified (async prefill/abort). On `RoutingContext.routingKnobs`, if resolve runs once before routing and `reset` clears it, a plain field is enough.

---

**Bottom line:** Keep the semantics (env default, invalid → drop, PD on leg, process-wide env-only). Simplify the shape to: **one typed config parse → one concrete overrides struct → one resolve site → leg copy for PD**. That should cut a lot of this diff without changing the product story.

## Code review

**Verdict: request changes on structure; happy-path correctness looks sound.** Gemini’s nil-guard notes are already fixed. Unit/lint/race/docs are green.

### What looks correct
- `ResolveRoutingKnobs` runs in `selectTargetPod` before `Select` / the load-imbalance gate, so auto-blend and LB knobs see the profile.
- PD longevity: `SetPDKnobs` at the start of `pdRouter.Route`; abort/prefill read from the leg; prefill timeout is captured before the async goroutine.

1. **`tokenLoad.maxSessions` should stay env-only** — it gates a shared `sessionCount` table; a per-request override is not a real per-model cap (same class as the process-wide knobs left env-only). See inline.
2. **Invalid profile values are dropped silently** — env loaders warn; profile validators return nil with no log. Log once at resolve when a field is rejected. See inline.

### bolubo · 2026-09-23

Addressed by simplifying the shape in place.

1. Resolve once into concrete values. `types.RoutingOverrides` holds concrete values and the read sites use `overrides.Field`. The `*OrDefault(env)` accessors and the per-call environment reads are gone; the process defaults are assembled once at startup from the same loaders (`processRoutingOverrides`, using `pd.EnvOverrides` and `vtc.EnvOverrides`).
2. One override bag. A single `types.RoutingOverrides` with `PD types.PDOverrides` nested inside it is parked on the `RoutingContext`. `pdRouter.Route` copies the PD half onto `PDLegState` before the async prefill leg starts, which is the only place the longevity requirement applies, so the dual type system is not needed.
3. Parse once. `configprofiles.ParseRoutingConfig` parses the selected profile's `routingConfig` once per request into `types.RoutingConfig` and stores it on `ResolvedConfigProfile.Routing`. The auto-selection hints, the score-policy fields and the knob catalog read that one struct, and one validator set mirrors what the `AIBRIX_*` loaders accept. The pod-side bucketing and combined checks keep parsing the pod's own profile, as before.
4. One resolve call site. `routing.ResolveRoutingOverrides(routeCtx)` runs next to profile resolution in `pkg/plugins/gateway/gateway.go`. `Route` only parks the already resolved values on the leg.
5. Scope. The catalog stays in this PR: the revision removes the old accessors rather than leaving them beside the new path, so there is one resolution mechanism left to read. A partial catalog would keep both mechanisms alive and make the boundary harder to review, not easier. The PR is the knob half of #1961 and does not change the strategies themselves.
6. Flatten the schema. `routingConfig.pd` is one flat object (`decodeAbortTimeout`, `decodeAbortRetryDelay`, `decodeLBWeightRunning`, `tokenLoadKVWeight`, ...), with no `abort` / `spreads` / `tokenLoad` nesting, and both docs tables use the flat names. `ttftThresholdS` keeps its profile-root placement because it is an existing field outside `routingConfig`; moving it would be a schema break rather than a simplification.
7. Drop `atomic.Pointer` where it is not needed. The `RoutingContext` overrides are a plain field, set before routing and cleared in `reset`. The atomic stays on the leg, where the prefill and abort goroutines outlive the request.
