## Code review

Overall this is a strong design: opaque owner-scoped public IDs, UID-based pod pinning, Redis Lua atomicity, Buffered vs Streamed Videos route split with golden xDS coverage, and careful failure taxonomy (404 vs 503). Gemini’s hash-tag / ID-validation / jitter nits look addressed in the harden commit.

**I’d hold merge** on the create-path ORIGINAL_DST rematch issue below, and I’d like an explicit decision on informer-miss → durable delete.

### Blocking / high
1. **Create may never rematch onto `original_destination_cluster`** — follow-ups clear the route cache at RequestHeaders; create sets `routing-strategy`/`target-pod` only in RequestBody with no `ClearRouteCache`. Videos HTTPRoutes backend to gateway-plugins; ORIGINAL_DST only matches once `routing-strategy` is present. Docs/xDS treat the second pass as load-bearing. E2E also omits `routing-strategy` on create.
2. **Informer `GetPod` miss permanently deletes the job** — still open after Gemini discussion. Cache desync can turn a valid durable mapping into a terminal 404.

### Medium
3. `scope:shared` is a real shared catalog when `user` is absent (easy multi-tenant footgun behind a static API key).
4. Redis list Lua does not check wall-clock expiry; `get` does — catalog/get can disagree.
5. Error-body ID scrub uses `bytes.ReplaceAll` (substring collision risk).
6. “Redis Cluster ready” is overstated: hash tags help, but the client is still `*redis.Client`.
7. E2E is happy-path only (no rematch / Redis-down / pod-gone / registration-failure cases).
8. Breaking surface: public `aibrixjob-…` IDs, registry list shape, `model=` on list → 400 — needs a migration note.

Inline comments follow on the specific sites. Focused `go test ./pkg/plugins/gateway/ -run 'AsyncJob|VideoJob|GeneratedXDS|ExtProcConfig'` passed locally; CI so far is DCO/docs/triage only.

## Pull request overview

This PR introduces an async job registry (in-memory + Redis) and updates the gateway’s Videos API routing so clients receive owner-scoped public job IDs while follow-up requests are pinned to the original backend pod (including xDS/manifest validation and E2E coverage).

**Changes:**
- Added `AsyncJobRegistry` (memory + Redis) for durable, owner-scoped async job resolution and listing.
- Reworked Videos routing to rewrite backend IDs ↔ public IDs, pin follow-ups via Envoy route cache re-evaluation, and clean up records on delete.
- Added/updated unit tests, xDS golden + drift tests, and E2E coverage; updated docs and the dev mock app to match the new behavior.
