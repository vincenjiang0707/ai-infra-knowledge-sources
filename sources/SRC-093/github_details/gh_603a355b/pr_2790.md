## What

Follow-up to the non-blocking nit on #2752.

`test_cursor_survives_the_channel_set_growing_and_shrinking` is named for the cursor tolerating the reachable set **both** growing and shrinking, and that is what the `RoundRobin` docstring promises:

> Tolerates the set growing/shrinking between calls (the cursor is taken modulo the live length)

But the sequence only ever shrank — `3 → 2 → 1`. The growing half of the claim was never exercised, so the spec's name and comment promised more than the assertions delivered.

## The change

Grow the set to four channels before shrinking it: `3 → 4 → 2 → 1`.

| call | live length | cursor before | `cursor % len` | picked | cursor after |
|---|---|---|---|---|---|
| 1 | 3 | 0 | 0 | first | 1 |
| 2 | **4** | 1 | 1 | second | 2 |
| 3 | 2 | 2 | 0 | first | 1 |
| 4 | 1 | 1 | 0 | first | 0 |

The growth step is deliberately placed where the cursor is non-zero. With a cursor of 0 the assertion would hold for any list length — `0 % anything` is `0` — so it would not actually demonstrate that the modulo tracks the live length.

The comment is updated to walk all four steps, since it described the old three-step sequence.
