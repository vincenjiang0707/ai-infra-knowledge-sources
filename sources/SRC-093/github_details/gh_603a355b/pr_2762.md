## Pull Request Description

Add `--kube-api-qps` and `--kube-api-burst` flags to the gateway plugin.

- Use `rest.DefaultQPS` and `rest.DefaultBurst` as flag defaults.
- Validate values early during startup.
- Apply the same settings to the shared REST configuration before creating the Kubernetes and Gateway API clients.
- Add focused tests and deployment documentation.

### Validation

- Gateway plugin unit tests and `go vet` passed.
- Formatting, whitespace, and focused line-length checks passed.
- Gateway manifests rendered successfully.
- Cluster testing with route cache TTL set to `1ns` showed serial steady-state request rates of approximately 1 and 5 requests/second for the corresponding QPS settings.

Full lint still needs verification with a compatible toolchain or CI.

## Review

**Verdict:** Solid, focused fix for #2727. Implementation matches the agreed scope and the existing controller-manager QPS/burst pattern. Blocked on a docs CI failure; a couple of follow-ups would make it clearer for Helm users.

### What works well
- Flags default to `rest.DefaultQPS` / `rest.DefaultBurst` → backward compatible.
- Applied to the shared `*rest.Config` before both clients (and cache/discovery reuse that config).
- Startup validation correctly rejects zero/negative/NaN/Inf and float32 underflow/overflow.
- Tests cover flag parsing, validation edge cases, and actual client rate-limiter behavior.
- Docs clearly state per-client limiters (not a shared budget) and that this is API-server QPS, not inference QPS.

### Must fix
1. **Sphinx CI is failing** — title underline is one character short:

```text
Gateway Plugin Kubernetes API Throttling   # 40 chars
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~    # 39 chars
```

CI reports: `gateway.rst:35: WARNING: Title underline too short.`

### Should fix / discuss
2. **Helm chart gap** (`dist/chart`) — as noted in review, production docs otherwise use Helm `values.yaml`, but the gateway-plugin Helm template has no `args` for the plugin container. Kustomize-only commented args leave Helm users without a clear way to set these flags. Mirror the comment and/or add `args` / dedicated values.

3. **Docs section placement** — the new subsection sits under “Configuring Resources and Replica Count” between Gateway Plugin and Envoy Proxy. Better as its own `----` section (or nested under Gateway Plugin), not under resource sizing.

### Non-issues (disagree with Gemini bot)
- `limiter.QPS()` **does compile** — `flowcontrol.RateLimiter` embeds `PassiveRateLimiter`, which defines `QPS()`. Unit tests already passed.
- Nil-check in `applyTo` is unnecessary; it’s only called after a successful config load.

### Minor nits
- No startup log of effective QPS/burst (helpful when debugging throttling).
- Controllers use defaults `100/100` without validation; this PR’s `5/10` + validation is correct for preserving current gateway behavior — worth a one-liner in the PR description so reviewers don’t expect parity.

**Recommendation:** Approve after fixing the RST underline and clarifying Helm configurability.
