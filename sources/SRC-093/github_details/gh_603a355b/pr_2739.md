### Should-fix before merge

**`TriggerReconcile` still races status updates** in `test/utils/controller/modelclaim.go`.

Every reconcile does an unconditional `Status().Update`, which bumps `resourceVersion`. A single Get→MergeFrom→Patch can still 409 if that status write lands in between. The idempotency spec fires three patches back-to-back, which is the highest flake risk. Copilot already flagged this; the RoleSet integration helper pattern is the right fix: wrap Get→Patch in `Eventually` and retry on `apierrors.IsConflict`.

Suggested shape:

```go
func (f *ModelClaimFixture) TriggerReconcile(claim *modelapi.ModelClaim) {
	ginkgo.GinkgoHelper()
	gomega.Eventually(func(g gomega.Gomega) {
		latest := &modelapi.ModelClaim{}
		g.Expect(f.client.Get(f.ctx, client.ObjectKeyFromObject(claim), latest)).To(gomega.Succeed())
		patch := client.MergeFrom(latest.DeepCopy())
		if latest.Annotations == nil {
			latest.Annotations = map[string]string{}
		}
		latest.Annotations["test.aibrix.ai/reconcile"] = fmt.Sprintf("%d", time.Now().UnixNano())
		err := f.client.Patch(f.ctx, latest, patch)
		if apierrors.IsConflict(err) {
			return
		}
		g.Expect(err).NotTo(gomega.HaveOccurred())
	}, f.timeout, f.interval).Should(gomega.Succeed())
}
```

### Non-blocking notes
- **`ExpectRoute` substring matching:** `"port":1` is a substring of `"port":19000`. Prefer JSON unmarshal (or match `"port":%d,`). Low practical risk with ports starting at 19000.
- **Coverage gaps vs unit tests:** Active→unhealthy demotion and snapshot port correction remain unit-only — fine as a follow-up.
- **PR label `area/kv-cache`:** looks unrelated to this change.
- **Double namespace cleanup** (`DeferCleanup` + `AfterEach`) is redundant but safe via `IgnoreNotFound`.

Once the conflict-retry lands on `TriggerReconcile`, this looks merge-ready for the ModelClaim integration coverage tracked in #2737.
