## Pull Request Description

Add a live-cluster ModelRouter E2E package covering the controller behavior that is already supported today.

- exercise Deployment and ModelAdapter discovery and validate generated HTTPRoute and ReferenceGrant configuration;
- send a uniquely identified request through the gateway and confirm it reaches the isolated mock backend;
- verify namespace-level ReferenceGrant sharing and cleanup, plus controller restart idempotency and post-restart add/delete handling;
- use unique namespaces, bounded polling, failure diagnostics, and the existing resource-preservation setting.

This PR does not change ModelRouter controller behavior and does not add update or same-model shared-HTTPRoute scenarios.

### varungup90 · 2026-09-17 · CHANGES_REQUESTED

## Review

The package shape is good: unique namespace, bounded polling, isolated mock backend, shared ReferenceGrant cleanup, and docs for the existing keep-on-failure setting. This should not change ModelRouter behavior, which is the right split from #2737 scope 2.

The main gap is that the live request does **not** exercise the generated HTTPRoute. `routing-strategy: random` makes the gateway plugin pick a pod and set `target-pod`, so the request can succeed even if the HTTPRoute is unaccepted, points at the wrong Service, or the ReferenceGrant is broken. That is the path this E2E is meant to lock in.

Please also tighten controller restart (graceful delete + wait until the controller is actually reconciling) and keep shared-namespace HTTPRoutes from leaking when resources are preserved on failure.

This package is in the default `controller` / `all` suites and has not been run against a cluster yet. After the request-path fix, please run:

```bash
go test -p 1 ./test/e2e/controller/modelrouter/... -v -count=1
```
