## Pull Request Description

Adds Gateway integration coverage for the four streaming chunk-edge cases listed in #2708, using the existing `test/integration/gateway` fixture:

- [x] Multiple SSE events in one callback chunk.
- [x] UTF-8 content split across callback chunks.
- [x] Empty end-of-stream chunks, including an empty EOS chunk that flushes a partial line buffered from the previous chunk.
- [x] Usage extraction from a final streaming chunk while preserving the original body.

The specs go through the real ext_proc `Server.Process` boundary and pin the callback acks plus the finalized token counts, so a regression in tail reassembly, usage extraction, or response pass-through shows up as a failing spec.

`fixture.go` now records the token counts passed to `DoneRequestTrace`, which lets the usage cases assert 3/5 and 5/7 instead of header presence only. Existing expectations are unchanged, and the parser matrices remain in the unit tests.

The fixture doesn't run Envoy, so the forwarded bytes are checked at the callback boundary rather than on the wire; the Envoy-side cases stay with the E2E follow-ups.

Verified locally:
- `go test ./test/integration/gateway/... -count=1` (36/36 specs)
- `go test -race ./test/integration/gateway/... -count=1`
- `go vet ./test/integration/gateway/...`
- `gofmt -l test/integration/gateway/` (no output) and `git diff --check`

### Findings

1. **UTF-8 mid-rune claim is under-asserted** (low/medium)

   `split++` does land mid-rune in Go (byte index), but nothing fails if someone later splits on a full rune. The gateway also reassembles incomplete **SSE lines**, not UTF-8 runes specifically. Strengthen with:

   ```go
   Expect(utf8.ValidString(first)).To(BeFalse())
   Expect(utf8.ValidString(first + second)).To(BeTrue())
   ```

2. **Input body asserts are tautological** (nit, inherited)

   `Expect(fixture.stream.inputs[N]...)` only checks the fixture setup. Real pass-through coverage is `BodyMutation == nil`. Same pattern as `streaming_test.go`; the PR text slightly overstates “forwarded bytes” checks.

3. **Empty-chunk case is shallow vs unit coverage** (optional)

   Complete SSE + empty mid-stream + empty EOS is fine for the checklist, but doesn’t cover empty EOS flushing a **buffered incomplete line** (`TestHandleResponseBody_SSEEmptyEOSChunkAfterBufferedTail`). Worth a fifth spec if you want Process-boundary parity with that unit test.

### Non-blocking

- Hardcoded `inputs[3]`/`[4]`/`[5]` indices match existing style.
- `triage/needs-information` looks stale for a ready test PR.

No blockers for merge once CI is green. The UTF-8 `utf8.ValidString` assert is the only change I’d ask for before merge if you want one more tightening pass.
