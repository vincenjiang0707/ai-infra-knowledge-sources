## 正文

## Pull Request Description

Standalone gateways can now discover inference endpoints from etcd without restarting or editing a static endpoint list. Each JSON registration adds a backend; updates change the routing cache, and deletion or lease expiry withdraws the route.

- Implement the existing discovery Provider with an initial snapshot, revision-based watch, reconnect and compaction recovery, stable endpoint identity, and prefill/decode metadata.
- Add strict `--etcd-config` loading, shared CLI/provider prefix normalization, encrypted username/password authentication, and verified TLS/mTLS.
- Reconcile immediately after compaction; report safe failure categories and gRPC status codes. Document snapshot readiness, asynchronous catch-up, hostname validation, and the etcd ACL routing boundary.
- Reuse the Registry snapshot implementation from #2728, now on main. Fix the remaining PodArray race by building deployment indexes without sorting a published snapshot and publishing indexes through `sync.Once`.
- Preserve IPv6 addresses in routing, prefill, engine metrics scraping, and PromQL instance labels. Build the gateway as a package so the CLI configuration file is included.

## Related Issues

Related: #2033. This implements the etcd provider; Consul remains future work. The Provider and WatchEvent.Object interfaces are unchanged, leaving the broader #2031 work independent.

## Validation

Validated after merging main `8f44dea87804972a5d2a6f893cd5ec1499edd90b`, using Go 1.22.12 and a dedicated etcd 3.5.17 server on a remote node.

- `go test -race -p=2 -count=1 ./pkg/cache/... ./pkg/plugins/gateway/... ./pkg/types ./pkg/utils ./cmd/plugins`: 17 tested packages passed.
- `make lint-all`: license check and full golangci-lint passed.
- Real-etcd race integration: compaction recovery, routing-cache lifecycle, and natural lease expiry passed.
- Regression tests cover prefix boundaries, plaintext credential rejection, immediate compaction recovery, safe diagnostics, concurrent PodArray readers, an IPv6 HTTP metrics scrape, and IPv6 PromQL labels. The configuration/compaction and PodArray tests reproduced failures before the fixes, including a data race.
- Rebuilt the gateway with `CGO_ENABLED=0 go build -tags=nozmq ./cmd/plugins`.
- A real ext_proc gRPC client verified registration, address updates, invalid-update withdrawal, repair, deletion, and lease expiry through the gateway.
- A separate etcd server requiring client certificates verified gateway discovery and deletion watch over mTLS.

The blackbox validation covers ext_proc decisions, not Envoy forwarding or GPU inference. Multi-node etcd failure injection and throughput benchmarking were not run. Watch readiness guarantees the initial snapshot is applied; subsequent revisions are caught up asynchronously. During etcd outages, the provider retains the last known routes until discovery recovers.

### Should fix

2. **Prefix delimiter safety** — `WithPrefix` is a byte prefix, so `/aibrix/endpoints` also matches `/aibrix/endpointsFoo/...`. Normalize to a trailing `/` (or reject) in both the CLI loader and `NewEtcdProvider`. `/` (whole keyspace) should also be rejected.
3. **Reconnect/snapshot error logs omit `err`** — permanent auth/TLS/permission failures will retry forever with no actionable signal.
4. **IPv6 completeness** — routing/prefill are fixed, but `pkg/cache/cache_metrics.go` still uses `fmt.Sprintf("%s:%d", podIP, port)`, so IPv6 backends will fail metrics scrape/labels. Fix in this PR or document as routing-only.

### Important

5. **Watch readiness is snapshot-only** — `Watch` returns after snapshot reconcile while post-snapshot events (and compaction-between-Get-and-Watch) are applied later in `run`, after a mandatory 1s `waitEtcdRetry`. Drain/establish the watch before returning, skip backoff on the first compaction resync, or document that ready means snapshot-only.
6. **Registry / `PodArray` alias** — rebuild allocates a new `[]*Pod`, but `valuesProvider` still wraps that same slice; `PodArray.initDeployments` sorts it in place and can race with concurrent `All()` readers.
7. **Hostname rules are stricter than static discovery** — DNS-1123 rejects underscores (`vllm_0:8000`). Static YAML accepts them. Align or document.

### Nits

- `pkg/cache/discovery/discovery.go` still says `TODO: Add ConsulProvider, EtcdProvider`.
- Hardcoded `"role-name"` / `"roleset-name"` should share constants with PD routing.
- Document that the etcd user should be read-only on the prefix; anyone who can write it controls gateway routing.
