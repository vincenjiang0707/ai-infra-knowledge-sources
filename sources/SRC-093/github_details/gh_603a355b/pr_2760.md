## Pull Request Description

One failed profile ranking made `SLOQueue.Peek` drop every ranked candidate and serve the earliest request in FIFO order. The rank error was stored in a variable shared by the whole scan, and after the scan the candidate list was truncated to the first (FIFO fallback) entry; a profile that cannot rank a single request, for example one whose index table does not cover the request signature, therefore collapsed the routing decision for all subqueues.

`rankImpl` already reports per-profile errors and `Peek` logs a warning for them, so this finishes that contract:

```go
if rankErr != nil {
	klog.Warningf("SLOQueue failed to get SLO info for request %s with profile %s: %v, skip.", r.RequestID, profile.Deployment, rankErr)
	continue
}
```

Candidates whose profiles all fail are removed from the ranked list instead of taking part in the cross-candidate sort. A subqueue with no rankable profiles still falls back to FIFO; I left that path unchanged, so say the word if you would rather revisit it.

Verified by reverting the fix locally: two of the added specs fail and return the FIFO candidate (`req-early` / `req-waiting`) instead of the most urgent ranked candidate; removing only the candidate cleanup makes the all-fail spec panic in the sort with `index out of range [0] with length 0`. With the fix, `go test -race ./pkg/plugins/gateway/queue/` and `go test ./pkg/plugins/gateway/...` pass.

## Review

**Verdict: Approve** — correct bug fix, focused change, solid tests; CI is green.

### What broke
In `SLOQueue.Peek`, any single `(request, profile)` `rankErr` was stored in a shared `err`. After scanning all subqueues, that triggered:

```go
q.dequeueCandidates = q.dequeueCandidates[:1]
```

which discarded every successfully ranked candidate and forced the FIFO head. One unrankable pair (e.g. signature OOB after #2756 started returning errors) collapsed routing for the whole model queue.

### What the PR does
1. Stops promoting per-profile `rankErr` into a global fallback.
2. Drops candidates whose profiles all fail (`[:idx]` + clear `RoutingContext`) so the later sort never hits empty `Profiles[0]`.
3. Leaves the existing all-profiles-fail → FIFO path intact.

That matches the existing “skip this profile / warn” contract.

### Tests
Three specs cover the important cases: one failing pair keeps SLO ranking, multi-fail still picks the urgent ranked request, all-fail still FIFO. I also ran `go test -race ./pkg/plugins/gateway/queue/` locally — pass. CI (unit, race, integration, E2E) is green.

### Nits (non-blocking)
- **Missing mixed coverage for the new truncate path:** current specs either keep every candidate rankable on `dep-good`, or fail all candidates. A case where one candidate is fully unrankable while another remains ranked (and FIFO would pick the unrankable/earliest one) would lock in the `[:idx]` cleanup specifically.
- **Log wording:** `"fallback to FIFO queue"` on a single empty candidate is misleading when other ranked candidates remain — pre-existing message, optional cleanup.
- **Broader slice retention** (as noted in the earlier review comment): clearing only the removed slot is enough for this fix; full stale-slot cleanup across `Peek` is a separate, pre-existing concern.

No API/compatibility surface changes. Related to #2756 in the right way: that PR made short indexes return errors; this one stops those errors from nuking the whole dequeue decision.
