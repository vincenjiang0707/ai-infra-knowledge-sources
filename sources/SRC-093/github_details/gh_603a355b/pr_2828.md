## Pull Request Description

Fixes the RoleSet topology integration spec that fails intermittently with a 409 conflict (item B2 in #2805).

The spec "applies topology policy updates only to newly created pods" (`test/integration/controller/roleset_test.go`) updates the RoleSet twice with a bare `Get`, mutate, `Update`. If the controller reconciles the RoleSet between the `Get` and the `Update`, the `Update` fails with:

```
Operation cannot be fulfilled on rolesets.orchestration.aibrix.ai "topology-update-test": the object has been modified; please apply your changes to the latest version and try again
```

The second update (`:1118`) is the one that fails. It runs right after `deletePodAndWaitForReplacement`, while the controller is still reconciling the replacement pod, so the window is widest there. This matches the CI hit on main linked in #2805 (run 35814726502, 89 of 90 specs passed, failure at `:1118`).

Every other RoleSet update in this file already runs inside `gomega.Eventually` with a fresh `Get` on each attempt (for example the image update at `:460-465`). This PR wraps both updates in this spec in the same pattern, with the same `5s` / `250ms` budget. A conflict now re-reads the object and retries instead of failing the spec.

This is a test-only change. The controller is untouched, and so are the assertions on which pods get preferred or required affinity.

### Reproduction and verification

I reproduced the failure locally on main (`4be9a600`) by running the spec repeatedly under envtest (k8s 1.29.0) while saturating every CPU core with `yes`, to approximate a busy CI runner:

```
bin/ginkgo --focus "applies topology policy updates only" --repeat=29 ./test/integration/controller/
```

| | Runs | Result |
|---|---|---|
| main (`4be9a600`) | 6 | Failed on run 6 at `roleset_test.go:1118` with the same 409 as CI |
| this PR | 30 | 30/30 passed, no conflicts |

`go vet ./test/integration/controller/` passes.

### Not in this PR

The other items in #2805 (B1, B3, B4) are separate issues and are not touched here.
