## Pull Request Description

Follow-up to #2476, which fixed the SGLang PD path only. The vLLM
(SHFS / NIXL / Mooncake) and TRT-LLM PD paths still built the prefill body
and the decode body through a `map[string]any` round trip
(`sonic.Unmarshal` → mutate → `sonic.Marshal`) in `prefill.PreparePayload`,
in the `MergePrefillResponse` implementations and in
`DefaultExecutor.executeHTTP`. `sonic` emits map keys in random order, so
nested objects (`messages[].content[]`, `tools[].function.parameters`, …)
were re-serialised differently on every request and differently between the
prefill body and the decode body of the same request. Chat templates render
those objects into the prompt, so `prompt_token_ids` became unstable and
prefix-cache reuse on both the prefill and the decode pod was defeated.
See #2724 for details.

This PR makes the whole PD pipeline byte-based, the same way #2476 did for
SGLang, and removes the map-based fallback entirely.

### Changes

- **Interfaces** (`pd/engine/handler.go`, `pd/transfer/agent.go`):
  `EngineHandler.AugmentPrefillRequest(routingCtx, pod, body []byte) ([]byte, error)`
  returns the prefill body derived from the client body;
  `MergePrefillResponse(routingCtx, prefillResponse []byte, pod) error`
  edits `routingCtx.ReqBody` in place with `sjson`. `KVTransferAgent` gets the
  same byte-based signatures. `RawPrefillPayloadPreparer` is removed since
  the byte-based contract is now the only one.
- **Shared helpers** (`pd/json.go`): `JSONEditor` (chained
  `sjson.SetBytes` / `SetRawBytes` / `DeleteBytes` with first-error
  capture), `ValidateJSONObject`, `ApplyPrefillControlFields` (sets
  `max_tokens=1`, `stream=false`, drops `stream_options` / `min_tokens`, and
  handles the TRT-LLM `max_completion_tokens` special case) and the
  `EngineTRTLLM` constant. `SonicJSONInt64` is removed.
- **`prefill.PreparePayload`**: validate body → `AugmentPrefillRequest` →
  `ApplyPrefillControlFields`. Control fields are now applied once for every
  engine, so the SGLang handler no longer applies them itself.
- **Request validation for every engine** (`pd/engine/handler.go`,
  `pd_disaggregation.go`): `sjson` only edits the *first* occurrence of a
  duplicate top-level key, so a body carrying two copies of a
  gateway-controlled field (e.g. `max_tokens`, `kv_transfer_params`,
  `disaggregated_params`, `bootstrap_room`) would let the second, unmodified
  copy reach the engine. This check previously existed for SGLang only. It
  now runs in `PDRouter.Route()` for all engines, before pod selection.
  `EngineHandler` and `KVTransferAgent` gain `ControlledFields()` so each
  engine/agent declares the top-level keys it rewrites; `engine.ValidateRequest`
  combines them with `pd.CommonControlledFields` (`max_tokens`,
  `max_completion_tokens`, `stream`, `stream_options`, `min_tokens`) and uses
  `pd.FindDuplicateTopLevelKey` (a single `gjson.ForEach` pass). vLLM reports
  the union over all registered KV transfer agents
  (`transfer.AllControlledFields()`) because the connector is only known
  after pod selection. `ValidateSGLangRequest` is kept as a thin wrapper.
- **`SetRaw` batching**: the TRT-LLM handler and the SHFS agent now perform a
  single top-level `SetRaw` per augment/merge (building the nested fragment
  with one `sjson.SetBytes` on the response fragment) instead of several
  nested edits.
- **SHFS**: `kv_transfer_params` skeleton is written with `sjson` on the
  prefill body (any client-supplied value is replaced); on merge the
  response's `kv_transfer_params` fragment is copied raw into the decode body
  and `remote_host` is set to the prefill pod IP.
- **NIXL**: prefill augmentation is a no-op; the prefill response is
  embedded verbatim (whitespace-trimmed) as `disagg_prefill_resp` instead of
  being decoded and re-encoded.
- **Mooncake**: passthrough, unchanged behaviour.
- **TRT-LLM**: `disaggregated_params` is written with `sjson`
  (`request_type=context_only`, `disagg_request_id`); on merge the response's
  `disaggregated_params` (top-level, falling back to `choices.0`) is copied
  raw, `request_type` is switched to `generation_only`, and
  `prompt_token_ids` is routed to `prompt` (`/v1/completions`) or
  `prompt_token_ids` (`/v1/chat/completions`) by request path. Large
  integers such as `ctx_request_id` / `disagg_request_id` are preserved as
  raw fragments, so the `float64` workaround (`SonicJSONInt64`,
  `anySliceForJSON` + reflection) is no longer needed.
- **SGLang**: same behaviour as after #2476, now expressed through the
  common interface (`AugmentPrefillRequest` sets the bootstrap fields on
  both bodies and updates `routingCtx.ReqBody`).
- **`DefaultExecutor.executeHTTP`** returns the validated raw response bytes
  instead of a `map[string]any`; `handleSync`'s merge callback takes `[]byte`.
- Log messages and error strings that existing tests match on are kept.

### Behaviour notes

- A client body that is not a JSON object (malformed, array, scalar,
  `null`) is now rejected in `PDRouter.Route()` with
  `engine.InvalidRequestError`, which the gateway maps to HTTP 400, before any
  pod is selected. Previously it surfaced as a prefill failure (HTTP 503).
  `PreparePayload` still validates as a defence-in-depth check.
- A body with a duplicate top-level gateway-controlled key is rejected with
  HTTP 400 for every engine (`duplicate top-level key "<key>" in request
  body`). Previously only SGLang rejected this; vLLM / TRT-LLM would silently
  forward the second copy. Duplicates of non-controlled keys are still
  accepted.
- A prefill response whose `kv_transfer_params` / `disaggregated_params` is
  missing is still a no-op; one that is present but not an object is still an
  error (same as the old type assertion). A prefill response that is not a
  JSON object is rejected (the old `Unmarshal` into a map failed on it too).
- NIXL's `disagg_prefill_resp` now contains the prefill response exactly as
  the engine sent it rather than a re-serialised copy.
- No new dependencies: `sjson` and `gjson` are already direct dependencies.

### Tests

- `pd/json_test.go`: editor semantics (nil → `null`, raw fragments keep
  2^53+1 exact), `ValidateJSONObject`, control fields for vLLM and TRT-LLM,
  byte-stability across 100 runs.
- `pd/transfer/agents_test.go`: SHFS skeleton / merge / missing / wrong type
  / invalid decode body, NIXL verbatim embedding, Mooncake passthrough, all
  asserting nested `messages` / `tools` are byte-identical and inputs are not
  mutated.
- `pd/engine/trtllm_test.go`: augment, `choices[0]` vs top-level params,
  `prompt` vs `prompt_token_ids` routing, big-int precision, no-op / error /
  invalid-body cases.
- `pd/prefill/payload_test.go`: control fields applied on top of handler
  output, TRT-LLM drops `max_completion_tokens`, handler errors propagate,
  non-object bodies → `InvalidRequestError` without calling the handler,
  vLLM/TRT-LLM/SGLang preserve nested bytes across 100 runs, existing SGLang
  integration and duplicate-field tests kept.
- Existing `pd_disaggregation_test.go`, `sglang_test.go`, `default_test.go`
  adapted to the byte-based signatures.
- `pd/engine/validate_test.go`: `ControlledFields()` per engine,
  `ValidateRequest` table over vLLM / SGLang / TRT-LLM / default × invalid
  bodies × common keys × engine-specific keys.
- `pd_disaggregation_test.go`: duplicate controlled keys rejected for all
  engines before the pod selector is invoked; duplicate non-controlled key
  still routes on vLLM.
- `test/integration/gateway/pd_request_body_test.go` (per review request):
  full ext_proc lifecycle with a fake prefill HTTP server for vLLM SHFS,
  vLLM NIXL, TRT-LLM and SGLang. Asserts nested `messages` / `tools` bytes
  are preserved verbatim on both the prefill body and the decode body,
  engine control fields are injected (`kv_transfer_params.remote_host`,
  `disagg_prefill_resp`, `disaggregated_params` context/generation, SGLang
  bootstrap fields), large integers survive, and duplicate controlled keys
  return 400 without the prefill server being called. To let the isolated
  `RouterManager` build a `pd` router this adds
  `NewPDRouterWithCacheAndPrefixIndexer` and registers `RouterPD` in
  `NewRouterManagerWithCacheAndPrefixIndexer`.

Verified locally: `go build ./...`, `go vet`, `golangci-lint run
./pkg/plugins/gateway/... ./test/integration/gateway/...` (0 issues),
`go test -count=1 ./pkg/plugins/gateway/...` and
`go test -count=1 -race ./test/integration/gateway/` all green.

## Code Review

This pull request refactors the PD-disaggregated prefill engine handlers and transfer agents to operate directly on raw JSON bytes instead of unmarshaling and marshaling through map[string]any. This change preserves the exact byte ordering of nested objects, ensuring stable prompt_token_ids and maximizing KV-cache prefix reuse. To support this, a new JSONEditor utility is introduced to chain byte-level edits. The review feedback focuses on optimizing these byte-level edits further by constructing nested JSON objects beforehand and applying them in a single pass using SetRaw, thereby avoiding multiple full-body JSON parses and copies on large request bodies.
