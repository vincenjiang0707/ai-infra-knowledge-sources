## Pull Request Description

The gateway keeps a process-wide rate history (`rateCalculator` in `pkg/cache`) for rates it derives from counters. Its keys used the bare pod name:

- `calculateRate1m`: `podName//metric`, with no namespace and no model. It feeds `RealtimeRunningRequestsDrainRate1m` (PD decode drain-rate scoring) and `RealtimeOutputTokenRateEWMA` (the load-balance router's capacity estimate).
- `calculatePerSecondRate`: `podName/model/metric`. It feeds `AvgPromptThroughputToksPerS` / `AvgGenerationThroughputToksPerS` (PD decode throughput scoring).

Same-named pods in different namespaces are common when a controller names pods by index, such as StatefulSet or LeaderWorkerSet. Those pods shared one series:

- A pod's rate could be computed against a snapshot of the other pod's counter.
- A smaller counter from the other pod was read as a counter reset, so the pod's whole counter value was used as the delta.

For `calculateRate1m` this happened even across models. In a local test with interleaved updates, `calculatePerSecondRate` reported about 994,000/s for a pod whose true rate was about 500/s. Deleting a pod also purged the history of its same-named twin, because `PurgeEntriesForPod` matched on the name only.

This PR:

- builds every history key through one helper, prefixed with `utils.GeneratePodKey(namespace, name)`:
  - `namespace/name/model/metric`
  - `namespace/name//metric`
- makes `PurgeEntriesForPod` take the namespace and purge by the same prefix.

The history is in-memory only, so the new key format needs no migration.

**Tests:**
- the per-second rate and the 1-minute rate stay separate for same-named pods in two namespaces
- purging one pod leaves its same-named twin and a pod whose name shares a prefix (`decode-0` vs `decode-00`) untouched
- all three tests fail when the namespace is dropped from the key

Verification:
- `go test -race ./pkg/cache/... ./pkg/plugins/gateway/...` passes
- golangci-lint reports no issues

This is the High item in #2800.

The fix is correct and is the right size for the bug. `rateCalculator.history` is one process-wide map. `calculatePerSecondRate` used `podName/model/metric` and `calculateRate1m` used `podName//metric`, and `PurgeEntriesForPod` deleted every key with that bare name as a prefix. Same-named StatefulSet or LeaderWorkerSet pods in two namespaces therefore shared a series, and deleting one of them dropped the other. A smaller counter on the shared series takes the existing reset branch (`valueDiff < 0` / `delta < 0`) and treats the whole counter as the delta, which is the ~994k/s case in the issue.

Both writers and the purge now go through `rateHistoryPodPrefix`, which is `utils.GeneratePodKey(namespace, name) + "/"`. That is the same `namespace/name` identity the rest of the cache already uses (`metaPods`, running-request keys, gateway snapshots). The trailing slash is load-bearing: `team-a/decode-0/` does not match `team-a/decode-00/...` or `team-a/decode-0-extra/...`, and `team/decode-0/` does not match `team-a/decode-0/...`. Kubernetes namespace and pod names cannot contain `/`, so the prefix boundary holds for real objects. The history is in-memory only, so the new key shape needs no migration; a gateway restart starts from an empty map, which is the same cold window as today.

`calculateRate1m` staying model-less is right. `completedRequests` and `completedOutputTokens` are pod-level atomics (`pkg/cache/pod.go`), and the metrics they feed (`RealtimeRunningRequestsDrainRate1m`, `RealtimeOutputTokenRateEWMA`) are pod-scoped. Putting a model in that key would split one counter across series. `calculatePerSecondRate` stays per model, which matches `AvgPromptThroughputToksPerS` / `AvgGenerationThroughputToksPerS`.

Purge stays on the informer delete path only. `updatePod` still calls `deletePodLocked` and does not purge, so an in-place pod update keeps the rate window. That matches counter resume in `addPodLocked`: a short delete/re-add of the same IP keeps `completedRequests` / `completedOutputTokens`, and wiping history there would cold-start the drain rate and the load-balance EWMA on every spec or status update. The sole caller of `PurgeEntriesForPod` is updated. A real delete still clears history for that `namespace/name`, including when the pod comes back with a new IP and the counters correctly start at zero.

### Risks

- The empty model segment means `rate1mKey(pod, metric)` and `perSecondRateKey(pod, "", metric)` are the same string (`namespace/name//metric`). Today they do not meet: the 1-minute series are `completed_requests` and `completed_output_tokens`, and the per-second series are engine counters (`PromptTokenTotal`, `GenerationTokenTotal`) passed with the model name from the scrape. A later caller that passes an empty model and one of those two metric names would mix the windows. The comment on `rate1mKey` already records the empty segment; keep new series on one of the two helpers so the shapes cannot drift.
- Model names may contain `/` (Hugging Face ids). Nothing parses these keys back — purge is a prefix match on `namespace/name/` — so a slash inside the model does not break deletion. Two series collide only if a model slash and a metric slash produce the same joined string. Engine metric names have no slash, so this is latent, and it was already true of `podName/model/metric`.
- After a true delete, a same-IP re-add within `recentlyDeletedPodGracePeriod` (60s) restores the counters and leaves the rate window empty, so drain rate and EWMA stay at "no sample" until the window fills again. That is the previous delete behavior, now limited to the pod that actually went away.
- `PurgeEntriesForPod` still walks the whole map. History is bounded (about 20 or 36 snapshots per series, a few minutes of age), and purge runs on pod delete. A nested map would make delete O(1) and is more code than this bug needs.
- `TestCalculateRate1m_SameNameInTwoNamespaces` uses `InDelta(..., 1)` on `3000 / ~30s`. The tolerance misses once the call is more than about 300ms after the seeded timestamp. That is the same pattern as `TestUpdateRealtimeOutputTokenRateEWMA`. It is fine on an unloaded unit-test run.

### Tests

The three new tests fail if the namespace is removed from the key, and they use the global calculator the production code uses.

- `TestCalculatePerSecondRate_SameNameInTwoNamespaces` — the second pod's first sample must return `-1`, and the two histories must be `[100000]` and `[500]`. A shared key would append `500` onto the first pod's snapshot (and usually return a rate, unless `time.Now()` did not advance and the `timeDiff <= 0` branch also returned `-1`). The history assertions are the ones that lock the bug; the `-1` on the second call is weaker if both calls share a timestamp.
- `TestCalculateRate1m_SameNameInTwoNamespaces` — this is the counter-reset case. `team-b` at `5` must not be read against `team-a`'s baseline of `1000`, and `team-a` must still report ~100/s for `4000` over 30s. Calling `team-b` first is what makes the assertion catch a shared key.
- `TestPurgeEntriesForPod_NamespaceScoped` — deleting `team-a/decode-0` removes both the per-second and the 1-minute series, and leaves `team-b/decode-0` and `team-a/decode-00` in place.

`seedCompletedOutputTokensHistory` and the no-history EWMA cleanup were switched to `rate1mKey`, so those tests exercise the new key instead of passing against an orphaned old key.

Gap: there is no per-second test that takes a third sample and checks the numeric rate (the 100000 → 500 → 100100 interleaving from #2800). Separate histories make that interleaving impossible, so the gap is coverage of the rate math, which already has its own tests, not of the key split. The package does not use `t.Parallel()`, and cleanup purges the pods under test. Keys are not cleared at the start; the `team-a` / `team-b` names are new, so they do not collide with older tests that still used a bare pod name.

### API and compatibility

No CRD, HTTP, metric name, label, annotation, or environment variable changes. Routers keep reading `RealtimeRunningRequestsDrainRate1m`, `RealtimeOutputTokenRateEWMA`, `AvgPromptThroughputToksPerS`, and `AvgGenerationThroughputToksPerS`. In a single namespace the computed rates are unchanged once the window has two samples (per-second) or 10s of history (1-minute). A rollout restarts the process, so old bare-name keys disappear with the process.

`PurgeEntriesForPod` is exported and gains a `namespace` argument. The only caller in this module is `deletePod`. The method is not a user-facing contract; the history map stays private.

## Design simplification

The structure is already the small version of this fix. One string map, one prefix helper, purge on the delete handler. Further redesign (nested `map[podKey]...`, a key struct, a pod UID in the key, a model segment on the 1-minute series) adds surface without changing the bug.

### Keep

- `utils.GeneratePodKey` as the pod identity, plus the trailing `/` on the purge prefix. That slash is the `decode-0` versus `decode-00` fix; a prefix of `namespace/name` without it deletes the longer name.
- One `rateCalculator.history` map shared by both calculators. The two series have different snapshot throttles and windows; they only need distinct keys.
- Pod-scoped 1-minute keys (no model) and model-scoped per-second keys. Those match the counters.
- Purge only from `deletePod`, with the namespace taken from the same object or tombstone key the handler already resolved.
- The three tests: cross-namespace per-second history, cross-namespace 1-minute counter reset, and purge versus a same name in another namespace and a longer name in the same namespace.
- The empty model segment (`namespace/name//metric`). It is the old `name//metric` layout with a pod key in front, and nothing on disk depends on it.

### Cut

- `perSecondRateKey` and `rate1mKey` as two wrappers. One function is enough:

```go
func rateHistoryKey(pod *Pod, modelName, metricName string) string {
    return rateHistoryPodPrefix(pod.Namespace, pod.Name) + modelName + "/" + metricName
}
```

`calculateRate1m` calls it with `modelName == ""`. `rateHistoryPodPrefix` stays, so purge and both writers cannot drift. The wrappers do not encode a rule the call sites do not already know.

- A new scope token in place of the empty segment (`_pod`, `pod`, and similar). It reads more clearly and removes the empty-model alias, and it is also a second key dialect for a map that is never parsed. Do that only if a third series appears.

Leave the linear purge scan, the global calculator, and the in-memory map as they are.
