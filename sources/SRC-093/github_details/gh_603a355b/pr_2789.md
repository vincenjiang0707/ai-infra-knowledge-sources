## 正文

What

Follow-up to the non-blocking nit on [#2757](https://github.com/vllm-project/aibrix/issues/2757): _write_json_file opens its temp file in text mode without newline="", the same pattern that caused the newline rewriting fixed there.

Why it is safe today, and why it is worth hardening

json.dump is called without indent, so it emits a single compact line with no bare \n, and any newline inside a string value is escaped as \\n. Nothing reaches the text layer for Python to translate, so the current behaviour is correct on every platform.

The risk is a future edit. The moment someone adds indent= to make the metadata readable, json.dump starts emitting real newlines, and on Windows those become \r\n — the exact failure mode #2757 fixed one branch above. Passing newline="" now means that change cannot reintroduce it.

No new test, deliberately

There is no input that distinguishes the two forms today: with json.dump emitting no bare newlines, the bytes written are identical with and without the argument. A test that fails before this change and passes after it cannot be written — which is itself the evidence that this is hardening rather than a bug fix.

Evidence that behaviour is unchanged

pytest tests/storage is 156 passed, 13 skipped on Windows, identical to before the change.
