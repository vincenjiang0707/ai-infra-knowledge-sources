# [PR #1984] feat(autoscaler): Add circuit breaker policy for HPA on bad metrics

## 正文

## Summary

Closes #1593

Implements a configurable circuit breaker mechanism in the PodAutoscaler that detects invalid metrics and applies a protective action to prevent erratic scaling behavior.

## Circuit Breaker Design

### Trigger Conditions
- **NaN** metric values
- **Infinite** (+Inf/-Inf) metric values
- **Negative** metric values

Validation is performed at two layers:
1. **Raw metrics** - immediately after collection from pods/external sources
2. **Aggregated metrics** - after stable/panic window processing

### Policy Actions
- `freeze` (default): Keep current replica count unchanged until metrics recover
- `max`: Scale target replicas to the maximum defined in spec and hold there until metrics recover

### Status Reporting
When triggered, a `CircuitBreakerTriggered` condition is set on the PodAutoscaler status. When metrics recover, the condition is automatically removed.

## API Changes

Added `CircuitBreakerConfig` type with `Enabled` and `Action` fields.
Added optional `CircuitBreaker` field to `PodAutoscalerSpec`.

## Usage

```yaml
apiVersion: autoscaling.aibrix.ai/v1alpha1
kind: PodAutoscaler
metadata:
  name: my-model-autoscaler
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: my-model
  minReplicas: 1
  maxReplicas: 10
  scalingStrategy: KPA
  circuitBreaker:
    enabled: true
    action: freeze  # or 'max'
  metricsSources:
    - metricSourceType: pod
      targetMetric: kv_cache_utilization
      targetValue: "50"
```

## Files Changed

- `api/autoscaling/v1alpha1/podautoscaler_types.go` - Added CircuitBreakerConfig, CircuitBreakerAction types and CircuitBreaker field
- `api/autoscaling/v1alpha1/zz_generated.deepcopy.go` - Added DeepCopy methods for CircuitBreakerConfig
- `pkg/controller/podautoscaler/circuitbreaker/circuitbreaker.go` - Core circuit breaker logic (validation + evaluation)
- `pkg/controller/podautoscaler/circuitbreaker/circuitbreaker_test.go` - Comprehensive unit tests (25+ test cases)
- `pkg/controller/podautoscaler/autoscaler.go` - Integrated circuit breaker validation in scaling pipeline
- `pkg/controller/podautoscaler/podautoscaler_controller.go` - Added CircuitBreakerTriggered condition + bypass normal scaling when triggered

## Backward Compatibility

- The `circuitBreaker` field is optional (omitempty) - existing CRDs continue to work without any changes
- No changes to the `ScalingStrategy` field type (kept as string enum)
- When `circuitBreaker` is nil or `enabled: false`, behavior is identical to current code
