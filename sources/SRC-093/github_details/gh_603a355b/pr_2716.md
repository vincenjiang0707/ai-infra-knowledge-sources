## Review

This is a useful PR1 foundation: driving the real `Server.Process` ext_proc loop with an isolated cache/router manager is the right integration seam, and the suite already covers a representative set of routing, lifecycle, cancellation, and profile-precedence cases.

I would **not merge as-is**. There is one production error-path change that exists to accommodate the fake stream, one routing assertion that cannot catch the regression it names, and the mutex-across-wait issue already flagged on `fakeProcessStream.Recv`.

### Must-fix

**1. Do not change `handleRecvError` for the fake stream**

```495:498:pkg/plugins/gateway/gateway.go
		if errors.Is(err, context.Canceled) || errors.Is(err, context.DeadlineExceeded) {
			return err
		}
		return status.Errorf(codes.Unknown, "recv stream error: %v", err)
```

Production Recv errors from Envoy are gRPC statuses. `codes.Canceled` is already handled above, and `preRecvCheck` already returns `st.ctx.Err()`. The new branch is here so the fake can return raw `context.Canceled` / `DeadlineExceeded`.

Make `fakeProcessStream.Recv` return `status.Error(codes.Canceled, ...)` / `codes.DeadlineExceeded` on `ctx.Done()`, and assert with `status.Code(err)`. That exercises the real Envoy path and keeps this test PR from changing production recv classification. Note that the existing gRPC-canceled path currently records **success** metrics, which this new branch does not.

**2. Zero-weight test cannot fail if weight `0` is ignored**

`configureZeroWeightMetrics` makes both `least-request` and `least-kv-cache` prefer `other`. If `least-request:0` were broken, the expected target would still be `10.0.0.3:8000`. Auto-blend of `load-balance` also agrees.

Invert the least-request scores so that algorithm would pick `target` and only kv-cache picks `other`. Then `target-pod=10.0.0.3:8000` actually proves opt-out.

**3. `Recv` holds `mu` while blocking on `ctx.Done()`** (agree with the existing comment)

Unlock before waiting. `processOnce` can return on `shutdownCh` while the Recv goroutine is still blocked; a later `responses()`/`diagnostics()` call deadlocks.

### Should-fix

- **`HasRequestBuffers` and `InFlightObserver` leak test hooks into the production API.** `InFlightObserver` runs on the request path with an explicit “must not panic” contract. Prefer unexported test helpers, or observe existing `GatewayInFlight` / cache events.
- **`NewRouterManagerWithCache*` is a hand-maintained subset of production `init()` registrations** (no PD, SLO, VTC, throughput, session affinity, …). Invalid-strategy tests can pass for algorithms that production accepts. Share one registration helper so production and fixtures cannot drift.
- **Nil indexer semantics disagree:** `NewPrefixCacheRouterWithOptions(c, nil)` uses the process-wide table; `NewRouterManagerWithCacheAndPrefixIndexer(c, nil)` allocates a private one. Easy to misuse outside this fixture.
- **Gemini’s `routerManager` init cleanup is right:** always store a non-nil manager (injected, cache-local, or `DefaultRouterManager()`), `Init()` it, and drop `routers()`.

### Test-strength nits

- Many cases use a single ready pod. `selectTargetPod` short-circuits that path and never calls the router. Fine for lifecycle/header tests; the strategy table correctly uses two pods.
- The SSE spec asserts the **inputs** the test itself wrote and that Gateway did not mutate the body. That is a callback-boundary check, not split-JSON/`[DONE]` parsing. The comment is honest; the test name is not.
- Upstream error coverage uses `:status 200` plus an error JSON body (the fake-success unmarshal path). A 4xx/5xx header status is still uncovered here.
- The “does not forward `user`” spec only inspects request-body `SetHeaders`, not whether the header is still on the downstream request.
- `test/README.md` should mention `make test-integration-gateway`. Title prefix `[TEST]` is not in the contribution template (`[Misc]` / `[CI]`).

The DI split (`ServerOptions`, cache-aware constructors, fixture-local prefix table) is the right shape. Tighten the three must-fix items and this is a solid PR1.
