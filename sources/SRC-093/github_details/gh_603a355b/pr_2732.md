## Pull Request Description

`POST /tokenize` cannot be reached through AIBrix: the gateway rejects it with
`501 unknown request path`, and even with that fixed Envoy 404s it before ext_proc
runs. This registers `/tokenize` in the request-path switch, excludes it from
`isLanguageRequest` so the engine's `model`-less response is not replaced by a 500,
and adds the path to both route allowlists — `modelPaths` and the static
`reserved-router` in `config/` and `dist/chart/`. Verified end to end against a
vLLM deployment.

## Review

**Verdict: LGTM with one should-fix** — agree with @googs1025 that a gateway e2e case belongs in this PR (or a linked follow-up before merge).

### What works well

The three-layer fix matches how the gateway actually fails today:

1. **Plugin** — `validateRequestBody` case + `PathTokenize`
2. **Response path** — exclude from `isLanguageRequest` (tokenize returns `{count, max_model_len, tokens}` with no `model`/`usage`; without this the gateway replaces the engine body with a 500)
3. **HTTPRoute** — both `reserved-router` (`config/` + chart) and `modelPaths`

`validateTokenizeRequest` is appropriately minimal: require `model` for routing, leave the rest of the schema to the engine, keep `prompt` as `json.RawMessage` so wrong types fail in vLLM's validator. Unit coverage of prompt/messages/missing-model/invalid-JSON/non-string prompt looks solid.

### Should-fix

**Add a gateway e2e** under `test/e2e/gateway` (raw HTTP `POST`, not the OpenAI SDK). Assert 200 + tokenize response fields for a valid body, and ideally missing-`model` → 400. The Kind/dev mock already exposes `/tokenize`.

### Open threads

| Thread | Take |
|--------|------|
| Gemini `bytes.Equal` suggestions | Agree with the author — `string(slice) == const` does not allocate for comparison ([Go wiki](https://go.dev/wiki/CompilerOptimizations)). Not worth changing. |
| `nolint:nakedret` on `validateRequestBody` | Fair: the extra case trips the linter; same pattern as the other `validate*` helpers in this file. |

### Non-blocking

- **`/detokenize`** would hit the same 501/404 (and 500 if only the switch were fixed). Fine as a follow-up if vLLM parity is desired.
- Chart vs config path lists were already out of sync (`/v1/videos` in config only); this PR does not make that worse.
- Exact path match in `validateRequestBody` means `/tokenize?…` would 501 — pre-existing for other JSON paths.

### CI

Unit / integration / lint look green. The intermittent `Build image (gateway-plugins)` failure looks flaky next to a passing run of the same job.

**Recommendation:** Approve after the e2e lands (or is explicitly deferred with a linked issue).
