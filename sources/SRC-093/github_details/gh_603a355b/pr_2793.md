## Pull Request Description

The bot marks a PR with `triage/needs-information` when the title prefix is not in `PR_PREFIXES`, even when the description is complete. That list was copied from the PR template written in July 2024 and never updated since, while `[Feat]` has become one of the most used prefixes in the repository.

Evidence (checked 2026-09-23):

- The last 400 PRs contain 11 `[Feat]` titles, and maintainers use the prefix themselves: #2742 and #2771 (@varungup90), #2716 (@googs1025). Long-time contributors use it too, for example #2746 (@qidaye).
- 11 of the 76 PRs opened since the validation bot landed are flagged on the prefix. For #2786, #2776, #2746 and #2750 the prefix is the only finding, so removing it makes those PRs pass with zero findings.
- None of the affected PRs had its title renamed to match the check, so the label reaches reviewers as noise rather than as a nudge. The check is advisory and has never blocked a merge.

What this changes:

- `PR_PREFIXES` accepts `[feat]`, and the advisory message lists it.
- The self-test covers a `[Feat]` title.
- The template lists `[Feat]` too, so the two definitions stay in sync instead of drifting apart again.

Scope: `[Gateway]`, `[Batch]` and `[TEST]` are used in titles as well and are still flagged. They read as area names rather than change categories, and the repository tracks areas separately, so they are left out here. Happy to add them too, or to drop `[Feat]` as well, if maintainers prefer to keep the list unchanged.
