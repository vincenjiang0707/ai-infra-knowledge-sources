## 正文

## Pull Request Description
Adds an explicit "Area" field as the primary source for `area/*` labels, instead of relying on keyword matching across the whole issue body (which could tag unrelated areas at once).

- Issue Forms (bug/feature/RFC): new "Area" dropdown. If set, it's used directly; keyword matching is now only a fallback, and it returns at most one label instead of every rule that happens to match.
- PR template: new "Area" checklist. If exactly one box is checked, the bot applies that label; otherwise the existing path-based labeler (`labeler.yml`) output stands untouched.
- Fixed the Issue Forms' stale default labels (`bug`, `triage`, `RFC`) to the labels the bot actually manages (`kind/bug`, `kind/feature`).
- Extended the bot's `--self-test` to cover the new parsing/precedence.

## Review

Looks close to merge: this matches #2714, prior review notes are addressed, and `python3 .github/scripts/aibrix-bot.py --self-test` passes locally.

**What works**
- Issues prefer the explicit Area dropdown; PRs only mutate `area/*` when exactly one checklist box is checked, otherwise `actions/labeler` is left alone.
- Keyword fallback is now first-match-only, which stops unrelated `area/*` pile-ups.
- Parsers match the templates (`kv-cache` stays intact; `[x]`/`[X]` and `Runtime` work).
- Default form labels now use labels that actually exist (`kind/bug`, `kind/feature`). `bug` / `triage` / `RFC` are not repo labels, so those old defaults were no-ops.

**Requested change:** `"Not sure"` still runs keyword matching. The dropdown copy says a maintainer will triage that choice instead of guessing from keywords, but `_explicit_area("Not sure")` is `None` (first token is `"not"`), so a report that mentions “docs” / “workflow” still gets `area/website` or `area/cicd`. Please treat a present Area section with `"Not sure"` / unrecognized value as “no area label”, and keep keyword fallback only for bodies with no Area section (legacy / free-form issues). Inline notes below.

**Non-blocking**
- Area names are duplicated across three Issue Forms, the PR checklist, `AREA_OPTIONS`, and `labeler.yml`; `self_test` only checks `AREA_RULES` vs `AREA_LABELS`.
- `--self-test` is not in CI. `aibrix-bot.yaml` is `pull_request_target` and checks out the **base** sha, so this branch’s script never runs on the PR. A `pull_request` job with no write perms that runs `--self-test` would lock this in.
- The dropdown only covers the nine areas the current bot/labeler know about, not the full repo set (`area/autoscaling`, `area/scheduling`, …). Fine if the taxonomy stays intentionally small.
