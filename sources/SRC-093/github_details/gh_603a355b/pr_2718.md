# [PR #2718] [Bug] Guard SLOQueue.queueRank against zero throughput

source: https://github.com/vllm-project/aibrix/pull/2718
state: closed | updated: 2026-09-15T10:18:33Z
labels: area/gateway, triage/needs-information

## 正文

## What this PR does

`SLOQueue.queueRank` divided by the throughput read from the GPU profile without checking for zero, and `SLOQueue` had no unit tests at all. This adds the guard and the first specs for the function.

## The defect

`ModelGPUProfile.ThroughputRPS` returns an error only when the whole `Tputs` table is absent. A zero cell *inside* the table is returned as a valid `0.0`, so `queueRank` computed `float64(sub.Len()-1) / 0` and returned `NaN` when the sub-queue held only the head request, or `+Inf` when requests were queued behind it — in both cases alongside a nil error, leaving `Peek` with no signal to skip the profile.

That matters because `Peek` orders profiles with `q.higherRank(...) < 0`. Every comparison involving `NaN` is false, which leaves `sort.Slice` with an inconsistent less function, and `Inf - Inf` is `NaN` too, so two zero-throughput heads would hit the same problem.

This is reachable with the project's own data: `simulator-llama2-7b-a100.json` has zero entries in `tputs`, including the whole top output-length row, which `GetSignature` clamps any longer request onto.

## The fix

`PendingLoadProvider.GetConsumption` already performs the same division and already guards it with `ErrorSLOFailureRequest`, and `Peek` already skips a profile when `queueRank` returns an error. This applies the established pattern rather than inventing one — two lines:

```go
} else if throughput == 0.0 {
	return 0.0, cache.ErrorSLOFailureRequest
}
```

## Tests

Three specs, on a hand-built `ModelGPUProfile`:

1. The test request maps onto the intended cell — pins the fixture, so a change to `GetSignature` or the index layout fails here rather than confusing the specs below.
2. A zero-throughput cell returns `ErrorSLOFailureRequest` and a zero rank.
3. A non-zero-throughput profile with two queued requests returns a finite rank, verifying the `(len-1)/throughput` arithmetic on the success path.

Spec 3 passes the head request's own `RequestTime` as `currentTime`, so the elapsed term is exactly zero and the assertion does not depend on wall-clock timing.

## Note on scope

The original PR was test-only and characterised the NaN and `+Inf` values instead of fixing them. Following review, it now fixes the defect, since the path is gated behind `queueOverallSLO` (a package-level `bool` fixed at `false`) and carries no user-facing risk, and since the codebase already had the guard elsewhere.

### Tests freeze a bug as the API

`queueOverallSLO` is a package-level `false`, so `Peek` never calls `queueRank`. This path is dead: changing it has no user-facing risk. Adjacent code already has the right policy. `PendingLoadProvider.GetConsumption` treats a zero `tputs` cell as failure (`ErrorSLOFailureRequest`). `Peek` already skips a profile when `rankErr != nil` and can fall back.

Returning `NaN, nil` / `+Inf, nil` is the one outcome that path cannot handle: `higherRank` is `rank1 - rank2`, and `sort.Slice` with a NaN-valued less function is not a strict weak order. Real shipped profiles (`simulator-llama2-7b-a100.json`) do contain zero cells, as you noted.

Shipping tests that require `err == nil` plus `IsNaN`/`IsInf` means the correct fix (return an error on `throughput == 0`) looks like a regression.

Prefer one of:

1. **Fix the dead path in this PR** (or a tiny follow-up that lands first): if `throughput == 0`, return an error (e.g. `cache.ErrorSLOFailureRequest`). Assert that. No change to the live `rank()` path.
2. **Keep characterization tests**, but file an issue and mark the specs (`Skip` / `PIt` / a `TODO(issue)` next to the NaN/+Inf expects) so nobody treats them as the contract.

Option 1 is better — you already diagnosed this.

### Coverage does not match the title

These specs exercise `queueRank` and a bit of `rankImpl` / `rankImplE2E`. They do not touch the live surface: `Enqueue` / `Peek` / `Dequeue` / `Route`, `rank()` (what `Peek` actually calls today), or the NaN `sort.Slice` problem described in the PR body (`Peek` is never called).

If the goal is “SLOQueue has unit tests,” add at least one finite-rank `queueRank` case (non-zero cell, `Len()==2` → `(len-1)/tput` is finite) and a `rank()` case. The zero-cell specs then have something to contrast against.

### Smaller notes

- `g` is an opaque name for the predictor; `predictor` would match the type.
- The `[1, 1]` pin is not really an `SLOQueue` spec. Fine as a `BeforeEach` invariant so a mapping break fails before `queueRank`.
- A one-line comment that `Indexes` are already in log2 space would help anyone who only knows the JSON profile shape (`Unmarshal` is what log2s them).
- Aligning `simple_queue_test.go` enqueue assertions can stay a follow-up.

Happy to re-review if you go with the error-on-zero-throughput fix.
