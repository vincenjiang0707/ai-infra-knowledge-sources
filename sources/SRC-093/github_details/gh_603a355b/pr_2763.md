## Pull Request Description

The per-request warning in `SLOQueue.Peek` claims the request would "fallback to FIFO queue" when no deployment profile can rank it. That is not the code path: the request is only excluded from this round's ranking, and the FIFO fallback candidate is used only when no candidate can be ranked at all. Whenever other ranked candidates remain, the message misstates the routing decision.

Rephrase the message to match the actual behavior, note in the fallback handler comment when the fallback candidate is used, and fix two `ealiest` typos in nearby comments. No behavior change; the FIFO fallback path itself is untouched.

Verified locally: `gofmt -l pkg/plugins/gateway/queue/` is clean, and `go vet ./pkg/plugins/gateway/queue/`, `go build ./...`, `go test ./pkg/plugins/gateway/queue/ -count=1` (also with `-race`) all pass.

### What this gets right

In #2760, a per-request empty-profile path started dropping only that candidate (`[:idx]`) instead of collapsing the whole model queue to FIFO. The leftover warning still said `"fallback to FIFO queue"`, which is wrong whenever any other candidate still ranks.

`Peek` does this:

1. `fallbackHandler` always records the earliest-arrival request in slot `0`.
2. If this request has no rankable profile, it is removed from the ranked slice and **not** chosen from ranking this round.
3. Slot `0` is used only when `len(q.dequeueCandidates) == 1` — i.e. nothing ranked.
4. If anything ranked remains, ranking uses `q.dequeueCandidates[1:]` and ignores the FIFO slot.

The new message (`excluding it from this round's ranking`) is the ranking-path behavior. The added fallback-handler comment (`only used when no candidate can be ranked`) matches the `len == 1` branch. The model-level warning (`no profile available … fallback to FIFO queue`) is left alone, which is correct: that path really is FIFO.

The `ealiest` → `earliest` comment fixes and `emulate` → `emulates` are fine and in-scope.

No API, routing, or dequeue change. Existing specs from #2760 already pin the mixed case (unrankable FIFO head dropped, ranked candidate served) and the all-unrankable FIFO path. A log-string change does not need a new test.

One non-blocking nit on the empty-profile comment is inline below. Out of scope and pre-existing: per-Peek `Warningf` noise, `"failed to get SLO info"` covering non-SLO rank errors, and broader stale `RoutingContext` retention on unused `dequeueCandidates` slots.
