## Pull Request Description
Replace the request drain-rate capacity in the load-balance router with

  score = (running + λ·queued) / EWMA(output tokens/sec) × (1 + α·(1 − kvFree)²)

and route to the lowest score. Capacity (observed token throughput), load (committed work) and KV headroom are now separate inputs, so a saturated replica is no longer read as "send it more traffic" and request size no longer skews the capacity estimate on heterogeneous hardware.

- Cache: count output tokens completed per pod (gateway-tracked, engine agnostic, carried across pod delete/re-add like completedRequests) and publish RealtimeOutputTokenRateEWMA: the 1-minute token rate smoothed with a 10s time constant. A window with no completed tokens keeps the previous estimate instead of decaying it, so a briefly idle pod is not starved.
- Router: pods with no estimate yet are scored at the mean of the measured pods (a fixed 1.0 would be off by the tokens/sec scale and lock a new pod out). A pod below the critical free-KV fraction scores +Inf; if every pod is below it the request still routes to the pod with the most KV headroom.
- New knobs: AIBRIX_LOAD_BALANCE_QUEUED_WEIGHT (default 0, since the running count already includes engine-queued requests), _KV_PRESSURE_ALPHA (2.0) and _KV_CRITICAL_FREE (0.10).
- The PD decode path keeps its own request drain-rate scoring.
- Add load_balance.md, update the router docs and ENV_VARS.md, migrate the load-balance unit and gateway integration tests, and add tests for the score, the KV guardrail, unmeasured pods, and the cache counter/EWMA.

## Review

**Verdict: Approve with comments.** The formula is the right split of capacity / load / KV, the cache counter follows the existing `completedRequests` flap path, and the tests actually pin the documented example, the KV guardrail, idle-keeps-EWMA, and unmeasured-pod fallback. PD correctly keeps request drain-rate.

I would not merge the draft until the NaN KV case is handled and the unmeasured-pod fallback is revisited for mixed GPU pools. The `samples/quickstart/vke/model.yaml` image bump is unrelated and should come out.

### What works

- Capacity is observed token throughput, load is committed requests, KV is a penalty/guardrail. A busy-fast replica is no longer “send it more because drain-rate is high.”
- `donePodStats(..., outputTokens)` with 0 on the count-only path, monotonic clamp, and snapshot/live redirect matches `completedRequests`.
- Idle window `rate <= 0` keeps the previous EWMA instead of decaying toward zero — that is the correct “idle ≠ slow” behavior.
- Unmeasured pods using a peer fallback instead of `1.0` is necessary at tokens/sec scale.
- All-critical still routes (via Inf==Inf candidates plus the empty fallback for NaN-only). Tie-break is least-KV.
- Blend interaction is correct: `normalizeScoresArray` drops non-finite scores, so `+Inf` stays 0, which is worst under `PolarityLeast`. The md file has this right.
- Docs (`load_balance.md`) are unusually precise, including multi-gateway 1/N and estimate lag.

### Must-fix / should-fix

1. **NaN KV usage** (Gemini, agree). `math.Min/Max` do not filter NaN, `NaN < kvCritical` is false, and the score becomes NaN. NaN is skipped in the min loop (`NaN < x` / `NaN == x` are both false), so a pod with a bad metric is silently excluded in a mixed pool, and an idle NaN pod does not score 0. Treat NaN like a missing metric (fully free).

2. **Unmeasured pods get the mean of measured capacities.** That is the wrong default for the heterogeneous B40/A100/H20 story this PR is selling. A new B40 in an H100 pool inherits H100-scale capacity, scores cheap, and is filled toward H100 request counts until EWMA catches up. Prefer the **min** of measured rates (conservative), or only apply the mean while `running == 0` (where the score is already 0). Add a mixed-GPU “fresh slow card” spec if you keep mean.

3. **`samples/quickstart/vke/model.yaml` `v0.5.0` → `v0.7.0`** is unrelated to scoring. Drop it from this PR.

### Nits

- `LoadEnvFloat` rejects `<= 0`, so `AIBRIX_LOAD_BALANCE_KV_PRESSURE_ALPHA=0` cannot turn the penalty off. Documented, but surprising if someone wants “guardrail only.”
- `if len(candidates) == 0` after the Inf loop is almost dead: `+Inf == +Inf` already collects every critical pod. It still matters for all-NaN. Worth a one-line comment so the next reader does not “clean it up.”
- `RealtimeOutputTokenRateEWMA` is not emitted to Prometheus while the request drain-rate is. Fine if intentional; a series would make the `-v=4` story easier in multi-replica gateways.
- PR body still has `Resolves: #[Insert issue number(s)]`.

CI was still running when I looked (DCO / RTD green). Draft, so no rush, but I would not land the mean-capacity behavior as-is.
