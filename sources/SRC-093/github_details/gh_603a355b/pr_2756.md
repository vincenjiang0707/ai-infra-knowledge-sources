## 正文

## Pull Request Description

`ModelGPUProfile.GetSignature` reads `indexes[i]` once per requested feature but only checks the inner slices, so a profile with fewer index ranges than features (a missing `indexes` field unmarshals to nil) panics with `index out of range`. The gRPC server in `cmd/plugins/main.go` is built without a recovery interceptor, so one malformed profile terminates the plugin process instead of failing a single routing decision.

The Python estimator already treats any dimension mismatch as an error: `get_signature()` raises before doing any work. This adds the equivalent guard on the Go side:

```go
if len(indexes) != len(features) {
    return nil, fmt.Errorf("profile index size mismatch, got %d, expected %d", len(indexes), len(features))
}
ret := make([]int, len(features))
```

`rankImpl` propagates `GetSignature` errors and `Peek` logs a warning and skips the profile, so the failure becomes "this deployment was not scored" and the gateway stays up. The guard requires an exact match, so profiles with extra index ranges are rejected as well instead of producing a short signature that fails later in `getValue`.

Verified by reverting the guard locally: the short-index specs fail with `index out of range`, while the extra-index case silently returns a short signature; with the guard, `go test ./pkg/cache/... ./pkg/plugins/gateway/queue/...` passes.

## Review

**Approve** — small, correct panic fix with good tests and green CI.

### What it does
`ModelGPUProfile.GetSignature` indexed `indexes[i]` without ensuring `len(indexes) == len(features)`. Missing/short `indexes` (nil after unmarshal) panics; the gateway plugin has no recovery interceptor, so one bad profile can take down routing.

The exact-length check (and allocating `ret` after validation) matches the Python estimator’s mismatch guard and is the right contract.

### Why the fix is sound
- **Panic path is real**: `Features()` always returns 2 dims (`outputLen`, `promptLen`); a profile with 0 or 1 index ranges hits `indexes[i]` OOB.
- **Error handling is already in place**: `rankImpl` returns the error; `Peek` logs and skips that profile / falls back to FIFO; `PendingLoadProvider` surfaces it.
- **Exact match is right**: extra index ranges previously produced a short signature that failed later in `getValue` (`too few signature dimensions`). Early, clear rejection is better.
- **Tests cover the three cases**: short, missing, and longer indexes. CI is green.

### Nits (non-blocking)
1. Consider moving the length check before building `formalizedVals` / `Log2` so malformed profiles fail before feature work.
2. Optionally assert the error substring (`profile index size mismatch`) so a future empty-inner-slice error can’t accidentally satisfy these specs.

No functional blockers. Safe to merge as-is.
