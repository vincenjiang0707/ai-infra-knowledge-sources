## Summary

`rng_init(seq=None)` derived the default curand subsequence from `threadIdx.x`
and `blockIdx.x` only. Every thread that differed only in `y`/`z` therefore
shared one subsequence, so e.g. the two threads at `(tx, 0)` and `(tx, 1)` of a
2-D block produced byte-identical draws.

Fold every launched dimension into the default sequence in row-major order.
Dimensions that were not launched have extent 1 and contribute nothing, so the
historical 1-D id `threadIdx.x + blockIdx.x * blockDim.x` is unchanged.

Fixes #2625

## Changes

`tilelang/cuda/language/random.py`
- add `_default_rng_sequence()`, a row-major linear id over every launched
  thread and block dimension;
- document the derived default in the `seq` parameter docstring.

`testing/python/language/test_tilelang_language_rand.py`
- 4 new cases: 2-D thread block, 2-D grid, 1-D layout preservation, and an
  explicit `seq=` control.

## Validation

Environment: NVIDIA L20 (sm_89), CUDA 12.8, PyTorch 2.10.0+cu128,
Python 3.13.14; base `e40e09e3e61595083d63a38bcf67f7ccb976b2ea` (current `main`).
`bash format.sh` passes on every changed file.

### Observable behaviour

| case | before | after |
|---|---|---|
| generated sequence | `curand_init(1234, ((int)threadIdx.x), 0, &state)` | `curand_init(1234, ((((int)threadIdx.y) * 2) + ((int)threadIdx.x)), 0, &state)` |
| 4 threads of a 2x2 block | 2 distinct values, row collisions `[True, True]` | 4/4 distinct, `[False, False]` |
| 2x2 `blockIdx` grid | `blockIdx.y` ignored | `blockIdx.y` folded in |
| 1-D launch | — | byte-identical to explicit `seq = threadIdx.x + blockIdx.x * blockDim.x` |
| explicit `seq=` | forwarded | forwarded unchanged |
