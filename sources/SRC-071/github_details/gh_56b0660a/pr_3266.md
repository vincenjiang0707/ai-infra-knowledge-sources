# [PR #3266] [BugFix] Reject non-power-of-two AllReduce thread strides

state: closed | updated: 2026-09-21T13:18:17Z

## 正文

## Summary

`tl::AllReduce` is an XOR butterfly: thread `t` pairs with `t ^ (scale * k)`. That only moves the reduce coordinate when `scale` (the thread stride between consecutive reduce participants) is a power of two. #2611 added the power-of-two check for the logical width (`threads / scale`) but not for the stride itself, so a stride-3 reduce slipped through the lowering, the CUDA `static_assert`, and the reducer v2 planner.

The natural trigger is any fragment whose non-reduced extent is not a power of two: reducing a `(32, 3)` fragment along `dim=0` with its default inferred layout (`thread = i * 3 + j + 96 * rep`) lowers to `AllReduce<MaxOp, 96, 3>`. Depending on the CTA size this either silently mixes columns and replicas (256 threads: `reduce_max` of `arange(96).reshape(32, 3)` returns `[63, 62, 62]` instead of `[93, 94, 95]`) or reads past the workspace (`t ^ 48` for `t >= 64` with exactly 96 or 192 threads: `illegal memory access`). The same shape shows up in an FP4 → FP8 scaling-factor cast kernel whenever `hidden / out_block_k` is not a power of two.

## Changes

- `CheckAllReduceWidth` (shared by `tl.reduce` and `tl.finalize_reducer`) now also requires `scale` to be a power of two, with an error that points at padding the non-reduced fragment extent.
- `tl::AllReduce` in the CUDA template carries the matching `static_assert`.
- The reducer v2 narrow-plan gate (`AnalyzeReducerUpdateSite`) rejects non-power-of-two strides alongside the existing width check, so the planner falls back to the wide plan instead of emitting the broken collective (`(32, 3) -> (3,)` max over 128 threads now produces a correct `AllReduce<MaxOp, 128, 1>`).

Non-power-of-two strides are deliberately rejected rather than supported: such layouts are already slower than their power-of-two-padded counterparts, so the right fix on the kernel side is to pad.

## Tests

- `test_allreduce_rejects_non_power_of_two_scale` (reduce, sum/max × three trigger shapes: exact-fit 96 threads, two replicas over 256 threads, shuffle-only width).
- `test_narrow_plan_rejects_non_power_of_two_thread_stride` (reducer v2: asserts the wide fallback plan and checks the result).
