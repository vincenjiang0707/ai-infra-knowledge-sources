## Summary

A function that draws from the curand stream without ever calling `rng_init`
emitted `curand(&)`: the state name was empty, so a TileLang semantic error
surfaced as an nvcc syntax error inside generated code.

Validate RNG state once per function, in the existing `AddFunction` pre-scan. If
the body contains an `rng_rand` / `rng_rand_float` but no `rng_init`, fail with
an intentional TileLang error instead.

Fixes #3034

## Changes

`src/cuda/codegen/codegen_cuda.cc`
- extend the `AddFunction` pre-scan to record whether the function declares an
  `rng_init` and whether it consumes the stream, and check the combination. The
  check is deliberately **function-scoped rather than
  control-flow-sensitive**: an `rng_init` inside a runtime branch still counts
  as an initialisation, so this does not become definite-initialisation
  analysis.
- clear the per-function curand state name and type, so a draw cannot reference
  the state registered by an earlier function of the same module.

`testing/python/language/test_tilelang_language_rand.py`
- 10 new cases: all five producer shapes without `rng_init`, plus the five
  positive controls.

**Explanation**

Issue `#3034` requires each RNG draw to have a preceding `rng_init()` in the same function. The CUDA pre-scan records only function-wide presence: `has_rng_consumer` and `has_rng_init` are independent booleans. Therefore, a draw that occurs before a later `rng_init()` is accepted. The new tests cover no-init and initialized variants, but they do not cover this ordering case. The implementation does provide a code-generation-time TileLang diagnostic for functions with no initialization, clears per-function state, and covers the listed producer variants.
