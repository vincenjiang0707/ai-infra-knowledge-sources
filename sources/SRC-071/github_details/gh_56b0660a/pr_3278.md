## 正文

## Summary

Fix a regression introduced by #3269 where explicit `T.async_copy` with a custom loop layout fails with `no eligible global->shared store was rewritten`. Simplifying indices before thread substitution leaves inverse-layout expressions too complex for the `cp.async` unit-stride check.

## Changes

- Restore index simplification after substitution in `PartitionLoop`. Teach `BufferIndiceSimplify` to refresh pure let bindings from the rewritten IR before simplifying their uses, preserving the fix for disabled let inlining without reintroducing logical loop variables.
- Add eight CUDA-gated lowering cases covering bfloat16/float32, vector widths 4/8, and both let-inlining settings. Check for a `cp.async` intrinsic, the expected vector width, and no unexpected free variables.

## Validation

- `cmake --build build -j 16`

- `TILELANG_DISABLE_CACHE=1 python -m pytest testing/python/language/test_tilelang_language_parallel.py testing/python/transform/test_tilelang_transform_lower_tile_op.py testing/python/transform/test_tilelang_transform_loop_vectorize.py -q --tb=short` — 121 passed, including CUDA runtime and CUDA/HIP lowering coverage.
