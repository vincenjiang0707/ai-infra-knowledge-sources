# [PR #3226] [BugFix]  Avoid stale analyzer bindings after parallel loop partitioning

## 正文

Fixes https://github.com/tile-ai/tilelang/issues/3225.

## Problem
Nested dynamic `T.serial` loops inside `T.Parallel` can fail during `LowerTileOp` with:
Trying to update var 'y' with a different maximum value:
original=bounds[p, 0] - 1, new=bounds[tx, 0] - 1
Partitioning rewrites loop bounds while retaining the inner loop variable’s identity. Vectorization then encounters bindings recorded before there write.
## Changes
- Clone the enclosing analyzer before visiting the parallel loop body.
- Keep partitioning and vectorization bindings separate.
- Make analyzer-taking vectorization APIs read-only, with planning performed on internal clones.
- Add regression coverage for dependent bounds, branches, sibling loops, and preserved vectorization.
