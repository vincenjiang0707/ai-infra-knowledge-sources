## 正文

Fixes #3024.

`T.clamp` now propagates a NaN in the input or either bound, including vector operands and FP8 values. Reversed bounds select the upper bound unless an operand is NaN.

The floating-point frontend emits a vectorizable `tl.clamp` intrinsic. CUDA uses scalar and packed device helpers, with half/bf16 pairs reusing `max2_nan`/`min2_nan` from the reduction templates. CPU uses scalar/vector C++ helpers, and other backends use shared lowering after vectorization. Each operand is evaluated once, including returning atomic operations.

Regression coverage includes NaN bounds, reversed bounds, mixed types, scalar bounds on explicit vectors, automatic vectorization, Python literals, and scalar/vector atomics.

Validation:

- Clamp language and target suites with the cache disabled: **47 passed, 2 skipped** (HIP and Metal codegen cases require their respective backends).
- Related CPU vector, CUDA bf16 math, and reduce NaN suites: **16 passed**.
- Codegen tests with CUDA devices hidden: **1 passed, 4 skipped**, confirming unsupported GPU cases are gated.
- Native build, `./format.sh`, and `git diff --check`: passed.

Runtime validation covered CUDA and CPU. Metal/CuTeDSL source generation and LLVM/HIP/Metal/WebGPU intrinsic lowering were also checked; those backends have no runtime validation from this environment.

Pushed 9697ef89 to use a dedicated `tl.clamp` intrinsic and device templates, following the NaN-aware reduction helpers.

The Python guard could evaluate an input expression more than once and prevented explicit vector operands from lowering correctly. The new path evaluates each operand once and preserves vectorization: half/bf16 pairs reuse `max2_nan`/`min2_nan`, while float32 keeps vector loads and stores. NaNs in either bound now propagate as well. CPU templates and shared lowering cover the other targets.

Added regression tests for NaN bounds, reversed bounds, type promotion, scalar/vector operands, and returning atomics. The clamp suites pass with **47 passed, 2 skipped**; the related CPU vector, bf16 math, and reduce NaN suites have **16 passed**. The native build and `./format.sh` also pass. Runtime validation was on CUDA and CPU; other backends were checked through source generation or intrinsic lowering.
