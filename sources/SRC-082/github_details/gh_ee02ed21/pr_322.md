# [PR #322] Move rotary_emb to target device for LlavaLlamaForCausalLM to avoid device mismatch

source: https://github.com/mit-han-lab/llm-awq/pull/322
state: closed | updated: 2026-05-29T10:26:43Z
labels: 

## 正文

Bug:
When performing AWQ search and quantization on `LlavaLlamaForCausalLM` models, a `RuntimeError: Expected all tensors to be on the same device, but found at least two devices, cpu and cuda:0!` is raised during the model execution/forward flow.

Root Cause:
In `awq/quantize/pre_quant.py`, the `move_embed` function handles moving embed weights and rotary embeddings for standard LLaMA and Qwen models, but for `LlavaLlamaForCausalLM` it only moves `model.model.embed_tokens` and vision tower embeddings, leaving the rotary embeddings `model.model.rotary_emb` on the CPU (leading to device mismatches during forward execution on GPU).

Why Fix is Correct:
By explicitly moving `model.model.rotary_emb` to the target `device` in the `LlavaLlamaForCausalLM` condition within `move_embed`, we guarantee that all relevant LLM/Llava model components reside on the same GPU device during the quantization process.
