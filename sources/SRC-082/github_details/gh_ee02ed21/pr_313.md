## Bug

In `scale_activations()`, the BigCode branch creates a `ScaledActivation` with `c = module.mlp.c_proj.out_features`. `c_proj` is the down-projection (inner_dim → hidden_size), but the activation sits between `c_fc` (up-projection) and `c_proj`, so its dimension should be `c_fc.out_features` (= inner_dim).

Every other architecture correctly uses the up-projection's `out_features`:
- Bloom: `dense_h_to_4h.out_features`
- MPT: `up_proj.out_features`
- Falcon: `dense_h_to_4h.out_features`
- NeoX: `dense_h_to_4h.out_features`

## Root cause

`c_proj` was used instead of `c_fc` — likely a typo since both are attributes of `module.mlp`.

## Fix

`c_proj.out_features` → `c_fc.out_features`
