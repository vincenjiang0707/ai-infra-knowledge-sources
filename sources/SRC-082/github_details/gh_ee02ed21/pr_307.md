## 正文

## Summary
- Fixes a `RuntimeError` when running AWQ quantization on Llama3 models with transformers >= 4.56
- The `Catcher` class captures `position_ids` during calibration, but the captured shape may not match the input sequence length in subsequent layer forward passes
- Regenerates `position_ids` from the actual input sequence length (`torch.arange(seq_len).unsqueeze(0)`) before each layer call to ensure consistent shapes

## Root Cause
In newer transformers versions, `apply_rotary_pos_emb` expects `position_ids` (and derived `cos`/`sin` tensors) to have the same sequence dimension as the query/key states. The `position_ids` captured once by the `Catcher` at layer 0 can have a mismatched shape when reused across layers, causing:
```
RuntimeError: The size of tensor a (32) must match the size of tensor b (128) at non-singleton dimension 3
```

- [ ] Test with older transformers versions to confirm backward compatibility

I'm using `transformers==5.3.0` version, where Llama (1, 2 & 3) model expects `position_embeddings` in the `forward` function call of `LlamaAttention`. 

A short code snippet from `forward` function call of `LlamaAttention`, that is causing this error,

```
    def forward(
        self,
        hidden_states: torch.Tensor,
        position_embeddings: tuple[torch.Tensor, torch.Tensor] | None = None,
        attention_mask: torch.Tensor | None = None,
        past_key_values: Cache | None = None,
        cache_position: torch.LongTensor | None = None,
        **kwargs: Unpack[TransformersKwargs],
    ) -> tuple[torch.Tensor, torch.Tensor]:
        input_shape = hidden_states.shape[:-1]
        hidden_shape = (*input_shape, -1, self.head_dim)

        query_states = self.q_proj(hidden_states).view(hidden_shape).transpose(1, 2)
        key_states = self.k_proj(hidden_states).view(hidden_shape).transpose(1, 2)
        value_states = self.v_proj(hidden_states).view(hidden_shape).transpose(1, 2)

        cos, sin = position_embeddings  # <== position_embeddings are NEEDED
        query_states, key_states = apply_rotary_pos_emb(query_states, key_states, cos, sin)
```

I feel, the code fix for this error should ensure `position_embeddings` rather than `position_ids`.

### Chessing234 · 2026-04-14

Thanks for testing, @kalyan-nakka. You're right — on transformers ≥5.x `LlamaAttention.forward` takes `position_embeddings=(cos, sin)` directly, so passing `position_ids` alone no longer plumbs the rotary embedding through. The correct fix there is to compute `cos, sin = model.model.rotary_emb(hidden_states, position_ids)` and forward them as `position_embeddings` (guarded by a `hasattr` check for backward compat with older transformers). I'll push that update shortly; marking this PR as needing revision.
