## 正文

## Bug

`awq/quantize/smooth.py::smooth_ln_fcs` unconditionally scales `ln.bias`:

```python
    ln.weight.div_(scales)
    ln.bias.div_(scales)
```

`nn.LayerNorm` accepts `bias=False` (PyTorch 2.1+), in which case the module has no `bias` parameter and `ln.bias is None`. Calling `.div_()` on `None` raises `AttributeError: 'NoneType' object has no attribute 'div_'`, killing smoothing for any model that uses bias-free LayerNorm (certain VLM and efficient-LLM variants).

## Root cause

The sibling rescaler `auto_scale.scale_ln_fcs`, which mirrors the same smoothing identity, already guards this case:

```python
ln.weight.div_(scales)
if hasattr(ln, "bias") and ln.bias is not None:
    ln.bias.div_(scales)
```

`smooth.py` just wasn't updated when the guard was added to `auto_scale.py`.

## Why the fix is correct

Adopt the exact same guard here:

```diff
     ln.weight.div_(scales)
-    ln.bias.div_(scales)
+    if hasattr(ln, "bias") and ln.bias is not None:
+        ln.bias.div_(scales)
```

- Models with a real `ln.bias` (the common case): guard evaluates `True`, behaviour unchanged — `ln.bias.div_(scales)` still runs.
- Models with `ln.bias=None` (LayerNorm(bias=False)): guard evaluates `False`, skipping the crash. This matches the smoothing identity, which has no bias term to rescale when the norm has no bias.
- The `hasattr` branch of the predicate is what `auto_scale.py` uses; keeping the same shape makes the two call sites easy to keep in sync in future.

Two added lines, one removed — net +1. No other changes to `smooth_ln_fcs` or the file.
