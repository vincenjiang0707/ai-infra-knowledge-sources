## 正文

## Bug

In `scale_activations` (`awq/quantize/quantizer.py`), the BigCode branch initializes the `ScaledActivation` scale vector using `module.mlp.c_proj.out_features`:

```python
elif "bigcode" in str(module.__class__).lower():
    ...
    c = module.mlp.c_proj.out_features   # wrong
    act = ScaledActivation(
        module.mlp.act, torch.ones(c, dtype=dtype, device=device)
    )
```

## Root cause

`module.mlp.act` (the GeLU activation) sits **between** `c_fc` and `c_proj` in the BigCode MLP stack:

```
x → c_fc (hidden → 4h) → act → c_proj (4h → hidden) → output
```

The `ScaledActivation` scale must match the output dimension of the layer that feeds *into* the activation, which is `c_fc.out_features` (the intermediate/4h size). Using `c_proj.out_features` (the smaller hidden dimension) creates a scale vector of the wrong size.

Every other architecture in the same function uses the first linear layer's output dimension:

| Architecture | Code |
|---|---|
| Bloom | `dense_h_to_4h.out_features` |
| Falcon | `dense_h_to_4h.out_features` |
| NeoX | `dense_h_to_4h.out_features` |
| MPT | `ffn.up_proj.out_features` |
| **BigCode** | `c_proj.out_features` ← **wrong** |

## Fix

Change `c_proj.out_features` to `c_fc.out_features`, matching the pattern used by all other architectures.
