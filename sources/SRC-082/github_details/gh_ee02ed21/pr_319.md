## 正文

## Bug

`awq/entry.py` crashes with `KeyError: 'config'` when run with
`--tasks wikitext --output_path <file>`.

## Root cause

The wikitext branch builds `results = {\"ppl\": ppl.item()}` and writes it
inside a nested `if args.output_path is not None:` block. After the
if/else for task type finishes, a second `if args.output_path is not
None:` block runs unconditionally and does:

```python
results[\"config\"][\"model\"] = args.model_path
with open(args.output_path, \"w\") as f:
    json.dump(results, f, indent=2)
```

But the wikitext `results` dict has no `\"config\"` key — only lm-eval's
`simple_evaluate()` return value has that structure. So the wikitext
path always hits `KeyError: 'config'` before it can write its output
file again, and any earlier correct write from lines 330-333 is
followed immediately by a crash.

## Why the fix is correct

Indenting the second output-path block into the `else` branch
limits the `results[\"config\"][\"model\"] = ...` statement to the path
where `results` actually has a `config` dict (from
`lm_eval.evaluator.simple_evaluate`). The wikitext branch keeps its
existing correct `json.dump(results, ...)` block. No behavioural
change for the non-wikitext path.

## Change

`awq/entry.py`: indent the trailing `if args.output_path is not None:`
block inside the lm-eval `else` arm. One-block (6 lines) indentation
change, no logic changes.
