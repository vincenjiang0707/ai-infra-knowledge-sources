# [PR #314] Fix scale_fc_fc dividing full bias when only last N rows of weight are scaled

state: closed | updated: 2026-05-04T23:43:08Z

## 正文

## Bug

In \`awq/quantize/auto_scale.py\`, \`scale_fc_fc\` scales only the last \`scales.size(0)\` rows of \`fc1.weight\` but divides the **entire** bias vector:

\`\`\`python
```python
fc1.weight[-scales.size(0) :].div_(scales.view(-1, 1))
if fc1.bias is not None:
    fc1.bias.div_(scales.view(-1))
```
\`\`\`

## Root cause

The \`[-scales.size(0):]\` slice on the weight is deliberate: for fused projections where \`fc1.out_features > scales.size(0)\` and only the trailing slice of \`fc1\`'s output actually feeds into \`fc2\`, the smoothing transform should touch only those rows. The canonical case is BLOOM's \`self_attention.query_key_value\`, a fused \`[q | k | v]\` projection where the caller (\`_auto_get_scale(prev_op=module.self_attention.query_key_value, layers=[module.self_attention.dense], ...)\`) supplies scales sized to the v slice so that v→dense is smoothed.

The bias, however, is divided across all \`3*H\` components. For BLOOM (which has \`bias=True\` on the fused qkv), this scales the q and k bias entries by a factor that was only meant to compensate v's weight change; downstream q/k outputs get corrupted.

## Fix

Apply the same trailing slice to the bias:

\`\`\`python
fc1.bias[-scales.size(0) :].div_(scales.view(-1))
\`\`\`

## Why this is safe

When \`scales.size(0) == fc1.out_features\` (no-fused-projection case), \`fc1.bias[-scales.size(0):]\` covers the entire bias, so the fix matches the existing behavior. The only changed path is the partial-slice case, which previously mis-scaled bias entries that do not feed \`fc2\`.
