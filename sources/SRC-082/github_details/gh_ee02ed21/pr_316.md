## 正文

## Bug

`move_embed()` in `awq/quantize/pre_quant.py` calls `isinstance(model, LlavaLlamaForCausalLM)` at line 69. Since #294 made `from tinychat.models import LlavaLlamaForCausalLM` optional:

```python
try:
    from tinychat.models import LlavaLlamaForCausalLM
except ImportError as e:
    pass
```

When `tinychat` is not installed, the symbol is never bound. Any model that doesn't match the earlier `LlamaForCausalLM`/`Qwen2ForCausalLM`/`InternVL3` branches (i.e., `OPT`, `BLOOM`, `MPT`, `Falcon`, `BigCode`, `GPT-NeoX`, `LlavaLlamaModel`) falls through to line 69 and raises `NameError: name 'LlavaLlamaForCausalLM' is not defined` — breaking `run_awq` for every AWQ-supported non-Llama model on a tinychat-less install.

## Root cause

#294 deliberately made the tinychat import optional but missed this one `isinstance` call. `get_blocks()` already uses string-based matching for the same class (line 35: `model.__class__.__name__ == \"LlavaLlamaForCausalLM\"`), as does the `InternVL3` branch in the same function (line 61) and the `LlavaLlamaModel` branch (line 95).

## Fix

Switch line 69 to the same `__class__.__name__` comparison. This preserves the original behavior when `tinychat` is installed (a `LlavaLlamaForCausalLM` instance still matches by class name) and no longer references the unbound symbol when it isn't.
