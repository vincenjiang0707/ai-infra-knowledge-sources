## 正文

### Bug
`pseudo_quantize_tensor` raises `NameError` in the `zero_point=False` branch because the first line asserts on a name that is never bound in that branch:

https://github.com/mit-han-lab/llm-awq/blob/d6e797a/awq/quantize/quantizer.py#L69-L83

```python
if zero_point:
    max_val = w.amax(dim=1, keepdim=True)
    min_val = w.amin(dim=1, keepdim=True)
    ...
else:  # we actually never used this
    assert min_val is None
    max_val = w.abs().amax(dim=1, keepdim=True)
    ...
```

`min_val` is only bound inside the `zero_point=True` branch, so in the `else` branch Python raises `NameError: name 'min_val' is not defined` before the assert can even be evaluated. Any caller that reaches this path (e.g. passing a `q_config` with `zero_point=False` through `auto_clip_layer` / `_search_module_scale`) crashes instead of taking the symmetric-quantization path that follows.

### Root cause
An orphaned sanity-check assert left over from an earlier version of the function where `min_val` was in scope. It now references an undefined name.

### Fix
Drop the assert. The rest of the `else` branch already recomputes `max_val`/`scales` from scratch and does not rely on `min_val`, so removing the line restores the intended symmetric-quantization path without changing behaviour for the `zero_point=True` case.
