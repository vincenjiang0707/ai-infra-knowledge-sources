## 正文

## Summary

Automatically decode OCP MXFP4 (E2M1) and MXFP8 (E4M3/E5M2) checkpoint weights with block-32 E8M0 scales into dense weights when a native MX forward kernel is unavailable. Quark is a quantization pipeline that can produce these layouts; the supported formats are OCP MX formats, including compatible checkpoints from other pipelines.

## What changed

- Detect MX layouts from checkpoint dtype, scale tensors, and format metadata, including metadata produced by Quark and compressed-tensors.
- Decode E8M0 scales and MXFP4/MXFP8 weights, including mixed-format weights, 3D experts, cross-shard scales, and sibling `.scale` tensors.
- Keep plain FP8 direct-scale and checkpoint-dependent NVFP8 handling, and preserve NVFP4 E4M3 block-16 plus global-scale handling.
- Use a dense BF16 module fallback where a matching native forward kernel is unavailable. Native mixed FP4 × FP8 GEMM execution is outside this PR.
- Clip padded E8M0 and secondary scale grids to the logical weight shape before expansion. Perform dequantization in FP32 and cast to BF16 once, avoiding premature scale rounding.

## Numerical validation

- Independent oracles cover all 256 E8M0 encodings exactly, all 16 E2M1 FP4 codes, and all 256 FP8 bit patterns for both E4M3 and E5M2. The FP8 and E8M0 exact-code tests have zero observed error. The FP4 and non-power-of-two global-scale FP8 tests use a separate FP64 Torch oracle cast to FP32, with both `rtol` and `atol` at `1e-6`.
- Shapes include FP8 `4×64` for exhaustive codes, MXFP4/MXFP8 `2×64` across two scale blocks, and packed expert weights `2×2×16` (logical `2×2×32`). Tests cover padded block grids, scalar and per-block secondary scales, and an E8M0 NaN block. BF16 module weights match the independent oracle exactly after one final cast.
- The BF16 decoder forward test runs on GPU 0 (NVIDIA PG506-230), comparing `1×64` inputs against Torch linear with `rtol=atol=2e-3`.
- No performance claim is made, so no benchmark was run.
