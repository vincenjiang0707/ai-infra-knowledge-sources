## 正文

## Summary

- store native MLX RTN pseudo-quantized weights directly as FP16/BF16 instead of writing an FP32 matrix and launching a second full-matrix cast
- retain the existing FP32 output path for FP32 and fallback inputs
- specialize the cached Metal source only for the three output storage types
- keep this PR limited to the RTN quantization method

## Accuracy

The independent Torch-oracle suite passes all 306 cases. It covers:

- every supported bit width (2–8)
- rowwise and group sizes 16–1024
- symmetric and asymmetric quantization
- FP16, BF16, and FP32 inputs
- zero rows, signed zero, rounding boundaries, zero-point ties, and saturation endpoints
- all nine Qwen3.8-27B projection shapes in FP16 and BF16

The Qwen benchmark also compares this PR directly with current `main`. All 18 projection/dtype cases have exactly zero code mismatches and zero output/scale/zero-point drift.
