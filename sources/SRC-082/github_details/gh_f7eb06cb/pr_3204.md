## 正文

## Summary

Store ParoQuant pseudo-quantized weights directly in their FP16/BF16 target dtype inside the Metal kernel. This removes the full-size FP32 output allocation and follow-up cast without changing the public API or quantization arithmetic.

This PR is limited to the ParoQuant transformed-weight pseudo-quantizer.

## What Changed

- specialize the cached ParoQuant Metal kernel for FP32, FP16, and BF16 output storage
- explicitly cast each dequantized value at the kernel store
- retain FP32 arithmetic for scale, zero point, rounding, and dequantization
- assert that non-contiguous low-precision inputs preserve their visible output dtype
- add a reproducible current-main A/B benchmark over every Qwen3.8-27B projection

## Accuracy

The independent Torch oracle passes all 66 tests, covering:

- bits 2–8
- symmetric and asymmetric quantization
- exact rounding thresholds and one-representable-step neighbors
- clamp/saturation endpoints, positive/negative zero, and zero-point ties
- FP32, FP16, and BF16 inputs
- non-contiguous weights and learned parameter layouts
- all nine Qwen3.8-27B projections in FP16 and BF16

The benchmark compared the PR directly with current `main`. Across all 36 projection/dtype/symmetry cases:

- recovered code mismatches: **0**
- visible output mismatches: **0**
- maximum output drift: **0**
