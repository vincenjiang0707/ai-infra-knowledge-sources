## Summary

Add a native MLX Metal kernel for EXL3 trellis packing on Apple silicon.

This PR is intentionally limited to one EXL3 quantization-finalization stage: converting the quantizer's 256-state int16 tiles into EXL3's checkpoint trellis words. It does not add EXL3 codebook search, Hessian processing, or optimizer integration.

## What Changed

- Added `exl3_pack_trellis_mlx` for EXL3 bit widths 1–8.
- Preserved EXL3's exact logical big-endian bitstream and adjacent uint16 swap used by its checkpoint layout.
- Added strict shape, dtype, nonempty-tile, and bit-width validation.
- Added an independent Torch arithmetic oracle that does not call or reuse the MLX kernel.
- Added exact boundary coverage for signed int16 state limits, low-bit mask endpoints, and values immediately across the mask boundary for every supported bit width.
- Added save/load and bits 1–8 roundtrips through the existing `ExllamaV3TorchLinear` decoder.
- Added exact complete-output checks and benchmarks for every Qwen3.8-27B projection shape.
- Follow-up intentionally out of scope: native MLX EXL3 Viterbi/codebook search and Hessian-driven optimization.

## Accuracy and Performance

Measured on Apple M5 Ultra, 256 GB, MLX 0.32.2, Torch 2.14.0. Qwen checks use EXL3's default 3-bit trellis layout. Inputs are already resident; timings are medians of three measured calls after one warmup.

Main's production `pack_trellis` implementation is CUDA-only and cannot execute on Apple silicon. Therefore the comparison below is against an independent exact Torch implementation of the same main-format bit-packing algorithm, not against CUDA timing. Packed int16 words are discrete format data and must match exactly.
