## Summary

- Add explicit `legacy`, `fused`, `dense`, and `auto` execution modes for ExLlamaV2 GPTQ.
- Preserve `force_cuda=True` as the highest-priority forced-fused path.
- Add a measured static selector for the validated RTX 4090 setup; unknown devices, shapes, layouts, and unsupported metadata fall back to the legacy `M > 50` rule.
- Keep the selector based on flattened M, K/N, GPU identity/SM scale, effective group size, actual `desc_act`, symmetry, and quantization layout.
- Fix GPTQ fused/reconstruct/cuBLAS stream ordering without changing AWQ scheduling or shared public declarations.
- Add simple comments around path selection, metadata matching, stream ordering, and the legacy ABI fallback.
- Add selector tests and a repeatable full-forward A/B benchmark.

## Measured dispatch rules

Validated on 4x NVIDIA GeForce RTX 4090, compute capability 8.9, 128 SM/device, driver 615.71.09, Torch 2.14.0+cu130. Rules cover 4-bit GPTQ with effective group sizes 32/64/128/full-K, both `desc_act` states, symmetric qzero layout, and the measured K/N families.

Only measured singleton M buckets are overridden; unmeasured shapes and boundaries retain legacy dispatch:

- `K=2048, N=512`: M=51,52,64,96,128,256 use fused.
- `K=2048, N=8192`: M=40,48,49,50 use dense.
- `K=8192, N=2048`: M=49,50 use dense.
- `K=4096, N=4096`: M=48,49,50 use dense.
- `K=2048, N=2048`: legacy fallback because the crossover was noisy/tied.

Dense mode reconstructs FP16 weights for every forward before cuBLAS GEMM; no permanent dense weights are cached.

## Optimization effect

The benchmark uses the same random packed weights and inputs for each mode. JIT compilation and q_handle creation happen before timing. Each timed sample includes the complete forward: input conversion, output allocation, selected kernel/reconstruction + GEMM, bias, and adapter hooks. Final verification used 4 GPUs, 640 cases, 10 timed repeats, and 5 warmups per mode.

Representative medians are averaged across the four GPUs, group sizes, and both `desc_act` states:

| Shape / M | Forced fused | Forced dense | Legacy | Auto | Auto path |
|---|---:|---:|---:|---:|---|
| 2048 -> 512 / 51 | 0.0460 ms | 0.0539 ms | 0.0537 ms | 0.0486 ms | fused |
| 2048 -> 512 / 256 | 0.0496 ms | 0.0540 ms | 0.0540 ms | 0.0527 ms | fused |
| 2048 -> 8192 / 40 | 0.0709 ms | 0.0656 ms | 0.0706 ms | 0.0702 ms | dense |
| 4096 -> 4096 / 48 | 0.0752 ms | 0.0631 ms | 0.0752 ms | 0.0709 ms | dense |
| 8192 -> 2048 / 49 | 0.0794 ms | 0.0736 ms | 0.0789 ms | 0.0792 ms | dense |

Across the 120 measured rows where auto selected a path different from legacy, auto had a 9.6% median and 8.5% mean latency reduction versus legacy; 107/120 rows improved. The result is shape- and layout-dependent, with some neutral or slightly slower individual rows, so the table remains conservative and all unmatched cases use legacy. There is no persistent dense-weight allocation; runtime memory remains owned by the existing scratch/output path.

## Scope limits

This PR only changes GPTQ_EXLLAMA_V2 dispatch. It does not add widths/devices/training support, alter dequantization or accumulation precision, cache dense weights, or change AWQ defaults.
