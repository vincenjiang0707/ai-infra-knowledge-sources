## Summary

- store MLX BitsAndBytes NF4/FP4 kernel results directly in the input activation dtype
- retain FP32 accumulation and preserve the existing decode/prefill thread dispatch
- avoid the separate FP32 output allocation and trailing FP16/BF16 cast
- keep BitsAndBytes INT8 unchanged after profiling showed no reliable FP16 benefit
- add exact current-main parity assertions and replace the stale dtype benchmark with a reproducible packed-kernel comparison

Sub-millisecond per-case timings are noisy; aggregate medians are the decision metric. A fallback INT8 direct-store prototype measured 0.993x median for FP16 decode, so INT8 remains on main's FP32-output path and is not part of this change.

Reproduce with:

```bash
PYTHONPATH=. python tests/benchmark_mlx_qwen38_bnb_output_dtype.py --samples 301
```
