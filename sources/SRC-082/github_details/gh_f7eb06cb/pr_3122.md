## Summary

Add the next native MLX GGUF packing kernel: `Q8_0`. It builds on the merged [Q4_0 kernel PR](https://github.com/ModelCloud/GPTQModel/pull/3121). Its diff against `main` contains only the `Q8_0` kernel and tests.

## What Changed

- Add a Metal `Q8_0` packer for 32-value, 34-byte GGUF blocks, including fp16 scale bytes and signed int8 codes.
- Extend `gguf_quantize_weight_mlx` to dispatch `Q8_0` while retaining `Q4_0`.
- Add independent Torch-oracle A/B tests for random weights, zero blocks, half-integer and neighboring-ULP rounding cases, float16/bfloat16 inputs, and 32/256/512 widths.
- Verify the packed bytes match the existing GGUF checkpoint layout and can be decoded by the current runtime.

## Accuracy and performance

On Apple M5 Ultra, packed bytes match the independent Torch oracle exactly. The merged Q4_0 parent includes the review fixes for half-bin rounding and signed-zero scale bytes. A separate 512×512 comparison against the current GGUF packer found **0 differing bytes in 278,528 bytes**.

For a 4096×4096 float32 weight matrix (524,288 GGUF blocks), inputs resident on their respective backends, 3 warmups, and median of 10 synchronized runs:

| Path | Median pack time |
| --- | ---: |
| Current main NumPy CPU GGUF `Q8_0` packer | 18.38 ms |
| Proposed MLX Metal `Q8_0` packer | 0.295 ms |

This is a **62.3× operation-level speedup** under the stated residency condition; host-to-device transfer and full-model quantization are not included.
