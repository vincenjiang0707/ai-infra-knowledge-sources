## Summary

Add a native MLX Metal packer for GGUF `Q1_0` and its `Q1_0_g128` alias. This is the next format in the [native MLX quantization plan](https://github.com/ModelCloud/GPTQModel/blob/main/docs/mlx-native-quantization-plan.md).

## What Changed

- Pack each 128-value block into the existing 18-byte layout: fp16 mean-absolute scale followed by 16 little-endian sign bytes.
- Accept 2D float16, bfloat16, and float32 weights with a nonzero input width divisible by 128; reject unsupported dtypes and shapes.
- Preserve the existing NumPy packer's eight-lane float32 scale reduction order. A naive sequential Metal sum differed at fp16 scale midpoints on 6,358 of 30,000 stress blocks.
- Add independent Torch-oracle tests for both names, random and zero blocks, signed zero, sign thresholds, fp16 midpoint and range boundaries, low-precision inputs, transposed weights, and decoding through the existing GGUF runtime.

## Accuracy and performance

On Apple M5 Ultra, all tested packed bytes match the Torch oracle exactly. A 30,000-block scale-midpoint stress comparison found **0 differing scale bytes** against the current NumPy packer after the reduction-order fix. On a separate 4096×4096 float32 matrix, the complete packed output matched the current packer in **all 2,359,296 bytes**.

For that 4096×4096 matrix (131,072 blocks), inputs already resident on their respective backends, 3 warmups, and the median of 10 synchronized runs:

| Path | Median pack time |
| --- | ---: |
| Current `main` NumPy CPU `Q1_0` packer | 7.48 ms |
| Proposed MLX Metal `Q1_0` packer | 1.015 ms |

That is a **7.37× operation-level speedup** under the stated residency condition. Host-to-device transfer and full-model quantization are outside this measurement.
