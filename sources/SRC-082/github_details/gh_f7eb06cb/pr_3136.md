## Scope
QQQ only. Whole-row QQQ (`group_size=-1`) now transfers its signed nibbles exactly into MLX native 4-bit affine weights. Group-128 QQQ keeps the existing exact 8-bit representation because its per-group rounding cannot be represented faithfully by affine 4-bit scales. A QQQ Metal kernel computes each token's activation maximum, FP16 scale, and quantized codes in one dispatch. Zero and empty token rows are handled.

## Accuracy
- Independent Torch oracle checks exact activation scales/codes for FP16 and BF16 inputs at widths 128, 5120, and 17408, including zero rows and signed extremes.
- Random packed QQQ checkpoints verify exact transferred codes for both supported group sizes (`-1`, `128`) and inference outputs within `rtol=atol=2e-3`.
- All nine pinned Qwen3.8-27B projection shapes verify the native 4-bit and 8-bit QQQ matmul against separate Torch arithmetic at `rtol=atol=2e-3`. The paired performance fixture observed max absolute output difference 0 with its deterministic pattern.
- Focused QQQ/method-selection run: **44 passed**. Full MLX run: **636 passed, 1 failed**; the failure is the existing `test_mlx_generate` fixture pointing to an unavailable local `/monster/data/model/...` path. Ruff and `git diff --check` pass.

Whole-row codes are signed 4-bit nibbles scaled by 16; grouped codes are nibble values multiplied by integer group scales from 1 to 16, rounded and clamped to INT8. Input activations are normal with standard deviation 0.05; channel scales are uniform from 0.001 to 0.005. The 16-row case includes one zero row. ## Performance versus merged `main`
Apple M5 Ultra, MLX 0.32.2, FP16 inputs, all nine Qwen3.8-27B projection shapes. `tests/benchmark_mlx_qwen38_qqq_optimization.py --repeats 21` alternates main and optimized calls, warms both paths, synchronizes each with `mx.eval`, and reports the median elapsed time per projection. Geometric mean speedups across the nine projections:

| QQQ group | Rows | Speedup | Mean main → new latency |
| --- | ---: | ---: | ---: |
| -1 | 1 | 1.115× | 0.331 → 0.294 ms |
| -1 | 16 | 1.073× | 0.455 → 0.424 ms |
| 128 | 1 | 1.049× | 0.334 → 0.320 ms |
| 128 | 16 | 1.034× | 0.440 → 0.430 ms |

Whole-row packed weight storage is halved (8 to 4 bits). Individual shapes vary: whole-row `full_attn.q_proj`, one row, improves 0.349 → 0.299 ms; `full_attn.o_proj`, 16 rows, measures 0.346 → 0.383 ms. The benchmark compares the exact merged-main QQQ MLX operations with the changed operations on the same decoded weights and inputs.

## Independent verification on the current PR head

On M5 Ultra, targeted QQQ tests passed (28 cases). A separate FP16 threshold-neighbor sweep compared 765 activation rows against Torch with zero scale or code mismatches. Random QQQ-compatible packed weights on all nine pinned Qwen projections matched Torch outputs exactly for both 4-bit whole-row and 8-bit group-128 QQQ; per-shape measurements are above.

The benchmark script completed all nine Qwen3.8-27B projections for both QQQ groups and token batches of 1 and 16 (36 cases; three paired repeats). The measured geometric mean speedups versus the merged-main operations were 1.198×, 1.098×, 1.070×, and 1.043× respectively; every deterministic benchmark output matched. One notable regression is MLP down with 16 tokens and whole-row QQQ: 0.830 → 1.069 ms (0.78×), alongside 50% smaller packed weights. The longer 21-repeat results above remain the primary timing report.
