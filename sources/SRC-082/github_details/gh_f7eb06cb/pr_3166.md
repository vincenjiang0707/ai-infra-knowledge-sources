## 正文

## Summary

Add native MLX orchestration for EXL3 global-scale search. The new API combines the merged wrapped-diagonal sampler and native Viterbi quantizer with EXL3's fixed golden-section search and float32 MSE calculation.

This PR is limited to the global-scale-search stage. Processor integration, regularization changes, Viterbi changes, and LDLQ remain out of scope.

## What Changed

- Added `exl3_global_scale_search_mlx(...)` with EXL3's `[0.1, 1.9]` interval and `0.01` stopping tolerance.
- Preserved float32 MSE/final-average semantics and Python-double interval arithmetic from the Torch path.
- Added an independent Torch oracle that performs its own Viterbi search and golden-section control flow.
- Added bits 2/4/8, all-codebook, rounding-boundary, validation, and all nine Qwen3.8-27B projection tests.
- Updated the reproducible Qwen benchmark to report exact selected-scale, absolute-MSE, and relative-MSE drift.

EXL3 quantization is canonically float32, so checkpoint bfloat16 is not applicable to this stage.

## Accuracy

Environment: Apple M5 Ultra (256 GB), MLX 0.32.2, Torch 2.14.0. Tests use full Qwen matrix dimensions with a deterministic four-tile pattern bank. The independent Torch oracle quantizes each unique tile itself, expands the results back over every sampled tile, and computes MSE over the complete sampled output.

## Performance

Inputs were resident. MLX timings are median of 3 measured full searches after 1 warmup.

The corresponding `main` implementation calls an EXL3 CUDA extension and cannot execute on Apple silicon. The Torch column is therefore clearly an estimate: measured `main` Torch sampling time plus median-of-3 independent CPU-oracle search time for one tile multiplied by the sampled-tile count. It is not a measured CUDA comparison.
