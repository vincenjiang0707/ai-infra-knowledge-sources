## 正文

## Summary

- add `MlxFP8PackedLinear`, a packed Metal inference runtime that consumes the checkpoint's original FP8 bytes without expanding them to dense FP16 weights
- support every GPTQModel FP8 storage format: E4M3FN, E5M2, E4M3FNUZ, E5M2FNUZ, and E8M0FNU
- support tensor, row, and block inverse-scale layouts
- keep MLX's official MXFP8 `nn.QuantizedLinear` path for compatible E4M3FN tensor/row checkpoints
- use a vectorized packed GEMV kernel for decode and a simdgroup-matrix path for eligible prefill shapes
- preserve FP16/BF16 activation and output dtypes; scales and accumulation remain FP32
- retain `FP8MlxQuantLinear` as the BaseQuantLinear holder/validator and auto-select this runtime through the existing MLX backend
- reduce fallback weight storage from 2 bytes/weight to 1 byte/weight (50%)

This is intentionally one quantization-method PR: FP8 only.

## Correctness fix

Current main dequantizes unsupported FP8 layouts to FP16 before MLX inference. For realistic E5M2 row inverse scales above FP16 max (65,504), that cast becomes infinity and the dense weight becomes zero. The packed path retains scales in FP32 and avoids that failure.

The benchmark below uses E5M2 row scales in the 600,000–609,999 range to exercise that real failure mode. Main therefore has relative L2 error 1.0; packed inference remains close to a float64 decode/matmul oracle.

| Output dtype | Packed max abs error | Packed max relative L2 | Main max relative L2 |
|---|---:|---:|---:|
| FP16 | 1.53e-5 | 2.10e-4 | 1.0 |
| BF16 | 1.22e-4 | 1.71e-3 | 1.0 |

FP16 prefill is an explicit tradeoff on the widest projections; the packed runtime provides correct E5M2 inference and halves weight memory where main's dense fallback is invalid. BF16 is faster on every tested projection and batch shape.

Weight memory is exactly halved for every projection (for example, each MLP projection is 170 MiB on main versus 85 MiB packed).
