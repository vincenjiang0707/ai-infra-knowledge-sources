## Summary

Replace the fused EXL3 regularization kernel's dense 128-term Hadamard evaluation with the repository's seven-stage in-threadgroup butterfly transform.

The public API and output shapes/dtypes are unchanged. The change reduces each 128-point vector from 16,384 coefficient FMAs to 896 butterfly additions/subtractions while keeping channel scaling and the transform in one Metal dispatch.

## What Changed

- Reuse two 128-float threadgroup buffers for the normalized Hadamard butterfly.
- Retain the existing input/output channel scaling, zero-channel behavior, and scale outputs.
- Add FP64 adjudication for values where butterfly and Torch dense-matmul reduction order differ.
- Add a targeted cancellation regression and a current-main Qwen3.8-27B benchmark.
- No follow-up work or unrelated quantization methods are included.

## Accuracy

The complete Qwen benchmark compares every output to an independent Torch dense-Hadamard oracle. Output-axis cases stay directly within `rtol=atol=1e-6`. Input-axis reduction order produces 3,468 values outside that direct comparison across 796,917,760 outputs (0.000435%), with maximum absolute Torch drift `4.29153442e-6`; maximum normalized drift is `2.17446825e-7`, and maximum scale drift is exactly `0`.

Those outliers are not accepted by a blanket tolerance. The tests recompute each outlier from the stored float32 scaled inputs using an independent float64 Hadamard row/column and require the butterfly result to be within `rtol=atol=1e-6` and no farther from FP64 than Torch. All outliers pass. On the full Qwen K input projection, maximum butterfly error versus FP64 is `8.53971528e-7` with normalized error `8.25177574e-8`, versus Torch's `3.45479022e-6` and `2.05758038e-7`.
