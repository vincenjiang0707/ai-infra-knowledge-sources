## Summary

Add a native MLX Metal packer for GGUF `Q6_K`.

## What Changed

- Pack each 256-value block into the existing 210-byte Q6_K layout: 128 low-nibble bytes, 64 high-bit bytes, 16 signed scale bytes, and a 2-byte fp16 base scale.
- Match the existing float32 subblock scale, round-to-even signed-code, and saturation behavior.
- Accept 2D float16, bfloat16, and float32 MLX weights with nonzero width divisible by 256. Reject unsupported shapes and dtypes.

The independent Torch oracle compares complete packed bytes exactly across multiple shapes, zero blocks, float16/bfloat16 inputs, signed-code thresholds and one adjacent float32 step on either side, all scale-code midpoint values and adjacent steps, saturation, and fp16 scale limits. The existing Q6_K runtime decoder accepts the bytes. Two separate 30,000-block stress comparisons against the current CPU fallback found **0 mismatching bytes of 6,300,000** each: one targeted signed-code thresholds; the other targeted scale-code thresholds. No numerical mismatch is known.

## Performance vs main

All 13,762,560 output bytes matched exactly. This measures the packing operation; host/device transfer and full-model quantization are outside the timed region.
