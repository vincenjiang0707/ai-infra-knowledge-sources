## Summary

Optimize MLX GGUF Q4_0 packing by accepting contiguous FP16, BF16, and FP32 weights directly in the Metal kernel instead of materializing a full FP32 copy first.

The kernel still converts each loaded value to FP32 before signed-maximum selection, scale calculation, rounding, and packing. This preserves the existing Q4_0 byte layout and numerical behavior while reducing memory traffic and peak temporary storage.

This PR is intentionally limited to GGUF Q4_0.

## Performance versus main

Measured on Apple M5 Ultra, MLX 0.32.2, with 10 warmups and 301 alternating samples per implementation. Times are median milliseconds; higher speedup is better.

| Projection | Input dtype | Main | PR | Speedup | Byte error |
|---|---:|---:|---:|---:|---:|
| full_attn.q_proj | FP16 | 0.8337 ms | 0.3742 ms | 2.228x | 0 |
| full_attn.q_proj | BF16 | 0.8310 ms | 0.3756 ms | 2.212x | 0 |
| full_attn.k_proj | FP16 | 0.2535 ms | 0.2410 ms | 1.052x | 0 |
| full_attn.k_proj | BF16 | 0.2527 ms | 0.2402 ms | 1.052x | 0 |
| full_attn.v_proj | FP16 | 0.2533 ms | 0.2410 ms | 1.051x | 0 |
| full_attn.v_proj | BF16 | 0.2382 ms | 0.2392 ms | 0.996x | 0 |
| full_attn.o_proj | FP16 | 0.4902 ms | 0.2594 ms | 1.890x | 0 |
| full_attn.o_proj | BF16 | 0.4911 ms | 0.2627 ms | 1.869x | 0 |

Median speedup is **2.171x** across all 18 rows. The 14 larger projection rows improve by **1.848–2.591x**. The four small K/V rows are close to the roughly 0.24 ms measurement floor at **0.996–1.052x**. A separate 201-sample controlled sweep at their identical 163,840-block workload measured **1.122–1.166x**, indicating that the single 0.996x result is sub-millisecond timing noise.

Reproduce with:

```bash
python -m tests.benchmark_mlx_qwen38_gguf_q4_0_pack --samples 301
```
