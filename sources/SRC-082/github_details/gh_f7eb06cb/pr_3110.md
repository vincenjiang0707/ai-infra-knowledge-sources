## Summary

- Add opt-in staged scalar GSQ for dense Llama GPTQ W2/W3/W4 and AWQ W4. The training schedule fits Q/K separately with projected-Hessian objectives, V/O jointly against attention output, and the MLP projections jointly against block output. Completed packed blocks feed the next block's calibration capture.
- Train discrete assignments and group scales with Gumbel-Softmax, Lion or AdamW, temperature/logit schedules, and GPTQ, RTN, or AWQ initializers. Export through existing GPTQ_V2 or AWQ GEMM checkpoints.
- Extend local GSQ refinement to compatible AWQ, RTN, QQQ, FP8, and ParoQuant paths. Add calibrated FP8 refinement, exact AWQ packing-code checks, and explicit QQQ Torch backend selection.
- Document supported methods, formats, constraints, and GSQ attribution in the README. New files carry ModelCloud/qubitium SPDX headers.

## Comparison with the GSQ paper

- The W3 scalar grid, five local shifts, trainable group scales, Gumbel-Softmax relaxation, Lion optimizer, annealing endpoints, and Q/K → V/O → MLP stage order follow the paper and its [public reference implementation](https://github.com/IST-DASLab/GSQ). The dense-attention teacher objective was corrected in `e3db0e4`; five tiny GPTQ/RTN/AWQ checkpoint tests pass after the change.
- The paper's Llama experiment uses FineWeb-Edu, 4,096 sequences of length 4,096, 20 epochs, and optimizer batches of 64. This Llama 3.2 1B quality test uses nm-calibration, 25 sequences of length 2,048, 10 epochs, and batches of 1: roughly 655 times fewer training token exposures. Its microbatch is also 1, so it does not average gradients across independent Gumbel draws as in the paper's accumulation recipe. Its Q/K schedule is 10 updates versus 2,000 in the reference code. The public reference separates GPTQ, training, and validation samples; this test reuses the 25 sequences for GPTQ and training and has no held-out validation stage.
- The [paper's Equation 6](https://arxiv.org/pdf/2604.18556) describes clipping shifts at grid boundaries; both the released integer quantizer and this port mask out-of-grid shifts. This is a paper-versus-code detail, separate from the test-budget differences.
- The paper evaluates Llama 3.1 8B/70B on five zero-shot tasks; this PR tests Llama 3.2 1B on 128 GSM8K Platinum questions. The paper's optional full-model scale-only pass is for 2-bit Llama and is not implemented here. Its ternary, GGUF, mixed-bit, and MoE training paths are outside this public dense-Llama staged path.

## Limits

- Staged training currently targets dense Llama blocks, one materialized device, eager or SDPA attention, and the listed GPTQ/AWQ formats. The paper's optional end-to-end scale-only pass for 2-bit Llama is not included.
- Full 1B AWQ training was attempted but stopped after over 22 minutes in the existing block-2 GPU-to-CPU calibration feature capture. Tiny AWQ all-projection training and exact save-load were validated.
- The native QQQ CUDA extension could not be exercised on this host because the CUDA toolkit is absent. Its Torch backend and packed checkpoint path were validated.

## Current W3 paper-budget recipe (NM source)

The new opt-in `tests/models/test_llama3_2_gsq_paper_w3.py` uses Llama 3.2 1B Instruct, W3/group128, all 16 blocks and all seven projections. It matches the paper's Llama data geometry: **4,096 training**, **128 validation**, and **512 GPTQ initialization** sequences, each **4,096 tokens** (19,398,656 tokens total). It also uses **20 epochs**, batch **64**, microbatch **2**, **2,000 Q/K updates**, and the Llama Lion learning rates, weight decay, annealing, and cosine schedule. GPTQ initialization and late MLP reinitialization now use the separate GPTQ split, and V/O plus MLP stages record held-out validation loss.

The full [FineWeb-Edu dataset](https://huggingface.co/datasets/HuggingFaceFW/fineweb-edu) is about **5.84 TB**, and the [sample/10BT](https://huggingface.co/datasets/HuggingFaceFW/fineweb-edu/tree/main/sample/10BT) is **28.5 GB**, so this recipe uses the existing 12.8 MB `nm-calibration/llm.parquet` instead. Its 10,000 source rows are shuffled and partitioned before repetition. Each split repeats only its own rows to reach the target tokens; unique text diversity remains about six times smaller than the paper's. Source SHA256 and exact counts are in `docs/experiments/gsq-paper-budget-1b-w3.md`. The model and 128-question GSM8K Platinum evaluation differ from the paper's Llama 3.1 8B/70B and five zero-shot benchmarks.

The public Llama module tree now carries explicit `q`, `k`, `v`, `o`, `gate`, `up`, and `down` roles while preserving shared-input tags and projection subsets. The staged trainer selects the seven projections by name, so these tags do not change the GSQ objective.

**Validation:** 245 focused tests passed; 2 full-budget E2E parametrizations were skipped by default. The real NM tokenizer produced the exact 4,096/128/512 sequences of length 4,096. Dense Llama 3.2 1B scored **54/128 (42.2%)** on the same GSM8K settings. The single-block, full-length GPU smoke passed with batch 64, microbatch 2, finite V/O and MLP validation losses, and cleaned disk capture (21.6 seconds for block quantization after data preparation). The 512-sequence, all-block W3 initializer completed, saved, and reloaded. It scored **5/128 (3.9%)** on GSM8K Platinum, versus **54/128 (42.2%)** for dense Llama 3.2 1B. The prior opt-in test failed solely because the 20% quality threshold was applied to this reference baseline; the threshold now applies only to GSQ. The complete 20-epoch W3 GSQ quantization and resulting GSM8K score have **not been measured**. This PR stays draft pending that quality result.

## Training speed update (commit `0b146b4`)

The attempted 20-epoch W3 run was stopped during block 1, MLP update 436/1,280, because the original training path was too slow. No completed GSQ checkpoint or GSM8K score exists from that run; the temporary 75 GB activation capture was removed.

A CUDA NVRTC fused scalar relaxation now covers W3/W4 BF16 MLP/V/O logits and FP32 Q/K logits, with any positive contiguous group size. Unsupported CUDA setups and CPU use the eager path. Fixed dense-teacher outputs and MLP residuals are cached at the original microbatch geometry for disk-backed SDPA Llama training; the next MLP optimizer batch is prefetched. The caches are removed after each stage. CUDA and eager use the same equations, with small floating-point rounding differences in the CUDA kernels. Numerical forward/gradient comparisons and 59 focused tests passed, followed by 8 CUDA-specific tests after adding the nonstandard group-size case; the opt-in full quality check remains unmeasured.

On 128 captured Llama 3.2 1B W3/group128 documents of 4,096 tokens, batch 64, microbatch 2, two optimizer batches per trial:

| Stage | Eager | Optimized | Speedup |
| --- | ---: | ---: | ---: |
| MLP, trial 1 | 18.34 s | 4.41 s | 4.16× |
| MLP, trial 2 | 19.08 s | 4.49 s | 4.25× |
| V/O attention, trial 1 | 3.54 s | 1.98 s | 1.79× |
| V/O attention, trial 2 | 3.36 s | 1.91 s | 1.76× |

A separate warmed 2,048×2,048 FP32-logit Q/K update with its quadratic loss took about 33 ms eager versus 13 ms fused (2.5×). The MLP and V/O measurements sum to roughly **3.4–3.5×**, so a **4× end-to-end speedup is not established**. Cache construction took 10.4 s for MLP and 2.0 s for attention on those 128 documents; these and GPTQ initialization, hard validation, packing, and generation are excluded from the table. Full-data MLP target caching temporarily requires roughly 128 GiB of disk, with separate stage caches cleaned on exit. Reproduction details and limitations are in `docs/experiments/gsq-paper-budget-1b-w3.md`.

## CUDA precision follow-up (`8834d8b`)

A targeted audit found a precision error in the first fused Q/K kernel: it stored FP32 softmax probabilities as BF16 and rounded W3/W4 scalar shifts before adding them to the FP32 initializer. Both are corrected. A crafted low-temperature test now checks that a nearly certain choice retains its small, nonzero FP32 gradient.

The updated focused suite passed **66 tests**. Three 30-update matched-randomness trajectories covered W3 BF16, W4 BF16, and W3 FP32, comparing hard choices and reconstruction loss. A paired three-epoch tiny Llama W3 run trained and packed all seven projections; eager and CUDA yielded identical packed-model logits and measured hard-stage losses in that case. In a separate synthetic 2,048×2,048 W3/group128 Q/K probe, the corrected kernel had no gradient-sign disagreements with eager among 20,971,520 logits at each of four sampled schedule points, including temperature 0.05 / multiplier 500. This does not establish full 1B model quality.

With the corrected kernel and isolated GPU measurements, the three-projection MLP relaxation measured **206.9 ms eager versus 25.8 ms fused** per microbatch (8.0× for this suboperation). A warmed 2,048×2,048 FP32 Q/K update measured about **33.5 ms eager versus 13.7 ms fused** (2.4×). The earlier stage timings above used the first kernel version; corrected-kernel timings are below. The stopped 20-epoch W3 GSM8K evaluation remains unmeasured; the PR stays draft.

## Corrected-kernel stage timing (`a1abd20`)

The two-stage timing was repeated after the FP32 precision correction with Llama 3.2 1B layer dimensions, W3/group128, 4,096 tokens, batch 64, microbatch 2, and 128 synthetic captured documents. Both paths used the same inputs and two optimizer batches. The synthetic source was repeated random BF16 activation data; this is a shape-matched speed test, not a quality result.

| Stage | Eager, trials 1 / 2 | Optimized, trials 1 / 2 | Speedup |
| --- | ---: | ---: | ---: |
| MLP | 18.08 / 18.11 s | 4.39 / 4.40 s | 4.11–4.12× |
| V/O attention | 3.51 / 3.39 s | 1.93 / 1.91 s | 1.77–1.82× |
| Sum of measured stages | 21.59 / 21.50 s | 6.32 / 6.30 s | 3.41× |

MLP cache setup took 7.60 s; attention cache setup took 2.06 s for 128 documents. These setup costs, Q/K training, GPTQ initialization, validation, packing, and evaluation are outside the table. Attention batch prefetch was tested and gave no reliable improvement, so it was omitted. The full 20-epoch W3 quality run remains stopped and unmeasured. See `docs/experiments/gsq-paper-budget-1b-w3.md` for method and limits.
