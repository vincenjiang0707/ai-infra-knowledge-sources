# [PR #3102] Speed up eager GPTQ block updates

## 正文

## Summary

- Reuse the eager GPTQ block's existing quantized-weight, loss, and error buffers.
- Compute the column residual once and update the remaining columns with elementwise multiplication.
- Keep the RTN fallback and quantization formats unchanged.

## Validation

- `tests/test_gptq.py`: 11 passed, 3 skipped.
- Original and updated GPTQ implementations produced bitwise-equal weights, quantization parameters, and loss on CPU and CUDA for group-aware ordering, activation ordering, static groups, and asymmetric 2-bit quantization. RTN fallback weights and parameters also matched.
- Llama 3.2 1B Instruct fast-test path: quantized the final two layers with 4-bit GPTQ, saved and reloaded the model, and ran Evalution GSM8K Platinum. The 64-row smoke run scored `acc,num=0.484375`. The complete 1,209-row run scored `acc,num=0.478081`, passing the test's stored `0.4690` baseline bounds.
- Isolated eager quantization timing with a fixed identity Hessian factor, median of three measurements: CPU 256×512 8.78 ms → 7.31 ms (1.20×); CUDA 1024×1024 84.51 ms → 74.74 ms (1.13×). These are local NVIDIA GB10 measurements, not full-model speedups.

The local Llama test used the public `unsloth/Llama-3.2-1B-Instruct` checkpoint because the official checkpoint was gated in this environment. This environment lacks the Marlin JIT compiler and FlashAttention2, so evaluation used GPTQModel's Torch inference backend with SDPA.

## Credit

The eager GPTQ optimization approach was informed by the vLLM project's llm-compressor work.
