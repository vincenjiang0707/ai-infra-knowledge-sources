## Summary

Add an opt-in MLX GPTAQ correction builder and fused Metal group update. The update follows GPTAQ's sequential weight correction, including the activation correction matrix and cross-group terms. This PR covers one quantization method only.

## What Changed

- Add `gptaq_correction_mlx` for the GPTAQ cross-covariance projection.
- Add `gptaq_quantize_weight_mlx` for dynamic-group GPTAQ weight quantization with 2–8 bits, symmetric or asymmetric codes, and float16/bfloat16/float32 input.
- Add independent Torch-oracle tests for correction construction, dense group updates, quantization boundaries and input casts, plus every Qwen3.8-27B projection.
- Add a reproducible benchmark for all nine Qwen projection shapes.
- The API is opt-in. Processor integration, activation-order permutation, static groups, and MSE search are outside this method-kernel PR.

## Accuracy and performance versus main

M5 Ultra, MLX 0.32.2, Torch 2.14.0, base main `e114733`. Q4 symmetric, group size 128, BF16 weights promoted to float32, float32 inverse-Hessian factor and GPTAQ correction. The full Qwen shape tests use nonzero one-superdiagonal factors to exercise within-group and cross-group corrections. Correction-matrix arithmetic is separately compared to Torch on dense 32×32 and 128×128 inputs for α = −0.5, 0, 0.25, and 1.5.

The timing comparison covers the update stage only: the independent Torch oracle follows main's dense GPTAQ update arithmetic; the MLX path uses the fused kernel and native matrix products. Inputs and correction matrices are already resident in each backend. Each timing is the median of three synchronized runs after one warmup. Hessian factorization, correction construction, and transfers are outside both timings. Torch uses float32 arithmetic; disputed code decisions are replayed at 80-digit Decimal precision from the stored BF16 values and stored float32 correction constants.

There are no unresolved non-tie code mismatches. Speedups range from 2.62× to 13.13×.
