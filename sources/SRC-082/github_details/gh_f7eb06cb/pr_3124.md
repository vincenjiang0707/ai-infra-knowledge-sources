## Summary

Add a native MLX Metal packer for GGUF `Q2_0`, the next format in the [native MLX quantization plan](https://github.com/ModelCloud/GPTQModel/blob/main/docs/mlx-native-quantization-plan.md).

## What Changed

- Pack each 64-value block into the existing 18-byte layout: a two-byte fp16 maximum-magnitude scale and 16 bytes of four 2-bit codes.
- Extend `gguf_quantize_weight_mlx` to accept `Q2_0` for 2D float16, bfloat16, and float32 weights with nonzero input width divisible by 64.
- Add an independent Torch oracle for the reference's float32 normalization and rounding, plus deterministic tests for neighboring float32 values around the ±0.5 code thresholds, fp16 scale midpoint/range boundaries, zero and signed-zero blocks, supported dtypes, widths, and decoding through the current GGUF runtime.

## Accuracy and performance

On Apple M5 Ultra, all tested packed bytes match the Torch oracle exactly. Two separate 30,000-block boundary stress comparisons against the current NumPy packer found **0 differing bytes in 540,000 bytes each**. The second spans maximum magnitudes from about 1e-8 to 1e4. On a 4096×4096 float32 matrix, the complete packed output matched the current packer in **all 4,718,592 bytes**.

For that 4096×4096 matrix (262,144 blocks), inputs already resident on their respective backends, 3 warmups, and the median of 10 synchronized runs:

| Path | Median pack time |
| --- | ---: |
| Current `main` NumPy CPU `Q2_0` packer | 78.67 ms |
| Proposed MLX Metal `Q2_0` packer | 0.991 ms |

That is a **79.35× operation-level speedup** under the stated residency condition. Host-to-device transfer and full-model quantization are outside this measurement.
