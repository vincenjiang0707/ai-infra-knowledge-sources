## 正文

## Summary
- Add opt-in Gumbel-Softmax refinement of GPTQ scalar code assignments and optional group scales. The initializer, checkpoint layout, packer, and inference kernels remain the existing GPTQ path.
- Score hard candidates using the calibration Hessian and the packer's rounding arithmetic. Keep the GPTQ initializer unless a candidate improves the local exported reconstruction objective.
- Bound candidate memory by processing independent output rows in chunks; expose per-module before/after diagnostics and dynamic module selection.
- Preserve inference-mode tensor behavior when returning refined weights so the next calibration replay can use them.
- List GSQ in the README feature table as a GPTQ scalar refinement, document its format-dependent runtime support, and include the existing `FORMAT.GPTQ_P` Torch path in the format matrix.

## Scope and attribution
This applies to calibrated linear projections in GPTQ, GPTQ_V2, and GPTQ_P formats at 2–8 bits. It is a local refinement inspired by [GSQ by Dadgarnia et al. (IST-DASLab)](https://arxiv.org/abs/2604.18556); it does not implement the paper's complete block-training schedule. The README now explains the stage/objective and optimizer differences. README attribution and BibTeX link to the [authors' implementation](https://github.com/IST-DASLab/GSQ). New source and test files use the ModelCloud.ai/qubitium Apache-2.0 license header.

## Verification
- 27 focused tests passed: config and dynamic overrides, rank-deficient Hessian, candidate improvement and baseline retention, 2–8-bit GPTQ pack/dequantize parity, activation ordering, group-size variants, disabled-path equivalence, and inference-mode forward replay.
- The new `tests/models/test_llama3_2_gsq.py` uses the existing Llama 3.2 1B GPTQ and Evalution GSM8K Platinum harness. The matched GPTQ-only smoke run scored 59/128 (46.09%). GSQ scored 59/128 (46.09%) both with only `q_proj` enabled and with all seven compatible decoder projection types enabled across the last two layers (32 calibration examples, 128 questions, 96 generated tokens). Both checkpoints were saved, reloaded, and evaluated with the Torch backend. The test now asserts that GSQ refined all 14 projections and that each local exported objective did not regress. The default opt-in mode runs the full GSM8K task.
- Ruff and `git diff --check` passed on changed source and tests.
- A 2048×2048 projection from the local Llama 3.2 1B checkpoint completed with GSQ enabled on NVIDIA GB10 using PyTorch 2.11.0+cu130: 14.96 s for the quantization call, 0.46 GiB peak allocated, and a retained baseline local score of 0.0010686422 (3 refinement steps, 5 candidates, 32 MiB candidate budget).

The full GSM8K task has not yet been run for this opt-in refinement. The local reconstruction acceptance check is not a model-level quality guarantee.
