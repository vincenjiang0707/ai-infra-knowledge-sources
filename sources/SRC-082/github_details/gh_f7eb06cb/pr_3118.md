## Summary

- Register `MlxQuantLinear` (GPTQ) and `AwqMlxQuantLinear` (AWQ GEMM) as GPT-QModel `BaseQuantLinear` subclasses. The kernel registry now validates Apple Silicon/Metal, 4-bit `int32` packing, affine groups 32/64/128, float16 source dtype, shapes, and unsupported adapters/training. `backend=auto` selects these classes on qualified hosts.
- Transfer packed codes, scales, and zero points into MLX's affine `QuantizedLinear` without dequantizing and requantizing compatible checkpoints. Float32 affine biases preserve numerical agreement with an independent Torch oracle. MLX supplies the runtime `quantized_matmul`.
- Use per-instance MLX generation dispatch and map sampling options to current MLX-LM sampler/logits-processor APIs. Keep `mlx>=0.32.2` and `mlx_lm>=0.31.3` as optional dependency floors, with usage docs and SPDX/license-credit headers.
- Merge current main's native MLX quantization work (#3117) and preserve its API/tests.

## Performance versus main

Apple M5 Ultra Mac Studio, 256 GB memory, macOS 27, Python 3.12, Torch 2.14, MLX 0.32.2, MLX-LM 0.31.3. Baseline `main`: `1faced2d`; benchmarked PR head: `f902f041`; current PR head: `0822f611` (same MLX implementation after merging `main`). Both used `backend=auto`, the same cached checkpoints and prompt `The capital of France is`, greedy decoding with repetition penalty explicitly set to 1.0 (Torch `do_sample=False`, MLX temperature 0). After a 2-token warmup, each run generated all 64 requested tokens. Figures are medians of three completed warm runs; Torch MPS was synchronized before timing ended.

| Checkpoint | main latency | PR latency | Speedup | main throughput | PR throughput |
| --- | ---: | ---: | ---: | ---: | ---: |
| [ModelCloud/Qwen2.5-0.5B-Instruct-gptqmodel-w4a16](https://huggingface.co/ModelCloud/Qwen2.5-0.5B-Instruct-gptqmodel-w4a16) (GPTQ) | 5.447 s | 0.229 s | **23.8×** | 11.7 tokens/s | 279.6 tokens/s |
| [Qwen/Qwen2.5-0.5B-Instruct-AWQ](https://huggingface.co/Qwen/Qwen2.5-0.5B-Instruct-AWQ) (AWQ GEMM) | 12.588 s | 0.226 s | **55.7×** | 5.1 tokens/s | 283.0 tokens/s |

Raw 64-token timings (seconds):

- GPTQ main: 5.390, 5.463, 5.447; PR: 0.247, 0.229, 0.228.
- AWQ main: 12.612, 12.588, 12.560; PR: 0.226, 0.225, 0.226.

This compares the complete default inference paths: main selected Torch; this PR selected MLX Metal. It is not an isolated MLX kernel speedup. Single cold-load runs were 5.50 s main versus 8.23 s PR for GPTQ and 5.95 s versus 6.86 s for AWQ. Cold load includes MLX conversion/reload and is noisier than warm generation.

## Numerical verification

- Independent float64 Torch arithmetic checked MLX 4-bit inference for GPTQ and AWQ using `(3, 128) @ (128, 64)` with group sizes 32, 64, and 128, float16 inputs/scales, and edge codes/zero points 0 and 15. Packed codes matched exactly. At `rtol=atol=2e-3`, the largest observed output absolute error was `2.73e-6` (zero tolerance violations).
- With the same prompt token IDs, greedy sampling, and repetition penalty 1.0, real GPTQ and AWQ models each matched Torch for **32/32 generated token IDs**.
- `tests/test_mlx_packing.py`: 26 passed. Native `tests/test_mlx_native_quantization.py`: 32 passed. The inference oracle covers GPTQ and AWQ 4-bit weights at every supported group size (32/64/128), plus biased GPTQ/GPTQ, AWQ/AWQ, and GPTQ/AWQ two-layer models with `(2, 3, 128)` float16 inputs; first-layer and final outputs satisfy `rtol=atol=2e-3` and max absolute error ≤`2e-3`. Native MLX GPTQ quantization has exact Torch packed-code checks and `1e-6` scale/bias checks for 2/4/8 bits × groups 32/64/128. Unsupported bits/groups and nonsequential GPTQ group indices are rejected. Real GPTQ/AWQ automatic MLX loading and AWQ-to-MLX export/reload generated successfully.
- After merging `main` at `1faced2d`, the MLX suites passed (58 tests), and the new main decoder/dequantization suites passed 68 tests. One main test requires the optional `bitsandbytes` package, which is absent from the test environment. Ruff and `git diff --check origin/main...HEAD` passed. The unrelated `tests/kernels/test_qlinear_hierarchy.py` suite had 8 passes and one existing macOS BitblasLinear platform failure.
