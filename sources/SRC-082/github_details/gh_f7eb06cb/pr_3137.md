## Summary

Add an opt-in native MLX/Metal FP8 weight quantizer. It returns the exact FP8 storage bytes and inverse scales used by the existing Torch FP8 quantizer, with tensor, row, and block scaling. The Metal kernel multiplies by the selected scale and encodes E4M3FN, E5M2, E4M3FNUZ, or E5M2FNUZ directly. Integer-bit reduction and explicit subnormal handling preserve Torch behavior even for tiny finite weights and infinite inverse scales.

This PR is scoped to FP8 quantization. The current FP8 processor and inference paths still use Torch. E8M0 is dequantization-only in the existing Torch implementation and is intentionally rejected for new quantization here.

## Accuracy and tests

- 157 targeted tests passed on M5 Ultra; Ruff and `git diff --check` passed.
- Independent Torch-oracle comparisons cover all four FP8 encodings, float16/bfloat16/float32 source weights, tensor/row/block scaling, zero groups, signed zero, FP8 thresholds and one float32 input step on each side, and float32 subnormal weights.
- All nine pinned Qwen3.8-27B projection shapes were compared in full with BF16 weights for each of four encodings and three scaling modes (108 model-scale cases). Every FP8 byte matched; inverse scales matched exactly.
- The benchmark compares all 54 measured format/mode/shape cases against main's Torch arithmetic and asserts zero byte mismatches and inverse-scale drift no greater than 1e-6. Observed maximum scale drift was **0** and observed byte mismatches were **0** in every case.

Reproduce: `python -m pytest -q tests/test_mlx_fp8_quantization.py` and `python -m scripts.benchmark_mlx_qwen38_fp8 --repeats 7 --scale-method row --format float8_e4m3fn --format float8_e5m2 --format float8_e4m3fnuz --format float8_e5m2fnuz`. Run the benchmark again with `--scale-method tensor` or `block` for those modes.
