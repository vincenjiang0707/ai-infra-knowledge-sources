## 正文

## Summary

Add an MLX-native quantization entry point for Apple silicon. GPTQ uses MLX Hessian accumulation and a fused Metal group update; AWQ uses MLX-LM's native quantization path. Both produce reloadable MLX-LM checkpoints. At head `e03b47f`, a repository skill also requires independent Torch-oracle A/B tests for future quantization and inference optimizations.

## What Changed

- Add `GPTQModel.quantize_mlx(..., method="gptq"|"awq")`.
- Fuse each GPTQ weight-group update and packing into one Metal dispatch, with CPU-stream Cholesky for the Hessian inverse.
- Recover float32 precision in GPU Hessian and cross-group matrix products with BF16 high/residual matmuls; validate against an independent Torch oracle.
- Add repository agent guidance and a reusable skill requiring exact quantization codes, `1e-6` quantization tolerance, and `2e-3` inference tolerance.
- Support 2D and expert weights, smaller groups for narrow layers, and a finite diagonal floor for zero Hessians.
- Document the API and require MLX 0.32.2 / MLX-LM 0.31.3 in the optional dependency.
- Add ModelCloud SPDX headers at the top of changed files, including tests; GPTQ paper credit remains in the README.

## Performance vs main

`main` at `9fc9006` has no native MLX quantization entry point; its GPTQ layer implementation runs through Torch MPS. The Torch GPTQ implementation is unchanged between main and this branch. On an Apple M5 Ultra (256 GB), both paths used the same seeded float32 512×512 weights and 1,024 calibration activations, with 4-bit asymmetric weights, group size 64, 1% Hessian damping, and activation ordering disabled (`desc_act=False`, `act_group_aware=False`, `sym=False`). Timings are medians of three synchronized runs after one warmup; imports, model loading, and setup are excluded.

| GPTQ layer stage | main: Torch MPS | PR: MLX/Metal | Speedup |
| --- | ---: | ---: | ---: |
| Hessian accumulation | 0.326 ms | 0.381 ms | 0.86× |
| Hessian factorization + weight quantization | 207.892 ms | 6.428 ms | 32.3× |
| **Total** | **208.142 ms** | **6.787 ms** | **30.7×** |

This is a layer-compute comparison of different implementations, not an end-to-end model comparison or an assertion that their checkpoint formats match. Main returns Torch quantized weights; the PR also packs MLX weights. With the current accuracy fix, the PR quantized SmolLM2-135M in **1.52 s** after loading on a fixed 64-token sample; its saved checkpoint reloaded and produced finite logits. A main high-level Torch MPS model run previously stopped at `Device not in pool: mps:0`, so no full-model speedup is claimed. AWQ delegates to MLX-LM's native AWQ implementation; no AWQ compute speedup is claimed.

## Numerical A/B validation

The tests use independent Torch arithmetic for affine parameters, GPTQ column and cross-group updates, packing, and Hessian accumulation. They cover 2/4/8-bit weights, group sizes 32/64/128, and Hessian widths 64/128/512. The Hessian oracle accumulates in float64; the inverse-factor test supplies the same float32 Hessian to both backends.

| Output | Largest observed difference | Required limit |
| --- | ---: | ---: |
| Packed quantization codes | 0 mismatches | Exact |
| Quantization scales | 2.38e-7 absolute | `rtol=atol=1e-6` |
| Quantization biases | 4.77e-7 absolute | `rtol=atol=1e-6` |
| Hessian | 4.93e-7 normalized matrix error | ≤1e-6 |
| Inverse factor | Passes `rtol=atol=1e-6` | `rtol=atol=1e-6` |

One upstream MLX-LM reference case differs by one packed word after the precision fix; this PR's packed codes match the independent Torch oracle. The new skill sets a `2e-3` inference tolerance for future kernel optimizations. This PR changes quantization code, so it does not claim an inference-kernel A/B result.


The repository skill passed the skill-creator validator. The current SmolLM2-135M GPTQ checkpoint saved, reloaded, and produced finite logits. Previous GPTQ and AWQ real-model checkpoint smoke tests and package artifact checks also passed.
