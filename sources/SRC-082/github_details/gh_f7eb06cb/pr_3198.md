# [PR #3198] Avoid FP32 temporaries in MLX BitsAndBytes quantization

## 正文

## Summary

- Quantize resident FP16 and BF16 BitsAndBytes weights directly instead of allocating full FP32 copies.
- Keep FP32 bit-exact handling for FP32 inputs, including subnormals and signed zero.
- Preserve FP32 arithmetic inside the NF4/FP4 pack and int8 kernels.
- Keep this PR scoped to BitsAndBytes weight quantization.

## Accuracy coverage

- NF4 and FP4, with compressed statistics enabled and disabled.
- All supported 4-bit block sizes: 32, 64, 128, 256, 512, 1024, 2048, and 4096.
- int8 vector-wise quantization.
- FP16, BF16, and existing FP32 source coverage.
- All nine Qwen3.8-27B projection shapes in FP16 and BF16.
- Zero blocks, remainder blocks, code boundaries and neighbors, subnormals, signed zero, and nested-statistics lookup boundaries.
- Full outputs are checked against bitsandbytes CPU oracles. Adjacent nested-statistics codes are accepted only within two FP32 reduction steps of a lookup boundary.
