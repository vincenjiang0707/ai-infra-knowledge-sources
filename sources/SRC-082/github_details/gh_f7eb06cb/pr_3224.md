## 正文

## Summary

Add the missing native MLX quantization-stage kernel for GGUF NVFP4 on Apple Silicon. The kernel emits the exact 64-value/36-byte GGUF block layout: four UE4M3 scale bytes and 32 packed E2M1 payload bytes.

This PR is intentionally limited to the GGUF NVFP4 weight packer. Connecting GGUF quantization kernels to the model-level processor remains separate follow-up work.

## What Changed

- Added a Metal NVFP4 packer to `gguf_quantize_weight_mlx(..., "NVFP4")`.
- Implemented the GGUF/llama.cpp UE4M3 scale conversion, 16-value subgroups, E2M1 nearest-code selection, saturation, and nibble layout.
- Kept FP16, BF16, and FP32 inputs resident in MLX; non-contiguous inputs are made contiguous by the existing entry point.
- Added an independent Torch oracle, a fixed canonical block-byte vector, random and transposed inputs, runtime decode compatibility, every UE4M3 rounding transition, E2M1 midpoint ±1 ULP checks, saturation, zero, and negative-zero coverage.
- Added a reproducible Qwen3.8-27B benchmark over every projection shape and both FP16/BF16 inputs.
- Out of scope: model-level GGUF processor integration and any non-NVFP4 quantization or inference changes.

## Accuracy

Packed output is discrete, so acceptance is exact bytes rather than a floating tolerance.

- Qwen3.8-27B projection checks: 18/18 exact
- Total byte mismatches: **0**
- Maximum byte error: **0**
- Canonical known block: exact
- Boundary/threshold/clamp suite: exact
- Existing MLX NVFP4 runtime accepts and decodes the emitted bytes
