## 正文

## Summary

Add an opt-in native MLX finalizer for EXL3 calibration Hessians. The complete path performs sample averaging, diagonal regularization, input-sign application, the two-sided order-128 Hadamard transform, fallback detection, block-LDL factorization, and scalar-diagonal clearing without routing tensors through Torch.

The two transform passes fuse averaging, regularization, and sign application. Their two `1/sqrt(128)` factors are applied once as the exactly representable combined factor `1/128`, reducing memory traffic and intermediate rounding.

## What Changed

- Added `exl3_finalize_hessian_mlx` for accumulated float32 Hessians and caller-supplied deterministic signs.
- Added explicit validation for shapes, dtypes, finite inputs, signs, sample counts, regularization, block sizes, and the Metal kernel's 32-bit index boundary.
- Added intended empty-capture fallback behavior and representable-neighbor tests around EXL3's `1e-20` fallback threshold.
- Added an independent Torch float32 oracle and a Torch float64 adjudication oracle, including EXL3's explicit identity-block overwrite before scalar-diagonal clearing.
- Added all nine Qwen3.8-27B projection checks and a resident-input benchmark.
- Kept processor integration and RNG/sign generation out of scope so this remains one focused EXL3 quantization-stage PR.

## Accuracy

The oracle starts from the same stored float32 accumulated Hessian and deterministic seeded pseudo-random signs. Matrix results are checked over the complete output with `atol=rtol=1e-6`, normalized drift `||actual-reference||/||reference|| <= 1e-6`, and explicit nonfinite counts. The table uses the independent Torch float64 path as the reference.

Both float32 backends remain within the normalized limit on the realistic sign pattern. MLX's zero-diagonal factor is closer to the higher-precision reference on every Qwen width: at most `6.25e-7` normalized drift versus Torch's `8.22e-7`.
