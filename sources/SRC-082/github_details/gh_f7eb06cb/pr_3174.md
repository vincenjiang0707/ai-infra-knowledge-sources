## 正文

## Summary

- add an opt-in native MLX implementation of EXL3's block-LDL Hessian factorization
- use MLX's supported CPU-stream Cholesky and batched triangular inverse
- fuse the dense block-column normalization into a Metal float32-FMA kernel
- write exact identity diagonal blocks and preserve the source algorithm's block-unit-lower layout
- reject nonfinite inputs, singular/non-positive-definite Hessians, invalid block sizes, nonfinite inverses, and nonfinite outputs
- keep this PR limited to block-LDL; LDLQ remains the separate merged PR #3172

MLX 0.32.2 does not expose Cholesky on the GPU. This implementation therefore keeps factorization on MLX's native CPU stream and moves the bandwidth-heavy normalization to Metal.

## Accuracy

Target: Mac Studio, M5 Ultra, 256 GB. Tests use block size 16 and a dense positive-definite AR(1) Hessian with correlation 0.2. The factorization depends only on input width, so repeated projection rows reuse the measured 5,120 or 6,144 result. Every full factor is compared with an independent Torch oracle using `atol=1e-6`, `rtol=1e-6`, normalized drift no greater than `1e-6`, and an explicit nonfinite check.
