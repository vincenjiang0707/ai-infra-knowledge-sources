## 正文

## Summary

- add a native MLX/Metal implementation of EXL3's two-pass tail-biting Viterbi tile quantizer
- support every EXL3 bit width (1–8) and all three codebooks (`3inst`, `mcg`, and `mul1`)
- preserve the canonical FP32-to-FP16 input conversion, fused FP16 cost accumulation, strict tie ordering, cyclic backtrace, unpacked int16 states, and FP32 reconstructed values
- bound scratch memory independently of projection size by reusing a fixed set of Viterbi workspace slots

This PR is intentionally limited to EXL3 path search/tile quantization. Codebook reconstruction and trellis packing were merged separately, and this does not wire the opt-in MLX primitive into the CUDA/HIP-only EXL3 processor.

## Accuracy

The independent Torch oracle implements the state graph and arithmetic separately. In particular, it models the CUDA/Metal fused `delta² + prior_cost` operation with one FP16 rounding; it does not call or reuse MLX intermediates.

Coverage includes:

- exact unpacked int16 states and reconstructed values for bits 1–8
- exact outputs for `3inst`, `mcg`, and `mul1`
- representable FP16 tie boundaries plus one FP16 step below and above
- positive/negative values, signed zero, codebook extrema, and forced one-slot workspace reuse
- complete outputs for every Qwen3.8-27B projection shape

The model-scale tests repeat a deterministic four-tile random bank to each full projection tile count. Every output element is checked; the repeated bank keeps the independent CPU oracle tractable without reducing the MLX workload.

## Performance

Apple M5 Ultra 256 GB, MLX 0.32.2, Torch 2.14.0, 4-bit MCG, 256 MiB workspace. MLX times are measured over the complete resident projection and are medians of 3 runs after warmup.

The resident Torch oracle is prohibitively slow at full projection scale, so its median four-tile runtime is linearly extrapolated to each tile count. The speedup column is therefore an estimate, not a directly measured end-to-end Torch or CUDA comparison.

| Projection | Shape | Torch oracle extrapolated (ms) | MLX measured (ms) | Estimated speedup |
|---|---:|---:|---:|---:|
| full_attn.q_proj | 12288×5120 | 18,259,722.240 | 9,850.414 | 1,853.70× |
| full_attn.k_proj | 1024×5120 | 1,424,540.375 | 824.198 | 1,728.40× |
| full_attn.v_proj | 1024×5120 | 1,589,089.280 | 824.422 | 1,927.52× |
| full_attn.o_proj | 5120×6144 | 9,664,433.910 | 4,928.887 | 1,960.77× |
| linear_attn.in_proj_qkv | 10240×5120 | 16,210,837.300 | 8,218.292 | 1,972.53× |
| linear_attn.out_proj | 5120×6144 | 9,462,137.580 | 4,930.837 | 1,918.97× |
| mlp.gate_proj | 17408×5120 | 26,906,243.655 | 13,970.136 | 1,925.98× |
| mlp.up_proj | 17408×5120 | 28,265,986.105 | 13,979.851 | 2,021.91× |
| mlp.down_proj | 5120×17408 | 24,101,771.249 | 13,977.496 | 1,724.33× |

Measured MLX range: **0.824–13.980 seconds**. Estimated Torch-oracle speedup range: **1,724.33×–2,021.91×**.

The production EXL3 quantizer on `main` is CUDA/HIP-only and cannot run on Apple Silicon, so this PR makes no measured main/CUDA speed claim.

Reproduce with:

```bash
PYTHONPATH=. python tests/benchmark_mlx_qwen38_exl3_viterbi.py --repeats 3
```
