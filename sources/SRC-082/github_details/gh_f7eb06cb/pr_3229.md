## 正文

## Summary

- add a BaseQuantLinear-compliant `GPTQBitBLASMlxQuantLinear` holder for portable serialized GPTQ BitBLAS checkpoints
- transcode GPTQ BitBLAS and legacy Marlin packed state directly into MLX affine packed weights
- allow `backend=auto` to select MLX for GPTQ `FORMAT.MARLIN` and `FORMAT.BITBLAS` on qualified Apple Silicon hosts
- preserve FP16/BF16 activation and output dtypes through the native `mlx.nn.QuantizedLinear` runtime
- remove GPTQ BitBLAS 1-bit support; no GPTQ/AWQ kernel now advertises below 2-bit (AWQ remains 4/8-bit depending on backend)
- include Apache-2.0 SPDX headers and upstream Marlin/BitBLAS credit notices in implementation and test files

## Supported layouts

| Format | Bits | Group sizes | Symmetry |
| --- | --- | --- | --- |
| GPTQ BitBLAS | 2, 4, 8 | -1, 32, 64, 128 | symmetric + asymmetric |
| GPTQ Marlin | 4, 8 | -1, 32, 64, 128 | symmetric |

Transformed/propagated BitBLAS runtime layouts are rejected; this supports the portable serialized row-packed layout.

## Qwen3.8-27B performance and accuracy

Apple Silicon host, all nine projection shapes from `tests/qwen38_27b_shapes.py`, rows 1 and 16, with 31 timed repeats per case. Current `main` rejects both serialized formats on MLX, so main latency is **unsupported**; dense MLX is included only as a runnable reference.

| dtype / rows | current main | packed median | geometric speed vs dense MLX | max abs error | max relative L2 |
| --- | ---: | ---: | ---: | ---: | ---: |
| FP16 / 1 | unsupported | 0.2613 ms | 0.9563x | 3.81e-6 | 9.11e-4 |
| FP16 / 16 | unsupported | 0.3043 ms | 1.0012x | 3.81e-6 | 1.05e-3 |
| BF16 / 1 | unsupported | 0.2564 ms | 1.0189x | 7.43e-6 | 3.75e-3 |
| BF16 / 16 | unsupported | 0.2997 ms | 1.0298x | 1.44e-5 | 2.06e-3 |

Across all 36 cases, packed 2-bit weights use 217.5 MiB versus 1740 MiB dense (8x reduction). Overall packed latency ranges were 0.2365–0.5183 ms (FP16) and 0.2176–0.5102 ms (BF16).
