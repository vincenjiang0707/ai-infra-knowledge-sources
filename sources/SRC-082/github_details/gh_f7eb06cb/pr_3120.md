## 正文

## Summary

Support GPTQ quantization of MiMo V2.6 Flash-RL and Pro-RL text decoders from
mixed MXFP4/FP8 checkpoints, extending the existing MiMo V2 definition and
module-local lazy materialization.

## What Changed

- Decode packed MXFP4 experts with E8M0 scales using existing floatx primitives.
  Reconstruct tensor-parallel FP8 QKV weights with their local scale padding
  and canonical Q/K/V ordering.
- Match source decoding to FP16/BF16 execution; reject incompatible explicit
  decoder dtypes and mixed-source AWQ before tokenizer/model construction.
- Apply mask compatibility within the MiMo modeling module, preserve MTP
  tensors and encoding metadata, and add CPU decoding/GPTQ/save/reload tests.

## Notes

Load with `trust_remote_code=True` and `QuantizeConfig`. This path forces disk
offload even when `offload_to_disk=False` is requested. Automatic source decoding
requires FP16/BF16; an explicit decoder dtype must match the model dtype. FP32
remains available for direct/offline source decoding. Quantize and reload through
GPTQModel so the MiMo mask adapter is applied.

MTP tensors retain their source encoding, recorded in
`mimo_mtp_source_quantization_config`; this does not enable MTP or multimodal
execution. These focused CPU results do not establish full-model quality, GPU
coverage, or memory/disk capacity. GPTQ starts from decoded, already-quantized
source weights.

### Qubitium · 2026-09-25 · CHANGES_REQUESTED

The MiMo CPU roundtrip fails on an Apple Silicon host when `dtype="auto"`: the loader chooses FP16 from the host MPS default even though `QuantizeConfig.device="cpu"`. With an explicit BF16 `AutoModuleDecoderConfig`, loading raises a dtype mismatch; without one, the decoder silently uses FP16. I reproduced both failing parameter cases in `tests/test_mimo_gptq_roundtrip.py` and fixed the source-path dtype selection to use the explicit quantization device.

Fix and regression test: https://github.com/ModelCloud/GPTQModel/commit/dcebe548201d3027bebc0d33a71ea0ef91af891d. Update: I pushed this commit directly to `peter-positron:feature/mimo-v26-mixed-source-gptq`, and it is now PR #3120's head. No cherry-pick is needed.
