## Summary

Add a native MLX Metal kernel for ParoQuant's calibration-time grouped Givens rotation stage on Apple silicon.

The new standalone primitive supports forward transformed-weight rotation and the inverse transform used to map export-domain weights back to input space. It keeps FP32 intermediates, validates pair schedules and finite/value boundaries, and is intentionally not wired into ParoQuant's Torch autograd optimizer in this PR.

## What Changed

- Added `paroquant_rotate_mlx` for rank-2+ FP16, BF16, and FP32 weights.
- Added grouped forward and inverse rotations for group sizes 16, 32, 64, and 128, with optional positive channel scales.
- Added explicit shape, dtype, finite-value, positive-scale, and local pair-permutation validation.
- Added an independent Torch arithmetic oracle covering:
  - FP16, BF16, and FP32 inputs
  - forward and inverse transforms
  - exact zero and quarter-turn angles plus one representable FP32 step on each side
  - rank-3 inputs and the no-channel-scale path
  - every Qwen3.8-27B Q/K/V/O, fused QKV/O, and MLP gate/up/down weight shape
  - quantize → pack → save/load compatibility with the merged ParoQuant MLX path
- Added a reproducible per-shape benchmark against `main`'s Torch ParoQuant rotation path.
- Follow-up intentionally out of scope: replacing the Torch autograd optimization loop. This PR is one method-stage/kernel only.

## Accuracy and Performance

Measured on Apple M5 Ultra, 256 GB, MLX 0.32.2, Torch 2.14.0. Inputs use Qwen3.8-27B BF16 weights, eight ParoQuant rotation stages, group size 128, and resident weight/theta/scale tensors. Timings are median of three measured calls after one warmup. MLX timings include public-API validation and pair-metadata preparation.

`outside 1e-6` counts outputs violating `abs_error <= 1e-6 + 1e-6 * abs(oracle)`. The normalized RMS value is `||MLX - Torch||₂ / ||Torch||₂`.
