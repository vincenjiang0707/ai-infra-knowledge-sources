## 正文

> # Adapted from the vLLM project's llm-compressor eager GPTQ update.

# Summary

- Reuse the Cholesky factor as the output buffer for `torch.cholesky_inverse` on CPU and CUDA. This removes one full Hessian-sized allocation during inversion.
- Keep the original Hessian intact for damping retries and diagonal restoration. NPU and other device paths retain their existing behavior.
- Add exact-factor and retry tests, plus a repeatable CUDA memory benchmark with an allocating reference and optional full quantization measurement.

# Memory results

NVIDIA GB10, PyTorch 2.14.0+cu132, float32 Hessians. Values below are peak **additional allocated** CUDA memory beyond tensors already resident before the measured call; inversion results use the maximum peak of three trials after warmup.

| Hessian | One matrix | Previous inversion | Reused buffer | Reduction |
| --- | ---: | ---: | ---: | ---: |
| 2048 × 2048 | 16 MiB | 64 MiB | 48 MiB | **16 MiB (25%)** |
| 4096 × 4096 | 64 MiB | 256 MiB | 192 MiB | **64 MiB (25%)** |

For the **full** 4096 × 4096 `GPTQ.quantize()` call, peak additional allocation was **322.1 MiB in both versions** (160.0 MiB resident beforehand). The inversion peak fell from 480.1 to 416.1 MiB total allocated, but a later quantization stage still reached 482.1 MiB. This change reduces inversion headroom; it does not reduce the measured full-call peak for this workload. No material runtime change was observed.

# Validation

- 221 related tests passed, 3 skipped, including eight new CPU/CUDA exact-factor and damping-retry cases.
- Inversion factors and restored Hessians matched the allocating reference bit for bit at 2048² and 4096².
- Full 2048² and 4096² quantization produced identical output tensor hashes and loss compared with the previous code.
