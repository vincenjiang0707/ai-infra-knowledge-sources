## 正文

## Summary

- add a native MLX Metal implementation of EXL3's block-of-32 RMS reduction
- support the two keep-dimension reductions used by regularization: per-column output scales (`axis=0`) and per-row input scales (`axis=1`)
- preserve EXL3's canonical float32 contract and reject nonfinite inputs
- keep this stage standalone and opt-in; this PR does not change processor orchestration
- add an independent Torch oracle, float32 boundary cases, zero/nonfinite coverage, and complete Qwen3.8-27B projection tests

This PR contains only the EXL3 RMS reduction. Hadamard transforms, tile layout, Viterbi search, and trellis packing remain separate kernels; regularization orchestration and LDLQ remain out of scope.

## Accuracy and performance versus main

Oracle/baseline: main's Torch blockwise implementation, independently reproduced with `torch.split(..., 32)`, float32 squaring, per-block sums, accumulated sums, division, and square root.

Acceptance requires combined `atol=1e-6, rtol=1e-6`, normalized RMS drift at most `1e-6`, and finite outputs. Complete outputs were compared for both axes of every Qwen3.8-27B projection. Checkpoint shapes use `out×in`; EXL3 internally operates on `in×out`.

Apple M5 Ultra, 256 GB, MLX 0.32.2, Torch 2.14.0. Timings are medians of 3 runs after warmup with inputs already resident. MLX timings include the public API's finite-input validation.

Observed ranges:

- maximum absolute drift: **2.98023224e-8–4.47034836e-8**
- normalized RMS drift: **4.88425736e-8–5.52492515e-8**
- speedup: **3.48×–10.49×**
- outputs outside tolerance: **0 in every row**

The nonzero differences are bounded floating-point reduction-order effects. They are approximately 18–20 times below the `1e-6` quantization threshold and do not indicate a changed scale selection rule.

Boundary fixtures cover signed zero, the adjacent float32 values on each side of zero, ±1 and their adjacent representable values, non-multiple-of-32 dimensions, an all-zero matrix, and nonfinite rejection. EXL3 converts weights to float32 before this stage, so BF16 is intentionally not accepted here.
