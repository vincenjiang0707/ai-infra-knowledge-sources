## Summary

- add `exl3_regularize_transforms_mlx`, a complete resident-MLX EXL3 transform stage
- reproduce EXL3 output-scale policy from the Hessian diagonal, including forced/fallback/all-zero behavior
- compose both native block-RMS reductions with output/input channel scaling and the two Hadamard transforms
- keep global-scale search separate because it already has its own native kernel and its full Torch CPU baseline is not runnable at Qwen scale without extrapolation
- add independent Torch and float64 oracle coverage, skew/zero/value-boundary tests, downstream 2/4/8-bit trellis checks, and all nine Qwen3.8-27B projection shapes

The larger per-element maxima are compounded natural float32 reduction/transform drift, not silently accepted quantization regressions. Downstream 2-bit and 4-bit reconstructed weights and trellis states are exact. At 8 bits, 57 of 16,384 states differ across two tiles; independent float64 adjudication shows the MLX result is better in both changed tiles and lowers total MSE from `0.0003439354152728463` to `0.0003439312291554561` (about `1.2171e-5` relative). The regression test requires every future differing tile to improve the float64 objective.
