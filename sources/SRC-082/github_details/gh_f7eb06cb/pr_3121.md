## Summary

Add the first native MLX quantization kernel in the one-kernel-per-PR rollout: GGUF `Q4_0` block packing. The companion plan inventories the remaining supported formats and method stages.

## What Changed

- Add a Metal kernel that packs 32 float values into the existing 18-byte GGUF `Q4_0` layout. It accepts 2D MLX weights and promotes float16, bfloat16, or float32 inputs to float32 for quantization.
- Add deterministic Torch-oracle A/B tests covering packed bytes, zero blocks, half-bin rounding boundaries, 32/256/512 input widths, and low-precision inputs.
- Check byte-for-byte compatibility with the repository's current GGUF quantizer and decoding through its existing GGUF runtime.
- Extend the repository's Torch-oracle skill and AGENTS guidance to require exact boundary, neighboring-ULP, signed-zero, clamp, scale-tie, and supported-dtype checks for changed packers and quantizers.
- Add [the kernel-by-kernel rollout plan](https://github.com/ModelCloud/GPTQModel/blob/feature/mlx-native-gguf-q4-0/docs/mlx-native-quantization-plan.md). This PR adds a standalone packing entry point; model-level MLX GGUF loading and inference are outside this kernel PR.

## Accuracy and performance

On Apple M5 Ultra, the tested packed bytes match the independent Torch oracle exactly. A separate 512×512 compatibility comparison against the current GGUF packer found **0 differing bytes in 147,456 bytes**. Review found and fixed float32 boundary-rounding and signed-zero scale-byte mismatches. The kernel now uses fused multiply-add boundary checks and preserves the first zero's sign. A 30,000-block boundary stress comparison then found **0 differing bytes in 540,000 bytes**. Discrete output acceptance is exact, per the repository's Torch-oracle skill.

For a 4096×4096 float32 weight matrix (524,288 GGUF blocks), with inputs already resident on each backend, 3 warmups and the median of 10 synchronized runs:

| Path | Median pack time |
| --- | ---: |
| Current main NumPy CPU GGUF `Q4_0` packer | 36.85 ms |
| Proposed MLX Metal `Q4_0` packer | 0.286 ms |

This is a **128.9× operation-level speedup** under the stated residency condition; it does not include host-to-device transfer or a full-model quantization pipeline.
