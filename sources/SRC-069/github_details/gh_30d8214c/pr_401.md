# [PR #401] feat(native): add standalone CUDA core

state: open | updated: 2026-08-07T08:23:07Z

## 正文

Edge deployment needs to link a runtime library without loading the Python wheel frontend, PyTorch, ATen, or pybind symbols.

- split CMake configuration so the Python extension and native core build independently
- expose a stable C ABI over opaque CUDA streams and row-major tensor views
- implement the NN GEMM path with CUDA Runtime and cuBLASLt only
- package the shared library and public header inside the wheel for build-time discovery and artifact copying
- retain the existing Python extension path as the default build

Recommendation: restore the reference implementation for CMakeLists.txt, csrc/native_api.h, csrc/native_api.cpp, setup.py; if per-stream state or a B^T-layout entry is genuinely required, land it as a separate MR with tests and a versioned ABI. The core PR items (independent CMake split, opaque-stream C ABI, CUDA Runtime + cuBLASLt-only GEMM, wheel packaging, Python-default build) are otherwise implemented correctly.

### v5
The MR delivers the standalone native core as described: CMake is split via DG_BUILD_PYTHON / DG_BUILD_NATIVE_CORE with the Python extension remaining the default; csrc/native_api.h exposes a stable C ABI over opaque cudaStream_t pointers and row-major tensor views; the GEMM path uses only CUDA Runtime + cuBLASLt APIs in code; setup.py builds the library via CMake and packages deep_gemm/lib/libdeep_gemm_native.so plus lib/include/native_api.h in the wheel, matched by package_data, while DG_SKIP_CUDA_BUILD and the default deep_gemm._C CUDAExtension path are retained. The core math was verified by inspection and is correct: for NN, row-major D[M,N]=A[M,K]@B[K,N] is mapped to column-major D^T = B^T (n x k, ld=b.row_stride, OP_N) times A^T (k x m, ld=a.row_stride, OP_N) into D^T (n x m, ld=d.row_stride); the NT compatibility entry ((k x n) layout with OP_T) is also correct, as are the transposed-aware shape/dtype validations. The revision commit fixes real defects from the first commit: true-NN semantics for gemm_nn (old A@B^T behavior preserved as gemm_nt), CUBLAS_COMPUTE_32F for FP16/BF16 (32F_FAST_TF32 is unsupported for 16-bit inputs), zeroing D when K==0 and accumulate==0 (previously left uninitialized), and per-device/per-stream cublasLt handle + workspace state with sound two-level locking (device-map mutex released before the per-stream mutex, unique_ptr-stable addresses, no cross-stream workspace sharing). Error handling never lets exceptions cross the C ABI and reports via a thread-local deep_gemm_native_last_error. Verified as acceptable design choices (no action requested): FP32 inputs use CUBLAS_COMPUTE_32F_FAST_TF32 consistent with the JIT cuBLASLt path in csrc/jit_kernels/impls/smxx_cublaslt.hpp; per-stream 32MB workspaces are never evicted and the g_cleanup static destructor releases CUDA resources at exit, both benign for the intended long-lived runtime usage. Remaining actionable findings are minor and listed as comments.
