## 正文

## Summary

Merges upstream `559d79f` (`#377`, Public release 26/07) into `nv_dev` at `a6b593d` (`#369`). This also brings in upstream `#364` and the race fix from `#343`; the merge base is `88965b0`.

The branch uses the same explicit non-fast-forward topology as the previous `nv_dev` sync PRs (`#314`, `#328`, and `#349`), keeping the upstream main commit as the merge commit's second parent.

B200 validation exposed two SM100 FP16-weight MQA synchronization gaps in the PTX-wrapper migration. Follow-up `96fbced` elects one lane for raw-PTX 2x1SM UMMA issue, waits for each CTA's local KV-scale TMA before consumption, and fences the TMEM producer/consumer handoff.

## Conflict resolution

- Adopted `#377`'s unified SM100 MQA and common MMA/PTX refactor while retaining nv_dev's SM90 `next_n=4` multicast and `block_kv=32`, dedicated SM120 paths, FP16/BF16 weights, and 16-head indexer support.
- Preserved metadata safety for empty/zero-context requests and made producer Q prefetch follow the scheduler's actual next task.
- Ported the FP16-weights path to the new headers, with padded host offsets, correct per-warpgroup row indexing, and per-row compressed-window bounds.
- Guarded the SM90 `block_kv=32` odd physical-page tail from reading one page past the block-table row.
- Combined upstream grouped scale-factor, PSUM, zero-padding, and Mega-MoE changes with nv_dev's SM120 dense/grouped GEMM dispatch.
- Merged and extended attention/GEMM/layout coverage for SM90, SM100, and SM120.

## Validation

Tests were run from isolated Docker worktrees on NVIDIA B200 GPUs (SM100):

- The final FP16-weight MQA fix passed a clean CUDA extension build/JIT.
- Core suites passed: `test_bf16.py`, `test_fp8_fp4.py`, `test_layout.py`, `test_einsum.py`, `test_legacy.py`, and `test_hyperconnection.py`.
- SM100 attention prefill passed all 1,824 generated cases. Each completed case includes 20 repeated bitwise-consistency checks plus mask and numerical-reference validation.
- Targeted SM100 FP16-weight MQA coverage passed head dimensions 32/64/128 with `CP=0/1`; the original H64/D32/CP0 failure passed 500 consecutive consistency runs.
- SM100 paged MQA passed all 6,624 generated configurations. The exhaustive matrix was completed across isolated resume shards with two-case overlaps at every interrupted handoff; each completed case includes 20 repeated bitwise-consistency checks plus mask and numerical-reference validation.
- Six-GPU Mega-MoE smoke runs passed for both `fp8xfp4` and `bf16xbf16`. The fused kernels launched and benchmarked successfully; the `deep_ep` baseline comparison was skipped because that module was unavailable in the image.
- All Git-tracked Python files pass `py_compile`; no unresolved conflicts, conflict markers, missing project-local includes, or references to removed headers were found.

GPU validation is SM100/B200 only. SM90 and SM120 GPU paths were not covered.

Three `git diff --check` warnings are inherited byte-for-byte from upstream `#377` (Mega-MoE trailing whitespace); the conflict resolutions and follow-up fix introduce no new whitespace warnings.
