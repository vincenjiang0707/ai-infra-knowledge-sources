# [PR #455] [Fix] SM90 heuristic offers block M 16/32 to the FP8 1D1D kernel (JIT failure for M <= 32)

## 正文

## Problem

On SM90, the layout heuristic (`csrc/jit_kernels/heuristics/sm90.hpp`) adds block M candidates of 16 and 32 when `m <= 32` for `Normal`, `Batched` and `KGroupedContiguous` GEMMs. The SM90 FP8 1D2D and BF16 kernels support these small tiles, but the SM90 FP8 **1D1D** kernel (used for FP32-output / weight-gradient GEMMs and for the k-grouped GEMM) only supports `BLOCK_M` of 64 or 128:

```
deep_gemm/include/deep_gemm/impls/sm90_fp8_gemm_1d1d.cuh(61): error: static assertion failed with "Invalid block size"
      static_assert(BLOCK_M % WGMMA::M == 0, "Invalid block size");
deep_gemm/include/deep_gemm/impls/sm90_fp8_gemm_1d1d.cuh(264): error: static assertion failed with "Invalid block sizes"
      static_assert(BLOCK_M == WGMMA::M * (BLOCK_M <= 64 ? 1 : 2), "Invalid block sizes");
```

For `m <= 32` the cost model always prefers the smaller tile (e.g. it picks `block_m=32, block_n=56` for `m=27, n=5744, k=7936`), so JIT compilation fails and the call raises. This affects, on Hopper:

- `fp8_gemm_nt(a, b, d, c=d)` with an FP32 `d` (the 1D1D wgrad path) whenever `m <= 32`
- `k_grouped_fp8_gemm_nt_contiguous` whenever `m <= 32`

Neither shape was covered by the tests (the wgrad shapes only use `m` from `nk_list`, all `>= 576`, and the k-grouped shapes all have `m >= 768`). Found with a randomized shape fuzzer on an H200.

## Fix

Only offer the 16/32 candidates to kernels that support them (`kernel_type != Kernel1D1D`). With the fix, the heuristic picks `block_m=64` for these shapes. Shapes with `m > 32` are unaffected, since the candidate list only changes when `m <= 32`.

Tests (`tests/generators.py`):

- Small-M weight-gradient shapes (`m in {16, 32}`, `n=4096, k=7168`, FP32 accumulate) in `enumerate_normal`. On SM90 they use the FP8 1D1D kernel and the BF16 kernel. On SM100 they should go through swap-AB.
- A small-M k-grouped shape (`num_groups=8, m=16, n=2048`) in `enumerate_k_grouped_contiguous`, enabled on SM90 only. 8 groups keep TMA multicast disabled, so this shape does not depend on the separate k-grouped multicast fix in #415 / #429.
