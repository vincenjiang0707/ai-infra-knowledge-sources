## 正文

## Summary

Issue #385 asks where the three SM120 cost-model constants came from and how to calibrate them. This PR adds a reproducible candidate sweep and documents each coefficient's role and origin in the 164-point SM120a sweep from `1383f15`.

No default constant changes are included. One GPU SKU is not enough evidence for global SM120 tuning.

Addresses #385.

## Changes

- add `DG_JIT_FORCE_LAYOUT=BMxBNxBK` for exact valid-candidate benchmarking
- add an SM120 FP8/BF16 calibration harness with correctness gates, randomized candidate order, steady/cold cache policies, nonnegative fitting, and held-out selection regret
- record raw timing samples, hardware/build metadata, feature rank, matrix conditioning, and timing dispersion in JSONL
- document `kCyPerTmaByte`, `kSyncBaseCy`, `kBlockOverheadCy`, calibration procedure, and cross-SKU limits

## Repro

```bash
python -m pip install numpy
./develop.sh
python scripts/calibrate_sm120_heuristic.py \
    --dtype fp8 \
    --cache-policy steady \
    --output sm120-fp8.jsonl
```

## Testing

- `PATH="$PWD/.venv/bin:$PATH" ./develop.sh`
- full FP8 sweep on RTX 5070 Ti: 39 auto/forced measurements, all within `0.001` correctness tolerance; maximum diff `0.0007362`
- full feature matrix rank `4`, condition number `10.42`; median relative MAD `2.69%`, maximum `7.38%`
- current constants held-out mean/max selection regret: `1.25%` / `3.74%`
- fitted local constants held-out mean/max selection regret: `2.20%` / `3.74%`
- forced BF16 candidate: diff `1.07e-8`
- `python -m py_compile scripts/calibrate_sm120_heuristic.py`
- `git diff --check`
- focused harness probes: NaN/Inf rejection, worker-record parsing, small-N candidate ordering, and `nvidia-smi` fallback
- SM120 BF16 auto/forced-layout smoke plus invalid-layout rejection


## Did this cause any problems?

Unset `DG_JIT_FORCE_LAYOUT` preserves existing selection. Revert this commit to remove calibration tooling and override.
