## 📌 Description

`BatchAttentionWithAttentionSinkWrapper` names its JIT module `batch_prefill_attention_sink_{dtype_q}_swa_{bool}_{backend}`. The name leaves out the KV dtype, the head dims, `pos_encoding_mode` and `use_fp16_qk_reduction`, although all of them change the generated sources. As a result, a BF16-KV wrapper and an FP8-KV wrapper share one cache directory, and each one rebuilds over the other's `.so`.

This PR builds the name with the existing `get_batch_prefill_attention_sink_uri`, the helper `aot.py` already uses for this variant. The helper now also encodes `pos_encoding_mode`, which it already took as an argument but ignored, and a new optional `use_fp16_qk_reduction`. Only the module name changes; the generated sources and nvcc flags are unchanged.

Measured on GB10 (SM121, unified memory), with q bf16, head_dim 128, window_left 1023, fa2. Each step ran as a fresh process on the same cache:

| Step | Before | After |
|---|---|---|
| FP8 KV, cache holds BF16 | rebuild: 10.9 s, peak compiler RSS 3911 MiB | builds its own module once: 10.1 s |
| BF16 KV after FP8 | rebuild: 10.9 s, peak compiler RSS 3816 MiB | no rebuild (0.02 s) |

Measured on 0.6.18.post1 with this diff applied; the naming code there is identical to main (ba87a55).

## Reviewer Notes

- The output of `get_batch_prefill_attention_sink_uri` changes, so the AOT module names for this variant change with it (`..._posenc_0_use_swa_{bool}_f16qk_False[_sm90]`). `aot.py` and the wrapper both go through the helper, so they stay consistent. The new parameter defaults to `False`, which keeps existing callers of the helper working.
- `tests/attention/conftest.py` now prebuilds the fa3 reference with `gen_batch_prefill_attention_sink_module`, so its name matches the wrapper's.
- The wrapper can now pick up the AOT-built sink modules: its spec matches `gen_batch_prefill_attention_sink_module` (same name, nvcc flags and rendered sources; checked on CPU for fa2/fa3 × fp16/bf16 × head_dim 64/128 × SWA on/off).
