## 📌 Description

<!-- What does this PR do? Briefly describe the changes and why they’re needed. -->

This PR adds out-of-place PCIe IPC all-gather and SUM reduce-scatter for
single-node tensor-parallel communication on PCIe systems. It provides
GPU-resident communication paths with topology-aware schedules and
shape-specific launch tuning.

Both operators reuse persistent CUDA IPC workspaces and synchronize through
GPU system-scope flags. Their steady-state paths avoid host-side collective
coordination.

- All-gather: flat push for TP4, recursive doubling for TP2/TP4/TP8, and a
  copy-engine path for supported TP8 topologies.
- Reduce-scatter: flat TP2/TP4 kernels and TP8 kernels that reduce within each
  four-GPU island before exchanging partial sums across islands.
- BF16, FP16, and FP32 support; contiguous rank-2 tensors; CUDA Graph
  capture/replay; optional caller-provided outputs and launch configurations.
- Correctness-checked tuning with exact-shape caching keyed by collective,
  dtype, world size, GPU placement, and workspace limits.

The code follows the existing PCIe IPC all-reduce integration pattern:
framework-independent CUDA headers, TVM-FFI bindings, JIT loading, workspace
APIs, launch policies, and focused unit tests. It also includes AOT registration
under `--add-comm`, per-rank `fi_trace` templates and examples, and API/design
documentation.

The new APIs are exposed through `flashinfer.comm`. Their Python implementation
and shared helpers live in `flashinfer.comm.pcie_ipc_collectives`.
All-reduce reuses the shared GPU UUID/NVML discovery and workspace lifecycle
helpers while retaining its existing public imports and module paths.
Operator-specific topology admission remains separate. The existing
all-reduce CUDA kernels and launch policy are unchanged.

### API example

Assuming an NCCL process group is initialized and each process has selected
its CUDA device:

```python
import torch
import torch.distributed as dist
import flashinfer.comm as comm

group = dist.group.WORLD
world_size = dist.get_world_size(group)
local_rows, hidden = 8, 6144
x = torch.randn(local_rows, hidden, device="cuda", dtype=torch.bfloat16)
reduction_input = torch.randn(world_size * local_rows, hidden, device="cuda",
                             dtype=x.dtype)

with comm.PcieIpcAllGatherWorkspace(group, x.numel(), dtype=x.dtype) as ag:
    gathered = ag.all_gather(x)  # [world_size * local_rows, hidden]

with comm.PcieIpcReduceScatterWorkspace(group, x.numel(), dtype=x.dtype) as rs:
    if rs.supports(reduction_input):
        shard = rs.reduce_scatter(reduction_input)  # [local_rows, hidden]
    else:
        shard = torch.empty_like(x)
        dist.reduce_scatter_tensor(shard, reduction_input)
```

The same API accepts `torch.float16` and `torch.float32`. Call
`workspace.tune([hidden])` collectively before capture to measure launch
configurations; otherwise the workspace uses cached configurations when
available and conservative defaults when not.

### Performance

Measured on **NVIDIA RTX 6000D**, with **BF16**, **TP2/TP4/TP8**,
hidden sizes **4096/6144**, and every power-of-two row count from **1 to
32768**: **192 shape points**, all passing correctness checks. These are
tuned PCIe IPC versus NCCL CUDA Graph microbenchmarks, not end-to-end model
measurements.

Software: PyTorch 2.13.0+cu130, CUDA 13.0, NCCL 2.29.7, and NVIDIA driver
580.95.05. TP2/TP4 use GPUs 0–1/0–3; TP8 uses the verified ordered 4+4 placement.

H4096 covers the text hidden size of both [DeepSeek-V4-Flash](https://huggingface.co/deepseek-ai/DeepSeek-V4-Flash/resolve/60d8d70770c6776ff598c94bb586a859a38244f1/config.json) and [GLM-5.3-Flash](https://huggingface.co/zai-org/GLM-5.3-Flash/resolve/eb9eb208eb0d988989d07a6a12d0fdeb5f52574a/config.json);
the same shape is measured once. Rows mean rank-local **AG input** rows or
**RS output** rows. BF16 shard sizes span **8 KiB–384 MiB** across the two
hidden sizes; full AG outputs and RS inputs are TP times larger.

PCIe IPC has a lower measured median at **192/192** points. Equal-point
geometric mean speedups are:

| Rows | Points | Geometric mean speedup |
|---|---:|---:|
| **1–32** | 72 | **2.81×** |
| 64–512 | 48 | 1.51× |
| 1024–32768 | 72 | 1.39× |
| All rows | 192 | 1.85× |

The full measured speedup range is **1.06–5.81×**. This is a median-based
result, not a claim that every sample is faster. TP8 has several variable
small-row points: in particular, AG/H6144/rows64 is near parity (1.06× in the
formal run, 1.04× in an independent same-config repeat). All 16 preselected
TP8 repeat points passed correctness and retained lower medians than NCCL;
those validation repeats do not replace any point below.

<summary>Self-contained BF16 benchmark reproduction</summary>

Save the following as `bench_pcie_ipc_example.py` and run it with this PR's
version of FlashInfer installed. It covers all-gather and reduce-scatter,
TP2/TP4/TP8, hidden sizes 4096/6144, and every power-of-two row count from
1 through 32768. Rows mean rank-local input rows for all-gather and
rank-local output rows for reduce-scatter.

Each hidden size uses a fixed workspace capacity of `32768 * hidden`
elements per rank-local shard. The PR tuner retains all legal candidates:
rows 1–512 use 10 warmups and 50 repeats per candidate; rows 1024–32768 use
1 warmup and 3 repeats. Tuning runs independently from formal measurement;
the latter loads its cache in a fresh process. The tuner times eager
launches, so this is not a per-shape oracle search under CUDA Graph timing.

Both backends use preallocated outputs, 20 operations per CUDA Graph,
5 configured warmup graph replays, and 20 measured samples, without L2
flushing. The shared timing helper additionally performs 3 eager warmups
and 5 estimation graph replays. Latency is the lower median of the
sample-wise maximum across ranks, in microseconds.

BF16 inputs are integers in [-8, 8], keeping every TP8 sum exactly
representable. Results are compared with NCCL before and after graph timing;
this does not imply general bitwise agreement between RS implementations.

```python
import argparse
import os

import torch
import torch.distributed as dist

import flashinfer.comm as comm
from flashinfer.testing.utils import bench_gpu_time

parser = argparse.ArgumentParser()
parser.add_argument("op", choices=("ag", "rs"))
parser.add_argument("--hidden", type=int, choices=(4096, 6144), required=True)
parser.add_argument("--rows", required=True, help="Comma-separated powers of two")
parser.add_argument("--cache", required=True, help="Shared tuning cache path")
parser.add_argument("--tune", action="store_true", help="Tune only, then exit")
args = parser.parse_args()
rows = tuple(int(value) for value in args.rows.split(","))
if not rows or rows != tuple(sorted(set(rows))) or any(
    row < 1 or row > 32768 or row & (row - 1) for row in rows
):
    parser.error("--rows must contain increasing unique powers of two up to 32768")
if min(rows) <= 512 < max(rows):
    parser.error("Run small and large rows in separate tuning/measurement stages")

rank, local_rank = int(os.environ["RANK"]), int(os.environ["LOCAL_RANK"])
torch.cuda.set_device(local_rank)
dist.init_process_group("nccl")
world_size = dist.get_world_size()
device, dtype = torch.device("cuda", local_rank), torch.bfloat16
timing = dict(use_cuda_graph=True, num_iters_within_graph=20,
              dry_run_iters=5, repeat_iters=20, cold_l2_cache=False)

def group_median_us(samples):
    counts = torch.tensor([len(samples), -len(samples)], dtype=torch.int64,
                          device=device)
    dist.all_reduce(counts, op=dist.ReduceOp.MAX)
    assert int(counts[0]) == -int(counts[1]) == 20
    times = torch.as_tensor(samples, dtype=torch.float64, device=device)
    dist.all_reduce(times, op=dist.ReduceOp.MAX)
    times *= 1000  # milliseconds -> microseconds, before torch's lower median
    return float(times.median())

def check_outputs(out, reference):
    correct = torch.tensor(int(torch.equal(out, reference)), dtype=torch.int32,
                           device=device)
    dist.all_reduce(correct, op=dist.ReduceOp.MIN)
    assert bool(correct.item()), "PCIe IPC result disagrees with NCCL"

workspace = None
try:
    cls = {"ag": comm.PcieIpcAllGatherWorkspace,
           "rs": comm.PcieIpcReduceScatterWorkspace}[args.op]
    workspace = cls(dist.group.WORLD, 32768 * args.hidden, dtype=dtype,
                    tune_batches=rows, tune_cache=args.cache)
    if args.tune:
        warmup, repeat = (10, 50) if max(rows) <= 512 else (1, 3)
        workspace.tune([args.hidden], cache=args.cache, warmup=warmup, repeat=repeat)
        raise SystemExit(0)  # finally still releases the workspace on every rank

    launch = workspace.all_gather if args.op == "ag" else workspace.reduce_scatter
    for row in rows:
        input_rows = row if args.op == "ag" else world_size * row
        output_rows = world_size * row if args.op == "ag" else row
        seed = (17 if args.op == "ag" else 29) + rank * 1009 + row * 31 + args.hidden
        generator = torch.Generator(device=device).manual_seed(seed)
        inp = torch.randint(-8, 9, (input_rows, args.hidden), device=device,
                            dtype=torch.int32, generator=generator).to(dtype)
        config = workspace.tuned_launch_config(inp)
        if config is None:
            raise RuntimeError(f"unsupported {args.op} TP{world_size} shape/placement")
        torch.cuda.synchronize(device)
        workspace.rebind_stream()
        out = torch.empty((output_rows, args.hidden), dtype=dtype, device=device)
        reference = torch.empty_like(out)
        custom = lambda: launch(inp, out=out)
        nccl = (lambda: dist.all_gather_into_tensor(reference, inp)) if args.op == "ag" else (
            lambda: dist.reduce_scatter_tensor(reference, inp, op=dist.ReduceOp.SUM))
        custom()
        nccl()
        torch.cuda.synchronize(device)
        check_outputs(out, reference)
        workspace.rebind_stream()
        dist.barrier()
        custom_samples = bench_gpu_time(custom, **timing)
        dist.barrier()
        nccl_samples = bench_gpu_time(nccl, **timing)
        torch.cuda.synchronize(device)
        check_outputs(out, reference)
        custom_us = group_median_us(custom_samples)
        nccl_us = group_median_us(nccl_samples)
        if rank == 0:
            print(f"{args.op} TP{world_size} H{args.hidden} rows={row}: "
                  f"NCCL={nccl_us:.2f} us, PCIe IPC={custom_us:.2f} us, "
                  f"speedup={nccl_us/custom_us:.2f}x; {config}", flush=True)
finally:
    if workspace is not None:
        workspace.destroy()
    dist.destroy_process_group()
```

Run on an otherwise idle single-node GPU system with the required peer
access. Use a new shared cache directory, and preserve the same physical
GPU placement between tuning and formal measurement:

```bash
set -euo pipefail
pcie_bench_run=$(mktemp -d -t fi-pcie-bench.XXXXXX)
for rows_csv in 1,2,4,8,16,32,64,128,256,512 1024,2048,4096 8192 16384 32768; do
  for tp in 2 4 8; do
    case "$tp" in
      2) pcie_bench_devices=0,1 ;;
      4) pcie_bench_devices=0,1,2,3 ;;
      8) pcie_bench_devices=0,1,2,3,4,5,6,7 ;;
    esac
    for hidden in 4096 6144; do
      for op in ag rs; do
        pcie_bench_cache="$pcie_bench_run/${op}_tp${tp}_h${hidden}.json"
        CUDA_VISIBLE_DEVICES="$pcie_bench_devices" \
          torchrun --standalone --nproc_per_node="$tp" \
          bench_pcie_ipc_example.py "$op" --hidden "$hidden" --rows "$rows_csv" \
          --cache "$pcie_bench_cache" --tune
        CUDA_VISIBLE_DEVICES="$pcie_bench_devices" \
          torchrun --standalone --nproc_per_node="$tp" \
          bench_pcie_ipc_example.py "$op" --hidden "$hidden" --rows "$rows_csv" \
          --cache "$pcie_bench_cache"
      done
    done
  done
done
```

The first launch is tuning-only; the second performs the NCCL comparison.
TP8 reduce-scatter requires the detected ordered 4+4 placement described
below. FP16/FP32 correctness support does not imply their performance matches
the BF16 results. This example is self-contained; no separate benchmark
package or scripts added by the PR are required.
