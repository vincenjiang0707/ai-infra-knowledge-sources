## 📌 Description

This POC builds on Yanqin's Frost integration in #5249 and improves prepared BF16 MoE execution in both the adapter and the source-distributed kernels. It preserves the paired tactic pool, numerical contract, and experimental admission policy, with coverage for repeated calls, changing CUDA Graph inputs, and small-shape boundaries.

Credit to Yanqin Zhai for the native adapter and source-distribution foundation, and to the cuDNN Frost, CuTe DSL, and CUTLASS contributors for the existing kernels. The incremental adapter and kernel scheduling changes here were developed and evaluated separately. Further kernel work adapts ideas from the CuTe DSL grouped-GEMM implementation, with credit to its contributors; the guarded adaptation and integration validation are specific to this POC.

## 🧪 Tests

- [x] Tests have been added or updated as needed.
- [ ] All repository tests are passing.

Target-GPU validation on SM107 passed all 87 BF16 cases in the declared file:

```bash
pytest -q tests/experimental/test_cudnn_frost_selected_kernels.py -k bf16
# 87 passed
```

This includes compound-tactic accuracy, model geometries, extended activations, CUDA Graph lifetime, public MoELayer dispatch/replay, and workspace reuse across the new shape boundaries. The public-layer tests deliberately select Frost to verify integration; they do not establish which backend an autotuner will select. Validation used Torch 2.14.0+cu130, a compatible CuTe DSL 4.8 development build, and CUDA 13.4. Quantized paths and the full repository suite were not run for this incremental change.

Focused device-memory `memcheck` and `initcheck` passed on both the prior revision and this revision, covering two model geometries, all offered paired tactics, and changing graph inputs. These isolated checks use a CPU numerical reference and disable CUDA API diagnostic reporting; unfiltered full-harness sanitizer reports also reproduce on the prior revision and are retained separately.

Existing mathematical-accuracy thresholds are retained. New scheduler variants were checked against a numerical reference and for bitwise agreement with the baseline across the offered paired tactics in two fresh-input studies. Previously identified stricter elementwise stress discrepancies remain a numerical qualification limit; this POC does not claim to resolve them.

## Reviewer Notes

This is an incremental draft for the parent PR's authors to evaluate and absorb. The studies use supported model geometries with synthetic inputs. The kernel study first selects the fastest baseline paired tactic on the actual inputs, then fixes that tactic and uses identical workspace/output addresses across implementations. Measurements and detailed experiment notes are retained privately; this PR does not claim full-model qualification.

The BF16 template changes are local prototype derivatives of the bundled Frost export. Manifest source hashes identify the derived code, while `producer_revision` retains original export lineage.
