## 📌 Description

I extended the existing `run(kv_len=...)` argument to non-causal FA3 plans. Callers can plan with host KV-length upper bounds and pass exact `int32` device lengths at execution time. This supports the sparse MLA consumer described in #5559 without copying exact lengths back to the host.

The attention kernel maps each work item's query offset to its request and clips `kv_len` and `kv_end` in place in registers. The host plan remains reusable as device lengths shrink and grow within the planned capacity. This adds no separate clamp kernel or per-work workspace allocation. Request lookup takes logarithmic time in batch size.

The existing native `run` entry point is preserved. A separate `run_with_kv_len` entry point receives device lengths and query offsets, and the SM90 JIT URI separates the updated module from cached binaries. Causal FA3 calls with runtime lengths receive an explicit error.

This PR is a draft during CUDA target-hardware validation.
