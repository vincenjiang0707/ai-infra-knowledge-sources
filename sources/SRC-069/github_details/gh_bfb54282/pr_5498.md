## 📌 Description

<!-- What does this PR do? Briefly describe the changes and why they're needed. -->

`gen_jit_spec()` in `flashinfer/jit/core.py` unconditionally passes
`--compress-mode=size` to nvcc. This flag was only introduced in CUDA 13.0
(the CUDA 13.0 release notes state that the fatbin default compression mode is
now equivalent to `--compress-mode=balance`). On toolchains older than CUDA
13.0 — e.g. CUDA 12.1, as reported in #5479 — every JIT build fails with

```
nvcc fatal : Unknown option '--compress-mode=size'
```

which currently breaks vLLM 0.29.0 users who get flashinfer 0.6.18 installed
automatically and have a CUDA toolkit < 13.0.

This PR gates the flag behind the existing `is_cuda_version_at_least("13.0")`
helper, mirroring:

- the pattern already used in this repository for `-static-global-template-stub`
  (CUDA >= 12.8) in `flashinfer/jit/cpp_ext.py`, and
- what vLLM itself does in its `CMakeLists.txt`: append `--compress-mode=size`
  only when `CMAKE_CUDA_COMPILER_VERSION >= 13.0`.

`-Xfatbin=-compress-all` is deliberately kept unconditional: it is a long-standing
fatbinary option (documented in the CUDA 12.4 `nvfatbin` reference and already in
use in CUDA 8-era builds), so it does not need a version gate.

1. **Fail-safe on unqueryable compiler** - `is_nvcc_at_least` no longer falls back to `is_cuda_version_at_least`; it now returns `False` when the selected nvcc cannot be queried, so we never attach `--compress-mode=size` to a compiler we couldn't actually verify.
