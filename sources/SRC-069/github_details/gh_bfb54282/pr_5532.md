## 📌 Description

FlashInfer currently exposes MoE expert-parallel (EP) communication through several unrelated entry points. `flashinfer.comm.MoeAlltoAll` is the NVLink one-sided wrapper, and since #4784 it has become an umbrella over a `backend="trtllm" | "cake"` switch. `flashinfer.comm.MnnvlMoe` is the NVLink two-sided path. `flashinfer.moe_ep` has the NCCL-EP / NIXL-EP `Fleet`/`Handle`. A MoE layer has no common interface to program against.

This PR adds that interface under `flashinfer.moe_ep`. It follows the layering TensorRT-LLM uses in `fused_moe/communication`: one MoE-level abstract class, with each transport specializing it. This is the interface-only step: no kernel changes. Porting the updated NVLink one-sided kernels from TRT-LLM will be a follow-up PR on top of this interface.

### Layering

```
MoEEpCommunication                 (core/comm/communication.py)  MoE-level dispatch/combine
├─ NVLinkOneSidedAlltoAll     wraps flashinfer.comm.MoeAlltoAll; Cake = NVLinkOneSidedConfig(kernel="cake")
├─ NVLinkTwoSidedAlltoAll     wraps flashinfer.comm.MnnvlMoe
└─ NcclEpCommunication             wraps the NCCL-EP Fleet/Handle (LL RANK_MAJOR)
Fleet / Handle                     transport-level API of NCCL-EP / NIXL-EP (unchanged)
```

Cake is not a separate communication algorithm. It uses the same one-sided protocol and workspace ABI as the trtllm kernels, so it is a kernel option of the one-sided backend rather than a sibling of it.

### Contract (rank-major), shared by every backend

- `dispatch(hidden_states, topk_ids, topk_weights, *, hidden_states_scale=None, max_tokens_per_rank=None, eplb_local_stats=None)` returns `ep_size * tokens_per_rank` receive rows with **global** top-k ids. Rows that carry no token have `invalid_expert_id`; picks owned by other ranks are either their global id or `invalid_expert_id`.
- The expert computation applies `topk_weights` and reduces over this rank's local experts.
- `combine(expert_output, *, output=None)` sums each token's per-rank results on its source rank.
- `get_combine_input_buffer(dtype)` is optional; it returns a zero-copy combine buffer (one-sided).
- Backend-specific differences are normalized inside each backend:
  - two-sided marks padding with `num_experts`, which is remapped to `invalid_expert_id`;
  - NCCL-EP reports local ids and leaves padding rows unwritten, so the backend maps local ids to global and invalidates padding rows using the per-source counters.

Backends register through `register_communication` and are created with `create_communication(bootstrap, MoEEpCommParams(...), backend=<config>)`.

### `MoEEpSplitLayer` integration

`SplitConfig(comm=NVLinkOneSidedConfig())` (or `NVLinkTwoSidedConfig()`) runs dispatch → split kernel (`identity` / `fused_moe`) → combine through the new interface. It requires `FleetParams(algorithm=LOW_LATENCY, layout=RANK_MAJOR)`. `nccl_ep` / `nixl_ep` keep their existing Fleet path unchanged. The communication path is eager-only for now; graph states and CUDA-graph capture through the layer raise a clear error.

### Compatibility

- No public API is removed or deprecated. `MoeAlltoAll`, `moe_a2a_*`, and `MnnvlMoe` are the kernel-level primitives the new backends build on, and external frameworks depend on them. They get a docstring / `docs/api/comm.rst` pointer to the new layer.
- `Fleet`/`Handle` stay public. Everything that falls outside the rank-major contract stays available through them:
  - EXPERT_MAJOR and HT FLAT layouts,
  - split send/recv staging,
  - persistent handles for CUDA graphs,
  - fault-tolerance masks.

  NIXL-EP (EXPERT_MAJOR only) therefore has no `MoEEpCommunication` specialization yet.

### Benchmark

`benchmarks/comm/bench_moe_ep_comm.py` times `dispatch()` / `combine()` of any `MoEEpCommunication` backend under torchrun (`nvlink_one_sided`, `nvlink_one_sided_cake`, `nvlink_two_sided`, `nccl_ep`):

- sweeps local batch sizes over model profiles (DeepSeek-V3/V4, GPT-OSS, Kimi-K3, ...), with optional balanced routing (`--perfect_router`);
- replays warmup and timed iterations in one CUDA graph; backends that cannot be captured (`supports_cuda_graph=False`, currently NCCL-EP) run eagerly;
- flushes L2 between iterations;
- reports per-phase CUPTI kernel spans with an optional per-kernel breakdown, falling back to CUDA events when CUPTI is unavailable.

Activations are quantized to the dispatched format (BF16 / FP8 / MXFP8 / NVFP4) by self-contained PyTorch reference quantizers outside the timed region, so the benchmark does not depend on any MoE kernel.

```bash
torchrun --standalone --nproc-per-node=8 benchmarks/comm/bench_moe_ep_comm.py \
    --backend nvlink_one_sided --profile deepseek_v3 -b 1 -e 1024 -f 2
```
