## 正文

## Summary

Regenerates the SM100a and SM103a BF16 KDA prefill modules (`csrc/kda/bf16/`, `flashinfer/jit/cake_kda_tf32.py`) from Cake revision `1791cd70ec4`, which fixes the unbounded-softplus (Kimi-Linear, `lower_bound=None`) decay path of the fused M128 schedule.

sgl-project/sglang#34299 replayed 600 real Kimi-Linear-48B prefill calls through `prepare_bf16_kda_prefill`: the per-64-token recurrent-state error of the exported `fused_unbounded_softplus_direct_m128` kernel reached **0.42 rel L2** against an FP32 recurrence while Triton stayed at 0.002. Real gates `-exp(A_log) * softplus(g + dt_bias)` reach -60 to -800 log2 per token on 1-19% of the key columns, and the schedule split every intra-chunk decay around one half-total anchor with exponents clamped at +-126, so pairs inside a saturated band decayed by 1 and the restore multipliers flushed to zero.

The new schedule floors each per-token log2 gate at -15 before the prefix scan (exact total kept for the state decay), anchors two 16-token tiles per column on integer powers of two published before the pairwise MMAs, rescales the cross-tile `ldmatrix` fragments exactly with packed BF16 powers of two, and restores per tile through integer exponent bits with a warp-uniform below-normal path.

## What changes

- The four unbounded fused-M128 modules per arch change content and get new module ids; the superseded module sources are removed (`export_bf16.py --replace-existing`, as in #5370).
- The remaining module sources differ only in generated uid suffixes / brace scopes; bounded-gate kernels are unchanged in behaviour.
- No Python API change.

## Validation

All 346 exported shapes replayed source-vs-export with `validate_bf16_export.py --triton` (4 GPUs per arch), plus `tests/kda/test_bf16_one_wave_route.py` and `tests/kda/test_tf32_prefill.py`:

|---|---|---|---|---|---|---|---|
| sm_100a (B200, 148 SMs) | 346 / 346 | 0 | 346 | 1.000 / 1.046 | 1.08 / 3.33 / 12.82 | 10, all bitwise | 31 passed |
| sm_103a (GB300, 152 SMs) | 346 / 346 | 0 | 346 | 1.000 / 1.035 | 1.09 / 3.35 / 12.75 | 10, all bitwise | 31 passed |

The ten unbounded rows run at 0.95-1.02x of the source kernel and 1.08-3.91x faster than Triton on both arches.

Real Kimi-Linear-48B activations (600 prefill dumps, 42 GB, GB300) replayed through the regenerated export via the SGLang adapter (`sgl-project/sglang#34299`): Cake-vs-Triton final-state rel L2 median 0.0046 over the 600 calls. Against an FP32 chunked recurrence (360 calls up to 1600 tokens, 600 sequences) the Cake final-state error is median 0.0025 / p95 0.0090 / max 0.0213 and the per-chunk checkpoint error max 0.0213, versus Triton `chunk_kda` at median 0.0009 / p95 0.0055 / max 0.340. The previous export measured 0.42 on the same layer-0 calls. The three short calls where Cake and Triton differ by more than 0.1 are Triton off the reference (0.34 / 0.24 / 0.11) with Cake at 0.003.

**Residual limitation (long sequences):** on 8K-token calls the Cake final-state error against the FP32 reference is 0.030-0.048 versus 0.0018 for Triton; the per-chunk checkpoint error grows ~2^-9 * sqrt(chunks) because the fused schedule carries the recurrent state between chunks in BF16 (Triton keeps that math in FP32). Up to ~2K tokens the error is the same order as Triton (0.0025 vs 0.0009 median). The previous export measured 0.019 median / 0.42 max on the same long calls; this PR brings them to 0.011 / 0.049. An FP32 state carrier is a separate change.
