## Summary

Performance follow-up to #5525 for the MiniMax-H3 direct-layout output projection + gated residual operator (`flashinfer.diffusion_ops.minimax_h3_out_proj*`, SM100 / SM103). No API, layout or numerics change; the regenerated device sources carry three measured schedule changes:

- **NVFP4 activation quantization pass**: 14 independent 16-byte loads in flight per lane with two warps per activation row (each warp quantizes 14 of the 28 vector steps). The pass runs at 75-80 % of HBM bandwidth and is 5-6 % faster on B200 and B300; the E2M1 values and UE4M3 scales are bit-identical to `nvfp4_quantize`.
- **NVFP4 GEMM raster group 16 -> 8**: +1-2 % on both GPUs (M = 4824 .. 109952), bit-exact output.
- **MXFP8 / NVFP4 epilogues drain the accumulator in 64-column chunks** (was 32): +0.4-1.0 % on B200, +0.2-0.7 % on B300, bit-exact.

The BF16 device code is unchanged apart from the shared quantization-kernel row-split plumbing (`ROW_SPLIT 1`, same instruction stream); MXFP8 changes only in the epilogue drain chunking. The B200 and B300 measurements behind the change, a per-shape ceiling model (roofline + bare library GEMM) and a ledger of the levers that were measured and closed on both GPUs (epilogue L2 prefetch, evict-last weight hints, 16 / 4 epilogue warps, TMEM load chunking, 128-bit stores, pipeline / work-ring depths, alternate raster groups, PDL off) are recorded in the internal design note; the round-4 conclusion is that the remaining gap to the bare GEMM is the power cap shared with the vendor GEMMs, the quantization pass and the epilogue's residual / output traffic.

## Correctness

- 47 shapes (24 production centers, 16 aligned / +-1-row tails, 7 small-M smoke rows) x 3 variants x 2 GPUs, zero violations under `|d| <= 1e-2 + 1e-2*|ref| + 2 ulp_bf16(|ref|)` against an FP32 oracle; invalid gate indices reproduce the residual bit-exactly.
- Quantized activations bit-exact against `mxfp8_quantize` / `nvfp4_quantize`.
- `tests/diffusion_ops/test_minimax_h3_out_proj.py` passes on B200 (sm_100a) and B300 (sm_103a) from this branch (JIT build, source checkout).
- `compute-sanitizer --tool synccheck` and `--tool memcheck`: 0 errors, both GPUs.
