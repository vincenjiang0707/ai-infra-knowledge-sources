## 📌 Description

On RTX 5090, several public Triton GEMM paths fail before launch because their three-stage configuration exceeds SM120's 99 KiB shared-memory limit ([NVIDIA documentation](https://docs.nvidia.com/cuda/archive/13.1.0/blackwell-tuning-guide/index.html)). The FP32 pointer kernels require 131072–147456 bytes in the tested configuration; the default FP16/BF16 descriptor kernel requires 131096 bytes, versus the device's 101376-byte limit.

Select fewer stages only for the affected SM120 input/output/epilogue combinations. The full FP32 TMA epilogue needs one stage; the other affected combinations fit with two. Preserve three stages for existing working combinations, including FP8 outputs, and for other architectures.

The pointer kernels' autotuners each contained just one configuration. Move those fixed tile/warp arguments into the existing Python launchers so stage selection can use the tensor's device and dtype, without adding profiling of an in-place C operation. Public wrapper signatures and the GEMM computation are unchanged.

A global three-to-two-stage change was rejected after it slowed the working 1024³ naive FP8 path by about 20%. The selective configuration retains its original timing.

## 🔍 Related Issues

Related to the SM120 resource failures reported during review of #4725. This resource failure is also reproducible on main; this PR does not include or replace that author's separate beta=0/uninitialized-C fix for #4724.

<summary>Minimal benchmark reproducer (run on each checkout)</summary>

```python
import statistics
import torch
from flashinfer.testing import bench_gpu_time
from flashinfer.triton import sm_constraint_gemm as g

torch.manual_seed(120)
for size in (256, 1024, 2048):
    for dtype in (torch.float16, torch.bfloat16, torch.float32, torch.float8_e4m3fn):
        a = (torch.randint(-3, 4, (size, size), device="cuda").float() / 16).to(dtype)
        b = (torch.randint(-3, 4, (size, size), device="cuda").float() / 16).to(dtype)
        bt = b.T.contiguous()
        out_dtype = torch.bfloat16 if dtype == torch.float8_e4m3fn else dtype
        for name in ("gemm", "gemm_persistent", "gemm_descriptor_persistent"):
            if name == "gemm_descriptor_persistent" and dtype == torch.float32:
                continue  # Unsupported by the existing descriptor API.
            c = torch.zeros((size, size), device="cuda", dtype=out_dtype)
            fn = getattr(g, name)
            rhs = bt if name == "gemm_descriptor_persistent" else b
            try:
                run = lambda: fn(a, rhs, c=c)
                run()
                torch.cuda.synchronize()
                torch.testing.assert_close(c, (a.float() @ b.float()).to(out_dtype), atol=0, rtol=0)
                ms = bench_gpu_time(run, dry_run_iters=10, repeat_iters=30,
                                    use_cuda_graph=True, num_iters_within_graph=20,
                                    cold_l2_cache=False)
                print(size, dtype, name, statistics.median(ms) * 1000, "us")
            except Exception as exc:
                print(size, dtype, name, type(exc).__name__, str(exc))
```

## Reviewer Notes

The selector is intentionally limited to CC (12, 0). H100/B200 keep the old tile/warp/stage arguments, but were not available for hardware validation; SM121 is outside this patch's tested scope. Upstream CI on other architectures is still needed.

Please focus on the stage-selection boundary and moving the single-entry autotune configuration into the launchers. No new backend or kernel arithmetic is introduced. AI-assisted implementation and testing; the stage/output-dtype choices above were validated on the actual GPU.
