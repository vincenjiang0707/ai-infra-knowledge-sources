## 📌 Description

Repeated cuDNN attention execution rebuilds Python UID-to-tensor mappings even when a wrapper has already planned its binding layout. Decode and planned ragged/paged prefill now keep the immutable UID order with their plan and pass fresh tensor sequences to the optional `graph.execute(..., tensor_uids=...)` overload.

The same FE execution contract serves native cuDNN backend and FROST plans. FI does not inspect the selected provider or use a backend-specific prepared object. FE still observes the current tensors and validates their effective layouts; FI keeps its existing compatibility, replan, workspace and output/LSE checks. Older FE installations use the existing mapping path, without a minimum-version bump.

ComputeLab B200 (1000 W), cuDNN 9.27, released CuTe DSL 4.7.1, Torch 2.13. Complete warm wrapper CPU enqueue in µs, paired mapping/ordered calls on the same plan:

| Provider / BF16 workload | Output contract | Mapping | Ordered |
|---|---|---:|---:|
| Backend decode B1, KV1024 | Fixed O, no LSE | 34.58 | 29.11 |
| Backend decode B1, KV1024 | Allocate O/LSE, log2 NH | 50.66 | 44.13 |
| Backend ragged prefill 512 | Fixed O, no LSE | 34.45 | 30.02 |
| Backend ragged prefill 512 | Allocate O/LSE, ln NH plus view | 46.43 | 41.71 |
| FROST ragged prefill 512 | Fixed O, no LSE | 53.83 | 45.45 |
| FROST ragged prefill 512 | Allocate O/LSE, ln NH plus view | 69.08 | 59.55 |

Hq/Hkv=32/8, D128; prefill is B1 causal Q=KV512; decode uses page size 16. Ten paired ABBA blocks × 80 samples per arm segment; planning/synchronization excluded. The full 18-case matrix covers ragged 32/512/4096, decode B1/B16 and FP16 ragged 512, with post-timing reference and changed-input CUDA Graph replay checks. GPU kernels are unchanged; no plan+run or model latency claim. FROST uses the existing Python binder in both arms.

The FE cache retains the most recent geometry. In a separate shared-envelope two-wrapper diagnostic, alternating actual geometries reduced paired host savings to 1.17 µs backend / 5.63 µs FROST, compared with 4.50 / 9.86 µs for repeated geometry.

## Reviewer Notes

The wrapper owns static metadata and ordered binding templates. Every execution creates a call-local tensor sequence, so runtime Q/K/V/O/LSE pointers cannot become stale or leak between wrappers sharing an envelope graph. FI does not bypass FE validation or retain runtime tensors in a generic graph cache.

Feature detection happens outside the warm execution path. A missing or uninspectable overload selects the original mapping transport; failures from a supported overload propagate rather than silently falling back. Please review optional LSE/sink binding order and capture/replan ownership. Ordinary CI may use an older FE, so the companion-FE GPU run separately verifies that the ordered path is exercised.
