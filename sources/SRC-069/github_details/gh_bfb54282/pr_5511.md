## 📌 Description

Since #5482, `tests/utils/test_cake_sampling.py::test_build_targets_follow_flashinfer_cuda_arch_list` asserts that `FLASHINFER_CUDA_ARCH_LIST="10.7 11.0"` yields `compute_107a`. `CompilationContext.get_nvcc_flags_list` rewrites `10.7` to `sm_100f` whenever the local nvcc cannot emit `compute_107`, which is every CUDA 12.x toolkit. The GitHub `JIT Unittest (H100)` lane runs the cu129 image, so this one node has failed on every PR merged with `main` since #5482 landed (evidence in #5510: two unrelated PRs, identical node and diff, everything else green).

The test is about which targets are named, not about the toolkit on the test host, so this pins `_nvcc_supports_sm107` to `True` with `monkeypatch` for the test's duration and documents why. No library code changes.

## 🔍 Related Issues

Fixes #5510. Follow-up to #5482.
