### qsang-nv · 2026-08-17

### `use_transform_kv` + split-head-dim K/V paths are unreachable in validated profiles

`use_split_head_dim_kv` is defined as `cfg.use_keeps_mma_ab and (...)` (`fmha_decode_kernel.py:376`), and `_validate_profile_support` now rejects `use_keeps_mma_ab and use_transform_kv` ("transform-KV is not supported with KeepsMmaAb for now"). So for **every configuration accepted by `make_decode_config()` / `_validate_profile_support`**, `use_split_head_dim_kv and use_transform_kv` is `False`. Consequently, the newly added split-transform branches are unreachable, while several adjacent conditions, parameters, and resource implementations are redundant or unusable in validated profiles:

- `fmha_decode_kernel.py:1081` — in `elif use_split_head_dim_kv and not cfg.use_transform_kv:`, the added `and not cfg.use_transform_kv` conjunct is always true whenever `use_split_head_dim_kv` is true, so it is a no-op.
- `fmha_decode_kernel.py:1242` — `elif cfg.use_transform_kv and use_split_head_dim_kv:` the whole ~35-line `resource_dependency_graph` branch never executes.
- `fmha_decode_kernel.py:1349` — `if not use_split_head_dim_kv or cfg.use_transform_kv:` the second disjunct is redundant.
- `fmha_decode_tasks.py` — `create_transform_kv_task` is only called in transform mode, where `smem_kv` is always non-`None`, so `use_split_sources` is always `False` and `transform_split_kv_schedule` / `source_for_label` / the `smem_k0/k1/v0/v1` parameters and their `ValueError` guard are all dead.
- `smem_transformed_kv.py` — the four `src_smem_k0/k1/v0/v1` fields and the source selection in `_transform_load` are unusable for the same reason.
- `smem_resources.py` — the entire NVFP4 scale-factor support added to `SmemKvTileResource` (`_sf_alloc`, `_smem_base_kv_sf`, `_sf_stage_base`, and the `use_nvfp4_kv` branch in its `_producer_load`) is unreachable: that class is only instantiated in the Keeps split-resource topology, and NVFP4 always requires transform.

That's roughly 150+ lines that no supported-profile test can exercise. This isn't a runtime correctness bug on any currently supported path, but it is a maintainability/testability problem worth resolving before merge. My preference is to drop this forward-looking code now and add it back together with the Keeps work; the alternative is to fully enable and validate KeepsMmaAb transform-KV support in this PR, with test coverage — note that simply deleting the last validation check would not be enough.

Separately, could you rebase onto current `main`? #4413 has landed, so the rebase should reduce this PR to the mixed-precision commit alone.
