### qsang-nv · 2026-09-23

**Blocker: values XQA can never reach take part in the pairwise selection — only 6 of the 187 selected cases survive the known XQA skip conditions.**

`backend` is fixed to `"xqa"` here, so `non_contiguous_query=True` (skip in this file), `skips_softmax=True` (`test_trtllm_gen_attention_decode.py:662`), `uses_shared_paged_kv_idx=False` (`:678`), `q_dtype="fp8"` (`:674`, 5 of the 11 dtype tuples) and any `nvfp4` dtype (`:671`, `:688`) are always skipped. `pairwise_product_cases` does not see those skips and counts the pairs those rows carry as covered.

```
--full  : 71808 selected ->  4896 survive
regular :   187 selected ->     6 survive
```

The six survivors share one value on every binary axis, so no surviving row uses `kv_layout="NHD"`, `head_dim=128`, `window_left=127`, `enable_sink=True`, or a bf16-query dtype tuple. 421 of the 583 reachable pairs (72%) are left uncovered.

The selector guarantees pairwise coverage before skip filtering, not among XQA-reachable cases; its modular filler also correlates unpinned binary axes. With this matrix and greedy selection, filtering out unreachable rows leaves the coverage above.

Numbers are a static replay of `pairwise_product_cases` (main `1ee3aee`) over the matrix in `182ae3c`, not a test run.
