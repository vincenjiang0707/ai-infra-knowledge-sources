## Overview
<!-- Describe what this PR does and why. Be concise but complete -->
Route eligible CPU FLASH_ATTN_EXT QK and AV tile products through the selected KleidiAI F32 SME2 kernel.

Keep KleidiAI-specific workspace sizing, packing requirements, and kernel dispatch behind the KleidiAI integration interface. Query the opaque workspace requirement once per Flash Attention operation and reuse it during dynamic chunk processing.

Pack Q once for the lifetime of each query tile instead of repacking it for every KV tile. Associate RHS packing with the selected kernel descriptor so that packed data remains compatible with its kernel layout.

Use ggml_vec_acc_f32() for AV accumulation and retain simd_gemm() for unsupported shapes, unavailable kernels, disabled SME, and builds without KleidiAI.

Flash Attention semantics and -fa auto selection remain unchanged.

Add focused FLASH_ATTN_EXT tests covering tile boundaries, asymmetric QK and AV dimensions, grouped heads, masks, attention sinks, soft-capping, and fallback configurations.

Validation:
- KleidiAI with SME enabled: 5/5 focused tests passed
- KleidiAI with SME disabled: 5/5 focused tests passed
- KleidiAI compiled out: 5/5 focused tests passed
- Android arm64 cross-build completed successfully

## Additional information
Performance measured on a Vivo X300 with Gemma-4 E2B Q4_0, pp512, Flash Attention enabled, comparing SME2 enabled against disabled:
- 1 thread: 55.676 to 86.197 tokens/s (+54.82%)
- 2 threads: 76.133 to 121.105 tokens/s (+59.07%)
- 4 threads: 122.923 to 165.301 tokens/s (+34.48%)
- 8 threads: 171.719 to 202.341 tokens/s (+17.83%)

The performance measurements were collected from the reviewed implementation  before its latest-upstream port.
