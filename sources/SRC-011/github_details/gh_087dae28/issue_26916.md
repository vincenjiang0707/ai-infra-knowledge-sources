# [Issue #26916] Eval bug: Qwen3.5-Hybrid model (qwen3_5, SSM+Attention) fails to load — "tensor 'blk.32.attn_norm.weight' not found"

## 正文

### Model
[ShaoShuai0605/Harness-R1](https://huggingface.co/ShaoShuai0605/Harness-R1) — 9B, `qwen3_5` architecture (Qwen3.5 hybrid SSM+Attention, mixed with regular attention layers at a fixed interval).

### Steps to reproduce
1. Convert with `convert_hf_to_gguf.py` from the `ghcr.io/ggml-org/llama.cpp:full` image (needed `transformers` installed from `git+https://github.com/huggingface/transformers.git` — the PyPI release doesn't recognize the `qwen3_5` architecture yet). Conversion to F16 completes successfully, writes 427 tensors across what the log reports as 32 transformer blocks (`blk.0`–`blk.31`).
2. Quantize to Q4_K_M with `llama-quantize` (same image) — completes successfully, all 427 tensors processed without error.
3. Load the resulting GGUF with `llama-server` (or `llama-cli`) — fails immediately:
```
check_tensor_dims: tensor 'blk.32.attn_norm.weight' not found
llama_model_load_from_file_impl: failed to load model
```

### Notes
- Reproduced identically on two llama.cpp builds: `b10290` and a fresh self-built `b10360` (today's latest tag as of this report) — not a stale-build issue.
- The GGUF metadata includes `qwen35.nextn_predict_layers = 1` alongside the 32 regular transformer blocks. My guess (not verified against the source) is that the loader computes an expected layer count that includes this NextN/MTP layer (`n_layer + 1` → expects `blk.32`), while the converter only writes tensors for the 32 "real" transformer blocks — a mismatch between what the converter emits and what the loader expects for this specific architecture's NextN handling.
- Relevant metadata dump:
```
qwen35.nextn_predict_layers u32 = 1
qwen35.ssm.conv_kernel u32 = 4
qwen35.ssm.state_size u32 = 128
qwen35.ssm.group_count u32 = 16
qwen35.ssm.time_step_rank u32 = 32
qwen35.ssm.inner_size u32 = 4096
qwen35.full_attention_interval u32 = 4
```
- Happy to provide the full metadata dump, the exact `convert_hf_to_gguf.py`/`llama-quantize` commands used, or test a patch if that's useful.

### CISC · 2026-08-12

If the model does not include MTP layers it must say so in it's config (`mtp_num_hidden_layers` must be 0), this is a model issue.

You can work around it with `--no-mtp` though.
