# [PR #29496] server : report usage across all choices when n > 1

source: https://github.com/ggml-org/llama.cpp/pull/29496
state: open | updated: 2026-09-26T20:14:25Z
labels: server

## 正文

The OAI-compatible /v1/chat/completions and /v1/completions responses of a request with n > 1 were built by merging the `choices` of the per-choice results into the first one, but the `usage` object of the first result was kept as-is. As a result `usage.completion_tokens` (and `total_tokens`) counted the tokens of a single choice instead of the sum over all choices. In streaming mode every choice emitted its own usage chunk, each again with a single choice's count. Requests with several prompts in /v1/completions also only reported the prompt tokens of the first prompt.

Add a small `server_task_result_usage` aggregator that sums `n_decoded` over every choice and counts the prompt tokens once per input (the n_cmpl choices of one prompt share it, and their results have consecutive indices starting with the parent task). Use it for the non-streaming merged response and, in streaming mode, drop the per-choice usage of all but the last final result, which then carries the usage of the whole request. Single-choice requests are unchanged.

Add regression tests for both endpoints, in streaming and non-streaming mode.

Fixes #29451
