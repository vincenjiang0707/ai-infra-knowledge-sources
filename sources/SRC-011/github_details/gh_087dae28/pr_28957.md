# [PR #28957] CUDA: bitonic argsort handles rows wider than one block

source: https://github.com/ggml-org/llama.cpp/pull/28957
state: open | updated: 2026-09-27T09:34:44Z
labels: ggml, CUDA

## 正文

## Overview

Fix argsort on HIP and MUSA builds for rows wider than 1024. Without CUB the bitonic kernel launched one thread per padded column, so a 2048 wide argsort aborted with an invalid block configuration. Nothing in-tree sorts rows that wide, it is a ggml level fix for downstream projects that do, such as qwentts.cpp.

## Additional information

Each thread now owns several columns and the block is capped at 1024 threads, shared memory becomes the only bound and supports_op checks it against the device. Rows up to 1024 run the same work as before, CUDA still switches to CUB above 1024. Bit-exact against CUB on NVIDIA with the bitonic kernel forced on rows of 2048, and tested on ROCm by the reporter of https://github.com/ServeurpersoCom/qwentts.cpp/issues/33 on a Radeon 780M.

No new test: the already existing argsort cases at 1025, 2047 and 2048 columns were skipped on HIP as unsupported, they now run on the ROCm ggml-ci.
