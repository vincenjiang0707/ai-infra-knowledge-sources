## 正文

### Name and Version

version: 0.2.0-dev (build 10591, commit 8144f3192)
built with GNU 16.1.1 for Linux x86_64

OS Fedora 44 latest packages, HIP/ROCM from dnf
HIP version: 7.1.52802-9999
clang version 20.0.0.rocm


### Operating systems

Linux

### GGML backends

HIP

### Hardware

AMD RX6950XT (gfx1030) has the issue. Yeah I know, it's old...
A similar machine (same OS, packages etc...) with newer RX9700 does not have this issue

### Models

unsloth/gemma-4-12b-it-qat-GGUF:UD-Q4_K_XL
and
unsloth/gemma-4-12b-it-GGUF:UD-Q4_K_XL

both have the same issue

### Problem description & steps to reproduce

cli: llama serve -hf unsloth/gemma-4-12B-it-qat-GGUF:UD-Q4_K_XL --spec-type draft-mtp --spec-draft-n-max 4 -ngl 999 -c 65536
(parameters recommended by unsloth)

server loads model and starts, at first prompt immediate crash on failed assert     GGML_ASSERT(max_blocks_per_sm > 0);

given the location of the crash, we tried using cli flag "-fa off", but the server fails to load the model, not really sure if we should expect it to succeed in that case
