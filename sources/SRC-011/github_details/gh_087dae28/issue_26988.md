### Problem description & steps to reproduce

As per https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md this flag takes:
> comma-separated list of allowed origins for CORS (default: *)
if set to special value 'localhost', reflect the Origin header only if it is localhost
(env: LLAMA_ARG_CORS_ORIGINS)

So I want to accept requests from localhost and a firefox extension

`--cors-origins "moz-extension://f745c4ad-86bf-4062-b715-e26739741e4d,http://localhost:8042"`

However this doesn't follow the spec

https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Access-Control-Allow-Origin

> Specifies a single origin. If the server supports clients from multiple origins, it must return the origin for the specific client making the request.

So it SHOULD return the origin (only 1) if it patched the header that is received but https://github.com/ggml-org/llama.cpp/blob/8e7f22b/tools/server/server-http.cpp#L292

returns the entire value pass AS-IS, this of course does not work correctly. 

The easiest fix is fixing the docs to mention only 1 origin can be specified, so people don't lose hours debugging why it's not working.

The proper fix would be to return the correct origin value based on the received origin header.
