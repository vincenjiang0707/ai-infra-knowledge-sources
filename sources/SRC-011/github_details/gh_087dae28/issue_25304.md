# [Issue #25304] [CUDA] cublasCreate_v2 resource allocation failure on first inference — regression between b9553 and b9870

source: https://github.com/ggml-org/llama.cpp/issues/25304
state: open | updated: 2026-09-26T01:11:29Z
labels: stale

## 正文

Summary

On b9870, the server starts and loads the model successfully but crashes on the first inference request with a CUDA resource allocation failure in cublasCreate_v2. The same command and model work correctly on b9553.

Environment

| Attribute | Details |
| :--- | :--- |
| **OS** | Fedora Linux (kernel 7.0.14-201.fc44.x86_64) |
| **GPU** | NVIDIA RTX 4060 Laptop GPU — 8 GB VRAM |
| **CUDA** | (check yours with `nvidia-smi`) |
| **Working version** | b9553 (9e3b928fd) |
| **Broken version** | b9870 (2d973636e) |

Model

- File: Qwopus3.6-35B-A3B-v1-MTP-IQ4_XS.gguf (Qwen3-based MoE, 19 GB, IQ4_XS quant)
- --n-cpu-moe 45 used to offload MoE expert layers to CPU

Command

llama serve \
  -m /path/to/Qwopus3.6-35B-A3B-v1-MTP-IQ4_XS.gguf \
  -ngl 99 -dev CUDA0 \
  -fa on -ctk q4_0 -ctv q4_0 --no-mmap \
  -t 12 -c 128000 \
  --parallel 1 -ub 1024 -b 1024 \
  --cache-ram 24576 --cache-reuse 512 \
  --n-cpu-moe 45 \
  --port 8080 --host 127.0.0.1 --slots

dmesg

llama[...]: segfault at 8 ip ...10ec965... error 4 in llama[...]

Same offset every crash — deterministic null pointer dereference triggered by the cuBLAS failure.

Analysis

The cuBLAS handle in cublas_handle (common.cuh:1477) is initialized lazily on first inference rather than at model load time. On an 8 GB GPU with a large MoE model and --n-cpu-moe, model weights fill the available VRAM during loading. When the first request arrives and cublasCreate_v2 attempts to allocate its workspace, no VRAM remains, causing the failure and subsequent crash.

On b9553 the same model and command work correctly on the same hardware, suggesting cuBLAS handle lifecycle or VRAM reservation changed between the two builds.

Steps to reproduce

1. Load a large MoE model with --n-cpu-moe on a GPU where VRAM is near-full after model load
2. Start the server — it reports model loaded and listening successfully
3. Send any inference request
4. Server crashes with cublasCreate_v2 resource allocation failure

Expected behaviour

cuBLAS handle is either pre-allocated at init time (before VRAM is fully committed to model weights), or the allocation failure is handled gracefully without crashing the server.

Workaround

Downgrade to b9553:
curl -L https://huggingface.co/buckets/ggml-org/install.sh/resolve/b9553/x86_64/linux/cuda/89/llama-app.zst | zstd -d > ~/.llama-app/llama && chmod +x ~/.llama-app/llama && ln -sf ~/.llama-app/llama ~/.local/bin/llama
