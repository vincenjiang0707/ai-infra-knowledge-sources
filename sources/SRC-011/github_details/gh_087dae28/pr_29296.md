## Overview

<!-- Describe what this PR does and why. Be concise but complete -->
Modified contiguity check/rule such that SUM runs if all the values are stored together with no gaps or the data is arranged in memory in the same exact way (normally) as long as there are no gaps.

Changes to rules/checks: *The data must be stored in one solid block with no gaps
			                    *each of the rows must still be filled normally

Significance: This modification allows metal to handle more valid tensor layouts. Now, the operations that got rejected for having densely packed tensors even with permuted dimensions can now run directly on APPLE M3.

Results: Before, metal was supporting 4/8 SUM layer cases but now it supports 7/8. There was one tensor arrangement (permute=[1,0,2,3]) that looked similar to the others but it gave wrong answer when it was tested; hence blocked/rejected, since it is set as an unsafe layout before it reaches the GPU kernel.
