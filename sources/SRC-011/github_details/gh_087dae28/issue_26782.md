### Models

[gemma 4 12B it qat](https://huggingface.co/unsloth/gemma-4-12B-it-qat-GGUF)

### Problem description & steps to reproduce

When running with `--spec-type draft-mtp` enabled llama-server crashes sporadically (most oftern after a few thousand tokens of prompt processing) with `memory access fault` error.  At no point did my system run out of vram. From my testing the crash is reproducible every single time (even with `-fit off` and `-flash-attn off`) unless I remove `draft-mtp`, in which case the server never crashes. This is the full llama-server command:

<br />

```
[f0x@Arch ~]$ llama-server \
  -hf unsloth/gemma-4-12B-it-qat-GGUF:UD-Q4_K_XL \
  --device ROCm0 \
  --gpu-layers all \
  --ctx-size 131072 \
  --flash-attn on \
  --cache-type-k q8_0 \
  --cache-type-v q8_0 \
  --spec-type draft-mtp \
  --spec-draft-n-max 4 \
  -fit off
```

<br />


Note: The issue might be similar to now closed [issue 24314](https://github.com/ggml-org/llama.cpp/issues/24314), but I'm not sure about it.

### First Bad Commit

I only ever used the current arch pacman repo version.
