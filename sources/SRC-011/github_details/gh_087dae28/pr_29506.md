## Overview

In my experiments, I wanted to test the GPU offloading with both ROCm and SYCL, however this configuration wasn't allowed because ggml-sycl wants -fsycl capable compiler and ggml-hip wants hipcc. So this allows ggml-sycl to be built separately.

Tested: Ninja, icpx 2026.1, ROCm 7.1 + Vulkan + SYCL in one tree. llama.cpp listed four devices (ROCm0, SYCL0, Vulkan0, Vulkan1 on an RX 9070 XT + Arc A770) and no-change incremental build finished immediately.

Not tested, possibly broken in new configuration: Windows build, only selected flags reach nested builds.

If somebody interested, here are the numbers, benchmarking Qwen 3.6 35B A3B at Q6_K, so it neatly fits both GPUs:

| Combo | tg128 | pp512 |
| ----- | ----- | ----- |

Vulkan0 is AMD card, Vulkan1 is Intel card. In the end, going through all this might not have been an optimal strategy. Glad to see vendor-neutral Vulkan backend beating ROCm, but at the same time, Mesa's ANV might not be optimal for inference compared to SYCL. :shrug:
