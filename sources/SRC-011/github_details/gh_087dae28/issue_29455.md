### Problem description & steps to reproduce

When I attempt to start llama server via my typical command

```
$ ./llama-server -hf unsloth/gemma-4-26B-A4B-it-qat-GGUF:UD-Q4_K_XL --ctx-size 36864 -ngl 20 --temp 1.0 --top-p 0.95  --top-k 64
```

it crashes with
```
terminate called after throwing an instance of 'vk::DeviceLostError'
  what():  vk::Queue::submit: ErrorDeviceLost
Aborted (core dumped)
```

Workaround confirmed via `--load-mode mmap` flag.

### 0cc4m · 2026-09-26

That just means you ran out of memory for the model when not using mmap. The default to mmap is still better because if the model does fit performance will be better. Increase your GPU-visible memory or use a smaller model, or just enable mmap manually as you've already done.
