## Overview

<!-- Describe what this PR does and why. Be concise but complete -->

Introduces a deterministic plugin mechanism via a simple SPI that keeps changes to the core at a minimal. 
This is a generic mechanism however what makes it different from the current per token validation is that it plugs into the existing MTP pipeline, by default the plugin will determine if a token is filtered or not but any valid token will be verified by the target and the bonus token is always generated unless a valid termination completes such as a complete parse if using xgrammar. With the --det-draft-accept-all , only the plugin's logic is used to verify, the target model's verification is bypassed even the correction/bonus token is arbitrated and on low end commodity hardware can result in faster TPS along with the guaranteed verification. 

A working PoC that uses Xgrammar for verifying Java,Python,JavaScript and C is under `deterministic-draft-model-poc` 

## Additional information

<!-- You can provide more details and link related discussions here. Delete this section if not applicable -->

Feature - Deterministic Draft Filter with pluggable SDK
- Add deterministic draft filter as a new speculative draft type
- Pluggable SDK via dlopen/dlsym with a single C API contract
- XGrammar based POC demonstrating plugin implementation. Bundled grammars for C, Java, Python, JavaScript Grammar format is XGrammar EBNF.
- Incremental draft validation: one persistent matcher per slot, per-token advance, no re-parse of concatenated text.
- --det-draft-n-max: -1=all, 0=disabled, >0 caps filter output and is copied to --spec-draft-n-max (auto-derive only when > 0).
- --det-draft-accept-all: skip target verification, filter is verifier
- Auto-derive --spec-draft-n-max from --det-draft-n-max (only when > 0)
- Benchmark tool with --compare, --n-runs, --det-draft-accept-all, --det-draft-language support.

The goal here is to provide a control mechanism for domain specific cases where speculation is not acceptable and the problem is well known.
This is a novel enhancement based on a time tested well known grammar based solution, instead of this being likely correct it is either correct or not. 

In addition since a grammar based intercept is cheaper and simpler than the heavy sampling of the target model it is also faster as benchmarks reveal. This is more evident in CPU only edge devices like the N100.
With the --det-draft-accept-all enabled the plugin is fully responsible for all verification, the target model is removed from the decision making.

In the default case, invalid tokens are pruned while the bonus token is verified by the target model. In the case where fewer tokens are accepted by the target model than what was verified by the plugin, the `deterministic_draft_rollback` rewinds the matcher to match what was emitted by the target model. The per-step final token is grammar-constrained before emission (post-fix; zero desync events observed since).
In short the real benefit is with the --det-draft-accept-all.
In this mode, the grammar is the sole verifier, the target model does no rejection sampling. Output distribution follows the grammar-constrained draft, not the target model an opt-in tradeoff.

** sample results **
Grammar-verified speculative decoding with a pluggable SDK. Every emitted token passes the grammar in both modes. Zero `commit_token reject` lines across all runs.

N100 results report C only. The multi-language test was run before the n-max tuning with n-max 100 on a 4-core CPU, default-mode Java and JavaScript runs exceeded
the 1-hour timeout and Python managed 0.88 t/s, because low acceptance means nearly all
of the oversized draft is wasted compute (see the Tuning Cautionary Note in
benchmark-overview.md). That failure is what the n-max 16/64 guidance comes from.

### Key Observations

- **Accept-all** skips target model verification; grammar is sole verifier. Speedups measure a different algorithm than default mode.
- **Default mode** target-verifies all filter-accepted tokens. Speedup is real but modest.
- **n-max matters**: on weak CPUs, oversized n-max (100) wastes draft compute (0.21x). Properly tuned (16-64) gives 1.3-17x.
- **Low baseline MTP acceptance** (3.8%-17.6% on N100 fine-tunes): speculative decoding alone is nearly worthless; the filter makes it viable.
- **Output validity**: 0/1 in all N100 runs (models write broken C). Filter guarantees grammar-valid tokens, not gcc-clean programs -- CFGs cannot check static semantics.

All numbers: single-run, n_runs=1, indicative not statistical. See benchmark-overview.md for full methodology.

### SamD · 2026-09-07

An update to this commit:

The latest rebase from upstream pulled in significant changes for
eagle3/dspark/dflash. Unlike the standard autoregressive MTP flow
(target-attached heads), these use separate draft models, so the
intercept-all flag cannot skip target verification.
They fall back to default mode (target still verifies) plus
additionally constraining the bonus token through the filter.

`--det-draft-accept-all` is renamed to `--det-draft-intercept-all` to
future-proof the flag for intercept operations beyond accept-all. The
internal name (det_draft_filter::det_accept_all) and getter stay unchanged -
they describe "skip target verification" specifically, while the new
param name describes the broader intercept pipeline.

In addition a smaller demo regex PoC plugin is included since the
more extensive XGrammar GBNF now resides in separate repo.
It constrains draft tokens to letters and whitespace
(space, newline, tab), rejecting digits and punctuation,
