### Problem description & steps to reproduce

./llama-server.exe -hf bartowski/Qwen_Qwen3.6-27B-GGUF:Q3_K_M --host 0.0.0.0 --port 8000 -ngl -1 -c 229376 -b 2048 -ub 2048 --cache-prompt -fa on --cache-type-k q4_0 --cache-type-v q4_0 --temp 0.6 --top_k 20 --repeat_penalty 1.05 --jinja --no-skip-chat-parsing --reasoning-format deepseek --reasoning-preserve --parallel 2 --kv-unified
This will throw the error on the logs below.

After a conversation with my agent, this is what we concluded:
- Commit 82dbc4f ("load MTP tensors only if they are really used", Jul 31) introduced the regression
- Line 42 of src/models/qwen35.cpp: int mtp_flags = !ml.load_mtp ? TENSOR_SKIP : 0;
- This applies TENSOR_SKIP to ALL blk.64 tensors (attn_norm, attn_qkv, wo, ffn_gate/down/up) when MTP is disabled
- TENSOR_SKIP triggers the "unused tensor" warning at llama-model-loader.cpp:1118
- For Qwen3.6-27B (block_count=65, n_layer_nextn=1), blk.64 is a hybrid MTP block with both attention/FFN and nextn tensors — the attention/FFN tensors shouldn't be skipped, only the nextn-specific ones
- The fix: apply mtp_flags (with TENSOR_SKIP) only to nextn-specific tensors in load_block_mtp, not to attention/FFN tensors
