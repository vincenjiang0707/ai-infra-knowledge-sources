## Overview

Added mechanism for caching **multiple** graphs by UIDs for using with new GRAPH_RECOMPUTE_UID instead  GRAPH_RECOMPUTE (old command version saved behaviour).

## Additional information

As mentioned in [Discussion #29253](https://github.com/ggml-org/llama.cpp/discussions/29253)  - patch gives noticeable boost on the decoding phase by reducing duplicated data sent on every turn, prefill performance has no improvement/regression.

Applicable for client using --split-mode tensor.

Patch impact comparison for **tg** - with Qwen3 4B_Q8 2.44 times, Gemma4 31B_Q4 2.51 times.

Added as optional feature that requires explicit parameters call:
--graph-cache-mib N for a sum of graphs serialized descriptions size budget (actual memory usage may exceed due to structures and auxiliary data)
--graph-cache-max-markers N for caching mode and limit of accounted called-once UIDs, optional

Tested with 2 miniPCs AMD Ryzen 7 H255 APU using Radeon 780M as workers with 16GB UMA (of 32 and 64 gb of system DDR5 5600) connected through 2.5G Ethernet
