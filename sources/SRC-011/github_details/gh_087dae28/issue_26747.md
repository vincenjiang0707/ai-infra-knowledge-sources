### Feature Description

It would be very cool if llama.cpp SYCL used less VRAM

### Motivation

A while ago, the VRAM usage was more or less stable. Now, when you load a model, the VRAM used is different from when you send a prompt; when you send a prompt, the VRAM usage increases. This also happens when it enters the response phase. Right now the VRAM usage looks like: load=10000 -> prompt processing=11000 -> token generation=11050.

If SYCL used less VRAM, we would be able to allocate more layers to the GPU and also increase the batch sizes

SYCL use static memory management policy as possible: LLM weight.

But there is still dynamic memory during running time.
SYCL use the memory pool to reduce the cost to malloc/free memory cost.

1. kv cache
2. all input tokens and output tokens will be added to context to impact next chat.

They are designed for performance and better answer, cost is the space.
If you want to reduce the cost above, set to use less kv cache and context.
But we will lose something.
You need make the balance.
