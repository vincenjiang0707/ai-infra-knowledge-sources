### Problem description & steps to reproduce

I use an Apple M1 2020 with 16GB under Asahi Debian. 
Compilation performs without issue:
```
cmake -B build -DGGML_BLAS=ON -DGGML_BLAS_VENDOR=OpenBLAS -DLLAMA_OPENSSL=ON -DGGML_VULKAN=ON -DCMAKE_INSTALL_PREFIX=/usr
cmake --build build --config Release -j$(nproc)
build/bin/llama-server -hf unsloth/gemma-4-E2B-it-GGUF:Q4_0 --tools all
```

At execution with gemma-4 E2B,  I get error:
```
ggml_vulkan: Device memory allocation of size 369827840 failed.
ggml_vulkan: vk::Device::allocateMemory: ErrorOutOfDeviceMemory
```
The system uses 6 GB total, and there are 10 GB free memory for the GPU.
This bug is recent (appeared at commit 4bc272fd729bd094c0422e4b8353da8d2fec91f8 on Sep 17, 2026 "vulkan: work around NV bug with argsort_large.comp").

Execution with a smaller `TheBloke--TinyLlama-1.1B-Chat-v1.0-GGUF` model works nicely.

### SG-Amadeus · 2026-09-26

This looks consistent with #28849 rather than 4bc272f. With unified KV and the default 4 slots, auto-fit increases the context from 131072 to 524288, raising peak memory from ~4.9 GiB to ~7.6 GiB in my reproduction; #29437 reverts exactly this behavior. It may be worth checking #28849 and #29437 here.


### farhi · 2026-09-26

Yes, I confirm that execution with `llama-server -np 1 ...` does not bring the ErrorOutOfDeviceMemory.
So the change in the default number of slots is the cause of issue.

Please merge PR #29437 to revert behavior and solve this issue.
