## Overview

<!-- Describe what this PR does and why. Be concise but complete -->

Adds `--verify` (and `--verify-max-error`) to `llama-quantize`.

After a normal quantize run, it reloads the input and output GGUF, dequantizes each tensor, and prints one JSON object with per-tensor `max_abs_error`, `rms_error`, and a 150-bucket `|diff|` histogram. Non-finite values come out as `null` so the JSON still parses.

Exit codes:
- `0` — ok
- `1` — structural problem (missing tensor, bad read, etc.)
- `2` — some tensor's `max_abs_error` is over `--verify-max-error` (default `1.0`)

JSON always prints before a gate exit, so you keep the numbers either way. Off by default — no behavior change unless you pass `--verify`. Refuses `--dry-run` and `--keep-split`.

Why: today you mostly eyeball perplexity or run `test-quantize-stats` by hand. This puts a machine-readable check on the tool people already run, so a script can catch a truncated file or bad scales.

Checked on Tiny-LLM F16 → Q8_0 against `test-quantize-stats -p` (same digits). Corrupt 1 KB of the output → `max_abs_error` spikes, exit `2`, names the tensor. Truncate the output → exit `1`.

## Additional information

<!-- You can provide more details and link related discussions here. Delete this section if not applicable -->

Default gate of `1.0` is deliberate: healthy Q8_0 / Q4_K_M errors I measured were ~0.001–0.03; a 1 KB corruption was ~7e5. Raise it with `--verify-max-error` if your weights are large enough that real quant error can exceed 1.0. Histogram constants match `test-quantize-stats`.
