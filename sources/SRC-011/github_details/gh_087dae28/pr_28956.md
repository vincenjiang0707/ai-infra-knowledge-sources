# [PR #28956] vulkan: fix wrong results when a mul_mat reads a slice of a larger cache

source: https://github.com/ggml-org/llama.cpp/pull/28956
state: open | updated: 2026-09-27T09:36:41Z
labels: testing, Vulkan, ggml

## 正文

## Overview

When GGML's Vulkan backend reads an attention cache view in place (the first n rows of a buffer that holds 5120), it assumed the heads were packed back to back while they are actually spaced by the full cache length, so every head but the first read the wrong data and the SheetSage2 decoder looped forever. The fix takes the real stride from the tensor instead of recomputing it from the visible row count, which also repairs the Qwen3 AR --no-fa path on Vulkan, and two new test-backend-ops cases lock it in.

## Additional information

Found while chasing https://github.com/ServeurpersoCom/yue2.cpp/issues/4, where the SheetSage2 decoder loops forever on Vulkan while it works on every other backend such as CPU and CUDA. This PR brings Vulkan in line with the others.
