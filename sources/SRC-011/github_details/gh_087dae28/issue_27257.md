### aether-png · 2026-08-18

Root cause looks like a CMake variable vs. environment variable mismatch in ggml/src/ggml-sycl/CMakeLists.txt.

Line 9 correctly checks if (DEFINED ENV{ONEAPI_ROOT}); so the script knows ONEAPI_ROOT is only ever a shell env var, never a CMake variable. But the Level Zero detection uses the bare form instead:

cmake
find_path(LEVEL_ZERO_INCLUDE_DIR level_zero/ze_api.h HINTS ${ONEAPI_ROOT}/include ${LEVEL_ZERO_V1_SDK_PATH}/include)
find_library(ZE_LOADER_LIB ze_loader HINTS ${ONEAPI_ROOT}/lib ${LEVEL_ZERO_V1_SDK_PATH}/lib ENV LD_LIBRARY_PATH)

ONEAPI_ROOT (without ENV) is never defined as a CMake variable, so that hint is always empty. The only other fallback, LEVEL_ZERO_V1_SDK_PATH, is Windows-only (set a few lines above, inside a Windows-gated block), so nothing backs it up on Linux. Result: find_path/find_library get no usable hint on Linux even with oneAPI sourced correctly — matching your sycl-ls output showing Level Zero working fine outside CMake.

Suggested fix: ${ONEAPI_ROOT} → $ENV{ONEAPI_ROOT} in both HINTS clauses.

Don't have a Linux/oneAPI setup to build and confirm, so posting this as a diagnosis rather than a tested patch.
