## 正文

models : fill the unwritten rollback snapshot slot on short ubatches

## Overview

Rolling back a whole ubatch with fewer than K tokens, the live state plus `n_rs_seq` snapshots, restores a snapshot slot the ubatch never wrote. That slot holds whatever was last written there, an older real state or the initial cache contents, and replay produces wrong logits.

Draft-model speculative decoding (MTP, EAGLE3) hits this when the drafter proposes fewer than `draft.n_max` tokens, or when the batch splitter divides a multi-sequence verify batch across sequences, since `n_rs_seq` is set to the draft size and a full verify batch is exactly K tokens.

Affected: the shared Gated Delta Net state write in `delta-net-base.cpp`, used by Qwen3.5, Qwen3.5MoE, Kimi-K3, qwen4exp, and BailingMoE3 (BailingMoE3 also has its own convolution write, fixed separately); Mamba2's convolution and SSM writes, used by Nemotron-H; and LFM2's and BailingMoE3's own convolution writes. The fix copies the state from before the ubatch into that slot on every ubatch, so the graph shape stays fixed regardless of ubatch length. See "why every ubatch" below.

#28286 reports cross-slot content contamination with `--spec-type draft-mtp` and `--parallel 4` on a qwen4exp model, which runs through this same rollback code. An earlier in-server trace showed rollbacks following cells that `find_slot` moved. That trace only counted rollbacks after a cell move, it never measured short batches on their own, and it isn't published for reviewers to check. The connection to #28286 is unconfirmed, and the gap this PR closes is real and confirmed at the `test-recurrent-state-rollback` level below regardless of that connection.

Related to #28286.

### Why the write runs on every ubatch, not just short ones

Writing it conditionally gave short and long ubatches different graph shapes. The scheduler re-reserves on every shape change, which aborts CUDA CI under `GGML_SCHED_NO_REALLOC`. The fix runs unconditionally now, using two different tricks depending on the state involved. Delta-net and Mamba2's SSM copy targets slot `K-1` on a long ubatch, and the real snapshot write immediately after overwrites it, so the final state comes out the same either way. The three convolution loops, bailingmoe3, lfm2, and mamba2's own conv path, do it differently: they loop over all K slots unconditionally and clamp the window offset to 0 with `std::max<int64_t>(0, ...)` once the window would start before offset 0, the start of the remembered inputs that sit ahead of the batch in that buffer.

Full `ci/run.sh` CPU and CUDA (RTX 4090), debug and release, against the final code: 54/54 and 55/55 passed. Not tested: Metal, Vulkan.

Identical within noise. Both tools run with rollback off, `n_rs_seq` defaults to 0 so K is 1, and the extra write never executes on that path. The only measurement where the new write runs is single-stream MTP decode on Qwen3.5-0.8B with `n_draft` 3 (K is 4). Accept rate held at 34.615% across all six runs, and `cmp` confirms byte-identical output on every master/branch pair. `--parallel` wasn't exercised here, so this doesn't touch #28286 multi-slot symptom.

### Out of scope

- Nothing clamps a rollback request to what the triggering ubatch actually wrote. `llama_memory_recurrent::seq_rm` only bounds it against the static configured `n_rs_seq` (`rollback <= n_rs_seq`); `set_rs_idx` just asserts that bound holds. A caller asking for a rollback deeper than the last ubatch's token count reads whatever sits in that deeper slot with no check. This PR fixes the one slot every existing and new test exercises. It doesn't add that bound.
- qwen4exp-moe hits a scheduler reallocation abort under `GGML_SCHED_NO_REALLOC` when running the new `test_short_ubatch_rollback`, on both master's code and this branch. lfm2moe-moe likely hits the same abort, inferred rather than reproduced directly, since on master it fails an earlier check before reaching that point. Neither model is in ctest, so neither blocks CI as it stands, but adding them would need this fixed first.
