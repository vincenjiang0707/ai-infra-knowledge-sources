## Overview
PH1 (MTT S5000, MUSA architecture `31`) is the current MUSA target, but parts of the CUDA backend still assumed the first generation (MTT S80, `21`) or carried compile-time workarounds for older MUSA toolkits. This series lets those paths use the upstream code and fixes the operator failures that `test-backend-ops` reports on an MTT S5000 with MUSA SDK 5.2.0:
- **build and enablement** — 16-byte copies like `sm_70` and up, the CUB based paths, the cooperative launch query and the device warp size, `CUDA_SET_SHARED_MEMORY_LIMIT`, `cudaFuncSetAttribute`, and MUSA-only guards that a runtime architecture check already covers
- **operator fixes** — the `q8_0` dequantization kernel was compiled out on MUSA (moved to #29292), the fused `TOPK_MOE` kernel could hang in `__syncthreads()`, `MMQ` computes wrong values on PH1, `GATED_DELTA_NET` is enabled
- **flash attention** — availability is decided from the runtime compute capability, and `IQ4_NL` is supported as a KV cache type (moved to #29293)
- **graphs** — the stream capture query API is aliased for MUSA, so a `-DGGML_MUSA_GRAPHS=ON` build compiles
- **CI and docs** — the MUSA job and the documented default target `31` and run in the PH1 MUSA SDK devel image
