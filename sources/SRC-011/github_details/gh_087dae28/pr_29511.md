## Overview

<!-- Describe what this PR does and why. Be concise but complete -->
Support the repacked (tiled) layout path for Q4_0 and Q8_0 GET_ROWS

## Additional information

<!-- You can provide more details and link related discussions here. Delete this section if not applicable -->
Motivation is bringing the main graph ops of the LFM2.5-DSpark draft model onto hexagon, instead of using the CPU fallback.  

The DSpark draft model Markov head has a large vocabulary tensor (markov_w1) in Q8_0 format.   The markov_w1 tensor is unconditionally repacked to a tile format during upload to the hexagon backend.

Before this change, the CPU GET_ROWS is used as fallback.  After this change, the new tiled hexagon GET_ROWS is selected.  

Tiled GET_ROWS is not covered by existing test-backend-ops.   A future PR will be submitted for new backend tests to exercise this path, including verification of the Q4_0 path.

The 44/44 already supported GET_ROWS tests continue to pass on HTP0.

Sample command to exercise Q8_0:
```
python scripts/snapdragon/run.py --install-dir <PR pkg dir> --devices HTP0 -- \
  llama-cli \
  -m <model dir>/LFM2.5-2.6B-Q8_0.gguf \
  -md <model dir>/LFM2.5-2.6B-DSpark-Q8_0.gguf \
  --spec-type draft-dspark --spec-draft-n-max 10 --spec-draft-n-min 0 \
  --no-spec-draft-backend-sampling \
  -c 4096 -ngl 99 -ngld 99 -fa on -n 256 \
  -p "The sky appears blue because" \
  --temp 0 --no-warmup --no-jinja --reasoning off --no-display-prompt -st -lv 4
```
This preserves the established acceptance 190/576, mean 3.92.  The backend trace confirms:
- markov_w1 uploaded as tiled Q8_0
- Markov Q8_0 tiled GET_ROWS executed on HTP0

Verification environment: Snapdragon X2 Elite HTP0
