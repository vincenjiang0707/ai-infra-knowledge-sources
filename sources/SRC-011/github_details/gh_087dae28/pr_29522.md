# [PR #29522] graph : do not reuse a token graph as an embedding graph (and vice versa)

source: https://github.com/ggml-org/llama.cpp/pull/29522
state: closed | updated: 2026-09-27T10:02:04Z
labels: model

## 正文

`llm_graph_input_embd` and `llm_graph_input_embd_h` pick between the token-lookup branch and the direct-embedding branch when the graph is built. `can_reuse()` only compares tensor shapes, and shapes cannot tell the two apart: an mtmd embedding batch and a token batch can both be 512 rows and still need different graphs.

The inputs now carry which branch they were built for and refuse a cross-modality reuse. This is strictly more conservative than the `true` it replaces — it can only refuse a reuse, never enable a wrong one.

I found this while chasing a scheduler-topology carryover after mtmd decodes, so it is motivated by a real failure rather than by inspection. Being honest about the evidence: I did not isolate a performance delta for this change on its own. It was already in place before I measured the carryover, and the fix that closed that specific regression is the re-reserve in #27428's companion PR. What this change stands on is correctness — today a 512-row embedding batch and a 512-row token batch are indistinguishable to `can_reuse()`, and nothing prevents the wrong graph from being replayed.

Call sites pass `ubatch.token != nullptr`. The parameter defaults to `true`, so models not touched here keep their current behaviour.

Touches `src/llama-graph.h`, `src/llama-graph.cpp` and 11 files under `src/models/`.
