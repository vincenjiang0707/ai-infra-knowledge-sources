### Problem description & steps to reproduce

### Observed behavior

In `src/llama-sampler.cpp`, `llama_sampler_top_k_backend_apply()` reduces the logits and candidate IDs to `k` elements. In `src/llama-context.cpp`, `copy_tensor_async_rows()` copies only `ggml_nbytes(tensor)` bytes and records `ggml_nelements(tensor)` in the corresponding row’s `*_count`.

However, `llama_context::output_reserve()` allocates space for the raw logits, sampled logits, sampled probabilities, and candidate IDs using `n_vocab * n_outputs_max`. With a backend sampler configured, the sampling output alone reserves two vocabulary-width float arrays, one vocabulary-width token ID array, and one sampled token per row. Space for the full raw logits is also reserved even when this backend-sampling path does not copy them.

In `decode()`, the sampling output still uses `n_vocab` as the destination row stride. `copy_tensor_async_rows()` writes to `base + row * stride`: each row copies `k` sampled logits and `k` candidate IDs, leaving up to approximately `n_vocab - k` unused positions in each array. The sampled-output getters locate rows using `row * n_vocab`. When reordering occurs, `output_reorder()` swaps sampling arrays one full `n_vocab`-wide row at a time.

### Results

**Allocation formula and measured capacity:** Let `V = n_vocab` and `R = n_outputs_max`. With both `float` and `llama_token` occupying 4 bytes, the sampling output reserves `12 * V * R + 4 * R` bytes, while the raw logits reserve another `4 * V * R` bytes. This excludes embeddings, layer inputs, the model, the KV cache, and backend workspaces.

**Reproduction (2026-09-27):** The reproduction program is in the first comment. Both backends used the same commit, the same Qwen3.5-0.8B BF16 GGUF (`V=248320`), and the same token sequence. For each K/R configuration, only the execution backend differed. The parameters were `n_ctx=2048`, `n_batch=n_ubatch=64`, `n_seq_max=1`, and `n_outputs_max=n_outputs_max_per_seq=R`. The last token returned by `llama_tokenize("Hello", add_special=true)` was repeated at R consecutive positions, with output requested at every position. Each run used a fresh process. In all six runs, `llama_decode` returned 0, the number of output rows equaled R, and every row’s logits and candidate counts equaled K.

| K | R | Logits / candidate count per row | Host output buffer | Buffer type |
| ---: | ---: | ---: | ---: | --- |
| 8 | 1 | 8 / 8 | 3,973,124 B | CPU |
| 8 | 64 | 8 / 8 | 254,279,936 B | CPU |
| 80 | 64 | 80 / 80 | 254,279,936 B | CPU |
| 8 | 1 | 8 / 8 | 3,973,124 B | CUDA_Host |
| 8 | 64 | 8 / 8 | 254,279,936 B | CUDA_Host |
| 80 | 64 | 80 / 80 | 254,279,936 B | CUDA_Host |

At a fixed R of 64, increasing K from 8 to 80 increases the actual logits and candidate counts per row tenfold, while the host output buffer capacity remains unchanged on both CPU and CUDA.

## 评论 (1)

### Tosuhc · 2026-09-26

This diagnostic program compares the actual Top-K output counts with the allocated host output buffer size. It uses a private llama.cpp header to inspect the buffer without modifying llama.cpp. Build the CPU and CUDA versions from the same commit, then run each configuration in a separate process.

Diagnostic program : [llama-topk-host-output-repro-min.cpp](https://github.com/user-attachments/files/32687763/llama-topk-host-output-repro-min.cpp)

```sh
LLAMA_SRC="<path-to-llama.cpp-source>"
CPU_BUILD="<path-to-CPU-build>"
CUDA_BUILD="<path-to-CUDA-build>"
MODEL="<path-to-GGUF-model>"
REPRO="<path-to-repro.cpp>"

cd "$LLAMA_SRC"

c++ -std=c++17 -O2 -fno-access-control \
  -Iinclude -Isrc -Iggml/include "$REPRO" \
  -L"$CPU_BUILD/bin" "-Wl,-rpath,$CPU_BUILD/bin" \
  -lllama -lggml -lggml-base -lggml-cpu \
  -o /tmp/llama-topk-repro-cpu

c++ -std=c++17 -O2 -fno-access-control \
  -Iinclude -Isrc -Iggml/include "$REPRO" \
  -L"$CUDA_BUILD/bin" "-Wl,-rpath,$CUDA_BUILD/bin" \
  -lllama -lggml -lggml-base -lggml-cpu -lggml-cuda \
  -o /tmp/llama-topk-repro-gpu

/tmp/llama-topk-repro-cpu "$MODEL" cpu 8 1
/tmp/llama-topk-repro-cpu "$MODEL" cpu 8 64
/tmp/llama-topk-repro-cpu "$MODEL" cpu 80 64

/tmp/llama-topk-repro-gpu "$MODEL" gpu 8 1
/tmp/llama-topk-repro-gpu "$MODEL" gpu 8 64
/tmp/llama-topk-repro-gpu "$MODEL" gpu 80 64
```
