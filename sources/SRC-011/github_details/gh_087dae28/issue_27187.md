### Problem description & steps to reproduce

Requests to /v1/chat/completions will randomly cause a hard crash in llama-server. The bug is not consistently reproducible, but I had more luck reproducing the crash with a large number of tool calls (i.e. more /v1/chat/completions requests). I _believe_ the dice is rolled at the end of each http stream.

```cpp
// tools/server/server-http.cpp
// ...

    sink.done(); // <-- crash site

// ...
```

### Frost-54 · 2026-08-22

I think your fix is correct. In `write_content_with_progress`
https://github.com/ggml-org/llama.cpp/blob/9d57ce456c94d241dde672b2db9cf18879766568/vendor/cpp-httplib/httplib.cpp#L3763
`done` is not set and the callback should not assume that `done` must be valid.

I couldn't reproduce this bug, but here are my findings anyway.
The lambda is a callback that streams chunks of data to the response body. It is called by various `write_*` functions. Most of them set `done` to a lambda, but `write_content_with_process` does not, which caused the crash.
`write_content_with_process` is called(indirectly) by `details::write_content`
https://github.com/ggml-org/llama.cpp/blob/9d57ce456c94d241dde672b2db9cf18879766568/vendor/cpp-httplib/httplib.cpp#L8094-L8106
which is reachable only if `res.content_length_ > 0`. There are 2 places where `res.content_length_ > 0` is set to a non-zero value:
https://github.com/ggml-org/llama.cpp/blob/9d57ce456c94d241dde672b2db9cf18879766568/vendor/cpp-httplib/httplib.cpp#L6598-L6606
and in `Server::apply_ranges`
https://github.com/ggml-org/llama.cpp/blob/9d57ce456c94d241dde672b2db9cf18879766568/vendor/cpp-httplib/httplib.cpp#L8809-L8810
Since the lambda that caused the crash is called set by 
https://github.com/ggml-org/llama.cpp/blob/9d57ce456c94d241dde672b2db9cf18879766568/tools/server/server-http.cpp#L578
`Server::apply_ranges` should be the case, and the path that sets `content_length_` is only reachable if 
https://github.com/ggml-org/llama.cpp/blob/9d57ce456c94d241dde672b2db9cf18879766568/vendor/cpp-httplib/httplib.cpp#L8740

However, [the handler for POST request](https://github.com/ggml-org/llama.cpp/blob/9d57ce456c94d241dde672b2db9cf18879766568/tools/server/server-http.cpp#L604) does not write `res.body` for POST requests. I don't know why `res.body` is set to a non-empty string.
