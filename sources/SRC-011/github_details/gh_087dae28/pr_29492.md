## Overview

<!-- Describe what this PR does and why. Be concise but complete -->

This PR fixes the issue #28095 where the cli still returns **exist status 0** when a missing or invalid media file is provided. 

After the fix, `llama-cli --single-turn` now returns **exit status 1** when the specified media file cannot be opened or decoded.

## Additional information

<!-- You can provide more details and link related discussions here. Delete this section if not applicable -->

### Reproduction

The issue can be reproduced and the fix can be observed by running the following from the repository root, first on the `master` branch, then on this `fix/28095-llama-cli-media-exit-code` branch.

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --target llama-cli -j 2

repro_dir=$(mktemp -d)
printf 'this is an invalid image\n' > "$repro_dir/invalid.png"

run_test_case() {
    local exit_code=0
    ./build/bin/llama-cli \
        -hf ggml-org/tinygemma3-GGUF:Q8_0 \
        -p test -n 1 -c 1024 \
        --no-warmup --simple-io --single-turn \
        "$@" || exit_code=$?
    printf 'exit status: %s\n' "$exit_code"
}

# Missing media: exit status 0 before the fix, 1 after the fix.
run_test_case --image "$repro_dir/missing.png"

# Invalid image: exit status 0 before the fix, 1 after the fix.
run_test_case --image "$repro_dir/invalid.png"

# Successful text generation: exit status 0 before and after the fix.
run_test_case
```
