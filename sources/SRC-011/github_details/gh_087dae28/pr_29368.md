## Overview

TL;DR: It is not worth it. 

The goal of this experiment is to add support for a [HQQ-backed 4-bit quant](https://dropbox.github.io/hqq_blog/). 


## Additional information

Although this new quant has the block layout matching the existing `Q4_1` quant (the latter has `(delta, minimum)` where `Q4_H` has `(scale, zero)` so they have identical bpw) and there exists a direct translation between parameters of these quants:

```cpp
d = fp16_round(1.0f / scale);
m = fp16_round(-zero / scale);
```

The decision is to build an independent quant to benchmark it side by side with the existing quants such as `Q4_0` and `Q4_1` instead of settling on a quantization-time HQQ encoder for the `Q4_1` format. The downside here is we will have to recreate the plumbing necessary for the quant to work instead of relying on the existing kernels for `Q4_1`. The upside is that we'll have a chance to see how `Q4_H` fares as a KV cache quant.


### Stage 1

I downloaded a small-ish model, excluding the original files, and symlinked the path into the current directory.

```
ln -s "$(hf download -q meta-llama/Llama-3.2-3B-Instruct --exclude "original/*")" Llama-3.2-3B-Instruct
```

Then I converted it into GGUF format using the safetensors-native BF16 type:

```
python convert_hf_to_gguf.py Llama-3.2-3B-Instruct --outfile Llama-3.2-3B-Instruct-bf16.gguf --outtype bf16
```

Next I quantized it into `Q4_0` and `Q4_1` as the latter is bpw-identical quant:

```
llama-quantize Llama-3.2-3B-Instruct-bf16.gguf Llama-3.2-3B-Instruct-Q4_0.gguf Q4_0
llama-quantize Llama-3.2-3B-Instruct-bf16.gguf Llama-3.2-3B-Instruct-Q4_1.gguf Q4_1
llama-quantize Llama-3.2-3B-Instruct-bf16.gguf Llama-3.2-3B-Instruct-Q5_0.gguf Q5_0
```
I also quantized the model into `Q5_0`, the next best quant.

For inference, I ran the quantized model on the example prompts with a command such as:

```
llama-completion -m Llama-3.2-3B-Instruct-Q4_0.gguf -lv 4 -st -p 'what is bitcoin?'
```

| Prompt | TTFT | Prefill | Decode | VRAM at full context |
| --- | --- | --- |--- |--- |
| What is bitcoin? | 9.94 ms| 1408 t/s | 533 t/s | 16669 MiB | 
| Write a Python function to reverse a list. | 9.99 ms | 1902 t/s | 533 t/s | 16669 MiB |

I did not have to limit the context size or use KV cache quantization as I had enough VRAM for a small model like this.

As I already had the wikitext-2 dataset cached (`get-wikitext-2.sh`), I computed the baseline for future perplexity benchmarking:

```
llama-perplexity -m Llama-3.2-3B-Instruct-bf16.gguf \
  -f wikitext-2-raw/wiki.test.raw \
  --kl-divergence-base Llama-3.2-3B-Instruct-bf16.kld \
  --chunks 20
```

Build command in my case, with RTX 5090:

```
cmake -B build -DCMAKE_BUILD_TYPE=Release \
  -DGGML_CUDA=ON -DGGML_VULKAN=ON \
  -DGGML_CUDA_FA_ALL_QUANTS=ON \
  -DCMAKE_CUDA_ARCHITECTURES=120a-real
```

### Stage 2

I cloned the [official implementation of HQQ](https://github.com/dropbox/hqq) and directed an agent to implement a new quantization format together with the HQQ solver. Once that's done (0d587ecf14842ced9605693b4de21ba1e2e4f52e), I quantized the model:

```
llama-quantize Llama-3.2-3B-Instruct-bf16.gguf Llama-3.2-3B-Instruct-Q4_H.gguf Q4_H
```

And followed that with a perplexity benchmark [using a script](https://gist.github.com/sanmai/d40a1f43fe2d7f9d847527b9022e6786).

```
DEV=none ./model-kld.sh Llama-3.2-3B-Instruct-Q*
```

| Model | Mean KLD | Same top p (%) |
| --- | ---: | ---: |
| Llama-3.2-3B-Instruct-Q4_0 | 0.060562 | 88.647 |
| Llama-3.2-3B-Instruct-Q4_1 | 0.075004 | 87.294 |

`Q4_H` came ahead of `Q4_1` just as we would expect, but it is a tie with `Q4_0`.

## Wrap up

We can now use Q4_H quantized models just like any other. Are they good? No.

Memory-wise, `Q4_H` has the same footprint as `Q4_1`, above `Q4_0` - no surprises.

|  | memory usage [MiB] |
| --- | --- |
|   Q4_H   | 16837 =  1988 +   14336 +     513 |
|  Q4_1  | 16837 =  1988 +   14336 +     513|
|   Q4_0   | 16669 =  1820 +   14336 +     513 |

Likewise, the model files sizes align perfectly with their bpw.

| size | model |
| --- | --- |
| 1,8G |	Llama-3.2-3B-Instruct-Q4_0.gguf |
|2,0G|	Llama-3.2-3B-Instruct-Q4_1.gguf|
|2,0G|	Llama-3.2-3B-Instruct-Q4_H.gguf |
|2,2G|	Llama-3.2-3B-Instruct-Q5_0.gguf|
