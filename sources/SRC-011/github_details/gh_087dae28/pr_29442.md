## Overview

Follow #28846
Chuncking the BF16/FP16 to FP32 convertion for lowering VRAM usage.
By default the var `GGML_CUDA_CUBLAS_CONVERT_CHUNK_SIZE` is set to 0 = disable ==> meaning full performance.
We are still getting a performance improvement over native bf16 (on gfx906 for example), but with a little performance drop compare to unchuncked. 

## Additional information

Test with BF16 to FP32 and FP16 to FP32 (useally when FA is set to OFF and context if growing)

| BF16 -> FP32 | 512 MiB | 8,557 | 4.02 TFLOPS | +6.3% |
| BF16 -> FP32 | 256 MiB | 9,139 | 3.76 TFLOPS | -0.1% |
| BF16 -> FP32 | 128 MiB | 9,953 | 3.45 TFLOPS | -9.0% |
| BF16 -> FP32 | 64 MiB | 11,092 | 3.10 TFLOPS | -21.5% |
| BF16 -> FP32 | 1 MiB | 332,390 | 103.37 GFLOPS | -97.3% |

Large chunks preserve most of the performance: 256 MiB performs essentially identically to the unchunked path, while 512 MiB was about 6% faster in this benchmark. Very small chunks should be avoided when performance matters: a 1 MiB chunk splits the operation into 1024 GEMMs and causes a severe performance regression.

FP16 ==> FP32

Test shape: `M=65536, N=64, K=4096`, AMD Instinct MI50 (`gfx906`).

| Compute path | Chunk size | Time (µs) | Throughput | Peak VRAM | Extra VRAM vs native | Perf vs unchunked |
|---|---:|---:|---:|---:|---:|---:|
| Native FP16 | N/A | 3,755 | 9.15 TFLOPS | 811 MiB | — | +59.0% |
| FP16 -> FP32 | Disabled | 9,159 | 3.75 TFLOPS | 1,889 MiB | +1,077 MiB | baseline |
| FP16 -> FP32 | 512 MiB | 8,547 | 4.02 TFLOPS | 1,352 MiB | +542 MiB | +6.7% |
| FP16 -> FP32 | 256 MiB | 9,171 | 3.75 TFLOPS | 1,084 MiB | +274 MiB | -0.1% |
| FP16 -> FP32 | 128 MiB | 9,990 | 3.44 TFLOPS | 950 MiB | +138 MiB | -9.1% |

The unchunked FP16 -> FP32 path allocates a 1024 MiB temporary conversion buffer. Chunking reduced this buffer to 512, 256, or 128 MiB respectively, with the measured VRAM peak decreasing accordingly.

Notably, a 256 MiB chunk reduced the conversion-related VRAM overhead from roughly 1.08 GiB to 274 MiB with essentially no performance loss in this benchmark.
