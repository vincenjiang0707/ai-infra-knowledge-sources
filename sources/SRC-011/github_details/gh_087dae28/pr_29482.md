# [PR #29482] server: emit tool results before user text in Anthropic conversion

source: https://github.com/ggml-org/llama.cpp/pull/29482
state: open | updated: 2026-09-26T15:42:37Z
labels: server

## 正文

I hit this running Claude Code against a local llama.cpp server. Compaction failed with "summarization produced empty response" and the only workaround was /clear.

The problem is in convert_anthropic_to_oai(). When a user message has both tool_result blocks and text, the text block is emitted first, then the tool results. The actual Anthropic API puts tool results first. Claude Code's compaction prompt relies on that ordering, the model sees the tool results, then the user's follow-up text. When the order is reversed, the summary comes back empty.

The fix is one loop moved. Tool results now emit before the text block.

Tested on llama.cpp b11156, CUDA build, qwen3-32b model. Compaction works now, produces a proper summary.

This only affects the /v1/messages endpoint. The OpenAI-compatible endpoint is unchanged.
