## Overview
Traditionally, rerank models were bidirectional cross-encoders like BERT, which mandated that all the tokens in the input must be within the same physical batch due to bidirectional attention. However, the Qwen3 and Qwen3-VL family of rerankers are just repurposed LLMs (causal decoders). This meant that prefill does not have to be all within the same physical batch. They can be chunked into batches just like any other decoder LLM. 

Currently, llama-server is outdated in enforcing this difference. llama-server is too conservative and forces all rerank models to have to batch their prefill into one physical batch (default 512 tokens). _**In other words, if the document is greater than the physical batch size, the rerank doesn't work**_. Thus, long documents or images cannot be fed into the rerank model in llama.cpp
