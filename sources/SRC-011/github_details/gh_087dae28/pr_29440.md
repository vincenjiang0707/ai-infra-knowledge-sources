## Overview

<!-- Describe what this PR does and why. Be concise but complete -->
Currently the RPC server spins 100% on `rdma_poll`, we can arm a [completion channel](https://www.ibm.com/docs/en/aix/7.2.0?topic=em-ibv-create-comp-channel-ibv-destroy-comp-channel) to wake up the thread when there is an event or a peer disconnect. I saw no performance drop with RPC `-sm layer` or `-sm tensor` with this change, the only change was the CPU went from 100% to 0.1% usage.
