# [Issue #27011] server : add Prometheus histogram for request context sizes

## 正文

## Motivation

When running llama-server with `--metrics`, the Prometheus endpoint exposes counters and gauges for throughput, token counts, and speculative decoding stats, but there is no visibility into the distribution of context sizes across requests. Knowing whether most requests are short (< 4k tokens) or long (> 64k) is useful for capacity planning, KV cache tuning, and monitoring workload characteristics over time.

## Proposal

Add a standard Prometheus histogram metric `llamacpp:request_context_tokens` that records the context size (prompt tokens) of each completed request. Key details:

- **Metric type**: Prometheus `histogram` (cumulative `_bucket`, `_sum`, `_count`)
- **Labels**: `model_name`, `model_alias` — allows per-model time series in multi-model / router setups
- **Default bucket boundaries**: `1024, 4096, 8192, 16384, 32768, 65536, 131072, 262144`
- **Custom boundaries**: new `--metrics-ctx-buckets B1,B2,...` CLI flag (env: `LLAMA_ARG_METRICS_CTX_BUCKETS`)
- **Gated**: only emitted when `--metrics` is enabled (existing gate)

This follows the same patterns as the existing speculative decoding per-position counter.

## Example output

```
# HELP llamacpp:request_context_tokens Distribution of context sizes (in tokens) across completed requests
# TYPE llamacpp:request_context_tokens histogram
llamacpp:request_context_tokens_bucket{model_name="qwen3",model_alias="qwen3",le="1024"} 3
llamacpp:request_context_tokens_bucket{model_name="qwen3",model_alias="qwen3",le="4096"} 8
...
llamacpp:request_context_tokens_bucket{model_name="qwen3",model_alias="qwen3",le="+Inf"} 17
llamacpp:request_context_tokens_sum{model_name="qwen3",model_alias="qwen3"} 683947
llamacpp:request_context_tokens_count{model_name="qwen3",model_alias="qwen3"} 17
```
