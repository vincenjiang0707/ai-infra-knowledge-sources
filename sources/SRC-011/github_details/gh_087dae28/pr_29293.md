## Overview

<!-- TODO(author): describe what this PR does and why. Be concise but complete -->
- `ggml_cuda_fattn_kv_type_supported` now accepts `GGML_TYPE_IQ4_NL` as a KV cache type, together with the dequantization counterpart the flash attention kernels use to read that cache: `dequantize_iq4_nl_pair` and the `to_fp16_nc_cuda` / `to_bf16_nc_cuda` / `to_fp32_nc_cuda` dispatch entries for `IQ4_NL`. This makes `-ctk iq4_nl -ctv iq4_nl -fa on` work instead of falling back.
- On MUSA, `FLASH_ATTN_AVAILABLE` is a property of the compilation pass rather than of the device: `__MUSA_ARCH__` is only defined in the device pass, so in every host pass the old condition removed the FA device code from the translation unit, and availability was decided at runtime today. The MUSA part of the guard is now additionally conditioned on `defined(__MUSA_ARCH__)`, and [the runtime check in the host code] rejects devices whose MUSA architecture has no FA device code (only `QY2` / `mp_22` and later have it).

The first change affects CUDA as well; the second is MUSA specific and does not change behaviour on devices that have FA code, such as the MTT S5000 (`mp_31`) used below.
