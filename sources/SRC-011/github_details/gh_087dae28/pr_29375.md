## Overview

<!-- Describe what this PR does and why. Be concise but complete -->

This PR optimized mulit token decode for Q5_K. I found while running DFlash on the B70 that increasing the `n-max` value sharply decreased decode t/s, suggesting that token verification was running much slower than it should. I used Opus 5.5 to run `test-backend-ops` tests to identify the bottleneck, and then had it make improvements (verified with correctness tests).

## Additional information

I ran correctness tests on this for Q5_K locally, but it is suggested not to add to base_types as it bloats the testing surface. 

All on B70 with `test-backend-ops test -b SYCL0` vs CPU.

* `-o MUL_MAT -p "type_a=q5_K,"`: 29/29 pass as-is. 55/55 with Q5_K added to `base_types`.
* `-o MUL_MAT_VEC_FUSION -p "type=q5_K,"`: 0/0 as-is, fusion tests only loop over `base_types`. With Q5_K added for the run only, 105/105 pass.
  Edit was temporary `sed` adding `GGML_TYPE_Q5_K` after `GGML_TYPE_Q4_K` in `base_types`.
