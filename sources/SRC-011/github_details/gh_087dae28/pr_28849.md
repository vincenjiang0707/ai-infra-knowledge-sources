## 正文

## Overview

Auto-fitting now tries up to model context length × parallel slots for unified KV. This is similar to no-unified-kv behaves, allowing more capacity for concurrent requests.
It remeasures memory at the larger size and shrinks context if needed. Minimum limits, alignment, and explicit nonzero `--ctx-size` values remain unchanged.

### gaugarg-nv · 2026-09-22

### ggerganov · 2026-09-22

One of the arguments for having a shared context pool among up to 4 parallel sequences was to be able to run short-lived sessions (usually chats) at the same time and also to not "hide" the fact that llama-server supports parallel execution. With the adoption of agentic workflows, it's now much easier to hit the ceiling and hence it's a good argument for the change in this PR. Without this change, you get errors when your agents fill the shared pool - this happens much easier today, compared to when we were choosing the defaults some months (or year?) ago.

Going to `-np 1` by default is not an easy decision. The result would likely be a large amount of users/influencers online coming to the incorrect conclusion that llama.cpp runs in serial mode and does not support parallelism.
