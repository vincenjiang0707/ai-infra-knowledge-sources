## Overview
In current PR introduced `--repack` option in llama-bench tool, which eliminates gap between this tool and `llama-cli`. It makes tool usage more flexible for multiple backends.
Initial problem was: llama-bench has no option to switch between code branches, while  `llama-cli` has.
In llama.cpp there always was a dedicated runtime knob to control compute code path (use_extra_bufts from llama_model_params). There were no command line option to set it in runtime exactly ,because it parses args in its own parse_cmd_params() rather than through common/arg.cpp . So current PR  only expose already available in engine capability to llama-bench tool. 

## Additional information
Once I was working with `llama-bench` and `llama-cli` tools, I have faced with lack of valuable (based on my opinion) option in `llama-bench`, but available in `llama-cli`. `--repack` allows to switch compute code branches and it might be useful for performance comparison for full picture of performance on HW understanding.
I have verified that neither LLAMA_ARG_REPACK nor -ot ".*=CPU"  can control it on runtime. The only option is to switch it in compile time -DGGML_CPU_REPACK=OFF.
Current option is valid at least for x86 and ARM CPUs
Based on it I come up with this proposal. 

Example:
```
./llama-bench -m models/gemma-3-1b-pt-q4_0.gguf --repack 0,1 -p 512 -n 128 -r 5 --delay 10
| model                          |       size |     params | backend    | threads | rpk |            test |                  t/s |
| ------------------------------ | ---------: | ---------: | ---------- | ------: | --: | --------------: | -------------------: |
| gemma3 1B Q4_0                 | 950.82 MiB |   999.89 M | CPU        |       4 |   0 |           pp512 |         59.65 ± 5.65 |
| gemma3 1B Q4_0                 | 950.82 MiB |   999.89 M | CPU        |       4 |   0 |           tg128 |         17.10 ± 2.12 |
| gemma3 1B Q4_0                 | 950.82 MiB |   999.89 M | CPU        |       4 |   1 |           pp512 |        86.48 ± 10.14 |
| gemma3 1B Q4_0                 | 950.82 MiB |   999.89 M | CPU        |       4 |   1 |           tg128 |         18.33 ± 0.89 |
```
