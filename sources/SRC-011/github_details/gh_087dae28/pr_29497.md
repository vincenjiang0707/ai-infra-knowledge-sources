## 正文

Closes #29462

### Description
A JSON schema request specifying an array with `minItems` greater than `maxItems` (e.g. `minItems: 10, maxItems: 2`) or a direct GBNF pattern like `root ::= "a"{10,2}` caused a fatal Out-Of-Memory (OOM) crash in `llama-server`. 

The crash happened because `llama-grammar.cpp` performed unsigned arithmetic (`max_times - min_times`) without verifying that `min_times <= max_times`. When `min > max`, this subtraction underflowed, resulting in a gigantic `n_opt` count (~18 quintillion), driving the server to immediately exhaust all available memory and crash with `std::bad_alloc`.

This PR:
1. Adds a guard in `json-schema-to-grammar.cpp` (`build_repetition`) to gracefully clamp `max_items = min_items` when contradictory bounds are provided in the schema.
2. Adds a strict safety check in `llama-grammar.cpp`'s `handle_repetitions` to throw a clean `std::runtime_error` if `min_times > max_times` ever reaches the engine, preventing the unbounded allocation loop.
