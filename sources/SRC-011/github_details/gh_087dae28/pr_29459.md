## 正文

## Overview

There is a bug in Level Zero that will crash or hang llama.cpp when using p2p in tensor split mode. See intel/compute-runtime#995 issue.

To avoid the issue, a contiguous block of direct memory is used which ensures that both GPUs involved in the p2p operation map it as one.

This only affects the tensor-split all-reduce buffers.

Run with GGML_SYCL_COMM_DIRECT_ALLOC=1 to enable the work-around.

## Additional information

The crash itself is a Level Zero bug, but while the driver fix in intel/compute-runtime is pending, this will be a work around for that.

The issue is triggered with `-sm tensor` and SYCL, and happens when the GPUs have a different physical mapping. The owning GPU may see a contiguous range, but the accessing GPU may have gaps.

I asked Claude Opus to work around the bug in intel/compute-runtime by simply not using a buffer that can be mapped non-contiguously. By not using the pool, but directly allocating, we get contiguous blocks.

When contiguous (for both GPUs involved in the p2p copy) there will be no crash and no hang.
