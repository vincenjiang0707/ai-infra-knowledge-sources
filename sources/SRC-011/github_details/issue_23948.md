# [Issue #23948] Feature request: (server) file upload API

state: open | updated: 2026-09-22T01:12:42Z
labels: 

## 正文

Problem: when user uploads large file, like a long audio recording, the uploading may take a while to finish. If this done on every new message, it will be quite annoying to wait

Proposed solution:
- Add a new POST and GET `files/{id}` API that allow upload (as multipart form data) and check if file exists  
    Note: the GET only return the file metadata, not the actual file; similar to [OAI endpoint](https://developers.openai.com/api/reference/resources/files/methods/retrieve)  
    Note (2): for POST, the web ui will be responsible for choosing the file ID, maybe by calculating hash of the file's content
- `/chat/completions` accepts an ID as file, maybe as a specific URI like `file_id://{id}` ; if files doesn't exist, the server returns with a status code error, containing a list of missing files to be uploaded
- Files are stored in-memory, not written to disk

CC @ggml-org/llama-ui if you agree on the spec to be implemented on the UI
