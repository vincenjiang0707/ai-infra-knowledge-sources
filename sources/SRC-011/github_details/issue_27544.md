### Problem description & steps to reproduce

On vulkan with np>1 and actually dispatching parallel sessions, along with model-native MTP (tested with Q3.6-27B and Q3.8-27B, different quants, from UD-Q4-XL to Q6_K) the performance collapses when n-max for the draft is set to > 1. My setup has 2xR9700, and ROCM seems to scale better, especially for np > 2, but I only tested until np = 4. See below. Single session works fine as expected, and also scales well with n-max, depending on the workload of course. With very large n-max (5-6) i sometime even see a spike to 60TPS+ when the predictions hit the spot. But mostly its in the 42-46TPS range single session. Setup / Contig notes included, mind that I rund with large context, 3x160k(*1024). 

This has also been reported in other issues, but I want to collect this here, so we can maybe focus efforts, debugging, etc. to arrive at a root cause. @0cc4m this follows up my statements in the dflash2 PR; hope this is a better home and naming you here since you mentioned that you are not aware of an issue with the scaling currently. Nvidia does not seem to be affected, but AMD seems to be, and one report in the dflash2 PR #27342 from one intel user did show the same behavior. I noticed that MTP/Dflash2 had the same issue, so my speculation is somewhere else, either in the vulkan backend or in some interworking between the sessions, spec and the backend. 

I tried to seach around, and here are some issues which might be related and/or have content / benchmarks which show the issue.

I'm happy to assist with any kind of debug output needed, and test patches. Would be super cool to have scalability with vulkan as well. Since I saw the same issue when testing the dFlash2 draft early on, this might be benefical there as well. If any further info is needed, dont hesitate.
