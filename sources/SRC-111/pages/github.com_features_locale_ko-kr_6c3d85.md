## 자동화 및 CI/CD


### /features Flex - 자동화 및 CI/CD - River Breakout

*모든 것을 자동화:* CI/CD, 테스트, 계획, 프로젝트 관리, GitHub Issues 라벨링, 승인, 온보딩 등

- 조직 전반에 걸쳐 모범 사례, 보안 및 규정 준수를 표준화하고 확장합니다.
- 파트너와 커뮤니티의 수천 가지 작업을 기반으로 빠르게 시작할 수 있습니다.

[GitHub 호스트 러너](https://docs.github.com/actions/using-github-hosted-runners/about-github-hosted-runners)

워크플로 실행을 위해 GitHub에서 호스팅하는 온디맨드 Linux, macOS, Windows, ARM 및 GPU 환경을 활용하여 클라우드로 자동화를 확장하세요.

[셀프 호스트 러너](https://docs.github.com/actions/hosting-your-own-runners)

레이블, 그룹, 정책을 활용해 환경을 더 많이 확보하고 자체 시스템에서 실행되는 작업을 보다 완벽하게 제어하세요. 오픈 소스 러너 애플리케이션도 함께 제공합니다.

## 애플리케이션 보안


### 발견 즉시 해결되는 애플리케이션 보안. GitHub Copilot Autofix 기반.

*발견 즉시 해결되는 애플리케이션 보안.* GitHub Copilot Autofix 기반.

- 앱 취약성과 secret 유출을
*방지, 포착, 해결*합니다. *과거 보안 경고를 타겟팅하여*대규모로 보안 부채를 줄입니다.- 개발자들에게 익숙하고 즐겨 사용하는
*GitHub 플랫폼에 내장*되어 있습니다.

[Code scanning](https://docs.github.com/code-security/code-scanning/automatically-scanning-your-code-for-vulnerabilities-and-errors/about-code-scanning)

GitHub의 업계 최고 수준의 의미론적 코드 분석 솔루션인 CodeQL을 사용하여 코드의 취약성을 찾으세요. 모든 pull request를 스캔하여 새로운 취약성이 발생하는 것을 방지합니다.

[GitHub Copilot Autofix](https://docs.github.com/en/code-security/code-scanning/managing-code-scanning-alerts/about-autofix-for-codeql-code-scanning)

GitHub Copilot을 기반으로 JavaScript, TypeScript, Java 및 Python에서 90%의 경고 유형에 대한 자동 수정을 생성합니다. 상황별 취약성 인텔리전스와 조언을 활용하여 신속하게 수정하세요.

[보안 캠페인](https://docs.github.com/en/enterprise-cloud@latest/code-security/securing-your-organization/fixing-security-alerts-at-scale&sa=D&source=docs&ust=1729524438944416&usg=AOvVaw2kubAWlMROH_emJPRJQNWU)

한 번에 최대 1,000건의 경고를 대상으로 자동 수정을 생성하여 취약성과 제로데이 공격의 위험을 빠르게 줄여주는 보안 캠페인을 통해 애플리케이션 보안 부채를 빠르게 해소하세요.

[Dependabot 경고](https://docs.github.com/code-security/dependabot/dependabot-alerts/about-dependabot-alerts#github-dependabot-alerts-for-vulnerable-dependencies)

새로운 취약성이 리포지토리에 영향을 미칠 때 알림을 받을 수 있으며, GitHub는 공개 및 비공개 리포지토리 모두에서 취약한 종속성을 감지하고 알려줍니다.

[GitHub Advisory Database](https://docs.github.com/code-security/security-advisories/global-security-advisories/browsing-security-advisories-in-the-github-advisory-database#about-the-github-advisory-database)

큐레이팅된 CVE와 GitHub 종속성 그래프에 연결된 보안 경고를 보여주는 GitHub의 알려진 취약성 데이터베이스를 탐색하거나 검색하세요.

## 거버넌스 및 관리


### 프로젝트와 팀 간의 액세스 및 권한 관리를 간소화하세요.

프로젝트와 팀 간의 *액세스 및 권한 관리를 간소화하세요*.

*권한을 업데이트하고, 조직의 성장에 따라 새로운 사용자를 추가하며*, 모든 사용자에게 필요한 권한을 정확하게 할당하세요.*Okta 및 Entra ID와 동기화하세요.*

[규정 준수 보고서](https://docs.github.com/enterprise-cloud@latest/admin/overview/accessing-compliance-reports-for-your-enterprise)

SOC 보고서, Cloud Security Alliance CAIQ(CSA CAIQ) 자체 평가 등의 GitHub의 클라우드 규정 준수 보고서에 액세스하여 보안 평가 및 인증 니즈를 지원하세요.

[리포지토리 규칙](https://docs.github.com/enterprise-cloud@latest/repositories/configuring-branches-and-merges-in-your-repository/managing-rulesets/about-rulesets)

확장 가능한 소스 코드 보호를 통해 조직의 보안을 강화하고, 규칙 인사이트를 사용하여 리포지토리에서 코드 변경이 어떻게 발생했는지, 그리고 그 이유가 무엇인지 쉽게 검토할 수 있습니다.

[Enterprise 계정](https://docs.github.com/enterprise-cloud@latest/admin/overview/about-enterprise-accounts)

Enterprise 계정을 통해 단일화된 가시성 및 관리 환경에서 조직과 GitHub 환경 간의 협업을 지원합니다.

[GitHub Connect](https://docs.github.com/enterprise-server@latest/admin/configuration/configuring-github-connect/about-github-connect)

GitHub Enterprise Server 인스턴스와 GitHub Enterprise Cloud 간에 기능과 워크플로를 공유합니다.

[SAML](https://docs.github.com/github-ae@latest/admin/identity-and-access-management/using-saml-for-enterprise-iam/about-saml-for-enterprise-iam)

SAML을 사용하여 리포지토리, 문제, pull request 등의 조직 리소스에 대한 액세스를 안전하게 제어하는 동시에, 사용자가 GitHub 사용자 이름으로 인증할 수 있도록 하세요.

[LDAP](https://docs.github.com/enterprise-server@latest/admin/identity-and-access-management/using-ldap-for-enterprise-iam/using-ldap)

리포지토리 관리를 중앙 집중화합니다. LDAP는 타사 소프트웨어와 대기업 사용자 디렉터리를 통합하는 데 가장 일반적으로 사용되는 프로토콜 중 하나입니다.

[Enterprise Managed User](https://docs.github.com/en/enterprise-cloud@latest/admin/managing-iam/understanding-iam-for-enterprises/about-enterprise-managed-users)

ID 공급자(IdP)가 제공하는 GitHub Enterprise Cloud 사용자의 수명 주기와 인증을 관리합니다.

[Enterprise Managed User에서 자체 ID 공급자 사용](https://docs.github.com/en/enterprise-cloud@latest/admin/managing-iam/provisioning-user-accounts-with-scim/provisioning-users-and-groups-with-scim-using-the-rest-api)

Enterprise Managed Users에 대해 SSO 및 SCIM 공급자를 각각 별도로 선택하여 사용할 수 있어, 사용자 수명 주기를 보다 유연하게 관리할 수 있습니다.
