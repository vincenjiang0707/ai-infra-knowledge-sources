# GitHub Issues

문제를 생성하여 세부 문제로 나누고 진행 상황을 추적하며 사용자 정의 필드를 추가하고 대화를 나눕니다. 대규모 프로젝트를 테이블, 보드, 로드맵으로 시각화하고 모두를 코드로 자동화합니다.

### 대화 간소화

GitHub Flavored Markdown를 사용하여 아이디어를 표현하고 기여자를 언급하며 이모지로 반응하고 첨부 파일로 증명하고 커밋, 풀 리퀘스트, 릴리스, 배포 참고 자료를 확인합니다. 기여자와 팀에 할당하거나 마일스톤 및 프로젝트에 이들을 추가하여 조율합니다. 단일한 타임라인에서 모두 처리합니다.

## 업무 방식에 맞춰 변하는 프로젝트

반복, 우선순위, 스토리 포인트, 일정, 참고 사항, 링크 등의 메타데이터를 추적합니다. 프로젝트에 고객 필드를 추가하고 문제 사이드바에서 수정합니다.

신규 프로젝트 인사이트로 생성한 반복 주기, 마일스톤 또는 기타 고객 필드의 현재 상태를 추적합니다. 팀이 새로운 번업 차트를 사용하여 진행하는 데 어려움을 주는 병목 현상과 문제를 확인합니다.

신규 프로젝트를 시작할 때 공유와 재사용을 위해 템플릿을 생성합니다. 팀 전체에 영감을 공유하고 단 한 번의 클릭으로 시작할 수 있습니다.

워크플로를 사용하여 프로젝트 계획을 가속화합니다. 문제를 자동으로 분류하고 사용자 정의 필드 값을 세팅하거나 문제를 보관합니다.

## 필요한 곳 어디에나 사용 가능한 GitHub Issues

### 자주 묻는 질문

#### GitHub Issues란 무엇인가요?


모두가 작업을 계획하고 문제를 추적하며 구축할 내용에 대해 상의할 방법을 찾습니다. 이런 보편적인 질문에 대한 해답이 GitHub Issues이며, 이는 모든 리포지토리에 내장되어 있습니다. GitHub의 문제 추적은 간편성, 참조 자료, 세련된 서식에 초점을 맞추었기 때문에 독보적입니다.

GitHub Issues를 사용하면 GitHub Flavored Markdown으로 아이디어를 표현할 수 있고 기여자를 할당하고 언급할 수 있으며 이모지로 반응하고 첨부 파일과 비디오로 증명하고 커밋, 풀 리퀘스트, 배포 등의 참조 코드를 추가할 수 있습니다. 작업 목록을 사용하면 큰 문제를 작업에 세분화하고 마일스톤과 라벨로 작업을 심도 있게 조직화하며 관계성과 의존성을 추적할 수 있습니다.

개발자를 위한 GitHub Issues가 구축되었습니다. 간편하고 유연하며 강력합니다.

#### Projects란 무엇인가요?


팀과 프로젝트가 커질수록 작업 방식도 변화합니다. 방법론이 하드 코딩된 도구는 매우 구체적이고 고정적이므로 보편적으로 적용할 수 없습니다. 종종 생각할 공간을 갖기 위해 전용 스프레드시트나 노트패드를 만들어 내는 경우가 있습니다. 그러면 계획과 실제 작업이 일어나는 곳 사이의 연결성이 끊깁니다.

새로운 Projects는 계획을 팀이 실행하고 있는 작업에 직접적으로 연결하고 팀이 원하는 무엇에든 유연하게 적용합니다. 프로젝트 테이블을 스프레드시트처럼 구축하면 필터링, 정렬, 그룹 문제, 풀 리퀘스트를 위한 실시간 캔버스를 제공합니다. 프로젝트 테이블이나 함께 제공되는 프로젝트 보드를 사용자 정의 필드와 함께 사용하여 스프린트를 추적하고 기능을 계획하며 대규모 릴리스를 관리할 수 있습니다.

#### Projects에 대한 액세스 계획은 무엇인가요?


모든 사용자가 GitHub Issues 및 Projects의 무료 티어에 액세스할 수 있습니다. 유료 티어에 대한 자세한 사항은 GitHub 요금 페이지를 참조하세요.

#### GitHub Enterprise Server에서 신규 Projects를 사용할 수 있나요?


예! GitHub Enterprise Server(GHES) 지원은 GitHub의 온프레미스 기능을 사용하기 전 한두 분기의 정규 케이던스를 따릅니다.
