#### GitHub Enterpriseについて


#### GitHub Enterpriseとは何ですか?


GitHub Enterprise は、現代の開発における複雑なワークフロー向けに設計された、エンタープライズ グレードのソフトウェア開発プラットフォームです。

拡張可能なプラットフォーム ソリューションである GitHub Enterprise は、組織が[追加のツールや機能をシームレスに統合](https://github.com/marketplace?type=&locale=ja)して、開発環境を特定のニーズに合わせてカスタマイズし、全体的な生産性を強化できるようにします。

#### 組織がGitHub Enterpriseを使用すべき理由とは


組織が GitHub Enterprise の使用を検討すべき理由はいくつかあります。

**AI 駆動の開発による大規模な開発迅速化:**GitHub は、世界で最も広く導入されている GitHub Copilot が搭載された開発者プラットフォームで、組織が革新的なソフトウェアを大規模にビルド、セキュア化、提供するために役立ちます。**簡素化されたアプリケーション セキュリティ:**開発者ワークフローに組み込まれた GitHub Advanced Security などのネイティブ セキュリティ ツールは、可視性とコントロールを向上させながら、開発者がセキュリティ問題を簡単に修正できるようにします。**ガバナンスとコンプライアンスの一元化:**お客様は、ガバナンスを大規模に管理し、特定のニーズに合わせてビジネス ルールやポリシーを適用するために役立つ、さまざまな管理機能にアクセスできます。**生産性とコラボレーションの強化:**GitHub Actions を使用する自動 CI/CD ワークフローで生産性を向上させ、GitHub Projects と GitHub Issues を用いて効果的にコラボレーションし、ホストされるパッケージを GitHub Packages で管理して、GitHub Codespace でビルド済みかつ設定済みの開発環境を活用します。**より優れた柔軟性とデータの制御:**GitHub Enterprise Server でセルフホストしているか、GitHub Enterprise Cloud を使用しているかにかかわらず、GitHub はお客様に柔軟性を提供し、データの制御を可能にします。[データ レジデンシー機能を備えた GitHub Enterprise Cloud](https://github.com/enterprise/data-residency?locale=ja)の提供開始により、お客様はコードなどの特定のデータが格納される場所をより良く制御できるようになりました。今すぐ[無料の 30 日トライアル](https://github.com/account/enterprises/new?locale=ja)を開始しましょう。または、詳細について[GitHubの営業チームにお問い合わせ](https://github.com/enterprise/contact/data-residency?locale=ja)ください。

#### 誰がGitHub Enterpriseを使用していますか?


GitHub Enterprise は、ソフトウェア開発プロセスにより優れた生産性、コラボレーション、セキュリティ機能を求めるあらゆる規模の組織によって使用されています。GitHub Enterprise は、スタートアップ企業から大企業まで、チームの規模に合わせてスケールできます。

#### GitHub Enterprise Cloudとは何ですか?


GitHub Enterprise Cloud は、GitHub Enterprise のクラウドベースのソリューションで、GitHub のサーバーでホストされています。このため、組織が独自のサーバー、インフラストラクチャ、更新を維持する必要がなくなり、開発に集中できるようになります。

GitHub Enterprise Cloud は、中核的な生産性機能とコラボレーション機能に加えて、セキュリティ、サポート、マネージド ユーザーなどに関する多くの追加機能やアドオンへのアクセスも提供します。

お客様は、必要に応じてユーザーを簡単に追加または削除でき、ニーズの変化に応じてストレージ容量や処理能力を増加させることも可能です。

データをより細かく制御したいと考えるお客様には、[データ レジデンシー機能を備えた GitHub Enterprise Cloud](https://github.com/enterprise/data-residency?locale=ja) が拡張されたエンタープライズ グレードの機能を提供し、コードの保存場所をより良く制御できるようにします。今すぐ[無料の 30 日トライアル](https://github.com/account/enterprises/new?locale=ja)を開始しましょう。または、詳細について[GitHubの営業チームにお問い合わせ](https://github.com/enterprise/contact/data-residency?locale=ja)ください。

#### GitHub Enterprise Serverとは何ですか?


[GitHub Enterprise Server](https://docs.github.com/enterprise-server@3.5/admin/overview/about-github-enterprise-server) は、GitHub Enterprise のセルフホステッド バージョンです。オンプレミスまたはプライベート クラウドにインストールされ、セキュアでカスタマイズ可能なソース コード管理とコラボレーション プラットフォームを組織に提供します。

GitHub Enterprise Server の主な利点の 1 つは、組織がそのソース コードとデータを完全に管理できるようにすることです。組織は、リポジトリの保存場所を選択し、誰がリポジトリにアクセスできるかを制御できます。管理者は、他のツールの統合や、カスタム ワークフローの実装などの特定のニーズを満たすために、プラットフォームをカスタマイズすることもできます。

GitHub Enterprise Server では、強化されたセキュリティ機能とコンプライアンス機能も提供されています。組織は、認証のための LDAP や SAML の使用、2 要素認証の設定、ネットワーク セキュリティ対策の実装など、特定のセキュリティ要件を満たすためにインスタンスを設定できます。また、監査ログ、アクセス コントロール、脆弱性スキャンなどのコンプライアンス機能も搭載されています。

#### GitHub Enterpriseのセキュリティについて教えてください。


GitHub Enterprise はセキュリティを念頭に設計されており、組織がコードとデータを保護するために役立つさまざまな機能が含まれています。GitHub Enterprise が提供するセキュリティ機能には以下のようなものがあります。

認証とアクセス コントロール: GitHub Enterprise には、2 要素認証、LDAP、Active Directory インテグレーション、OAuth 認証が含まれています。これらは、組織内で認可されたユーザーのみがリポジトリとデータにアクセスできることを確実にするために役立ちます。

暗号化: ユーザーのコンピューターと GitHub Enterprise のサーバー間で転送されるすべてのデータは、HTTPS を使用して暗号化されています。保管されているすべてのデータには AES-256 暗号化が使用されます。

脆弱性スキャン: GitHub Enterprise には、既知の脆弱性を検知してユーザーに警告できる、セキュリティ スキャン機能が組み込まれています。

監査ログ: プラットフォームには、リポジトリ アクセス、変更、削除を含めたすべてのユーザー アクションが記録された詳しい監査ログがあります。このログは、組織がユーザー アクティビティを追跡して監視し、潜在的なセキュリティ問題を特定するために役立ちます。

カスタマイズ可能なポリシー: GitHub Enterprise では、組織がリポジトリ アクセスに関するカスタム ポリシーを作成できます。カスタム ポリシーは、コンプライアンス要件の適用や、極秘データへの許可されていないアクセスの防止に役立ちます。

定期的なセキュリティ更新: 定期的な更新を提供し、潜在的なセキュリティ上の脅威を監視して、発生するあらゆる問題にすばやく対応する専属のセキュリティ チームも設置されています。

#### 開発者がGitHub Enterpriseと連携するにはどうすればよいですか?


開発者は、プラットフォームに組み込まれているさまざまなツールを使用して GitHub Enterprise と連携できます。これには以下が含まれます。

プルリクエスト: 開発者がリポジトリに対する変更を提案し、それらをレビューのために送信することを可能にします。他のチーム メンバーは、変更をレビューし、コメントを残して、さらなる改善を提案できます。

GitHub Projects: 開発者が問題を追跡し、タスクを割り当てて、作業の優先順位付けを行えるようにします。これは、チームが計画通りに作業を進め、問題をすばやく特定して解決し、全員が同じ目標を目指して取り組んでいることを確実にするために役立ちます。

GitHub Discussions: 特定のトピックに関する開発者間の話し合いを推奨します。これは特に、複雑な問題のトリアージや、プロジェクトの方向性に関する意思決定に役立ちます。

#### DevOpsプラットフォームとは何ですか?


DevOps プラットフォームとは、ソフトウェア開発チームと IT 運用チームが連携し、ソフトウェア デリバリー プロセスを自動化できるようにする一連のツール、テクノロジー、およびプラクティスのことです。通常、これにはバージョン管理、継続的インテグレーションと継続的デリバリー (CI/CD)、自動テスト、デプロイ自動化、監視が含まれます。

DevOps プラットフォームの主な目的は、ソフトウェア開発チームと IT 運用チームに単一の環境を提供することです。DevOps プラットフォームは、組織がソフトウェア デリバリー プロセスの自動化を通じてソフトウェアを提供する時間とコストを節約できるようにすると同時に、アプリケーションの信頼性、セキュリティ、スケーラビリティも向上させます。

#### デベロッパーエクスペリエンスとは何ですか?


デベロッパーエクスペリエンス (DevEx) とは、ソフトウェア開発者が開発ツール、フレームワーク、プラットフォームを使用してソフトウェア アプリケーションを作成するときの全体的な経験のことです。これには、オンボーディング、メンテナンス、使いやすさ、生産性など、開発者とツールのやり取りにおけるあらゆる側面が含まれます。

DevEx 最適化の目的は、開発者による高品質ソフトウェアの迅速な開発を、可能な限り容易にすることです。これには、直感的なインターフェイスを備えたツールの設計、簡潔明瞭なドキュメントの提供、ワークフローへのツールのシームレスな統合、開発者が課題や障害を乗り越えられるように支援する包括的なサポートの提供などが考えられます。

DevEx を優先することで、組織はソフトウェア開発プロセスのスピードと品質を改善し、開発者の満足度と定着率を向上させて、最終的により優れた製品を提供することができます。

#### ソフトウェア開発プラットフォームとは何ですか?


ソフトウェア開発プラットフォームとは、ソフトウェア開発者がソフトウェア アプリケーションの作成、テスト、デプロイ、保守を行えるようにする一連のツール、テクノロジー、およびリソースのことです。通常、これにはプログラミング言語またはフレームワーク、統合開発環境 (IDE)、ライブラリ、コード リポジトリ、デバッグ ツール、テスト ツール、デプロイ オプション、ホスティング オプションが含まれます。

ソフトウェア開発プラットフォームの目的は、高品質ソフトウェアの開発を容易にする包括的な一連のツールとリソースを開発者に提供することです。ソフトウェア開発プラットフォームは、ソフトウェア開発向けの統合された環境を提供することで、開発者がそのワークフローを合理化し、エラーを低減して、作業のスピードと品質を向上できるように支援します。さらに、ソフトウェア開発プラットフォームの多くは、ソフトウェア開発プラクティスを改善するためのサポート、アドバイス、リソースを提供できる開発者コミュニティへのアクセスも提供します。

#### アプリケーション開発プラットフォームとは何ですか?


アプリケーション開発プラットフォームは、開発者がカスタム ソフトウェア アプリケーションをビルド、デプロイ、管理することを可能にする一連のツールです。

通常、このタイプのプラットフォームには、プログラミング言語、ソフトウェア開発キット (SDK)、アプリケーション プログラミング インターフェイス (API)、ライブラリ、テストツール、デバッグツールが含まれています。

これらのツールは、モバイル デバイスやウェブ ブラウザなどの特定のプラットフォーム向けのカスタム アプリケーションを、開発者がより簡単に作成し、デプロイできるように設計されています。

アプリケーション開発プラットフォームの目的は、特定のプラットフォームやデバイス固有の要件を満たす高品質アプリケーションの作成を容易にする、包括的な一連のツールを開発者に提供することです。

#### ソフトウェアの共同開発とは何ですか?


ソフトウェアの共同開発とは、ソフトウェア アプリケーションを作成、テスト、デプロイするためのチームとして共同で作業するプロセスのことです。これには、ブレインストーミング、計画、コード レビュー、テスト、デプロイなどのさまざまなアクティビティが含まれます。コラボレーションは、複数の開発者とステークホルダーが連携することを可能にするため、ソフトウェア開発プロセスに不可欠な要素です。

### GitHub Enterpriseについて

#### GitHub Enterpriseとは何ですか?


GitHub Enterprise は、現代の開発における複雑なワークフロー向けに設計された、エンタープライズ グレードのソフトウェア開発プラットフォームです。

拡張可能なプラットフォーム ソリューションである GitHub Enterprise は、組織が[追加のツールや機能をシームレスに統合](https://github.com/marketplace?type=&locale=ja)して、開発環境を特定のニーズに合わせてカスタマイズし、全体的な生産性を強化できるようにします。

#### 組織がGitHub Enterpriseを使用すべき理由とは


組織が GitHub Enterprise の使用を検討すべき理由はいくつかあります。

**AI 駆動の開発による大規模な開発迅速化:**GitHub は、世界で最も広く導入されている GitHub Copilot が搭載された開発者プラットフォームで、組織が革新的なソフトウェアを大規模にビルド、セキュア化、提供するために役立ちます。**簡素化されたアプリケーション セキュリティ:**開発者ワークフローに組み込まれた GitHub Advanced Security などのネイティブ セキュリティ ツールは、可視性とコントロールを向上させながら、開発者がセキュリティ問題を簡単に修正できるようにします。**ガバナンスとコンプライアンスの一元化:**お客様は、ガバナンスを大規模に管理し、特定のニーズに合わせてビジネス ルールやポリシーを適用するために役立つ、さまざまな管理機能にアクセスできます。**生産性とコラボレーションの強化:**GitHub Actions を使用する自動 CI/CD ワークフローで生産性を向上させ、GitHub Projects と GitHub Issues を用いて効果的にコラボレーションし、ホストされるパッケージを GitHub Packages で管理して、GitHub Codespace でビルド済みかつ設定済みの開発環境を活用します。**より優れた柔軟性とデータの制御:**GitHub Enterprise Server でセルフホストしているか、GitHub Enterprise Cloud を使用しているかにかかわらず、GitHub はお客様に柔軟性を提供し、データの制御を可能にします。[データ レジデンシー機能を備えた GitHub Enterprise Cloud](https://github.com/enterprise/data-residency?locale=ja)の提供開始により、お客様はコードなどの特定のデータが格納される場所をより良く制御できるようになりました。今すぐ[無料の 30 日トライアル](https://github.com/account/enterprises/new?locale=ja)を開始しましょう。または、詳細について[GitHubの営業チームにお問い合わせ](https://github.com/enterprise/contact/data-residency?locale=ja)ください。

#### 誰がGitHub Enterpriseを使用していますか?


GitHub Enterprise は、ソフトウェア開発プロセスにより優れた生産性、コラボレーション、セキュリティ機能を求めるあらゆる規模の組織によって使用されています。GitHub Enterprise は、スタートアップ企業から大企業まで、チームの規模に合わせてスケールできます。

#### GitHub Enterprise Cloudとは何ですか?


GitHub Enterprise Cloud は、GitHub Enterprise のクラウドベースのソリューションで、GitHub のサーバーでホストされています。このため、組織が独自のサーバー、インフラストラクチャ、更新を維持する必要がなくなり、開発に集中できるようになります。

GitHub Enterprise Cloud は、中核的な生産性機能とコラボレーション機能に加えて、セキュリティ、サポート、マネージド ユーザーなどに関する多くの追加機能やアドオンへのアクセスも提供します。

お客様は、必要に応じてユーザーを簡単に追加または削除でき、ニーズの変化に応じてストレージ容量や処理能力を増加させることも可能です。

データをより細かく制御したいと考えるお客様には、[データ レジデンシー機能を備えた GitHub Enterprise Cloud](https://github.com/enterprise/data-residency?locale=ja) が拡張されたエンタープライズ グレードの機能を提供し、コードの保存場所をより良く制御できるようにします。今すぐ[無料の 30 日トライアル](https://github.com/account/enterprises/new?locale=ja)を開始しましょう。または、詳細について[GitHubの営業チームにお問い合わせ](https://github.com/enterprise/contact/data-residency?locale=ja)ください。

#### GitHub Enterprise Serverとは何ですか?


[GitHub Enterprise Server](https://docs.github.com/enterprise-server@3.5/admin/overview/about-github-enterprise-server) は、GitHub Enterprise のセルフホステッド バージョンです。オンプレミスまたはプライベート クラウドにインストールされ、セキュアでカスタマイズ可能なソース コード管理とコラボレーション プラットフォームを組織に提供します。

GitHub Enterprise Server の主な利点の 1 つは、組織がそのソース コードとデータを完全に管理できるようにすることです。組織は、リポジトリの保存場所を選択し、誰がリポジトリにアクセスできるかを制御できます。管理者は、他のツールの統合や、カスタム ワークフローの実装などの特定のニーズを満たすために、プラットフォームをカスタマイズすることもできます。

GitHub Enterprise Server では、強化されたセキュリティ機能とコンプライアンス機能も提供されています。組織は、認証のための LDAP や SAML の使用、2 要素認証の設定、ネットワーク セキュリティ対策の実装など、特定のセキュリティ要件を満たすためにインスタンスを設定できます。また、監査ログ、アクセス コントロール、脆弱性スキャンなどのコンプライアンス機能も搭載されています。

#### GitHub Enterpriseのセキュリティについて教えてください。


GitHub Enterprise はセキュリティを念頭に設計されており、組織がコードとデータを保護するために役立つさまざまな機能が含まれています。GitHub Enterprise が提供するセキュリティ機能には以下のようなものがあります。

認証とアクセス コントロール: GitHub Enterprise には、2 要素認証、LDAP、Active Directory インテグレーション、OAuth 認証が含まれています。これらは、組織内で認可されたユーザーのみがリポジトリとデータにアクセスできることを確実にするために役立ちます。

暗号化: ユーザーのコンピューターと GitHub Enterprise のサーバー間で転送されるすべてのデータは、HTTPS を使用して暗号化されています。保管されているすべてのデータには AES-256 暗号化が使用されます。

脆弱性スキャン: GitHub Enterprise には、既知の脆弱性を検知してユーザーに警告できる、セキュリティ スキャン機能が組み込まれています。

監査ログ: プラットフォームには、リポジトリ アクセス、変更、削除を含めたすべてのユーザー アクションが記録された詳しい監査ログがあります。このログは、組織がユーザー アクティビティを追跡して監視し、潜在的なセキュリティ問題を特定するために役立ちます。

カスタマイズ可能なポリシー: GitHub Enterprise では、組織がリポジトリ アクセスに関するカスタム ポリシーを作成できます。カスタム ポリシーは、コンプライアンス要件の適用や、極秘データへの許可されていないアクセスの防止に役立ちます。

定期的なセキュリティ更新: 定期的な更新を提供し、潜在的なセキュリティ上の脅威を監視して、発生するあらゆる問題にすばやく対応する専属のセキュリティ チームも設置されています。

### GitHub Enterpriseを使用する

#### 開発者がGitHub Enterpriseと連携するにはどうすればよいですか?


開発者は、プラットフォームに組み込まれているさまざまなツールを使用して GitHub Enterprise と連携できます。これには以下が含まれます。

プルリクエスト: 開発者がリポジトリに対する変更を提案し、それらをレビューのために送信することを可能にします。他のチーム メンバーは、変更をレビューし、コメントを残して、さらなる改善を提案できます。

GitHub Projects: 開発者が問題を追跡し、タスクを割り当てて、作業の優先順位付けを行えるようにします。これは、チームが計画通りに作業を進め、問題をすばやく特定して解決し、全員が同じ目標を目指して取り組んでいることを確実にするために役立ちます。

GitHub Discussions: 特定のトピックに関する開発者間の話し合いを推奨します。これは特に、複雑な問題のトリアージや、プロジェクトの方向性に関する意思決定に役立ちます。


#### Azure の Boards と Pipelines を停止することなく、リポジトリを Azure DevOps から GitHub Enterprise に移行可能ですか?


はい。[Azure DevOps から GitHub Enterpriseには](https://github.com/enterprise/migrating-to-github/ado?locale=ja)、運用を維持したまま移行できます。単一の"パイロット" リポジトリをまず移行させ、エージェント型 DevOps の利点を検証することから始めます。既存の Azure DevOps プロジェクトと並行して GitHub を利用し、ご自身のタイミングで移行を進められます。

### エンタープライズ ソフトウェア開発プラットフォームの使用を開始する

#### DevOpsプラットフォームとは何ですか?


DevOps プラットフォームとは、ソフトウェア開発チームと IT 運用チームが連携し、ソフトウェア デリバリー プロセスを自動化できるようにする一連のツール、テクノロジー、およびプラクティスのことです。通常、これにはバージョン管理、継続的インテグレーションと継続的デリバリー (CI/CD)、自動テスト、デプロイ自動化、監視が含まれます。

DevOps プラットフォームの主な目的は、ソフトウェア開発チームと IT 運用チームに単一の環境を提供することです。DevOps プラットフォームは、組織がソフトウェア デリバリー プロセスの自動化を通じてソフトウェアを提供する時間とコストを節約できるようにすると同時に、アプリケーションの信頼性、セキュリティ、スケーラビリティも向上させます。

#### デベロッパーエクスペリエンスとは何ですか?


デベロッパーエクスペリエンス (DevEx) とは、ソフトウェア開発者が開発ツール、フレームワーク、プラットフォームを使用してソフトウェア アプリケーションを作成するときの全体的な経験のことです。これには、オンボーディング、メンテナンス、使いやすさ、生産性など、開発者とツールのやり取りにおけるあらゆる側面が含まれます。

DevEx 最適化の目的は、開発者による高品質ソフトウェアの迅速な開発を、可能な限り容易にすることです。これには、直感的なインターフェイスを備えたツールの設計、簡潔明瞭なドキュメントの提供、ワークフローへのツールのシームレスな統合、開発者が課題や障害を乗り越えられるように支援する包括的なサポートの提供などが考えられます。

DevEx を優先することで、組織はソフトウェア開発プロセスのスピードと品質を改善し、開発者の満足度と定着率を向上させて、最終的により優れた製品を提供することができます。

#### ソフトウェア開発プラットフォームとは何ですか?


ソフトウェア開発プラットフォームとは、ソフトウェア開発者がソフトウェア アプリケーションの作成、テスト、デプロイ、保守を行えるようにする一連のツール、テクノロジー、およびリソースのことです。通常、これにはプログラミング言語またはフレームワーク、統合開発環境 (IDE)、ライブラリ、コード リポジトリ、デバッグ ツール、テスト ツール、デプロイ オプション、ホスティング オプションが含まれます。

ソフトウェア開発プラットフォームの目的は、高品質ソフトウェアの開発を容易にする包括的な一連のツールとリソースを開発者に提供することです。ソフトウェア開発プラットフォームは、ソフトウェア開発向けの統合された環境を提供することで、開発者がそのワークフローを合理化し、エラーを低減して、作業のスピードと品質を向上できるように支援します。さらに、ソフトウェア開発プラットフォームの多くは、ソフトウェア開発プラクティスを改善するためのサポート、アドバイス、リソースを提供できる開発者コミュニティへのアクセスも提供します。

これらのツールは、モバイル デバイスやウェブ ブラウザなどの特定のプラットフォーム向けのカスタム アプリケーションを、開発者がより簡単に作成し、デプロイできるように設計されています。

アプリケーション開発プラットフォームの目的は、特定のプラットフォームやデバイス固有の要件を満たす高品質アプリケーションの作成を容易にする、包括的な一連のツールを開発者に提供することです。
