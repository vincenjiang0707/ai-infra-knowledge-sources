# Faites avancer le code. Maintenez le main au vert.

Que le code soit écrit par vous, un membre de votre équipe ou un agent IA, révisez-le dans le contexte, exécutez les vérifications qui importent et décidez ce qui mérite de passer au `main`

.

## Chaque mois sur GitHub

+ de 43 millions de pull requests fusionnées

+ de 82 millions de pushs de commits

+ de 10 millions de nouveaux repos créés

## Fusionnez ce qui satisfait aux critères

Faites circuler chaque modification au travers d’un workflow connecté, divisé en étapes révisables, vérifié selon vos normes et prêt à être fusionné.

Divisez les modifications étendues en pull requests plus petites et connectées grâce aux pull requests empilées.

[En savoir plus sur les pull requests empilées](https://gh.io/stacks)

Placez les pull requests qui sont prêtes dans une file d’attente de fusion qui vérifie chacune d’entre elles par rapport à la dernière branche de base avant la fusion.

[En savoir plus sur la file d’attente de fusion](https://docs.github.com/repositories/configuring-branches-and-merges-in-your-repository/configuring-pull-request-merges/managing-a-merge-queue)

Utilisez des ensembles de règles pour protéger les branches et l’historique de commits dans l’ensemble de votre organisation.

[En savoir plus sur les ensembles de règles](https://docs.github.com/repositories/configuring-branches-and-merges-in-your-repository/managing-rulesets/about-rulesets)

## Offrez à chaque modification la révision dont elle a besoin.

Visualisez l’ensemble du contexte, concentrez-vous sur les tâches qui nécessitent votre intervention et sollicitez Copilot lorsqu’une autre paire d’yeux peut être mise à contribution.

Révisez le code avec la conversation, les vérifications et l’historique nécessaires à partir de github.com, la CLI GitHub, votre éditeur ou GitHub Mobile.

[Passez en revue les révisions de pull requests](https://docs.github.com/pull-requests/reference/pull-request-reviews)

Utilisez la boîte de réception de pull requests pour prendre connaissance des révisions qui nécessitent votre intervention, des pull requests qui doivent être corrigées et des tâches prêtes à être fusionnées.

[Ouvrez la boîte de réception de pull requests](https://github.com/pulls?locale=fr-FR)

Faites intervenir Copilot dans la revue pour comprendre les modifications, traiter les commentaires et effectuer un passage automatisé en complément de l'appréciation de votre équipe.

[En savoir plus sur la revue de code Copilot](https://docs.github.com/copilot/how-tos/copilot-on-github/use-copilot-agents/copilot-code-review)
