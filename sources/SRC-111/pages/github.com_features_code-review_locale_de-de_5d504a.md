# Halte den Code in Bewegung. Halte main stabil.

Unabhängig davon, ob der Code von dir, einem Teammitglied oder einem KI-Agenten geschrieben wurde – überprüfe ihn im Kontext, führe die relevanten Prüfungen aus und entscheide, was in `main`

übernommen wird.

## Merge das, was den Anforderungen entspricht

Führe jede Änderung durch einen durchgängigen Workflow: aufgelöst in überschaubare Schritte, überprüft anhand deiner Standards und bereit zum Mergen.

Teile eine große Änderung mit gestapelten Pull Requests in kleinere, miteinander verbundene Pull Requests auf.

[Mehr über gestapelte Pull Requests erfahren](https://gh.io/stacks)

Füge fertige Pull Requests in eine Mergewarteschlange ein, die jeden Pull Request vor dem Mergen mit dem neuesten Basis-Branch abgleicht.

[Mehr über Mergewarteschlangen erfahren](https://docs.github.com/repositories/configuring-branches-and-merges-in-your-repository/configuring-pull-request-merges/managing-a-merge-queue)

Verwende Regelsätze, um deine Branches und den Commit-Verlauf in deiner gesamten Organisation zu schützen.

[Mehr über Regelsätze erfahren](https://docs.github.com/repositories/configuring-branches-and-merges-in-your-repository/managing-rulesets/about-rulesets)

## Überprüfe jede Änderung so, wie es nötig ist.

Behalte den gesamten Kontext im Blick, konzentriere dich auf die Aufgaben, bei denen du gefragt bist, und setze GitHub Copilot ein, wenn eine zweite Meinung helfen kann.

Überprüfe Code zusammen mit den dazugehörigen Kommentaren, Checks und dem Verlauf – auf github.com, mit GitHub CLI, in deinem Editor oder über GitHub Mobile.

[Entdecke Pull Request Reviews](https://docs.github.com/pull-requests/reference/pull-request-reviews)

Im Posteingang für Pull Requests siehst du Überprüfungen, die auf dich warten, Pull Requests, die korrigiert werden müssen, und Arbeit, die zum Mergen bereit ist.

[Öffne den Posteingang für Pull Requests](https://github.com/pulls?locale=de-DE)

Beziehe GitHub Copilot in den Review ein, um Änderungen zu verstehen, Feedback zu bearbeiten und neben der Einschätzung deines Teams auch eine automatisierte Freigabe zu erhalten.

[Mehr über GitHub Copilot Code Review](https://docs.github.com/copilot/how-tos/copilot-on-github/use-copilot-agents/copilot-code-review)
