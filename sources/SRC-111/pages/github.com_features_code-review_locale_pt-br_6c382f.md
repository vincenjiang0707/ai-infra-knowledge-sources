## Faça o merge do que está no nível

Mova todas as alterações através de um fluxo de trabalho conectado: dividido em etapas passíveis de revisão, verificado em relação aos seus padrões e prontos para o merge.

Divida uma grande alteração em pull requests menores e conectados com pull requests empilhados.

[Saiba sobre pull requests em pilha](https://gh.io/stacks)

Ponha os pull requests prontos em uma fila de merge que verifica cada um em relação ao branch mais recente antes de fazer o merge.

[Saiba sobre a fila de merge](https://docs.github.com/repositories/configuring-branches-and-merges-in-your-repository/configuring-pull-request-merges/managing-a-merge-queue)

Use rulesets para proteger seus branches e faça commit do histórico em sua organização.

[Saiba sobre rulesets](https://docs.github.com/repositories/configuring-branches-and-merges-in-your-repository/managing-rulesets/about-rulesets)

## Dê todas as chances de revisão de que ele precisa.

Veja todo o contexto, enfoque no trabalho que precisa de você, e use o Copilot quando um segundo par de olhos puder ajudar.

Revise o código com a conversação, verificações e histórico necessários de github.com, GitHub CLI, seu editor ou o GitHub Mobile.

[Explore as revisões de pull requests](https://docs.github.com/pull-requests/reference/pull-request-reviews)

Use a caixa de entrada de pull requests para ver as revisões que o aguardam, pull requests que precisam correção e trabalho pronto para merge.

[Abra a caixa de entrada de pull requests](https://github.com/pulls?locale=pt-BR)

Inclua o Copilot na revisão para entender as alterações, trabalhar através de feedback e obter uma aprovação automatizada, complementando a avaliação da sua equipe.

[Saiba mais sobre o code review do Copilot](https://docs.github.com/copilot/how-tos/copilot-on-github/use-copilot-agents/copilot-code-review)
