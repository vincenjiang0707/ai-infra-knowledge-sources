コードレビューとプルリクエスト

# コードをスムーズに進める。main を常に正常に保とう。

コードを書いたのが、あなたでも、同僚でも、AI エージェントでも、そのコードをコンテキストに沿ってレビューし、重要な検証を実行し、`main`

に入れるべきか判断します。

## GitHub で毎月

4,300万超 マージされたプルリクエスト

8,200万超 プッシュされたコミット

1,000万超 新たなリポジトリを作成

## 基準をクリアしたものだけをマージ

すべての変更を、連携された一つのワークフローに沿って管理。レビューしやすい単位に分割し、設定した基準を基に検証してマージできる状態にします。

スタック型プルリクエストによって、大きな変更を、関連付けられた小さなプルリクエストに分割します。

[スタック型プルリクエストの詳細はこちら](https://gh.io/stacks)

準備のできたプルリクエストをマージキューに追加すると、マージ前に最新のベースブランチに対してチェックを行います。

[マージキューについて詳しく知る](https://docs.github.com/repositories/configuring-branches-and-merges-in-your-repository/configuring-pull-request-merges/managing-a-merge-queue)

ルールセットを使用することで、組織全体のブランチとコミット履歴を保護できます。

[ルールセットについて詳しく知る](https://docs.github.com/repositories/configuring-branches-and-merges-in-your-repository/managing-rulesets/about-rulesets)

## すべての変更に、必要なレビューを。

すべてのコンテキストを把握し、人間の手が必要な作業に集中し、別の視点での確認が必要な場合には GitHub Copilot を活用しましょう。

GitHub.com、GitHub CLI、エディター、GitHub Mobile を使い、会話、検証、履歴など必要な情報でコードをレビューしましょう。

[プルリクエストレビューについて詳しく知る](https://docs.github.com/pull-requests/reference/pull-request-reviews)

プルリクエストのインボックスを活用し、レビュー待ちのアイテム、修正が必要なプルリクエスト、マージの準備ができた作業を確認しましょう。

[プルリクエストをインボックスで開く](https://github.com/pulls?locale=ja)

レビュー作業時に GitHub Copilot を使うことで、変更点の把握、フィードバックの対応、チームの判断と合わせた自動チェックができます。

[GitHub Copilot コードレビューの詳細はこちら](https://docs.github.com/copilot/how-tos/copilot-on-github/use-copilot-agents/copilot-code-review)
