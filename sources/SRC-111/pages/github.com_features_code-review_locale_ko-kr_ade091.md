# 코드 흐름은 막힘 없이. main 상태는 정상으로.

본인, 팀 동료, AI 에이전트 중 누가 코드를 작성했든 맥락과 함께 코드를 검토하고, 중요 검사를 실행하고, 어떤 코드가 `main`

에 들어갈 자격이 있는지 결정하세요.

## 매월 GitHub에서는

4,300만 개 이상 병합된 pull request

8,200만 개 이상 푸시된 커밋

1,000만 개 이상 새로 생성된 리포지토리

## 기준을 충족하는 것만 병합

하나의 연결된 워크플로를 통해 모든 변경 사항을 처리하세요. 변경 사항을 검토하기 쉬운 단위로 나누고, 기준에 따라 검증하고, 병합 가능한 상태로 준비할 수 있습니다.

스택형 pull request를 사용해 대규모 변경 사항을 더 작고 상호 연관된 pull request로 나누세요.

[스택형 pull request에 대해 알아보기](https://gh.io/stacks)

준비가 끝난 작업을 병합 큐에 넣고 병합 전에 최신 기본 브랜치를 기준으로 검사하세요.

[병합 큐에 대해 알아보기](https://docs.github.com/repositories/configuring-branches-and-merges-in-your-repository/configuring-pull-request-merges/managing-a-merge-queue)

rulesets를 사용해 조직 전체에서 브랜치와 커밋 기록을 보호하세요.

[rulesets에 대해 알아보기](https://docs.github.com/repositories/configuring-branches-and-merges-in-your-repository/managing-rulesets/about-rulesets)

## 모든 변경 사항을 필요한 만큼 검토하세요.

전체 맥락을 보고, 본인의 손길이 필요한 작업에 집중하고, 다른 시각이 필요할 때 Copilot을 투입하세요.

github.com, GitHub CLI, 편집기 또는 GitHub Mobile에서 필요한 대화, 검사 결과, 기록과 함께 코드를 검토하세요.

[pull request review 살펴보기](https://docs.github.com/pull-requests/reference/pull-request-reviews)

pull request 받은 편지함에서 대기 중인 검토 작업과 수정이 필요한 pull request, 병합 준비가 끝난 작업을 확인하세요.

[pull request 받은 편지함 열기](https://github.com/pulls?locale=ko-KR)

Copilot을 검토에 투입하여 변경 사항을 파악하고, 피드백을 하나씩 처리하고, 팀 판단에 더해 자동 검토를 받으세요.

[Copilot 코드 검토에 대해 알아보기](https://docs.github.com/copilot/how-tos/copilot-on-github/use-copilot-agents/copilot-code-review)
