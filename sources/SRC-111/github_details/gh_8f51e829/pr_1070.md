## Summary

Console logging was completely broken when used with the Live progress. This PR fixes a bunch of issues that prevented it from working. Additionally logging due to external packages in workers should also be handled properly (e.g. vLLM)

## Details

There were a bunch of reasons logging was not working correctly:

### 1. `loguru` grabbed an instance of stderr before Rich could redirect it

`loguru`, package we use for logging, is initialized early into the package load and by default will grab a copy of `sys.stderr`. Later when Rich would load, it would replace `sys.stderr` (and `sys.stdout`) with a custom class called `FileProxy` which would redirect writes though itself. Since `loguru` loaded earlier it did not have this redirect in place.

### 2. Spawned worker processes did not receive Rich's `FileProxy`

 TODO Write explaination

### 3. `loguru` not properly configured for multiprocess logging

When initializing non-fork workers `loguru` requires that its state be passed as an argument to the worker in order to share logging queues. This does not matter as much for console logs since the logger can just be initialized again with the stderr pipe in (2). However for log files this causes each worker to open the same file separately.
