## Summary

Non-streaming OpenAI requests that required a tool call yielded a successful response before reporting that the model omitted the tool call. This makes `error_stop` consistent with the documented streaming behavior: it now raises before any final response is emitted, while `ignore_stop` still emits the compiled response once and then stops the conversation.

## Details

- Validate missing tool calls before the normal non-streaming final yield.
- Preserve `ignore_stop` by yielding the compiled response once when the validation raises `CancelledError`, then re-raising it.
- Add a regression test for both `error_stop` and `ignore_stop` yield ordering.
