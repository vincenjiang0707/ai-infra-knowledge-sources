## 正文

## Summary

Log benchmark progress automatically through the existing logger, including in non-interactive shells where the Rich display is unavailable. Users do not need any additional progress configuration. Interactive users keep the Rich display and receive progress logs at the same time.

## Behavior

- Emit INFO records at strategy start, at most once every ten seconds during progress updates, and at completion, including short benchmarks.
- Include elapsed time, successful/errored/incomplete request counts, request throughput and output-token throughput.
- Enable logging in the benchmark entrypoint for both CLI and Python callers. Console-disable flags affect displays, not logging.
- Reuse existing logger levels and sinks, including stderr redirection and the built-in structured file logger. No new logger configuration is introduced.
- Reuse main-process lifecycle callbacks and metrics; periodic updates are not an independent heartbeat during a stalled callback.
- Keep logging and Rich as independent `BenchmarkerProgress` implementations. `Benchmarker.run` accepts a list and concurrently notifies every observer for each lifecycle event, using `_notify_progress` with `asyncio.gather`; each event waits for all callbacks before propagating the first failure. Finalization runs only after normal benchmark execution. The logging observer releases its own state without calling the process-wide `logger.complete()` method.

The final implementation has no new console-mode selector or progress-logging CLI switch.

## Validation

Latest revision on macOS arm64 / Python 3.12.14:

- 179 related tests passed: benchmark unit tests, CLI display flags, queued logs sharing a Rich terminal, and three end-to-end cases using the built-in mock HTTP server.
- Observer tests use synchronization barriers to verify concurrent dispatch and cover observer-update, initialization, and scheduler failures. Initialization and scheduler failures propagate without finalization. Normal execution still finalizes both observers.
- All 12 focused observer and progress tests also passed under Python 3.10.21 without a TaskGroup backport.
- End-to-end cases use no progress-enabling options: default Rich plus logs, displays disabled, and interactive progress disabled. Each crosses the default ten-second interval and checks intermediate records plus final counts against the JSON report. Existing file-logger configuration is also exercised.
- `tox -e lint-check` passed; configured type checks passed across 224 source files.
- No GPU is required for these reporting tests.

Earlier full-suite validation: 3024 unit tests passed, 31 skipped, 163 xfailed; 28 integration tests passed, 25 xfailed; 14 end-to-end tests passed. Fourteen audio unit failures and one realtime audio setup error caused by unavailable local torchcodec/FFmpeg libraries were also reproduced on unchanged upstream commit `d469d0e`. The full suite has not been rerun for this revision.
