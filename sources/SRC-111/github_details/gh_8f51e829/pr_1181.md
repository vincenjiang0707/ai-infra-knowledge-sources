## Summary

Adds per-turn-position metrics for multi-turn workloads, as a first slice of #722. `GenerativeMetrics` gains an optional `turns` field with one entry per observed `turn_index`: request counts plus distributions for request latency, prompt tokens, time to first token and inter-token latency. This makes it possible to see how latency changes as conversation history grows, for example how well prefix caching keeps first-token latency flat on later turns, which the pooled distributions hide.

Single-turn workloads leave `turns` as `None`, following the concern raised in #722 that per-turn breakdowns of a single-turn run would only repeat the aggregate metrics.

## Details

- [x] New `GenerativeTurnMetrics` schema in `src/guidellm/benchmark/schemas/metrics.py`, built by `GenerativeTurnMetrics.compile_by_turn()`.
- [x] Per-turn distributions use exactly the same measurement-window filtering as the aggregate ones (time to first token windowed by the first-token event, inter-token latency by decode start), so the per-turn counts partition the aggregate counts. To guarantee this, the two windowed request lists in `GenerativeMetrics.compile()` are computed once and shared by both. The aggregate outputs are unchanged.
- [x] `turns` defaults to `None`, so existing reports still load.
- [ ] Not included, and happy to follow up on once this shape is agreed: conversation-level metrics (end-to-end conversation time, turn gap), rendering `turns` in the console / HTML / CSV outputs, and the incomplete-conversation handling discussed in #722.

## Test Plan

- `tox -e test-unit`
- `tox -e lint-check`
- `tox -e type-check`
- New tests in `tests/unit/benchmark/schemas/test_metrics.py::TestTurnMetrics`:
  - a single-turn workload reports `turns is None`;
  - turns are emitted in ascending order with per-turn counts;
  - each turn reports its own time to first token and prompt size, not the pooled mean;
  - per-turn counts sum to the aggregate counts for all four distributions, including a request that started before the measurement window, which counts toward latency but not toward time to first token;
  - errored requests are counted at the turn they failed at.
- I also checked that the tests fail when the implementation is broken in three ways: not filtering by turn, windowing per-turn time to first token like request latency, and emitting per-turn entries for single-turn runs.
