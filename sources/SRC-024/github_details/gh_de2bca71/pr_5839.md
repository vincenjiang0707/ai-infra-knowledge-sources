## 正文

## Summary

Add gfx942 (MI325X, 304 CUs) CK tunings for `gemm_a8w8_blockscale`: **286 (M, N, K) rows** over 28 weight shapes that no existing `model_configs` table covers. The shapes come from Qwen3-14B (TP1), Qwen3.5-122B (TP2), and Qwen3.5-397B / DeepSeek-V4-Flash / GLM-5.2 / GLM-5.3-Flash (TP8), with M ∈ {1, 2, 4, …, 16384}.

- Tuned on this repo's main (a75ba53) with `csrc/ck_gemm_a8w8_blockscale/gemm_a8w8_blockscale_tune.py --libtype ck --splitK`. CKTile is left out: its gfx942 candidates for these shapes abort the worker with GPU memory faults (#5840).
- Every `(gfx, cu_num, M, N, K)` already present in `model_configs/` is dropped (267 keys), as are 2 rows whose tuned kernel measured slower than the heuristic default (M=1 and M=16 of N=34816, K=5120).
- All 14 kernel names already appear in existing tables, so no new instances need to be compiled.

File: `aiter/configs/model_configs/a8w8_blockscale_tuned_gemm_qwen_glm_dsv4_gfx942.csv`

## Validation (MI325X)

**Tuning consistency.** Re-tuning the 267 keys main already has picks the same kernel for 223 of them (84%), with timings at 0.91–1.16× the stored values (median 1.05×).

**Kernel level.** Every row goes through the public `aiter.gemm_a8w8_blockscale`, and all 286 resolve to their tuned kernel and splitK. Speedup over the CK heuristic default (`kernelName=""`), HIP-graph timed with rotating weights:

| M | rows | geomean | min | max |
|---|---:|---:|---:|---:|
| ≤ 16 | 119 | 1.99× | 1.00× | 5.22× |
| 32–256 | 64 | 1.77× | 0.99× | 4.47× |
| 512–2048 | 50 | 2.15× | 1.02× | 3.52× |
| ≥ 4096 | 53 | 2.99× | 1.21× | 4.21× |
| all | 286 | **2.12×** | 0.99× | |

Accuracy against an fp32 dequantized reference: splitK=0 rows (161) match the default kernel (max relative error 0.37%). splitK rows are higher: max 0.62% / 0.69% / 1.13% for splitK 1 / 2 / 3. Every row has tuner errRatio ≤ 0.0031, and the existing gfx942 tables for ds_v3, gemma4_31b and glm5_1 also carry splitK rows.

**split-K and out-of-bounds writes.** CK-Tile split-K kernels on gfx942 write past the end of `out` when M is not a multiple of the tile M (#5840, ROCm/rocm-libraries#12594). This file has no CK-Tile rows. To check that the CK split-K kernels do not do the same, every (kernel, splitK > 0) pair in this file and in the existing gfx942 tables (19 pairs) was run with M = 1, 3, 17, 100 and 1000, with `out` placed at the very end of its own allocation so that any write past it faults. None of the 95 calls faulted, and every result matched the same kernel at splitK=0. In the same setup, a CK-Tile split-K kernel faults at M=1.

**End to end.** Qwen3-14B-FP8 at TP1 on sglang with the gfx942 CK blockscale route (sgl-project/sglang#41071) and this repo's main. The two arms differ only in `AITER_CONFIG_GEMM_A8W8_BLOCKSCALE`: main's merged tables with or without this file. Benchmarks use random-ids, `--random-range-ratio 1.0`, `--seed 1`:
