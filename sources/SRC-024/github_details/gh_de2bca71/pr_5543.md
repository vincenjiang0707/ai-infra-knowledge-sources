# [PR #5543] [FlyDSL] Add token-major layout option to GDN prefill h kernel

source: https://github.com/ROCm/aiter/pull/5543
state: open | updated: 2026-09-24T10:55:09Z
labels: FlyDSL

## 正文

Summary

Adds an optional token-major layout for the w/u inputs and the v_new output of the FlyDSL gated-delta-rule hidden-state kernel chunk_gated_delta_rule_fwd_h_flydsl_opt. New public param wu_head_major: bool = True on the host wrapper (aiter/ops/flydsl/linear_attention_prefill_kernels.py); when False, w/u are consumed token-major ([B,T,H,D]) and v_new is stored token-major ([B,T,H,V]). Default True preserves the existing head-major behavior exactly. Implemented via a compile-time const_expr branch in the device kernel (aiter/ops/flydsl/kernels/gdr_prefill/chunk_gated_delta_h.py), so the head-major path is unchanged.

Motivation: lets a consumer with native token-major GDN tensors (e.g. SGLang's linear-attention path) reach the kernel without a transpose.

Technical Details

- Head-major path is provably unchanged: emitted ISA is byte-identical between base and this branch (same VGPR/occupancy). Zero regression by construction (compile-time dead-branch elimination).
- Correctness: token-major output is bit-exact against the head-major reference on dense and production varlen shapes, including an unaligned tail.
- wu_head_major=False changes both the v_new store base/stride and the w/u input loads, which move from head-major ([B,H,T,D], token-row stride D) to token-major ([B,T,H,D], token-row stride H*D) — see chunk_gated_delta_h.py:394-400. K/V stays the unit-stride innermost dimension in both layouts, so lane-level coalescing is unchanged; the difference is inter-token-row locality (head-major advances 256 B/row for K=V=128 BF16, token-major advances H·256 B/row).
- Performance is layout- and architecture-dependent, not neutral. On gfx950 (CDNA4, the target arch) token-major is within noise to slightly faster. On gfx942 (CDNA3) token-major measures ~4.3% slower (dense T=1024) and ~6.1% slower (varlen 8×1024) than head-major, from the reduced token-row spatial locality above (a secondary cache/prefetch effect, not a coalescing failure). For a consumer with native token-major tensors, the saved host transpose can still make wu_head_major=False a net win; on gfx942 it is a trade-off to weigh against the transpose cost.

AOT / prebuild

The FlyDSL AOT enumeration (aiter/aot/flydsl/chunk_gdn_h.py) now fans out wu_contig over both values with layout-matched compile dummies, so the token-major specialization is prebuilt into the packaged cache rather than cold-JIT-compiling on the first wu_head_major=False serving-path call. Verified on gfx950: enumeration count doubles (288 → 576 jobs, 288 head-major + 288 token-major), and a fresh-process token-major call under FLYDSL_RUNTIME_RUN_ONLY=1 (which forbids compile-on-miss) hits the prebuilt cache — with an empty-cache negative control raising the expected "no usable AOT cache" error, confirming the hit depends on the prebuilt artifact and not a JIT fallback.

Test Plan

- op_tests/test_flydsl_linear_attention_prefill.py runs a direct token-major == head-major torch.equal exact assertion (on h, layout-normalized v_new, and final_state) on every case in the default sweep.
- Default run also exercises two dedicated review cases: review-unaligned-varlen (varlen T=1000, a non-multiple-of-BT=64 tail) and review-dense-b2 (dense_batch=2, token-major dense base path).
- ISA diff of the head-major path between base and this branch.

Test Result

- Bit-exact match (torch.equal) between token-major and head-major outputs on all tested shapes, including the unaligned-tail and dense_batch>1 cases, on gfx950.
- Identical emitted ISA (VGPR/occupancy) for the head-major path, confirming no regression.

Submission Checklist

- [x] Default behavior (wu_head_major=True) unchanged
- [x] New path validated bit-exact against reference (direct token-major == head-major torch.equal assertion)
- [x] Token-major specialization AOT-prebuilt (no cold-JIT serving stall)
- [x] Performance characterized per architecture (gfx950 neutral/faster; gfx942 ~4–6% slower
