# [PR #5754] [Triton/Gluon] FlashKDA in-kernel paged state_cache I/O

## 正文

## Motivation
 
FlashKDA still spoke a dense ABI: `initial_state[N, H, V, K]` plus a freshly allocated `out`. vLLM Kimi-K3 serving keeps recurrent state in a paged pool `[slots, H, V, K]` with `state_indices` / `has_initial_state`.

Wiring that through AITER meant:
 
1. `gather_initial_states` (or `state_cache[indices]`) into a dense tensor

2. run `chunk_kimi_delta_attn`

3. scatter `final_state` back

4. `out.copy_(kernel_out)`
 
Those copies sit in the serving timer. On MI350, a K3-shaped FlashKDA prefill paid ~40–60 µs for them (4K: 171 → 130 µs, 16K: 499 → 440 µs with the same segment pin). The fused vLLM path already reads and writes the pool in-kernel ([vLLM #54038](https://github.com/vllm-project/vllm/pull/54038)); this PR gives FlashKDA the same cache contract so a later vLLM dispatch ([#56036](https://github.com/vllm-project/vllm/pull/56036)) does not have to gather around AITER.

 
## Technical Details
 
Public kwargs on `chunk_kimi_delta_attn` / `flash_kda_fwd`:
 
- `state_cache`: fp32 V-first `[slots, H, V, K]`. Each slot plane is dense; `stride(0)` may pad.

- `state_indices`: int32 `[N]`

- `has_initial_state`: bool `[N]`; false starts that sequence from zero and does not read a dirty slot

- `out`: required with `state_cache`, same shape as `v` (K2 still loads `v`, so `out` must not alias it)
 
K2 and the scan load/store `slot * stride(0) + head * V * K + …`. The last segment writes the final state back to the same row. Segmented pass A does not bind `state_cache` (keeps the existing K2 binary / autotune; binding it here previously ~2× slowed K2).
 
`@input_guard(skip=("state_cache",))` leaves the pool’s storage and `stride(0)` alone. Other operands are still packed. The skip is an AITER decorator default, not a vLLM flag; the caller just passes `state_cache=` as a keyword.
 
Dense `initial_state` is unchanged and mutually exclusive with `state_cache`. `final_state` is `None` when the cache is used.
 
The default five-kernel path indexes a dense `h0` and is GVA / C=64 / K-first. If `state_cache` is set and FlashKDA is not selected,

`chunk_delta_attn_fwd` raises instead of ignoring the argument.
 
 
## Test Plan
 
```bash

pytest op_tests/triton_tests/chunk_delta_attn/test_flash_kda.py \

  -k 'paged_cache or flash_kda' -q

```
 
Added cases:
 
- `test_paged_cache_matches_dense` — paged vs dense `initial_state`, bit-identical `out` and selected slots; empty slots untouched; unsegmented and segmented

- `test_paged_cache_has_initial_state_false` — false flag matches a zero `initial_state`

- `test_paged_cache_padded_stride_writes_live_pool` — non-contiguous `stride(0)` updates the original storage pointer

- `test_paged_cache_rejected_on_default_pipeline` — non-FlashKDA call with `state_cache` raises
 
Serving-shaped A/B (K3 H=12, D=128, `lower_bound=-5`, varlen `cu_seqlens`)

vs gather and vs vLLM fused prefill on gfx950.
 
## Test Result
 
Paged vs dense FlashKDA: `torch.equal` on output and selected cache rows (rel err 0).
 
Paged FlashKDA vs vLLM fused prefill (same op, not e2e): output rel L2 ~4.8e-3, state ~2.5e-3 at 4K/16K.
 
MI350X, official vLLM ROCm image, serving-style call (µs, smaller is better):

 
| shape | gather FlashKDA | paged FlashKDA | fused |
| --- | --- | --- | --- |
| 1×4096, H=12 | 171 | **130** | 125 |
| 1×16384, H=12, `--segment 8` | 499 | **440** | 389 |
| 1×16384, H=12, auto segment | — | **380** | 388 |

 
Default-pipeline reject and padded-stride tests pass.
