# [PR #5685] [CI] Add PRs to the AITER-triton Kernels board without relying on labels

state: closed | updated: 2026-09-25T22:07:27Z

## 正文

## Motivation

The AITER-triton Kernels board (https://github.com/orgs/ROCm/projects/232) fills only through the `Triton/Gluon` label today: the board's auto-add rule matches labeled PRs, and the label comes from `pr-title-tags.yaml`. That leaves two holes. The `no-auto-title` opt-out skipped the label sync entirely, so an opted-out Triton PR never reached the board, and nothing puts work on the board when the label is missing for any other reason. The Triton kernels team also wants everything assigned to a team member on the board, whatever it touches (CI, docs, config, ...).

## Technical Details

- `pr-title-tags.yaml`: `no-auto-title` now only leaves the title alone. Component labels are always synced.
- `pr-welcome-comment.yaml`: the CI guide comment says so too.
- New `aiter-triton-board.yaml`: on PR events (`opened`, `reopened`, `ready_for_review`, `synchronize`, `assigned`, `labeled`) and issue events (`opened`, `reopened`, `assigned`, `labeled`) it adds the item to the board when any of these hold: assigned to a member of `@ROCm/triton_kernels_team` (roster inline, GitHub offers no team filter for projects), the PR diff touches Triton/Gluon paths (same list as `isTriton` in `pr-title-tags.yaml`), or it carries the `Triton/Gluon` label. Drafts wait for `ready_for_review`. Adding an item that is already on the board is a no-op, so re-evaluating on every event is harmless. `pull_request_target` with no checkout, same pattern as the title workflow.
- Token: `actions/create-github-app-token@v1` with the existing `AITER_CI_APP_ID` / `AITER_CI_APP_PRIVATE_KEY` secrets, then `actions/add-to-project@v2`.
- The job is gated on the repository variable `AITER_TRITON_BOARD_ADD == 'true'`, so merging this changes nothing until it is switched on.

**Enabling it (org / repo admin):**
1. Grant the AITER CI GitHub App the organization permission **Projects: Read & write** and accept the new permission on the ROCm installation.
2. Add the repository variable `AITER_TRITON_BOARD_ADD` = `true` (Settings → Secrets and variables → Actions → Variables).

The board's own auto-add rules (`label:Triton/Gluon`, and assignee in the team roster) keep working alongside this as a second path.

| `ci:vllm` | vLLM benchmark: GPT-OSS-120B, DeepSeek-R1-0528, Kimi-K2.5 |
| `ci:all` | All standard extended tests (excludes `ci:atom_full`) |

> Only add `ci:atom_full` for FlyDSL or Triton upgrades.
> Add labels via the sidebar or `gh pr edit 5685 --add-label <label>`

**PR title tags & labels:**
Component tags (`[Triton/Gluon]`, `[HIP]`, `[CK]`, `[ASM]`, ...) are added to the PR title and as PR labels automatically from the changed files and re-synced on every push — change-type tags like `[fix]`/`[Perf]`, op tags like `[MLA]`, and human labels (`ci:*`) are left untouched. Add the `no-auto-title` label to opt this PR out.
