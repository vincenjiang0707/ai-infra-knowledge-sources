# [Triton] unified_attention 2D: optional block skipping (BLASST)

## Motivation

Adds opt-in dynamic block sparsity to `kernel_unified_attention_2d`, following BLASST (arXiv:2512.12087) - a dynamic sparse attention mechanism that reuses online softmax statistics to identify negligible attention scores, skipping softmax, value block loads, and the subsequent matrix multiplication. Off by default and inert when off.

On long-context prefill a large fraction of K/V tiles contribute nothing after softmax normalisation. Because the running maximum is already maintained by the online softmax, identifying those tiles needs no pre-computation, no proxy scores and no training - only a comparison against a threshold.

Measured on Qwen3-8B / RULER at 32K context: **1.2475× at 45.0% achieved tile elision**, with no change whatsoever to the dense path.

## Technical Details

### API

```python
unified_attention(..., block_skip_threshold=0.0, skip_counter=None)
```

| | |
|---|---|
| `block_skip_threshold` | `0.0` disables. Above 0, the threshold λ against which `tile_max - running_max` is compared. |
| `skip_counter` | optional `int32[2]`, accumulated in place as `[tiles visited, tiles elided]`. Passing a buffer is the opt-in; there is no flag and no module-level state. |

λ is model- and sequence-length-dependent and must be calibrated. The counter exists so a caller can check that their threshold elides anything at all.

### The skip decision

Per K/V tile, when enabled:

```python
skip     = (s_max - M) < log2_threshold       # M is the max BEFORE this tile
all_skip = tl.sum(skip.to(tl.int32)) == BLOCK_M
if not (ENABLE_BLOCK_SKIP and all_skip):
    ... compute exactly as dense, for every row ...
```

Three details are load-bearing:

**The decision is per tile, not per row.** A tile that survives the vote is computed exactly as dense. `test_no_elision_is_dense_within_rounding` holds the kernel to this.

**The comparison is against the running maximum BEFORE the tile**, not the value after folding in the current tile. The latter is equivalent for λ < 1 but reduces to `0 < log2(λ)` above it, which skips every tile including the one holding the maximum. `test_no_nan_above_unity` guards it.

**The V load is deferred** behind the skip decision when the feature is on, so an elided tile never touches V. That is where the bandwidth saving comes from.

Both tile loops are patched, including the `SPLIT_UNMASKED_LOOP` variant. The unmasked loop holds nearly all elidable tiles on long prefill.

### Nothing changes when it is off

`ENABLE_BLOCK_SKIP` and `PRELOAD_V` are `tl.constexpr`, so at the default threshold every addition folds away at compile time. `log2_threshold` is a runtime scalar rather than a constexpr so that sweeping thresholds does not recompile per value.

### Scheduling

Enabling the threshold also enables descending-q ordering and an atomic work ticket. Both are gated on it and neither touches the dense path.

The 2D grid is `(num_kv_heads, total_num_q_blocks)` and the hardware places workgroup `w` on `XCD w % 8`, so at 8 KV heads on 8 XCDs every workgroup for a head is pinned to one chiplet - verified on hardware by reading `HW_REG_XCC_ID` for all 8192 workgroups. That costs nothing while every head does the same work. Skipping is what makes per-head cost data-dependent, and then the launch waits on whichever chiplet drew the densest head. These exist to repair a problem skipping introduces.

They only permute which workgroup computes which tile, so the result is bitwise unchanged. Tickets are head-major, and the order is not arbitrary - a q-major decode measures slower.

### Not supported

Silently disabled, because a caller enabling this once for a whole model still reaches this wrapper on every step:

- **decode** (`ALL_DECODE`) - one query row per sequence, nothing to be far below
- **sliding window** - a fully-masked row leaves the running maximum at `-inf`, which the sanitizer rewrites to `0.0`, changing what the comparison means
- **the 3D path** - segments restart the running maximum, so the first tile of each can never skip; different semantics, out of scope here

Rejected loudly:

- **the Gluon backend** - asserts rather than ignoring the threshold, so a caller cannot believe they asked for sparsity and silently measure dense

### Env vars

Both default to the shipping configuration and exist for rollback and A/B:

| | |
|---|---|
| `AITER_UA_BLASST_SCHED=0` | disable the scheduling, keep skipping |
| `AITER_UA_BLASST_PRELOAD_V=1` | keep V hoisted instead of deferring it |

## Test Plan

**Existing suite, unchanged.** `op_tests/triton_tests/attention/test_unified_attention.py` run in full (non-Gluon) to confirm the dense path is unaffected.

**New suite.** `op_tests/triton_tests/attention/test_unified_attention_blasst.py`, 16 tests, reusing `generate_data` and `ref_paged_attn` from the existing suite so the inputs and the reference match:

- threshold 0 matches the reference and is bitwise identical to omitting the argument
- no elision means no approximation, within floating-point reassociation
- degradation is bounded and monotonic in λ
- λ ∈ {1.001 … 12.0} stay finite
- decode, sliding window and 3D-routed shapes fall back to dense, bitwise
- the Gluon path raises
- scheduling on/off is bitwise identical
- the elision counter is wired, monotonic, untouched when disabled, and rejects a bad buffer

A guard asserts the test shape actually reaches the 2D kernel; a shape routing to 3D would pass every test while exercising nothing.

**Codegen.** `blasst_repro/codegen_diff.sh` compiles this branch and the pre-change sources and diffs the emitted AMDGCN, to check the claim that the feature costs nothing when off at the instruction level rather than by timing.

**Benchmark.** `blasst_repro/bench_blasst_ua2d.py` sweeps λ on random inputs and reports achieved elision beside every speedup, taken from the kernel's own counter. `blasst_repro/README.md` has the full reproduction steps; no dataset is required.

**End-to-end.** Qwen3-8B / RULER, 13 tasks × 50 prompts × 36 layers at 32K context, λ = 0.02878, timing dense against the feature on for every (prompt, layer) pair.

## Test Result

**Existing suite:** 1088 passed, 1056 skipped, 0 failed.

**New suite:** 16 passed, 3 skipped (gfx1250-only), 0 failed. Verified with the chain-dot patch both enabled and disabled.

**Codegen with the feature off: identical emitted code** - same 1,181 lines, same instruction stream, sgpr 100 / vgpr 206 / zero spills on both. The only difference is the kernel signature, where `log2_threshold` and `num_q_blocks` are runtime scalars, growing the kernarg segment 184 → 192 bytes and shifting the offsets after them. No instruction loads either with skipping off.

**Random inputs**, MI355X, 32 query heads / 8 KV heads, head_dim 128, seqlen 16384, dense baseline 2.950 ms:

| λ | speedup | achieved elision | relative error |
|---|---|---|---|
| 1e-9 | 0.899× | 0.0% | 0.000 |
| 0.02878 | 0.898× | 0.0% | 0.000 |
| 0.1 | 0.901× | 0.0% | 0.000 |
| 0.3 | 0.908× | 0.0% | 0.000 |
| 1 | 1.033× | 21.4% | 0.245 |
| 1.5 | 1.274× | 54.8% | 0.656 |
| 2 | 1.433× | 70.9% | 1.025 |
| 4 | 1.684× | 90.2% | 2.214 |

These results show: The **overhead floor**: at a threshold that elides nothing the skip check costs about 10%, so the feature has to elide before it pays. And the **conversion ceiling**: once tiles are actually being dropped, speedup rises with elision to 1.68× at 90%. Relative error is exactly 0 wherever elision is 0: a tile that survives the vote is computed as dense, so nothing is approximated until something is skipped.

**End-to-end**, MI355X (gfx950), bf16, 23,400 (prompt, layer) measurements:

| | |
|---|---|
| speedup vs dense | **1.2475×** |
| achieved tile elision | **45.0%** |
| measurements at or above 1.0× | 21,245 / 23,400 (90.8%) |
| relative error vs dense | 0.0349 mean, 0.2340 max |
| non-finite outputs | 0 |

Speedup tracks achieved elision closely, and both vary by task and by layer. Per-task and per-layer breakdowns available on request.

Measurements were taken in the environment under `blasst_repro/`, which pins the Triton build; see its README.
