## 正文

## Motivation

Fixes https://github.com/ROCm/aiter/issues/5729.

The MLA PS metadata scheduler returns a pessimistic bound on the max number of partial entries needed to be allocated. This could lead to OOM. The pessimism stems from the fact that it assumed that all requests used the same (maximal) number of query tokens which is not true in inference engines with a fixed query token budget per step.

This PR fixes it to correctly give a much tighter bound by accounting for fixed token budget (c.f. max num batched tokens in vllm) if passed.

## Technical Details

A temporary fix was required on serving engine side: https://github.com/vllm-project/vllm/pull/57923/changes

It's better if we do this in AITER.
