# [PR #5614] [Triton/Gluon] [Bugfix] [Perf] Fix non-preshuffle MQA paging and large KV offsets, retune the decode grid, and cut plain-path instruction count

source: https://github.com/ROCm/aiter/pull/5614
state: open | updated: 2026-09-24T13:58:29Z

## 正文

## Summary

Four defects in the paged MQA logits decode path, all silent: no fault, no NaN or Inf, just wrong or missing logits.

The branch has since picked up two pieces of performance work on the same path, both originally reviewed as stacked PRs and now folded in: the decode grid sizing from #5711 and its follow-up, and the two instruction-level changes to the plain kernel from #5700. They are described in their own sections below and neither touches the correctness of the four fixes.

**1. Block paging for non-preshuffled multi-token blocks.** With `Preshuffle=False` and `KVBlockSize > 1` the Gluon kernel used token positions as page-table columns and always read token 0's K values and scale from each physical block. Compact block tables caused illegal memory accesses; padding the table kept the reads in allocated memory but produced incorrect logits. Resolve the physical block with `token_pos // KVBlockSize` and add the in-block token offset to both the K and the scale address, in the initial loads and in the prefetch loop. This fixes the failures reproduced in #5591. Related: #5600.

**2. KV caches past 2 GiB in the plain kernel.** That kernel forms a per-token address from the page table, so `physical_block * stride` overflowed a 32-bit product and wrapped into another page once the cache crossed 2 GiB. Its KV and scale strides are now 64-bit for every shape and the loads go through global pointers. A size-dependent switch between a 32-bit and a 64-bit variant was considered and dropped: it gives one shape two ABIs behind one AOT directory name, and the measured cost of always using 64-bit is bounded (see Performance).

**3. KV caches past 2 GiB in the preshuffle kernel.** When `ChunkKPerStage % KVBlockSize != 0`, which is `KVBlockSize=256` at `ChunkK=256`, the K and scale addresses came from the same 32-bit page-index product. Read them through a global pointer with the index promoted to 64 bits, the way the other branch of that kernel already does.

**4. Preshuffle tail store reaching into the next output row.** The branch that loads a page index per lane stored its last stage across the whole tile, including the columns past `context_length` that hold `-inf`. When the output width equals an unaligned context those columns land in the next row: with `context_lengths=(3001, 513)` and a compact output, row 1 lost its first 7 logits. Those three stores are now bounded by `max_model_len`, which the kernel's six other stores already did.

## Changes

- Correct block-table, K and scale addressing for sectioned, non-preshuffled caches, and keep negative positions in the backward-shifted first tile mapped to token 0 of physical block 0 after masking the page-table load.
- Generate the new address arithmetic only for `KVBlockSize > 1`, preserving the original scalar-first expressions, code generation and register usage for `KVBlockSize=1`.
- Use 64-bit KV and scale strides in the plain kernel unconditionally, and drop the now dead 32-bit load paths.
- Promote the preshuffle per-stage K and scale addresses to 64 bits.
- Bound the preshuffle per-lane stores by `max_model_len`.
- Extend `op_tests/test_pa_mqa_logits_offset.py`: 48 paging cases (block sizes 1/16/64/128, chunks 64/256, compact and padded tables, randomized physical pages, per-token scales, short and empty contexts, MTP, multiple prefetch iterations) and 12 large-offset cases (plain `B1`/`B64` and preshuffle `B64`/`B256`, each at the 2, 4 and 8 GiB boundaries) against an independent FP32 reference, plus the two existing output-offset cases.

Note for AOT users: the plain kernel's stride arguments changed from `i32` to `i64`, its instruction stream changed again with the two optimizations below, and the preshuffle kernel's instruction stream changed, so cached `.hsaco` artifacts have to be regenerated from this branch. The grid change does not add to that — `SplitKV` is a runtime `i32` argument, not a `constexpr`, so it is not part of the compile key.

## Decode grid sizing

`deepgemm_fp8_paged_mqa_logits` derived `SplitKV` from the batch and rounded **SplitKV** up to a multiple of five, but the thing that has to line up with the CU count is the **grid**, and the two differ by a factor of `TileQCount`. At batch 16/32/64 on 256 CU that landed on 2.5 workgroups per CU, so half the CUs ran three and half ran two and the kernel waited for the deeper half. The grid is now sized directly at two workgroups per CU, clamped so splits that start past the end of the context are not launched.

Two per CU is not enough at the top of the batch range, where each workgroup ends up chewing 128 to 256 chunks with no queue behind it, so a second term raises `SplitKV` toward 32 chunks per workgroup — by at most 2x, because `max_model_len` is only an upper bound on the real context and a loose bound must not be able to over-split without limit.

Scoring each candidate rule by how far its pick sits from the best `SplitKV` measured at each of 42 shapes:

| rule | exact | 4x over-estimate | 16x | 64x |
| --- | ---: | ---: | ---: | ---: |
| the original formula | 7.69% | 7.69% | 7.69% | 7.69% |
| two per CU (context-free) | 0.85% | 0.87% | 0.89% | 0.89% |
| + cap 32 chunks/WG, unbounded | 0.46% | 1.69% | 7.45% | 20.11% |
| **+ cap 32, at most 2x** | **0.56%** | **1.40%** | **2.87%** | **4.08%** |

Over 48 shapes (batch 1..256, context 8k/32k/128k, `next_n` 1 and 2, both layouts) the median is −2.01%, 21 shapes improve by more than 5%, the best is −18.90%, and zero mismatches. Batch 256 at a 128k context is the one shape that stays slower: its grid was already an exact 10 per CU so it never paid the quantisation cost, and its curve is a broad plateau on which the old value sat near the middle. Closing the remaining 1.9% would need the real context length, which lives in a device tensor.

The optional `SplitKV` argument added here is an override in the same spirit as the existing `TotalCuCount`; it is what lets both arms of the measurements come from a single binary. `gfx1250` keeps its own formula, having had no part available to re-tune on.

Correctness for this part: 62 passed, plus a 91-case scan aimed at the split seams — awkward chunk counts, non-uniform context lengths including `(8192, 8191, 1, 256, 257, 255, 65536, 3)` and `(20000, 3001, 513, 131072)`, contexts of length 1 and 2, exact multiples of `ChunkK` and one less, and `KVBlockSize` 1/16/64/256 on both layouts — zero mismatches over the whole output, masked region included.

## Plain-path instruction-level optimizations

Two changes to the `Preshuffle=False` Gluon kernel. Both are unconditional; the shape gate on the first is a correctness condition, not a switch.

**1. Hoist the KV block index and in-block offset out of the loop.** The kernel recomputed `token // KVBlockSize` and `token % KVBlockSize` over a `ChunkK`-wide vector every iteration. `KVBlockSize` is a `constexpr` power of two, so that should be one shift and one AND per register, but it expanded to 64 instructions because `context_idx` is loop-variant and the compiler cannot fold through it. `context_idx` advances by `ChunkK` and the gate requires `ChunkK % KVBlockSize == 0`, so the modulo is loop-invariant and the quotient grows by a constant. The identity does not require `context_idx` to be `KVBlockSize`-aligned, and `KVBlockSize > ChunkK` leaves the quotient without a constant stride, so those shapes keep the general form.

**2. Mask the logits after the head reduce, not before.** The kernel wrote `-inf` into the whole `(ChunkQ, ChunkK)` accumulator before reducing over heads, one `v_cndmask` per accumulator register: 32 in the loop and 32 more in the epilogue. Masking the reduced logits needs four and is the same value, since summing `ChunkQ` copies of `-inf` is `-inf`. The preshuffle kernel already masks after its reduce at all four of its store sites. Removing the `-inf` write also unblocks packed FP32 in the epilogue.

| | in-loop integer address ops | `v_cndmask` | `v_mul_f32` | `v_pk_add_f32` | `v_pk_mul_f32` | `v_pk_fma_f32` | VGPR |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| before | 168 | 98 | 132 | 35 | 0 | 0 | 186 |
| + 1 | **76** | 98 | 132 | 35 | 0 | 0 | 188 |
| + 2 | **76** | **42** | **68** | **18** | **16** | **16** | 190 |

Neither improves register pressure: all three allocate 192 VGPR, so occupancy stays at 2 waves/SIMD.

Measured on top of the grid change above. Three worktrees run back to back inside each round with the arm order rotated, eight rounds; the statistic is the median of the per-round paired ratio, since clocks are not locked here and only pairing cancels the drift. `Preshuffle=True` is untouched by both, so its paired ratio is the noise floor.

| Batch | change 1 | change 2 | both | control (noise floor) |
| ---: | ---: | ---: | ---: | ---: |
| 16 | −0.58% | **−2.83%** | **−3.57%** | +0.09% |
| 64 | −0.40% | **−1.02%** | **−1.36%** | +0.01% |
| 128 | −0.12% | **−0.69%** | **−0.80%** | +0.06% |

Change 2 carries almost all of the gain. Change 1 only just clears the noise floor at batch 16 and sits inside it at batch 128; it is worth keeping because it costs nothing and the instruction count genuinely drops, not because it is a measurable speedup on its own. **Batch 1 does not resolve and no claim is made for it**: over 16 paired rounds plain moves −0.97% with an IQR of [−3.08%, +0.28%] while the unchanged control moves +0.61% with an IQR of [−0.75%, +9.18%].

Both sides of the `HoistKvAddr` gate were measured at the same production scale:

| KVBlockSize | ChunkK | gate | b=16 | b=128 |
| ---: | ---: | :---: | ---: | ---: |
| 16 | 256 | on | −2.88% | −0.66% |
| 64 | 256 | on | −3.57% | −0.80% |
| 128 | 256 | on | −3.95% | −0.89% |
| 256 | 256 | on | −5.02% | −1.38% |
| 128 | 64 | **off** | −2.21% | −1.38% |
| 256 | 128 | **off** | −0.58% | −0.35% |
| 1 | 256 | **off** | −2.96% | — |

No shape regresses. The gated-off shapes still gain because change 2 is unconditional. `KVBlockSize=1` takes the branch where the logical index is never computed and `KVBlockSize > ChunkK` takes the branch where it is computed but the hoist is off, so all three paths are exercised; `op_tests/test_pa_mqa_logits_offset.py` already parametrises `block_size ∈ {1, 16, 64, 128} × chunk_k ∈ {64, 256}`, which covers the same split for correctness.

Change 1 is bit-identical to its parent. Change 2 is not, because folding a multiply and an add into `v_pk_fma_f32` skips the rounding of the intermediate product: 410363 of 2097152 logits move by at most `3.05e-05` on a `±273` range. Against an fp64 reference the two are equally far from the truth (mean absolute error `4.615302e-04` before, `4.615247e-04` after, identical maxima), because the error floor is the fp8 quantisation of `q` and `k`, not the fp32 epilogue.

All 430 measurement processes across these campaigns were 0-mismatched against the fp32 reference, with no NaN or Inf.

```python
#!/usr/bin/env python3
"""Decode perf/accuracy driver for one (batch, layout) pair per process.

Reuses the input generation, fp32 reference and packing helpers of the fixed
op_tests/test_mqa_logits.py (PR #5434, commit 849c7c25), and switches both the
KV packing and the interface Preshuffle flag together. Counts mismatches over
the whole output and returns exit code 2 on an accuracy failure.
"""

import argparse
import importlib.util
import json
import os
import sys

SCRIPT_DIR = os.path.dirname(os.path.abspath(__file__))
_spec = importlib.util.spec_from_file_location(
    "fixed_test_mqa_logits", os.path.join(SCRIPT_DIR, "test_mqa_logits.py")
)
fixed = importlib.util.module_from_spec(_spec)
_spec.loader.exec_module(fixed)

import torch  # noqa: E402

from aiter import dtypes  # noqa: E402
from aiter.jit.utils.chip_info import get_gfx  # noqa: E402
from aiter.ops.triton.attention.pa_mqa_logits import (  # noqa: E402
    deepgemm_fp8_paged_mqa_logits,
)
from aiter.ops.triton.utils.types import get_fp8_e4m3_dtype  # noqa: E402
from aiter.test_common import run_perftest  # noqa: E402


def main():
    parser = argparse.ArgumentParser()
    parser.add_argument("--batch", type=int, required=True)
    parser.add_argument("--layout", choices=["preshuffle", "plain"], required=True)
    parser.add_argument("--n", type=int, default=131072)
    parser.add_argument("--heads", type=int, default=32)
    parser.add_argument("--head-dim", type=int, default=128)
    parser.add_argument("--next-n", type=int, default=1)
    parser.add_argument("--kv-block", type=int, default=64)
    parser.add_argument("--chunk-k", type=int, default=256)
    parser.add_argument("--wave-per-eu", type=int, default=2)
    parser.add_argument("--num-iters", type=int, default=101)
    parser.add_argument("--num-warmup", type=int, default=2)
    parser.add_argument("--output", required=True)
    args = parser.parse_args()

    if os.path.exists(args.output):
        sys.exit(f"refusing to overwrite {args.output}")

    preshuffle = args.layout == "preshuffle"

    batch, n, heads, dim = args.batch, args.n, args.heads, args.head_dim
    next_n, kv_block = args.next_n, args.kv_block

    torch.manual_seed(0)
    fp8_dtype = get_fp8_e4m3_dtype()

    rows = batch * next_n
    blocks_per_seq = (n + kv_block - 1) // kv_block
    num_blocks = batch * blocks_per_seq

    q = torch.randn(batch, next_n, heads, dim, dtype=dtypes.bf16)
    q_fp8 = q.to(fp8_dtype)
    del q

    kv = torch.randn(num_blocks * kv_block, dim, dtype=dtypes.bf16)
    kv_q, kv_sf = fixed._pertoken_cast_to_fp8(kv, fp8_dtype)
    del kv
    kv_q = kv_q.view(num_blocks, kv_block, dim)
    kv_sf = kv_sf.view(num_blocks, kv_block)

    weights = torch.randn(rows, heads, dtype=dtypes.fp32)
    context_lens = torch.full((batch,), n, dtype=dtypes.i32)
    block_tables = torch.randperm(num_blocks).to(dtypes.i32).view(batch, blocks_per_seq)

    ref, inside = fixed.run_torch_decode(
        q_fp8.float(), kv_q, kv_sf, weights, context_lens, block_tables, n
    )

    kv_cache = fixed._pack_paged_kv(kv_q, kv_sf, preshuffle=preshuffle)
    out_logits = torch.full((rows, n), -float("inf"), dtype=dtypes.fp32)

    def run_triton():
        deepgemm_fp8_paged_mqa_logits(
            q_fp8,
            kv_cache,
            weights,
            out_logits,
            context_lens,
            block_tables,
            n,
            Preshuffle=preshuffle,
            KVBlockSize=kv_block,
            ChunkK=args.chunk_k,
            WavePerEU=args.wave_per_eu,
        )
        return out_logits

    total_ctx = int(context_lens.sum().item())
    flops = 2.0 * heads * dim * next_n * total_ctx
    read_bytes = q_fp8.nbytes + total_ctx * (dim + 4) + weights.nbytes
    nbytes = read_bytes + rows * n * 4

    out, us = run_perftest(
        run_triton,
        num_iters=args.num_iters,
        num_warmup=args.num_warmup,
        num_rotate_args=fixed._rotate_args(read_bytes),
    )

    close = torch.isclose(out, ref, rtol=1e-2, atol=1e-2)
    mismatch = int((~close).sum().item())
    total = out.numel()
    inside_mismatch = int((~close[inside]).sum().item())
    nan_inf = int((~torch.isfinite(out[inside])).sum().item())

    record = {
        "gfx": get_gfx(),
        "batch": batch,
        "layout": args.layout,
        "n": n,
        "heads": heads,
        "head_dim": dim,
        "next_n": next_n,
        "kv_block": kv_block,
        "chunk_k": args.chunk_k,
        "wave_per_eu": args.wave_per_eu,
        "num_iters": args.num_iters,
        "num_warmup": args.num_warmup,
        "us": us,
        "TFLOPS": flops / us / 1e6,
        "TB/s": nbytes / us / 1e6,
        "mismatch": mismatch,
        "total": total,
        "inside_mismatch": inside_mismatch,
        "inside_total": int(inside.sum().item()),
        "nonfinite_inside": nan_inf,
        "kv_bytes": num_blocks * kv_block * (dim + 4),
        "aot": os.environ.get("AITER_ENABLE_AOT_GLUON_PA_MQA_LOGITS", "0"),
    }
    with open(args.output, "w") as f:
        json.dump(record, f, indent=2, sort_keys=True)
    print(json.dumps(record, sort_keys=True))

    if mismatch:
        print(f"ACCURACY FAILURE: {mismatch}/{total} mismatched", file=sys.stderr)
        sys.exit(2)


if __name__ == "__main__":
    main()
```
