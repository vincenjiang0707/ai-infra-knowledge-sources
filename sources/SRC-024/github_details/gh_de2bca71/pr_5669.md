## Motivation

Follow-up to #5350 (A4W4 CSV for `gemm_a4w4`). Qwen3.8-27B MXFP4 GDN `in_proj_ba` is dispatched through AITER Triton `gemm_afp4wfp4`. Those kernels load `GEMM-AFP4WFP4-N=<N>-K=<K>.json` by shape. gfx950 currently has no tiles for this model's BA widths.

On TP2, `in_proj_ba` scale rows are not divisible by 32, so vLLM always falls back to Triton for this layer. A TP2 A/B on MI355X (ISL 8192 / OSL 1024 / c=4) measured **+1.7% output tok/s** with the N=48 JSON vs `DEFAULT.json` (434.91 vs 427.68 tok/s). TP1 N=96 is scale-swizzle legal and stays on ASM unless a per-layer Triton force is applied, so that JSON is for the fallback / correctness path, not the default ASM path.

- Triton BA configs passed reference comparisons at representative M=16, 128, 1024.
- Lookup is by filename `N`/`K` only. TP4 must be N=24, not a copy of the TP2 N=48 file.
