## 正文

## Summary

- Add SwiGLU OAI activation (`gate * sigmoid(1.702*gate) * (clamp(up,±7)+1)`) to the MXFP4 FLAT fused-MoE asm kernels for gfx950 (MI355X)
- Three tile variants: 16x32 (wave-specialized), 16x128, 16x256
- All kernels support in-kernel bf16→MXFP4 dynamic quantization (X_BF16=1)
- Integrated into aiter dispatch for Minimax M3 model (model_dim=6144, inter_dim=768, experts=129, topk=5)
- 1.12-1.45x faster than FlyDSL for decode (token ≤ 4)

## Changes

- `hsa/gfx950/fmoe/swiglu_oai/`: 3 kernel .co files + CSV manifest
- `csrc/py_itfs_cu/asm_fmoe.cu`: Route `ActivationType::Swiglu` to pertokenMXfp4 config maps (both fp4 and bf16 X paths)
- `aiter/fused_moe.py`: Add `(Swiglu, per_1x32, bf16, fp4x2)` and `(Swiglu, per_1x32, bf16, bf16, fp4x2)` to `fused_moe_1stage_dict`; add Swiglu to 1-stage activation whitelist
- `aiter/ops/quant.py`: Add `ActivationType.Swiglu: F.silu` to `get_torch_act()`
- `aiter/configs/model_configs/minimax_m3_a16w4_tuned_fmoe.csv`: Tuned config entries for t=1,2,4 with flat kernel selection
- `op_tests/test_moe.py`: Add `swiglu` to activation choices

## Test plan

- [ ] Kernel .co files verified instruction-identical to sp3 reference (neg_hi don't-care bit only)
- [ ] All baselines pass on llvmFSim simulator (nrms < 5e-3)
- [ ] Verify dispatch: `python op_tests/test_moe_2stage.py -q 6 -dim 6144,768 -e 129 -k 5 -t 1 2 4 -hip 0,0 --no-flydsl-csv`
- [ ] Performance: 18-33us for t=1..4 (vs 35-82us FlyDSL)

## Known limitations

The xbf16 path quantizes X to MXFP4 in-kernel (fp4×fp4 MFMA), introducing quantization noise not present in the bf16 torch reference. logits_diff ~0.07 against the unquantized reference is expected — FlyDSL avoids this by doing bf16×fp4 GEMM directly. With a quantization-aware reference the accuracy matches at nrms ~1.2e-3.
