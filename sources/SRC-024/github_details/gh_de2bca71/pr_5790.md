# [PR #5790] [Triton/Gluon] [Config] Tune gfx1201 unified attention 2d for D=512 for full attention and D=256 for Sliding Window (Gemma4 shapes) and fix D=1024 launches

## 正文

## Motivation

Improve unified-attention prefill on Radeon AI PRO R9700 (gfx1201) for Gemma-4-31B shapes (full attention D=512, sliding attention D=256), including fp8 KV cache, and stop `attn_2d` launch failures for head sizes that pad to 1024.

Related PRs:

- **Merged:** [#4044](https://github.com/ROCm/aiter/pull/4044) documents Gemma-4 tuning on gfx950; [#4868](https://github.com/ROCm/aiter/pull/4868) adds RDNA **3D** LDS guards. This change targets gfx1201 **2D**.
- **Open tuning:** [#5601](https://github.com/ROCm/aiter/pull/5601) targets gfx1151; [#5650](https://github.com/ROCm/aiter/pull/5650) targets gfx942 and supersedes closed [#5063](https://github.com/ROCm/aiter/pull/5063); [#5432](https://github.com/ROCm/aiter/pull/5432) targets gfx950.
- **Open related fix:** [#5035](https://github.com/ROCm/aiter/pull/5035) is a draft gfx1201 **3D** LDS-budget fix.

## Technical Details

Only `aiter/ops/triton/configs/gfx1201/triton/attention/unified_attention/DEFAULT.json` changes (`attn_2d` section; schema `[D, Q, SW, DT]`). **Padding-safe head-size bands.** Following the encoding adopted in [#4868](https://github.com/ROCm/aiter/pull/4868), head size is keyed with power-of-two `D_LEQ_*` bands.

| Band | Pads to | Entries |
|---|---|---|
| D ≤ 128 | ≤ 128 | verbatim copies of the existing D-less entries (routing unchanged) |
| 129–256 | 256 | tuned, Q ≥ 64: bf16 query (bf16 or fp8 KV), fp8/fp8; plus bf16 sliding at Q ≥ 256 |
| 257–512 | 512 | tuned, Q ≥ 64: bf16/bf16, bf16/fp8, fp8/fp8 |
| 513–1024 | 1024 | LDS guard, Q ≥ 256, any dtype: BLOCK_M=32, TILE=16, 8 warps |
| > 1024, Q < 64, decode | — | unchanged existing entries |

**D=512 retune.** BLOCK_M=64 / TILE=16 / 8 warps beats the previous BLOCK_M=32
entry by ~1.3× (the earlier staged search fixed 4 warps while choosing tiles).

## Test Plan

- `git diff --check`; JSON validation.
- Routing check against the baseline table: D ≤ 128 and D > 1024 must route identically for every Q (1–299 and larger), sliding on/off, and dtype pair; heads 129–1024 must land in the band of their padded width.
- `python -m pytest -q op_tests/triton_tests/attention/test_unified_attention.py -k '2048'`.
- `bench_unified_attention.py -test` on 119 targeted cases: Q ∈ {63, 64, 255, 256, 1025} × D ∈ {256, 512} × full/sliding × {bf16, fp8 KV, fp8}; D ∈ {128, 192, 384, 576, 768, 1024} × Q ∈ {64, 255, 256, 1024} × full/sliding; headline shapes. Also confirm that the baseline fails at D=1024 and the previous revision of this PR fails at D=576 sliding (both 128 KiB vs 64 KiB).
- Performance: baseline JSON (`52ffe895e`), previous PR JSON and this JSON on the same source, median of 5 trials after prewarm, alternating order.

## Test Result

- Routing check: passed.
- pytest `-k '2048'`: **512 passed**, 1536 skipped, 2144 deselected. Skips are Gluon/shuffled-cache paths unavailable on gfx1201; deselected are the `num_blocks=32768` cases, which exceed this 32 GiB GPU's memory.
- Targeted cases: **119/119 passed** the reference check, including all fp8 cases; both expected baseline/previous-revision launch failures reproduced. D=576/768 sliding now launch.
- fp8 note: `bench_unified_attention.py -test` passes the unquantized tensors together with fp8 descales to `ref_paged_attn`, so its fp8 reference is scaled down by the descale a second time and every fp8 run prints FAIL regardless of config. The fp8 cases here were checked with that call fixed to pass the tensors the kernel receives (`q_tensor`/`k_tensor`/`v_tensor`); Fix is added
