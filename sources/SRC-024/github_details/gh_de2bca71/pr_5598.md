# [PR #5598] [Triton/Gluon] [Config] Enable unified-attention skip-mask for gfx950 hd256 FP8 prefill

state: open | updated: 2026-09-24T13:59:46Z

## 正文

## Summary

- Enable the existing `SPLIT_UNMASKED_LOOP` fast path for gfx950 head-size-256 FP8 Q / FP8 KV, non-windowed, non-shuffled prefill with `max_seqlen_q >= 256`.
- This is config-only: the kernel and wrapper from [AITER PR #4761](https://github.com/ROCm/aiter/pull/4761) are unchanged.
- Add the head-size-256 `Q_GEQ_256` config family while keeping sliding-window and shuffled variants on the non-skip path.
- Restore efficient long-context FP8-Q unified prefill: the exact [SGLang PR #39998](https://github.com/sgl-project/sglang/pull/39998) parent stack regresses badly at long context without this config, while [AITER PR #5598](https://github.com/ROCm/aiter/pull/5598) recovers and exceeds the true-stock serving baseline.

## Why

[AITER PR #4761](https://github.com/ROCm/aiter/pull/4761) enabled skip-mask only for `D_LEQ_128.Q_GEQ_256.DT_fp8_fp8`. Qwen3.8-27B full-attention layers use `head_dim=256`, so they match `D_GEQ_256` first and never reach the head-size-128 key.

This PR adds `D_GEQ_256.Q_GEQ_256.DT_fp8_fp8` with `BLOCK_M=128`, tile 64, and `SPLIT_UNMASKED_LOOP=true`. Sliding-window and shuffled siblings use the same long-prefill tile without enabling the skip loop. Lookup continues to prefer `D_GEQ_512` for head size 512, while decode continues to prefer `D_GEQ_256.Q_LEQ_1*`.

## Activation requirements

This config is used only when SGLang routes prefill through AITER unified attention:

- `SGLANG_USE_AITER=1`
- `SGLANG_USE_AITER_UNIFIED_ATTN=1`
- `attention-backend=aiter`
- FP8 Q conversion from [SGLang PR #39998](https://github.com/sgl-project/sglang/pull/39998)

For full AITER page-size-1 decode, the CUDA-graph page-table fix from [SGLang PR #40410](https://github.com/sgl-project/sglang/pull/40410) is also required. The stock/parent/candidate crossover below used Triton decode for every arm, avoiding the affected unified-decode path while preserving the AITER prefill comparison.

## Direct unified-attention kernel evidence

The kernel gate uses the production Qwen3.8 geometry: 24 Q heads, 4 KV heads, head dimension 256, page size 1, and FP8 Q / FP8 KV. Both parent and candidate completed 18/18 executable cases with zero runtime errors and zero quantized-reference failures.

Measured after one warmup invocation:

| Prefill shape | Parent config | [#5598](https://github.com/ROCm/aiter/pull/5598) config | Speedup |
|---|---:|---:|---:|
| Q=16K, KV=16K | 9.16 ms | 2.94 ms | 3.12× |
| Q=16K, KV=64K | 88.18 ms | 15.37 ms | 5.74× |
| Q=16K, KV=128K | 218.02 ms | 32.92 ms | 6.62× |

The short-Q and decode probes remained close, which matches the PR scope: the new key targets long prefill rather than decode.

At Q=16K and KV=16K, the candidate FP8-Q output had approximately 0.9998 cosine similarity to the quantized-input reference and passed the configured tolerance. The same output had approximately 0.9988 cosine similarity and 91.6% head-output argmax agreement versus the original BF16 reference.

## Corrected full-stack validation

A separate corrected page-size-1 stack added [SGLang PR #40410](https://github.com/sgl-project/sglang/pull/40410) and kept Triton `7cb7b059`. Full correctness validation produced:

- GPQA: 48.48% over 198 samples, matching the BF16-Q parent.
- NIAH: 100% at both 64K and 128K over 1,000 total samples.
- MMMU: 59.11% over 900 samples, within the planned two-point tolerance.

The corrected TP1+TP2 40-row text and multimodal sweep completed every expected request. Absolute output-throughput geomeans were:

- Text: 603.49 tok/s.
- Multimodal: 427.99 tok/s.
- Overall: 525.98 tok/s.

These absolute numbers are not a stock-versus-candidate isolation; the crossover table above is the direct PR comparison.

## Complementary Gluon result

On the same corrected Triton `7cb7b059` stack, [AITER PR #4614](https://github.com/ROCm/aiter/pull/4614) at `f54d368` plus runtime-stride [commit `89f96298`](https://github.com/vorapolsiloai/aiter/commit/89f9629872726be8c93fcc896d53577c83705dbc) measured 622.82 tok/s on text, 415.83 tok/s on multimodal, and 529.89 tok/s overall.

The implementations are complementary: adjusted Gluon is stronger on text, while [AITER PR #5598](https://github.com/ROCm/aiter/pull/5598) remains stronger on important multimodal shapes. Because this PR changes only the Triton config, it remains useful as the fallback even if the Gluon implementation merges.

## Triton compiler sensitivity

An older [AITER PR #5598](https://github.com/ROCm/aiter/pull/5598) image used `triton==3.8.0+git4cff872c.rocm10.0.0` and did not contain [SGLang PR #40410](https://github.com/sgl-project/sglang/pull/40410). Its overall 40-row output-throughput geomean was 540.15 tok/s versus 525.98 tok/s for the corrected Triton `7cb7b059` stack, a −2.6% stack-level difference.

This is not a clean compiler-only A/B because [SGLang PR #40410](https://github.com/sgl-project/sglang/pull/40410) also changed. A `4cff872c` run with the page-table fix is needed to isolate the compiler contribution. The older result is not a correctness-valid deployment result because it lacks the page-size-1 fix.

## Interpretation

[AITER PR #5598](https://github.com/ROCm/aiter/pull/5598) fixes a severe long-context configuration gap in the FP8-Q parent path:

- 3.12–6.62× faster direct long-prefill kernels.
- +44.95% end-to-end output-throughput geomean versus its exact [SGLang PR #39998](https://github.com/sgl-project/sglang/pull/39998) parent.
- +10.10% end-to-end output-throughput geomean versus true stock.
- Near-neutral behavior at 8K.

It is a low-risk, config-only improvement and remains valuable as the Triton implementation and fallback independently of the Gluon work.

Follow-up after more testing:

Last night I found [#4614](https://github.com/ROCm/aiter/pull/4614) and had some time to compare it with [#5598](https://github.com/ROCm/aiter/pull/5598).
