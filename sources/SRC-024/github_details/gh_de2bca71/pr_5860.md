Follow-up to #5648 (kept separate so the approved PR stays untouched). **Stacked on `fix-mla-gluon-2gb-oob`** — retarget to `main` once #5648 merges.

Addresses the Copilot review comments that are real against the merged code:

- **Stale kernel comments** (`mla_gluon.py`): the >2 GB `global_load_to_shared` calls now carry `mask=… , other=0.0`, but the comments above them still said "No mask needed / in-bounds" — the opposite (and unsafe) guidance for a future maintainer. Replaced with an accurate one-liner.
- **`test_mla.py`:**
  - allocate the output tensor with `device=q_nope.device` instead of relying on the module's global default device;
  - `torch.cuda.empty_cache()` before the `mem_get_info()` free-memory gate (matches the sibling tests; avoids allocator-state skip/OOM flakiness);
  - assert **exact** parity (`atol=rtol=0`) between the >2 GB and <2 GB paths — they read identical KV and reduce identically, so they must be bit-identical; the previous `1e-2` tolerance could mask a regression.

Not changed (Copilot comments that were stale / already handled): the "10 cases / `test_mla_gluon_over_2gb.py` path" notes were against the pre-fix PR description (already corrected); `torch.zeros` is kept deliberately (deterministic for a regression test).
