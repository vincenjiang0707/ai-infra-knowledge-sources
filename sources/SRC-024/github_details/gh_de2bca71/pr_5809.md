# [PR #5809] [FlyDSL] Refactor PA decode and load CSV tuning results

## 正文

Refactor the monolithic FlyDSL PA decode kernel into operation classes following `fmha_gfx950`, and let the PA interface consume offline workgroup-budget recommendations from CSV.

- Split schedule/traits, context, memory movement, GEMM, softmax, epilogue, and pipeline components. Carry forward dense planned query splitting, eligible unsigned FP8 buffer addressing between 2 and 4 GiB, K/V prefetch scheduling, and compact/window-bounded reductions.
- Store complete tuning results in one CSV: readable shape/budget/performance columns plus structured payload cells preserve raw timing samples, accuracy checks, failures, and source fingerprints. Loading validates the row hierarchy and displayed values. `--output results.csv` is the output path; `--csv` is an alias. Dry-run output is also CSV.
- Add `load_tuned_results()` to the PA interface. It caches an immutable index of validated recommendations, checks current source fingerprints, and rejects ambiguous recommendations for the same device-local geometry. The default path is `aiter/configs/model_configs/flydsl_pa_decode_tuned.csv`; an absent default gives no recommendations. Explicit missing or malformed files raise an error, and `reload=True` refreshes the index.

Omitting `max_context_partition_num` and `work_plan` enables automatic eager planning:

```python
pa_decode(
    ...,
    max_context_partition_num=None,
    tuned_file="results.csv",
    max_context_length=max_context_length,
)
```

The host context bound and local tensor geometry select the recommendation. Missing, stale, conflicting, or unmatched recommendations use the default budget of `2 * CU`; attention with sinks also uses the default because the tuner measures attention without sinks. The host bound controls page-rounded planned scheduling, so padded block tables retain the measured query-splitting policy. Callers must ensure GPU context lengths do not exceed that bound; matching does not read lengths back from the GPU.

Explicit integer partition counts retain static execution. Explicit work plans take precedence and can supply their partition cap when the argument is omitted. For graph capture or preallocated scratch, load the CSV and use `results.lookup_budget(shape, architecture, num_cu)` to prepare a plan before capture, then pass `work_plan` and the matching context bound. Automatic planning is rejected during capture.

Validation of the CSV/API change:

- 62 CPU checks pass, covering complete CSV roundtrips, malformed/truncated/duplicate data, CLI output, atomic replacement, cache/reload behavior, immutable results, source/accuracy rejection, and local-shape conflicts. These harnesses exercise the actual codec and loader definitions without GPU imports.
- 144 independent offline scheduling-bound checks pass across page sizes 16/64/128 and automatic, explicit-plan, and static modes. The gfx950 B4/QL4/G16/D128/L4096/budget256 example selects identical complete schedules for compact and padded tables when given the same host bound.
- Black, Ruff, and diff checks pass. `op_tests/test_flydsl_pa_decode.py` adds 11 host test cases and two GPU integration cases for automatic planning, fallback, padded tables, explicit-plan precedence, and graph replay. The existing 242 native cases are retained.
- **GPU validation of this update remains unexecuted:** all eight available remote MI355 devices retained other workloads, and the local gfx942 probe blocked in HIP initialization before PA/FlyDSL code ran. No new GPU accuracy, throughput, or regression result is claimed. Frozen snapshots, verified source manifests, and guarded accuracy/performance launchers are prepared for a rerun.

The kernel operation files are unchanged by the CSV/API update. Earlier validation at `a24ea4967`, against the optimized monolithic implementation `7f3d014cd`, passed 242/242 native cases on each revision. Across 35 offline gfx950/gfx942 tile specializations, location-stripped MLIR, complete HSACO, and register/LDS/spill metadata matched. gfx942 coverage in that comparison was offline only.

The earlier MI355/gfx950 target comparison used batch 200, QL4, Hkv1/G16, D128, page128, transposed V, BF16 Q/output, per-token FP8 KV, and contexts from 4 to 200000:

| Workgroup budget | Monolithic `7f3d014cd` median (µs) | Validated `a24ea4967` median (µs) | Validated logical KV TB/s |
| --- | ---: | ---: | ---: |
| 512 | 1135.582 | 1139.307 | 4.494 |
| 2048 | 973.574 | 973.608 | **5.259** |

Each row is a separate paired run. Timing includes decode and reduction and excludes loading/planning, JIT, allocation, quantization, and reference calculation. Logical KV throughput counts 5,120,077,056 K+V bytes once per call, without a QL multiplier, using `bytes / (median_us * 1e6)`.

**Known precision limitation from that comparison:** `varlen_b81_q4_c1027` (batch 81, QL4, Hkv1/G16, D128/page128, per-token FP8 KV, contexts 4–1027) fails the strict FP32-reference check at `atol=rtol=0.005` on both validated revisions: 38 elements exceed tolerance, with maximum absolute error 0.00712435. Outputs are byte-identical. This failure was retained and excluded from timing; tolerances were not changed.
