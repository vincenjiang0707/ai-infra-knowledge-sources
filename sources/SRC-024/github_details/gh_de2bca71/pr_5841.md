# [PR #5841] [tuner] Fail a task as soon as its worker process exits

## 正文

## Summary

Fixes #5840.

A GPU memory fault aborts the worker process, so its task never returns a result. `mp_tuner` only noticed at the per-task timeout (1800 s by default through `base_tuner`), or never when called without a timeout, and then counted it as a GPU hang.

This PR records the PID of the worker that starts each task, next to the existing start timestamp. When a poll times out and that PID no longer exists, the task is failed right away and the pool restarts, the same way the existing `AcceleratorError` path handles it.

## Repro (MI325X, main a75ba53)

Five fake tasks go through `mp_tuner(..., fast_mode=True)`. Task 2 calls `os.abort()`, which is how the HSA runtime ends a process on a memory fault.

| | main | this PR |
|---|---|---|
| `timeout=None` | never returns (killed after 150 s) | returns after **23.8 s**; task 2 counted as a crash |
| `timeout=60` | 73.3 s; task 2 counted as `Timeouts (GPU hang): 1` | **23.7 s**; `Crashes (memory fault): 1` |

The other four tasks return the same results in both.

## Real tuning run

`gemm_a8w8_blockscale_tune.py --libtype both --splitK --mp 2` on 21 gfx942 shapes, default timeout, 40-minute cap. The CKTile candidates for these shapes fault repeatedly on gfx942:

| | main | this PR |
|---|---:|---:|
| worker faults handled in 40 min | 1 (via the 1800 s timeout) | 144 |
| time spent waiting on a dead worker | most of the run | none |

Neither run finishes the batch within 40 minutes, because every CK-Tile split-K candidate on these shapes kills its worker and each kill still costs a pool restart (about 16 s).

## Why the workers die

On gfx942, CK issues bf16 atomic adds as `global_atomic_pk_add_bf16`, which skips the buffer range check. A split-K GEMM with M not a multiple of the tile M therefore adds past the end of the output and faults whenever that memory is unmapped. The fix is in ROCm/rocm-libraries#12594. With that fix and this PR together, the same 21-shape batch finishes in 80 s on 7 GPUs (`--mp 7`) with no faults. Adding #5847 as well, it also tunes on a single GPU (`--mp 1`) in 705 s with no failed shapes, and 5 of the 21 winners are CK-Tile kernels (max errRatio 0.0002). This PR still matters for any other fault: without it, a dead worker costs the full task timeout, or hangs the tuner when no timeout is set.
