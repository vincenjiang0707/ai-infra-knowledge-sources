# [PR #5872] [Triton/Gluon] Unify GEMM tuning through config lookup

## 正文

Replace separate GEMM tuning harnesses and post-processing scripts with one config-lookup driver and 40 input-building cases. Each architecture/backend uses its own DEFAULT.json keys; kernel authors own that contract and can constrain search values per case.

The driver profiles the current config and candidates with rocprofv3. It sums selected GEMM and split-K reduction kernel durations per invocation, then takes the median of 250 cold-cache runs. Warmup, Python/wrapper overhead, cache clears and output resets are excluded. Each config runs in a fresh process with a configurable timeout; failures are logged with the exact config and compiler/driver output, and the next config still runs. This simple isolation has more process startup overhead than the old batched sweep.

Save the best working config when it is faster than the current config, or when no tuned M bucket exists. Preserve other buckets. Output checks use a deterministic reference from the current config when available. Both backends can be requested with --backend both and are tuned separately; omitted backend selection follows the wrapper default, including Gluon preference on supported gfx1250 routes. Triton can still be selected explicitly. The observed lookup handles gfx942, gfx950, gfx1250 and future supported architectures without another tuner.

Add backend selection to the FP4 preshuffle wrapper and document kernel coverage, author requirements and the differences from the old workflow. Remove the CPU unit-test file as requested. Shared Triton pruning/tile blacklisting, old screen-log/CLI compatibility, multi-shape log aggregation, verify-only command and throughput printing are not carried forward. MoE/grouped GEMMs with different loaders remain outside this tuner.

Validation: Black, Ruff, Python compilation, --list and git diff --check pass. An ad hoc synthetic-trace/simulated-process smoke check verifies main+reduction timing, exclusion of warmup/cache work, incomplete-trace rejection, failure logs and continuation after crashes/timeouts. No CPU unit-test file was retained. GPU correctness, real rocprofv3 integration and Linux process-group termination are unverified on this Windows host, so this PR remains draft.
