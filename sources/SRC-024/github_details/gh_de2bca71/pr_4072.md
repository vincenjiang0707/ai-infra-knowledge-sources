# [PR #4072] [FlyDSL] [Bugfix] Grouped MoE build should respect GPU_ARCHS

source: https://github.com/ROCm/aiter/pull/4072
state: open | updated: 2026-09-27T03:19:12Z
labels: FlyDSL

## 正文

## Motivation

Fixes #4071. 

FlyDSL Grouped MoE kernel (gfx1250 only) was always built, irrespective of `GPU_ARCHS`. This slows down build time for say gfx950-only builds. 

Co-authored with @elliotz-ai.

## Technical Details

Don't build kernels whose gfx column in [the csv](https://github.com/ROCm/aiter/blob/d9b3e0d2e876233d1d14bec01b1c9713a267df57/aiter/configs/tuned_grouped_fmoe.csv) is not part of GPU_ARCHS. When GPU_ARCHS is not set, we always build the kernels (as expected). 

At the moment all rows in the csv have gfx1250 so technically we could skip parsing the entire file if GPU_ARCHS is not gfx1250, but to avoid future bugs we make a decision based on the gfx value in every row.

## Test Plan

        python3 setup.py bdist_wheel --dist-dir=/aiter/dist;

### chandankumr · 2026-09-27

Thanks for working on this fix @simondanielsson!

I investigated #4071 and found one edge case in the current parse_csv() filtering.

The current PR checks row_gfx before filtering. If a CSV row has a missing or empty gfx value, that value is empty and the row is not filtered.

However, compile_one_config() later falls back to GROUPED_MOE_AOT_ARCH_DEFAULT, which is gfx1250, when gfx is empty. Therefore an unannotated/default row can still be compiled when GPU_ARCHS=gfx950.

I think the filtering should resolve the fallback architecture before checking the target architecture:

row_arch = (row.get("gfx") or "").strip() or GROUPED_MOE_AOT_ARCH_DEFAULT
if target_archs is not None and row_arch not in target_archs:
    continue

I also noticed that _parse_gpu_archs_env() only handles semicolon-separated values and can raise on an effectively empty value such as " ; ". A small local parser would avoid that dependency and keep the AOT filtering self-contained.

I have a 31-test regression suite covering architecture filtering, fallback behavior, delimiter handling, and grouped-MoE collection boundaries. Happy to share the tests if useful.
