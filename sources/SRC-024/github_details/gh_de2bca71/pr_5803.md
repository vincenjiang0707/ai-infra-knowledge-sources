## 正文

Completes #5785. That PR was meant to land a 40min timeout + smart retry, but the amend left those edits unstaged, so main got a 25min single-attempt timeout instead.

**This lands the intended behaviour:**
- `AITER_AGENT_TIMEOUT` 1500 -> **2400s (40min)**. Measured worker time on #5778 (+1544/-339) is **~19min**; the old 1000s killed it 2min short. 40min gives margin.
- `run_agent` **no longer retries a timeout** (exit 124) -- only a transient failure (dropped connection / 5xx) is retried (up to `AITER_REVIEW_RETRIES`, default 2). Restores the retry resilience #5785 dropped, envelope stays under the 120min job cap.
