## 正文

## Motivation

DeepSeek-V4 fp8 MLA decode (v4 nm) on gfx950 runs the asm `mla_a8w8_qh64_qseqlen1_gqaratio64_nm.co` plus a separate split-merge kernel. This PR adds a FlyDSL version that does both in one launch. It is faster than the best asm configuration in every cell of the kernel matrix, and it lowers DSv4-Pro 8K/1K ITL by 0.6–2.6%.

## Technical Details

- New entry points in `aiter.ops.flydsl`. `aiter.mla` is unchanged, so nothing is routed by default.
  - `flydsl_mla_decode_fwd_v4_nm`: drop-in for `mla_decode_fwd_v4_nm` (bf16 output). It covers every pair the asm ships: H 16/32/64/128 at msq 1, and H16 at msq 2/4.
  - `flydsl_mla_v4_decode_fused`: the same kernel with an inverse-RoPE + wo_a mxfp8 quant epilogue.
  - `q_kv_bounds` + `flydsl_mla_v4_grouped_verify_meta`: native grouped DSpark verify (sgl-project/sglang#41120-style), one stream per request with per-draft key ranges.
- A graph-capture-safe host plan picks the tile loop (K / RP / RQ / RD / Q16) and the split count for each (H, msq, batch, stream kind). The split merge runs inside the same launch through a ticket protocol that needs no co-residency.
- Requires `flydsl==0.3.4.1`, the current pin.
- Known gaps: a few shapes outside the matrix are still slower than asm, for example H128 B100 ragged L4096 (1.17x) and H16 B17 L16–32K (~1.1x). Follow-up work is in progress.

## Test Plan

`python op_tests/test_flydsl_mla_v4_decode.py` covers decode, fused and grouped (bf16 / mxfp8) against an fp64 reference. It also checks the contracts: empty rows return NaN, padding bytes are never read, CUDA-graph replay is bit-exact, B=0 is a no-op, and batches over 4096 merge groups run unsplit.

## Test Result

- Op test: all 384 cases pass.
- Stress: 16k launches under concurrent load with a garbage-filled workspace, 0 bad.
- The ISA of all 267 variants the plan can select has 0 VALU→MFMA hazards.
- Setup for the numbers below: MI355X, `lmsysorg/sglang-rocm:v0.5.20-rocm724-mi35x-20260922`.
