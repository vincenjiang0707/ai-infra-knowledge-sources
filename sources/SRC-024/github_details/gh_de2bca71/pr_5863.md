# [PR #5863] [Triton/Gluon] Expert-parallel support for moe_gemm_a16w4

source: https://github.com/ROCm/aiter/pull/5863
state: open | updated: 2026-09-25T21:46:37Z
labels: Triton/Gluon

## 正文

Adds `expert_map` support to the monolithic A16W4 Triton MoE (`moe_gemm_a16w4`) so it works under expert parallelism.

Routing metadata is in the global expert space while the weight tensors hold only the rank-local experts. The kernel now remaps the weight expert id via `expert_map` and early-returns for blocks whose expert is not local (`expert_map == -1`); the wrapper zero-inits the output so the downstream top-k combine + all-reduce sum correctly. Non-EP path is unchanged (`expert_map=None`). Gluon backend asserts `expert_map is None`.

## Validation (gfx950 / MI355X)

vLLM `aiter_triton_mxfp4_bf16` backend, TP=8, `--enable-expert-parallel`, ISL/OSL 1024/1024, gpu-mem-util 0.9. Prior to this change both models mem-access-faulted at engine init under EP; now they boot clean.
