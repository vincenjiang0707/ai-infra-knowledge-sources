## 正文

A second step on the existing title and label workflow rather than a new one: it wants the same trigger, the same permissions and the same PR, and the header already offers no-auto-title as the way to opt a PR out entirely, so that label now covers this as well.

For each changed file the step reads the commit history and counts who wrote it, then assigns the heaviest contributors.

Thanks for the thoughtful proposal and for addressing the implementation feedback. Automated PR routing is a useful direction, and the event handling and manual-override ideas here are valuable.

After considering the overall design, though, I don’t think we should merge this PR. We already have a private agent-based assignment flow, and adding another controller that derives assignees from commit authorship would create two sources of truth for the same field. It also conflates contribution with ownership, cannot represent external or unresolved committers consistently, and may consume the limited assignee slots without identifying who is actually responsible for driving the PR.

I’d prefer to keep `assignee` as a clear accountability signal—normally one DRI—and integrate any useful ideas from this PR into the existing routing flow, with reviewers handled separately. Let’s close this for now.
