## 正文

## Motivation

MiniMax-M3 dense MXFP8 on gfx950 stores B in the MX-scale preshuffle layout. The Triton path has to reshape those tensors first. This PR adds a FlyDSL GEMM that consumes packed A, shuffled B, and MX scales as they sit in the checkpoint, plus the MiniMax-M3 TP4 tune table so those signatures dispatch.

Fused MoE EP lookup still has two key conventions: routed top-k, and routed top-k plus a fake slot. Callers that pass the real width need to select that key instead of matching topk-1.

## Technical Details
Five commits:
1. FlyDSL MX-scale preshuffle GEMM — gfx950 kernel, host dispatch, AOT, and minimax_m3_dense_mxfp8_mxscale_preshuffle_tuned_gemm.csv (147 fp8×fp8 rows, M=1…16384, MiniMax TP4 NKs such as 1536/2560×6144).
2. has_fake_topk_slot on fused MoE — default EP lookup still tries the historical fake-slot key, then the runtime width. False uses the routed width only. Same flag on fused_moe / fused_moe_ / fhmoe.
3. Tuner at op_tests/tuners/tune_mxscale_preshuffle.py; tile catalog under ops/flydsl/gemm_tune/.
4. GPU sweep at op_tests/test_flydsl_mxscale_preshuffle.py (2D contiguous host contract).
5. Kernel cleanup — gpu.thread_id / block_id to i32 at first use; split-K bf16 pack via .to() instead of arith.trunc_f.

Kernel, dispatch, tuner, and EP lookup were written from FlyDSL GEMM / translation rules and the AMD GPU authoring contract (gfx950, AITER harness, correctness before a win), then checked in a separate review pass (Index types, layouts, lookup keys, tests). Companion SGLang wiring is not in this PR.
