# [Triton/Gluon] Fused Qwen3-Next GDN decode op for gfx950

## Motivation

Qwen3-Next's Gated DeltaNet decode step runs as four separate kernels today:

```
fused_qkvzba_split_reshape_cat  ->  causal_conv1d_update
  ->  fused_recurrent_gated_delta_rule_packed_decode  ->  gated RMSNorm
```

aiter has all the pieces for GDN — `chunk_gated_delta_rule`,
`fused_recurrent_gated_delta_rule`, `causal_conv1d_update_split_qkv`,
`gated_rmsnorm_fp8_group_quant` — but **not the single-launch fusion**, and not
one that consumes the packed `qkvz`/`ba` projections directly.

This adds that op. On 4x MI355X / TP4 with Qwen3-Next-80B-A3B-Instruct-FP8 it is
worth **+6.0% to +9.1% end-to-end output throughput** when wired into SGLang
(companion PR), with no accuracy regression.

### Why a new op rather than a mode on `fused_kda_decode`

`fused_kda_decode` is the same *shape* of fusion — conv, recurrence, gated norm,
one launch — but it implements **KDA**, and the differences are structural, not
parametric:

| | `fused_kda_decode` | this op |
|---|---|---|
| head topology | one `H`; q/k/v all `H` heads | `VH == 2*KH` |
| gate | `lower_bound * sigmoid(exp(A)*(a+dt))`, vector over K | `exp(-exp(A_log)*softplus(a+dt))`, scalar per head |
| output gate | `sigmoid(z)` | `z * sigmoid(z)` (SiLU) |
| conv bias | none | seeds the accumulator |
| input | pre-split `mixed_qkv`/`gate`/`beta` | packed `qkvz`/`ba`, split internally |

The head topology alone settles it: KDA's `lp = H*K`, `q_off = i_h*K`,
`v_off = 2*lp + i_h*V` offsets cannot express `VH = 2*KH`. A mode flag would
double an existing kernel's branch factor to host a different algorithm, so this
ships as a sibling instead. `fused_kda_decode` is not exported from
`gated_delta_net/__init__.py`, so no existing interface is perturbed.

## Modifications

New:
  * `aiter/ops/triton/_gluon_kernels/gfx950/gated_delta_net/fused_gdn_decode_qkvz.py`                            
    — the Gluon kernels. Two decompositions behind one entry point:                                              
    * **batch < 128** — `_fused_decode` / `_fused_decode_tiled`. One eight-wave                                  
      workgroup owns a token/key-head group's convolution history and both FP32                                  
      value-head states, with prefetch and tiling to hide memory latency while                                   
      the machine is under-occupied.                                                                             
    * **batch >= 128** — `_decode_group`, which keeps the whole `[V, K]` state                                   
      tile in registers across both matrix-vector products. Above that threshold                                 
      the kernel is bandwidth-bound, where the latency-hiding machinery stops                                    
      paying and the simpler traffic pattern reaches a better fraction of peak.                                  
                                                                                                                 
    Selection is a **range check, not a shape table**, so every batch size is                                    
    covered.  
* `aiter/ops/triton/gated_delta_net/fused_gdn_decode_qkvz.py` — public wrapper,
  shape/dtype validation and the support predicate.
* `op_tests/triton_tests/test_fused_gdn_decode_qkvz.py` — a pure-torch fp32
  reference plus correctness, pad-slot, bf16-only and determinism tests.
* `op_tests/op_benchmarks/triton/bench_fused_gdn_decode_qkvz.py` — bandwidth and
  roofline sweep.

Modified:
* `aiter/ops/triton/gated_delta_net/__init__.py` — export the op and its
  predicate.

### What it fuses

1. unpack packed `projected_qkvz` -> Q/K/V/Z and `projected_ba` -> b/a
2. depthwise causal conv1d against the rolling window, **with bias**, + SiLU
3. delta-rule gating, `decay = exp(-exp(A_log) * softplus(a + dt_bias))`
4. FP32 recurrent state update at `ssm_state[indices]`
5. gated RMSNorm with a SiLU gate
6. *optional* per-head group-128 FP8 quantization

Stage 6 is opt-in via `quant_dtype=`. With `None` the op returns bf16 only,
because an unquantized `Linear` consumer cannot accept an `(fp8, scales)` tuple.

### `pad_slot_id`

Rows whose state index equals `pad_slot_id` (default `-1`) are skipped without
reading or writing state. This matches what the other indexed-state ops in this
directory already do — `fused_conv_recurrent_norm` returns on `state_idx < 0`,
`causal_conv1d_update_split_qkv` takes an explicit `pad_slot_id` — and it is the
contract SGLang's `replay_state_indices_validator` documents. Measured cost:
**0.2-0.3%**, i.e. within noise.

## Scope and supported shapes

Deliberately narrow, and **reported rather than asserted**:
`fused_gdn_decode_qkvz_supported()` returns `(bool, reason)` so callers fall
back and can log why.

* gfx950 only — CDNA buffer addressing, `v_exp_f32`/`v_rcp_f32` inline asm,
  explicit register layouts
* `num_v_heads == 2 * num_k_heads`; `head_k_dim == head_v_dim == 128`
* conv width 4; contiguous conv and recurrent state pools
* bf16 packed projections / conv weight / conv bias / `dt_bias` / `norm_weight`;
  fp32 `A_log` and `ssm_state`; int32 state indices
* fp8 output, when requested, is `e4m3fn` or `e4m3fnuz`

**No CUDA path is affected.** The op is reachable only through its own module,
and every caller is expected to gate on the predicate.

## Accuracy Tests

`pytest op_tests/triton_tests/test_fused_gdn_decode_qkvz.py` — **22 passed** on
MI355X / ROCm 7.0 / Triton 3.8.

* `test_fused_gdn_decode_correctness` at batch 1, 2, 4, 8, 16, 32, 64, 128 —
  output, scales, and both mutated state pools against the fp32 reference at
  ATOL/RTOL 0.05, the bar this directory already uses for `fused_kda_decode`.
* `test_fused_gdn_decode_pad_slot` — `PAD_SLOT_ID` rows leave `ssm_state` and
  `conv_state` bit-unchanged.
* `test_fused_gdn_decode_bf16_only` — `quant_dtype=None` returns `(out, None, None)`.
* `test_fused_gdn_decode_determinism` — same inputs twice, bit-identical.
* Eleven reference-only tests pin the packed layout, gate algebra and quant
  round-trip independently of the kernel.

The reference itself was validated before being trusted: run against **seven
independent implementations of this kernel across nine batch sizes**, it agrees
on every one, and `conv_state` matches **bit-exactly** on all 63 combinations.

## Speed Tests and Profiling

Hardware: 4x AMD Instinct MI355X (gfx950), TP4 / EP1.
Image: `lmsysorg/sglang-rocm:v0.5.19-rocm700-mi35x-20260910` (ROCm 7.0,
Triton 3.8.0, torch 2.9). Model: `Qwen/Qwen3-Next-80B-A3B-Instruct-FP8`.

### Kernel level

Per-launch time under **CUDA graph replay** with a fixed 512-slot state pool.
Both matter: timing the Python call instead of the kernel produces a flat ~25 us
floor that is host overhead, and sizing the pool to the batch puts small batches
entirely in cache.

  | batch | 1 | 2 | 4 | 8 | 16 | 32 | 64 | 128 | 192 | 256 |                                                     
  |---|---|---|---|---|---|---|---|---|---|---|                                                                  
  | this op (us/call) | 9.70 | 9.73 | 9.80 | 10.02 | 9.84 | 10.40 | 14.24 | 26.95 | 36.81 | 46.52 | 

Replaced chain, same conditions, per decode step over 36 GDN layers:
**830.8 us -> 279.2 us (2.98x)** for the four kernels listed in Motivation.

### Roofline

`python3 op_tests/op_benchmarks/triton/bench_fused_gdn_decode_qkvz.py`, MI355X
(8.0 TB/s peak HBM). The op performs no MFMA and no `gl.dot`; it is bound by the
FP32 recurrent state, read and written once per token per value head, which
dominates every other tensor by an order of magnitude.

  | batch | 1 | 8 | 32 | 64 | 128 | 192 | 256 |                                                                  
  |---|---|---|---|---|---|---|---|                                                                              
  | us/call | 9.39 | 9.69 | 10.40 | 14.24 | 26.95 | 36.81 | 46.52 |                                              
  | TB/s | 0.12 | 0.89 | 3.33 | 4.87 | 5.14 | 5.65 | **5.96** |
  | % peak | 1.4% | 11.2% | 41.6% | 60.8% | 64.3% | 70.6% | **74.5%** |

  Two regimes, and they are why the op carries two decompositions. Up to batch
  ~32 it is **latency-bound** — there is not enough state traffic to fill the
  machine, and time is nearly flat at ~9.4-10.4 us regardless of batch, so
  prefetch and tiling pay. From batch 64 it becomes **bandwidth-bound**, where
  that machinery stops paying and the register-resident tile reaches a better
  fraction of peak: **74.5% at batch 256**.

  A single decomposition plateaued at 5.20 TB/s (65%) there. Three candidate fixes
  were tested and rejected before concluding the gap was structural: extra HBM
  passes (identical byte counts, by source-level count of the state load/stores),
  launch-order locality (rewriting the grid to the other kernel's order gained
  0.75%), and store cache policy (`.cs` to `.wt`, slightly worse). What remains is
  the register layout and reduction structure — a different algorithm, not a
  tuning constant.
