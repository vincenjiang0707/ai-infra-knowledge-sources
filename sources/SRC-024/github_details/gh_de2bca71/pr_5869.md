### Motivation
`main` has no tuned configs for **Qwen/Qwen3.8-Flash-Next-FP8** (`qwen4_exp`) in `aiter/configs/model_configs/` yet (#5213 added
FP8-PTPC/BF16 MoE tables for gfx942 on the `Qwen3.5_dev` branch; #5379 is FP8 blockwise prefill MoE on MI308X). The official FP8
checkpoint uses per_1x128 block-scale routed experts, and on a single MI350X (gfx950, TP1) every MoE shape and all but one BF16 dense
shape fell back to default heuristics. This PR adds tables for that
deployment (gfx950, `cu_num=256`, TP1), produced with the in-tree tuners, `--compare --update_improved` (only shapes ≥3% faster than the
current default are written).

Only the routed experts are FP8 (per_1x128 block scale) in this checkpoint (`modules_to_not_convert` covers 943 modules); everything
else (GDN / QSA projections, shared expert, router, hyper-connections, `lm_head`, MTP) runs as BF16 GEMM through `gemm_a16w16`.

### How to reproduce
Tuner commands (inside the ATOM image, `/app/aiter-test`):
```
TUNE_ONLY=asm,cktile python3 csrc/ck_gemm_moe_2stages_codegen/gemm_moe_tune.py -i <untuned_fmoe> -o <tuned_fmoe> --compare --update_improved --mp 1
python3 csrc/gemm_a16w16/gemm_a16w16_tune.py -i <untuned_bf16> -o <tuned_bf16> --libtype asm,opus,triton,skinny,torch --compare --update_improved --mp 1 --batch 10
```
Note: without `TUNE_ONLY`, the MoE tuner only tries flydsl v2, which has no FP8 per_1x128 kernel (0 candidates).
Note: hipBLASLt candidates were excluded for decode shapes (two VF resets during a `--with-hipblaslt` run on this host).
