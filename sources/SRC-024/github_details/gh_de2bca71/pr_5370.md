## 正文

## Motivation

aiter has no conv3d (only Triton conv2d). Two diffusion VAEs need one:

- **Wan2.1** encodes in 4-frame chunks and prepends 2 cached feature frames
  after the first chunk. Those frames are real, not causal-pad zeros, so the
  `T=1` `conv3d -> conv2d` identity fails. That is **67.7% of one encode's 650
  convolution calls**.
- **Qwen-Image** is the same VAE fine-tuned at `T=1`, where the identity holds,
  so it needs this kernel's 2-D path.

A GEMM library cannot absorb these shapes: N is the 96/192/384 channel ladder,
and 7 of 18 Qwen-Image shapes have `K` not a multiple of 64 or `N=3`, which
A16W16 cannot express.

## Technical Details

### 1. Vendored implicit-GEMM convolution (`flydsl_conv_implicit`)

Same vendoring as `gemm_a16w16_gfx950`. Dispatches 1D/2D/3D off filter rank;
gathers from the source instead of im2col (~9× less activation traffic).
Keyword surface unchanged (`groups`, `padding_mode`, `splitk`, `stream`,
`tile`, `wgm`, `autotune`, `input_layout`, `output_layout`).

Three mechanical edits vs upstream: local `buffer_atomic_add` (flydsl wheel
has no `kernels/common/`); `kt` -> `k_tile` (filter temporal extent); one
`if` collapsed to `and`. 54/56 top-level definitions byte-identical.

Named `flydsl_conv_implicit` because the entry point dispatches on rank.

### 2. Offline tile tuner

The heuristic N tiles are powers of two. Against 96/192/384, two rungs sit at
**75% N occupancy**; masked B columns still issue MFMA. `TILE_N` 96/192 is
legal but was unreachable: `TILE_{M,N} % (16 * WAVE_M * WAVE_N) == 0` excludes
the eight-wave shape every shipped candidate uses.

- `conv3d_policy.py` enumerates that closed form (reject = arithmetic, not a
  compile), then prunes on N fill, waves, LDS, accumulators.
- `csrc/flydsl_conv3d/conv3d_tune.py` writes per-model CSVs under
  `aiter/configs/model_configs/` (`qwenimage_vae_*`, `wan21_vae_*`).
- `_lookup_tuned_tile` reads them. Miss / missing file / malformed row falls
  back to the unmodified heuristic.

Launch config is five integers, not a `solidx` (reordering candidates must not
silently invalidate the table).

**Tune with `--compare --update_improved`.** `mp_tuner` times across eight GPU
processes; production runs one. A bare sweep regressed three shapes by up to
4.8%. The compare gate re-times on the production path and rejects gains below
`--min_improvement_pct` (default 3%).

Also fixes `autotune=True` / `FLYDSL_CONV3D_AUTOTUNE=1`, which imported a
FlyDSL-repo path and raised `ImportError`.

### 3. A16W16 pruner fix

`GemmConfigPruner` `keep_ratio` climbs with M: at M=27556 it kept only tiles
wasting <0.44% on padding. HTI needs `block_n=256`, so N=384 (pad to 512)
dropped the whole HTI catalog (~30% loss). Cap lets a tile pad up to 30%.

### 4. Tests

`op_tests/test_flydsl_conv_implicit.py`: keyword surface plus Wan / Qwen
shapes from an input resolution (`--wan-res`, `--wan-frames`, `--qwen-res`),
traced on meta-device encodes. Benches:
`op_tests/op_benchmarks/flydsl/qwenimage_vae_conv/bench_three_way.py` (conv vs
A16W16 vs hipBLASLt) and `bench_conv_tuned_ab.py` (tile table on vs off).

### Scope and limits

- **bf16, forward only.** Grad tensors route to torch. These VAEs run
  `no_grad`.
- Tuned tables are per-model, keyed on the full conv shape including `bias`
  (compile-time). Anything else uses the heuristic.
- Benches time only; correctness is the op_test and the tuner's `errRatio`
  gate.
- `three_way.json` predates the tile table (conv arm = heuristic). Conv arm
  reproduces within 0.6% weighted; 5.5% slower than current HEAD.

- `_launch.compile` appends `*extra_args`, so the 4-tensor `_dispatch` in the AOT pass is correct against both kernel signatures.
- The 14 `fx.Int64` scalars have `__cache_signature__ == (type(self),)`, so the extents really do leave the artifact key.

One substantive issue below, then some small stuff.

## The AOT artifacts are unreachable at the resolutions whose rows were dropped

The module docstring says:

> one artifact serves every resolution of the same layer, so a row covers sizes the table never listed

The *artifact* is resolution-agnostic, but the *launch config* isn't. `tuned_key` (`conv_kernels.py:845`) still carries `n, d, h, w` and `_lookup_tuned_tile` is an exact match, so an unlisted resolution misses the table, falls through to `_pick_tile`/`_pick_wgm`, and asks for a different `(tile, wgm)` — which *is* part of the compile key. That matters here because the same change drops the second resolution of each model from the tuned tables (76 rows → 38).

### Repro

AOT only the 1024x1024 row of one Qwen layer, then run both resolutions under `FLYDSL_RUNTIME_RUN_ONLY=1` (gfx950):

```
1024x1024: hits the AOT cache
1328x1328: RuntimeError: FLYDSL_RUNTIME_RUN_ONLY=1 but no usable AOT cache for launch
```

Forcing the tuned tile at the unlisted resolution makes it hit, which isolates the cause to the tile lookup rather than to `dyn_hw`:

```
1328x1328 + tile=(128,128,2,2): hits
```

### How often it happens

Of the 38 dropped rows, 3 have a heuristic `(tile, wgm)` that happens to match the retained row's tuned one; 35 don't. The structural reason doesn't depend on my arithmetic: `_pick_tile` can only ever return one of four tiles (`TILE_LADDER` + `TILE_WIDE_N`), and 28 of the 38 tuned rows use a tile outside that set — `(128,192,2,2)`, `(96,96,2,3)`, `(192,128,4,1)`, and so on.

### What it costs

Ran each dropped row two ways on one idle gfx950: the tile the runtime picks today (heuristic, since the row is gone) vs the tile that row was tuned to. Median of 20 iterations after 3 warmups, `torch.cuda.Event`.

| | heuristic (today) | deleted row's tuned tile | delta |
|---|---|---|---|
| Qwen-Image VAE @ 1328x1328 (14 layers) | 5703 us | 5348 us | **+6.6%** |
| Wan2.1 VAE @ 480x832 (15 layers) | 7984 us | 7341 us | **+8.8%** |
| combined | 13687 us | 12690 us | **+7.9%** |

27 of the 29 layers I could measure are >2% slower on the heuristic tile; the worst are +14.7% (`C=384 K=192 1x332x332`), +14.3% (`C=96 K=192 1x664x664`), +12.6% (`C=192 K=192 6x242x418`) and +12.2% (`C=384 K=384 1x166x166`). Caveat: 9 of the 38 rows didn't run for me — they take the WGM-swizzle path, which needs `fx.min`, and my local flydsl is 0.3.1 against the 0.3.4.1 in `requirements.txt`. They're excluded from both columns, so the comparison is still apples to apples, but the sample isn't the full set.

So at 1328x1328 and 480x832 the VAE now (a) JITs on first call despite the AOT pass and (b) runs ~8% slower in kernel time. Worth noting the test file's own comment already describes (b) correctly — "fall back to `_pick_tile`'s heuristic at any other" — which reads at odds with the AOT docstring. The -0.70% median / -1.4% total quoted in `conv_kernels.py` is `dyn_hw` on-vs-off and doesn't cover the row removal.

### Options

1. Have the table lookup fall back to a resolution-agnostic row for the same layer when the exact match misses. That's what closes the loop `dyn_hw` opens, and it's the one that makes the docstring claim true.
2. Keep the dropped rows. Dedupe already collapses same-layer/same-tile rows, so this doesn't take the job count back to where it was.
3. At minimum, reword the docstring claim so it doesn't promise coverage the dispatch can't deliver.

## Smaller things

- `aiter/aot/flydsl/README.md` gained a `mega_moe.py` row in this PR but still doesn't mention `conv.py` at all — neither the module table nor the usage list.
- `_probe`'s docstring says only rank and dtype reach the cache key. With `dynamic_layout=True` the signature is `(type, dtype, align, use_32bit_stride, (-1,)*n, strides-with-unit-index)`, so `strides.index(1)` is in there too. The probes work because the innermost extent is `TR_VEC`, which puts the unit stride on the last axis like a real contiguous tensor; a probe with a trailing extent of 1 would put it at rank-2 and silently miss. Worth stating that invariant — and perhaps not borrowing the transpose's `TR_VEC` for it. (The `if rank > 1` ternary is also redundant: both branches give `(TR_VEC,)` at rank 1.)
- `c_padded % TR_VEC == 0` is always true — `LDG_VEC == TR_VEC == 8` and `c_padded = groups * _pad_channels(C // groups)`.
- The `ARCH`/`GPU_ARCHS` filter only exists in `main()`; `run_aot()` (the `setup.py` path) calls `collect_aot_jobs` directly and skips it. Same shape as `gemm.py`, so pre-existing rather than introduced here — but conv contributes the most jobs of any kind.
