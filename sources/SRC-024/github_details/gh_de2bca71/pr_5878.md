# [PR #5878] [CI] Select impacted Triton and Gluon unit tests

source: https://github.com/ROCm/aiter/pull/5878
state: open | updated: 2026-09-26T20:25:53Z
labels: CI

## 正文

PR CI ran the whole op-type folder for any kernel edit.

Select the paired test for each edited kernel instead, plus every test whose imports reach that module, so fused coverage is computed rather than maintained by hand. 

A GEMM kernel edit now runs 3 tests instead of 25; a kernel with no paired test falls back to its op-type folder, and shared machinery (utils/, package init, CI infra) still falls open to the full suite.

Configs are read at run time rather than imported, so the import graph cannot say which variants consume them: a config change runs its whole op folder plus any test outside it that imports the module the family is named after.

**One backend per PR:**
A PR changes one kernel backend: `[Triton/Gluon]` (Triton and Gluon count as one), `[HIP]`, `[ASM]`, `[CK]`, `[OPUS]` or `[FlyDSL]`. If the title ends up with two backend tags, split the PR -- as [stacked pull requests](https://docs.github.com/en/pull-requests/get-started/about-stacked-prs) when one part cannot merge without the other.

**PR title tags & labels:**
Component tags (`[Triton/Gluon]`, `[HIP]`, `[CK]`, `[ASM]`, ...) are added to the PR title and as PR labels automatically from the changed files and re-synced on every push — change-type tags like `[fix]`/`[Perf]`, op tags like `[MLA]`, and human labels (`ci:*`) are left untouched. Add the `no-auto-title` label to stop the title rewrites; labels stay in sync either way.
