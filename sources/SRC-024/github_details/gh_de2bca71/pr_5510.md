## 正文

## Motivation

Stock FlyDSL K5 assigns one program per `(sequence, head, V tile)` and walks 64-token chunks serially. A single 16k Qwen3.8 TP8 sequence therefore launches only 128 programs. Segmenting recovers occupancy on long, narrow prefills without changing the prepare or `o` kernels.

### Isolated kernel (gfx950)

`python op_tests/op_benchmarks/triton/bench_gdn_segment_scan.py` — H=16, indexed varlen, idle GPU:

| seq_lens | N | stock | segmented | delta |
| --- | --: | --: | --: | --: |
| 8192    | 1 | 253.3 µs | 150.7 µs | −40.5% |
| 16384   | 1 | 507.2 µs | 275.6 µs | −45.7% |
| 32768   | 1 | 952.3 µs | 504.4 µs | −47.0% |
| 16384×2 | 2 | 575.7 µs | 492.0 µs | −14.5% |
| 8192×4  | 4 | 400.6 µs | 487.9 µs | +21.8% |

The N=4 row is why the dispatch gate keeps packed batches on FlyDSL.

## Technical Details

The per-chunk hidden-state update is affine in the incoming state: for `h` shaped `[V, K]`,

```text
h' = h @ A + b
```

A long sequence is split into segments of `ceil(total_chunks / 16)` chunks. Each segment is an independent affine map, recovered without materializing a dense operator per chunk:

1. **Summaries.** Run the same recurrence over each segment twice in one launch: start at `h=0` with `u` to get `b_seg`, and start at `h=I` with `u=0` to get `A_seg`. `A_seg` is stored as `[V, K]` with `K=V=128`.
2. **Scan.** A short sequential kernel composes those maps along the sequence and writes each segment's true incoming state, including `h0` / `state_indices` for indexed varlen pools.
3. **Output.** Rerun every segment from that state and write the stock K5 contract: chunk snapshots `h`, `v_new`, and optional final state (in-place into the SSM pool when the FlyDSL wrapper would).

`T_FLAT` is a runtime kernel argument so packed batches of different lengths do not retrigger Triton constexpr compiles. The segment kernels use `BV=64` and the scan `BV=16`, both tuned on gfx950 over the gated shapes.

The FlyDSL wrapper (`chunk_gated_delta_rule_fwd_h_flydsl_opt`) intercepts before BV selection when all of the following hold:

- `B=1`, `K=V=128`, `use_g`, not `use_gk`, head-major log2-scaled `g`, `save_new_value`
- total chunks ≥ 128 ≈ 8k tokens
- `N<=2`, or `N==3` with total chunks ≥ 512 and max seq chunks ≥ 256

Varlen needs `prefill_metadata` so CPU `seq_lens` are available. Prepare (`gdn_prepare_fwd_flydsl`) and `chunk_fwd_kernel_o_opt_vk` are unchanged.
