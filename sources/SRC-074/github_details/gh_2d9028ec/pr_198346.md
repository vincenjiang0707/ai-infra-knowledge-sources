# [PR #198346] Generalize quantile float64-rank fallback off hardcoded MPS check

## 正文

Fixes #198345.

Generalizes quantile's float64-rank fallback off the hardcoded `self.device().type() != kMPS` check to use the device's reported capabilities via `DeviceGuardImplInterface::getDeviceCapability` (the `has_Double` bit). See the linked issue for rationale, including the XPU case (consumer Intel iGPUs / Arc without the `sycl::aspect::fp64` aspect) and the PrivateUse1 case.

- `aten/src/ATen/native/Sorting.cpp`: `double_ranks = scalar_type == kDouble || deviceSupportsDouble(self.device())`, where `deviceSupportsDouble` dispatches through `VirtualGuardImpl` and reads `has_Double`. Backends that have not implemented `getDeviceCapability` raise (`TORCH_CHECK`); that is caught and treated as supported, preserving the permissive CUDA/HIP/CPU behavior (CPU's no-op guard impl already reports every type as supported, so the CPU special-case is dropped).
- `test/test_reductions.py`: `test_quantile_size_limit` branches on `torch.accelerator.get_device_capability` instead of `device_type == "mps"`.
