# [Issue #189970] [MPS] index_reduce_ does not validate indices and performs out-of-bounds atomic writes

source: https://github.com/pytorch/pytorch/issues/189970
state: closed | updated: 2026-09-25T02:19:26Z
labels: module: error checking, triaged, module: advanced indexing, module: mps, bot-triaged

## 正文

### 🐛 Describe the bug

`index_reduce_` on MPS never validates index values. The kernel computes
`self_offset += uint32_t(index[...]) * stride` with no check, so an
out-of-range index atomically mutates whatever memory follows the tensor, and
a negative index casts to a huge uint32. CPU raises `IndexError`.

```python
import torch

storage = torch.ones(64, device="mps")
view5 = storage[:5]
view5.index_reduce_(0, torch.tensor([11], device="mps"),
                    torch.tensor([88.0], device="mps"), "amax", include_self=True)
torch.mps.synchronize()
print("storage[11]:", storage[11].item())  # 88.0 -- atomic write 6 elements past the view

# corruption of a separately allocated tensor
a = torch.ones(16, device="mps")
b = torch.ones(16, device="mps")
a.index_reduce_(0, torch.arange(16, 4096, device="mps"),
                torch.full((4080,), 55.0, device="mps"), "amax")
torch.mps.synchronize()
print("b corrupted:", bool((b != 1).any().item()), "b.max:", b.max().item())

torch.ones(5).index_reduce_(0, torch.tensor([11]), torch.tensor([88.0]), "amax")  # CPU: IndexError
```

Output on a source build of current main (2.14.0a0+git2662808); also
reproduces on 2.13.0 stable:

```text
storage[11]: 88.0
b corrupted: True b.max: 55.0
IndexError: index out of range in self
```

All reduce modes are affected. `amax`, `amin`, and `prod` stay silent; `mean`
may raise later through its internal bounds-checked `index_add_` count, but
only after the unsafe reduction has already executed.

The host dispatch never encodes the shared index bounds check that
`index_add_` and `index_select` use
(https://github.com/pytorch/pytorch/blob/26628087023e5102381849e9a27c3f09b6d485a4/aten/src/ATen/native/mps/operations/Indexing.mm#L543-L554),
and the kernel casts the raw index to `uint32_t` before the atomic reduction:
https://github.com/pytorch/pytorch/blob/26628087023e5102381849e9a27c3f09b6d485a4/aten/src/ATen/native/mps/kernels/Indexing.metal#L302-L331

### Versions

PyTorch 2.14.0a0+git2662808 (source build of main) and 2.13.0; macOS 26.5.2 (arm64), Apple M5 Max, Python 3.12.13.
