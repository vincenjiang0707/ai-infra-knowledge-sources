# [PR #198616] [dynamo] Match CPython errors for bound __contains__ calls

## 正文

I reproduced this myself with a small script. When `__contains__` is called directly with the wrong arguments, for example `{}.__contains__()`, compiled code raised the right exception type, `TypeError`, but with a different message: `expected 1 argument, got 0` instead of `dict.__contains__() takes exactly one argument (0 given)`. The message does not say which method failed, so it shows the error but points the reader in the wrong direction. This is hard to hit in everyday code. With this PR the messages match eager.

> **AI-generated technical summary (Claude), reviewed by me:**
>
> Part of #195901 (match CPython errors for bound `__contains__` calls).
>
> The `sq_contains` slot wrapper (`_wrap_objobjproc`) raised generic `TypeError`s for a bound `__contains__` call with the wrong arguments: `expected 1 argument, got N` and `this method takes no keyword arguments`. CPython names the type and method, e.g. `dict.__contains__() takes exactly one argument (0 given)` and `dict.__contains__() takes no keyword arguments`. The wrapper now formats both messages with the bound type's name and `__contains__`. Keeping the change in this slot wrapper leaves the other wrappers and method calls unchanged.
>
> Scope: only the message text changes; the exception type was already correct. The `in` operator always passes exactly one argument, so this only shows up when `__contains__` is called explicitly with bad arguments. The same wrapper serves `set.__contains__`, which was also checked manually (`set.__contains__() takes exactly one argument (0 given)`).
>
> **Tests**
>
> - `test_contains_protocol.py::test_bound_contains_argument_errors`: the four call shapes from CPython's tests (`{}.__contains__()`, `(0, 1)`, `(x=2)`, `(x=2, y=2)`) raise `TypeError` with CPython's exact messages under Dynamo. Fails without the fix.
>
> CPython `test_call` under Dynamo: `CFunctionCallsErrorMessages.test_varargs0`, `test_varargs2`, `test_varargs1_kw` and `test_varargs2_kw` go from error to passing and no test goes from passing to failing; their expected-failure markers are removed. All tests in `test/dynamo/test_contains_protocol.py` pass.
>
