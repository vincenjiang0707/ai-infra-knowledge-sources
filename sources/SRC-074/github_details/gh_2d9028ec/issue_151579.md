### vikrambal · 2026-09-21

Hi @neural-agi, I noticed your comment from a couple months back. If you are still actively working on this, happy to sync up or help review instead. Otherwise I would love to pick it up.

Before diving in, I looked into both files and found a detail worth confirming first.

`.github/labeler.yml` (via test-infra's `getLabelsFromLabelerConfig`) is **additive**: every matching glob applies its label; no ordering. `autoLabelBot.ts`'s `filenameRegexToReleaseCategory` (used only for the single `release notes: X` label) is **exclusive**: it stops at the first matching regex, and it is wrapped in extra logic (skip-if-not-user-facing, `[codemod]`/caffe2/`.cu`/OpInfo special cases, topic derivation from existing labels).

Copying the 40 regexes straight into labeler.yml as globs would make release-note categorization additive as well, so a PR could end up with multiple `release notes: X` labels instead of one. I think this conflict already exists today for categories in both files (e.g. quantization).

Proposed approach: keep labeler.yml as the source of truth for the glob patterns (add the missing 36 categories), and have `getReleaseNotesCategoryAndTopic()` read its ordered candidate list from labeler.yml instead of its own hardcoded array. This would preserve current behavior while sourcing everything from a single place. This would land as two PRs: (1) pytorch/pytorch for the labeler.yml entries, then (2) test-infra for the refactor once those merge.

Does that match what you had in mind, or were you thinking of something simpler? Super happy to tweak before working on this.
