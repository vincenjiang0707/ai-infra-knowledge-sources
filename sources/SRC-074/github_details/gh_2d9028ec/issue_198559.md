## 正文

### 🐛 Describe the bug

### Description

`torch.compile` crashes in Inductor's `merge_select_cat_aten` post-grad fusion pass with `IndexError: tuple index out of range`, on a graph that does `select` followed by `cat`. The **same model runs fine in eager**, and also compiles fine with **default** `torch.compile` — the crash requires the Inductor fusion/freezing config below (the fuzzer's config). The failing pass is the `select_cat_aten_pass` (`torch/_inductor/fx_passes/split_cat.py: merge_select_cat_aten`).

### Minimal reproducer

```python
import torch
from torch._inductor import config

_CONFIG = {'b2b_gemm_pass': True, 'batch_fusion': True, 'cpp.enable_concat_linear': True, 'cpp.enable_grouped_gemm_template': True, 'decompose_mem_bound_mm': True, 'efficient_conv_bn_eval_fx_passes': True, 'force_fuse_int_mm_with_mul': True, 'freezing': True, 'group_fusion': True, 'pattern_matcher': True, 'post_grad_fusion_options': {'batch_aten_add': {'fuse_nodes_with_same_parent': True}, 'batch_aten_div': {}, 'batch_aten_mul': {'fuse_nodes_with_same_parent': False}, 'batch_aten_relu': {}, 'batch_aten_sigmoid': {}, 'batch_aten_sub': {}, 'batch_aten_tanh': {}, 'batch_linear_post_grad': {'fuse_nodes_with_same_users': True, 'require_fbgemm': False, 'shape_broadcast_batch_linear': True}, 'decompose_mm_pass': {'skip_dynamic_shape_dim_check': True}, 'move_view_after_cat_aten_pass': {}, 'normalization_aten_pass': {}, 'pad_aten_mm_pass': {'k_threshold_to_pad': 1}, 'select_cat_aten_pass': {}, 'split_cat_aten_pass': {'threshold_to_cat': 5}, 'unbind_stack_aten_pass': {}}, 'pre_grad_fusion_options': {'batch_clamp': {}, 'batch_detach': {}, 'batch_dropout': {}, 'batch_layernorm': {}, 'batch_linear': {}, 'batch_linear_lhs': {}, 'batch_nan_to_num': {}, 'batch_relu': {}, 'batch_sigmoid': {}, 'einsum_to_pointwise_pass': {}, 'merge_getitem_cat_pass': {}, 'merge_splits_pass': {}, 'move_reshape_out_of_split_stack_pass': {}, 'mutate_cat_pass': {}, 'normalization_pass': {}, 'remove_split_with_size_one_pass': {}, 'split_cat_pass': {}, 'split_cat_to_slices_pass': {}, 'split_stack_to_cats_pass': {}, 'unbind_cat_to_view_pass': {}, 'unbind_stack_pass': {}, 'unbind_stack_to_slices_pass': {}}, 'split_cat_fx_passes': True, 'use_joint_graph_passes': True, 'use_post_grad_passes': True, 'use_pre_grad_passes': True}

a = torch.randn([4, 4, 4, 4], dtype=torch.float64)
b = torch.randn([4, 4, 4], dtype=torch.float64)

def model(a, b):
    s = torch.select(a, 1, 0)                       # -> [4, 4, 4]
    c = torch.cat([s, torch.mul(b, 2.0), b], dim=1)
    x = torch.sin(torch.nn.functional.relu(torch.sigmoid(torch.cos(c))))
    x2 = torch.add(torch.add(x, 1), 1)
    x3 = torch.add(c, 2)
    return torch.cat([x2, x3], dim=0)

print("eager ok:", tuple(model(a, b).shape))        # (8, 12, 4)

with config.patch(_CONFIG):
    compiled = torch.compile(model)
    with torch.no_grad():
        out = compiled(a, b)                         # raises InductorError
```

> **Note:** this reproduces under the Inductor fusion/freezing config above (the config our fuzzer runs). It does **not** trigger with default `torch.compile`. The relevant flag is `post_grad_fusion_options={'select_cat_aten_pass': {}}`.

### Ablation

- Eager (no compile): ✅ works, returns `(8, 12, 4)`
- `torch.compile` default (no fusion config): ✅ compiles fine
- `torch.compile` + the config above (`select_cat_aten_pass`): ❌ `IndexError: tuple index out of range`
