Part of the set of changes the two-phase precompile workflow needs at pytorch tip, on top of the open precompile stack that ends in #198558. In that workflow, one GPU captures the model against a fake process group of the serving world size, and then every rank replays the saved artifact with recompilation refused. The set was found by running the workflow end to end at tip on a large production FSDP2 recommendation model. Each change here was the first blocker at its step: the run got past that step once the change was applied. With the full set, the replay completed on all 16 ranks for 100 batches with no refusals.

**What.** When guards are saved, only the builtins that a `BUILTIN_MATCH` reads are recorded in `used_builtin_vars`, and the loaded builtins dict is rebuilt from that set. Other guards also reach builtins through the builtins-dict global. One example is the `CLASS_MATCH` on `G['__builtins_dict__']['enumerate']`, which (c) now keeps. Such a guard referenced a key that was missing at load, and installing it failed with `KeyError: 'enumerate'`.

This change walks every guard source rooted at the builtins-dict global and records each key it reads.

**Why it's needed.** With the capture gates passing, installing the artifact at tip failed with `KeyError: 'enumerate'`. With this change, the install got past this step. This depends on (c), which is what makes the builtin CLASS_MATCH serializable at all.
