# [Issue #195901] [dynamo] Meta-issue: torch.compile gaps found via the CPython test suite

source: https://github.com/pytorch/pytorch/issues/195901

## 正文

I asked an agent to look at the graph break messages from the CPython test suite and
summarize the missing features in Dynamo. This is not an exhaustive list of all missing
features, but it contains some of the gaps that we want to close in the near term.

Some items are harder than they look (`functools.lru_cache` is the usual example).

## How to run

```bash
# one module
PYTORCH_TEST_WITH_DYNAMO=1 python test/cpython/v3_13/test_iter.py -v

# one test
PYTORCH_TEST_WITH_DYNAMO=1 python test/cpython/v3_13/test_iter.py -v -k test_countOf
```

PyTorch must be built against Python 3.13. A known-failing test reports as `skipped` with
the graph-break reason attached, because it has a file under
`test/dynamo_expected_failures/CPython313-<module>-<Class>.<test>`. **Deleting that file is
part of your fix** - CI fails the test as an unexpected success otherwise.

## Shared root causes

The six items below each account for several failures across unrelated modules. Fixing one
unlocks every test listed under it, which makes these the highest-leverage work in this
issue.

### 1. `type.__new__` on a C-implemented type

`Unsupported method call: type.__new__`. This is the general "constructing any
non-allowlisted C-implemented type" gap, confirmed at four unrelated call sites. Probably
the single highest-leverage fix here.

- [ ] `test_functools.py::TestLRUPy::test_lru_no_args` and `TestLRUC::test_lru_no_args` - `@lru_cache` decoration
- [x] `test_set.py::TestSetSubclass::test_keywords_in_subclass` - `set`/`frozenset` subclassing (#196425)
- [ ] `test_sys.py::ExceptHookTest::test_excepthook` - `io.StringIO()` construction
- [ ] `test_contextlib.py::TestRedirectStdout::test_enter_result_is_target` - `io.StringIO()` construction

### 3. Detected user errors don't surface as the real exception

Dynamo already knows the call is invalid, but instead of raising the `TypeError` CPython
would raise, it produces a generic wrapper, an internal crash, or an
`InternalTorchDynamoError`. Three severities, same underlying gap: user errors detected
during tracing need a path to "raise the real exception."

## Correctness bugs

Compiles, no exception, no graph break, wrong answer. Prioritize over everything below
regardless of how narrow the trigger looks.

- [ ] Enum's metaclass makes a property/method-shadowing member break guard construction (`AttributeError: 'fget'`) - sometimes silently computes a wrong value instead of erroring
- [ ] Enum member write/delete protection not enforced - mutation silently allowed where CPython raises `AttributeError`

`__class__` cell resolves to `None` or a wrong value in `super()`-adjacent constructions.
Same feature area as the already-fixed `__build_class__` closure-cell work; these shapes
still regress:

- [ ] `test_super.py::TestSuper::test___class___delayed`

- [ ] `test_super.py::TestSuper::test_various___class___pathologies`

Dynamo is too permissive:
