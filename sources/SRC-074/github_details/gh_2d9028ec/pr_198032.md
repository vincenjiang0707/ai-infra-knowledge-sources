# [PR #198032] [ROCm] Parallelize grid_sampler_2d backward across channels

## 正文

Co-reviewed by AI assistants (Opus-5 + GPT-6 Astra)

> The generic 2D backward kernel processes channels serially. This adds a ROCm channel-parallel kernel with per-lane grid-gradient contributions and one block reduction, improving large-C channels-last backward.
>
> The optimized kernel is restricted to the measured architecture and eligible shapes (`C >= 2` for channels-last input, including mixed `grad_output` layouts, otherwise `C >= 32`, within HIP launch limits). ROCm `grad_input` preserves the input's channels-last strides even on generic fallbacks. Shared 2D gather/scatter helpers use the kernel's index type for spatial offsets, and Meta reproduces the input-layout rule without architecture or launch-limit checks. CUDA allocation/dispatch and 3D behavior retain their existing rules.
>
> Recorded FP32 operator timings: **~7.49 → 0.796 ms (~9.4×)** on the earlier ROCm-based revision; **7.556 → 0.796 ms (~9.49×)** after rebasing upstream. Both use a fixed-seed uniform surrogate: input `(42,128,120,160)` and `grad_output` `(42,128,1,10000)` channels-last; grid `(42,1,10000,2)`; bilinear/zeros, `align_corners=False`, both gradients. These measurements cover one ROCm configuration, with customer-grid and end-to-end performance unvalidated. The follow-up measured **0.795929 → 0.796221 ms** against the preceding PR head on this case.
>
> Validation: **63 regression variants passed**, covering CPU-reference gradients, eager/FakeTensor strides, mixed/empty/singleton layouts, nearest-mode zeros, HIP launch fallback and spatial offsets beyond `2**31`. The **41-case prior-head versus follow-up comparison passed** at `atol=rtol=2e-4`. The earlier upstream-baseline comparison retains its numerical qualification: three full-size FP32 cases each had 140/840000 grid-gradient values outside that tolerance; independent FP64 and coordinate controls supported reduction-order rounding differences. Full Inductor execution remains unverified.
>
> Performance on other architectures remains unmeasured. The gate restricts the channel-parallel mapping; the input-only layout rule also changes generic ROCm fallbacks. File-level linters passed; the complete lint invocation reproduced the same five SDK type errors on the unchanged prior head.
>
> Builds on [pytorch/pytorch#166825](https://github.com/pytorch/pytorch/pull/166825). AI-assisted implementation and validation.

>
> **Test coverage.** The standard `grid_sampler_2d` OpInfo samples use three contiguous channels, below the ordinary-layout `C >= 32` threshold. >
> **Layout and Meta.** ROCm input-gradient strides now depend only on the input layout. The native allocation and Meta no longer mirror channel thresholds, `grad_output` layout or HIP launch bounds. Shared 2D gather/scatter helpers keep spatial offsets in `index_t`, including bicubic input reads. Meta uses explicit strides to match eager for empty channels-last tensors as well. Tests cover eager/FakeTensor parity, mixed and singleton layouts, empty batch/channel/output dimensions, noncontiguous inputs and CPU FakeTensor behavior.
>
> **Dispatch and large tensors.** The channel-parallel mapping is gated to the measured architecture through the input's device index; the launch-size and channel-count conditions remain local to dispatch. The launch-fallback regression now preserves channels-last output. A separate regression crosses a `2**31` spatial offset with one channel, forcing the generic path; all three interpolation modes and both output masks are exercised. Its bicubic grid gradient depends on a nonzero input value beyond the boundary.
>
> **Historical comment corrections.** The earlier kernel header described a superseded mapping. The quoted 6.27 ms and 9.84 ms values were two whole-operator timings under different output masks, so they cannot be attributed to one phase of a single execution. The stale zero-channel dispatcher explanation was also removed.
>
> **Validation and remaining scope.** All 63 selected regression variants passed. The 41-workload comparison with the preceding PR head passed its numerical checks and measured 0.795929 → 0.796221 ms for large-C channels-last backward. Earlier same-base baseline measurements of ~7.49 → 0.796 ms (~9.4×), followed by the upstream-based 7.556 → 0.796 ms (~9.49×), remain historical operator results. *Co-authored, reviewed, revised by AI assistants (GPT-6 Astra & Opus-5).*

> **What PR #198032 adds to PR #166825 — updated September 26, 2026**
>
> [#166823](https://github.com/pytorch/pytorch/issues/166823) is an unrelated documentation-navigation issue. The relevant predecessor is [PR #166825](https://github.com/pytorch/pytorch/pull/166825).
>
> **Main contribution:** #198032 retains the predecessor's channel-parallel work mapping, then combines a parallel `grad_grid` reduction with channels-last `grad_input` storage. It adds dispatch, indexing, Meta and regression work to support that combination.
>
> #166825 had two materially different versions: approved `4611c4d` assigned one thread per `(n,c,h,w)`, with adjacent lanes traversing output points; later `634b411` used one block per `(n,h,w)` with lanes striding over channels. #198032 builds on the later mapping, which was not covered by the earlier approval. That head was a non-building ROCm prototype: its [CI report](https://github.com/pytorch/pytorch/pull/166825#issuecomment-3478627101) records the undefined host-scope `index_t` error. It required build and correctness repairs before benchmarking. The prior art supplies a prototype design, without establishing a validated, working starting point. #166825 closed unmerged; this PR has no dependency on it landing.
>
> | Area | #166825, final head | What #198032 adds or changes |
> |---|---|---|
> | Grid-gradient computation | Lane 0 serially gathers across channels; bilinear repeats that work when C exceeds the block size. | Per-lane `opmath_t` accumulation and one shared-memory tree reduction after the channel loop; coordinate work is hoisted. |
> | Input-gradient layout | Contiguous/NCHW `grad_input`. | ROCm channels-last input retains its strides for any `grad_output` layout, including generic fallbacks. Other input layouts produce contiguous gradients. |
> | Dispatch and Meta | Selects the new kernel for ROCm without the new eligibility policy. | Restricts optimized dispatch to the measured architecture; uses `C >= 2` for channels-last input (including mixed layouts), otherwise `C >= 32`, with positive point count and HIP launch bounds. Allocation and Meta depend only on input layout. |
> | Atomics and indexing | Architecture-gated `opportunistic_fastAtomicAdd` calls; undefined host `index_t`, uninitialized shuffle operands and unwritten `grad_grid` at C=0. | Uses direct `fastAtomicAdd`; widens shared 2D scatter offsets and bicubic reads to the selected `index_t`; fixes host typing, replaces coordinate shuffles with loads and sends C=0 through the generic kernel. Distinct channel destinations do not provide same-address FP32 warp-aggregation opportunities. |
> | Regression coverage | No repository tests. | CPU-reference bilinear/bicubic configurations, nearest-zero checks, eager/FakeTensor layout parity, launch fallback and offsets beyond `2**31`. The follow-up's 63 generated variants passed on the measured configuration. |
>
> Nearest-mode literal-zero grid gradients were already present in #166825; #198032 preserves that behavior and tests it. The shared 2D indexing fix also covers the generic CUDA implementation; CUDA allocation and dispatch remain unchanged. The 3D helpers are outside this change.
>
> Other related PRs have distinct roles:
>
> - [#165337](https://github.com/pytorch/pytorch/pull/165337): rejected spatial-LDS tiling assumed locality that arbitrary grids do not provide. This PR uses shared memory for channel reduction, which requires no input-space locality assumption.
> - [#191915](https://github.com/pytorch/pytorch/pull/191915), upstream `ed3545d`: backward `grad_output` shape validation already present in the base, retained here.
> - [#172476](https://github.com/pytorch/pytorch/pull/172476), upstream `8203775`: atomic-helper architecture checks for SPIR-V, also already in the base. This PR avoids the optional aggregation helper and does not modify `KernelUtils.cuh`.
>
> Historical same-base ablations explain the combination: the repaired diagnostic port of #166825's later mapping took **9.838 ms**; reduction alone **6.568 ms**; preserved layout alone **6.425 ms**; both **0.794 ms**, with final verification **0.796 ms**. The original **~9.4×** used the generic baseline **7.493 ms**. These were synthetic operator measurements on the earlier ROCm-based revision. The later upstream-based comparison measured **7.556 → 0.796 ms (~9.49×)**. Customer end-to-end results remain unvalidated, and the documented full-size FP32 rounding qualification remains applicable.
>
> Earlier validation recorded 25 `test_nn` tests and 59 operator/gradient/Meta selections, plus eager/FakeTensor parity and `aot_eager`. Before this follow-up, all six generated ROCm-specific variants were reported passing on MI300 and MI350; those correctness results are not before/after performance measurements. The current follow-up passed 63 regression variants and a 41-case numerical comparison against the preceding PR head, with **0.795929 → 0.796221 ms** on large-C channels-last backward. Broader performance evidence is still needed before expanding the optimized architecture gate; the generic fallback layout change also needs cross-device performance validation.
>
