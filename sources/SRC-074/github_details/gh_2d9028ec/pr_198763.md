Part of the set of changes the two-phase precompile workflow needs at pytorch tip, on top of the open precompile stack that ends in #198558. In that workflow, one GPU captures the model against a fake process group of the serving world size, and then every rank replays the saved artifact with recompilation refused. The set was found by running the workflow end to end at tip on a large production FSDP2 recommendation model. Each change here was the first blocker at its step: the run got past that step once the change was applied. With the full set, the replay completed on all 16 ranks for 100 batches with no refusals.

**What.** `load_guards_state` rebuilds guarded modules with `cls.__new__(cls)` inside `disable_fsdp_module_new_init()`. `FSDPModule.__new__` always built the original class, for example `Linear` for `FSDPLinear`. So the loaded guard state held a module of the wrong type, and type-derived guards on FSDP2-sharded submodules could never match the live model. There was a second problem: the switch was a module global, so a load on one thread made `FSDPModule(...)` on every other thread skip `__init__`.

This change:
- makes the switch a `ContextVar`, so it only affects the loading context;
- while it is set, returns `object.__new__(cls)`, which keeps the wrapper class;
- adds an `FSDPModule.__init__` that is a no-op while the switch is set and otherwise forwards to the original class's `__init__`.

Outside a load, behaviour is unchanged.

**Why it's needed.** Loading the model's guard state at tip failed with a `KeyError` on a method that exists only on the FSDP2 wrapper's MRO, because the rebuilt module had lost its wrapper type. With this change, the install got past this step.
