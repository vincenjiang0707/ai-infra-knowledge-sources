Part of the set of changes the two-phase precompile workflow needs at pytorch tip, on top of the open precompile stack that ends in #198558. In that workflow, one GPU captures the model against a fake process group of the serving world size, and then every rank replays the saved artifact with recompilation refused. The set was found by running the workflow end to end at tip on a large production FSDP2 recommendation model. Each change here was the first blocker at its step: the run got past that step once the change was applied. With the full set, the replay completed on all 16 ranks for 100 batches with no refusals.

**What.** `GuardsStatePickler` pickles every object the guard tree reaches. For `nn.Module`s it already prunes the `__dict__` entries that no guard reads. Any other guarded user object was pickled whole, so one unpicklable attribute that nothing guards made pickling fail and the frame was bypassed. Examples of such attributes: a lock, or a data loader whose `__getstate__` raises.

This change applies `_prune_unguarded_attributes` to any guarded plain user object that has a `__dict__` and is not a class, module, `nn.Module`, tensor or `torch.*` type. It runs last, so the specific reducers above it take precedence. Attributes a guard does read are still pickled and checked.

**Why it's needed.** At tip, all 5 of the model's compiled frames were bypassed. A guarded training-pipeline object held a distributed data loader whose `__getstate__` raises ("does not support pickle"). The capture completeness gate then refused the artifact. With this change, no frames were bypassed.
