# [PR #187999] Fix uninitialized memory warnings in CPU linear algebra kernels

source: https://github.com/pytorch/pytorch/pull/187999
state: closed | updated: 2026-09-26T23:35:46Z
labels: triaged, open source, Stale, topic: not user facing

## 正文

Modifies ATen CPU linear algebra kernels in `BatchLinearAlgebraKernel.cpp` to value-initialize workspace query variables and `.zero_()` output tensors before passing their buffers to external BLAS/LAPACK functions.

When building PyTorch with MemorySanitizer (`msan`), test suites executing CPU linear algebra operations (such as `torch.linalg.svd`, `cholesky`, `qr`, and` lu_factor`) fail with false-positive `MemorySanitizer: use-of-uninitialized-value` errors.

This occurs due to two distinct patterns when interacting with external BLAS/LAPACK libraries (e.g., MKL, OpenBLAS, Netlib LAPACK):

1. **Optimal workspace size queries**: When querying LAPACK routines for optimal workspace sizes (`lwork = -1`), local floating-point variables (e.g., `wkopt`, `work_query`) were passed by pointer uninitialized. Because external precompiled BLAS/LAPACK libraries are uninstrumented under MSan, writes to `&wkopt` do not update MSan shadow memory. When 
`lapack_work_to_int` subsequently invokes `std::nextafter()` on the returned value, MSan checks shadow memory and triggers an error.
2. **Computational outputs**: Output tensors allocated via structured kernels or `at::empty()` start with uninitialized memory and uninitialized MSan shadow memory. When uninstrumented LAPACK computation routines populate these buffers, shadow memory remains marked uninitialized. Subsequent tensor operations or test comparisons (e.g., ``at::isnan()`) trigger uninitialized storage exceptions.

### Changes

- `BatchLinearAlgebraKernel.cpp`:
  - Value-initialized scalar workspace query variables (`work_query = 0`, `lwork_query = 0`, `rwork_query = 0`, `wkopt = 0`, `work_opt = 0`, `rwork_opt = 0`) across all LAPACK query sites (`lapackEig`, `lapackSyevd`, `lapackGeqrf`, `lapackOrgqr`, `lapackOrmqr`, `lapackLdl*`, `lapackSvd`).
  - Added zero initialization calls (`.zero_()`) for output tensors in Cholesky, LU factorization, and SVD kernels before passing their underlying data pointers to BLAS/LAPACK routines.
- `ts_native_functions.cpp`:
  - Added 0-dimension tensor zeroing in `empty_symint` to prevent MSan failures when hashing newly initialized lazy scalar tensors during device data caching.
