# [PR #196924] [MPS] Migrate `addc[mul|div]` to Metal

## 正文

Stack from [ghstack](https://github.com/ezyang/ghstack/tree/0.18.0) (oldest at bottom):
* #198753
* #198743
* __->__ #196924

Follows the precedent set by lerp and clamp: both ops now register `addc{mul,div}_stub` and run through the shared `exec_ternary_kernel`, which gains an alpha flavor for the `value` scalar so the family covers `clamp`, `lerp`, `addcmul` and `addcdiv` alike.

Fixes the same cast error lerp had: the `_cast_` ternary kernels were instantiated for the output dtype, so an `out=` wider than the common dtype widened the computation as well. They now compute at the iterator's common dtype and cast on store, like CPU. 

Against MPSGraph on an M4 Pro, microseconds per call: dense is 2.4x faster below 64K elements (4K 14.1 -> 6.0, 64K 14.3 -> 8.5) and on par from 1M up (35.2 -> 34.8, 16M 984 -> 1003). Broadcast shapes are at parity thanks to the fused-offset kernels two commits down (2D 17.9 -> 19.0, 3D 18.8 -> 19.0), but MPSGraph is still ahead on 4D broadcast (18.4 -> 30.2) and when an operand is transposed (33.9 -> 99.5), where it materializes a tiled copy instead of gathering. Recovering those is follow-up work on the shared family, and would benefit `clamp` and `lerp` too.
