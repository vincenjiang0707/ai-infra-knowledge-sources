With every workflow naming its pod, the mapper has nothing left to translate.
Its other behaviours are gone too: the ROCm and XPU passthroughs return their
input unchanged, and the H100 `mt-` forcing is now literal in the workflows.

One behaviour does disappear with it. The script dropped `config: "onnx"` from
every ARC matrix, so that job has not run since the ARC switch -- onnxruntime
sizes its thread pool from `hardware_concurrency()`, which sees the node's CPUs
rather than the pod's cpuset. The matrix entry is kept rather than deleted
alongside the script, so onnx will actually run again and we find out whether
it still trips over that. If it does, the fix belongs in the onnxruntime
session options, not in a runner mapping.

arc.yaml stays: it documents the naming scheme and the EC2 correspondence,
which is still worth having as reference.
