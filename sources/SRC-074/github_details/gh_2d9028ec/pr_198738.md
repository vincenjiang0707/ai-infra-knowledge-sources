# [PR #198738] [MPS] Promote mixed-dtype operands in the loss kernels and addr

source: https://github.com/pytorch/pytorch/pull/198738
state: open | updated: 2026-09-27T05:23:45Z
labels: open source, release notes: mps, ciflow/mps

## 正文

Stack from [ghstack](https://github.com/ezyang/ghstack/tree/0.14.0) (oldest at bottom):
* #198740
* #198739
* __->__ #198738

MPSGraph refuses to mix element types across an operand pair: feeding it `mps.subtract(tensor<4xf32>, tensor<4xf16>)` fails its module verifier, which calls `abort()`. `mse_loss`, `smooth_l1_loss`, `huber_loss` and `addr` all built their placeholders at each operand's own dtype, so a mixed pair that CPU and CUDA compute happily killed the process.

The fix follows `isin` pattern: cast the placeholders up to the promoted dtype and cast the result back down to the destination's, using `castMPSTensor` helper, and create constant nodes using compute type too.

Also fixes a second bug in `addr` found while verifying it: `addr_mps` allocated its result with `at::empty({0}, self.options())`, so `addr(bf16_self, f32_vec1, f32_vec2)` returned bfloat16 where the reference returns float32.

Test Plan:

New tests, each of which aborts the interpreter without this change (verified by reverting the aten/ half and re-running):

```
python -m pytest test/test_mps.py -q -k "mixed_dtype"
```
