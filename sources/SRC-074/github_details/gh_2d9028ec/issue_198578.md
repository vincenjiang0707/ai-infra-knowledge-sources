# [Issue #198578] torch.distributions.Cauchy.log_prob returns -inf (and NaN gradients) for large |value - loc| / scale because the square overflows

source: https://github.com/pytorch/pytorch/issues/198578
state: open | updated: 2026-09-25T03:49:35Z
labels: module: distributions, triaged, module: correctness (silent), module: edge cases, bot-triaged, release triage

## 正文

### Description

`Cauchy.log_prob` computes `-log(pi) - log(scale) - log1p(((value - loc) / scale) ** 2)`. The square
overflows to `inf` once `|value - loc| / scale` exceeds about 1.8e19 in float32 (1.3e154 in float64), so
`log_prob` returns `-inf` for points in the support whose log density is an ordinary finite number, and
backpropagation through it gives a NaN gradient for `scale`.

### Steps to reproduce

```python
import torch
from torch.distributions import Cauchy
print(Cauchy(0.0, 1.0).log_prob(torch.tensor(1e20)))   # -inf   (exact: -93.248)
d = Cauchy(torch.tensor(0.0, dtype=torch.float64), torch.tensor(1.0, dtype=torch.float64))
print(d.log_prob(torch.tensor(1e160, dtype=torch.float64)))  # -inf   (exact: -737.97)
```

### Expected

A finite log density close to `-log(pi*scale) - 2*log(|z|)`.

### Versions

Environment

PyTorch 2.14.0 (the latest release, CPU wheel) and 2.12.0, Python 3.12, Ubuntu 24.04, x86_64

### vanshdev0101 · 2026-09-25

Looked into the root cause with the help of an AI assistant. Posting the analysis in case it helps with triage — happy to open a PR if this gets an `actionable` label.

> The bug is in `Cauchy.log_prob` (`torch/distributions/cauchy.py`): `log1p(((value - loc) / scale) ** 2)` squares the ratio, which overflows for large deviations or tiny scale even when the true log-density is representable.
>
> Example: `Cauchy(0.0, 1.0).log_prob(1e30)` on float32 returns `-inf`, but the true value is a finite ~-139.3.
>
> Fix: `log1p(z**2)` is algebraically `log(scale**2 + (value-loc)**2) - 2*log(scale)`, and `torch.hypot(scale, value-loc)` computes that Pythagorean sum without ever forming either square in isolation — it's the numerically-stable primitive PyTorch already has for exactly this. Verified against the true values for several extreme-scale cases in float32 and float64, with no change to ordinary-range results.
