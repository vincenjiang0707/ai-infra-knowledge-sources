Part of the set of changes the two-phase precompile workflow needs at pytorch tip, on top of the open precompile stack that ends in #198558. In that workflow, one GPU captures the model against a fake process group of the serving world size, and then every rank replays the saved artifact with recompilation refused. The set was found by running the workflow end to end at tip on a large production FSDP2 recommendation model. Each change here was the first blocker at its step: the run got past that step once the change was applied. With the full set, the replay completed on all 16 ranks for 100 batches with no refusals.

**What.** A TENSOR_MATCH on an input marked with `mark_dynamic` also checks the marking attributes (`_dynamo_dynamic_indices` and related). The tensor rebuilt at load had lost those attributes: the marking sets were never registered as guard-tree values, so (f) did not carry them. The loaded guard therefore took the markings to be absent at compile time, and it rejected every marked input at serve time with `_dynamo_dynamic_indices should be absent but is present on runtime tensor`.

This change registers each marking set it reads while building the guard (`read_marking`), so the set is carried with the tensor. It depends on (f).

**Why it's needed.** The model marks its inputs dynamic before capture. An end-to-end run at tip with this change removed, and everything else in the stack applied, refused the first served call with exactly the error above. This is the only change proven by removing it from the final passing set.
