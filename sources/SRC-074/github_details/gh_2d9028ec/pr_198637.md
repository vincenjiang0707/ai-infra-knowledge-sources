# [PR #198637] [inductor] Don't reinplace index_put when indices or values share storage with the input

source: https://github.com/pytorch/pytorch/pull/198637
state: open | updated: 2026-09-25T13:08:55Z
labels: module: inductor, ciflow/inductor, ciflow/torchtitan

## 正文

## Issue

Fixes #198567

## Summary

The reinplace pass turns `index_put(x, [idx], val)` into `index_put_` when `x` isn't used afterwards, but it doesn't check whether `idx` or `val` read `x`'s storage themselves. For `torch.put(r, r, r, accumulate=True)` the kernel then reads indices and values from the buffer it is writing to: the result is wrong on CPU, and on CUDA aten's overlap check raises. This adds `should_reinplace_index_put` as the `extra_check` for `index_put` / `_unsafe_index_put`, the same kind of check #198010 added for scatter. #198260 handles `auto_functionalized` ops and user Triton kernels and doesn't fix this case on its own. The check compares storages, so disjoint slices of the same buffer also stay functional, which is conservative.

Tests: a graph-level test on `reinplace_inplaceable_ops_core` (`index_put` / `_unsafe_index_put` x aliased indices / values that are a view of the input / no aliasing as the control), and an end-to-end test on `device`. On CPU the aliased graph-level cases fail before and pass after. On a T4 (nightly 20260924, cu130), `test_inplacing_pass.py` goes from 5 failed / 31 passed to 36 passed, and the index_put / scatter / reinplace tests in `test_torchinductor.py` are unchanged (45 passed, 4 skipped).
