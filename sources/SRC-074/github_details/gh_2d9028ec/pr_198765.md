Part of the set of changes the two-phase precompile workflow needs at pytorch tip, on top of the open precompile stack that ends in #198558. In that workflow, one GPU captures the model against a fake process group of the serving world size, and then every rank replays the saved artifact with recompilation refused. The set was found by running the workflow end to end at tip on a large production FSDP2 recommendation model. Each change here was the first blocker at its step: the run got past that step once the change was applied. With the full set, the replay completed on all 16 ranks for 100 batches with no refusals.

**What.** The AUTOGRAD_SAVED_TENSORS_HOOKS global guard compares the `id()`s of the active pack/unpack hooks. A deserialized guard re-pinned whatever ids were live when it was loaded. A serving process installs fresh hook objects, and the hooks active at load need not be the ones active at serve time, so every captured entry missed on this guard.

This change fingerprints inlineable (GraphModule) hooks by the sha256 of their generated code plus any `user_cache_hash`. It saves the fingerprint with the guard, and the loaded guard compares the live hooks' fingerprint to it, with a small weakref fast path. The same hooks match across processes, and different hooks still miss. The live, unserialized guard is unchanged.

**Why it's needed.** At tip, the artifact installed but its first call was refused on `top_saved_tensors_hooks ids == None`. The model runs its step under saved-tensors hooks, but the artifact is loaded outside them. With this change, the call passed this guard.
