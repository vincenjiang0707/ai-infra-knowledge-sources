## 正文

Part of #142029.

`test/profiler/test_profiler.py` was treated as device-specific as a whole. Most of it is not. Three commits, reviewable in order:

1. Tag all 11 test classes with `hw_classification`, suffix the four CUDA-gated classes that were not already named for it, and move `test_forked_process` out of the accelerator-parameterized class - it was `@onlyOn("cpu")` and never used its `device` argument.
2. Make `setUpModule`'s Kineto priming device-generic. The process-global profiler cannot upgrade from a CPU-only first session, so without priming XPU collection is dead process-wide (`kernel`, `ac2g`, `xpu_runtime` all 0). This commit also carries the `test_forked_process` skip, because generic priming turns that deadlock from order-dependent into unconditional.
3. `allow_xpu=True` on `TestProfilerDevice`, drop a stale skip for the now-closed torch-xpu-ops#2263, widen `test_kineto` to XPU.
