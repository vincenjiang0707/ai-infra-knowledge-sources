# [Issue #198624] [aot_autograd] y = x.detach() updated in place with a value that requires grad is returned without its grad_fn

source: https://github.com/pytorch/pytorch/issues/198624
state: open | updated: 2026-09-26T04:38:17Z

## 正文

### 🐛 Describe the bug

```python
import torch


def f(x):
    y = x.detach()
    y.add_(x)
    return y


for backend in ("eager", "aot_eager", "inductor"):
    torch._dynamo.reset()
    x = torch.ones(3, requires_grad=True)
    out = (f if backend == "eager" else torch.compile(f, backend=backend))(x)
    print(backend, out.requires_grad, out.grad_fn)
```

```
eager True <AddBackward0 object at 0x...>
aot_eager False None
inductor False None
```

Eager returns a tensor that requires grad (the in-place add gives `y` a history), aot_eager and inductor one that doesn't, so a loss through it silently gets no gradient from it. Leaf or non-leaf `x`, 2.9.1, 2.14.0 and the 21 Sep nightly on CPU, 2.14.0 on CUDA.

The output is recorded as `alias_of_input` with `view_meta_sequence=ViewMetaSequence(detach)` and `requires_grad=True`, and the runtime wrapper regenerates it from the updated input by replaying the `detach` in `gen_alias_from_base`, which drops that history. I haven't looked at where a fix should go.

## 评论 (1)

### XFDG · 2026-09-26

I reproduced this on `torch 2.9.1+cu128` (CPU): eager returns an alias with `AddBackward0` and `x.grad == 1`, while `aot_eager` and `inductor` preserve the storage alias but return `requires_grad=False`/`grad_fn=None`.

The runtime path appears to be `AliasOfInputHandler` -> `gen_alias_from_base`: replaying the recorded `ViewMetaSequence(detach)` on the mutated input drops the history, and `patch_requires_grad()` cannot restore that edge. The compiled output is currently used as target metadata while the user-visible alias is regenerated from the input. Simply returning the compiled output would risk breaking the required storage-alias semantics.

This looks like it needs an explicit design for grad-requiring aliases whose replay recipe contains `detach` (for example, deciding whether these aliases need a backward tangent or a differentiable alias/rebase-history path in the epilogue). Is there a preferred AOTAutograd direction for this case? I am holding off on a patch until the gradient and alias contracts are clear, rather than changing only the `requires_grad` flag.
