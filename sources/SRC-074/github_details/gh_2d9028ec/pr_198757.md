Part of the set of changes the two-phase precompile workflow needs at pytorch tip, on top of the open precompile stack that ends in #198558. In that workflow, one GPU captures the model against a fake process group of the serving world size, and then every rank replays the saved artifact with recompilation refused. The set was found by running the workflow end to end at tip on a large production FSDP2 recommendation model. Each change here was the first blocker at its step: the run got past that step once the change was applied. With the full set, the replay completed on all 16 ranks for 100 batches with no refusals.

**What.** `dataclasses` and similar helpers build methods with `exec()`. The resulting code object has file `"<string>"` and a synthetic `co_qualname` (`__create_fn__.<locals>.__init__`). `inspect.getmodule(code)` returns None, and the qualname walk cannot work either, so packaging such a frame raised:

    PackageError: Cannot find module for code <code object __init__ at ..., file "<string>", line 2>

This change passes the frame's globals from `convert_frame` into `CompilePackage.code_context`. `_globals_module_name` maps those globals back to the owning module, and only when `vars(module) is globals`. `_get_code_source` takes that module as a hint: when the code has no module of its own, it searches the module tree, and the class search also looks inside descriptors.

**Why it's needed.** The model compiles the `__init__` of a dataclass. At tip, capture failed on it with exactly the error above. With this change, capture completed.
