# [PR #198411] [AArch64] Use native GEMV for single-column BF16 GEMMs

source: https://github.com/pytorch/pytorch/pull/198411
state: open | updated: 2026-09-25T12:35:01Z
labels: module: cpu, open source, ciflow/trunk

## 正文

Requires `is_arm_neoverse()` to recognize Neoverse V3: https://github.com/pytorch/cpuinfo/pull/435

On Arm Neoverse systems built with the oneDNN ACL backend, decline BF16 CPUBlas GEMMs when `n == 1` and `alpha == 1` so the existing native GEMV fallback is used. `n == 1` makes the operation a matrix-vector product, and these shapes are common during single-token transformer decode.
In official Linux AArch64 wheels, the fallback is OpenBLAS `sbgemm_` when available. Otherwise, CPUBlas uses ATen `gemm_stub`.
`is_arm_neoverse()` is required because this fallback only benefits Arm.

Tested on Neoverse V3 - c8g.16xlarge and Neoverse V2 - c9g.16xlarge.
GCC 13.3 and oneDNN 3.12.0

Workload: GPT-2 BF16 single token decode on one pinned thread

| CPU | Before | After | Speedup |
|---|---:|---:|---:|
| Graviton 5 | 56.0842 ms | 10.5462 ms | **5.32x** |
| Graviton 4 | 75.9550 ms | 14.1522 ms | **5.37x** |

Across other thread counts:
| CPU | Threads | Before | After | Speedup |
|---|---:|---:|---:|---:|
| Graviton 5 | 8 | 11.2110 ms | 4.0912 ms | **2.74x** |
| Graviton 5 | 16 | 8.2988 ms | 4.5431 ms | **1.83x** |
| Graviton 5 | 32 | 7.0627 ms | 4.2545 ms | **1.66x** |
| Graviton 5 | 64 | 6.1616 ms | 4.2753 ms | **1.44x** |

Correctness:
CPUBlas results were compared against the existing oneDNN results across every transpose layout, `beta=0` and `beta=1`, and both aligned and non-aligned dimensions.
