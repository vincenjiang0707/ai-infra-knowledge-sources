## 正文

Makes `test/test_fake_tensor.py` device-agnostic and enables it on XPU.

What changed:

- device-dependent tests now run per device (cpu, cuda, xpu) instead of hard-coding `cuda`; device-independent tests are untouched
- tests that need real accelerator hardware no longer generate a cpu copy that only skips
- two mixed cpu/xpu conv tests are skipped on XPU: the cpu-input/xpu-weight conv hits `aten::_slow_conv2d_forward`, which XPU does not implement (intel/torch-xpu-ops#5125)
- `test_fake_gpu_no_init` and `test_move_module_under_fake` intentionally stay `GPU_TYPE`-based: they must run when the device is absent, which a per-device test cannot do. `test_move_module_under_fake` now also runs on accelerator machines, not just CUDA builds
- test classes are renamed to the `TestFakeTensor*` convention; the one compiled_autograd skip marker is renamed with them
- fixes a ~1% flake in the `numpy_nonzero` custom-op sample generator, which the rename would otherwise expose by reseeding OpInfo samples
- coverage caveat: on CPU-only builds, the fake-only paths of `test_conv_rejects_mismatched_fake_devices` and the device half of the embedding-indices test no longer run, as both are now accelerator-only

Results on XPU (Intel Arc B580):

    Before: 340 passed, 118 skipped, 7 xfailed
    After:  446 passed, 105 skipped, 7 xfailed
    ------------------------------------------
    Delta: +106 passed,  -13 skipped

Every passing test name that disappears reappears under its new device-generic name; the remaining skips are either pre-existing/tracked or the cpu instances of accelerator-only tests.

Prepared with the assistance of an AI assistant; all test numbers above were produced by running the suites locally.
