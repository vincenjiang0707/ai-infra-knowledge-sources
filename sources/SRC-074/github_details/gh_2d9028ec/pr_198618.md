# [PR #198618] [dynamo] Preserve hasattr keyword errors and answer exact-object checks

## 正文

I reproduced this myself with a small script. This PR fixes two separate problems in `hasattr()`. First, on a plain `object()` instance, `hasattr(o, "foo")` and `hasattr(o, "__dict__")` gave the right answer under normal `torch.compile`, but `fullgraph=True` failed with `Unsupported`. Normal compile giving the right result while fullgraph fails is a graph break. Second, `hasattr(x=2)` raised `TypeError` with an empty message instead of `hasattr() takes no keyword arguments`, which is a wrong error message. With this PR both match eager.

> **AI-generated technical summary (Claude), reviewed by me:**
>
> Part of #195901 (preserve `hasattr()` keyword-argument errors; answer `hasattr` for exact `object` instances).
>
> - `HasAttrBuiltinVariable` combined the keyword check with the arity check and raised a message-less `TypeError`. The keyword check is now separate and raises CPython's `hasattr() takes no keyword arguments`; the arity path is unchanged.
> - `ObjectVariable` used the generic `hasattr` path for exact `object()` instances, which graph-broke ("Unsupported hasattr call") on absent attributes. An exact `object()` has no `__dict__` and cannot gain attributes, so `call_obj_hasattr` now answers from the represented value when `type(value) is object` and leaves every other value on the generic path. Changing the general attribute protocol would widen the scope without helping this case.
>
> **Tests**
>
> - `test_tp_getattro.py::test_hasattr_keyword_error`: under `fullgraph=True`, `hasattr(x=2)` raises `TypeError` with CPython's message. Fails without the fix.
> - `test_tp_getattro.py::test_hasattr_exact_object`: under `fullgraph=True`, `hasattr` on an `object()` for `foo`, `__call__`, `__dict__`, `__class__` and `__str__` matches eager. Fails without the fix.
>
> CPython tests under Dynamo: `test_call` `CFunctionCallsErrorMessages.test_varargs5_kw` and `test_class` `ClassTests.testPredefinedAttrs` go from error to passing, and no test goes from passing to failing in `test_builtin`, `test_call`, `test_class` or `test_descr`; the two expected-failure markers are removed. The other tests in `test/dynamo/test_tp_getattro.py` show the same results with and without the change.
