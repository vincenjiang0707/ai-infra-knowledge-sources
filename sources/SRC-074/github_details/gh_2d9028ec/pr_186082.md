* __->__ #186082

SymIntArrayRef to IntArrayRef conversion fails in asIntArrayRefSlow
when any SymInt is heap allocated, but the previous error only said that
concrete integers were expected. For symbolic sizes this hid the actual
bad element and gave no guidance about the common dynamic-shape causes,
which made failures such as torch.empty((s0, 5, 10)) hard to debug.

Report the offending index, value, and full SymIntArrayRef from the shared
conversion helper. Symbolic values now get dynamic-shape guidance covering
FakeTensorMode, missing SymInt kernel support, and Python dispatcher setup.
Heap-allocated concrete values get separate wording because they are
concrete but still cannot be viewed through the non-owning IntArrayRef
reinterpret-cast path.

The nearby sym_equals initialization is also made explicit after the size
mismatch return. This is behavior-preserving and keeps clang-tidy happy
when this header is touched.

Fixes #140960
