## Summary

The alias-analysis path (`get_executor` → `optimized_graph` → `preoptimizeGraph` → `PeepholeOptimize`/`ConstantPooling` → `AliasDb`) repeatedly rebuilds `UnionType` instances as keys into `wildcardIndex_`. This memoizes those `UnionType::create` calls so each union key is built at most once per `AliasDb`. 
A new const helper `getWildcardKeyType(type, mut_types)` returns the wildcard index key:

- the **sole mutable type** when there is exactly one, or
- a `UnionType` cached per-`AliasDb` in a new `wildcard_key_types_` map (keyed by
  the declared `TypePtr`) when there are several.

It replaces the `toSingleType`/`UnionType::create` path in
`tryGetOrCreateWildcard` and the inline `UnionType::create` in `getWildcard`.

## Why it's safe

- `UnionType::create` is deterministic and `wildcardIndex_` uses **structural**   hash/equality, so reusing a memoized instance is functionally identical to building a fresh one.
- `toSingleType` is retained for the `Future`/`Await`/`Tuple` mapping paths.
- **No behavior change.**
