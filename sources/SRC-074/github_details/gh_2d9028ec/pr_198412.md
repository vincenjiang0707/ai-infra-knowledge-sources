# [PR #198412] cmake: Fix clobbering of COMPILE_OPTIONS

## 正文

Using `set_source_file_properties(... PROPERTIES COMPILE_OPTIONS ...)` replaces the entire `COMPILE_OPTIONS` list. Using `set_property(SOURCE ... APPEND PROPERTY COMPILE_OPTIONS ...)` appends new flags.

Similarly `set_target_properties(... PROPERTIES LINK_FLAGS ...)` replaces all link flags, `target_link_options` appends flags instead.

The build error comes from the new `"SHELL:-gencode arch=compute_90a,code=sm_90a"` option on `AsyncMM.cu` (`caffe2/CMakeLists.txt:655`). CMake doesn't expand the `SHELL:` prefix here, so nvcc gets the whole string as one argument and fails.

<details>
<summary>Details</summary>

### Failing job
[`linux-jammy-cuda13.0-py3.10-gcc11-build-native-aot-h100 / build`](https://github.com/pytorch/pytorch/actions/runs/35905590699/job/107332442295). This is the only failure so far; the other builds are still running or passed. It uses CMake 3.31.6, nvcc 13.0, GCC 11.

```
FAILED: caffe2/CMakeFiles/torch_cuda.dir/__/torch/csrc/distributed/c10d/cuda/AsyncMM.cu.o
nvcc ... -Wno-unused-but-set-variable "SHELL:-gencode arch=compute_90a,code=sm_90a" -MD ... -c .../AsyncMM.cu -o .../AsyncMM.cu.o
nvcc fatal   : A single input file is required for a non-link phase when an outputfile is specified
```

### Root cause
In the generated command line, the source-level `COMPILE_OPTIONS` entry reaches nvcc exactly as written, `SHELL:` prefix and quotes included. nvcc doesn't recognize `SHELL:-gencode arch=...` as a flag, so it treats it as a second input file, and that triggers the "single input file" error.

The old code used `COMPILE_FLAGS`, a plain string that gets split like a shell command, so `-gencode arch=...` arrived as two arguments.

My previous review was wrong to recommend the `SHELL:` form: I cited line 655 as existing precedent, but that line is this PR's own change.

### Fix
Use the append form of the string property the old code used. This keeps the original behavior and still stops the clobbering:

```cmake
if(CUDA_NVCC_FLAGS MATCHES ".*compute_90.*")
  set_property(SOURCE ${ASYNC_MM_FILE} APPEND_STRING PROPERTY COMPILE_FLAGS " -gencode arch=compute_90a,code=sm_90a")
endif()
```

(Another option is two separate list items, `"-gencode" "arch=compute_90a,code=sm_90a"`, in `COMPILE_OPTIONS`. But CMake's option de-duplication could remove the repeated `-gencode` if another one is ever added to this file, so `APPEND_STRING` on `COMPILE_FLAGS` is safer.)

The same concern applies to `-mllvm;-openmp-opt-disable` at line 873, but plain list items are the right choice there for the same reason. Please ignore my earlier `SHELL:` suggestion for that line too.

[Fix this →](https://claude.ai/code?q=In%20caffe2%2FCMakeLists.txt%20line%20655%20on%20branch%20cmake-option-clobbering%2C%20replace%20%60set_property(SOURCE%20%24%7BASYNC_MM_FILE%7D%20APPEND%20PROPERTY%20COMPILE_OPTIONS%20%22SHELL%3A-gencode%20arch%3Dcompute_90a%2Ccode%3Dsm_90a%22)%60%20with%20%60set_property(SOURCE%20%24%7BASYNC_MM_FILE%7D%20APPEND_STRING%20PROPERTY%20COMPILE_FLAGS%20%22%20-gencode%20arch%3Dcompute_90a%2Ccode%3Dsm_90a%22)%60%20because%20nvcc%20receives%20the%20SHELL%3A%20prefix%20literally%20and%20fails&repo=pytorch/pytorch)
