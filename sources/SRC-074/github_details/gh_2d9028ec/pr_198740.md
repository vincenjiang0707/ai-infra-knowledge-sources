Fixes #154887

`batch_norm` with a half input and float32 running stats -- the ordinary AMP combination, accepted by CPU and CUDA -- killed the interpreter, because MPSGraph fails its module verifier on a mixed operand pair and calls `abort()` rather than throwing.

Narrowing the stats to the input dtype clears both aborts and makes the output, `grad_input` and `grad_bias` match the reference bit-exactly. `grad_weight` is the exception: it is stored at the parameter dtype and the reference computes it there too, so narrowing left it computed in f16 and widened afterwards, a little under 1e-3 off CPU. That one path therefore widens the input to the stats dtype instead, which brings it within a single float32 ulp. The two gradient paths consequently need their epsilon and rsqrt tensors at different dtypes, so the sharing between them is gone and the duplicated version check became a local helper.

The backward also casts `save_mean`/`save_var` on the way in, which costs nothing today because `batch_norm_mps` allocates them at the input dtype. That is deliberate: the reference gives them the parameter dtype when mixed, so ours are arguably wrong, and whoever resolves the standing "Accumulate type?" TODO should not have to fix the backward too.

Training mode is left alone. It never aborted, and its few-ulp difference from CPU is the same TODO -- MPS accumulates batch statistics at the input dtype where the reference uses float. Confirmed pre-existing by reverting this patch and re-running: MPS returns byte-identical values either way. Including it would have forced tolerances loose enough to hide the reinterpretation this is about.

As with the two commits below, OpInfo cannot generate this: every `sample_inputs_*` threads one `dtype` through all operands, so there is no skip to remove either -- the case was never reachable. Hence the hand-written test.

Test Plan:

Both repros from the issue abort before this change and return correct values after:

```
python -c "
import torch
print(torch.nn.functional.batch_norm(
    torch.rand((2, 3, 4), dtype=torch.float16, device='mps'),
    torch.rand((3,), dtype=torch.float32, device='mps'),
    torch.rand((3,), dtype=torch.float32, device='mps')))
"
python -c "
import torch
print(torch.ops.aten._native_batch_norm_legit_no_training.default(
    torch.rand((2, 3, 4), dtype=torch.float16, device='mps'), None, None,
    torch.rand((3,), dtype=torch.float32, device='mps'),
    torch.rand((3,), dtype=torch.float32, device='mps'), 0.1, 1e-05)[0])
"
```
