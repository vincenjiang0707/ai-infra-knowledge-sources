# [PR #194904] [profiler][xpu] Test that ac2g CPU->GPU flow arrows end on the device

## 正文

## What
Add an XPU profiler regression test that asserts CPU→GPU ("ac2g") flow arrows
end on the device, in `test/profiler/test_xpu_profiler.py`.

## Why
`ac2g` means *async CPU→GPU*: a flow starts at a host launch and must end at
the device op, so no flow may both start and end on the host. On XPU the
exporter could attach flow endpoints to host-side Level Zero (`ze*`) driver /
overhead subspans, producing redundant host→host arrows and orphan host
finishes that break CPU→GPU trace correlation. This test locks the invariant so
the class of bug cannot regress.

## How
Profile a small workload, export a Chrome trace, and check every ac2g flow
finish lands on a GPU device track. GPU tracks are the pids labelled `"GPU …"`
in the trace's `process_labels` metadata; a finish on any other (host) track is
malformed. The check is type-agnostic (it does not enumerate record kinds), so
it catches any nested host subspan. A sanity assertion ensures the workload
actually produced ac2g flows.

## Notes
- **Draft on purpose:** the underlying fix lives in Kineto
  (pytorch/kineto#1549); this test will only pass once that fix is pulled into
  `third_party/kineto`. Ready to un-draft after the Kineto PR lands.
- Validated on Intel GPU hardware: the test correctly fails on the current
  (unfixed) trace and passes on the fixed one. XPU-gated (`TEST_XPU`).
