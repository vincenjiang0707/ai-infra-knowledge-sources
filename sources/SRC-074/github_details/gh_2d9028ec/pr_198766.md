Part of the set of changes the two-phase precompile workflow needs at pytorch tip, on top of the open precompile stack that ends in #198558. In that workflow, one GPU captures the model against a fake process group of the serving world size, and then every rank replays the saved artifact with recompilation refused. The set was found by running the workflow end to end at tip on a large production FSDP2 recommendation model. Each change here was the first blocker at its step: the run got past that step once the change was applied. With the full set, the replay completed on all 16 ranks for 100 batches with no refusals.

**What.** `convert_frame` skips a frame wrapped with `torch._dynamo.disable(recursive=False)` only when asked to compile it. So that frame never gets a cache entry, and every call reaches the eval-frame callback as a cache miss. The refuse-recompile callback, which the `fail_on_recompile` stance and an installed precompile artifact both use, treated that miss as a recompile. It raised with no guard failure to report, for example "no captured variant matches this call".

This change makes the callback recognize a frame entered through `_nonrecursive_disable_wrapper_code` and return `apply_to_code=False` for it. The frame's callees still go through the callback, so a real recompile inside them is still refused.

User-visible effect: `torch.compiler.set_stance("fail_on_recompile")` no longer raises spuriously on a `disable(recursive=False)` frame.

**Why it's needed.** The model's config wraps some forward methods in `disable(recursive=False)`. At tip, the installed artifact refused the first call into one of them. With this change, the end-to-end run completed on all 16 ranks.
