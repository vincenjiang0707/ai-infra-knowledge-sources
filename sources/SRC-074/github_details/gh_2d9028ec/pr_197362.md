# [PR #197362] [ROCm][CI] Remove DIND for rocm CI

## 正文

## Motivation
Teardown of nested DinD containers on shared overlay storage causes writeback contention on MI350 nodes. Running the CI image as the ARC job pod removes that nested docker exec path.

## Summary
Adds reusable `_rocm-test-kubernetes.yml` and ports the #197330 default-shard Kubernetes split into `trunk.yml` (the labeled substitute for dispatch-only `rocm-mi350-kubernetes.yml`). When the GHCR mirror of the build image is present, default x8 shards run as kubernetes job pods on `linux.rocm.gpu.gfx950.1-no-dind`; inductor and distributed stay on DinD. A CPU `resolve-image` job fails fast if the mirror is missing.

## Test plan
- Apply `ciflow/trunk` so trunk MI350 actually runs on this head SHA.
- Confirm default shards schedule on `linux.rocm.gpu.gfx950.1-no-dind` via `_rocm-test-kubernetes.yml`.
- Confirm inductor and distributed remain on `_rocm-test.yml` (DinD).
