## 正文

`test_aot_autograd_symbolic_exhaustive_linalg_pinv_hermitian_cpu_float32` fails consistently when run in isolation on Apple Silicon (M1 on macOS 14.8.1 and 15.7.1 in CI, M5 Pro on macOS 27 locally):
In CI it only fails occasionally , depending on the test execution order, and for the same reason it fails on every rerun.

The mismatches are not a correctness issue. The two out-of-tolerance entries are -331.688 (diff 4.9e-4, 12 ulp) and -7.1977 (diff 3.1e-5, 36 ulp), while the largest entry of the same gradient is ~2.87e4 and the input's condition number is ~7.2e2. Relative to the gradient's scale both errors are ~1e-8, below float32 epsilon; the small entries are produced by cancellation, so eager and compiled rounding differences are absolute. `atol=1e-3, rtol=1e-5` gives ~2x headroom and is still tighter than the existing `linalg.pinv` "singular" override (1e-2/1e-2). It is added to `aot_autograd_failures`, so it applies to all four AOTDispatch variants.
