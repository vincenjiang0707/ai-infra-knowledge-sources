## 正文

### 🐛 Describe the bug

### Description

`torch.compile(backend="inductor")` crashes with `NotImplementedError: Negation, the '-' operator, on a bool tensor is not supported` when a `softmax` is applied to a value derived from a boolean tensor (`torch.eq` → `torch.div`). The **same model runs fine in eager**, and also under `backend="eager"` and `backend="aot_eager"` — only the Inductor lowering negates the bool tensor. Reproduces on 2.14.0 and current nightly (2.15.0.dev).

### Minimal reproducer (CPU)

```python
import torch

a = torch.randn(8, 8, dtype=torch.float32)
b = torch.randn(8, dtype=torch.float64)

def model(a, b):
    m = torch.eq(a, 2.0)          # bool tensor
    d = torch.div(m, b)           # bool / float64
    return torch.softmax(d, 0)

print("eager ok:", tuple(model(a, b).shape))     # (8, 8)

out = torch.compile(model)(a, b)                 # raises under inductor
```

### Ablation

| backend | result |
| --- | --- |
| eager (no compile) | ✅ works |
| `backend="eager"` | ✅ works |
| `backend="aot_eager"` | ✅ works |
| `backend="inductor"` | ❌ `NotImplementedError: Negation on bool tensor` |

So the bool negation is introduced by the **Inductor lowering** (of `softmax` over the bool-derived tensor), not by Dynamo/AOT.

### Error

```
torch._dynamo.exc.BackendCompilerFailed: backend='inductor' raised:
NotImplementedError: Negation, the `-` operator, on a bool tensor is not supported.
If you are trying to invert a mask, use the `~` or `logical_not()` operator instead.
```

### anna-researcher · 2026-09-25

This is the same root cause as #196743 — the scaled-softmax rewrite (mul_softmax_pattern in torch/_inductor/fx_passes/joint_graph.py) negates a constant derived from the input dtype, which fails when that input is a bool tensor (neg(bool)). The difference here is that the bool reaches softmax via division rather than multiplication:

```python
import torch
a = torch.randn(8, 8); b = torch.randn(8, dtype=torch.float64)
def f(a, b):
    m = torch.eq(a, 2.0)       # bool
    return torch.softmax(torch.div(m, b), 0)   # bool -> div -> softmax
```
f(a, b)                        # eager: OK
torch.compile(f)(a, b)         # inductor: NotImplementedError: Negation on bool tensor

Why this is still worth tracking even though #196743 exists: the pending fix #196874 skips the rewrite for bool inputs only in the multiplication path, so this division variant is likely not covered. It still reproduces on today's nightly (2.15.0.dev20260925+cpu), on all backends where the scaled-softmax pattern applies. It'd be good to confirm the fix also guards the div/reciprocal form of the pattern.

Happy to close as a duplicate of #196743 if you'd prefer to track it there — flagging mainly so the div case doesn't slip through the fix. (Found via fuzzing.)
