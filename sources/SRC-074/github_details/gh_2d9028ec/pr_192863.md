# [PR #192863] [dynamo] apply the out= resize check to schema-named out arguments

Dynamo deliberately graph-breaks when an `out=` tensor is resized by the call,
because out variants that resize are hard to get right across
dynamo/aot/inductor. That check only ran when the argument was literally spelled
`out`, so out variants that name their outputs differently skipped it entirely:
autogenerated multi-output variants use `out0`/`out1`/..., and some ops name the
arguments after the outputs (`aten.aminmax` uses `min`/`max`). For those, the
resize was applied to the fake tensor during tracing and never to the real one,
so the caller silently read back the original (unresized) tensor instead of
either the resized result or an eager fallback.

This is a silent wrong result under plain `torch.compile`, not just a missing
graph break:

    def fn():
        mn, mx = torch.empty(0), torch.empty(0)
        torch.ops.aten.aminmax(torch.zeros(4, 5), min=mn, max=mx)
        return mn.shape, mx.shape

    eager    -> (torch.Size([]), torch.Size([]))
    compiled -> (torch.Size([0]), torch.Size([0]))

The argument names are only discoverable from the schema (`Argument.is_out`), so
`torch._ops._out_arg_names` reads them, memoized per operator. The memo is keyed
on the qualified name plus overload names rather than on the operator object,
because a packet hashes on its `_op`, which `_refresh_packet` reassigns in place
when a library adds an overload; the freed address can be reused, aliasing a
stranded entry and serving a stale answer. That name key is itself reused when a
library is torn down and the op redefined with a different schema, so
`_clear_torch_ops_cache` drops the memo.

Dynamo snapshots those arguments' shapes before the call and checks them
afterwards in a pass of its own, leaving the existing `out=` handling untouched.
Reusing the pre-existing list-of-out-tensors path instead would have been a
smaller diff but is wrong twice over: that path answers the layout question with
`false_if_dde=False`, so an unbacked-size `out=` on one of the eight schemas that
declare `out` alongside other named out arguments (`aten::native_batch_norm.out`
and friends) would hard-error under `fullgraph=True` where it compiles today, and
routing `out=` through it also changes the reported `gb_type` for programs that
are otherwise unaffected.

For the same reason the layout restriction is deliberately not extended to
schema-named arguments -- only the resize check is. Extending it would newly
reject calls that compile correctly today, both for genuine out variants with a
non-contiguous named out argument and for custom ops whose kwarg-only mutable
arguments are `is_out` without the op being an out variant at all. Verified
across ten ops and the contiguous/strided/transposed/channels-last layouts on
eager, aot_eager and inductor that leaving the check off yields no wrong result.

The new break gets its own `gb_type` rather than reusing the `out=` one, since
the registry requires each `gb_type` to be unique.

This surfaced as 20 failing `test_meta.py` `test_{batch,group,layer}_norm_
backward_output_mask*_cpu` tests under `PYTORCH_TEST_WITH_DYNAMO=1` once nested
graph breaks were enabled (#186100): those tests call
`native_layer_norm_backward` with `out0`/`out1`/`out2` and then assert the out
tensors' shapes. The bug is not NGB-specific -- it reproduces with nested graph
breaks off, and on CPU as well as meta -- NGB only widened symbolic coverage
enough for the tests to reach the call instead of running it eagerly.

Test Plan:

```
python test/dynamo/test_repros.py -k out_
python test/dynamo/test_misc.py -k out_variant
python test/test_custom_ops.py -k out_arg_names
python test/dynamo/test_dicts.py
PYTORCH_TEST_WITH_DYNAMO=1 python test/test_meta.py -k norm_backward_output_mask
```

Each new test was mutation-checked. Making `_out_arg_names` return an empty set
fails exactly the four resize tests; rerouting the lone `out=` onto the list path
fails both `test_out_kwarg_*` tests; extending the layout check to schema-named
arguments fails `test_out_schema_named_out_kwargs_non_contiguous`; and removing
the `_clear_torch_ops_cache` hook fails
`test_out_arg_names_not_stale_after_redefinition`. The 20 previously-failing
norm-backward tests pass, and the existing `out=` tests are unchanged.

Two tests pin `canonicalize_output_graph_node_order=False`: that pass keys its
reorder barrier on a literal `out` kwarg too, so it floats a named-out call past
the readers of what it writes. That is a separate pre-existing bug, fixed
outside this stack.

```python
import torch
lib = torch.library.Library("mylib4", "FRAGMENT")
lib.define("baz(Tensor x, *, Tensor(a!)[] dst) -> ()")
def baz(x, *, dst):
    for d in dst:
        d.resize_(x.shape); d.copy_(x)
lib.impl("baz", baz, "CompositeExplicitAutograd")

def fn():
    a = torch.empty(0); b = torch.empty(0)
    torch.ops.mylib4.baz(torch.ones(3), dst=[a, b])
    return tuple(a.size()), tuple(b.size())

print("eager   ", fn())                                                   # ((3,), (3,))
print("compiled", torch.compile(fn, backend="eager", fullgraph=True)())    # ((0,), (0,))
```
