# [PR #198750] Don't import DTensor, FSDP, ONNX and networkx on the torch.compile path

A single-process torch.compile imported torch.distributed.tensor (~80ms plus
its op registrations), FSDP, torch.onnx and networkx, although none of them
are used unless the program uses them. The general fix everywhere is the
same: an object can't be a DTensor/FSDP method/ONNX function before its
module has been imported, so checks look the module up in sys.modules
instead of importing it.

Dynamo: variables/functions.py and variables/torch.py imported FSDP's
`_fsdp_param_group` at module level only to compare against
`FSDPParamGroup.use_training_state`. `should_wrap_in_hop` imported
`torch.distributed.tensor.experimental._func_map` on the first traced call.
The EQUALS_MATCH guard imported placement_types for its list of allowed
types. isinstance checks in builder.py, decorators.py and symbolic_shapes.py
spelled `torch.distributed.tensor.DTensor`, which only worked because
something else had imported it; they now use a new
`torch._utils._is_dtensor`. The FSDP guard unpickler imports
`get_cls_to_fsdp_cls` itself since it can run in a fresh process.

Trace rules: `get_torch_obj_rule_map()` resolved every entry of
`torch_name_rule_map` while Dynamo was being imported, importing DTensor
(for `DTensor.from_local`) and torch.onnx. Entries whose module isn't
loaded yet are now kept pending per module and added once the module
appears in sys.modules. Deferring only the polyfill duplicate check was
considered, but tracing calls the same map, so DTensor would just have been
imported during the first compile.

Inductor: inductor_prims imported `_pointwise_ops` to register sharding
strategies for its prims. Now whichever of the two modules is imported
second calls `register_inductor_prims()`. Dropping the FSDP import also
stopped registering the Python-defined symm_mem ops before
`register_symm_mem_lowerings` referenced them, so that function imports
torch.distributed._symmetric_memory itself.

partitioners.py imported GraphInfoProvider, KnapsackEvaluator and
minimum_cut (all of which import networkx) at module level; they are now
imported in the code paths that use them.

Making torch.distributed.tensor cheaper to import was the alternative; it is
a much larger change and still wasted work when DTensor is unused. One
DTensor import remains, in C++ `is_dtensor()` in python_arg_parser.cpp, left
for a follow-up.
