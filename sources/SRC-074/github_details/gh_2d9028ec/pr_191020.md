Proof-of-concept consumer for the new Philox reservation API: aten's fused
dropout (fp32 VEC=4 path) reimplemented in both Triton and CuTeDSL as
native_dropout CUDA overrides. Both draw RNG state through
Generator.philox_state and replicate aten's launch geometry and philox
counter mapping, so output, mask, and generator offset advancement are
bit-identical to the aten kernel. Both kernels implement the API's
HostState/DevState protocol the same way aten kernels consume
PhiloxCudaState via unpack(): in eager, seed/offset arrive as scalar kernel
arguments; under capture, the kernel variant loads them at run time from
the generator's extragraph tensors, so a captured graph replays with the
same stream semantics as eager. Ineligible inputs (non-fp32,
non-contiguous, numel % 4 != 0, eval mode) fall through to aten.

Not intended to merge: this exists to validate and demonstrate the
philox_state contract end to end from Python-authored kernels.

Authored with Claude Code.

Test Plan:

test/python_native/test_dropout_dsl.py: bit-exact output/mask/offset vs
stock aten (computed with the overrides disabled) across shapes including
grid-capped sizes, stream composition with eager RNG ops, fp64 fallback,
and CUDA graph capture/replay reproducing consecutive eager calls
(exercising the DevState kernel variants); all parametrized over both
DSLs.

```
python test/python_native/test_dropout_dsl.py
```
