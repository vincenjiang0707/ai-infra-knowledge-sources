## 正文

 ### The feature, motivation and pitch
Add native MPS support for `torch.segment_reduce`, including its backward implementation.

`segment_reduce` combines consecutive, variable-length groups using `sum`, `mean`, `min`, `max`, or `prod`. It is useful for pooling packed token embeddings into sentence/document embeddings and aggregating ragged feature groups without padding each group to the same length.

The existing operator has CPU, CUDA, and XPU implementations, but the base
of pytorch has no native MPS dispatch. On the installed runtime, this minimal example raises `NotImplementedError` when MPS fallback is disabled:

```python
 # Run with PYTORCH_ENABLE_MPS_FALLBACK=0
import torch

 print(torch.__version__, torch.version.git_version)
 data = torch.tensor([1., 2., 3., 4., 5., 6.], device="mps")
lengths = torch.tensor([2, 1, 3], device="mps")
torch.segment_reduce(data, "sum", lengths=lengths)
# Expected: tensor([3., 3., 15.], device="mps:0")
# Actual: NotImplementedError: aten::segment_reduce is not currently
# implemented for the MPS device.
```


The requested scope is FP32/FP16/BF16 data, INT32/INT64 lengths and offsets,  and first-order gradients using the existing operator schema. Indices-based  reduction is not part of this request.

 ### Additional context

 An initial implementation is under review in pytorch/pytorch#197014. Feedback on the scope and preferred test coverage would help prepare it for merging.
