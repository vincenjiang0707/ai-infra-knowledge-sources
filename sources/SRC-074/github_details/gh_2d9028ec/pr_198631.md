# [PR #198631] [ROCm] Revert Free rocFFT plans (#197425)

source: https://github.com/pytorch/pytorch/pull/198631
state: open | updated: 2026-09-25T13:01:22Z
labels: module: rocm, open source, ciflow/trunk, ci-no-td

## 正文

This restores the `#if !defined(USE_ROCM)` guard around `cufftDestroy` in `~CuFFTHandle()`, which #197425 (`ffc54724`) removed. On ROCm, destroying cached plans while static objects are torn down at process exit writes into memory that rocFFT has already freed, and corrupts the heap.


## Root cause

The plan cache is a namespace-scope static in `libtorch_hip.so` ([`SpectralOps.cpp:89`](https://github.com/pytorch/pytorch/blob/ffc54724e283412d8d396faaee20e281bb7cd67b/aten/src/ATen/native/cuda/SpectralOps.cpp#L89)):

```cpp
static std::vector<std::unique_ptr<CuFFTParamsLRUCache>> plan_caches;
```

It is constructed when `libtorch_hip.so` loads, during `import torch`, so its destructor is registered with `__cxa_atexit` early and runs late at exit. Since #197425, destroying it calls `hipfftDestroy` on every plan still in the cache.

rocFFT tracks device memory in a singleton that is a function-local static ([rocm-libraries `gpubuf.h:43-47`](https://github.com/ROCm/rocm-libraries/blob/c283a2bf239eef5d1fe06ddc4b9402634ce99c5c/projects/rocfft/shared/gpubuf.h#L43-L47)), added in [rocm-libraries `184a43da`](https://github.com/ROCm/rocm-libraries/commit/184a43daa41c):

```cpp
static device_memory_accountant& singleton()
{
    static device_memory_accountant instance;
    return instance;
}
```

A function-local static is constructed, and registers its destructor, the first time the function runs. That is the first FFT plan creation, well after `libtorch_hip.so` loaded. Exit handlers run in reverse order of registration, so the accountant is destroyed before `plan_caches`. hipFFT's own `rocfft_initializer` static, which calls `rocfft_cleanup()` from its destructor ([`hipfft.cpp:429-441`](https://github.com/ROCm/rocm-libraries/blob/c283a2bf239eef5d1fe06ddc4b9402634ce99c5c/projects/hipfft/library/src/amd_detail/hipfft.cpp#L429-L441)), is created at the same point and is also gone first. The recorded exit-handler order for a process with 4 cached plans was:

| Exit handler | Destroys |
|---|---|
| #8-28 | rocFFT and hipFFT statics created at first use, including `device_memory_accountant` |
| about #5091 | `plan_caches`, which calls `hipfftDestroy` for each cached plan |

Destroying a plan frees its device buffers. `gpubuf_t::free()` reports every free to the accountant with no check that it still exists ([`gpubuf.h:278-287`](https://github.com/ROCm/rocm-libraries/blob/c283a2bf239eef5d1fe06ddc4b9402634ce99c5c/projects/rocfft/shared/gpubuf.h#L278-L287)):

```cpp
(void)hipFree(buf);
device_memory_accountant::singleton().release_used_bytes(bsize, device);
```

`release_used_bytes` indexes the accountant's per-device vector and writes the new count ([`gpubuf.h:66-77`](https://github.com/ROCm/rocm-libraries/blob/c283a2bf239eef5d1fe06ddc4b9402634ce99c5c/projects/rocfft/shared/gpubuf.h#L66-L77)):

```cpp
if(dev_id < 0 || static_cast<size_t>(dev_id) >= num_devices())
    throw std::invalid_argument(...);
auto& dev_account = mem_account_on_device[dev_id];
dev_account.used_bytes -= std::min(dev_account.used_bytes, allocation_size);
```

The accountant's destructor already returned the vector's storage to malloc, but left `begin` and `end` in the dead object. `num_devices()` still returns the old size, so the bounds check passes, and the `-=` writes into freed heap memory. The full call chain is `~CuFFTHandle` → `hipfftDestroy` → `rocfft_plan_destroy` → `~ExecPlan` → `~TreeNode` → `gpubuf_t::free` → `release_used_bytes`.

A hardware watchpoint on the accountant's freed buffer during the exit of a real `test_ops_gradients` shard recorded 106 `hipfftDestroy` calls making 479 writes to the freed address. If malloc has not reused that memory, the writes land in unused space and the process exits cleanly. If it has, they overwrite a live object or malloc's free-list pointers. A later allocation during exit then fails glibc's checks (`corrupted double-linked list (not small)`, `malloc(): largebin double linked list corrupted (nextsize)`, `malloc.c:4196 (_int_malloc): assertion failed: chunk_main_arena (fwd)`), or the process segfaults. Whether the memory was reused depends on heap layout, so the crash is intermittent.

#197425 relied on rocFFT fixes that make its `Repo` singleton safe after destruction, such as [rocFFT `c2ed8163`](https://github.com/ROCm/rocFFT/commit/c2ed8163725e83f82da37832b4661b2a4bd789f3). The accountant was added later with the same lifetime pattern and no such protection. cuFFT does not have this singleton, so CUDA keeps freeing plans at exit.

## Impact

Since #197425 landed, about 3% of MI350 `default` CI jobs crash at exit after all tests pass, and each crash makes `run_test.py` rerun the whole shard twice. That cost at least 58 hours of MI350 and MI300 runner time between 2026-09-18 and 2026-09-24, and the crash was misreported under at least 10 test names that never failed.
