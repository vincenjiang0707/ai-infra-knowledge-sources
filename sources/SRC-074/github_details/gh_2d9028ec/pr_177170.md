## 正文

Stack from [ghstack](https://github.com/ezyang/ghstack/tree/0.14.0) (oldest at bottom):
* __->__ #177170

The fsdp::all_gather_copy_in op mutates `all_gather_output` (via
_foreach_copy_ into views of it) and returns two tensors that alias it,
but the schema declared no mutation or aliasing. This could lead to
silent incorrectness under torch.compile.

Fix the schema to use `Tensor(a!) all_gather_output` and
`-> (Tensor(a), Tensor(a))`, and remove the explicit skip for this op
in the alias annotation checker since `_schema_allows_aliasing` now
handles it.

Pull Request resolved: https://github.com/pytorch/pytorch/issues/170986

cc @ezyang @gchanan

### Diagnosis

**The revert is legitimate.** The test failure is a direct consequence of the schema change in this PR.

### Root Cause

The failing test is `test_all_gather_extensions_monkey_patch` with error:
```
RuntimeError: The size of tensor a (64) must match the size of tensor b (512) at non-singleton dimension 0
```
at `multi_threaded_pg.py:198` during `dest_tensor.detach().copy_(src_tensor)`.

The problem is with the new schema annotation:

```python
all_gather_copy_in(
    Tensor[] all_gather_inputs,
    Tensor(a!) all_gather_output,     # <-- mutated input
    ...
) -> (Tensor(a!), Tensor(a!))         # <-- both returns aliased to input
```

**PyTorch's functionalization layer replaces `Tensor(a!)` returns with the original input argument itself**, not with the actual return value from the op implementation. This is codified in `torchgen/gen_functionalization_type.py:533-547` (`get_mutable_redispatch_return_names`) — for aliased returns, it uses the **input argument name** directly.

The actual implementation returns:
```python
all_gather_input = all_gather_output.narrow(0, offset, length)  # size = numel_per_rank
return all_gather_input, all_gather_output                       # (narrow view, full tensor)
```

But functionalization sees both returns annotated as `(a!)` and replaces **both** with `all_gather_output` (the full tensor of size `numel_per_rank * world_size = 64 * 8 = 512`). This means the first return — which should be the narrow slice of size 64 — becomes the full tensor of size 512. When this is subsequently passed to `dist.all_gather_into_tensor` as the `input_tensor`, the multi-threaded PG tries to copy a 512-element tensor into a 64-element destination chunk, causing the size mismatch.

Additionally, `aten/src/ATen/FunctionalizeFallbackKernel.cpp:63-79` explicitly rejects custom ops with alias annotations in returns, and auto-functionalization (`torch/_higher_order_ops/auto_functionalize.py:462-468`) also returns `False` for schemas with aliased returns. This means the `(a!)` return annotations are fundamentally incompatible with PyTorch's functionalization infrastructure for custom ops.

### Fix Guidance

The schema needs to correctly represent the aliasing semantics without using `(a!)` on both returns. Options:

1. **Keep mutation annotation on input only, remove alias from returns:**
   ```
   all_gather_copy_in(
       Tensor[] all_gather_inputs,
       Tensor(a!) all_gather_output,
       ...
   ) -> (Tensor, Tensor)
   ```
   This correctly declares the mutation of `all_gather_output` but doesn't promise the returns alias it. The `"fsdp"` namespace skip in `runtime_wrappers.py` would need to be kept to suppress aliasing checker warnings since the returns *do* actually alias the input (they're views of it).

2. **Only annotate the second return (which IS the full input):**
   ```
   ) -> (Tensor, Tensor(a))
   ```
   The first return (the narrow view) gets no alias annotation. However, this still may not work with auto-functionalization.

3. **Restructure the op** to not return aliased tensors — e.g., return only `all_gather_output` and have the caller reconstruct the narrow view, or make it a purely mutating op with `-> ()`.

Option 1 with the namespace skip restored is the safest minimal fix. Option 3 would be the cleanest long-term solution.
