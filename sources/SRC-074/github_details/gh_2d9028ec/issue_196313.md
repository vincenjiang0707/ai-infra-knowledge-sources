# [Issue #196313] [Inductor][NVGEMM] Heuristic config key compares nvMatmulHeuristics per-CTA tile_m with cutlass.operators' pair MMA tile, so 2-CTA kernels are never chosen for dense GEMM

source: https://github.com/pytorch/pytorch/issues/196313
state: closed | updated: 2026-09-24T22:15:23Z
labels: module: performance, triaged, oncall: pt2, module: inductor, matrix multiplication, bot-triaged, release triage, module: nvgemm

## 正文

### 🐛 Describe the bug

When we use `max_autotune_gemm_backends="NVGEMM"` with 2.14, dense BF16 gemm will lose 5-15% perf compare to cuBLAS on Blackwell. This is because `nvMatmulHeuristics` drops the optimal 2-CTA kernels (see below for why).

Cause:
In `torch/_inductor/heuristics/template/nv_universal_gemm.py`, `nvMatmulHeuristics` uses the per-CTA tile size, but `cutlass.operators` API uses 2-CTA using the aggregate MMA tile across CTA pair (i.e different unit of comparisons, getting only half of the size). 

Inductor compares these ints directly and `tile_m=128` reccomendations matches 64 row per CTA, not 128 row per CTA (choosing tile128x instead of tile256x, tile256x would be correct).

The simple method to fix this is:
Divide `tile_m` by 2 for `use_2cta_mma` when building th ekey, and NVGEMM will have cuBLAS parity when using only 10 candidates for autotune on torch 2.14 AND nightly (originally, I found the bug in 2.14).

## Cause
If we look at what the heuristic model returns vs. what cuBLAS actually selects on the hardware:
*   **bf16 512x4096x4096:** Heuristic suggests `cta_tile=(128,128,64)`. cuBLAS uses `128x128...2cta`.
*   **bf16 2048x4096x4096:** Heuristic suggests `cta_tile=(128,256,64)`. cuBLAS uses `128x256...2cta`.

Both describe a 2-SM kernel with 128 rows *per CTA*. In `cutlass.operators`, that exact kernel is named `..._2cta_cluster2x2x1_tile256x128x64`. The kernel derives rows per CTA as `mma_tiler_mn[0] // 2`. 

However, Inductor's key generation logic compares them raw:
```python
def _make_config_key_from_heuristic(cfg):            # nvMatmulHeuristics side: per-CTA tile
    return (cfg.tile_m, cfg.tile_n, cfg.cluster_m, cfg.cluster_n)

def _make_config_key_from_kernel_design(design):     # cutlass.operators side: MMA tile across the pair
    return (design.tile_shape[0], design.tile_shape[1], design.cluster_shape[0], design.cluster_shape[1])
```
Because of this, the `(128, 128, 2, 2)` tuple from the heuristic matches `tile128x128` designs (which are either 1-CTA kernels, or crippled 2-CTA kernels given only 64 rows per CTA). It never matches `tile256x128`. 

And if we test w/ NCU, on the default NVGEMM winners for 512x4096x4096, Nsight Compute shows 32,768 `tcgen05` 1-CTA-scope MMAs and *zero* 2-CTA-scope MMAs. (cuBLAS correctly issues 16,384 2-CTA-scope MMAs, resulting in 22% less L2 traffic)

## Repro
The `repro_keyfix.py` script (attached at the bottom) runs a minimal benchmark of NVGEMM vs cuBLAS. Use the `--fix` flag to patch your code.

```bash
TORCHINDUCTOR_COMPILE_THREADS=1 TORCHINDUCTOR_FORCE_DISABLE_CACHES=1 python repro_keyfix.py
TORCHINDUCTOR_COMPILE_THREADS=1 TORCHINDUCTOR_FORCE_DISABLE_CACHES=1 python repro_keyfix.py --fix
```

## Fix
Normalize the `tile_m` parameter for 2-CTA designs on the `cutlass.operators` side of the key check.

```diff
--- a/torch/_inductor/heuristics/template/nv_universal_gemm.py
+++ b/torch/_inductor/heuristics/template/nv_universal_gemm.py
@@ def _make_config_key_from_kernel_design(design) -> ConfigKey | None:
     if (
         hasattr(design, "tile_shape")
         and len(design.tile_shape) >= 2
         and hasattr(design, "cluster_shape")
         and len(design.cluster_shape) >= 2
     ):
+        # nvMatmulHeuristics reports per-CTA tiles; cutlass.operators 2cta designs
+        # report the MMA tile across the CTA pair (tile_shape[0] == 2 * rows per CTA).
+        tile_m = design.tile_shape[0]
+        if getattr(design, "use_2cta_mma", False):
+            tile_m //= 2
         return (
-            design.tile_shape[0],
+            tile_m,
             design.tile_shape[1],
             design.cluster_shape[0],
             design.cluster_shape[1],
         )
```

```python
"""
Minimal repro: Inductor NVGEMM heuristic key compares nvMatmulHeuristics per-CTA tiles 
with cutlass.operators pair-aggregate MMA tiles, so 2-CTA designs never match.
usage: python repro_keyfix.py [--fix]
"""
import os, sys, subprocess, importlib.metadata as md, torch, torch._inductor.config as config
from torch.profiler import profile, ProfilerActivity

FIX = "--fix" in sys.argv

def env():
    print(f"python {sys.version.split()[0]} | torch {torch.__version__} | cuda {torch.version.cuda} | triton {md.version('triton')}")
    for p in ("nvidia-cutlass-dsl", "nvidia-cutlass-operators", "nvidia-matmul-heuristics", "cuda-bindings"):
        try: print(f"  {p} {md.version(p)}")
        except Exception: print(f"  {p} MISSING")
    p = torch.cuda.get_device_properties(0)
    drv = subprocess.run(["nvidia-smi", "--query-gpu=driver_version", "--format=csv,noheader"], capture_output=True, text=True).stdout.strip().splitlines()[0]
    print(f"  GPU {p.name} sm_{p.major}{p.minor} SMs={p.multi_processor_count} driver {drv}")
    print(f"  nvgemm_max_profiling_configs={config.nvgemm_max_profiling_configs} supplement={config.nvgemm_supplement_configs} swap_ab={config.nvgemm_swap_ab} COMPILE_THREADS={os.environ.get('TORCHINDUCTOR_COMPILE_THREADS')}")

def kernel_time_us(fn, *args, iters=20):
    fn(*args); torch.cuda.synchronize()
    with profile(activities=[ProfilerActivity.CUDA]) as prof:
        for _ in range(iters): fn(*args)
        torch.cuda.synchronize()
    ev = [e for e in prof.key_averages() if "CUDA" in str(getattr(e, "device_type", "")) and e.self_device_time_total > 0]
    return sum(e.self_device_time_total for e in ev) / iters, [e.key[:60] for e in ev]

if FIX:
    from torch._inductor.heuristics.template import nv_universal_gemm as H
    _orig = H._make_config_key_from_kernel_design
    def _key(design):
        k = _orig(design)
        # nvMatmulHeuristics reports per-CTA tiles; cutlass.operators 2cta designs report the MMA tile across the CTA pair
        if k is not None and getattr(design, "use_2cta_mma", False): 
            k = (k[0] // 2, k[1], k[2], k[3])
        return k
    H._make_config_key_from_kernel_design = _key

env()
print(f"key fix: {'ON' if FIX else 'OFF'}\n")

config.max_autotune_gemm_backends = "NVGEMM"
config.autotune_fallback_to_aten = False

for (M, N, K) in [(512, 4096, 4096), (2048, 4096, 4096)]:
    A = torch.randn(M, K, device="cuda", dtype=torch.bfloat16)
    B = torch.randn(K, N, device="cuda", dtype=torch.bfloat16)
    
    torch._dynamo.reset()
    f = torch.compile(lambda a, b: a @ b, mode="max-autotune-no-cudagraphs")
    
    t, ks = kernel_time_us(f, A, B)
    ok = torch.allclose(f(A, B).float(), (A.float() @ B.float()), rtol=2e-2, atol=2.0)
    tc, _ = kernel_time_us(lambda a, b: a @ b, A, B)
    
    print(f"bf16 {M}x{N}x{K}: NVGEMM kernel {t:6.1f} us  (cuBLAS eager {tc:6.1f} us)  correct={ok}  kernel={ks[0] if ks else '?'}")
```

### vincentzed · 2026-09-09

Ok, for blockscaled kernel, this cannot be used as-is because it breaks them.

Cutlass operator block-scaled generator hardcodes `use_2cta_mma=True` on every design ( even the 1-CTA ones) If we halve tile_m based on that label, valid 1-CTA block-scaled kernels get their keys messed up (e.g., the case of tile_m=128 becomes 64), match nothing, and drop wholly.

Yet this patch could fix both case.
```python
pair = getattr(getattr(kernel, "impl", None), "use_2cta_instrs", None)
if pair is None:
    pair = bool(getattr(design, "use_2cta_mma", False))
tile_m = tile_shape[0] // 2 if pair else tile_shape[0]
```

Under this key, a model pick maps to both the 1-CTA and the pair kernel of that per-CTA footprint. They get ranked by the model's estimate, and the autotuner separates them. 

Measurement:
| shape | default | #196313 diff | twins | key only | key + rule |
| :--- | :--- | :--- | :--- | :--- | :--- |
