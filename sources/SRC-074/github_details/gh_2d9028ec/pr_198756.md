Part of the set of changes the two-phase precompile workflow needs at pytorch tip, on top of the open precompile stack that ends in #198558. In that workflow, one GPU captures the model against a fake process group of the serving world size, and then every rank replays the saved artifact with recompilation refused. The set was found by running the workflow end to end at tip on a large production FSDP2 recommendation model. Each change here was the first blocker at its step: the run got past that step once the change was applied. With the full set, the replay completed on all 16 ranks for 100 batches with no refusals.

**What.** `_get_code_source` records a code object's location by walking its `co_qualname` from the module with `getattr`. On a class, `getattr` returns the `property` or `functools.cached_property` descriptor, not the function inside it. So a code object that is a property getter, or a function nested in one (`C.prop.<locals>.inner`), could not be resolved. Packaging then aborted with:

    PackageError: Cannot resolve a fully qualified name for <code object ...>. Lookup scope: <property object ...>

This change:
- stops the qualname walk at a descriptor;
- descends through `fget`, `fset`, `fdel` or `func`, emitting a path the loader replays with plain `getattr` (for example `.fget`);
- lets the class search in `_find_code_source` look inside descriptors too.

**Why it's needed.** The model compiles a frame whose code is defined under a `@property`. At tip, capture failed at package save with exactly the error above. With this change, capture got past package save.
