## 正文

Stack from [ghstack](https://github.com/ezyang/ghstack/tree/0.15.0) (oldest at bottom):
* #198706
* #198704
* #198703
* __->__ #198700
* #198705

`pull`, `trunk`, `lint` and `docs-build` gate viable/strict, so they go first.
Their test matrices still name EC2 runners and `_linux-build.yml` translates
them at runtime through `arc.yaml`, which hides which pod a job lands on.

Each label becomes the pod it already resolved to. A label the workflow
already prefixes keeps the determinator expression, so fleet routing is
untouched; a label written raw gets the literal Meta pod, which is what the
mapper produced for it.

`map_ec2_to_arc.py` exits on a label it cannot find in `arc.yaml`, and an ARC
name is never a key there, so it now passes those through instead. That keeps
it translating anything not yet converted. A typo still fails rather than
being mistaken for a direct name, which the tests cover.

No job changes runner.
