## Issue

Fixes #198559

## Summary

`merge_select_cat_aten` (only runs with `select_cat_aten_pass` enabled) replaces `cat([select(x, d, 0), ..., select(x, d, n-1)], d)` with a view of `x`, but it builds the select list from `x.users` instead of the cat's inputs. So a cat input that isn't a select crashes (the case in the issue), selects of two tensors or indices like `[-1, 0]` give wrong results, and a non-contiguous `x` crashes in `view`. The view also aliases `x`, so mutating one shows up in the other. This checks that every cat input is `select(x, cat_dim, i)` with `i` covering `0..n-1` in order (negative dims and indices normalized), skips the rewrite when the dims can't be viewed together or the cat output isn't contiguous, and replaces the cat with `clone(view(x))`. The clone adds a copy that I haven't benchmarked. If you'd rather keep the view and only rewrite when it's known to be safe (x isn't mutated and the result isn't a graph output), I can switch to that.

Tests: three CPU tests (cases that must not merge, a negative dim/index case that should merge, and the aliasing cases). They fail before and pass after. On a T4 the file goes from 3 failed / 5 passed to 8 passed, including the existing GPU tests.
