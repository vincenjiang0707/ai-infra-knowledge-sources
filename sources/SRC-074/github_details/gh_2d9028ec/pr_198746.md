A warm-cache compile never lowers a graph, yet it imported ~200 modules of
the lowering/scheduling stack (lowering, select_algorithm, codegen.triton/cpp,
graph, fx_passes, kernel/*), about 280ms per process. The entry points were:

init_backend_registration() imported every scheduling class. They are now
registered as lazy constructors that import the class on first use; only the
wrapper classes are still imported eagerly.

The generated wrapper header imported select_algorithm for extern_kernels
and codegen.memory_planning for align. KernelNamespace moves to a small
torch._inductor.extern_kernels module (re-exported from select_algorithm);
attribute lookups import select_algorithm on demand, since extern kernels
register themselves as a side effect of importing it. align comes from
torch._inductor.utils directly.

compile_fx.py imported GraphLowering, the pre/joint/post-grad passes and
distributed_autotune at module level; they are now imported at the use sites.

Serializing the config for the cache key imported choices.py just to find no
registered InductorChoices, and cache_hit_post_compile imported graph.py to
read the save_output_code test hook. Both now skip the import when the module
isn't loaded yet, because in that case nothing can have been registered/set.

Test Plan:

torchtitan PR53 regional-compile benchmark, warm cache, 6 runs each on H100
(median first-call compile time / process wall): 0.85s / 3.06s -> 0.72s /
2.92s. Cold is unchanged (~6.7s). An import audit hook confirms none of the
modules above load on a warm run.
