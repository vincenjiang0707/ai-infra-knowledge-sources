# [PR #198743] [MPS] Don't request grads in test_output_match

## 正文

Stack from [ghstack](https://github.com/ezyang/ghstack/tree/0.18.0) (oldest at bottom):
* #198753
* __->__ #198743
* #196924

`TestConsistency.test_output_match` only compares forward outputs against CPU, gradients are covered by `test_output_grad_match`, yet it always asked `sample_inputs` for `requires_grad=True` on floating dtypes. That hid every sample an OpInfo generates only under `if not requires_grad:`, e.g. the NaN-propagation samples of `masked.norm`, so the forward-only MPS check never saw them.

Dropping the argument exposes those samples. `masked.norm` with `ord=±inf` would have failed on NaN inputs before #198611 moved `vector_norm` to the shared, NaN-propagating Max/Min reductions; it passes now, so this change guards against that regression. The one other change is that complex `to_sparse` now passes: its entry in `UNSUPPORTED_COMPLEX_OPS` only reflected that `_to_sparse` has no complex autograd on any device, so it is removed.
