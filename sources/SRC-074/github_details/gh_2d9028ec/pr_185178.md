# [PR #185178] [FSDP][AC] Bypass SAC tracking for all-gather internals

## 正文

Fixes a selective activation checkpointing replay mismatch seen in TorchTitan DeepSeek V3 with FSDP+EP.

TorchTitan tracking issue: https://github.com/pytorch/torchtitan/issues/3427

During non-reentrant checkpoint recompute, SAC installs a `TorchDispatchMode` to track ops for replay. FSDP pre-forward hooks may run during that recompute and unshard parameters via all-gather. The all-gather implementation performs communication/materialization internals such as `aten.split_with_sizes.default` and `aten._foreach_copy_.default`; those are not user/model-region ops and may differ between the original forward and recompute.

This introduces an internal SAC bypass context for runtime plumbing regions. SAC caching/replay modes execute ops directly under that bypass without policy calls, storage updates/lookups, or counter increments. FSDP wraps all-gather and copy-out internals in that bypass while preserving the outer FSDP profiler ranges. This keeps unrelated ambient `TorchDispatchMode`s able to observe FSDP internals, unlike a blanket `no_dispatch()` guard.

Profiler `record_function` enter/exit ops are also ignored by SAC because annotations may legitimately differ between forward and recompute and do not produce model values.

The updated regression coverage checks that ambient dispatch modes can still see FSDP all-gather internals, while SAC does not replay-index them. Targeted SAC/FSDP tests and the original TorchTitan repro passed in the H100 validation container.
