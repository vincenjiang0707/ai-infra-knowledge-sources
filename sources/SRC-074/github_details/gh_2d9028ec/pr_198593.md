# [PR #198593] [MPS] Support range factories with more than 2^32 elements

## 正文

Fixes https://github.com/pytorch/pytorch/issues/198473

Since the port of arange/linspace/logspace to native Metal kernels (#188921), each op issued a single 1D dispatch of `numel` threads. Kernels receive a 32-bit `thread_position_in_grid`, and Metal silently truncates a grid wider than 2^32 to its low 32 bits, so for `numel > 2^32` only the first `numel mod 2^32` elements were written and the rest stayed zero (the previous commit turns that into an error).

Every range-factory kernel (contiguous and strided `arange`, `linspace`, integral `linspace`, `logspace`) now adds a 64-bit `base` to its thread index, and the host dispatches in chunks of at most 2^31 threads via `dispatch_1d_chunks`, passing each chunk's first element index. Tensors with at most 2^31 elements still take a single dispatch. The strided kernels also took `steps` as a 32-bit `uint`; they now take it as 64-bit. Chunking was chosen over a 2D grid because the kernels compute a linear element index anyway, so a base offset is the smallest change and keeps the per-thread math identical.
