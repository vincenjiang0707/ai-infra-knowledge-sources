# [Issue #198676] [inductor] weight_norm(..., name="bias") returns wrong values and non-finite gradients

source: https://github.com/pytorch/pytorch/issues/198676
state: open | updated: 2026-09-25T21:02:49Z
labels: triage review, oncall: pt2, module: decompositions, bot-triaged

## 正文

### 🐛 Describe the bug

Applying `torch.nn.utils.parametrizations.weight_norm` to a 1-D parameter silently changes both
the forward result and gradients under `torch.compile` with the Inductor backend.

```python
import torch
from torch import nn
from torch.nn.utils.parametrizations import weight_norm

torch.set_default_dtype(torch.float64)

def make_model():
    torch.manual_seed(0)
    return weight_norm(nn.Linear(4, 3), name="bias")

x = torch.zeros(2, 4)
eager_model = make_model()
compiled_model = make_model()

eager = eager_model(x)
compiled = torch.compile(compiled_model)(x)

eager.sum().backward()
compiled.sum().backward()

print("eager:", eager[0])
print("compiled:", compiled[0])

for name, parameter in compiled_model.named_parameters():
    if "bias" in name:
        print(name, parameter.grad)
```

Output:

```text
eager:    tensor([-0.1447,  0.1219, -0.0182])
compiled: tensor([-0.1102,  0.0782, -0.0017])

parametrizations.bias.original0
tensor([-1.5227,     inf, -5.9002e+307])

parametrizations.bias.original1
tensor([0.6401,    nan,   -inf])
```

The problem is in the Inductor decomposition of `aten._weight_norm_interface`:

```python
keep_dim = tuple(i for i in range(len(v.shape)) if i != dim)
norm = v.norm(2, keep_dim, keepdim=True, dtype=norm_dtype)
```

For a 1-D parameter with `dim=0`, `keep_dim` is empty. `v.norm(..., dim=())` reduces over all
dimensions, so the compiled path computes `v * g / ||v||`. The eager ATen implementation uses
`norm_except_dim` semantics and computes `v * g / abs(v)` instead.

The direct reproducer also affects float32 and bfloat16. `backend="eager"` and
`backend="aot_eager"` match eager, and an explicit expression using `torch.norm_except_dim`
compiles correctly.

This is different from #121304, which reported a missing `dim` argument and raised an exception.
Here compilation succeeds and silently returns incorrect values and non-finite training gradients.
