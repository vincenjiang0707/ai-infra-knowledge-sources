Attribute access on a `SkipFunctionVariable` fell through to a deferred
`GetAttrVariable`. It does reach `object_generic_getattr` -- the base
`python_type()` derives the type from `as_python_constant()`, which this class
implements -- but it lacks the two per-VT hooks that walk delegates to: step 3
`lookup_instance_dict`, so an attribute living in the callable's own `__dict__`
was invisible, and step 6 `call_getattr_fallback`, so a genuine miss fell
through `const_getattr` to `NotImplementedError` and `generic_getattr` turned it
into a deferred access. A deferred access is materialized wherever the value is
later reconstructed, and after a graph break that is no longer inside the `try`
that guarded the original access, so the `AttributeError` escapes into user
code.

The shape comes straight from `inspect._signature_from_callable`, which probes
`obj.__signature__` inside a `try/except AttributeError`. Tracing that with a
skipped callable produced a `GetAttrVariable` whose type the following
`isinstance(sig, Signature)` could not determine; the resulting graph break
reconstructed the probe outside the handler:

    obj = torch.fx.Node.prepend
    def fn(t):
        torch._dynamo.graph_break()
        try:
            s = obj.__signature__
        except AttributeError:
            s = "caught"
        return t + 1, s

    eager    -> "caught"
    compiled -> AttributeError: 'function' object has no attribute '__signature__'

Implement the two hooks rather than overriding `tp_getattro_impl`. Overriding
the slot wholesale would mean re-implementing the MRO walk and
`_resolve_descriptor_get` that already resolve `__qualname__`, `__self__` and
`__text_signature__` correctly for skipped callables; the two narrow hooks are
exactly what the generic walk delegates to, and they are the same pair
`BaseUserFunctionVariable` uses. `lookup_instance_dict` is the shared choke
point for every entry path (`LOAD_ATTR`, `getattr`, 3-arg `getattr`, `hasattr`),
so one override covers them all and `call_getattr_fallback` cannot report
absence for an attribute the instance dict holds.

`SkipFunctionVariable` wraps any `disallow_in_graph`'d callable, not just plain
functions -- instances, classes, objects whose type defines `__getattr__`. For
those, `object_generic_getattr` does not model the lookup, and concluding
"absent" from a step-7 miss would turn a valid attribute into an
`AttributeError`; a disallowed class is the clearest case. Both hooks therefore
gate on the new `type_uses_generic_getattr` predicate and decline otherwise,
which also means no user `__getattr__` or property runs during tracing.

Absence is a compile-time answer baked into the trace, so it needs a guard:
without one, setting the attribute afterwards reuses the "missing" branch and
the compiled result silently diverges from eager. `create_with_source` installs
only `CLOSURE_MATCH`/`BUILTIN_MATCH`, which guard `__code__` and not the
callable's `__dict__`, so `call_getattr_fallback` installs a `HASATTR` guard
before raising. With no source there is nothing to guard on, so it graph-breaks
rather than baking in an unguarded answer.

This is not nested-graph-break-specific -- the repro above fails with
`nested_graph_breaks=False` too. NGB only widens symbolic coverage enough to
reach it, which is how it surfaced: `test_fx.py -k test_function_back_compat`
fails under `PYTORCH_TEST_WITH_DYNAMO=1` once #186100 turns NGB on, because 66
of the 77 `compatibility`-marked objects it inspects hit this path.

`-k skipped` goes from 7 red to 16 green; reverting only the product change
returns it to 1 failure and 6 errors. The suite covers a plain function, a
builtin with no `__dict__` at all, a callable instance, a callable class (whose
`type.__getattribute__` must make both hooks decline -- forcing the predicate
true turns a valid class attribute into an `AttributeError`), a type defining
`__getattr__`, the absent-then-present recompile, and a traced `setattr`
winning over the hooks. The last two commands are the generated mirrors, which
rebind copied `@staticmethod` test helpers as instance methods and so must be
run whenever these files change.
