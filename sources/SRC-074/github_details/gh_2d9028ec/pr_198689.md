# [PR #198689] MPS: also gate int64 scatter_reduce and the large-tensor tests on M1

## 正文

Ten MPS tests fail consistently on the macOS 15 **M1** runners that
pytorch-gha-infra#1535 created, and pass on macOS 15 **M2 Pro**. Each already had
a `MACOS_VERSION` gate standing in for a hardware property, and that held only
while macOS 14 meant M1 and macOS 15 meant M2 Pro.

- **`test_large_bmm` x2, `grid_sample_large_index` 2d/3d** — gate reads
  `"macOS 14 runners have lower memory"`. `mac2.metal` M1 is 16 GB,
  `mac2-m2pro.metal` is 32 GB.
- **int64 `scatter_reduce` amin/amax** (6 OpInfo/consistency tests) —
  `dtypesIfMPS` enabled int64 on macOS 15+, proxying for the `ulong`
  atomic_max/min intrinsic. Apple7 (M1) does not have it at any macOS version.

Each gate gains `or IS_APPLE_M1`; nothing else changes. M2 Pro behaviour is
untouched, so no currently-green job moves.

Notes:
- `test_large_bmm` never passed on M1 — it was `xfailIf(MACOS_VERSION < 15.0)`,
  so it failed-as-expected on Sonoma and read green.
- Deliberately minimal: this keeps trunk green so the us-east-1 Sonoma → Sequoia
  migration can continue. The underlying M1 gaps are unchanged and still worth
  fixing.
