# [Issue #198539] [inductor] With freezing on CPU, x.copy_(self.conv(x)) leaves x unchanged

source: https://github.com/pytorch/pytorch/issues/198539
state: closed | updated: 2026-09-24T20:33:11Z
labels: oncall: cpu inductor, bot-triaged

## 正文

### 🐛 Describe the bug

```python
import torch


class M(torch.nn.Module):
    def __init__(self):
        super().__init__()
        self.conv = torch.nn.Conv2d(4, 4, 3, padding=1, bias=False)

    def forward(self, x):
        x.copy_(self.conv(x))
        return x


torch.manual_seed(0)
m = M().eval()
x = torch.rand(4, 4, 6, 6)
with torch.no_grad(), torch._inductor.config.patch(freezing=True):
    x_eager, x_comp = x.clone(), x.clone()
    m(x_eager)
    torch.compile(m)(x_comp)
print((x_eager - x_comp).abs().max().item(), (x_comp - x).abs().max().item())
```

```
1.6600873470306396 0.0
```

The compiled module doesn't update `x` at all, and returns it. `x[1:] = self.conv(x)[:-1]` does the same. Right without freezing, and on CUDA with freezing. 2.9.1, 2.14.0 and the 21 Sep nightly.

The post-grad graph is `_convolution_pointwise(arg1_1, ...)` then `copy_(arg1_1, ...)`; the output code copies `arg1_1` into a channels-last `buf0`, runs the convolution on it, and then writes the result into a buffer that reuses `buf0`, never into `arg1_1`. I think it's this block of `GraphLowering.run_node`: when a node has several users and one of them is an mkldnn convolution taking it as input, the node is rebound to `require_stride_order(result, channels_last)`. For a graph input, which has a fixed layout, that's a copy, and every other user, the `copy_` included, then gets the copy instead of the input. Skipping the rebinding for placeholders (the convolution's own lowering makes the copy it needs) makes both cases right. I have it with a test and can open a PR.

## 评论 (3)

### JingHao-Leon · 2026-09-24

Boundary datapoint: this does **not** reproduce on **torch 2.14.0, CPU on Apple Silicon arm64 (macOS 26.5)** — same script verbatim: eager vs compiled max diff `1.19e-07` (float noise, assert_close passes), and the compiled module does update `x`.

That's consistent with the mkldnn-rebinding root cause: on arm64 CPU the conv doesn't route through mkldnn/channels-last the same way, so the input placeholder never gets rebound to the strided copy. Worth noting for triage since it means the freeze-time rebinding fix can be validated on x86 without worrying about arm64 regressions.
