# [Issue #128791] CUDA error in torch.cdist with compute_mode=donot_use_mm_for_euclid_dist

## 正文

### 🐛 Describe the bug

I observe the following crash in `torch.cdist` under certain conditions:
```Shell
Traceback (most recent call last):
  File "/workspaces/models/notebooks/cdist.py", line 13, in <module>
    torch.cdist(
  File "/opt/venv/lib/python3.11/site-packages/torch/functional.py", line 1339, in cdist
    return _VF.cdist(x1, x2, p, 2)  # type: ignore[attr-defined]
           ^^^^^^^^^^^^^^^^^^^^^^^
RuntimeError: CUDA error: invalid configuration argument
CUDA kernel errors might be asynchronously reported at some other API call, so the stacktrace below might be incorrect.
For debugging consider passing CUDA_LAUNCH_BLOCKING=1.
Compile with `TORCH_USE_CUDA_DSA` to enable device-side assertions.
```
I can trigger the crash with:
```python
import torch

a = torch.rand(32, 8192, 3).cuda()
torch.cdist(
    x1=a,
    x2=a,
    compute_mode="donot_use_mm_for_euclid_dist",
    p=2.0,
)
```
However, the crash does not occur when I reduce the size of the second dimension from `8192` (`2^13`) to `8191`:
``` Python
import torch

a = torch.rand(32, 8191, 3).cuda()
torch.cdist(
    x1=a,
    x2=a,
    compute_mode="donot_use_mm_for_euclid_dist",
    p=2.0,
)
```
The crash also does not occur when the size of the second dimension is `8192`, but I use the default `compute_mode`:
``` Python
import torch

a = torch.rand(32, 8192, 3).cuda()
torch.cdist(
    x1=a,
    x2=a,
    p=2.0,
)
```
The [docs](https://pytorch.org/docs/stable/generated/torch.cdist.html) suggest that `cdist` will fall back to using matrix multiplication if the second dim is larger than `25`, which explains the different behaviour.

However, I'm keen to avoid using matrix multiplication, since I see a significant performance improvement, and matrix multiplication is known to suffer from [numerical instabilities](https://github.com/pytorch/pytorch/issues/42479):
```
donot_use_mm_for_euclid_dist:   0.0116 seconds
use_mm_for_euclid_dist_if_necessary:  16.9030 seconds
```

From what I can see, `cdist` is implemented [here](https://github.com/pytorch/pytorch/blob/ab13980424fea6817f18cc83dac4729743348de2/aten/src/ATen/native/Distance.cpp#L81-L148), and the kernel is implemented [here](https://github.com/pytorch/pytorch/blob/a61939467a5669288ae89da781bce9645ddce1ae/aten/src/ATen/native/cuda/DistanceKernel.cu#L362)

### LiRunGuo · 2026-09-24

Re-checked this on the 2026-09-23 nightly on an H200: the forward repro above now passes (fixed by #188006), but the backward still crashes at the same scale. I have a small fix for the backward kernel and will open a PR.

Claude Code helped me narrow it down; its summary, which I verified:

> `cdist_backward_kernel_cuda_impl` in `aten/src/ATen/native/cuda/DistanceKernel.cu` still uses `int` for the output index `y`, for `l`/`k`, and for the per-batch buffer offset `l_size = r1 * r2 * m`, while the forward kernel uses `int64_t` for the same quantities. On `2.15.0.dev20260923+cu130` with p=1:
>
> ```
> (b, r, m) = (2, 8191, 32)  OK
> (b, r, m) = (2, 8192, 32)  CUDA error: an illegal memory access   # r*r*m = 2^31 -> l_size overflows
> (b, r, m) = (31, 8192, 1)  OK
> (b, r, m) = (32, 8192, 1)  CUDA error: an illegal memory access   # dist.numel() = 2^31 -> y overflows
> ```
