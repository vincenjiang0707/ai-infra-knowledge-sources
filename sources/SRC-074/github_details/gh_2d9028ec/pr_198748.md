# [PR #198748] [library] Don't scan sys.modules when registering ops

## 正文

Stack from [ghstack](https://github.com/ezyang/ghstack/tree/0.15.0) (oldest at bottom):
* #198752
* #198751
* #198750
* #198755
* __->__ #198748
* #198747
* #198746
* #198745

Importing Dynamo and Inductor registers dozens of ops through
`Library.impl`/`register_fake`, and each registration did work proportional
to the number of loaded modules, while that number keeps growing during the
import.

`torch._library.utils.get_source` used `inspect.getframeinfo`, which reads
the source file for context lines and scans `sys.modules`; it now reads
`co_filename`/`f_lineno` off the frame, which gives the same string.
`Library._register_fake` resolved the caller's module with
`inspect.getmodule(frame)`, which rescans sys.modules whenever it has grown;
it now takes the module from the frame's `__name__` global, and falls back to
inspect.getmodule when that module's `__file__` doesn't match the frame's
code (e.g. `__main__` or exec'd code).

Test Plan:

~50ms less over the 34 register_fake calls made while importing Dynamo and
Inductor.

```
python test/test_custom_ops.py
python test/test_python_dispatch.py
```

All pass except two failures in test_python_dispatch that are unrelated to
this change (an OMP kmp_affinity abort in a DataLoader worker, and lstsq
without LAPACK in this build).
