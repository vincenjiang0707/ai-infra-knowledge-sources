## Summary

This PR is the first staged step toward a first-class embedding serving/runtime path in MLC LLM.

It introduces an explicit embedding metadata abstraction so embedding models are described by metadata/config traits instead of being identified implicitly from exported function names alone.

This PR is scoped to metadata propagation only. It does not change the `/v1/embeddings` API contract, does not change the normal chat serving path, and does not yet introduce a dedicated embedding runtime boundary.

Part of #3451

## What this PR does

- adds task-level metadata to the model registry for embedding models
- adds embedding-specific metadata traits to model definitions
- propagates embedding metadata into compiled model metadata
- propagates embedding metadata into `mlc-chat-config.json`
- extends C++ metadata parsing to understand the new embedding metadata fields
- updates the Python embedding runtime to prefer metadata-driven model classification, while keeping the old function-name-based detection as fallback for older compiled artifacts
- documents the API-level renormalization behavior for `dimensions` truncation in `/v1/embeddings`
- updates embedding engine/server tests to align with the current embedding runtime behavior
- fixes the embedding server test fixture import path so endpoint tests launch correctly
- makes the encoder truncation test robust across encoder models with different `prefill_chunk_size` values

## Embedding metadata introduced

The metadata added in this PR makes the following traits explicit for embedding models:

- model task
- embedding model type (`encoder` or `decoder`)
- pooling strategy
- normalize behavior

This is intended to establish a stable metadata contract for later staged work.

## Scope and non-goals

This PR intentionally does not:

- change the `/v1/embeddings` API schema
- refactor the main chat serving engine
- introduce backend-specific embedding optimizations
- make encoder/decoder embedding fully first-class at runtime yet

Those will come in later staged PRs.

## Validation
Validated with both Qwen3-Embedding (decoder) and BGE-M3 (encoder), covering both metadata-driven and fallback-compatible paths during development.

- embedding metadata propagates through registry/config/runtime code paths
- metadata-driven runtime classification works with fallback retained for older compiled artifacts
- embedding engine tests pass for both decoder and encoder embedding models
- embedding server endpoint tests pass for both decoder and encoder embedding models
- encoder truncation coverage now validates true truncation behavior instead of relying on a fixed text length assumption

## Follow-up stages

Planned follow-up work after this PR:

1. dedicated TVM-native embedding runtime boundary
2. first-class encoder embedding path
3. first-class decoder-only embedding path
4. backend registry for future hardware-specific optimization
