## 正文

## Summary

Adds vision support for Qwen3.5 VLM (`qwen3_5_vision` model type) and proper conversation templates with correct stop token IDs.

**Vision encoder** (`qwen35_vision.py`): Custom ViT with 2D RoPE and 2×2 spatial patch merging. Conv3D→Conv2D conversion at weight load time (sum over temporal dimension). Position embeddings interpolated from 48×48 to target grid at conversion time. Produces 196 image tokens at 448×448 resolution.

**VLM wrapper** (`qwen35v_model.py`): Wraps the existing `Qwen35LMHeadModel` text backbone with the vision encoder. Uses dual-state passing (`paged_kv_cache` + `rnn_state`) matching the existing hybrid architecture. Image preprocessing: resize→rescale→normalize (SigLIP-style).

**Conversation templates** (`qwen3_5.py`):
The existing qwen3.5 implementation uses the chatml template; this results in the model never thinking and always just outputting <think>\n\n</think> to start responses. Qwen 3.5 models expect <think> as a prefill to prompt thinking.
- `qwen3_5`: Thinking enabled — opens a `<think>` block for the model to reason before responding
- `qwen3_5_nothink`: Thinking suppressed — includes a closed empty `<think>` block
- Both use correct Qwen3.5 stop token IDs (248046/248044) instead of the Qwen2 IDs used by `chatml`

In other frameworks (including WebLLM) there's support for runtime enabling/disabling of thinking by passing an `enable_thinking` flag to the chat completions `extra_body` field - see mlc-ai/web-llm#686 . I'm open to adding this support here rather than using the separate conversation templates.

This PR also includes the fix for `str(target.kind)` → `target.kind.name` (PR #3470), needed for compilation with current TVM. I can rebase and remove that change once that PR is merged.

Stacked on #3429 (Gemma3V, for shared VLM infrastructure). Open to removing that dependency so this could be merged first if there's more demand (it's definitely a better model than Gemma).

## Code Review

This pull request introduces support for Gemma 3 and Qwen 3.5 Vision-Language Models (VLMs). Key additions include the implementation of the SigLIP vision encoder, model definitions for Gemma3V and Qwen35V, and their respective weight loaders. The PR also updates the conversation protocol to handle image tokens for these models, refactors image normalization to support SigLIP, and adds FP16 clamping in Gemma 3 to prevent numerical overflow. Two critical issues were identified: a TypeError in the Qwen 3.5 vision encoder due to an incorrect argument name in op.concat, and a missing reshape operation in the SigLIP attention block before a linear projection.
