# [PR #3461] [Embedding][Serve] Phase 2: TVM-native runtime and single-task serving

## 正文

## Summary

Completes embedding phase 2: embedding serving is now a first-class single-task serve mode, selected automatically from the primary model's `model_task` from the metadata introduced in phase 1.

This PR introduces an `EmbeddingRuntime` abstraction, switches embedding serve to a dedicated TVM-native runtime path, and hard-cuts to the phase-1 metadata contract. Legacy function-name-based fallback is removed.

Phase 2 focuses on establishing the Python-side runtime and serving abstraction boundary. This prepares the embedding stack for follow-up work that will move encoder and decoder embedding paths further down into the lower-level C++ serving/runtime layer for better efficiency and future acceleration work.

In that follow-up work, the current Python-heavy TVM-native embedding runtime is expected to be replaced underneath this abstraction boundary by more specialized **_encoder-first-class_** and _**decoder-first-class**_ implementations.

It also aligns server routing, CLI behavior, `PopenServer`, help text, and REST docs with the new embedding-only serving model.

## Breaking Changes

- `--embedding-model` and `--embedding-model-lib` have been removed from `mlc_llm serve`
- `serve(...)` no longer accepts `embedding_model` / `embedding_model_lib`
- Chat serve no longer exposes `/v1/embeddings`
- Embedding models without `embedding_metadata` are no longer supported for embedding serve
- Legacy compiled embedding artifacts must be regenerated / recompiled with the current toolchain

## What Changed

### Embedding Related

<details>
<summary>Embedding Runtime</summary>

- Introduces an `EmbeddingRuntime` abstraction
- Adds `TVMNativeEmbeddingRuntime` as the default implementation
- Moves the existing TVM-native embedding logic out of `AsyncEmbeddingEngine` into the runtime implementation, including:
  - tokenizer / module / params / metadata initialization
  - encoder vs decoder path dispatch
  - token post-processing
  - KV cache handling
  - batch / sequential prefill
  - pooling
  - normalization
- Shrinks `AsyncEmbeddingEngine` into a thin wrapper that keeps the existing public API:
  - `embed`
  - `async_embed`
  - `terminate`
- Preserves compatibility-facing attributes used by existing tests and callers:
  - `tokenizer`
  - `model_type`
  - `pooling_strategy`
  - `normalize`
  - `embedding_metadata`
  - `_metadata`
  - `_cls_token_id`
  - `_sep_token_id`
- Hard-switches embedding serving to metadata-driven behavior:
  - `model_type`
  - `pooling_strategy`
  - `normalize`
  are now read only from `embedding_metadata`
- Removes legacy fallback behavior:
  - no function-name-based model-type detection
  - no implicit defaults such as `encoder -> cls`, `decoder -> last`, `normalize=True`
- Embedding runtime now fails fast when metadata is missing or incomplete, with a clear error instructing users to regenerate / recompile model artifacts
- Removes the legacy `detect_embedding_model_type()` helper

</details>

<details>
<summary>Server / CLI / PopenServer</summary>

Server:
- Adds primary-model `model_task` detection
- Splits serve bootstrap into:
  - `_serve_chat(...)`
  - `_serve_embedding(...)`
- For embedding primary models:
  - only creates `AsyncEmbeddingEngine`
  - only registers an embedding engine in `ServerContext`
  - does not create `AsyncMLCEngine`
  - does not go through the chat runtime path
- Embedding-only serve now exposes only:
  - `GET /v1/models`
  - `POST /v1/embeddings`
- Embedding-only serve does not register:
  - `/v1/completions`
  - `/v1/chat/completions`
  - `/metrics`
  - `/debug/*`
- Refactors OpenAI entrypoints into composable routers:
  - `models_router`
  - `embeddings_router`
  - `completions_router`
  - `chat_completions_router`
- Adds symmetric combined routers:
  - `chat_app` for chat-only endpoints
  - `embedding_app` for embedding-only endpoints
- Retains `app` as a backward-compatible combined router containing all endpoints
- Fixes the previous issue where chat serve still exposed a dead `/v1/embeddings` endpoint after sidecar embedding support was removed
- Adds consistent startup summaries for both chat and embedding serving paths

CLI:
- Removes:
  - `--embedding-model`
  - `--embedding-model-lib`
- Adds primary-model `model_task` detection
- Enforces embedding-model validation at the CLI layer:
  - `--model-lib` is required for embedding primary models
  - the following chat-only flags are rejected when explicitly passed for embedding primary models:
    - `--additional-models`
    - `--mode`
    - `--speculative-mode`
    - `--prefix-cache-mode`
    - `--prefill-mode`
    - `--overrides`
    - `--enable-tracing`
    - `--enable-debug`
- Keeps chat-model behavior unchanged

PopenServer:
- Detects the primary model task before constructing subprocess argv
- Sends only embedding-valid flags for embedding primary models
- Keeps the existing chat-oriented argv profile for chat primary models
- Fixes the incompatibility between `PopenServer` and the new strict embedding CLI validation
- Restores consistent launch failure behavior for invalid model paths by rewrapping config-detection failures as `RuntimeError(...)`

</details>

## Notes
