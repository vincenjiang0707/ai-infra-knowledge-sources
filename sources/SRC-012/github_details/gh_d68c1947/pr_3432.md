### MagellaX · 2026-02-27

Thanks! Yep, here are the exact commands I used for the Qwen public LoRA sanity check.

Base model:
- Qwen/Qwen2.5-1.5B
LoRA adapter:
- kaitchup/Qwen2.5-1.5B-oasst-guanaco-LoRA-adapter

# 1) Download base + adapter locally
python - <<'PY'
from huggingface_hub import snapshot_download
snapshot_download("Qwen/Qwen2.5-1.5B", local_dir="dist/public_lora/base", local_dir_use_symlinks=False)
snapshot_download("kaitchup/Qwen2.5-1.5B-oasst-guanaco-LoRA-adapter", local_dir="dist/public_lora/adapter", local_dir_use_symlinks=False)
PY

# 2) Convert base weights
python -m mlc_llm convert_weight dist/public_lora/base \
  --quantization q0f16 \
  --device cuda \
  -o dist/public_lora/out_base

# 3) Convert with LoRA merge
python -m mlc_llm convert_weight dist/public_lora/base \
  --quantization q0f16 \
  --device cuda \
  --lora-adapter dist/public_lora/adapter \
  -o dist/public_lora/out_lora

> @MagellaX Thanks. How did you compile and run this lora after that?

After LoRA merge + convert, I used the normal MLC compile/deploy flow on the merged output.

Commands I used:

# 1) Convert with LoRA merge
python -m mlc_llm convert_weight dist/public_lora/base \
  --quantization q0f16 \
  --device cuda \
  --lora-adapter dist/public_lora/adapter \
  -o dist/public_lora/out_lora

# 2) Generate chat config/tokenizer package
python -m mlc_llm gen_config dist/public_lora/base \
  --quantization q0f16 \
  --conv-template qwen2 \
  -o dist/public_lora/out_lora

# 3) Compile model lib
mkdir -p dist/public_lora/libs
python -m mlc_llm compile dist/public_lora/out_lora/mlc-chat-config.json \
  --device cuda \
  -o dist/public_lora/libs/qwen2_5_1_5b_q0f16_cuda.so

# 4) Run chat locally
python -m mlc_llm chat dist/public_lora/out_lora \
  --device cuda \
  --model-lib dist/public_lora/libs/qwen2_5_1_5b_q0f16_cuda.so

(Equivalent server path also works with `mlc_llm serve` + OpenAI-compatible `/v1/chat/completions`.)

## Code Review

This pull request introduces support for merging `LoRA adapters` into a base model before weight conversion. A critical security review identified a potential `Remote Code Execution (RCE)` vulnerability due to the hardcoded use of `trust_remote_code=True` when loading base models with the `transformers` library, which allows arbitrary code execution from the model directory. Additionally, while the implementation is well-structured, a suggestion is to improve the serialization format of the merged model for better safety and performance.
