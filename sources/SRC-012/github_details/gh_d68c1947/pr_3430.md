## 正文

## Summary
Add end to end embedding inference support with /v1/embeddings endpoint, also provide related test files.

### Key Changes:
 - Add `Qwen3EmbeddingModel` subclass with quantize functions to fix embedding model compilation 
 - Add `AsyncEmbeddingEngine` with auto model-type detection, batch prefill optimization, and chunked prefill fallback
 - Add `/v1/embeddings` endpoint similar to openai, has dimension truncation and base64 encoding support
 - Add `bert-bge` model type 
 - Add comprehensive tests (logit match, engine-level, server test)
 
## Changes:

### 1. Model compilation
- `qwen3_model.py`: add new `Qwen3EmbeddingModel` subclass that returns hidden states instead of logits via `prefill_to_last_hidden_states` and batch variants
-  `qwen3_quantization.py`: 4 new `*_embedding` quantize functions（`no_quant_embedding`, `group_quant_embedding`, `ft_quant_embedding`, `block_scale_quant_embedding`) that instantiate `Qwen3EmbeddingModel` 
- `model.py`: register `bert-bge`
- `bert_loader.py`: `hf_prefix` support for BGE weight name mapping

### 2. Inference engine
- `engine.py`: New `AsyncEmbeddingEngine`
  - Auto-detects encoder and decoder from compiled module functions
  - Encoder path: CLS/SEP token injection, truncation, cls/mean/last pooling
  - Decoder path: Last-token pooling with EOS token append(matches HF tokenizer behavior), batch prefill when total tokens fit in prefill_chunk_size, chunked prefill fallback for long sequences
  - L2 normalization, async support via ThreadPoolExecutor
- `engine_utils.py`: `extract_embedding_metadata()`, `load_embedding_params()`, `detect_embedding_model_type()`

### 3. API endpoint
- `openai_api_protocol.py`: `EmbeddingRequest` and `EmbeddingResponse` protocol classes
- `openai_entrypoints.py`: `POST /v1/embeddings` with dimension truncation and base64 encoding format
- `server_context.py`: Embedding engine lifecycle management
- `cli/serve.py` + `interface/serve.py`: `--embedding-model` / `--embedding-model-lib` CLI arguments

## Notes

### 1. EOS Token Append for Decoder Models

MLC tokenizer does not add special tokens by default, but HF `sentence-transformers` does. Without appending EOS, last-token pooling extracts the wrong hidden state. After fix, cross-backend cosine similarity > 0.99.

**Before (without EOS):**

| | MLC-LLM | HuggingFace | Ollama |
|---|---|---|---|
| **MLC-LLM** | 1.0000 | 0.6663 | 0.6644 |
| **HuggingFace** | 0.6663 | 1.0000 | 0.9996 |
| **Ollama** | 0.6644 | 0.9996 | 1.0000 |

**After (with EOS):**

| | MLC-LLM | HuggingFace | Ollama |
|---|---|---|---|
| **MLC-LLM** | 1.0000 | 0.9996 | 0.9995 |
| **HuggingFace** | 0.9996 | 1.0000 | 0.9996 |
| **Ollama** | 0.9995 | 0.9996 | 1.0000 |

### 2. Batch Prefill Optimization

Multiple sequences share one KV cache via `kv_state_add_sequence` + `batch_prefill_to_last_hidden_states`. Single forward pass when total tokens ≤ `prefill_chunk_size`. 

### 3. Model Type Auto-Detection

- `embed` + `prefill_to_last_hidden_states` → **decoder**
- `prefill` only → **encoder**

No user configuration required.

### 4. Encoder Truncation

Inputs exceeding `prefill_chunk_size` (default 512) are truncated. Future improvement: sliding window + mean pooling strategy for better long-text support.

## Test Plan

**Model-level**: MLC vs HuggingFace logit match (cosine > 0.99 across 9 multilingual test texts)
```bash
MLC_QWEN3_EMB_HF_DIR=<hf_model> \
MLC_QWEN3_EMB_MODEL_DIR=<compiled_dir> \
MLC_QWEN3_EMB_MODEL_LIB=<model.dylib> \
  pytest tests/python/model/test_qwen3_embedding.py -v
```

**Engine-level**: 15 tests (shape, L2 norm, batch, similarity ranking, determinism, async, edge cases)
```bash
MLC_SERVE_EMBEDDING_MODEL_LIB=<model.dylib> \
  pytest -m engine tests/python/serve/test_embedding_engine.py -v
```

**Endpoint e2e**: HTTP endpoint tests (single/batch input, dimension truncation, base64, model fallback)
```bash
MLC_SERVE_EMBEDDING_MODEL_LIB=<model.dylib> \
  pytest -m endpoint tests/python/serve/server/test_embedding_server.py -v
```

**Cross-backend benchmark** (attached `benchmark.py`): Compares MLC vs HuggingFace vs Ollama on retrieval (EN/ZH/multilingual/code), STS, classification, MRL dimension truncation, and throughput. [benchmark.py](https://github.com/user-attachments/files/25502865/benchmark.py)

> **Note on quantization**: MLC-LLM uses q0f16 (fp16, ~1.1 GB), HuggingFace uses BFloat16 (~1.1 GB) — both unquantized. Ollama uses Q8_0 8-bit quantization (639 MB). Despite quantization differences, cross-backend cosine > 0.99.
```bash
# Start MLC server in terminal 1
python start_mlc_server.py
# Run benchmark in terminal 2
python benchmark.py  #auto-detect 3 backends
python benchmark.py --backends mlc hf       # without Ollama
python benchmark.py --skip-speed            # skip speed test
```
