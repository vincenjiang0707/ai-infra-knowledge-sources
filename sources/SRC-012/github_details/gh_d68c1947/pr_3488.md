## Summary

Phase 4 of the embedding-serving stack tracked in #3451.

This adds first-class serving support for decoder-only embedding models such as Qwen3-Embedding:

- Adds `Qwen3EmbeddingModel.prefill_embedding(...)`.
- Adds decoder masked prefill via `mask_mode="causal_padded_left"`.
- Adds C++ `DecoderEmbeddingPrefill` and `BatchDecoderEmbeddingPrefillAction`.
- Routes decoder embedding models through `ThreadedEmbeddingRuntime`.
- Adds runtime guards for EOS truncation, empty inputs, non-`last` pooling, and `prefill_chunk_size` admission.
- Adds decoder parity and runtime canary tests.

## Performance Notes

Benchmark / profiling notes are tracked in #3451.

Test setup: `Qwen3-Embedding-4B`, MLC `q0f16`, HF/Ollama/oMLX `fp16`, Metal backend on MacBook Pro M1 Pro 16GB. Server backends include HTTP overhead.

Selected decoder benchmark results:

| seq | batch | `mlc_thread` | `mlc_tvm_native` | `hf_mps_fp16` | `ollama` | `omlx` |
|---:|---:|---:|---:|---:|---:|---:|
| 256 | 4 | 2626 ms, 1.52 texts/s | 2684 ms, 1.49 texts/s | 2677 ms, 1.49 texts/s | 2168 ms, 1.85 texts/s | 2038 ms, 1.96 texts/s |
| 512 | 4 | 5953 ms, 0.67 texts/s | 6342 ms, 0.63 texts/s | 5839 ms, 0.69 texts/s | 4367 ms, 0.92 texts/s | 4102 ms, 0.98 texts/s |
| 1024 | 4 | 14608 ms, 0.27 texts/s | 15986 ms, 0.25 texts/s | 27005 ms, 0.15 texts/s | 8919 ms, 0.45 texts/s | 4112 ms, 0.97 texts/s |
| 1024 | 8 | 29176 ms, 0.27 texts/s | 32230 ms, 0.25 texts/s | 41383 ms, 0.19 texts/s | 17790 ms, 0.45 texts/s | 8169 ms, 0.98 texts/s |

Phase 4 improves the MLC runtime path over the legacy native path: at `seq=1024`, `mlc_thread` is about 8-10% faster than `mlc_tvm_native`.

The remaining long-sequence throughput gap appears related to the masked attention prefill kernel (`batch_sequence_prefill_kv_masked`), not Python/C++ embedding runtime overhead. This conclusion is currently based only on Metal / M1 Pro testing and should not be assumed to generalize to CUDA without separate benchmarking.
