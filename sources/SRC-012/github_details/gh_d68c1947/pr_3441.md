## 正文

Explored the codebase, and found that quantization infrastructure is duplicated on a per-model basis, when it could be centralized. This PR should be treated as experimental until I'm able to follow up with some testing, but wanted to raise it early just for visibility. I'm planning to test numerical correctness on like 1~2 models on some varying quant levels against the main branch using debug chat.

Hello, I'm Gemini Code Assist[^1]! I'm currently reviewing this pull request and will post my feedback shortly. In the meantime, here's a summary to help you and other reviewers quickly get up to speed!

This pull request significantly refactors the quantization infrastructure by moving from a decentralized, per-model implementation to a centralized factory-based system. This change aims to reduce code duplication, streamline the addition of new quantization methods, and improve overall maintainability. Model definitions now utilize a new `make_quantization_functions` utility to configure their supported quantization types, leading to a cleaner and more modular codebase.

### Highlights

* **Centralized Quantization Logic**: Replaced duplicated per-model quantization files with a single, centralized factory approach to manage quantization methods.
* **New Quantization Factory**: Introduced `make_quantization_functions` and `make_awq_quant` utilities to dynamically generate quantization methods based on model capabilities (e.g., AWQ, per-tensor, block-scale support).
* **Simplified Model Definitions**: Updated model configurations in `model.py` to leverage the new centralized factory functions, reducing boilerplate and improving maintainability.
* **Removed Redundant Files**: Eliminated numerous `*_quantization.py` files across various model directories, consolidating their logic into the new factory.
