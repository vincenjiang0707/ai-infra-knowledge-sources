## 正文

## Problem

`EngineState` keeps its async request registry and callback state as class attributes. As a result, separate `AsyncMLCEngine` instances share the same request-id namespace. If two engines use the same request ID, one engine can reject the request as a duplicate or route/remove callback state belonging to the other engine.

## Changes

- Initialize trace, event-loop, async-stream, and sync callback state per `EngineState` instance.
- Add a regression test with two engine states using the same request ID and verify that a final callback only removes the originating engine's stream.
