# [PR #17291] [BugFix][KV Transfer] Suppress PD send after pool load failure

## 正文

### What this PR does / why we need it?

When a layerwise MemCache load loses its GVA/lease, AscendStore reports the invalid block to the scheduler. The SFA producer can still have queued layer send tasks for the same request and may publish `READ_READY_BATCH`, including a success completion marker, for KV that was never loaded.

This change records failed request IDs in a process-local, TTL-bounded registry and filters those requests before the SFA producer builds PD notifications. The marker remains visible across all queued layer tasks.

This complements #16876: that PR fences writes back to the shared pool, while this PR prevents forwarding the failed local prefix to the decode side.

### Does this PR introduce any user-facing change?

Yes. A request whose layerwise MemCache load fails is no longer advertised as a successful PD transfer.

### How was this patch tested?

- Added focused tests for AscendStore failure registration, producer-side filtering, and registry expiry.
- `ruff check` and `ruff format --check` pass for all changed files.
- `py_compile` passes for all changed Python files.
- Full CPU pytest was not run locally because the available macOS environment does not provide `torch`/`vllm`; CI is expected to run the added tests.
