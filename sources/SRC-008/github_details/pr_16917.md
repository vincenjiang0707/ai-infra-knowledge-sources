## 正文

### What this PR does / why we need it?

This PR optimizes the `_triton_rope_siso` kernel by moving offset and mask calculations outside the loop and using CANN extension slice operations (`extract_slice` and `insert_slice`) for more efficient memory access. It also adds documentation for the Triton RoPE kernels and introduces a new end-to-end test for the SISO RoPE kernel with cos/sin cache.. This PR reduces global memory traffic, eliminates redundant computations, and adds explicit in-place reuse through five changes:

1. **Split input/output pointers for explicit in-place reuse.**
   The kernel signature is changed from a single `qk_ptr` (used for both read and write) to two separate pointers: `qk_ptr` (input) and `output_ptr` (output). The host function `rope_forward_triton_siso` passes the **same tensor address** to both parameters, enabling in-place operation. Splitting the parameters makes the in-place reuse explicit at the call site and allows the compiler to better reason about read/write aliasings, which helps avoid unnecessary buffer copies and improves kernel execution performance on Ascend.

2. **Hoist loop-invariant offsets/masks out of the token loop.**
   `cos_sin_offsets`, `qk_offsets` and their masks are now computed once before the `for row_idx` loop instead of once per iteration.

3. **Single contiguous load for cos/sin (USE_COS_SIN path).**
   Previously: two non-contiguous loads (`cos_offsets` and `sin_offsets`) from the `cos_sin_cache` row.
   Now: one full-row load + `extension.extract_slice` to separate cos and sin halves. The `else` path (separate cos/sin) also benefits from the hoisted unified offsets.

4. **Single-tile load for qk.**
   Previously: compute `first_half_offsets` -> load left half -> compute `second_half_offsets` -> load right half.
   Now: one `tl.load` of the full `(pad_n_h, pad_rope_dim)` tile, then `extension.extract_slice` to split into halves (NeoX) or even/odd pairs (interleaved).

5. **Single-tile store for qk.**
   Previously: compute and store `new_qk_tile_1`, then compute and store `new_qk_tile_2` - two stores.
   Now: compute both halves, recombine via `extension.insert_slice`, and write with a single `tl.store`.

Net effect per token row:
- Original: **4 loads** (cos, sin, qk_L, qk_R) + **2 stores** = 6 global ops
- Optimized: **2 loads** (cos_sin_row, qk_tile) + **1 store** = 3 global ops
- In-place reuse eliminates one full tensor allocation per call.

Numerical results are identical (same rotation math, same masks).

### Does this PR introduce _any_ user-facing change?

No. This is an internal performance optimization for _triton_rope_siso.

### How was this patch tested?

- Correctness: `_triton_rope_siso` output matches the reference RoPE implementation for both NeoX and interleaved styles, and for both `cos/sin` and `cos_sin_cache` input paths.
- In-place reuse verified by passing the same tensor as both `qk` and `output`; result identical to out-of-place path.
- A new end-to-end test `test_rotary_embedding_triton_kernel_siso_with_cos_sin_cache` was added in `test_rope.py`.

### Notes

- The optimization requires `triton.language.extra.cann.extension`  (`extract_slice` / `insert_slice`), which is available on Ascend Triton.
- Only `_triton_rope_siso` is modified; `_triton_rope` (separate q/k) and `_triton_rope_fp8` are untouched.
- **NeoX vs interleaved style on Ascend**: The current optimization yields significant gains for the **NeoX style** (half-split layout), while the benefit is limited for the **interleaved style** (GPT-J, even/odd pair layout). This is because Ascend NPU primarily uses a **SIMD execution model**, where the NeoX-style contiguous half-split maps naturally to vectorized load/store operations, whereas the interleaved strided access pattern requires gather/scatter-like sequences that are less efficient on SIMD hardware. Therefore, when deploying RoPE operators on Ascend, it is recommended to use the **NeoX-style data layout** whenever possible to maximize kernel performance.
