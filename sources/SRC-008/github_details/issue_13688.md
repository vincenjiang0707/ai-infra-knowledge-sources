## Describe the Bug

When `HCCL_OP_EXPANSION_MODE=AIV` is enabled, calling `torch.npu.graph_task_group_begin()` followed by HCCL collective communication (e.g., `dist.all_reduce()`) inside `torch.npu.graph()` causes graph capture to fail with:

```
rtEventRecord execution failed, reason=task not supported
record event failed, runtime result = 507009
Failed to submit capture task, retCode=0x7100003
```

In vllm-ascend's full serving scenario (GLM-4.6V, TP8+EP8), this manifests as:
- Graph capture may partially succeed (some paths)
- First inference request hangs at "Replaying aclgraph" with **AIVector 8–16%, AICore 0%** (device-side deadlock)
- Service crashes after ~5 min (EngineCore shm_broadcast timeout)

Additionally, even after working around the task_group issue, **MC2 MoE dispatch/combine operators still deadlock during NPUGraph replay with AIV** — this is a deeper issue in torch_npu/CANN (separate issue to be filed).

## To Reproduce

### Minimal reproduction (2-rank, standalone)

```python
import os
os.environ['HCCL_OP_EXPANSION_MODE'] = 'AIV'
import torch, torch_npu, torch.distributed as dist

dist.init_process_group('hccl', init_method='tcp://127.0.0.1:24680',
                         rank=RANK, world_size=2)
x = torch.randn(2048, device='npu')

g = torch.npu.NPUGraph()
with torch.npu.graph(g):
    stream = torch.npu.current_stream()
    torch.npu.graph_task_group_begin(stream)
    dist.all_reduce(x)                          # ← ERROR: "task not supported"
    handle = torch.npu.graph_task_group_end(stream)
# RuntimeError: capture_end error code 507903
```

Run with 2 ranks:
```bash
HCCL_OP_EXPANSION_MODE=AIV ASCEND_RT_VISIBLE_DEVICES=2 RANK=0 WORLD_SIZE=2 \
  timeout 60 python3 repro.py &
HCCL_OP_EXPANSION_MODE=AIV ASCEND_RT_VISIBLE_DEVICES=3 RANK=1 WORLD_SIZE=2 \
  timeout 60 python3 repro.py &
wait
```

| tg_no_hccl | task_group + pure compute (no HCCL) + AIV | ✅ PASS |

| allreduce_tg | allreduce THEN task_group (separate) + AIV | ✅ PASS |

Key observations:
- `graph_task_group` itself is fine with AIV when no HCCL is involved
- The conflict is **RIC mode + AIV HCCL event record** specifically
- Separating the operations avoids the conflict → proves it's the **wrapping** combination

**Without AIV** (`# export HCCL_OP_EXPANSION_MODE=AIV`), same setup works: 3 rounds of requests all succeed.

## Expected Behavior

One of:
1. `graph_task_group_begin` should be compatible with AIV-mode HCCL communication inside the task group
2. If this is a known CANN limitation, `graph_task_group_begin` should detect AIV mode and raise a **clear error at capture time** (not silently produce a broken graph or deadlock on replay)
3. Automatically fall back to non-RIC mode when AIV is active
