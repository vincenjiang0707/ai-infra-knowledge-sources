## 正文

### What this PR does / why we need it?

The NPU visible-to-physical device mapping from #16256 is merged in upstream main as `9750add07ee64aa966ce2d03e86c8e070b46e9f6`. This PR builds on that merged implementation and contains only the endpoint-selection fix.

DP workers can share `local_rank=0` while binding different visible NPUs. The old `setup_ascend_local_comm_res()` indexed `ASCEND_RT_VISIBLE_DEVICES` with this rank, which could select the wrong `ub_endpoint_npu_<id>.json`. Containers exposing only part of a host's NPUs additionally require runtime-to-host conversion.

Pass the bound `visible_device_index` from the worker into the helper, then resolve its host physical ID through `current_platform.visible_device_id_to_physical_device_id()` merged by #16256. Select the endpoint file using that physical ID and propagate mapping errors. Calls without endpoint configuration still return without performing conversion.

Rebased onto upstream main `e2f7e3110` after #16256 merged. The PR now contains one endpoint-fix commit and four files: `vllm_ascend/utils.py`, `vllm_ascend/worker/worker.py`, `tests/ut/test_local_comm_res.py`, and `tests/ut/worker/test_worker_v1.py`. No prerequisite platform or native-binding commits remain in this PR.

### Does this PR introduce _any_ user-facing change?

Endpoint files configured through `ascend_local_comm_res_path` are selected by the bound NPU's host physical ID. This uses the native conversion binding already merged by #16256 and requires an extension built with a supporting CANN version.

### How was this patch tested?

- 12 focused unit tests passed for the combined stack, including endpoint selection, error propagation, platform delegation, and passing the bound visible ordinal instead of local rank.
- Built and installed the native extension with CANN 9.1.0 for Ascend950DT (`ascend950dt_9582`).
- All 13 independent process checks passed across non-privileged container mounts `0,1,2,3`, `2,3`, `1,3`, and `3`. Each used vLLM local rank 0 and checked device count, host physical ID, real endpoint-file selection, and invalid IDs. Visibility was unset or restricted to the last container logical device.
- The hardware and focused-UT results above describe the earlier combined stack. No model-serving or P/D transfer workload was run. For the latest rebase, the endpoint patch is unchanged (`git range-diff`), Python syntax checks, Ruff 0.14.0 lint/format checks on all four changed files, and `git diff --check` passed. The merged platform interface and worker device-binding order were reviewed. Hardware tests were not rerun on this rebased checkout; CI will validate the rewritten commit.

Runtime validation used vLLM `2cf0a6915ce544dc493a0990f2ea38d81601128a` and vLLM-Ascend `f8481287a07cd7c407a3142f5d4188d71d964467`, existing connector changes, and the combined patch (SHA256 `6509d3bdd0f3ab437e505329bd5fc01124d7010a1b73ed0d76c789c557005db6`). The installed torch_npu requires ascending visibility lists; descending lists fail before the binding.

### Additional partial-container validation (2026-09-11)

Tested on Ascend950DT with CANN 9.1.0, torch 2.10.0+cpu, and torch_npu 2.10.0.post4, using the previously validated image `vllm-ascend:npu-id-fixed-v2-20260910`. The non-privileged container mounted only host NPUs `3,4,5,6,7` and set `ASCEND_RT_VISIBLE_DEVICES=2`. Device count was 1. The test set vLLM's assigned device list to `[2]`, resolved local rank 0 through the platform binding interface, and called `torch.npu.set_device(0)`.

The after case executed the installed compiled binding and fixed helper. Both endpoint contents were compared against the real `/etc/hixlep` files, and the old and new contents differed. This verifies device mapping and endpoint selection, not model serving or P/D transfer. The temporary test container exited with code 0 and was removed.
