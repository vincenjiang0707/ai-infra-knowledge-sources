## 正文

### What this PR does / why we need it?
In the scenario where GLM5.2 enables dspark, the seq_lens in attention_v1 requires a device-to-host synchronization (on the NPU, seq_lens has num_rejects subtracted, whereas on the CPU it does not), causing a large number of bubbles between the main model and the draft model. Since seq_lens is a device tensor, performing a tolist() operation triggers a device-to-host synchronization. Therefore, a whitelist approach is used to address this scenario. Empirical tests show that using seq_lens without num_rejects has almost no impact on the model acceptance rate, but greatly improves performance.
