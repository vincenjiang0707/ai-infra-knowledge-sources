### Bug description

After upgrading vLLM from `v0.23.0` to `v0.24.0` or later, the workload above shows an uneven distribution across the A5 cards in the `DP16 EP16` deployment. There are visibly fast and slow cards, and some cards become `hostbound` in profiling/observability data.

The issue is observed with the `GLM5.1-W4A4C8-mxfp4` model on a two-node A5 mixed deployment. The same workload is used as the comparison baseline on vLLM `v0.23.0`.

Expected behavior:

- Work should remain reasonably balanced across cards.
- No subset of cards should become host-bound and determine the overall step/request latency.

Actual behavior:

- Card execution speed is uneven, with fast and slow cards.
- Work distribution is uneven.
- Some cards show `hostbound` behavior.

### Workaround

As a short-term workaround, using [Ascend/msboost](https://gitcode.com/Ascend/msboost) can avoid the issue in this scenario. This workaround is provided from the test environment and has not been independently validated in the current checkout.

### Request

Please investigate the regression introduced after vLLM `v0.23.0`, including the A5 multi-node `DP16 EP16` execution path. In particular, please help identify whether the behavior is related to scheduling, CPU affinity, or host-device execution/synchronization. No specific root cause is assumed at this time.

The issue has not been reproduced in the current Mac checkout. Additional logs, the launch command, and complete environment information can be provided in a follow-up.
