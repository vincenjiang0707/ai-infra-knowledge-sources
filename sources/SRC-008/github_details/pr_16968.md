# [PR #16968] [BugFix][MoE] Release requantized W4A4 MXFP4 activations before GMM1

## 正文

### What this PR does / why we need it?

Fix the W4A4 MXFP4 MoE activation lifetime regression introduced by the MoE MLP refactor. When the dispatcher does not provide a dynamic scale, local dynamic MXFP quantization produces a separate FP4 activation tensor. Release the original BF16 activation before GMM1 so it does not overlap with the GMM1 allocation during profile-run.

Keep dispatcher-quantized inputs alive through GMM1 because they are consumed directly by the operator. Apply the same lifetime rule to both fused GMM1+activation+quantization and regular GMM1 paths.

### Does this PR introduce any user-facing change?

Yes. W4A4 MXFP4 MoE profile-run uses less transient NPU memory when local activation re-quantization is required, which can recover KV-cache capacity and allow affected engine configurations to start. No API or configuration changes are introduced.

### How was this patch tested?

Added unittest-compatible coverage for both GMM1 paths, verifying that re-quantized inputs are released before GMM1 and dispatcher-quantized inputs are released after GMM1. The targeted tests passed in the b153_bpz_smoke Ascend container:

2 passed, 16 deselected

The original launch configuration was also exercised. Available KV-cache memory changed from a negative value to 0.09 GiB, removing the original `No available memory for the cache blocks` failure. The run then reached the separate max-sequence-length capacity check because 0.19 GiB is required for max_model_len=5000.
