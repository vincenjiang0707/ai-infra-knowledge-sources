# [Issue #11099] [Build] Avoid duplicate CMake configure during custom kernel builds

source: https://github.com/vllm-project/vllm-ascend/issues/11099
state: closed | updated: 2026-09-21T12:39:21Z
labels: ci/build, triaged

## 正文

### Problem

During custom-kernel builds, `cmake_build_ext.configure()` in `setup.py` invokes CMake twice in the same `self.build_temp` directory when the first invocation succeeds.

The first invocation already executes a complete configure command:

```python
cmake_args = ["cmake"]
# Append the existing configuration options.
cmake_args += [source_dir]
subprocess.check_call(cmake_args, cwd=self.build_temp)
```

The method then invokes CMake again:

```python
subprocess.check_call(
    ["cmake", ext.cmake_lists_dir, *build_tool, *cmake_args],
    cwd=self.build_temp,
)
```

`build_tool` is an empty list; its Ninja-related code is commented out. Because `cmake_args` already contains the executable and source directory, the second command has this redundant shape:

```text
cmake <extension source directory> cmake <configure options> <source directory>
```

### Impact

The second invocation repeats configuration work before compilation and includes an unintended extra `cmake` positional argument. A local CMake probe emitted an extra-path warning, but full Ascend compilation and build-time savings have not been measured. This is not a claim that every build fails or that compilation time is halved.

### Expected behavior and minimal fix

Run CMake configuration once per `configure(ext)` call:

- Keep the existing configure options and error handling.
- Use `ext.cmake_lists_dir`, initialized by `CMakeExtension` from `cmake_lists_dir="."` and normalized to an absolute path, as the source directory.
- Remove the second invocation, the unused `build_tool` block, and the now-unused local `source_dir`.
- Preserve optional `-DVLLM_ASCEND_ENABLE_BATCH_MEMCPY=...` forwarding. The source directory is a separate argument and does not replace the options.
- Leave compilation, installation, generator selection, and cache behavior unchanged; enabling Ninja or ccache is outside this issue's scope.

### Validation and follow-up

PR #11102 implements this single-file fix. On head `a0c6679e4`, syntax/lint checks, CPU unit tests, and DCO passed. Full Ascend custom-kernel compilation remains unverified locally. The remaining CI gate requires a maintainer test-enabling label before downstream tests can run.
