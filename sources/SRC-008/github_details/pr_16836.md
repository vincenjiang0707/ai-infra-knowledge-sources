## 正文

### What this PR does / why we need it?

This PR adds independently triggerable DeepSeek V4 Flash MRV2 Nightly cases:

- registers the single-node Flash case for the A3 and A3-560T runner pools;
- registers the two-node Flash P/D prefix-cache case;
- enables PCP4 on the prefill node with TP1 (`--prefill-context-parallel-size 4`);
- uses `enable_cpu_binding=true` and `enable_fused_mc2=1` without the retired `enable_flashcomm1` switch;
- runs accuracy first, then a 128K/1-token warmup, then the 128K/1K performance benchmark;
- sets the measured output-throughput baseline to 2267.90 token/s with threshold 0.95;
- keeps the `generate_zh_docs.py` import-path fix required by CI.

### Does this PR introduce any user-facing change?

No.

### How was this patch tested?

- Rebased onto current `main` and resolved the Nightly matrix conflict while preserving current runner labels.
- Parsed the Nightly matrix and both case YAML files successfully.
- Parsed all changed `--additional-config` JSON values and corrected `enable_cpu_binding` to a JSON boolean.
- Loaded the P/D YAML through `ExternalDPConfigLoader`; the prefill topology resolves to TP1/PCP4.
- Verified the `/nightly` dispatcher selects the A3 workflow for both registered case names.
- Ran Python bytecode compilation for the changed docs utility and Nightly config loaders.
- NPU Nightly execution is pending an authorized `/nightly` trigger.

### CI scheduling

Please trigger this PR separately from the three Pro case PRs so the Nightly cases do not compete for the same CI resources.
