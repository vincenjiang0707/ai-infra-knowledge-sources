## 正文

### Your current environment

- vLLM Ascend branch: `releases/v0.26.0rc` at `820a21d6593b74211863c7787e1ba9b4deaf9126`
- vLLM version: `v0.26.0`
- Regression introduced by #13993 and still present after #14624
- Reproduction is tokenizer-only; the user-visible impact was found by the DeepSeek V4 Flash GPQA smoke test

### Describe the bug

The DeepSeek V4 thinking patch added by #13993 unconditionally applies the post-Preview reasoning-effort mapping to every DeepSeek V4 checkpoint.

The official DeepSeek V4 Preview encoders and the encoders shipped with later checkpoints such as DeepSeek-V4-Flash-0731 and DeepSeek-V4-Pro-0813 use different meanings for the same effort names:

| Requested effort | V4 Preview prompt | Post-Preview prompt |
|---|---|---|
| `high` (also the API default) | no effort prefix | `Reasoning Effort: Absolute maximum...` |
| `max` / `xhigh` | `Reasoning Effort: Absolute maximum...` | `max` uses `Reasoning Effort: Beyond maximum...`; `xhigh` maps to post-Preview high |

After #13993, a V4 Preview request with omitted effort or explicit `high` therefore receives the prompt that its own encoder associates with maximum effort. In the GPQA smoke test with thinking enabled and `max_tokens=131072`, this produces many truncated answers and lowers accuracy.

This is a checkpoint compatibility regression in the reasoning-effort patch. It is separate from the system/tools placement bug reported in https://github.com/vllm-project/vllm/issues/51829.

A tokenizer-only probe on the current release branch shows the incorrect behavior before the fix:

```text
DeepSeek-V4-Flash (Preview):
  default: absolute-maximum
  high: absolute-maximum
  max: beyond-maximum
```

The checkpoint generations can be distinguished from `config.json` without relying on model path names:

- DeepSeek-V4-Flash and DeepSeek-V4-Pro Preview have no `dspark_*` fields.
- DeepSeek-V4-Flash-0731 and DeepSeek-V4-Pro-0813 contain `dspark_block_size`, `dspark_markov_rank`, `dspark_noise_token_id`, and `dspark_target_layer_ids`.

Expected behavior:

1. If `config.json` contains any `dspark_*` field, use the post-Preview mapping added by #13993.
2. Otherwise, preserve the V4 Preview mapping: default/high has no effort prefix, while max/xhigh uses the original `Absolute maximum` prefix.
3. Explicit thinking disablement must continue to override the requested effort.

Regression coverage should verify both mapping tables and the exact prompt prefix for Preview default/high/max and post-Preview high/max.
