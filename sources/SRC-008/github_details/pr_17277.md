### What this PR does / why we need it?

Follow-up to #16964. When drafting is skipped, the current code stores a Python list of empty drafts. Async scheduling can already have reserved speculative placeholders for the next step. The inherited GPUModelRunner._prepare_input_ids requires a Tensor to scatter those slots and asserts on the list.

- Pass SchedulerOutput into _skip_drafting.
- Publish an int32 zero Tensor on the runner device with shape (num_reqs, configured num_spec_tokens).
- Call the existing _copy_draft_token_ids_to_cpu(..., zeros_only=True), refreshing the actual draft stride before its async early return and publishing CPU zeros/request IDs/events only when needed.
- Preserve sampled-token/count updates and DP dummy behavior; clear stale draft probabilities as before.

The full configured width covers all reserved slots, including reduced per-step speculative widths. The zeros are draft candidates/placeholders for normal target verification, not directly emitted output tokens. This follows the representation already used on the 0.26 branch.

Add regression coverage for skip -> next async input preparation with reordered requests and 1/3/5 speculative slots; verify sampled tokens and zeros reach the correct positions. Exercise real CPU publication logic for sync, structured output, penalties, and PP, including event recording and untouched unused buffer rows. Check that stale previous draft width is refreshed even when CPU publication is skipped.

Scope: no max-model-length threshold change, no removal of assertions, and no unrelated n-gram state-handling change. The reported 131072 input + 1024 output with max_model_len=133120 does not by itself prove that overflow occurred. Runtime SHA, actual metadata length and effective drafter limit are still needed to attribute that incident.

### Does this PR introduce _any_ user-facing change?

Prevents a next-step Tensor assertion after the drafter-length skip path. Normal drafting and configuration remain unchanged. No accuracy or performance improvement is claimed without NPU evaluation.

### What this PR does / why we need it?
This PR updates the `_skip_drafting` method in `model_runner_v1.py` to accept `scheduler_output` and publish zero draft placeholders (using a full-width tensor) instead of empty lists. This ensures that when drafting is skipped during async scheduling, the next step scatters zeros instead of using stale draft token IDs.

Additionally, there is feedback regarding the tensor allocation in `_skip_drafting`. Using `.expand()` on a 1-element tensor creates a 0-stride tensor, which can cause silent correctness bugs or crashes in custom NPU/GPU kernels that assume contiguous memory layouts. It is recommended to allocate a contiguous tensor of zeros directly using `torch.zeros` with the target shape.

No.
