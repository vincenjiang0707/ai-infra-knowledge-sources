# [PR #17241] [BugFix][Model] Make MiniMax-M3 prefill KV-gather-Q optional on A5

state: open | updated: 2026-09-23T03:55:20Z
labels: module:tests, ready-a5, ready-precise

## 正文

### What this PR does / why we need it?

Follow up on #14685: A3 already falls back when the experimental Split-KV package is absent, but A5 currently skips the availability check and unconditionally calls the vendor prefill entry point.

- Select the prefill path by optional Split-KV ACLNN availability before building K2Q, without a separate device allowlist. Remove the unused `MINIMAX_M3_PREFILL_KV_GATHER_Q` capability declaration and registrations; retain `FP8_ATTENTION` for dtype validation and existing precision-mode selection.
- Use the existing Q-gather-KV prefill path when the package is unavailable.
- Extend that fallback to A5 E4M3 KV caches: cast/clamp Q consistently with decode, supply unit dequantization scales, and return BF16 output. Variable per-request query lengths and the original `-1` top-k sentinels are preserved.
- Harden the native availability probe: require both entry points from the same provider and reject the **known metadata-enabled experimental ABI**, which adds `metadataOptional` to the workspace-size signature without renaming the entry point. Inspect the selected provider so a lower-priority incompatible library does not disable a compatible provider.

This does not add support for the metadata-enabled ABI or attempt universal ABI detection. It safely falls back for that known incompatible package. Compatible packages retain the current KV-gather-Q path. Precision modes and decode are unchanged. The dedicated KV-gather-Q hardware capability is removed; other capability definitions, including `FP8_ATTENTION`, are unchanged.

### Does this PR introduce _any_ user-facing change?

Yes. MiniMax-M3 A5 prefill no longer requires the optional experimental Split-KV package: it can use Q-gather-KV with BF16 or E4M3 KV caches.

Dispatch now depends solely on the ACLNN availability probe, not the former A3/A5 capability allowlist. A device previously excluded by that allowlist will also attempt KV-gather-Q if the probe succeeds. Users must install a package containing kernels for the actual SoC: the probe does not verify device-kernel compatibility, and execution errors are not automatically caught and retried on the fallback path. The mocked A2 dispatch test verifies routing only, not A2 hardware support.

To enable KV-gather-Q, install a **compatible** experimental package, source its environment, and restart the workers. No source-code change or new environment switch is needed. The availability result and loader search paths are cached per process; installing a package into an already running worker is not supported.

### How was this patch tested?

- `python -m pytest tests/ut/models/minimax_m3/test_msa_m3.py tests/ut/device/test_hardware_profile.py -q`: **89 passed** on CPU, using the repository's verified vLLM revision `84030bbe3d74d99bad477a3d2e37a973ccd8865c`.
- Added regression coverage for A5 with/without Split-KV, BF16/FP8 fallback across tensor/tuple/list caches, variable query lengths, invalid FP8 inputs, and ensuring fallback calls neither K2Q nor Split-KV. Updated dispatch coverage for A2/A3/A5 and the hardware-profile tests after removing the dedicated capability.
- Compiled and exercised the exact C++ availability function against synthetic ELF providers: **8 cases passed**, covering missing/partial entry points, compatible/incompatible providers, mixed providers, and both library-priority orders. An additional null-filename fault-injection case passed, confirming that a successful `dladdr` with `dli_fname == nullptr` returns false without calling `dlopen`.
- Inspected the supplied metadata-enabled A3/A5 package headers and ELF exports to confirm the changed signature and metadata entry-point marker.
- Changed `torch_binding.cpp` passed `-fsyntax-only` using the existing A5 CANN/PyTorch build toolchain. This is not a complete wheel rebuild.
- Ruff check/format and `git diff --check`: passed for the changed files.
- `bash format.sh ci` was attempted but could not bootstrap its GitHub-hosted hooks: this server's connection to GitHub timed out. Full pre-commit validation remains for CI.
- **NPU execution and GPQA were not rerun for this patch** because the available A5 devices are occupied by another service. Hardware/CI validation is still required before merging; prior A5 validation is not presented as a test of this patch.
