### 🐛 Describe the bug

Testing platform: A5
Dataset and accuracy test tool: Math-500 + aisbench
Our A5 script:
```sh
export VLLM_VERSION=0.27.1
# export VLLM_LOGGING_LEVEL=DEBUG
vllm serve /mnt/share/weight/Qwen3.5-35B-A3B/ \
       --served-model-name auto \
       --max-num-seqs 256 \
       --max-model-len 131072 \
       --trust-remote-code \
       --tensor-parallel-size 4 \
       --data-parallel-size 1 \
       --decode-context-parallel-size 2 \
       --cp-kv-cache-interleave-size 128 \
       --port 21007 \
       --enable-expert-parallel \
       --gpu-memory-utilization 0.95 \
       --compilation_config '{
              "cudagraph_mode": "FULL_DECODE_ONLY"
       }' \

ais_bench --models vllm_api_stream_chat --datasets math500_gen_0_shot_cot_chat_prompt

# vllm_stream_chat.py
from ais_bench.benchmark.models import VLLMCustomAPIChat
from ais_bench.benchmark.utils.postprocess.model_postprocessors import extract_non_reasoning_content

models = [
    dict(
        attr="service",
        type=VLLMCustomAPIChat,
        abbr="vllm-api-stream-chat",
        path="/mnt/share/weight/Qwen3.5-35B-A3B/",
        model="",
        stream=True,
        request_rate=0,
        use_timestamp=False,
        retry=2,
        api_key="",
        host_ip="localhost",
        host_port=21007,
        url="",
        max_out_len=20480,
        batch_size=1024,
        trust_remote_code=False,
        generation_kwargs=dict(
            temperature=0,
            seed = 1234,
        ),
        pred_postprocessor=dict(type=extract_non_reasoning_content),
    )
]
```
Using the server script above, our Qwen3.5-35B only scored 14.8 on Math-500. In contrast to this, using the same script on A3 platform, we got 94.8.
Also, we found if we disable graph mode and use `--enforce-eager`, the Qwen3.5-35B can score 95.

### kitaikuyo421esfj-hub · 2026-09-20

Thanks for the report. This appears to be a graph-mode accuracy issue on A5: the same setup recovers to ~95 with `--enforce-eager`.

The configuration uses `--decode-context-parallel-size 2` together with `FULL_DECODE_ONLY`, so we suspect the DCP full-graph replay path. As a workaround, please use `--enforce-eager` for now.

Could you also try setting `--decode-context-parallel-size 1` while keeping graph mode enabled? This will help confirm whether the issue is DCP-related.
