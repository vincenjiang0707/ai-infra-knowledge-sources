# [PR #17337] - [Feature] Materialize only the local padded MC2 input shard

## 正文

### What this PR does / why we need it?

MC2 preparation currently pads the complete hidden-state and router-logit tensors before selecting the local tensor-parallel shard. With one decode token and TP=4, each rank materializes four rows while consuming only one.

This PR computes the local shard boundaries first and materializes only the required data:

- Fully valid shards return contiguous slices.
- Fully padded shards allocate independent local zero tensors.
- Partially valid shards pad only their local slice.

The implementation preserves `torch.tensor_split` semantics, including uneven splits, global padded shapes, MC2 masks, and the finalize contract. The sequence-parallel / `replace_allreduce` path remains unchanged.

#### Performance

Prior serving A/B measurements of this implementation used GLM-5.2 W4A8 on Ascend 910C with TP=4 and fused MC2 enabled. Both versions already included the RoPE contiguous-cache optimization; the candidate added only this MC2 padding change.

| Input tokens | Output tokens | Requests / concurrency | Baseline TPOT (ms) | Optimized TPOT (ms) | Reduction |
| --- | --- | --- | --- | --- | --- |
| 100000 | 1024 | 4 / 4 | 52.1215 | 49.9419 | 4.18% |
| 8192 | 512 | 8 / 8 | 52.9287 | 50.5735 | 4.45% |

Each value is the median of three per-round **mean TPOT** measurements, using matched seeds 42/43/44. Profiling was disabled during timing.

These measurements were collected on the deployment branch before porting to community main. They represent short, fixed-load workloads, not saturation-throughput results. Prefix caches were not reset.

Profile inspection also confirmed that the targeted full-tensor padding Concat operations disappeared on the inspected DP0 TP0/TP1 ranks.

### Does this PR introduce _any_ user-facing change?

No API, configuration, or environment-variable changes.

The optimization applies when MC2 preparation requires padding and TP > 1. Zero-only outputs use independent storage, avoiding shared mutable padding buffers.

### How was this patch tested?

The ported community-main source passed:

- **230 unit tests**, covering empty and noncontiguous inputs, FP32/FP16/BF16, TP sizes 1/2/4/8, uneven splits, masks, global padded shapes, and existing prepare/finalize behavior.
- **12 NPU graph tests**, covering all four TP ranks and three dtypes, with changing input values and alternating graph sizes.
- All applicable pre-commit checks for the three changed files.

Commands:

```bash
python -m pytest -q \
  tests/ut/ops/test_mc2_local_padding.py \
  tests/ut/ops/test_prepare_finalize.py

python -m pytest -q \

```

Prior serving regression checks passed 12/12 cases for both versions, with identical answers and token sequences. This was a correctness smoke test, not a comprehensive model-accuracy evaluation.
