## 正文

### What this PR does / why we need it?

Backport of #17293 for `releases/v0.26.0rc`, adapted to the release protocol without main-only PP handshake changes.

This makes SFA PD failure handling converge:

- retry only pre-delivery connection failures (`ConnectError`, `ConnectTimeout`, and `PoolTimeout`); do not replay HTTP non-2xx or post-send read/write failures;
- cap outer rendezvous retries and publish a failed consumer terminal with the destination blocks;
- serialize failed terminals through the read thread and defer cleanup until the terminal is reported;
- filter duplicate or late batches before destination lookup/copy using TTL-bounded tombstones;
- clear prior terminal state when an external request ID starts a fresh round.

This PR does not include the proxy backport (#17323), producer load-failure suppression (#17322), main-only PP protocol changes, or a vLLM core scheduler monkey patch.

### Does this PR introduce any user-facing change?

Yes. Failed SFA PD requests terminate instead of waiting indefinitely, and potentially side-effectful notifications are not re-POSTed.

### How was this patch tested?

- Added focused regression coverage for retry classification, failed metadata propagation, receive terminals, deferred cleanup, tombstone filtering, and request rearming.
- `ruff check`, `ruff format --check`, `py_compile`, and `git diff --check` pass.
- Full CPU pytest was not run locally because the available macOS environment does not provide `torch`/`vllm`; CI is expected to run the added tests.
- vLLM main: https://github.com/vllm-project/vllm/commit/d02df748bf9efd99022f1a062597dc3cb3808485
