# [PR #11733] [Performance] Fuse Compressor with ScatterNdUpdateV2 for DeepSeek V4

## 正文

This PR fuses Compressor and ScatterNdUpdateV2 for DeepSeek‑V4 DSA‑CP compressed KV‑Cache update:
1. The compressor accepts optional slot_mapping, paged_kv_cache and block_size arguments, and writes compressed KV results into paged KV‑Cache directly, removing a separate npu_scatter_nd_update_v2 launch.
2. It extends the op schema, passes scatter_block_size via tiling parameters, and implements the paged‑cache write‑back inside arch32/arch35 vector‑based compressor kernels.

### Performance (Tested on DeepSeek‑V4‑Flash‑w8a8‑mtp, TP=8 DP=2)
- HCA: ~30µs saving per‑layer (1.1× speed‑up), total 20 layers
- CSA: ~600µs saving per‑layer (1.4× speed‑up), total 21 layers
- End‑to‑end median TTFT improves by ~16 ms, matching per‑layer profiling results.

### Compatibility
- Default compressor behavior remains unchanged when fused‑scatter inputs are omitted.
- SWA‑KV‑Cache and indexer‑KV‑Cache paths are untouched and still use standalone scatter‑nd‑update.

### What this PR does / why we need it?
This PR integrates fused scatter support directly into the compressor operator by adding `slot_mapping` and `paged_kv_cache` as optional inputs, along with a `scatter_block_size` attribute. This allows the kernel to perform the scatter operation internally, eliminating the need for a separate `npu_scatter_nd_update_v2` call in Python and improving performance.

However, there are critical issues in the implementation:
1. **Defensive Check for Negative `blockIdx`**: In `arch32` and `arch35` vector performance kernels, `slot_mapping` can contain `-1` for padding/unmapped tokens. Without checking if `blockIdx >= 0`, casting `-1` to `uint64_t` leads to out-of-bounds memory access.
2. **Synchronization for Asynchronous MTE3 Writes**: A `PipeBarrier<PIPE_MTE3>()` is missing before returning from `CopyFinalResultOut`, which can cause a Write-After-Read (WAR) hazard since `cmpKvOutUb` is freed immediately.

### Does this PR introduce _any_ user-facing change?
No, this is an internal optimization for the compressor operator.
