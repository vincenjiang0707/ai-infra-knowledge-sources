## 正文

Draft PR adding CI gates for the **non-Flash GLM-5.x** reduced checkpoint (11 main
layers plus one retained MTP layer). Three commits:

- `36e93d504` GLM reduced-model nightly gates and prefix parity probes
- `72a3fb0a3` truncated-logits gate: fixed 200 GSM8K samples, all 20,693
  prediction positions, A1 argmax agreement >= 90%
- `313b11baa` 11-layer offline performance gate (this change)

## What is in this PR

- The profile-based reduced-checkpoint builder/preparer under `tools/glm_reduced`
  (`profiles.py`, `reducer.py`, `prepare.py`, `safetensors_io.py`).
- The fixed-position truncated-logits gate (11-layer GLM-5.2 W4A8, 20,693
  positions, A1 argmax agreement >= 90%).
- The offline 11-layer performance gate (this change).

The builder is the provisioning prerequisite for both gates; the three are kept
in one PR on purpose rather than split.

## Scope: non-Flash GLM5.x only

- Both gates target non-Flash GLM5.x DSA checkpoints. The currently registered
  model is `Eco-Tech/GLM-5.2-w4a8` reduced to 11 main layers plus one retained
  MTP layer (MTP disabled in the gate).
- Flash and hybrid/linear-attention models are rejected before any measurement:
  both gates run the shared `validate_model`, which raises
  "Flash models are excluded from this gate" when the model id or the config
  mentions flash, and which requires `model_type == glm_moe_dsa` with every
  `layer_types` entry equal to `deepseek_sparse_attention`.
- The reduction tooling under `tools/glm_reduced` is profile-based and can
  describe other families, but neither gate applies a GLM5.x baseline to another
  family. Other non-Flash GLM5.x models need their own registered baseline, and
  this PR claims nothing about Flash models.

## Performance gate

- Offline single-round runner (no OpenAI server), mirroring the logits gate.
- Compares a fresh run against a pinned, host-scoped baseline; model, hardware
  tag, runner architecture, engine settings, workload shapes and iteration
  counts must match exactly or it fails closed.
- Thresholds: output throughput >= 90% of baseline; TTFT/TPOT/whole-workload
  latency <= 120%. Derived from a three-start A/A calibration, not chosen to let
  a candidate pass.
- CI never writes or bootstraps a baseline; evidence directories are never
  overwritten.

## Calibration

Three independent starts on the lab x86_64 A3 host, one warmup plus three
measured iterations each. Cross-start relative MAD: 4.22% throughput, 10.19%
TTFT, 4.42% TPOT, 4.40% whole-workload latency. The earlier single-launch
baseline was an optimistic outlier (8.7%-13.3% above the three-start median), so
the baseline is now the median of three starts.

## Boundaries

- The baseline is scoped to `linux-x86_64-a3-800i-8-167`; there is no aarch64
  calibration yet, so the nightly registration is left commented out in
  `nightly_config.yaml`. Enabling it on aarch64 would fail closed by design.
- `enforce_eager=True` and MTP disabled: this is a regression baseline, not a
  deployment peak, and it does not extrapolate to the full 78-layer model.
- The 3% relative-MAD stability cap used by the earlier Reduced8 gate is not met
  on this shared host, so the thresholds carry roughly twice the worst observed
  one-sided ratio (0.9578 low-side throughput, 1.1019 high-side latency).
- A confirmation round with the calibrated baseline was not completed: the
  attempt hit resource contention on the shared host. The runner pipeline itself
  was exercised end-to-end once.

## Testing

- 15 CPU gate tests (`tests/ut/tools/glm_reduced/test_perf_gate.py`); ruff check
  and ruff format clean.
- Logits gate: 20 CPU tests, single-round NPU agreement 20,693/20,693, exit 0.
- No GitHub nightly has been run.

- vLLM main: https://github.com/vllm-project/vllm/commit/84030bbe3d74d99bad477a3d2e37a973ccd8865c

Thanks for the review. Both points are addressed in head `939037ad3`:

- **Dispatch placement**: the three model-specific gate branches were removed from `test_single_node()` and moved into `tests/e2e/nightly/single_node/models/scripts/gate_dispatch.py`. The generic runner now only calls a single `dispatch_gate(config)` entry point.
- **Local model construction (K3 placement)**: added `tests/e2e/pull_request/four_card/test_glm52_reduced.py`, an independent test file that constructs the 11-layer model inside the test by cropping the locally cached 78-layer W4A8 checkpoint (`/root/.cache/modelscope/hub/models/Eco-Tech/GLM-5.2-w4a8`, the same local-cache convention the other model configs already use). It needs no network access and skips when the local source is absent.

One deliberate difference from the K3 pattern: we keep the real W4A8 checkpoint instead of random dummy weights. Dummy weights do not exercise the quantized checkpoint-loading path, which is the part this test is meant to cover. The added test is a functional startup/generation check (TP4 + EP, eager) and makes no accuracy claim.
