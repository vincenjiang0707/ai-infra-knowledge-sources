## 正文

### 📚 The doc issue

 Environment： vllm-ascend 0.23.0 ~ latest

## Describe problem
In `docs/source/tutorials/models/GLM5.2.md`, the description of `load_async` is inconsistent with the actual code logic.

- Line 1159: the `AscendStoreConnector` has `kv_role` set to `kv_consumer` (Decode node) and configures `"load_async": true`;
- Line 1246: `"load_async": true` (decode side): Asynchronously loads KV cache from the pool on decode nodes.

Both places describe `load_async` as a feature of the **Decode (kv_consumer) node**, but in reality, asynchronously loading KV cache from the KV Pool happens on the **Prefill (kv_producer) node** — when the prefix cache hits the external cache, the Prefill node uses `load_async` to asynchronously load the external KV cache, avoiding redundant prefill computation.

## Code evidence

`vllm_ascend/distributed/kv_transfer/kv_pool/ascend_store/pool_scheduler.py`:

```python
def get_num_new_matched_tokens(...) -> tuple[int, bool]:
    ...
    if self.kv_role == "kv_consumer" and not self.consumer_is_to_load:
        return 0, False   # Decode node defaults to consumer_is_to_load=False, so it does not load
```

As shown:

- `kv_producer` (Prefill) does not satisfy this condition, so it normally performs the load logic (loading from the KV Pool on a prefix-cache hit);
- `kv_consumer` (Decode) defaults to `consumer_is_to_load=False`, so it does **not** load from the KV Pool (Decode mainly gets KV via Mooncake P2P transfer).

Therefore, the "asynchronously load external cache" capability of `load_async` actually serves the **Prefill node**, not the Decode node.

### Suggest a potential alternative/fix


1. Change line 1246 to:

   > `"load_async": true` (prefill side): Asynchronously loads KV cache from the pool on prefill nodes when the prefix cache hits the external KV Pool.

2. For the Decode-node configuration around line 1159, please confirm whether `load_async` should be kept there or moved to the Prefill-node configuration (if the Decode node really needs to load from the KV Pool, it should explicitly set `consumer_is_to_load: true`).
