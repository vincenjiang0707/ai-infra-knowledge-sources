# [PR #17487] [BugFix][KV Pool] Prepare layerwise state before forward hooks

source: https://github.com/vllm-project/vllm-ascend/pull/17487
state: open | updated: 2026-09-24T15:14:33Z
labels: module:tests

## 正文

### What this PR does / why we need it?

Align AscendStore's layerwise state lifecycle with the deferred `start_load_kv()` contract introduced by https://github.com/vllm-project/vllm/pull/53333.

When a step has no synchronous KV loads, the runner binds metadata before the main-model forward but may call `start_load_kv()` only after that forward. AscendStore currently initializes its layer cursor, transfer task lists, prefetch cursor and attention gate in `start_load_kv()`. Consequently, the layer hooks can consume empty or stale state. With MTP, the deferred call can then reset the cursor and replace the tasks between the main-model and draft forwards.

Move per-step preparation to `bind_connector_metadata()`, following the upstream LMCache lifecycle. Keep actual layerwise load submission in `wait_for_layer_load()`. A deferred start must not discard the already prepared state or Mamba copy buffers. Preserve fresh task-list ownership across steps and leave the non-layerwise loading path unchanged.

This does not mutate `SchedulerOutput`, force synchronous loading, or skip the final/MTP layer. The allocation rounding issue is separate and remains in #16926; its code is not duplicated here.

### Does this PR introduce _any_ user-facing change?

Fixes layerwise save/load state corruption when load submission is deferred, including steps that run MTP after the main forward. No new flags or configuration changes.

### How was this patch tested?

- vLLM main: https://github.com/vllm-project/vllm/commit/ced6857afa0ea7b2e3f0846a62e1394e90f15607
