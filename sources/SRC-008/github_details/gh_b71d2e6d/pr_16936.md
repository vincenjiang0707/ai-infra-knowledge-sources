## 正文

### What this PR does / why we need it?

Adds GLM-5.3-Flash Model Runner V2 integration for hybrid cache layout, decode graphs, and MTP. MRV2 must preserve the cache capabilities, shared physical pages, and circular tail addressing contract used by MRV1.

Refs #15665
Refs #16755

- Reuse main's `view_glm5_next_cache()` for kernel-granularity NoPE/indexer views and the packed tail region. Preserve shared MLA/Mamba pages and per-layer bindings.
- Keep copy-on-write layout handling in the existing `models/glm5next/cache_views.py` module, then reuse upstream block copying. Shared MLA/Mamba pages are copied once; separately packed indexer and tail components retain their own strides.
- Reuse upstream `AttentionGroup` directly. SFA/KPool builders restore their layer's logical block size while retaining grouped padding; KPool updates compressed geometry through the existing `set_kernel_block_size()` hook. No factory subclass, concrete-builder dispatch, or `AttentionGroup` symbol replacement remains.
- Carry graph capture lifecycle in KPool metadata, including warmup and rebuilt metadata during multi-step drafting, instead of reading `_EXTRA_CTX.capturing` in the backend.
- Obtain speculative-history requirements from `get_kpool_tail_ring_capacity()` and retain power-of-two ring alignment for the no-prefix coordinator's scheduler-block divisibility contract.
- Generate circular slots in the framework: `request_block[0] * capacity + position % capacity`. This fixes writes to block 0 when compression reads another physical ring. The GLM tail operator and its slot interface remain unchanged.
- Reuse #16755's replicated-tail and empty-component Mooncake handling, and Flash frame sampling for inherited video placeholders.

`AscendBlockTables` owns circular validation and device flags. Only groups with slot mapping enabled participate; disabled groups continue to produce PAD slots. Context parallelism and split physical blocks are rejected only for active circular slot mapping. Ordinary groups retain the `HAS_CIRCULAR=False` specialization. The existing factory and MRV1 proposer are not replaced. Cache views and COW layout handling share the existing model module; this PR does not introduce a layout registry, new capability flags, or a common graph-state enum. No new environment variable or nightly case is introduced.

### Does this PR introduce _any_ user-facing change?

Yes. It enables the tested GLM-5.3-Flash MRV2 graph/MTP path, subject to the source-specific validation below.

SP uses #16804 on a [separate branch](https://github.com/lijiahang226/vllm-ascend/tree/glm53-mrv2-sp-validation). PD end-to-end, Store, CP/PP, other hardware and other quantization formats remain unvalidated. P/D requires compatible tail capacities; Mooncake unit tests do not establish end-to-end PD support.
