# [PR #16823] [Performance][Worker] Restore selective eager DP padding with graph safety

## 正文

### What this PR does / why we need it?

Reintroduce selective MRV1 DP padding on `main` after #15196 was reverted by #16331, retaining the graph safety fallback proposed in #16167.

When DP metadata synchronization is active:

- Keep uniform runner inputs for ACL graphs, ALLGATHER, MC2, CANN MegaMoe and cross-DP fine-grained TP.
- Conservatively retain uniform inputs for routed-expert capture. This does not teach the capture code to remove padding inside individual SP shards.
- Allow per-DP eager token lengths on remaining eligible paths; keep draft-model padding conservative.
- Preserve upstream main's synchronized DP metadata in dummy runs without rewriting any rank's token count. Keep its eager request replication and graph-only zero-length request padding.
- Use the common CPU DP maximum for stage-specific EPLB collection decisions in both normal and dummy execution, so its counters and collective schedule remain aligned without padding the computation.
- Update the extract-hidden-states proposer after removing the old padding-policy argument, with a signature-constrained regression test.

MC2 steps participating in DP synchronization follow #15551's uniform-input / active-mask policy, not #11772's non-hierarchical policy.

Scope boundary: `should_skip_allreduce_across_dp_group` eligibility and its early return are unchanged. The replicated local lengths returned by that fast path are not global DP metadata; the new uniform-input guards run only on synchronized steps. Fine-grained TP groups larger than one retain uniform runner inputs on synchronized steps, padded to the existing DP maximum without additional fine-grained-TP size rounding. This does not override the existing skip-sync early return. Xlite alone does not force runner-level DP padding. Configuration-specific NPU validation, including existing skip-sync combinations, remains pending.

Related: #11772, #14567, #15196, #15551, #16167, #16331. Companion draft: #16822. The existing v0.26.0rc PR is #15551.

### Does this PR introduce _any_ user-facing change?

Eligible eager multi-DP workloads can avoid runner-level padding. No performance or model-accuracy improvement is claimed without NPU measurement. ACL graph, MC2 and routing capture retain uniform inputs on synchronized steps.
