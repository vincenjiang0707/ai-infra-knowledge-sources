# [PR #17051] [BugFix][310P] fix performance degrade issue with MTP for Qwen3.5-2B on the 310P

## 正文


### What this PR does / why we need it?

On Ascend **310P**, enabling MTP (`num_speculative_tokens=1`) for **Qwen3.5-2B-W8A8** can make ais_bench synthetic decode **slower** than MTP-off (higher TPOT / lower output throughput), while larger models such as Qwen3.5-9B still benefit from MTP on the same stack.

**Root cause:** MTP=1 does ≥2 FULL ACLGraph replays per step (target SpecDecoding verify + draft). On 310P SpecDecoding, capture-stable buffer refreshes already run on the **compute stream**, but the path still paid heavy **device-wide `synchronize()`** barriers, plus **update↔compute handshakes even when `UpdatableGraph` has no `graph_task`s** (310P attention typically does not register FIA/PA tasks), plus repeated **D2H / `.item()`** on rejection and draft-prefill metadata. Short 2B kernels make that fixed overhead dominate; 9B compute can hide it.

**What this PR changes:**
1. **Weaken / remove hard sync before FULL replay**
   - `ACLGraphWrapper`: `synchronize()` → `wait_stream(update_stream)`; skip wait when the updatable graph has no tasks; skip empty `graph.update`.
   - Remove speculative `synchronize()` in 310P MRV2 target/draft ACLGraph managers.
   - MRV1 (`NPUModelRunner310`): skip runner-side `update_before_replay` barriers when `use_updatable_graph` (ordering owned by `ACLGraphWrapper`).
2. **Skip empty update↔compute handshake** in MRV2 `ModelAclGraphManager` / draft `AutoRegressiveAclGraphManager` when `resolved_tasks` is empty (no-op for backends that still register FIA/PA tasks).
3. **Host mirrors to cut MTP hot-path D2H** on 310P MRV2: reuse rejection CPU buffers / `set_prefill_host_meta` for draft-prefill; prefer host `query_lens` / `seq_lens_np` / `num_actual_tokens` in attention mask & prefill; avoid `current_draft_step.item()` via `_DRAFT_STEP_HOST`.
4. **Startup fix:** draft `ModelConfig.hf_overrides` may be a **callable** from `SpeculativeConfig.compose_draft_hf_overrides`. Ascend W8A8 has no HF `quantization_config`, so `VllmConfig` rebuild → `get_quant_config` requires dict overrides. Copy draft config and normalize non-dict overrides to `{}` before `replace()` (do not mutate the shared speculative config).
Does **not** change MTP accept/reject semantics or capture-size contract (`cudagraph_capture_sizes` must remain multiples of `(1+K)×batch`).

### Does this PR introduce _any_ user-facing change?

- **Behavior:** No API change. MTP accuracy path unchanged.
- **Perf:** 310P small hybrid models (e.g. Qwen3.5-2B-W8A8) with MTP should no longer regress vs MTP-off / should meet the reference numbers below under the stated bench.
- **Ops:** Recommend `--quantization ascend` (or rely on auto-detect) and, for random synthetic ais_bench, `--no-enable-prefix-caching` to stabilize TTFT (prefix hits are rare on random tokenids).
