# [PR #17436] [BugFix] Require the recompute scheduler only for o_proj/MLP TP

## 正文

### What this PR does / why we need it?

Follow-up to #17361: scope the recompute-scheduler requirement it extended to all four `finegrained_tp_config` knobs back to the two that need it (`oproj` / `mlp`).

- The requirement exists to keep decode-node steps decode-shaped — a uniform-token (o_proj/MLP) concern: their exchanges bind the collectives to the actual per-step token count.
- The lmhead/embedding exchanges are capacity-based — the embedding exchange pads every step to a deployment-wide capacity constant before `all_gather` / `reduce_scatter` and trims after, so the collective shapes are step-count-independent and cannot desync in eager or mixed steps either.
- lmhead was never gated before #17361; the extension rejects the bare-`lmhead_tensor_parallel_size` nightly/weekly recipes (no `recompute_scheduler_enable`) at config load. embedding's coupling predates the visible repo history with no recorded mechanism basis.
- On the PD MRV2 test bed, `embedding=2` without the recompute scheduler is bit-identical to the no-knob no-recompute run — no fine-grained-TP-specific effect. That path has a pre-existing output defect that reproduces with every knob off (tracked separately), so gating embedding does not guard it.

### Does this PR introduce _any_ user-facing change?

Yes: `lmhead_tensor_parallel_size` and `embedding_tensor_parallel_size` no longer require `recompute_scheduler_enable=true` (restores lmhead to its pre-#17361 status); `oproj` / `mlp` keep the requirement.

### How was this patch tested?

The bare-lmhead recipes referenced above pass config load again; the requirement line stays covered by the existing o_proj cases (one test fixture line added by #17361 is reverted to main's version). CI: `pre-commit` and `cpu-ut`.
