## 正文

### What this PR does / why we need it?

Enables the sparse SFA C8 (INT8 packed KV cache) path (#16706) for GLM-5.3-Flash, a kpool-indexer hybrid (KDA + sparse attention) model. **Depends on #16706 (not included here).**

1. **Enablement** (`cf275ac1f`): the existing `use_sparse` gate only covers lightning-indexer models, so no C8 KV spec is ever created for GLM-5.3-Flash.
   - `ascend_config.py`: add a `model_uses_kpool_indexer` disjunct to the SFA C8 derivation (LI C8 stays gated by `use_sparse`).
   - `model_runner_v1.py`: create C8 KV specs without requiring `use_sparse`; forward glm5_next layout markers (`model_version` / `indexes_kv_by_block_stride`, both pre-existing `AscendMLAAttentionSpec` fields, published by the model on the attention layer itself) onto the constructed spec; return the packed row width `(head_size, 0)` from `_get_attention_kv_cache_dims` for c8 specs.

2. **Block sizing for contiguous C8 pages** (`50aab81fb`): the C8 packed page must cover the fp32 KDA state page (~280KiB) that sizes the shared pool slot. A 512-token block packs 264KiB, leaving a 16KiB per-block hole; the non-contiguous view then forces the CANN operator's AutoContiguous to copy the whole KV pool (~2GiB) once per layer per decode step (measured: 87% of device time, single-stream decode collapses to ~5 tok/s). The block is therefore derived from the packed page width: `ceil(280KiB/528B)=544`, rounded up to the hybrid-split alignment = **640 tokens** (640×528=330KiB fully covers the slot); larger requests are capped at this covering size since they only coarsen scheduling granularity. Kernel blocks stay 128 via hybrid split.
   - `patch/platform/patch_mamba_config.py` only.

**Measured results** (A3, TP16, gpu-memory-utilization 0.85, with #16706 applied):
- KV cache capacity: 2.27M (C16) → **4.04M tokens (+78%)**
- Single-stream decode (1k-in/1k-out ×32, ais_bench): **34.89 tok/s** (min 34.82 / max 34.94), E2EL 29.35s — parity with the healthy C16 baseline (~34.4 tok/s)
- gsm8k (128 concurrency): **97.19%** accuracy
- Sanity probes: exact-recall questions (3+5, word problem, 1000×1000) all correct

**Deployment note (important)**: the custom CANN operator package (`vllm_ascend/_cann_ops_custom`, untracked local install) must be rebuilt from source after cherry-picking #16706. Running new host code with a stale operator binary is silently wrong: the pre-PR kernel reads dequant scales at the old hardcoded offset while the host packs them at the new one, corrupting attention outputs (exact-recall tokens such as digits get garbled while semantics survive).
