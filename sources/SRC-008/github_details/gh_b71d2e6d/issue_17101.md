## 正文

### 🚀 The feature, motivation and pitch

## Motivation

When using DeepSeek-V4 with TP, the KV cache is currently replicated across all TP ranks.

For example, with TP=8, each TP rank keeps its own copy of the KV cache. Since the attention KV states are not naturally partitioned by TP in this case, this introduces substantial redundant HBM usage and limits the effective KV cache capacity, especially for long-context workloads.

We'd like to use DCP (Decode Context Parallelism) to shard the KV cache across ranks, so each rank only stores part of the cache instead of keeping a full copy.

I'd like to check the current status in vLLM Ascend:

Is anyone already working on DCP support for the DeepSeek-V4 DSA/hybrid KV-cache path?
If work has already started, what parts are currently supported?

Thanks!
