## 正文

### What this PR does / why we need it?

Support `rope_head_dim=0` in the existing C8 `KvQuantSparseFlashAttention` operator:

- A2/A3: INT8
- A5: INT8 and `FLOAT8_E4M3FN`

Callers can provide 512-element queries and 528-byte packed KV rows without an external RoPE payload. Existing RoPE64 inputs remain 576-element queries and 656-byte packed KV rows.

- Reuse the existing Torch/ACLNN interfaces and quantization modes. The default RoPE dimension remains 64.
- Derive GM strides and scale offsets from the actual input width, and zero the absent RoPE lanes inside the retained 576-wide computation buffers.
- Preserve the existing NoPE512 layout, four FP32 per-tile scales and 128-element quantization tile.
- Add A5 `FLOAT8_E4M3FN` RoPE0 host validation while retaining INT8 RoPE0 and the existing HiFloat8 RoPE64 path.
- Include the A5 build-list and shared-buffer/header compatibility changes required by the existing arch35 implementation.
- Keep model-side changes inside the existing SFA call path for empty-RoPE preprocessing, packed cache writes and custom QSFA dispatch. No A5-specific model entrypoint or loading path is added; the C8 path is reached only when SFA is selected and `enable_sparse_sfa_c8=True`. Context-parallel implementations are unchanged.
- Add direct operator accuracy, compact-versus-zero-padded equivalence, graph replay and invalid-input tests, focused Python UTs, and two real A2 RMSNorm/INT8 quantization/cache/attention pipeline tests.

### Does this PR introduce _any_ user-facing change?

Yes. C8 NoPE accepts Q512 and KV528. Each packed KV row contains 512 one-byte NoPE values followed by four FP32 scales at byte offset 512. The one-byte values are INT8 on A2/A3 and INT8 or `FLOAT8_E4M3FN` on A5. Output width remains 512 and the caller-provided attention scale is preserved.

The existing C8 contract remains `key_quant_mode=value_quant_mode=2`, `quant_scale_repo_mode=1` and `tile_size=128`. A2/A3 retain their existing LSE return contract. A5 uses `sparse_block_size=1` and `return_softmax_lse=False`. HiFloat8 remains limited to RoPE64. Existing nonzero-RoPE behavior remains supported. There is no performance-improvement claim.

For the existing A2/A3 model caller, model-config dimensions must match the layer dimensions. This PR does not adapt mixed global-RoPE64/layer-RoPE0 cache allocation. No dedicated context-parallel rejection is added; the existing context-parallel flow is retained. Real multi-card C8 NoPE execution has not been validated.

### How was this patch tested?

Submitted commit: `0956c7700b33cdcbca787c947b795480220c147b`, one signed-off commit.

- A2: targeted OPP build and installation passed, and **54 NPU tests passed**. NPU coverage includes independent accuracy, compact-versus-zero-padded equivalence, LSE, graph replay, invalid inputs, and two real preprocessing/cache/attention pipeline cases. The final cleanup removes only three CPU cases tied to the deleted hardware-adaptor guard; it does not change the validated kernel/cache path.
- A5: rebuilt the targeted OPP and native extension from the updated INT8/FP8 source, then ran **67 direct operator tests: 67 passed**. Coverage includes INT8 and `FLOAT8_E4M3FN`, RoPE0 and RoPE64 equivalence, accuracy, graph replay and host validation.
- `git diff --check` passed on the submitted tree.

Environments: CANN 9.1.0, Python 3.11.10, torch 2.10.0 and torch_npu 2.10.0.post4; A2 910B4-1 and A5 Ascend 950DT.

From the repository root after building and installing the operator for the device:

```bash
# A2/A3
python -m pytest -v tests/e2e/nightly/single_node/ops/singlecard_ops/test_kv_quant_sparse_flash_attention.py tests/e2e/nightly/single_node/ops/singlecard_ops/test_kv_quant_sparse_flash_attention_rope0_a2a3.py

# A5 direct operator tests; the fixture explicitly loads the native extension.
python -m pytest --noconftest -o addopts= -v tests/e2e/nightly/single_node/ops/singlecard_ops/test_kv_quant_sparse_flash_attention_rope0_a5.py
```

Coverage limits: A3 hardware, full-model generation on A2/A5, real multi-card execution, HiFloat8 RoPE0 and performance have not been validated. The two A2 pipeline tests are operator integration tests, not full-model generation.
