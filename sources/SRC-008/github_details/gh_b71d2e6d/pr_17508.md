### What this PR does / why we need it?

This is PR 1 of the STAIR EPLB series described in vllm-project/vllm-ascend#17506.
It provides the MRV2 data-plane behavior needed by any asynchronous policy:

- spreads initial redundant experts across EP ranks while preserving V1 and
  zero-redundancy layouts;
- keeps the graph-stable routing operation separate from load recording;
- records compact local expert counts already returned by the MoE operator;
- validates the operator count range instead of silently falling back to
  token-level recounting; and
- reports the PP-local DeepSeek V4 MTP MoE layer count to EPLB.

The branch starts from the shared series baseline
`9f1af00c7fcd7c22cf0c791ab9f6c8d98402ec06`. It does not add STAIR policy or
planner code.

Refs vllm-project/vllm-ascend#17506.
Refs vllm-project/vllm#49702.
Refs vllm-project/vllm#51005.

### Does this PR introduce _any_ user-facing change?

Yes. MRV2 EPLB initializes redundant experts across EP ranks and uses
operator-provided expert counts. Existing V1 EPLB behavior is unchanged.

### How was this patch tested?

- `bash format.sh ci`
- Focused CPU unit tests: 23 passed. One existing NPU-event construction test
  cannot run in the CPU-only environment and remains covered by NPU CI.
- Added or updated CPU tests for initial layout, mapping, count recording,
  malformed counts, and PP-local MTP layer count.
- Updated the one-card NPU mapping/recording test for the split operations.

The PR remains draft until repository CI and NPU coverage complete.
