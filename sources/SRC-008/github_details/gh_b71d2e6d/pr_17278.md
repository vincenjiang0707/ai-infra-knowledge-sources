# [PR #17278] [BugFix][310P] fix performance issue for Qwen3.5-2B on the 310P

source: https://github.com/vllm-project/vllm-ascend/pull/17278
state: open | updated: 2026-09-23T02:19:31Z
labels: module:tests

## 正文

### What this PR does / why we need it?

On Ascend 310P, enabling MTP for small models (e.g. Qwen3.5-2B) regresses decode latency because SpecDecoding FULL ACLGraph still pays empty update↔compute handshakes and repeated D2H syncs for rejection/prefill metadata. This PR is scoped to the MRV2 `_310p` path only: skip empty updatable-graph handshakes, reuse host mirrors after the existing rejection `synchronize_cpu`, and avoid redundant stream syncs on the MTP hot path.

### Does this PR introduce _any_ user-facing change?

No. No new public APIs or config knobs; behavior change is limited to 310P MRV2 speculative decoding performance.

### How was this patch tested?
- Unit: `tests/.../test_model_runner_v2_310p.py` updated for the 310P speculator attributes.
- E2E: ais_bench synthetic chat, IO=1024, BS1, TP1, 4 prompts, `VLLM_USE_V2_MODEL_RUNNER=1`, `--no-enable-prefix-caching` on 310P; MTP TTFT/TPOT/throughput improved vs pre-fix MRV2 baseline.

- vLLM main: https://github.com/vllm-project/vllm/commit/84030bbe3d74d99bad477a3d2e37a973ccd8865c

### What this PR does / why we need it?
This pull request optimizes speculative decoding and Multi-Token Prediction (MTP) performance on the 310P platform by avoiding redundant Device-to-Host (D2H) synchronizations and copies. It achieves this by leveraging host mirrors for metadata (such as query lengths and rejection counts), skipping empty update-compute handshakes in updatable graphs, and removing unnecessary stream synchronizations.

However, several critical issues were identified in the review:
- **Data Corruption Risks:** Direct assignments and views of persistent staging buffers (like `_num_rejected_cpu` and `_num_sampled_cpu.numpy()`) can lead to silent data corruption if they are overwritten in subsequent steps. These should be cloned or copied.
- **Runtime TypeError:** The overridden `_updatable_graph_replay` method in `AutoRegressiveAclGraphManager310` lacks the `attn_metadata` parameter, which will cause a runtime crash.
- **Stale State Leakage:** Stale values in `_last_num_rejected_cpu` and `_PREFILL_HOST_META` could leak into subsequent iterations and should be cleared after consumption.

### Does this PR introduce _any_ user-facing change?
No user-facing API changes are introduced. This is a performance optimization for speculative decoding on 310P.

### How was this patch tested?
The changes are covered by existing unit tests, with updates to `test_model_runner_v2_310p.py` to support the new speculator attributes.
