## Summary of Changes

Hello, I'm Gemini Code Assist[^1]! I'm currently reviewing this pull request and will post my feedback shortly. In the meantime, here's a summary to help you and other reviewers quickly get up to speed!

本 PR 旨在 MRV2 (vLLM Ascend) 后端中全面支持 DeepSeek V4.1 模型。通过引入 V4.1 特有的缓存分配逻辑、元数据构建器以及针对图模式的 eager fallback 策略，解决了模型在 Ascend 平台上的适配难题。此外，通过自定义算子化 SP 分片逻辑及 engram 状态镜像，确保了在 FULL_DECODE_ONLY 图模式下的功能正确性与性能稳定性，实现了与 MRV1 的功能对齐。

### Highlights

* **V4.1 缓存与元数据支持**: 在 MRV2 中实现了 DeepSeek V4.1 的 KV 缓存分配与元数据构建，支持 layer-outermost 分配与不同 placement 的共享机制。
* **Eager Fallback 机制**: 针对 V4.1 模型在非均匀 decode 或 prefill 阶段，通过模块级 set_forward_context 注入 eager fallback，确保仅均匀 decode 走 FULL ACL graph。
* **Engram 历史镜像与路由**: 通过 AscendModelState 钩子实现了 engram 历史输入的 device 侧镜像，并确保 dummy 批次正确参与路由集合通信，避免死锁。
* **图模式适配与 SP 算子化**: 通过自定义算子将 SP 分片形状逻辑对 dynamo 透明化，解决了图模式下因形状烘焙导致的 DP 组间 padding 不一致死锁问题。
