# [PR #17502] [BugFix][PCP] support PCP SFA Prolog V3

## 正文

### What this PR does / why we need it?
Fix SFA Prolog V3 support with PCP by keeping query computation local and synchronizing only newly written prefill KV across PCP ranks.
- Support both BF16 and packed C8 caches, using DeviceOperator.reshape_and_cache() for cache writeback.
- Use split_decodes_and_prefills() with PCP-aware short-extend handling.
- Handle padded decode batches without introducing prefill KV collectives into decode-only graphs.

### Does this PR introduce _any_ user-facing change?
Enables PCP with SFA Prolog V3 for both BF16 and C8 KV caches, including configurations with indexer C8 enabled. No new configuration options or API changes are introduced.

### How was this patch tested?
Passed 233 related SFA unit tests.
Passed 18 NPU cache-copy tests covering BF16/FP16 and packed INT8/FP8 storage, including padding and non-contiguous layouts.
Verified two-rank KV synchronization and C8 cache writeback on Ascend NPU.
Passed seven GLM-5.2 serving cases with TP4/PCP2, SFA C8 and indexer C8 enabled, covering a 17,542-token prompt, long decoding, concurrent mixed prefill/decode workloads, and decode graph replay.
