## 正文

### What this PR does / why we need it?

vLLM Ascend currently has an exact csrc artifact cache. It is very fast on an exact match, but any tracked csrc change invalidates the whole artifact and forces the native source build to start from scratch.

This PR adds a persistent, fine-grained L1 cache for csrc compilation while keeping the existing exact artifact cache as L0:

```text
L0 exact final artifact
        |
        | miss
        v
L1 persistent per-action cache
        |
        v
ordinary source build
```

L0 remains the only cache layer that can skip the whole native build. On an L0 miss, L1 restores a compatible set of candidate entries, then the normal source build runs. Each compiler action independently recomputes its identity and either reuses a verified entry or executes the original compiler command.

The source build therefore remains authoritative: an L1 miss, unavailable remote cache, or unsupported source snapshot falls back to the ordinary build.

### Cache identity and correctness

Each cached action is keyed by three semantic identities:

```text
prepared_input_hash
recipe_hash
compiler_environment_hash
```

The local cache engine in `csrc/scripts/build_cache.py` validates the action key, schema, artifact model, manifest, and artifact contents before accepting a HIT.

Prepared inputs cover generated operator sources, shared kernel sources, recipe files, and shared compatibility headers such as `cann_compat.h`. Explicit checkout/build roots may be normalized for UTF-8 text so equivalent workspaces can share entries, while binary content, external paths, symlink identity/targets, and semantic file contents remain sensitive.

The cache also preserves the build's concurrency and publication invariants:

- atomic local entry save;
- entry/action/publish locks with separate failure semantics;
- private staging for custom operators;
- artifact ownership tracking and collision detection;
- safe manifest/path validation before restored artifacts are used.

The persistent outer snapshot is only a transport/candidate-selection layer. It is not the correctness authority; inner action validation always decides whether an entry may be reused.

See the [design document](docs/source/developer_guide/Design_Documents/persistent_csrc_build_cache.md) for the full contract.

### Persistent L1 transport

CI persists the local action cache through `runs-on/cache` using the existing Huawei OBS S3-compatible backend.

`prepare_csrc_l1_restore.py` is the shared key-preparation helper. It:

- detects whether the tested source contains the cache engine;
- derives the tracked-csrc identity;
- builds the compatibility/snapshot keys; and
- exports the local cache and telemetry paths.

Persistent callers use workflow-owned same-repository actions:

```text
$/.github/actions/csrc-l1-restore
$/.github/actions/csrc-l1-save
```

This intentionally separates workflow implementation from the source being tested. A caller may build a PR, fork, external repository, or historical ref without requiring that source snapshot to carry the current CI action implementation.

The restore action resets the `.updated` marker. The local engine creates that marker only when a new/replaced entry is successfully saved. Trusted writers therefore publish an updated shared snapshot only when the local L1 actually changed; an all-HIT build does not republish the same cache.

Historical source that predates `csrc/scripts/build_cache.py` is explicitly unsupported by L1:

```text
supported=false
→ skip L1 export/save
→ continue the original wheel/image/source build unchanged
```

No cache engine is injected or backported into old source snapshots.

### Trust and failure model

Shared L1 publication is limited to trusted producer paths, including the central csrc producer, image builds, and release wheel builds. PR-triggered nightly, selected tests, doctest/source consumers, and other consumer paths restore only.

The failure boundary is intentional:

```text
cache availability / performance failure
→ fail open to ordinary source compilation

integrity / correctness violation
→ fail safely
```

Examples of fail-open cases include remote MISS, unavailable OBS transport, missing writer credentials, unsupported historical source, or an unavailable optional snapshot.

Unsafe manifests, artifact ownership collisions, or synchronization failures that would make publication correctness ambiguous are not treated as cache misses.

### Does this PR introduce _any_ user-facing change?

No model-serving API or runtime behavior changes.

This PR only changes native csrc build/CI caching and related diagnostics.
