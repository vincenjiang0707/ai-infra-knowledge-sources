## 正文

### What this PR does / why we need it?

- Update the A3 single-node GLM-5.2 example to the verified W8A8C8 checkpoint with DP1/TP16 and a 32K context. The previous 135K setting exceeded available KV-cache memory on the tested 64 GB × 16 setup.
- Update the A3 dual-node co-located example to W8A8C8, DP4/TP8 with EP and INT8 KV/indexer cache.
- Remove `fuse_muls_add` from the dual-node example and start an API server on each node instead of using `--headless` on node 1; both options blocked startup in the tested vLLM 0.29 image.

### Does this PR introduce _any_ user-facing change?

No runtime code change. It updates deployment documentation.

### How was this patch tested?

- Image: `vllm-ascend:dev-26.2.0.day20260923-800I-A3-py311-Ubuntu24.04-lts-aarch64` (vLLM 0.29).
- Single A3, DP1/TP16, W8A8C8, INT8 KV/indexer, 32K max length: service started; one chat-completion request returned HTTP 200 with `OK` and `finish_reason=stop`.
- Two A3 nodes, DP4/TP8/EP, W8A8C8, INT8 KV/indexer, 135K max length: all four DP ranks loaded, graph capture completed, both API servers started; a chat-completion request to each node returned HTTP 200 and `finish_reason=stop`.
- `git diff --check` passed. No automated test was added because this is a documentation-only change.
- The HTTP checks establish startup and response-path functionality, not model accuracy or throughput.

- vLLM main: https://github.com/vllm-project/vllm/commit/ced6857afa0ea7b2e3f0846a62e1394e90f15607
