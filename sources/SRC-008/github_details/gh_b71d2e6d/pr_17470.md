### What this PR does / why we need it?

Diagnostic PR only; please do not merge until the Nightly comparison is evaluated.

Reverts #17066 (ad7a731b9c0db2592bbe1f568a776207745017ed) on main e152f7f2db5b6e036cf367fa915d5a6cac88d81d to test whether the MRV1 dirty block-table optimization contributes to the DeepSeek-V4-Pro-w4a8-prefix-cache-PD throughput regression.

Runs [35894461799](https://github.com/vllm-project/vllm-ascend/actions/runs/35894461799) and [35913906630](https://github.com/vllm-project/vllm-ascend/actions/runs/35913906630) reported approximately 703.61 and 719.66 output tokens/s. These observations motivate the experiment; they do not establish #17066 as the root cause.

The revert restores the previous full block-table copy path and removes the optimization-specific configuration, kernel, documentation and tests. Nightly YAML, warmup, baseline, FlashComm configuration and vLLM version are unchanged relative to the base commit.

### Does this PR introduce _any_ user-facing change?

This test branch restores pre-#17066 MRV1 block-table behavior and removes the block_table_no_commit_optimize option introduced by that PR. It is an experimental regression-isolation branch, not a confirmed fix.

### How was this patch tested?

- Clean revert with no conflicts.
- git diff --cached --check passed.
- Python AST parsing passed for all three remaining modified Python files.
- No remaining references to the removed configuration option or block_table_scatter kernel in implementation/tests.
- NPU unit tests and performance validation have not been run locally. Community CI/Nightly results are pending.
- Full format.sh ci could not run locally because pre-commit is not installed; lint CI is pending.

