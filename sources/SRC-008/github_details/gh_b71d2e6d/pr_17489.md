## 正文

### What this PR does / why we need it?
Add DCP Q replication support for Ascend dense MLA and sparse SFA/DSA attention.
When enabled, Q projection weights are partitioned by DCP group so each rank computes the group's Q heads locally, avoiding the decode Q all-gather. The implementation gathers the corresponding UK weights and preserves local-head Q projection for prefill, including chunked prefill and mixed batches. Keeping the original prefill projection width also avoids BF16 rounding differences introduced by a wider GEMM.

### Does this PR introduce _any_ user-facing change?
Ascend supports the upstream dcp_q_replicate option and VLLM_DCP_Q_REPLICATE environment variable. An explicitly set environment variable takes precedence. The optimization is activated only when PCP=1 and DCP>1.
The current implementation targets unquantized MLA with native preprocessing. Quantized weights/KV caches, MLAPO/prolog fusion, LoRA adapters, and DSA-CP token sharding are not supported in this combination. Sparse attention additionally follows the existing DCP=TP topology requirement and requires the supported RoPE/Q-LoRA path.

### How was this patch tested?
- Unit tests: 456 tests passed across eight related test files, covering weight partitioning, local/group Q projections, weight loading, dense/sparse attention integration, and runner configuration.
- Model tests: 31 retained parameter combinations have passing results:- 10 dense MLA/ngram cases with the complete DeepSeek-V2-Lite model.
  - 12 sparse attention cases with a reduced-layer GLM functional checkpoint.
  - Eight overlay cases, including chunked prefill, prefix caching, graph modes, MRV2, and LMHead TP configuration.

- Numerical validation: WikiText-2 evaluation on DeepSeek-V2-Lite covered 311,124 scored tokens. Q replication OFF/ON produced identical recorded token scores, with no violations of the 0.05 absolute-error threshold.
- Performance: 36 serving measurements across six tested workload/mode combinations showed average throughput improvements of 5.6%–9.1%, with lower TTFT and TPOT.

### What this PR does / why we need it?
This pull request introduces `dcp_q_replicate` (Decode Context Parallel Q Replication) for both Multi-Head Latent Attention (MLA) and Sparse Flash Attention (SFA) on Ascend NPUs. By replicating the query (Q) projection weights across the DCP group, each rank can compute the full group's Q heads locally, eliminating the need for an all-gather communication step of the query projections during decode.

Feedback on the implementation:
1. **Avoid Slicing Private Formats**: In `vllm_ascend/ops/dcp_linear.py`, slicing/chunking is performed on a tensor cast to `ACL_FORMAT_FRACTAL_ND`. Slicing private formats on Ascend is highly discouraged due to risk of data corruption; chunking should be done on the standard ND tensor first.
2. **Ensure Contiguous Query Tensors**: In both `mla_cp.py` and `sfa_cp.py`, bypassing the gather steps when Q replication is active leaves the query tensors as non-contiguous transposed views. These must be made contiguous to prevent downstream custom NPU attention kernels from crashing or producing incorrect results.

### Does this PR introduce _any_ user-facing change?
Yes, it adds the `dcp_q_replicate` configuration option (and `VLLM_DCP_Q_REPLICATE` environment variable) to enable Q replication during decode context parallel execution on Ascend.

### How was this patch tested?
The changes are covered by newly added end-to-end tests (`test_dcp_q_replicate.py`, `test_dcp_q_replicate_mtp_controlled.py`, `test_dcp_q_replicate_overlays.py`, `test_sfa_dcp_q_replicate.py`) and unit tests (`test_dcp_linear.py`, `test_sfa_dcp_q_replicate.py`).
