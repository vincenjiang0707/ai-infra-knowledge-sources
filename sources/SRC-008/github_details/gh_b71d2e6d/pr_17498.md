# [PR #17498] [BugFix] Keep tid2eid when ModelSlim FLOAT MoE layers skip quantization

## 正文

### What this PR does / why we need it?
Fixes #17476  
BF16 checkpoints converted by msmodelslim include `quant_model_description.json` with weight entries set to `FLOAT`. That file selects `AscendModelSlimConfig`. When a MoE layer is skipped as unquantized, `get_quant_method` built `AscendUnquantizedFusedMoEMethod` without `tid2eid`.

The plain BF16 path keeps this hash-routing table. Dropping it makes `scoring_func=sqrtsoftplus` hash layers (`layer_idx < num_hash_layers`) call `moe_gating_top_k_hash` with an empty table, so expert ids come from logits instead of `tid2eid[token_id]`. Softmax and sigmoid routing are unchanged.

### Does this PR introduce _any_ user-facing change?

No

### How was this patch tested?

Added `test_get_quant_method_for_float_moe_keeps_tid2eid`.

### QwertyJack · 2026-09-24

Thanks for tracking this down. Please target `releases/v0.26.0rc` and adapt the patch and regression test to that branch.

On current main, expert selection happens in the separate router, which already receives the hash-routing table. `AscendUnquantizedFusedMoEMethod.tid2eid` is stored but no longer read during routing, so this change does not affect expert selection there.

The reported bug is present on v0.26: the FLOAT skip path drops `tid2eid`, while `AscendUnquantizedFusedMoEMethod.apply()` still forwards that field to `select_experts()`. Passing it through is the right fix for that branch. Ideally, the regression test should verify that the FLOAT path preserves the table through to expert selection, failing before the fix and passing afterward.
