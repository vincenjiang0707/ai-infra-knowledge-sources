# [PR #17497] [BugFix][Mooncake] Handle empty receives with decode-only DCP

## 正文

### What this PR does / why we need it?

A rejected remote-prefill request can enqueue an empty receive so the decode worker notifies the prefill worker to release its KV cache. With decode-only DCP, the block mapper still indexes the empty local block list using the remote prompt blocks, raising `IndexError` and terminating the decode engine.

Skip mapping an attention group with no local blocks, while preserving the selected source ports and empty block lists so the existing receive path can send completion notifications. This fixes the observed PCP=2 / DCP=8 rejection-cleanup crash.

### Does this PR introduce _any_ user-facing change?

The decode engine survives empty receives for rejected requests with decode-only DCP. No configuration or API changes.

### How was this patch tested?

- Added a worker regression test covering all eight DCP ranks, P-side PCP=1/2, and MLA/SFA layouts. It checks that empty receives are queued on the selected source port with completion enabled.

- `git diff --check` passed.
- Remote before/after check in the supplied Ascend container: the installed baseline reproduces the original `IndexError`; the exact PR connector passes all 32 regression combinations.
- Five targeted tests pass on each supplied host, covering rejected-request metadata, empty-transfer completion, normal SFA/DCP mapping, and PCP replica routing/completion.
- Full connector module: baseline **127 passed / 7 failed**, patched **128 passed / 6 failed**. The six unchanged failures concern existing cache-layout/version compatibility tests; this is not a clean full-suite pass.
- Command: `PYTHONPATH=$PWD python -m pytest --noconftest --import-mode=importlib -q ../tests/ut/kv_offload/test_mooncake_connector.py`, from an isolated copy of the installed package with the PR connector substituted.
