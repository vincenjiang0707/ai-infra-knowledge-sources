# [PR #17499] [Performance][KV Pool] Avoid repeated block_hash_to_str in _alloc_gvas_for_save

## 正文

## What this PR does / why we need it?
`_alloc_gvas_for_save` converted each block hash to a key string up to 3x per
save: once when building `candidate_keys`, again in the cached-prefix skip
loop, and again in the allocation loop. This reuses the already-built
`candidate_keys` (plus a `transfer_keys = candidate_keys[allocated_prefix:]`
slice) in the two loops, so each block hash is converted exactly once.
`transfer_blocks` is preserved for the padding step.
Contribution task #14148. Generated keys, `save_keys` and `block_gvas` are
unchanged (existing tests stay green).
## Does this PR introduce _any_ user-facing change?
No.
## How was this patch tested?
- New UT in `tests/ut/distributed/ascend_store/test_pool_worker.py`:
  `test_alloc_gvas_for_save_converts_each_hash_once` and
  `..._with_cached_prefix` patch `block_hash_to_str` and assert each block
  hash is converted exactly once (all-new and cached-prefix paths).
- Existing `test_alloc_gvas_for_save_without_mask_allocates_all` /
  `..._respects_store_mask` still pass (behavior unchanged).
- `ruff check` and `ruff format --check` pass.

- vLLM main: https://github.com/vllm-project/vllm/commit/ced6857afa0ea7b2e3f0846a62e1394e90f15607
