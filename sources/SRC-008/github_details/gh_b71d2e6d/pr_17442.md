## 正文

### What this PR does / why we need it?

Reverts #17128 (commit dfb7219e4e354bd78f2a0fef487d9cc134a1854c).

#17128 reclassified the PD prompt-boundary recompute request as decode so that a mixed decode batch could keep hitting `FULL_DECODE_ONLY` graphs. That reclassification breaks the recompute itself on the D node.

- With PD separation, a request arrives on the decode node with the KV transferred from the producer and `num_computed_tokens == prefill_len - 1`, so the current step recomputes the last prompt token (`query_len == 1`).
- Upstream writes that token into `input_ids` only inside `prepare_prefill_inputs()`, which `GPUModelRunner` calls behind `if np.any(is_prefilling_np)`.
- #17128 set `is_prefilling_np[...] = False` for exactly that request and refreshed `has_prefill`. When the batch contains no other prefilling request, nothing is prefilling any more: `prepare_prefill_inputs()` is skipped entirely, and `_combine_sampled_and_draft_tokens_kernel` also returns early for this request because `seq_len <= prefill_len`.
- The last prompt token therefore never reaches this step's `input_ids`. The slot keeps whatever was left in the buffer from a previous step instead of `all_token_ids[num_computed_tokens]`, and the first decode token is recomputed from the wrong input.

The reclassification is the only thing this PR changes, so this PR reverts it, together with the three unit tests that locked the new classification in, restoring the pre-#17128 baseline.

A follow-up is still needed to re-solve the missed `FULL_DECODE_ONLY` graph **without** dropping the prefill flag of the prompt-boundary recompute request, e.g. relax only the graph-dispatch decision while keeping `is_prefilling_np` intact for the `input_ids` write path.

Reverts #17128

### Does this PR introduce _any_ user-facing change?

Yes, it restores pre-#17128 behavior: with `recompute_scheduler_enable=true` on a PD decode node, the prompt-boundary recompute fills the correct last prompt token into `input_ids` again, and in exchange a mixed decode batch misses `FULL_DECODE_ONLY` graphs as it did before #17128.

### How was this patch tested?

Pure revert of a merged commit. `git revert` was resolved against the current `main`; only the `vllm_ascend.utils` import list conflicted, because it was touched by later PRs (#17174, #17361), and it is resolved by dropping the now-unused `is_pd_decode_recompute_scheduler_enabled` import while keeping the unrelated imports.

- `python -m py_compile vllm_ascend/worker/v2/model_runner.py tests/ut/worker/test_model_runner_v2.py` passes.
- `tests/ut/worker/test_model_runner_v2.py` is restored to its pre-#17128 content, so the existing CI unit tests cover the change.

The full revert diff is 2 files changed, 2 insertions(+), 97 deletions(-), i.e. exactly the inverse of #17128.
