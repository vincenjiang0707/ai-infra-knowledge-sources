# [PR #17483] [BugFix] Reshape bf16 wo_a to 3D layout for ModelSlim-quantized DSV4

source: https://github.com/vllm-project/vllm-ascend/pull/17483
state: closed | updated: 2026-09-24T12:01:52Z
labels: module:tests, module:ops, ready-precise

## 正文

### What this PR does / why we need it?

DSV4 `wo_a` weights must be loaded in the 3D layout`[n_local_groups, hidden_size, o_lora_rank]` for `npu_transpose_batchmatmul`. The bf16 reshape path introduced by PR #13716 required `quant_config is None`, so partially-quantized checkpoints (e.g. ModelSlim) that keep FLOAT `wo_a` alongside a global quant config skipped the reshape. The 2D weight then crashed the A5 forward (`IndexError` in `npu_transpose_batchmatmul` `perm_x2`) during ACL graph capture.

Drop the `quant_config is None` condition and judge by dtype only: bf16 `wo_a` is never quantized and has no `process_weights_after_loading` fallback, so it must be reshaped at load time regardless of the global quant config. fp8/int8 `wo_a` still resolves False here and is handled by the quantization path.

### Does this PR introduce _any_ user-facing change?

no

### How was this patch tested?

- Unit test: `tests/ut/ops/test_linear.py::TestShouldReshapeWoATo3d` (new regression test covering: bf16 `wo_a` with a global quant config, non-A5 bf16 `wo_a`, fp8 `wo_a`, and non-`wo_a` layers)
- Manual testing on Ascend A5 (Ascend950) with ModelSlim-quantized DeepSeek-V4: service starts without crash; `wo_a.weight` shape is 3D `[n_local_groups, hidden_size, o_lora_rank]`; dummy run passes
- CI for the rest

- vLLM main: https://github.com/vllm-project/vllm/commit/ced6857afa0ea7b2e3f0846a62e1394e90f15607
