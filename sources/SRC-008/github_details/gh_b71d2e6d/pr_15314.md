## 正文

### What this PR does / why we need it?

DFlash `prepare_dflash_inputs` serialized most Context, Query, Sample, and graph-padding work per request. This PR keeps the optimized implementation and uses a VectorCore-aware 2-D grid `(request, worker)`. Quotient/remainder partitioning assigns disjoint, balanced spans in each domain. The existing worker-level patch forwards calls to this launcher.

After rebasing onto current vLLM-Ascend main (`abe8ff18a`), the wrapper retains main's `BatchExecutionDescriptor` and `_build_uniform_attn_metadata` flow. The optimized kernel also follows main's CP-aware logical-block indexing and upstream `cp_local_slot`, including rank ownership and interleave. The operator documentation describes this behavior and the remaining multimodal/M-RoPE limitation (see #9340).

### Does this PR introduce _any_ user-facing change?

No new API or CLI option. DCP KV-slot behavior in the optimized path now matches main.

### How was this patch tested?

- At `38897d1fe`, `pytest -sv --noconftest tests/e2e/nightly/single_node/ops/singlecard_ops/triton/test_prepare_dflash_inputs.py`: **22 passed** on Ascend NPU with vLLM `84030bbe`. Outputs matched an independent Python reference bit-exactly (`rtol=atol=0`).
- At `27e168248`, the test inputs were corrected to match upstream rejection-sampler invariants (`num_rejected < context length`, and zero rejected tokens during chunked prefill). On Ascend 910B4-1, main's scalar JIT and the unchanged optimized kernel each passed **22/22** exact-reference input checks. This was a kernel-level harness with vLLM `2cf0a691`; the full wrapper pytest has not been rerun at the new HEAD.
- The cases cover B8/T1626 and B64/T576, partition boundaries, long context, rejected tokens, null blocks, `num_context = num_speculative_steps + 1`, CP rank ownership, interleave sizes 1/2/4, cross-block positions, and wrapper forwarding.
- Ruff check/format and `git diff --check` passed for the test-input correction. Earlier pre-commit code/style checks and manual markdownlint passed; the gitleaks hook could not complete because its binary download timed out.
- Same-device `msprof op` kernel comparison using identical inputs and the same vLLM source; the profiler used five warm-up launches before measuring each target kernel:

| Case | main Ascend scalar kernel | optimized 2-D kernel | main / optimized |
| --- | ---: | ---: | ---: |
| B8 / T1626 | 1139.62 μs | 22.00 μs | 51.8× |

The main Ascend scalar JIT function was taken unchanged from main and launched through upstream `prepare_dflash_inputs`; both cases passed the independent reference check. The ratio is main / optimized. Each table entry is one profiled kernel capture after warm-up. These are kernel-level measurements, not full-model throughput results. Earlier captures used different conditions and are not directly comparable.

On the recorded first-decode business dump (1 active request, 5 context tokens; configured capacities 256 requests / 8192 tokens; 7 speculative steps), both main's original scalar kernel and this PR's 2-D kernel matched the independent CPU reference exactly. The standalone operator harness used the saved tensor shapes/dtypes and source extracted from PR HEAD `27e168248` and main `abe8ff18a`.
