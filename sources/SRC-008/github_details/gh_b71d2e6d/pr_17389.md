# [PR #17389] [BugFix][Platform] Keep MiniMax-M3 GQA KV cache in BF16 on A5

## 正文

### What this PR does / why we need it?

Split the MiniMax-M3 A5 mixed KV-cache policy out of #16904 so it can land independently of the pending CANN operators.

When MiniMax-M3 runs on Ascend A5 with FP8 KV cache, sparse-attention layers retain the configured FP8 policy while GQA layers are added to `kv_cache_dtype_skip_layers` and therefore use BF16. Existing user-provided skip layers are preserved and deduplicated.

The policy is limited to the two MiniMax-M3 architectures, FP8 KV-cache configurations, and hardware with FP8-attention capability. It has no dependency on `aclnnMsaIndexScore` or Generic Block Sparse Attention.

### Does this PR introduce _any_ user-facing change?

Yes. MiniMax-M3 deployments on Ascend A5 that request FP8 KV cache will use BF16 KV cache for GQA layers. Other models, non-FP8 KV-cache configurations, and non-A5 devices are unchanged.

### How was this patch tested?

- `python -m compileall -q vllm_ascend/platform.py`
- `ruff check vllm_ascend/platform.py`
- `ruff format --check vllm_ascend/platform.py`
- `git diff --check`
- Focused configuration checks covering MiniMax-M3 A5 mixed-layer selection, preservation/deduplication of existing skip layers, unrelated architectures, and non-A5 hardware.

No dedicated `test_platform.py` cases are added because this is the same locally validated platform policy split from #16904; the PR intentionally keeps the change focused and avoids the broad assertion-only test expansion removed during that review.
