## 正文

### Summary

Preserve each model's router precision policy instead of forcing all internal gates to FP32. Models that explicitly prepare `weight_fp32` retain that path; other models use their native gate implementation and avoid the unused activation cast. Runtime code and unit tests are restored exactly to the original commit `79d3334bc86cede8575e05b581d486571b66e91e`.

Update the Qwen3.6-35B DSpark per-position acceptance baseline from `[0.78, 0.61, 0.49, 0.39, 0.33, 0.29, 0.25]` to `[0.78, 0.57, 0.42, 0.29, 0.22, 0.18, 0.15]`. The new values are the rounded per-position mean of four native-gate measurements: two repeats on vLLM main `84030bbe` and two on v0.28.0. The existing one-sided `0.03` tolerance, prompts, generation parameters, and dependency markers remain unchanged.

This explicitly establishes the lower native-router DSpark acceptance baseline; it does not claim to recover FP32-router acceptance or prove unchanged end-to-end speculative throughput or model quality.
