# [PR #17519] fix(attention): maintain per-query causal KV boundaries in FIA for DFlash

state: open | updated: 2026-09-24T15:35:19Z

## 正文

## Problem

When multiple queries are folded into a single `npu_fused_infer_attention_score` (FIA) call — which happens in DFlash speculative decoding verify, and in grouped prefill — query groups can incorrectly share a causal KV length. Queries that should see different KV extents end up in the same group, producing wrong attention outputs (token-level diff vs eager reference).

Additionally, the CANN FAI kernel processes KV in `MAX_KV_STACK_LEN=512` chunks and uses special reduction trees when the tail block has exactly 256 or 512 columns. Rows ending at those positions must be isolated into separate groups to keep bf16 online-softmax reduction order deterministic across different query groupings.

## Root cause

In `vllm_ascend/attention/attention_v1.py`, when constructing FIA metadata for multi-query batches:

1. **Causal boundary violation**: queries with different causal KV visibility were grouped together in a single FIA call, so earlier queries could see KV belonging to later queries
2. **Reduction order instability**: query groups crossing 256/512-column tail boundaries changed the online-softmax reduction path (`CalcLocalRowSum` special tree vs `RowsumTAILTILE`), producing bf16 drift

## Fix

This PR adds per-query causal metadata expansion before the FIA call:

- `kv_boundary_metadata.py`: plans query groups that respect both causal boundaries and the 256/512 special reduction positions. Short queries (≤16) and long prefill queries (≤128) are grouped, but never across a causal boundary or a special reduction position
- `query_invariant.py`: `expand_query_metadata()` builds the expanded read-only metadata; `query_invariant_attention()` calls FIA with per-group `actual_seq_lengths` and `actual_seq_lengths_kv`
- `graph_query_metadata.py`: graph-capture-safe metadata builder (strongly-owned table, refreshed per step)
- `attention_v1.py`: hooks the fix into the eager forward path

Key properties:
- **Read-only**: metadata is reused across layers, never used for cache writes
- **No KV ownership change**: block tables, slot mappings, prefix cache behavior all unchanged
- **Coverage**: applies to all causal target queries (verify, prefill, chunked prefill), not just short verify blocks

## Reproduction evidence

- 155-request full corpus, cold+hot, target+dflash: 620 complete EOS responses, all token-exact with eager reference
- DFlash QPM improved from 43.5 (corrected naive per-query) to 76.4 (boundary grouping)
- NPU matrix tests: 160 boundary cases all bit-exact, including 256/512 tail positions, mixed verify, padding, owner reorder
