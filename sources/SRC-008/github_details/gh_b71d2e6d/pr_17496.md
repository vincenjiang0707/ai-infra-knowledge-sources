### What this PR does / why we need it?

This pull request implements the Ascend decoder bounded replay mechanism for the DeepSeek V4.1 model. It introduces `AscendDecoderReplayLayers` to manage replaying layers during prefill, integrates Triton-based batch gathering (`gather_replay_batch`), and updates the `NPUModelRunner` to initialize and prepare the decoder replay metadata. Additionally, it refactors the model's forward pass to split layer execution and support replaying.

Several critical issues were identified during the review:
- A missing import for `should_skip_allreduce_across_dp_group` in `model_runner_v1.py` which will cause a `NameError`.
- Invalid accesses to `self.parallel_config.data_parallel_rank` in `model_runner_v1.py` which will cause `AttributeError`s.
- Unused local variables `ori_block_table` and `seq_lens` in `dsa_v41.py`.
- A potential out-of-bounds `RuntimeError` in `decoder_replay_layers.py` when `enable_dsa_cp()` is enabled due to sharded buffer slicing.

### Does this PR introduce _any_ user-facing change?

No, this is an internal optimization and feature implementation for DeepSeek V4.1 on Ascend NPUs.

### How was this patch tested?

The changes were tested using existing unit tests, with updates to `test_deepseek_v41_hyper_connection.py` and `test_model_runner_v1.py` to mock the new decoder replay parameters.
