## 正文

### What this PR does / why we need it?

Enables **DeepSeek-V4.1-Flash + DSpark on Ascend950 (A5)**.

Before this change the model starts but is unusable: generation is garbled and loops, and DSpark accepts only the first speculative position.

#### Root cause of the garbled output

The A5 `HcPre` kernel ignores the `pre_mix` weights it is given and collapses the four hyper-connection streams by its own internally computed coefficients. At layer 0 all four streams are the token embedding, so the layer input becomes

```
y = (sum of the kernel's own coefficients) x embedding = 0.356 x embedding
```

instead of `1.0 x embedding`. Every layer is fed its input scaled down by ~2.8x, and the error compounds through the stack. The same kernel also leaves its optional mixing-coefficient output unwritten.

`DeepseekV41DecoderLayer.hc_pre` now performs both reductions itself. The combination is the same weighted sum `hc_collapse` already implements, so no numerical behaviour is invented:

```python
y = (pre_mix.unsqueeze(-1) * x.float()).sum(-2).to(x.dtype)
```

DSpark is fixed by the same change: the draft model consumes the main model's hidden states, so once those were wrong the draft could not match beyond the first position.

#### The rest of the A5 enablement

| Area | Change |
| --- | --- |
| Attention | Use `SparseFlashMla` on A5 instead of `npu_sparse_attn_sharedkv`, with `PA_BBND` layout and sliding-window `ori` masking |
| CSA odd-length trap | Duplicate one query per request so no request ever presents an odd packed query count (AI core 507015) |
| Compressed KV geometry | Derive the storage block size from `tokens_per_state`; a compress-ratio-2 plane stores half a logical block per page |
| MoE dispatch | Fall back to AllGather on A5, where `aclnnMoeDistributeDispatchV4` fails with 561000 (gated on `DSV4_COMPRESSED_CACHE`, other SoCs unaffected) |
| Quantization | Select the FP8 scheme from the checkpoint's `weight_block_size`; released V4.1-Flash ships 32-wide blocks and must skip the 128x128 to 32x1 scale reorganization |
| Indexer | Select TopK straight from the compressed stream: `quant_lightning_indexer_v2` only implements the two-level candidate path in its arch22 kernel |
| Plan construction | Resolve `npu_sparse_attn_sharedkv` at call time, since V4.1 builds the DSA plan while configuring the KV cache |
| Custom ops | Add `sparse_flash_mla`, `sparse_flash_mla_metadata` and `rms_norm_cast` to the ascend950 build list |

### Does this PR introduce any user-facing change?

No new flags or configuration. DeepSeek-V4.1-Flash simply works on A5.

### How was this patch tested?

Hardware: Ascend950PR, 8 cards, TP8 + EP, released `DeepSeek-V4.1-Flash` weights.

```bash
vllm serve /data/DeepSeek-V4.1-Flash \
  --served-model-name dsv41 --host 0.0.0.0 --port 8000 \
  --tensor-parallel-size 8 --enable-expert-parallel \
  --block-size 128 --max-model-len 1000000 \
  --max-num-batched-tokens 4096 --max-num-seqs 10 \
  --gpu-memory-utilization 0.92 \
  --no-disable-hybrid-kv-cache-manager \
  --compilation-config '{"cudagraph_mode":"FULL_DECODE_ONLY","max_cudagraph_capture_size":64}' \
  --tokenizer-mode deepseek_v41 --reasoning-parser deepseek_v41 \
  --tool-call-parser deepseek_v41 --trust-remote-code \
  --safetensors-load-strategy lazy \
  --quantization deepseek_v4_fp8 \
  --speculative-config '{"method":"dspark","num_speculative_tokens":5,"enforce_eager":true}'
```

**Generation quality.** A 1M-token context serves with the KV pool clamped to 9,592,505 tokens (9.59x concurrency for 1M-token requests). An 800-word Chinese essay prompt finishes on its own at 1247 tokens, 50.9 tok/s, with every date and name correct. Mixed long/short/long requests answer correctly and hit the prefix cache (0.2s on the repeated 532-token prompt).

**Dataset accuracy (GSM8K).** 5-shot GSM8K over `/v1/chat/completions`, `temperature=0`, thinking disabled, answer taken as the last number in the reply, scored against the `####` gold value:

| Setting | Samples | exact_match |
| --- | --- | --- |
| 5-shot | 200 | **190 / 200 = 95.0%** |
| 5-shot | 50 | 50 / 50 = 100% |

One of the ten misses is a formatting difference only (`57.00` against a gold of `57`). Two replies out of 200 hit the 512-token cap; the mean reply is 121 tokens, so generation terminates on its own.

This was measured on the command above with `--max-model-len 69632` and `--no-enable-prefix-caching`.


**Concurrent serving.** SparseFlashMla does not keep requests independent when several are packed into one TND batch: only the request at row 0 is computed from its own rows. A batch of identical requests is unaffected, so this stayed hidden until concurrent requests carried different content. Attention now issues one call per request. With 16 requests in flight at once (6 five-shot GSM8K, 6 short factual questions, 4 open-ended 150-word answers):

| Workload | Result |
| --- | --- |
| 5-shot GSM8K | 5 / 6 correct, every reply ended on its own |
| Short factual questions | 6 / 6 correct, 2 - 3 tokens each |
| Open-ended answers | 4 / 4 coherent, all ended on their own |

Before the fix the same 8-way GSM8K load scored 3/40 with 32 of the 40 replies running to the token cap, and open-ended answers degenerated into a repeated token.

**Agreement with a known-good reference.** Compared against a working DeepSeek-V4.1-Flash deployment on the same weights:

| Metric | Before | After |
| --- | --- | --- |
| Layers with identical routed-expert sets | 3/40 | 30/40 |
| Mean expert overlap | 3.0/6 | 5.72/6 |
| DSpark per-position acceptance | 0.135, 0, 0, 0, 0 | 0.61, 0.35, 0.17, 0.09, 0.05 |
| Mean acceptance length | ~1.1 | 1.8 - 2.3 |

Short-prompt logit distributions now match the reference to within bf16 noise, including top-5 ordering.

**Unit tests.** `tests/ut` was run against this branch and against unmodified main in the same container to separate pre-existing failures (missing `acl` module and LoRA ops in that image) from real regressions. Test updates in this PR cover the A5 behaviour changes: the `hc_pre` contract, A5 MoE dispatch collapsing to AllGather, and metadata fixtures gaining `num_reqs`.
