# [PR #17513] [BugFix][Engram] Support BF16 checkpoints without implicit quantization

## 正文

### What this PR does / why we need it?

DeepSeek V4.1 BF16 checkpoints are needed for RL rollout inference, but Engram unconditionally opens a QuaRot file and converts BF16 embedding rows to INT8. A non-quantized checkpoint now keeps BF16 tables and uses the original-basis gate without requiring rotation metadata. Quantized checkpoints retain INT8 storage and use the QuaRot path declared in their quantization metadata.

Both device and HOST_UVA lookup support BF16, including shared host tables. The WKV projection and gate parameters remain BF16. This change is independent of the node-local EDP support in #17427.

### Does this PR introduce _any_ user-facing change?

Load BF16 checkpoints with `--dtype bfloat16`, omitting `--quantization ascend`. Engram does not silently quantize their tables. Host offload and sharing remain controlled by `--engram-config`.

### How was this patch tested?

Local unit tests passed. Tested the real BF16 checkpoint on two Ascend A3 nodes with #17427, using TP8/DP4/EP32, Engram host offload/shared memory, DSpark(5), and full decode graphs. Teacher forcing against the official API covered 540 comparable positions from 3 GPQA traces: top-1 token agreement was 95.74%, with a mean absolute logprob difference of 0.046 for the official top-1 token. Separate multi-token generation checks passed all 3 GPQA and 3 OCRBench cases locally, with DSpark execution confirmed by runtime counters.
