# [PR #17161] [BugFix][KV] Avoid Mooncake IndexError on asymmetric P/D TP remote rank

source: https://github.com/vllm-project/vllm-ascend/pull/17161
state: open | updated: 2026-09-24T17:08:00Z
labels: module:tests

## 正文

### What this PR does / why we need it?

`_get_remote_ranks_for_req` returns a list indexed by decode TP rank (length ≈ D-TP). `_get_remote_rank` always indexed that list with `self.tp_rank`.

That is correct for decode consumers and for symmetric P/D TP. Under external DPLB, a prefill (`kv_producer`) worker can run a cross-P `start_load_kv` with a P-side `tp_rank` in `0..P-TP-1`. For P-TP8 / D-TP1 the list has length 1, so `tp_rank=5` raises `IndexError`.

This PR:
- Keeps decode-side and symmetric-TP indexing by `tp_rank`
- When `kv_role == kv_producer` and `tp_rank` is out of range, uses decode-group 0 (no modulo shuffle)
- Applies the same guard in `mooncake_connector.py` and `mooncake_hybrid_connector.py`
- Adds CPU unit tests with fake rank lists plus a real P-TP8 / D-TP1 grouping path

Fixes #16723

### Does this PR introduce _any_ user-facing change?

No. Behavior change is limited to the previously crashing P-side DPLB cross-P load path under asymmetric P/D TP.

### How was this patch tested?

CPU unit tests (no NPU required):

```bash
PYTHONPATH=/path/to/vllm:/path/to/vllm-ascend python -m pytest \
  tests/ut/kv_offload/test_mooncake_connector.py \
  tests/ut/kv_offload/test_mooncake_hybrid_connector.py \
  -k "get_remote_tp_rank or get_remote_rank" -q
# 3 passed

PYTHONPATH=/path/to/vllm:/path/to/vllm-ascend python -m pytest \
  tests/ut/kv_offload/test_mooncake_hybrid_connector.py -q
# 17 passed
```

Without the fix, the new asymmetric cases raise `IndexError: list index out of range`.
