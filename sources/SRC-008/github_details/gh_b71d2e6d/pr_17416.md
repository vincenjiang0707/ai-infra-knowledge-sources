# [PR #17416] [BugFix][310P] Restore hybrid KV cache capacity by sharing Mamba group slots

## 正文

### What this PR does / why we need it?
vLLM 0.29.0 changed hybrid KV cache descriptors from cross-group shared slots to per-group layer lists. The 310P runners continued to allocate cache storage per layer, losing the Mamba storage sharing used in v0.28.0. The worker then reduced the planner budget by 1/4. In the reported Qwen3.6-27B configuration, reported capacity fell from 166,697 to 41,436 tokens.
This PR:
- Reuses ND Mamba storage for compatible layers at the same position in different cache groups, in both MRV1 and MRV2.
- Keeps separate NZ K/V storage for each Attention layer and separate storage for different layers within one group.
- Applies the same sharing eligibility check to allocation and worker budget calculation, avoiding the extra 1/4 reduction when sharing is enabled.
- Falls back to the existing per-layer allocation and budget scaling for unsupported layouts.
