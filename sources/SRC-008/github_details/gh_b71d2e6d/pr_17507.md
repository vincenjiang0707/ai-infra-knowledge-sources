## 正文

## What this PR does / why we need it?

The layerwise KV pool (AscendStore memcache GVA path) derives its shard stride/offset from the worker's **local** `decode_context_parallel_size`. In PD disaggregation the producer (`kv_producer`, usually prefill) and consumer (`kv_consumer`, usually decode) are separate worker groups. When the two sides use different DCP sizes, both compute different shard layouts for the SAME pool region, so the current code rejects the mismatch with a `ValueError`.

This PR supports the common asymmetric shape: **decode-only DCP** — one side has `dcp == 1` and the peer has `dcp > 1`, with `pcp == 1` on both. Producer and consumer now agree on a single `layout_dcp_size` (the peer-sharded size) so block/hash granularity, GVA region size, and per-shard stride stay aligned. Every other asymmetric CP shape (both sides sharded with unequal sizes, or any `pcp > 1`) keeps the existing explicit mismatch rejection.

## Changes

### `metadata.py`
- Add `infer_peer_cp_sizes`: resolve the peer `(dcp, pcp)` from the flat store config (`prefill_dcp_size` / `decode_dcp_size`, mirroring the existing `prefill_tp_size` / `decode_tp_size` convention).
- Add `infer_decode_only_dcp`: true only for the decode-only DCP shape.
- Add `resolve_layout_dcp_size`: the single shared sharding factor (`max(local, peer)` for decode-only DCP, otherwise local).
- Refactor `infer_dcp_mismatch_info` to reuse `infer_peer_cp_sizes`.

### `pool_worker.py`
- Resolve `peer_dcp_size` / `peer_pcp_size` / `layout_dcp_size` in `_init_kv_transfer_config`.
- `grouped_block_size` and `hash_block_size` now use `layout_dcp_size` so producer and consumer produce the same block/hash granularity.
- `_build_group_layer_builders` and `_global_group_alloc_size` use `layout_dcp_size` for the shard-major region layout; producer (dcp==1) keeps `shard_idx = 0`.
- The mismatch `ValueError` is now skipped for decode-only DCP.

### `pool_scheduler.py`
- Mirror the same `layout_dcp_size` resolution so the hit-check keys track the producer/consumer layout.

## Tests

- `test_metadata.py::TestDecodeOnlyDcpLayout`: covers the three new helpers.
- `test_layerwise_dcp_sharding.py::TestDecodeOnlyDcpLayout`: covers producer (dcp=1) allocating the decoder (dcp=N) region layout.

## Scope / non-goals

- Only the KV pool / connector layer is touched; no attention-model KV-sharding semantics are modified.
- P/D asymmetric shapes beyond decode-only DCP (both sides sharded with unequal sizes, `pcp > 1` on either side, or non-divisible sizes) continue to be rejected explicitly.
- Peer topology is supplied through `kv_connector_extra_config` (`prefill_*` / `decode_*`) as before; this PR does not add a runtime handshake field.

## Verification

- `py_compile` and `ruff format` / `ruff check` pass locally.
- Unit tests run in CI's matching environment; end-to-end NPU validation for decode-only DCP is tracked as follow-up.

Depends on nothing beyond current `main` (includes #16498 and #17246).

This PR introduces support for "decode-only DCP" layout in the AscendStore KV transfer pool. In this asymmetric topology, one side uses decode-context-parallel sharding (dcp > 1) while the peer has no DCP (dcp == 1), and neither side uses prefill-context-parallel (pcp == 1). This is achieved by resolving a shared layout DCP size (the maximum of local and peer DCP sizes) so both sides agree on the shared layerwise GVA region layout.

Feedback:
- In `pool_scheduler.py`, when `is_decode_only_dcp` is active, the consumer (dcp > 1) will look up keys for all its ranks (e.g., `dcp_rank` 0 to 7), but the producer (dcp == 1) only writes a single key with `dcp_rank == 0`. This will cause lookup failures for ranks 1 to 7. Key generation and lookup must be forced to use `dcp_rank = 0`.
- In `pool_worker.py`, a similar key mismatch occurs on the worker side during GVA allocation/loading, which also needs to force `dcp_rank = 0` when `is_decode_only_dcp` is true.

### Does this PR introduce _any_ user-facing change?
No.

### How was this patch tested?
New unit tests were added in `test_metadata.py` and `test_layerwise_dcp_sharding.py` to verify the inference of decode-only DCP layouts and allocation sizes.
