### 🐛 Describe the bug

【问题现象】
- vllm-ascend 0.23.0 + vllm 0.23.0，Atlas 800T A2（910B3 ×8，64GB）
- gemma-4-12B-it / gemma-4-31B-it + 对应 assistant draft 模型（Gemma4MTPModel，num_speculative_tokens=1）开启投机解码后：
  - 服务正常启动，target 模型推理结果完全正确
  - 但 SpecDecoding 指标显示 Avg Draft acceptance rate 恒为 0.0%，Accepted: 0 tokens
  - 投机解码为纯负优化：每步多跑一次 draft forward，产出的 draft token 全部被 target 拒绝，解码速度反而低于不开 MTP
- 仅 eager 模式验证（--enforce-eager），TP1（12B）与 TP2（31B）均复现

【复现步骤】
1. 启动命令（12B 单卡）：
   vllm serve /data/llm_model/gemma4/gemma-4-12B-it \
     --tensor-parallel-size 1 --dtype bfloat16 --max-model-len 8192 \
     --enforce-eager --gpu-memory-utilization 0.45 --max-num-seqs 4 \
     --trust-remote-code \
     --speculative-config '{"model": "/data/llm_model/gemma4/gemma-4-12B-it-assistant", "num_speculative_tokens": 1}'
   （注意：speculative-config 中不要带 "method": "mtp"，显式指定会触发上游 NotImplementedError；省略后自动识别为 mtp）
2. 发起请求：POST /v1/chat/completions，问题如"中国的首都是哪里？"，max_tokens=60，temperature=0
3. 观察 API Server 周期性输出的 SpecDecoding metrics：
   Accepted: 0 tokens, Drafted: 40 tokens, Avg Draft acceptance rate: 0.0%
