## 正文

### What this PR does / why we need it?

Layerwise load tasks in the same cache group do not necessarily describe the same transfer. Independent layers can retain a local prefix and load `[local_hit, end)`, while reused layers load `[0, end)`. The current implementation builds one descriptor from the first task in a group and assigns it to every layer, which can omit required blocks.

`LayerBatchBuilder` also reuses internal NumPy buffers. A second descriptor build can overwrite arrays retained by an already queued task unless each task owns a snapshot.

This draft PR:

- builds shared load metadata from each task's own block ranges;
- copies `block_ids_arr` and `block_gvas_arr` before queuing;
- validates the GVA descriptor invariant;
- adds a regression test using two task plans backed by the same reusable arrays.

This overlaps the layerwise transfer refactor in #16377. The intent of opening it as a draft is to make the correctness bug and regression test reviewable so the fix can either merge first or be incorporated into that refactor.

### Does this PR introduce _any_ user-facing change?

No API or configuration change. Layerwise loads now use the block range prepared for each layer instead of reusing another layer's plan.

### What this PR does / why we need it?
This PR refactors `_build_shared_load_data` in `pool_worker.py` to build and attach an owned block-data snapshot for each layer load plan, copying the internal arrays (`block_ids_arr` and `block_gvas_arr`) to prevent issues when `LayerBatchBuilder` reuses them.
