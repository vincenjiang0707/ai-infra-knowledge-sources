# [PR #17451] [BugFix][Worker] Fix block-copy crash with Ascend per-layer cache containers on v2 runner

source: https://github.com/vllm-project/vllm-ascend/pull/17451
state: open | updated: 2026-09-26T04:46:26Z
labels: module:tests, merge-conflicts, ready-precise

## 正文


Root cause: upstream `copy_kv_cache_blocks_inplace` assumes one tensor per runner cache
entry. Ascend, however, binds per-layer containers — `(k_cache, v_cache)` tuples for
attention layers and `[conv_state, ssm_state]` lists for Mamba layers
(`vllm_ascend/worker/v2/attn_utils.py:_reshape_kv_cache_v2`), which `bind_kv_cache`
appends verbatim into the runner's cache list (`vllm/v1/worker/utils.py:637`).

Fix: add worker patch `patch_v2/patch_worker_utils.py` that rebinds
`vllm.v1.worker.utils.copy_kv_cache_blocks_inplace` — and the reference imported into
`vllm.v1.worker.gpu.model_runner` — to the Ascend implementation in
`vllm_ascend/worker/utils.py`, which unpacks nested entries and deduplicates shared views
by `data_ptr` before copying. Beyond nested entries, the Ascend implementation also
copies each tensor segment as its own `[num_blocks, -1]` view instead of reshaping the
whole untyped storage, which is required for Ascend's segmented/shared-storage cache
layouts (e.g. Mamba conv+SSM segments in one allocation).

Layer bindings, cache views and the `kv_caches` dict used by KV connectors are untouched;
only the runner-internal copy path is affected.

### Does this PR introduce _any_ user-facing change?

No. No API, configuration or default-behavior change. It only fixes a crash on
preemption/rollback block copies for hybrid models on the v2 runner.

### How was this patch tested?

- Unit tests (CPU): `pytest -sv tests/ut/worker/test_kv_cache_block_copy.py`
  covers the Ascend implementation — segmented conv/SSM storage, shared-view
  deduplication, `None` entries, multi-kernel-block pages, and cyclic
  source/destination copies.
- Manual NPU test: serve a hybrid model with DFlash speculative decoding
  (`Qwen3.6-27B` + `Qwen3.6-27B-DFlash-swa`, TP2) and drive enough load to trigger
  preemption (which emits `kv_cache_block_copies`). Before this patch the worker dies
  with the `AttributeError` above; after it, the workload runs to completion.

- vLLM main: https://github.com/vllm-project/vllm/commit/ced6857afa0ea7b2e3f0846a62e1394e90f15607
