## 正文

### What this PR does / why we need it?

Add an A5 native KDA state-copy operator that tiles the state payload across cores, addresses first-axis-strided cache pages with 64-bit offsets, and folds initial-state clearing into gather. Wire it into Kimi prefill gather/scatter while keeping recurrent decode unchanged.

Include build and torch/Meta registration, the Python capability check, tests and a focused benchmark. Unsupported devices/layouts retain contiguous indexing or the existing-style strided byte-copy route. Cache page gaps and neighboring layers are not copied.

### Does this PR introduce _any_ user-facing change?

No new runtime switch. Eligible A5 prefill uses the native state-copy path automatically; it supports FP32/BF16 state payloads and preserves selected-row semantics.

### How was this patch tested?

21 CPU cases passed using `--confcutdir=tests/ut/ops` for `test_kda_state_copy_dispatch_cpu.py` and `test_kimi_kda_strided_state_cpu.py`. Python syntax, Ruff, shell syntax and diff checks passed. Included NPU tests cover strided pages, invalid indices, flags, empty selections and graph replay; native compilation/NPU execution were not rerun for this standalone branch.
