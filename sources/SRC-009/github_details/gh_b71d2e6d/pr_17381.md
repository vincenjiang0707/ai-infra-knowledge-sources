# [PR #17381] [CPP][Spec Decode] Disable profiling chunk for draft models

## 正文

### What this PR does / why we need it?

This PR prevents Chunked Pipeline Parallelism (CPP) profiling-chunk configuration from being applied to speculative draft models.

Draft models used by MTP, EAGLE, DSpark, and the 310P MTP path should not inherit the target model's profiling-chunk settings. Applying CPP to those draft models can create an unsupported scheduler configuration during speculative decoding. The target model keeps its CPP configuration; only the draft-model configuration is disabled.

The PR also separates CPP-enabled speculative-decoding E2E cases from the base MTP/DSpark tests so failures are isolated and both configurations retain independent coverage. The CPP E2E requests generate exactly one output token to model prefill-node behavior.

This PR is intended to merge after #17380, which provides the CPP asynchronous scheduler used by the MTP CPP E2E configuration.

### Does this PR introduce _any_ user-facing change?

Yes. Speculative decoding with CPP no longer enables profiling chunk on the draft model, avoiding unsupported draft-model scheduling while preserving CPP on the target model.

### How was this patch tested?

- Added and updated unit coverage for MTP, EAGLE, DSpark, and the 310P speculative-decoding paths.
- Added a dedicated four-card Qwen3.5 PP + MTP + CPP prefill E2E test with one output token per request.
- Added a dedicated eight-card DeepSeek V4 DSpark PP + CPP prefill E2E test with one output token.
- Registered the new E2E files in the CI estimated-times configuration.
- GitHub Actions is running on the head branch.
