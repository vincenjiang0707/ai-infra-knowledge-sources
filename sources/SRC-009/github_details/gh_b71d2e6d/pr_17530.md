# [PR #17530] [BugFix] Pad negative positions in every group of the fused slot mapping

source: https://github.com/vllm-project/vllm-ascend/pull/17530
state: open | updated: 2026-09-25T05:47:53Z
labels: module:tests, module:ops

## 正文

### What this PR does / why we need it?

Fixes #17528.

`positions` is shared by every KV-cache group of a fused slot-mapping
launch, but since #16537 the fused kernels pad negative positions only in
circular groups. In a mixed circular/non-circular layout (DSV4.1's
compressor state, GLM-5-Next's indexer tail) a non-circular group turns a
negative position into a real-looking slot ID. For `pos <= -block_size`
the block-table window base goes negative and the load leaves the
request's row. It is latent today (MRV1 positions are non-negative); the
standalone repro in #17528 shows the wrong slot IDs on 910B2.

Changes:

- Under `HAS_CIRCULAR`, negative positions are excluded from the window
  base, the base is clamped into the row, and they map to `PAD_ID` in
  every group.
- `MultiGroupBlockTable` passes `is_circular_ptr=None` when no group is
  circular (today it always passes the tensor), so engines without a
  circular group, e.g. plain DSV4, compile the path out.

The same change is part of #17529 (runtime recompile fix, #17527).
Whichever lands first, the other rebases trivially.

### Does this PR introduce _any_ user-facing change?

No. Negative positions in mixed layouts now map to `PAD_SLOT_ID` in every
group; no current caller produces them.

### How was this patch tested?

New `tests/e2e/nightly/single_node/ops/singlecard_ops/triton/test_compute_slot_mapping_fused_negative_positions.py`:
negative positions across the adaptive small/large-tile and parallel
kernels (sharing a tile with regular tokens, `pos <= -block_size`, a whole
negative request) in a mixed layout and an all-circular control, plus
`is_circular_ptr=None` equivalence. On 910B2: 16 passed. The fused-kernel
portion of `test_glm5next_tail_slot_mapping_triton.py` (mixed circular layout
across three length shapes, NPU-graph capture/replay, and the no-descriptor
single-group call) passes bit-identically with and without this patch; the
nightly test itself is broken on main since #16925 (its `BlockTable.__new__`
harness predates the DSV4.1 block-table rewrite: missing `is_circular_group`,
numpy-style draft harness, drifted single-group expectations) and fails 4/4
identically with and without this patch, so it is reported separately instead
of being claimed as a gate. The standalone repro from #17528 goes from
3 FAIL on main to 5/5 PASS with this patch.
