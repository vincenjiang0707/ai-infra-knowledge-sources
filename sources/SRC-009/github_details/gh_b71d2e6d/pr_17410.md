# [PR #17410] [Feature][Worker] Support PCP with PIECEWISE and FULL_AND_PIECEWISE CUDA graphs

state: open | updated: 2026-09-26T02:38:39Z

## 正文

### What this PR does / why we need it?

Enable and fix PCP (prefill context parallel) execution with PIECEWISE and
FULL_AND_PIECEWISE CUDA graph modes.

Previously, sparse attention (DSA/SFA) with PCP was restricted to eager mode
or FULL_DECODE_ONLY graphs. This PR:

1. **Supports sparse MLA (DSA) PCP with PIECEWISE / FULL_AND_PIECEWISE graphs**
   - Relaxes the graph-mode validation in `AscendPCPManager` to only reject
     pure FULL graphs (prefill shapes are dynamic, FULL graph capture is not
     applicable), allowing PIECEWISE and FULL_AND_PIECEWISE.
   - Trims graph padding before DSA cache updates: rotary embedding and
     `dsa_kv_compress_scatter` now operate on the actual token extent instead
     of the padded graph shape, so padding tokens are never written into the
     KV cache. FULL graph mode keeps the fixed padded shape as required.
   - Pads compact restored hidden states back to the graph layout after PCP
     all-gather, keeping downstream graph segments shape-consistent.

2. **Fixes SFA-PCP crash with fused preprocessing (PROLOG_V3)**
   - Under PCP, the attention impl receives rank-local tokens while the slot
     mapping uses the global gathered layout (padded local tokens x PCP world
     size). Fused preprocessing writes the KV cache inline with one cache
     index per input token, so the layouts mismatch and trigger an assertion
     (e.g. `token_x=256 and cache_index=512` with PCP=2).
   - `AscendSFAPCPImpl` now overrides `_get_fused_type_unsupported_reasons`
     to veto fused preprocessing under PCP, falling back to the NATIVE chain,
     which gathers prefill cache inputs before the KV cache write and is
     layout compatible. This mirrors the existing protection already in place
     for DSA-CP.

### Does this PR introduce *any* user-facing change?

Yes. Models using sparse attention (DSA/SFA, e.g. DeepSeek-V3.2, GLM5) with
`prefill_context_parallel_size > 1` can now run with `PIECEWISE` and
`FULL_AND_PIECEWISE` compilation modes. Previously these configurations
either raised `NotImplementedError` or crashed during graph capture warmup.

### How was this patch tested?

- Manual testing on Ascend NPU:
  - GLM5 (SFA) with PCP=2 + PIECEWISE graph mode: previously failed in graph
    capture warmup with `token_x=256 and cache_index=512` assertion; now
    selects the NATIVE preprocessing chain and runs inference correctly.
  - DSA models with PCP + FULL_AND_PIECEWISE: verified prefill runs under
    PIECEWISE graphs and decode under FULL graphs, with KV cache updates
    correctly trimmed to the actual token span.

- vLLM main: https://github.com/vllm-project/vllm/commit/ced6857afa0ea7b2e3f0846a62e1394e90f15607
