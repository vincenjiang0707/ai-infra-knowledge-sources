This pull request refactors the KV cache quantization logic for the Ascend platform. It replaces hardcoded device-specific dtype assignments with a more robust registration-based approach, allowing for better flexibility and consistency across different model architectures. By centralizing the dtype handling and ensuring proper registration in worker processes, the changes improve maintainability and resolve potential issues with dtype resolution during model initialization.

### Highlights

* **KV Cache Dtype Registration**: Introduced a new module `vllm_ascend/core/kv_cache_dtype_handlers.py` to register Ascend-specific KV cache dtypes (fp8 and int8) using vLLM's registration mechanism, ensuring correct mapping to `torch.float8_e4m3fn` and `torch.int8`.
* **Worker-side Initialization**: Moved the registration of KV cache dtype handlers to a top-level side-effect import in `vllm_ascend/worker/worker.py` to ensure handlers are correctly registered in every spawned worker process.
* **Configuration Refactoring**: Updated `ascend_config.py` and model-specific logic to derive cache dtypes and sparse configurations dynamically from `vllm_config.attention_config.indexer_kv_dtype` instead of relying on hardcoded device-type checks.
