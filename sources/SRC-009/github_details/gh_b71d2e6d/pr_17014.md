## 正文

### What this PR does / why we need it?
Adds a `sparse_kv_offload_config.lru_max_threads` option so deployments can configure the CPU LRU planner thread budget per Decode Worker. The effective workspace team is limited by both the configured value and the process CPU affinity, while the native planner continues to cap active threads by the current work rows.

This keeps the existing default of 8 threads, makes larger thread budgets explicit, and avoids using `max_num_reqs` as the row cap for fused overlap/MTP workloads.

### Does this PR introduce _any_ user-facing change?
Yes. `sparse_kv_offload_config` now accepts `lru_max_threads`, a positive integer defaulting to 8. The new option is documented in the Sparse KV Cache Offload guide.
