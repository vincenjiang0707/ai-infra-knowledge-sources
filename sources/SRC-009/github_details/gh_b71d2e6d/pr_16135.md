## 正文

### What this PR does / why we need it?

This is the `releases/v0.26.0rc` adaptation of #16129.

The v0.26 connector normally registers `kv_cache_tensor.size`, which remains the lower bound in this patch. For 0.26-derived deployments that expose padded runtime KV tensor views, however, the physical span addressed by block-stride transfers can exceed that configured logical size.

The connector now records each runtime tensor's end as:

```text
data_ptr + shape[0] * stride(0) * element_size
```

and registers the larger of:

- the existing `kv_cache_tensor.size`; and
- the runtime span from the lowest tensor address to the highest tensor end.

This preserves the native v0.26 layout while preventing high block IDs from falling outside Mooncake's registered region when a hybrid KV tensor includes inter-block padding.

The observed DeepSeek V4 indexer layout had a 4096-byte payload and a 4160-byte block stride. Registering only the logical payload caused a high-block remote-buffer lookup failure, followed by HCCL/AICPU and sampling failures.

### Does this PR introduce _any_ user-facing change?

No API or configuration change. Hybrid P/D KV transfer registration now covers padded runtime tensor layouts.

### How was this patch tested?

- Added unit coverage for a padded `as_strided` tensor.
- Added connector-level coverage verifying that a configured 12-byte region is expanded to its 18-byte runtime stride span.
- `python -m py_compile vllm_ascend/distributed/kv_transfer/kv_p2p/mooncake_hybrid_connector.py tests/ut/kv_offload/test_mooncake_hybrid_connector.py`
- `git diff --check`
- The root cause and stride-span correction were validated on an Ascend A3 DeepSeek V4 P/D + DSpark deployment based on the v0.26 nightly image; the same high-block transfer succeeded and pressure testing completed more than 30,000 audited transfers without OOB, transfer failure, NaN, IndexCheck, or EZ9999.

The focused pytest target could not start in the Windows checkout because the matching vLLM test dependency set is incomplete (`cbor2` is missing); CI is expected to run the added tests.
