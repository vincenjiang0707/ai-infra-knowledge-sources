## 正文

### What this PR does / why we need it?

In scenarios with high traffic congestion, in order to avoid affecting high-priority operations such as operator distribution and aggregate communication, KV pool needs to support configuring QoS to lower its transfer priority.

This PR adds a qos field to kv_connector_extra_config , which is automatically injected into the backend-specific environment variables during store initialization:

- Mooncake : injected into store.comm_resource_config.qos of ASCEND_GLOBAL_RESOURCE_CONFIG (merged into the existing JSON config so other HIXL fields like protocol_desc / listen_port are preserved; an explicit extra-config value overrides a pre-existing one)
- Memcache : injected into MF_DEVICE_UB_QOS
The QoS is fetched internally via fetch_qos_from_current_config() inside _inject_store_qos() / _inject_device_ub_qos() , so no qos parameter is passed through __init__ . Values are validated to be an integer in [0, 4] (larger means higher priority), failing fast with a clear error message on invalid input. The injection is a no-op when qos is not configured, preserving existing behavior.

Example configuration:

```
  --kv-transfer-config \
    '{
            "kv_connector": "MultiConnector",
            "kv_role": "kv_producer",
            "engine_id": "0",
            "kv_connector_extra_config": {
                "connectors": 
				[
					{
                            "kv_connector": "MooncakeHybridConnector",
                            "kv_role": "kv_producer",
                            "kv_port": "33002",
                            "kv_connector_extra_config": {
									"qos_priority": 3,
                                    "use_ascend_direct": true,
                                    "prefill": {
                                            "dp_size": 4,
                                            "tp_size": 1
                                    },
                                    "decode": {
                                            "dp_size": 4,
                                            "tp_size": 1
                                    }
                            }
                    },
                    {
                            "kv_connector": "AscendStoreConnector",
                            "kv_role": "kv_producer",
                            "kv_connector_extra_config":{
									"qos_priority": 2,
                                    "backend": "memcache",
                                    "lookup_rpc_port":"0"
                            }
                    }
                ]
			}
    }'
```
### Does this PR introduce any user-facing change?
Yes. A new optional qos field (integer in [0, 4] ) is supported in kv_connector_extra_config for the mooncake/memcache backends. No change when the field is absent.
