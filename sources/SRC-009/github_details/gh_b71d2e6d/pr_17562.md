## 正文

### What this PR does / why we need it?

Run the 40-prompt Qwen3.6 DSpark acceptance E2E with a calibrated baseline. Set its acceptance length baseline to 3.93 based on repeated CI runs: 15 vLLM main and 15 v0.30.0 jobs across eager and graph execution measured 3.883 to 3.965. Keep the shared symmetric 8% tolerance, giving an accepted interval of 3.6156 to 4.2444. The shared helper now always prints the acceptance length and all seven per-position rates before the assertion for every speculative decoding E2E that calls it.

### Does this PR introduce any user-facing change?

No. The change is limited to the E2E test and its logging helper.

### How was this patch tested?

1. Checked the 30 E2E job logs used to calibrate the baseline; each run printed the acceptance length and seven per-position rates.
2. Ran `ruff check`, `ruff format --check`, Python AST parsing, and `git diff --check` on the new commit.
3. The E2E result with the calibrated baseline is pending CI.
