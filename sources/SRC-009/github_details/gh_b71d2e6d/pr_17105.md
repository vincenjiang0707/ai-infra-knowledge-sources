Title: [Performance][Quantization] Release dead W8A8 fp32 MoE scales under MegaMoe

---
### What this PR does / why we need it?

Part 2 of 2 (quantization side). In `AscendW8A8DynamicFusedMoEMethod.process_weights_after_loading`, the `use_cann_megamoe` branch switches consumers over to `cann_mega_moe_fused_w*_scale_list` (unbind views), but the dense `w13/w2_weight_scale_fp32` fp32 blocks allocated earlier stay resident and are never read on this path — dead memory. The EPLB branch in the same function already follows the `del + torch.npu.empty_cache()` pattern; `routed_experts.py` has the same precedent for the weights themselves.

This PR releases the dead fp32 scale blocks in the MegaMoe branch (gated to non-EPLB, which is structurally mutually exclusive with the MegaMoe branch via the existing if/elif). Frees ~0.15–0.4 GiB per card on W8A8 MoE deployments, on top of part 1 (attention side).

Known follow-up (out of scope): the `del` lacks an activation guard for the MiniMax-M3 `swigluoai_uninterleave` + `enable_fused_mc2=2` combination, which has no in-tree e2e config today.

### How was this patch tested?

- `tests/ut/quantization/methods/w8a8/test_w8a8_dynamic.py`: new case asserting the dead attributes are released on the MegaMoe path and retained otherwise
- Full w8a8 quantization suite locally; ruff clean
- NPU memory before/after to be confirmed on CI

- vLLM main: https://github.com/vllm-project/vllm/commit/ced6857afa0ea7b2e3f0846a62e1394e90f15607
