# [Issue #17333] [`Bug/Docs`] `/v1/completions` endpoint is deprecated in vLLM Ascend but official docs still list it as active

state: open | updated: 2026-09-24T02:58:26Z

## 正文

### 📚 The doc issue

### Description

When using the `/v1/completions` endpoint with vLLM Ascend, the API behaves inconsistently and may return outdated/incorrect responses. This endpoint has been deprecated in the current vLLM Ascend deployment, but the official documentation has **not** been updated accordingly. Users following the docs may unknowingly call a deprecated interface and receive degraded results (e.g., "降智" / poor-quality answers, or generation stops abruptly after thinking).

### Environment

- vLLM Ascend version: `0.26.0`
- Model: `GLM-5.2-W8A8C8`
- Hardware: Atlas 800I (A3), 4-node PD-separated setup
- Driver/HDK: `HDK26.0.RC3`

### Steps to Reproduce

1. Start a vLLM Ascend server with a GLM-5.2 model.
2. Send a request to the `/v1/completions` endpoint:

```bash
curl -X POST http://<P_NODE_IP>:<PORT>/v1/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "glm-5.2",
    "prompt": "What is heap sort?"
  }'
```

3. Observe the response: it may be outdated, low-quality, or the generation may stop prematurely (e.g., after "thinking" phase without producing final output).

### Expected Behavior

- If `/v1/completions` is truly deprecated, the server should return a clear deprecation notice (e.g., `410 Gone` or `400 Bad Request` with a message) so clients can migrate immediately.
- The official documentation should be updated to mark `/v1/completions` as deprecated and point users to the recommended alternative (`/v1/chat/completions`).

### Actual Behavior

- The endpoint still accepts requests but returns unreliable/outdated results, causing confusion and potential integration failures (e.g., in WorkBuddy or other agents).

### Additional Context

This was discovered during integration testing with external agents (WorkBuddy and Telecom AI Agent). The issue causes abnormal reply behavior and interrupts generation, which blocks normal service usage. Please also verify whether the deprecation is intentional in the current release or a regression.

### Suggest a potential alternative/fix

1. Update the official vLLM Ascend documentation to:
   - Mark `/v1/completions` as deprecated.
   - Provide migration guidance to `/v1/chat/completions` (or the correct replacement endpoint).
2. Add a deprecation warning in the server response for `/v1/completions` to help users detect the issue early.
