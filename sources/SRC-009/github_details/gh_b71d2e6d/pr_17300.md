## 正文

### What this PR does / why we need it?

Avoid materializing packed KDA gate views and copying normalized output back into the caller buffer. The Triton path reads independent input/gate/output strides and tunes row partitioning for small decode batches. Add the A5 D128 BF16 native RMSNorm + sigmoid/SiLU gate for eligible pure-prefill calls.

Include the native kernel, build and torch/Meta registration, norm wrapper and actual Kimi dispatch. Preserve mainline KV connector hooks. Decode/mixed/speculative calls retain the selected module dispatch; short or unsupported prefill calls use the existing implementation.

### Does this PR introduce _any_ user-facing change?

No new runtime switch. The internal norm wrapper accepts a caller-owned output buffer; the prefill specialization preserves sigmoid versus SiLU behavior.

### How was this patch tested?

25 CPU tests passed for output ownership and phase-specific dispatch (`test_kda_norm_prefill_dispatch_cpu.py`, `test_kimi_kda_output_cpu.py`, with `--confcutdir=tests/ut/ops`). Python syntax, Ruff, shell syntax and diff checks passed. Native and Triton NPU accuracy tests are included, but native compilation/NPU execution were not rerun for this standalone branch.
