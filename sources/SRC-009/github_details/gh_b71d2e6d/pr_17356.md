## 正文

### What this PR does / why we need it?
- Delete the retired Qwen3-235B nightly config files: the 2-node internal-DP
  `Qwen3-235B-A22B.yaml`, `Qwen3-235B-W8A8.yaml`, `Qwen3-235B-W8A8-EPLB.yaml`,
  `Qwen3-235B-disagg-pd.yaml`, the 2-node external-DP
  `QWEN3_235B_PD_3_5K_1_5k.yaml`, and the single-node
  `Qwen3-235B-A22B-W8A8.yaml`, `Qwen3-235B-A22B-W8A8-MRV2-EPLB.yaml`, together
  with their entries in `nightly_config.yaml` (`multi-node-qwen3-dp`,
  `multi-node-qwen-disagg-pd`, `multi-node-qwenw8a8-2node-eplb`,
  `QWEN3_235B_PD_3_5K_1_5k`, `qwen3-235b-a22b-w8a8`,
  `qwen3-235b-a22b-w8a8-MRV2-EPLB`). Also drop
  `Qwen3-235B-W8A8-EPLB-mxfp0.yaml`, which had no registry entry left.
- Refresh `Qwen3-235B-A22B-A2.yaml`: remove the `OMP_PROC_BIND`,
  `OMP_NUM_THREADS` and `TASK_QUEUE_ENABLE` envs, add
  `--additional-config '{"enable_flashcomm1": true,
  "ascend_compilation_config":{"enable_npugraph_ex":true,
  "enable_static_kernel":true}}'` to both servers, and change the accuracy
  threshold from 10 to 2.
- Add a `perf` benchmark section to the external-DP `QWEN3_235B_PD.yaml`
  (in3500/out1500, 760 prompts, batch size 190, baseline 3583.8747,
  threshold 0.97).
- Refresh the single-node `Qwen3-235B-A22B-W8A8_piecewise_fullgraph_A3.yaml`:
  remove the redundant envs (`TASK_QUEUE_ENABLE`, `VLLM_USE_V1`,
  `OMP_PROC_BIND`, `OMP_NUM_THREADS`, `VLLM_ENGINE_READY_TIMEOUT_S`), merge
  `enable_flashcomm1` and the `ascend_compilation_config` flags into the
  existing `pa_shape_list` additional-config, drop the standalone
  `--compilation-config '{"cudagraph_mode": "FULL_DECODE_ONLY"}'` overrides,
  and change the accuracy threshold from 10 to 2.
- Refresh the weekly `Qwen3_235b_w8a8_A5.yaml`: remove `OMP_PROC_BIND` and
  `VLLM_USE_V1`, and add the same `enable_flashcomm1` /
  `ascend_compilation_config` additional-config.
- Sync the docs: drop the removed rows from the `nightly_ci_test.md` tables,
  and point the `multi_node_test.md` example and the `tools/bisect` examples
  (`README.md`, `USAGE_zh.md`) at `Qwen3-VL-235B-disagg-pd.yaml`.

### Does this PR introduce _any_ user-facing change?
No. This PR only changes nightly/weekly CI test configurations and developer
docs.

### How was this patch tested?
Needs to be verified by triggering the remaining Qwen3-235B cases
(`Qwen3-235B-A22B-A2.yaml`, `QWEN3_235B_PD.yaml`,
`Qwen3-235B-A22B-W8A8_piecewise_fullgraph_A3.yaml` and the weekly
`Qwen3_235b_w8a8_A5.yaml`). No new tests are added.
