# [PR #17558] [BugFix][PCP] Write all gathered SFA C8 KV cache rows

source: https://github.com/vllm-project/vllm-ascend/pull/17558
state: open | updated: 2026-09-27T10:13:59Z
labels: module:tests

## 正文

### What this PR does / why we need it?

During PCP prefill, SFA C8 gathers KV rows from all PCP ranks. The cache write still used the local `num_actual_tokens`, so it skipped the gathered rows from other ranks. Use the full gathered slot count for prefill cache writes while keeping the local count for decode.

### Does this PR introduce _any_ user-facing change?

Yes. It fixes incorrect responses caused by missing SFA C8 KV cache rows in PCP prefill.

### How was this patch tested?

On A3 with GLM-5.2 W8A8C8 (TP8, PCP2, SFA/indexer C8, `FULL_DECODE_ONLY`, MTP 1), ran the same 8 AIME25 questions with concurrency 4 and vLLM `9ed533eb`:

- Before (`7e2c563f`): 0/5 completed answers correct; 3 long-running requests were canceled, so no 8-question accuracy is reported.
- After (`a0a24f11`): 8/8 correct; all requests completed. Graph capture and MTP draft/accepted tokens were observed in both runs.

### Version

- vLLM main: https://github.com/vllm-project/vllm/commit/ced6857afa0ea7b2e3f0846a62e1394e90f15607

This PR introduces `_get_sfa_kv_store_num_tokens` to correctly determine the number of tokens to store in the SFA KV cache during context-parallel (PCP) prefill, where prefill KV rows are gathered across PCP ranks. However, there is a critical issue where negative slots in `slot_mapping_sfa` are not filtered before calling `DeviceOperator.scatter_cache`, which can cause cache corruption or undefined behavior on the NPU. We should filter out negative slots and their corresponding rows from `packed_kv` before scattering.
