# [PR #17480] [BugFix][KV Cache] Propagate resolved prefix retention config

## 正文

### What this PR does / why we need it?

vLLM PR [#52216](https://github.com/vllm-project/vllm/pull/52216) promoted `prefix_cache_retention_interval` from an environment variable to `CacheConfig` / `KVCacheConfig`. Follow-ups [#55760](https://github.com/vllm-project/vllm/pull/55760) and [#55861](https://github.com/vllm-project/vllm/pull/55861) made the unset value model-aware: hybrid models with EAGLE resolve to dense retention (`None`), while other models resolve to `0`; explicit `None`, `0`, and positive intervals remain unchanged.

Several vLLM Ascend-owned paths still read `VLLM_PREFIX_CACHE_RETENTION_INTERVAL` directly. As a result, they can ignore the resolved CLI/Python configuration, use the wrong default, or disagree with the upstream coordinator:

- `AscendHybridKVCacheCoordinator`
- AscendStore scheduler and worker coordinators
- the GLM-Next custom `KVCacheConfig` planner

This PR makes those paths consume the already-resolved `CacheConfig` / `KVCacheConfig` field and preserves it in the GLM-Next plan. It deliberately does not duplicate upstream model/EAGLE default-selection logic in the plugin.

Regression coverage verifies propagation of all three policy forms: dense (`None`), semantic-only sparse retention (`0`), and a positive periodic interval.

Refs vllm-project/vllm#52216, vllm-project/vllm#55760, vllm-project/vllm#55861, and #16449.

### Does this PR introduce _any_ user-facing change?

Yes. Existing `--prefix-cache-retention-interval`, Python API values, deprecated environment-variable compatibility, and upstream model-aware defaults are now honored consistently by the Ascend hybrid coordinator, AscendStore, and GLM-Next custom cache planning paths.

No new option or launch-command change is introduced.

### How was this patch tested?

Added CPU regression coverage for:

- `AscendHybridKVCacheCoordinator` consuming the resolved `KVCacheConfig` value;
- AscendStore scheduler and worker propagation;
- GLM-Next custom cache-plan propagation;
- `None`, `0`, and positive interval values.

Local checks completed:

- `python -m compileall -q` on all modified Python files
- `uvx ruff check` on all modified Python files
- `uvx ruff format --check` on all modified Python files
- `git diff --check upstream/main...HEAD`

Targeted pytest execution was not available in the local Windows environment because `torch` is not installed; test collection stops in `tests/ut/conftest.py`. The repository CI is expected to run the added unit tests.

NPU field validation and end-to-end serving tests were not run. This patch only changes the source of an already-resolved scalar configuration value and adds missing field propagation; it does not change cache lookup/retention algorithms, transfer addressing or protocol, scheduler behavior, NPU kernels, or model numerics.
