# [PR #17406] [BugFix][EPLB] Make dynamic EPLB work end-to-end on A2

## 正文

### What this PR does / why we need it?

Fixes #14080.

#### Related

- #14178 — [RFC]: Migrate Dynamic EPLB to the upstream lifecycle and sunset `patch_multiproc_executor.py`
- #14845 — implementation PR of #14178 (open draft); the `multiprocessing.Manager` + `shared_dict` IPC it retires is exactly the path Bug 4 fixes here
- #11150 — [Bug]: Dynamic EPLB TP+EP E2E tests broken on main due to expert index mismatch
- #5633 — [RFC]: Expert Parallelism Load Balancer (open); the umbrella RFC tracking the EPLB bugfix line
- #13161 — Fix(eplb): load redundant expert weights (merged); the redundant-expert slot-resolution precedent this PR's `init_eplb_config` layout invariant builds on

Supersedes #17358 (the author's earlier A2 dynamic-EPLB attempt, now closed in favour of this one).

Dynamic EPLB on A2 (910B) was documented as partially unsupported and, in practice, crashed at every stage of the EPLB lifecycle. This PR makes dynamic EPLB work end-to-end on A2: **five bugs, one atomic change**, plus A2 acceptance coverage in CI and a corrected doc note.

#### Bug 1 — ALLGATHER OOB at first forward (the #14080 crash)

With EPLB (`num_redundant_experts > 0`) on A2 + MRv1, the MoE **ALLGATHER** path crashes during decode CUDA-graph capture / first forward:

```
Index out of range in dimension 0: index value 263 exceeds bounds 256!
index_check.h:130 IndexCheckKernel<int>::ProcessScalar ... (idx < bound)
```

Two independent data points, same signature (bound == logical expert count, index == a redundant **physical** expert ID):

| Case | Logical experts | Redundant | Crash |
|---|---|---|---|
| #14080 (Qwen3-30B-A3B, EP=2) | 128 | 2 | `129 > 128` |
| User report (Qwen3.6-35B-A3B-w8a8, EP=4/TP=4) | 256 | 16 | `263 > 256` |

`layer.ascend_expert_map` was built in `init_eplb_config` over **logical** IDs only (`torch.full((n_experts,), -1)`), so physical IDs in `[n_logical, n_logical + redundant)` trip the CANN `Index` op's embedded `IndexCheckKernel` (`idx < bound`) on the next forward — the initial EPLB placement already puts redundant copies into the tail physical slots, no rebalance cycle required.

The A2 ALLGATHER dispatcher is the only consumer that indexes this map with physical topk IDs: A3 selects `FUSED_MC2` (MegaMoe consumes `topk_ids` + physical `moe_expert_num`, never indexes the map), and A2 without EPLB keeps `log2phy is None`.

#### Bug 2 — Heat collection shape mismatch (dies at the first heat cycle)

`npu_moe_init_routing` returns per-*global*-expert counts (`[num_experts]`) while `moe_load` is sized `num_local_experts` → `add_` shape error at the first EPLB cycle. Now gathered to per-slot counts via a new `local_phys_expert_ids` NPU buffer. The gather is size-guarded: the MC2/FusedMC2 dispatchers' `npu_moe_init_routing` returns per-*local* counts whose shape already matches `moe_load`, so they pass through untouched and only the AllGather global histogram is gathered.

#### Bug 3 — Stale layer maps after rebalance (silent misrouting)

Only the CPU bookkeeping copy was refreshed; `layer.ascend_expert_map` / `global_expert_map` kept pointing at pre-rebalance slots. `update_ascend_eplb_maps` now refreshes them, and the record file is written with logical IDs (it previously stored physical slot positions).

#### Bug 4 — `phys_to_logical` IPC contract (worker dies at the first rebalance)

`warm_up_eplb` stored `phys_to_logical` as a *device* tensor in the Manager-backed `shared_dict`; torch_npu refuses to re-share an NPU tensor received from another process, so the EPLB worker's `pack_update_info` raised `RemoteError` on the first rebalance and "EPLB optimization will stop". Now stored as `.cpu()` at the only write site — matching the CPU-only contract of `expert_maps` / `moe_load` in the same dict.

#### Bug 5 — Runtime expert maps demoted off-device after rebalance

`update_ascend_eplb_maps` replaced `layer.ascend_expert_map` — set on the execution device by upstream `update_expert_map()` at checkpoint load — with a dtype-only conversion of the worker's CPU payload → `Expected all tensors to be on the same device` at `mask = expert_map[topk_ids]` (`token_dispatcher.py`). Now preserved via `.to(device=old.device, dtype=old.dtype)`.

#### Why this is one atomic change

Bug 1 is the root: it changes the map layout from logical-length to full physical-length. Bugs 2, 3 and 5 are its consumers — the per-slot heat histogram (Bug 2) is gathered through `local_phys_expert_ids`, the post-rebalance refresh (Bugs 3 and 5) rewrites the physical-length `ascend_expert_map` / `global_expert_map`, and the record file (Bug 3's export) is written through the `phys_to_logical` bridge the layout introduces.

A partial fix on this path cannot be verified independently: the map-length invariant is consumed at every stage of the EPLB lifecycle, so merging Bug 1 alone breaks heat collection (Bug 2) and the record-file format (Bug 3) at the same time — the next consumer in the chain fails on the same invariant. {Bugs 1, 2, 3, 5} must land together.

Bug 4 (the `phys_to_logical` CPU-only IPC contract) and the doc note are logically independent and could be split out, but they sit on the same rebalance path and are small, so they are kept here to avoid a second review round.

#### The fix invariant

`ascend_expert_map` is always a **global-physical → local-slot** map of length `num_experts` (logical + redundant). All consumers use the physical length directly or the new `phys_to_logical` bridge; `log2phy` output stays logical-length (router input unchanged).

| File | Change |
|---|---|
| `vllm_ascend/eplb/core/eplb_utils.py` | `init_eplb_config`: per-rank maps built full-length; returns `phys_to_logical` (flat placement; `None` for the `expert_map_path` layout, which keeps the legacy logical-length map); `generate_log2phy_map(..., phys_to_logical=None)` — physical-row grouping, output stays logical-length; `None` keeps the legacy behavior exactly. |
| `vllm_ascend/ops/fused_moe/routed_experts.py` | stores `phys_to_logical`; new `compute_local_phys_expert_ids`; `init_eplb` builds the NPU `local_phys_expert_ids` buffer and promotes it, with the runtime maps, to Level-2 sleep buffers; `update_ascend_eplb_maps` refreshes runtime maps and preserves device/dtype; `forward_impl` gathers the global histogram into per-slot counts. |
| `vllm_ascend/ops/fused_moe/token_dispatcher.py` | AllGather: `global_num_experts = self.num_experts` (physical total from `moe_config`) — value-identical in every existing case, immune to the map-length invariant; MC2: `moe_expert_num = len(expert_map)` (physical length) — value-identical. |
| `vllm_ascend/eplb/core/eplb_worker.py`, `vllm_ascend/eplb/eplb_updator.py` | `phys_to_logical` published **CPU-side** through `shared_dict` during `warm_up_eplb` and consumed in `pack_update_info`. |
| `vllm_ascend/eplb/adaptor/vllm_adaptor.py` | record file converts physical → logical IDs; `do_update_expert_map` refreshes layer runtime maps. |

The EPLB worker machinery (global2local/local2global, policies) is slot-value based and layout-agnostic — unchanged.

#### Out of scope

`mix_placement` + dynamic EPLB is an untested niche combination. With `mix_placement` the dispatcher's `expert_num` changes from `logical + 2*redundant + 2*shared` to `logical + redundant`; when `shared > redundant + 1` the max topk ID (`logical + shared - 1`) can exceed `expert_num`. No deployed config exercises this today, so it is left as-is rather than special-cased; if #12871 (remove mix placement support) lands, this note becomes moot.

#### Merge coordination

#12663 ("Vectorize EPLB log2phy map generation") and #9244 (RFC: make the log2phy mapping TP/DP-aware) both edit the same `generate_log2phy_map` function touched here; the merge order should be coordinated to avoid a function-level conflict.

#### Sleep/wake: runtime maps as Level-2 buffers

Level-2 sleep discards pooled NPU tensors that are not parameters/buffers and restores only `named_buffers()` on wake. `init_eplb` already promotes the EPLB NPU state (`log2phy`, `moe_load`, `load_counter`) to named buffers for that reason; this PR extends the same treatment to the new `local_phys_expert_ids` buffer and to the runtime maps. main's comment assumes `ascend_expert_map` "stays a plain CPU attribute and does not need promotion" because it is re-derived from the worker on every rebalance — but a sleep/wake cycle can land between two rebalances, in which case the AllGather mask (`expert_map[topk_ids]`) reads released storage after wake. The maps are promoted like `log2phy`.

**CI.** New acceptance test `tests/e2e/pull_request/two_card/test_qwen3_moe_eplb_a2.py` (Qwen3-30B-A3B-W8A8, TP2/EP2, dynamic EPLB, `num_redundant_experts=2`, exact-match vs. a non-EPLB baseline — the #14080 repro). It is routed to a dedicated `a2-2` partition (`linux-aarch64-a2b3-2`) via a file-specific `runner_mapping` pattern; no other routing changes. The test runs under the default (PIECEWISE) cudagraph mode; the #14080 crash was originally reported under `FULL_DECODE_ONLY`. The fix is graph-mode-agnostic: the post-rebalance map refresh is done in place (`copy_`, preserving tensor identity), so a captured graph that references the map's storage sees the updated values on replay rather than a stale map.

**Docs.** The blanket note "A2 does not support redundant experts" (added by #15458) is replaced with the verified constraint: the CANN grouped-matmul weight list is capped at 128 per rank, so 256-expert models need EP >= 4 while 128-expert models work with any EP size.

### Does this PR introduce _any_ user-facing change?

No API/interface change. Behavior change is limited to A2 + MRv1 + EPLB with `num_redundant_experts >= 0` dynamic mode, which previously crashed: dynamic EPLB now runs end-to-end. A3 (FUSED_MC2/MC2/ALLTOALL), A2 without EPLB, and MRv2 paths are value-identical pre/post patch. User-facing: the corrected doc note above.
