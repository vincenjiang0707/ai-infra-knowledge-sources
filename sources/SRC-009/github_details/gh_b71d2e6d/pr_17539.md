# [PR #17539] [BugFix][MRV2] Register every K/V cache view with KV connectors

source: https://github.com/vllm-project/vllm-ascend/pull/17539
state: open | updated: 2026-09-26T04:46:31Z

## 正文

### What this PR does / why we need it?

KV cache offloading stores and reloads each KV cache view separately. Ascend
keeps K and V in separate views, but under Model Runner V2 the KV cache map that
reaches `get_kv_connector` was flattened to a single tensor per layer, because
the runner filters that map by `.device`. Only the K view was therefore
registered with the offload connector: the CPU tier stored and reloaded half of
every layer, so a reloaded prefix cache no longer reproduced the cold-run output
(`test_simple_cpu_offload_accuracy` failed 0/5 on CI, and a manual reload
returned a different token on every attempt).

- `patch_v2/patch_attn_utils.py`: keep the complete per-layer (k, v) views on
  the map handed to `get_kv_connector`, while still exposing one tensor per
  layer to the runner. The runner-facing map class and the connector wrapper
  stay inside the patched function so no module-level names are added.
- `distributed/kv_transfer/kv_pool/kv_offload/simple/worker.py`: deduplicate
  registered KV caches by view geometry instead of the storage pointer, so K and
  V views sharing one Model Runner V2 allocation are both offloaded.

### Does this PR introduce *any* user-facing change?

No. KV cache offloading under Model Runner V2 now stores and reloads every K/V
view instead of half of them.

### How was this patch tested?

- UT pin the two boundaries: `tests/ut/kv_offload/test_mrv2_kv_cache_views.py`
  checks that the runner sees one tensor per layer while the connector receives
  every K/V view, and `tests/ut/simple_kv_offload` covers two views sliced out
  of one allocation.
- Verified on A2 (910B3, vllm `ced6857afa0ea7b2e3f0846a62e1394e90f15607`):
  - V2: `test_simple_cpu_offload.py` 3 passed; `test_cpu_offloading.py` 2 passed;
    V1 regression for both files also passes.
  - UT: `tests/ut/kv_offload` + `tests/ut/simple_kv_offload` 12 passed.
  - Without the fix V2 reloads returned different tokens every time (0/5).

- vLLM main: https://github.com/vllm-project/vllm/commit/ced6857afa0ea7b2e3f0846a62e1394e90f15607
