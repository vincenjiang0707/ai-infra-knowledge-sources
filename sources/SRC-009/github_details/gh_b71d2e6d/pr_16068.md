## 正文

### What this PR does / why we need it?

Integrate native AttnResFwd into Kimi K3 on `main` to compute the learned residual mixture.

- Add ACLNN/AscendC kernels for A3 and A5, tiling, build integration, PyTorch registration, and Meta dispatch.
- Call the registered native operator directly and return the prefix for zero valid blocks. Remove the unused Triton implementation and fallback paths.
- Pass tensor views directly to ACLNN, which handles noncontiguous inputs. The kernel still consumes a contiguous layout, so block packing remains necessary.
- Fix resident-row copies to cover the entire BF16 row and document the interface in the repository's operator format.

### Does this PR introduce _any_ user-facing change?

Kimi K3 residual mixing uses `torch.ops._C_ascend.attn_res_fwd` and requires the custom extension and operator package. The interface accepts noncontiguous BF16 inputs; zero valid blocks retain the existing direct-return behavior.

### How was this patch tested?

- Accuracy validation (reported by the project owner): **GPQA Avg@5: 93.03**.
- Built the updated AttnResFwd package and validated the ACLNN kernels on Ascend 950DT/A5 through an isolated binding using this PR's C++ adapter: **40 passed** (5 token/block/hidden shapes, 2 epsilon values, and contiguous, block-slice, strided-offset, and transposed layouts). BF16 outputs match an FP32 reference at unchanged `rtol=atol=0.01`.
- Both residual adapter tests passed in isolated CPU execution with the native operator mocked, covering valid-block views and the zero-block return.
- Changed-file Ruff check/format, Markdown lint, and diff checks passed. The complete local `format.sh ci` stopped during actionlint environment installation with a connection reset; CI status is tracked separately.
- A3 kernels and full model integration were not exercised by the isolated A5 test.
