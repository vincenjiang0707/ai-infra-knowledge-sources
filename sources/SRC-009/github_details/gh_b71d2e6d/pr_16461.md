# [PR #16461] [BugFix][KVTransfer] Keep AscendStore receive registration until completion

## 正文

### What this PR does / why we need it?

Fixes #16460.

When a request is aborted while waiting for an asynchronous AscendStore load, the core scheduler retains its KV blocks until receive completion. AscendStore currently removes the request from `_loading_req_ids` when it sees `finished_req_ids`. The worker filters receive completions against that set, so the completion is never reported and the deferred release cannot finish.

Keep the receive registration across request termination, and clear it through the existing `update_finished_recving()` method when connector output reports completion. This also clears registrations after normal receives. The scheduler's ownership assertions, worker completion filter and preemption cleanup remain unchanged.

Updated against upstream `bea70ab8` on September 25 as a single linear commit. This replaces the previous merge-based update, whose original commit conflicted when CI replayed it with `git rebase`. The file tree is unchanged from `51674873`, and a local replay of the CI rebase command passed. The send-side cleanup from #16119 is preserved; the send-state regression checks the current `sending_events` and `sending_blocks` bookkeeping. This PR still changes only the scheduler and its unit tests.

Related work: #14132 addresses load/save co-queueing. #16119 removes the synchronous-save delayed-free handshake but leaves this receive-registration path unchanged. This change addresses missing receive completion, distinct from the late notification for an already-removed request described in vllm-project/vllm#43226.

### Does this PR introduce _any_ user-facing change?

Aborted requests can complete their deferred KV-block release after asynchronous AscendStore loads finish. No API or configuration changes.
