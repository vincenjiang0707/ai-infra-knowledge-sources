Title: [Feature][Quantization] Add online quantization weight ops and per-layer cosine accuracy tool

---
### What this PR does / why we need it?

Groundwork for online (load-time) quantization of unquantized checkpoints. Today a BF16 checkpoint has no in-process path to a low-bit runtime on Ascend: the three documented routes all require offline tooling (docs/source/user_guide/feature_guide/quantization.md). The only in-tree load-time requant precedent is the FP8-block → MXFP8 path on 950 (`fp8_block.py`). This PR adds the reusable weight-side kernels and the accuracy harness that a follow-up `--quantization online` config/adapter will consume, so the math and layout contracts are reviewable in isolation.

**`vllm_ascend/quantization/online/weight_ops.py`**:

- `quantize_weight_int8_per_channel`: symmetric per-channel (output dim) int8 with fp32 scale, 1024-row chunked peak-memory control, plus a CPU reference oracle. Layout follows the `w8a8_dynamic` loading convention so the existing runtime consumes it unchanged.
- `quantize_weight_mx_fp8`: MXFP8 (group=32) weights with E8M0 scales. The scale uses the ceil-to-UE8M0 rule (`scale = 2^ceil(log2(amax/448))`), matching the production semantics in `deep_gemm.py::_ceil_to_ue8m0` and `kpool_compress.py` — the naive floor rule saturates (amax/scale up to 896 > 448) and is rejected in tests. NPU wrapper around `npu_dynamic_mx_quant` (hardware-gated) with a CPU reference.
- MXFP4 entry point is an explicit stub for the follow-up PR.

**`accuracy.py`**: forward-hook based per-layer cosine comparison between two model instances (BF16 baseline vs quantized), markdown report rendering, pure-CPU runnable — fills the gap called out in #15346 (no measured per-layer baseline tooling).

### Accuracy contract

int8/MXFP8 quantize→dequantantine vs reference: cosine ≥ 0.999 asserted on random and adversarial (outlier-heavy) matrices; chunked and full-tensor paths bit-identical; MX scales are exact powers of two.

### How was this patch tested?

- `tests/ut/quantization/online/test_weight_ops.py`: 40 cases (39 pass, 1 NPU-gated skip)
- Neighboring quantization UTs: 58 passed, no regression
- ruff clean
