## What this PR does / why we need it?

This PR completely removes the image build pipeline's dependency on the internal cache-service mirror, so builds use public sources only (the cluster relies on a squid proxy cache for public sources; a separately maintained internal mirror service is no longer needed).

Changes:

- **8 root Dockerfiles** (`Dockerfile` / `.a3` / `.a5` / `.310p` / `.openEuler` variants): remove all internal mirror ARGs (`APTMIRROR`, `YUM_MIRROR`, `PIP_INDEX_URL`, `PIP_TRUSTED_HOST`, `GIT_PROXY`, `RUSTUP_DIST_SERVER`, `RUSTUP_UPDATE_ROOT`, `CRATES_IO_INDEX`, `MOONCAKE_INDEX_URL`) and the corresponding APT source replacement / pip index configuration / git proxy / rustup pre-install / cargo mirror configuration logic, plus the final restore-public-sources RUN step; layer structure is kept unchanged
- **4 nightly Dockerfiles** (`.github/workflows/dockerfiles/Dockerfile.nightly.*`): remove the `PIP_INDEX_URL` / `PIP_TRUSTED_HOST` / `GIT_PROXY` ARGs and the pip config / git proxy logic; keep the public `PIP_EXTRA_INDEX_URL`
- **`.github/workflows/_schedule_image_build.yaml`**: remove the `aptmirror` input, the `APTMIRROR` env var and all internal cache-service build-args (the `COMPILE_CUSTOM_KERNELS` dynamic logic is kept unchanged)
- **`.github/workflows/_nightly_image_build.yaml`**: remove the internal cache-service env block and its 4 build-args
- **Delete `.github/workflows/scripts/restore_public_sources.sh`**: internal sources are no longer swapped in, so the restore script is dead code

Kept unchanged: the public source configuration `PYTORCH_INDEX_URL` / `ASCEND_INDEX_URL` / `PIP_EXTRA_INDEX_URL`; test workflows (`pr_test.yaml` / `_selected_tests.yaml` / etc.) are out of scope for this PR.

Note: builds against existing base images may still show tuna as the pip index — that is baked into the current public base images' `pip.conf` and will disappear once base images are rebuilt without it.

## Does this PR introduce _any_ user-facing change?

No. This only affects the internal configuration of the CI image build pipeline; the behavior of the produced images is unchanged.
