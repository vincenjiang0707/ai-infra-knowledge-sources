## 正文

### What this PR does / why we need it?

Port PR #14269 (merged into releases/v0.26.0rc) to the releases/v0.23.0 branch. Removes the batch_matmul_transpose custom operator and all of its build wiring. The operator is no longer needed: the MLA v_up_proj path already had a fallback to torch_npu.npu_transpose_batchmatmul (and torch.bmm), which now becomes the primary path.

- Delete csrc/batch_matmul_transpose/ (kernel, op_host, tiling, adapter)
- Drop CMakeLists.txt entries: kernel sources, the A5 exclude list and its status message, tiling_data.cpp, and the op_host include directory
- Remove the op def/impl registration in torch_binding.cpp and the meta implementation in torch_binding_meta.cpp; drop the batch_matmul_transpose_impl extern declaration in csrc/ops.h
- Remove the batch_matmul_transpose branch in sfa_v1.py::_v_up_proj and the now-unused BMM_TRANS_MAX_SUPPORTED_TOKENS constant; split the npu_transpose_batchmatmul path by the N*L<65536 aclnn constraint, including the ACL graph K*B<65536 bypass
- Delete the nightly test test_batch_matmul_transpose.py

Commits are cherry-picked from PR #14269 (5 commits, no conflicts on this branch).

### Does this PR introduce _any_ user-facing change?

No public API change. The MLA v_up_proj computation result is unchanged; only the underlying kernel selection changes (falls back to the existing npu_transpose_batchmatmul / torch.bmm path).

### How was this patch tested?

- ruff check / format pass on the modified sfa_v1.py
- Existing MLA/SFA tests cover the now-primary npu_transpose_batchmatmul path
