# [PR #17477] [BugFix][A5] Package DCP SFA and fix INT8 indexer weights dtype

## 正文

### What this PR does / why we need it?

Fix two integration blockers encountered when serving GLM-5.2 MXFP4 on
Ascend 950 with TP8/DCP8, graph mode, and an INT8 indexer cache.

This branch starts directly from `72bde513b321d686173aa9de99dc796e2f45276e`,
the vllm-ascend revision recorded by the 2026-09-22 A5 image
(`0.19.1rc2.dev2296+g72bde513b.d20260921`). It does not include unrelated
post-image changes or reimplement the SFA numerical fixes already merged in #16656.

Changes:

1. **Build/package the existing A5 SFA implementation.** Add
   `sparse_flash_attention` to the Ascend 950 custom ACLNN build list. In the
   affected image the custom op API library did not export SFA, and the
   fallback CANN implementation rejected `PA_BSND` with `return_softmax_lse`.
   The in-tree implementation is needed for this DCP configuration.
2. **Restore the Buffer interface used by that implementation.** Add
   `SetCrossCoreID(id0, id1)` to `attention/common/op_kernel/buffer.h`, matching
   the setter already present in `attn_buffer.h`. The A5 SFA caller explicitly
   assigns these event IDs. This only assigns the two fields; it does not
   change the caller's flags, Set/Wait ordering, attention math, or LSE math.
3. **Match the A5 INT8 indexer operator signature.** Convert weights to FP16
   only when the quantized query is INT8. The failing configuration passed
   BF16 weights to the CANN 9.1 INT8 QuantLightningIndexer signature. Leave
   FP8, unquantized paths, query/key tensors, and dequantization scales unchanged.
4. **Add regression coverage.** Eight indexer cases in
   `tests/ut/device/test_a5_indexer_weights.py` cover INT8/FP8 and
   unquantized dtype handling; five shell-entry-point cases cover A5 variants,
   A2, A3 and 310P custom-op selection with a stub compiler/installer.

No machine-specific deployment files, custom vendor names, offline dependency
paths, ONNX-build bypasses, model weights, or compiled binaries are included.

### Does this PR introduce _any_ user-facing change?

Yes. A5 builds include the existing SFA custom op, and INT8 indexer calls with
BF16 model activations no longer fail because of the weights argument dtype.
There are no new CLI options or environment variables. The main MLA KV cache
in the reported model test remained BF16 (`--kv-cache-dtype auto`); INT8 refers
to the indexer cache, not all KV tensors.

### How was this patch tested?

**Tests of this exact source patch:**

```bash
TORCH_DEVICE_BACKEND_AUTOLOAD=0 python -m pytest -q \
  tests/ut/device/test_device_op.py \
  tests/ut/device/test_a5_indexer_weights.py tests/ut/test_build_aclnn.py
```

- **17 passed** using the repository's CPU mock fixtures, including 13 new
  regression cases. The test runner selected CPU fixtures without allocating
  NPU memory or interrupting the running model service.
- Negative control: run the same tests against unmodified `72bde513b`:
  **3 failed, 14 passed**. Failures are exactly INT8 query + BF16 weights and
  the two A5 build-list cases. FP8, unquantized, A2/A3/310P cases stay green.
- Ruff 0.14.0 check/format, shell syntax and `git diff --check` passed.
- Full pre-commit was attempted but could not initialize its GitHub-hosted
  hooks because GitHub HTTPS was unreachable from the local git client.
  This is not reported as a full pre-commit or CI pass.

**Earlier hardware validation of the same production fixes:**

- Ascend 950DT, CANN 9.1.0, torch_npu 2.10.0.post4, the 2026-09-22 A5 image.
- Built both BF16/FP16 SFA kernels with the Buffer setter, then checked the
  loaded library through the actual model worker import path. That isolated
  build used source `d0450c5c0`; `git diff 72bde513b d0450c5c0` is empty for
  `csrc/attention/sparse_flash_attention`, `csrc/attention/common`,
  `csrc/common`, and the SFA LSE regression file. Offline build accommodations
  were limited to dependency resolution and the unrelated ONNX converter and
  are deliberately not included here.
- All six existing `test_sparse_flash_attention_dcp_lse.py` cases passed:
  selected-key counts 0, 1, 127, 128, 129 and 257, checking attention output
  and reconstructed LSE against a CPU reference, including the empty shard.
- The INT8/FP16-weights QuantLightningIndexer hardware smoke test passed.
- GLM-5.2 MXFP4, TP8/DCP8/EP, PCP1/PP1/DP1, max sequences 1,
  max batched tokens 4096, block size/interleave 128, memory utilization 0.95:
  PIECEWISE and FULL-decode graph capture completed, followed by a request
  with **131,072 input + 2,048 output tokens**. Metrics confirmed all 131,072
  input tokens were computed and both local/external cache hits were zero.
  TTFT was 41.8936 s; total latency was 104.1005 s. Final usage, SSE completion,
  health and three post-request functional checks passed.

**Limits:** the full A5 wheel was not rebuilt through the complete multi-op
packaging pipeline; the build-list tests use stubs. A2/A3 kernel builds and
full upstream CI are still required. FP8 tests here verify dispatch/dtype
preservation, not FP8 kernel accuracy. The model request used synthetic input
and `ignore_eos=true` to force 2,048 output tokens: it establishes execution
and capacity, not long-context quality. Although the service was configured
with `max-model-len=1024000`, a complete 1M request, speculative decoding, and
comprehensive model accuracy are **not** claimed as validated.
