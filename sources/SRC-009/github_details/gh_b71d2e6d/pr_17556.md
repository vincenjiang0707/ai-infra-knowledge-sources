# [PR #17556] [BugFix][Worker] Port V2 kernel warmup with enable_jit_warmup guard

## 正文

## What this PR does / why we need it?

`NPUWorker.compile_or_warm_up_model` never calls upstream `warmup_kernels`. That function runs dummy prefill and decode steps so the V2 Triton kernels compile at startup. Without it, both phases compile on the first real request.

Cold cache, 8 × 910B, DeepSeek-V4 TP8, dspark, warmup off: first token **46.68s** (prefill, no output yet), first content token **87.02s** (decode compile adds about **40s**). After this call, first content token was **28.46s**.

The call is guarded by `use_v2_model_runner` and `kernel_config.enable_jit_warmup`, matching upstream. `enforce_eager` turns the second guard off.

## Does this PR introduce _any_ user-facing change?

No API change. Startup pays for the warmup pass. Users who disable JIT warmup are unchanged.

## How was this patch tested?

Cold `TRITON_CACHE_DIR`, 8 × Ascend 910B, DeepSeek-V4 TP8, dspark `num_speculative_tokens=7`. Warmup off: first token 46.68s, first content token 87.02s. With the call: first content token 28.46s. Warmup logged on the ranks, streaming responses checked.

`tests/ut/worker/test_worker_v1.py` builds an `NPUWorker` with `__init__` stubbed out and calls `compile_or_warm_up_model`. Those tests do not set `use_v2_model_runner`, so the new attribute read raises `AttributeError`. Set it to `False` in:

- `test_compile_or_warm_up_model_with_eager_mode`
- `test_compile_or_warm_up_model_with_graph_capture`
- `test_compile_or_warm_up_model_saves_startup_plan_after_graph_capture`
- vLLM main: https://github.com/vllm-project/vllm/commit/ced6857afa0ea7b2e3f0846a62e1394e90f15607
