## 正文


### What this PR does / why we need it?

Enables GLM-5.3-Flash + DFlash2 speculative decoding on Model Runner V2 with vLLM 0.30.

**Target-side support**

GLM-5.3-Flash is an mHC model: between decoder layers flows the *deferred*
`hc_post` state (raw FFN output + n residual streams + post/comb weights).
The DFlash drafter consumes the target's per-layer hidden states contracted
to a single stream, so the completed output of layer k must be materialized
with `hc_post` before contracting — `hc_contract(hidden_states + residual)`,
the semantics SGLang implements for the same drafter
(sgl-project/sglang#36708). This adds the aux hidden-state capture to
`Glm5NextModel.forward` plus the `SupportsEagle3` plumbing, and adapts the
existing PP contract UT stub to the new layer-index attributes.

**MRV2 + vLLM 0.30 enabling fixes**

Without these, no GLM-5.3-Flash engine — not even plain serving — can
initialize on MRV2 with vLLM 0.30 (upstream `main` is affected):

- MRV2 `_allocate_kv_cache` rejected the GLM-Next pooled descriptors
  (`layer_stride == 0`) after vLLM #51718; the pooled allocation and
  per-layer views only existed on MRV1. Port the MRV1 semantics: one shared
  backing per pooled slot, private buffers for foreign descriptors, and
  glm5 layer views built through `view_glm5_next_cache`.
- The DFlash2 drafter (a Qwen3 sliding-window layer integrated as extra
  target layers) produced a plain `SlidingWindowSpec` that the GLM-Next
  grouping rejected as an unsupported cache role. Foreign specs now keep
  the generic grouping alongside the pooled layout, with standard packed
  descriptors.
- The engine core recomputes `cache_config.block_size` as the minimum over
  prefix-cacheable groups; the drafter's 128-token kernel block dragged it
  below the platform-aligned blocks and desynced the SFA metadata and KPool
  indexer sizing. The drafter's sliding-window cache now opts out of prefix
  hashing (mirroring the kpool tail exclusion).
- The compressor tail ring capacity (`kpool + num_speculative_tokens`) did
  not divide the platform-aligned attention block size and tripped the
  coordinator divisibility assertion; it is now rounded up to a power of two.
- A NoPE rope (rotary_dim == 0 — the sparse-indexer rope of a text-only
  `Glm5NextForCausalLM`) crashed `AscendRotaryEmbedding`'s module-global
  recording. #17552 proposes the same fix at the model layer (skip
  constructing the rope); this PR guards the op-layer recording instead —
  either suffices, and I'm happy to rebase onto #17552 once it merges and
  drop the guard.

**Related but not duplicated**

#16358 adds the DFlash2 speculator (`AscendDFlash2Speculator`, probabilistic
selector kernel) — the speculator side of the same feature. This PR is the
GLM-5.3-Flash target side plus the MRV2 cache infrastructure; there is zero
file overlap. With both, GLM-5.3-Flash + DFlash2 works end to end on MRV2
(this PR's e2e passes using the existing dflash speculator with greedy
decoding).

### Does this PR introduce _any_ user-facing change?

Yes — it enables a new capability: GLM-5.3-Flash with DFlash2 speculative
decoding on Model Runner V2 (`VLLM_USE_V2_MODEL_RUNNER=1`), with the serving
recipe documented in `speculative_decoding.md`. It also fixes GLM-5.3-Flash
engine initialization on MRV2 in general (plain serving was broken on `main`
with vLLM 0.30).

### How was this patch tested?

- **e2e** (single Ascend 910B, nightly image, vLLM 0.30.0 @ ced6857):
  `pytest -sv tests/e2e/pull_request/one_card/model_runner_v2/test_glm5_next_dflash2.py`
  → 2 passed. Single-NPU synthetic GLM-5.3-Flash target + DFlash2DraftModel
  drafter with dummy weights (same recipe as the K3 synthetic test): the
  whole chain (target aux capture → fc combine → draft context-KV precompute
  → parallel draft → rejection sampling) runs, `vllm:spec_decode_num_drafts`
  is non-zero, and greedy spec output matches the non-speculative baseline
  token for token.
- **Unit tests**: full `pytest tests/ut` sweep on the same box — 6700+
  passed; the remaining failure set is identical to upstream `main`
  (pre-existing failures in `_310p` / `eplb` / `gdn` / `quantization` /
  `eagle_proposer` / `bisect`, plus one environmental collection error for a
  missing `pytest_mock` in the runtime image). The glm5next suites pass
  (53/53 including the PP contract tests).
- **Lint**: `ruff check` / `ruff format` (v0.14.0), `typos` (v1.32.0) and
  `markdownlint-cli` (v0.45.0) all clean.
