# [PR #17269] [BugFix][Ops] Skip negative padding slots in scatter HP paths

## 正文

### What this PR does / why we need it?

`npu_scatter_nd_update_sk` receives negative padding slots from compressed-cache metadata. For example, `[-1, 31]` in a 32-token page flattens to linear index `-1`. The arch22 HP batch and slice copy paths currently calculate output addresses for these rows instead of skipping them. This can overwrite bytes before a cache view, including another region in its backing allocation. The no-sort path already ignores negative linear indices.

Keep the batch-copy index signed until checking it, and skip negative indices in the wide-row slice path. The batch path still advances its source offset for skipped rows, preserving subsequent valid updates and pipeline signaling.

Add 32 cases to the existing native scatter operator test: mixed valid/padding and all-padding slots; int32/int64 indices; BF16 compressed KV, INT8 keys, FP16 scales and 256-KiB rows; two nonzero-offset guard layouts. Each case compares the complete backing allocation with a CPU reference, including shared-page regions, gaps and guard bytes. No PyPTO dependency or helper is introduced.

Related: #17214 also contains negative-slot checks as part of a broader model/device-adaptor change. This PR isolates the native-kernel correctness fix and operator regression coverage, with no caller migration or performance optimization.

### Does this PR introduce _any_ user-facing change?

Padding rows with negative linear indices leave the cache untouched instead of writing outside its logical view. Valid writes retain their existing behavior. No public API or configuration change.

### How was this patch tested?

Based on upstream `1ebf3a6c3a887b00bf680a2184b78af7aacae2ac`.

- **70 native operator tests passed on A3 / CANN 9.0**, including all 32 new padding cases. Executed the existing `test_scatter_nd_update_sk.py` file using pytest with `--confcutdir=tests/e2e/nightly/single_node/ops/singlecard_ops` to isolate the operator tests from model-level conftest setup.
- The test process loaded an existing locally built native extension and the previously rebuilt scatter-fix custom-OPP package. The complete `csrc/moe/scatter_nd_update_sk` source directory was compared byte-for-byte with this PR's source; all 17 installed native artifact hashes matched the recorded scatter-fix build manifest. This is reuse of the matching operator build, not a fresh full build of upstream main.
- Earlier local reproduction with the old binary observed out-of-view changes for BF16 cache, INT8 key and FP16 scale padding cases. The newly added 32-case test matrix was run against the patched binary; no new unpatched-binary matrix is claimed.
- Ruff lint/format and `git diff --check` passed.
- A2/A5 hardware, a full-model run and performance measurements were not run for this PR.
- vLLM main: https://github.com/vllm-project/vllm/commit/84030bbe3d74d99bad477a3d2e37a973ccd8865c
