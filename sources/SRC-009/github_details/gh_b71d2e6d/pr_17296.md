## 正文

### What this PR does / why we need it?

Adds **Laya** (`convaiinnovations/laya`) support on Ascend.

Laya is **not a generative LLM** — it is a bidirectional ModernBERT encoder (28 layers, hidden 1024) followed by a small transformer decision head, served through vLLM's **pooling** (`classify`) interface.

Every answer option is represented by a `[MASK]` marker token in the prompt; the head scores each marker, and the softmax over those marker scores is the answer distribution. A second head predicts whether the agent should escalate to a human.

One request carries exactly one question. The returned `probs` vector is:

```
[p_0, ..., p_{K-1}, act_escalate, act_not_escalate]
```

where `K` is the number of options — the final two entries come from the act head.

**Changes:**

| File | What |
| :--- | :--- |
| `vllm_ascend/models/laya.py` **(new)** | `LayaForDecision` + `LayaPooler`. 28-layer ModernBERT encoder with per-layer rope theta (160000 full / 10000 sliding), decision head (`head` / `act_head` / `scorer` / `type_emb`), option-count temperature bucket. |
| `vllm_ascend/models/__init__.py` | Register `LayaForDecision` through the built-in `register_model()` hook — **no vllm-side change required**. |
| `vllm_ascend/patch/platform/patch_encoder_sliding_window.py` **(new)** | The encoder-only attention path lost its sliding window (`npu_fusion_attention` called without `atten_mask`, `sparse_mode=0`). Builds a band mask and clamps q/k/v to `actual_seq_qlen[-1]`. |
| `vllm_ascend/patch/platform/patch_mha_fastpath.py` **(new)** | Disables the `torch.backends.mha` fastpath so `MultiheadAttention` / `TransformerEncoderLayer` do not silently fall back to CPU. |
| `vllm_ascend/patch/platform/__init__.py` | Hooks the two new platform patches. |
| `vllm_ascend/attention/attention_v1.py` | Write encoder attention output back with a guarded `copy_` instead of double slicing. |

### Does this PR introduce *any* user-facing change?

Yes — `LayaForDecision` becomes a supported architecture on Ascend. Users can serve a Laya checkpoint through `vllm serve <path>` using the pooling / `classify` task; the two platform patches apply automatically.

It also fixes two pre-existing correctness/performance issues on the encoder-only path (see the patch entries above), which affect any encoder model routed through the same code, not only Laya.

### How was this patch tested?

**Encoder sliding-window patch**
The encoder-only path previously called `npu_fusion_attention` without `atten_mask` and with `sparse_mode=0`, so sliding-window layers attended over the full sequence instead of the window. With the band mask + `actual_seq_qlen[-1]` clamp the per-layer attention now matches the intended window.

**MHA fastpath patch**
Measured on the classify head: **711 ms → 2.1 ms** after disabling the `torch.backends.mha` fastpath, which was silently dispatching to CPU.

**`attention_v1.py` output write-back**
**40 µs → 21 µs** per layer by replacing the double slice with a guarded `copy_`.
