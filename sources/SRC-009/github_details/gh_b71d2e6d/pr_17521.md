## 正文

### What this PR does / why we need it?

ModelSlim checkpoints can describe standalone linear projections as `W4A8_DYNAMIC`, but vLLM Ascend currently registers that format only for fused MoE layers. Models whose shared experts are implemented as a regular MLP therefore cannot construct their W4A8 gate/up/down projections.

This PR:

- registers a generic `W4A8_DYNAMIC/linear` scheme for ModelSlim per-channel packed INT4 weights;
- loads `weight_scale`, `weight_offset`, and `scale_bias`, converts the packed weight to WeightNZ, and executes the projection as one `npu_grouped_matmul` group;
- keeps shared-expert projections carrying `scale_bias` on their registered linear wrappers, because the direct A8 shared-expert path does not consume that correction term;
- adds ModelSlim resolution, weight-layout, grouped-matmul, validation, and shared-expert path-selection coverage;
- updates the Kimi K3 W4A8 E2E fixture so both routed and shared experts use W4A8.

The implementation is selected by quantization format and layer type. It does not add Kimi-specific quantization classes or model checks, and it does not modify ModelSlim's dispatch logic.

### Does this PR introduce _any_ user-facing change?

Yes. ModelSlim per-channel `W4A8_DYNAMIC` linear layers are now supported. This enables checkpoints with standalone W4A8 shared-expert projections, including Kimi K3 all-W4A8 expert checkpoints.

Unsupported layouts still fail explicitly: the scheme requires per-channel weights (`group_size=0`) and quantization description version `1.0.0`.

### How was this patch tested?

Added or updated unit coverage for:

- generic `W4A8_DYNAMIC/linear` scheme registration;
- ModelSlim selection of the scheme for a packed shared-expert projection;
- packed weight and scale parameter shapes;
- unsupported group size and version validation;
- post-load WeightNZ/int32 conversion;
- single-group `npu_grouped_matmul` execution;
- shared-expert fallback to the linear wrapper when `scale_bias` is present.
