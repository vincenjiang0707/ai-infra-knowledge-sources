## 正文

### What this PR does / why we need it?

Rename the AscendC `chunk_fwd_o` operator to `chunk_fwd_o_vllm` to avoid naming conflicts with the upstream Triton implementation, following the same naming convention as `causal_conv1d_v310`.

- Rename operator directory `csrc/moe/chunk_fwd_o` -> `csrc/moe/chunk_fwd_o_vllm` and internal source files
- Update full symbol chain: OpDef class (`ChunkFwdO` -> `ChunkFwdOVllm`), tiling data, `l0op::ChunkFwdOVllm`, `aclnnChunkFwdOVllm*` C API, kernel entry `chunk_fwd_o_vllm`
- Update torch binding schema and registration (`torch.ops._C_ascend.chunk_fwd_o_vllm`) for both vLLM version branches
- Update `build_aclnn.sh` custom op list, Python callers (`vllm_ascend/ops/triton/fla/chunk.py`, `vllm_ascend/_310p/ops/fla/chunk_gated_delta_rule.py`), UT mocks, e2e test file and CI op registration check

### Does this PR introduce _any_ user-facing change?

Yes. The torch.ops registration name changes from `torch.ops._C_ascend.chunk_fwd_o` to `torch.ops._C_ascend.chunk_fwd_o_vllm`. All in-repo callers are updated in this PR.

### How was this patch tested?

- Verified no remaining old-name references (`chunk_fwd_o` / `ChunkFwdO` / `aclnnChunkFwdO`) except the unrelated Triton-side Python wrapper (`vllm_ascend/ops/triton/fla/chunk_o.py::chunk_fwd_o`), which is intentionally unchanged
- `tests/ut/ops/test_gdn_chunk_meta.py` mocks updated to the new op name
- e2e test renamed to `test_chunk_fwd_o_vllm_310.py` and updated to call the new binding
