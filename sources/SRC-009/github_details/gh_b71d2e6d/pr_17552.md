# [PR #17552] [BugFix][Model] Skip zero-width GLM5-Next indexer RoPE for NoPE

source: https://github.com/vllm-project/vllm-ascend/pull/17552
state: open | updated: 2026-09-27T01:21:30Z

## 正文

### What this PR does / why we need it?

GLM-5.3-Flash NoPE checkpoints set `qk_rope_head_dim=0`. The sparse indexer currently constructs a zero-width rotary embedding anyway, and its interleaved cache reshape aborts model initialization. Construct the indexer RoPE only when the rotary dimension is positive. This is a focused runtime prerequisite for #17273; the same guard also appears in the broader draft #17281, which should drop the duplicate when rebased.

### Does this PR introduce _any_ user-facing change?

Yes. NoPE GLM5-Next models can initialize instead of failing at zero-width RoPE cache construction. Nonzero rotary dimensions retain the existing behavior.

### How was this patch tested?

- `ruff check` and `ruff format --check` passed for both changed files; `git diff --check` passed.
- On A3 80.5.9.103 with the Sep 23 `nightly-main-a3` image and four visible NPUs, the NoPE regression test passed for both `rope_dim=0` and `rope_dim=64` (2 passed).
- In a task-only synthetic combination of #17273 at `6b8966b84` and the runtime changes from #17281 at `eb214398e`, the TP4 functional smoke passed in eager and graph modes (1 passed each, exit 0). This is **not** a claim that #17273 alone or this exact latest-main branch has passed end-to-end. The combination used the image's prebuilt native extension, not a rebuild of #17281's C++ change.
