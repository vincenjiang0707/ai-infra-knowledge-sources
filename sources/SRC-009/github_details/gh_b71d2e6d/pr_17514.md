## What this PR does / why we need it?

This is PR 6/6 of the STAIR EPLB series proposed in #17506. It integrates the data-plane, statistics, transfer, and planning components into Model Runner V2 without changing the legacy V1 policy path.

The preceding data-plane, statistics, load-planning, and constrained-placement PRs have merged. The only remaining dependency is #17510, which provides explicit-source asynchronous transfer. Until #17510 merges, this PR's visible diff also contains that dependency; review this PR after, or on top of, #17510.

The integration:

- selects `default` or `stair` exclusively through the upstream `EPLBConfig.policy` field;
- keeps MRV2 `additional_config.eplb_config` limited to `load_collection_phase` and detailed `stair_config` tuning;
- constructs policies through a small factory and keeps the default policy on the upstream behavior;
- uses the existing EPLB CPU group to statically shard PP-stage-local layers and reconstruct the deterministic plan with all-gather, without a rank-0 planning coordinator;
- preserves weighted temporal bins through the common `rebalance_experts` entry point;
- runs STAIR's CPU planning in one persistent child process with bounded BLAS threads and a framed NPZ/JSON local protocol (`allow_pickle=False`);
- supplies stage-local node topology and per-layer ratios from the last placement that actually committed;
- attaches exact source coordinates for constrained asynchronous transfers and advances hysteresis anchors only after the corresponding layer commits;
- logs committed-cycle mean/p95 ratios before and after planning, changed-layer count, cross-rank transfer count, and cross-node transfer count.

The architecture keeps generic EPLB lifecycle and publication in `AscendEplbState`, policy-specific statistics and planning in `StairEplbPolicy`, and narrow upstream compatibility adapters in `patch_eplb.py`. Future policies can therefore reuse the framework without inheriting STAIR's binning, covariance, subprocess, or placement constraints.

RFC: #17506

Upstream extensibility context: https://github.com/vllm-project/vllm/issues/33549

## Does this PR introduce _any_ user-facing change?

Yes. Model Runner V2 can select the STAIR EPLB policy and tune its advanced parameters. Defaults are intended to work without tuning. The upstream `default` policy remains selectable for experiments and compatibility.

## How was this patch tested?

- 132 focused unit tests passed for STAIR planning, the planner process protocol, layer sharding, policy statistics, state, upstream adapters, and MRV2 controller/load collection.
- The same 132 focused tests passed in a real Ascend NPU environment using the exact pushed commit.
- `bash format.sh ci` passed, including Ruff, spelling, markdown, secret scan, forbidden-import, and repository-specific checks.
