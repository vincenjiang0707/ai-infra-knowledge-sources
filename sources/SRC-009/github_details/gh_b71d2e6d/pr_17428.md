### What this PR does / why we need it?

**Dependency / joint-validation Draft. Depends on #16456; not ready for merge.**

This branch combines the strided MLA cache dependency with a minimal MRV2 BF16
FlashMLA tiling-offload integration so both can be validated together on A5.
It is not a claim that either part has passed hardware acceptance.

Review boundaries:

- **Cache ownership:** #16456, pinned at `a583897e0c67d9c23288686728124b04b511a462`,
  supplies the token-fused strided cache and its allocator/lifecycle changes.
  Those changes remain attributed to that PR and are included here as a dependency.
- **Operator increment:** `4647cd8182152307c5cd8456b768aa48bc74b261`, one signed-off
  commit on integration base `f38a89de02c8b1a88a54a6a1e5f8b1debe3923e5`.
  [Operator-only Draft and seven-file diff](https://github.com/Henry-Avery/vllm-ascend/pull/3/files).
  Four production files add 278 lines; the other three files are tests/documentation.
- **Main baseline:** `ad7a731b9c0db2592bbe1f568a776207745017ed`, already containing
  #16347 via `d4511510e15eb52744089e40d8cd7c9fc23ac0f4`. No separate DSpark port
  is added by the operator increment.

Against this main baseline the combined Draft contains 19 files and 18 commits.
That larger diff includes the cache dependency history; it is not all new
FlashMLA work. The existing dependency PR and fork Draft remain unchanged.

The operator integration connects:

1. MRV2 device sequence lengths and query boundaries to
   `flash_mla_with_kvcache_metadata`.
2. The resulting fresh per-batch schedule, Q, original cache view and block table
   to `flash_mla_with_kvcache` on the current stream.
3. Head-major latent output to the existing V-up, optional gate and O projection.

The adapter does not convert device sequence lengths into host lists. It does
not claim elimination of all engine synchronization. Relative to the dependency
base it does not change allocators, COW, zeroing, runner cache views or models.

### Does this PR introduce _any_ user-facing change?

Default-off `VLLM_ASCEND_ENABLE_FLASH_MLA=1` opts into the external operator pair.
The minimal route requires A5, MRV2, BF16 dense MLA, unquantized BF16 KV,
`--enforce-eager`, PCP/DCP=1, no speculative decoding and no PD/KV transfer.
Unsupported modes fail explicitly; absent operators do not silently fall back.

Install both operators from `cann_ops_transformer.ops`. Contract: actual local
Q heads 8/12/64/96; Q `TND`, cache `PA_BBND [P,128,1,576]`, output `NTD` with
value width 512; both max-length attributes -1/-1. Device cumulative query
boundaries, used-query lengths and KV lengths are shared by the two calls.
Cache stride/offset are preserved, padding cannot write cache slots, and no LSE
merge is required. RoPE/NoPE and ordinary projection semantics are retained.

No C8, DSpark-specific integration, graph lifecycle, DCP history/current merge,
new native kernels or output fusion is added. See
`docs/flash_mla_tiling_offload.md` for the contract and reproduction steps.

### How was this patch tested?

Local evidence for the operator increment at `4647cd81`:

- 11 CPU/mock tests passed with CPU torch 2.8.0:
  `python tests/ut/attention/test_flash_mla_host_contract.py`.
  Covers device-derived metadata, fresh schedules, two-call parameter consistency,
  head/batch/query/length combinations, strided views, mocked cross-page writes,
  padding, RoPE/NoPE and ordinary gated/ungated output.
- Six incremental Python files passed Ruff 0.14.0 lint/format;
  whitespace and package-init checks passed.
- Full `format.sh ci` could not run locally because `pre-commit` is unavailable.
- Real A5 smoke added but **not executed**:
  `python tests/e2e/nightly/single_node/ops/flash_mla_tiling_smoke.py --heads 8`.
  Repeat with 12/64/96. It uses the real package and CPU FP32 reference, with
  output atol=rtol=0.02 and exact cache/guard comparison.

These results do not qualify the whole combined branch. No NPU connection,
package/build verification, model run, graph run or performance measurement was
performed for this candidate. Joint hardware validation remains pending:

- Real metadata/main operators, page/token stride, nonzero offset, page crossing,
  padding, cache writes and numerical agreement.
- Same-environment original path at `f38a89de` versus FlashMLA at `4647cd81`,
  followed by model eager, mixed batches, multistep decode and prefix reuse.
- Cache COW/zeroing/block-table/guard regressions for the combined implementation,
  then long contexts, larger batches and the intended supported multi-rank setup.
- Record both repository SHAs, installed package/CANN/torch_npu versions,
  actual import paths, model/configuration, commands and logs.

**Landing plan:** validate both parts together, coordinate dependency landing with
the maintainers, then port/rebase only the operator increment onto main after
#16456 lands and revalidate the final SHA. Do not merge the dependency history
as an unrelated replacement for #16456. Keep Draft until hardware evidence and
review are complete; no speedup, DSpark or graph-support claim is made here.
