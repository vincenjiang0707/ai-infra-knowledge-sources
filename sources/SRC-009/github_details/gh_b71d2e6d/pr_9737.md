### What this PR does / why we need it?
This PR enables eager mode support for `OProjRowParallelOp` in Ascend vLLM. It removes the graph-mode-only restriction for `oproj_tensor_parallel_size` and implements `eager_apply_impl` using all-to-all and reduce-scatter operations. It also adds support for `wo_b` layers in pure DP OTP mode.

However, several critical issues were identified in the review:
- **Shape Mismatch for `wo_b`**: Returning `(custom_op, 0, 1)` for `wo_b` causes a mismatch because `self.tp_size` is not overridden to 1, leading to incorrect input splitting and batch dimension corruption.
- **Potential AttributeError**: `forward_context.dp_metadata` can be `None` during initialization or profiling, which will cause a crash when accessing `cu_tokens_across_dp_cpu`.
- **Reduce-Scatter Crash**: `dist.reduce_scatter` requires equal-sized chunks and will crash with dynamic batch sizes. An `all_reduce` followed by slicing is recommended instead.

### Does this PR introduce _any_ user-facing change?
No user-facing API changes, but it enables eager mode execution for models using `OProjRowParallelOp`.

### How was this patch tested?
No tests were provided in this PR. It is highly recommended to add unit tests for eager mode execution with varying batch sizes.
