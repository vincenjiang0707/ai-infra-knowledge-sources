## 正文

### What this PR does / why we need it?

GLM-5.3-Flash writes its NoPE main KV cache through the existing `DeviceOperator.scatter_cache` interface in all execution modes, including FULL graph mode. After layer normalization and cache-dtype conversion, pass the available actual-token count to the shared interface, matching the existing SFA C8 calling pattern.

The shared implementation selects `_sk` on supported A2/A3 layouts, `npu_scatter_pa_cache` on A5, and the generic fallback otherwise. It retains its existing contract that slots within the passed token prefix are valid. The caller has no separate graph-mode fallback. The DeviceOp implementation and native kernels are unchanged.

Refs #15665

### Does this PR introduce _any_ user-facing change?

NoPE KV writes use the existing device-specific cache-store dispatch without new configuration. End-to-end performance gains have not been measured.

### How was this patch tested?

- 33 local CPU regression cases passed by executing the relevant repository tests against the exact `exec_kv` and `scatter_cache` method bodies, with unavailable vLLM/NPU imports isolated. Covers device dispatch, FULL-mode use of the shared interface with valid slots, actual-token trimming, dtype conversion, cache storage and invalid page layouts. This is not a full-module integration test or an actual graph capture/replay test.
- Ran `bash format.sh ci`; Windows-incompatible shell checks were run separately in local Linux.
- Independent static review completed. NPU integration and end-to-end performance were not rerun for this revision. No nightly cases were added.
