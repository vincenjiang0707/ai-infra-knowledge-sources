# [PR #16887] [Performance][GDN]Skip unused device metadata copies for fused prefill

## 正文

### What this PR does / why we need it?

This PR avoids constructing and copying unused GDN prefill metadata tensors from host to device.

The generic GDN metadata builder previously generated six device-side chunk metadata tensors for every prefill batch. These tensors are required by the Triton fallback and PCP paths, but they are not consumed by:

- Qwen GDN when the fused chunk operator is available and PCP is disabled.
- Kimi KDA using the AscendC prefill operator.
- GLM KDA using the AscendC prefill operator.

This PR:

- Adds a host-only GDN metadata builder and backend.
- Makes the six device chunk metadata fields optional.
- Retains only `cu_seqlens_host`, `chunk_indices_chunk64_host`, and the optional device-side `keep_meta` in host-only paths.
- Routes Kimi and GLM KDA to the host-only backend.
- Selects the host-only builder for Qwen only when the fused chunk operator is available and the PCP world size is one.
- Preserves the complete metadata builder for Triton fallback, PCP, and 310P paths.
- Avoids computing unused chunk offsets, final indices, large-block indices, and cumsum indices in host-only paths.
- Adds a device-type guard so CPU execution cannot accidentally dispatch the NPU-only fused operator.

This removes six small H2D copy tasks and their associated allocation and runtime submission overhead from supported fused prefill paths.

### Does this PR introduce _any_ user-facing change?

No.

The inference API and model output behavior remain unchanged. This is an internal performance optimization for GDN/KDA prefill metadata construction.

### How was this patch tested?

Added and updated unit tests covering:

- Qwen fused and fallback builder selection.
- PCP fallback to complete device metadata.
- Fused-operator-unavailable fallback.
- Kimi and GLM host-only backend routing.
- Host descriptor construction without device chunk tensors.
- Elimination of unused metadata helper calls.
- Mixed prefill/decode execution.
- Layerwise KV state updates.
- Existing 310P behavior.
