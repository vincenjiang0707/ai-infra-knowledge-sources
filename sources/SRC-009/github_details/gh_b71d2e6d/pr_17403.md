## 正文

### What this PR does / why we need it?

Consolidates the three interdependent PD failure-handling fixes into one coherent lifecycle repair. **Supersedes #17291, #17272 and #17293** — those PRs patch consecutive stages of the same lifecycle, and merging only a subset can leave a half-applied state machine (e.g. a generation-aware failure registry combined with a send thread or terminal path that still keys state by external request id alone).

The consolidated repair makes `(external_request_id, generation)` the logical identity of a PD transfer and enforces these invariants end to end:

1. **One terminal outcome per generation.** A success that has already been reported can never be re-terminated by a late HTTP / remote-TP failure, and late events for a retired generation are dropped instead of resurrecting it.
2. **Generations of the same external request id are fully isolated.** A failed G1 tombstone (600 s TTL) never suppresses or poisons a recompute G2 of the same request.
3. **Stale generations are rejected before any destination-block access**, both in the read-thread batch filter and in `_wait_for_dest_blocks`, so a late G1 descriptor can never touch G2's blocks.
4. **Genuine first failures still invalidate blocks** and surface a failure terminal for scheduler recompute — the guards only suppress *late/duplicate* failures.

Main components:

- **`load_failure_registry.py` (new)**: process-local registry recording failed loads per `(req_id, generation)`. `KVPoolWorker.start_load_kv` opens a load generation per request; the single-group invalid-block path records the failed generation; `AscendStoreKVConnector.clear_connector_metadata` finishes it on success.
- **P-side send suppression** (`send_thread.py`): each `SendTask` snapshots the load generation at creation; READ_READY items for load-failed generations are skipped, so a delayed old-generation send task waking up after a recompute is inert.
- **D-side generation state** (`read_thread.py`, `worker.py`): `ConsumerReadState` keys destinations by `ReqKey = (external_req_id, transfer_generation)` and tracks the active generation per external id; stale batches and stale done-keys are filtered before `_do_read_batch`; `rearm`/`discard`/`mark_failed` operate on exact generations; contributor completion state is dropped on cleanup so a dead contributor cannot complete a later request on stale arrivals; `get_finished` skips already-reported and stale generations before block invalidation and reports exactly one terminal per generation; request re-registration retires the previous generation's mappings/destinations and tombstones it for late batches.
- **Proxy safe retry** (`load_balance_proxy_layerwise_server_example.py`): only 2xx counts as prefill-notification success — HTTP 302/307/5xx raise `HTTPStatusError` with no retry; retries are restricted to pre-send connection errors (`ConnectError` / `ConnectTimeout` / `PoolTimeout`); post-send transport failures such as `ReadTimeout` are never blindly retried because the backend may already have received the request.
- **Wire protocol** (`protocol.py`): producer and consumer metadata carry `transfer_generation`; consumer metadata additionally carries failed-rendezvous requests so D can mark and tombstone them in one step.

### Does this PR introduce _any_ user-facing change?

No API or config changes. Behavior changes are internal failure-path corrections: late/duplicate failures no longer invalidate already-transferred blocks or re-finish requests; a failed pool load no longer poisons the recompute of the same request; the layerwise proxy no longer treats 3xx redirects as success and no longer retries post-send transport errors. Net effect: fewer spurious recomputes, duplicate-terminal assertion crashes and stale-state corruptions on PD failure paths.

### How was this patch tested?

- Focused pytest (isolated tree, pinned vLLM main `84030bbe3d74d99bad477a3d2e37a973ccd8865c`): `tests/ut/kv_offload/test_sfa_pd_rd2h_connector.py` — 94 passed; `tests/ut/distributed/ascend_store/test_ascend_store_connector.py` + `test_pool_worker.py` + `tests/ut/proxy/test_layerwise_proxy_retry.py` — 126 passed (includes new regression tests: proxy 302/307 rejection with no retry / no sleep / no success side effect, ReadTimeout no-retry, pool-worker `record_failed_load` generation capture, SFA generation-aware consumer state).
