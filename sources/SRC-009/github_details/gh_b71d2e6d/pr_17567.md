# [PR #17567] [Performance][Model] Fuse Kimi K3 latent RMSNorm and MXFP8 quantization on A5

## 正文

### What this PR does / why we need it?

Use the existing `npu_rms_norm_dynamic_mx_quant` operator for Kimi K3's latent routed-output RMSNorm on A5 when the following up-projection uses W8A8 MXFP8. Pass the operator's `(quantized, scale)` output directly to the existing prequantized linear input path, avoiding a separate RMSNorm output and activation quantization launch.

The fused operator and the MXFP8 linear tuple contract already exist in vLLM-Ascend. This PR only adds the Kimi-specific dispatch and preserves the original path for other devices, quantization schemes, and unsupported shapes. It adds no new native operator or vLLM core change.

### Does this PR introduce _any_ user-facing change?

No API or configuration change. Eligible Kimi K3 A5 inference selects the fused path automatically.

### How was this patch tested?

- `python -m ruff check` and `python -m ruff format --check` on all three changed Python files — passed.
- `python -m py_compile` on all three changed Python files and `git diff --check` — passed.
- A5 single-card on host 232: ran the added test against the installed vLLM/vLLM-Ascend environment with this PR's model file loaded from an isolated overlay; **5 passed**. Coverage includes both scale algorithms, exact projection output comparison, ACLGraph replay with changed inputs, and fallback paths.
- Reproduce in a matching A5 environment: `pytest -q tests/e2e/nightly/single_node/ops/singlecard_ops/test_kimi_rmsnorm_mxquant.py`.
- A5 standalone benchmark on host 232: `python tests/e2e/nightly/single_node/ops/singlecard_ops/benchmark_kimi_rmsnorm_mxquant.py --tokens 8 32 --warmup 10 --repeats 30`. At BF16/H3584, median event intervals for fused norm+quant were 37.3–38.1 µs versus 67.6–69.8 µs for separate norm and quant across both scale algorithms. These are single-stage event measurements, not full-model latency.
