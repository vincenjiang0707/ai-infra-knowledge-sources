# [PR #17542] [Performance] Optimize GLM-5.3-Flash Triton KPool and gated norm

## 正文

### What this PR does / why we need it?

GLM-5.3-Flash's Triton KPool path repeatedly initializes, sanitizes, expands and copies intermediate buffers. Compression also processes tokens that do not complete a pool, while gated RMS norm writes inference statistics that its caller never reads.

- Preserve the mainline FP32 head-weighted query and dot-product scoring formula and reduction order. Parallelize small batches across pool chunks and reuse weighted queries across pool tiles for larger batches.
- Use bounded packed-cache reads when query reuse justifies packing; retain paged reads when token and request counts match. Score and packed-cache scratch are each limited to 256 MiB, except for a single score row exceeding that limit.
- Fuse score sanitization and final index expansion, including causal tails, graph padding and SFA alignment clearing. Write directly into the final SFA output buffer and keep changing context lengths dynamic.
- Skip invalid, padded and incomplete pools before compression, preserving the separate ordered tail-update launch.
- Tune gated norm for small batches and omit unused inference statistics while retaining the underlying statistics API.

Refs #15665

### Does this PR introduce _any_ user-facing change?

Reduced Triton operator overhead with mainline scoring semantics retained. There are no new configuration flags or CANN/AscendC changes.

### How was this patch tested?

Results below correspond to head `4a73c393db5686dda81d63326e6feaaf8722d444`.

**Operator validation on Atlas A3:** PyTorch/torch_npu 2.10 and Triton-Ascend 3.2.0. All 27 existing indexer/compressor cases passed; no new nightly cases were added. All 13 benchmark shapes passed bitwise comparisons of the actual Top-K score input and ordered output against mainline. Independent checks cover strided buffers/cache, multiple requests, causal tails, graph padding, NaN/Inf, chunk boundaries and an actual cache span above 4 GiB. Gated norm is bitwise equal across FP16/BF16/FP32 and supported activation/residual/statistics branches. Cold-cache checks on the same kernels confirmed no extra score/gather/expansion variants for pool capacities 40/44/48/52/56.

Graph microbenchmarks measured latency reductions of 8.56%–73.05% for the 13 indexer shapes, 7.52%–42.31% for compression, and 39.30%–43.42% for gated norm at T=4/8. Larger norm shapes were neutral.

**Fresh paired full-model performance:** W8A8, A3 eight NPUs, TP4/DP2/EP8, MTP off, FULL_DECODE_ONLY, context 16384 and 320 blocks. Fixed 3500 input/128 output tokens, one warmup and three measured rounds per concurrency; results are medians of per-round request medians. Every request's token usage was verified.

The paired run improves 13 questions and regresses 7, for a net +6 (+0.4549 percentage points). Aggregate accuracy did not decrease in this run; individual responses are not identical. The candidate also matches the prior complete 1280/1319 (97.0432%) reference. That reference is retained separately rather than substituted for the fresh baseline. Its original P/D deployment differs from this test, so this aligns the evaluation protocol rather than reproducing that deployment.

All request hashes, dataset hashes and 2638 raw responses were independently checked and rescored. HTTP errors and observed preemptions were zero. Empty/truncated outputs remain in the score; no retries, exclusions or relaxed extraction were used.

**Validation scope:** both arms use the same known-compatible Ascend source tree with exactly the five product files overlaid, identical weights/native libraries and eight-rank source/native hash checks. The available vLLM `84030bbe3d74d99bad477a3d2e37a973ccd8865c` cannot import current main's `vllm.models.deepseek_v41` dependency. This is validation in that compatible stack, not current-main full-tree model integration. Both arms use the supported `--skip-mm-profiling` flag after pinned-memory allocation failures during unused vision initialization; this covers text inference. Each arm also passed the 10 existing model-backend UTs. Owned test containers were stopped and device cleanup verified.

Raw responses, per-round timings, launch arguments, manifests and audit scripts are retained under `artifacts/glm53-triton-opt-20260926/`. Full-model evidence archive SHA256: `e62d8320e219ded9ba8c77774b1a43208e6f582dc7515afb2c1bfb14a8f7ac90`.
