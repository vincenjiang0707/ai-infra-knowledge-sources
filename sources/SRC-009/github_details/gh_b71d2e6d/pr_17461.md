## 正文

### What this PR does / why we need it?

MRv2 MTP currently labels both single-token decode and speculative verification as `SpecDecoding`, and the first draft step inherits target metadata. Use `DecodeOnly` when exactly one token is scheduled, and `ChunkedPrefill` when a speculative batch has one valid token plus draft tokens. Both states already select the MLA TND layout, allowing removal of the draft-specific layout override. Keep `SpecDecoding` compatibility in shared MLA code while V1 and 310P paths still depend on it, with TODOs at those call sites.

### Does this PR introduce any user-facing change?

No API change. MRv2 MTP attention metadata now distinguishes single-token decode from multi-token speculative verification.
