## Description

`confidential_compute_enabled()` in `tensorrt_llm/_utils.py` calls `pynvml.nvmlSystemGetConfComputeSettings(cc_settings)`, passing the `c_nvmlSystemConfComputeSettings_v1_t` struct by value. The underlying NVML C API declares this function as taking a pointer (`nvmlSystemGetConfComputeSettings(nvmlSystemConfComputeSettings_v1_t *)`), so the pointer/by-value mismatch can crash the worker during initialization on Hopper-and-newer GPUs, before the HTTP server becomes ready.

The equivalent call was already corrected on `main` via https://github.com/NVIDIA/TensorRT-LLM/pull/16850 (`byref(cc_settings)`), but that PR also did a larger, unrelated refactor (new cached `get_cc_and_nvle_status()`, split CC/NVLE booleans). This change backports only the pointer fix to `release/1.2.1`, leaving this branch's existing `confidential_compute_enabled()` function and its CC/NVLE classification logic (the three-way `or` across `ccFeature`/`multiGpuMode`) untouched.

## Approach

- Add `from ctypes import byref` and wrap the settings struct in `byref(cc_settings)` when calling `pynvml.nvmlSystemGetConfComputeSettings`, matching the fix already on `main`.
- Add regression tests (`tests/unittest/utils/test_confidential_compute.py`) covering all branches of the CC/NVLE classification (`ccFeature` enabled, `PROTECTED_PCIE`, `NVLE`, and combined), and register the file in `tests/integration/test_lists/test-db/l0_a10.yml` under the existing "CPU-only test, no dedicated job" precedent comment (this branch predates the `l0_cpu.yml`/`cpu_only` marker convention introduced by #16850 on `main`).
