## Description

`CnnDailymail.compute_score` (`tensorrt_llm/evaluate/cnn_dailymail.py`) assigns `rouge1` only inside the beam loop:

```python
for beam_idx in range(len(outputs[0].outputs)):
    ...
    if beam_idx == 0:
        rouge1 = metrics["rouge1"] * 100
return rouge1   # UnboundLocalError if outputs[0].outputs is empty
```

If `outputs[0].outputs` is empty the loop never runs and `return rouge1` raises `UnboundLocalError` instead of yielding a score.

## Change

Initialize `rouge1 = 0.0` before the loop.

## Test

New CPU-only unit test in `tests/unittest/others/test_cnn_dailymail_score.py`: `compute_score` with an empty beam list returns `0.0` (constructed via `__new__` to skip the heavy metric-loading `__init__`).

### brnguyen2 · 2026-08-10 · APPROVED

Approving — the comments below are optional touch-ups, not blockers.

The fix itself is fine and harmless. Two things to settle before merge:

1. Is an empty `outputs[0].outputs` actually reachable? `RequestOutput.outputs` is populated with one `CompletionOutput` per requested beam/sequence, so in the normal evaluator flow (`interface.py:142` passing collected results) it should always be non-empty. If you have a concrete path that produces an empty beam list, put it in the PR description — that changes this from a speculative guard into a real fix, and it also determines whether silently returning `0.0` is the right behavior versus raising something explicit. A score of `0.0` propagates into accuracy-threshold comparisons; a caller can't distinguish "the model scored zero" from "there was nothing to score".

2. The repo asks that the copyright year on modified files be bumped to the current year — `[tensorrt_llm/evaluate/cnn_dailymail.py:1](https://github.com/NVIDIA/TensorRT-LLM/pull/16261/files#diff-b49e7bfe993e772395157950c60e8dab0c8f152b5a48890d5e60d4b1d7fdc1a9R1)` still says 2025.
