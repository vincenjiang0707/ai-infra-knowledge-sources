## Summary

- `_sync_gen_only_benchmark_has_insufficient_kv()` returned before
  `_allgather_model_parallel_status()` whenever this rank's
  `_benchmark_fill_phase_active` flag was clear. That flag is rank-local dynamic state,
  so a post-fill rank could skip the gather while a still-filling peer was already inside
  it, leaving the two ranks on different collectives of the same communicator.
- The flag is now voted instead of read: only the rank-uniform
  `benchmark_req_queues_size` / `is_warmup` conditions short-circuit, the flag travels in
  the status tuple, and the fail-fast decision is taken from the gathered result. Normal
  serving (`TLLM_BENCHMARK_REQ_QUEUES_SIZE` unset) still returns before any collective.
- **The terminal vote is counted only from ranks that are still filling** (rev2, see
  below). A rank that has cleared its own fill phase has no fill left to declare
  unfittable, so its `terminal_no_fit` must not fail-fast a peer whose fill is healthy.
- Regression coverage is added to the existing `TestFailFastDuringBenchmarkFill` class,
  reusing its executor stub, so the tests drive `_prepare_and_schedule_batch()` rather
  than a copy of the decision logic.

## Root cause

`py_executor.py:3686-3688` gated the model-parallel gather on rank-local state:

```python
if (self.benchmark_req_queues_size <= 0 or self.is_warmup
        or not self._benchmark_fill_phase_active):
    return False
```

`_benchmark_fill_phase_active` is seeded from the static benchmark-disagg config but is
cleared per rank when the *global* fill gate opens (`_check_benchmark_disagg_gate`,
`py_executor.py:3995`). A rank that has cleared it then returns before the gather its
peers are entering. The fill gate gathers a pickled object (`MPIDist.tp_allgather`) while
`_can_queue()` gathers a raw `MPI.INT64_T` (`tp_allgather_int64`), so MPI matches them by
order and datatype instead of failing — the same failure class already documented from a
live run at `py_executor.py:4676-4679`.

This was the only site in the tree that gated a collective on rank-local state before
entering it. The rank-safe sibling states the required discipline at
`py_executor.py:3903-3905`: *"Keep going to the shared allgather even when this rank is
not done so model-parallel ranks cannot diverge in collective order."*

### rev2: the terminal vote is also rank-local

Voting the flag fixed the *collective-order* divergence but left a second, opposite
divergence: rev1 still read `status[2]` from every rank.

```python
any_rank_terminal_no_fit = any(status[2] for status in all_rank_status)   # rev1
any_rank_terminal_no_fit = any(
    status[2] for status in all_rank_status if status[0])                 # rev2
```

`local_terminal_no_fit` means *"my fill cannot fit"*. It is only meaningful on a rank
that is itself still filling. A post-fill rank's stale `True` could therefore fail-fast a
peer whose own fill was perfectly healthy — one rank still kills the other, just from the
post-fill side. `all_ranks_fetched` is unchanged: every rank must still have fetched the
full queue before the gate can open.

### Why earlier runs never reached the gate

`benchmark_serving.py:322-347` sends **one** warm-up prompt before the burst
(`no_test_input=False`, the default). With `TLLM_BENCHMARK_REQ_QUEUES_SIZE=64` the GEN
worker holds that single request until 64 have been fetched, and the client blocks on the
warm-up response before ever submitting the burst — a client-side deadlock that looks
exactly like "the fill gate never opens" (`num_fetch_requests=1 < 64`, one
`POST /v1/completions` in the router log). Passing `--no-test-input` is what makes the
gate observable at all; with it, the same configuration opens the gate and serves
requests.

## Limitations

- **The original #17095 signature was not reproduced.** The gate opens and requests are
  served, but the run then wedges *after* the gate, in the sampler's D2H event wait:
  `py-spy` on both GEN ranks shows `_executor_loop` → `_update_requests` →
  `sampler.update_requests` → `SamplerEvent.synchronize()` → `cuda_event.synchronize()`,
  with the CTX rank idle in `queue.get()`. 32 of 64 requests are served, then the GPU
  event never completes. This change is therefore **not** claimed to fix that deadlock;
  it removes a rank-divergence at the fill-gate vote and is validated as such.
- The wedge is not caused by `TRTLLM_GPU_KEEPALIVE`: it reproduces identically with the
  keepalive disabled (`TRTLLM_GPU_KEEPALIVE=0`, no keepalive activity in the worker log).
- DSpark is Blackwell-only (`dspark_attention_custom_op.py:70-71`), so the reporter's
  backend cannot run on this hardware; the E2E used `NGram` on the GEN worker.
- `tests/unittest/_torch/disaggregation/` as a whole cannot be collected in this
  environment: `test_backend_contract.py` and `test_disagg_coordinator_admission.py`
  import symbols (`Attempt`, `transfer_window_bypass_eligible`) that the installed wheel
  does not export. That is repo-vs-wheel drift, unrelated to this change, and both files
  fail identically before and after it.
