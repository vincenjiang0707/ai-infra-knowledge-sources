## Description

Iteration logs expose only the sum of cached KV tokens, making it difficult to inspect individual cached-prefix lengths in a disaggregated GEN batch. Set `TLLM_LOG_CACHED_KV_TOKENS_PER_REQ=1` before starting workers to add `cached_kv_tokens_per_req` to the existing `states` log. The flag is read once during model-engine initialization and defaults to off.

The list follows model-input sequence order and excludes CUDA graph padding requests. Filtering follows the context, extend, first-draft, and generation groups used by input preparation, including beam expansion. This handles padding inside the packed MTP batch and preserves all real beam entries. The normal input, steady-generation, and encoder-decoder fast paths all update the diagnostic. Attention-DP dummy rows remain part of the scheduled-input accounting.

The existing `cached_kv_tokens` total retains its original semantics. The companion `cached_kv_tokens_cuda_graph_padding` field reports the excluded contribution, so:

```text
cached_kv_tokens = sum(cached_kv_tokens_per_req) + cached_kv_tokens_cuda_graph_padding
```

For example, `[100, 200]` with a padding contribution of `7` corresponds to a total of `307`. With beam width 1, each retained entry corresponds to one scheduled request; multiple beams produce per-sequence entries. These are cached-prefix token counts, not physical KV-cache occupancy.

Disabled mode does not traverse requests, copy counts, or format the extra fields. Enabled mode adds CPU filtering and logging without new CUDA synchronization.
