## 正文

## Description

`ClusterStorage.get()` and its implementations were annotated `-> str`, but `None` is an established result. The HTTP server returns `None` for missing or expired keys, the HTTP client returns `None` on non-200 responses, and the etcd implementation returns `None` for missing keys as well as through `@handle_etcd_error(return_on_error=None)`.

The comment above the base declaration already documents this behavior. Only the annotation disagreed.

This annotates the shared declaration and all three implementations as `str | None`. Type-only, no behavior change. Signature change is API-compatible.

Fixes #17977.

Note: `get_prefix`, `Etcd3ClusterStorage.delete`, and `_get_lease` have similar annotation mismatches in this file. Left out of scope, happy to file a follow-up.

## Test Coverage

No new tests. Type-annotation-only change with no runtime behavior change. Existing coverage in `tests/unittest/disaggregated/test_cluster_storage.py` is unaffected.
