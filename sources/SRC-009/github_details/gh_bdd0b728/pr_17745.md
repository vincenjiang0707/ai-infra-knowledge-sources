## Description

Fixes #17743.

`normalize_path` in `scripts/legacy_utils.py` builds the baseline lookup key
with `str(p.relative_to(repo_root))`, which carries the platform separator.
`ruff-legacy-baseline.json` stores forward-slash keys, so on Windows every
lookup in `compare_against_baseline` misses: each rule falls back to a baseline
count of `0`, and every violation already recorded in the baseline is reported
as a new regression.

The effect is that the `ruff-legacy` pre-commit hook fails on files that have
not been touched at all. It blocks every commit involving a legacy file and
gives Windows contributors no way to tell a real regression from the noise.

Before, on a clean working tree:

```
$ git status --porcelain          # empty
$ python scripts/legacy_utils.py lint-precommit \
      tensorrt_llm/serve/tool_parser/base_tool_parser.py \
      tests/unittest/llmapi/apps/test_tool_parsers.py

New violations (28 regressions vs baseline):
  tensorrt_llm\serve\tool_parser\base_tool_parser.py:46  D212  ...
  ...
```

After, the same command exits 0.

## Fix

Return a POSIX path, matching how the baseline is stored. The same normalized
key feeds `current_counts`, `checked_files`, `identify_new_violations` and the
auto-fix report, so the single change covers all of them.

On Linux and macOS `as_posix()` already matches `str()`, making this a no-op
there.

## Verification

On Windows:

- unmodified legacy files → exit 0 (was 28 reported regressions)
- a deliberately introduced `D212` violation → still reported, exit 1
- the hook now passes on a real in-progress change that is genuinely
  violation-neutral, which it previously blocked
