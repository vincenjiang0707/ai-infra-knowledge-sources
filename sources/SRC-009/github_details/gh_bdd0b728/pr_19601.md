## Description

<!--
Please explain the issue and the solution in short.
-->
Requests with explicit seeds are supposed to be reproducible (at least, if they are in different batches). This the contract for the spec dec off path; the spec dec path attempts to replicate this behavior but is buggy. 

Internally, the engine maintains a buffer of `offset`s for the RNG indexed by the request's `seq_slot`. These slot IDs are handed out arbitrarily; if you send in the same request over and over serially, the scheduler seems to hand out `0, 1, 2, ..., max_batch_size, 0, 1, 2, ...`, and so on. 

The `offset`s start at 0 and progress as the request is decoded. They are never reset. The net behavior is that the seeded request is reproducible `max_batch_size` many times in the above example. When a dirty seq slot is handed out, you get different results. 

The fix is to reset each offset when the owning request terminates.
