## 正文

Fixes #19193.

### Problem

`--cpp_only` (documented in `docs/source/installation/build-from-source.md:87` as "Build
only the C++ runtime library, without Python bindings") cannot configure on `main`:

```
CMake Error at tensorrt_llm/runtime/utils/CMakeLists.txt:28 (find_library):
  Could not find TORCH_PYTHON_LIB using the following names: torch_python

-- Configuring incomplete, errors occurred!
```

Torch discovery lives inside `if(BUILD_PYT)` at `cpp/CMakeLists.txt:529`, so with
`BUILD_PYT=OFF` neither `TORCH_INSTALL_PREFIX` nor `CMAKE_PREFIX_PATH` is populated, and
three unguarded call sites fail: `runtime/utils/CMakeLists.txt:28`,
`executor/cache_transmission/ucx_utils/CMakeLists.txt:6`, and
`batch_manager/CMakeLists.txt:105`.

Supplying the paths by hand is not enough, because core C++ headers include torch
unconditionally:

```
include/tensorrt_llm/batch_manager/cacheTransceiver.h:28
  -> include/tensorrt_llm/runtime/utils/pgUtils.h:24
    -> torch/csrc/distributed/c10d/ProcessGroup.hpp, torch/torch.h
tensorrt_llm/common/ncclUtils.h:25 -> ATen/cuda/CUDAContext.h
tensorrt_llm/kernels/trtllmGenKernels/blockScaleMoe/runner.h
  -> tensorrt_llm/thop/thUtils.h:22 -> ATen/cuda/CUDAContext.h
```

### Change

Run the Torch discovery regardless of `BUILD_PYT`, and keep only
`add_compile_definitions(TORCH_CUDA=1)` conditional. The `else()` branch that set
`-D_GLIBCXX_USE_CXX11_ABI=0` for a torch-less build is unreachable once Torch is always
required, so it is removed.

This reflects what the sources already need. It does not attempt the larger question
raised in #19193, namely whether the C++ runtime should depend on torch at all. If you
would rather decouple `cacheTransceiver` from `c10d` and keep `--cpp_only` free of torch,
I am happy to redo this as that change instead.

Most of the diff is re-indentation. `git diff -w` reports 7 insertions and 9 deletions.
