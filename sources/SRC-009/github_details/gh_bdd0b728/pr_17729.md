## Description

The `except ValueError` block in `load_dataset_from_hf` tested membership and used `+=` on the exception object itself (`"Config" in e` / `e += ...`), both of which raise `TypeError`. Any dataset-loading failure (e.g. an invalid `--dataset-split`) therefore crashed with `TypeError: argument of type 'ValueError' is not iterable` instead of showing the intended hint.

Port the `_create_dataset_load_error` helper already used by the same handler in `benchmarks/cpp/utils/prepare_real_data.py` (before its removal), operating on `str(e)` and chaining the original exception.

## Test Plan

- `trtllm-bench prepare-dataset real-dataset --dataset-name <name> --dataset-split bogus` now reports the underlying ValueError plus the split hint instead of a TypeError.
