## Description

Fixes #19564.

`HfWeightLoader._load_bin_or_path_file` returns from a `finally` block:

```python
try:
    part_weights = torch.load(file, weights_only=True, map_location='cpu', mmap=True)
except Exception:
    logger.warning(f"Failed to load {file} with mmap=True, fallback to mmap=False")
    part_weights = torch.load(file, weights_only=True, map_location='cpu', mmap=False)
finally:
    return part_weights
```

If the `mmap=False` retry also raises, `part_weights` is unbound and the `return` in `finally` raises `UnboundLocalError`, replacing the real error. That path runs for checkpoints without `*.safetensors`, where the loader falls back to `*.bin`/`*.pth` files. A `.bin` that is not a weights file — HF Trainer's `training_args.bin`, for instance, which fails `torch.load(..., weights_only=True)` with `UnpicklingError` — is then reported as:

```
[ERROR] Error executing _load_bin_or_path_file with args ('.../training_args.bin',): cannot access local variable 'part_weights' where it is not associated with a value
```

The fix removes the `finally:` and returns after the `try`/`except`. Both successful paths (mmap=True, and the mmap=False fallback) return exactly as before; the only difference is that a failed fallback now raises the original `torch.load` exception. It also removes the `SyntaxWarning: 'return' in a 'finally' block` Python 3.14 emits for this function (PEP 765).

No existing test covers this function. The file compiles cleanly with `-W error::SyntaxWarning`, and `yapf --diff` (v0.43.0, the version pinned in pre-commit; this file is on the legacy lint list) reports no changes.
