# [PR #19620] [None][fix] Keep telemetry heartbeats running for long-lived sessions

## 正文

## Description

Remove the 1,000-heartbeat cap, which stops duration reporting after approximately seven days at the default 600-second interval (10,000 minutes). Keep heartbeats running until process exit, terminal reporting, or telemetry opt-out.

- Preserve the interval, fail-silent delivery, shutdown handling, and existing event fields/schema version.
- Saturate `seq` at the existing uint32 maximum rather than eventually emitting invalid values.
- Update the documentation and the initial-report-only test's stop mechanism.

Tradeoff: long-running reporting processes continue producing about 144 heartbeat events per day after the former cutoff, increasing ingestion/storage volume. Heartbeats indicate process-session liveness, not active GPU utilization. No dashboard/cache changes or migrations are required; this does not backfill missed historical heartbeats.

## Test Coverage

- Core reporter, schema, opt-out, collectors, transport, and architecture-allowlist suites: **232 passed, 6 skipped**.
- CLI telemetry and Uvicorn signal/shutdown suites in the TRT-LLM container: **37 passed**.
- New regression simulates 10,001 heartbeats, verifies the interval and stop behavior, and exercises sequence saturation.
- Pre-commit checks and `git diff --check` passed.
- Local limitation: the updated configuration-capture regression could not collect without native TRT-LLM bindings in the source checkout. It remains for CI verification; no full GPU E2E or live staging run was performed.
