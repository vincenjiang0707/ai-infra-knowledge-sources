## 正文

## Description

Fixes the `test_cute_dsl_moe.py -k rubin` failures on VR200 post-merge.

- **`forward_chunk` AttributeError**: the locality domain MoE module tests called `CuteDslFusedMoE.forward_chunk()`, which was removed in #16863. Migrate them to `create_moe()` + `ConfigurableMoE.forward()`. A follow-up PR will move the locality domain weight split into the staged hooks.
- **Illegal memory access**: the BF16 gather SwiGLU and grouped GEMM finalize tests rounded `num_non_exiting_tiles` up to even, so the kernels read uninitialized `moe_sort` tile metadata past the last tile. Pass the real tile count, as production does.

## Notes

The `test_moe_module_*` locality domain tests exercise the full MoE layer (`create_moe` + `forward`), unlike the kernel-level tests in this file. It might be better to move them to `tests/unittest/_torch/moe/` (e.g. `test_moe_module.py`), which has no locality domain coverage today.

## Test Coverage

`unittest/_torch/thop/parallel/test_cute_dsl_moe.py -k rubin` on VR200: the locality domain tests and all BF16 FC1/finalize cases pass. Remaining flaky NVFP4 FC1 gather failures are unrelated and tracked separately.
