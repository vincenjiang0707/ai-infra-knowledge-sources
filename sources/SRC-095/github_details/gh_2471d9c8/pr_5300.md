## Why are these changes needed?
This is the second and last PR of the series adding device-agnostic node label delivery webhook. #5260 added the API: `workerGroupSpecs[].topology.labelMappings` and the `allowedNodeLabels` operator config. This PR adds the delivery mechanism itself. Each worker pod receives the actual labels that are attainable in the kubernetes node after it's bound to, so that placement groups and tasks can use the label for placement strategies. The feature is behind the alpha `TopologyLabelDelivery` gate and requires the operator to run with webhooks (`ENABLE_WEBHOOKS`)

### What this PR adds
1. **Validating webhooks** (RayCluster, RayJob, RayService) reject a worker group with `labelMappings` when a `nodeLabel` is not in `allowedNodeLabels`, two mappings produce the same Ray key, `ray.io/overwrite-container-cmd` is set on the CR or the template, or the container command runs `ray start`. The error names the field.
2. **Reconciler validation** rejects a topology group when the feature gate is off, the operator runs without webhooks, or `rayVersion` is below 2.45.0 (`ray start --labels-file` was added there).
3. **pods CREATE webhook** (Ray node pods only, failurePolicy: Fail). On a topology worker it adds the env var `RAY_NODE_LABELS_JSON`, a downward API reference to the pod annotation `ray.io/topology-labels`, and wraps the generated `ray start`: exit 1 if the env var is empty, write it to `/tmp/ray-labels.yaml`, pass `--labels-file`.
4. **pods/binding webhook** (failurePolicy: Ignore, 5 second timeout). On bind, it reads the target node, maps its labels through `labelMappings`, and writes the JSON into the Binding annotations. The API server copies them onto the pod with `spec.nodeName`, so labels arrive with placement. If any label specified in the `labelMappings` is not available, no labels are delivered. For example, if a user has `labelMappings` specified for zone and clique, and only zone label was available from the node, this would be considered a failure. The annotation is left unset, a `RequiredNodeLabelMissing` warning event is recorded on the pod, and the container exit before ray start. The timeout is 5 seconds because this webhook sees every binding in the cluster. An unhealthy operator can only delay, and 5 seconds caps that delay.
5. **RBAC** `nodes get`. **Kustomize** webhook manifests and the objectSelector patch. **Helm** support behind `webhooks.enabled`.

### Manual test instructions

On a kind cluster with labeled nodes: a topology worker gets its node's labels as Ray node labels, a worker on a node missing a label is withheld with an event, admission rejects bad specs, other pods are untouched.

**1. Cluster with three workers, cert-manager, operator with webhooks, allowlist and the gate on**

```bash
cat > kind-tas.yaml <<'EOF'
kind: Cluster
apiVersion: kind.x-k8s.io/v1alpha4
nodes: [{role: control-plane}, {role: worker}, {role: worker}, {role: worker}]
EOF
kind create cluster --name tas --config kind-tas.yaml
kubectl apply -f https://github.com/cert-manager/cert-manager/releases/download/v1.17.2/cert-manager.yaml
kubectl -n cert-manager wait deploy --all --for=condition=Available --timeout=180s

kubectl label node tas-worker  nvidia.com/gpu.clique=rack-a.0 topology.kubernetes.io/zone=zone-1
kubectl label node tas-worker2 nvidia.com/gpu.clique=rack-b.0 topology.kubernetes.io/zone=zone-1
kubectl label node tas-worker3 topology.kubernetes.io/zone=zone-1   # no clique, on purpose

cd ray-operator && make docker-image IMG=kuberay/operator:tas && kind load docker-image kuberay/operator:tas --name tas
cat > tas-values.yaml <<'EOF'
image: {repository: kuberay/operator, tag: tas}
webhooks: {enabled: true}
configuration:
  enabled: true
  allowedNodeLabels: [nvidia.com/gpu.clique, topology.kubernetes.io/zone]
featureGates:
- {name: TopologyLabelDelivery, enabled: true}
EOF
helm install kuberay-operator ../helm-chart/kuberay-operator -n ray-system --create-namespace -f tas-values.yaml
kubectl -n ray-system rollout status deploy/kuberay-operator
```

**2. Happy path.** `train` maps the clique to `ray.io/accelerator-domain` and the zone under its own key, one worker per clique node. `plain` has no topology.

```bash
kubectl apply -f - <<'EOF'
apiVersion: ray.io/v1
kind: RayCluster
metadata: {name: topo}
spec:
  rayVersion: "2.49.0"
  headGroupSpec:
    rayStartParams: {dashboard-host: "0.0.0.0"}
    template: {spec: {containers: [{name: ray-head, image: rayproject/ray:2.49.0}]}}
  workerGroupSpecs:
  - groupName: train
    replicas: 2
    minReplicas: 2
    maxReplicas: 2
    topology:
      labelMappings:
      - {nodeLabel: nvidia.com/gpu.clique, mapTo: ray.io/accelerator-domain}
      - {nodeLabel: topology.kubernetes.io/zone}
    template:
      spec:
        affinity:
          nodeAffinity: {requiredDuringSchedulingIgnoredDuringExecution: {nodeSelectorTerms: [{matchExpressions: [{key: nvidia.com/gpu.clique, operator: Exists}]}]}}
          podAntiAffinity: {requiredDuringSchedulingIgnoredDuringExecution: [{labelSelector: {matchLabels: {ray.io/group: train}}, topologyKey: kubernetes.io/hostname}]}
        containers: [{name: ray-worker, image: rayproject/ray:2.49.0}]
  - groupName: plain
    replicas: 1
    minReplicas: 1
    maxReplicas: 1
    template: {spec: {containers: [{name: ray-worker, image: rayproject/ray:2.49.0}]}}
EOF
kubectl wait pod -l ray.io/cluster=topo --for=condition=Ready --timeout=300s

# annotation delivered at bind equals the node's labels, and the container wrote it to the labels file
for p in $(kubectl get pod -l ray.io/group=train -o name); do
  kubectl get $p -o jsonpath='{.spec.nodeName}  {.metadata.annotations.ray\.io/topology-labels}{"\n"}'
  kubectl exec $p -c ray-worker -- cat /tmp/ray-labels.yaml; echo
done
#  tas-worker   {"ray.io/accelerator-domain":"rack-a.0","topology.kubernetes.io/zone":"zone-1"}
#  tas-worker2  {"ray.io/accelerator-domain":"rack-b.0","topology.kubernetes.io/zone":"zone-1"}

# Ray sees them as node labels; head and plain carry only ray.io/node-id and ray.io/node-group
kubectl exec $(kubectl get pod -l ray.io/node-type=head -o name) -c ray-head -- \
  python -c "import ray, json; ray.init(address='auto', logging_level='ERROR'); print(json.dumps({n['NodeManagerAddress']: n.get('Labels') for n in ray.nodes()}, indent=1))"

# plain worker untouched
kubectl get $(kubectl get pod -l ray.io/group=plain -o name) -o jsonpath='{.spec.containers[0].env[*].name}  {.metadata.annotations.ray\.io/topology-labels}{"\n"}'   # no RAY_NODE_LABELS_JSON, no annotation
```

**3. Missing label is withheld.** Same `train` group pinned to `tas-worker3`.

```bash
kubectl apply -f - <<'EOF'
apiVersion: ray.io/v1
kind: RayCluster
metadata: {name: topo-missing}
spec:
  rayVersion: "2.49.0"
  headGroupSpec:
    rayStartParams: {dashboard-host: "0.0.0.0"}
    template: {spec: {containers: [{name: ray-head, image: rayproject/ray:2.49.0}]}}
  workerGroupSpecs:
  - groupName: train
    replicas: 1
    minReplicas: 1
    maxReplicas: 1
    topology:
      labelMappings:
      - {nodeLabel: nvidia.com/gpu.clique, mapTo: ray.io/accelerator-domain}
      - {nodeLabel: topology.kubernetes.io/zone}
    template:
      spec:
        nodeSelector: {kubernetes.io/hostname: tas-worker3}
        containers: [{name: ray-worker, image: rayproject/ray:2.49.0}]
EOF
sleep 60
W=$(kubectl get pod -l ray.io/cluster=topo-missing,ray.io/group=train -o name)
kubectl get $W -o jsonpath='{.status.containerStatuses[0].state.waiting.reason}  {.metadata.annotations.ray\.io/topology-labels}{"\n"}'   # CrashLoopBackOff, no annotation
kubectl logs $W -c ray-worker --previous | tail -1
#  RAY_NODE_LABELS_JSON is empty: node labels were not delivered to this pod, see the pod events
kubectl get events --field-selector reason=RequiredNodeLabelMissing -o custom-columns=MESSAGE:.message
#  node labels not delivered for the binding to node tas-worker3: node lacks label "nvidia.com/gpu.clique"

# recovery
kubectl label node tas-worker3 nvidia.com/gpu.clique=rack-c.0 && kubectl delete $W
kubectl wait pod -l ray.io/cluster=topo-missing --for=condition=Ready --timeout=300s
kubectl get pod -l ray.io/cluster=topo-missing,ray.io/group=train -o jsonpath='{.items[0].metadata.annotations.ray\.io/topology-labels}{"\n"}'
#  {"ray.io/accelerator-domain":"rack-c.0","topology.kubernetes.io/zone":"zone-1"}
```

**4. Admission rejections.** Apply `topo` again with `--dry-run=server` after each edit.

| edit to the `train` group | error |
|---|---|
| `nodeLabel: cloud.google.com/gke-nodepool` | `spec.workerGroupSpecs[0].topology.labelMappings[0].nodeLabel: Forbidden: node label "cloud.google.com/gke-nodepool" is not in the operator's allowedNodeLabels` |
| both mappings `mapTo: ray.io/zone` | `spec.workerGroupSpecs[0].topology.labelMappings[1]: Duplicate value: "ray.io/zone"` |
| `metadata.annotations: {ray.io/overwrite-container-cmd: "true"}` on the RayCluster | `spec.workerGroupSpecs[0].topology: Forbidden: cannot be combined with the ray.io/overwrite-container-cmd annotation; ...` |
| `command: ["ray start --block"]` on the worker container | `spec.workerGroupSpecs[0].topology: Forbidden: cannot be combined with a container command that runs ray start; ...` |
| operator without `--feature-gates=TopologyLabelDelivery=true` | admitted, no pods created, event `InvalidRayClusterSpec`: `worker group train sets topology, which requires the TopologyLabelDelivery feature gate to be enabled` |

**5. Non-Ray pods bypass the fail-closed webhook**

```bash
kubectl run nginx --image=nginx --restart=Never && kubectl wait pod/nginx --for=condition=Ready --timeout=60s
```
