## Why are these changes needed?

In https://github.com/ray-project/kuberay/pull/4873, we added a retry mechanism to handle transient CI failures such as 504 Gateway Time-out.


However, in [Build #17141](https://buildkite.com/ray-project/ray-ecosystem-ci-kuberay-ci/builds/17141/list?jid=01a0ab29-a32b-4c09-8019-c7c0ac18b8da&tab=output), the build failed with a TLS handshake timeout, but the retry was not triggered:

There are two issues with this:

1. `source` executes the script in the current shell. Since it is used as an if condition, `errexit` (set -e) is ignored for commands executed by the sourced script, so the script can continue after make docker-image fails.

> -e
> 
> Exit immediately if a pipeline (see Pipelines), which may consist of a single simple command (see Simple Commands), a list (see Lists of Commands), or a compound command (see Compound Commands) returns a non-zero status. The shell does not exit if the command that fails is part of the command list immediately following a while or until keyword, part of the test in an if statement, part of any command executed in a && or || list except the command following the final && or ||, any command in a pipeline but the last, or if the command’s return status is being inverted with !. If a compound command other than a subshell returns a non-zero status because a command failed while -e was being ignored, the shell does not exit. A trap on ERR, if set, is executed before the shell exits.


https://stackoverflow.com/a/76866330


2. `source` returns the exit status of the last command executed. If a later command succeeds, the earlier build failure is effectively hidden and source returns 0, causing the retry loop to exit successfully.


## Fix

Use `bash` instead of `source`, this preserves the script's set -e behavior, so a failed command causes the script to exit with a non-zero status and correctly triggers the retry logic.

Also verified in https://buildkite.com/ray-project/ray-ecosystem-ci-kuberay-ci/builds/17152/canvas?jid=01a0ad21-033a-45b8-b5d7-446ef8714d45&tab=output that the retry mechanism works as expected and successfully retries after the initial failure.
