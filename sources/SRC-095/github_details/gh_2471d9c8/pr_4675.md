# [PR #4675] [operator] Fix RayClusterProvisioned and State=Ready checks for autoscaling clusters

## 正文

## Summary

When `enableInTreeAutoscaling: true` with `replicas: 0` and `minReplicas >= 1`, the `RayClusterProvisioned` condition never transitions to `True` and `State` never becomes `Ready`. This causes `RayJob.jobDeploymentStatus` to stay `Initializing` indefinitely — even when workers are actively processing data.

**Root cause:** Two checks in `calculateStatus` are too strict for autoscaling clusters:
1. `State = Ready` requires `len(runtimePods) == DesiredWorkerReplicas + 1` — but `DesiredWorkerReplicas` is a moving target because the autoscaler continuously adjusts `spec.replicas`
2. `CheckAllPodsRunning` fails on pods in transition (Pending from scale-up, Terminating from scale-down)

**Fix:**
- Filter out terminating pods (`DeletionTimestamp != nil`) before readiness checks
- When autoscaling is enabled, use `ReadyWorkerReplicas >= MinWorkerReplicas` + head pod readiness instead of requiring all pods to match — the cluster is operational once the head and minimum workers are running

Non-autoscaling clusters are unaffected — the existing exact-pod-count check is preserved.

Fixes https://github.com/ray-project/kuberay/issues/4674

## Changes

- `controllers/ray/utils/util.go`: Add `FilterActivePods` (excludes terminating pods) and `IsHeadPodRunningAndReady` helpers
- `controllers/ray/raycluster_controller.go`: Use autoscaling-aware logic in `calculateStatus` for `State=Ready` and `RayClusterProvisioned` checks
- `controllers/ray/utils/util_test.go`: Unit tests for `FilterActivePods` and `IsHeadPodRunningAndReady`
- `controllers/ray/raycluster_controller_unit_test.go`: Integration test for autoscaling with `replicas: 0, minReplicas: 1` verifying both `RayClusterProvisioned=True` and `State=Ready` even with pending scale-up pods
