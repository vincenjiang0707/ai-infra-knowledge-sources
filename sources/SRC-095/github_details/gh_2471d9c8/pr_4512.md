## Why are these changes needed?

This PR reduces YAML boilerplate for RayCluster/RayJob examples and making head-service port behavior consistent.

Today, many sample manifests explicitly define `ray-head` container `ports`. This is repetitive and error-prone.  
With this change, the operator can populate missing default named ports for head service generation, so users do not need to manually specify the common ports in many examples.

In addition, sample naming is aligned with the current operator default port-name convention (`gcs-server`), which avoids mismatches when defaulting/merging service ports.

## Changes made

1. **Head service port defaulting (`getServicePorts`)**
- Keep user-defined ports.
- Fill missing default named ports (`client`, `gcs-server`, `dashboard`, `metrics`, `serve`).
- Avoid duplicate port-number assignment.

2. **HeadService custom port merge safety**
- For user-provided `headService`, merge default ports by name instead of blindly appending.
- This prevents duplicate named service ports in generated Service specs.

3. **ServeService compatibility/safety adjustments**
- Preserve existing ServeService behavior while handling custom ServeService ports safely.
- Keep only the `serve` port in serve service output.
- If user custom ServeService does not include a `serve`-named port, fall back to operator-generated serve port to preserve compatibility.

4. **Sample YAML updates**
- Remove `ray-head` default `ports` blocks from selected `ray-cluster.*.yaml` / `ray-job*.yaml` where they were only default values.
- Align remaining sample port naming from `gcs` to `gcs-server` where needed.
