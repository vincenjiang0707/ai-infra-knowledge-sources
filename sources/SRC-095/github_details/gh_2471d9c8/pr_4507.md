## Why are these changes needed?
`checkSubmitterAndUpdateStatusIfNeeded`: https://github.com/ray-project/kuberay/blob/master/ray-operator/controllers/ray/rayjob_controller.go#L1053-L1068
In sidecar mode and k8sJobMode, if submitter container failed and if job status is already Failed then it's `AppFailed` otherwise its `SubmissionFailed`. But with AsyncJobInfoQuery enabled, the dashboard response is refreshed on an interval, so the cache might still hold `JobStatusRunning` (stale status), so then then we are incorrectly `SubmissionFailed` `rayJob.Status.JobStatus != JobStatusFailed`. Since there are times when submitter exits before the cache updates. 

## Fix
Per this comment suggestion: https://github.com/ray-project/kuberay/pull/4484#issuecomment-3939945353
`checkSubmitterAndUpdateStatusIfNeeded` no longer sets status when submitter fails. Instead it checks that the submitter finished and just logs. GetJobInfo will be the single source of truth for deciding between AppFailed versus SubmissionFailed.
The main reconciling loop queries the Ray dashboard with `GetJobInfo`. `GetJobInfo` interface is updated to return a timestamp for when the reponse was fetched.
- In sync mode the response fetch time is set after the HTTP response. 
- In async mode it's stored in `JobInfoCache.FetchedAt` when the background worker fetches, then returned on cache read
After `GetJobInfo`, if submitter exited and `fetchedAt` is before the submitter's exit time then we requeue.

## Pull request overview

This pull request fixes a race condition where application failures were incorrectly classified as submission failures when the async JobInfo cache hadn't populated yet. The fix introduces exit code distinction in the rayjob-submitter (exit code 1 for application failures, exit code 2 for submission failures) and updates the controller logic to check these exit codes in SidecarMode. Additionally, the PR includes significant refactoring of the async job info query feature, including removing unused context parameters, switching from hashicorp/golang-lru to maypok86/otter for caching, and making query parameters configurable via environment variables.

**Changes:**
- Introduces exit code semantics: exit code 1 for application failures, exit code 2 for submission failures in rayjob-submitter
- Refactors async job info query to use a singleton WorkerPool pattern with configurable parameters
- Removes unnecessary context parameters from multiple function signatures
- Switches cache implementation from hashicorp/golang-lru to maypok86/otter/v2
