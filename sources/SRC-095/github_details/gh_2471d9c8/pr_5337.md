# [PR #5337] [RayCluster] Delete terminal extra head Pods instead of getting stuck…

source: https://github.com/ray-project/kuberay/pull/5337
state: open | updated: 2026-09-23T10:25:52Z
labels: 

## 正文

… when multiple heads exist

When more than one head Pod exists for a RayCluster, reconcilePods used to only log and return an error, assuming the situation could only be caused by users manually creating head Pods. In practice it also happens without any user action: a head Pod Create request can return an error to the operator (e.g. an API server timeout) after the Pod was already persisted. Since the error path records no scale expectation, the immediate retry runs before the informer cache observes the first Pod, lists zero heads, and creates a second one. From then on every reconcile hits the ">1 head Pods" branch, calculateStatus fails on GetRayClusterHeadPod, and the RayCluster (and any owning RayJob) is stuck forever.

Make the branch self-healing: delete every extra head Pod that is in a terminal state or otherwise unable to restart (reusing shouldDeletePod), record a Delete expectation for each, emit the usual events, and return an error so the reconcile is requeued. Healthy head Pods are left untouched, and when nothing can be deleted the previous "please delete extra head pods" error is preserved.
