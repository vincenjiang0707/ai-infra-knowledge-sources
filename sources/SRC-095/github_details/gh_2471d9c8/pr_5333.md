## 正文

## Why are these changes needed?

`get_job_info` and `list_job_info` lose the job's error type and user metadata because `RayJobInfo` reads `ErrorType` and `Metadata`, while the API server returns `errorType` and `metadata`.

Read the API's field names while retaining compatibility with the previously accepted capitalized keys. Add regression coverage for both public read methods, direct decoding, and absent optional fields.

## Related issue number

Discovered while checking the Python client against the job submission API's JSON contract.

### Manual test instructions

Marshal a Go `JobSubmissionInfo` containing `ErrorType` and `Metadata` with the API server's `protojson.MarshalOptions{UseProtoNames: false, UseEnumNumbers: true}`. Serve this JSON from a local HTTP server as an individual job and inside a `submissions` list. Call the real client's `get_job_info` and `list_job_info`: both return `None` for the two fields before the fix and retain both fields afterward. This validates real HTTP reads of the protobuf JSON contract; no Ray cluster or API server deployment was run.
