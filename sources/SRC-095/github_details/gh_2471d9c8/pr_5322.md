# [PR #5322] [Bug] logStdoutEncoder and logFileEncoder setting from `--config` are ignored

## 正文

## Why are these changes needed?

When `--config` is used, `logStdoutEncoder` and `logFileEncoder` are loaded into
`config.LogStdoutEncoder` / `config.LogFileEncoder`, but `main.go` still built
the zap encoders from the raw flag variables. Since the flag defaults are always
`"json"`, this silently overrode any encoder setting from the config file, even
though the flag help text says "Flags are ignored if config file is set".

This PR switches the `newLogEncoder()` calls to use `config.LogStdoutEncoder` /
`config.LogFileEncoder` instead.

- Without `--config`, behavior is unchanged: the flag values are copied into
  `config` before this point, so both code paths read the same value.
- `newLogEncoder` already treats an empty value as `"json"`, matching the flag
  default, so a config file that omits the encoder fields still gets `"json"`.
