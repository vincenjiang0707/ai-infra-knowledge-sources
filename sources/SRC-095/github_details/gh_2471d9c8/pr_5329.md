## Why are these changes needed?
Following a discussion with @robertnishihara and @rueian, we are moving labelMappings up to the workerGroup level and removing the topology wrapper.

The main rationale is that node labels carry broader intent than just network/rack topology. For example, a user could use `labelMappings` to map one worker group to compute-heavy nodes and another to memory-optimized nodes. Furthremore, "labels" is already native vocabulary in both Ray and Kubernetes, so a `labelMappings` field is immediately understandable, while a topology layer above it adds a concept users have to learn. One thing to acknowledge is that we may still need topology-specific fields later; we will add them when a concrete need appears rather than having the `topology` namespace now.
