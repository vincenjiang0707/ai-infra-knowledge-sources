## Why are these changes needed?
We have had multiple end users ask for a cron job-like feature to run Ray Jobs on a repeated schedule. I propose a new RayCronJob CRD and controller to implement this feature. This current proposal is an iteration of a [previous PR](https://github.com/ray-project/kuberay/issues/2426) and [commit](https://github.com/ray-project/kuberay/commit/f6b4f1708b6db79b6f4c0506fcfeb46835085e05) which edited the Ray Job CRD and controller directly; we decided to revert these changes for the reasons seen in the [concerns](https://docs.google.com/document/d/1Sg3hpjDdZJoXVp6r6IsTtpQYSYWKpIHT_fSNUKE3K9M/edit?tab=t.0#heading=h.js0546noh66o) section. As an overview, a new RayCronJob controller would fix the concerns with the previous implementation.

We have a new controller that manages the scheduling and running of a ray job and the expected shutdown and cleanup after each ray job run which uses the logic from the reverted PR having its own controller-runtime reconcile function.
