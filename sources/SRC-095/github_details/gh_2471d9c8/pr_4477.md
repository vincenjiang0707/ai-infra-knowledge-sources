## Why are these changes needed?

These changes allow users to specify a container template to be used for submitter container when using Sidecar submission mode.
This functionality has been requested so sidecar submitter containers can specify volume mounts and/or env vars to be used during job ray job submission.

Hi @marosset,

Would it make sense to validate that the `VolumeMounts` specified in `SubmitterContainerTemplate` reference volumes defined in `HeadGroupSpec`'s `Volumes`? For example:

```go
func validateSubmitterContainerTemplateVolumeMounts(rayJob *rayv1.RayJob) error {
	headSpec := &rayJob.Spec.RayClusterSpec.HeadGroupSpec.Template.Spec
	volumeNames := make(map[string]bool, len(headSpec.Volumes))
	for i := range headSpec.Volumes {
		volumeNames[headSpec.Volumes[i].Name] = true
	}
	for _, mount := range rayJob.Spec.SubmitterContainerTemplate.VolumeMounts {
		if _, ok := volumeNames[mount.Name]; !ok {
			return fmt.Errorf("The RayJob spec is invalid: SubmitterContainerTemplate volume mount %q references volume %q which is not defined in RayClusterSpec.HeadGroupSpec.Template.Spec.Volumes; add the volume to the head pod template", mount.Name, mount.Name)
		}
	}
	return nil
}
```

> This is something @andrewsykim , @rueian , and I discussed today. Would love to hear your thoughts on whether this direction makes sense.

I initially thought of doing this.
My thoughts were that it would add a lot more confusion because many of the fields in `submitterPodTemplate.spec` aren't applicable (restartPolicy, tolerations, nodeSelector, serviceAccountName, etc) and also there would be a lot of weirdness in where volume mounts would need to be defined.

Volumes need to be declared in the `rayClusterSpec.headGroupSpec.template.spec` for them to be mountable by the sidecar container.

If we stick with the **submittedContainerTemplate** the pod spec would look like

something like

```yaml
apiVersion: ray.io/v1
kind: RayJob
metadata:
  name: my-rayjob-sidecar
spec:
  submissionMode: SidecarMode
  entrypoint: "python /scripts/my_job.py"
  
  submitterContainerTemplate:
    image: rayproject/ray:2.52.0  
    volumeMounts:
      - name: job-scripts
        mountPath: /scripts
    resources:
      requests:
        cpu: "200m"
        memory: "256Mi"
      limits:
        cpu: "500m"
        memory: "512Mi"
  
  rayClusterSpec:
    rayVersion: "2.9.0"
    headGroupSpec:
      rayStartParams:
        dashboard-host: "0.0.0.0"
      template:
        spec:
          # Volumes must be defined here (Pod level)
          volumes:
            - name: job-scripts
              configMap:
                name: my-job-scripts
          containers:
            - name: ray-head
              image: rayproject/ray:2.52.0
```

If we re-use the **submittedPodTemplate**

the spec would look like

```yaml
apiVersion: ray.io/v1
kind: RayJob
metadata:
  name: my-rayjob-sidecar
spec:
  submissionMode: SidecarMode
  entrypoint: "python /scripts/my_job.py"
  
  submitterPodTemplate:
    spec:
      containers:
        - name: ray-job-submitter 
          image: rayproject/ray:2.52.0
          volumeMounts:
            - name: job-scripts
              mountPath: /scripts
          resources:
            requests:
              cpu: "200m"
              memory: "256Mi"
  
  rayClusterSpec:
    rayVersion: "2.9.0"
    headGroupSpec:
      template:
        spec:
          # Volumes STILL must be defined here (not in submitterPodTemplate.spec.volumes)
          volumes:
            - name: job-scripts
              configMap:
                name: my-job-scripts
          containers:
            - name: ray-head
              image: rayproject/ray:2.52.0
```

And I was thinking this would cause a lot of confusion  

Let me know what you all think @andrewsykim @Future-Outlier @rueian
