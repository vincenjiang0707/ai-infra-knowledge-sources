## 正文

## Fixes

Fixes #5301

## Summary

When YuniKorn hard-gang `placeholderTimeoutInSeconds` expires, Pods are failed with `Reason: ResourceReservationTimeout` and the YuniKorn application is removed. KubeRay previously treated those as ordinary terminal Pods, deleted them, and recreated replacements against the same dead `applicationId`, leaving RayJob running until `activeDeadlineSeconds`.

This change:

1. Treats `Failed` + `ResourceReservationTimeout` as a non-recreate terminal failure in `shouldDeletePod`.
2. Short-circuits `reconcilePods` when such Pods are present (or when `Status.Reason` is already set) so `WorkersToDelete` cannot remove them and trigger recreation.
3. Surfaces the failure on RayCluster (`Status.State=failed`, `Status.Reason=ResourceReservationTimeout`, and `BatchSchedulingFailed` condition when the status-conditions feature gate is enabled).
4. Transitions RayJob to `Failed` with `Reason=ResourceReservationTimeout` while waiting for the cluster to become ready.

A broader `BatchScheduler` plugin hook (issue option 3) is left for a follow-up / maintainer design choice; this implements the smallest correct stop-recreate + surface-failure path.
