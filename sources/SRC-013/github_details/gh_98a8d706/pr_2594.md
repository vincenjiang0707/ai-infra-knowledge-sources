# [PR #2594] never-run badges

source: https://github.com/llm-d/llm-d/pull/2594
state: closed | updated: 2026-09-26T12:55:43Z
labels: 

## 正文

Seed a grey `never run` badge for every cell of the Release Testing matrix, so a
freshly cut release branch renders a readable table instead of a grid of broken
images.

## Problem

Every cell of the [Release Testing matrix](https://github.com/llm-d/llm-d/blob/main/release/README.md#release-testing)
is a live shields.io endpoint pointing at `badges/<badge_name>_<release-branch>.json`
on `gh-pages`. That is what lets a single lane re-run update the table with no
re-render, and it should stay that way.

Shields has no default-if-missing, though. A cell whose endpoint file does not
exist renders the literal text `custom badge: resource not found` — there is no
such thing as an empty cell. #2590 says as much in its own description: *"a cell
showing an error badge means that lane has not published a badge for this release
yet."*

So a release branch starts as a table of broken images and stays partly broken
until every lane has been dispatched at least once. Measured against
`release-0.10` today:

| | count |
| --- | --- |
| cells in the matrix | 50 |
| `_release-0.10` badge files on `gh-pages` | 39 — all `"message": "dry-run"` |
| cells rendering `resource not found` | **11** |

There is a second, subtler problem visible in that table. Because `dry-run` is
the cheapest badge to produce, it is currently doubling as a placeholder — which
loses the distinction between *"we exercised this lane and the guide resolved
cleanly"* and *"nobody has touched this"*. Both read blue.

## What this does

`release-e2e.yaml` now seeds a placeholder for every badge the matrix references
before it dispatches anything:

```json
{
  "schemaVersion": 1,
  "label": "VLLM GPU",
  "message": "never run",
  "color": "lightgrey"
}
```

Same field set and order as the heredoc in llm-d-infra's
`reusable-update-badge.yaml`, so a real run replacing a placeholder is a two-line
diff. `label` is copied from the lane's own `badge_label:` rather than recomputed,
so a cell's label does not change when the placeholder is replaced.

`lightgrey` is deliberately the same grey that reusable already writes for
`skipped` and `cancelled`: one consistent "no result" shade, distinguished by the
message rather than the colour.

### Three properties that are load-bearing

**Create-if-absent.** A placeholder must never overwrite a real result or a
deliberate `dry-run`. That is also what makes re-running free, which is why this
seeds on *every* dispatch rather than only the first.

**The full set, never the `lanes` subset.** The badge list comes from the same
`GUIDES` × `PROVIDERS` walk the sync scripts use, so it cannot drift from the
rendered table. Seeding only the matched lanes would leave every other cell
broken — the problem being fixed.

**One commit, not 50.** `gh-pages` is a Pages branch, and one push per badge
would mean ~50 Pages builds against a soft limit of about ten an hour. The
seeder builds a single tree via the Git Data API and updates the ref
**unforced** — losing the race to a lane's own push is better than clobbering it,
since `reusable-update-badge.yaml` pushes with no concurrency group and no retry.
On a rejected update it re-reads `gh-pages` and retries, which is what keeps it
create-if-absent: a badge written in between drops out of the next attempt. A
truncated tree listing is refused rather than guessed, because that would make
present files look overwritable.

## Changes

- **`scripts/seed-release-badges.py`** (new) — the seeder. Stdlib only, since
  `ci-guides-check.yaml` installs just `pyyaml` and `pytest`. Supports
  `--dry-run`.
- **`scripts/matrix_common.py`** — `badge_file_name()` extracted out of
  `badge_endpoint()` so the `_{matrix_type}` suffix rule (which has to agree with
  llm-d-infra or the matrices point at files nobody writes) exists in exactly one
  place; plus `_extract_badge_label()` and `matrix_badge_labels()`. The tuple
  `discover_workflows()` yields is unchanged — both sync scripts unpack it
  positionally.
- **`.github/workflows/release-e2e.yaml`** — one job becomes
  `validate` → `seed-badges` → `dispatch`.
- **`.github/ISSUE_TEMPLATE/new-release.md`** — the outstanding-lane check had to
  change; see below.
- **`scripts/tests/test_seed_release_badges.py`** (new) — 30 tests, picked up by
  `ci-guides-check.yaml`, whose path filter now also covers the two scripts.

### Why validation became its own job

Seeding must not run before `release_branch` has been checked, and it needs
`contents: write`, which the dispatch step should not have. `badge_file_name()`
gives `nightly` no suffix, so a `--matrix-type nightly` slip would quietly write
placeholders over the **nightly** badges and blank out the Nightly Testing
matrix. Hence validation ahead of the write, a second independent guard inside
the script for hand runs, top-level `permissions` narrowed to `contents: read`,
and `contents: write` scoped to `seed-badges` alone.

### The release template's badge check had to change

The "which lanes are still missing" step used
`comm -23 /tmp/expected.txt /tmp/got.txt`, i.e. it detected lanes by the
**absence** of a badge file. Once every cell is seeded that returns nothing,
always. It is now a query over badge *contents*, printing every non-green cell
with the reason:

```text
fast-model-actuation-base-ocp                 never run
pd-disaggregation-ocp                         dry-run
```

`never run` for a lane nobody has dispatched, `dry-run` for one only exercised
without a stack, a failure category for one that ran and failed, and `MISSING`
for a badge the seeder did not create — which now means the matrix has a broken
cell and the `seed-badges` job needs a look.

Also corrected two stale counts in that template and in the workflow header:
there are **50** lanes and 50 distinct badge names, one per cell, not "42 names
for 43 lanes".

## Verification

- `pytest scripts/tests/` — 68 pass (30 new).
- yamllint, actionlint and markdownlint clean at the pinned pre-commit versions.
- `sync-nightly-matrix.py --check` in sync, and `release/README.md` is

- The matrix-type guard rejects `nightly`, `main`, `release-0.99.1` and `""`
  before any API call.
- A test asserts the seeded badge set equals the set
  `sync-release-matrix.py` actually renders, so the two cannot drift.
- Live `--dry-run` against `gh-pages`: **would seed 11 of 50 (39 already
  present)** — the same 11 cells independently confirmed to be rendering
  `resource not found`.

Nothing has been written to `gh-pages` yet.

### After merge

Dispatch `release-e2e.yaml` with `release_branch=release-0.10`,
`list_only=true`. Expect one commit on `gh-pages` adding 11 files, a step summary
reporting 11 seeded / 39 present, zero lanes dispatched, and the `release-0.10`
section rendering 50 badges with no `resource not found` — 39 blue `dry-run`,
11 grey `never run`.

## Out of scope

`reusable-update-badge.yaml` lives in llm-d-infra and pushes to `gh-pages` with
no concurrency group and no retry. This PR works around that rather than fixing
it; the seeder's retry loop is the workaround.
