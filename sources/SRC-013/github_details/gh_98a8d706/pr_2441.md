## Description

Adds a new "General Serving Operations" page (`docs/operations/general-serving.md`) covering operational flows for a standard, non-disaggregated deployment, and links it from `docs/operations/README.md`.

Issue #1519 asked for the same operational documentation that already exists for disaggregated serving (`docs/architecture/advanced/disaggregation/operations-vllm`, now at `docs/operations/disaggregation/vllm.md`), applied to general serving: request cancellation, readiness/health probes, and graceful shutdown with request draining, under an Operations section.

The `docs/operations/` section already exists and already covers readiness/health probes in full (`docs/operations/readiness-probes.md`), so this PR does not duplicate that page, it links to it. The two pieces that were not covered anywhere for a non-disaggregated deployment were request cancellation and graceful shutdown, so this PR adds those:

- **Request cancellation**: explains the general mechanism (client disconnect propagates through the router's `httputil.ReverseProxy` context, which cancels the proxied request to the model server, which runs vLLM's abort codepath), grounded in the router's actual proxy code (`pkg/coordinator/server/passthrough.go`, `pkg/coordinator/steps/decode_proxy.go` in llm-d-router). It also links to the disaggregated-serving version of this section for the additional KV-cache cleanup step that case needs and general serving does not.
- **Graceful shutdown**: documents the standard stop-intake / drain / SIGKILL sequence via `preStop` and `terminationGracePeriodSeconds`, the same pattern already documented and used for the router's own EPP pods, applied to a model-serving pod in the request path.
