## Summary

Add the nightly E2E workflow and status consolidation job for SGLang tiered prefix cache CPU offloading on GKE GPU, closing the remaining automated-testing gap for SGLang alongside `optimized-baseline` and `pd-disaggregation`.

The lane resolves to `guides/tiered-prefix-cache/modelserver/gpu/sglang/native/cpu/gke` (`offloading_target: cpu`, `connector: native`). L3 / filesystem offloading is **not** added to CI here.

## Overlay fixes required for CI execution

Two defects in the `cpu` overlay prevented `llm-d-infra` from standing it up:

- **Model auto-detection.** `llm-d-infra` derives the served model by stripping the `--model-path=` prefix and discarding anything still shaped like a flag. Bare option values on their own list items (`write_through`, `kernel`) survive that filter, so detection returned 3 lines instead of 1 and the result was passed on as `--model`. Normalizing to `--flag=value` restores single-line detection.
- **`decode_pods` override.** Renaming `base/patch-sglang.yaml` to `base/patch-decode.yaml` lets `llm-d-infra`'s glob (`patch-{vllm,decode}.yaml`) apply the functional-gate override. Without it the lane would stand up the guide's benchmark topology of 8 replicas at TP=2.

## Memory sizing

Raise decode container memory `limits` from `400Gi` to `512Gi` and `requests` from `200Gi` to `400Gi`. `--hicache-size` is **per TP rank**, so `200` at TP=2 pins ~372.5 GiB of host memory; together with the `20Gi` memory-backed `/dev/shm` volume charged to the same cgroup, a `400Gi` limit left no room for Python and CUDA runtime allocations.

## Scope note: the `fs` overlay

The `fs` overlay is **not exercised by this lane**. It is fixed here because it carries the identical model-detection defect (5 bare values rather than 3) and would fail the moment CI is pointed at it. That change is limited to the argument form plus one wrong field name in a comment — no behavioural change.

## Workflow scheduling and isolation

Runs at `18:30 UTC` daily, 3 hours after P/D SGLang on the same cluster, with status consolidation at `20:30 UTC`. Dedicated namespace, Helm release (`llmdbenchcicdr-gke-sglang-tiered`), and runner workspace directory (`/tmp/llmdbenchcicdk-gke-sglang-tiered`) so runs do not collide with sibling GKE lanes.

## Testing

Replayed `llm-d-infra`'s model detection pipeline against all four `sglang` overlays — each now returns exactly one line (`Qwen/Qwen3-32B`), where `cpu/gke` previously returned 3 and `fs/gke` 5:

```bash
kubectl kustomize <overlay> \
  | yq .spec.template.spec.containers[0].args \
  | sed 's^--model-path=^^g' \
  | grep -Ev "\- \--|\- '|\---|\- \||    \--|.*exec vllm|'|null|#|\"|find|START_RANK" \
  | sed -e 's^ ^^g' -e 's|^-||g' -e 's^\\^^g' -e '/^$/d' | uniq
```

Rendering, lint, and matrix sync:

```bash
kubectl kustomize guides/tiered-prefix-cache/modelserver/gpu/sglang/native/cpu/gke
kubectl kustomize guides/tiered-prefix-cache/modelserver/gpu/sglang/native/fs/gke
pre-commit run --files \
  .github/workflows/nightly-e2e-tiered-prefix-cache-gke-cpu-gpu-sglang-native.yaml \
  .github/workflows/consolidate-status-tiered-prefix-cache-gke-cpu-gpu-sglang-native.yaml \
  guides/tiered-prefix-cache/modelserver/gpu/sglang/base/kustomization.yaml \
  guides/tiered-prefix-cache/modelserver/gpu/sglang/base/patch-decode.yaml \
  guides/tiered-prefix-cache/modelserver/gpu/sglang/native/cpu/base/patch-sglang.yaml \
  guides/tiered-prefix-cache/modelserver/gpu/sglang/native/fs/base/patch-sglang.yaml
touch .release-team && python3 scripts/sync-nightly-matrix.py --check && rm -f .release-team
```

> [!NOTE]
> `scripts/sync-nightly-matrix.py --check` also fails on a clean `main` checkout — the `wide-ep-lws` AMD MoRIIO workflow was added without regenerating `release/README.md`. That drift is pre-existing and deliberately left out of this PR; `release/README.md` here changes only the row for this lane.
