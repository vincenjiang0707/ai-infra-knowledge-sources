## 正文

**(Stacked ontop of https://github.com/llm-d/llm-d/pull/2555, see latest commit for diff)**

Add an aggregated (non-disaggregated) wide expert parallelism modelserver
overlay (`guides/wide-ep/modelserver/gpu/vllm-glm-5.3-flash-aggregated/`)
for serving `zai-org/GLM-5.3-Flash` (`Glm5NextForConditionalGeneration`,
320B total / 18B active parameters, 288 routed experts) across 2 x 8-GPU
nodes (16 x NVIDIA B200 GPUs).

Key details:
- Configure `LeaderWorkerSet` (`size: 2`) with `DP=16, EP=16, TP=1`
  (18 routed experts per GPU) using vLLM's DP Supervisor on port 8008
  (`--data-parallel-multi-port-external-lb`, ports 8000-8007) and
  `--reasoning-parser glm47` / `--tool-call-parser glm47`.
- Use the `gpu-vllm/nightly` component (`v0.29.1rc1+`) required for the
  `glm5_next` hybrid KDA linear attention + sparse NoPE MLA architecture
  and TileLang mHC / DSA kernels.
- Set `TRITON_LIBCUDA_PATH=/usr/local/nvidia/lib64` and `LD_LIBRARY_PATH`
  so Triton/FLA kernels locate GKE's mounted `libcuda.so.1` in Ubuntu-based
  upstream `vllm-openai` images.
- Use `--all2all-backend allgather_reducescatter` over GKE DRANET RoCEv2
  RDMA NICs (`gke-rdma-nic-template`, `mrdma.google.com` `gpu0rdma0`-`gpu7rdma0`)
  to avoid the unpatched NVSHMEM `ibv_create_ah` issue on GKE COS.
- Document `GLM-5.3-Flash` deployment and architecture sizing in
  `guides/wide-ep/README.aggregated.md` and `gke/README.md`.
