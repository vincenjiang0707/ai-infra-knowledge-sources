## 正文

Part of #1982 (Phase 3, wide expert parallelism).

Adds an Observability & Troubleshooting section to the wide expert parallelism guide, following the P/D, optimized-baseline and tiered prefix cache sections.

- `guides/wide-ep/README.md`: new step 4 with the signals specific to this path (per DP rank load and KV cache, requests scheduled per rank port, prefill and decode balance, NIXL transfer health, DisaggregatedSet rollout gating) and four common failure modes.
- `docs/operations/observability/promql.md`: adds a Wide Expert Parallelism query table.
- `docs/well-lit-paths/foundations/wide-expert-parallelism.md`: adds an Observability paragraph that links to the guide section.

The queries rely on two labels this guide's own monitoring overlay produces. Prometheus Operator sets `endpoint` to the scraped port name, so each DP rank (`rank0` to `rank7`) is separable, and it sets `job` to `<namespace>/<PodMonitor name>`, so the prefill and decode roles separate without matching on pod names. DeepEP dispatch and combine expose no Prometheus metrics, so the section points at the startup logs for those failures instead.

Docs only. Checked that the new links and anchors resolve.
