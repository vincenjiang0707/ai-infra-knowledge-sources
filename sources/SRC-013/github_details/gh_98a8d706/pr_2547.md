# [PR #2547] fix(ci): unpin SGLang tiered cache nightly cluster

## 正文

## What

Drop `cluster_name` and `cluster_zone` from the SGLang tiered-prefix-cache
nightly lane so it uses the llm-d-infra default, `llm-d-e2e-us-east5`. This is a follow-up PR for https://github.com/llm-d/llm-d/pull/2480

## Why

The lane was pinned to `llm-d-e2e-us-south1-2`, which no longer has any GPU
nodes. Its `a3u-dra-pool` is gone and only `default-pool` and `pool-1` remain,
so llm-d-benchmark cannot resolve the accelerator for the `decode` section and
every run aborts during the pre-standup teardown, about two minutes in:

```
RuntimeError: Could not auto-detect the following cluster resources:
decode.acceleratorType.labelValue
  cluster_resource_resolver.py:244 in resolve_all
```

Because nothing is deployed at that point, the run also logs a misleading
`namespaces "..." not found` while collecting debug information.

The pin was never needed. This lane serves Qwen3-32B at TP=2 and requests
`nvidia.com/gpu` directly, with no DRA or RDMA, so it belongs on the reserved
H100 cluster alongside the optimized-baseline SGLang lane and both vLLM
tiered-prefix-cache lanes, none of which set `cluster_name`. `us-east5` has a
16-node `h100-pool` and already carries the vLLM tiered lane at 4 replicas x 2
GPUs, so it has room for this lane's 2 x 2.

## Testing

Confirmed the lane passes only `cluster_namespace`, matching the other H100
lanes, and that yamllint is clean:

```shell
yq '.jobs.nightly.with | keys' \
  .github/workflows/nightly-e2e-tiered-prefix-cache-gke-cpu-gpu-sglang-native.yaml
pre-commit run --files \
  .github/workflows/nightly-e2e-tiered-prefix-cache-gke-cpu-gpu-sglang-native.yaml
```

A scheduled or dispatched run is needed to confirm standup on the new cluster.
I do not have permission to trigger `/test-nightly`, so a guide owner running it
on this PR would help.
