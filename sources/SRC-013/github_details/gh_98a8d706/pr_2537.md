## 正文

Add an Intel XPU deployment for aggregated `Qwen/Qwen3-235B-A22B` serving using
vLLM, in the WideEP guide with TP8 per node and EP16 spanning 16 XPUs across two nodes.

## Topology

This configuration deploys Qwen3-235B with **EP16 across two nodes**:

| Setting | Value |
|---|---:|
| Nodes / LWS pods | 2 |
| XPUs per node | 8 |
| Total XPUs | 16 |
| Tensor parallel size | 8 |
| Data parallel size | 2 |
| Expert parallel size | 16 |
| RDMA NICs per node | 1 |

Each node runs one vLLM instance using TP8 across its eight local XPUs.
The two instances form DP2 across the two nodes. With expert parallelism
enabled, the model's experts are distributed across all 16 XPU ranks,
forming an **EP16 cross-node topology**.

```text
                       llm-d Router / EPP
                               |
                        Service port 8200
                               |
              +----------------+----------------+
              |                                 |
          Node 0 / LWS leader              Node 1 / LWS worker
          DP rank 0                        DP rank 1
          TP8: XPU 0-7                     TP8: XPU 8-15
          1 RDMA NIC                       1 RDMA NIC
              |                                 |
              +------ EP16 over XCCL/OFI -------+
                    allgather_reducescatter
```

Intel XPUs and RDMA network devices are allocated through Kubernetes
DRA using the gpu.intel.com and dranet-rdma DeviceClasses.

Changes
- Add the Qwen3-235B LeaderWorkerSet model server manifests.
- Configure vLLM with TP=8, DP=2, FP8 quantization, and expert
parallelism.
- Configure XCCL over OFI verbs for cross-node communication.
- Add DRA claims for eight Intel XPUs and one RDMA NIC per pod.
- Add an aggregated-serving EPP configuration targeting port 8200.
- Document the commands required to deploy the Qwen3-235B model and
its router configuration.
- Assign stable qwen-0 and qwen-1 hostnames to avoid ambiguous
hostname-prefix matching during oneCCL local-rank discovery.
