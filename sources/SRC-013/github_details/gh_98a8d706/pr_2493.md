### shikamd123 · 2026-09-24

@ahg-g : Thanks — rebasing onto guides/wide-ep/ and converting to DisaggregatedSet now. One design question before I push, since MoRI-IO's peer requirement differs from NIXL's.

I deployed a throwaway DisaggregatedSet to check pod naming. Child objects are <ds-name>-<template-hash>-<role>, and the hash is stable across restarts but changes on any pod-template edit (confirmed: c4f06366 → ea2cc728 after a one-line change). So the FQDNs this recipe currently passes to the routing sidecar can't survive the migration.

For NIXL that's a non-issue — the sidecar takes no peer flags and the EPP injects x-prefiller-host-port per request, with disaggregatedset-rollout-screener keeping both legs on one revision. I'd like to adopt that.

The gap is that MoRI-IO also needs an ordered per-pod host list at startup, not just a per-request pick. _background_moriio_handshake iterates for cur_dp_rank in range(remote_dp_size) and indexes pod_hosts[pod_index(rank, dp_local)] to do an all-to-all handshake with every remote DP rank. That list reaches the connector as kv_transfer_params["remote_hosts"], which the sidecar builds today from static flags.

Is there an intended way to source that list under DisaggregatedSet? The options I can see are (a) an EPP plugin surfacing the role's pod set rather than a single pick, (b) the per-role -prv headless service, or (c) having the sidecar derive peers from its own subdomain, since both roles share the hash. Happy to implement whichever fits the direction.
