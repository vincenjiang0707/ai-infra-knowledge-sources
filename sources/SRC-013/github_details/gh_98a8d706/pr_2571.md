## 正文

**What type of PR is this?**

/kind bug

**What this PR does / why we need it**:

The generic-Kubernetes KEDA autoscaling path in both keda-epp guides was broken. KEDA's prometheus scaler only applies a `TriggerAuthentication` CA when the trigger also sets `authModes` (its `GetAuthConfigs` returns early without it), so the shipped "CA-only" trigger silently fell back to the system trust store and failed serving-cert verification with `x509: certificate signed by unknown authority`. This path was never end-to-end tested against a real TLS Prometheus.

This PR reworks the generic-k8s path to plain in-cluster HTTP and preserves the (working) OpenShift path exactly:

- keda-epp-saturation and keda-epp-queue `k8s` overlays now target the bundled kube-prometheus-stack over plain in-cluster HTTP (`http://...:9090`) with no client auth, no `TriggerAuthentication`, and no CA secret.
- Removed the base `TriggerAuthentication` (deleted the saturation `base/triggerauthentication.yaml`; removed the embedded TA block from the queue `base/scaledobject.yaml`) and dropped the `deploy.prometheus_auth` step and the CA-secret cleanup from both `guide.yaml` files.
- OpenShift is unchanged: each guide now carries its own `ocp/triggerauthentication.yaml` (`authModes: bearer` + metrics-reader `service-ca.crt`), and the `ocp` overlay patches `serverAddress` to Thanos Querier and attaches it. `kubectl kustomize .../ocp` is byte-identical to `main` for both guides.
- Refreshed the README and `guide.yaml` prose, re-rendered both guides (`guide.py render --check` is clean), and added an `> [!IMPORTANT]` note documenting the KEDA CA/`authModes` caveat so future readers do not re-introduce a CA-only trigger.

Verified end to end on a kind cluster for both guides against a plain-HTTP Prometheus: the ScaledObject reaches `Ready=True`/`Active=True` with no `x509` errors, the generated HPA reads both external metrics over threshold, and the target Deployment performs a real 1-to-N scale-out.

**Which issue(s) this PR fixes**:

Refs #2565

**Release note**:

```release-note
The generic-Kubernetes KEDA + EPP autoscaling guides (keda-epp-saturation, keda-epp-queue) now connect to the bundled Prometheus over plain in-cluster HTTP. The previous CA-only TriggerAuthentication never verified TLS on KEDA's prometheus scaler (it requires authModes to load the CA). The OpenShift path is unchanged and still uses bearer auth over HTTPS to Thanos Querier.
```
