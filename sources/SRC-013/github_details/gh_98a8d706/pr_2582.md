## What this adds

The CI half of a nightly for the queue-based KEDA + EPP autoscaling path on the AMD ROCm cluster. It replaces the AMD WVA lane removed in #2576, now that WVA is deprecated and KEDA + EPP is the recommended path.

- `nightly-e2e-workload-autoscaling-keda-epp-amd-acc-rocm-vllm-x.yaml`, the nightly caller on `reusable-nightly-e2e-amd.yaml`
- `consolidate-status-workload-autoscaling-keda-epp-amd-acc-rocm-vllm-x.yaml`, its past-status companion
- The lane registered under `#sig-autoscaling` for Slack failure notifications

## Dispatch-only for now

The deploy script the caller invokes lands in #2583, so both workflows ship without schedules and that PR adds them. Until then the lane can be dispatched from main with `llm_d_ref` set to `refs/pull/2583/merge`.

A run starts on 2 GPUs, can scale to 4, and does not preempt other workloads.
