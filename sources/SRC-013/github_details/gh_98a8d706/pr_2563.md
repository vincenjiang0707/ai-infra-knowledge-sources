# [PR #2563] fix(wide-ep): make Intel XPU decode manifest actually cross-node wide-EP

state: open | updated: 2026-09-24T19:45:06Z

## 正文

## Problem

`decode.yaml` shipped with `leaderWorkerTemplate.size: 1` and only a `workerTemplate` (no `leaderTemplate`). Every "decode" pod was a fully independent TP+EP-only replica — no pod ever shared a DP/EP group with another pod. Despite the guide's name, expert parallelism was never actually organized across pods/nodes on the Intel XPU path.

## Fix

* `decode.yaml`: split into `leaderTemplate` (HTTP API + routing-proxy sidecar, DP-supervisor rank 0) and `workerTemplate` (`--headless`, exec-based probes). `leaderWorkerTemplate.size` bumped `1 -> 2` (smallest config that exercises real cross-pod EP). `vllm serve` args rewritten to the DP-supervisor pattern. Added `podAntiAffinity` (leader/workers on distinct hosts, scoped to this guide) and `rolloutStrategy` (avoids surge-based rollout deadlocks on capacity-constrained clusters).
* `prefill.yaml`: added the same `podAntiAffinity`/`rolloutStrategy`. `size` stays `1` — prefill scales via independent replicas, not a cross-node EP group; its own wide-EP is unvalidated and documented as such inline.
* `kustomization.yaml`: added a labels-transformer path for the new `leaderTemplate`.
* `router/xpu.values.yaml`: EPP endpoint selection now also requires `leaderworkerset.sigs.k8s.io/worker-index: "0"`, since headless decode workers share every other label with the leader but don't serve HTTP on port 8000.
* `README.md`: updated the Intel XPU config table and added notes on the fix and current EPLB status.

## Validation

Validated on a real 4-node/16-XPU Intel cluster: EP world size > 1 actually spans pods, correct expert split, cross-node P/D traffic (NIXL), and light concurrent request handling.

EPLB (expert-parallel load balancing) was not enabled as part of this fix; it's left as follow-up work for Intel XPU.

## Known gaps

* EPLB unsupported/unvalidated on Intel XPU (follow-up work).
* Not tested behind a Gateway/InferencePool front-end (direct Service routing only).
* Only tested with the small `DeepSeek-V2-Lite-Chat` model, light concurrency only.
* `guides/wide-ep/monitoring` still assumes GPU-style `rank0..rank7` ports; pre-existing gap, not touched here.
* Prefill's own cross-node wide-EP (vs. replica scale-out) is unvalidated and out of scope.
