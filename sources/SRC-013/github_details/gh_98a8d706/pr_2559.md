## What does this PR do?

Removes the explicit `image: REPLACE_MODEL_SERVER_IMAGE` line from `guides/multimodal-serving/e-disaggregation/modelserver/gpu/vllm/e-pd/base/patch-encode.yaml`.

## Why is this change needed?

The GKE e-disaggregation nightly fails with encode pods stuck in `InvalidImageName`:

```
spec.containers[modelserver]: Failed to apply default image tag "REPLACE_MODEL_SERVER_IMAGE": couldn't parse image name ...
```

Root cause is kustomize transformer ordering. In `e-pd/base/kustomization.yaml`, the encode skeleton comes from `recipes/modelserver/base/single-host/e-pd` and is filled in by `patch-encode.yaml`. Kustomize applies **component** transformers before the kustomization's own **patches**, so the `images/gpu-vllm/ec-connector` component substitutes the placeholder first, and the explicit `image:` field in `patch-encode.yaml` then overwrites it back to `REPLACE_MODEL_SERVER_IMAGE`. Decode is unaffected because `patch-decode.yaml` carries no `image:` field, and e-p-d is unaffected because it ships encode as a full resource (substituted by the component, never re-patched).

With the image line removed, the encode container keeps the component-substituted image.
