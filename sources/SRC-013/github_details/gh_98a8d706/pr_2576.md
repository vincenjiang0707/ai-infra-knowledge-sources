## Summary
WVA (Workload Variant Autoscaler) is deprecated as of `v0.9.0` with no further releases, and its nightly regression lanes already had scheduling disabled in-repo (`WVA is deprecated`). This PR finishes that by deleting the WVA nightly CI outright:

- Deletes the 3 `nightly-e2e-workload-autoscaling-{amd,cks,ibm}-...yaml` lanes and their 3 `consolidate-status-workload-autoscaling-{amd,cks,ibm}-...yaml` counterparts
- Deletes `guides/workload-autoscaling/scripts/nightly-deploy-{amd,cks,ocp}.sh` and their unit tests (`scripts/tests/test_nightly_deploy_{amd,cks}.py`)
- Removes the "Workload Autoscaling (WVA)" row from `scripts/matrix_common.py` and regenerates `release/README.md` via `scripts/sync-nightly-matrix.py --fix`
- Drops the stale WVA status badge from `guides/workload-autoscaling/README.md`
- Removes a doc reference in `guides/workload-autoscaling/wva/README.md` that pointed at the deleted `nightly-deploy-amd.sh`
- Removes the stale `/test-nightly wva-*` example from `slash-test-nightly.yaml`

**Not touched:** the WVA guide/docs themselves, and the separate KEDA + EPP Queue autoscaling nightly (`nightly-e2e-workload-autoscaling-keda-epp-ibm-...yaml` and its deploy script/badge/matrix row) — that path uses a different autoscaler and explicitly has no WVA controller involved.
