## Summary

The TPU PodMonitor added in #2190 provides a scrape recipe, but llm-d has no dashboard for inspecting the collected hardware metrics. This PR adds a GKE TPU overview dashboard and documentation for enabling it and diagnosing missing data.

- Show exporter scrape health, TensorCore utilization, HBM bandwidth utilization, and runtime duty-cycle and memory gauges when available.
- Reuse the shared dashboard loader and `${DS_PROMETHEUS}` convention. The dashboard selects a single exporter job using an exact match and filters hardware metrics with `make="cloud-tpu"`. It preserves per-instance and per-accelerator series instead of aggregating them. Panels show `No data` when a metric is unavailable.
- Document metric names, units, label scope, availability checks, and compatibility limits in the TPU recipe and observability reference.

The metric names and labels are based on the GKE device-plugin metrics consumed by [Ray's TPU metrics parser](https://github.com/ray-project/ray/blob/be4889928d3a396d7a1476d1bac3288dac72f9ab/python/ray/dashboard/modules/reporter/reporter_agent.py). The utilization metrics and their `make="cloud-tpu"` labels also appear in a [GKE v6e sample shared in a Ray issue](https://github.com/ray-project/ray/issues/57829).

ICI, PCIe, VPU, and kube-state-metrics topology recording rules remain follow-up work.

Relates to #2157

## Validation

- `make verify` passed.
- Markdown lint, JSON parsing, local documentation links, and `git diff --check` passed.
- Local Prometheus 3.5.0 `promtool` checks passed: 34 dashboard query cases and six label-isolation cases using synthetic data. Coverage includes missing metrics, scrape failures, multiple instances, other component jobs, and foreign/missing `make` labels.
- As a negative control, replacing the exact job matcher with a regex matcher caused the label-isolation checks to fail.

The query checks were run locally; this PR adds no test tooling or CI dependencies. No live GKE/TPU deployment validation was available. The synthetic checks validate query behavior, not hardware metric availability.
