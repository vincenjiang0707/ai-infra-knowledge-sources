# [PR #2544] fix(build): remove invalid buildx command prefix

source: https://github.com/llm-d/llm-d/pull/2544
state: open | updated: 2026-09-24T19:48:39Z
labels: Image builds

## 正文

The Docker branch of the buildah-build recipe runs as one continued shell block, so the leading '-' before docker buildx create was passed to the shell as a command name instead of acting as a Make error-ignore prefix. The existing || true hid that error, and docker buildx use image-builder then failed in a clean environment because the builder was never created.

Remove the invalid '-' while retaining || true, allowing the buildx create command to run and preserving the existing tolerance for an already-existing builder.

Tests:
- make -n buildah-build BUILDER=docker
- git diff --check
- Verified the generated recipe contains docker buildx create followed by docker buildx use without the invalid command prefix.

### chrikrah · 2026-09-26 · COMMENTED

Correct, minimal, and reproduced here. The line is `Makefile:139`, in the `elif [ "$(BUILDER)" = "docker" ]` branch of `buildah-build`. `cat -A` shows a continuation line rather than a recipe line start, so make does not strip the `-`. It reaches the shell verbatim:

```
$ make -n buildah-build BUILDER=docker
  sed -e '1 s/\(^FROM\)/FROM --platform=${BUILDPLATFORM}/' docker/Dockerfile.cuda >docker/Dockerfile.cross; \
  - docker buildx create --use --name image-builder || true; \
  docker buildx use image-builder; \
```

`docker buildx create` never runs, and `|| true` hides it. Running the fragment under bash with a `docker` shim:

```
frag.sh: line 2: -: command not found
rc_after_create=0
docker shim invocations: 1
calls: SHIM-DOCKER-CALLED: buildx use image-builder
```

One invocation, and it is `buildx use`. Identical under `dash` and `sh`.

One nuance the body does not mention, and it explains why somebody may have believed the line worked. **Under zsh the `-` is harmless.** zsh reads a leading `-` as its login-shell invocation prefix, and runs the command:

```
argv0=[/tmp/dockershim/docker] args=[buildx create --use --name image-builder]
argv0=[/tmp/dockershim/docker] args=[buildx use image-builder]
```

So the defect is shell-dependent rather than docker-version-dependent. It is live for everyone all the same, because `Makefile:1` is `SHELL := /usr/bin/env bash`, and make honours it: `BASH_VERSION=5.2.21(1)-release`.

The fix also keeps the already-exists tolerance. When `create --use` succeeds, the following `use` is redundant. When the builder already exists, `create` fails, `|| true` absorbs it, and `use` selects it. Both orders work.

No other instance of the pattern exists in the repository: `grep -rn '^[[:space:]]*-[[:space:]]\+[a-z]' --include=Makefile --include='*.mk'` returns nothing. `buildah-build` is called by no CI workflow, which is why this went unnoticed.

One sub-claim I could not check: docker is not installed here, so I did not see `buildx use` error with `no builder "image-builder" found`. The primary claim, that `create` never runs, is proven.
