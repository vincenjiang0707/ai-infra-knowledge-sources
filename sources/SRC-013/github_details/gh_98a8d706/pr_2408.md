## 正文

## Summary

Adds the `mm-embeddings-cache-producer` and `mm-embeddings-cache-scorer` plugins to both vLLM e-disaggregation router profiles (E/PD and E/P/D), so repeated multimodal media routes to the encode worker that already holds the embeddings.

Fixes #1952

## Changes

- `router/vllm/e-pd-disaggregation.values.yaml` and `router/vllm/e-p-d-disaggregation.values.yaml`: add `mm-embeddings-cache-producer` and `mm-embeddings-cache-scorer`, with the scorer referenced in the `encode` scheduling profile at weight 4 (matching the plugin README example). `cacheSizeInMBPerServer` is left unset (plugin default 4096 MiB) with a comment explaining the relationship to the vLLM `num_ec_blocks` this guide configures.
- `README.md`: new "Encoder-Cache Affinity" section covering what the plugins do, the three EPP metrics (`encoder_cache_queries_total`, `encoder_cache_hits_total`, `encoder_cache_hit_ratio`), and how to tune `cacheSizeInMBPerServer` relative to `num_ec_blocks`.

## Notes

- The affinity signal only benefits repeated-media workloads; the README states this.
- Benchmarking the guide with and without the plugins is tracked separately and will follow.
- End-to-end encoder-cache affinity in E/PD depends on the router-side fix in llm-d/llm-d-router#2627 (without it the scorer scores 0). This guide change is the config/docs half.
