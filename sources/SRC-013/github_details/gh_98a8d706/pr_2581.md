# [PR #2581] fix(pd-disaggregation): use kv_consumer for TPU v6 decode

## 正文

vLLM defines KV roles as overlapping sets, so kv_both sets is_kv_producer=True. 
TPUConnector collapses the roles into a single is_producer flag and returns early in get_num_new_matched_tokens when it is set, never consulting is_kv_consumer. With kv_both the decode engine reports zero loadable tokens on every request: prefill stages KV blocks that are never pulled and expire with "KV transfer timeout. 


Measured on TPU v6e (Qwen3-30B-A3B), kv_both -> kv_consumer:
  decode reqs_to_load:          0 -> 12
  decode insert_kv_chunks:      0 -> 3 per 3 reqs
  prefill KV transfer timeouts: every request -> 0
  avg transfer size:            0 -> 420-810 MB
