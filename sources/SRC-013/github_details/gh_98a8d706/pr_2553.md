## 正文

## What

Adds `COMPONENTS.md`, defining two classes of component the project maintains:

- **Core** - on the inference request path; a failure or regression there
  degrades or breaks live inference. Deliberately small, carries production
  reliability expectations.
- **Ecosystem** - maintained and first-class, but not needed to serve a
  request (planning, benchmarking, analysis, simulation, adjacent services).

The role is orthogonal to graduation: a component moves from
`llm-d-incubation` into the main `llm-d` org and takes on one of the two roles
at that point. An ecosystem component can later be promoted to core if it moves
onto the request path and meets the higher bar.

## Why

Today "in the main org" is a single undifferentiated signal with no written
graduation criteria, so every graduation becomes an argument. This gives
committed-but-off-path components (starting with `llm-d-planner`) a real home
without implying request-path guarantees, while keeping the core set small and
high-bar to protect the request path.

## Notes

- Graduation criteria are grounded in the existing principles in `PROJECT.md`
- Includes a starter roster. The roster is the source of truth and changes by
  pull request.
