## 正文

This commit introduces a prefix caching mechanism to accelerate the prefill stage for requests with common prompt prefixes, specifically when using chunked prefill.

Key changes include:

1.  **Prefix Cache Implementation (`jetstream/core/prefix_cache.py`):**
    *   Introduces `PrefixCache`, which utilizes a `PrefixCacheTrie` for
        key management and a `HierarchicalCache` (HBM/DRAM LRU) for
        storing KV cache values (`Prefix`).
    *   Adds helper functions `load_existing_prefix` and
        `save_existing_prefix` to manage cache interactions, ensuring
        prefixes are aligned with `chunk_size` and handling cache hits/misses.
    *   Modifies `PrefixCache.load` to find the longest common prefix key
        and support a minimum match length.
        Which prevent race condition that cannot load the key fetched before.
    *   Adds `PrefixCache.contains` to efficiently check for existing keys.

2.  **Orchestrator Integration (`jetstream/core/orchestrator.py`):**
    *   Adds an optional `_prefix_cache` attribute to the `Driver`.
    *   Refactors the chunked prefill logic into `_do_chunked_prefill`.
    *   Introduces `_do_chunked_prefill_with_prefix_cache` which attempts
        to load from the cache, performs chunked prefill on remaining tokens,
        and saves the result back to the cache.
    *   Updates the prefill path to use the cache-aware logic when the
        prefix cache is enabled.

3.  **Chunked Prefill Refactoring (`jetstream/engine/chunked_prefill.py`):**
    *   Extracts the core logic for generating chunked tokens and performing
        the iterative prefill process into a new dedicated file.
    *   If the prompt length is less than chunk size, fallback using standard prefill.
    *   Always input tokens padding to chunked size to prevent too many graphs.

4.  **Configuration (`jetstream/core/config_lib.py`, `jetstream/core/server_lib.py`):**
    *   Adds `PrefixCachingConfig` to define cache size limits (HBM/DRAM).
    *   Updates `server_lib.create_driver` and `run` to accept the config
        and instantiate/pass the `PrefixCache` to the `Driver`.

5.  **Testing (`jetstream/tests/core/test_prefix_cache.py`):**
    *   Updates existing tests to reflect API changes (`load` replaces
        `fetch_longest_common_prefix_key`).
    *   Adds tests for new functionality like `min_common_prefix_key_length`.

This feature aims to reduce redundant computations during prefill for prompts sharing initial token sequences, improving overall throughput and latency when chunked prefill is active.
