## 正文

## Motivation

Fixes #40739. For the same complete output, `qwen3_coder`'s non-streaming and streaming paths returned different visible content: `detect_and_parse` built `normal_text` only from `text[:start_idx]`, so `before<tool_call>...</tool_call>after` yielded `content="before"` non-streaming but `"beforeafter"` streaming. Visible text the model emitted after (or between) tool calls was silently dropped on the one-shot path.

## Modifications

One-shot parsing now carves complete `<tool_call>...</tool_call>` blocks out of the text and keeps the rest, matching what the streaming state machine emits for the same output (text before, between, and after calls). An unclosed trailing block or a partial tag is still cut, so malformed tails do not leak into visible content either. Three tests cover the parity: trailing text after a call, text between two calls, and the unclosed-tail case.

### Pranjulcr7 · 2026-09-27 · COMMENTED

One remaining parity case at `b942209`: the suffix can end partway through a marker.

```python
call = '<tool_call><function=get_weather><parameter=city>Paris</parameter></function></tool_call>'
text = 'before' + call + 'after<tool_call'
```

With `get_weather(city: string)` declared, non-streaming returns `beforeafter<tool_call`; character-by-character streaming returns `beforeafter`. The same happens with a final `after<fun`. The new trimming loop only searches for complete `<tool_call>` and `<function=` tokens, so it misses prefixes buffered by the streaming parser.

Please add truncated-marker suffix cases and retain the streaming parser's prefix-buffering behavior. The new complete-call and full unclosed-call cases otherwise behaved as expected in this probe.

Checked with a CPU detector probe using the repository implementations, bypassing package startup imports; no server or model evaluation.

### he-yufeng · 2026-09-27

Good catch, fixed in eb36b7a1. The one-shot pass now also truncates at any end-of-string tail that prefixes one of the six known tags (`<tool_call`, `<fun`, a lone `<`), which is exactly where the streaming parser stops emitting and buffers. Your two probes now return `beforeafter` in both modes; ordinary prose with a mid-text `<` is unaffected since only an end-of-string tail can prefix a full tag. Regression subtests cover all three tail shapes; the full function-call parser file passes locally (254 tests + 54 subtests).
