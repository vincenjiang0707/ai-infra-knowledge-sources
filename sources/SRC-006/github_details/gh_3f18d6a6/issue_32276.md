## Describe the bug

MiniMax-M3 exposes reasoning control through the official OpenAI-compatible request field
`thinking: {"type": "disabled" | "adaptive"}` (documented in the MiniMax platform API docs, the
HuggingFace model card, and used by MiniMax's own `MiniMax-Provider-Verifier`).

When this field is sent to SGLang, it is **silently dropped**: the request returns `200 OK`, but the
model still produces reasoning (`reasoning_content` is non-empty). So `thinking: {"type": "disabled"}`
has no effect — thinking is never actually disabled.

This makes MiniMax's official verifier test `TestThinking::test_04_01_thinking_disabled` fail against
SGLang.

## Reproduction

Launch:

```bash
python -m sglang.launch_server \
  --model-path MiniMaxAI/MiniMax-M3 \
  --trust-remote-code \
  --reasoning-parser auto \
  --tool-call-parser auto \
  --tp-size 4 \
  --port 8043
```

### A) Official API field — DOES NOT WORK (bug)

```bash
curl -s http://localhost:8043/v1/chat/completions -H 'Content-Type: application/json' -d '{
  "model": "MiniMaxAI/MiniMax-M3",
  "messages": [{"role": "user", "content": "Say hello"}],
  "max_tokens": 128,
  "thinking": {"type": "disabled"}
}' | python3 -c 'import sys,json;m=json.load(sys.stdin)["choices"][0]["message"];print("reasoning_content:",repr(m.get("reasoning_content"))[:160])'
```

Actual: `reasoning_content: 'The user is asking me to say hello...'`  ← still thinking ❌

### B) reasoning_effort:"none" (SGLang native "reasoning off") — ALSO DOES NOT WORK

Same request but with `"reasoning_effort": "none"` instead of `thinking` → still returns
`reasoning_content` ❌

### C) chat_template_kwargs.thinking_mode=disabled — WORKS

```bash
curl -s http://localhost:8043/v1/chat/completions -H 'Content-Type: application/json' -d '{
  "model": "MiniMaxAI/MiniMax-M3",
  "messages": [{"role,
  "messages": [{"role": "user", "content": "Say hello"}],
  "max_tokens": 128,
  "chat_template_kwargs": {"thinking_mode": "disabled"}
}' | python3 -c 'import sys,json;m=json.load(sys.stdin)["choices"][0]["message"];print("reasoning_content:",repr(m.get("reasoning_content")))'
```

Actual: `reasoning_content: None` ← thinking disabled ✅

So the model and the M3 chat template are correct; only the serving-layer field mapping is missing.


## Expected behavior

Sending the official `thinking: {"type": "disabled"}`  should disable reasoning for MiniMax-M3


## Environment

- SGLang version: `0.5.15.post1.dev20260722+gb13abfdedf` (also present on current main)
- Model: `MiniMaxAI/MiniMax-M3`
