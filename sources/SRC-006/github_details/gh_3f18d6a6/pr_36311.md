## Motivation

Adding HunyuanImage3-Instruct support with T2I and TI2I generation.

Usage example:
```
sglang generate --model-path tencent/HunyuanImage-3.0-Instruct \
                --prompt $PROMPT --image-path $IMAGE_PATH \
                --tp-size 4 --num-gpus 4 \
                --seed 42 --guidance-scale 2.5 --num-inference-steps 50
```

## Model-specific options

### Server flags

- `--batching-max-size N` (default `1`) — enables dynamic batching; must be > 1. Also caps the cond-encode chunk for TI2I.
- `--batching-delay-ms MS` (default `0`) — how long the first queued request waits for companions; use `200`–`2000` for bursty traffic.

### Environment variables

- `SGLANG_HI3_COND_ENCODE_BATCHING=1` (default `0`) — batch condition-image VAE/ViT encoding (TI2I/I2I); halve-on-OOM backoff, chunk capped by `--batching-max-size`.
- `SGLANG_HI3_OUTPUT_CROP=0` (default `1`) — skip post-decode crop/pad/resample and return the raw native bucket.

### Request parameters

- `bot_task` (default `image`) — `image`, `auto`, `think`, `recaption`, `think_recaption`, `img_ratio`, `none`.
- `system_prompt` (default `en_unified`) — presets `en_vanilla` / `en_recaption` / `en_think_recaption` / `dynamic` / `none`, or raw text.
- Supported resolutions (multiples of 16): 1024x1024, 768x1024, 1024x768, 720x1280, 1280x720.

Notes: requests batch together only when bucket fields match (resolution, steps, guidance, `bot_task`, `system_prompt`, condition count) — `prompt` and `seed` may differ freely.

## Speed Tests and Profiling


<details>
<summary><b>T2I</b></summary>

Num prompts: <b>50</b>

| --batching-max-size | --max-concurrency | Cache-DiT |  Benchmark duration (s)  |
|---|---|---|---|
| 1 | 1 | ❌|  2140.66 |
| 1 | 1 |✅| 878.88 |
| 2 | 5 |✅|  848.71  |

</details>

<details>
<summary><b>I2I</b></summary>

Num prompts: <b>10</b>

| --batching-max-size | --max-concurrency | Cache-DiT | Benchmark duration (s)  |
|---|---|---|---|
| 1 |  1 | ❌| 845.40 | 
| 1 |  1 | ✅| 318.25 | 
| 2 |  5 |✅| 309.82 |

</details>

- **Cache-DiT is the dominant lever**: it cuts end-to-end time by **2.4x for T2I** (2140.7 s → 878.9 s) and **2.7x for I2I** (845.4 s → 318.3 s), with no change to request parameters.
- **Dynamic batching adds a modest further gain**: with `--batching-max-size 2` and concurrency 5, wall time improves by **~3.5% for T2I** (878.9 s → 848.7 s) and **~2.7% for I2I** (318.3 s → 309.8 s) over Cache-DiT alone.
