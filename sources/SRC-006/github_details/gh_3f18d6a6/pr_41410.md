# Fix DFLASH compact draft cache: `seq_lens_cpu` must include the verify block

## Summary

`--speculative-draft-window-size` (the DFLASH compact draft cache) builds the verify
attention args from a host-side `seq_lens_cpu` that is `block_size` **shorter** than the
device KV length. The windowed path is therefore not merely unhelpful, it is broken: draft
acceptance collapses to the floor.

One-line-per-branch fix: make the compact path's host bound cover the verify block, exactly
as the non-compact path already does.

## The invariant being violated

`python/sglang/srt/layers/attention/flashinfer_backend.py` states, in the sync-free
DFLASH-verify fast path:

> the batch carries `seq_lens_cpu` = prefix + draft_token_num (… `dflash_worker_v2` all add
> the verify window host-side), **which equals the device kv length**
> `generate_attn_arg_prefill` produces

The non-compact path upholds it:

```python
seq_lens_cpu.copy_(batch.seq_lens_cpu)
seq_lens_cpu.add_(block_size)          # <- the verify block
```

The compact path does not:

```python
self._fill_compact_seq_lens_cpu_bound(...)   # -> min(len, window + page_size)
draft_seq_lens = draft_prefix_lens
```

`_compute_compact_draft_seq_lens_host` computes

```python
bound = int(self.draft_window_size) + (self.page_size if self.page_size > 1 else 0)
```

and never adds `block_size`, while the device KV length for the draft is
`draft_prefix_lens + block_size`. Its docstring calls the result *"a safe upper bound"* — for
the device kv length it is an **under-estimate**, which is what makes this a correctness bug
rather than a conservative choice.

## Measurement

One L40S (driver 580, torch 2.13.0+cu130, SGLang 0.5.20), `Qwen/Qwen3-4B` +
`z-lab/Qwen3-4B-DFlash-b16`, 16 long LongBench prompts (16k–28k tokens), greedy,
`--speculative-num-draft-tokens 16`, `--max-new-tokens 64`, one request at a time.

Instrumented values for `L = 28110`, `W = 2048`:

```
[DBG] seq_lens_cpu (host planning value) = 2048
[DBG] TRUE device kv length = draft_prefix + block = 2064
[DBG] SHORTFALL = 16
```

Acceptance, before → after the fix:

| condition | median acceptance length | draft accept rate |
|---|---:|---:|
| no window (full) | 1.7564 | 0.063 |
| `W = 1024` | — → **2.3704** | — |
| `W = 2048` | **1.0323 → 2.5185** | **0.002 → ~0.055** |
| `W = 4096` | — → **2.3280** | — |

An accept rate of 0.002 means the drafter's proposals are essentially never correct — the
windowed path was producing the floor acceptance length (1.0 + the bonus token), not a
gradually degraded one. After the fix, windowing improves acceptance *over full context*
(−1.7564 → 2.5185 at `W = 2048`, matching the published behaviour of DFlash-style drafters
on long context), and `W = 2048` is the optimum among the windows tested.

Ruled out while diagnosing (all measured, not assumed):

* the compact page table — dumped and correct (the retained window is contiguous in the
  target's slot order and the block slots follow it);
* the draft KV for the retained window — valid (`|v| ≈ 47–49`);
* RoPE — the cached keys were rotated with absolute positions at write time and the block
  queries use absolute positions too, so the two are self-consistent;
* attention masking — DFLASH's draft attention is encoder-only, so there is none;
* the Triton compact-rebuild / prepare-block kernels — forcing the eager paths with a
  bisect switch gives the same result.

Only the host/device length mismatch remained, and adding the block removes it.

## Fix

```diff
         assert self.draft_window_size is not None
-        bound = int(self.draft_window_size) + (
-            self.page_size if self.page_size > 1 else 0
+        # The value filled here must equal the DEVICE kv length, which for the
+        # draft is the compact prefix PLUS the verify block. The non-compact
+        # path adds block_size for exactly this reason.
+        bound = (
+            int(self.draft_window_size)
+            + (self.page_size if self.page_size > 1 else 0)
+            + int(self.block_size)
         )
```

and the blocking fallback in the same helper:

```diff
         else:
-            # Last resort: the legacy blocking D2H copy.
+            # Last resort: the legacy blocking D2H copy. draft_prefix_lens is
+            # the compact prefix only, so the block is added here as well.
             out.copy_(draft_prefix_lens)
+            out.add_(int(self.block_size))
```

## Testing

* Verified against an installed SGLang 0.5.20 (the affected code is identical on `main`)
  with the measurement table above; the shortfall goes to 0 and acceptance length to 2.5185.
* `--speculative-draft-window-size` is left alone semantically: no change to the page-table
  rebuild, the sequence lengths passed as `draft_seq_lens`, or the query positions.

## Notes

The same shortfall exists for any consumer of `seq_lens_cpu` in the compact path, so the fix
is applied in the helper rather than at the call site.
