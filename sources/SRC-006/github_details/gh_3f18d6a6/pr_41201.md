## 正文

## Motivation

`validate_deepep_v2_dispatch_token_budget` compares the whole prefill-buffer ceiling (`--chunked-prefill-size` / `--max-prefill-tokens`) against `SGLANG_DEEPEP_V2_NUM_MAX_DISPATCH_TOKENS_PER_RANK`. A model package that scatters each prefill chunk over its attention-TP group before the MoE dispatch (sequence-parallel prefill under DP attention) sends only a fraction of that ceiling from any one rank, so the unsharded check rejects configurations that fit. For example, a 32768-token per-DP ceiling scattered over 8 attention-TP ranks dispatches 4096 tokens per rank.

The DeepEP v2 registry already lets an external model package declare its architecture and its MXFP8 precision policy. This extends that same entry point so the package can also declare how its prefill dispatch is sized, without SGLang core learning anything model-specific.

## Modifications

- `python/sglang/srt/configs/moe_model_registry.py`: the registry value becomes a frozen `msgspec.Struct` policy holding `silu_mul_keep_fp32` and an optional `prefill_dispatch_tokens` callback. `register_deepep_v2_model` accepts `prefill_dispatch_tokens(cfg, tokens)`, which receives the resolved read-only configuration and the prefill-buffer ceiling and returns the maximum tokens one rank dispatches. Re-registering an architecture with a different policy still raises. `model_deepep_v2_prefill_dispatch_tokens(hf_config, cfg, default_tokens)` applies the primary architecture's callback, or returns the ceiling unchanged when none is registered. The built-in architectures keep the default policy, so their behavior does not change.
- `python/sglang/srt/arg_groups/moe_hook.py`: `required_deepep_v2_prefill_tokens_per_rank` sizes the prefill budget through the registry, and the prefill branch of `validate_deepep_v2_dispatch_token_budget` uses it. Scheduler and buffer settings and the decode-graph budget check are unchanged.
- `test/registered/unit/layers/moe/test_hpc_ops_runner_guard.py`: the registration test now covers the callback applied on the primary architecture, the unchanged ceiling when the primary architecture is unregistered, and the conflict raised when an architecture is re-registered with the same precision flag but a different callback.

The policy container is a `msgspec.Struct` rather than a dataclass, following `.claude/rules/no-dataclasses.md`.
