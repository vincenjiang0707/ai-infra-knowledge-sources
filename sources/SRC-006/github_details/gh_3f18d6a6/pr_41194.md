## Motivation

This PR fixes three defects in NextN / MTP draft layers. Each commit fixes one.

1. **Layout plan.** `LayerScatterModes` treats `layer_id == 0` as the first layer (it takes the model's input layout) and `layer_id == num_layers - 1` as the last (it returns the model's output layout). Two draft layers were planned as middle layers instead:
   - the Bailing V2 / V2.5 NextN layers, passed as layer 0 of `num_hidden_layers`;
   - the Step-3.5 MTP layer, passed as layer 45 of 1.

   When the draft's MLP runs on SCATTERED tokens with attention TP > 1, the draft returned this rank's shard of tokens to the logits and to the next step. The SCATTERED triggers are an a2a backend, dwdp, FP4 cutlass allgather, or `moe_dense_tp_size` 1. The Step-3.5 MTP layer also planned an all-gather for an input that is already full. Separately, the Bailing V2.5 NextN plan treated the layer as dense whenever the model's first layers are dense, even though the layer builds an MoE. DeepSeek NextN and Bailing V3 already pass layer 0 of 1 (the same fix as #7420 for DeepSeek).
2. **Unloaded Bailing V2 NextN MLP.** `BailingMoEBlock` chose between the MoE and the dense MLP with `is_nextn=False`. So the NextN layer (layer 0) became a dense MLP whenever `first_k_dense_replace >= 1`, while the checkpoint's NextN layer holds expert weights (Ling-mini-2.0: `model.layers.20.mlp.experts.*`). `load_weights` skips names with no matching parameter, so the draft ran an MLP whose weights were never loaded (all zeros).
3. **Bailing V2 NextN could not start.** Every Bailing draft is renamed `BailingMoeForCausalLMNextN`, and `_derive_model_shapes` sent that name down the MLA branch added for V2.5. V2 is GQA and has no `kv_lora_rank`, so NextN speculative decoding on a V2 target failed at startup with `'BailingMoeV2Config' object has no attribute 'kv_lora_rank'`.

## Modifications

- **`models/bailing_moe.py`, `models/bailing_moe_linear.py`, `models/step3p5.py`:** draft layers pass `layer_id=0, num_layers=1` to `LayerScatterModes.init_new`. The Step-3.5 layer id still indexes its per-layer config. The Bailing V2.5 NextN plan is sparse.
- **`models/bailing_moe.py`:** the NextN layer builds `BailingMoESparseMoeBlock`.
- **`configs/model_config.py`:** the MLA branch takes `BailingMoeForCausalLMNextN` only when the draft config carries `kv_lora_rank`, which the V2.5 and V3 drafts do. A V2 draft now derives its shapes the way its target does. V3 drafts still take this branch rather than the V3 one, as before.
- **Tests:**
  - `test_last_layer_communicator.py` now records the `LayerScatterModes.init_new` arguments. It checks that every draft layer is planned as layer 0 of 1, that the V2.5 NextN plan is sparse, and that the V2 NextN layer builds the MoE block.
  - `test_model_config_shapes.py`: a GQA and an MLA Bailing draft each keep their attention architecture.

  All of these fail on main.

Configurations whose MLP does not run on SCATTERED tokens plan the same layouts before and after.

## Accuracy Tests

**GPU, H200, Ling-mini-base-2.0 TP2.** 4 greedy requests × 32 tokens; text, token logprobs and top-5 logprobs compared. NextN speculative decoding with 1 step, topk 1 and 2 draft tokens; also the default 3 / 1 / 4. Accept length = completion tokens / verify steps.

Runs before the third commit need a test-harness shim that only derives the draft's shapes. It is applied identically to every tree and is not needed after the third commit.

| Tree | Config | Result | Accept length |
|---|---|---|---|
| main | speculative off | reference | – |
| main / first commit | speculative | identical to the reference | 1.600 / 1.600 |
| second commit | speculative | text identical to the reference | **1.939** |
| main / first / second | speculative, default 3 / 1 / 4 | text identical | 1.684 / 1.684 / **2.462** |
| main | speculative, `moe_dense_tp_size=1` | **crash** on the first draft forward: index out of bounds in `logits_processor._get_logits` | – |
| first / second commit | speculative, `moe_dense_tp_size=1` | identical to the target-only run with the same setting | 1.580 / 1.910 |
| third commit, no shim | the configurations above | starts; identical to each shimmed run | 1.939 / 2.462 / 1.910 |

- **Draft-layer audit:**
  - main under `moe_dense_tp_size=1`: `mlp=SCATTERED, layer_output_mode=SCATTERED`;
  - first commit: `layer_output_mode=TP_ATTN_FULL`;
  - second commit: the NextN layer is `BailingMoESparseMoeBlock`.
- **Weight checksums before and after `load_weights`:**
  - on main, the draft's dense `gate_up_proj` / `down_proj` stay all zeros;
  - after the second commit, only the `word_embeddings` / `lm_head` shared with the target are untouched.

**GPU, H200, Step-3.5-Flash BF16 TP8 MTP** (EAGLE 3 / 1 / 4):

- **Default configuration:** main and this PR are bit-identical (accept length 2.560).
- **With `moe_dense_tp_size=1`:** main crashes in the draft's CUDA graph capture (`size of tensor a (32) must match ... b (4)`: the MTP layer returned its shard), and this PR does not.
- **Caveat:** the Step-3.5 target and its MTP draft are not correct under that setting. `Step3p5MLP` always shards over TP and all-reduces, so on SCATTERED tokens it sums different ranks' tokens. Only the crash fix is verified here, not end-to-end output; the dense MLP under `moe_dense_tp_size=1` is left for a follow-up.

Rebased onto main `9dc4c5d891`: every commit's patch is unchanged, and the related unit tests pass on the new base. The GPU results above were measured on the previous base, `5bb850d536`.
