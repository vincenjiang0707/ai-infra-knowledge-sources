## 正文

## Motivation

Loading any LoRA crashes plain inference for two models on `main`. Each crash comes from a forward path that reads a field of a linear layer, while the LoRA wrapper (`*WithLoRA`) does not expose that field:

| Model | Crash | Introduced by |
|---|---|---|
| Qwen-Image | `'MergedColumnParallelLinearWithLoRA' object has no attribute 'output_partition_sizes'` | #36680 (packed `to_added_qkv` split path) |
| MiniMax-H3 | `'RowParallelLinearWithLoRA' object has no attribute 'quant_method'` | #37903 (`_accepts_mxfp8_input` gate) |

## Modifications

- `7e6906d7f7` Qwen-Image: the packed-weight split runs only for an unwrapped `MergedColumnParallelLinear`. A LoRA-wrapped projection runs its own forward, base plus delta. (+1 line)
- `f7547ecee4` MiniMax-H3: `_accepts_mxfp8_input` returns False for a non-`LinearBase` wrapper, so LoRA layers get bf16 input. (+3 lines)

## Accuracy Tests

No change without LoRA: both new conditions are true for unwrapped layers.

- Plain LoRA inference on `main` @ `24b6930076` (Qwen-Image 512px, 4 steps; MiniMax-H3 t2va 768p, tp2): the worker raises the errors above, and with the fix both return a `GenerationResult`.
