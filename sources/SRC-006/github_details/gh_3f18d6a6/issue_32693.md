# [Issue #32693] [Bug] HiCache NIXL clear() deletes ALL files under the base dir, including other models'/deployments' data on a shared mount

source: https://github.com/sgl-project/sglang/issues/32693
state: closed | updated: 2026-09-27T00:33:31Z
labels: inactive

## 正文

## Describe the bug

`NixlFileManager.clear()` recursively deletes **every file under every configured base directory**, with no scoping to the instance that issued the clear:

```python
# python/sglang/srt/mem_cache/storage/nixl/nixl_utils.py:236
def clear(self) -> None:
    """Clear all files below every configured base directory."""
    ...
    for base in self.base_dirs:
        for root, _dirs, files in os.walk(base):
            for file in files:
                os.remove(os.path.join(root, file))  # (with warning on OSError)
```

But per-instance scoping in this backend lives only in the **key suffix**, not the directory layout:

- Files are stored at `base_dir/<bucket>/<key>` (`nixl_utils.py:272-277`), where `<bucket>` is a hash-route of the key, not a per-model namespace.
- Isolation between models/TP configs is done by suffixing keys with `_{model_name}` or `_{model_name}_{tp_rank}_{tp_size}` (`hicache_nixl.py:108-113`).

So when the base directory is a **shared L3 mount** (the intended deployment for a NIXL-backed L3 tier, with multiple serving instances, multiple models and potentially multiple tenants pointing at the same filesystem), any single instance calling clear wipes the cached KV data of *every* instance sharing that mount, plus any unrelated files that happen to live under the base dir.

## Trigger path

This is reachable from the public admin API, not just internal code:

`/clear_hicache_storage` (`ClearHiCacheReqInput`) → `Scheduler.clear_hicache_storage_wrapped` (`scheduler.py:3720-3722`) → `HiRadixCache.clear_storage_backend` (`hiradix_cache.py:814-819`) → `HiCacheNixl.clear()` (`hicache_nixl.py:609-612`) → `NixlFileManager.clear()`.

One operator clearing the cache on one model's deployment silently destroys the warm L3 cache (or worse, non-cache files) for everything else on the mount. Since every TP rank runs the same clear, ranks also race each other on `os.remove` (benign, but the logged `Failed to remove file` warnings are a symptom of the missing scoping).

## Reproduce

CPU-only, no GPU transfer needed:

1. Start two SGLang instances with HiCache + NIXL storage (`posix` plugin), both with `--hicache-storage-backend nixl` and the same base dir (e.g. `/mnt/shared-l3`), serving different models (or same model, different `tp_size`).
2. Warm both caches (a few requests each); observe files for both key suffixes under `/mnt/shared-l3/*/`.
3. `POST /clear_hicache_storage` on instance A.
4. Instance B's files are gone too. `batch_exists` on B now misses; any file not created by SGLang under the base dir is also deleted.

## Expected behavior

`clear()` should only remove files belonging to the clearing instance, i.e. files whose names carry that instance's `config_suffix`, mirroring how the HF3FS backend scopes clears per rank/namespace (`storage_hf3fs.py:109`, `mini_3fs_metadata_server.py:415`).

## Proposed fix (happy to send a PR)

Pass the instance's scope down: `HiCacheNixl.clear()` → `self.file_manager.clear(suffix=self.config_suffix)`, and in `NixlFileManager.clear()` only delete files where `suffix in file` (keys are `{hash}{config_suffix}` or `{hash}{config_suffix}_{component}`, so a substring/`endswith`-with-component match on the filename is sufficient). Two details:

- When `model_name` is empty the suffix degenerates to `_` (`hicache_nixl.py:108-113`), which matches everything. That case is worth a warning log and/or refusing an unscoped clear.
- The OBJ backend (`file_manager is None`) already no-ops in `clear()`; unchanged.

If maintainers prefer stronger isolation, an alternative is to namespace the directory layout itself (`base_dir/<config_suffix>/<bucket>/<key>`), which also makes clears O(1) directory removals. This lines up with the tenant-aware L3 directory layout discussed on #26693 (proposed by @chivalryq and called desirable by @lluki). But that's a layout migration; the suffix filter is the minimal correctness fix that works with today's layout.

## Environment

Found by code inspection on main @ 5f33000; applies to any deployment using `--hicache-storage-backend nixl` with file-based plugins (POSIX/GDS/GDS_MT/HF3FS-via-NIXL) on a shared mount.
