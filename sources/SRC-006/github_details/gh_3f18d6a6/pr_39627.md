Centralized Python fallback applies to both default and explicit Rust selection for:

- Session-aware caching.
- C128 or other unsupported components.
- Custom component overrides.
- Non-Linux platforms.
- PyTorch versions outside 2.11–2.13, or unrecognized versions.
- Devices other than CPU or CUDA.
- Installations containing neither the Rust extension nor its sources.
- Source builds with a missing or unusable Rust toolchain.

Trusted bundled extensions need no compiler. Supported configurations continue to surface build, import and runtime errors. Rust exports return `PyResult`: ordinary Python errors pass through unchanged, and unexpected native panics become `RuntimeError` in the binding. The Python adapter holds the concrete binding directly. Panic handling stays outside the mutex scope, so a core interrupted by a panic remains poisoned and subsequent calls refuse to reuse it. Production, inspection, bigram, constructor and tensor-return paths are covered.

T-LRU supports integer and floating-point parameters with Python's operation order, rounding and exact integer/float comparisons, including NaN and infinity. Integer-only parameters retain the exact tail-budget path. Mixed integer estimates must fit i128; larger values raise `OverflowError` at construction, and checked native addition panics on overflow. Priority evaluation uses native scalar arithmetic without allocation or Python callbacks. T-LRU adds two counters per node (16 bytes on 64-bit platforms); its ancestor history walk runs only for T-LRU and costs O(path nodes).

One insertion-ordered `NodeSet` serves device leaves, host leaves and Full host duplicates. It preserves constant-time membership/removal, amortized constant-time insertion and exact-size iteration. Leaf eviction still ranks candidates in its policy heap; Full duplicate reclamation follows Python's insertion order.

Auxiliary eviction respects each component's own transfer/request locks. An unrelated Full load or expanded SWA backup must not pin independently restored auxiliary state. Actual transfer sources/destinations and Full leaf guards remain protected. Deferred Mamba and SWA eviction revalidate the victim after the controller's backup attempt, preserve device state on submission/acknowledgment exceptions, and retain progress when host allocation fails. The controller uses the existing transfer and ACK path; the optional finish hooks support native pause/resume without requiring inline backends to implement them.

Hybrid transfer plans cross the binding in Python's component order, removing native HashMap nondeterminism. The shared host allocator now follows main's pool-name ordering from #40512; paired host-pressure expectations follow that order. Main's unified-memory decode host pools (#39478) use the shared controller path and need no separate native port.

The real default-cache test exercises construction, insertion and matching without factory mocks. Shared inspections replace native-specific test skips. This update removes the internal-SWA Rust skip and five obsolete Full+SWA+Mamba HiCache skips, enabling the now-supported hybrid fixtures. Legitimate configuration-applicability guards remain. Session cases in a Rust-selected run exercise centralized Python fallback. External backends must implement the two abstract SWA repair methods; the README documents this and the optional deferred-eviction hooks.
