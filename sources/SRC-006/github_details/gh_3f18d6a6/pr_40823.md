# [PR #40823] [Tool Call] Forward unknown tools to clients by default

state: open | updated: 2026-09-27T01:00:55Z

## 正文

## Summary
- Flip the default of `SGLANG_FORWARD_UNKNOWN_TOOLS` from `false` to `true` so that tool calls with names not in the declared list are forwarded to the client (with `tool_index=-1`) instead of being silently dropped.
- This matches the behavior of hosted APIs and is essential for agent loops: the client validates tool names and returns an error to the model, which can then recover with the correct name.
- The previous drop behavior was invisible on the wire and indistinguishable from "the model decided to stop", causing agent runs to terminate early when the model made a minor naming mistake.

## Changes
- `python/sglang/srt/environ.py`: Changed default of `SGLANG_FORWARD_UNKNOWN_TOOLS` from `False` to `True`.
- `docs/docs/references/environment_variables.mdx`: Updated documentation to reflect the new default and explain the behavior.
- `test/registered/unit/function_call/test_unknown_tool_name.py`: Renamed test to clarify it tests the opt-out behavior; added new test verifying the new default (forward) behavior.
- `test/registered/unit/function_call/test_function_call_parser.py`: Updated test to explicitly set `SGLANG_FORWARD_UNKNOWN_TOOLS=False` to maintain the original test intent (testing the drop behavior).

## Test plan
- [x] `test_unknown_tool_name.py`: All 3 tests pass (dropped when disabled, forwarded when enabled, forwarded by default).
- [x] `test_function_call_parser.py::TestLfm2Detector::test_detect_and_parse_unknown_function`: Passes with explicit env override.
- [x] `test_k2_v3_detector.py::test_unknown_tool_respects_forwarding_policy`: Passes (already uses explicit overrides).
- [x] `test_spark25_detector.py::test_malformed_block_is_text_and_unknown_tool_honors_policy`: Passes (already uses explicit overrides).

## Backward compatibility
Deployments that want the old drop behavior can set `SGLANG_FORWARD_UNKNOWN_TOOLS=false`.

### Pranjulcr7 · 2026-09-27 · COMMENTED

Changing the default does not yet fix forwarding for parsers using `BaseFormatDetector.parse_streaming_increment`.

At `0b48c44`, with `SGLANG_FORWARD_UNKNOWN_TOOLS=True`, a declared `get_weather` tool, and:

```text
<tool_call>
{"name":"Read","arguments":{"path":"x"}}
</tool_call>
```

`Qwen25Detector.detect_and_parse` forwards `Read`. Feeding the same text character by character through `parse_streaming_increment` emits no tool name. The base streaming implementation still unconditionally resets on an unknown name and later only emits names in `_tool_indices`.

Could this be paired with #23453, or could the description/docs explicitly limit the current guarantee? Please add a regression using a real streaming detector: `DummyDetector.detect_and_parse` only checks the non-streaming path. Also clear the environment variable in the default-value test so an inherited explicit setting does not change the test's meaning.
