# [PR #41237] Fix streaming text loss after detokenizer state eviction

source: https://github.com/sgl-project/sglang/pull/41237
state: open | updated: 2026-09-25T09:11:23Z
labels: 

## 正文

fixes #41236

the scheduler sent `read_offsets` as an absolute offset into the request's cumulative surrogate+decode id list (a constant 5, `INIT_INCREMENTAL_DETOKENIZATION_OFFSET`, from the first chunk on), while `decode_ids` is sliced to only the ids since the last send. when the detokenizer re-initialized a request's `DecodeStatus` after an eviction (`detokenizer_manager.py:311`, the `SGLANG_DETOKENIZER_MAX_STATES` / #2812 scenario), it consumed `read_offsets` as the committed-prefix count inside the chunk, so the constant pointed past ids that were not in the chunk. the text of up to 5 newly generated tokens was silently dropped from the stream, and lost entirely when the request finished inside that window.

fix: send the committed-prefix count chunk-relative, `max(0, read_offset - send_decode_id_offset)` at `output_streamer.py`, computed before the offset advances. first chunk value unchanged (the 5 prompt-tail tokens are inside the chunk), later chunks send 0, detokenizer unchanged.

test evidence (`test_detokenizer_eviction_read_offsets.py`, real accumulator + real detokenizer, injected eviction):

```
main:  test_streamer_sends_chunk_relative_read_offsets  FAILED (second chunk sends [5], expected [0])
main:  test_evicted_stream_reinit_keeps_all_text        FAILED (assembled deltas 'A' != 'ABCD')
this change:                                             2 passed
```

macOS, `PYTHONPATH=python`, no GPU needed.

also flagged in the issue, deliberately not part of this pr: `req.decoded_text` (`schedule_batch.py:1137`) is never written, so the stop-string fallback at `schedule_batch.py:1821` never fires. happy to split that into a separate discussion if maintainers want.
