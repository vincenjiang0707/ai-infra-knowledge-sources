## 正文

> This PR was "stack 1/4" of the DeepSeek-V4.1 AMD series (#41018 to #41021). It now follows the CUDA dsv4.1 layout (#39646, #39652, #39653, #39656, #39664, then #38798): kernel PRs by domain, each on `main` with no callers, then one integration PR. This is the first kernel PR.

## Summary
- Native MXFP8 dense route for 32x32-block ue8m0 fp8 checkpoints on gfx950 (`ops/quantization/mxfp8_native_amd_gfx95.py`, `csrc/deepseek_v4/mxfp8_gemv_gfx95.cuh`): the weight is reordered once at load into the scaled-MFMA lane order and stays fp8, with K zero-padded to a multiple of 128 and the activation tail masked. M <= 32 runs a HIP GEMV on `v_mfma_scale_f32_16x16x128_f8f6f4`, larger M a Triton `tl.dot_scaled` GEMM. The input is bf16, bf16 on the fp8 grid, or fp8 + ue8m0 scales, and all three give the same bits.
- Tile tables (`mxfp8_gemv_gfx95_configs.json`) tuned at DeepSeek-V4.1-Flash's TP4 shapes, fastest config per M bucket; `benchmark/kernels/quantization/tuning_mxfp8_native_gfx95.py` regenerates a shape's rows.
- fp8-grid helpers in `mxfp8_amd_gfx95.py`: `fake_quant_fp8_activation` / `fp8_grid_quantize` with the ue8m0 rule of CUDA's `per_token_group_quant`, the bf16-dequant linear for shapes the native kernels cannot tile, and the `Fp8GridActivation` / `Mxfp8Activation` wrappers that let a consumer skip its own quant.
- Fused producers of those wrappers: RMSNorm (+ residual) + quant (`rmsnorm_fake_quant_amd_gfx95.py`), clamped SiLU-mul + quant (`silu_and_mul_clamp_hip.py`), and the wo_a batched GEMM with the quant in its epilogue (`gfx95_batched_gemm_bf16_fp8_grid.py`, fixed-order split-K up to 64 rows).
- Model call sites are in the integration PR of this stack.

## Changes to existing kernels
- `mxfp8_amd_gfx95.py`: new code appended; existing functions and callers unchanged. Every other file is new and HIP-only, and the `.cuh` refuses to build for any target but gfx950.

## Verification
- MI350X (ROCm 10.0.0, torch 2.11, triton 3.8, aiter at the Dockerfile pin): `test_mxfp8_amd_gfx95.py` and `test_fp8_grid_producers_gfx95.py` pass (fp64 references, bitwise agreement of the three input encodings including non-finite activations, bitwise match to aiter `batched_gemm_bf16`), and so does the existing `test_minimax_m3_mxfp8.py`.
- With the integration PR's callers, DeepSeek-V4.1-Flash at TP4 loads every dense block-FP8 linear on the native route. Tuned tiles are up to 2.2x faster than the defaults; the native K tail takes 0.63-0.93x the time of the bf16-dequant route at (5120, 576) up to M 4096.
- Not executed on this branch alone: end-to-end serving and accuracy.
