## 正文

## Motivation

Pipeline parallelism and speculative decoding are still gated off against each other, but the pieces to lift the gate have been landing and are now in flight from several authors with overlapping scope. This issue tracks the work so the remaining PRs can converge on one design instead of a per-model allowlist.

Concrete use case: PD-disaggregated serving of large hybrid MoE models (Qwen3.5 / Qwen3.8 / DeepSeek / GLM) where the prefill role runs PP (e.g. PP4 for the InferenceMAX AgentX recipe) and the decode role uses MTP. Today the prefill role only starts with `PYTHONOPTIMIZE=1` to skip the assertion, or with one of the model-specific gate PRs below.

## What is already model-agnostic (merged)

Since #35758 the prefill-side runtime does not depend on the model:

- The draft worker is created only on the last PP stage (`EAGLEWorkerV2._hosts_draft`); other stages return proxy tensors so scheduler dispatch stays rank-uniform.
- `scheduler_pp_mixin` carries the draft output (`draft_topk_p`, `draft_topk_index`, `draft_hidden_states`) along the PP ring and rebinds it as `batch.spec_info` on stage 0 so the PD result contains it.

## What is still model-specific today

**1. Last-stage draft embedding (the only hard dependency).** `EagleDraftWorker.init_lm_head` calls `target.get_embed_and_head()`. On the last stage `embed_tokens` is a `PPMissingLayer` for most targets (`deepseek_v2`, `llama`, `glm4_moe`, ...), so `.weight` raises. Two different fixes exist:

- Qwen3.5 (#37471, merged): the draft keeps its own embedding and `qwen3_5_mtp.load_weights` loads it from the target checkpoint; the target returns `embed=None` on non-first stages.
- DeepSeek / GLM (#39378, open): the target materializes `embed_tokens` on the last stage (`pp_stage_needs_embedding`) and the draft borrows it.

Every new model currently has to pick one and re-implement it in its own model file. The allowlists in #39378 / #39602 / #38698 exist only to express "this model did that work".

**2. Extra `spec_info` fields on the ring.** The ring serializes three hard-coded tensors. DSA models need `draft_dsa_topk_indices` (added by hand in #39378); the next model with extra draft state will need another hand-written field.

**3. EAGLE3 / DFLASH aux-hidden capture is silently disabled under PP.** `set_eagle3_layers_to_capture` / `set_dflash_layers_to_capture` return early on non-last ranks, so capture layers that live on earlier stages are never captured. Affects Llama / gpt-oss / Kimi-K2.5 EAGLE3 drafts. This is a correctness gap, not a gate.

**4. Targets without PP at all.** `qwen3_next.py`, `longcat_flash.py`, `hunyuan_v4.py` have no PP support in the target; PP+MTP is moot there until PP lands.

**5. PD KV transfer under PP** for non-standard pools is being fixed per pool: MLA layer offsets in nixl (#39378), hybrid mamba pools (#33584), QSA / PLE pools (#38698). PP is only permitted on the disagg prefill role, so these block the actual use case.

## Proposed plan

**P0 — make the prefill path generic and drop the allowlist**
- [ ] Land one gate PR (#39378 with the Qwen3_5 names folded in; close #39602).
- [ ] Shared last-stage draft-embedding path (#39643): when `pp_size > 1` and the target does not own the embedding, the draft loads it from the target checkpoint through a common helper. Then the validation check becomes "draft has an embedding source" and `_PP_EAGLE_SUPPORTED_ARCHITECTURES` can be removed. Whichever of #39643 / #30775 lands second drops its copy of the embedding read.
- [ ] Serialize all non-None tensor fields of `EagleDraftInput` on the PP ring instead of three hard-coded names.
- [ ] Acceptance: GSM8K equal to `pp_size=1` for Qwen3.5 / DeepSeek-V3.2 / Qwen3.8 PP4 prefill; the AgentX PP4 recipe no longer needs `PYTHONOPTIMIZE=1`.

**P1 — decode side**
- [ ] PP x spec under the overlap scheduler. #30775 forces `--disable-overlap-schedule`; per its own measurements TP8+MTP is now faster than PP at bs1 because the overlap path is where recent gains landed, so this decides whether PP decode has value where TP fits.
- [ ] Fold `SGLANG_ENABLE_PP_SPEC` (#30775, non-disagg decode) and #39378's PD-prefill gate into one PP x spec check in `validation_hook` instead of two parallel branches with different constraints.
- [ ] Add a PP x spec entry to #11857.

**P2 — multi-layer drafts**
- [ ] Until a draft family supports it, fail loudly instead of returning early when aux hidden-state capture is requested under PP (#39644).
- [ ] EAGLE3 / DFLASH: ship aux hidden states across stages so capture layers on earlier stages work.
- [ ] DSpark under PP: #38702.

**Out of scope here:** adding PP to targets that lack it (item 4).
