## 正文

## Motivation

Serve the official GLM-5.3-Flash FP8 checkpoint and [`OneNexus/GLM-5.3-Flash-MXFP4`](https://huggingface.co/OneNexus/GLM-5.3-Flash-MXFP4) on MI355X (gfx950) at full speed and correct output. The target stack is zero-RoPE sparse attention, FP8 KV cache, and graph-enabled EAGLE 5/1/6.

`main` now includes all ten Day-0 enablement PRs (#38545, #38546, #38547, #39317, #39338, #39339, #39340, #39341, #39778, #39779). This PR adds the remaining correctness fixes and optimizations for serving Flash on gfx950. On the same four MI355X GPUs and AgentX replay, it measures **+14.3%** geomean output throughput over `main` at c1–c32, with higher P90 interactivity at every rung. At c48, `main` falls off the frontier, while this PR holds it.

The four CI and test-hygiene fixes that used to be here now live in #40721.

## Serving performance

Setup: four MI355X VFs, TP4/EP4, FP8 E4M3 KV, EAGLE 5/1/6, 393-entry AgentX corpus, 900 s per rung, image `lmsysorg/sglang-rocm:v0.5.20-rocm724-mi35x-20260918`. The client and server are pinned to the same NUMA placement, and `main` and this PR ran back to back on the same GPUs.

## Measured operator optimizations

**KDA fused verify.** At batch 8 with eight verification tokens, the reference graph launches convolution and recurrence separately (**38.9 μs**). The single fused kernel with BV4 tiles is slower (**41.7 μs**), because it repeats the Q/K convolution across 32 value tiles. BV16 cuts the grid to 8 tiles and the paired time to **28.4 μs**, **27.0% less operator time**. For the six-token EAGLE 5/1/6 shape: **31.50 → 23.02 μs** at batch 8 and **37.66 → 33.03 μs** at batch 16. On this PR's head, the tuning still measures about 26% faster at batch 8 on top of #39524, with bit-exact output.

![KDA before/after GPU traces and paired graph timings: reference, initial fusion, and tuned fusion](https://huggingface.co/OneNexus/GLM-5.3-Flash-MXFP4/resolve/main/assets/kda-trace-optimization.png)

This is an isolated MI350X VF (gfx950) study with synthetic GLM TP4-shaped tensors, not model throughput. See the [study and full data](https://huggingface.co/OneNexus/GLM-5.3-Flash-MXFP4/blob/main/reproduction/kda-trace-study.md).

**Vision merge.** The 2×2 downsample has a non-overlapping kernel and stride, no padding and one group, so each patch is a linear projection. Reusing `Conv2dLayer`'s unfold + linear path skips the MIOpen search. On the model's actual `[256, 1024, 2, 2]` merge layout, first-call time falls **4.50 → 3.31 s (−26.5%)** and warmed graph time **63.28 → 25.62 μs (−59.5%)**, with identical output. See the [operator study](https://huggingface.co/OneNexus/GLM-5.3-Flash-MXFP4/blob/main/reproduction/mhc-vision-operator-study.md).

The AITER mHC dispatch and its caller-applied RMSNorm fix, measured in the same study, landed in `main` via #38545.

## Accuracy

On the serving configuration above (sgl-eval 0.1.2, 500 examples, reasoning effort max, temperature 0): GSM8K **0.978**, MMLU **0.870**.

Checkpoint quality against `amd/GLM-5.3-Flash-Quark-MXFP4`, on identical pinned samples with one frozen runtime, graphs and speculation off, BF16 KV, greedy decoding, and truncations kept in the denominator:

| Checkpoint | GSM8K | MMLU | GPQA Diamond |
| --- | ---: | ---: | ---: |
| `OneNexus/GLM-5.3-Flash-MXFP4` | 490/500 | **428/500** | **139/198** |
| `amd/GLM-5.3-Flash-Quark-MXFP4` | 491/500 | 423/500 | 132/198 |

The MMLU (+1.0 point) and GPQA Diamond (+3.5 points) differences do not reach `p < 0.05`; see the [quality protocol and paired statistics](https://huggingface.co/OneNexus/GLM-5.3-Flash-MXFP4#text-reasoning-quality).
