# [PR #40768] [ROCm] Fuse GLM-5.2 indexer preparation on gfx950

## 正文

## Summary

- add gfx950 full indexer-prepare kernels for compatible GLM-5.2 DSA decode shapes from M=1 through M=128, including C10 M=10/M=40 graphs
- fuse indexer projections, LayerNorm, RoPE, FP8 quantization, head-gate scaling, and paged index-K cache writes
- use the same no-Hadamard cache representation as current main's AITER fused writer, so per-call fallback cannot mix cache formats within one request
- support 16/32 indexer heads, 1024/2048 query LoRA ranks, BF16/FP32 LayerNorm parameters, and non-default LayerNorm epsilon
- use an async shared-memory projection schedule for validated 32-head M=64/96/128 graphs; route the remaining admitted cases through the generic schedule
- require the current-main fused writer to be available before enabling this path; unsupported modes, layouts, shapes, or runtimes remain on that compatible fallback

## Validation

- rebased onto current main (`a1eb691ab`); PR is mergeable
- combined CPU and MI355X run: 11 tests passed, 36 subtests passed
- correctness and CUDA graph replay cover M=1/2/4/8/10/16/32/40/64/96/128
- generalized coverage includes every admitted 16/32-head and 1024/2048-rank combination at M=10 and M=64
- FP32 and BF16 LayerNorm parameters, non-default epsilon, cross-page cache writes, and negative/padded cache slots are covered
- the existing AITER fused-writer parity tests run alongside the full-prepare tests to validate the shared no-Hadamard cache representation
- performance tests require at least a 10% gain for every decode shape and generalized case; M=64/96/128 also require at least a 20% gain from the large-M schedule
- Ruff, formatting, import ordering, registered-test validation, and diff checks pass

## Direct comparison with #38583

The following is a same-host comparison against #38583 commit `ca91c497e`. Both arms used TP8/EP1, 100k input tokens, 100 output tokens, MTP 5/6, no HiCache, `max-running-requests=8`, and `cuda-graph-max-bs-decode=8`. Values are the mean of two hot runs after a full warmup run.

| Concurrency | #38583 P50 ITV (ms) | this PR P50 ITV (ms) | change | #38583 P90 ITV (ms) | this PR P90 ITV (ms) | change | throughput change |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 1 | 3.394 | 3.200 | -5.71% | 4.523 | 4.335 | -4.15% | +4.59% |
| 8 | 5.281 | 4.909 | -7.03% | 7.019 | 6.548 | -6.71% | +6.03% |

#38583 replaces the complete decode chain and has a faster prepare stage for M=1-16. This PR crosses over at M=32: its prepare kernel is 29% faster at M=32, 40% faster at M=40, and 48% faster at M=48, then continues through M=128. It also supports more head/rank combinations.

As currently written, #38583 stores Hadamard-rotated keys and only handles rows up to 48, while current main's fallback writer stores no-Hadamard keys. Mixing those paths at larger graph rows can therefore mix cache representations within a request. This PR follows current main's representation and only enables when the compatible fallback is active.
