## 正文

## Motivation

MiniMax-H3 DiT attention uses a **packed varlen** path (`[text | cond | audio | video]`, `cu_seqlens=[0, used, total]`). The existing `sla_attn` backend only implements dense `forward()`, not `forward_varlen()`, so H3 admission (`validate_server_args` requires `packed_varlen=True`) rejects `sla_attn` today.

The official[ LightX2V Turbo-SLA](https://huggingface.co/lightx2v/Minimax-h3-Turbo-SLA) stack has two layers that should not be conflated:

| Component | Role |
|---|---|
| **SLA LoRA** | Standard QKV/FFN LoRA merged into `W`; drives few-step generation quality |
| **`sla_attn` kernel** | Runtime block-sparse attention acceleration; no sparse weights in the checkpoint |

Goal: let H3 opt into `sla_attn` for DiT acceleration **without breaking existing `sla_attn` users such as TurboWan**, and correctly handle the fact that text/cond/audio prefixes in the packed sequence must not be dropped by top-k sparsification.

---

## Changes

**1. Backend — `sparse_linear_attn.py`**

- `forward_varlen()` + `_packed_sla_forward()` for H3 `[T,H,D]` packed layout
- `protect_upto` pins prefix K blocks; `_localize_protect_upto` maps global bounds per segment
- `_resolve_sla_impl_config()`: config overrides only unset/default ctor fields
- `linear_mix=false` skips `proj_l` (H3 path); shared defaults stay 128×64, `topk=0.1`

 H3 config: `topk_ratio=0.15,blkq=64,blkk=64,linear_mix=false`

**2. Kernel — `sparse_linear_attn_triton.py`**

- `get_block_map(..., protect_upto=0)` pins prefix blocks
- `topk = max(1, ...)`; GQA `repeat_interleave` fix

**3.H3 wiring — `minimax_h3.py`**

- `protect_upto` from `audio_pos.max()+1`, passed only for `SLA_ATTN`
- Ulysses keeps global token coordinates (A2A before attention)

---

## Impact on other models

- **Default `sla_attn` (e.g. TurboWan):** unchanged — same 128×64, `topk=0.1`, `proj_l`
- **Other backends (FA / Sage / SDPA):** no change
- **H3:** enabled via `forward_varlen` + admission probe; no pipeline whitelist

## Notes

- **Few-step quality comes from LoRA merge, not the SLA kernel**; the SLA kernel is mainly an attention speedup (and may be slower on very short schedules)
- H3 must use the **official HF 13-shard DiT**; a Comfy single-file overlay on this CLI path produces gray mud (unrelated to SLA)
- `--steps 6` means 5 denoise updates (sigmas include endpoint 0)
- Plain top-k without `protect_upto` drops most of the audio prefix blocks; always enable prefix pinning for H3 packed layout
