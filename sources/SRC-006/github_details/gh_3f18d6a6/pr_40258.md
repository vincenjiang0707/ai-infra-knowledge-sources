## 正文

## Motivation

Rust's native `POST /generate` omits five scheduler statistics returned by Python: `cached_tokens`, `cached_tokens_details`, `reasoning_tokens`, `num_retractions`, and `dp_rank`. It also ignores `require_reasoning=true`, so the scheduler does not enable the requested reasoning accounting.

Return Python-compatible field presence and scheduler values for JSON and cumulative/incremental SSE, including zero counts, null values and nondefault statistics. Forward the reasoning flag into the existing scheduler accounting and grammar path.

## Modifications

- Collect the existing scheduler statistics for both frontends and transmit typed snapshots through the Python/Rust MessagePack header. Preserve old headers and reject incomplete or malformed columns.
- Retain the latest snapshot in the existing accumulator and expose it in both native formatters; do not add already-cumulative counters together.
- Forward the request-wide `require_reasoning` boolean at Python's existing wire position, after a null routing-key placeholder, for single and batch requests.

Weight-version metadata is reviewed separately in [the stacked Draft PR in my fork](https://github.com/lagoon0o0/sglang/pull/1). This PR retains five signed commits, ending at `083742d530`; no weight-version implementation remains in its diff.

## Accuracy Tests

The split restores the exact file tree of `0308e2afb5` (re-signed as `083742d530`). Its only change from the reasoning implementation at `18dbd0545a` (signed `5557244eb9`) is a source comment. No new code was introduced by splitting, and hardware experiments were not rerun for the split.

- **Existing A-only acceptance:** MLX and single-L4 CUDA each exercised 96 reasoning-flag requests / 136 comparisons at `18dbd0545a`, covering omitted/false/true, single/batch, JSON and cumulative/incremental SSE, repeatability, and generated text/token IDs. All focused comparisons passed.
- **CPU coverage retained:** statistics collection and MessagePack validation, legacy/idle/malformed batches, snapshot replacement, both formatter paths, and HTTP-to-wire reasoning-flag propagation. Existing scheduler grammar tests exercise the shared reasoning path.
- **Separate A+B evidence:** the later `ebf182bbd2` run included the now-separated weight-version change. All five statistics matched in 72 MLX result pairs. On CUDA, all five fields were present; forced-retraction counts differed in four paired attempts, with two unstable Rust checks and a JSON/SSE retraction-count mismatch. These are joint-run observations, not a claim of a fresh A-only run or complete parity success.

Pinned models: `mlx-community/Qwen3-0.6B-4bit@73e3e38d981303bc594367cd910ea6eb48349da8` and `Qwen/Qwen3-0.6B@c1899de289a04d12100db370d81485cdf75e47ca`. The A+B parity harness was `ef1b419696`; original reports retain their original source SHAs.

Limits: two-GPU DP and hardware grammar/strict-thinking scenarios remain unverified. Retraction-count stability, response timestamps, weight versions and separate logprob metadata alignment are outside this PR's completion claim. Validation numbers for the combined A+B CPU suite are documented with the weight-version PR, rather than attributed to this narrower tree.

## Speed Tests and Profiling

Existing A statistics benchmarks at `466d91e1b3` (re-signed as `54acee1cb6`) measured batch 1/128/4096 bridge encoding at 0.80/8.44/220.08 to 1.59/13.56/352.64 microseconds, five added decode allocations per batch, and `ChunkEvent` growth from 144 to 200 bytes. These are historical microbenchmarks, not model-throughput measurements. The separate weight-version overhead is not included here.
