# [PR #41144] [Unified Memory] Fix Inkling conv-checkpoint track ids written to virtual slot numbers

## 正文

## Motivation

With `--enable-unified-memory`, Inkling (FULL + SWA + short-conv Mamba state) writes every prefix-cache conv checkpoint to the wrong slot, so later prefix hits restore stale or foreign conv state. HiCache is not involved: the bug reproduces with HiCache off. HiCache L2/L3 faithfully round-trips checkpoints that were already wrong on device.

On the unified pool, `forward_batch.mamba_track_indices` holds virtual Mamba slot ids. `InklingShortConvAttnBackend._forward_metadata` overrides the base and translates only `mamba_cache_indices`. The base `MambaAttnBackendBase._forward_metadata` also translates `mamba_track_indices`, and GDN's graph path copies translated ids into a static buffer. Inkling's conv kernels (`fused_causal_conv1d_update_decode`, `fused_gather_scatter_to_sconv_cache`, and the fused-AR / attn-side paths in `inkling_common`) read `forward_batch.mamba_track_indices` directly as physical slot ids. So each checkpoint lands in the physical slot whose number equals the virtual id. The tree node's virtual id translates to a different, stale slot, and the write clobbers whatever lives at that physical slot.

Evidence (Inkling `--revision test`, 1x H200):
- The seed request's running conv state after 1152 tokens hashes the same on the static and unified pools. The static pool's 1152 checkpoint matches it. The unified pool's 1152 checkpoint does not, while its 1408 checkpoint holds the true 1152 state.
- A cold full recompute is bit-identical between the two pools, but prefix hits differ by 0.086 / 0.12 max |Δlogprob| (and flip the greedy first token).
- Not affected by `SGLANG_DISABLE_LAZY_COMPACTION=1` or `--disable-overlap-schedule`: this is deterministic, not a race.

## Modifications

- `InklingShortConvAttnBackend`: on a pool whose slot gather is not recordable (the unified pool), translate `mamba_track_indices` into a backend-owned, graph-static int64 buffer during slot prep, and point `forward_batch.mamba_track_indices` at it. Graph-static because the decode (and full prefill) CUDA graphs bind the track destination at capture; rebinding to a fresh tensor instead causes an illegal memory access on replay. A re-run of prep on the same batch (for example split-prefill reinit) is a no-op, so ids are never translated twice. The static pool path is unchanged.
- `test_unified_radix_cache_kl_hybrid_bitexact.py`: add `TestUnifiedMemoryHybridBitExact`, the existing bit-exact KL class on `--enable-unified-memory`. Record its reverted-fix numbers in the file's table and bump `est_time` by the measured class runtime.

Not in this PR: `commit_conv_state_after_mtp_verify` passes the scheduler's virtual `mamba_track_indices` to the verify scatter untranslated as well. GDN translates the same argument at `hybrid_linear_attn_backend.py:1439`. On the unified pool only DSPARK reaches this path, and it needs a 4-GPU Inkling-Small + DSpark run to verify, so it will follow separately.
