## 正文

## Motivation

`amd/Qwen3.5-397B-A17B-MXFP4-AttnFP8-V2` keeps the attention and GDN projections in FP8: per-channel weights with dynamic per-token activations. At decode sizes on MI355X TP4, each layer runs two quant + GEMM pairs through `gemm_a8w8_bpreshuffle`. In each pair, the GEMM reads its weights far below the bandwidth a plain streaming read reaches: 21 MB for the packed GDN `in_proj`, 19 MB for `qkv_proj`, 8 MB for `out_proj` / `o_proj`. At 4 tokens the old GEMMs take 10.0 / 9.7 / 5.4 us for these, versus 4.8 / 4.5 / 2.8 us for a streaming-read kernel of the same size. The output-side activation quant, after the GDN gated norm and the attention gate multiply, also runs as its own launch. This PR adds a small-M GEMM for these shapes and folds the output-side quant into the kernel that produces the activation.

## Modifications

- New `python/sglang/kernels/ops/gemm/smallm_fp8_gfx950/` (`__init__.py`, `smallm_fp8_gemm.hip`). It is built with `hipcc` on first use and launched through ctypes, reusing #40204's helpers. `_Kernel.launch` gains `block` / `shared` arguments whose defaults keep the MoE kernel unchanged.
- The GEMM reads the weight exactly as loaded: aiter's (16, 16)-preshuffled `[N, K]`, including #39902's packed QKVZ+BA buffer. There is no loader change and no extra weight copy.
  - Each wave issues all its 16 B non-temporal weight loads up front.
  - It uses `v_mfma_scale_f32_16x16x128_f8f6f4` with fp32 accumulation.
  - For small M on K = 4096, activations are staged once in LDS.
  - `x_scale * w_scale` is applied once per output, with a bf16 store.
- `apply_fp8_linear`: one guarded swap for `gemm_a8w8_bpreshuffle` on the aiter per-token path. It accepts an already-quantized `(fp8, x_scale [M, 1])` tuple through the existing pre-quantized branch, so it composes with #34502's input-side fusion. The input-side quant itself is unchanged here.
- Output-side quant fusion: `_layer_norm_fwd_1pass_kernel` (GDN `RMSNormGated`) and `_fused_sigmoid_mul_kernel` (attention gate) gain a `QUANT` constexpr that writes per-token FP8 plus scale, bit-identical to `_per_token_group_quant_8bit` on the unfused output. `qwen3_5.py` uses it for `out_proj` / `o_proj` when the consumer is a Quark W8A8 per-token linear and 1 <= M <= 40. The BF16 MTP layer is untouched.
- Guard: gfx950, ROCm >= 7.2, fp8 e4m3fn, bf16 output, and exact shapes with an M window per shape where the new GEMM is at least as fast as the old one:
  - packed `in_proj` (5184, 4096) and `qkv_proj` (4608, 4096): M <= 28;
  - `out_proj` / `o_proj` (4096, 2048): M <= 36.

  Everything else takes today's path.
- On by default on gfx950; `SGLANG_ROCM_SMALLM_FP8_PROJ=0` turns both parts off. A build or load failure disables it for the process.
- Registered AMD unit test `test/registered/amd/test_smallm_fp8_proj_gfx950.py`:
  - the GEMM against `gemm_a8w8_bpreshuffle` for the three TP4 shapes at M in {1, 4, 16, 24, 29, 36, 41}, with dispatch inside the guard and fallback outside;
  - tuple input == bf16 input;
  - the off switch;
  - the producer guard;
  - bit-exactness of the fused quant for both producers;
  - graph replay == eager.

  It passes on `v0.5.20-rocm720-mi35x-20260923`, together with the existing `test_qwen35_gdn_packed_fp8_in_proj.py` and `test_smallm_moe_gfx950.py`.

## Accuracy Tests

The math stays W8A8. Against `gemm_a8w8_bpreshuffle` on the real shapes, outputs are bit-identical in 20 of 21 (shape, M) cases, and the rest differ by at most 1 bf16 ulp. The fused quant is bit-identical.
