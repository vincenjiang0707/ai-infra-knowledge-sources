# [PR #41386] [AMD] Retry Mooncake etcd Go module fetch in rocm.Dockerfile

source: https://github.com/sgl-project/sglang/pull/41386
state: open | updated: 2026-09-27T02:51:49Z
labels: amd

## 正文

Mooncake's etcd wrapper build rule runs `go mod tidy` inside `make -j`. That fetches the go1.25.10 toolchain named in its go.mod plus about 38 modules from proxy.golang.org, with no retry. One transient HTTP/2 stream reset on a module zip fails the whole `--no-cache` image build, as in the nightly ROCm 10 publish-gfx1250 job
(actions/runs/36257652494).

Run the same `go mod tidy` in mooncake-common/etcd before cmake, retried up to 5 times. The in-make rule then finds everything in the module cache. `go mod download` is not enough: the untidy go.mod needs x/sys/x/text bumps plus test-only imports that only tidy resolves.
