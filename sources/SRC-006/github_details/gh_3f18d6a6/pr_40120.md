## 正文

## Motivation

Add Ascend deployment choices to the MiniMax-M2.5 cookbook: a smoke-tested A2 eight-device configuration and a separately labelled A3 reference. Related task: https://github.com/Ascend/sglang/issues/1215

HiDevLab supplied A2 multi-card resources; A3 multi-card resources are unavailable for this contribution. The tested scope therefore uses A2. This does not imply hardware or performance equivalence to the A3 reference, and acceptance of the adjusted scope remains subject to maintainer review.

## Changes

- Add an A2 selector for 8 x Ascend 910B4 / 32 GiB, TP8, W8A8 main weights, one request at a time, and no EAGLE3 draft model. Model/tokenizer directories are editable and shell-quoted.
- Keep the A3 8-card / 16-die W8A8 + EAGLE3 recipe explicitly unvalidated, with separate prerequisites and reference evaluation instructions.
- Record reproducible launch settings, observed software versions, successful requests, failed long-input probes, and interpretation limits.
- Add 13 command-generator regression tests, including NVIDIA/AMD behavior and platform transitions.

## A2 hardware validation

September 22: main weights loaded, warm-up completed, eight-rank HCCL/BF16 checks passed, and three chat answers (Paris, Chinese addition, and valid JSON) stopped naturally with a 512-token output budget. Final health returned HTTP 200.

September 23: a bounded serial follow-up completed two warmups and six simple answer checks. Five passed; the JSON request exhausted its smaller 128-token output budget and was inconclusive. Three native probes with 64/128/256 exact input tokens each generated the requested 128 tokens. Their end-to-end times were 37.265/32.139/32.780 seconds, and first observed output times were 8.102/3.277/3.548 seconds. These are single observations, not standardized throughput or latency percentiles.

**Observed capacity limit:** despite configured context 4096, startup allocated only 896 KV tokens. Requests with 1024 and 2048 input tokens were rejected with BadRequestError reporting a maximum input length of 890. The client stopped after two consecutive failures, so the planned 3500-token case was not attempted. Post-test health remained HTTP 200. The guide and generated command disclose this restriction.

Runtime: SGLang 0.5.14.dev172+gf308abc05, Torch 2.10.0+cpu, TorchNPU 2.10.0, Transformers 5.8.1, kernel 2026.5.1; follow-up inspection recorded CANN 9.0.0 and driver 25.5.2. The supplied source tree had packaging-file modifications. Image digest and immutable model revision were not captured. Raw request streams, launch settings, runtime logs, and shutdown evidence were archived locally; all eight NPU processes exited and the instance was shut down.

## Accuracy and performance scope

No GPQA score is claimed. The short exact-answer checks do not establish general model accuracy. Standardized throughput, sustained stability, tool calling, and A3 hardware validation remain untested. The documented A3 50 ms TPOT and GPQA baseline are upstream references, not results of this PR. This remains a draft while the observed A2 capacity restriction and adjusted task scope are reviewed.
