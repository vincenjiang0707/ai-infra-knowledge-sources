# [PR #40979] [Fix] Allocate SWA KV pools inside the memory-saver region

source: https://github.com/sgl-project/sglang/pull/40979
state: open | updated: 2026-09-25T06:44:53Z
labels: memory-pool

## 正文

## Summary
`release_memory_occupation` now frees the KV cache of MHA, MLA and DSA sliding-window models.

## Symptom & Reproduction
- **Symptom:** with `--enable-memory-saver`, releasing `kv_cache` leaves the KV cache of SWA models resident, and every DSA model keeps its index-K buffers.
- **Engine measurement:** an H200 TP2 engine of a hybrid SWA model used 85.3 GiB after load, 32.9 GiB after releasing everything, and 85.3 GiB after resuming only the weights, so only the weights were pausable.
- **Reproduction:** build a pool through its `KVCacheConfigurator` builder with the flag on, pause the torch_memory_saver `kv_cache` tag, and read `torch.cuda.mem_get_info`; expected: the pool's bytes are freed; observed on the merge base: 0 GiB freed for all three SWA pool kinds.

## Root Cause
1. `pause(GPU_MEMORY_TYPE_KV_CACHE)` unmaps only buffers allocated inside a memory-saver region.
2. `_build_hybrid_swa_kv_pool` never passes the flag, so `SWAKVPool` gives both sub-pools `False`.
3. `_build_hybrid_mla_swa_kv_pool` hard-codes `False` in the explicit sub-pool kwargs it hands `SWAKVPool`.
4. `IndexKeyCache.__init__` allocates index-K outside `memory_saver_adapter.region`, in every DSA pool.

## Fix
Each pool builder now passes `get_exec().features.enable_memory_saver`, as every other pool builder already does. The MHA builder uses a new `SWAKVPool` argument that is forwarded to both sub-pools and defaults to `False`. The hybrid MLA/DSA builder sets the flag in its explicit `common` kwargs, because explicit sub-pool kwargs bypass that argument. `IndexKeyCache` allocates index-K inside the `GPU_MEMORY_TYPE_KV_CACHE` region, like the MLA buffers of the same pool. With the flag off the adapter is a no-op, so allocation is unchanged. Unchanged: the NPU SWA path, `LayerSplitIndexKeyCache.remote_buffer` and the DSA compress-tail buffers.

## Verification
- `pre-commit run --files` on the three changed files at this head: passed.
- Pause/resume on one H200 with torch_memory_saver 0.0.9.post1: pools built through the real builders (48 layers, 12 full and 36 SWA), freed GiB per tree:

| tree | MHA SWA (21.0) | hybrid MLA (5.9) | hybrid DSA (6.3, index-K 0.39) |
|---|---|---|---|
| merge base `6fe4b66f5c` | 0 | 0 | 0 |
| `f9b27e254a` | 21.2 | 0 | 0 |
| builder change only | 21.2 | 6.0 | 6.0 |
| this head `29bc585196` | 21.2 | 6.0 | 6.4 |

- After resume every paused buffer kept its `data_ptr`, read back zero, and accepted writes.
- Not run: a full engine with a hybrid MLA/DSA model, or the NPU path.

## Review Focus
- `index_key_cache.py`: index-K now joins the `kv_cache` tag for every DSA model; resume zero-fills it, and `flush_cache()` runs right after the pause, so stale index-K is never read.
- `_build_hybrid_mla_swa_kv_pool`: its explicit sub-pool kwargs bypass the `SWAKVPool` argument, so the flag must stay in `common`.
