## Motivation

- **Decided twice.** `FfnExit` asked three decisions before the FFN ran. Then `finish()` chose again how the next layer completes the output (`_scatter_for_next_layer`, `_reduce_scatter_for_next_layer`), reading the postprocess function's identity and comparing step objects.
- **Group guessed by the consumer.** The next layer completed a deferred sum with `deferred_post_experts_all_reduce`, which picks the MoE output's group, even for a dense layer.

## Modifications

- **`LayerCommunicator._select_ffn_completion`:** decides once, before the FFN runs, what the FFN skips (the published flags) and what completes its output: the next layer's input, or this layer's postprocess. `FfnExit.finish` only wraps the output or runs postprocess.
- **`UnreducedOutput` carries the group its partial owes one all-reduce over,** declared by the producer:
  - the TP group for a dense layer;
  - the MoE output's group for a sparse one.

  `post_experts_reduction_group` now defines that group once; `deferred_post_experts_all_reduce` and `resolve_fusion_group` use it. `reduce_output` and `prepare_attn`'s unfused completion all-reduce over the declared group. `prepare_attn` hands the partial to the fused kernel, which reduces over the MoE output's group, only when that is the declared group.
- **Postprocess capability at construction:** whether postprocess's move back to this rank's tokens can run in the next layer is fixed once. It is true for the base `_scatter_hidden_states`, not for the MHC or DSA-CP ones.
- **Reduce-scatter step:** it returns None when only a scatter remains, instead of being compared with `_redistribute_output`.
- **Removed:** `_scatter_for_next_layer`, `_reduce_scatter_for_next_layer`, `_next_layer_input_can_restore_the_layout` and `_output_to_local_tokens_step`.
- **Nemotron-H:** its deferred outputs declare the same groups: the TP group for a Mamba or attention output, and the communicator's `ffn_reduction_group()` for an MLP or MoE output.

**Incidental fix.** The declared group follows what the FFN owes. It differs from the MoE rule only when the MoE group is not the TP group. That needs `moe_dp_size > 1`, which in turn requires context parallel. There, a dense layer's deferred sum was completed over the EP group only; it is now completed over the TP group, fused or not (the fused kernel is skipped, since it reduces over the EP group). No supported configuration reaches this today: the prefill context-parallel modes either force DP attention and `moe_dense_tp_size=1`, or plan dense layers as MOE_FULL.

## Accuracy Tests

- **Decision-table call sequences, 46,080 cases.** Both trees run their own completion code, with `get_parallel` patched to recording groups in every module that reads it, so each all-reduce is recorded with its group object.
  - **Matrix:** attention DP on / off × fused kernel × group layout (pure TP / pure EP / mergeable EP × TP / EP group ≠ TP group) × dense / sparse × last layer × postprocess function × each excluded condition (a2a, complete output, quantized communication, TP1 shared, LoRA) × LayerNorm SP × reduce_scatterv / MAX_LEN / tiles × allow reduce-scatter × token counts × a reader between layers.
  - **Result:** 45,864 cases are identical. The other 216 are exactly the dense layer + fused decision + (EP group ≠ TP group) cases above, where the completion moves from the EP group to the TP group.
- **`prepare_attn` call sequences, 49,152 cases** (the previous matrix × whether the declared group is the fused kernel's): identical to the parent whenever it is. When it is not, the 1,536 cases with a pending sum, a residual and no post-residual addition no longer try the fused kernel and complete the sum unfused.
- **Unit tests:** the related files pass, including a new `prepare_attn` case for a partial owed over another group than the kernel's.
- **GPU, B200, fusion on, 4 greedy requests × 32 tokens; text, token logprobs and top-5 logprobs compared:** Qwen3-30B-A3B-FP8 TP2, GLM-4.7-Flash TP2, Qwen3.5-35B-A3B TP2 and DeepSeek-V2-Lite TP2 × DP2 (reduce-scatter and all-reduce + scatter moved to the next layer) are all bit-identical to the parent.

Rebased onto main `9dc4c5d891`: every commit's patch is unchanged, and the related unit tests pass on the new base. The GPU results above were measured on the previous base, `5bb850d536`.
