### Describe the bug

On the MLX backend, any hybrid-SSM model with the radix cache enabled (the default) hard-crashes the scheduler on the very first request, because `MlxAuxiliaryStateComponent` / `MlxAuxiliaryStateReqToTokenPool` don't fully satisfy the contracts of the `MambaComponent` code they inherit:

1. **Missing config fields.** `MlxAuxiliaryStateComponent.__init__` (`python/sglang/srt/hardware_backend/mlx/kv_cache/auxiliary_state.py`) calls `TreeComponent.__init__` directly — it cannot call `MambaComponent.__init__`, whose `HybridReqToTokenPool` assert can't hold on MLX — so `self.mamba_cache_chunk_size` and `self.mamba_max_states_per_path` (set at `mamba_component.py:68-69`) are never assigned. The inherited `finalize_match_result_in_tree_core` (`mamba_component.py:125`) and `_emit_excess_path_states_eviction` (`mamba_component.py:211`) then raise `AttributeError` on the first `match_prefix` / first radix insert (`cache_finished_req`).

2. **Missing `mamba_allocator`.** `MlxAuxiliaryStateReqToTokenPool` exposes the slot pool as `mamba_pool` / `auxiliary_state_pool` only, but several live paths hard-code `req_to_token_pool.mamba_allocator`: the inherited CoW alloc in `MambaComponent.finalize_match_result_in_cache` (`mamba_component.py:154`, reached because `init_next_round_input` defaults `cow_mamba=tree_cache.supports_mamba()`), `_free_mamba_value` on the eviction path (`mamba_component.py:456` — the MLX component itself triggers this evict when the slot pool runs dry), the scheduler's revert of a matched-but-not-admitted request (`scheduler.py:3069`), and pool stats (`pool_stats_observer.py:249`). Each crashes with `AttributeError` on eviction, on a CoW prefix hit, or on prefill-queue rejection.

3. **Follow-on gap (silent, once 2 is fixed):** the CoW staged by the base class is applied on CUDA via `forward_batch.mamba_cow_src_indices` in `model_executor/model_runner.py:1459`; the MLX runner has no such pass and restores from the request's own slot, so the staged snapshot copy would never run and every prefix hit would silently fall back to the full-prompt recompute path (`hardware_backend/mlx/model_runner.py:781`).

The existing unit tests (`test_attention_patching.py`) hand the component a `SimpleNamespace` stand-in for the cache, which is why these inherited-path crashes were never exercised.

### Reproduction

Serving: launch any hybrid-SSM model on Apple Silicon with the MLX backend and the radix cache enabled (default flags) and send one request — the scheduler dies with `AttributeError: 'MlxAuxiliaryStateComponent' object has no attribute 'mamba_max_states_per_path'` when the finished request is inserted into the radix cache. A prefix-hit or eviction instead dies on `mamba_allocator`.

Model-free reproduction: the regression tests added in the linked PR build a real `UnifiedRadixCache` with `MlxAuxiliaryStateComponent` (as `mem_cache/registry.py:184` wires it for `use_mlx() and is_hybrid_ssm`) and drive insert/match/CoW/evict; on current main every one of them crashes with the `AttributeError`s above:

```
python -m pytest test/registered/unit/hardware_backend/mlx/test_auxiliary_state_radix_cache.py
```
