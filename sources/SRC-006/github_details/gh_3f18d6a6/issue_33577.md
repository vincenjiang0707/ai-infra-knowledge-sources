### Describe the bug

Two bugs prevent `--dcp-comm-backend a2a` from working at production concurrency and with `--enable-symm-mem`:

1. **NCCL crash (conc>32)**: `unhandled cuda error` in `pyncclGroupEnd` during eager decode (B > `cuda-graph-max-bs-decode`). Root cause: `_all_to_all_single` doesn't enable pynccl via `change_state(enable=True)`, falls back to `torch.distributed.all_to_all_single` which crashes on NCCL 2.27.7.
2. **OOM with `--enable-symm-mem`**: `prealloc_symmetric_memory_pool` allocates 4GB after `_profile_available_bytes` computes the KV cache budget, so the 4GB isn't accounted for → OOM at startup.

### Reproduction

* Start server with the above args
* Send 64+ concurrent requests (ISL=1024, OSL=1024)
* Server crashes during the first decode batch with `B > 32` (eager path)

### Environment

When using `--dcp-comm-backend a2a` with `--cuda-graph-max-bs-decode 32` and `--max-running-requests 64`, the server crashes with `NCCL Error 1: unhandled cuda error` in `pyncclGroupEnd` during decode batches where `B > cuda-graph-max-bs-decode` (i.e., the eager decode path).

```
--tp-size 8 --dcp-size 8 --dcp-comm-backend a2a
--attention-backend flashinfer --dtype bfloat16
--mem-fraction-static 0.88 --chunked-prefill-size 8192
--kv-cache-dtype fp8_e4m3
--cuda-graph-max-bs-decode 32 --max-running-requests 64
```
