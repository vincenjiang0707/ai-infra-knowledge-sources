# [PR #40456] [HiCache] Give trailing sidecar storage transfers a contiguous prefix_keys chain

## 正文

## Motivation

`HiCacheStorageExtraInfo.prefix_keys` is the page-hash chain preceding a storage call's keys, from the sequence start. The KV path honors that: `_page_backup` and `_storage_hit_query` extend it batch by batch, so `prefix_keys + keys` is always one contiguous chain.

Trailing sidecar transfers (SWA window, Mamba state, and the pools derived from them) do not. Their keys are the last `N` pages of the node, but `prefix_keys` is still the node's ancestor chain, so the node's own pages before the window belong to neither:

```
KV     prefix=[h0]  keys=[h1 h2 h3 h4 h5 h6]   contiguous
SWA    prefix=[h0]  keys=[h5 h6]               h1..h4 missing
MAMBA  prefix=[h0]  keys=[h6]                  h1..h5 missing
```

Flat key-value backends never notice, but any backend that places or evicts pages by chain position (depth-aware eviction, path-indexed stores) gets a wrong position for every sidecar page.

## Modifications

- `hybrid_cache_controller.py`: `_trailing_chain_groups` groups sidecar transfers by how many span pages precede their keys and builds one `HiCacheStorageExtraInfo` per group, so `prefix_keys + keys` is contiguous for every sidecar call. `_page_backup` (write) and `_page_transfer_sidecar` (read) use it. Transfers with the same tail length still share one backend call, so cross-pool batching is unchanged; with prefix keys disabled the single call with `prefix_keys=None` is kept as before.
- `hicache_storage.py`: state the `prefix_keys` contract on the field.
