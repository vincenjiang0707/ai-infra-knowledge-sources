# [PR #37941] [DSA] Make the fused top-k exact on an overflowing threshold bin

source: https://github.com/sgl-project/sglang/pull/37941
state: open | updated: 2026-09-27T02:04:49Z
labels: run-ci, jit-kernel

## 正文

## Motivation

The coarse histogram bin comes from the top bits of the fp16 cast, so one bin spans a quarter-binade. The collect pass stores at most 2048 threshold-bin candidates; when the bin is larger, `handle_tie` ranks whichever arrived first and silently returns a wrong top-k set.

Found while profiling GLM-5.2 decode on MI355X: ~0.04% of rows entered this path across all 8 ranks, with a largest observed bin of 4139 against the 2048 cap and none of those rows bit-identical. #35257 reports the same defect independently from the CUDA side — referenced, not closed.

## Modifications

When the threshold bin overflows, narrow it with three exact-key radix rounds (12 / 12 / 8 bits), then make one final input scan to emit candidates above the selected bucket and re-stage the bucket for the existing tie handler. The refinement histogram overlays the dead arrival-order buffer, so LDS is unchanged.

The cold scan uses a separate reversed-lane load path. This keeps its load-address state out of the fast path's registers and restores most of the CUDA regression reported in review.

Replace the fp16-bin boundary conversion with exact fp32 bounds. In particular, when a bin's high edge is `+0.0`, the boundary advances to the smallest positive subnormal so `-0.0` cannot be misclassified as above the bin.

The fast path only adds the overflow comparison. The ROCm `__launch_bounds__` argument also states the physical floor of 4 waves/SIMD; the CUDA spelling is unchanged.

## Accuracy Tests

The exactness test is ROCm-only because CUDA may route these shapes to the still-unrefined cluster path. It covers register and streaming shapes with six distributions, including adjacent fp32 values and the `+0.0/-0.0` boundary.

| suite | result before the fix |
|---|---|
| 300 pre-existing cases | 300 passed |
| 10 overflowing non-identical cases | 10 failed |
| 2 `all_equal` controls | 2 passed |

The signed-zero cases also fail on the pre-review refinement and pass with the new boundary conversion. All 312 cases pass with this change.

## Known gap

The CUDA-only `TopKCluster` path still truncates. Refining there needs cluster-wide histogram and emit counters rather than the block-local ones used here.

### xiaofei-zheng · 2026-09-10

@DarkSharpness thanks — all three addressed in c05fe161c9, and measured on MI355X.

**The min/max early-out is gone.** You are right that it was paying a scan on every refinement to serve a degenerate case. Without it the radix rounds still terminate correctly on an all-equal row: they consume all 32 bits and then truncate a bit-identical set, which is exact. Removing it also freed the tie staging buffer, which this path does not need — it re-derives the candidates rather than trusting what the collect pass staged there — so the buffer now carries the histogram.

**Down to at most four passes.** Two changes got there. The radix is 12 bits instead of 8, using that freed buffer (it is exactly `kRefineSize` uint32 wide, so the shared-memory footprint is unchanged at 27392 B), which covers the 32-bit key in three rounds instead of four. And each round's emit is fused with the next round's histogram: one scan classifies a candidate as above / equal / below the round's threshold digit and does both. So the cost is one pass to seed the first histogram plus one per round — four worst case, two if the bin resolves in the first round.

**The staging pass is eliminated too**, fused into the last round's emit the same way.

### xiaofei-zheng · 2026-09-16

Rebased onto #39648 and re-ported, now `e503afa6bd`.

A correction to what I said earlier: I claimed the padding change would break the refinement's counting invariant. That was wrong. `padding_value()` is `quiet_NaN()`, and NaN fails both `val >= v_hi` and `val >= v_lo`, so padding is counted by neither `count_gt` nor `count_eq` — the ragged path even writes the NaN into the score buffer itself. Since `for_each_input` visits exactly `[0, seq_len)`, the collect pass and the refinement's re-read agree on which elements exist, and no extra handling was needed. There is now a test that pins this rather than leaving it to code reading: overflow on an unaligned ragged window, which fails on the kernel on main.

Also worth flagging: #39648 restructured the kernel but left all four truncation sites unchanged, so the defect is exactly as it was.

Verified on MI355X — 304 pass here, and against the kernel on main the 14 new overflow cases fail while the 2 `all_equal` controls pass. Numbers are in the updated description.
