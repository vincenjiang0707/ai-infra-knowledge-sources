## Motivation

A decoder layer can leave its FFN all-reduce to the next layer's input norm. Until now it did so only when the fused all-reduce + residual + norm kernel took the batch, and it marked the output tensor with a `_sglang_needs_allreduce_fusion` attribute.

- **The marker was easy to lose.** Slicing, views and copies drop the attribute, and code that reads the tensor never sees it. So a consumer between layers could use the partial sum as if it were complete; the pipeline send, deepstack and aux capture fixes were each such a consumer.
- **The completion lived in two places.** The FFN reduced its own output whenever the fused kernel did not take the batch.

## Modifications

- **`UnreducedOutput`** (first commit): a small value holding the partial sum. It is not a tensor, so using it as one raises. Only the next layer's `prepare_attn` and an explicit `reduce_output()` read it.
  - `reduce_output()` replaces `complete_deferred_allreduce()`.
  - `layer_input_buffer()` serves the two layers that reuse their input's memory as the MoE output buffer.
  - `FfnExit.finish` returns the wrapper, and `finish_layer_stack` reduces it.
  - The CuteDSL communicator fuses the all-reduce of the wrapper's partial sum where it fused a marked tensor.
  - The models that set the marker themselves (Step-3.5, Qwen3.5, MiniMax-M3, GLM5-Next, Dots3, Nemotron-H) return the wrapper.
  - The deepstack additions and aux captures call `reduce_output()`. The two-batch-overlap entry reduces its input first, before it splits the batch and reads the input's length.
- **Next layer completes the sum** (second commit): `should_defer_ffn_reduction()`, used by `ffn_exit`, defers whenever the fused kernel would.
  - **Otherwise it defers** whenever the next layer would run exactly the reduction the FFN would have: one full-precision sum over the same TP group object, on a plain partial sum.
  - **Excluded:**
    - attention DP (handled in the next PR);
    - MoE combines that already sum (a2a, FP4 all-gather, DWDP);
    - quantized communication;
    - a replicated TP1 shared expert;
    - LoRA;
    - EP × MoE-TP hybrids;
    - MoE groups that are not the TP group object.
  - **Applies to `ffn_exit` models.** The models that call `should_fuse_mlp_allreduce_with_next_layer` themselves (Step-3.5, Qwen3.5, MiniMax-M3, GLM5-Next, Dots3, Nemotron-H) still defer only when the fused kernel runs. #41198 moves the first five onto `ffn_exit`.
  - When the fused kernel does not take the batch, or a post-residual addition must be added, `prepare_attn` all-reduces the pending sum and then takes the same quant-format residual step as a complete input. That fallback used to apply a plain norm and drop `quant_format` and `post_residual_addition`.

## Accuracy Tests

No numeric change: the next layer runs the same all-reduce over the same group on the same buffer.

- **`UnreducedOutput`:**
  - **`prepare_attn` call-sequence comparison** (all collectives and kernels stubbed): 24,576 cases identical to the parent.
  - **GPU, H200, 4 greedy requests × 32 tokens; text, token logprobs and top-5 logprobs compared; each configuration's audit shows the deferral happening.** Seven configurations are bit-identical: GLM-4.7-Flash TP2, PP2 × TP2 and TP2 + NextN; gpt-oss-120b TP2 + EAGLE3 (aux capture); Nemotron-3-Nano-30B-A3B-FP8 TP2; Qwen3-VL-30B-A3B TP2 image requests (deepstack); Qwen3-30B-A3B-FP8 TP2.
- **Deferral without the fused kernel:**
  - **Call sequences:** 22,528 of 24,576 cases are identical. The other 2,048 change in exactly one way: a pending sum is all-reduced first and then takes the normal path.
  - **GPU, H200, 15 configurations bit-identical to the parent:** GLM-4.7-Flash TP2 (fusion on, off, ~3000-token prompt, PP2 × TP2, + NextN); DeepSeek-V2-Lite TP2 (on / off); Qwen3-30B-A3B-FP8 TP2 (off); gpt-oss-120b TP2 (off, + EAGLE3 on / off); Ling-3.0-flash TP4 (on / off); Laguna-M.1 TP4 (on / off). In the fusion-off configurations the parent never defers and this PR does.

Under `torch.compile`, building the wrapper is a graph break: with `fullgraph=True`, torch 2.13 raises `Unsupported: object.__new__ user-defined class construction`. Decode compiles without `fullgraph`, so a deferring layer splits the compiled graph there. The `tc_piecewise` prefill backend compiles with `fullgraph` and cannot trace a deferring layer; with the second commit that includes prefill at TP > 1 without the fused kernel. The default `breakable` prefill backend is not traced. The `ffn_exit` fullgraph test is removed.

**Two-batch-overlap entry.**

- **CPU test:** a new test hands the entry an `UnreducedOutput` and checks that the split and the merge see the reduced tensor.
- **GPU, B200, DeepSeek-V2-Lite TP2 with two-batch overlap:** the previous revision of this stack crashes at the entry with `AttributeError: 'UnreducedOutput' object has no attribute 'shape'` in four configurations: DeepEP normal mode without attention DP, and attention DP2 with EP2, EP1 and DeepEP.
  - With the fix, each run passes the entry and then stops where main stops in the same configuration. Main stops on a flashinfer MLA ragged-prefill shape check, or on a missing global DP buffer length under two-batch overlap.
  - So there is no bit-identity comparison with two-batch overlap on this machine.

## Speed Tests and Profiling

Decode latency, H200, GLM-4.7-Flash TP2 with fusion off, `bench_one_batch` input 512 / output 128, decode CUDA graph on. The two trees ran on separate GPUs, then swapped.

| Batch size | Parent median (ms) | This PR median (ms) |
|---|---|---|
| 1 | 6.51 / 6.49 | 6.45 / 6.46 |
| 8 | 8.73 / 8.78 | 8.53 / 8.64 |
| 32 | 12.19 / 11.99 | 12.16 / 11.66 |

The differences are within noise. The all-reduce moves from the end of the FFN to the next layer's `prepare_attn`; the count is the same.
