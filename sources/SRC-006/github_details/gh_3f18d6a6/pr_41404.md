# [PR #41404] [PD] Defer decode KV release on every transfer failure, not only decode-initiated aborts

state: open | updated: 2026-09-27T10:34:56Z

## 正文

## Motivation

`pop_transferred` defers an aborted-mid-transfer request's KV pages only when `abort_notified` is set — i.e. only when the **decode itself** initiated the abort. A failure the decode did not initiate (a prefill fault, a transport error, a hicache restore failure) takes the immediate-release path while a sibling rank's chunk can still be writing toward those pages: the allocator hands them to a victim and the late write lands on it. This is the original mid-transfer reuse corruption through a different door — the hold never arms, so no release timeout applies and no tuning can reach it.

With deferred release on by default (#41023) this is the remaining corruption hole on the P→D transfer path; it is the "defer all failures" core of the #38961 audit.

**Stacked on #41402 — merge after it lands** (this PR then reduces to one commit). The arm-before-send from #41402 is what lets the drain acks for these newly-notified failures land instead of falling to the timeout.

## Modifications

- `CommonKVReceiver.ensure_abort_notified()`: sends the abort notification and arms drain-ack accounting exactly once. Extracted from `abort()`, which now calls it — unlike `abort()`, it does **not** overwrite the recorded root cause (`record_failure` assigns, so calling `abort()` here would replace the true failure reason with "Aborted by AbortReq.").
- `pop_transferred`'s Failed branch: when the room is deferrable and `abort_notified` is not yet set, call `ensure_abort_notified()` — every prefill rank is told to stop, drain, and ack — then defer the release like any decode-initiated abort.
- A receiver that could not notify (metadata never published → no prefill holds its destination info → nothing can be in flight) keeps the immediate release: holding it would waste a full timeout on pages nobody can touch.
- Backends without the deferred-release capability (mori, fake) are unchanged: no notification is added and the release stays immediate.

End-to-end: the ABORT lands at each prefill rank's bootstrap handler, which marks the room Failed (stopping new chunks), registers/acks per #40645+#41402 semantics; the healthy sibling drains its in-flight chunk and acks; decode releases on the last ack, or on the timeout if acks are lost.
