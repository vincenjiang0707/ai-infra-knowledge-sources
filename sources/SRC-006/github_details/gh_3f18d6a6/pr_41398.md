# [PR #41398] [Bug] Accept pp_proxy_tensors in frozen-KV MTP and UNO spec-v2 workers

## 正文

## Motivation

Fixes #40155.

The scheduler non-overlap speculative path always calls:

```python
self.model_worker.forward_batch_generation(batch, pp_proxy_tensors=pp_proxy_tensors)
```

`FrozenKVMTPWorkerV2` and `UnoWorkerV2` did not accept `pp_proxy_tensors`, so the first step on those workers raised:

```text
TypeError: ...forward_batch_generation() got an unexpected keyword argument 'pp_proxy_tensors'
```

`DSparkWorkerV2` / `MultiLayerEagleWorkerV2` already had the parameter; these two were the remaining gaps.

## Modifications

- Add `pp_proxy_tensors=None` to `FrozenKVMTPWorkerV2.forward_batch_generation` and pass it through to the target prefill and `verify` paths.
- Add the same parameter to `UnoWorkerV2.forward_batch_generation` / `_forward_prefill` and forward it to the target worker.
- Declare abstract `forward_batch_generation(..., pp_proxy_tensors=None)` on `BaseSpecWorker` so future workers cannot silently omit it.
- Add `test/registered/unit/spec/test_spec_worker_pp_proxy_signature.py` (AST bookkeeping) so every concrete override under `speculative/` must accept the keyword.
