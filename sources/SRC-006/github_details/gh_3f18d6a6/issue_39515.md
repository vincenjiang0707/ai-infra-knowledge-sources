### Describe the bug

I was running Qwen3.5-122B-A10B-FP8 on a rented B200 with and without NEXTN, one request at a time, just to see what speculative decoding does for it. The speculative server came out *slower* than the plain one on long prompts — 119 tok/s vs 229 at ~12k tokens — which seemed backwards, since acceptance was fine (1.7–1.9 tokens per step in the scheduler log).

The `server_args` line explained it. The plain server had picked `attention_backend: trtllm_mha, page_size: 64`; the identical command plus the NEXTN flags had picked `attention_backend: triton, page_size: 1`. Nothing in the log mentions the change. So I put `--attention-backend trtllm_mha` on the speculative command, and it just works — page size stays at 16 and it's flat across context:

| server | ~200 | ~2k | ~12k tokens |
|---|---|---|---|
| plain, auto → `trtllm_mha` | 232.8 | 232.7 | 229.5 |
| plain, `--attention-backend triton` | 224.7 | 210.8 | 159.2 |
| NEXTN, auto → `triton` (page_size 1) | 301.5 | 206.9 | 119.1 |
| NEXTN, `--attention-backend trtllm_mha` forced | **318.4** | **294.3** | **310.7** |

(Batch 1, 128 output tokens, prompts of 186 / 1,862 / 11,150 tokens, tokens counted from `usage.completion_tokens`, radix cache off, a warm-up request then best of two. Same on three separate pods.)

I poked around in v0.5.19 to see where it decides, and I think it's one rule applied to the wrong backend — happy to be corrected:

- `utils/common.py::is_no_spec_infer_or_topk_one` only returns True for topk 1 when `page_size` is 1 or None.
- `arg_groups/model_override_base.py::get_default_attn_backend` only hands out `trtllm_mha` on SM100 when that's True — so with `--page-size 16`, a speculative server never gets it. Its own docstring says the intent is *"Use trtllm_mha for SM100/SM103 ... excluding spec with topk > 1"*, i.e. topk 1 spec should get it.
- `arg_groups/model_overrides/qwen3_5.py::_qwen3_5_hybrid_overrides` then falls back to `triton` and sets `page_size = 1`. Its comment says *"trtllm_mha requires speculative_eagle_topk == 1 and page_size > 1"* — exactly the combination the first rule rejects.
- `arg_groups/overrides.py` accepts 16 / 32 / 64 / 128 for `trtllm_mha`, and my forced run served with 16 without complaint.

If I don't pass `--page-size` at all, the auto path does pick `trtllm_mha`, so the trigger is specifically an explicit page size with topk 1. Per step, `trtllm_mha` does a draft+verify in about 1.35× a plain step at every prompt length; `triton` is 1.40× at 200 tokens and 2.44× at 12k, which is how the auto-selected speculative server ends up slower than no speculation at all.

Other backends, for the record: `fa4` fails at graph capture on this model (`SM100 forward with head_dim=256 does not support seqused_q/seqused_k`; with NEXTN, `q.dtype torch.bfloat16 != k.dtype torch.float8_e4m3fn`), `flashinfer` is refused by the assertion, `fa3` is SM 80–90 only. So `trtllm_mha` is the one backend that runs NEXTN well here, and the one the auto-selector can't reach.

Is that intended — should the topk-1 rule not require `page_size == 1` for a backend that needs `page_size > 1`? Or at least a log line when adding speculation swaps the backend and page size? Workaround for anyone searching: `--attention-backend trtllm_mha`, or leave `--page-size` off.

I've kept the `server_args` lines for all three servers and the fa4 tracebacks if they're useful.

*I used an AI assistant to help with the benchmark harness and to tidy this up; the runs are mine and I can re-run any of them.*

### Reproduction

Model: `Qwen/Qwen3.5-122B-A10B-FP8`, TP=1, one B200.

Plain server (auto-selects `trtllm_mha`, page_size 64):

```
python3 -m sglang.launch_server --model-path Qwen/Qwen3.5-122B-A10B-FP8 --host 0.0.0.0 --port 8000 \
  --page-size 16 --context-length 32768 --kv-cache-dtype fp8_e4m3 --disable-radix-cache \
  --mem-fraction-static 0.8
```

NEXTN — same flags plus the following (auto-selects `triton`, page_size 1; add `--attention-backend trtllm_mha` and it keeps page_size 16 and runs 2.6× faster at 12k):

```
  --mem-fraction-static 0.90 \
  --speculative-algorithm NEXTN --speculative-draft-model-path Qwen/Qwen3.5-122B-A10B-FP8 \
  --speculative-num-steps 1 --speculative-eagle-topk 1 --speculative-num-draft-tokens 2
```

Compare the `attention_backend` / `page_size` values in the `server_args` log line of the two servers, then time a single `/v1/completions` request with a ~11k-token prompt and 128 output tokens against each.
