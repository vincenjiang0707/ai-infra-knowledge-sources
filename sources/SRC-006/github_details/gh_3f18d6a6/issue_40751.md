### Describe the bug

We observe severe reasoning degeneration when serving Kimi-K3 with MegaMoE on GB300. Switching the Decode backend to DeepEP resolves this behavior in our tests.

Requests initially produce coherent reasoning, then may enter prolonged repetition (hmm, or other words), generate tens of thousands of tokens, and fail to complete the task. This also occurs with approximately 34K input tokens, well below the context limit.

**Observed results**


Decode configuration | DeepSWE score
-- | --
TP8 baseline | 68.14% (77/113)
EP32 + DeepEP | ~65.5%
EP32 + MegaMoE, latest run | 42.48% (48/113)

In the latest MegaMoE run, 57/113 tasks contained long mechanical repetition, versus 0/113 in the TP8 baseline using the same detection rule. All 37 responses exceeding 50K output tokens contained repetitive loops. Some affected tasks eventually passed, so successful completion alone does not indicate normal generation.

### Reproduction

Request settings: temperature=1.0, top_p=0.95, thinking_effort=max.

DeepSWE benchmark case: ofetch-per-origin-circuit-breake__qTK9hR7

Expected: Coherent reasoning and normal task completion, as observed with DeepEP.

Actual: MegaMoE produces excessive reasoning and repetitive loops. We have not identified the underlying cause.

### Environment

**Environment**

- Hardware: NVIDIA GB300, ARM64, CUDA 13.0
- Model: Kimi-K3
- SGLang: internal v0.5.19-based build; also observed with an earlier v0.5.18-based build
- FlashInfer: 0.6.18
- sgl-deep-gemm: 0.1.7, with [DeepGEMM #389](https://github.com/deepseek-ai/DeepGEMM/pull/389) and [#441](https://github.com/deepseek-ai/DeepGEMM/pull/441) backported
- PD disaggregation using Mooncake
- Prefill: TP8, trtllm_mla
- Decode: 32 GPUs, EP32, Attention TP4 × DP8, CUDA Graph enabled

Relevant Decode arguments:

```
--disaggregation-mode decode \
--tp-size 32 \
--ep-size 32 \
--dp-size 8 \
--enable-dp-attention \
--enable-dp-lm-head \
--moe-a2a-backend megamoe \
--attention-backend cutedsl_mla \
--kv-cache-dtype fp8_e4m3 \
--mamba-ssm-dtype bfloat16 \
--disable-radix-cache \
--cuda-graph-backend-decode full \
--cuda-graph-max-bs-decode 128 \
--reasoning-parser kimi_k3 \
--tool-call-parser kimi_k3
```

The problem persists with SGLANG_DEEPGEMM_PDL=0. It has also been observed with trtllm_mla and with Triton KDA.
