## 正文

## Motivation

Serve Black Forest Labs FLUX 3 Action robot policies (`black-forest-labs/flux-3-action-droid`) in SGLang's native `multimodal_gen` runtime. From the current camera frames, the robot state, and a language instruction, the policy denoises future video latents jointly with a chunk of continuous actions and returns only the actions (`[32, 8]` on DROID).

## Modifications

- **Model:** the FLUX 3 `JointSingleSeq` DiT, the Swin3D video VAE, and the stacked Qwen3-VL-4B text encoder.
  - LayerNorm + modulate, SwiGLU and the gated residual use bit-exact fused kernels.
  - QK-RMSNorm + RoPE uses a fused kernel at bf16 rounding level.
- **Pipeline:** a `VLA_ACTION` pipeline that reads the policy package (`config.native.json`, manifest, `--model-variant`).
  - Variants: `base`, `fp8r`, `gd`, `gd-fp8r`, `sd`, `sd-fp8r`.
  - FP8r loads native E4M3 weights with one scale per output row and runs `torch._scaled_mm` (SM89+).
- **Sampling:** Cosmos UniPC.
  - The text context is cached per caption.
  - Observation and state streams run once per request.
  - Mode blocks of the noised streams run once per step and are shared by the CFG passes.
- **NATTEN is optional:** without it, the VAE runs the same neighborhood windows through a compiled FlexAttention block mask.
- **Multi-GPU:** `num_gpus = tp x sp x (2 with --enable-cfg-parallel)`.
  - CFG parallel.
  - Tensor parallel: `MergedColumnParallelLinear` over `[q, k, v, gate, value]`, `RowParallelLinear`, one all-reduce per block.
  - Ulysses / K/V-gather sequence parallel.
- **Shared-code changes:**
  - `rank_local_checkpoint.py`: the rank-local TP fast path now falls back to the full load when a checkpoint source spans several `MergedColumnParallelLinear` partitions. Before, a fused `[gate | up]` on disk was silently mis-sharded.
  - Action endpoints: a pipeline can own `/v1/actions/metadata`, and the optional `seed` and guidance scales are forwarded when the client sends them.
- **Tooling:** `benchmarks/bench_flux3_action.py` (the latency protocol below) and the `flux3_action_http` GPU CI case.
- **Docs:** deployment, multi-GPU, the request schema, and the OpenPI websocket in `docs/cookbook/vla/FLUX/FLUX-3-Action.mdx`.

## Speed Tests and Profiling

Supported checkpoints (`black-forest-labs/flux-3-action-droid`; three 360x640 cameras `wrist`, `left`, `right`; state and action dim 8; 32-action chunks):

| `--model-variant` | Recipe | Weights | Latency on 1x RTX 5090 | Latency on 1x H200 |
| --- | --- | --- | ---: | ---: |
| (default) / `base` | 4 steps, guidance 4.0 (video) / 1.0 (action) | BF16 | 1.14 s | 0.41 s |
| `fp8r` | same | FP8 rowwise | 0.93 s | 0.47 s |
| `gd` | guidance-distilled: 4 steps, no CFG | BF16 | 0.63 s | 0.24 s |
| `gd-fp8r` | same | FP8 rowwise | 0.52 s | 0.27 s |
| `sd` | step-distilled: 1 step | BF16 | 0.18 s | 0.09 s |
| `sd-fp8r` | same | FP8 rowwise | 0.16 s | 0.11 s |

A BF16 package peaks at about 27 GB (DiT 13.9 GB, text encoder 8.9 GB, video VAE 2.5 GB, plus activations).
