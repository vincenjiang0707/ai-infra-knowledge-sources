## 正文

## Motivation

[Laya](https://huggingface.co/convaiinnovations/laya) is a non-autoregressive decision model: a bidirectional ModernBERT encoder (28 layers, hidden 1024) plus a small transformer decision head, 421M parameters. Every answer option is a `[MASK]` marker in the prompt, the head scores each marker, and the softmax over those markers is the answer distribution. A second head predicts whether the agent should escalate to a human.

Nothing is generated, so it does not fit the generation-based `/v1/decisions` path, which needs a chat template and single-token answer labels. SGLang also has no ModernBERT implementation at all. This adds one, together with the decision head, and serves the checkpoint as an embedding model where one request returns `[p_0, ..., p_{K-1}, act_escalate, act_not_escalate]`, with `K` varying per request.

## Modifications

- `python/sglang/srt/models/laya.py` (new): `LayaForDecision`, its ModernBERT encoder (alternating full and sliding attention, per-layer RoPE base) and the per-request pooling path.
- `python/sglang/srt/configs/embedding_model_spec.py`: declare the architecture as a bidirectional encoder that needs the full prompt, and switch off prefix reuse and chunked prefill for it.
- `python/sglang/srt/arg_groups/model_hook.py`: honour `safe_disable_radix_cache` and `safe_disable_chunked_prefill` for every spec, not only the Gemma embedding path. A bidirectional encoder must not read a cached prefix, because the cached hidden states were computed without the tokens that follow them and the request silently reaches the model as a suffix-only batch. This is a correctness fix, not an optimization.
- `python/sglang/srt/configs/model_config.py`: `LayaForDecision` is never a generation model.
- `python/sglang/srt/environ.py`: `SGLANG_LAYA_TEMPERATURE_CLAMP` and `SGLANG_LAYA_ATTENTION_BACKEND`.
- `test/registered/unit/models/test_laya_registration.py` (new) and `test/registered/unit/configs/test_embedding_model_spec.py`.
- `docs/docs/supported-models/laya.mdx` (new) and the docs nav.

Two details worth knowing when serving this checkpoint. It ships no root `config.json`, so the docs page describes the small script that builds one; the per-question-type temperatures live under `laya_temperature` because `PretrainedConfig` consumes `temperature` as a generation default while building the config object, so a value stored under that name never reaches the model.

A prompt with no `[MASK]` marker returns the act head alone and logs a warning instead of raising: SGLang's own startup warm-up sends such a prompt, and a malformed request must not abort the engine.

The encoder computes its own bidirectional attention instead of routing through the attention backend, because the local layers keep keys within `|i - j| <= local_attention / 2` and the windowed backend path does not reproduce that mask. See the accuracy section for the measurement.

Limitations: tensor parallelism is not supported, because the decision head pools per request and is not sharded, and the encoder does not use the paged KV cache. Only the English root checkpoint is covered; the `multilingual` and `typed-decisions` subfolders use different encoders.

## Accuracy Tests

Evaluated with the model repository's own harness (`research/eval/laya_eval.py`), the one its weekly regression workflow runs: `mteb/amazon_massive_intent`, `en`, `test`, 100 cases, 20 options, seed 13.

| | accuracy | macro F1 | ECE | mean confidence |
| --- | --- | --- | --- | --- |
| committed baseline | 0.8200 | 0.7876 | 0.1382 | 0.9582 |
| reference SDK | 0.8200 | 0.7876 | 0.1382 | 0.9582 |
| SGLang (bf16) | 0.8200 | 0.7876 | 0.1371 | 0.9571 |
| SGLang (fp32) | 0.8200 | 0.7876 | 0.1382 | 0.9582 |

The repository's `research/evals/check_regression.py` gate passes (`exit=0`, tolerances 0.02 / 0.03 / 0.03). In fp32 the per-case probabilities match the reference to 1.5e-5 (mean 1e-6) with the chosen option identical in 100 of 100 cases; the bf16 difference is dtype rounding, amplified by the 0.5 temperature the checkpoint uses for this question shape.

Backend comparison on the same evaluation: with `--attention-backend fa3` the accuracy drops to 0.8100 with 96 of 100 per-case agreement, which is why the encoder computes its own attention. Sweeping the local-attention radius (63 / 64 / 65) gives the exact published macro F1 and the best per-case agreement only at 64.

## Speed Tests and Profiling

Not benchmarked. For scale, the 421M-parameter checkpoint answered the 100 requests above in 3.3 s end to end over HTTP; that is a sanity figure, not a benchmark.
