# [Issue #40901] [Bug]: abort chunk re-sends the full accumulated text under --incremental-streaming-output

source: https://github.com/sgl-project/sglang/issues/40901
state: open | updated: 2026-09-23T11:38:17Z
labels: 

## 正文

### Describe the bug

`--incremental-streaming-output` promises disjoint segments. the contract is stated twice in-tree: the coalescing docstring in `_coalesce_streaming_chunks` ("Both text and output_ids are incremental deltas, so we concatenate them") and the flag help text ("Whether to output as a sequence of disjoint segments").

the abort path violates both. `_handle_abort_req` slices `output_ids` to a delta but emits `state.get_text()`, the full accumulated text, in the same message. under the flag both serving layers append whatever arrives (`serving_chat.py` and `serving_completions.py` use `content["text"]` as the delta), so a client that concatenates deltas receives the entire generation a second time on every graceful abort (client disconnect, `/abort_request`, session cleanup).

the id slicing is also lossy: `[output_ids[-1]]` keeps only the last pending token when more than one arrives after the final incremental chunk, and re-sends the last id when none are pending.

### Steps to reproduce

headless, no gpu, on current main:

```python
import asyncio
from types import SimpleNamespace
from sglang.srt.managers.tokenizer_manager import ReqState, TokenizerManager

tm = object.__new__(TokenizerManager)
tm.rid_to_state = {}
tm.incremental_streaming_output = True
tm.config_value = lambda name: 0
state = ReqState(
    obj=SimpleNamespace(stream=True, return_logprob=False),
    out_list=[], finished=False, event=asyncio.Event(),
    time_stats=SimpleNamespace(set_finished_time=lambda: None, get_e2e_latency=lambda: 0.0),
)
state.output_ids = [1, 2, 3, 4, 5, 6, 7]
state.last_output_offset = 5      # 5 tokens already streamed as deltas
state.append_text("hello world")   # 10 chars already streamed as deltas
tm.rid_to_state["r"] = state
tm._handle_abort_req(SimpleNamespace(rid="r", abort_message=None, finished_reason=None, weight_versions=None))
print(state.out_list[-1])
# contract says: {"text": "d", "output_ids": [6, 7], ...}  the un-streamed remainder
# main returns:  {"text": "hello world", "output_ids": [7], ...}  full text re-sent, id 6 lost
```

live repro: serve any model with `--incremental-streaming-output`, stream a completion, disconnect mid-stream or call `/abort_request`, concatenate the SSE deltas: the text appears twice.

### Expected behavior

the abort chunk honors the incremental contract like every other chunk: text and output_ids are the un-streamed deltas. for a request aborted before any chunk, that means the full output as the first and only delta. non-incremental streaming keeps today's behavior (full accumulated text).

### Environment details

main @ 401d5aed, darwin arm64, no gpu needed, reproduced headless via the snippet above.
