# [PR #41405] [AMD][DI][CI] Escape backticks in the SPUR drive_batch.sh heredoc

state: open | updated: 2026-09-27T09:17:50Z
labels: 

## 正文

## What
Escape two backticks in a comment inside the heredoc that `launch_mi355x.sh` uses to generate `drive_batch.sh` on the SPUR cluster.

## Why
The heredoc is unquoted (`<<EOF`), because it needs `$WORKDIR` and the other launch variables expanded. As a side effect, the backticked `` `| tee` `` and `` `tail -F` `` in the comment ran as command substitutions while the file was being written. Every SPUR leg logs this, for example in [run 36225745974](https://github.com/sgl-project/sglang/actions/runs/36225745974) and [run 36302133557](https://github.com/sgl-project/sglang/actions/runs/36302133557):

```
launch_mi355x.sh: command substitution: line 1532: syntax error near unexpected token `|'
tail: cannot follow '-' by name
```

The legs still pass because both substitutions fail immediately and expand to nothing. But the generated comment loses those words, the errors look like a real launch failure when someone is triaging a red leg, and a bare `tail -F` reads stdin, so it could block if stdin were ever a pipe. The fix escapes them as `` \` ``, the same way the heredoc already escapes `\$`.

## Test plan
- Rendered the heredoc from the old and new versions of the script with bash. The old version reproduces both errors above. The new version produces no stderr, and the only difference in the generated `drive_batch.sh` is the restored comment text. `bash -n` passes on the launcher and on the generated script.
- Checked every unquoted heredoc under `scripts/`. These two lines were the only unescaped backticks.
- Not yet run in a nightly. The change affects only comment text in the generated file.
