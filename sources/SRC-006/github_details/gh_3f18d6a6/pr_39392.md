## Summary

- Capture logical expert IDs from DeepSeek V4 HashTopK before logical-to-physical remapping for R3 replay. Mask CUDA-graph padding, disable target capture from draft modules, and reject the unsupported HashTopK waterfill/capture combination.
- Synchronize CUDA IPC tensor imports in the weight updater before returning to the producer, including flattened buckets and other tensor load formats.
- Support repeated TRT-LLM MXFP4 online loads: permute expert weights in place, retain checkpoint-layout scale parameters, and maintain separate shuffled scale copies with stable kernel addresses.
- Register the GEMM1 clamp limit as a non-persistent buffer so memory offload preserves it.
- Keep the padded-row Triton fast path off CPU tensors.

## FP8/MXFP8 activation-state follow-up (2026-09-23)

Commit `104716dc91` also fixes the TRT-LLM activation tensors introduced in the new base's FP8/MXFP8 path. These alpha/beta/clamp tensors were ordinary attributes, so the memory-saver static-state backup omitted them. Repeated postprocessing also replaced their storage even though CUDA graphs retained the old addresses. Register them as non-persistent buffers and copy into existing storage on reload.

Evidence: an isolated reproduction using the actual preparation and static-state export/import functions left the old clamp at zero after simulated storage loss; re-preparation created a different pointer holding 10. The same function-level check passes after the fix (restored values, stable storage, no checkpoint entries). The existing runner-ownership test fixture now also covers this lifecycle.
