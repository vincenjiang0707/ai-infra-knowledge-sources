# [PR #41402] [PD] Fan drain abort ACKs out to every decode peer of the room

source: https://github.com/sgl-project/sglang/pull/41402
state: open | updated: 2026-09-27T10:35:13Z
labels: run-ci

## 正文

## Motivation

With prefill TP < decode TP (the MLA fan-out shape) several decode ranks share one bootstrap room, but the prefill's `_deferred_ack_targets` registry holds a single `(ip, port)` per room. Each decode rank's ABORT overwrites the previous registration, so when the transfer drains only the **last** rank to abort receives the `ABORT_ACK` — every other rank holds its KV pages for the full `SGLANG_DISAGGREGATION_DEFERRED_DECODE_KV_RELEASE_TIMEOUT` on **every** abort of that shape. With deferred release now on by default (#41023), that is a systematic 30s (or configured-timeout) capacity hold whenever an MLA-shaped request aborts mid-transfer.

This is claim (2) of the #38961 audit ("only one decode rank per room can register"); claim (1) was fixed by #40645.

## Modifications

**Commit 1 — fan the drain ack out to every decode peer of the room.** On drain, `_maybe_ack_drained_abort` now acks the union of:

- the registered target (the guaranteed floor — may be the only source when the abort lands during bootstrap), and
- every peer recorded in `transfer_infos[room]`, via the new `_abort_ack_fanout_targets` helper.

**Commit 2 — close the two interleavings where the fan-out still degraded to the old behavior:**

- *Snapshot the peers at registration.* The fan-out read `transfer_infos` at drain time, so a sender `clear()` that popped the room while a chunk was still in flight degraded the drain ack back to the registered target alone. `register_deferred_ack_target` now snapshots the peer set, and the drain acks the union of the live infos (peers that registered after the ABORT), the snapshot (survives mid-flight teardown), and the registered sender. The snapshot is popped in lockstep with the target, so it shares the registry's lifecycle exactly; it is also written before the target (commit 3), so a drain racing the registration can never strand it.
- *Arm the decode tracker before the ABORT goes out.* With fan-out, a peer rank's earlier abort of the same room can deliver an ack before this rank has armed its own tracker, and the scheduler armed only after `receiver.abort()` returned — an ack racing back in between was dropped and the rank waited out the full release timeout. The arming now lives in `CommonKVReceiver._send_abort_notification`, before the send, gated on the backend capability and a published-metadata `init_time` (so aborted prealloc-queue receivers, which never enter the deferred-release flow that cleans the tracker up, stay unarmed). This also arms the decode waiting-timeout abort path and the other `kv_receiver.abort()` call sites, which never armed before and always fell to the timeout hold. The scheduler block collapses to plain `abort()` — the same shape as #37077, minimizing conflicts with it.

Design notes:

- The target set is derived from `transfer_infos`, which the prefill already maintains — mirroring how the failure-notification path fans out via `_room_notify_targets` (#36612). `TransferInfo.endpoint`/`dst_port` is byte-identical to the `(local_ip, rank_port)` the ABORT carries, on both mooncake and NIXL, so the ack reaches the same decode listener either way.
- Unlike `_room_notify_targets`, **dummy pairings are included**: each decode rank's release denominator is `len(bootstrap_infos)` — it counts an ack from every prefill rank it notified, dummy pairing or not, and a dummy pairing is trivially drained.
- No over-count is possible: acks are keyed per prefill rank into a set, a prefill rank's `transfer_infos[room]` only ever contains decode ranks that registered with it, and a decode rank registers with a prefill rank precisely because that rank is in its `bootstrap_infos` denominator.
- The fan-out only fires when a target was registered (an ABORT actually arrived), so a normal successful drain still acks nobody.
- Ordering is unchanged and safe: the worker's drain-site ack runs before the teardown that pops `transfer_infos`, and the pop-once semantics of `_deferred_ack_targets` still make the ack fire at most once per room. Only the winning pop consumes the snapshot, so a concurrent drain/registration race cannot strand it.
- Single-arm invariant: `abort_notified` guards `_send_abort_notification`, so the tracker is armed exactly once per receiver — a later redundant abort no longer re-wipes acks already collected (the wipe only matters at first arming, for bootstrap-room reuse).
- Duplicate acks to the registered target are deduped; even if delivered twice, the decode aggregates acks per prefill rank into a set, so double delivery cannot over-count.
- Lives in `CommonKVManager` / `CommonKVReceiver`, so mooncake and NIXL both get it; mori/fake never register targets and `enable_deferred_decode_kv_release` is off for them, so both paths stay unreachable there.

- `test_drain_ack_fans_out_to_every_room_peer` — three peers, only the last registered (the overwrite): all three acked, each once; a second drain acks nobody. **Fails before commit 1** (`[('10.0.0.2', 5001, 7)] != [3 targets]`).
- `test_drain_ack_fanout_survives_mid_flight_teardown` — sender clear() pops `transfer_infos` while a chunk is in flight; the drain still acks every snapshotted peer. **Fails before commit 2** (only the registered target acked).
- `test_drain_ack_after_teardown_falls_back_to_registered_target` — abort during bootstrap (nothing to snapshot) still acks the registered sender.
- `test_populated_room_without_registration_acks_nobody` — no spurious acks on normal drains.

`test/registered/unit/disaggregation/test_deferred_decode_kv_release.py` (base-a-test-cpu):

- `test_tracker_armed_before_the_abort_is_sent` — the tracker is armed at the moment the ABORT hits the wire. **Fails before commit 2** (armed only after `abort()` returned).
- `test_prealloc_abort_does_not_arm` / `test_opted_out_backend_does_not_arm` — the `init_time` and capability gates: no tracker-entry leak for prealloc aborts or non-acking backends (mori).
