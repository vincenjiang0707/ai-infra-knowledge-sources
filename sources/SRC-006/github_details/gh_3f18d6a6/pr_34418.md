## 正文

## Motivation

Reported in #34000 (Bug 3).

`LatentPreparationStage.forward` runs two different preparations depending on where the latents came from:

```python
if latents is None:
    latents = randn_tensor(...)
    latent_ids = server_args.pipeline_config.maybe_prepare_latent_ids(latents) ...
    if latent_ids is not None:
        batch.latent_ids = latent_ids.to(device=device)
    if spec.pack_latents:
        latents = server_args.pipeline_config.maybe_pack_latents(latents, batch_size, batch)
else:
    latents = latents.to(device)     # <- no latent_ids, no packing
```

For packed models this is fatal. `Flux2PipelineConfig` supplies both hooks, and `FluxPipelineConfig.get_freqs_cis` later does:

```python
img_ids = batch.latent_ids
if img_ids.ndim == 3:
```

so an injected `x_T` reaches the denoising loop with `latent_ids` still `None` → `AttributeError: 'NoneType' object has no attribute 'ndim'`. The latents also stay unpacked `(B, C, H, W)` where the transformer expects the packed `(B, H*W, C)` layout.

The grouped path already funnels provided latents into `forward`: `run_grouped_requests` falls back to per-request `self(batch, server_args)` when `any(batch.latents is not None ...)`, so fixing `forward` covers both paths.

## Modifications

Hoist the shared preparation so provided latents can run it too, **gated on the provided tensor matching the layout the randn branch would have produced** (`spec.shape`).

The gate is load-bearing, and I'd appreciate a maintainer sanity-check on it. The ComfyUI executors assign `Req.latents` in the already-packed `[B, S, D]` layout (`apps/ComfyUI_SGLDiffusion/executors/flux.py:54`, `req.latents = hidden_states  # Set as [B, S, D] format directly`), and those requests **do** reach this stage — `ComfyUIFluxPipeline.create_pipeline_stages` installs `ComfyUILatentPreparationStage`, which inherits this `forward` and pairs it with `FluxPipelineConfig`. Packing such a tensor a second time leaves the element count unchanged, so `_pack_latents`' `view` succeeds and **silently permutes** the caller's latents rather than raising. Latents in a layout this stage would not have drawn are therefore passed through untouched, exactly as before.

Corroborating evidence that this is the intended split: `ComfyUILatentPreparationStage.forward` saves `original_latents_shape` before calling `super().forward()` and restores it after, commented "before any potential packing/conversion (e.g., 4D spatial -> 3D sequence) to ensure proper unpadding later" — i.e. the parent packing provided latents is an expected outcome for the 4D case.

No-op for models that don't pack: the base `PipelineConfig` returns `None` from `maybe_prepare_latent_ids` and returns the latents unchanged from `maybe_pack_latents`, and stages that set `prepare_latent_ids=False` / `pack_latents=False` on their spec (realtime, LongLive2) skip both hooks as before. The randn path is unchanged.

## Accuracy Test

With a packed-model config stub whose `maybe_pack_latents` reshapes off the spec dims (mirroring the real `view`-based `_pack_latents`):

```
case                            latent_ids   packs   out shape
before  randn (drawn)           (1, 64, 4)     1     (1, 16, 16)
before  provided, drawn-layout        None     0     (1, 4, 8, 8)   <- unusable downstream
before  provided, PRE-PACKED          None     0     (1, 16, 4)

after   randn (drawn)           (1, 64, 4)     1     (1, 16, 16)
after   provided, drawn-layout  (1, 64, 4)     1     (1, 16, 16)    <- fixed
after   provided, PRE-PACKED          None     0     (1, 16, 4)     <- byte-identical, 0 pack calls
```

The pre-packed row is checked with `torch.equal` against the input, not just by shape.

**Verification caveat, please read:** I could not run the pytest suite against `main` — the sglang install I have is `0.5.12.post1`, whose tree predates the current layout, and my only box is a CPU node where importing `sglang.multimodal_gen` off network storage takes >10 minutes. The table above comes from extracting the real `forward` from both `main` and this branch via `git show` and executing them side by side against stubs. **The added unit test has not been executed under a real sglang install** — please treat it as unvalidated and let CI be the first real run. Given the ComfyUI interaction, an E2E run on a ComfyUI Flux workflow would be the most valuable check you could add here.
