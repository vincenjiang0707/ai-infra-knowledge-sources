### Describe the bug

ep_scatter_from_psum (python/sglang/kernels/ops/moe/ep_moe_kernels.py) launches the Triton kernel _fwd_kernel_ep_scatter_2 but omits the two positional arguments expert_start and num_experts. In the kernel signature they sit between output_index_stride1 and topk_num: tl.constexpr:
```
def _fwd_kernel_ep_scatter_2(
    ...,
    output_index, output_index_stride0, output_index_stride1,
    expert_start,          # <- missing at the call site
    num_experts,           # <- missing at the call site
    topk_num: tl.constexpr,
    ...,
):
```
The sibling ep_scatter passes both; ep_scatter_from_psum jumps straight from output_index.stride(1) to the topk_num= keyword, so Triton's dynamic_func() fails at argument binding:
```
TypeError: dynamic_func() missing 2 required positional arguments: 'expert_start' and 'num_experts'
```

This path is reached on the DeepEP v2 contiguous/extend (prefill) route via pre_permute_deepep_v2_to_deep_gemm (python/sglang/srt/layers/moe/moe_runner/deep_gemm.py). Every rank raises the exception on the first extend/prefill forward, so the server never becomes ready. 

### Reproduction

Launch sglang with the DeepEP v2 MoE all-to-all backend on an FP8 blockwise-quantized MoE model (e.g. DeepSeek-R1), then send a request that triggers prefill/extend:

```
python -m sglang.launch_server \
  --model <deepseek-r1-fp8> \
  --tp-size 16 --ep-size 16 \
  --moe-a2a-backend deepep_v2 \
  ...
```

The first extend/prefill forward crashes all ranks with the TypeError above. (Also reproduces with smaller EP, e.g. --ep-size 2; the trigger is deepep_v2 + FP8 psum path, independent of decode.)

### Environment

- sglang version: v0.5.19 (0bcd822), also present on current main.
- Model: DeepSeek-R1 (DeepseekV3ForCausalLM, FP8 blockwise), num_experts=256, hidden_size=7168, intermediate_size=18432, topk=8.
- Hardware: 16× NVIDIA GPUs (2 nodes).

### dmvevents · 2026-09-26

Confirming on v0.5.20 (pip). Qwen3-30B-A3B-FP8, TP16/EP16 hybrid, `--moe-a2a-backend deepep_v2`, deep_ep 2.1.0, 2x AWS p5en.48xlarge (H200). Server starts fine; the first real prefill forward through `pre_permute_deepep_v2_to_deep_gemm` -> `ep_scatter_from_psum` fails with:

> TypeError: dynamic_func() missing 2 required positional arguments: 'expert_start' and 'num_experts'

BF16 is not a workaround: `is_fp8` only selects which scale tensor is passed; the same launch omits both args either way.

This is already fixed on main by #38160 (merged 2026-09-15, `406c9c71d833`): the callsite now passes `0, num_experts` (DeepEP v2 pre-rebases `recv_topk` to local expert ids) plus a `recv_x_scale_arg` specialization. v0.5.20 was published 2026-09-18 and does not contain it, so the latest release still ships the broken kernel.

A whole-file drop-in of main's `ep_moe_kernels.py` onto 0.5.20 is import-compatible; with it, the same setup served real traffic green at every rate we tested.

Ask: include the #38160 `ep_moe_kernels.py` fix in the next release (or a 0.5.20.x patch), and link this issue to #38160 so it can close when that ships.
