# [PR #41092] [HiCache] fix: Drain pending backups before internal Mamba write-back

source: https://github.com/sgl-project/sglang/pull/41092
state: closed | updated: 2026-09-25T07:14:23Z
labels: run-ci, run-ci-extra, unified-radix-cache, bypass-fail-fast

## 正文

## Motivation

Internal Mamba eviction can crash when an expanded SWA backup already covers the same ancestor under another ack. A successful Mamba backup commits its host slots and tries to register a new ack before waiting for the existing one, triggering `already pending under a different write-through ack`.

This is an existing Python-path issue following #40680. The shared fix is independent of the Rust port in #39627.

## Modifications

Drain outstanding backups before building and submitting an internal Mamba write-back. The helper already waits synchronously for backups; this establishes ack ownership before the new commit without changing the ack protocol.

Add a focused regression using existing insertion helpers and real Full+SWA+Mamba pools at page sizes 1 and 64. It constructs the overlapping ack, then verifies successful Mamba backup/eviction, ack cleanup, and cache invariants.

## Accuracy Tests

On GB300 with PyTorch 2.13.0+cu130:

- New regression on unmodified main `261cb826e6`: **2 failed**, both with the ack-conflict assertion.
- With the fix: **2 passed**, 17 configuration skips.
- `pre-commit run --files python/sglang/srt/mem_cache/unified_radix_cache.py test/registered/unit/mem_cache/test_unified_radix_cache_unittest.py`: passed.

```bash
PYTHONPATH=python CUDA_VISIBLE_DEVICES=0 python3 -m pytest -q \
  test/registered/unit/mem_cache/test_unified_radix_cache_unittest.py \
  -k internal_mamba_backup_waits_for_pending_swa
```

The Rust version of this internal-state eviction path is not yet implemented on main, so the new regression uses the same native applicability guard as the existing internal-Mamba write-back test. No model-level accuracy run was performed. Pytest reported the environment's missing `asyncio_mode` plugin warning and PyTorch JIT deprecation warnings.

Based on main `261cb826e6`.

## Speed Tests and Profiling

No benchmark run. The change is limited to the already synchronous internal-state write-back path. An existing backlog is drained before the new backup instead of only afterward.
