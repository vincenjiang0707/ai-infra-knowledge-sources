# [PR #41044] [RL] Stream LoRA adapter weights through the weight-update session

source: https://github.com/sgl-project/sglang/pull/41044
state: open | updated: 2026-09-25T07:06:03Z
labels: lora, run-ci

## 正文

## Motivation

RL training that fine-tunes LoRA adapters needs to push adapter weights into the rollout engine on every step, alongside or instead of base weights, without a second transport, without a full reload, and without serving a half-written adapter. On main the only route is `load_lora_adapter_from_tensors`, which is a separate whole-adapter IPC call outside the weight-update session.

## Modifications

- **Streamed adapter updates.** `POST /register_lora_adapter` (also `Engine.register_lora_adapter`) creates or refreshes an adapter's identity and config with zeroed weights. The weights then travel as `{lora_name}:{hf_key}`-prefixed tensors in the ordinary `update_weights_from_{tensor,distributed}` stream: the scheduler stashes them for the session and applies each adapter whole at `end_weight_update`, verifying an optional `expected_lora_checksums` manifest (name set + sha256). `begin_weight_update(sync_base=False)` opens an adapter-only session that skips the base unpack/finalize and rejects base tensors.
- **Staged publication.** `register_lora_adapter(defer_publish=True)` keeps a fresh name unservable until its session commits; such sessions take the reader lock and run alongside generation, `end_weight_update(abort=True)` discards the stash and the pending identities, and requests may carry `lora_backfill_paths` so a fresh engine serves a published adapter from disk.
- **Lease lifecycle.** Every terminal path of a request releases its LoRA lease exactly once (`_finalize_lora_lease`), the registry distinguishes reloadable (disk-backed) from wire-only adapters, and over-cap eviction is one helper (`_evict_lru_over_cap`).
- `weight_updater.py`: the session struct gains `sync_base` and `pending_version`; the version reported by buckets is recorded only when the session commits.
- Tests: `test_lora_stream_update.py`, `test_lora_staged_publication.py`, `test_lora_lease.py`, `test_lora_upsert.py` (CPU units) and `test_lora_load_from_tensor.py` (e2e, now through the stream).

Squash of sglang-miles #27268, #31759, #30913, #33299, #36384, #38165, rebased onto the `_WeightUpdateSession` design of #40777 (authors credited as co-authors). Not carried over: `load_lora_adapter_from_distributed` / `upsert` (the intermediate API on sglang-miles, superseded by the stream). main's `load_lora_adapter_from_tensors` is unchanged.

Deliberately different from sglang-miles: an explicit `unload_lora_adapter` keeps the adapter's entry in the reload catalog (`lora_ref_cache`). sglang-miles made it a delete; main's dynamic-update contract (`test_lora_update`) is that a later request for an unloaded disk-backed adapter reloads it implicitly, and wire-only adapters are already refused by the `reloadable` check.
