# [PR #40894] [Fix] Resolve Inkling think-end IDs in ReasonerGrammarBackend and gate the canonical-schema bypass

## 正文

## Motivation

Follow-up to #40468 (merged). Two issues from review:

1. `ReasonerGrammarBackend.__init__` still resolved `think_end_ids` by encoding `think_end_token` as ordinary text. For Inkling the native `END_MESSAGE` id (200010) differs from its printed-spelling encoding, so every grammar that keeps the wrapper — strict thinking mode, and non-canonical constraints (json_schema / regex / modified structural_tag) with reasoning enabled — never observes think end and stays in the thinking phase. #40468 fixed the scheduler's `model_config.think_end_ids`, but `create_grammar_backend` only uses that value as a construction gate; the constructor re-encoded the marker on its own.

2. The canonical-schema bypass matched schema content alone, so a byte-identical user-supplied `structural_tag` response format would bypass reasoning deferral regardless of the model's reasoning detector.

## Modifications

- Resolve `think_end_ids` via `reasoning_parser.detector.get_think_end_token_ids(tokenizer)` (the hook #40468 added) in `ReasonerGrammarBackend.__init__`.
- Gate the canonical-schema bypass on the Inkling reasoning detector, and build the canonical schema once as a lazy module constant instead of reconstructing it per dispatch (the lazy import stays: `function_call.inkling_detector` imports xgrammar unconditionally, which XPU installs may not ship).
- Tests: the backend resolves the native `END_MESSAGE` id and the wrapper transitions on it in both strict and non-strict mode; the canonical schema with a non-Inkling detector still defers until reasoning ends (folded into `test_other_grammars_still_defer_until_reasoning_ends`).
