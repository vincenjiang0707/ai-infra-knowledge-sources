## 正文

## Motivation

Integration PR of the DeepSeek-V4.1 AMD (gfx950 / MI350X) series. It follows the CUDA dsv4.1 layout (#39646, #39652, #39653, #39656, #39664, then #38798): kernel PRs by domain with no callers, then this PR with the callers. With it, DeepSeek-V4.1-Flash serves on gfx950 with DSpark.

**This branch carries the unmerged kernel PRs #41019, #41020 and #41021 (#41018 is merged). Review only the last commit.**

## Modifications

- **Attention.** `deepseek_v4_backend_hip_radix.py` serves V4.1: the compact V4.1 KV pages through `compact_attention_hip` (#41020), the swap-AB Gluon kernel for small decode batches, DSpark draft and target-verify metadata, and breakable-CUDA-graph prefill. `dsv4/low_ratio_backend_hip.py` orchestrates the ratio-1 / 2 indexer, like main's `dsv4/v41_indexer`: FlyDSL fp4 paged MQA logits over the split index-K pools (#41019), then the candidate-block and sorted top-k kernels (#41020). `hip_flash_mla.py` routes the HIP decode kernels (`SGLANG_HACK_FLASHMLA_BACKEND=auto`: aiter's sparse kernel on gfx950, tilelang elsewhere).
- **Dense fp8.** `fp8_hip.py` serves 32x32-block fp8 checkpoints as MXFP8 on the gfx950 native route (#41018); the RMSNorm, SiLU and wo_a producers hand it fp8-grid or MXFP8 operands (`deepseek_common/amd/deepseek_v4_gfx95_dense.py`, `deepseek_v2_hip_act.py`).
- **mHC.** `deepseek_v4_fused_mhc.py` runs each sublayer boundary as one launch, with its Sinkhorn carried by the next RMSNorm, and the TP4 all-reduce fused with the mHC post for decode batches of 1-8 rows (#41021).
- **MoE and Engram.** The split-K router GEMV and gate for DeepSeek-V4 gates (#41019). Engram's all-reduce and reduce-scatter add BF16 rows as int32 on ROCm, so they are bit-exact.
- **Other.** DSpark runs on HIP. `SGLANG_OPT_USE_AITER_BATCHED_GEMM` now defaults to on for ROCm.

The ROCm code lives in `models/deepseek_common/amd/` and the HIP backend files. `deepseek_v4.py` and `deepseek_v2.py` call into it only on HIP.

### Changes visible off ROCm
Each of these is a no-op for CUDA / NPU:
- `deepseek_v4.py`: `q=`, `inv_rope=` and `router_logits_partials=` are passed only when set. The hc_mix gate keeps CUDA's conditions. The three input-norm sites keep their gfx95-only fp8 quant, so gfx1250 is unchanged.
- `breakable_cuda_graph.py`: weak-ref'd NamedTuple arguments keep their type (a NamedTuple still indexes as a tuple).
- `dspark_draft_model.py`: the stacked-dequant path requires a 2-D weight.
- `deepseek_v4_backend.py`: the split index-K store is taken only when the pool reports the split layout, which is HIP only.

## Tests

- **Tests.** Runtime tests sit with their subsystem, as in #38798: the HIP backend, fused-compress and aiter_sparse backend tests in `attention/unittests/dsv4/`; the wo_a, MoE, fused-mHC and TP4 torchrun model tests in `unit/models/`; kernel cases live in the kernel PRs. All pass on MI350X on this branch with the kernel PRs' tests; the TP4 test compares fused and unfused mHC outputs eagerly (registered-buffer copy-in) and under graph replay.
- **End to end.** DeepSeek-V4.1-Flash, 4x MI350X, TP4 / EP4, DSpark, `--attention-backend dsv4 --kv-cache-dtype fp8_e4m3 --page-size 256 --disable-radix-cache`, `AITER_BF16_FP8_MOE_BOUND=0`. The comparison is back to back on one node against this series' previous integration head (3e8187fa88, kept as `dsv41-amd-4-model-old-stack`), same flags, `--cuda-graph-max-bs-decode 128`. The old head aborts in aiter's `_varctx_cta_info_kernel` when it captures decode graphs above 128; #41019's in-tree schedule fixes that.

  This PR's numbers are from the current head (e8d0b1e653); GSM8K is five runs.

## Deployment note

Set `AITER_BF16_FP8_MOE_BOUND=0` until ROCm/aiter#5802 is in the aiter pin. At the default bound, small batches take aiter's BF16-activation MoE route, which does not apply `swiglu_limit`.

## Not in this PR
- `deepseek_v4_backend_hip_radix.py` is over 3k lines. Splitting out the late-layer tail and breakable-prefill sections, and binding more CUDA backend methods instead of HIP copies, are follow-ups.
