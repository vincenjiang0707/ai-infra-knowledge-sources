# [PR #40981] [Fix] MiMo-V2: attend sliding_window_size keys in SWA layers

## 正文

## Summary
MiMo-V2 SWA layers and the runner now share a 128-key window that matches the HF reference.

## Symptom & Reproduction
- **Symptom:** each SWA query attends one more key than the HF implementation. On MiMo-V2.6-Flash-RL (BF16, TP8), token-weighted prefill NLL over 8 reasoning traces of 4466–7628 tokens was 0.47393 with 129 keys and 0.47360 with 128; 128 keys scored lower on 6 of 8 texts.
- **Reproduction:** score a text longer than 128 tokens with HF eager attention, then with SGLang prefill; expected: matching SWA outputs; observed: they diverge from the 129th token on, and on a 4-layer partial 0.35% of rollout tokens differed from the trainer's log-probs by more than 2 nats (max 19.6).

## Root Cause
1. `config.sliding_window_size` (128) counts keys including the query token in the HF reference.
2. `RadixAttention` excludes the query, so gpt-oss and Gemma3 subtract 1 in `get_attention_sliding_window_size`.
3. `MiMoV2DecoderLayer` and `MiMoV2MTPLayer` passed `config.sliding_window_size` unchanged, giving 129 keys.
4. MiMo-V2 had no `get_attention_sliding_window_size`, so `resolve_sliding_window_size` gave the runner 128 too.

## Fix
Follow the gpt-oss / Gemma3 convention: a module-level `get_attention_sliding_window_size(config)` returns `sliding_window_size - 1`, both SWA layer types use it, and `MiMoV2ForCausalLM` exposes it as a method that `MiMoV2MTP` and `MiMoV2FlashForCausalLM` inherit. The runner-level window now equals the per-layer window (127). It drives SWA eviction in the scheduler and the tree/chunk caches, the FA3 SWA metadata and the flashinfer/triton window buffers, so SWA eviction keeps exactly the 127 previous tokens a query needs. KV pool sizing, which reads `model_config.sliding_window_size`, and global layers are unchanged.

## Verification
- `pre-commit` on both files at this head: passed.
- `resolve_sliding_window_size` with the MiMo-V2.6 config on the sglang-miles tree with the same patch (#40977): 127 for `MiMoV2ForCausalLM` and `MiMoV2MTP`, 128 before this change.
- Live-slot check in `FlashAttentionBackend.init_forward_metadata` (4-layer partial, TP4 FA3, `SGLANG_SWA_EVICTION_INTERVAL=1`, overlap off, radix or chunk cache): every query's 127 previous keys had a live SWA slot; requiring 128 flagged exactly the key at distance 128.
- The NLL comparison above ran on the sglang-miles tree with and without the per-layer change.
- Not re-run on a GPU against this `main` head; the full-model NLL was not repeated after the runner-level change.

## Review Focus
- `get_attention_sliding_window_size`: the runner-level window drops to 127, so SWA eviction now keeps exactly the 127 previous tokens.
- `sliding_window_size - 1`: changes outputs of every MiMo-V2 SWA layer, including inference-only use.
- `triton_backend.py`: decode builds its window buffer as `min(seq_lens, W)`, which looks one key short for `W = window - 1` as for gpt-oss and Gemma3; not changed here.
