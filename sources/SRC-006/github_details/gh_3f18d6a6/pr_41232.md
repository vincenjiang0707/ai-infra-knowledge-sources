## Motivation

DiffusionGemma currently rejects logprob requests. This enables callers to compare candidate labels at an answer position using `return_logprob` and `token_ids_logprob`, without a custom response patch. First step toward the decision work in #39499.

## Modifications

- Return output-token and candidate-token logprobs from each request's final active denoising step, through the existing response fields.
- Preserve scores when requests finish at different steps; support synchronous/FDFO scheduling and normal streaming/truncation.
- Keep scoring in the dLLM paths. The shared scheduler only forwards the original request for validation.

Scores use raw logits normalized over the vocabulary. They are denoiser scores, not causal sequence likelihoods or calibrated decision probabilities. Prompt/top-k logprobs and the decision API remain out of scope.
