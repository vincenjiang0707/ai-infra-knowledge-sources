# [PR #34200] [AMD] Port CP V2 to the DeepSeek-V4 HIP backend

source: https://github.com/sgl-project/sglang/pull/34200
state: open | updated: 2026-09-25T07:36:16Z
labels: amd, deepseek, run-ci

## 正文

Enables DeepSeek-V4 CP-v2 on ROCm by aligning the HIP metadata and KV-cache paths with the strategy-based CP layout.

## Motivation

[#33532](https://github.com/sgl-project/sglang/pull/33532) enabled DeepSeek-V4 CP-v2 in the CUDA backend, but the HIP backend still built metadata for the unsplit layout. Enabling CP-v2 on ROCm therefore produced inconsistent query metadata and cache-write locations.

## Changes

- Port the padded query-metadata/global cache-write contract to the HIP backend and canonical `is_cp_active` flow.
- Build unified metadata before rank-local reindexing; exclude physical padding from KV-cache writes.
- Gather transformed KV in global logical-token order and avoid recomputing fused QK/RoPE output.
- Support CP draft-prefill metadata when compression fields are absent.
- Scope HIP prefill CP to single-node DeepSeek-V4 with the `dsv4` backend.

No attention kernel changes are required.

Both CP modes were verified to engage (`ATTN_CP0..7`), and `Enable CP decode attention TP` appears on all 8 ranks only in the third mode. All requests completed in every point. The DSpark-5 C16 row is the mean of two independent repeats (64 requests each); the C16 point in the first sweep was an outlier and was discarded.

`--enable-cp-decode-attn-tp` turns the CP decode penalty (+2% to +37% TPOT) into a gain (-3% to -16% TPOT), lifts output throughput above plain TP8 by 10-20% at C16-C48, and leaves CP's 27-35% TTFT reduction intact. The residual deficit at C1 (-2% to -6%) is expected: at batch 1 decode is launch-latency bound, so the per-forward slice/restore bookkeeping is not amortized.

#### Note on the C1 TTFT sign above

In the earlier table, CP8 mean TTFT at C1 is +26.9% vs TP8 while every higher concurrency is -27% to -31%. That C1 inversion is a warmup artifact, not a property of CP. Measured on the same server, cold (0 warmup requests) then warm (2 warmup requests):

| Mode | Cold TTFT (ms) | Warm TTFT (ms) | Cold/Warm |
|---|---:|---:|---:|
| TP8 (no CP) | 735.8 | 325.8 | 2.26x |
| PCP8 | 874.7 | 231.7 | 3.78x |
| PCP8 + decode-attn-TP | 898.5 | 236.0 | 3.81x |

CP carries an extra one-time initialization cost (first-call CP collectives, autotuning for the CP-split shapes), so its cold/warm ratio is ~1.7x that of plain TP8. Cold, CP is +18.9% vs TP8, reproducing the sign of the published +26.9%; warm it is -28.9%. Since C1 measures only two requests, that one-time cost cannot be amortized, which is why only C1 flips; higher concurrencies are unaffected.
