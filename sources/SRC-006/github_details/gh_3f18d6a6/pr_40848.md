## Motivation

This PR adds DPCache, a training-free step-skipping cache that uses an offline-calibrated schedule. It adapts [Denoising as Path Planning: Training-Free Acceleration of Diffusion Models with DPCache](https://arxiv.org/abs/2602.22654); the algorithm is credited to that paper.

A request carries a schedule of `K` full steps. Those steps run the whole transformer block stack. On every other step, DPCache extrapolates the final block feature from the two most recent full steps and runs only the output head, using the current timestep. Every scheduler update still runs and the weights are unchanged, so this is approximate inference, not distillation or a reduced-step sampler.

On Qwen-Image 2.1 (1024x1024, 40 steps, one RTX 5090), `K=20` is **1.97x faster end to end** with mean LPIPS 0.0076 against native output. That is 10.9% less time than the conservative Cache-DiT preset, with lower mean and max LPIPS. `K=12` is **3.21x faster**.

DPCache plugs in the same way as Spectrum and TeaCache: a mixin on `CachableDiT`. Any DiT can opt in; Qwen-Image 2.1 is the first. A schedule is calibrated per deployment, so the server owns the schedules and a request only picks a budget. A calibration tool builds the schedules.

```bash
# 1. calibrate once per checkpoint and request configuration
python -m sglang.multimodal_gen.tools.dpcache_calibrate record --model-path MODEL \
  --prompts-file prompts.txt --height 1024 --width 1024 --num-inference-steps 40 \
  --capture-dir captures
python -m sglang.multimodal_gen.tools.dpcache_calibrate plan \
  --capture-dir captures --budgets 12 20 --out-dir schedules
# 2. serve; requests pick a budget with dpcache_budget, or use the default
sglang serve --model-path MODEL --dpcache-schedule-dir schedules --dpcache-default-budget 20
```

## Modifications

- `runtime/cache/dpcache.py`: a BF16 first-order predictor and per-request, per-CFG-branch state. Also PACT calibration costs, an exact DP planner over anchor pairs, and a versioned JSON schedule. The schedule records the checkpoint, scheduler class and config, timesteps and sigmas, resolution, guidance, attention backend and dtype, and a request that doesn't match it is rejected before denoising.
- Schedules belong to the deployment. `--dpcache-schedule-dir` loads the schedules a server serves and checks them against its pipeline, checkpoint and attention backend at startup, so a schedule built for another deployment fails the launch. A request sets `dpcache_budget: K` and the server picks the schedule with that budget calibrated for the request's resolution, step count, scheduler, guidance and dtype. If none fits, the request fails. `--dpcache-default-budget` applies to requests that set no budget and falls back to native where no schedule fits, and `dpcache_budget: 0` opts a request out. `sglang generate --dpcache-budget` and the image/video APIs (extra field) accept the budget.
- `DPCacheMixin` on `CachableDiT`: to opt in, a model sets `_supports_dpcache = True` and routes its block stack through `self.dpcache_blocks(run_blocks)`. The output head stays outside the callable. The model takes no extra arguments; the hook reads the current step and the branch's state from the forward context.
- `DenoisingStage.forward`: checks scope, selects the schedule, attaches fresh state for each CFG branch (`Req.dpcache_states`), and clears it after success or failure. Requests that use no budget take the native path unchanged. A requested budget outside the supported scope fails explicitly; only the server default falls back to native.
- DPCache requests are excluded from dynamic batching: a merged request carries several prompts, and DPCache is calibrated for one. Warmup requests run natively because they use fewer steps than any calibrated schedule.
- Qwen-Image 2.1: `_supports_dpcache = True`, and the block loop moves into `_forward_blocks` without changes.
- Calibration tool (second commit), `python -m sglang.multimodal_gen.tools.dpcache_calibrate`:
  - `record` runs a prompts file natively with the new `dpcache_calibration` request field. The worker scores prediction errors online from each step's final block feature and writes one small capture per prompt; features never leave the worker. It can be sharded across GPUs and resumed.
  - `plan` averages the captures and writes one `K{n}.json` schedule per budget into the directory the server serves.
  - Online and offline scoring share one routine. `dpcache_calibration` writes a file on the worker, so the HTTP APIs do not accept it.
  - Also in this commit: the worker bootstrap's early-import warning no longer reports namespace packages. They run no code, and `python -m sglang.multimodal_gen.tools.<tool>` imports `sglang.multimodal_gen.tools` in every spawned child.
- Docs: `dpcache.mdx` covers scope, the schedule format, the calibration API and how to add a model, and it is listed in the caching overview.

Supported scope for now: BF16, single-image text-to-image, one GPU, eager execution. The following are rejected: CFG, reference images, LoRA, dual-transformer models, torch compile or CUDA graphs, SP/TP/CFG parallelism, and combining DPCache with Cache-DiT, TeaCache, Spectrum, skip-softmax or attention-backend overrides. No calibrated schedule ships with this PR, because a schedule is bound to one checkpoint and request configuration. Operators build one per configuration with the calibration tool.

Review feedback is especially welcome on the serving API (server-owned schedules plus a per-request budget) and on the mixin hook as the integration point for more models.

## Accuracy Tests

- `test_dpcache.py`, `test_dpcache_calibrate.py` and the DPCache cases in `test_qwen_image21_cuda.py`: **158 passed**. The related regression tests (Qwen-Image 2.1, sampling params, SenseNova-U1 scheduler batching, Spectrum, MiniMax-H3 denoise loop, worker bootstrap), each file run on its own: **181 passed**.
- Requests without DPCache produce output identical to upstream `1d59ce7c9`: 8/8 final latents, decoded tensors and PNG bytes match on a real Qwen-Image 2.1 checkpoint.
- End to end on a real Qwen-Image 2.1 checkpoint:
  - The calibration tool, run on the 10 calibration prompts behind the schedules measured below, reproduced them exactly: identical full steps and calibrated costs for every budget from `K=12` to `K=39`. Recording took 2 min 53 s on one RTX 5090 including model load, and the 10 captures total 5 MB.
  - Serving those schedules from `--dpcache-schedule-dir` reproduced the measured held-out outputs bit for bit on 9 of 9 requests: `K=20` through the server default, `K=12` requested explicitly, and native through `dpcache_budget: 0`.
  - With the default budget, a 768x768 request (no schedule) ran natively. The same request with an explicit `K=20` was rejected with the available schedules listed.
- Quality with a schedule is reported in the table below.

## Speed Tests and Profiling

Setup: Qwen-Image 2.1 BF16 (revision `790c9263`), 1x RTX 5090 32 GB, torch 2.13, 1024x1024, 40 steps, guidance 1.0, `torch_sdpa`, eager, DiT layerwise offload. DPCache schedules were calibrated on 10 prompts, `K` was selected on 8 different prompts, and the Cache-DiT presets were tuned on those same 8. Every choice was frozen before one measurement on 20 fresh held-out prompt/seed pairs. The prompt sets are disjoint.

| Config | Transformer blocks / image | DenoisingStage | E2E | E2E speedup | LPIPS mean / max | PSNR mean / min |
| --- | --- | --- | --- | --- | --- | --- |
| native | 1280 | 13.26 s | 13.46 s | 1.00x | - | - |
| **DPCache `K=20`** | 640 | 6.63 s | 6.85 s | **1.97x** | **0.0076 / 0.035** | **41.5 / 28.2 dB** |
| Cache-DiT conservative | 710 | 7.47 s | 7.68 s | 1.75x | 0.0159 / 0.042 | 38.1 / 27.8 dB |
| uniform `K=20` (ablation) | 640 | 6.63 s | 6.85 s | 1.97x | 0.070 / 0.208 | 28.3 / 17.2 dB |
| **DPCache `K=12`** | 384 | 3.99 s | 4.20 s | **3.21x** | **0.085** / 0.220 | **27.6** / 17.1 dB |
| Cache-DiT stock | 443 | 4.77 s | 4.98 s | 2.71x | 0.102 / 0.176 | 26.2 / 20.7 dB |
| uniform `K=12` (ablation) | 384 | 3.99 s | 4.20 s | 3.21x | 0.155 / 0.280 | 22.3 / 16.2 dB |

- `K=20` takes 10.9% less time than conservative Cache-DiT and is closer to native on every quality column. `K=12` takes 15.6% less time than stock Cache-DiT and has the better mean, but a worse worst case (LPIPS max 0.220 vs 0.176).
- The uniform ablations keep DPCache's budget, first three steps and last full step, and spread the other full steps evenly. They take the same time and are clearly further from native, so the gain comes from the calibrated placement, not only from the budget.
- DenoisingStage is device time averaged over the 20 held-out images. E2E is client wall-clock for a warm generation (encode, denoise, decode, offload transfers), from interleaved paired runs over 4 held-out prompts. Speedup is the paired mean.
- LPIPS (AlexNet) and PSNR compare each image with the native output for the same prompt and seed, after compositing on white.
- With layerwise offload, predicted steps loaded no block weights, and peak memory rose by 154 MB (0.6%). Time scales almost linearly with `K`, because a predicted step costs only the per-step preparation and the output head.
- A low mean LPIPS does not guarantee that every image is preserved. `K=12` rearranged the chairs in a counting prompt and changed the lettering on a sign. `K=20` stayed visually close on every held-out pair.
- One-time cost: about 3 GPU-minutes of calibration per checkpoint and request configuration (10 prompts), plus choosing `K` on a separate validation set.

The benchmark harnesses, frozen corpora, published schedules, the full report and worst-case galleries are in [`fractalyze/sglang@experiment/qwen-image21-dpcache`](https://github.com/fractalyze/sglang/tree/experiment/qwen-image21-dpcache/benchmark/experiments/qwen_image21_dpcache). That branch is not part of this PR. It stacks on an earlier revision of this PR (`2754e6ecf`) that passed the schedule with each request. The inference path is the same, and the served-schedule outputs above are bit-identical to those measurements.
