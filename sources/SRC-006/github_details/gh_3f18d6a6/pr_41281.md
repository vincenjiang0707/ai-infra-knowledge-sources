# [PR #41281] [mem_cache] Replace `cache_finished_req` with `insert_req`; `release_kv_cache` frees and unpins

source: https://github.com/sgl-project/sglang/pull/41281
state: closed | updated: 2026-09-27T09:53:19Z
labels: documentation, hicache, run-ci, run-ci-extra, unified-radix-cache, memory-pool, bypass-fail-fast, parallel-stages

## 正文

- `cache_finished_req(req, *, owned_kv_len)` -> `insert_req(req, *, up_to)`: the tree only inserts and advances `cache_protected_len`; it no longer frees slots or drops the lock
- `release_kv_cache` does the release on both paths: optional `insert_req`, then free `[cache_protected_len, owned_kv_len)`, the over-allocated tail, `unpin`, `on_release`
- `register_session_ref(req, leaf=...)` takes the leaf the insert ended on instead of reading `req.last_node`, which now stays the lock anchor until `unpin`
- Tests: tree-level finish calls go through `finish_req` (`sglang/test/mem_cache_utils.py`) or `release_kv_cache`; stale `cache_finished` test names renamed
- No behavior change; stacks on #41312
