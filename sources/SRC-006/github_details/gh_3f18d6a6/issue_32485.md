### Motivation

`RunaiModelStreamerLoader` currently passes every safetensors shard to RunAI when loading an MTP/NextN speculative draft model. Draft tensor filtering happens only after `runai_safetensors_weights_iterator()` has opened the shards and started producing tensors.

For a large sharded target checkpoint with bundled draft weights, the draft worker therefore scans and opens all target-model shards even though it needs only one requested MTP layer and draft-wide shared parameters. With object storage this also causes unnecessary remote header reads and increases startup I/O and file-descriptor pressure.

SGLang already downloads `model.safetensors.index.json` into the object-storage metadata cache before worker startup. The RunAI loader should use that index to select the shards containing the requested draft layer before constructing the RunAI iterator.

The selection should support checkpoint layouts seen in practice:

- Native DeepSeek keys such as `mtp.<index>.*`.
- Hugging Face-style keys such as `model.mtp.layers.<index>.*`.
- Draft-wide parameters under the MTP namespace that are required by every draft layer.

If the index is missing, malformed, or uses an unknown layout, loading should safely fall back to all shards.

### Related resources

- RunAI Model Streamer loader: `python/sglang/srt/model_loader/loader.py`
- Safetensors shard mapping: `model.safetensors.index.json`
- Related object-storage draft metadata preparation is tracked separately because it applies before shard selection.
