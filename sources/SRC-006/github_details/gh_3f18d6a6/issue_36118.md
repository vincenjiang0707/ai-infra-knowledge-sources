### Describe the bug

Updating SGLang from main commit `db2eb47500c54be4934d7efbdad57864999216e8` to main commit `95f5ecd3d26665423d3e6577a2a00c04f5cde733` consistently increased cold TTFT by approximately 3.1% at both 10K and 60K input lengths on a single RTX PRO 6000 Blackwell, while decode throughput and DFlash2 acceptance were effectively unchanged.

The target is `orcarouter/Qwen3.8-27B-Uncensored-FP8` at revision `21411e351948ec029617fa3c9833adcb2ad25da9`. The draft is `z-lab/Qwen3.8-27B-DFlash2` at revision `50307d4c4cde6860d4eee73e2547cd786fe8e8a4`, which is byte-identical to the corresponding `incoai` draft according to the current Qwen3.8 DFlash2 submission.

Both SGLang revisions reached readiness, retained the full 262,144-token pool, returned a successful chat completion, and completed all benchmark requests without a server error. The newer revision was rolled back after the matched comparison.

#### Median of three measured runs

| Input | SGLang commit | TTFT | Decode | End-to-end | Accepted span |
|---:|---|---:|---:|---:|---:|
| 10,000 | `db2eb475` | 1.087 s | 168.0 tok/s | 2.605 s | 4.49 |
| 10,000 | `95f5ecd3` | 1.121 s | 167.8 tok/s | 2.641 s | 4.49 |
| 60,000 | `db2eb475` | 8.771 s | 124.6 tok/s | 10.797 s | 3.61 |
| 60,000 | `95f5ecd3` | 9.043 s | 124.7 tok/s | 11.045 s | 3.61 |

This is a +3.1% TTFT regression at both input lengths. At 60K, median end-to-end latency increased by approximately 2.3%. The unchanged accepted spans and decode rates suggest the difference is in prefill/first-token work rather than DFlash2 verification quality.

Benchmark protocol:

1. Construct exact token-ID prompts of 10,000 and 60,000 tokens with the target tokenizer.
2. Flush the SGLang radix cache before every request through `/flush_cache`.
3. Send requests to `/generate` with `temperature=0`, `max_new_tokens=256`, `ignore_eos=true`, and streaming enabled.
4. Use one warm-up followed by three measured requests per input length.
5. Use the same fixed per-run prompt nonces for both revisions.
6. Calculate TTFT from request start to the first streamed completion token. Calculate decode rate as the remaining 255 tokens divided by `end_to_end - TTFT`. Report medians of measured runs.
