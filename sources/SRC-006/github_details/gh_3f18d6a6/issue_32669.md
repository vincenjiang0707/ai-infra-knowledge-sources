# [Issue #32669] [Bug] DeepSeek-V4 non-EP TBO uses TP-wide metadata and combine for attention-TP > 1

## 正文

## Summary

DeepSeek-V4 non-EP two-batch overlap (`--enable-two-batch-overlap` with `moe_a2a_backend=none`) accepts DP-attention topologies where `attn_tp_size > 1`, but its variable-length gather/combine metadata is only valid when `attn_tp_size == 1`.

For TP16/DP4 (attention TP4) or TP16/DP2 (attention TP8), `_forward_layers_tbo` gathers each child padded length and its input IDs across the full TP group. Each DP shard is therefore represented once per attention-TP rank. `dp_reduce_scatterv_async` then uses those duplicated sizes in a full-TP reduce-scatter. Hidden rows and input IDs no longer map one-to-one to DP shards.

## Affected configuration

- DeepSeek-V4 or DeepSeek-V4-Pro
- `--enable-dp-attention`
- `--enable-two-batch-overlap`
- `moe_a2a_backend=none`
- `data_parallel_size > 1`
- `attn_tp_size > 1`
- PP1 and no prefill CP, so the DeepSeek-V4 TBO strategy is eligible

The existing non-EP TBO coverage uses TP8/DP8, where `attn_tp_size == 1`, so the duplicated-rank layout is invisible.

## Reproduction

Use revision `d92ba3c2665da4668fe9aa1ca998f3ab140f2553`, where the synchronous DeepSeek-V4 DP gather is coherent, on two hosts with eight GPUs each. Launch one process per host with TP16/DP4 and the same paths on both hosts.

```bash
export SGLANG_SHARED_EXPERT_TP1=1
export SGLANG_TBO_DEBUG=1

python3 -m sglang.launch_server \
  --model-path /shared/models/DeepSeek-V4-Pro-NVFP4 \
  --served-model-name deepseek-ai/DeepSeek-V4-Pro \
  --tensor-parallel-size 16 \
  --data-parallel-size 4 \
  --enable-dp-attention \
  --enable-two-batch-overlap \
  --enable-dp-lm-head \
  --nnodes 2 \
  --node-rank "$NODE_RANK" \
  --dist-init-addr "$HEAD_NODE:29500" \
  --kv-cache-dtype fp8_e4m3 \
  --moe-runner-backend marlin \
  --fp4-gemm-backend marlin \
  --chunked-prefill-size 4096 \
  --disable-flashinfer-autotune \
  --mem-fraction-static 0.85 \
  --context-length 2200 \
  --cuda-graph-max-bs 256 \
  --max-running-requests 256 \
  --disable-radix-cache \
  --host 0.0.0.0 \
  --port 8000
```

Send a deterministic prefill request:

```bash
curl -s "http://$HEAD_NODE:8000/v1/chat/completions" \
  -H "Content-Type: application/json" \
  -d "{\"model\":\"deepseek-ai/DeepSeek-V4-Pro\",\"messages\":[{\"role\":\"user\",\"content\":\"What is the capital of France?\"}],\"temperature\":0,\"max_tokens\":32}"
```

A single prompt with at least two input tokens is sufficient: the TBO preparer splits one sequence into two token chunks, and idle DP ranks remain eligible. `SGLANG_TBO_DEBUG=1` should log `TboForwardBatchPreparer.prepare` for the EXTEND batch.

A/B on the same revision and launch arguments:

1. Without `--enable-two-batch-overlap`: coherent response.
2. With `--enable-two-batch-overlap`: the non-EP TBO path uses duplicated TP-wide metadata and can return numerically corrupted output.
3. With the scoped gate below: coherent response through the synchronous fallback.

The reproduction is source-derived; a captured hardware A/B is pending.

## Root cause

`DeepseekV4Model._forward_layers_tbo` describes the child-length collective as DP-wide but uses `get_tp_group()`. At `attn_tp_size > 1`, adjacent ranks within each DP shard contribute the same child length and replicated IDs. The resulting `global_num_tokens_*` arrays contain one entry per TP rank rather than one entry per DP shard.

`dp_reduce_scatterv_async` is the symmetric full-TP combine and returns one distinct segment per global TP rank. It does not reconstruct and replicate one DP-local result across the attention-TP ranks as the synchronous combine does.

## Expected behavior

Non-EP DeepSeek-V4 TBO should either use DP/attention-TP-aware metadata and combine semantics or fall back to the synchronous path when `attn_tp_size > 1`.

## Minimal correctness fix

Gate only the non-EP TBO strategy in `DeepseekV4Model._can_run_tbo`, preserving EP/Mori TBO:

```python
and (
    not get_moe_a2a_backend().is_none()
    or get_parallel().attn_tp_size == 1
)
```

Full attention-TP-aware TBO support can be implemented separately from this correctness gate.
