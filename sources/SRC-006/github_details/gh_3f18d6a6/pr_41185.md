# [PR #41185] [sgl-router] Track input_ids forwarding outcomes per chat request

source: https://github.com/sgl-project/sglang/pull/41185
state: open | updated: 2026-09-25T07:30:50Z
labels: router, npu, run-ci

## 正文

The router tokenizes many chat requests, but only some of them get their `input_ids` forwarded to the engine. The rest are tokenized again by the engine. The only existing signal is `sgl_router_ingress_tokenize_errors_total`, which covers just one failure mode. There was no way to see what share of traffic is actually offloaded, or why the rest isn't.

## Modifications

New counter `sgl_router_input_ids_forwarding_total{model_id, outcome}`, booked exactly once per dispatched `/v1/chat/completions` request:

| `outcome` | Meaning |
|---|---|
| `forwarded` | Router-rendered `input_ids` replaced engine tokenization |
| `disabled` | Forwarding is off for the model (`--disable-input-ids-forwarding`, or no chat formatter) |
| `ineligible_multimodal` | The chat carries image, video, or audio content parts, which only the engine's multimodal processor can tokenize |
| `ineligible` | The forwarding guard excluded some other request shape (tools, non-string content, caller `input_ids`, template controls, ...) |
| `tokenize_failed` | Eligible, but ingress rendering failed (the same requests as `sgl_router_ingress_tokenize_errors_total`, which is kept) |

- A single `input_ids_forwarding()` decision drives both the outgoing body and the metric. It replaces the `chat_tokenization_failed` helper. Forwarding behaviour is unchanged.
- Multimodal is checked right after `disabled`, so a multimodal chat that also trips another guard books as `ineligible_multimodal`. Content arrays of only `text` parts stay `ineligible`.
- Grafana: new stacked "input_ids forwarding share by outcome" panel in the Cache & Load row.

```promql
sum by (outcome) (rate(sgl_router_input_ids_forwarding_total[5m]))
  / scalar(sum(rate(sgl_router_input_ids_forwarding_total[5m])))
```
