# [PR #40621] Fix multimodal feature offload races

## 正文

## Summary

Asynchronous multimodal offload can release a GPU source allocation while encoder reads or the host copy are still queued. A later embedding-cache miss can also read the CPU destination before the copy finishes, corrupting inputs and producing NaNs.

Record the consuming stream on GPU sources and lazily create one reusable completion event per worker. `general_mm_embed_routine` records that event after actual device-to-host copies. The worker submits offloads on the same execution stream, so the latest record also covers older CPU backups retained across prefill batches.

`_move_items_to_device` synchronizes the event before encoders prepare inputs on CPU or features move to a non-CUDA device. CUDA uploads enqueue a stream wait before the nonblocking copy. CPU readers of precomputed embeddings synchronize before concatenating them.

`general_mm_embed_routine` also accepts an optional per-modality `feature_dtypes` mapping. For opted-in modalities, it casts CUDA features before embedding-cache lookup, records the consuming stream before releasing the original allocation, and saves the prepared tensor in `item.feature`. Offload then retains the encoder-ready dtype for later chunks, including on an embedding-cache hit, avoiding repeated dtype conversion. This saved feature remains separate from the embedding cache. CPU features are unchanged, and callers that omit the mapping retain their existing feature placement, transport, and dtype behavior.
