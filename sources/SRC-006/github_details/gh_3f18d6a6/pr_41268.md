## 正文

Stacked on #41226.

Router tokenization runs on the request path and re-encodes the full chat history on each turn. This adds two opt-in settings to reduce that work:

- `--tokenizer-backend fast` uses fastokens for encoding while retaining HF decoding. Unsupported JSON tokenizers fall back to HF with a warning; `.model` tokenizers retain the tiktoken backend.
- `--tokenizer-l1-cache-mb N` enables a bounded prefix-tokenization cache. It reuses tokens up to a shared special-token boundary and extends the cache as conversations grow.

Defaults remain HF encoding with the cache disabled. The resolved backend and cache state are logged at startup; `/metrics` exposes those settings and cache lookup/token counters.

Validation adds token-ID parity checks across HF, fastokens, and cached fastokens, plus growing-conversation cache checks and CLI/metrics unit tests. Tokenizer-dependent checks require the pinned files in the local HF cache. After rebasing onto #41226: formatting, strict Clippy, and 1,016 passing tests.
