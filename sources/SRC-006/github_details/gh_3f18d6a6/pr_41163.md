# [PR #41163] [DSV4] Reserve the FULL logical page in the c4 indexer pool like its KV pool

source: https://github.com/sgl-project/sglang/pull/41163
state: open | updated: 2026-09-25T07:58:51Z
labels: deepseek, run-ci, run-ci-extra, memory-pool

## 正文

## Motivation

- DeepSeek-V4 registers one PD transfer buffer per KV sub-pool and per indexer pool. The NIXL connector assumes they all have the same number of pages: it takes the page count of the first entry and builds descriptor lists of that length for every entry.
- Since #39921 the compressed KV pools reserve one full logical page for the dummy page, while the c4 indexer pool still reserves a single physical page. Its entries are now shorter than the first one, descriptor preparation walks past the registered region, and prefill fails with NIXL_ERR_NOT_FOUND.
- Mooncake does not prebuild full-range descriptor lists, which is why it was not affected.

Pages per registered entry, flash layout (compress ratios 4/128, page size 256):

| entry | before #39921 | main | this PR |
| --- | --- | --- | --- |
| c4 KV (first entry, sets the slot count) | 33 | 36 | 36 |
| c4 indexer | 33 | 33 | 36 |
| c128 KV | 33 | 160 | 160 |

## Modifications

- (-) The c4 indexer pool sized itself with its own formula, one physical page above the token count.
- (+) The indexer pool reserves the same full logical page as the KV pool it pairs with, through the same page-count helper, so no registered entry is shorter than the first. A unit test checks the c4 KV and indexer entries agree (fails on main).

## Accuracy Tests

Not applicable: only reserved pages are added, live page addressing is unchanged.

## Speed Tests and Profiling

Not applicable: the indexer pool grows by three 64-token pages per layer at page size 256.
