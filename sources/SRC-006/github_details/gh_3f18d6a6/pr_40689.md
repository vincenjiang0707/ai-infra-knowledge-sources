<summary>What the series does</summary>

A router replica subscribes to each worker's KV topic **mid-stream**, so every
block already resident in the engine's radix cache is invisible to it — and
engines publish `BlockStored` only as they *insert*, so a prefix cached hours
ago is never re-announced. A cache-blind replica then scatters the prefixes the
warm replicas were keeping consolidated, degrading the **engines'** locality for
the whole fleet; a rolling update does that to every replica in turn. This
series makes a booting replica pull a tree snapshot from a warm sibling over
HTTP and graft it beneath its live delta stream. Off unless `--kv-peer-selector`
is set.

Supersedes #39750, which carried the same work as one branch on a stale base.

</details>

## What this change does

The config surface for peer bootstrap, and the registry a discovered peer set
lands in. Nothing watches EndpointSlices yet and nothing fetches a snapshot, so
an operator who sets the selector gets a validated config, a warning-free boot
and `sgl_router_kv_bootstrap_peers 0` — no behaviour changes here.

`PeerRegistry` exists because an empty peer set has two meanings and conflating
them is the failure mode. "The watch has not delivered yet" is routine — worker
discovery regularly wins that race — and treating it as "I have no siblings"
makes a joining replica give up before its peers are even known. It tracks
`synced` for that, and `ever_had_peers` for the other direction: an
EndpointSlice repack deletes the last slice before its replacement arrives, and
during a rolling update every sibling can be notReady at once, so a dip to
empty after siblings were seen is transient. Candidates come back shuffled so
simultaneous boots do not all stampede whichever peer sorts first.

The selector is rejected unless the router maintains its own radix tree and
finds workers through Kubernetes: with an external Indexer there is nothing to
graft into, and without EndpointSlices there is no way to find a sibling. Both
would otherwise be accepted and silently ignored, leaving cold boots with no
explanation. `--kv-bootstrap-timeout-ms` is bounded at 600s because
`Instant::now() + Duration::from_millis(n)` panics on overflow — an unbounded
value would abort the process at startup instead of failing to parse.

`sgl_router_kv_bootstrap_peers` plus its `_synced` companion make both readings
of a zero visible. An RBAC gap on the router's own Service — the likeliest
misconfiguration, since the existing worker Role already covers it
namespace-wide — shows up as `synced 0` that never becomes 1.
