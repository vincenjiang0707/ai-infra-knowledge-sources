# [PR #41413] [Bugfix] Preserve Pythonic sibling calls with unsupported dictionary keys

source: https://github.com/sgl-project/sglang/pull/41413
state: open | updated: 2026-09-27T10:39:27Z
labels: 

## 正文

## Motivation

An unsupported dictionary key in a Pythonic tool argument raises AttributeError during AST conversion and reaches the block-level handler. For example, `[search(query='first'), search(query={**other}), search(query='last')]` currently loses both valid sibling calls.

## Modifications

Validate dictionary keys before extracting their values. Dictionary unpacking, names, and expression keys now raise ValueError, so the existing per-call handler skips only the unsupported call. Literal dictionaries retain their existing conversion behavior.

## Accuracy Tests

Run locally on an Apple M5 MacBook Air, using Python 3.12:
- The new regression fails before the fix in all 8 subcases.
- Pythonic detector tests: 25 passed, 8 subtests passed.
- Full function-call parser test file: 251 passed, 59 subtests passed.
- Changed-file pre-commit hooks passed.

Coverage includes unpacking, tuple keys, name keys, and nested unpacking in both non-streaming and streaming parsing, with valid calls before and after the invalid call.
