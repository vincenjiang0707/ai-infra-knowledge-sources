# [PR #41065] Fix MUSA detection under torch.compile fullgraph

## 正文

## Motivation

`is_musa()` performs a lazy optional import of `torchada`. When called from a
`torch.compile(fullgraph=True)` region on a system without `torchada`, Dynamo
unwraps the `lru_cache` wrapper and attempts to trace the import. This causes an
`Unsupported: Import failure` instead of returning `False`.

## Modifications

- Move lazy MUSA detection into a private cached helper.
- Mark the public `is_musa()` function with
`torch.compiler.assume_constant_result`.
- Preserve process-lifetime caching without triggering Dynamo's `lru_cache`
warning.
- Add a CPU-only regression test covering fullgraph compilation when `torchada`
is unavailable.

Not applicable. This change does not affect model outputs.

### rumitdesai · 2026-09-25

> @rumitdesai shoudn't we do this for all lru_cache tagged functions as I see dynamo warnings for all of them, why does this one in particular cause an error ?

@DevashishLal-CB 
Good question. I audited the other `@lru_cache` uses. Dynamo emits this warning for every cached callable because it bypasses the cache and traces the wrapped function, but that warning does not itself imply a graph break. For example, cached predicates such as `is_hip()`, `is_cuda()`, and `is_npu()` trace successfully under `fullgraph=True`; `is_musa()` fails specifically because its traced body contains the optional `import torchada` which is causing dynamo to fail.

Also, I wanted this change to be surgical and only address the path that is not traceable by dynamo. Would you recommend a much broader sweep of such instances and include all of them in this PR?
