## Motivation

`_forward_with_allreduce_fusion` (`layers/layernorm.py`) hands the all-reduce, residual add and RMSNorm to `flashinfer_allreduce_residual_rmsnorm`. That call returns `(None, None)` when it does not take the batch, for example when an input is not contiguous, or when the workspace has to be (re)initialized on that call and initialization fails.

On that path the flashinfer branch fell through to the plain norm, with two effects:

- the partial sum the caller left for the kernel was never all-reduced;
- `post_residual_addition`, which had already been folded into the residual, was added a second time.

The aiter branch already has a correct fallback.

The caller's gate, `apply_flashinfer_allreduce_fusion`, only rules out an unavailable flashinfer comm API. So a decline can still happen after the gate has passed. It was not observed in a shipped configuration: warmup pre-initializes the workspaces.

The fallback assumes every rank of the group declines together. That holds for a non-contiguous input and for a setup that fails on every rank. A setup that fails on only some ranks still leaves the ranks in different collectives, as it did before this PR.

## Modifications

- `layers/layernorm.py`, when the flashinfer kernel declines:
  - all-reduce over the group the kernel reduces over: the attention-TP group when `use_attn_tp_group` is set, otherwise the group `deferred_post_experts_all_reduce` uses (the same choice as `resolve_fusion_group`);
  - then add the residual and apply the norm into a new residual tensor.

  Like the kernel, this leaves the input residual unmodified. The Eagle3 aux capture keeps a reference to it on the fused path.
- New CPU test `test/registered/unit/layers/test_layernorm_allreduce_fusion.py`. On a decline it checks that:
  - exactly one all-reduce runs, over the kernel's group (attention TP, MoE-TP, MoE-EP, and mergeable EP × TP → TP);
  - `post_residual_addition` is added once;
  - the input residual is left unchanged.

## Accuracy Tests

- **New test:** fails on the parent (9 failures: no all-reduce, numeric mismatches, mutated residual) and passes on this PR. The 20 related unit files pass, run one by one and together.
- **GPU, B200, Qwen3-30B-A3B-FP8 TP2:** fusion `auto` (resolves to MNNVL), 4 greedy requests × 32 tokens; text, token logprobs and top-5 logprobs compared. A per-process counter confirms both callers reached the forced decline (4,183 calls with `use_attn_tp_group=True` and 4,096 with `False` per rank):

| Run | Result |
|---|---|
| This PR, fusion disabled | reference |
| This PR, fusion on, kernel forced to decline | **identical** to the reference |
| Parent, fusion on, kernel forced to decline | garbage output ("honey honey honey …") |
| This PR, fusion on, kernel running normally | differs from the reference only by the fused kernel's own rounding, as before |

Rebased onto main `9dc4c5d891`: every commit's patch is unchanged, and the related unit tests pass on the new base. The GPU results above were measured on the previous base, `5bb850d536`.
