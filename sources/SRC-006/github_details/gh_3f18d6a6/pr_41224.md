## 正文

## Motivation

Since #31362 (Speculative Decoding with NGRAM support for XPU), `stage-a-test-1-gpu-xpu` fails on every PR and on `main`:

```
test/registered/unit/spec/test_ngram_corpus.py:12
  -> sglang/srt/speculative/cpp_ngram/ngram_corpus.py:9
  -> sglang/kernels/ops/speculative/ngram_corpus.py:8   import tvm_ffi
ModuleNotFoundError: No module named 'tvm_ffi'
```

`python/pyproject_xpu.toml` does not include `apache-tvm-ffi`, so the XPU CI image never installs it. CPU CI (`base-a-test-cpu`) runs the same test and passes.

Example on `main`: https://github.com/sgl-project/sglang/actions/runs/35931860828/job/107420144221

Split out of #41075 (part 1/2). Dynamic XPU test detection is in the companion PR.

## Modifications

1. Mark the XPU registration of `test_ngram_corpus.py` as `disabled=`. CPU registration is unchanged. Follow-up: add `apache-tvm-ffi==0.1.11` to `pyproject_xpu.toml` and re-enable once the NgramCorpus JIT build is verified on XPU.
2. Add the 12 per-commit XPU test files missing from the `main_package` path filter (`test/registered/e2e/xpu/**` as a glob; the 4 XPU `kv_canary` files explicitly).
3. Add the NgramCorpus kernel paths (`speculative/@(reconstruct_tree|ngram_corpus).py`, `jit/csrc/ngram_corpus/**`), which `main_package` previously excluded via `kernels`.

## Checklist

- [x] CPU registration untouched
- [ ] `stage-a-test-1-gpu-xpu` passes on this PR
