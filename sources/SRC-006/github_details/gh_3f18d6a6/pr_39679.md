## Modifications

Every non-scalar payload the embedded Rust server sends to the scheduler
(`input_ids`, `token_ids_logprob`, multimodal features and their per-item
metadata) now crosses the ring and the pyo3 boundary the same way: as a named
`Buffer` beside the msgpack scalar header. An inline buffer hands its Rust
allocation to numpy without a copy; a shm buffer hands over only its segment
name. This replaces two separate mechanisms, the columnar `input_ids` cell and
the rid-keyed multimodal result store, and deletes the store, its purge hooks,
and `take_mm_result`.

Two preparatory changes are included because the buffer work builds on them:
the POSIX shm helper is rewritten on `rustix` and moved to `utils`, and the
request FSM now runs `Tokenizing` before `Encoding` so the MM worker never
tokenizes.

### merrymercy · 2026-09-22

Reviewed at [602282f](https://github.com/sgl-project/sglang/commit/602282f000303a6d63c783102456cdc27fd05e16). The named-buffer handoff unifies Rust-to-Python scheduler ingress, and the inline Rust `Vec` -> NumPy transfer is zero-copy. These are the five remaining items I would address for correctness, performance, and simpler ownership/data flow:

1. **Preserve cancellation across worker handoffs.** [to_scheduler.rs:207](https://github.com/sgl-project/sglang/blob/602282f000303a6d63c783102456cdc27fd05e16/rust/sglang-server/src/tokenizer_manager/to_scheduler.rs#L207)

   If a client disconnects while its request is in the tokenizer or MM pool, `on_abort()` sends `AbortReq` before the generate request exists in the scheduler. The returning worker result is then submitted anyway, so cancelled requests consume GPU time and KV memory until completion. The new `abort_while_in_mm_pool_pushes_on_return` test explicitly expects this behavior.

   Please keep cancellation state shared between the abort path and the owned request, check it when a worker result returns and before scheduler submission, and drop cancelled requests with their buffers. This can preserve the single owned request without restoring the MM payload store. Update the test to assert no generate request is submitted after cancellation and its SHM is released; cover both worker stages.

2. **Keep SHM cleanup ownership through Python admission.** [lib.rs:104](https://github.com/sgl-project/sglang/blob/602282f000303a6d63c783102456cdc27fd05e16/rust/sglang-server/src/lib.rs#L104), [server.py:230](https://github.com/sgl-project/sglang/blob/602282f000303a6d63c783102456cdc27fd05e16/python/sglang/srt/rust_server/server.py#L230)

   `segment.into_name()` relinquishes Rust's unlink responsibility before Python successfully decodes/wraps the request. If header decoding raises, `drain()` continues without processing the buffers, and dropping the name-only `ShmBuffer` never unlinks its segment. Partial buffer conversion/wrapping failures need the same cleanup guarantee.

   Please retain a cleanup owner until an explicit successful handoff to the Python SHM wrapper, and clean up all buffers on rejection, including already-wrapped items if a later item fails. Successful handoff must keep the segment available until the TP receivers have opened it. Add malformed-header and partial-wrapping tests that verify no segments remain, plus a successful TP handoff check against premature unlinking.

3. **Make SHM exhaustion reach the inline fallback.** [shm.rs:39](https://github.com/sgl-project/sglang/blob/602282f000303a6d63c783102456cdc27fd05e16/rust/sglang-server/src/utils/shm.rs#L39)

   `ftruncate()` sets the length but does not reserve backing pages. On a full `/dev/shm`, `mmap()` can succeed and `copy_nonoverlapping()` can raise `SIGBUS`, killing the server before `place_features()` can fall back to inline buffers. This gap also exists in the previous Rust writer.

   On Linux, reserve pages before touching the mapping, following [Python's `posix_fallocate` handling](https://github.com/sgl-project/sglang/blob/602282f000303a6d63c783102456cdc27fd05e16/python/sglang/srt/managers/mm_utils.py#L1304). Propagate allocation failure through `Result` so the existing fallback runs. Inject `ENOSPC` or use an isolated small tmpfs to verify fallback preserves feature values and cleans up any partially created segments.

4. **Preserve zero-copy through the scheduler adapter.** [server.py:242](https://github.com/sgl-project/sglang/blob/602282f000303a6d63c783102456cdc27fd05e16/python/sglang/srt/rust_server/server.py#L242), [multimodal.py:300](https://github.com/sgl-project/sglang/blob/602282f000303a6d63c783102456cdc27fd05e16/python/sglang/srt/rust_server/multimodal.py#L300)

   Immediately after the zero-copy FFI handoff, `input_ids.frombytes(...)` allocates/copies the token buffer, `token_ids_logprob.tolist()` creates a list of Python integers, and `mm.meta.tobytes()` duplicates the metadata bytes. Inline features and M-RoPE retain their allocations through `torch.from_numpy()`.

   Please let scheduler token fields retain buffer-backed storage and adapt consumers that require list operations or mutation. Decode metadata from `memoryview(buffers["mm.meta"])` to avoid the extra bytes copy; decoding still creates metadata objects. Add tests using an actual Rust producer plus `recv_requests()`/`drain()` to check allocation sharing, values, and lifetime after request/server references are dropped. Local pointer/lifetime probes passed all 42 dtype/shape cases at `64c55e0`; the relevant FFI and adapter code is unchanged at this head.

   The SHM route separately copies the producer vector into SHM and clones in `materialize()`. Extending zero-copy through that whole route requires producing directly into SHM, keeping the mapping alive with the tensor, and coordinating unlinking across TP ranks.

5. **Remove the Qwen packing round trip.** [worker.rs:87](https://github.com/sgl-project/sglang/blob/602282f000303a6d63c783102456cdc27fd05e16/rust/sglang-server/src/multi_modality/worker.rs#L87)

   `driver::Output -> QwenPackedOutput -> MmEncodedEntry` discards the feature's original shape and reconstructs it from `t*h*w` and the vector length. Grid metadata also goes from `i64` tensors to `u32` grids and back to `i64`. The feature vector is moved, but these redundant schema conversions add assumptions and maintenance work.

   Please map the driver's output directly into the common encoded result: move the existing feature tensors, preserve their shape/dtype, carry hashes/offsets/positions, and translate supported auxiliary metadata once. Keep the Qwen-specific packed form at its parity binding if still needed. Verify unchanged feature values, grids, token spans, and M-RoPE against the existing Qwen parity tests.
