## 正文

## Motivation

Add an SM100 CuTe DSL kernel that fuses two BF16 GEMMs with the SiTU activation:

    gate = X @ W_gate.T
    up   = X @ W_up.T
    output = softcap(gate) * sigmoid(gate) * softcap(up)

The kernel accepts a packed [2 * intermediate_size, K] gate/up weight, accumulates both projections in FP32 TMEM, applies SiTU in registers, and writes one BF16 output tensor.

## Implementation Details

The kernel computes the gate and up projections together instead of launching two independent GEMMs, we split the packed `[2I, K]` weight into gate and up views, Load one activation tile and the corresponding gate/up weight tiles through the same pipelined TMA mainloop and issue two MMAs per K tile, reusing the activation tile for both projections. Gate and Up FP32 accumulators is kept in separate TMEM column regions. Other contributions include -

- Supports 1-CTA and 2-CTA Blackwell MMA paths.
- Pipelines gate weights, up weights, and activations with TMA.
- Uses the required TMEM ordering and load-completion fences before releasing
  TMEM.
- Provides explicit tactics covering CTA_M 64/128 and CTA_N 8/16/32/64/128.
- Uses reduced pipeline depths where required by the fused kernel's doubled A-side SMEM footprint.

## Accuracy Tests

The kernel is validated with:

- **FP32 reference:** Computes both projections with FP32 PyTorch matmuls, applies the SiTU formula in FP32, then converts the result to BF16.
- **Existing-kernel comparison:** Compares against two calls to the existing `cutedsl_bf16_gemm` kernel followed by SiTU.
- **All-tactic coverage:** Compiles and checks all 26 1-CTA and 2-CTA tactics, including CTA_M 64/128 and CTA_N 8/16/32/64/128 configurations.
- **Shape coverage:** Tests single-token, aligned, ragged, and larger token counts, including `T=1, 7, 8, 9, 16, 63, 64, and 128`.
- **Numerical tolerance:** BF16 results are checked with `rtol=2e-2, atol=0.25`.
