# [PR #41390] Fix MiniCPMV.__getattr__ to preserve chaining on delegated methods

state: closed | updated: 2026-09-27T03:31:49Z

## 正文

## Summary

`MiniCPMV` delegates every undefined attribute to the inner
`self.minicpmv` module, so `model.eval()`/`train()`/`to()`/`cuda()`
returned the inner module instead of the wrapper — breaking method
chaining. This wraps delegated callables so a result identical to
`self.minicpmv` is rewritten to `self`.

Two related corrections in the same spot:

- `__getattr__("minicpmv")` used to return `None`, which makes
  `hasattr(obj, "minicpmv")` wrongly return `True` before `__init__`
  assigns it; it now raises `AttributeError` as the protocol requires.
- The one-off `eval()` override in `MiniCPMV4_5` (a semantic no-op —
  `nn.Module.eval()` already returns `self`) is removed; the general
  wrapper covers chaining for all versions, including
  `MiniCPMV4_6ForConditionalGeneration`.

Continues the work from cjhgo's #7281, rebased and extended onto
current master.

## Testing

Extracted the `__getattr__`/`__call__` source from the modified file
via `ast` (the module can't be imported without the full sglang
runtime) and grafted it onto a stub wrapping a real `torch.nn.Module`.
Verified `eval()`/`train()`/`to()`/`float()`/`half()`/`cuda()` all
return the wrapper and mutate the inner module; `eval().train().eval()`
chains correctly; `load_state_dict` returns its `_IncompatibleKeys`
result untouched; non-callable attributes pass through by identity;
`hasattr(w, "minicpmv")` is False before init and True after;
`__call__` forwards to the inner module.
