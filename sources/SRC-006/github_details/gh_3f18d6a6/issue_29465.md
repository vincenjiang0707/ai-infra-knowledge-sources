## Context

PR #28688 converted IPC dataclasses to `msgspec.Struct` and added opt-in msgpack transport (`SGLANG_USE_PICKLE_IPC=0`). However, several fields still use `PickleWrapper` as a fallback, and pickle remains the default. This issue tracks the remaining work to make the IPC path fully msgpack-native.

---

### Task 1 — [P0] Make `mm_inputs` fully msgpack-compatible

The `mm_inputs` field on both [`TokenizedGenerateReqInput`](https://github.com/sgl-project/sglang/blob/267d165ad0/python/sglang/srt/managers/io_struct.py#L775) and [`TokenizedEmbeddingReqInput`](https://github.com/sgl-project/sglang/blob/267d165ad0/python/sglang/srt/managers/io_struct.py#L1124) is typed as `Optional[PickleWrapper]` and carries a pickled [`MultimodalProcessorOutput`](https://github.com/sgl-project/sglang/blob/267d165ad0/python/sglang/srt/managers/schedule_batch.py#L381).

**Why this is hard:** `MultimodalProcessorOutput` contains a list of [`MultimodalDataItem`](https://github.com/sgl-project/sglang/blob/267d165ad0/python/sglang/srt/managers/schedule_batch.py#L244), which can hold:
- `torch.Tensor` / `np.ndarray` features (handled by existing `enc_hook`/`dec_hook`)
- [`CudaIpcTensorTransportProxy`](https://github.com/sgl-project/sglang/blob/267d165ad0/python/sglang/srt/utils/cuda_ipc_transport_utils.py#L286) — an opaque CUDA IPC handle wrapper with internal state dicts, pool handles, etc.
- `model_specific_data: dict[str, Any]` — a catch-all dict that different model processors populate with arbitrary tensors/values

**Work needed:**
1. Convert `MultimodalDataItem` and `MultimodalProcessorOutput` from `@dataclass` to `msgspec.Struct`.
2. Tighten `model_specific_data` — either enumerate known keys or add a `Dict[str, Union[torch.Tensor, ...]]` annotation.
3. Change the field type from `Optional[PickleWrapper]` to its real type and remove the corresponding lines in `wrap_pickle_fields()`/`unwrap_pickle_fields()` on [`TokenizedGenerateReqInput`](https://github.com/sgl-project/sglang/blob/267d165ad0/python/sglang/srt/managers/io_struct.py#L861-L869) and [`TokenizedEmbeddingReqInput`](https://github.com/sgl-project/sglang/blob/267d165ad0/python/sglang/srt/managers/io_struct.py#L1148-L1154).

---

### Task 2 — [P0] Make `time_stats` fully msgpack-compatible

The `time_stats` field appears on:
- [`TokenizedGenerateReqInput`](https://github.com/sgl-project/sglang/blob/267d165ad0/python/sglang/srt/managers/io_struct.py#L859) — carries `APIServerReqTimeStats` or `DPControllerReqTimeStats`
- [`TokenizedEmbeddingReqInput`](https://github.com/sgl-project/sglang/blob/267d165ad0/python/sglang/srt/managers/io_struct.py#L1146) — same
- [`BatchTokenIDOutput`](https://github.com/sgl-project/sglang/blob/267d165ad0/python/sglang/srt/managers/io_struct.py#L1251), [`BatchStrOutput`](https://github.com/sgl-project/sglang/blob/267d165ad0/python/sglang/srt/managers/io_struct.py#L1326), [`BatchEmbeddingOutput`](https://github.com/sgl-project/sglang/blob/267d165ad0/python/sglang/srt/managers/io_struct.py#L1360) — carry `List[SchedulerReqTimeStats]`

**Why this is hard:** The time stats classes ([`ReqTimeStatsBase`](https://github.com/sgl-project/sglang/blob/267d165ad0/python/sglang/srt/observability/req_time_stats.py#L224)) are `@dataclass` hierarchies that hold:
- [`TraceReqContext`](https://github.com/sgl-project/sglang/blob/267d165ad0/python/sglang/srt/observability/req_time_stats.py#L229) / `TraceNullContext` — OpenTelemetry tracing contexts with custom `__getstate__`/`__setstate__`
- [`SchedulerMetricsCollector`](https://github.com/sgl-project/sglang/blob/267d165ad0/python/sglang/srt/observability/req_time_stats.py#L226-L228) / `TokenizerMetricsCollector` — Prometheus metric objects (not serializable; excluded via `__getstate__`)
- [`DisaggregationMode`](https://github.com/sgl-project/sglang/blob/267d165ad0/python/sglang/srt/observability/req_time_stats.py#L232) enum
- Cross-process time calibration logic in `__getstate__`/`__setstate__`

**Work needed:**
1. Convert `ReqTimeStatsBase`, `APIServerReqTimeStats`, `DPControllerReqTimeStats`, `SchedulerReqTimeStats` from `@dataclass` to `msgspec.Struct`.
2. Update all `time_stats` fields from `Optional[PickleWrapper]` to their real types.

### Task 3 — [P1] Flip `SGLANG_USE_PICKLE_IPC` default to `False`

[`SGLANG_USE_PICKLE_IPC`](https://github.com/sgl-project/sglang/blob/267d165ad0/python/sglang/srt/environ.py#L245) is currently `EnvBool(True)`. Once Tasks 1 and 2 are done, flip to `False` and fix any CI failures that surface. This can be done incrementally — run CI with `SGLANG_USE_PICKLE_IPC=0` to find breakages before flipping the default.

---

### Task 4 — [P2] Eliminate opaque type annotations in `_REQ_TYPES_WITH_OPAQUE_FIELDS`

 [13 struct types](https://github.com/sgl-project/sglang/blob/267d165ad0/python/sglang/srt/managers/io_struct.py#L2131-L2145) still use `Dict[str, Any]` / `List[Any]` fields, which forces them through whole-struct pickle wrapping in the msgpack path. For each type, tighten the field annotations to precise msgspec-compatible types so they can be removed from the registry.

---

### Task 5 — [P2] Make `customized_info` fully msgpack-compatible

The [`customized_info`](https://github.com/sgl-project/sglang/blob/267d165ad0/python/sglang/srt/managers/io_struct.py#L1243) field on `BatchTokenIDOutput` and [`BatchStrOutput`](https://github.com/sgl-project/sglang/blob/267d165ad0/python/sglang/srt/managers/io_struct.py#L1318) is typed as `Optional[PickleWrapper]` and carries arbitrary per-request metadata. Needs a concrete type annotation and msgpack serialization path.

---

### Task 6 — [P2] Make `mm_data_mooncake` fully msgpack-compatible

The [`mm_data_mooncake`](https://github.com/sgl-project/sglang/blob/267d165ad0/python/sglang/srt/managers/io_struct.py#L848) field on `TokenizedGenerateReqInput` is typed as `Optional[PickleWrapper]` and carries a pickled `Optional[List[{"url": MultimodalDataInputItem, "modality": Modality}]]` from `MMReceiverBase._extract_url_data`. Needs a concrete struct/type and msgpack serialization path.
