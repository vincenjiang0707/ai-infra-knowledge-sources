## 正文

> This PR was "stack 3/4" of the DeepSeek-V4.1 AMD series (#41018 to #41021). It now follows the CUDA dsv4.1 layout (#39646, #39652, #39653, #39656, #39664, then #38798): kernel PRs by domain, each on `main` with no callers, then one integration PR. This is the third kernel PR; it does not depend on #41018 or #41019.

## Summary
- `ops/attention/aiter_sparse_decode_reduce.py`: `aiter_sparse_split_reduce` combines the split-KV partials of aiter's gfx950 `pa_decode_sparse(..., skip_reduce=True)`, bitwise equal to aiter's own reduce, with the attention sink and an optional inverse RoPE of each head's tail.
- `ops/attention/dsv4/compact_attention_hip.py`: sparse decode attention that reads the compact V4.1 pages (528 B fp8 + ue8m0, 288 B e2m1 + e4m3) directly through aiter's gfx950 `_qkpv_fp8`, with main and extra slot ranges and 16-head groups.
- `ops/attention/dsv4/swapab_gluon_hip.py`: the 16-head swap-AB Gluon kernel for HIP, argument-compatible with the SM100 kernel (CDNA4 MFMA, bf16 hi + lo compensated PV). It reuses the SM100 module's `_load_v4`, which is plain Gluon; `swapab_attention` gains `inv_rope=None`.
- `ops/attention/dsv4/attn_glue_hip.py`: single-launch Triton replacements for the torch glue around the V4.1 sparse decode metadata, each bitwise equal to the torch expression in its docstring.
- ROCm AOT top-k (`deepseek_v4_topk.cu`, `sgl_kernel/top_k.py`): `sort_output` sorts each row's picks ascending with a block-wide bitonic sort, `-1` padding last; the selected set is unchanged. Strides below the wave width use lane shuffles and the rest LDS, so it is also right on 32-lane waves (gfx1250).
- `q_rope_store.py` on HIP rounds like the batched HIP RoPE kernel.
- `ops/attention/dsv4/candidate_blocks_hip.py`, beside main's `candidate_blocks.py`: the V4.1 two-level indexer's level-one block scores and top blocks, the top-k within the chosen blocks and the paged top-k sorted in the AOT epilogue, graph-safe.
- Model call sites are in the integration PR of this stack.

## Changes to existing kernels
- `decode_attention_sm100.py`: `swapab_attention` imports `partial_gluon` from `swapab_gluon_hip` on HIP; `_combine` compiles the inverse RoPE out when `inv_rope=None`, so SM100 output is unchanged. `decode_attention_sm100_gluon.py` is untouched.
- `q_rope_store.py`: the new branch is a HIP-only constexpr; CUDA arithmetic is unchanged.
- The top-k epilogue, op schema and declaration are ROCm-only (`setup_rocm.py`); with `sort_output=False` the kernel is the same, plus a 4 KB static LDS array. The wrapper always passes `sort_output`, so sgl-kernel must be rebuilt from this PR.

## Verification
- New tests: `test_swapab_attention.py` (SM100 and gfx950: fp64 reference over padded and poisoned pages, `-1` / out-of-range slots, sinks, graph replay, and the combine's inverse RoPE bitwise to `fused_rope_inplace`); `test_compact_attention_hip.py` (both packed layouts, a second cache, `-1` slots and a key-less row against a torch softmax with sink); `test_topk.py::test_deepseek_v4_topk_transform_sorted_output`; `test_dsv41_decode_glue_hip.py` (candidate blocks against main's `select_candidate_block_ids` with garbage past each row's reach, the sorted mapping, and the `attn_glue_hip` builders bitwise to their torch forms). `test_dsv4_q_rope_store.py` is now also registered for AMD.
- MI350X (ROCm 10.0.0, torch 2.11, triton 3.8, aiter at the Dockerfile pin): these tests pass on this branch. The top-k epilogue built from this source matches the installed op over 120 shapes (sorted rows bitwise, unsorted rows the same set) and compiles for gfx1250.
- With the integration PR's callers, DeepSeek-V4.1-Flash at TP4 / EP4 with DSpark serves and scores 0.900-0.905 on GSM8K (200 questions, two runs).
- [ ] Pending on an SM100 runner: `test_swapab_attention.py`, `test_dsv4_q_rope_store.py`.
