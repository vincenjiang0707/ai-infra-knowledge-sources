<summary>What the series does</summary>

A router replica subscribes to each worker's KV topic **mid-stream**, so every
block already resident in the engine's radix cache is invisible to it — and
engines publish `BlockStored` only as they *insert*, so a prefix cached hours
ago is never re-announced. A cache-blind replica then scatters the prefixes the
warm replicas were keeping consolidated, degrading the **engines'** locality for
the whole fleet; a rolling update does that to every replica in turn. This
series makes a booting replica pull a tree snapshot from a warm sibling over
HTTP and graft it beneath its live delta stream. Off unless `--kv-peer-selector`
is set.

Supersedes #39750, which carried the same work as one branch on a stale base.

</details>

## What this change does

Two thirds of the consumer's half of the wire contract, with no consumer yet:
the per-rank state that tracks a bootstrap, and the client that fetches a body
from a peer. The type that turns a fetched body into something graftable lands
next, and the pump that uses all three after that.

`BootstrapTracker` holds per-rank state and the outcome tallies. Its epoch is
per rank, not process-wide: a process-wide counter would let one worker's re-add
invalidate another worker's in-flight task. `RankOutcome` and `SnapshotOutcome`
are deliberately separate tallies — one counts ranks that finished bootstrapping,
the other counts peers that were asked — because a single peer answers for many
ranks and summing them together would make neither readable.

The answer latches. Once settled, a steady-state scale-up registering a fresh
`Pending` rank must not flip an already-serving replica back to 503 — the gate
exists to hold traffic off a *newly booted* replica, not to turn a cache
optimisation into an availability incident.

Three bounds on a fetch, not one. `reqwest`'s `timeout` is a TOTAL request bound,
so a single value has to serve two opposite jobs: cutting a peer that is gone,
and allowing a large body to finish. Sized for the first, it rejects every peer
whose snapshot is big enough to be worth having — the failure gets MORE likely
the warmer, i.e. the more useful, the fleet's tree becomes. So `connect_timeout`
cuts a peer that is gone, `read_timeout` cuts one that stopped sending mid-body,
and the total bounds only a transfer that is progressing.

`flate2` moves from dev-dependencies to dependencies for the inflate path, used
directly rather than through reqwest's `gzip` feature: that feature is crate-wide,
so enabling it would make every client in the process advertise gzip and
auto-decode — including the proxy client carrying SSE.
