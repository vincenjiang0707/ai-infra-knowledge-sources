## Motivation

<!-- Describe the purpose and goals of this pull request. -->

`enable_return_indexer_topk` currently supports the CUDA indexer path, but the NPU backend does not create an indexer-topk capturer or expose the top-k results produced by NPU attention indexers.

  Ascend NPU already provides indexer implementations for:

  - DeepSeek DSA models, through `torch_npu.npu_lightning_indexer`
  - DeepSeek-V4 C4 indexers, through `torch.ops.custom.npu_quant_lightning_indexer`

  However, their results were not connected to the existing request-level return pipeline. As a result, NPU inference requests could not return indexer top-k metadata even when `--enable-return-indexer-topk` and `return_indexer_topk=true` were specified.

  This PR connects the NPU producer paths to the existing indexer-topk capturer and response pipeline while preserving the same output format and layer-index semantics as the CUDA implementation.

## Modifications

<!-- Detail the changes made in this pull request. -->

- Enable indexer-topk capturer creation on both CUDA and NPU backends.
    - Model-specific layer counts continue to be resolved through `get_num_indexer_layers()`.
    - DSA models use one capturer slot per transformer layer.
    - DeepSeek-V4 uses one capturer slot per C4 compression layer.

- Add indexer-topk capture to the NPU DSA path.
    - Capture results from `forward_dsa_prepare_npu()`.
    - Cover both freshly computed top-k results and `skip_topk` layers that reuse the previous layer's result.
    - Preserve the transformer layer id in the capturer layout.

- Add indexer-topk capture to the NPU DeepSeek-V4 C4 path.
    - Capture the output of `npu_quant_lightning_indexer`.
    - Use `token_to_kv_pool.layer_mapping[].compress_layer_id` to map raw transformer layers to contiguous C4 capturer slots.
    - Keep the captured indices in the logical compressed-token coordinate system used by the NPU sparse attention path.

- Extend overlap result handling to NPU.
    - Reuse the existing `TopkCaptureOutput` and result-finalization pipeline.
    - Add NPU support to asynchronous device-to-host copies through `torch.get_device_module()`.
    - Preserve the existing synchronous path when overlap scheduling is disabled.

- Add unit tests covering:
    - NPU DSA capturer initialization.
    - DeepSeek-V4 C4 layer-count resolution.
    - Non-indexer models being disabled through a zero indexer-layer count.
    - Invalid `index_topk` configurations.
