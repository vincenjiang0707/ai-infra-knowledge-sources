<details>
<summary>What the series does</summary>

A router replica subscribes to each worker's KV topic **mid-stream**, so every
block already resident in the engine's radix cache is invisible to it — and
engines publish `BlockStored` only as they *insert*, so a prefix cached hours
ago is never re-announced. A cache-blind replica then scatters the prefixes the
warm replicas were keeping consolidated, degrading the **engines'** locality for
the whole fleet; a rolling update does that to every replica in turn. This
series makes a booting replica pull a tree snapshot from a warm sibling over
HTTP and graft it beneath its live delta stream. Off unless `--kv-peer-selector`
is set.

Supersedes #39750, which carried the same work as one branch on a stale base.

</details>

## What this change does

Nothing consumes this yet. It is the producer half of peer bootstrap: a
replica that already holds a warm tree makes it fetchable, so a sibling
starting later can graft it instead of routing cache-blind until traffic
re-stores every block the engines already hold.

`GET /internal/kv_snapshot` answers a `PeerSnapshot` — worker table, per-rank
cursors, and the tree. The cursors are half the payload's purpose: a graft is
only sound if the consumer can prove its own live stream resumes at
`cursor + 1`, so the body has to say where the producer's stream stopped.

`404` when this router maintains no local tree (an external Indexer is the
routing signal, or cache-aware routing is off). A consumer reads that exactly
as it reads an unreachable peer, which is also what an older router image
answers for an unknown path, so a mixed-version fleet degrades to cold boots
rather than errors.

Three things the endpoint refuses to claim. `producer_ready` is false unless
the tree is non-empty AND the hashing config is fully established: an empty
tree would let two replicas in a rolling update bootstrap off each other and
both inherit nothing, and a half-published config — `block_size` visible
before the bigram flag, a real window in `add_worker` — would stamp unigram
hashing on a bigram fleet and hand the recipient blocks it can never match.
`BlockSizeOracle::hash_config` is the both-or-neither read that closes it.

`?max_age_ms=N` lets the CONSUMER state its freshness requirement, because
only the consumer knows when its ranks began holding. Staleness is a
correctness input here, not a preference: an export older than the consumer's
subscribe leaves the events in between in neither place, and the graft has to
be thrown away. The build is single-flighted behind an async mutex and the
encoded body is cached, so a boot herd shares one tree walk; the entry is
stamped BEFORE the cursors are read, so it never claims to cover more of the
publisher's stream than it does.

`?cursors_only=true` answers the cursor table alone, read live with no cache.
A splice probe asks one question — is your cursor for this rank above my
watermark? — and paying a full tree export for it costs a walk, a
multi-megabyte serialise and a compress, per peer per probe. That table is
deliberately a SUPERSET of the export's, which is filtered to ranks still
carrying nodes: a graft recipient needs a block source, but a witness only
needs to have seen the publisher's stream. Its `nodes` is always empty, which
makes the body ungraftable by construction rather than by discipline.

The route carries its own gzip layer rather than the app carrying one. It is
the only response here big enough to be worth compressing, and route-scoping
means the proxy path pays no per-response predicate check and does not depend
on tower-http continuing to exempt `text/event-stream`. Quality is `Fastest`:
the body is highly repetitive, so level 1 already shrinks it several-fold, and
this runs on a replica serving traffic during a boot herd.
