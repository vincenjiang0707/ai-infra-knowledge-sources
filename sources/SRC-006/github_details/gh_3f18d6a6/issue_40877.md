## Summary

Field data from running **DeepSeek-V4.1-Flash** as a production SGLang backend on **8× RTX PRO 6000 Blackwell Max-Q (SM120, 96 GB, PCIe-only — no NVLink)**, including the *only* topology we could get to start, measured prefill/decode, a speculative-decoding A/B, and the configuration traps that cost us real experiments. Posting because SM120 + V4.1-Flash users currently have to rediscover all of this from scratch.

Full write-up (with methodology and reproduction artifacts): https://github.com/Lei-010/hermes-agent/blob/main/docs/DeepSeek-V4.1-Flash-SM120-Performance-and-Production-Config.md

Related: vLLM field report https://github.com/vllm-project/vllm/issues/56700 (same hardware, vLLM side), vLLM https://github.com/vllm-project/vllm/issues/56892 (SM120 bug/perf tracker).

## What works

```bash
docker run --gpus all -d --name dsv41 \
  --shm-size=64g --ipc=host --network host \
  --restart unless-stopped \
  -e TP_SIZE=8 -e DP_SIZE=1 -e EP_SIZE=8 \
  -e SPEC_ALGORITHM=dspark -e DSPARK_BLOCK_SIZE=6 \
  -e CHUNKED_PREFILL_SIZE=2048 \
  -v /ssd/DeepSeek-V4.1-Flash:/model \
  <sglang image>
```

Effective `server_args` (verified at runtime via `/get_server_info`):

| Parameter | Value |
|---|---|
| `tp_size` / `ep_size` / `dp_size` | 8 / 8 / 1 |
| `speculative_algorithm` | DSPARK, `speculative_dspark_block_size = 6` |
| `chunked_prefill_size` | 2048 |
| `context_length` | 1,048,576 |
| `kv_cache_dtype` | `fp8_e4m3` |
| `mem_fraction_static` | 0.72 |
| `max_running_requests` | 16 |
| `attention_backend` / `moe_runner_backend` | `dsv4` / `flashinfer_mxfp4` |
| CUDA graph decode / prefill | full (max_bs 16) / **disabled** |

**TP8/EP8 is not a preference — it is the only layout that starts** (see "Topologies SGLang rejects" below).

## Measured throughput (cold, single stream, tokens from `usage`, not SSE chunk counts)

128K cold prefill:

| Config | tok/s |
|---|---|
| `chunked_prefill_size=2048` (production) | **6,853** |
| same config re-run | 6,765 (−1.3%) |
| flashmla prefill backend | 6,845 |
| fused-MoE all-reduce | 6,828 |
| `chunked_prefill_size=4096` | 6,301 |
| `chunked_prefill_size=1024` | 6,012 |

32K prompt: ≈7,196 tok/s. GPU util ≈87% at 220 W of 600 W → **communication-bound on PCIe**, not compute-bound. ~7K tok/s looks like the ceiling for this board without NVLink.

Radix/prefix cache is the only large multiplier: cache-hit prefill **0.34 s for a 112K-token prefix ≈ 325K tok/s (≈39×)**.

Decode (client path over SSH tunnel, production config): prose 93.9 tok/s, structured/JSON 134.1 tok/s, TTFT 143–169 ms.

## DSPARK A/B (block_size=2, clean legs, each verified via `server_info` + acceptance length)

| Prompt class | DSPARK ON | DSPARK OFF |
|---|---|---|
| prose | 76.5–78.9 tok/s | 36.4–36.5 tok/s |
| structured | 120.3–120.5 tok/s | 36.5 tok/s |
| `accept len` | 3.0 tokens/step | 1.0 |

With DSPARK off the model flattens to ~36.5 tok/s regardless of prompt class — speculation is the difference between usable and unusable latency on this hardware. Production ships `block_size=6` (structured ≈237–252 tok/s vs 120 at block 2).

## Traps that cost us experiments (SGLang-specific)

1. **`--enable-expert-parallel` is a vLLM flag** — SGLang takes `ep_size`; the vLLM spelling is rejected outright.
2. **`docker run` must pass `TP_SIZE`/`DP_SIZE`/`EP_SIZE` explicitly.** Without `-e`, the container silently serves TP8 defaults and your "new" config never happens (we recorded a full sweep of false data this way before adding a config gate).
3. **`ep_size ≤ tp_size`** or the MoE rank computation divides by zero: `moe_ep_rank = tp_rank % (tp_size // moe_dp_size) // (tp_size // moe_dp_size // ep_size)`.
4. **DSPARK + DP attention requires `--enable-dp-lm-head`** — but is unreachable on this model anyway (next section).

## Topologies SGLang rejects on this model

| Attempt | Result |
|---|---|
| DP2 × TP4 (any EP) | `ValueError: V4.1 vision currently supports TP/EP without DP, CP, PP or MoE A2A` — both replicas die within ~70 s |
| prefill context-parallel | same class of rejection |
| `--enable-dp-attention` alone | silently no DP group (`dp_size: 1`) — looks fine, isn't |

Other SM120 gaps we hit: MSCCL++ (`_tune` kernel crash), FlashInfer all-reduce fusion, `flashmla_sparse_q8`, and CUDA-graph capture for **prefill** (crashes even with DSPARK off, i.e. unrelated to speculation).

## Operational notes

- A defunct container can survive a single `docker rm -f`; the next `docker run` then fails on the name conflict while an orphaned engine process keeps the port and answers health checks — which silently mislabels the next experiment. Loop `docker rm -f` until the container is gone **and** nothing listens on the port.
- A parse failure must never satisfy an "expected config" assertion, or a server that has not started yet gets recorded as "spec disabled".
- Verify intended config from the server (`/get_server_info`) before timing anything; discard legs that fail the gate rather than recording them.

## Not established

No 24 h soak (numbers come from a working day of production use), block sizes 4/8/12 not re-measured with the fixed sweep tool, and >32K prefill/long-context degradation not characterised.
