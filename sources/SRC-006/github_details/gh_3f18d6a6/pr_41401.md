# [PR #41401] [XPU][Diffusion] Use the AOT SYCL fused residual-norm-scale-shift kernel

source: https://github.com/sgl-project/sglang/pull/41401
state: open | updated: 2026-09-27T07:46:39Z
labels: diffusion, jit-kernel

## 正文

sgl-kernel-xpu's AOT SYCL kernel is about 2x cheaper per denoise step than the hand-written triton one forward_xpu used (0.137 s vs 0.275 s on Wan2.2-I2V-A14B 832x480/40f, TP=4, Arc Pro B60) and more accurate: the residual output is bit-identical to triton, the normalized output agrees to under one bf16 ULP, and it is closer to an fp32 reference (rms err 0.001660 vs 0.002153).

Add it as another backend under kernels/ops/diffusion/norm/ and prefer it in forward_xpu, keeping triton as the fallback. The facade lookup is resolved in the existing _is_xpu import block, so the sgl_kernel import stays off other platforms and an sgl-kernel-xpu without the op leaves _has_sycl_fused_norm False and keeps the triton path.

It also unblocks regional torch.compile of a Wan2.2 DiT block: inductor keeps a registered custom op opaque, while it re-lowers the triton kernel and Intel triton then fails to compile the result. The register_fake companion is what lets Dynamo trace the op, since sgl-kernel-xpu registers only the XPU implementation.
