# [PR #41346] [HiSparse] fix: return HiSparse slots on PD decode waiting abort and DeepSeek V4 free

source: https://github.com/sgl-project/sglang/pull/41346
state: open | updated: 2026-09-27T08:52:06Z
labels: run-ci, memory-pool

## 正文

## Motivation

Two request exits give a request's KV back without returning its HiSparse slots, and the idle leak check is skipped under HiSparse, so both leaks are silent:

1. **PD decode abort of a waiting request.** Transferred requests are admitted with `admit_request_direct` (device buffer + host slots) before they enter `waiting_queue`. Aborting one from the queue only calls `release_kv_cache`; `alloc_device_buffer` already zeroed the mapping, so nothing frees the buffer or the host pages. Every such abort leaks `padded_buffer_size` device slots plus the request's host pages, and `hisparse_req_budget` shrinks with it.
2. **DeepSeek V4 `free()`.** `DeepSeekV4HiSparseTokenToKVPoolAllocator.free()` frees only the logical pool, while the non-V4 allocator also calls `free_hisparse`. `alloc_extend` maps every compressed token to a C4 slot, so any exit that does not go through the coordinator (a request finished at prefill, an aborted chunked request) leaks its C4 pages, and `full_available_size` (bounded by the C4 pool) shrinks until admission stalls.

## Modifications

- `Scheduler.abort_request`: on a PD decode waiting-queue abort, call `hisparse_coordinator.request_finished(req)` before `release_kv_cache`, as the finish paths do.
- `DeepSeekV4HiSparseTokenToKVPoolAllocator.free`: call `free_hisparse` after the logical free, matching the non-V4 allocator. Paths that already went through the coordinator zeroed the mapping, so this frees nothing twice.

## Accuracy Tests

- `test_free_returns_c4_slots` (real `DeepSeekV4TokenToKVPool` with HiSparse + real allocators): on main the C4 pool ends at `192 != 256` (one page leaked); with this change it returns to baseline and the mapping is cleared.
- Before removing the mocked waiting-abort test, `test_hisparse_allocator.py`, `test_priority_scheduling_disaggregation.py`, and `test_hisparse_unit.py`: 45 passed, 2 skipped. The suites have not been rerun after that test removal.
