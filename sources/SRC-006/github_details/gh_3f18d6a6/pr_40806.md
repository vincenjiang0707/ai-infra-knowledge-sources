## 正文

## Motivation

For disaggregated RL where the trainer and the rollout engines don't share GPUs or a fast interconnect, the trainer publishes weights to shared storage and each engine host pulls them locally before reloading. Full checkpoints per step are too big; a delta stream needs an engine-side applier that is idempotent across ranks and fails loud on corruption.

## Modifications

- New `sglang/srt/weight_sync/local_checkpoint.py`: `pull(local_checkpoint_dir, base_dir, source_dir, target_version)`.
  - A published version `weight_v{N:06d}/` is a full HF checkpoint, or a delta (index metadata carries `delta_encoding`) of zstd-compressed per-tensor payloads against N-1, `xor` or sparse `overwrite`, with per-tensor checksums (`adler32` / `xxh3-128` / `blake3`).
  - Seeds from the newest full version at or below the target (the engine's own `model_path` for a pure-delta stream), then applies the remaining deltas in place through mmap on a thread pool. Any checksum mismatch or out-of-order delta raises.
  - A per-host `flock` plus an applied-version marker make concurrent calls from co-located ranks collapse to one pull.
- `POST /pull_weights` (`local_checkpoint_dir`, `source_dir`, `target_version`) → `SchedulerWeightUpdaterManager.pull_weights`. Success is all-gathered across the TP group, so the reply only reports success once every host holds a verified checkpoint. The engine reloads afterwards via the existing `update_weights_from_disk`.
- `--custom-pull-weights-pre-read-hook`: import path of a `hook(source_dir, target_version)` called before reading, for object-store-backed mounts without cross-host read-after-write consistency.
- CPU unit test `test/registered/unit/weight_sync/test_local_checkpoint.py`: seed-from-base + xor delta, chained overwrite delta with idempotent re-pull, fresh host seeding from a later full version with stale-file pruning, checksum mismatch, out-of-order delta.

Squash of sglang-miles #30366 (author credited as co-author).
