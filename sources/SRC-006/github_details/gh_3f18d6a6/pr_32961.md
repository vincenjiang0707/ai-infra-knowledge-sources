## Motivation

Attention-backend selection in SGLang is a static heuristic frozen at init:
`_get_default_attn_backend` keys on SM class, CUDA version, MLA-vs-MHA, and a spec-decode
flag, and never observes batch size, context length, or the prefill/decode phase — the
axes where attention kernels actually cross over. The result is a well-documented pattern
of boundary-SKU regressions (`fa3` 2.2× slower than FlashInfer for H20 decode under the
H100's own predicate, #5630; 7.72× slower for MLA `page_size=64` decode on CUDA 13,
#31310; SM120 startup crashes from SKU-within-SM-class blindness, #14814/#18995) that
users today resolve by trial-and-error flag flipping.

This PR implements the attention slice of the `sglang.auto_tune` roadmap (#13363,
TODO-4): **`sglang tune`, an automated pre-flight benchmark that generates a per-device,
per-model-profile selection matrix from measurements on the user's own silicon**, and a
gated, off-by-default ingest hook that applies it at engine init. It does not change the
heuristic's correctness role — it adds an empirical refinement on top, reusing the pattern
SGLang originated for MoE (#2628) and already ships default-on for FlashInfer
(`flashinfer_autotune.py`).

## Modifications

**New: `sglang tune` subcommand + `sglang.tune` package** (all off unless `--enable-attune`):

- `python/sglang/cli/tune.py` — `tune(args, extra_argv)` handler wired into `cli/main.py`
  subparsers, matching the `serve`/`generate` house style. Also `python -m sglang.tune`.
- `python/sglang/tune/` — `shapes.py` (profile + grid), `candidates.py` (capability
  pre-flight = the gate reused as the candidate generator), `pagesize.py` (backend→page-size
  snap, mirroring `overrides.py`; never a free sweep axis), `harness.py`, `isolation.py`,
  `writer.py` + `loader.py` (the two config artifacts + the runtime ingest hook),
  `device.py`, `orchestrate.py`, `realbench.py`.

**Measurement layer** (`harness.py`) — `triton.testing.do_bench` semantics: millisecond
warmup/rep budgets, 256 MiB L2 flush between timed runs, CUDA events with a single
trailing sync, median/min/p20/p80. Small-batch decode additionally uses a
`do_bench_cudagraph`-style path (32 unrolled calls captured per graph, per-iteration
quantiles from replay timing) so launch overhead is excluded exactly where it distorts
most. The graph path is defended by a **plausibility guard** (`GRAPH_SANITY_FLOOR_US`):
any graph-mode median below 0.5 µs/iteration is physically impossible for an attention
kernel, so the result is discarded and the cell re-measured eagerly, loudly. This guard is
battle-tested in both directions: on a virtualized GPU-over-TCP environment it correctly
rejected systematic fantasy readings (graph replays returning 0.0000 µs without observably
executing), and on physical A100 hardware it stayed completely silent while the same code
produced correctly-ordered, physically-scaled timings (see Evidence).

**Crash-safe isolation** (`isolation.py`) — one spawned subprocess per backend candidate.
The parent classifies every failure (`ImportError` / "no kernel image" / OOM / crash /
timeout) and continues; per-bucket results **stream** from the child, so a timeout or
crash partway through the grid keeps every completed measurement instead of discarding the
candidate; per-shape OOMs are skipped individually ("skip shape, keep smaller") with the
CUDA cache emptied so a failed allocation can't poison the next bucket. This layer was
validated against deliberate real failures (CUDA OOM, `SIGABRT`, incompatible-kernel
launch — all classified correctly, suite continued) and, more convincingly, against an
**unprompted one**: on one test image the cuDNN frontend could not plan the test config
and crashed the candidate outright, twice; both crashes were contained as candidate-level
failures, recorded in the artifact's `skipped` map, and the remaining backends completed
normally. OOM trimming is deterministic: on a 40 GB A100 the sweep skipped exactly the
cells whose KV working set exceeds VRAM (`256:16384`, `64:65536`, `128:65536`,
`256:65536` for the flash-class backends; earlier for the math fallback, which
materializes the attention matrix), identically across repeated runs.

**Two config artifacts** (each schema-versioned, `json.dump(indent=2)`):
  1. *Committed corpus* — coarse, human-readable filename key
     (`attn,device_name=…,sm=…,family=…,qo=…,kv=…,hd=…,dtype=…,tp=…,ep=…,dp=….json`),
     PR-reviewable, contributed one device at a time. Ships under
     `python/sglang/srt/layers/attention/configs/`.
  2. *Local first-boot cache* — `sha256` fingerprint over `{device name, sm, CUDA + driver
     version, applied SM clock, power cap, PCIe gen/width}` + profile + schema, atomic
     write. A throttled, power-capped, or CUDA-bumped box re-tunes instead of reusing a
     mismatched file; a PCIe Gen3 host never silently serves its Gen4 twin.

**Runtime ingest** — `get_attune_config()` (lru-cached; `SGLANG_ATTUNE_CONFIG_FOLDER`
override → local cache → packaged corpus → miss = loud warning + heuristic fallback) and
`attune_select()`, the ~10-line pass after `_attention_backend_default`. Per phase it
collapses the fine grid by equal-weight majority vote over the buckets, or — when the
caller supplies a workload hint (expected batch/context) — by nearest-bucket lookup in
log2 space, with the vote as fallback if the hinted winner is not currently eligible:

  ```python
  if server_args.enable_attune and server_args.is_attention_backend_not_set():
      overrides = attune_select(dev, profile, PACKAGED_CONFIG_DIR,
                                eligible_prefill, eligible_decode, LOCAL_CACHE_DIR)
      if overrides:                     # else keep the heuristic (fail-safe; never raises)
          server_args._apply(overrides) # prefill/decode backend + derived page_size
  # _handle_attention_backend_compatibility runs next and may still override (double-duty gate)
  ```

- **Flags/env**: `--enable-attune` (default `False`) + `--attune-config PATH` on `ServerArgs`;
  `SGLANG_ATTUNE_CONFIG_FOLDER` declared in `environ.py` (typed `EnvField`).
- **Scope**: v1 is CUDA-only and per-engine (`prefill_backend`, `decode_backend`,
  `page_size`) — the existing `HybridAttnBackend` split is the lever. v2 (separate PRs):
  per-request selection via `sglang.kernels`, first-boot runtime profiling, intra-kernel
  Triton block-size autotune, ROCm/AITER.

## Accuracy Tests

Attune only changes *which correct kernel* runs among gate-survivors, so outputs are
invariant by construction; the compatibility pass retains final authority.

- Unit tests (28, `test/registered/unit/tune/`): capability pruning per arch,
  filename/fingerprint round-trip, workload-hint nearest-bucket lookup and its fallback
  to the vote when the hinted winner is ineligible, fail-safe never-pick-ineligible, and
  subprocess isolation surviving an uncatchable signal-killed child with correct failure
  classification. Green on macOS (no GPU), on a virtualized A100 environment, and on
  physical A100 hardware.
- Fail-safe legs exercised live: a fresh artifact round-trips through the loader and
  yields a valid override dict; with no eligible winners, selection declines and the
  engine keeps the heuristic — no exception, one warning line.
- Output-parity generations with/without `--enable-attune`: **pending the in-tree kernel
  adapters** (see Limitations).

## Speed Tests and Profiling

**Worked example — physical A100-SXM4-40GB** (artifact and raw logs live in the development repository; happy to attach them here or in a gist on request): 32 decode + 15 prefill cells measured, 26
self-documenting skips, schema `attune/1`, fingerprint `a21377ffa7d5880c`. Decode latency
scales the way HBM-bound physics demands — 23.52 µs → 63.42 → 212.38 → 804.74 µs across
1K→64K context at batch 1, and 12,148.74 µs at `64:16384` — with `flash` dominant and two
distinct decode winners across the grid. The full validation suite (crossover
measurement, crash-recovery injection, fingerprint stability) passed with zero timeouts.

**Timing-fidelity audit.** The identical suite was first run on a virtualized
GPU-over-TCP A100, which proved a hostile and therefore useful environment: CUDA-graph
replays there returned 0.0000 µs (rejected wholesale by the sanity guard), and even eager
event timing under-measured sub-100 µs kernels. Conclusion, stated plainly: **tuning
artifacts must be generated on hardware with native CUDA execution**; the harness now
detects and refuses the failure mode rather than emitting fantasy configs. The physical
A100's PCIe 3.0 bus was audited as a contamination risk and exonerated by construction —
all benchmark tensors are generated directly on-device (`torch.randn(..., device="cuda")`),
no host-to-device transfer exists inside any event-bracketed region, and a 1 MB KV
crossing a 7.6 GB/s bus would add ~130 µs to readings that measure 23 µs.

**Pending** (see Limitations): end-to-end `bench_one_batch`/`bench_serving` A/B on
target-class SKUs (H20, H100) with the real SGLang kernels, which will populate the
heuristic-vs-attune table and the PR's headline numbers.

## Limitations — stated up front

1. **The benchmark adapters currently drive torch SDPA backends as stand-ins**
   (`flash`/`cudnn`/`mem_efficient`/`math`), chosen so the harness, isolation, artifact,
   and ingest machinery could be validated end-to-end on real silicon without a full
   SGLang build. The immediate next step is the thin per-backend adapter layer that
   constructs `ForwardBatch`es and drives the registered `AttentionBackend`
   implementations (`fa3`, `flashinfer`, `flashmla`, …); only `realbench.py` changes.
2. **The `--auto-throttle` power-cap validation is proven on its failure paths only.**
   On both cloud environments tested, NVML power-limit writes are reserved to the host
   (two distinct refusal modes observed); in both cases the tool detected the refusal,
   attempted no restore for a change it never made, and left the cap bit-identical —
   zero hardware state damage, restore logic guarded by `finally`. The positive proof
   (cap lowered → fingerprint changes → cap restored) requires tenant-held bare-metal
   rights and is pending; the fingerprint's sensitivity to its inputs is unit-tested
   meanwhile.
