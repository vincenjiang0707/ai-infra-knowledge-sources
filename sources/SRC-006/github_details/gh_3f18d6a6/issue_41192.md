# [Issue #41192] [Bug] Diffusion Qwen-Image-2.1: TP=2 output corrupted with dense chroma speckle (single-GPU clean; vLLM-Omni TP=2 shows the identical corruption)

source: https://github.com/sgl-project/sglang/issues/41192
state: open | updated: 2026-09-27T08:56:53Z
labels: 

## 正文

### Summary

Qwen-Image-2.1 on the diffusion serving path with `--tp-size 2` produces images corrupted by **dense multicolored (chroma) speckle noise** across smooth regions, while image structure/composition stays correct. The **same prompt/config with `--tp-size 1` is clean**. We also reproduced the identical corruption with vLLM-Omni's independent TP implementation, and verified NCCL numerics across our GPU pair are clean — so this looks like an issue in how this DiT is sharded under TP rather than a hardware/transport problem.

### Environment

| Item | Value |
|---|---|
| GPUs | RTX 5070 Ti (16GB) + RTX 5070 (12GB), both Blackwell `sm_120` |
| OS | Windows 11 + WSL2 (Ubuntu 24.04) |
| SGLang | main @ `8ab21c8a9` (2026-09-24), source install with `sglang[diffusion]` |
| flash-attn | 2.8.3 self-built for `sm_120` (FA3 wheels ship no sm_120 kernels; pip nvcc + patched CCCL headers) |
| Model | Qwen/Qwen-Image-2.1 (bf16) |

### Reproduce

```bash
sglang serve \
  --model-type diffusion \
  --model-path /root/models/Qwen-Image-2.1 \
  --host 0.0.0.0 --port 8094 \
  --tp-size 2 --num-gpus 2 \
  --performance-mode manual \
  --attention-backend fa2 \
  --text-encoder-cpu-offload true \
  --dit-layerwise-offload true \
  --dit-layerwise-resident-layers 24 \
  --vae-cpu-offload true \
  --pin-cpu-memory false
```

```bash
curl http://localhost:8094/v1/images/generations -H "Content-Type: application/json" -d '{
  "prompt": "a ceramic teapot on a wooden table, soft window light, clean background",
  "size": "1024x1024",
  "num_inference_steps": 30,
  "seed": 42,
  "output_format": "png",
  "response_format": "b64_json"
}'
```

Result: 1024×1024 renders in ~32s but is covered in dense green/purple/orange speckles on smooth surfaces (wall, table, gradients). Switching to `--tp-size 1` with the same offload flags produces a clean image.

### What we ruled out

1. **flash-attn build** — the corruption is identical with `--attention-backend sdpa` on the vLLM side and with FA2 on the SGLang side; a single-GPU run with the same self-built FA2 wheel is clean.
2. **Mixed GPU models / rank order** — swapped the two cards between ranks; corruption identical.
3. **NCCL transport** — dedicated `torch.distributed` test: bf16/fp16/fp32 all-reduce between the two cards vs Gloo CPU fp64 reference. Errors are exactly normal rounding (fp32 ≈ 4e-8 rel; fp16 ≈ half-ulp; bf16 ≈ one ulp); 50-round 4096² stress: zero NaN/Inf.
4. **Offload flags** — single-GPU with the same offload flags is clean, so the offloader itself is not corrupting activations.
5. **Engine-specific plumbing** — vLLM-Omni (PR #7759 branch, its own TP code) shows the **same corruption** under TP=2 and clean single-GPU output (cross-filed at vllm-project/vllm-omni#8135).

### Hypothesis

Both engines shard this DiT with vLLM-style parallel-layer conventions. Qwen-Image-2.1 has single-stream joint text+image attention (32 single-stream blocks, structural block-causal masks), per-head QK-norm with a zero-centered RMSNorm (fp32, weight+1), and AdaLN modulation MLPs. If modulation outputs or norm state are sharded/all-reduced like ordinary FFNs, the summed partials would produce exactly this class of mild, structure-preserving corruption.

Happy to provide side-by-side PNGs, pixel-diff maps, or the NCCL test script on request.
