## Observed impact

In a Prefill/Decode disaggregation deployment using the Mooncake transfer backend, the Decode control path can fail while:

* the Decode process is still running;
* the Decode and Router health endpoints still return HTTP 200; and
* later end-to-end inference requests stall until they time out.

As a result, a router or orchestration system that relies on health checks may continue sending requests to a Decode worker that is no longer usable.

Triggering this issue requires network access to an internal PD control-plane endpoint. Access to the public OpenAI-compatible HTTP API alone is not enough.

I did not observe any confidentiality loss, data modification, native memory corruption, or code execution. The confirmed impact is loss of availability.

## Tested scope

* SGLang: `0.5.15.post1`
* Deployment mode: Prefill/Decode disaggregation
* Transfer backend: Mooncake
* Model used for reproduction: Qwen3-8B
* Impact category: availability

I reproduced the issue on `0.5.15.post1`. Based on my review of the current `main` branch, it still appears to be affected.

## Relation to existing work

I reviewed #28440, #29984, and #31966. Those changes focus on receiver-thread robustness or corrupted internal messages.

This report covers a separate case that I reproduced through a network-reachable control-plane endpoint. It also shows that the health checks can remain successful after the Decode control path has failed.

Some of the existing defensive changes may reduce part of the impact. However, the full reproduction method, security boundary, and health-check behavior are documented in the private report.

### Reproduction

Tested with `Qwen3-8B` in a one-Prefill/one-Decode deployment.

A normal Mooncake PD deployment was started with the following configuration:

```bash
export MODEL=/path/to/Qwen3-8B
export MC_FORCE_TCP=1

CUDA_VISIBLE_DEVICES=0 sglang serve \
  --model-path "$MODEL" \
  --served-model-name Qwen3-8B \
  --host 127.0.0.1 \
  --port 31000 \
  --tp-size 1 \
  --disaggregation-mode prefill \
  --disaggregation-transfer-backend mooncake_tcp \
  --disaggregation-bootstrap-port 31998

CUDA_VISIBLE_DEVICES=1 sglang serve \
  --model-path "$MODEL" \
  --served-model-name Qwen3-8B \
  --host 127.0.0.1 \
  --port 31001 \
  --tp-size 1 \
  --disaggregation-mode decode \
  --disaggregation-transfer-backend mooncake_tcp

python -m sglang_router.launch_router \
  --pd-disaggregation \
  --prefill http://127.0.0.1:31000 31998 \
  --decode http://127.0.0.1:31001 \
  --host 127.0.0.1 \
  --port 31800
Before the confidential negative-input step, health checks returned HTTP 200
and an inference request completed normally.
After executing the confidential reproduction step:
the Decode process remained running;
the Decode and Router health endpoints still returned HTTP 200; and
a new inference request through the Router timed out without a response.
The construction and delivery of the triggering input are withheld from this
public issue. The complete minimal reproducer is available through private
security coordination and was included in the CNA submission.
