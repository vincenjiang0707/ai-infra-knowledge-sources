## Motivation

Under attention DP, `postprocess_layer` brings a FULL-layout layer output back to this rank's tokens. It does so in one of two ways:

- **FFN left its sum out:** a reduce-scatter (reduce_scatterv, or `dp_reduce_scatter_tensor` on MAX_LEN padding) that also completes the sum;
- **FFN reduced its own output:** a plain scatter.

Both ran in the layer, while without attention DP the next layer's input already completes a deferred sum. This PR moves both to the next layer's input, so a layer's FFN sum is always completed where the next layer reads it.

## Modifications

- **First commit:**
  - Postprocess's `_scatter_hidden_states` is split into `_reduce_and_redistribute_output_varlen`, `_reduce_and_redistribute_output_max_len` and `_redistribute_output`, chosen under the same conditions as before.
  - `FfnExit.finish` returns `UnreducedOutput(partial, reduce_and_redistribute=...)` when postprocess would run one of the reduce-scatters. This applies on a FULL → TP_ATTN_FULL layer that is not the last one and is not in an active LayerNorm SP region.
  - `prepare_attn` runs the bound reduce-scatter first, where postprocess used to, then takes the complete-input path. No fused kernel runs under attention DP.
- **Second commit:**
  - `should_defer_ffn_reduction` also defers under attention DP when postprocess would only scatter: the next layer runs the FFN's all-reduce and then the scatter.
  - The token check reads the gathered buffer length under attention DP, so every DP rank takes the same decision on the new deferral. The fused decision (`should_fuse_mlp_allreduce_with_next_layer`) still reads the local batch size; that is harmless because neither fused kernel runs under attention DP.
  - A guard, `TestFfnExitUsersOweATpSum`, walks from every `ffn_exit` caller through its FFN parts. It checks that none of them sums only over the attention-TP group (`use_dp_attention_reduce`), because the next layer completes a TP-group sum.

- **Layer-input buffer:** under attention DP, `layer_input_buffer()` in DeepSeek and GLM5-Next now yields the previous layer's FULL-length partial. The non-inplace flashinfer TRT-LLM MoE's `moe_output_buffer` check then matches its shape, and the MoE writes its output into that tensor. The partial is dead once `prepare_attn` has reduced it.
- **Two-batch overlap:** the layer before a TBO section can now hand the TBO entry an `UnreducedOutput` under attention DP. The entry reduces it first; that fix lives in #41196, where the same read was already reachable.

## Accuracy Tests

No numeric change: the same collectives run on the same tensors, one layer boundary later.

- **Call sequences** (stubbed collectives):
  - boundary-level, 8,192 cases: identical to the parent;
  - end to end (the FFN exit's real decision and the FFN's own skip rule), 4,096 cases: identical;
  - `prepare_attn`, 24,576 cases: identical.
  - In the end-to-end matrix, the parent leaves no reduction to the next layer; this PR leaves the reduce-scatter in 224 cases (first commit) and the all-reduce + scatter in 72 more (second commit).
- **GPU, H200, 4 greedy requests × 32 tokens; text, token logprobs and top-5 logprobs compared; each configuration's audit shows the deferral.**
  - Reduce-scatter moved, 8 configurations bit-identical to the parent: Qwen3-30B-A3B-FP8 TP2 DP2 EP2 (reduce_scatterv); DeepSeek-V2-Lite TP2 DP2 EP2 (reduce_scatterv) and TP2 DP2 (MAX_LEN); GLM-4.7-Flash TP2 DP2 and + NextN; Qwen3-VL-30B-A3B TP2 DP2 EP2 image requests; DeepSeek-V2-Lite TP4 DP2; Qwen3-30B-A3B-FP8 TP4 DP4 EP4.
  - All-reduce + scatter moved, 11 more configurations bit-identical. These include ~3000-token prompts that reach the SUM_LEN path on DeepSeek-V2-Lite, GLM-4.7-Flash and Qwen3-VL.

Rebased onto main `9dc4c5d891`: every commit's patch is unchanged, and the related unit tests pass on the new base. The GPU results above were measured on the previous base, `5bb850d536`.

## Speed Tests and Profiling

Throughput, H200, `bench_offline_throughput` 512 × 512, 4 runs per side with the GPUs swapped:

- **DeepSeek-V2-Lite TP2 DP2:** 9,514 → 9,608 tok/s (+1.0%).
- **Qwen3-30B-A3B-FP8 TP2 DP2 EP2:** 5,772 → 5,708 (−1.1%) with the decode CUDA graph limited to batch 64. There, decode batches above 64 run eager and the extra Python calls per layer show. With the graph covering batch 256: 26,888 → 26,936 (+0.2%).
