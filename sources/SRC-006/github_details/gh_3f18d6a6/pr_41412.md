# [PR #41412] [MLX] Honor checkpoint revision in one-batch benchmarks

## 正文

## Motivation

`sglang.benchmark.one_batch` accepts `--revision`, but its standalone MLX adapter omits the revision when constructing `MlxModelRunner`. The native loader therefore resolves the default checkpoint revision even when the benchmark configuration requests a pinned commit. This can benchmark different weights from those requested.

## Modifications

Forward the resolved `revision` to the native MLX model runner, alongside the existing model path and quantization settings. Add a registered MLX regression for an explicit pinned revision and the default `None` case.

## Accuracy Tests

Local validation on MacBook Air M5, 16 GiB, macOS 26.6.2; Python 3.12.14, Torch 2.13.0, MLX 0.32.2, mlx-lm 0.31.3:

- Both new revision subcases fail before the change because the native loader receives no `revision` argument.
- `SGLANG_USE_MLX=1 PYTHONPATH=python python -m pytest test/registered/unit/hardware_backend/mlx/test_one_batch_revision.py -q`: **1 passed, 2 subtests passed**.
- Real adapter check: construct resolved `ServerArgs` for `mlx-community/Qwen3-0.6B-4bit` at revision `73e3e38d981303bc594367cd910ea6eb48349da8`, then instantiate `_MlxBenchRunner` with the native loader and a minimal Torch-runner capacity stub. The real checkpoint resolver received that exact revision, weights loaded from the cached snapshot, and prefill plus decode succeeded (token IDs 284 and 330). This checks the adapter directly, not the full benchmark CLI.
- Changed-file pre-commit checks passed.

These are local results; remote CI has not run.

## Speed Tests and Profiling

This fixes checkpoint selection. No model-forward or sampling algorithm changes and no throughput claim.
