# [Issue #39675] [Bug] Apple Metal (mps) reports no device memory capacity, so mem_fraction_static falls back to 0.95 and prefill OOMs

## 正文

## Describe the bug

On Apple Silicon, `get_device_memory_capacity()` has no `mps` branch, so it falls through to `gpu_mem = None`:

https://github.com/sgl-project/sglang/blob/main/python/sglang/srt/utils/common.py#L825-L850

That single `None` has two consequences in `handle_gpu_memory_settings` (`python/sglang/srt/arg_groups/memory_hook.py`):

1. The whole `if gpu_mem is not None:` capacity-tier block is skipped, so the per-capacity `chunked_prefill_size` / decode `max_bs` defaults never apply.
2. `mem_fraction_static` takes the `else 0.95` fallback instead of `(gpu_mem - reserved_mem) / gpu_mem`. On every other device `reserved_mem` covers the activation working set (`activation_tokens * 1.5` MB plus a floor); the 0.95 fallback reserves nothing.

The MLX runner then fills that fraction with KV (`_compute_pool_size` in `python/sglang/srt/hardware_backend/mlx/model_runner.py`), leaving ~5% for everything else, and the first real prefill aborts the scheduler:

```
File "python/sglang/srt/hardware_backend/mlx/tp_worker.py", line 547, in _async_extend_batch
    mx.async_eval(*async_args)
RuntimeError: [METAL] Command buffer execution failed: Insufficient Memory (00000008:kIOGPUCommandBufferCallbackErrorOutOfMemory).

SIGQUIT received. signum=None, frame=None. It usually means one child failed.
```

The sibling function `get_available_gpu_memory()` already carries an `elif device == "mps":` branch (`common.py:534`), which suggests this is an omission rather than a deliberate gap.

## Reproduction

24 GB M-series Mac, macOS 15.7.9, Python 3.12, torch 2.13.0, MLX backend:

```bash
SGLANG_USE_MLX=1 python -m sglang.launch_server \
  --model-path mlx-community/Qwen3-0.6B-4bit --disable-cuda-graph
```

The server starts and auto-sizes a ~7.2 GB KV pool, then dies on the first non-trivial request.

The resolved configuration can be inspected without launching anything:

```python
from sglang.srt.server_args import ServerArgs
from sglang.srt.arg_groups.overrides import resolution_result
from sglang.srt.utils.common import get_device_memory_capacity

sa = ServerArgs(model_path="mlx-community/Qwen3-0.6B-4bit", disable_cuda_graph=True)
sa.resolve_once()
print(get_device_memory_capacity("mps"))                  # None
print(resolution_result(sa, "device"))                    # 'mps'
print(resolution_result(sa, "mem_fraction_static"))       # 0.95
print(resolution_result(sa, "chunked_prefill_size"))      # 4096
```

`handle_gpu_memory_settings` is reached with the device already resolved, so a `device == "mps"` branch is in time to be used:

```
>>> get_device_memory_capacity(device='mps') -> None
```

## Suggested fix

Metal exposes a recommended working-set size (`torch.mps.recommended_max_memory()`, about two thirds of physical RAM — 16 GB on this 24 GB machine, matching MLX's own `max_recommended_working_set_size`). That cap, not total system memory, is the budget every allocation shares, so reporting it as the device capacity lets the existing reserve formula apply to `mps` like any other device.

With that branch added, the same configuration resolves to `mem_fraction_static=0.773` and `chunked_prefill_size=2048`, and an 8016-token prompt prefills in 2048-token chunks and completes instead of aborting the scheduler.

PR to follow.
