## 正文

## Motivation

Related to #18891 (VAE portion). The diffusion disk-refit tests compare the transformer's checkpoint checksum, but do not prove that the VAE matches the requested checkpoint. The reload path also omits persistent buffers, so FLUX.2 BatchNorm statistics can remain stale while an update reports success.

This PR adds VAE checkpoint parity checks and the small buffer-loading fix needed for them. Text-encoder name mapping, fused weights, and sharded text-encoder refits remain follow-up work; this does not close the entire issue.

## Modifications

- Reuse the existing per-tensor checksum checker to compare VAE checkpoint tensors with live state after full updates, VAE-only updates, non-target preservation, rollback, and the existing DiT-offload fixture. Floating checkpoint tensors are normalized to the explicitly selected bf16 VAE precision; integer buffers retain their dtype. These checks target the existing FLUX.2 and Qwen-Image fixture pairs.
- Include persistent buffers in the shared reload target lookup, preserving parameter-specific loaders, excluding runtime-only buffers, and handling persistent aliases correctly.
- Support scalar tensors in SHA-256 byte hashing, including FLUX.2's int64 `bn.num_batches_tracked`, while retaining dtype and shape in the hash.
- Add 14 CPU regression cases using real Torch modules, safetensors checkpoints, and the production updater/checker. No new API or change to the existing aggregate-checksum response is needed.

Related prior work: #33588 identified the VAE buffer-loading failure alongside broader text-encoder fixes. This PR overlaps only that small buffer-loading portion, with persistence filtering and regression coverage; it does not include the text-encoder loader, VRAM-budget, or loaded-count changes from that PR.

### Real Hugging Face checkpoint validation (CPU)

Loaded the actual **black-forest-labs/FLUX.2-klein-4B VAE**, pinned to Hugging Face revision `e7b7dc27f91deacad38e78976d1f2b499d76a294`: 168.1 MB, 84,046,115 parameters, 251 checkpoint tensors. Only the VAE config and safetensors were downloaded.

Executed SGLang's native `VAELoader` with Diffusers fallback disabled, `SGLANG_DIFFUSION_PLATFORM_OVERRIDE=cpu`, and bf16 VAE precision. All 251 native-loaded tensors matched the checkpoint before any reference reload.

- **BF16 disk refit:** deliberately changed a decoder parameter and all three BatchNorm buffers. The unmodified parent-commit `WeightsUpdater` returned success but left three buffer mismatches; production latent de-normalization differed by up to **0.9296875**. This PR's updater restored all 251 tensor hashes, the integer counter, and exact de-normalization output.
- **Real encoding/decoding:** on CPU in FP32, encoded a deterministic 64x64 RGB input to `[1, 32, 8, 8]` latents and decoded back to `[1, 3, 64, 64]`; outputs were finite. Native SGLang and Diffusers 0.37.0 using the same checkpoint matched with **0 maximum absolute error** for both encode and decode.
- **Output regression:** used SGLang's real latent scaling/unpatchifying path before decoding, so the output depends on the BatchNorm buffers. The parent updater left a maximum decoded-output error of **0.61149448** after corruption. This PR's disk refit restored the baseline output exactly (**0 error**).

These are real-weight **component** tests using the native loader, updater, checker, and encode/decode paths. BF16 refit/parity and FP32 CPU inference were checked separately; no BF16 inference result, full HTTP diffusion server, CUDA execution, or distributed validation is claimed.

**Full diffusion-server / CUDA validation is pending.** The extended server-based suite below has not yet run on CUDA for either FLUX.2 or Qwen-Image:

```bash
PYTHONPATH=python python -m pytest -q \
  python/sglang/multimodal_gen/test/single_test_file/test_update_weights_from_disk.py
```

The existing offload fixture enables DiT offload; it does not claim VAE layerwise-offload coverage. The existing ROCm skip for #31924 is unchanged.
