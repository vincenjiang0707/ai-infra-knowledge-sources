# [PR #41226] [sgl-router] Scope input_ids forwarding by renderer: all text chats for DeepSeek-V4

state: open | updated: 2026-09-25T07:42:08Z

## 正文

Stacked on #41221 (itself on #41185).

## Motivation

The forwarding check excluded most real traffic: tools, tool history, reasoning history, kwargs, effort, `task`, continuation, array content and role rewrites all fell back to engine tokenization. For DeepSeek-V4 these request types are verified against SGLang, so V4 can forward every non-multimodal chat. Other renderers aren't verified and keep the existing check.

## Changes

Forwarding now depends on the model's renderer (`ForwardingScope`):

| Renderer | Scope | What gets forwarded |
|---|---|---|
| Native DeepSeek-V4 | `AllText` | Every chat except multimodal ones and those with caller-provided `input_ids` |
| HF Jinja templates, Kimi-K3, and others | `Guarded` | Only what the existing per-request-type check allows (unchanged); logs a loud `UNVERIFIED` warning at startup |
| DeepSeek-V4.1 | `Never` | Nothing; its effort mapping is stale against SGLang main. Routing tokenization still works |

Also:
- **V4 fixtures:** 7 new cases generated from SGLang's Python: mid-conversation system message, final assistant turn without `continue_final_message`, agentic thinking history (reasoning + tool calls + tool results), thinking multi-turn, tool results with array content, the `reasoning` object, and ignored fields (`name`, `response_format`, `stream`).
- **Generator fix:** `generate_deepseek_parity.py` no longer crashes on V4.1 cases, which have no `profile`.
- **Tests:** the proxy tests on the V4 model that asserted tool and thinking requests aren't forwarded were removed. The guarded-path tests on Jinja templates are kept.

## Safety for DeepSeek-V4

- The router matches SGLang on all 31 V4 fixture cases, both rendered text and token ids.
- The fixtures were generated with SGLang main and with v0.5.20, and the two produce identical output.
- DeepSeek-V4-Flash-0731's tokenizer is identical to V4-Flash's, and both engine and router detect its official effort profile.
- Remaining risk: request types no fixture covers. Also, requests the engine would reject while rendering now succeed with the router's tokens.
- The router pod needs the workers' `--default-chat-template-kwargs` and `SGLANG_DSV4_REASONING_EFFORT` (see #41221), and a `--tokenizer-path` inside the full model snapshot.

## Testing

- `cargo test`: all tests pass. `cargo fmt` and `cargo clippy --all-targets` are clean.
- `v4_matches_sglang_serving` also passes with the V4-Flash tokenizer cached, so token ids are compared, not just text.
