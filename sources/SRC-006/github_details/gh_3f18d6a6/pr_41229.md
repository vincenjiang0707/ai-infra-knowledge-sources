# [PR #41229] [ROCm] Rotate even-batch decode attention grid across XCDs

state: open | updated: 2026-09-25T07:14:31Z

## 正文

## Summary

Fixes #41151.

HIP assigns workgroups to XCDs round-robin. Triton decode stage-1 launches with `batch` as the fastest grid axis, so an **even** batch size parks every workgroup for a given request on a subset of XCDs. CUDA-graph padding fills unused slots with `seq_len=1`, and those empty slots still take whole XCDs — at long context the padded bs-5→8 graph was ~1.4× slower than an exact bs-5 launch on the attention kernel alone (Olmo-3-7B shapes).

When `batch % 2 == 0` on HIP, rotate the batch index by `(head + split) % batch` so work from every request is spread across XCDs. Odd batches are already interleaved by the round-robin mapping and are left alone. CUDA is unchanged.

## Kernel microbench (MI325X, 304 CUs, best of 3 interleaved)

`us` per layer call; ratio &lt; 1 is faster. Uniform even batches stay within ~3%.

| model | ctx | case | base us | patched / base |
|---|---:|---|---:|---:|
| Olmo3-7B MHA | 31000 | 5→8 padded | 2431 | **0.74** |
| Olmo3-7B MHA | 31000 | 8 ragged (1 long + 7×1K) | 2379 | **0.36** |
| Olmo3-7B MHA | 31000 | 16 ragged | 4403 | **0.31** |
| Olmo3-7B MHA | 31000 | 64 uniform | 19843 | 1.00 |
| Qwen3-8B GQA | 31000 | 5→8 padded | 562 | **0.77** |
| Qwen3-8B GQA | 31000 | 8 ragged | 502 | **0.27** |
| Llama-70B TP8 | 31000 | 5→8 padded | 120 | 1.00 |
| Llama-70B TP8 | 31000 | 64 random | 508 | **0.75** |

Outputs are bitwise identical with and without the rotation (checked across the microbench cases).
