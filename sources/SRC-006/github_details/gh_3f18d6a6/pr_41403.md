## Motivation

`bench_serving` has no audio workload generator, so audio-capable models cannot be exercised through an equivalent of its synthetic image benchmark. This adds an `audio` dataset for measuring serving latency and throughput through `sglang-oai-chat`.

Related to #8072. This continues the audio benchmarking effort proposed by @Jenson97 in #27448, adapted to the current dataset and message-list interfaces. A coordination note is posted in [the issue](https://github.com/sgl-project/sglang/issues/8072#issuecomment-5844045155).

## Modifications

- Generate reproducible mono PCM16 WAV clips at 16 kHz using existing NumPy and standard-library WAV encoding. Configure clip duration/count; support zero-clip controls and randomized clip counts.
- Send `input_audio` content through the existing OpenAI chat request path.
- Require server-reported `usage.prompt_tokens` for audio requests in streaming and non-streaming modes, including warmup. Missing or invalid usage fails the request instead of reporting a text-only estimate as total input.
- Report submitted audio seconds and throughput for successful measured requests, excluding warmup and failures. Leave unsupported text/vision token splits unset. Other datasets retain their existing accounting.
- Add CPU regression tests and document the command.

Initial scope is synthetic audio performance testing through `sglang-oai-chat`. Native `/generate` transport and transcription accuracy evaluation are outside this PR.
