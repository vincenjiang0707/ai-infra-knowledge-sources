# [PR #39380] [Feature] Support Lark grammars with XGrammar

## 正文

## Motivation

XGrammar 0.2.7 provides `GrammarCompiler.compile_lark`, but SGLang currently sends the existing `ebnf` grammar input only to `compile_grammar`. As a result, XGrammar cannot accept Lark syntax through the established grammar API.

## Modifications

- Pin XGrammar to the stable 0.2.7 release.
- Keep the existing `ebnf` sampling parameter and public API unchanged.
- In the XGrammar backend, compile as EBNF first and fall back to `compile_lark` when EBNF parsing fails.
- Preserve the resolved grammar format in compilation statistics and report both parser errors when neither format is valid.
- Document that XGrammar accepts Lark syntax through the existing `ebnf` parameter.
- Add focused XGrammar unit coverage for EBNF compilation, Lark fallback, real compilation with XGrammar 0.2.7, and invalid input.

## Accuracy Tests

Focused Python unit tests:

    159 passed, 36 subtests passed

The tests include real compilation of both `root ::= "yes" | "no"` and `start: "yes" | "no"` through `XGrammarGrammarBackend.dispatch_ebnf` with XGrammar 0.2.7.

## Speed Tests and Profiling

Not applicable. Existing valid EBNF inputs retain the same compilation and decoding path. Lark compilation occurs only after the EBNF parser rejects the input.
