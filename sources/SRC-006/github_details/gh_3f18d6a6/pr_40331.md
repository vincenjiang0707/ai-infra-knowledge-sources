# 7/7 — stride the write-loc kernel, then fold the last translate

Base: #40330 (6/7). 2 commits, 9 files, +322/−108.

This is the **only PR in the series that adds content beyond the original PR's tree**, which
is why it lands last and carries its own GPU pass. It closes the TODO 6/7 left behind.

## Why two commits, in this order

After 6/7 two implementations of one formula remain, and the TODO names two blockers. They
have to be removed in this order:

1. **`write_loc_to_kernel_ids` flat-addresses** (`ptr + offs`) and therefore asserts its
   input is contiguous — while the SWA read path hands down
   `page_table[:bs, :max_seq_len]`, a column slice of the capture-stable buffer, which is
   non-contiguous whenever `max_seq_len` is less than the full width (i.e. normally).
2. **The negative-loc semantics differ**: the torch body lets the v2p lookup wrap, the fused
   kernel sends it to the page-0 sink.

Commit 1 removes blocker 1; commit 2 does the fold and settles blocker 2. Applying the fold
without the kernel change fails — `test_translate_accepts_a_strided_page_table` is green on
both commits individually but **red on 2 applied without 1**, which is what pins the order.

## Commit 1 — walk the kernel by its strides

`loc` and `out` are walked as a `(rows, cols)` view with row/column strides passed per
launch, instead of `ptr + offs`.

The decomposition sits behind a `STRIDED` constexpr: **a contiguous pair still takes the
flat path and pays no div/mod**, which is what the per-forward write translate under
cuda-graph capture uses. So the hot path is untouched.

Three details that are not stride arithmetic:

- **The strides are runtime arguments, not `tl.constexpr`.** A page table's live width
  changes every few decode steps, and a constexpr stride would JIT-recompile with it. The
  tree states this rule twice already (`kv_indices.py`, and `do_not_specialize` in
  `transform_index.py`).
- **Offsets are computed in int64.** A row stride times a row count can exceed 2^31, and an
  i32 overflow here mis-addresses silently rather than faulting.
- **`out_width` stays on the flat path, by assert.** That mode writes a packed lane range
  `[0, W)` with a zero tail `[N, W)` — a flat notion. A non-contiguous 1-D `loc` with
  `cols == N` would send the tail lanes to `out_off = offs - N` and **overwrite the live
  prefix**, so the new `assert loc.is_contiguous()` inside that branch is load-bearing, not
  defensive. Its only live caller already passes a contiguous 1-D loc.
- The `out=None` allocation moves off `empty_like`, which would mirror a strided `loc` and
  hand the caller back a non-contiguous result.

Nothing feeds this kernel a strided tensor *before* commit 2, so on its own this commit
changes no behaviour.

## Commit 2 — the fold

`translate_kv_loc` becomes a call into `_translate_loc_fused`; `_translate_kv_loc_impl` and
`translate_kv_loc_for_kernel` are deleted along with the TODO, and the last `_for_kernel`
caller (the SWA read path) moves over. One implementation remains.

**What changes for a caller**, measured at page sizes 1 and 4:

- **`-1`, the padding id every read table carries, is unaffected** — the v2p table's
  trailing sentinel is `-1`, so both paths already resolved it to 0.
- **A loc below `-(ps + 1)` floors onto a REAL page** instead of the sentinel. The old body
  indexed with it and returned a live slot belonging to another request (7 at ps 1, 31 at
  ps 4, with the last page bound); it now resolves to 0, the sink. **This is the fix.**
- **An id past the table** used to fault, because torch's gather bounds-checks; `tl.load`
  does not, so the kernel now excludes those lanes explicitly and they resolve to the sink
  too. Trading a fault for a sink is deliberate: this is reachable inside a captured graph,
  where a fault is not a diagnostic and an out-of-bounds read is worse than a
  wrong-but-addressable id. The fa3 comment that described the old fault is corrected.

Unchanged: int32 and 2-D inputs, the int64 result shaped like the input, `out=` identity and
`data_ptr` stability, `translate(x, out=x)` aliasing, and the tombstoned-v2p clamp. Strided
inputs become legal, which is what the SWA read path needs.

On the read path this replaces up to six torch launches with one; on the write path nothing
moves, since it already used this kernel. Non-CUDA accelerators take the wrapper's torch
reference for one more surface, as they already do for writes.

## Tests

- `test_matches_reference_on_a_strided_view` — **red before commit 1**
  (`AssertionError: loc must be contiguous`), green after. Reuses the existing
  definition-not-expectation reference rather than adding a second oracle.
- `test_out_width_needs_a_packed_loc` — green on both sides (before, on the blanket assert;
  after, on the narrow one); it pins the branch that would otherwise regress silently.
- `test_a_loc_past_the_sentinel_lands_on_the_sink` and
  `test_an_out_of_range_loc_lands_on_the_sink` — **red on commit 1, green on commit 2**.
  These carry the fold.
- `test_a_negative_loc_lands_on_the_sink` — 6/7's deliberately loose test, tightened to
  `== 0`. Green on both sides, and labelled as such: it pins semantics that are now
  single-valued, it is not a regression guard.
- `kernels/ops/memory/test_write_loc_to_kernel_ids_strided.py` (new, GPU) — the Triton
  addressing is reachable only on a GPU, so this is the **only** test that can catch a wrong
  `row * rs + col * cs`. Its oracle is the kernel itself on a contiguous copy of the same
  values, so a stride bug shows as a value mismatch rather than a crash that may never come.

## Validation

Model families exercised — a hybrid of every pool shape the unified pool supports, plus a
non-hybrid control. Perf covers the gated-deltanet hybrid (Qwen3.5-9B), the MLA hybrid
(Kimi-Linear-48B-A3B), the sliding-window hybrid (gpt-oss-20b), the tri-pool hybrid
(Inkling and Inkling-Small), and dense Llama-3.1-8B as a control. Accuracy covers the same
set and additionally the Mamba hybrid, Falcon-H1-7B. Each model is run unified against a
baseline on the same model, backend and configuration, so every delta isolates the pool.

Median inter-token latency, unified vs baseline: **+0.71%** (measured run-to-run noise floor
for this metric: 1.9%). Median GSM8K delta at n=200: **+0.00 pt** (binomial delta-sigma ≈ 3.0 pt).

Re-validated on the current base after review feedback: the stack tip (7/7) gives **+0.95%** median inter-token latency over 40 paired configurations (median per-configuration shift against the previous run of the same 40: +0.12 pp) and **−0.25 pt** median GSM8K over 26, with the full unit scope green.

Accuracy spread is sd 1.67 pt against a **measured** same-arm floor of ±2.9 pt, obtained by
running two identical configurations against each other rather than assuming the binomial.

## Not yet validated

aiter, fa4, trtllm_mla, cutedsl_mla and tokenspeed_mla are admitted under
`--enable-unified-memory` and supported by this change but not yet validated on SM100-class
or ROCm hardware; the same holds for trtllm_mha's SM100 kernels and `--dcp-size > 1`.

## Follow-ups this PR deliberately does not do

- **Lift the fa3/fa4 local-attention refusal** under `--enable-unified-memory`. Commit 1
  removes one technical reason for it, but validating the lift needs a local-attention model
  our harness does not carry.
- **Drop the now-redundant `stride` parameter** of `write_loc_to_kernel_ids` — since 5/7 it
  always equals `page_size`. A separate simplification; folding it in would blur this PR's
  red/green story.
- **Fold the mamba id translate.** `UnifiedMambaPool.translate` is still a plain torch gather.
  At `page_size == 1` it computes the same value, but it does not clamp, so a tombstoned row
  returns `-1` rather than the sink. Whether a tombstoned id can reach it is a caller
  question we have not settled; flagged rather than changed blind.
