# [PR #41165] Let predicate-registered linear-attention models carry the mamba radix-cache leaves

source: https://github.com/sgl-project/sglang/pull/41165
state: open | updated: 2026-09-25T07:37:26Z
labels: run-ci, run-ci-extra

## 正文

## Motivation

- A hybrid linear-attention model can register either by architecture name or by a predicate on its HF config.
- The mamba radix-cache resolution and the validation from #37474 only looked the spec up by architecture name, and extra-buffer support came only from a hard-coded set of architectures.
- A predicate-registered model therefore never got its mamba radix-cache leaf: auto could not pick the extra-buffer strategy, and an explicit extra-buffer strategy was rejected as "needs mamba state". Out-of-tree models had to patch the architecture sets, even though the spec already carries the information, including an unused extra-buffer support field.

## Modifications

- (-) Spec lookup by architecture name only, extra-buffer support from the hard-coded set only, and the resolution, validation, and hook helpers took an architecture string.
- (+) One lookup resolves the spec by architecture name first and by config predicate second, the spec's extra-buffer field is honoured under the same triton-backend condition, and the helpers take the HF config so the name and the spec come from one input. Behaviour for hard-coded and arch-registered models is unchanged; unit tests cover predicate-registered specs (auto and explicit), predicate misses, and arch-registered specs without the opt-in.

Possible follow-up: migrate the hard-coded architecture sets onto registry specs so the registry becomes the single source of truth.
