## Motivation

This PR fixes two cases where a layer's output was summed more than it should be when its FFN reduction runs later than the FFN.

1. **Replicated TP1 shared expert.** With `SGLANG_SHARED_EXPERT_TP1=1`, Laguna and `DeepseekV2MoE` (DeepSeek-V2/V3, GLM5-Next without MHC) replicate the shared expert on every TP rank and add its full output after the MoE all-reduce. When that all-reduce is left to a later step, the MoE block returns a partial sum and every rank still adds the shared output. So the later sum counts it `tp_size` times. The later step is either fused into the next layer's residual norm, or, under DP attention, the reduce-scatter back to the local tokens.
2. **Dense layers under DP attention reduce_scatterv.** Under DP attention with tp == dp == ep and no a2a backend, `postprocess_layer` reduce-scatterv'd every FULL-mode layer's output, whether or not the layer allows reduce-scatter.
   - A MoE block leaves its all-reduce out under the same condition, so that sum is owed.
   - A dense MLP leaves it out only under the published `mlp_reduce_scatter`, which needs `allow_reduce_scatter`. Without it, the MLP has already all-reduced, and the reduce-scatterv sums the output `tp_size` times.

   The layers affected are the dense layers of Qwen3, MOSS-VL, Step3-VL, LongCat-Flash and Bailing-MoE-Linear, and the MiMo-V2 MTP layer. The MoE blocks of Step3-VL (`Step3TextMoEMLP`) and LongCat-Flash (`LongcatFlashMoE`) all-reduce inside the block, so reduce_scatterv still sums their output twice; this PR does not change them. Separately, the LongCat-Flash NextN dense MLP never reduced its output at TP > 1; only reduce_scatterv summed it, by accident.

## Modifications

- **TP1 shared expert:**
  - `should_add_replicated_moe_output()`: when a later step still owes the TP sum, only TP rank 0 adds the replicated shared output; otherwise every rank adds it. Paths that reduce inside the MoE block, or whose output is already complete, keep their numerics.
  - A source guard requires every model that reads `SGLANG_SHARED_EXPERT_TP1` to add the shared output under this predicate.
- **Dense reduce_scatterv:**
  - postprocess uses reduce_scatterv only when the layer is sparse or allows reduce-scatter, and otherwise scatters without summing. `LayerScatterModes` records `is_layer_sparse` for this.
  - The LongCat-Flash NextN MLP all-reduces its own output like the other dense layers.
  - `test_postprocess_reduce_scatterv.py` pairs every (sparse × allow) combination with the FFN's own skip predicate, so postprocess sums exactly when the FFN left the sum out.

## Accuracy Tests

**TP1 shared expert, B200, DeepSeek-V2-Lite TP2 with the env on** (4 greedy requests × 32 tokens; text, token logprobs and top-5 logprobs compared; TP1 is the reference):

| Config | First diverging token (4 requests) | Max step-0 top-5 \|Δlogp\| |
|---|---|---|
| parent, fusion on | 1, 1, 1, 0 | 1.846 |
| this PR, fusion on | 32, 4, 32, 32 | 0.112 |
| parent, fusion off (noise reference) | 1, 32, 32, 32 | 0.092 |
| parent, DP attention (dp 2) | 1, 1, 1, 2 | 1.075 |
| this PR, DP attention (dp 2) | 32, 32, 32, 32 | 0.073 |

The configurations that owe no later sum are bit-identical to the parent: env on with fusion off, and env off with fusion on.

**Dense reduce_scatterv, B200:**

| Config | Result |
|---|---|
| main, Qwen3-0.6B TP2 DP2 ep 2 | diverges at tokens 0, 0, 6, 1 (max step-0 top-5 \|Δlogp\| 1.75); output turns into garbage |
| main, same with ep 1 (reduce_scatterv does not apply) | TP2 noise level |
| this PR, ep 2 vs this PR, ep 1 | identical (for a dense model, ep only changes the reduce_scatterv decision) |
| this PR ep 1 vs main ep 1 | identical |
| Qwen3-30B-A3B-FP8 TP2 DP2 ep 2 (sparse, allows reduce-scatter), parent vs this PR | identical |
| DeepSeek-V2-Lite TP2 DP2 ep 2, parent vs this PR | identical |

The unit tests for MoE output reduction, the layer-stack exit, aux capture, postprocess reduce_scatterv, the layout and the CP dense MLP all pass.

Rebased onto main `9dc4c5d891`: every commit's patch is unchanged, and the related unit tests pass on the new base. The GPU results above were measured on the previous base, `5bb850d536`.
