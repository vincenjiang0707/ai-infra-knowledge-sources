## 正文

### Motivation

SGLang currently ships three DCP (Decode Context Parallel) attention-reduction backends (`server_args.py`, default `ag_rs`):

- **`ag_rs`** (default): NCCL `all_gather` of the head-partial output + LSE, then Triton correction + `reduce_scatter` (`cp_lse_ag_out_rs_mla` in `layers/dcp/comm.py`). Two NCCL collectives per layer.
- **`a2a`**: packs output + fp32 LSE into one buffer, runs NCCL `all_to_all_single`, then a local Triton combine (`dcp_a2a_lse_reduce`). Still one NCCL collective + pack/unpack copies per layer.
- **`fi_a2a`**: FlashInfer MNNVL All-to-All kernel — requires SM90+ **and MNNVL fabric memory** (e.g. GB200 NVL72), unavailable on the common single-node NVLink/NVSwitch clusters.

On a single-node NVLink/NVSwitch GPU domain (e.g. H20 ×8, A100 ×8, H100 ×8), the only usable backends are `ag_rs` and `a2a` — **both route the exchange through NCCL collectives**. Neither leverages the direct peer-to-peer memory access that PyTorch symmetric memory makes available inside a single node. At high concurrency (conc=64+) this NCCL exchange sits on the critical path of every decode step and becomes a measurable bottleneck.

### Proposed Solution

Add a new `--dcp-comm-backend symm_a2a` backend that:

1. Allocates a **peer-mapped symmetric memory slab** across DCP ranks (via PyTorch `_SymmetricMemory.empty_strided_p2p` + rendezvous)
2. Each rank **directly writes** partial attention output + LSE into peer buffers using vectorized `uint4` P2P stores over NVLink/NVSwitch (no NCCL)
3. Each rank signals peers (release) then spin-waits on its local signal slots (acquire) and runs a lightweight **CUDA combine kernel** to perform the LSE-weighted reduction
4. Uses **epoch double-buffering** (`parity = epoch & 1`) for CUDA graph compatibility (no host-side sync between replays)

### Key advantages over `ag_rs`/`a2a`:

- **No NCCL on the exchange**: replaces the NCCL collective (+ pack/unpack for `a2a`) with direct P2P writes + a local combine kernel
- **Fully kernel-based**: all four steps are plain CUDA kernels on the compute stream, captured inside the existing decode CUDA graph (epoch double-buffering removes host-side sync between replays)
- **Lower latency at high concurrency**: direct NVLink/NVSwitch writes + local LSE combine vs. NCCL collective round-trip
- **No MNNVL required**: works on any single-node NVLink/NVSwitch domain, unlike `fi_a2a`

### Cerdore · 2026-08-04

> Can you try if `a2a` with `--enable-symm-mem` work for your use case?

Hi, I tested --dcp-comm-backend a2a --enable-symm-mem and found two bugs that prevent it from working:

1. NCCL crash at conc>32 (eager decode path): _all_to_all_single in parallel_state.py checks pynccl_comm.disabled but never enables it via change_state(enable=True). In the eager decode path (B > cuda-graph-max-bs-decode), pynccl stays disabled → falls back to torch.distributed.all_to_all_single → NCCL 2.27.7 unhandled cuda error in ncclGroupEnd.

2. OOM from symm_mem prealloc: prealloc_symmetric_memory_pool allocates 4GB after _profile_available_bytes computes the KV cache budget, so the 4GB isn't accounted for → OOM at startup.

| Config | conc=8 | conc=64 |
|---|---|---|
| a2a | ✅ | ❌ NCCL crash |
| a2a + --enable-symm-mem | ❌ OOM | ❌ OOM |

I've prepared a patch for both issues and will open an issue with full details + repro.

Hey @Cerdore,

I've been building an automated GPU cluster forensics tool called **Denpex** (https://denpex.com), and I'm testing it on real-world cluster traces to gather engineer feedback. Looking at this trace:

### Diagnosis: NVLINK_P2P_SYMM_A2A (85% confidence)

### Root Cause
When running MLA decode with peer-direct A2A on single-node NVLink, latency spikes or silent CUDA illegal memory access can occur if CUDA IPC handles are not cached across iterations, forcing repeated `cudaIpcOpenMemHandle` calls during the decode micro-batch.

### Immediate Troubleshooting Steps
1. **Pre-map Peer Memory**: Pre-register and cache all peer IPC buffer pointers during initialization so the eager decode path never invokes synchronous CUDA driver runtime calls.
2. **Verify Full NVLink Mesh**: Check NVLink connectivity between all GPU pairs:
   ```bash
   nvidia-smi topo -m
   ```
   Ensure all interconnects show `NV12` or `NV18` without PCIe bridging.

*(Tested via Denpex: https://denpex.com. If you test this, I'd really appreciate your feedback on whether the pointer caching improves decode throughput!)*
