### AlejandroParedesLT · 2026-07-13

I dug into this a bit — pulled out the exact source file that's failing to compile (`topk_v2.cuh`) and fed it to `nvcc` directly, outside the full sglang stack. A few findings:

- It really is `nvcc` itself crashing (specifically `cicc`, the device-code compiler stage), not something flaky about the machine. It's 100% reproducible.
- CUDA 13.1 and 13.2 both crash on this file targeting `sm_90`. CUDA 12.4 compiles it just fine. So this smells like a regression in the CUDA 13.x compiler rather than something 13.1-specific — I wouldn't assume 13.0 fixes it without testing.
- Narrowed it down to the two Hopper cluster kernels in that file (`topk_small_batch_kernel` / `topk_persistent_cluster_kernel`). Everything else in the file compiles fine; it's specifically these that trip the compiler up.

Given 12.4 works, a workaround short-term might be pointing the JIT build at a CUDA 12.x toolkit instead of downgrading your whole driver/runtime — this is purely a compile-time issue.

This looks like an nvcc bug worth reporting to NVIDIA directly rather than something fixable on the sglang side. Happy to help shrink it into a minimal repro if that'd be useful for a bug report.
