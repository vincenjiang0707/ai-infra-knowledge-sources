# [Issue #39277] [Bug] b12x-vision dev-v4f-2dgx regresses DSV4 history argument encoding from #28035

## 正文

## Summary

The `b12x-vision` branch at `452239a74f5b31798290f57aeac2645d98a52f44`, used by the two-DGX/GB10 DeepSeek V4 preview images, has regressed the `encoding_dsv4.py` portion of #28035.

The image commit is a descendant of the #28035 merge commit, and `serving_chat.py` still normalizes valid OpenAI assistant-history `function.arguments` JSON strings into dictionaries. However, `encode_arguments_to_dsml()` on this branch again calls `json.loads()` unconditionally. When it receives that already-normalized dictionary, the resulting `TypeError` is caught and the dictionary is wrapped as `{"arguments": original_dict}`. This encodes an incorrect extra DSML parameter layer.

## Affected branch and images

- Branch: `b12x-vision`
- SGLang commit: `452239a74f5b31798290f57aeac2645d98a52f44`
- ARM64 image digest: `sha256:03f2844f04c943aad743e36b8f8ce4716d1d0258c54de8503543fcc38aa48c87`
- Tags resolving to that digest:
  - `lmsysorg/sglang-staging:dev-v4f-2dgx`
  - `lmsysorg/sglang-staging:dev-cu13-v4f-2dgx`
  - `lmsysorg/sglang:dev-v4f-2dgx-v2`

The staging tags were last pushed on 2026-09-02; the public `-v2` alias was last updated on 2026-09-03.

## Minimal reproduction

This is the value passed to the DSV4 encoder after `serving_chat.py` has normalized a valid OpenAI history call:

```python
from sglang.srt.entrypoints.openai.encoding_dsv4 import encode_arguments_to_dsml

print(
    encode_arguments_to_dsml(
        {
            "name": "read",
            "arguments": {"filePath": "/tmp/example.txt"},
        }
    )
)
```

Actual output is equivalent to:

```xml
<｜DSML｜parameter name="arguments" string="false">{"filePath":"/tmp/example.txt"}</｜DSML｜parameter>
```

Expected output:

```xml
<｜DSML｜parameter name="filePath" string="true">/tmp/example.txt</｜DSML｜parameter>
```

Current branch logic:

```python
try:
    arguments = json.loads(tool_call["arguments"])
except Exception:
    arguments = {"arguments": tool_call["arguments"]}
```

The #28035 behavior accepts either the original JSON string or the already-normalized dictionary, then validates that the result is an object:

```python
raw_arguments = tool_call["arguments"]
arguments = (
    json.loads(raw_arguments) if isinstance(raw_arguments, str) else raw_arguments
)
if not isinstance(arguments, dict):
    raise ValueError(
        "Assistant tool call function.arguments must be a JSON object."
    )
```

## Impact

Valid multi-turn OpenAI tool histories are encoded back into the model prompt with an extra `arguments` wrapper. This can teach or induce DeepSeek V4 to emit the same invalid nested shape, causing downstream agents to reject otherwise valid tool calls because required schema fields appear to be missing.

## Relationship to #38386

#38386 repairs nested arguments emitted by the model in the DeepSeek tool-call detector. It is useful but is not a replacement for this fix: this regression corrupts valid assistant tool-call history while constructing the prompt, before output parsing happens.

## Requested fix

1. Restore the #28035 `encoding_dsv4.py` behavior on `b12x-vision`.
2. Add a branch regression test where `encode_arguments_to_dsml()` receives an already-normalized dictionary.
3. Publish a refreshed, preferably versioned two-DGX/GB10 image and update the DeepSeek V4 cookbook to its immutable digest.


## 评论 (1)

### RayJueWang · 2026-09-23

Confirming this on a separate production deployment, with a minimal repro script and evidence isolating the defect to prompt encoding rather than the response parser.

**Environment**

- `DeepSeek-V4-Flash-Vision-Exp`, SGLang preview image, 4-way TP
- `--tool-call-parser deepseekv4 --reasoning-parser deepseek-v4 --speculative-algorithm DSPARK --moe-runner-backend marlin`

**Trigger, isolated**

Ran five scenarios that differ by exactly one field in the message history, 10 iterations each:

| # | history | result |
|---|---|---|
| 1 | single turn (no history) | 10/10 OK |
| 2 | `assistant.tool_calls` + `role:tool` | **7/10 wrapped** |
| 3 | `role:tool` only, no `tool_calls` | 10/10 OK |
| 4 | `assistant.tool_calls` only | **6/10 wrapped** |
| 5 | plain-text `assistant` history | 10/10 OK |

The trigger is solely the presence of `tool_calls` on an assistant history message. `role:tool`, multi-turn on its own, and plain-text history are all clean. Failure rate is ~60-90% and does not accumulate with history depth — one prior `tool_calls` is enough.

**Evidence that this is encoding, not parsing**

Sending the same `tool_calls` history but omitting `tools` from the request bypasses the tool-call parser, so the model's raw output lands in `content` verbatim:

```
<｜DSML｜tool_calls>
<｜DSML｜invoke name="read_file">
<｜DSML｜parameter name="arguments" string="false">{"path": "/tmp/b.txt"}</｜DSML｜parameter>
</｜DSML｜invoke>
</｜DSML｜tool_calls>
```

Expected instead: `<｜DSML｜parameter name="path" string="true">/tmp/b.txt</｜DSML｜parameter>`.

6/6 reproduction. Note `string="false"` — the model is faithfully imitating a malformed in-context example, not generating randomly. The parser is downstream and blameless; it correctly parses what the model was shown how to write.

Two further checks support the "imitates the prompt" reading: deliberately writing the *history* `arguments` as already-double-wrapped keeps the failure rate at 7/10, and passing history `arguments` as a dict instead of a JSON string raises it to 8/10. Multi-argument tools collapse the same way (`mv` with `src`/`dst` becomes one `arguments` element), so this is not specific to single-argument tools.

**Repro script**

Endpoint, key and model come from env vars; no other configuration needed.

```python
#!/usr/bin/env python3
"""
Minimal repro for the DSV4 multi-turn tool-call double-wrapping bug.

    export OPENAI_BASE_URL=http://<host>:<port>/v1
    export OPENAI_API_KEY=<key-if-any>
    export MODEL=<served-model-name>
    python repro_dsv4_history.py [N]        # iterations per scenario, default 10

Exits 1 if any double-wrapped response was observed.
"""

import collections
import json
import os
import sys
import urllib.error
import urllib.request

BASE_URL = os.environ.get("OPENAI_BASE_URL", "http://localhost:30000/v1").rstrip("/")
API_KEY = os.environ.get("OPENAI_API_KEY", "EMPTY")
MODEL = os.environ.get("MODEL", "deepseek-v4")
N = int(sys.argv[1]) if len(sys.argv) > 1 else 10

TOOLS = [
    {
        "type": "function",
        "function": {
            "name": "read_file",
            "description": "Read a file's contents",
            "parameters": {
                "type": "object",
                "properties": {"path": {"type": "string"}},
                "required": ["path"],
            },
        },
    }
]

ASSISTANT_TOOL_CALL = {
    "role": "assistant",
    "content": None,
    "tool_calls": [
        {
            "id": "call_1",
            "type": "function",
            # Per the OpenAI schema this is a JSON *string*.
            "function": {"name": "read_file", "arguments": '{"path": "/tmp/a.txt"}'},
        }
    ],
}
TOOL_RESULT = {"role": "tool", "tool_call_id": "call_1", "content": "hello"}
FIRST_USER = {"role": "user", "content": "Read /tmp/a.txt"}
SECOND_USER = {"role": "user", "content": "Now read /tmp/b.txt"}

# Each scenario isolates one variable, to pin down what actually triggers the bug.
SCENARIOS = [
    ("1. single turn (baseline)", [FIRST_USER]),
    (
        "2. assistant.tool_calls + role:tool",
        [FIRST_USER, ASSISTANT_TOOL_CALL, TOOL_RESULT, SECOND_USER],
    ),
    ("3. role:tool only, no tool_calls", [FIRST_USER, TOOL_RESULT, SECOND_USER]),
    ("4. assistant.tool_calls only", [FIRST_USER, ASSISTANT_TOOL_CALL, SECOND_USER]),
    (
        "5. plain-text assistant history",
        [
            FIRST_USER,
            {"role": "assistant", "content": "I read /tmp/a.txt; it says hello"},
            SECOND_USER,
        ],
    ),
]


def post(payload):
    req = urllib.request.Request(
        f"{BASE_URL}/chat/completions",
        data=json.dumps(payload).encode(),
        headers={
            "Authorization": f"Bearer {API_KEY}",
            "Content-Type": "application/json",
        },
    )
    with urllib.request.urlopen(req, timeout=180) as resp:
        return json.loads(resp.read())


def classify(resp):
    """-> (label, detail). WRAPPED means the bug reproduced."""
    message = resp["choices"][0]["message"]
    tool_calls = message.get("tool_calls")
    if not tool_calls:
        return "NO_TOOL_CALLS", (message.get("content") or "")[:160]
    raw = tool_calls[0]["function"]["arguments"]
    try:
        args = json.loads(raw) if isinstance(raw, str) else raw
    except (TypeError, ValueError):
        return "BAD_JSON", repr(raw)[:160]
    if isinstance(args, dict) and list(args.keys()) in (["arguments"], ["parameters"]):
        return "WRAPPED", repr(raw)[:160]
    return "OK", repr(raw)[:80]


def run_scenario(messages):
    counts = collections.Counter()
    samples = {}
    for _ in range(N):
        try:
            label, detail = classify(
                post(
                    {
                        "model": MODEL,
                        "messages": messages,
                        "tools": TOOLS,
                        "tool_choice": "auto",
                    }
                )
            )
        except (urllib.error.URLError, OSError, KeyError) as err:
            label, detail = "REQUEST_FAILED", repr(err)[:160]
        counts[label] += 1
        samples.setdefault(label, detail)
    return counts, samples


def show_raw_model_output():
    """Send the tool_calls history WITHOUT `tools` so the parser is bypassed.

    The malformed DSML then shows up verbatim in `content`, which is what proves
    the defect is in prompt encoding rather than in the response parser.
    """
    resp = post(
        {
            "model": MODEL,
            "messages": [FIRST_USER, ASSISTANT_TOOL_CALL, TOOL_RESULT, SECOND_USER],
        }
    )
    content = resp["choices"][0]["message"].get("content") or ""
    print("raw model output (no `tools` in request, parser bypassed):")
    print(f"  {content[:400]!r}")
    if 'name="arguments"' in content:
        print('  => CONFIRMED: prompt contains a parameter literally named "arguments"')
        print('     expected instead: parameter name="path"')
    else:
        print("  => no malformed parameter seen in this sample")


def main():
    print(f"endpoint={BASE_URL}  model={MODEL}  iterations={N}\n")

    wrapped_total = 0
    for name, messages in SCENARIOS:
        counts, samples = run_scenario(messages)
        wrapped_total += counts["WRAPPED"]
        print(f"{name:40s} {dict(counts)}")
        for label, detail in samples.items():
            if label != "OK":
                print(f"    {label}: {detail}")
    print()
    show_raw_model_output()

    print()
    if wrapped_total:
        print(f"RESULT: bug reproduced ({wrapped_total} wrapped responses).")
        print("Scenarios 2 and 4 fail; 1, 3 and 5 are clean -> the trigger is the")
        print("presence of `tool_calls` on an assistant history message.")
        return 1
    print("RESULT: no double-wrapping observed.")
    return 0


if __name__ == "__main__":
    sys.exit(main())
```

```
2. assistant.tool_calls + role:tool      {'WRAPPED': 6}
    WRAPPED: '{"arguments": {"path": "/tmp/b.txt"}}'
3. role:tool only, no tool_calls         {'OK': 6}
4. assistant.tool_calls only             {'WRAPPED': 6}
    WRAPPED: '{"arguments": {"path": "/tmp/b.txt"}}'
5. plain-text assistant history          {'OK': 6}

raw model output (no `tools` in request, parser bypassed):
  '\n\n<｜DSML｜tool_calls>\n<｜DSML｜invoke name="read_file">\n<｜DSML｜parameter name="arguments" string="false">{"path": "/tmp/b.txt"}</｜DSML｜parameter>\n</｜DSML｜invoke>\n</｜DSML｜tool_calls>'

     expected instead: parameter name="path"

RESULT: bug reproduced (12 wrapped responses).
```

**On the fix**

Consistent with this issue's analysis, `76603c6c` on #37253 repairs the hunk, and the published preview images predate it — overlaying `encoding_dsv4.py` from that commit resolves it here too, matching what @aditya-ha1 reported on 4x H200. So a rebuilt preview image is the actual ask; +1 to that request.

Two workarounds for anyone blocked meanwhile, both verified here:

1. Unwrap client-side — retry `json.loads`, then strip a sole `arguments`/`parameters` key when it maps to a dict. Guard against stripping a tool that genuinely has a parameter by that name. Keeps standard `tool_calls` history intact.
2. Replace `assistant.tool_calls` history with a plain-text summary (scenario 5) — 12/12 clean, but loses structured history and `tool_call_id` pairing, so it is a stopgap.

Separately, `encode_arguments_to_dsml()` has no test coverage on any branch, which is why the revert went unnoticed. I opened #40830 against `main` with a regression test for the dict-valued case, verified to fail on the pre-fix implementation and pass on current `main`. Happy to retarget or drop it if maintainers would rather it ride along with #37253.
