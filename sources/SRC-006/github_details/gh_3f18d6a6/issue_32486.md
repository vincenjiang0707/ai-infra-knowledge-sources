### Describe the bug

When the target and speculative draft models use different S3-compatible object-storage paths, SGLang downloads metadata only for the target model and tokenizer during `ServerArgs` post-processing. The draft path is not prepared by `ObjectStorageModel.download_and_get_path()` before the draft worker constructs its `ModelConfig`.

This leaves the draft metadata cache without files such as `config.json` and `model.safetensors.index.json`. Even when the draft load format is correctly selected as `runai_streamer`, configuration or shard-index access can fail or fall through to behavior intended for a local/Hugging Face path.

The draft object-storage path should have its non-weight metadata downloaded before workers are launched. If the draft and target paths are identical, the metadata should be downloaded only once.

This is separate from #32202: that issue covers resolving an explicit draft `auto` load format to the correct loader. This issue covers preparing the draft metadata after an object-storage loader is selected, including when `runai_streamer` is specified explicitly.

### Reproduction

Launch speculative decoding with separate target and draft paths in S3-compatible object storage:

```bash
python3 -m sglang.launch_server \
  --model-path s3://bucket/target-model \
  --load-format runai_streamer \
  --speculative-algorithm EAGLE \
  --speculative-draft-model-path s3://bucket/draft-model \
  --speculative-draft-load-format runai_streamer
```

Before worker initialization, observe that `ServerArgs._handle_model_source_paths()` calls `ObjectStorageModel.download_and_get_path()` for the target path, but not for the distinct draft path. The draft `ModelConfig` later resolves its local metadata directory with `ObjectStorageModel.get_path()` even though that cache was never populated.

### Environment

- SGLang: latest `origin/main`, commit `5cc273a780`
- Model storage: S3-compatible object storage
- Deployment where observed: 2 nodes, TP=8, PP=2, NVIDIA H20
- The failure occurs during draft configuration/weight preparation before model execution.
