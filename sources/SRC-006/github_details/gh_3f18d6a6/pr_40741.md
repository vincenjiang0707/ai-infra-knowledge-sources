## Summary

`Qwen3CoderDetector.detect_and_parse()` built `normal_text` only from text before the first `<tool_call>`, so a valid trailing visible suffix was dropped. Streaming already kept emitting after `</tool_call>`, so the same complete output disagreed between modes.

Strip complete `<tool_call>...</tool_call>` blocks when forming non-streaming `normal_text` (prefix, inter-call text, and suffix). Incomplete / stripped tags keep the previous prefix-only fallback.

Fixes #40739

### Pranjulcr7 · 2026-09-27 · COMMENTED

At head `0a7f81d`, the complete-call case works, but a complete call followed by an incomplete call leaks the latter into `normal_text`.

```python
call = '<tool_call><function=get_weather><parameter=city>Paris</parameter></function></tool_call>'
text = 'before' + call + 'between<tool_call><function=get_weather><parameter=city>Rome'
```

With `get_weather(city: string)` declared, non-streaming returns the entire unfinished suffix after `beforebetween`; character-by-character streaming returns only `beforebetween`. The `else` fallback never runs because the earlier complete block makes `tool_call_regex.search(text)` succeed.

Please cover a complete call followed by an unclosed call, and trim the unfinished suffix after removing complete blocks. A truncated final marker such as `after<tool_call` also needs coverage.
