<summary>What the series does</summary>

A router replica subscribes to each worker's KV topic **mid-stream**, so every
block already resident in the engine's radix cache is invisible to it — and
engines publish `BlockStored` only as they *insert*, so a prefix cached hours
ago is never re-announced. A cache-blind replica then scatters the prefixes the
warm replicas were keeping consolidated, degrading the **engines'** locality for
the whole fleet; a rolling update does that to every replica in turn. This
series makes a booting replica pull a tree snapshot from a warm sibling over
HTTP and graft it beneath its live delta stream. Off unless `--kv-peer-selector`
is set.

## What this change does

A router replica subscribes to each worker's KV topic mid-stream, so every
block already resident in the engine's radix cache is invisible to it. The
recovery paths for that — pulling tree state from a warm sibling, or later
from the worker itself — all need the same thing first: a way to get the
tree out and back in without losing what it knows.

Add that surface and nothing else. `export_snapshot` emits a flat,
parent-linked node list in DFS pre-order; `restore_snapshot` grafts one back,
creating nodes that are absent and unioning carriers into nodes that are
present, so restoring onto a live tree is well defined.

Records are parent-linked by INDEX, not by block hash. The same hash
legitimately occupies several tree positions, so a hash-keyed replay would
land in `resolve_parent`'s ambiguous branch and could graft a chain under the
wrong node. Full root-to-node hash paths would be unambiguous too, and
quadratic in depth against chains that run thousands of blocks deep.

Tiers ride along per carrier, parallel to `workers` by index, and
`SnapshotNode::retain_carriers` is the only correct way to filter that pair —
filtering `workers` alone silently re-pairs every later carrier with another
carrier's tiers. An absent `tiers` list reads as device, which is what a
carrier list meant before tiering existed, so the format needs no version bump
in either direction. A tier entry naming only bits this build does not rank is
DROPPED rather than folded onto device: folding would make a future tier's
carrier a preferred device owner here, which is the trade `Tiers::for_store`
already refuses to make for an unknown `medium`.

A snapshot arrives over the network, so shape is validated before any
mutation: backward parent references, in-range worker indices, and a tier list
that either pairs one-to-one with its carriers or is absent. `restore_snapshot`
stays `pub(super)` — the ids in a worker table must be resolved against the
live worker set, never deserialized straight off the wire.

Both passes take the shards one at a time and release a shard's lock every
4096 records. Sharding caps how much of the tree one lock covers, not how long
a pass over that much of it runs, so an unchunked walk would still stall every
match and every publisher cursor rooted in the shard being walked. The result
is a point-in-time aggregate rather than one consistent instant, which is what
a consumer grafting beneath a live delta stream already tolerates. Restore
holds the tree's writer mutex across those gaps, so the other writer cannot
prune a parent an earlier chunk placed and a later chunk hangs a child from.

A snapshot records no shard column. Restore re-derives a chain's shard from its
root hash, landing it where `insert` would have — so a chain that a racing
prune had stranded under some other shard's sentinel is rebuilt where
`match_prefix` can reach it, instead of being copied stranded onto the consumer.
