## 正文

## Summary

Bump `transformers` 5.12.1 -> 5.17.0 (`tokenizers` 0.22.2 -> 0.23.2, required by it), drop the compat patches upstream has made dead, and port the 5.17.0 vision rotary refactor.

The `tokenizers<0.23` note goes away: CLIPTokenizer round-trips identically on slow and fast backends at 0.23.2.

### Patches removed

| Patch | Why it is dead |
|---|---|
| `_patch_nemotron_h_pattern` | Upstream maps `M`/`*` -> `linear_attention`/`full_attention` and handles `-`. Forcing the legacy names now makes the config's own validator reject it. |
| `_ensure_clean_up_tokenization_compat` | `clean_up_tokenization` is back on `PreTrainedTokenizerBase`. |
| `is_flash_attn_greater_or_equal_2_10` half of `_patch_removed_symbols` | Back on `transformers.utils`. |
| ROCm `dynamic_module_utils` symlink hot-patch | Fixed upstream in 5.13.0 (transformers#46618). |

`is_torch_fx_available` is still absent, so that patch stays.

### Changes that are not mechanical

**Config registration.** transformers now ships native configs for types SGLang defines its own classes for, and `AutoConfig.register` without `exist_ok` silently lost to them. Register with `exist_ok=True` only where no `_CONFIG_REGISTRY` re-parse backs the entry up (`zaya`, `cosmos3_edge`). `_LazyAutoMapping` keys on the config class `__name__`, so a differently-named shadow would drop out of PROCESSOR/TOKENIZER/MODEL_MAPPING. `cosmos3_omni` keeps losing to the native `Cosmos3OmniConfig` for that reason.

**Gemma4 attention shapes.** transformers now states Gemma4's global/SWA split as a heterogeneous `per_layer_config` -- the base attributes are the sliding-window values and the full-attention layers override `head_dim` (plus `num_key_value_heads` where the checkpoint sets it) -- and consumes `global_head_dim` / `num_global_key_value_heads` building it. A plain `text_config.head_dim` read raises `AmbiguousGlobalPerLayerAttributeError`, so every Gemma4 launch died in `get_config`. The parser takes both shapes off concrete layer indices, then drops the spec once it has flattened them onto SGLang's base / `swa_*` pair. A spec declaring anything beyond those two attributes, or a layer type carrying more than one shape, is rejected rather than silently flattened: SGLang carries one shape per layer type, and dropping the spec would revert the rest to the global value with the weights still loading.

**`embedding_rowwise`.** transformers appends `embed_tokens: embedding_rowwise` to `base_model_tp_plan` for every tied-embedding config. The style targets an `nn.Embedding`, which the Transformers backend shards itself in `replace_vocab_embed_class`, but `_normalize_tp_plan` rejected the unknown name up front and those models stopped loading.

**`layer_types` length.** Step-3.5-Flash lists an entry per main *and* next-n-predict layer (45 + 3), which the strict `validate_layer_type` in 5.17 rejects. The new patch re-runs the original validator against the wider count, so every other rule it applies -- per-list vocabularies, legacy remapping -- still holds.

**`_patch_rope_parameters_validation`.** Narrowed to swallow the missing `max_position_embeddings` rather than skip `standardize_rope_params` outright. The call also resolves `default_rope_type`, so the blanket early return left every config without `max_position_embeddings` on `"default"`. Pixtral's vision config is exactly that, and its tower refuses to build unless it sees `"axial"`.

Pixtral's rope table is unchanged: the axial `PixtralVisionRotaryEmbedding` indexes the `(h, w)` grid pairs that this file's own `position_meshgrid` already produces, instead of the flattened `h * max_width + w` offsets. `TestPixtralVisionRope` pins it to the closed form so an upstream change to the recomposition cannot silently rotate every patch by the wrong angle.
