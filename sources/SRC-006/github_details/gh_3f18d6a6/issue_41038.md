## Describe the bug
With Mooncake PD disaggregation, GLM-5.3-Flash plus DFlash2 and smaller prefill TP than decode TP can fail KV transfer. Target MLA KV has compatible per-rank layout, but the draft KV is head-sharded: a P TP2 draft page has twice the per-rank bytes of a D TP4 draft page. The generic transfer uses the P item length as the D stride, so draft writes address the wrong D locations. This is a different path from the DCP-specific relayout merged in #40045.

## Reproduction
- Model: GLM-5.3-Flash with a compatible DFlash2 draft checkpoint (BF16 draft KV).
- Hardware: B300. Two P replicas, each TP2/EP2; one D worker TP4/EP4. No CP/DCP.
- Both roles: `--speculative-algorithm DFLASH --speculative-draft-model-path <draft> --speculative-dflash-block-size 8 --disaggregation-transfer-backend mooncake`. P uses `--disaggregation-mode prefill`; D uses `--disaggregation-mode decode`. CacheLink disabled.
- Route through Hydra; send 256 chat-completions requests at concurrency 64, with approximately 4096 input and 1536 output tokens.
- Observed before the local fix: 228/256 completed, with 28 failed KV transfers. Narrowing RDMA HCAs removed transport retries but did not remove these failures. A local prototype that keeps target KV on the generic path and transfers only the owning D rank draft-head slice completed 256/256 on the same short regression. This is transfer-completion evidence, not a full accuracy claim.

## Expected behavior
P TP2 to D TP4 should preserve each D rank draft KV head slice and use destination per-entry item lengths for destination addresses, without changing the target KV path. Unsupported layouts should fail explicitly rather than silently copy with the P stride.

## Environment
Original reproduction: B300, SGLang v0.5.19-based 2026-09-22 nightly image, Mooncake RDMA, DFlash2 block size 8. Code-path inspection above is against community main be495a6174 (2026-09-24); a full GPU rerun on this exact main commit remains pending.
