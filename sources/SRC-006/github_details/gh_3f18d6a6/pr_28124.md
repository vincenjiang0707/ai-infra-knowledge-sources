# [PR #28124] [AMD] GQA-grouped split-K verify kernel for EAGLE3/MTP extend attention

## 正文

The EAGLE3/MTP verify shape (~4 query tokens over a long ~50K paged KV prefix) is doubly inefficient on AMD (gfx950/MI355X): the default BLOCK_M=64 wastes 60/64 tile rows, and one-program-per-query-head means all kv_group_num GQA heads re-stream the same KV head (6x redundant HBM traffic, ~770 GB/s).

This adds two stacked optimizations for the few-query verify shape only; every other shape and all non-HIP targets keep the existing _fwd_kernel:

1. Block-size tune: when hip_few_query, BLOCK_M=16/BLOCK_N=128/ waves_per_eu=4 (~3.5x microbench over stock).
2. GQA split-K kernels: _fwd_kernel_gqa_split loads each KV head once, packs all kv_group_num q-heads into the M dim (per-row softmax exact) and splits the prefix across NUM_KV_SPLITS to keep the grid full; _fwd_kernel_gqa_combine does the online-softmax reduction + stage-2 triangle. 4.8x microbench / 2.3x E2E ITL over the tuned kernel.

Gated by SGLANG_DISABLE_GQA_VERIFY_KERNEL (kill-switch, environ.py). Max abs err ~1.6e-3 vs the per-head kernel (fp8 KV). New unit test test_extend_attention_gqa_verify registered on AMD CI.
