# [PR #32168] [Fix] Fix Mamba write-back kernel indices lifetime

## 正文

## Motivation

`MambaPoolHost` has `can_use_write_back_jit = True`, which causes `cache_controller.start_writing()` to skip `move_indices()` and pass CPU `host_indices` directly to the kernel. The kernel methods (`_copy_tensor_pf_lf`, `_copy_tensor_all_layers_lf_pf`) then call `.to(cuda)` inside `write_stream` to move indices to GPU. However, these locally created CUDA tensors are not protected by `record_stream()`, creating a potential use-after-free: after the function returns, PyTorch may reclaim the tensor while the kernel is still executing on `write_stream`.

## Modifications

1. Add `_uses_staged_write_back = False` to `MambaPoolHost` class — distinguishes Mamba (doesn't use staged kernel) from MLA (does), while keeping `can_use_write_back_jit = True` for HostPoolGroup AND logic.

2. Add `getattr(self.mem_pool_host, "_uses_staged_write_back", True)` check in `cache_controller.start_writing()` — Mamba now goes through `move_indices()` (default stream `.to()` + `record_stream`), other pools unaffected (default `True`).

3. Remove dead `.to()` code in `_copy_tensor_pf_lf` and `_copy_tensor_all_layers_lf_pf` — indices are now on CUDA before kernel call, making these checks unreachable.

4. Adapt `test_transfer_mamba.py` — `host_indices` created on CUDA (matching production path), assertions use `.cpu()` to index CPU buffers.

Net change: 3 files, +10/-19 lines. Zero impact on MLA/HostPoolGroup paths (getattr defaults to `True`).

## Accuracy Tests

- **Unit tests**: 16 passed (`test_transfer_mamba.py` — covers backup/load roundtrip, single item, full indices, empty indices across `page_first`/`page_first_direct` × bf16/fp16)
- **E2e smoke test**: Passed — Mamba server (kernel + page_first + write_through, TP=4), 6 requests with `flush_cache` triggering both backup and loadback paths, no errors in server log.

## Speed Tests and Profiling

No speed impact. The only runtime change is moving `.to()` from `write_stream` to default stream (via `move_indices`), which is functionally equivalent but safer. Kernel receives identical CUDA indices in both cases.
