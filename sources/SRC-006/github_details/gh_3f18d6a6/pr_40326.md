# 1/7 — derive KV row addresses from strides, not shapes

Base: `main`. 1 commit, 12 files, +355/−71.

## The problem

A per-layer K/V buffer is not always a contiguous `[slots, heads, head_dim]` tensor. The
unified memory pool hands out per-layer *views* into one page envelope, and such a view's
slot stride can exceed `heads * head_dim`.

Two things then go wrong, and **neither raises**:

- a consumer that computes a slot address from the tensor's **shape** addresses the wrong
  slot;
- a `.contiguous()` on such a view makes a private copy instead of aliasing the live pool,
  so writes land somewhere the kernels never read.

This PR fixes the sglang-side sites that did either. **On contiguous buffers every change
is a no-op**, so behaviour on today's pools is unchanged — which is why it ships first and
alone.

## What changes

Every sglang-side consumer that derived a KV row address from a tensor's **shape** now
derives it from the tensor's **stride**, and every gate that tested `is_contiguous()` as a
proxy for "addressable" now tests the property the kernel actually requires.

That covers three kinds of site: the pool's own stride tables, which feed the HiCache and
slot-move engines; the write and fused-quantisation kernels, which step by a destination
slot stride instead of assuming a packed row; and the canary/debug sources, which alias the
live layer view rather than snapshotting a copy of it.

One stride helper is narrowed as part of this: it rebuilt every stride from the sizes, which
silently turned a strided view into a contiguous description of itself.

Four CUDA `.cuh` kernels gain a stride parameter. That is the one part of this PR whose blast
radius is not confined to Python, and it is the reason this lands first and by itself.

## Why this is worth its own PR

It is pure hardening: it fixes a class of bug (address derived from shape, not stride)
that is *latent today* and becomes reachable the moment a pool hands out strided views —
which is exactly what 3/7 does. Landing it separately means the layout change that makes
these paths live does not also have to carry their fixes.

## Tests

- `test/registered/unit/mem_cache/test_kv_stride_hygiene.py` — CPU, pins each Python-side
  behaviour on a deliberately strided buffer.
- `test/registered/kernels/ops/kvcache/test_masked_set_kv_buffer_strided.py` — GPU, builds a
  buffer whose slot stride exceeds one K row via `as_strided` and asserts writes land at the
  slot stride. A hardcoded `loc * H * D` writes into the wrong slot **without any error**, so
  this test is the only thing that can catch a regression here.
- `test/registered/kernels/ops/kvcache/test_fused_fp8_qkv_kv_cache.py` — GPU, the strided
  fp8 path.

## Validation

Model families exercised — a hybrid of every pool shape the unified pool supports, plus a
non-hybrid control. Perf covers the gated-deltanet hybrid (Qwen3.5-9B), the MLA hybrid
(Kimi-Linear-48B-A3B), the sliding-window hybrid (gpt-oss-20b), the tri-pool hybrid
(Inkling and Inkling-Small), and dense Llama-3.1-8B as a control. Accuracy covers the same
set and additionally the Mamba hybrid, Falcon-H1-7B. Each model is run unified against a
baseline on the same model, backend and configuration, so every delta isolates the pool.

Median inter-token latency, unified vs baseline: **+0.79%** (measured run-to-run noise floor
for this metric: 1.9%). Median GSM8K delta at n=200: **+0.25 pt** (binomial delta-sigma ≈ 3.0 pt).

Re-validated on the current base after review feedback: the stack tip (7/7) gives **+0.95%** median inter-token latency over 40 paired configurations (median per-configuration shift against the previous run of the same 40: +0.12 pp) and **−0.25 pt** median GSM8K over 26, with the full unit scope green.
