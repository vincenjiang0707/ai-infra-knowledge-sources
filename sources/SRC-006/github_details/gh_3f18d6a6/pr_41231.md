## Summary

Run every base-b, base-b-kernel-unit and extra-a file registered on 1-gpu-large (H100) on an RTX 5090 (SM120, 32 GB) with the CI install and environment, and move the ones that pass without losing coverage. A file with tests skipped on the 5090 only moves when those tests also skip on H100 (ROCm-, SM100- or missing-op-gated).

- base-b-kernel-unit: 154 of 176 files move. The kernel lane now runs 3 shards on 1-gpu-small and 1 job on 1-gpu-large (was 1 and 2).
- base-b: 84 files move; extra-a: 15 files move. Both are sized from est_time by compute_partitions.py (base-b: 5090 8 -> 13, H100 4 -> 2).
- test_nvfp4_marlin was already registered on 1-gpu-small; drop its 1-gpu-large duplicate.
- Raise est_time to the measured 5090 duration where the H100 estimate was more than 1.5x low (24 files).
- Point new kernel correctness tests at 1-gpu-small in test/README.md and the write-sglang-test / add-jit-kernel skills; 1-gpu-large stays for SM90-only kernels.

About 189 min of per-commit H100 est_time moves to the 5090 pool.

Kept on 1-gpu-large: FA3 / FlashMLA / DeepGEMM / HPC-Ops / SM90-only kernels; weights over ~26 GB or two resident models; H100-tuned perf thresholds; int8_scaled_mm (no SM120 kernel); lmms_eval (not installed on Blackwell runners); and files that fail on SM120 (Triton shared- memory limits, FlashInfer top-k, dsv3_fused_a_gemm / tiny_gemm mismatches, EAGLE3 deterministic parity).
