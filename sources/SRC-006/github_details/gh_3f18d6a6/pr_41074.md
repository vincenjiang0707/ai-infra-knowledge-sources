# [PR #41074] fix: load fused shared-expert LoRA weights and bound expert indices

## 正文

Fix fused shared-expert LoRA loading and prevent expert IDs from aliasing another adapter.

- Size each layer's LoRA expert pool from its actual fused MoE layout, including shared slots.
- Load shared-expert factors into those slots using the base module's EP mapping and existing TP slicing/scaling; merge packed routed factors regardless of checkpoint key order, and accept both `.shared_expert.` and `.shared_experts.` paths.
- Assert while allocating the pool that both A/B expert dimensions match the base fused MoE layout (local or global IDs); no device assert or GPU synchronization.
- Reject unsupported shared-outer factors and global-ID/per-rank shared-slot layouts; reject out-of-range expert IDs before adding adapter offsets.

Selected for the v0.1.1 cutoff. FP32 Qwen3-MoE router support remains after cutoff in #40997, paired with Miles #3697. No dtype or accumulation-policy change. 

Validation: existing coverage includes 60 passing tests (5 abstract-base skips), a distinguishing GPU bounds regression, and GLM-5.2 5L TP4/EP1 with fusion enabled. On 8 DAPO 4K sequences ×3, the shared-expert fix reduced slot mean logprob differences from 0.050144/0.039706 to 0.019414/0.015895 (base 0.013156); the additional Bridge row-parallel fix is separate and is not part of this cutoff PR. EP mapping is unit-tested; distributed EP, other backends and CUDA-graph combinations are not comprehensively validated. A host-only probe of the actual initialization check accepts matching global/local dimensions and rejects a missing shared slot on either A or B. CPU loader regression: packed-first and shared-first inputs failed in all 6 EP/order subcases before the fix; after merging packed routed views with shared factors, the full loader file passes 46 tests and 22 subtests. The 9 singular-name subcases also fail before the naming fix and pass afterward. Test fixture cleanup removes 45 net lines. Full local pre-commit passed; fresh split-head GPU CI is pending.

[Model tracking and release split](https://github.com/radixark/miles/issues/3284#issuecomment-5810394134).
