# [PPU][1/N] CI: Add backend registration and runner preflight

<!-- Part of the T-Head PPU roadmap: #37519 -->

## Motivation

First step of the T-Head PPU roadmap (#37519). This lands the CI skeleton only — `HWBackend.PPU` registration, a runner preflight, and a new `pr-test-ppu.yml`. No SGLang-on-PPU runtime code is added, so this PR does not depend on any later PR in the roadmap (SRT platform, kernels, packaging, nightly, docs each land separately).

## Modifications

**Registry plumbing** :

- `python/sglang/test/ci/ci_register.py` — add `HWBackend.PPU` and the AST-parsed `register_ppu_ci()` marker.
- `test/run_suite.py` — support `--hw ppu`. `PER_COMMIT_SUITES[PPU]` is empty and no PPU suite is declared in any of the three suite dicts yet.

**Three hand-maintained mirrors of the registry** need the new backend or they break / mislead once PPU registers anything:

- `scripts/ci/utils/ci_coverage_report.py` — `BACKEND_DISPLAY_ORDER`. Asserted against `HWBackend` at import time, so a missing entry immediately breaks `ci-coverage-overview.yml`. Markdown tables omit the PPU column while it has no tests; JSON keeps a zero entry.
- `scripts/ci/utils/slash_command_handler.py` — `_OTHER_BACKEND_REGISTERS`. Otherwise `/rerun-test` on a PPU test falls through to *"may not be a registered CI test"* instead of the per-backend message.
- `scripts/lint/check_no_registered_tests_in_package.py` — `_MARKERS`. Gates which files under `python/sglang/` this lint AST-parses; a missing marker silently exempts PPU.

**Runner preflight and workflow**:

- `scripts/ci/ppu/check_ppu_environment.py` — validates the `ppu-smi` inventory, the required device nodes, `PPU_SDK`, one tensor op on `cuda:0`, and that `torch.cuda.device_count()` is consistent with `ppu-smi`'s count.
- `.github/workflows/pr-test-ppu.yml` — `check-changes` (live dual-label authorization + paths-filter) → shared `pr-gate`  → `ppu-preflight` → finish aggregator. The shared gate is unchanged.

## Why `torch.cuda`

PPU exposes a CUDA-compatible API — `cuda` is the valid torch device type on a PPU host, and `torch.cuda.is_available()` is `true` even with no NVIDIA GPU present. The preflight logs `PPU_SDK` and
`torch.cuda.get_device_name(0)` (e.g. `PPU-ZW810E`) so the CI output makes the hardware unambiguous.

## Verification

**Registry wiring UTs (34/34 pass):** `python3 -m unittest scripts/ci/ppu/test_ppu_registry.py`. 

**Preflight script on real PPU hardware:** `python3 scripts/ci/ppu/check_ppu_environment.py` inside a T-Head-provided container on a PPU host with `PPU-ZW810E`, PyTorch 2.10.0, `ppu-smi v1.28`, `PPU_SDK v2.1.0`. Every check passes, `exit=0`. This exercises the script directly. A self-hosted PPU runner (label `1-ppu-m890p`) has been onboarded to the upstream repository following the official `setup_github_runner` guide, so the full `ppu-preflight` job can be triggered manually by a maintainer.

**Static:** `ruff format --check`, `ruff check --select=F401,F821,UP037`, and the in-repo lint hooks all pass. `ci_coverage_report.py` still loads and reports PPU.

## Runner triggering

- **PR authorization:** Both `run-ci` and `run-ci-ppu` are checked live on a
  GitHub-hosted runner before PPU scheduling; the shared `pr-gate` remains
  unchanged. Missing labels skip PPU; API errors fail the check.
  `run_all_tests` bypasses path filtering, not authorization.
- **Triggers:** Maintainer-applied authorization labels re-trigger the workflow.
  Unrelated labels skip PPU and use isolated concurrency groups and check names.
  Other runs use ref-based cancellation, including manual and reusable calls.
