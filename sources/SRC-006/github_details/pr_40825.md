## 正文

## Motivation

Enable decode context parallelism for Kimi-K3 on Ascend NPU, including DSPARK target verification, while reusing SGLang's common DCP planner, collectives, and Triton kernels.

This PR publishes the implementation at `72de60d145d9b93f67379a3b0032a4c7813d2b64`, preserving its original seven-commit history, followed by a documentation-only commit excluding local Markdown notes and a prefix-builder performance fix. It includes the compact-communication and shared-metadata refactors beyond the earlier implementation in #37802. The older PR is left unchanged.

## Modifications

- Shard MLA KV storage across DCP ranks while preserving the scheduler's logical token address space. Use fixed-shape ownership masking for NPU KV writes.
- Adapt global DCP state to FIA's local page table, sequence lengths, and causal/MTP mask. Support decode and DSPARK target verification, including empty-shard and graph-padding handling.
- Reuse the common Q AllGather, prefix planner/index translation, and DCP page-table Triton kernel; avoid building packed-KV metadata and ownership masks that the NPU path does not consume. The unpacked Ascend prefix path uses the previous per-request slice/cat construction after an end-to-end TTFT regression report; the packed-KV GPU path retains the shared prefix Triton kernel.
- Reuse `dcp_a2a_lse_reduce`, the Triton compact pack kernel, and the fused packed-view LSE merge. Exchange BF16/FP16 partial output plus FP32 LSE in one HCCL AllToAll instead of casting the entire output to FP32. The NPU DCP merge path no longer calls `npu_attention_update`.
- Reuse persistent send/receive buffers for NPUGraph replay and keep graph metadata storage stable.
- Use standard HCCL buffer configuration rather than an additional DCP-specific buffer environment variable.
- Add configuration checks and unit/kernel coverage. The initial NPU support requires FIA; speculative decoding is limited to DSPARK with static ragged verification. Replicated Q projection and mixed-chunk execution are not supported by this implementation.

## Accuracy Tests

The previous validation run on implementation commit `72de60d145` reported **136 passed, 39 skipped**:

- Shared DCP layout/metadata, LSE merge, and Kimi-K3 override tests: 35 passed, 39 skipped.
- Ascend backend unit tests (run separately with mocks): 92 passed.
- NPU compact communication/page-table/prefix/graph kernel tests: 9 passed.

For the prefix-builder follow-up, the CPU DCP layout/metadata suite was rerun: **22 passed**. Tests verify exact local indices, empty prefixes, bypassing the prefix kernel for unpacked KV, and retaining it for packed KV. Ruff and Black checks passed for the three modified files. The other suites above are historical results, not newly rerun results for this follow-up.

The current graph replay tests use real NPU kernels and NPUGraph but replace HCCL transport with a local copy. They do **not** establish four-node collective correctness or end-to-end model accuracy. Fresh GPQA, long-context prefix-cache, and broader four-node regressions remain to be run for this head. Local Markdown documents are intentionally excluded from the PR diff.

### KDA compatibility / validation boundary

This PR does not modify `ascend_kda_backend.py` relative to its branch base, and does not modify the external `sgl-kernel-npu` source. Its head retains the previous KDA implementation rather than switching to `torch.ops.npu.chunk_kda_fwd`.

Upstream main now uses `chunk_kda_fwd` (introduced by #39589). An accuracy concern was observed in our local evaluation after that upstream transition; attribution to the operator has not been independently established here. We intentionally have not merged/rebased main into this tested snapshot or changed the deployed local trees. Integrating upstream changes requires a separate accuracy validation; opening this PR does not revert the KDA implementation on main.

## Speed Tests and Profiling

For BF16 output with K3 `head_dim=512`, the partial-state payload changes from `(512 + 1) * 4 = 2052` bytes to `512 * 2 + 4 = 1028` bytes per head/query, approximately **49.9% fewer payload bytes**. This is a layout calculation, not a measured TPOT improvement. There is still one Q AllGather and one partial-state AllToAll per participating attention-layer invocation.

Fresh end-to-end TPOT, throughput, and peak-HBM measurements for this refactor remain pending. No TPOT regression or speedup is claimed in this PR.

### Prefix-builder TTFT follow-up

The deployment tester reported TTFT changing from approximately 113 s to 115 s after the reuse refactor, and subsequently confirmed the prefix-builder change as the source through a single-variable end-to-end rollback. The follow-up restores slice/cat prefix construction only for the unpacked Ascend path; shared index translation, Q AllGather, FIA page-table construction, compact communication, fused LSE merge and persistent graph buffers are unchanged. No external kernel was changed or rebuilt. Exact post-rollback request samples are not provided here, and the low-level mechanism has not yet been profiled.

An isolated NPU microbenchmark of 63 prefix constructions (128000 input tokens, 2048-token chunks) measured 12.25 vs 20.48 ms and 11.95 vs 19.50 ms for old vs shared-Triton construction in two warmed runs. Indices matched exactly for both DCP ranks over nine input shapes. These function-level timings do not include full-model execution, inter-rank waits or stream dependencies, and therefore do not rule out the reported end-to-end effect.
