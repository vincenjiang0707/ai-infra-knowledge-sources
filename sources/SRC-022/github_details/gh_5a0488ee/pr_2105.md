## Details

**Work item:** _"Internal"_

**What were the changes?**  
Added multi-threaded replay support to RcclReplayer, to enable replay of logs with multiple CPU threads executing collectives on the same GPU.

**Why were the changes made?**  
The existing replayer was single-threaded and couldn't replay logs from multi-threaded applications where multiple threads use separate communicators concurrently.

**How was the outcome achieved?**  
- Recorded HIP synchronization calls to preserve cross-thread coordination. Without these, event-based dependencies between threads cannot be reproduced, leading to race conditions or deadlocks during replay.

- Extended HIP call recording to capture thread synchronization via external tracer plugin (tools/RcclReplayer/hip-tracer/):
`hipStreamSynchronize`, `hipDeviceSynchronize`
`hipEventCreate/CreateWithFlags/Destroy/Record/Synchronize`
`hipStreamWaitEvent`

_Plugin uses `roctracer` callbacks and is dynamically loaded via `RCCL_HIP_TRACER_PLUGIN` environment variable._

- Updated recorder to support HIP sync operations:
  - Added new `rcclCall_t` enums
  - Extended `rcclApiCall` with `hipEvent_t`
  - Added `record()` overloads

- Implemented multi-threaded replay in the replayer:
  - Grouped operations by original thread ID
  - Introduced thread-safe tracking of streams and events
  - Used a 3-phase model:
    - Sequential communicator creation
    - Parallel execution using one thread per recorded thread
    - Sequential communicator destruction

- Added a **multi-thread, single gpu test** to validate concurrent collective replay    
```
# Build test and generate logs
cd tools/RcclReplayer/test
MPI_DIR=/path/to/mpi ./build_and_run.sh [MPI_RANKS] [NUM_THREADS]                                                                       
```
