## Details
___Do not mention proprietary info or link to internal work items in this PR.___

**Work item:** _AICOMRCCL-361_

**What were the changes?**  
- Reduce all-reduce CU usage to 56 CUs by default on a single node
- Modify `RCCL_WARP_SPEED_ENABLE` to `RCCL_WARP_SPEED_FORCE_ENABLE` for debugging
- Set chunksteps to 1 for single node all-reduce which performs better with unroll factor of 2 needed by WarpSpeed
- Return `RING*` to rccl-tests to highlight warp-specialized ring usage
- Ensure semantic equivalence to NCCL_MAX_NCHANNELS to reflect CU count (not logical channels) when WarpSpeed is enabled or force-enabled. 


**Why were the changes made?**  
- End-to-end workload performance is impacted when compute is overlapped with communication. `all_reduce` is heavily used in such workloads
- WarpSpeed performance could not be observed out-of-the-box for a single node all-reduce
- Implementation's peak BW for all-reduce can now be realized without special environment variables using 56 CUs (down from 112)

**How was the outcome achieved?**  
- Changes to channel upscaling and downscaling logic
- For single node, use single slice and chunk for all-reduce to get an uplift for message sizes that do not use WarpSpeed with lower CU count of 56. WarpSpeed does require unroll factor of 2, so it is applied to all message sizes.
