# [PR #4997] fix: correct tool choice handling for Intern-S and GPT-OSS

## 正文

## Motivation

`tool_choice="required"` could return ordinary text with Intern-S2-Preview or be rejected by the Intern-S1 parser. GPT-OSS tool-enabled requests could fail with HTTP 400 because their structural-tag response format was nested incorrectly.

## Modification

- Build raw vocabulary bytes for `InternS1Tokenizer` so PyTorch and TurboMind can apply guided decoding to Intern-S1 and Intern-S2-Preview, preserving partial UTF-8 tokens and vocabulary padding.
- Add required-tool grammar to the shared `intern-s1`/`internlm` parser, enforcing function names and parameter schemas and allowing multiple calls and optional reasoning.
- Pass GPT-OSS structural tags in XGrammar's native format, enable required tool choice, and reject required requests if grammar construction fails.
- Add grammar and parser regressions and update the English and Chinese tool-calling documentation.

Intern-S2 checks include text/image inputs and reasoning, plus `none`, `auto`, and `required` on TurboMind. GPT-OSS checks cover `auto`, `none`, `required`, and a named function.
