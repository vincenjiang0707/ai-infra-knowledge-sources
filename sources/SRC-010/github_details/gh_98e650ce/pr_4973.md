# [PR #4973] Move shared expert into the MoE FFN layer; shard dense FFN node-locally in MoE models

source: https://github.com/InternLM/lmdeploy/pull/4973
state: closed | updated: 2026-09-17T09:22:30Z
labels: enhancement

## 正文

### Motivation

Today the shared expert is executed by the decoder as a separate dense FFN after the MoE combine, via `GetShardFfnInput` and its clear-stream machinery — a second dense-FFN code path bolted onto the MoE layer. This moves ownership into `MoeFfnLayer` where it belongs, and folds it into the combine. Along the way, dense (non-expert) layers in MoE models stop replicating weights across EP ranks: they shard node-locally and reduce within the node.

### Changes

**Shared expert (`6e3d7d286`)**
- `MoeWeight` owns the shared expert as a `shared` `FfnWeight` child (`X(FfnWeight, shared)`); the decoder's dense-FFN slot is no longer used for it.
- `MoeFfnLayer` (default and A2A impls) runs the shared expert on the main stream into a private buffer and folds it into the combine for its own sequence-parallel rows only (`shared_src` + `shared_begin`/`shared_end`). The row-aware fold is arithmetically identical to the retired zeroed-complement scheme, minus a full-buffer memset per layer per step.
- `Forward`/`Combine` collapsed into one call; `GetShardFfnInput` and its clear-stream machinery deleted.
- `invokeMoeA2ASharedCombine` stays unconditional — the kernel doubles as the routed write-back; shared-expert nullability lives kernel-side, so no-shared models (mixtral, gpt_oss, qwen3-moe) are unaffected.
- `invokeMoeReduce`/`invokeMoeCombine`: `dst` is now write-only (the old in-place `dst` read is gone); `dst_scales` (gate logits) scales the shared-base term only; `shared_src` + row range added; a mismatched `shared_src` dtype aborts in `Buffer::data<T>()`.
- Python builders wire `m.shared` (qwen2, qwen3_5, glm4_moe_lite, interns2_mobius); qwen3 additionally honors `mlp_only_layers` for hybrid checkpoints (previously routed every layer to MoE and failed at load).

**Node-local dense TP in MoE models (`6e3d7d286`)**
- Dense layers in MoE models shard over the node's ranks within the comm domain (loader group `dense_tp`, size `min(comm_size, node_size)`) and reduce within the node (`d_node_group`) — dense layers no longer inherit the EP-row reduce and never pay cross-node traffic. Comm domains spanning nodes must tile the node (`TM_CHECK(comm_size % node_size == 0)`).
- Pure-dense models keep the historical whole-domain allreduce (cross-node legal there); `ep_size == 1` / single-node is byte-identical to before.
- Behavior-change region, code-review-only: dense × EP on multi-node (no local checkpoint has dense layers; all-MoE locally).

**NCCL (`13ae85215`, independent)**
- Relax the DeepEP symmetric-context rail-GIN requirement from a hard check to a warning: single-node runs (no RDMA scale-out) work without GIN contexts. Unrelated to the feature; lands in its own commit.

### Verification

Local suite (scripts/test_turbomind_model.py as-is, ≥128 tokens, greedy), all byte-identical vs the pre-change build:
- Qwen3.5-35B-A3B bf16 tp=1; Qwen3.5-35B-A3B-FP8 tp=1
- Qwen3-30B-A3B tp=1 (no-shared regression)
- Qwen3.5-35B-A3B tp=2 ep=2 (default backend, uneven SP split)
- Qwen3-30B-A3B tp=2 ep=2 under forced single-node deepep (unconditional-write-back path)
- Chunked prefill (token_mask)
- Qwen3.5-35B-A3B tp=2 ep=2 under forced single-node deepep — coherent output (A2A shared fold; no pre-change baseline exists for this cell)

### Not covered

Dense × EP on multi-node; multi-node deepep (shared and no-shared); glm4_moe_lite / qwen2-MoE builders (no local checkpoints — syntax only); `attn_dp > 1` + EP (pre-existing open question, unaffected by this PR).
