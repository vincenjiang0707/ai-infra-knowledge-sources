# [PR #390] Don't enable the assertion check for release build

## 正文

There are lots of DG_HOST_ASSERT before lauch the kernel. For example, https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb6994a58b8a15b4b93bf13ccc16edf247/csrc/apis/mega.hpp 
For now, DG_HOST_ASSERT always do the runtime check which will hurt the performance. Only enable the assertion check when DG_DEBUG is set.

### v6
The release assertion macro suppresses required side effects and breaks JIT kernel generation. The new debug switch also does not reliably re-enable assertions.

### v4
Gate the host assertion macro on the build's own `DG_DEBUG` define instead of the standard `NDEBUG`, and make a debug build pass `-DDG_DEBUG`. This minimal (2-file) change makes the assertion check a pure debug/development aid and removes it from the per-call launch path of every release build (including the runtime JIT recompilation of these headers).

### v3
本次变更旨在避免在 release 构建中因大量 DG_HOST_ASSERT 运行时检查而损失性能，仅在设置 DG_DEBUG 时启用断言。改动涉及 2 个文件：

1. csrc/utils/exception.hpp：将 DG_HOST_ASSERT 宏基于 NDEBUG 做条件编译。定义了 NDEBUG 时，宏展开为空操作 `do { (void)sizeof(cond); } while (0)`，既不产生运行时开销，又通过 sizeof 未求值上下文保留 cond 表达式的编译期合法性检查、避免未使用变量告警；未定义 NDEBUG 时保留原有抛异常行为。

2. setup.py：新增 DG_DEBUG 环境变量（默认 0），当非 DEBUG（release）时向 cxx_flags 追加 `-DNDEBUG`，从而让上面的宏在 release 构建中变为空操作。

整体实现正确、改动范围小且聚焦，符合需求描述。基于 NDEBUG 的条件编译是标准且合理的做法，release 分支的 `(void)sizeof(cond)` 处理得当，既消除运行时开销又保留编译期检查。
