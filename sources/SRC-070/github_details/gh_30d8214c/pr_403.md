## 正文

## Summary

Addresses #372 by allowing explicit SM120 scale-factor recipes to use the existing SM100 UE8M0 packing and validation paths. The architecture checks match the implementation already present in [`nv_dev`](https://github.com/deepseek-ai/DeepGEMM/commit/373f0738de7a320d71d1e7d1824f012a10416e8b).

Scope is limited to scale-factor layout transformation. This does not add a default SM120 recipe, K-grouped SM120 support, full SM120 inference support, or SM121 runtime validation.

## Reproduction

On upstream `main` at `559d79f`, using an RTX 5070 Ti (SM120), CUDA 13.2, and PyTorch 2.13.0+cu130:

```python
import torch
import deep_gemm

sf = torch.ones((4, 128, 8), device="cuda", dtype=torch.float32)
deep_gemm.transform_sf_into_required_layout(
    sf,
    128,
    256,
    (1, 1, 32),
    num_groups=4,
    is_sfa=False,
)
```

Before this change:

```text
RuntimeError: Assertion error (csrc/apis/layout.hpp:60): Unknown SF transformation
```

With this change, the call returns packed `torch.int32` scales with shape `(4, 128, 2)` and stride `(256, 1, 128)`.

### maci0 · 2026-08-24

Correction + sharper finding: `arch_major == 12` checks are already present in `nv_dev` `8b1392b` (csrc/apis/layout.hpp lines 49/57/112), which is what vLLM vendors — so this PR's fix is already in our tree and the SF layout is NOT the remaining SM120 bug on the vLLM-vendored pin.

The actual silent-corruption mechanism on nv_dev 8b1392b: `csrc/apis/gemm.hpp` exports `fp8_gemm_nt` as an **alias of `fp8_fp4_gemm_nt`** (`m.attr("fp8_gemm_nt") = m.attr("fp8_fp4_gemm_nt")`), and on `arch_major == 12` that dispatcher runs `sm120_fp8_fp4_gemm_1d1d` regardless of B's dtype — so a pure fp8×fp8 block-scaled GEMM feeds fp8 weights to an fp4 kernel and silently corrupts output (repro: DSV4-Flash linear on SM121a). The tree has no `sm100_fp8_gemm_1d1d` / `sm120_fp8_gemm_1d1d` impl at all (only `sm90_fp8_gemm_1d1d.hpp` exists). We are preparing a kernel patchset adding the missing pure-fp8 1d1d impl + a dtype-aware dispatch; will link it here when open.
