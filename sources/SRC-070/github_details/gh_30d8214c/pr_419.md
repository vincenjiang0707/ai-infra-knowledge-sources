## 正文

## Summary

`8b1392b` deleted the pure-fp8 1d1d kernels (`sm100_fp8_gemm_1d1d.{hpp,cuh}`, −983 lines) and rewrote the SM12x fp8 dispatch. On arch 12, fp8xfp8 inputs then run the combined `sm120_fp8_fp4_gemm_1d1d` kernel, which misreads fp8 weights as fp4 — **silent numerical corruption** of FP8 linear layers.

Measured on 2x DGX Spark (GB10 / sm_121a), DeepSeek-V4-Flash-0731, vLLM `--linear-backend deep_gemm`:
- `8b1392b` pin: France output degenerates (`' Septy Septy…'`), DSpark draft acceptance collapses, decode ~25.8 → ~4.4 tok/s.
- `a6b593d` pin (last commit with the pure-fp8 kernel): coherent output.

Tracked in #417; vLLM-side interim pin: vllm-project/vllm#53680.

## What this restores

- `csrc/jit_kernels/impls/sm100_fp8_gemm_1d1d.hpp` (JIT kernel runtime)
- `deep_gemm/include/deep_gemm/dg25_fp8/` — the pure-fp8 kernel + its common/ dependencies as a self-contained module
- `gemm.hpp`: fp8xfp8 on arch 10/12 routes to `sm100_fp8_gemm_1d1d`; fp4 keeps the combined kernel (AB-swap paths handled).

## Header fixes the a6b593d TU needs to compile at all

The original 1d1d TU cannot be compiled as generated:

- `common/math.cuh` was never included by the 1d1d include chain → `align`/`swap` in `common/scheduler.cuh:192` / `common/sm100_utils.cuh:127` were undefined (`identifier "align" is undefined`). The TU now includes it and pulls in `deep_gemm::math` (include before the impl header, so the using-directive precedes the dependent code).
- `math.cuh`'s `cast_into_bf16_and_pack` needs `#include <cuda_bf16.h>` (`__float22bfloat162_rn`).
- `std::is_same_v` → `cute::is_same_v` for NVRTC (libcu++ does not expose variable templates in `std` under NVRTC).

## Validation status (honest)

- NVRTC frontend (CUDA 13.3): with the header fixes the TU compiles to PTX for `compute_121a` (~231 KB) — the preamble fix is verified.
- GB10 JIT toolchain gap (same as #417): stock CUDA 13.0/13.3 ptxas rejects `tcgen05.mma`/`.cta_group::1`/`.block32` for every sm_12x target; the NVRTC cubin is rejected by the driver (`CUDA_ERROR_INVALID_IMAGE`); the driver-JIT PTX route is rejected too (`CUDA_ERROR_INVALID_PTX`). So the kernel needs either a toolchain that can assemble tcgen05 for sm_121a, or build-time compilation (the golden/2.5.0 stack precompiles it).
- The `fp8_einsum` o_proj path runs correctly on SM121a with the restored stack (T=10/96/8192, finite output).

Happy to adjust the module naming (e.g. rename `dg25_fp8` → `sm100_fp8` or fold into the existing tree) to match maintainer preference.

### maci0 · 2026-08-26

Thanks for the detailed review — all three criticals are addressed in 44d9d2e:

1. **SM120 swap_ab (transposed D)**: pure fp8 is now excluded from the host-side AB-swap decision (`swap_ab` requires `!pure_fp8`). The pure-fp8 branch always calls `sm100_fp8_gemm_1d1d` with the original a/b and m/n, with SF transformed unswapped — the restored kernel has no transposed-store support, and the SM100 heuristics cover small M with block_m<=32 candidates.

2. **SM100 swap layouts from heuristics**: added `GemmDesc::allow_swap_ab` (default `true`, so all existing kernels keep their candidate set); `SM100ArchSpec::get_layout_candidates` skips the `swap_ab==1` iteration when it is false; the restored runtime sets it false. This prevents both the silent store/smem mismatch and the `kIsMulticastOnA` static-assert JIT failure.

3. **arch-10 mixed FP4×FP8 routing**: the pure-fp8 branch now requires `a` *and* `b` to be non-FP4 (`a.first.scalar_type() != kPackedFP4 and b.first.scalar_type() != kPackedFP4`), matching the SM120 branch — fp4_A x fp8_B stays on the combined kernel.

Also folded in the minors: `epilogue_type` is wired through `get_default_epilogue_type(args.epilogue_type)` instead of the hardcoded literal; `dg25_fp8/common/math.cuh` now includes `cuda_bf16.h` itself (self-contained header); noted the `SM100ArchSpec::smem_capacity` reuse for sm_12x (GB10 matches SM100's 227 KB dynamic smem, so stage sizing is safe there).

Happy to re-run anything or adjust the `allow_swap_ab` approach if you'd prefer a different mechanism for filtering swap candidates.

### maci0 · 2026-08-27

The re-review comments duplicate the earlier v4p/v5/v6 findings — all of them were addressed in 44d9d2e (the current head, plus the ci: re-trigger commit on top). Point-by-point:

1. **AB-swap for pure fp8 (gemm.hpp, `fp8_fp4_gemm_nt_sm120`)** — resolved: `const bool pure_fp8 = (a_data.scalar_type() != kPackedFP4) and (b_data.scalar_type() != kPackedFP4)` and the swap condition now includes `!pure_fp8`, so the restored kernel only ever runs non-swapped.

2. **`get_best_config<SM100ArchSpec>` may select swap_ab=true** (sm100_fp8_gemm_1d1d.hpp / heuristics) — resolved: `GemmDesc.allow_swap_ab=false` (config.hpp) is set in the restored kernel runtime, and `get_layout_candidates` (sm100.hpp:52) does `if (swap_ab == 1 and not desc.allow_swap_ab) continue;` — swapped layouts are never enumerated. The multicast-on-A hazard from the swapped `cluster_n=2` path can no longer be reached; with swap_ab=0, `cluster_n>1` is also filtered (sm100.hpp:93), so `kIsMulticastOnA` stays false and the `kNumMulticast == 1` static assert is not tripped.

3. **arch-10 routing checks only B's dtype** (gemm.hpp:218) — resolved: the pure-fp8 route condition now checks both operands (`a_data.scalar_type() != kPackedFP4 and b_data.scalar_type() != kPackedFP4`), so fp4-A × fp8-B stays on the combined kernel.

4. **sm_12x smem capacity** — comment added in the kernel runtime: GB10 per-SM dynamic smem matches SM100 (227 KB), so SM100ArchSpec stage sizing is safe on sm_12x. (Runtime verification on GB10 is pending a toolchain-capable wheel; the kernel JIT path itself compiles.)

5. **EpilogueIdentity hardcoded** — resolved: `get_default_epilogue_type(args.epilogue_type)` is wired back in the template args.

6. **math.cuh not self-contained** — resolved: `#include <cuda_bf16.h>` added at the top of `dg25_fp8/common/math.cuh`.

Happy to adjust anything that still looks off on re-review.
