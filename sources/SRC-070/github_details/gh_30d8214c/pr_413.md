## 正文

Fixes #412

## Summary

Make integer environment-variable parsing deterministic and reject malformed or
out-of-range values.

## Root cause

`get_env<int>()` ignored the return value from `std::sscanf()` and returned an
uninitialized local variable when an environment value did not begin with a
valid integer. Partial values such as `16abc` were also silently accepted.

## Fix

- parse base-10 integers with `std::from_chars()` and require full consumption
- preserve the existing acceptance of surrounding ASCII whitespace and a
  leading `+`
- reject empty, malformed, partial, and out-of-range values with an error that
  identifies the environment variable
- add a dependency-free host test covering valid boundaries and failure cases

This does not change unset-variable defaults or string environment variables.

## Validation

The host-only regression test passed with GCC 9.4 in C++17 mode using:

```text
g++ -std=c++17 -O2 -Wall -Wextra -Werror -pedantic \
    -fsanitize=undefined -fno-sanitize-recover=all \
    tests/test_env.cpp -I. -o /tmp/deepgemm-test-env
/tmp/deepgemm-test-env
```

The test covers zero, signed values, surrounding whitespace, `INT_MIN`,
`INT_MAX`, empty input, whitespace-only input, malformed booleans, partial
numbers, hex-like input, and positive/negative overflow. It requires no CUDA,
GPU, model, network access, or submodules.

The CUDA/GPU test suite was not run in this environment.

Closing as superseded by the current main architecture. DeepGEMM removed csrc/utils/system.hpp and now delegates environment parsing to deep_jit::get_env via the pinned DeepJIT submodule (e5bdee2). That implementation uses std::from_chars and requires complete input consumption, so malformed and partial integer values no longer reach an uninitialized result. Rebasing this PR would restore a deleted utility and duplicate the replacement parser. The original #412 failure is therefore addressed by the DeepJIT migration rather than this branch.
