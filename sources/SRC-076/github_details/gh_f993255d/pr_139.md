# [PR #139] Fix pytorch_wrap regex to catch both nn.X and torch.nn.X

## 正文

## Summary
- The `pytorch_wrap` check used `torch\.nn\.(?!...)` which only matched fully qualified `torch.nn.Linear` style calls
- Generated kernels commonly use `from torch import nn` then `nn.Conv2d`, `nn.Linear` etc., which slipped through
- Changed pattern to `(?<!\w)nn\.(?!...)` which catches both import styles while avoiding false positives on identifiers like `cnn.layer` via the negative lookbehind

## Test plan
- `nn.Linear` → caught (no word char before `nn`)
- `torch.nn.Linear` → caught (`.` before `nn` is not `\w`)
- `cnn.layer` → not caught (`c` before `nn` is `\w`)
- `nn.Module` → not caught (negative lookahead excludes allowed names)
