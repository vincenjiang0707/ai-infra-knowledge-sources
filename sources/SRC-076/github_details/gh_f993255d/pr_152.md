# [PR #152] fix(eval): preserve integer tensor dtype during precision cast

## 正文

Closes #151.

## Summary

`_process_input_tensor` currently casts every input tensor to the configured `precision` (default `torch.float32`). For tasks whose `get_inputs()` returns integer class indices (e.g. `torch.randint(0, num_classes, ...)` in CrossEntropyLoss / NLLLoss / KLDivLoss problems), this turns the int64 target tensor into float32 and breaks PyTorch dispatch:

```
NotImplementedError: "nll_loss_forward_reduce_cuda_kernel_2d_index"
  not implemented for 'Float'
```

This regression was introduced by #80; earlier versions had explicit integer-dtype protection that was lost during the precision-support refactor.

## Change

Skip the precision cast for non-floating-point tensors and only move them to the target device. Floating-point activations / weights still get cast to the requested precision unchanged. Boolean tensors (e.g. masks) are also preserved.

```python
if not input.is_floating_point():
    return input.to(device=device)
input_tensor = input.to(dtype=precision)
return input_tensor.to(device=device)
```
