## 正文

There was a bug in eval_from_generations that was: 

When a bad kernel (e.g. illegal memory access) corrupts the GPU memory state, several subsequent kernels (that would be in that same Modal container) would also be evaluated on that GPU, also rendering them incorrect automatically, regardless if they were right or not. The fix is to launch a new container when the GPU is left in a "bad" state.

### BenCowen · 2026-01-19

Hey @msaroufim. Each Modal container starts with a clean instance of the image. In that sense, containers are stateless across instances (ignoring shared storage mounts, etc.).

At the function call level, our orchestrator will reuse containers for multiple inputs to avoid cold starts (unless `single_use_containers=True`). Function calls _can_ alter the state of the container: the Modal `cls` object makes this more explicit with its [lifecycle hooks](https://modal.com/docs/guide/lifecycle-functions#container-lifecycle-hooks) and `self`, but `function`s work the same way.

@simonguozirui will have to answer about what exactly happened to the GPU state.
