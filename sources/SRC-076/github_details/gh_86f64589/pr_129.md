## 正文

 ## Summary

  This PR streamlines the Blackwell RMSNorm implementation while keeping the current B200 speedups and correctness parity.

  Specifically, it:
  - consolidates the optimized pointer-path and stage-2 scheduling logic into a single maintained implementation,
  - replaces the old duplicated stage-2 module with a thin compatibility facade,
  - factors reusable CuTeDSL fast-launch plumbing into shared helpers, and
  - adds shape-specialized forward fast paths for hot BF16 RMSNorm cases.

  The result is a smaller and easier-to-review RMSNorm codebase without giving up the tuned Blackwell behavior. The public-facing README in this PR also stays scoped to Quack-based public comparisons only.

  ## Perf

  Measured on B200 / SM100 with the in-tree forward RMSNorm benchmark sweeps:

  - **Same-dtype weights:** `1.15x` geomean vs Quack on Quack-suite, `1.07x` on DSv3
  - **FP32 weights:** `1.21x` geomean vs Quack on Quack-suite, `1.07x` on DSv3

  The remaining wins come from two main changes:
  - lower pointer-path launch overhead on hot forward paths, and
  - Blackwell-tuned shape routing for both small-`M` and larger RMSNorm rows.

  ## Correctness

  Correctness parity was re-validated against the pure PyTorch reference and Quack on both the Quack-suite and DSv3 forward sweeps.

  - Worst output relative L2 in the latest rerun: **Oink** `1.37e-5`
  - Corresponding worst Quack output relative L2: **Quack** `1.87e-5`

  There are no intended numerical behavior changes in this PR; the optimized paths preserve correctness parity.

  ## Code Size

  This refactor also reduces the in-tree Blackwell RMSNorm implementation footprint across the touched RMSNorm files:

  - **Before:** `5,262` LOC
  - **After:** `4,447` LOC
  - **Delta:** `-815` LOC (`-15.5%`)

  Most of the reduction comes from removing the old duplicated stage-2 implementation and collapsing RMSNorm scheduling decisions into one primary implementation path.
