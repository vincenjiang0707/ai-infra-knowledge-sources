## 正文

### What changed

**Summary**: Extend the optimization orchestrator to learn from prior attempts and make smarter kernel selection decisions.                        
                                                            
  
  **Reflexion and history tracking**

  - Adds `OptimizationAttempt` and `Reflexion` dataclasses to record each optimization round's diagnosis, fix, config changes, and outcome.
  - Generates self-reflections after each attempt, evaluating whether the bottleneck diagnosis was correct and whether the fix was effective.
  - Passes attempt history and reflexions into the optimization prompt so the LLM avoids repeating ineffective strategies.
  - Supports shared history from beam search manager via `prior_history` and `prior_reflexions` init parameters.

  **Two-kernel tracking**

  - Tracks best-by-runtime and best-by-SOL (speed of light) kernels independently to avoid mixing metrics from different kernels.
  - Profiles each new kernel immediately after benchmarking to get its SOL metrics, rather than relying on stale roofline data from the previous round.
  - Accepts kernels that show significant SOL improvement even without runtime improvement.

  **Bottleneck selection and RAG support**

  - Adds `bottleneck_id` parameter for beam search diversity — each worker can explore a different bottleneck direction from the same profiling results.
  - Adds `bottleneck_override` to skip LLM bottleneck analysis when the category is already known.
  - Integrates optional `rag_prescriber` for retrieval-augmented optimization context.

  **Config extraction**

  - Adds `extract_triton_config()` utility to parse `@triton.autotune` decorator parameters, enabling tracking of config changes between optimization rounds.
