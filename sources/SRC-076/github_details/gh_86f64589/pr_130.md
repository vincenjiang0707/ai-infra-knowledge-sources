# [PR #130] Add register_all_kernels API to override PyTorch aten ops with oink CuTeDSL kernels

source: https://github.com/meta-pytorch/KernelAgent/pull/130

labels: CLA Signed

## 正文

### Summary:
- Adds kernelagent_oink.register_all_kernels(force=True) — overrides PyTorch's native aten operators at the CUDA dispatch key, so that standard PyTorch calls transparently use oink's SM100 CuTeDSL kernels.
  - Overrided aten ops:           
    - aten::_fused_rms_norm / aten::_fused_rms_norm_backward → rmsnorm.rmsnorm_forward / rmsnorm_backward             
  - Original CUDA kernels are captured via torch.library.get_kernel before override for automatic fallback on unsupported inputs (wrong dtype, SM < 100, incompatible strides).                 

### Test plan:
 - Unittest: `pytest oink/tests/test_aten_override.py -v`    
 - Kernel benchmarking: `python benchmarks/benchmark/benchmark_rmsnorm_all.py`, need to register Quack via torch._native (quack PR)

### Laurawly · 2026-04-16 · CHANGES_REQUESTED

1. The new test file is inconsistent with the implementation: it imports _fallbacks, _get_device_sm, _can_view_as_2d, and _is_oink_stride_compatible_2d, but aten_override.py does not define them.

2. register_all_kernels() and the tests claim layernorm/softmax overrides, but override_all_aten_kernels() only patches _fused_rms_norm and _fused_rms_norm_backward. That means the layernorm/softmax tests are exercising native PyTorch, not the new override.

3. The RMSNorm backward override ignores output_mask until after launching the full backward and then zero-fills masked grads. Native _fused_rms_norm_backward uses the mask to avoid allocating/producing those outputs.

4. restore_all_aten_kernels() cannot be followed by register_all_kernels() in the same process because _ALL_KERNELS_REGISTERED is never reset.
