## 正文

## What?

The contracts the CPU proxy is built on, as a new `nixl_device_proxy` library
under `src/utils/device/proxy`. Nothing constructs these yet. The registry and
the runtime that use them are the next two PRs.

- `proxy_protocol.h`: the wire contract between device code and the host worker.
- `proxy_config.{h,cpp}`: parsing of the `device_proxy` and `proxy_*` backend
  parameters into `nixl::proxyConfig`.
- `proxy_backend_ops.h`: `nixl::proxyBackendOps`, the callbacks a transport
  fills in to sit behind the proxy.
- `proxy_control_buffer.{h,cpp}`: `nixl::proxyControlBuffer`, the doorbell words
  the CPU publishes and the GPU reads.

```
  proxy_protocol.h: installed header, the one layout both sides compile against
  ---------------------------------------------------------------------------------
  GPU kernels  ---work ring, 64 B records--->  [proxy worker: later PR]
  GPU kernels  <--completion slot------------  [proxy worker: later PR]
  GPU kernels  <--control words--------------  proxyControlBuffer (GDRCopy device memory or mapped host memory)
  [proxy worker] --submit, check_completion-->  proxyBackendOps  -->  [UCX engine: later PR]
  proxyConfig  <--  device_proxy, proxy_* backend params
```

## Why?

Where a transport has no device-callable submission path, the GPU writes a
fixed-layout record into a ring and a host thread turns it into an ordinary
backend transfer. The layout, the configuration surface, the backend boundary,
and the doorbell memory are the parts of that design that must stay stable, so
they are reviewed first and on their own.

## How?

Protocol

- Plain C++ with no CUDA includes and no `std::atomic` members. Device code reaches
  the fields through `cuda::atomic_ref`, host code through `__atomic` builtins.
- Frozen except additively. New data goes in `flags`, `reserved`, or a new opcode.
  Every shared struct carries a size assert; a firing assert is an ABI break.
- A submission is 64 bytes with `op_idx` first, because that word publishes the
  record as ready. Zero means empty.
- Nothing backend-specific enters the ring. A record names memory views by id and
  offset; backend handles are resolved on the host after dequeue.
- The protocol types keep their global `nixlProxy*` names: this header is the
  installed contract compiled into device code. The host-side library lives in
  `namespace nixl`.

Configuration

- Parsing is strict. An unknown `proxy_*` key, a zero count, a ring depth that is
  not a power of two, or `proxy_*` tuning without `device_proxy=true` is an error,
  and the log names the offending key and value.
- `device_proxy=true` together with the shared progress thread is rejected: the
  proxy's own threads own the backend workers.
- The output config is written only on success.
- The config exposes the topology generically (`ringCount()` = channels x peers,
  `effectiveThreadCount()`); how a backend maps rings to its own resources is up
  to the backend.
- `proxy_max_peers` defaults small on purpose. Each peer costs one ring per channel.

Backend interface

- Six required callbacks: init, submit, check_completion, quiesce, progress,
  shutdown. One optional: direct-pointer resolution. The runtime rejects a struct
  with a required callback unset when it is created.
- `std::function` rather than an abstract adapter class: the engine fills the
  struct with lambdas at creation, so it needs no adapter type with friend access,
  optional means unset, and tests inject single callbacks. It is an in-process
  boundary between the runtime and an engine in the same binary, not an ABI.
- A request is an opaque token plus a context word.

Control buffer

- Created through `proxyControlBuffer::create()`, which hands out the buffer only
  once it owns its memory; the destructor releases it.
- Backing is chosen at runtime. With GDRCopy the words live in BAR-mapped device
  memory the host writes directly. Without gdrdrv the pin fails, the buffer reports
  it once at INFO, and the words come from mapped host memory.
- One slab holds the shutdown word and one consumer index per ring.

Build

- Built with or without CUDA: it depends only on `nixl_common` and the device
  operations interface from #2196, plus GDRCopy when found. The proxy host test
  suites in the next PRs therefore build and run on machines without CUDA.
- `proxy_protocol.h` is installed as `<device/proxy/proxy_protocol.h>`.

## Testing

- No tests in this PR, per review: the registry and runtime PRs cover these types
  with host-only suites (mock device operations and mock backend callbacks), and
  the UCX PR covers the parameters end to end.
- Checked: debug `-Dwerror=true` build of every commit, the full host unit binary,
  a build and unit run with CUDA disabled, and the CI clang-format check.

<details><summary>Full analysis</summary>

**Summary:** Stage 417 ("Build", the aarch64 non-GPU variant) failed after 7s during `meson setup nixl_build` — `ERROR: Subproject taskflow is buildable: NO / Git command failed: git clone --depth 1 --branch v3.10.0 https://github.com/taskflow/taskflow.git`.

**Root cause:** Environmental/dependency-fetch failure, not a code defect in PR #2225. On the aarch64 agent the git clone of the taskflow wrap failed immediately:
```
Cloning into 'taskflow'...
fatal: could not read Username for 'https://github.com': No such device or address
fatal: expected flush after ref listing
```
git got an interactive-credential/401-style response (and a malformed ref listing, typical of a proxy or blocked egress) rather than anonymous access, so meson aborted at `meson.build:233`. Note that meson's own tarball downloads on the *same* agent worked (`Downloading liburing source from https://github.com/axboe/liburing/...` succeeded), so plain HTTPS fetch works there while `git clone` to github does not. The x86_64 variant (stage 399) resolved the same dependency fine — `Cloning into 'taskflow'...` took ~10s and `Dependency taskflow from subproject subprojects/taskflow found: YES 3.10.0` — which is why 5 of 6 variants passed and only the arm one failed. The root fragility is that `taskflow` is the only dependency fetched via `git clone` at configure time; every other subproject (liburing, tomlplusplus, abseil) uses a downloadable archive.

**Implicated commit:** 76275cfc — "Use tagged Taskflow git wrap for NIXL builds (#2121)", bzsuni (introduced the `[wrap-git]` taskflow dependency). The build-breaking commit under test (e18c9cfe / PR #2225) is not implicated.

**File:** `subprojects/taskflow.wrap:1-4` (consumed at `meson.build:233`)

**Suggested fix:**
1. Preferred — make taskflow fetch match the other subprojects by using an archive instead of git, e.g.:
   ```
   [wrap-file]
   directory = taskflow-3.10.0
   source_url = https://github.com/taskflow/taskflow/archive/refs/tags/v3.10.0.tar.gz
   source_filename = taskflow-3.10.0.tar.gz
   source_hash = <sha256 of the tarball>
   patch_directory = taskflow
   [provide]
   taskflow = taskflow_dep
   ```
   This removes the `git clone` dependency that the aarch64 container cannot satisfy and also makes the dependency hash-pinned.
2. Or pre-install taskflow headers into the aarch64 CI image (`/opt/nixl`) so `dependency('taskflow')` is found via pkg-config/cmake and the fallback is never exercised — matching how abseil/etcd are already provided.
3. Infra side: have the arm CI image share the same git egress/proxy configuration as the x86 image (`git config --global url.*.insteadOf` to an internal mirror, plus `GIT_TERMINAL_PROMPT=0` so this fails loudly and fast rather than prompting for a username).
4. Re-running the build will likely pass if the arm agent's git egress is transient, but the wrap should still be converted — this will recur otherwise.

**Related:** PR #2121 (introduced the git wrap); no existing issue tracks this failure signature.
