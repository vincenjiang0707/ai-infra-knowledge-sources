> This implementation has several critical API usage issues and build configuration problems that need to be addressed:
> 
> 1. Missing GPU signal APIs
>    This implementations missing the required `prepGpuSignal()` and `getGpuSignalSize()` APIs that are essential for GPU signal initialization.
> 2. Incorrect transfer API usage
>    The `gdakiFullTransferKernel` incorrectly uses `nixlGpuPostSignalXferReq()` instead of `nixlGpuPostWriteXferReq()` API. While the GPU transfer request already contains the IOV data from the original transfer request, (This is what you passed to `createGpuXferReq`) the signal-only API doesn't transfer the actual data, instead it only sends signals.

>    Both `gdakiFullTransferKernel` and `gdakiPartialTransferKernel` are passing signal objects directly instead of providing the required IOV parameters (sizes, local addresses, remote addresses arrays) that the transfer APIs expect for data transfer operations.

1, 2, 3 should be addressed now. For 4, we need a different macro anyway (we need to check if NIXL supports device API) and also since nixlbench is a separate meson project under nixl git.

### michal-shalev · 2025-09-28 · CHANGES_REQUESTED

This implementation has several critical API usage issues and build configuration problems that need to be addressed:

1. Missing GPU signal APIs
This implementations missing the required `prepGpuSignal()` and `getGpuSignalSize()` APIs that are essential for GPU signal initialization.
2. Incorrect transfer API usage
The `gdakiFullTransferKernel` incorrectly uses `nixlGpuPostSignalXferReq()` instead of `nixlGpuPostWriteXferReq()` API. While the GPU transfer request already contains the IOV data from the original transfer request, (This is what you passed to `createGpuXferReq`) the signal-only API doesn't transfer the actual data, instead it only sends signals. 
3. Missing IOV parameters
Both `gdakiFullTransferKernel` and `gdakiPartialTransferKernel` are passing signal objects directly instead of providing the required IOV parameters (sizes, local addresses, remote addresses arrays) that the transfer APIs expect for data transfer operations.
4. Build configuration duplication
The benchmark's `meson.build` defines `-DHAVE_NIXL_DEV_API` when the root `meson.build` already provides `-DHAVE_UCX_GPU_DEVICE_API` and `ucx_gpu_device_api_available`.
