## 正文

## What?
Clarify the wheel-specific `install_headers=false` override in the README and Fern build guide, and point C++ users to the source-installation instructions and header destination.

## Why?
The documented Meson default is `true`, but wheel builds override it. Explaining both paths resolves the ambiguity reported in #679 without changing packaging behavior.

🤖 **CI Triage Agent** — `nixl-ci-build-container-pr` · commit `5285c152`

**TL;DR:** Two of the four parallel container builds died at unauthenticated `git clone https://github.com/...` steps in `contrib/Dockerfile` with `fatal: could not read Username for 'https://github.com'` — GitHub rejected the anonymous clone (rate-limit/auth challenge), not a code defect. Fix is to authenticate (and retry) third-party clones, as already proposed in PR #2263.

<details><summary>Full analysis</summary>

**Summary:** `nixl-ci-build-container-pr` #738: parallel "Build image" stages 201 and 207 failed while building `contrib/Dockerfile`; both failed on a `git clone` from github.com.

**Root cause:** Anonymous HTTPS clones of third-party repos in the Dockerfile were refused by GitHub, which fell back to prompting for credentials in a non-interactive container:
- Stage 201, STEP 44/73: `git clone --depth 1 https://github.com/google/gtest-parallel.git` → `fatal: could not read Username for 'https://github.com': No such device or address` / `fatal: expected flush after ref listing` → `Error: building at STEP ... exit status 128`
- Stage 207, STEP 36/73: `git clone https://github.com/nvidia/gusli.git` → identical error, `exit status 128`

Evidence this is throttling/transient and not a bad URL or a code change:
- The two stages failed at *different* steps and *different* repos, while the other two parallel variants (stages 222 and 233) ran the same Dockerfile steps to completion.
- In the failing stages themselves, earlier github.com clones succeeded (`openucx/ucx` cloned fine at STEP 43 of stage 201, including its `NVIDIA-DOCA/gpunetio` submodule; abseil/grpc/etcd-cpp/aws-sdk-cpp all built in stage 207 right before the failure).
- Logs show continuous activity with no multi-minute gaps — no hang, no timeout involved.
- The PR branch is `docs/clarify-wheel-development-headers` (documentation), which cannot affect these Dockerfile clone steps.

These clones are unauthenticated and have no retry, so a single throttled request fails the whole image build:
- `contrib/Dockerfile:213` — `RUN git clone https://github.com/nvidia/gusli.git` (no `--depth 1`, no pinned ref, no retry)
- `contrib/Dockerfile:294-297` — `RUN cd /tmp && git clone --depth 1 https://github.com/google/gtest-parallel.git`
(Contrast with the `wget` steps at lines 135, 237, 301, which do use `--tries=3 --waitretry=5`.)

**Implicated commit:** unknown — not a regression from a specific commit; the failure is in the pre-existing unauthenticated clone steps of `contrib/Dockerfile` (no recent commits found on that path).

**File:** contrib/Dockerfile:213 (gusli) and contrib/Dockerfile:294 (gtest-parallel)

**Suggested fix:**
1. Land/adopt PR #2263 ("ci: authenticate third-party github.com clones") so these clones use a CI GitHub token via a build secret (e.g. `RUN --mount=type=secret,id=gh_token` writing a short-lived `~/.git-credentials` or `GIT_CONFIG` `url.…insteadOf` rewrite). Do **not** bake a token into an image layer.
2. Independently, make the clones resilient: wrap each third-party clone in a retry loop and pin/shallow them, e.g.
   `RUN for i in 1 2 3; do git clone --depth 1 --branch <pinned-ref> https://github.com/nvidia/gusli.git && break || sleep 15; done`
   and the same for `google/gtest-parallel`.
3. Longer term, mirror these small third-party dependencies (gusli, gtest-parallel) into an internal mirror/registry so PR container builds don't depend on anonymous github.com throughput.
4. Retrying build #738 will likely pass as-is; the failure is not caused by the PR.

**Related:** PR #2263 (ci: authenticate third-party github.com clones) — https://github.com/ai-dynamo/nixl/pull/2263; PR #2279 is the affected PR.
