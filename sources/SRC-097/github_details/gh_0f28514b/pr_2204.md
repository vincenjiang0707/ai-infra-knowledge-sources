## 正文

## What?

When postXfer fails midway in the enqueue cancel the already submitted requests. Cancelling for POSIX requests that fail on the read/write path was just merged, this fixes the error cases on enqueue using the same cancel mechanism.

Fixes #1957 

## Why?
Fix #1957


## How?

postXfer now also runs through the queueResult mechanism. The queueResult was fixed to work also with backends that do not support cancellation yet (POSIXAIO). However please note that POSIXAIO on certain error cases will leave the request in `IN_PROG` forever. I'll address POSIXAIO in a separate PR.

This PR is aligned with the [posix-backend-contract.md](https://github.com/user-attachments/files/32298535/posix-backend-contract.md) and i checked with AI that it adheres to this.
