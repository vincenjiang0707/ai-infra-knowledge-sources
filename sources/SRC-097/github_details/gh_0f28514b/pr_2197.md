## Summary

This PR adds the first modeled NIXLBench scenario:

```text
nixlbench scenario allocate-once <plugin> ...
```

`allocate-once` keeps a fixed file-backed dataset registered for the full run while changing the block-aligned transfer offsets. Each thread gets a disjoint part of one file. File descriptors, transfer buffers, and memory registrations stay alive across iterations; each iteration creates and releases its own transfer request.

Offsets can be random or sequential. Random mode accepts an explicit seed, or generates a nonzero seed and prints it in the resolved plan. The scenario can use NIXLBench-managed files or existing files supplied with `--filenames`. It also supports direct I/O and consistency checks.

## Design

`benchmarkScenario` handles the parts shared by modeled workloads: common benchmark options, file options, plugin discovery, plan output, dry-run behavior, and translation into the existing worker configuration.

`allocateOnceScenario` handles only the rules for this workload: file size, offset selection, thread partitions, file preparation, and its worker strategy.

```text
common scenario options ------> benchmarkScenario ---------\
allocate-once options --------> allocateOnceScenario -------+-> existing NIXL worker
plugin metadata and overrides -> exact parameter map -------/
```

A plugin is available to this scenario when its metadata advertises `FILE_SEG` and either `DRAM_SEG` or `VRAM_SEG`. Plugin parameter names, defaults, and values come from that metadata. NIXLBench forwards overrides without renaming or interpreting them.

The NIXL worker now accepts an optional per-request lifecycle with `prepare`, `complete`, and `release` phases. `allocate-once` uses `prepare` to set the next offsets and `complete` to remember the descriptors used by the finished request. Cleanup releases the transfer request and any request-scoped registration before calling the scenario's `release` method. The raw and flags-only paths do not install this lifecycle.

## Example

The scenario command is built when `-Dbuild_raw_cli=true` is enabled.

```bash
mkdir -p /tmp/nixlbench-data

nixlbench scenario allocate-once posix \
  --path /tmp/nixlbench-data \
  --file-size 1GB \
  --block-size 64KB \
  --batch-size 16 \
  --threads 4 \
  --num-files 2 \
  --iterations 1000 \
  --offset-mode random \
  --seed 42
```

Scenario options may appear before or after the plugin subcommand. `--dry-run` prints the resolved file paths, dataset and working-memory sizes, memory placement, offset policy and seed, lifecycle, and plugin parameters. It does not open files or create transfer resources.
