# [PR #2252] posix: refuse to release a transfer with outstanding I/O

source: https://github.com/ai-dynamo/nixl/pull/2252
state: open | updated: 2026-09-23T19:39:01Z
labels: external-contribution, size/L, cancellation

## 正文

## What?

Make the POSIX backend refuse to release a transfer request that still has outstanding I/O. `releaseReqH()` returns `NIXL_ERR_REPOST_ACTIVE` and keeps the handle in that case. Once the request is complete, release deletes it and returns success.

## Why?

Fixes #1955. `releaseReqH()` deleted the request unconditionally, even while queue entries still stored it as their completion callback context. A later poll on the shared queue then invoked `ioDoneClb()` through the freed pointer.

The #2077 review dropped the deferred-free approach in favor of not deleting the backend handle while requests are outstanding. This PR restores the refusal semantics of #2077's first revision, now as the agreed direction. Replaces #2077 per review there.

Scope is the backend refusal only. #2244 covers the northbound side. It keeps a request pollable after a refused release, and the client keeps polling until the transfer completes, then retries the release. On main today `releaseXferReq()` already reports `NIXL_ERR_REPOST_ACTIVE` and keeps the request handle after a backend refusal. Either merge order works. Nothing in `nixl_agent.cpp` or the API docs changes here.

## How?

Under `io_queue_lock_`, `releaseReqH()` checks `isComplete()`, which moves to the public section of the request handle unchanged. Null handles go through `castPosixHandle()` like the other entry points.

The regression test posts 256 descriptors against the 64 entry poll cap with no progress thread. One poll inside `releaseXferReq()` cannot complete the transfer, the release deterministically hits an active one, and the backend refuses it with the request still valid. A second write on the same queue then drains the refused transfer's completions. Against the unfixed backend, a `-Dsanitizer=address,undefined` build reports that drain as heap-use-after-free in `ioDoneClb()`. Release after completion must succeed, and a read-back validates file contents. Between drain and final release, a completion poll exits on the stored status until #2244 lands and then polls for real.
