# [PR #2271] fix(python): return None from get_xfer_telemetry when telemetry is disabled

source: https://github.com/ai-dynamo/nixl/pull/2271
state: open | updated: 2026-09-22T07:05:05Z
labels: external-contribution, size/S

## 正文

## What?

Make `nixl_agent.get_xfer_telemetry()` return `None` instead of raising `nixlNoTelemetryError` when telemetry capture is not enabled on the agent.

## Why?

Telemetry is opt-in (`capture_telemetry=False` by default, `NIXL_TELEMETRY_ENABLE` unset), so "telemetry not available" is an expected state, not an error. Raising forces every downstream consumer (e.g. vLLM's `NixlBaseConnectorWorker`) to add its own exception guard; in Dynamo P/D disaggregation on the default UCX backend this caused every completed KV transfer to be misclassified as failed, returning HTTP 500 for 100% of requests.

Fixes #2266 (Option A from the issue).

## How?

- Wrap the `getXferTelemetry` binding call with `try/except nixlBind.nixlNoTelemetryError: return None` in `src/api/python/_api.py`
- Update the return type annotation to `Optional[nixlBind.nixlXferTelemetry]` and document the `None` case in the docstring
- Update `test/python/test_nixl_api.py` (`_run_xfer_telemetry_check` with `expect_telemetry=False`) to assert `None` is returned instead of expecting the exception

Companion vLLM-side guard: vllm-project/vllm#57734
