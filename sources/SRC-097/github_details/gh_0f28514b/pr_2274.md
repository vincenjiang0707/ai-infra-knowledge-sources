# [PR #2274] CORE: never load the UCX plugin with RTLD_DEEPBIND

state: open | updated: 2026-09-24T07:08:49Z

## 正文

**Incremental review:** [Files changed](https://github.com/ai-dynamo/nixl/pull/2274/files) against `main`.

## What?

Stop loading the UCX plugin with `RTLD_DEEPBIND`, and make `NIXL_UCX_DEEPBIND` a no-op with a warning. An unparseable value warns too, rather than failing the backend creation.

## Why?

With `RTLD_DEEPBIND` the plugin resolves symbols from its own link scope first, which mis-binds the copy-relocated libc data symbols that `libucs` reads directly. `libucs.so` imports `environ`/`__environ`/`_environ` as copy relocs, and UCS walks them while creating a worker:

```
#0 ucs_config_parser_print_env_vars   ucs/config/parser.c:2545
#2 ucp_worker_create                  ucp/core/ucp_worker.c:2804
#3 nixlUcxWorker::createUcpWorker
#4 nixlUcxEngine::nixlUcxEngine
#9 nixlAgent::createBackend
```

`config/parser.c:2545` is `for (envp = environ; *envp != NULL; ++envp)`; under `RTLD_DEEPBIND` that pointer is not the process environment, so every UCX backend creation segfaults.

No concurrency, GPUs or extra agents are needed — `NIXL_UCX_DEEPBIND=1` alone is enough:

```bash
export NIXL_UCX_DEEPBIND=1
python -c "import nixl; nixl.nixl_agent('p', nixl.nixl_agent_config(True, True, 0))"   # SIGSEGV
```

The private UCX SONAME suffix from the packaging step already provides the isolation this flag was meant to add, so the flag is not needed. `getValueDefaulted` returns the fallback rather than throwing, so the previous `try`/`catch` was unreachable.

Refs #1668 — this is the residual deep-bind defect in the same loading path, not the original concurrent-init hang, which did not reproduce for me on 1.4.1 (84 child processes across 1/2/4/8 ranks, zero hangs).

## How?

`shouldDeepBindPlugin()` now returns `false` for the UCX plugin and logs a warning when the variable is set, so the behaviour change is visible. One file, +10/-9.

**Unparseable values.** `configTraits<bool>::convert` ends in `throwRuntimeError`, so `getValueDefaulted`'s fallback covers an absent variable only. The first revision of this patch removed the `try`/`catch` on the mistaken reading that it was unreachable, which let that exception reach `createBackend`: `NIXL_UCX_DEEPBIND=garbage` became a failed backend creation where it used to warn and continue. The lookup is wrapped again, so an unparseable value warns (`Invalid NIXL_UCX_DEEPBIND value: ...`) and the plugin still loads, without deep binding.
