# [PR #2284] [NIXLBench] Fix GPUNETIO WRITE consistency validation

## 正文

## What?

Fix GPUNETIO WRITE consistency checking in NIXLBench by using the existing
network-memory validation path rather than the storage-backend path.

## Why?

`checkConsistency()` currently includes GPUNETIO in the storage branch. For
WRITE, that branch allocates a host buffer but only populates it for actual
storage backends. GPUNETIO therefore compares uninitialized host bytes instead
of the transfer destination. This can report false failures or otherwise
unreliable results when `--check_consistency=true`.

## How?

- Remove the GPUNETIO exception from the storage predicate. The network path
  already reads back VRAM or directly checks DRAM, as appropriate.
- Add CPU GoogleTest regressions that call the real validation function with
  valid and corrupted destination data for both WRITE and READ.
- Make the existing test target available when raw CLI is disabled; keep the
  raw CLI/POSIX test sources conditional on that feature.

No backend, completion, transfer-timing or bandwidth-calculation change is
included. The test itself needs no GPU, RDMA device or GPUNETIO plugin.

## Validation

Based on upstream main `c8d94ee7302af988e5eb92e6ff2ca4d1f2478b3d`:

- Matching NIXL core (POSIX plugin) and NIXLBench builds with warnings as errors: PASS.
- Before the predicate fix: the new WRITE regression fails on valid data;
  the READ control passes.
- After the fix: both tests pass, including deliberate corruption checks.
- Three shuffled-order repetitions: PASS.
- Formatting and `git diff --check`: PASS.

Reproduce with GoogleTest installed and a matching NIXL installation:

```bash
cd benchmark/nixlbench
meson setup build-check --buildtype=debugoptimized -Dwerror=true \
  -Dnixl_path="$NIXL_INSTALL" -Dbuild_tests=true -Dbuild_raw_cli=false
ninja -C build-check
CUDA_VISIBLE_DEVICES="" meson test -C build-check --print-errorlogs -v
```

The negative cases intentionally emit consistency-failure diagnostics while
the GoogleTest assertions pass. No performance improvement is claimed:
destination validation runs outside the measured transfer loop.
