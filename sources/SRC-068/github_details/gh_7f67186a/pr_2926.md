[CuTe, SM100] Count Q heads in the SplitKV heuristic when not packing GQA

_get_fwd_config sized total_mblocks as batch * num_head_kv * num_m_blocks,
which is the CTA count only with PackGQA. With pack_gqa=False each Q head
gets its own m blocks, so the SplitKV heuristic saw qhead_per_kvhead times
fewer CTAs than the kernel launches and over-split (e.g. b=1, 12 Q / 4 KV
heads, seqlen_q=512, seqlen_k=8192 picked 9 splits instead of 3), which
also disabled 2CTA. This affects every head dim with pack_gqa=False; the
deleted hd256 forward compensated with its own CTA count.
