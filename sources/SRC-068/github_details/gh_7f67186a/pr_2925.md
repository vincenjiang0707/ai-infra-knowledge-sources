[CuTe, SM100] Run hd256 forward on FlashAttentionForwardSm100; delete the dedicated kernel

hdim 256 now uses the general forward with q_stage=1 (two Q tiles would need 768 of 512 TMEM
columns), the S ping-pong, 2CTA from seqlen_q > 128, overlapped sO/sQ, and the chunked SplitKV
epilogue. It inherits PackGQA for any head ratio (cp.async Q when the ratio doesn't divide the
tile), SplitKV/paged/varlen scheduling, and the general kernel's softcap, sink, local,
score_mod, mask_mod and block-sparse paths. The hd256 backward is unchanged.

Behavior change: with paged KV and no seqused_k, the KV length is the page-table width, as for
every other head dim; the dedicated kernel instead trimmed the table to max_seqlen_k.

GB200, Qwen3.5-27B decode (24 q / 4 kv heads, paged, auto splits, CUDA graph, L2 flushed), us:
32x8k 1210 -> 181, 64x8k 2464 -> 380, 1x32k 137 -> 45 (TRT-LLM 162 / 325 / 39). Prefill is
4-9% faster on long sequences (16k causal 2404 -> 2190 us, 32k causal 6288 -> 5909 us) and
20-28% faster on short/chunked ones (8x1k causal 111 -> 86 us, 8x128 over 8k 309 -> 223 us).
