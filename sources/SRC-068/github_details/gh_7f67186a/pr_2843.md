## 正文

## Summary

This PR adds a narrow FA4 CuTeDSL decode adapter for SM103 with the following
contract:

- BF16 Q/K/V and output;
- Q1, 32 query heads, 4 KV heads, head dimension 512;
- packed HND page-64 KV cache;
- causal full attention;
- up to 32 KV splits.

The producer partitions the KV range across CTAs and writes FP32 output/LSE
partials. A warp-cooperative combine kernel performs the stable log-sum-exp
reduction and writes BF16 output. The adapter validates device, dtype, shape,
stride, page-table, and workspace contracts before compilation. It caches the
compiled CuTe specialization and rejects cold compilation during CUDA Graph
capture.

This does not change the existing public `flash_attn_func` dispatch and does
not claim support for the class's internal page-128, NHD, or dense branches.
The intended first consumer is an inference integration that imports the
narrow adapter directly and retains its existing fallback for all unmatched
calls.

Related: #2456.

## Correctness and graph validation

Tested on one NVIDIA B300 SXM6 AC, compute capability 10.3, against commit
`792115567cf00f3b96d3697954899f9e63996702` on main
`ce088ab9ce0fc0434dcd8afa0a791da9fcc3a820`.

```text
5 passed, 415818 deselected, 40 warnings in 35.32s
```

The focused cells cover K11, K129, K1024, K4096, and heterogeneous B2
sequence lengths `(11, 129)`. A separate regression matrix passed B1/B4/B8
ragged eager execution and CUDA Graph replay with K mutations from 63 through
8192. The modules also import successfully from
`vllm.vllm_flash_attn.cute.*`, validating the relative combine import used by
vendoring integrations.

Standard focused command:

```bash
pytest -vv -x tests/cute/test_flash_attn.py \
  -k sm103_hd512_splitkv_packed_hnd_adapter
```

The recorded archive run used a small package bootstrap because the archive
did not contain the separately built FA2 `flash_attn_2_cuda` extension that
the repository's top-level initializer imports. The bootstrap changed only
package loading; it passed the same test file and selection shown above.

## Performance

Same-input CUDA Graph replay, BF16, B1/Q1, page 64, three rounds of 500
replays; medians are microseconds per attention call:

| KV length | This PR | FlashInfer TRTLLM-gen | Speedup |
| ---: | ---: | ---: | ---: |
| 65 | 8.202 | 8.200 | 1.000x |
| 512 | 8.201 | 12.290 | 1.499x |
| 1024 | 9.599 | 14.346 | 1.495x |
| 2048 | 10.243 | 14.337 | 1.400x |
| 4096 | 10.260 | 14.350 | 1.399x |
| 8192 | 12.831 | 16.388 | 1.277x |

These numbers measure only the maintained attention-call contract; they are
not whole-model tokens-per-second claims.

## Scope and follow-up

- The adapter is intentionally strict and fail closed.
- General D512 prefill, NHD, page-128, other head counts, and other dtypes are
  outside this PR.
- The consumer-side dispatch and fallback integration will be submitted
  separately after this kernel is available in its vendored dependency. That
  integration is tracked in
  [vllm-project/vllm#55017](https://github.com/vllm-project/vllm/issues/55017).
