[CuTe, SM100] Extend the S ping-pong to hd256 (1CTA and 2CTA) in the general forward

hd256 fits only one Q tile per CTA in TMEM (2 x S + O = 512 columns), so on
the general kernel the softmax and the MMA warp serialize per KV block the
same way decode does: PV_i needs P_i and QK_{i+1} was issued after PV_i, so
the tensor pipe idles during every softmax. The S ping-pong already fixes
this for hd64/128 decode and nothing in it is specific to those head dims or
to 1CTA, so allow head_dim 256, including with 2CTA instructions (the only
2CTA config with q_stage == 1). sO overlaps sQ for hd256 (64 KB each), which
leaves 5 KV stages with 2CTA and 2 with 1CTA; with #2817's K0, K1, V0, ...
load order the 2-stage case is neutral to 4% faster on 1CTA decode/chunked
shapes, so it is not excluded. hd256 with SplitKV is not supported by the
kernel yet and stays out of the ping-pong until measured.

hd256 still routes to the dedicated kernel, so no existing config changes.
