[CuTe, SM100] Fix 2CTA + causal and the q_stage=1 register budget in the general forward

The general forward kernel only ever ran 2CTA for non-causal shapes and
q_stage=1 only with the small hd64/128 register configs, which hid three
problems on the path to running hd256 with a single Q tile per CTA:

- SingleTileLPTScheduler (causal/local) indexed the static path by block_idx
  and sized the grid in clusters, so the two CTAs of a cluster got different
  m blocks. Use cluster_idx and launch cluster_shape_m CTAs per cluster when
  use_cluster_idx, matching SingleTileScheduler.
- BlockInfo.tile_m was the per-CTA tile, so with 2CTA the pair iterated
  different causal n_block ranges. It now covers both CTAs of the cluster.
- With q_stage == 1 there is one softmax WG and the softmax1 WG becomes an
  empty/load WG at num_regs_other, so num_regs_other is
  (512 - softmax - correction) // 2 rather than 512 - 2 * softmax - correction
  (negative for the hd256 tuning entries, 256/160).
- setmaxnreg.dec above the launch register count is an illegal instruction;
  the correction warps use .inc when the tuning entry asks for more than
  64K / threads_per_cta.

All changes are compile-time gated: PTX is unchanged for q_stage=2 configs
(hd128 2CTA non-causal, hd64/128/192 causal and local); q_stage=1 hd128
configs change only the setmaxnreg immediate of the non-softmax WGs (48 -> 120).
