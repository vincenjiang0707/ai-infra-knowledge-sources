### Human note

Pure refactor PR

## Problem

Each of the four warp roles in the SM100 hd256 2CTA forward kernel (load, MMA, softmax, correction)
rebuilt the per-batch Q/K lengths and offsets by hand, in about 35 near-identical lines: cu_seqlens reads,
seqused overrides, the paged static KV length, and the varlen tile check. Each role then called the
`Sm100FusedMask.get_trip_*_via_block_info` helpers, which construct a fresh `BlockInfo` and a dummy
`SeqlenInfoQK` on every call. The roles must agree exactly on skips and KV ranges or the pipelines
deadlock, and four copies make that easy to break.

## Fix

The kernel now builds one `BlockInfo` and one `SeqlenInfoQK.create` factory before the role dispatch, the
same pattern `FlashAttentionForwardSm100` uses. Every role does
`seqlen = SeqlenInfoCls(batch)` → `block_info.get_n_block_min_max(seqlen, m_block)` →
`if self.tile_has_work(seqlen, m_block)`. The causal/local mask bounds call
`block_info.get_n_block_min_causal_local_mask` / `get_n_block_min_before_local_mask` directly.

This is a refactor with no intended behavior change (+76/−180 in one file).
- `SeqlenInfoQK.create` resolves lengths the same way the hand-written code did: seqused over cu_seqlens
  over the static extent, with the static KV extent being `max_seqlen_k` when paged.
- The load warp used to read `cu_seqlens_k` only inside the `cu_seqlens_q` branch. The interface already
  asserts that `cu_seqlens_k` implies `cu_seqlens_q`, so this is equivalent.
- The hd256 backward kernels still use the `FusedMask` helpers and are unchanged.

This is the base of a stack; the next PR adds SplitKV on top.

## Performance

Setup: GB300, bf16, 16 Q heads / 8 KV heads, d=256. `flash_attn_func`, CUDA-graph replay median, 5
interleaved rounds against `main`, in us (lower is better).

| shape (b, sq, sk) | main | this PR | ratio |
|---|---|---|---|
| decode 1, 1, 4k | 66.5 | 66.9 | 1.005 |
| decode 1, 1, 64k | 901.6 | 902.6 | 1.001 |
| decode 1, 1, 128k | 1792.5 | 1795.0 | 1.001 |
| decode 64, 1, 8k | 1640.6 | 1641.1 | 1.000 |
| chunk 1, 128, 32k causal | 460.0 | 459.0 | 0.998 |
| prefill 2, 4k, 4k | 471.0 | 471.6 | 1.001 |
| prefill 2, 4k, 4k causal | 322.3 | 322.8 | 1.002 |

Generated code:
- **Dense causal kernel:** byte-identical SASS.
- **Varlen-scheduler kernel:** same registers (168), stack and instruction count (6264); about ten
  integer address ops are reordered.

- All 6204 hd256 cases of `test_flash_attn_output` / `test_flash_attn_varlen_output`: 4692 passed, 1512
  skipped for unsupported features. Compiled first with `FLASH_ATTENTION_FAKE_TENSOR=1 -n 48`.
- `pytest tests/cute/test_flash_attn.py -k hd256`: 67 passed. Includes the paged, paged + `seqused_k` and
  output-alignment tests.
- `pytest tests/cute/test_hd256_varlen_scheduler.py`: 101 passed, 48 skipped.
- `test_flash_attn_hd256_varlen_output_alignment` fails identically on `main` in this environment:
  tvm-ffi 0.1.12 rejects the test's nonzero storage offset (`expected byte_offset=0`). I ran it with a
  zero-offset buffer.
