## 正文

Four scheduling changes to optimize the SM100 forward kernel (head_dim=128, fp16, causal). We trace FA-4 against cuDNN's SDPA at shapes where cuDNN led. We collect these traces using [G-Watch Xtrace](https://g-watch.github.io/en/open-traces/).

At this head dim both kernels use enough SMEM to allow only one resident CTA per SM, so a grid wider than the SM count is serialized into waves. cuDNN is persistent at 148 CTAs; `main` launches one CTA per work tile, so it retires in two waves and idles across the boundary. This PR makes FA-4 persistent at 148 CTAs as well.

## Optimization 1: apply the L2 swizzle to the CLC schedule

<p align="center">
  <img width="1870" height="714" alt="image" src="https://github.com/user-attachments/assets/8cca4c93-1eb0-4256-aeef-9bdfec5717ec" />
</p>

**Bottleneck.** One CTA per work tile gives a 512-CTA grid over 148 SMs, tail wave dispatched at 84% of the kernel. CLC makes it persistent but returns raw grid coordinates, bypassing the L2 swizzle: alone it reaches only 1149 TFLOP/s at `b2 h16 s4096`, below `main`'s 1336.

**Change.** Linearize the CLC coordinate and decode it through the swizzle the static path uses, in `SingleTileLPTScheduler.clc_work_to_coords`.

**Result.** `b8 h16 s1024` goes 737 → 806 TFLOP/s.

## Optimization 2: order tiles over the whole problem

<p align="center">
  <img width="1326" height="663" alt="image" src="https://github.com/user-attachments/assets/ad2f84f9-6f47-418e-85e8-8c6cf436a11f" />
</p>

**Bottleneck.** The longest-resident CTA sets the kernel duration. The longest-processing-time order is applied per L2 section, so a section narrower than the problem issues every section's heaviest tile at once, leaving 1.49x residency variation.

**Change.** Order across the whole problem when it fits one section (`lpt_global`).

**Result.** Variation falls to 1.20x. `b8 h16 s1024` goes 806 → 822 TFLOP/s, `b2 h16 s4096` 1257 → 1393.

## Optimization 3: release the output buffer only when an iteration follows

**Bottleneck.** Each tile drains its output TMA store and returns the SMEM buffer to the correction warps. On a CTA's final tile neither is required, and a span over that drain measures 544 ns per CTA. cuDNN peels its final iteration instead: its epilogue warps each record one more loop entry than exit.

**Change.** Move the `cp_async_bulk_wait_group` and the release past `advance_to_next_work`, predicated on the next tile being valid, dropping the correction warps' tail acquire.

**Result.** Every shape gains. `b8 h16 s1024` goes 822 → 832 TFLOP/s.

## Optimization 4: use the static schedule at two or fewer tiles per CTA

<p align="center">
  <img width="1938" height="663" alt="image" src="https://github.com/user-attachments/assets/8bec581b-25ff-4465-8a62-010b6eb8f83c" />
</p>

**Bottleneck.** A causal tile's K-loop trip count follows its query block index, so a balanced schedule pairs a long tile with a short one. CLC resolves the dispatch order in hardware, and at 1.73 tiles per CTA a coordinate remapping cannot steer it: the two tile durations of a CTA correlate at +0.21, against cuDNN's -0.81.

**Change.** At no more than two tiles per CTA, use the static persistent scheduler: a CTA advances by `gridDim.x`, so its tiles are fixed. Rank them by descending trip count, traversed forwards on even rounds and backwards on odd ones. Applied unconditionally at 3.46 tiles per CTA this costs 7%, hence the guard.

**Result.** The correlation moves to -0.76. `b8 h8 s1024` goes 778 → 864 TFLOP/s, past cuDNN's 821.

## Testing

Measured at `b8 h8 s1024`, `b8 h16 s1024`, `b4 h32 s1024` and `b2 h16 s4096`, head_dim=128, fp16, causal, on B300 (148 SMs). Output is bitwise identical to `main` at every shape, with no NaN. Shapes that do not satisfy the static-pairing condition, and launches without `FA_CLC`, are unchanged.
