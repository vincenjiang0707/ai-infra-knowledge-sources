## Summary

The softmax backward forms `dS = P * (dP - dpsum)` with `dpsum = rowsum(dO * O)`. The backward only has the bf16 output, and whenever a row's attention is peaked (one key carries most of the weight, the norm in causal DSA) `dP ~ dpsum` on the dominant key: the small difference of two large numbers is dominated by the bf16 rounding of `O`, which is coherent along the row and so does not average out in the dot product with `dO`. That error lands on the dominant key's `dS` and propagates coherently into dq and dk.

A stage-by-stage fp64 error decomposition of the sparse-MLA training path (`AI/SPARSE_MLA_DPSUM_PRECISION.md`) shows every kernel is fp32-accurate for its own inputs; the gap to fp64 is bf16 rounding, and this one term is avoidable and dominant for peaked rows: at ~80% self-attention weight dq/dk rel-L2 vs fp64 is 0.89% with ~1% of rows at ~100% error, identically in load-P and recompute-P mode and in an emulated dense bf16 pipeline that forms dpsum from bf16 O. At 97% self weight it is 3.8%.

## Change

Sparse-MLA forwards whose inputs require grad additionally write `o_lo = fp32(O) - bf16(O)`, the exact rounding residual of `out` (same shape/dtype as `out`, saved for backward), and the backward preprocess forms `dpsum = rowsum(dO * (out + o_lo))`. `out + o_lo` reproduces the kernel's fp32 accumulator to ~2^-17. `out`/`lse` are bitwise unchanged; composes with `gather_bwd_recompute_p` and `gather_bwd_token_chunk`; no user-facing knobs. `_flash_attn_fwd` returns a 5th value (`o_lo`); `_flash_attn_bwd_sparse_mla` / `_bwd_preprocess` take an optional `o_lo` and behave exactly as before when it is `None`.

Why a residual rather than an fp32 output or a recompute: dpsum needs `dO`, which only exists in the backward, so the fp32 `O` has to cross the fwd/bwd boundary; a bf16 residual costs the same as `o_lo` would in fp32 while the model keeps consuming a bf16 `out`, and recomputing `O` in the backward would be another full P·V pass.

With fewer than 128 Q heads (#2883 pads the heads to the 128-row tile inside the kernel) the residual store, a plain register-to-global copy rather than TMA, guards padded rows with `is_valid_qhead_row` like the LSE store. Without the guard the padded rows of each token wrap into the next token's `o_lo` and those of the last tokens run past the end of the tensor.

Both kernels sit at their register cap, so the naive implementations spilled badly (+8 ms). The shipped versions re-read the fp32 O from TMEM per 32-column chunk after the O TMA store (the `correction_rescale` access pattern) and stream the preprocess one row-slice at a time when a residual is present; the original preprocess path is untouched when no residual is passed.

The +2.0 GiB is one `out`-sized bf16 tensor (16K × 128 heads × 512 × 2 B); the streamed preprocess is ~0.5 ms faster than the whole-tile one despite reading a third tensor. For scale, the FlashMLA + cuDNN pipeline keeps only `out + lse` between fwd and bwd (2.0 GiB at this size and head count vs 12.5 GiB here, of which the saved bf16 P is 8 GiB and `o_lo` 2 GiB; with `gather_bwd_recompute_p=True` FA4 keeps 4 GiB), and at equal head count FA4's fwd+bwd is ~1.4x faster than that pipeline in a separate benchmark, so the residual's cost does not change the standing of either.

### Blocker: padded Q heads corrupt `o_lo`

Main’s `d15f153` pads sparse-MLA Q-head tiles to 128 for any real head count from 1–128. TMA accesses handle padded rows, while non-TMA accesses must explicitly guard them.

The PR packs `mOlo` using the padded head count (`flash_fwd_mla_sm100.py:471`), then performs a direct register-to-global store with only:

```python
store_residual = row_idx < seqlen_q
```

(`flash_fwd_mla_sm100.py:3188`)

After rebasing, padded head rows therefore wrap into later tokens; trailing rows can address beyond the real `o_lo` tensor. This corrupts the residual and potentially adjacent memory.

A real-GPU invariant check, `abs(o_lo) <= half_ulp(out)`, produced:

| Q heads | Violations |
|---:|---:|
| 128 | 0 |
| 96 | 75,836 |
| 64 | 181,095 |
| 24 | 127,818 |
| 1 | 6,582 |

The likely correction is:

```python
store_residual = (
    row_idx < seqlen_q
    and self.is_valid_qhead_row(row_idx)
)
```

Main already adds `is_valid_qhead_row()` for precisely this purpose.

The precision test misses this because it hardcodes 128 heads (`test_flash_attn.py:5353`). It should cover at least 64 and 24 heads, including varlen.

Everything else looked structurally sound:

- The remote PR tip rebased cleanly onto `origin/main`; range-diff showed no dropped patches.
- All repository and `benchmarks/` `_flash_attn_fwd` callers handle the five-element return safely.
- The ordinary and sparse-MLA preprocess callers remain compatible.
- Representative padded-head compile tests and current sentinel tests pass—but those tests do not detect the residual corruption.
