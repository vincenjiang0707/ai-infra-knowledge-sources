## Summary

Second optimisation round on `flashinfer.experimental.cake_mla_varq_dcp_decode` (the Blackwell MLA variable-query decode with static decode context parallelism from #5577). Six levers were measured on B200 and GB300 against the shipped kernel with same-tree A/B runs and timeline stamps; none beat it, so the generated modules and the host plan are unchanged. This PR records the attribution in the package and adds the benchmark option that reproduces its main finding:

* `flashinfer/experimental/cake_mla_varq_dcp_decode/README.md`: new section "Where the time goes" with the roofline share of the 24 rows, the fixed costs of the tightest row, the rejected changes with numbers, and why the static unit size stays at the uniform-query optimum.
* `benchmarks/bench_cake_mla_varq_dcp_decode.py`: `--q-pattern {row,uniform,ragged}` overrides every row's query-length pattern (default: the row's own).

No CUDA, planner or runner change; the validated tolerances, the prepared-runner replay footprint and the 38-row contract are those of #5577.

## What was measured

Same-tree A/B (candidate vs shipped trace, alternating arms, three repeats per row, cold-L2 CUPTI timing) on both GPUs:

| lever | change | result |
|---|---|---|
| start-up | extra clusters issue their Q / K loads before publishing the unit token | fp8 h128 w8 b16 q1 s32k -5 % (B200) / -6 % (GB300): the load warp blocks in the TMA issue queue and the token waits |
| start-up | partition-pass loads hoisted to kernel entry | geomean -1 % on both GPUs |
| epilogue | two-round pipelined O epilogue (TMEM loads of round i+1 in flight while round i converts and stores) | GB300 within noise on re-measure, B200 FP8 rows -1..-4 % |
| split rows | in-kernel last-arriver merge replacing the reduce kernel | -4..-9 % on every split row on both GPUs (one cluster folds every partial of an item through one SM pair's L2 path; the reduce kernel spreads an item over eight CTAs and overlaps through PDL) |
| teardown | launch / empty-geometry / one-tile floor probes | 2.4-3.2 us from the last store to the kernel end in every geometry; a trivial kernel needs 1.25-1.30 us for launch + exit; nothing runs after the last store |
| host plan | `unit_min` 2 / 4 / 8; static unit size sweeps | `unit_min` neutral; smaller static units gain 4-13 % on the ragged-query `mtp3` rows but lose 5-9 % on the same geometry with uniform query lengths (`--q-pattern uniform`), which the host plan cannot distinguish |

Roofline: every row at 14-57 % of the HBM / dense-tensor roofline on both GPUs; the tightest row (`fp8_h128_w8_b16_q1_s32k`, 18.6 / 20.1 us) is fixed-cost bound: Q and first K tile land at 3.4-3.5 us on a flushed L2, first QK MMA at 3.9 / 4.4 us, epilogue 1.5-1.7 us per unit, merge 0.6 us, teardown 2.4-3.2 us.

Shipped-kernel performance (same-session paired timing, `cute_dsl_mla_decode` / this route): GB300 geomean 1.196, B200 1.195, 24 / 24 rows above 1 on both. The export-protocol tables of #5577 remain the published numbers (geomean 1.1817 / 1.1791, 24 / 24).
