## Kimi-K3 fused MoE router (896 experts, top-16) for SM100 / SM103 — generated program export

One launch routes FP32 gate logits `[num_tokens, 896]` (sigmoid gate, top-16 selected on `sigmoid(logit) + bias`, weights renormalized over the selected unbiased sigmoid scores, lower expert id on ties) and writes the expert-aligned route plan consumed by grouped MoE GEMMs (`sorted_token_ids`, `expert_ids`, `num_tokens_post_padded`, per-expert `expert_counts` / `expert_offsets` / `expert_scatter_offsets`, `block_m` 8 or 16). Nothing is planned on the host and nothing is allocated at launch: a prepared runner (or a CUDA Graph capturing it) replays for new values written into the same `logits` / `bias` buffers.

Package `flashinfer/experimental/kimi_k3_fused_router/` (public entries `flashinfer.fused_moe.kimi_k3_fused_router` / `prepare_kimi_k3_fused_router`), JIT-built through `gen_jit_spec` with `use_fast_math=False` and the `CompilationContext` / `FLASHINFER_CUDA_ARCH_LIST` target flags (`sm100a_nvcc_flags` / `sm103a_nvcc_flags`; no nvcc probes). One generated CUDA source (+ binding) per kernel arm, architecture and `block_m`.

### Dispatch arms (per exact `(num_tokens, block_m)` shape, `num_tokens ∈ {1, 2, 4, …, 8192}`)
| arm | shapes | launch |
|---|---|---|
| L (one-join plan builder) | M1, M16–M128 | cooperative, ≥ 128 CTAs |
| LC (cluster of M CTAs, DSMEM id exchange) | M2, M4, M8 | non-cooperative cluster `(M,1,1)` |
| M (one-join bitmap plan, lane-parallel emit) | M256 | cooperative, one CTA per row |
| Q4S (cp.async id stream in 4-CTA clusters, 4 CTAs/SM build) | M512, M1024, M2048 | cooperative cluster, grid a multiple of 4 bounded by `cudaOccupancyMaxActiveClusters` |
| G (two-join persistent) | M4096, M8192 | cooperative, `__launch_bounds__` 4 CTAs/SM (SM100) / 6 (SM103) |

Revision 2 (this head) replaces the M4S / Q arms of the first export with Q4S at M512–M2048 on both arches (same K3 semantics,
same route plan; the Q4S kernel reads peer slice counts with one `ld.shared::cluster.v4` per peer and hoists the owner clears
before the grid join). Both arches: 14 generated programs each (5 arms).

### Exactness
`tests/experimental/test_cake_kimi_k3_fused_router.py`: host contract (route tables, launch-grid rules, plan capacity, input validation, self-consistent PyTorch reference) plus GPU tests on every one of the 28 routed shapes against the PyTorch reference (exact ids / plan metadata, weights atol 1e-6 rtol 1e-5, ascending pair order, untouched capacity suffix), the allocating API, CUDA Graph replay with new device inputs (M1, M8, M256, M2048, M4096), and a no-allocation launch check. The kernel reproduces the SGLang router's `__expf` / `__fdividef` sigmoid; its last FP32 bit can differ from `torch.sigmoid` (and its rounding differs between SM100 and SM103), so the tests validate the selection against the biased scores with a `2**-22` tie tolerance at the top-16 boundary (rows with a clear gap must match exactly; observed once, seed-21 inputs at M2048 on B200, exact gap 1.4e-8) and derive weights and plan from the validated selection.

Export receipts (source ↔ export bitwise parity on all 28 shapes per arch, generated grid == source grid): B200 (sm_100a): `pytest tests/experimental/test_cake_kimi_k3_fused_router.py` 44 passed; GB300 (sm_103a): 44 passed. Export runs (fixed-count cold-L2 CUPTI, 3 counterbalanced groups, 200 warm-up + 2000 reportable samples per arm and group, source arm = the generating launcher): B200 28/28 rows correct, byte-identical source/export programs, launch grid == source grid, source/export time ratio 0.981–1.028; GB300 28/28 rows correct, byte-identical, grid parity, ratio 0.985–1.042 (revision 2; revision 1 was 0.963–1.030 / 0.966–1.036). Timing gates 0.94 (ratio floor) / 0.08 (pair-order disagreement): the 5–8 µs rows quantise to the 32 ns CUPTI quantum and the counterbalanced pair order carries a 1–2 % second-launch advantage; the strict 0.97 / 0.02 gates failed 8 (B200) and 10 (GB300) of those rows with identical binaries. `pre-commit run --all-files` clean on both delivered trees.
