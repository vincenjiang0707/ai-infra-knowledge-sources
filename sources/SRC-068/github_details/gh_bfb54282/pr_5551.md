## 📌 Description

Adds Kimi-K3 tensor-parallel-12 support (`num_heads == 8`) to the Cake backend of `fused_kda_decode` on SM100 (B200) and SM103 (B300). Closes #4542 (tracker #4254).

- H=8 admitted in `select_cake_fused_kda_decode_variant`, `_SUPPORTED_HEADS` and the binding `TVM_FFI_ICHECK`; the head list of the T=1 trace template follows.
- H=8 dispatch bands mirror the Cake source dispatcher (`B200_SM_COUNT = 148`): FP32 positive-unique rows 1–9 → cluster2 (two-CTA split), 10–18 → wide512 with the 128-register cap, 19–37 and 56–76 → wide512, 38–55 and ≥77 → high-work; BF16 positive-unique rows ≤18 → wide512, 19–63 → compact-async, ≥64 → new persistent `stream_bf16` family; null/repeated modes keep their generic routes.
- New two-CTA cluster route for FP32 positive-unique rows 1–9 (`cluster2_wide_positive_f32{,_wide_slot_offsets}`): one (row, head) item is split by value tile across a `__cluster_dims__(2,1,1)` pair (grid `(2·H, rows)`, 512 threads, 9344 B dynamic smem, `cluster_x = 2` in the registry). The binding launches cluster variants through `cudaLaunchKernelExC` with `cudaLaunchAttributeClusterDimension` (`FLASHINFER_CAKE_FUSED_KDA_DECODE_CLUSTER_X`); the static asserts keep cluster variants on the standard ABI. Generated sources `csrc/kda/cake_fused_kda_decode_cluster2_wide_positive_f32{,_wide_slot_offsets}.cu` are the Cake render of kernel commit `59347568947` (registry sha256 pinned). Dispatch boundary 9/10 is covered by the CPU tests; the GPU tests run the cluster route at rows 1 (dense), 9 (padded) and 8 (random slots, wide offsets).
- Round 5: `wide512_regcap128_positive_f32{,_wide_slot_offsets}` — the wide512 spread-producer kernel built with `__launch_bounds__(512, 1)` (128 registers per thread) for FP32 positive-unique rows 10–18, where the (row, head) grid fits one CTA per SM and the two-CTA register cap buys nothing; on scattered 8192-slot pools it keeps more slot loads in flight (B200 rows 10/14/16/18: 5.12/5.47/5.63/5.95 us vs 5.25/5.70/5.86/6.14 us). Dispatch `_H8_WIDE512_REGCAP128_MAX_ROWS = 18` mirrors the Cake launcher; generated sources are the Cake render of kernel commit `df8af201235` (registry sha256 pinned); CPU tests cover the 9/10 and 18/19 edges and the GPU tests run the route at rows 16 (dense) and 18 (padded). 52 registry variants per target.
- Round 6: the FP32 `wide512_positive_f32_wide_slot_offsets` and `wide512_regcap128_positive_f32_wide_slot_offsets` twins bind one pointer per CTA for the slot's state and conv cache and index with 32-bit offsets (their 64-bit per-access address arithmetic cost 0.4–0.5 us at two CTAs per SM on B200 rows 28–37; random 8192-slot pools rows 19/20/24/28/32/37 now 1.083/1.063/1.083/1.079/0.977/1.024× vs `cute-dsl`, rows 28 and 37 were 1.008–1.020× and 0.970–0.980×). `wide512_positive_f32` is re-rendered from the same generator so the twin pair shares one preamble (kernel body unchanged). Generated sources are the Cake render of kernel commit `ad1688e2999`; registry sha256 refreshed for the three files.
- New `persistent_rows` ABI: the `stream_bf16{,_wide_slot_offsets}` kernels take the row count and walk (row, head) items grid-stride; the binding launches `grid = max(1, min(rows * H, 3 * multiProcessorCount))` from the tensor's device behind `FLASHINFER_CAKE_FUSED_KDA_DECODE_PERSISTENT_GRID` (one launch for all rows).
- Generated sources `csrc/kda/cake_fused_kda_decode_stream_bf16{,_wide_slot_offsets}.cu` (256 threads, 70272 B dynamic smem, `--use_fast_math`; registry sha256 pinned).
- Tests: CPU dispatch coverage of every H=8 band and boundary (9/10, 18/19, 37/38, 55/56, 63/64, 76/77), wide-slot twins, unsupported heads; GPU tests for every H=8 route including the stream family with random slots, graph replay and write guards. Selection for the existing heads is unchanged (verified over 72k CPU selections against `bf82326b0`).
- Benchmark: `benchmarks/bench_cake_fused_kda_decode.py --shapes h8 --state-dtype {bfloat16,float32}`.
  In-repo result (abba-interleaved CUDA-graph cold-L2 CUPTI, 30 iterations per cell, cake vs `cute-dsl` on this branch, rows 1…4096 in powers of two):

  | GPU | state | geomean | min | every shape faster |
  |---|---|---|---|---|
  | B200 (sm_100a) | BF16 | 1.200× | 1.060× | yes |
  | B200 (sm_100a) | FP32 | 1.059× | 1.002× | yes |
  | B300 (sm_103a) | BF16 | 1.194× | 1.063× | yes |
  | B300 (sm_103a) | FP32 | 1.059× | 1.004× | yes |

Measured with the Cake evaluation contract (interleaved CUDA-Graph cold-L2 CUPTI pairing against this repo's `cute-dsl` fused decode with only its Python head check lifted; 34 shapes = H=8 × {BF16, FP32} × rows 1…4096 + random-slot serving rows over 8192 slots): B200 (sm_100a) geomean 1.122×, minimum 0.996× (`f32_rows32`, compact pool, 8.24 vs 8.18 us; 33/34 shapes strictly faster — this row pairs with `cute-dsl` at the shared memory-system floor, 0.997× in a second full sample and 1.004× in round 5 with a byte-identical route); B300 (sm_103a) geomean 1.120×, minimum 1.0026× (`f32_rows4096`), 34/34 shapes strictly faster. The two-CTA cluster route carries FP32 rows 1–8 at 1.07–1.14× (B200) / 1.07–1.11× (B300) vs cute; the 128-register wide512 route carries the FP32 rows-16 serving shape at 1.097× (B200) / 1.027× (B300); FP32 rows ≥512 run at 94–99 % of the same-node copy bandwidth on both GPUs. Correctness is oracle-gated on every row (torch semantic reference at the existing tolerances); synccheck and racecheck pass on 15 witnesses per GPU, including the cluster, 128-register and 8192-slot pointer-local routes.

### Security Architecture Review

**Security architecture risk:** _🟡 Moderate_ · up to `0d4a8`

The new H=8 path relies on callers supplying valid, uniquely owned cache slots. If untrusted slot values reach that path under an incorrect mode assertion, the kernel can access memory outside the cache allocation. The default backend remains unchanged, and no remote or cross-tenant exposure is established.

**Retained concerns**
- **Medium · security · inferred:** New H=8 Cake positive-unique routes trust the caller's mode assertion and GPU slot values when addressing mutable cache allocations. If that assertion or the slot bounds are wrong, the wide512 path can read or write outside the selected cache slot; falsely declared unique slots can also conflict.
