## 📌 Description

Follow-up to #5504 (per-token alpha for NVFP4 `mm_fp4`), from the one CodeRabbit finding left open there.

`_check_mm_fp4_problem_size` accepts any `alpha` with `m` elements, so a caller may pass `(1, m)` (for example `per_token_scale.unsqueeze(0)`). The non-tuned call handles that (`reshape(m)`), but the per-token tuning config ties alpha's dim 0 to the profiled M, so under `autotune(True)` the tuner would allocate a `(profiled_m, m)` alpha and the runner's `reshape(m)` would raise during profiling. `mm_fp4` now hands the tuner a 1-D view of a per-token alpha. One line of library code plus a test that runs the `(1, m)` shape through autotuning on SM100/SM103.
