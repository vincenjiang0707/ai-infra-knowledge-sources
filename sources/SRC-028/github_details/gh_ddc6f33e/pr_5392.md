## 正文

DiLoCo fragmenter: optionally bucketize large non-scanned params across layer fragments.

Streaming DiLoCo always puts every non-scanned parameter (embedding, output head,
final norm) into fragment 0, so the step that syncs fragment 0 moves far more data
than the layer steps: for Qwen3-8B the 151936-row embedding and head together
exceed a decoder layer several times over. With `diloco_bucketize_non_scanned`, every non-scanned leaf
with ndim >= 2 and at least `num_diloco_fragments - 1` rows is split row-wise
across the layer fragments, so each sync step moves about the same amount of data.

-   `FragmentedTreeManipulator` routes leaves through one keyed path
    (`_iter_keyed_leaves`) and describes each bucketized leaf with a `BucketSpec`
    (`chunk_size`, `remainder`). Flat fragment keys use the `#bucket` and
    `#remainder` suffixes; the remainder rows stay in fragment 0.
-   New config field `diloco_bucketize_non_scanned` (default `False`). With the
    default, fragment contents and the SPMD streaming DiLoCo trajectory are unchanged.
-   Both runners build their fragments with this class: the SPMD runner
    (`diloco.py`) and the threaded (MPMD) runner that a follow-up CL adds. The flag
    therefore works with either. SPMD needs no other change: it picks the fragment
    with `lax.switch` over static indices, so every branch has static row ranges.

Testing:

-   New `tests/unit/diloco_fragmenter_test.py`:
    -   Fragmenter: extract/apply round trips (bucketized or not, sequential or
        strided layer assignment), every parameter lands in exactly one fragment,
        bucket/remainder keys and shapes, off by default, a leading replica dim, and
        `ShapeDtypeStruct` leaves.
    -   SPMD sync path: running `spmd_diloco_sync.synchronize_fragment_state` once
        per fragment inside a 2-replica `drjax.program` must equal one full-tree
        Nesterov outer step (params and momentum trace), with and without
        bucketization. Injecting a replica-axis slicing bug into the bucket
        extraction makes the bucketized case fail.
-   `test_streaming_diloco_two_slices_bucketized` in `tests/integration/diloco_test.py`:
    AOT compile of the SPMD streaming step with bucketization for a 2x tpu7x-8
    topology.
-   CPU SPMD streaming DiLoCo smoke run (8 steps, 2 replicas, 3 fragments): the losses
    with the flag off match the pre-change code at every step (7.462 -> 7.399).
-   Hardware: SPMD streaming DiLoCo, 2x v6e-8, Qwen3-8B, 37 fragments (one per step),
    tau=5, 200 steps, synthetic data, run with the flag off and on. Both exit 0 with
    no errors and finite losses at every step.
    -   Losses match to the logged 3 decimals through step 6 and diverge from step 7
        on. The first synced fragment is applied at the end of step 5.
    -   Mean loss over steps 150-199: 6.917 (off) vs 6.944 (on).
    -   Wall time over steps 20-199: 1.378 s/step (off) vs 1.389 s/step (on).
