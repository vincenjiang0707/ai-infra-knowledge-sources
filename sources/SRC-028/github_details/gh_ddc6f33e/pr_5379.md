# Description

Port of cl/979649927.

Some consumers of `tgmm_v2` want its output in the spatial minor layout `[k, n, g]`, with the group axis on lanes. Getting there from `tgmm_v2` needs a relayout copy that materializes a second full size output in HBM.

This PR adds `tgmm_spatial_minor_v2`, a Pallas kernel that writes `[k, n, g]` directly. Each output tile is written to HBM once. A per group matmul fills a VMEM stage, and a register transpose built on native XLU transposes produces the output layout on chip. `tgmm_gnk_v2` dispatches on the requested layout and falls back to `tgmm_v2` plus a transpose. `tgmm_v2` gains input validation for operand ranks, `group_offset` forms and unaligned `m`.

On Ghostfish at `m=4096, k=7168, n=2048`, bf16:

| g | kernel | `tgmm_v2` + copy | peak HBM, kernel vs copy |
|---|---|---|---|
| 128 | 8.75 ms | 6.16 ms | 3.83 GB vs 7.59 GB |
| 16 | 3.26 ms | 2.92 ms | 3.83 GB vs 4.30 GB |

The kernel trades latency for half the peak HBM at `g=128`.
No existing caller changes.

# Tests

- Unit tests in `tests/unit/pallas_mosaic_tpu_v2_kernel_test.py` covering:
  - Numerical correctness tests against NumPy reference
  - Equivalence against existing `tgmm_v2` baseline
  - Dynamic `group_offset` slicing and window shifting
  - Input validation (operand ranks, mismatched shapes, layout permutations)
  - Dtype coverage (bf16/f32 inputs/outputs and accumulation)
  - Layout dispatch and HLO entry computation verification
