## Summary

Enables Qwen3.5-35B hybrid attention (Gated Delta Net + full self-attention) serving on TPU v6e under vLLM using the MaxText adapter.

Serving command paste: https://paste.googleplex.com/6558303367331840

## Context & Motivation

When attempting to run the Qwen3.5-35B vLLM serving command on `main`, serving fails during model initialization and JIT warmup. While colleagues running experimental branches (e.g., PR #5305 / `wxd/gdn-align-block-table`) had partial workarounds for prefix caching, pristine `main` encounters several blocking issues.

## Issues Addressed & Errors Seen

### 1. Paged GDN State Fallback to MaxEngine Cache
* **Error**:
  ```python
  File "maxtext/models/qwen3.py", line 913, in __call__
    recurrent_state, conv_state = active_cache.get_gdn_states()
  AttributeError: 'tuple' object has no attribute 'get_gdn_states'
  ```
* **Cause**: In `Qwen3NextGatedDeltaNet`, `use_paged_state` was gated strictly on `getattr(attention_metadata, "mamba_state_indices", None) is not None`. Under vLLM, `block_tables` is passed instead. When `mamba_state_indices` was `None`, `use_paged_state` evaluated to `False` and incorrectly tried to call `.get_gdn_states()` on the 2-tuple of paged buffers.
* **Fix**: Gated `use_paged_state` on either `mamba_state_indices` or `block_tables` being present. When `mamba_state_indices` is absent, extracted slots from `block_tables[:, 0]` with safe truncation handling.

### 2. Per-Layer Attention Metadata Dictionary Unwrapping
* **Error**:
  ```python
  AttributeError: 'dict' object has no attribute 'padded_num_reqs'
  ```
* **Cause**: vLLM passes `attention_metadata` as a per-layer dictionary (`{"layer.0": AttentionMetadata, ...}`). In `qwen3_5.py` and `qwen3.py`, `attention_metadata` was passed as-is to `self.attention(...)`, causing attribute lookups to fail on dictionary objects.
* **Fix**: Unwrapped `layer_attn_md = attention_metadata.get(f"layer.{self.layer_idx}")` if `isinstance(attention_metadata, dict)` in both `Qwen3NextDecoderLayer` and `Qwen3_5DecoderLayer`.

### 3. KV Cache Spec Resolution Timing in vLLM Adapter
* **Cause**: vLLM's `KVCacheManager.get_kv_cache_spec()` is invoked before `runner.model` is instantiated. The existing monkey patch in `adapter.py` checked `if not hasattr(runner, "model"): return original_get_kv_cache_spec(self)`, causing it to fall back to the unpatched spec and allocate standard `AttentionSpec` instead of `MambaSpec` for GDN layers.
* **Fix**: Stored `_maxtext_config` onto `vllm_config` during `MaxTextForCausalLM.__init__` and supported generating or resolving config directly from `runner.vllm_config`. Updated `MambaSpec` uniform page size handling with `dataclasses.replace`.

### 4. Dependency & Import Compatibility
* Added safe fallback imports for `must_fuse_call` in `jax_flash_attention.py` and multimodal utilities in `multimodal.py`.

---

## Operational Note: Memory Headroom
When running `--max-model-len=65536` with hybrid attention, `--gpu-memory-utilization=0.90` left only ~20 MB of free HBM, causing an XLA `RESOURCE_EXHAUSTED` (by 134 MB) during JIT program loading. Lowering `--gpu-memory-utilization` to `0.85` resolved this and provided ~4.7 GiB headroom while maintaining >3.1M KV cache tokens.

## Code Review

This pull request introduces several robustness improvements and fallback mechanisms to the MaxText vLLM adapter and model implementations, including fallback imports for tpu_inference and must_fuse_call, support for dictionary-based layer-specific attention metadata, and handling of block_tables alongside mamba_state_indices in Qwen3. Feedback highlights potential crashes, such as a StopIteration when attention_metadata is an empty dictionary, a ZeroDivisionError if seq_lens is empty, and potential instability when converting PyTorch bfloat16 tensors to JAX using NumPy views.
