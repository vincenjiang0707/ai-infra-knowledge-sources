# Description

Tests marked `scheduled_only` (and the whole TPU7X suite) only run in the periodic scheduled CI, so regressions in them are only caught hours after a PR lands, and a PR author who knowingly touches that area has no way to validate it before merging.

This PR adds a `scheduled-only` PR label that re-runs the CI pipeline as if it were a scheduled run:

- `ci_pipeline.yml` now listens to the `pull_request: [labeled]` event. Every entry job (`analyze_code_changes`, `code_quality_check`, `docs_build_check`) is gated on the added label being `scheduled-only`, so adding any other label (`pull ready`, `gemini-review`, etc.) leaves all jobs skipped and costs no CI capacity.
- `is_scheduled_run` is set to true when the label is present, so the `not scheduled_only` pytest filter is dropped, `cpu-unit` installs torch-cpu, and coverage is uploaded under the `scheduled` flag — identical to a cron run.
- `analyze_code_changes.sh` gains a `FORCE_ALL_TESTS` escape hatch so a labeled PR runs every suite instead of only the ones matching the changed files.
- TPU7X tests, previously hard-skipped on PRs, run when the label is present.

`notify_failure` / `investigate_failure` deliberately stay `schedule`-only, so a failing labeled PR does not open or comment on tracking issues.

The label is opt-in: remove and re-add it to trigger another run.
