# Description

This draft adds an opt-in, layer-level 1F1B gradient-accumulation schedule to MaxText’s normal training entry point. The existing serial schedule remains the default.

With `gradient_accumulation_schedule=dual_pipe`, three microbatches execute as:

```text
F0 → (B0 + F1) → (B1 + F2) → B2
```

Each combined layer-scan iteration contains backward for layer `L-1-k` of the previous microbatch and forward for layer `k` of the next microbatch. Both are inside the same jitted training step, exposing independent work to XLA’s scheduler that could overlap computation and communication.

This is microbatch scheduling within a training step, not distributed pipeline parallelism. It enables overlap opportunities but does not guarantee concurrent execution.

## Implementation

- Adds a JAX scheduler for the initial forward, combined backward/forward scans, and final backward.
- Adds an NNX adapter that reuses MaxText’s existing layers, embedding, and output head, and restores gradients to the original parameter structure.
- Extracts the existing masked loss calculation into a small helper shared by ordinary and dual-pipe training.
- Accumulates gradients with fixed parameters across microbatches and retains valid-token normalization. Optimizer updates remain in the normal training path.
- Handles DeepSeek’s dense prefix and MoE layers as separate homogeneous scan groups.

## Scope and limitations

Initial support covers NNX Llama and DeepSeek with TE-MoE, scanned layers, deterministic execution, and full or no rematerialization. Supported TE quantization recipes are stateless; unsupported configurations are rejected explicitly.

Broader model coverage, custom rematerialization, and mutable layer-state support remain future work. Peak memory can increase because old and next-microbatch residuals may coexist.

This change does not modify TE kernels, weight layouts, or TE-EP bootstrap capacity sizing.


# Tests

The 23 scheduler and NNX-adapter CPU tests pass:

```bash
PYTHONPATH=src JAX_PLATFORMS=cpu python -m unittest discover \
  -s tests/unit -p 'dualpipe*_test.py' -v
```

Coverage includes loss/gradient comparisons against reference autodiff, full rematerialization, heterogeneous layer groups, combined BF scan structure, gradient-tree restoration, frozen router state, and TE metric reductions.

The three dedicated shared-loss tests have not run successfully in the local environment because of missing dependencies (`filelock`/`omegaconf`).

The current review branch has not yet been GPU-validated. CPU tests do not establish full-model numerical equivalence, TE communication correctness, or a performance improvement.

This pull request introduces an experimental layer-fused dual-pipe scheduling feature (`gradient_accumulation_schedule=dual_pipe`) for Llama and DeepSeek models in MaxText, enabling layer-level 1F1B gradient accumulation. The implementation includes configuration updates, validation logic, pure-JAX scheduling routines, and comprehensive unit tests. The review feedback highlights two critical issues in `src/maxtext/experimental/dualpipe_nnx.py` where unconditional `jnp.moveaxis` operations on parameters and restored gradients could raise a `ValueError` if `param_scan_axis` is non-zero and any parameters have fewer dimensions than the scan axis. It is recommended to apply the suggested checks to ensure the dimensions are sufficient before moving the axes.
