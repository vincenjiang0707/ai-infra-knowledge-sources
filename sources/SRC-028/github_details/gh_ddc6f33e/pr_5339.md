# Description

Adds Multi-Token Prediction (MTP) support for DeepSeek V4, covering both the model layers and checkpoint conversion.

DeepSeek V4 carries a 4D residual stream `[batch, seq, mhc_expansion_rate, emb]` through the decoder (Manifold-Constrained Hyper-Connections), whereas V3 is plain 3D. Enabling MTP for V4 therefore means handling two orthogonal concerns at the prediction head:

- **Normalization**, which was already solved by the `normalize_y` flag added for V3 MTP in "Add separate final normalization for Multi-Token Prediction in DeepSeek models". This change reuses that mechanism rather than introducing a parallel one.
- **Collapsing the mHC streams**, which is V4-specific and is introduced here as a `reduce_mhc` flag on `apply_output_head`.

`NNXDecoder.__call__` now leaves the hidden state expanded and defers the collapse to `apply_output_head`, so the MTP block receives the full 4D state. Each MTP depth collapses it with its own learned hyper-connection head, applies its dedicated final norm, and then projects to logits with both normalization and reduction disabled. The unnormalized 4D state is what carries to the next depth:

```
NNXDecoder.__call__  ->  hidden_state = y          (stays 4D)
  main logits:  apply_output_head(hidden_state)     # reduce_mhc=True -> hc_head, then decoder_norm
  mtp_block(main_hidden_state=hidden_state)         # receives the full 4D state
      per depth k:  MTP layer (4D in -> 4D out)
                 -> mtp_layer.hc_head(...)          # 4D -> 3D, per-depth learned collapse
                 -> mtp_layer.final_norm(...)       # dedicated MTP RMSNorm
                 -> apply_output_head(..., normalize_y=False, reduce_mhc=False)
```

`reduce_mhc` defaults to `True`, which preserves existing behaviour for every current caller of `apply_output_head` (main logits, vocab tiling, and the vLLM adapter).

Two V4-specific details worth a reviewer's attention:

- `MultiTokenPredictionLayer` constructs a `DeepSeek4DecoderLayer` directly rather than using `transformer_layer_module`. With `scan_layers=True`, `get_decoder_layers()` returns a `DeepSeek4ScannableBlock` (a bundled HCA + CSA pair), which is not a single layer and cannot serve as an MTP layer.
- The per-depth `hc_head` is deliberately left unprefixed, unlike the other MTP submodules which are renamed to `mtp_{k}_*`, so that it matches the checkpoint key layout.

This also removes the config validation error that previously rejected `DecoderBlockType.DEEPSEEK4` in combination with MTP layers.

# Tests

**Unit tests**

- `tests/unit/param_mapping_test.py` — 35 passed. Adds three DeepSeek V4 MTP cases: the keys the MTP block contributes, that they disappear when `mtp_num_layers=0`, and a split/rejoin round-trip for the fused projection kernel.
- `tests/unit/multi_token_prediction_test.py` and `tests/unit/flop_calculation_test.py` — 84 passed, 9 skipped (skips unrelated to this change).

**Checkpoint conversion**

The MaxText-side keys generated for the MTP block were diffed against the `mtp_block` keys actually present in a converted DeepSeek V4 MTP checkpoint: an exact 45/45 match, no missing and no extra keys, for both `scan_layers=True` and `scan_layers=False`. That also confirms the MTP transformer layer carries a MoE gate bias but neither a compressor nor a hash-routing table, consistent with it being built with `compress_ratio=0` and `is_hash_routing=False`.

**End-to-end**
