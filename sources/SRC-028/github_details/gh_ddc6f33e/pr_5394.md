## 正文

DiLoCo: fragment extraction/application and outer step for threaded streaming DiLoCo.

Adds `trainers/diloco/utils/fragment_transfer.py`: the jitted pieces a threaded
DiLoCo learner uses to extract one parameter fragment per sync step, move it to the
host-side syncer, and apply the synced result a few steps later. Nothing uses it yet.
The trainer comes in a follow-up CL.

-   A *transfer fragment* is a dict `key -> 1-D jax.Array`, keyed like
    `FragmentedTreeManipulator.get_flat_fragment`. Each leaf is flattened
    shard-locally with `jax.shard_map`, so extract/apply never move data between
    chips and host transfers only see 1-D arrays. Leaves whose fragment shape isn't
    divisible by their sharding fall back to a global reshape.
-   `FragmentTransfer(manipulator, params, alpha)`: one jitted extract and one
    jitted apply for all layer fragments (the fragment index is a traced argument),
    plus a pair for fragment 0. `apply` pins its output shardings to the live
    parameters and donates them, so the train step sees unchanged shardings and the
    scanned layer stacks are updated in place. `alpha` implements
    `communication_overlapping_alpha`. Layer fragments must form an arithmetic
    progression (sequential or strided assignment), which is checked at construction.
-   `move_fragment(fragment, mesh)`: one batched `device_put` that keeps each
    array's PartitionSpec.
-   `nesterov_outer_step(...)`: float32 Nesterov outer step on the pseudo-gradient
    `outer - mean(learner fragments)`, equivalent to
    `optax.sgd(lr, momentum, nesterov=True)`.

Testing: new `tests/unit/diloco_fragment_transfer_test.py` on 8 CPU devices:
extract->apply moves exactly one fragment (sequential/strided, bucketized or not),
transfer arrays are 1-D and shard-local, apply keeps shardings and donates, alpha
interpolation, non-arithmetic layer assignment is rejected, `move_fragment` keeps
specs, and the outer step matches optax and keeps dtypes.
