# [PR #5360] Fix GDN Mamba block table indexing and enable align cache mode

## Overview
This PR fixes a critical GDN state corruption and logprob explosion bug in hybrid models (e.g. Qwen 3.5 / Qwen 3-Next) when served via `maxtext_vllm_adapter` with alignment-aware prefix caching enabled (`mamba_cache_mode="align"`).

---

## The Issue 

1. **Metadata Flattening in `adapter.py`**:
   `tpu_runner.py` correctly prepares `GroupedAttentionMetadata` mapping each layer/group to its respective metadata:
   - Groups 0, 1, 2 (Mamba/GDN layers) carry **Mamba block tables** with size proportional to `custom_mamba_cache_multiplier` (e.g., 5 blocks in constrained settings).
   - Group 3 (Full-Attention layers) carries the **Attention block table** (e.g., 14,485 blocks).
   However, `maxtext_vllm_adapter/adapter.py` contained legacy logic that intentionally discarded `GroupedAttentionMetadata` and picked metadata from a full-attention layer (`layer.3`), forwarding only Group 3 to the entire model.

2. **GDN Block Table Indexing Mismatch in `qwen3.py` / `qwen3_5.py`**:
   In `Qwen3NextGatedDeltaNet`, under alignment-aware prefix caching (`mamba_cache_mode == "align"`), `mamba_state_indices` is `None` and the layer determines state slots via:
   ```python
   block_tables = attention_metadata.block_tables
   write_state_indices = jnp.clip(
       block_tables_sliced[batch_idx, write_col], 0, local_rows - 1
   )
   ```
   Because `attention_metadata` had been replaced with Group 3 (Attention), `block_tables` contained Attention block IDs (e.g., block IDs 14, 28, 42). Since `local_rows = 5`, `jnp.clip` clamped every block ID >= 5 to **slot 4**.
   As concurrent requests generated tokens, they repeatedly overwrote each other's GDN recurrent states in slot 4, causing garbage state retrieval on subsequent turns.

3. **Missing `mamba_cache_mode` in `MambaSpec`**:
   In `adapter.py:patched_get_kv_cache_spec`, `mamba_cache_mode` was not forwarded when creating `MambaSpec`, preventing alignment-aware caching logic from activating in `TPUMambaManager`.

---

## Fixes Implemented

1. **`src/maxtext/integration/vllm/maxtext_vllm_adapter/adapter.py`**:
   - Preserves `GroupedAttentionMetadata` across the model call rather than collapsing it to a single attention layer metadata.
   - Extracts `input_positions` from the first available metadata entry (`first_meta`).
   - Forwards `mamba_cache_mode = getattr(self.runner.cache_config, "mamba_cache_mode", "none")` into `MambaSpec`.

2. **`src/maxtext/layers/nnx_decoders.py`**:
   - In `NNXDecoder.__call__`'s unscanned decode loop, dynamically supplies per-layer metadata:
     `current_kwargs["attention_metadata"] = attention_metadata.get(f"layer.{lyr}")`
     ensuring GDN layers receive Mamba block tables and full-attention layers receive Attention block tables.

3. **`src/maxtext/models/qwen3.py` & `src/maxtext/models/qwen3_5.py`**:
   - Defensively unpacks `attention_metadata.get(f"layer.{self.layer_idx}")` in `Qwen3NextDecoderLayer` and `Qwen3_5DecoderLayer` if `attention_metadata` is passed as a mapping.
