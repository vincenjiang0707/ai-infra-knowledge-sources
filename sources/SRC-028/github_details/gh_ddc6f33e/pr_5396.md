# Description

`decoupled-requirements.txt` is meant to install on any hardware (its header says the accelerator wheels are left out "so the file installs on any hardware"), but it currently fails to resolve on macOS:

```
error: No solution found when resolving dependencies
  cause: Because cuda-bindings>=13.4.2 has no wheels with a matching platform tag (e.g., `macosx_13_0_arm64`) and you require cuda-bindings>=13.4.2, we can conclude that your requirements are unsatisfiable.
```

The cuda12 lock now pulls in `cuda-bindings` and `nvidia-cutlass-dsl*` (including a `-cu13` variant), and `generate_decoupled_requirements.py` does not match them: its accelerator filters only cover `nvidia-cuda-*`, `nvidia-cudnn-*` and `*-cu12`. `cuda-bindings` 13.4.2 ships only `manylinux` and `win` wheels, so the lock is unsatisfiable on macOS. CI runs on Linux only, so this did not show up there.

This PR:
- adds `cuda-bindings` and `nvidia-cutlass-dsl` to `EXCLUDED_ACCELERATOR_PREFIXES` and `-cu13` to `EXCLUDED_ACCELERATOR_SUFFIXES`, and updates the comment explaining what is kept and why;
- regenerates `decoupled-requirements.txt` with the script (5 lines removed, nothing else changes).

The excluded packages now appear in `--print-accelerator-requirements`, so a GPU run of the decoupled suite still installs them on top, as with the other CUDA libraries. `cuda-pathfinder` is intentionally kept: it is a pure-Python wheel (`cuda_pathfinder-1.8.2-py3-none-any.whl`) and resolves everywhere, like `nvidia-ml-py`.

No code in `src/` or `tests/` imports `cutlass` or `cuda.bindings`, so dropping them from the decoupled environment does not affect the `decoupled_target` tests.
