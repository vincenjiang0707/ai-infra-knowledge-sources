## Overview

Follow-up to merged PRs #5344, #5364, and #5386. During post-merge verification of Qwen3-Next / Qwen3.5 Gated Delta Net (GDN) sequence packing, context parallelism (`gdn_cp_mode="head"` / `"seq"`), and the Pallas TPU forward/backward kernels, we identified several configuration traps, sharding/gradient bugs, and numerical/runtime edge cases.

This PR resolves each of those issues and adds fast-fail configuration checks in `pyconfig` (`MaxTextConfig` and `RLConfig`). Comprehensive CPU, 1-chip TPU v7x, and 4-chip TPU v7x correctness and performance/HBM verification was conducted on Google3 Forge via companion CL **[http://cl/971437186](http://cl/971437186)** (to keep the unit tests in this repo lightweight and fast).

## Bugs Identified & How They Are Fixed

### 1. Configuration Validation & Fast-Fail Guards (`src/maxtext/configs/types.py`, `src/maxtext/utils/maxtext_utils.py`)

* **Silent cross-document state leakage when `use_gdn_kernel=True` with packed sequences and `enable_gdn_sequence_packing=False`:**
  * *Issue:* `enable_gdn_sequence_packing` defaults to `False`. Previously, running the Pallas GDN kernel with packed data while leaving `enable_gdn_sequence_packing=False` only logged a one-time warning in `MaxTextConfig` (and did not check `RLConfig` or `max_seq_token_per_tpu > 0`), allowing the kernel to ignore `decoder_segment_ids` and leak `conv1d` taps and recurrent state across packed documents.
  * *Fix:* Replaced the warning with a `ValueError` in `validate_gdn_config`, invoked by both `MaxTextConfig` (when `packing=True`) and `RLConfig` (when `max_seq_token_per_tpu > 0` or `packing=True` without `max_seq_token_per_tpu`). (The pure-JAX path `use_gdn_kernel=False` always honors `decoder_segment_ids` and is unaffected.)
* **Duplicate GDN computation and memory under Tensor Parallelism (`TP > 1`) with `use_gdn_kernel=True`:**
  * *Issue:* The Pallas GDN kernel `shard_map` partition specs do not shard heads along the `tensor` mesh axis (`P(mesh_batch, cp_axis_name, None)`), causing every TP rank to redundantly compute and store all GDN heads when `TP > 1`.
  * *Fix:* Added a fast-fail `ValueError` in both `MaxTextConfig` and `RLConfig` when `use_gdn_kernel=True` and `ici_tensor_parallelism * dcn_tensor_parallelism > 1`.
* **Unsupported kernel shapes (`gdn_chunk_size != 64`, head dims not multiples of `128`, unaligned per-rank sequence lengths) and `use_qk_norm_in_gdn=False`:**
  * *Issue:* When `use_gdn_kernel=True` was configured with `gdn_chunk_size != 64`, `gdn_key_head_dim % 128 != 0`, or `gdn_value_head_dim % 128 != 0`, the forward pass fell back to pure JAX while the backward pass fell back to slow Pallas interpret mode. When the per-rank sequence length (`max_target_length // cp` or `max_seq_token_per_tpu // cp`) was not a multiple of `gdn_chunk_size`, the forward fallback crashed inside `_compute_forward_conv_and_states` during chunk reshaping. Additionally, the TPU forward kernel always normalized `q` and `k` even if `use_qk_norm_in_gdn=False`.
  * *Fix:* `validate_gdn_config` now fast-fails up front in both `MaxTextConfig` and `RLConfig` unless `gdn_chunk_size == 64`, `gdn_key_head_dim % 128 == 0`, `gdn_value_head_dim % 128 == 0`, `(seq_len // cp) % gdn_chunk_size == 0`, and `use_qk_norm_in_gdn == True`. Also added a runtime guard at the top of `gdn_decoupled_conv1d` (`api.py`) for direct callers, and wired `use_qk_norm_in_gdn` through the forward kernel (`config.py`, `wrapper.py`, `compute_gdn.py`, `api.py`).
* **Overlapping granular GDN remat tensor groups & missing `ShardMode.EXPLICIT` + CP guard:**
  * *Issue:* `_expand_gdn_remat_names` (`maxtext_utils.py`) placed overlapping checkpoint names in `gdn`, `gdn_conv`, and `gdn_states`, so mixing `"device"` and `"offload"` across `gdn` and `gdn_conv` crashed at model build time (`ValueError: names should be exclusive`). Setting `gdn*` remat options without `remat_policy="custom"` was also silently ignored, and `ShardMode.EXPLICIT` with `cp > 1` bypassed validation when `use_gdn_kernel=True` (crashing later in head-CP `shard_map`).
  * *Fix:* Partitioned `_GDN_CONV_NAMES`, `_GDN_STATE_NAMES`, and `_GDN_OTHER_NAMES` into disjoint sets (`gdn` expands to the union of all three), added fast-fail checks when `gdn* != "remat"` without `remat_policy="custom"` or when `tensors_on_device` and `tensors_to_offload` intersect, removed the `not self.use_gdn_kernel` exemption on the `ShardMode.EXPLICIT` + CP check, and typed `gdn_cp_mode` as `Literal["auto", "seq", "head"]`.

### 2. Pure-JAX Head-Sharded Context Parallelism (`gdn_cp_mode="head"`) Gradient & TP Sharding Fix (`src/maxtext/kernels/gdn/model_runner.py`)

* **Corrupted `norm.rms_norm.scale` / `out_proj` gradients under pure-JAX `gdn_cp_mode="head"` with data parallelism (`data > 1`) and unsharded `tensor` axis (`TP > 1`):**
  * *Issue:* In `run_jax_gdn_delta_rule`, `gdn_cp_mode="head"` returned `core_attn_out` still sharded along the head axis (`P(mesh_batch, None, cp_axis, None)`) rather than sequence-sharded (`P(mesh_batch, cp_axis, mesh_head, None)`). When `data > 1`, feeding this head-sharded layout directly into the downstream gated RMSNorm and `out_proj` produced corrupted gradients on `norm.rms_norm.scale` and `out_proj.kernel`. In addition, `gdn_cp_mode="head"` did not include the `tensor` axis in its head sharding spec when `TP > 1`.
  * *Fix:* In `run_jax_gdn_delta_rule`:
    1. Sharded heads across the combined `(*head_tuple, *cp_tuple)` axes inside `shard_mapped_delta_rule`.
    2. Added `jax.lax.all_to_all` at the end of `shard_mapped_delta_rule` to return `core_attn_out` to sequence sharding (`P(mesh_batch, cp_axis_for_pspec, mesh_head, None)`), matching the kernel head-CP contract.
    3. Unified `gdn_cp_mode="auto"` resolution (`_resolve_gdn_cp_mode`: selects `"head"` at `cp == 2` when divisible and `"seq"` at `cp >= 4`) and the `context_parallel_load_balance=False` guard across both the kernel and pure-JAX runners.

### 3. Pallas TPU Kernel Forward, Backward & Context-Parallel Fixes (`src/maxtext/kernels/gdn/**`, `src/maxtext/models/qwen3.py`)

* **Eliminate unnecessary final-state gradient collectives in training (`api.py`, `model_runner.py`):**
  * *Issue:* Setting `symbolic_zeros=False` on `gdn_decoupled_conv1d.defvjp` and allocating zero initial states during `MODEL_MODE_TRAIN` caused every training step to materialize zero final-state cotangents (`d_next_conv_state`, `d_next_recurrent_state`) and execute an unnecessary cross-chip `jax.lax.psum` (~4 MiB/layer) under sequence-sharded CP.
  * *Fix:* Restored `symbolic_zeros=True` on `gdn_decoupled_conv1d.defvjp` (`api.py`) and pass `None` initial states during `MODEL_MODE_TRAIN` (`model_runner.py`). For unjitted eager calls (`if not isinstance(qkv, jax.core.Tracer)`), `shard_mapped_gdn` is wrapped in `jax.jit` so `shard_map` + `custom_vjp(symbolic_zeros=True)` works in eager mode while keeping the jitted training jaxpr and StableHLO 100% unchanged.
* **Target-platform dispatch for CPU-host AOT compilation (`runtime_utils.py`, `api.py`, `pallas_mosaic_tpu_bwd.py`):**
  * *Issue:* Forward and backward kernel dispatch checked `jax.extend.backend.get_backend().platform == "cpu"`, which caused CPU-host AOT compilation targeting a TPU mesh to lower the pure-JAX / interpret-mode fallback instead of the Pallas TPU kernels.
  * *Fix:* Added `target_platform(*arrays)` in `runtime_utils.py` (inspecting array sharding devices, active mesh devices, or default device platform). When `target_platform == "tpu"`, both forward and backward lower the Pallas Mosaic TPU kernels and raise a `ValueError` if given unsupported shapes instead of falling back to interpret mode.
* **Right-padded prefill `next_conv_state` & 1-token autoregressive decode (`model_runner.py`, `qwen3.py`):**
  * *Issue:* When `enable_gdn_sequence_packing=False`, `run_gdn_kernel_layer` dropped `decoder_segment_ids` before extracting `next_conv_state`, causing right-padded prefill prompts to save trailing `0`-padding tokens into the conv state cache instead of the last `K-1` valid prompt tokens. Additionally, 1-token `MODEL_MODE_AUTOREGRESSIVE` decode with `use_gdn_kernel=True` entered the chunked kernel path and failed chunk-size validation.
  * *Fix:* Preserved `raw_segment_ids` in `run_gdn_kernel_layer` so `extract_segment_conv_state` always extracts the last `K-1` valid tokens after prefill, and routed 1-token `MODEL_MODE_AUTOREGRESSIVE` decode (`seq_len == 1`) in `qwen3.py` to the pure-JAX recurrent step (`jax_ar_gated_delta_rule`).
* **Numerical precision, segment-ID canonicalization & SMEM/DMA fixes:**
  * *Float32 intra-chunk log-decay cumsum (`compute_gdn.py`):* Always accumulate `g_cum_sum_list` and compute `g_cum[i] - g_cum[j]` in `float32` before `jnp.exp`, preventing catastrophic cancellation when `gdn_state_dtype=bfloat16`.
  * *Float32 post-conv keys in CP pass 1 (`compute_conv1d_bwd.py`, `api.py`):* Added `output_dtype=jnp.float32` to `conv1d_silu_fwd` during CP pass-1 `compose_local_from_t_inv` so `m_local` matches `s_ext`'s `float32` precision.
  * *Zero-norm `q`/`k` guard in backward kernel (`pallas_mosaic_tpu_bwd.py`):* Masked `dq` and `dk` to zero when $\lVert q\rVert^2 \le 10^{-30}$ or $\lVert k\rVert^2 \le 10^{-30}$, matching `qwen3._l2norm`'s forward guard on padded/zero rows.
  * *Direct-caller segment-ID canonicalization (`wrapper.py`, `api.py`, `pallas_mosaic_tpu_bwd.py`):* Added `canonicalize_local_segment_ids` so direct kernel callers passing raw non-monotonic IDs (`[1, 2, 1]`) or IDs $> 2^{24}$ automatically canonicalize to `1..N` and align `init_seg`.
  * *SMEM repeat-table sizing & decode DMA indexing (`metadata.py`, `wrapper.py`, `memory_ref.py`, `tiling.py`):* Sized SMEM repeat tables by chunk count ($\lceil N_{\text{tokens}} / C \rceil + N_{\text{reqs}} + 2$, 64× smaller in prefill), fixed decode DMA indexing `p_id * seq_tile_size + idx` in `memory_ref.py`, clamped `decode_tile_size` to `num_seqs` in `tiling.py`, vectorized per-chunk conv halo construction in `wrapper.py`, and removed dead monkey-patches/branches in `runtime_utils.py` and `model_runner.py`.

## Code Review

This pull request refactors and unifies the GatedDeltaNet (GDN) configuration validation and execution paths across MaxText and RLConfig, introducing stricter fast-fail constraints for tensor parallelism, chunk sizes, and head dimensions. It also updates the GDN forward and backward kernels to support optional QK normalization, correct segment ID canonicalization, and float32 accumulation for gating calculations to prevent precision drift. The review feedback highlights a critical bug in `runtime_utils.py` where the non-existent `jax.typeof` is called, and identifies two high-severity precision loss issues in `compute_gdn.py` where intermediate variables are unnecessarily downcast to the compute dtype before being upcast to float32.
