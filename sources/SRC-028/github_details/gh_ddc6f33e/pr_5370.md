# Description

This PR updates `gpu_docker_images_pipeline.yml` and `tpu_docker_images_pipeline.yml` to isolate manual (`workflow_dispatch`) Docker image builds from production (`maxtext-images`) builds and separate GPU/TPU failure tracking issues:
- **Separate issue labels for GPU and TPU failures:** `jayqi/failed-build-issue-action` looks up existing open issues solely by `label-name` (ignoring `title-template`). Because both GPU and TPU pipelines previously used `docker-image-build-failure`, GPU build failures appended comments to the open TPU failure issue (e.g., #5369). Updated the labels to `gpu-docker-image-build-failure` and `tpu-docker-image-build-failure` respectively.
- **Default manual runs to `maxtext-test-images`:** Set the default `workflow_dispatch` `repository_name` input in both pipelines to `maxtext-test-images` (newly created in `us-docker.pkg.dev/tpu-prod-env-multipod` with matching IAM permissions) so manual runs do not overwrite images in `maxtext-images`.
- **Consistent fallback for scheduled runs:** Passed `${{ inputs.repository_name || 'maxtext-images' }}` to `run_ci_tests` and updated `notify_failure` to run on `schedule` events or when `inputs.repository_name == 'maxtext-images'`.
