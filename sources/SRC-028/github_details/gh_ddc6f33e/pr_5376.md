# [PR #5376] Restore custom NNX collections in model_creation_utils.from_pretrained

state: open | updated: 2026-09-26T00:01:00Z

## 正文

`from_pretrained` has its own Orbax restore path, separate from `checkpointing.load_params_from_path` (fixed in #5226). For Linen-layout checkpoints (`params/params/...`) it had the same bug #5226 fixed for the training path: weights promoted to custom `nnx.Variable` subclasses (`MoEBiasVar`, `Tid2EidVar`) were never restored.

Two defects:

1. Request built at the wrong path. The whole model state was requested under `params/params`, but converters such as the DeepSeek-V4 one write each custom collection as a sibling (`params/MoEBiasVar/...`, `params/Tid2EidVar/...`). Custom-collection leaves were requested at paths that do not exist on disk.

2. Restored collections dropped. After restore only `restored["params"]["params"]` was kept, discarding every other collection.

Fix:

- Group abstract leaves by collection via `variable_name_from_type` and build one restore target + restore_args per collection present on disk. Collections on disk that the model does not define are skipped.
- Merge all restored collections into a single tree (`_deep_merge_dicts`) before alignment to model shapes.
- When freeing device memory ahead of restore, skip variables whose collection is not being restored, so they keep their initialized buffer instead of becoming dangling deleted arrays that fail at first use.

The NNX-layout checkpoint branch is unchanged.

Affects callers of `from_pretrained`, including
`tests/utils/forward_pass_logit_checker.py`. This loader was used for the DeepSeek-V4 scanned/unscanned forward-pass logit checks on v5p-32 (median KL ~0.012 vs HF goldens, max KL 0.41/37 respectively).
