## Summary
1. **Wire up `optimizer_memory_host_offload` in `MaxTextTrainingEngine` (`src/maxtext/training_engine/maxtext_engine.py`)**:
   - Previously, `MaxTextTrainingEngine` ignored `config.optimizer_memory_host_offload` and left `self._state.optimizer` on device HBM across both live execution and ahead-of-time compilation (`maxtext_engine_compile.py`).
   - Added `_offload_optimizer_state_to_host()` in `_compile_for_batch`, which places optimizer leaves onto `base.with_memory_kind(kind="pinned_host")` via `self._place_leaf` (mirroring `maxtext_utils.get_abstract_state_nnx` on the pre-train path).
   - Preserved `base.memory_kind` in `_zero1_sharding` so `shard_optimizer_over_data=True` (Zero-1) and `optimizer_memory_host_offload=True` compose cleanly and remain idempotent across recompiles.
   - Staged `state_pure["optimizer"]` onto `self._device_optimizer_shardings` (`memory_kind="device"`) inside `_update_kernel` before `nnx.merge(..., copy=True)`, matching `train.py`; `update_out_shardings` automatically returns the updated moments to `pinned_host`.

2. **Fix `AbstractMaxTextEngine._trace_train_state` mesh context (`src/maxtext/training_engine/maxtext_engine_compile.py`)**:
   - Run `nnx.eval_shape(build, model_pure)` under `logical_axis_rules(self._config.logical_axis_rules)` before entering `jax.set_mesh(propagation_mesh)` (matching `create_nnx_abstract_model` in `model_creation_utils.py`).
   - Prevents Flax 0.12.6's `_to_variable` from mistaking logical axis names stored on `nnx.Variable` metadata (such as `('norm',)` in `Qwen3NextRMSNorm`) for physical mesh axes when an `AbstractMesh` is active under `shard_mode=auto` (e.g. `custom_mesh_and_rule=cp-as-ep` on `qwen3.5-397b-a17b`).
