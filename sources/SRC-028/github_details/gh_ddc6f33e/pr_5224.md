# Description

Fixes two independent bugs causing cudnn_flash_jax attention failures during autoregressive inference:

1. Query/KV batch-dimension mismatch: query and key/value can arrive with different batch sizes at the cuDNN flash attention call (e.g. KV cache batch reduced to 1 while query keeps the full batch size). This is handled defensively in attention_op.py regardless of sharding config.
2. Missing autoregressive axis mapping for query heads: in inference.yml, activation_kv_heads was already sharded along the autoregressive mesh axis, but activation_heads (query) was not — an inconsistency in the logical axis rules, fixed independently in the config.

Fix:
- src/maxtext/configs/inference/inference.yml: add 'autoregressive' to the activation_heads logical axis rule so query heads are sharded consistently with KV heads under autoregressive parallelism.
- src/maxtext/layers/attention_op.py:
  - Move validate_gpu_flash_attention and KV dequantization earlier (before check_attention_inputs) for the cudnn_flash_jax path.
  - Add _align_qkv_for_cudnn_flash, which broadcasts key/value along the batch dimension to match query's batch size when KV has batch size 1 (raises ValueError for any other mismatch).
  - In cudnn_jax_flash_attention, broadcast the computed autoregressive lengths array to match the query batch size when it was reduced to length 1.


# Tests

- tests/unit/attention_test.py: new CudnnFlashJaxInferenceTest covering _align_qkv_for_cudnn_flash (broadcast success + invalid-mismatch error) and that autoregressive q_seqlen/kv_seqlen are broadcast correctly in cudnn_jax_flash_attention.
- tests/unit/generate_param_only_checkpoint_test.py: updated/expanded coverage for the config change.
