# [PR #5342] Add in-memory elastic snapshot utilities for Pathways multi-slice training.

## 正文

Add in-memory elastic snapshot utilities for Pathways multi-slice training.

Elastic training recovers from slice loss by restoring the most recent Orbax
checkpoint from GCS, and that read dominates recovery time at large multi-slice
scale. Surviving slices already hold a complete replica of the model state, so
recovery can be served from host and device memory instead.

Add the utility layer this requires to `elastic_utils`. `maybe_snapshot_state`
and `restore_resharded_state` capture and reshard either a `TrainStateNNX` or a
Linen train state across a mutated device mesh, `wait_for_devices_placed` polls
for device placement while slices join or leave, and `mutate_config_for_topology`
and `recalculate_batch_sizes` adapt batch sizing to the surviving topology.
Slice-count recording becomes non-fatal so a failed health check cannot abort a
training step.

Add `elastic_snapshot_interval` and `elastic_new_slice_check_period`, and raise
the `elastic_timeout_seconds` and `elastic_max_retries` defaults to values
validated during multi-slice scale testing. Resolve the slice count before the
hardware-dependent configuration block so elastic startup settles the topology
before device counts are derived.

Pin `pathwaysutils` to the revision that supplies the snapshot entry points
these helpers call.

Nothing calls the new helpers yet. The training loop integration follows in a
subsequent change.
