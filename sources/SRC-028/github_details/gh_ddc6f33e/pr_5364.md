## How Sequence Packing Works in GDN

Unlike standard Softmax attention—where sequence packing only requires a block-diagonal `segment_ids[i] == segment_ids[j]` mask on the $QK^T$ scores—a **Gated Delta Net (`Qwen3NextGatedDeltaNet`)** has **two stateful stages** where tokens from an earlier sequence will leak into a later sequence unless explicitly isolated:

1. **Stage 1 — Causal 1D Depthwise Convolution (`Conv1D`, kernel size $K = 4$)**: Every token looks back at the previous 3 tokens (`[t-3, t-2, t-1, t]`). If a new sequence starts at token $t$, taps reaching into `t-1`, `t-2`, or `t-3` belong to the *previous* sequence and must be zeroed out in both the forward and backward passes.
2. **Stage 2 — Chunked Gated Delta Rule (`chunk_size = 64`)**: Tokens are processed in 64-token chunks while maintaining a running recurrent hidden state $S_t \in \mathbb{R}^{D_k \times D_v}$ from chunk to chunk. Within a chunk, tokens interact causally weighted by cumulative log-decay (`g_cumsum`). When multiple sequences are packed together, we must control both **intra-chunk token interactions** and **inter-chunk recurrent state ($S_t$) propagation**.

## Edge Cases & How Each Is Handled

1. **Exact Chunk-Aligned Boundary (`Seq 1: 0..63` $\to$ `Seq 2: 64..135`)**:
   - When a sequence ends at the exact end of a chunk (`token 63`) and the next sequence starts at `token 64`, every token inside Chunk 0 has `m_out = 1` and every token inside Chunk 1 has `m_in = 1`.
   - To prevent `Seq 1`'s final state $S_0$ from leaking into `Seq 2`, we compare the last active sequence ID of Chunk 0 (`seg_prev = Seq 1`) against Chunk 1's sequence IDs. Because `Seq 1 != Seq 2`, the carry-over gate `m_keep` zeros out $S_0$ at the chunk boundary, and `Conv1D` masks out the 3-token halo (`61..63`).

2. **Sequence Crossing a Chunk Boundary and Ending Mid-Chunk (`Seq 2: 64..135`)**:
   - `Seq 2` crosses from Chunk 1 into Chunk 2 and ends at `token 135`.
   - At the start of Chunk 2, `m_keep = 1` preserves $S_1$, while the input state mask `m_in` (`seg_c == seg_c[0]`) is `True` only for tokens `128..135` and `False` for `136..191`. Thus $S_1$ updates `Seq 2`'s final 8 tokens and is invisible to `Seq 3` and `Seq 4`.

3. **Short Sequence Contained Entirely Within One Chunk (`Seq 3: 136..180`)**:
   - Because `Seq 3` starts after `token 128` and ends before `token 191`, both `m_in` (reads incoming state from Chunk 1) and `m_out` (writes outgoing state to Chunk 3) are `False` for every token in `Seq 3`.
   - `Seq 3` is solved purely within Chunk 2: its cumulative decay `g_cumsum` resets at `token 136`, and its $64 \times 64$ intra-chunk causal/strict masks (`seg_c[i] == seg_c[j]`) isolate `136..180` from both `Seq 2` (`128..135`) and `Seq 4` (`181..191`).

4. **Sequence Starting Mid-Chunk and Continuing to the Next Chunk (`Seq 4: 181..255`)**:
   - `Seq 4` begins at `token 181` inside Chunk 2 and continues into Chunk 3.
   - At the end of Chunk 2, the outgoing state mask `m_out` (`seg_c == seg_last_active`) is `True` **only** for tokens `181..191` (`Seq 4`), decaying and summing only `Seq 4`'s tokens into $S_2$ while discarding `Seq 2` and `Seq 3`.

5. **Mid-Row / Trailing `0`-Padding & Ultra-Short Sequences ($L < 4$ in `Conv1D`)**:
   - Packed rows often contain `0`-padding at the end of a row (or between segments). If `0`-padding were treated as a regular segment ID, a sequence ending right before trailing zeros at a chunk boundary would appear to change segment IDs (`Seq k -> 0`) and lose its state, or padding tokens could corrupt running sums.
   - We encode segment IDs (`encode_segment_ids`) using an associative scan that preserves the **last active sequence ID** with a negative sign (`-d`) on padding positions (`+d` on valid tokens). Padding tokens (`s_enc <= 0`) have their `Conv1D` outputs, gates (`g`, `beta`), and attention outputs zeroed out, while `abs(s_enc)` carries the active sequence identity across padding gaps without corrupting $S_t$.
   - For sequences shorter than the `Conv1D` window ($L \in \{1, 2, 3\}$), each tap $k \in \{0, 1, 2, 3\}$ checks `(seg_id[t] == seg_id[t - k]) & (seg_id[t] > 0)` in both forward and backward passes (and masks `dz` before shifting in backward `conv1d_silu_bwd`), guaranteeing zero cross-sequence bleed.

6. **Context Parallelism (`cp_size > 1` in both `head` and `seq` Modes)**:
   - When a packed sequence is sharded across multiple TPU chips (`cp_size > 1`), sequences and `Conv1D` 3-token halos can straddle chip boundaries.
   - Both the Pallas kernel path (`cp_gdn.py`) and Pure JAX path (`gdn_cp.py`) exchange the 3-token `Conv1D` segment halo and apply segment-aware inter-chunk state composition (`m_keep`, `m_in`, `m_out`) across TPU sub-chunks, ensuring bitwise-equivalent results whether `cp_size = 1`, `2`, or `4`.

## Improvements to Pure JAX + Sequence Packing Over PR #5351

We also upgraded the **Pure JAX + Sequence Packing (`use_gdn_kernel=False`)** implementation relative to [#5351](https://github.com/AI-Hypercomputer/maxtext/pull/5351):

1. **Clean Modularization Matching [#5344](https://github.com/AI-Hypercomputer/maxtext/pull/5344)**:
   - Extracted `segmented_causal_depthwise_conv1d`, `prepare_jax_gdn_segment_masks`, and `run_jax_gdn_delta_rule` into `src/maxtext/kernels/gdn/model_runner.py` and delegated from `src/maxtext/models/qwen3.py` (while keeping backward compatibility with `#5351`'s 4-argument helper signature).
2. **Full Context Parallelism (`cp_size > 1`) Support in Pure JAX**:
   - In `#5351`, Pure JAX sequence packing only applied when `cp_size == 1` (the `cp_size > 1` `shard_map` path did not pass `segment_ids`). Our Pure JAX path supports **both** `head`-sharded CP (`all_to_all`) and `seq`-sharded CP (`gdn_cp.custom_chunk_gated_delta_rule` with cross-chip `Conv1D` halo + segment-aware `compose_local`).
3. **Memory-Efficient `bfloat16` Per-Tap `Conv1D` Slicing**:
   - Keeps the padded `Conv1D` input in `bfloat16` before slicing each tap and accumulates the 4 masked tap products in `float32`, cutting temporary `Conv1D` tensor memory in half compared to upcasting the entire padded tensor upfront.
4. **Mid-Row & Trailing `0`-Padding State Preservation**:
   - Uses `encode_segment_ids` (`+d` / `-d`) in `prepare_jax_gdn_segment_masks` and `gdn_cp.py` so mid-row or trailing `0`-padding never corrupts state propagation across chunks.

## CLI Flags to Enable

To enable GDN sequence packing in training or compilation runs, pass:

```yaml
packing: true
enable_gdn_sequence_packing: true
use_gdn_kernel: true          # True = TPU Pallas Fwd/Bwd kernels; False = Pure JAX reference path
gdn_cp_mode: "auto"           # Supports "auto", "head", and "seq" with cp_size >= 1
```
