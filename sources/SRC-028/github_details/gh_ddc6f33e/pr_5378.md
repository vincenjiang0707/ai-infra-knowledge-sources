# Description

Cherry-picks four commits from `main` into `atwigg/mlperf`, applied in the order they landed on main. Each commit keeps its original author and has a `(cherry picked from commit …)` line.

| Commit on main | Original PR | What it does |
|---|---|---|
| edfd9fcc1 | #5293 | Adds `quantize_router_proj` (default `true`). When `false`, a qwix rule keeps the MoE router (`.*/gate$`) matmul unquantized. Only has an effect when `use_qwix_quantization=True` and `quantization` is set. |
| 341466e6e | #5207 | Adds `quantization="serve_fp8_weight"`, which runs FP8 weights natively (no dequantization) at inference time in `DenseGeneral` (qwix FP8 dot_general), the fused vLLM MoE path, and the gmm_v2 MoE path. Also passes `quant` into the Qwen3-Next / Qwen3.5 GDN projections. |
| 4d3d1535e | #5355 | Fixes AOT compilation for the ragged kernels (`pltpu.is_tpu_device()` instead of checking `jax.devices()[0].platform`) and passes data sharding into `load_compiled`. |
| cc19f4bb9 | #5360 | Uses `None` for `attention_metadata` when a layer is missing from the grouped metadata dict, instead of passing the whole dict down (`nnx_decoders.py`, `qwen3.py`, `qwen3_5.py`). |

**Why:** these main changes are relevant to the Qwen3.5-397B MLPerf RL work. They add native FP8 serving and router-quantization control for the MoE/GDN model, fix a vLLM grouped-metadata `AttributeError` on the same path as #5359, and fix AOT compilation of the ragged kernels.

**Notes for reviewers**
- The first three commits applied cleanly. For cc19f4bb9, the source changes applied cleanly, but its test file `tests/unit/grouped_attention_metadata_test.py` doesn't exist on this branch: the branch's port of #5359 (2fd1b5fad) left it out. The commit adds main's current version of that test. See the commit message.
- **Config interaction (edfd9fcc1):** a new check rejects `float32_gate_logits=True` together with `quantize_router_proj=True` when `quantization` is set and `use_qwix_quantization=True`. The Qwen3.5-397B configs set `float32_gate_logits: True`, so enabling qwix quantization with them will now also require `quantize_router_proj: false`. Nothing changes for the current bf16 (unquantized) runs.
- **serve_fp8_weight** is opt-in. It changes nothing unless `quantization: serve_fp8_weight` is set together with an FP8 `weight_dtype`. For RL rollout, the trainer → sampler weight sync would also need to send FP8 weights plus scales. That isn't part of this PR.
- 341466e6e also includes small changes to the shared `dequantize_weight` (handles size-1 scales; leading-dimension scale broadcasting only for weights with ndim ≥ 3). That code path is used even without the new mode.
