# [PR #5381] MoE: dense custom VJP for the router top-k selection (no scatter in the backward)

`deepseek_routing` takes the top-k routing weights with `jnp.take_along_axis(pre_bias_logits, top_k_indices, axis=-1)`.
Its transpose is a scatter-add of the `[tokens, k]` cotangent into `[tokens, num_experts]`, which XLA lowers on the TPU
to an element-serial `scatter_fusion`. The backward runs two of these per MoE layer (one per routing chunk); an earlier
profile of this model put them at about 1.6 ms per call.

This PR adds `router_topk_matmul_vjp` (default `false`). With it on, the gather goes through
`take_along_last_axis_dense_vjp`, a `jax.custom_vjp` whose forward is the same `take_along_axis` and whose backward
builds the dense gradient as a one-hot compare-select sum over the k slots,
`dx[..., e] = sum_k g[..., k] * (indices[..., k] == e)`. Top-k indices are distinct per token, so each output element
receives at most one term and the gradient of the op is bitwise equal to the scatter-add. In the full model the dense
result joins the other gate-logit gradient terms in a different fusion, so the summed gradient may differ by fp
reassociation. The config read uses `getattr(config, "router_topk_matmul_vjp", False)` so configs that do not declare
the field (e.g. `DummyConfig` in `router_replay_test.py`) keep the existing path.

### Measured effect

512 chips (one 8x8x8 v7x slice), DeepSeek-V3 671B MLPerf recipe, seed 1234, flag on vs off. Both runs were profiled
(steps 25-26); steady step is the mean of steps 21-42 excluding the profile steps.

| | flag off | flag on |
|---|---|---|
| steady step (s) | 3.829 | 3.675 (-4.0%) |
| `scatter_fusion` time in the profiled window (ms) | 748.9 | 0 |
| eval target reached at (samples) | 58368 | 55296 |

Loss agrees within 0.001 through step 16, then drifts by up to 0.06 (the flag-on run lower), consistent with the
reassociation above. One seed each; an unprofiled multi-seed confirmation has not run yet.

Compiled program (AOT, same config): with the flag off it is identical to the program before this change; with it on
there are 4 fewer scatter ops, code -3.9 MB, temps -2.2 MB, arguments and outputs unchanged, and the same dot count.

### Usage

Add `router_topk_matmul_vjp=true` to the run's config overrides (DeepSeek routing only; default `false`).

### Tests

Two new tests in `tests/unit/moe_test.py`:
`test_take_along_last_axis_dense_vjp_matches_take_along_axis` (forward and gradient bitwise equal to
`take_along_axis` for top-k indices; the lowered gradient contains no scatter) and
`test_deepseek_routing_topk_matmul_vjp` (`deepseek_routing` indices, weights and gradients bitwise equal with the flag
on and off).

On CPU (`JAX_PLATFORMS=cpu`, `pytest -n 16 -m "not tpu_only and not gpu_only"`) `tests/unit/moe_test.py` and
`tests/unit/router_replay_test.py`: 85 passed with this change (48 moe, 37 router replay) vs 83 on main (46 + 37).
`pre-commit run --files` on the four changed files passes (codespell, pylint, pyink, yamllint).
