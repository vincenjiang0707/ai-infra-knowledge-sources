### bvandermoon · 2026-09-24 · COMMENTED

Thanks for the PR @parsley9877. We should talk more about this offline. The goal of m3 is to use a single-file-per-model type of setup. This will help with readability. But the m3 work has just started and virtually all features are missing because of that. 

This PR takes the pattern of moving the model logic to a single file. But it seems like it is trying to make up for the features that aren't available in m3 yet (like kernel support, shardings, etc.) by fitting them all into this model file as well. These types of features will be shared for all of m3 rather than fitting them into the model files.

If we are going to support this model in m3 right now, then we will want to fit the m3 pattern of keeping just the core model logic in this file, and get access to performance features as they become available for m3 as a whole. Otherwise, we are sacrificing the goals of m3 and risking setting precedent for other models. Let me know your thoughts on this
