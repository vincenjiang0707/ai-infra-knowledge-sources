# [PR #5280] Disallow use_indexer config combinations that zero the entire training objective

# Description

In DeepSeek-V4 Stage 2 (Lightning Indexer Warm-up: use_indexer=True, indexer_sparse_training=False), train.py intentionally sets xent_sum = 0.0 (lm_loss = 0.0) so main model parameters remain frozen while the indexer trains via indexer_loss scaled by indexer_loss_scaling_factor.

However, base.yml defaults both indexer_sparse_training to False and indexer_loss_scaling_factor to 0.0. Enabling use_indexer=True without overriding at least one of these flags zeroes both lm_loss and indexer_loss, running training steps with total_loss == 0.0 and zero gradients without error.

Reject configurations where use_indexer=True, indexer_sparse_training=False, and indexer_loss_scaling_factor <= 0.0 in validate_train_config and loss_fn, while permitting valid Stage 2 warm-up (indexer_loss_scaling_factor > 0.0) and Stage 3 sparse training (indexer_sparse_training=True).
