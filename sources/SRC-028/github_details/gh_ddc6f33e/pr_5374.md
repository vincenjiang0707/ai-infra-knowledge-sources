# Description

This PR adds Grouped GEMM support to accelerate MoE workloads.
 
At the moment, JAX `ragged_dot` delivers insufficient performance for many MoE scenarios. To address this limitation, an option has been added to execute expert GEMMs using Grouped GEMM instead. Bias support is also fused into the operation, reducing execution time by approximately 20%.
 
## Motivation
 
MoE models use routing, which naturally creates an uneven distribution of tokens across experts. As a result, the number of tokens processed by each expert is dynamic and only becomes known at runtime. This requires a GEMM implementation capable of handling variable workloads for individual experts.
 
In addition, when Expert Parallelism (EP) is greater than one, token buffers must be allocated for the worst-case routing scenario. In practice, this often means that the amount of padding exceeds the number of real tokens.
 
Performing computations over the entire padded buffer results in substantial performance loss. Therefore, a ragged-style execution model is required, where each expert processes only the amount of data actually assigned to it.
 
Grouped GEMM provides an efficient solution to this problem by allowing per-expert workloads with dynamically varying sizes while avoiding unnecessary computation on padding. This significantly improves utilization and overall MoE performance.
