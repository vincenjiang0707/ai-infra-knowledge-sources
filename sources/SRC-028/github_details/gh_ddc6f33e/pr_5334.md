# Description
Implements the MVP for Qwen3 (`qwen3-0.6b`) under the modernized MaxText (m3) architecture, enabled via `use_m3_model=true`.

- **M3 Model Dispatch & Registry**: Added `use_m3_model` config flag to `base.yml` and routed `create_model` to dispatch `qwen3-0.6b` through the m3 registry (`m3/models/`).
- **Native NNX Implementation (`modeling_qwen3.py`)**: Built a standalone, top-to-bottom `Qwen3Model` and `Qwen3ForCausalLM` directly utilizing Flax NNX primitives (`nnx.RMSNorm`, `nnx.Linear`, `nnx.Embed`, `nnx.Einsum`) with zero unnecessary wrapper boilerplate.
- **RoPE Integration**: Fully integrated with m3's shared rotary positional embedding (`m3.core.rope`).
- **Simplified Scope for Follow-ups**: Kept the model definition pure by removing legacy KV cache handling (to be managed by vLLM backend) and omitting embedded sharding annotations (to be handled via post-construction transforms in a dedicated PR).
- **Comprehensive Parity Test Suite (`qwen3_comparison_test.py`)**: Added consolidated tests covering parameter paths/shapes/dtypes, numerical logit parity, and loss/gradient sanity.
- **Docs Update**: Updated `src/maxtext/m3/README.md` status to reflect active `qwen3-0.6b` registration.

## Code Review

This pull request introduces the modern "m3" backend for MaxText, implementing a pure Flax NNX model-agnostic Key-Value (KV) cache, a rotary positional embedding (RoPE) utility, and a fully self-contained dense Qwen3 model implementation alongside comprehensive unit and parity tests. The review feedback highlights several improvement opportunities: removing redundant arguments (`key_seq_len` and `value_seq_len`) passed to `KVCache` in `modeling_qwen3.py`, using the idiomatic `.value` property instead of `[...]` to access `nnx.Variable` values in `RMSNorm`, raising a `ValueError` for unsupported model modes during `KVCache` initialization to avoid silent failures, and completing an unfinished module docstring in the KV cache tests.
