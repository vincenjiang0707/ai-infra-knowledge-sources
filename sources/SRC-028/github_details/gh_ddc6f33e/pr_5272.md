# Description

Fixes `remove_gathered_mesh_axes` in `utils/pipeline_utils.py` mutating its `axes_to_remove` argument, and adds the first direct unit tests for `pipeline_utils`.

**The bug.** For every non-MoE leaf, `remove_gathered_mesh_axes` did `axes_to_remove.append("expert")` on the caller's list. `derive_stage_weight_partition_specs` (called from `NNXCircularPipeline.from_repeat_weights_to_bsw`) passes that same list to every leaf, so once any non-MoE leaf has been visited, `"expert"` is also stripped from the routed MoE block (`MoeBlock_0`) of every leaf visited afterwards. That contradicts the docstring ("The 'expert' mesh axis is only retained for the routed block").

**When it shows up.** JAX flattens dicts in sorted key order. In a single decoder layer `MoeBlock_0` sorts before its lowercase siblings (`self_attention`, `mlp`, the norms, `shared_experts`), so it is visited before the list gets polluted, which is why this is easy to miss. With `num_layers_per_pipeline_stage > 1` the stage is an `NNXSequentialPipelineStage` with children `layers_0`, `layers_1`, ...; `layers_0`'s non-MoE leaves are then visited before `layers_1`'s `MoeBlock_0`, and the routed-expert weights of every sub-layer after the first lose their `expert` axis in the BSW partition specs. Reproduction at the `PartitionSpec` level, using a Mixtral-style layer:

```
num_layers_per_pipeline_stage=2
  layers_0 MoeBlock_0/wi_0 -> P('expert', None, 'tensor')
  layers_1 MoeBlock_0/wi_0 -> P(None, None, 'tensor')   # expected P('expert', None, 'tensor')
```

**The fix.** Build a new list (`[*axes_to_remove, "expert"]`) instead of appending to the argument. Results are unchanged for single-layer stages and for non-MoE models; only the multiple-sub-layers-per-stage MoE case changes.

I have only reproduced this at the spec level. I have not run a multi-layer-per-stage MoE pipeline on TPU/GPU, so I can't quantify the runtime effect (I'd expect extra gathering and memory for the expert weights).

**Tests.** `pipeline_utils.py` had no direct unit tests. `tests/unit/pipeline_utils_test.py` (CPU only, `cpu_only` marker) covers:
- the partition-spec helpers (`get_mesh_axis_dim_indices`, `remove_gathered_mesh_axes`, `derive_stage_weight_partition_specs`, `strip_pipeline_repeat_logical_axis`, `is_spec_leaf`), including regression cases for the bug above;
- `is_static_param`, `flatten_nnx_state` / `unflatten_nnx_state`, `advance_rng_state`, the Linen-collection helpers and `PipelineContext`;
- `create_gradient_accumulation_scan`: outputs and gradients (eager and under `jit`) match a plain `jax.lax.scan` over the same step, including the accumulated `bsw` cotangent.
