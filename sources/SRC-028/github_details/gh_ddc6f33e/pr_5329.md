## Summary
Fixes CPU RAM OOM (`exitCode: 137`) during 397B Orbax/Pathways checkpointing and weight synchronization while keeping checkpoint persistence asynchronous (`async_checkpointing=True`).

### Changes
1. **Pathways Persistence `gs://` Guard (`src/maxtext/training_engine/checkpointing.py`)**:
   - Validate in `CheckpointManager.__init__` (before `_maybe_register_pathways_persistence()`) that `checkpoint_dir` starts with `gs://` whenever `ENABLE_PATHWAYS_PERSISTENCE=1`, so every `CheckpointManager` instantiation validates the path even after `_PATHWAYS_PERSISTENCE_REGISTERED` is set.
2. **Purge Staged Sync Buffers Without Blocking on Async Checkpointing (`src/maxtext/training_engine/maxtext_engine.py`)**:
   - Add `_purge_raiden_buffers()` (`self._raiden_sync.release_buffers()` + `gc.collect()`) called before `convert()` in `prepare_weight_sync()` and after `metrics()` in `release_weight_sync()`, without calling `_checkpoint_manager.wait_until_finished()` so async GCS checkpoint uploads overlap concurrently with weight conversion and transfer.
3. **Unit Tests**:
   - `tests/unit/checkpointing_test.py`
   - `tests/post_training/unit/prepare_weight_sync_test.py`

## Code Review

This pull request introduces a configuration option `save_optimizer_state` to conditionally save the optimizer state in checkpoints, and adds a GCS URI validation guard when `ENABLE_PATHWAYS_PERSISTENCE` is enabled. It also implements buffer purging (`_purge_raiden_buffers`) in the training engine to release Raiden buffers and trigger garbage collection before weight conversion and after transfer completion. The review feedback suggests adding a defensive `hasattr` check for `release_buffers` on `_raiden_sync` to prevent potential `AttributeError` crashes when running with older versions of the `tunix` package.
