# [PR #5397] Add in-layer MoE dropless fallback (moe_in_layer_dropless_fallback)

## 正文

Adds an in-layer alternative to retry_when_tokens_dropped. Each ring-of-experts MoE layer predicts from the router top-k (local tokens + a [chunks, EP] psum, all-reduced over the mesh) whether its ragged buffer would overflow, then uses lax.cond to run either the normal capped path or a chunked, fully rematerialized dropless path whose per-chunk buffer is no larger than the capped buffer.

Unlike the step-level retry, this never replays the train step, keeps state donation enabled, and needs no per-step host sync. The two options are mutually exclusive. The number of layers that took the dropless branch is logged as learning/moe_dropless_fallback_layers.

## Code Review

This pull request introduces an in-layer dropless fallback mechanism (`moe_in_layer_dropless_fallback`) for MoE layers, which conditionally routes to a chunked dropless path using `jax.lax.cond` when a ragged buffer overflow is predicted. This avoids the need for a full-step replay. The feedback points out a potential runtime crash when context parallelism is enabled, as the configured number of fallback chunks might not evenly divide the local sequence length, and suggests adding validation in `types.py` to prevent this.
