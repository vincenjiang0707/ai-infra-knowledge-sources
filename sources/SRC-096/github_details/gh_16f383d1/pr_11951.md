<details><summary>Full analysis</summary>

**Summary:** `make test` aborted after the gtest `shm_ib/test_ucp_wireup_1sided.send_disconnect_onesided_nozcopy/0 <shm,ib/rma>` case hung; `ucp_test.cc:300 UCX ERROR request 0x62e000182718 did not complete on time`, then `test_helpers.cc:57: Failure / Connection timed out - abort testing`, SIGABRT, core dumped, `Bash exited with code '2'`.

**Root cause:** Evidence from the log: the test starts at `10:27:24.03` and the next line is at `10:38:41.11` — an 11‑minute gap with no output at all, followed by the request‑deadline error and the abort at `10:42:23`. There is no CQE error, no error‑callback message, no ASAN report — i.e. a silent hang of a UCP RMA request, not a slow test. This test does 100 × 8000‑byte `ucp_put_nb` with `ZCOPY_THRESH=-1` (→ inf) and `RNDV_THRESH=inf`, then `ucp_ep_flush_nbx` + `request_wait` (test/gtest/ucp/test_ucp_wireup.cc:286‑308), so what hung is a PUT (or its flush) on the ib/rc_mlx5 lane.

The only thing this PR changes is the mlx5 capability query, and the new native implementation changes what the rc_mlx5 iface advertises to UCP:
- `src/uct/ib/mlx5/rc/rc_mlx5_iface.c:1185-1203`: `max_sgl = uct_ib_mlx5_ext_max_put_sgl_zcopy_count()`; that returns **0** when no external plugin is registered (`src/uct/ib/mlx5/ib_mlx5_ext.c:32-46`, the normal CI case), and the code then falls back to `uct_rc_mlx5_base_put_sgl_zcopy_max_count()`, which is *always* positive (`src/uct/ib/mlx5/rc/rc_mlx5.inl:27-38`). Result: `UCT_IFACE_FLAG_V2_PUT_SGL_ZCOPY` and a non‑zero `max_put_sgl_zcopy_count` are now reported unconditionally, which feeds UCP's RMA protocol/lane selection (the SGL‑PUT protocol is still actively being fixed — see #11778, #11940, #11947). The SGL PUT path signals a CQE only on the last WQE of the batch (`src/uct/ib/mlx5/rc/rc_mlx5_ep.c:296-339`), so a mis-selected/partially-posted SGL PUT completes never and shows up exactly as "request did not complete on time" with no error.
- Secondary regression from the same commit: the plugin's `iface_query` op (still declared at `src/uct/ib/mlx5/ib_mlx5_ext.h:119`) is no longer invoked from `uct_rc_mlx5_iface_query_v2()`, so plugin-provided v2 cap flags are silently dropped.
