# [PR #11841] UCT/RC: Reserve TX credits for multi-credit sends

source: https://github.com/openucx/ucx/pull/11841
state: open | updated: 2026-09-13T19:33:07Z
labels: Ready for Review

## 正文

## What?

Reserve the TX credits a multi-credit send needs, so that later single-credit sends on the same EP cannot consume them.

## Why?

`put_sgl_zcopy` needs `count` WQEs, so it returns `NO_RESOURCE` while credits are still available and is queued in pending. A later 1-credit AM then passes the resource check and is posted ahead of it:
```text
rc_iface.h:620 Assertion `iface->tx.in_pending || ucs_arbiter_group_is_empty(arb_group)' failed
```

## How?

Resource checks compare the available credits against `max(requirement, EP reservation)`, and a failing send records its requirement in `txqp_reserve` / `cq_reserve`. 
The reservation is released by `uct_rc_ep_schedule_pending()` once nothing is queued on the EP, and by `uct_rc_ep_pending_purge()`.

<details><summary>Full analysis</summary>

**Summary:** `run_ucx_perftest_fault_tolerance` (task 1/4) failed on `swx-rain03` (roce worker 1): `verify_active_devices ucx_perftest.stdout 1 mlx5_1` returned 1, causing `./contrib/test_jenkins.sh` to exit with code 1.

**Root cause:** At 18:26:16 the script launched `/hpc/local/oss/ucx/fault_tolerance/ucx_drop_tool -d mlx5_0 -s 10 -t 40`, which immediately failed:
```
ucx_drop_tool.c:409  UCX ERROR failed to create TX RDMA flow table, syndrome 0x31ed04: Remote I/O error
ucx_drop_tool.c:661  UCX ERROR failed to setup flow table for device 0: Input/output error
```
The tool is started in the background (`${drop_tool} ... &`, line 549) and its exit status is never checked. Because it died, traffic on `mlx5_0` was never dropped, so `ucx_perftest` never triggered failover and never emitted a second protocol-info block (`| perftest self cfg#1 |`) — the log shows only `cfg#0` with `50% on rc_mlx5/mlx5_0:1 and 50% on rc_mlx5/mlx5_1:1` and continuous thread-0 latency lines. `parse_active_devices` therefore hit EOF and returned 1, and the run aborted (`kill -9 1471392 - No such process` confirms the drop tool was already dead).

Two contributing factors, both specific to this worker: (a) this is a **RoCE** node, where SL-based flow steering used by the drop tool is not applicable/supported on the device, and (b) `sl=$((EXECUTOR_NUMBER + 1))` produced `UCX_IB_SL=10`, which is outside the valid 0–7 priority range on RoCE. Nothing in the failure path touches the RC pending/SGL-order code changed by this PR.

**Implicated commit:** `[REDACTED:Hex High Entropy String]` — "CI/FT: Adds fault tolerance CI test (#11570)", william-gallagher-nv (test was added without gating on IB vs. RoCE link layer). PR head commit `165dea4a` is not implicated.

**File:** `contrib/test_jenkins.sh:549` (unchecked background launch of drop tool); failure surfaces at `contrib/test_jenkins.sh:557` and `:430`

**Suggested fix:**
1. Gate the test on the link layer — skip when devices are Ethernet/RoCE, e.g. in `run_ucx_perftest_fault_tolerance` (before line 515):
   ```bash
   if ibv_devinfo -d "${dev}" | grep -q 'link_layer:.*Ethernet'; then
       echo "==== Skip UCX Perftest Fault Tolerance Test on RoCE device ${dev} ===="
       return 0
   fi
   ```
2. Validate the drop tool actually started instead of failing later with a misleading message:
   ```bash
   ${drop_tool} -d ${dev} -s ${sl} -t ${tc} > drop_tool.${dev}.log 2>&1 &
   drop_pid=$!
   background_pids+=($drop_pid)
   sleep 1
   if ! kill -0 ${drop_pid} 2>/dev/null; then
       echo "Error: ucx_drop_tool failed to start on ${dev}"; cat drop_tool.${dev}.log
       kill_background_processes "${background_pids[@]}"; return 1
   fi
   ```
3. Clamp the derived SL/TC to valid ranges (`sl=$(( (EXECUTOR_NUMBER + 1) % 8 ))`) so RoCE/IB SL values stay legal regardless of `EXECUTOR_NUMBER`.
4. Short term: re-run the `roce` job / do not block PR #11841 on this failure.
