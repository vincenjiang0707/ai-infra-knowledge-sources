### drmichaeltcvx · 2026-02-19

Removing the offending `libfabrics` provider 
`$I_MPI_ROOT/libfabric/lib/prov/libefa-fi.so`
is a workaround. 

Note that the libfabrics and UCX libraries do not crash on systems with lower number of cores. The offending provider `libefa` crashes on HBv5 (MI300C) SJUs that have **368** cores / node. Other platforms with 176 cores / node seem to be working OK. 

I under54stand that this is NOT a UCX bug per se but the libibverbs library crashes on the HBv5s when it calls the `try_all_drivers ()` from `/lib64/libibverbs.so.1`

If `try_all_drivers ()` can be hardened NOT to terminate the MPI program when one of the `libfabrics` provider ungracefully fails, MPI codes can avoid crashing when these irrelevant conditions arise in non-applicable h/w.
