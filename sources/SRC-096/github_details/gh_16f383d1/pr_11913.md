## 正文

Opened to reproduce a sporadic CI failure.

Reverts the skip added in #11620, which disabled `test_ucp_rma_sgl` on CUDA memory type. The underlying bug only reproduces in CI (GPU lane), so this draft re-enables the test to get a failing run to investigate.

The failure looks like:

```
[swx-rdmz-ucx-gpu-01:61675:0]  proto_reconfig.c:104  UCX  ERROR cannot find remote protocol for: ucp_context_5834 intra-node cfg#2 | put from sgl cuda/GPU1 to cuda/dev[1]
```

i.e. a request parked on the reconfig protocol finds no SGL PUT protocol for cuda -> cuda in the endpoint configuration it is re-resolved against.

This PR will be turned into the actual fix (keeping the test enabled) once the root cause is understood.

### svc-ucx · 2026-09-07

🤖 **CI Triage Agent** — `UCX PR (AddressSanitizer roce on worker 0)` · commit `c9af1107`

**TL;DR:** `shm_ib/test_ucp_atomic32.misaligned_post/1` failed because `ucp_rkey_pack()` returned `UCS_ERR_IO_ERROR` after a ~30 s stall (mlx5 on-demand key creation inside `uct_ib_mlx5_devx_mkey_pack`), and the gtest binary then **aborted** because `test_xfer()` leaks the mapped `memheap_memh` on the early `ASSERT_UCS_OK` return, tripping the fatal rcache `region->refcount == 0` assertion at `ucp_cleanup`.

<details><summary>Full analysis</summary>

**Summary:** ASan/roce gtest job crashed (`make: *** [Makefile:4713: test] Aborted (core dumped)`) after `test/gtest/ucp/test_ucp_memheap.cc:68` reported `Error: Input/output error` from `ucp_rkey_pack()`.

**Root cause:**
- Log evidence: `[ RUN ] shm_ib/test_ucp_atomic32.misaligned_post/1` at 15:31:46.914, then 30.5 s of silence, then `test_ucp_memheap.cc:68: Failure / Error: Input/output error` at 15:32:17.415. Line 68 is `ASSERT_UCS_OK(ucp_rkey_pack(...))`, so a `uct_md_mkey_pack_v2()` call failed (`src/ucp/core/ucp_rkey.c:222-228`).
- For a plain (non-export) rkey pack, the only error source in the mlx5 DEVX MD is the on-demand atomic (KSM) key creation: `uct_ib_mlx5_devx_reg_atomic_key()` at `src/uct/ib/mlx5/dv/ib_mlx5dv_md.c:3017`. The variant is `ATOMIC_MODE=device`, so an indirect atomic mkey is required. The 30 s stall + an `IO_ERROR` also exactly matches the other synchronous device path in this MD — `uct_ib_mlx5_devx_umr_post_sync()` polls the UMR CQ with a hard 30 s timeout (`ib_mlx5dv_md.c:1441-1448`) and its failure is converted to `UCS_ERR_IO_ERROR` in `uct_ib_mlx5_devx_reg_xgvmi_umr_mr()` (`ib_mlx5dv_md.c:2908-2910`) — i.e. a device/UMR operation that never completed.
- The real UCT error text is invisible because `misaligned_post` wraps the *entire* `test()` call in `scoped_log_handler slh(hide_errors_logger)` (`test/gtest/ucp/test_ucp_atomic.cc:330-337`), so all `ucs_error()` output was suppressed — that is why the log shows only "Input/output error".
- The job-killing abort is a separate test bug: when `ASSERT_UCS_OK` at `test_ucp_memheap.cc:68` returns early, `ucp_mem_unmap(memheap_memh)` at line 120 is never reached. The leaked memh keeps a UCP rcache region referenced (`rcache.c:670 WARN ucp_rcache: destroying inuse region ... ref 1 md[2]=mlx5_0 md[3]=mlx5_1 ...`), so `ucs_rcache_destroy()` during `ucp_cleanup()` hits `Assertion 'region->refcount == 0' failed` (`rcache.c:394`) and core-dumps, aborting all remaining tests.

**Implicated commit:** unknown — no recent commit touches the atomic/KSM pack path or `test_ucp_memheap.cc`; PR #11913 (c9af110) only un-skips CUDA SGL tests and the failing test is not an SGL test, so the mkey failure looks environment/HW-sporadic while the abort is a long-standing test-cleanup bug.

**File:** `test/gtest/ucp/test_ucp_memheap.cc:68` (failure) and `:120` (missing unmap on early return); `src/uct/ib/mlx5/dv/ib_mlx5dv_md.c:3017` / `:1441-1448` (failing device key creation); `test/gtest/ucp/test_ucp_atomic.cc:333` (error log suppression)

**Suggested fix:**
1. Make `test_ucp_memheap::test_xfer()` failure-safe: hold `memheap_memh`/`send_memh` in a RAII wrapper (e.g. `ucs::handle<ucp_mem_h>` with `ucp_mem_unmap`) so an early `ASSERT_*` return still unmaps them. This removes the fatal rcache abort so a single test failure no longer kills the whole gtest binary.
2. Narrow the `scoped_log_handler(hide_errors_logger)` in `test_ucp_atomic{32,64}.misaligned_post` to only the `do_atomic()` call, so the underlying UCT error (`... atomic-key ... failed` / `ibv_poll_cq(UMR CQ ...) timed out`) is visible in CI and this failure becomes diagnosable.
3. Re-run this variant with `UCX_LOG_LEVEL=debug` on swx-rain04 to confirm whether the 30 s stall is the UMR CQ poll timeout or a DEVX `CREATE_MKEY` (atomic-key) failure; if it is the UMR poll, that 30 s busy-wait loop should also be shortened/made non-fatal and should return `UCS_ERR_TIMED_OUT` instead of being masked as `IO_ERROR`.

**Related:** PR #11913 (this build); PR #11780 (UMR QP INIT2RTR failure on LAG-bonded/RoCE devices — same UMR machinery); issue #4176 (older rcache "inuse region" abort in `test_ucp_atomic32`)
