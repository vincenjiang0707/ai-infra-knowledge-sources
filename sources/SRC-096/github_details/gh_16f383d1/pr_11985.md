# [PR #11985] UCP/PROTO: Apply GPU-NIC assignment to RMA and rendezvous lanes

source: https://github.com/openucx/ucx/pull/11985
state: open | updated: 2026-09-23T15:15:06Z
labels: 

## 正文

## What?
Restrict the RMA_BW lanes of zcopy RMA and rendezvous protocols to the NICs assigned to the GPU that owns the buffer.

## How?
- The owner is the staging buffer's GPU for pipeline (mtype) protocols when it is known, otherwise the application buffer's GPU. Non-CUDA memory and GPUs without an assignment keep the existing lane selection logic.
- Unassigned RMA_BW lanes are removed before lane performance is queried. If none are left, the protocol is skipped.
- The assignment applies to put/get zcopy (including IOV and SGL) and to rendezvous get/put, both zcopy and mtype. Bcopy is excluded, because with CUDA memory it only handles zero-length messages.
- When an assignment is in use, ties between equally fast lanes always go to the first lane, `SINGLE_NET_DEVICE` filtering is skipped.
- Tests use a mocked `rc_mlx5` fixture with a synthetic assignment.
