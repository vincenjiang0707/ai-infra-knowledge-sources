# [PR #11944] UCS/DATASTRUCT: Extract red-black tree core from interval tree

source: https://github.com/openucx/ucx/pull/11944
state: closed | updated: 2026-09-18T11:33:07Z
labels: 

## 正文

## What?
Factor the balancing mechanics of ucs_interval_tree_t into a reusable intrusive red-black tree, ucs_rbtree_t, and port the interval tree onto it. The caller performs its own descent and hands the attachment point to ucs_rbtree_insert_at, so the ordering key stays in the embedding struct.

The only behavior that changes is node identity on removal: the successor is relinked rather than having its interval copied into the removed node, so the node object a caller names is the one removed. Interval tree nodes are pool allocated and never referenced from outside, so this is not observable here; it is what lets a later user hold node pointers across unrelated removals.

## Why?
For later reuse of the rbtree in an interval_map structure

🤖 **CI Triage Agent** — `UCX PR (go gpu)` · commit `440231f1`

**TL;DR:** The Go binding test `TestUcpWorkerEfd` deadlocked and hit the 10-minute `go test` timeout because `syscall.EpollWait` returned `EINTR` (a Go runtime preemption signal, SIGURG), and the test's error path calls `t.Fatalf` from inside a goroutine — which kills that goroutine without ever sending on `eventsChan`, leaving the main test goroutine blocked forever. Fix: retry `EpollWait` on `EINTR` and never call `t.Fatalf` from a non-test goroutine.

**Summary:** Azure job "UCX PR (go gpu)" step "Run go tests" failed: `panic: test timed out after 10m0s` in `github.com/openucx/ucx/bindings/go/tests`, hung in `TestUcpWorkerEfd`.

**Root cause:** Log evidence:
- `08:15:42.838  worker_test.go:61: Failed to call epoll_wait interrupted system call`
- then a **9m55s gap with zero output** until `08:25:37 panic: test timed out after 10m0s`
- stack trace: `goroutine 36 [chan receive, 9 minutes] ... TestUcpWorkerEfd ... worker_test.go:74`

So this is a **hang, not a slow test**. `syscall.EpollWait(epfdLocal, events[:], -1)` at `worker_test.go:59` returned `EINTR` — expected on Linux when the Go runtime delivers an async-preemption signal (SIGURG) to the thread blocked in the syscall; the test does not retry. The error branch then calls `t.Fatalf` at line 61, but `t.Fatalf` from a non-test goroutine only records the failure and calls `runtime.Goexit()` on that goroutine, so line 64 `eventsChan <- nevents` is never reached. The main test goroutine is parked forever on `nevents := <-eventsChan` (line 74) with no timeout guard (unlike the `started` channel, which has a 500 ms `select`/`time.After`). The result is a permanent deadlock that only the global 10-minute test alarm breaks, and the panic exit code 2 fails `make -C build/bindings/go test`.

This is a pre-existing flaky test, **not caused by this PR**: `bindings/go/tests/worker_test.go` was last modified in 2024 (`bd1b1143`, Artemy Kovalyov), and the PR under test (#11944, branch `rb_tree`, commit 440231f) touches the UCS red-black tree, which is unrelated to the Go wakeup/efd path. All preceding Go tests (`TestUcpContext`, `TestUcpEpTag`, `TestUcpEpAm`, `TestUcpListener`, `TestUcpMmap`) passed.

**Implicated commit:** unknown for the failure trigger (flaky pre-existing test); the test code originates from `2bbf7cfe` (Peter Rudenko, "BINDINGS/GO: Ucp endpoint functionality") and was last touched by `bd1b1143` (Artemy Kovalyov). PR commit 440231f (`rb_tree`) is not implicated.

**File:** `bindings/go/tests/worker_test.go:59-64` (EINTR not retried; `t.Fatalf` in goroutine) and `bindings/go/tests/worker_test.go:74` (unbounded channel receive)

**Suggested fix:**
1. Retry the syscall on `EINTR` instead of failing:
```go
var nevents int
for {
    nevents, err = syscall.EpollWait(epfdLocal, events[:], -1)
    if err != syscall.EINTR {
        break
    }
}
if err != nil {
    t.Errorf("Failed to call epoll_wait %v", err)
    close(eventsChan)   // never leave the parent blocked
    return
}
eventsChan <- nevents
```
2. Replace all `t.Fatalf` calls inside the goroutine (lines 39, 44, 51, 61) with `t.Errorf` + `return`, ensuring `eventsChan` is always closed/written on every exit path — `t.Fatalf` is documented as unsafe outside the test goroutine.
3. Guard the receive at line 74 with a `select` + `time.After(...)` (same pattern as the `started` channel) so a future regression reports a real test failure in seconds instead of burning the 10-minute suite timeout and giving a useless "test timed out" panic.
4. Consider re-running the PR job; since the failure is unrelated to `rb_tree`, it should not block #11944.

**Related:** PR #11944 (build under test); no existing issue found tracking this `TestUcpWorkerEfd` EINTR flake — worth opening one.

`src/ucs/datastruct/interval_tree.c`

`ucs_interval_tree_cleanup()` frees every node but never clears `rb.root`, so afterwards `num_nodes == 0` (tree reports empty) while `rb.root` points at released mpool elements. A later `ucs_interval_tree_insert()` takes the slow path → `remove_overlapping()` → `find_overlap(tree->rb.root)` and walks freed memory. Not reachable today (all callers free/re-init right after), but now it is a one-liner.

pls also reset the tree root here; otherwise `rb.root` keeps pointing to freed nodes while `num_nodes` is 0, so a later insert into the same tree walks released memory.
```suggestion
    ucs_interval_tree_cleanup_recursive(tree, tree->rb.root);
    ucs_rbtree_init(&tree->rb);
```
