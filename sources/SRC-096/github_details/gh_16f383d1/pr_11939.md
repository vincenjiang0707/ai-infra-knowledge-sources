### svc-ucx · 2026-09-11

🤖 **CI Triage Agent** — `UCX PR (Tests roce on worker 3)` · commit `07af4610`

**TL;DR:** The only failure in the `roce on worker 3` gtest run is `rcx/test_ucp_fault_tolerance.probe_gated_recovery/6 (rc_x/AM)`, which fails on its own timing-sensitive `EXPECT_TRUE(probe_armed)` check — the aux `uct_ep_check` probe is armed *and* cleared inside one `short_progress_loop()`, so the test's poll can miss it. Fix the test to record probe arming durably (a counter in `ucp_ep_recovery_arg_t`/mocked `ep_check`) instead of sampling `probe[lane].comp.func`.

<details><summary>Full analysis</summary>

**Summary:** `make test` in the gtest stage exited with `Error 1`: 8725 passed, 1 failed — `rcx/test_ucp_fault_tolerance.probe_gated_recovery/6, where GetParam() = rc_x/AM`.

**Root cause:** The Azure log tail shows exactly one failing test and no crash/timeout (test ran to completion, teardown clean, no exit-143/hang; the largest inter-line gap is a normal ~9 s UD `no_rx_buffs` test). `probe_gated_recovery` is the only test whose body adds a check beyond the shared `test_am_with_injected_failure()` helper (which passes for the same `rc_x/AM` variant in `initiator_failure`/`target_failure`), so the failing check is `EXPECT_TRUE(probe_armed) << "RC p2p lane recovery completed without arming an aux probe"` at test/gtest/ucp/test_ucp_fault_tolerance.cc:941. That check is racy by construction:
- The test samples `ep->ext->recovery_arg->probe[lane].comp.func != NULL` once per `wait_for_cond` iteration, but the poll body calls `short_progress_loop()`, which performs ~100 worker progress iterations per sample.
- In `src/ucp/core/ucp_ep.c`, `ucp_ep_recovery_rebuild_p2p_lane()` arms the probe (`ucp_ep_recovery_arm_probe`, line 2072) and, on the success path, immediately calls `ucp_wireup_ep_connect_to_ep_v2()` followed by `ucp_ep_recovery_reset_probe(probe)` (line 2187), which sets `comp.func = NULL`; when recovery finishes, `ucp_ep_recovery_arg_free()` frees `recovery_arg` and NULLs it (line 2043).
So if the whole recovery (LANES_ADDR request/reply → arm probe → probe completion → connect → reset → clear failed lanes) completes inside one `short_progress_loop()`, `probe_armed` stays false while `ucp_ep_get_failed_lanes(ep) == 0` becomes true, and the test fails. All evidence for the probe is destroyed by design, so this is an intermittent test bug, not a product regression. PR #11939 (`UCS/TOPO: Build topology groups by NUMA node`) only touches `src/ucs/sys/topo` + `test/gtest/ucs/test_topo.cc`; it can perturb device/lane ordering and hence timing, but it does not touch the FT/recovery path.

Caveat: only the ~500-line tail of the job log was retrievable, so the verbatim assertion text for the failing test was truncated out; the identification above is from the test source plus the failure list.

**Implicated commit:** db208ee4 "UCP/FT: probe-gated lane recovery via aux uct_ep_check (#11563)", Evgeny Leksikov (added the test and the arm/reset probe logic). The PR under test (07af4610, Guy Ealey Morag, topo NUMA groups) is not implicated.

**File:** test/gtest/ucp/test_ucp_fault_tolerance.cc:941 (check), with src/ucp/core/ucp_ep.c:2187 and src/ucp/core/ucp_ep.c:2043 clearing the observed state.

**Suggested fix:** Make probe arming observable independently of polling timing, then assert on that:
1. Add a monotonic counter to `ucp_ep_recovery_arg_t` (or an EP/worker stats counter, e.g. `probes_armed`) incremented in `ucp_ep_recovery_arm_probe()`; since `recovery_arg` is freed on success, expose it via a worker counter (like `worker->counters.ep_failures`) that survives recovery, and have the test check `counters.recovery_probes > 0` after `wait_for_cond`.
2. Alternatively make the test deterministic the way `teardown_with_outstanding_probe` already does: install `mock_recovery_probe(sender().worker(), mock, recovery_probe_hold)` so the probe stays in flight and is guaranteed observable, then release it with `mock_invoke_completion(UCS_OK)`.
3. Minimal stop-gap: replace `short_progress_loop()` in the poll body with a single `progress()` step so the state is sampled every progress iteration, and downgrade the check to a `UCS_TEST_SKIP_R`/`ucs_diag` when recovery completed before any sample (to avoid re-introducing the same race).

**Related:** https://github.com/openucx/ucx/pull/11563 (introduced probe-gated recovery + this test), https://github.com/openucx/ucx/pull/11939 (PR under test — topo NUMA groups, unrelated to the failure)

</details>
