# [PR #11958] UCS/RCACHE: Adds capability for merging adjacent rcache regions

source: https://github.com/openucx/ucx/pull/11958
state: open | updated: 2026-09-24T03:20:10Z
labels: 

## 正文

## Why?
Reduce the number of memory keys in use for sequences of adjacent memory regions. When using too many memory keys, NIC can run out of resources and fail to register memory.
Fixes #6264 

## What?
When enabled, rcache regions of adjacent memory will be merged. Merges only occur when new region is the same size or larger than the existing region. This prevents continually reregistering the same memory region when adding many small regions in a row.

## How?
The rcache already has handling for memory regions that overlap with existing registrations. This is extend to handle regions that sit adjacent in memory when enabled. This is a little more difficult. Overlapping regions can be can safely be assumed to be of the same memory type and from the same allocation. This isn't true for adjacent memory regions. This is handled by checking to make sure that the regions have the same memory type, memory flags, and are part of the same allocation.

1. Remove the `/* Temp for testing merge code. */ UCS_RCACHE_FLAG_MERGE_ADJACENT` from `get_default_rcache_params()` (pass `0` for `flags`), and add a dedicated fixture for the new tests:

<details><summary>Full analysis</summary>

**Summary:** "Build ucx artifact" step of the WireCompat build on `althca` failed — `make` aborted with a `-Werror=maybe-uninitialized` compile error in `memory/rcache.c` (`ucs_rcache_create_region`/`ucs_rcache_check_adj_regions`).

**Root cause:** In `ucs_rcache_check_adj_regions()` the pointers `region_left` and `region_right` are declared without initializers and are only assigned inside `if (pgt_left != NULL)` / `if (pgt_right != NULL)`. They are later dereferenced via `ucs_list_add_tail(list, &region_left->tmp_list)` guarded only by `can_merge_left` / `can_merge_right`, which are set by an opaque callback `rcache->params.ops->can_merge(...)`. The compiler cannot prove that `can_merge_left != 0` implies `pgt_left != NULL`, so after inlining `ucs_list_add_tail` (hence the diagnostic pointing at `src/ucs/datastruct/list.h:60: elem->next = next;`) it emits `'region_left' may be used uninitialized`. Since UCX builds with `-Wall -Werror`, this is a hard build failure. The logic itself is safe at runtime (the flags can only be set when the pointer was assigned), so this is purely a compiler-provability issue — which explains why it only trips on this agent's (older) GCC while other legs may pass.

Exact log evidence:
```

src/ucs/datastruct/list.h:60:16: error: 'region_left' may be used uninitialized in this function [-Werror=maybe-uninitialized]
memory/rcache.c:841:26: note: 'region_left' was declared here
cc1: all warnings being treated as errors
make[3]: *** [memory/libucs_la-rcache.lo] Error 1
```

**Implicated commit:** `[REDACTED:Hex High Entropy String]` — William Gallagher, "UCS/RACHE: Check adjacent regions for memtype, flags and allocation" (introduced the `can_merge` callback gating; the helper itself was added in `[REDACTED:Hex High Entropy String]`, same author/series, PR #11958)

**File:** `src/ucs/memory/rcache.c:841` (declaration), failure surfaces at `src/ucs/memory/rcache.c:864` / `876` via `src/ucs/datastruct/list.h:60`

**Suggested fix:** Initialize the pointers and use them as the guard so the compiler can see the correlation, dropping the redundant `can_merge_*` ints:

```c
static void
ucs_rcache_check_adj_regions(ucs_rcache_t *rcache, void *arg,
                             ucs_pgt_addr_t start, ucs_pgt_addr_t end,
                             ucs_list_link_t *list)
{
    ucs_pgt_region_t *pgt_left, *pgt_right;
    ucs_rcache_region_t *region_left  = NULL;
    ucs_rcache_region_t *region_right = NULL;

    if (rcache->params.ops->can_merge == NULL) {
        return;
    }

    pgt_left  = ucs_pgtable_lookup(&rcache->pgtable, start - 1);
    pgt_right = ucs_pgtable_lookup(&rcache->pgtable, end);

    if (pgt_left != NULL) {
        region_left = ucs_derived_of(pgt_left, ucs_rcache_region_t);
        if (!rcache->params.ops->can_merge(arg, region_left)) {
            region_left = NULL;
        }
    }

    if (pgt_right != NULL) {
        region_right = ucs_derived_of(pgt_right, ucs_rcache_region_t);
        if (!rcache->params.ops->can_merge(arg, region_right)) {
            region_right = NULL;
        }
    }

    /* Fill in a gap between two existing registrations */
    if ((region_left != NULL) && (region_right != NULL)) {
        ucs_list_add_tail(list, &region_left->tmp_list);
        ucs_list_add_tail(list, &region_right->tmp_list);
        return;
    }

    if ((region_left != NULL) &&
        ucs_rcache_check_adj_size(start, end, region_left)) {
        ucs_list_add_tail(list, &region_left->tmp_list);
    }

    if ((region_right != NULL) &&
        ucs_rcache_check_adj_size(start, end, region_right)) {
        ucs_list_add_tail(list, &region_right->tmp_list);
    }
}
```
This keeps behavior identical and removes the warning on all GCC versions. (Do not silence it with a `#pragma` — the NULL-init version is cleaner and self-documenting.)

Alternatively, make `ucp_memh_rcache_get()` tolerate `mem_info == NULL` by falling back to defaults (e.g. `ucs_memory_info_set_host()`-style init), but the explicit fill is safer given the new `can_merge`/`merge` callbacks read `alloc_base`, `alloc_len` and `mem_flags`. Passing `0` for a pointer parameter should also be changed to `NULL` style everywhere to avoid this class of mistake.
