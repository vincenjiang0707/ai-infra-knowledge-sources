# [PR #11795] UCT/IB/MLX5/GDAKI: Try VMM Fabric Allocation.

## 正文

## What?
GDAKI now tries CUDA VMM fabric allocation and falls back to `cuMemAlloc` if it is not available.

## Why?
GDAKI previously always allocated with `cuMemAlloc`. VMM fabric allocations are created RDMA capability.
`UCS_TRY` keeps the old `cuMemAlloc` path on systems where CUDA VMM fabric allocation is not available.

### svc-nvidia-pr-review · 2026-08-26


`src/uct/ib/mlx5/gdaki/gdaki.c`

GDAKI now takes the context-wide sync-memops write-lock (potential deadlock). Before this PR, GDAKI set sync-memops per pointer via cuPointerSetAttribute(SYNC_MEMOPS), which takes no context lock. After the change, uct_rc_gdaki_alloc calls uct_cuda_mem_alloc(), which internally calls uct_cuda_copy_sync_memops() -> uct_cuda_copy_set_ctx_sync_memops(), which may call cuCtxSetFlags(CU_CTX_SYNC_MEMOPS) and take the context write-lock. The comment at that call site documents that this deadlocks a progress thread against an application thread inside cudaLaunchKernel(), and the hazard is only pre-empted for the context current at cuda_copy MD open. GDAKI allocations happen at ep/channel-pool init on the GDAKI primary context (a different context) and can run concurrently with application kernels, so this path can now hit the documented deadlock the old per-pointer call avoided. Blocker-level question: can this deadlock against an app thread in cudaLaunchKernel()?


`src/uct/cuda/cuda_copy/cuda_copy_md.c`

Return value of fabric release is now silently dropped. uct_cuda_copy_mem_free previously propagated the status from uct_cuda_copy_mem_release_fabric. Now uct_cuda_mem_free is void and uct_cuda_copy_mem_free always returns UCS_OK, so a real fabric-release failure (e.g. cuMemRelease/cuMemUnmap error) is no longer reported to the uct_md_mem_free caller. Minor behavior change; if intentional, fine, but worth confirming since VMM release errors used to be surfaced.


`src/uct/cuda/cuda_copy/cuda_copy_md.h`

Doc typo: '@param [in,out] granularity_p   Allocation granularity,if fabric VMM is used' is missing a space after the comma — should be 'granularity, if fabric VMM is used'.
