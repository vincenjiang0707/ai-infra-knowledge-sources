# [PR #11914] UCT/IB: Allow ODP with DDP for FW >= 49.1014

## 正文

## What?
Enable ODP/cuda-managed with FW >= 49.1014 as mentioned in report.

Has impact on wireup lanes: https://nvbugspro.nvidia.com/bug/6665318

## Why?
Enable broad cuda-managed support. Incidentally uniform memory support across interfaces help wireup lanes selection.

## How?
Confirmed cuda-managed zcopy using rc_mlx5.

Tested on 40.49.1014:
```
UCX_NET_DEVICES=mlx5_1 ./rfs/bin/ucx_perftest
UCX_PROTO_INFO=used UCX_NET_DEVICES=mlx5_0 ./rfs/bin/ucx_perftest \
    -m cuda-managed -t ucp_put_bw -n 10000 localhost
```

Tested on 40.51.0230 (soul):
```
UCX_REG_NONBLOCK_MEM_TYPES=host,cuda-managed UCX_IB_ODP_MEM_TYPES=host,cuda-managed \
    UCX_NET_DEVICES=mlx5_0 ./rfs/bin/ucx_perftest &
UCX_REG_NONBLOCK_MEM_TYPES=host,cuda-managed UCX_IB_ODP_MEM_TYPES=host,cuda-managed \
UCX_TLS=^cuda_ipc,cma \
UCX_NET_DEVICES=mlx5_0 UCX_PROTO_INFO=used rfs/bin/ucx_perftest \
    -t ucp_get/ucp_put_bw -m cuda-managed -n 1000  localhost -s 1024
```

This job is exactly the **roce** job (DDP is the RoCE feature being gated) on `swx-rain04`, and the symptom is silent non-delivery of UD traffic, consistent with a bad ODP mkey/DDP combination.

<details><summary>Full analysis</summary>

**Summary:** `roce on worker 0` job aborted: `shm_ib/test_ucp_sockaddr.onesided_disconnect_s2c/0 <shm,ib/tag>` failed to connect ("cannot connect to server"), teardown hung, gtest watchdog fired (`test_helpers.cc:57` → `strerror(ETIMEDOUT)` = "Connection timed out - abort testing"), and the Azure agent shut down mid‑hang.

**Root cause:** Hang, not slowness. Timeline from the log: 14:39:59 test starts and server listens on 1.1.1.1:51839 → **3‑minute silence** → 14:42:59 `[SKIP] (cannot connect to server)` (client wireup over the ib/RoCE lane never completed) → **3 more minutes** → 14:46:00 `ucp_test.cc:300 request ... did not complete on time` (worker flush stuck) → 14:57:59 watchdog kill. The only functional change on this branch is in the ODP/DDP gate: `uct_ib_mlx5_md_check_odp_common()` used to disable ODP whenever DDP (out‑of‑order data placement / `UCT_IB_MLX5_DP_ORDERING_OOO_ALL`, `ddp_support_dv`) is available; commits [REDACTED:Hex High Entropy String] ("Allow ODP with DDP for FW >= 48.1000") and [REDACTED:Hex High Entropy String] ("Move FW version check to mlx5") now allow ODP together with DDP when `uct_ib_mlx5_fw_ver_release_at_least(fw_ver, 49, 1014)`. Note the log has no `UCX_LOG_LEVEL=debug` output, so the ODP‑enabled state and the node's FW version are not directly visible — this is the strongest candidate given the diff, not a directly logged fact.
