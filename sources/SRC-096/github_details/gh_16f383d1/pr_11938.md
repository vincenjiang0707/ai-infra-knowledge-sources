# [PR #11938] GTEST/UCT/IB: Add gtest coverage for rc_verbs QPs without SRQ.

## 正文

## What?

Add gtest coverage for rc_verbs QPs without SRQ.

## Why?

The mode added by #11933 is not covered by any test, and its receive
path differs from the SRQ one in ways which are easy to break: receives are
posted and refilled per endpoint, QP destruction waits for the completions of
the posted receive WRs, and both the flow control window and the RX CQ
accounting derive from the receive WR count of a single QP.

## How?

Add the test_rc_no_srq fixture, which disables the SRQ through
UCX_RC_VERBS_SRQ_ENABLE and therefore runs wherever the SRQ can be disabled,
and assert that the interface really has no SRQ before every test. The tests
cover:

- receive posting and the refill of a completed receive WR, including active
  message flow
- QP destruction waiting for the receive WR completions
- the flow control window against the receive WR count of one QP
- flush cancel
- receive buffer pool exhaustion, with and without an endpoint moved to the
  error state
- endpoint creation with an exhausted pool, both the partial and the failing
  case
- the RX CQ capacity warning
- rejection of a receive WR count outside the supported range, and acceptance
  of the boundaries of that range

This PR depends on PR #11933.
