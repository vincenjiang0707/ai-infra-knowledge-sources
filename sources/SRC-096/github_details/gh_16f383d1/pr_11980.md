# [PR #11980] UCP/CORE: Add shared topology assignment policy

source: https://github.com/openucx/ucx/pull/11980
state: closed | updated: 2026-09-23T13:38:52Z

## 正文

## What?
* Add `UCX_GPU_NIC_ASSIGNMENT_MODE` to control how NICs are assigned to GPUs: `auto` (default), `off`, `flip`, `round_robin` and `shared`.
* Add the `shared` mode, which assigns all NICs of a topology group to every GPU in that group.
* `auto` uses `flip` on Vera and disables the assignment on other CPUs.
* Replace the internal assignment policy enum with the mode enum, so that `auto` and `off` are handled once, in `ucp_context_gpu_nic_assignment_init()`.
* Implement all modes in a single `ucp_gpu_nic_assignment_add_group()`.
* Add tests for the `shared` mode.

**Summary:** Azure job "coverity devel on coverity_rh7" (build 137036) failed at the end of `cov-analyze`: `##[error]Coverity found 2 issues:` — both `DIVIDE_BY_ZERO` in `test/gtest/ucp/test_ucp_gpu_nic_assignment.cc:426` and `:430`. **Implicated commit:** [REDACTED:Hex High Entropy String] "TEST/UCP: Add check_assignment template" (Guy Ealey Morag) exposed the path; the divisions and the zero-argument tests come from 3f1fa079 "UCP/CORE: Add shared topology assignment policy" (Guy Ealey Morag).

**File:** `test/gtest/ucp/test_ucp_gpu_nic_assignment.cc:282` and `:287-288` (triggered from `:426` and `:430`)

**Suggested fix:** Make the zero cases explicit in `check_assignment_shared_inner()` so the divisors are guarded on the same path Coverity analyzes, e.g.:

```c
    check_gpu_device_aliases(config);

    /* No NICs: every GPU must map to an empty bitmap, no division needed */
    if (config.num_nics() == 0) {
        for (size_t gpu_idx = 0; gpu_idx < config.num_gpus(); ++gpu_idx) {
            const auto *bitmap = ucp_gpu_nic_assignment_lookup(
                    &m_assignment, gpu_sys_dev(config, gpu_idx, 0));
            ASSERT_NE(nullptr, bitmap);
            EXPECT_EQ(0, UCS_STATIC_BITMAP_POPCOUNT(*bitmap));
        }
        return;
    }

    /* Reached only when both per-group counts are non-zero */
    ASSERT_NE(0ul, config.num_gpus_per_group);
    ASSERT_NE(0ul, config.num_nics_per_group);
```

placed right after the existing `config.num_gpus() == 0` early return (line 271-275) and before the loop at line 279. The `ASSERT_NE` pair alone is usually enough for Coverity to drop both findings, and it also documents the precondition. Alternative (less preferred): route the zero-count cases through a dedicated checker instead of `check_assignment_shared`, or add a Coverity suppression comment — but the guards are cheap and keep the assertion coverage the tests intend.

<details><summary>Full analysis</summary>

**Summary:** Coverity static analysis (`cov-analyze` on branch `devel`) reported 2 issues and the pipeline step exited non-zero (`##[error]Coverity found 2 issues`), both `DIVIDE_BY_ZERO` in `test/gtest/ucp/test_ucp_gpu_nic_assignment.cc` at lines 473 and 477.

**Root cause:** The build/compile and link succeeded ("745 C/C++ compilation units (100%) successfully", "cov-build utility completed successfully"); the failure is purely the analysis gate. Coverity traces:
- `shared_no_nics` → `check_assignment_shared(2, 3, 0)` (line 473) → `num_nics_per_group = 0` → divisor in `nic_idx / config.num_nics_per_group` (line 304).
- `shared_no_gpus` → `check_assignment_shared(2, 0, 3)` (line 477) → `num_gpus_per_group = 0` → divisor in `gpu_idx / config.num_gpus_per_group` (line 299).

At runtime these paths are unreachable: `num_gpus() == 0` returns early at line 271/274 and `num_nics() == 0` returns early at line 281/291, and lines 279/294 hold `ASSERT_NE(..., 0)`. But the Coverity trace explicitly shows it does not honor the gtest assertion macros as exits — "path: Condition `gtest_ar.operator bool()`, taking true branch / Falling through to end of if statement" — and it also fails to correlate `num_gpus() == 0` (i.e. `num_groups * num_gpus_per_group`) with `num_gpus_per_group == 0`. So it is a false positive, newly exposed because the checks are now reached through a template + lambda indirection (`check_assignment` → `operator()` → `check_assignment_shared_inner`), which gives Coverity a concrete interprocedural path with the literal `0` argument.

**Implicated commit:** `[REDACTED:Hex High Entropy String]` "TEST/UCP: Add check_assignment template" (Guy Ealey Morag), on top of `3f1fa079` "UCP/CORE: Add shared topology assignment policy"; build HEAD is `e66bc853` (same author/PR #11980).

**File:** `test/gtest/ucp/test_ucp_gpu_nic_assignment.cc:279` and `:294` (defects reported at `:473` and `:477`; divisions at `:299` and `:304`)

**Suggested fix:** Make the zero-divisor guards visible to Coverity by turning the gtest assertions into real control flow, e.g.:

```c++
    // was: ASSERT_NE(config.num_gpus_per_group, 0);
    if (config.num_gpus_per_group == 0) {
        ADD_FAILURE() << "num_gpus_per_group must be non-zero";
        return;
    }
    ...
    // was: ASSERT_NE(config.num_nics_per_group, 0);
    if (config.num_nics_per_group == 0) {
        ADD_FAILURE() << "num_nics_per_group must be non-zero";
        return;
    }
```

Do this *before* the loop at line 296 for `num_gpus_per_group` and before line 303 for `num_nics_per_group`. Alternatively, hoist the group indices out of the loops into locals computed only after an explicit non-zero check, or have `shared_no_nics`/`shared_no_gpus` call a dedicated `check_assignment_shared_empty()` helper that never contains a division. Avoid suppressing with a Coverity annotation unless the maintainers prefer that, since an explicit guard is cheap in test code.

**Related:** PR #11980 (`shared-assign-policy`); prior work in `fd1eb5e0` (#11868, "UCP/CORE: Implement GPU to NIC assignment logic"). No existing issue found for this specific Coverity defect.
