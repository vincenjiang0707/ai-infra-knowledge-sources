# [Issue #11012] Performance regression with UCX 1.19 on a single node with UCX_PROTO_ENABLE=n

source: https://github.com/openucx/ucx/issues/11012
state: open | updated: 2025-12-12T08:06:30Z
labels: Bug

## 正文

### Describe the bug
When upgrading from UCX 1.18 to UCX 1.19, we see a performance regression for single-node runs for the [AMD HPL-MxP](https://www.amd.com/en/developer/zen-software-studio/applications/pre-built-applications/zen-hpl-mxp.html) benchmark on our HPC system [Viper](https://docs.mpcdf.mpg.de/doc/computing/viper-user-guide.html). We use `UCX_PROTO_ENABLE=n`. A similar regression is seen for single-node runs of the mbw benchmark of the OSU microbenchmark suite for large message sizes. Other multi-node application runs are fine with this configuration.

The performance of the HPL-MxP benchmark is:
- UCX 1.18: 22216.5 GFlops
- UCX 1.19: 16830 GFlops

The bandwidth for the mbw-mr test at a message size of 1MB is:
- UCX 1.18: about 1 TB/s
- UCX 1.19: about 50 GB/s

With `UCX_PROTO_ENABLE=y`, we see the same performance as with 1.18. With the new protocol selection, however, we see performance issues with multi-node applications (I'll open a separate issue in the coming days), so we don't want to use that. Is there maybe an environment variable that allows us to get back the behavior from 1.18?

### Steps to Reproduce
- HPL-MxP
  - download the binary from [the AMD web page](https://www.amd.com/en/developer/zen-software-studio/applications/pre-built-applications/zen-hpl-mxp.html)
  - start with latest OpenMPI (5.0.8) and UCX 1.18 or 1.19
  - compare value of "overall performance"
- OSU microbenchmarks mbw
  - get OSU microbenchmarks from https://mvapich.cse.ohio-state.edu/benchmarks/
  - run  osu_mbw_mr
  - compare bandwidth for large message sizes
- Configure line: (same for both versions except the prefix)
- `# Configured with: --prefix=/mpcdf/soft/RHEL_9/packages/znver4/UCX/gcc_14-14.1.0/1.18.0 --enable-optimizations --enable-mt --enable-cma --enable-compiler-opt=2 --disable-tuning --enable-builtin-memcpy --with-cache-line-size=64 --without-go --disable-logging --disable-debug --disable-assertions --disable-params-check --with-rc --with-dc --with-ud --with-mlx5-dv --with-verbs --with-xpmem --with-dm --with-devx --with-avx --with-bfd --with-rdmacm --without-xpmem`
- environment variables:
```
UCX_PROTO_ENABLE=n
UCX_UNIFIED_MODE=y
UCX_TLS=^ud,tcp
```
- hardware: AMD Epyc Genoa 9554 + NDR (see [documentation](https://docs.mpcdf.mpg.de/doc/computing/viper-user-guide.html#hardware-configuration))
