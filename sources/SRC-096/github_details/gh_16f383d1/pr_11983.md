# [PR #11983] UCP/DEVICE: Retry remote mem list create on wireup lane

source: https://github.com/openucx/ucx/pull/11983
state: closed | updated: 2026-09-23T14:51:08Z
labels: 

## 正文

## What?
Return `UCS_ERR_NOT_CONNECTED` instead of `UCS_ERR_NO_RESOURCE` from `ucp_device_remote_mem_list_create()` when a device lane is still a wireup proxy.

## Why?
Real life issue also seen as intermittent CI failure:

```
[ RUN      ] rc_gda/test_ucp_device.get_remote_mem_list_length/1 <rc,rc_gda,cuda_copy,rocm_copy/cuda>
ucp_device.c:553  UCX  ERROR failed to get device_ep for lane=2
ucp_device.c:818  UCX  ERROR failed to create handle: No resources are available to initiate the operation
test/gtest/ucp/test_ucp_device.cc:219: Failure
Error: No resources are available to initiate the operation
[  FAILED  ] rc_gda/test_ucp_device.get_remote_mem_list_length/1
```

`ucp_wireup_remote_connected()` sets `UCP_EP_FLAG_REMOTE_CONNECTED` but only schedules `ucp_wireup_eps_progress()` to install the real transport endpoints. Until it runs, the lane is a `ucp_wireup_ep_t` whose stub iface returns `UCS_ERR_NO_RESOURCE`, so callers retrying on `UCS_ERR_NOT_CONNECTED` get a hard error. `ucp_device_remote_mem_list_params_check()` does not cover this window.

## How?
Test `ucp_wireup_ep_test()` on the lane in `ucp_device_remote_mem_list_element_pack()` and return `UCS_ERR_NOT_CONNECTED`, which is already retryable and not error-logged. The existing `err:` path frees elements packed so far, so retries do not leak. Only the device lane is checked, since the CM lane keeps its wireup endpoint permanently.

## Verification
Built with `--with-gda`; `rc_gda/test_ucp_device.*` and `cuda_ipc/test_ucp_device.*` pass (20 tests).

The race does not reproduce by looping (25 runs passed): the scheduled callback usually runs within the same `ucp_worker_progress()` call. Temporarily patching `ucp_wireup_eps_progress()` to defer itself once reproduced the CI log exactly and confirmed `REMOTE_CONNECTED` was already set; with the fix the errors disappear. That instrumentation is not part of this PR.
