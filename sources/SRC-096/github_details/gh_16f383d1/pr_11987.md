## 正文

Add Level Zero IPC transport for intra-node GPU-to-GPU communication:

- IPC component, iface, endpoint, and memory domain
- IPC handle caching with page table for efficient reuse
- Async copy via immediate command lists with event pool
- eventfd-based async notification support
- Multi-command-list round-robin for parallel progress
- Stale mapping invalidation and orphan list management
- Process creation time + allocation ID for cache correctness
- CI lane for ZE build validation
- GTest coverage for base, copy MD, IPC cache, IPC MD, and RMA

blocker: this PR adds ~2.8k lines (new `ze_ipc` transport + 5 new gtest files + CI lane), far above the 500-added-line limit in `REVIEW.md`; pls split into separate PRs, e.g. (1) `ze_base` ordinal helpers, (2) `ze_ipc` md + cache, (3) iface + ep, (4) gtests, (5) CI lane.
Also, the branch looks stale: the `ubuntu2404_ze` CI lane, the ZE builder container and the `if HAVE_ZE` gtest block already exist on the base branch, and several prototypes are added twice. Pls rebase and drop the unrelated changes (`AUTHORS` entries, `ze_copy_ep.c`/`ze_copy_iface.c` logging).


Coverage gaps worth noting:
- The new gtests all skip without a Level Zero device, and the new `ubuntu2404_ze` lane is a no-GPU build lane, so none of the `ze_ipc` data-path code (map/unmap cache, event pool, progress, flush) is covered by CI.
- No test covers the cross-process path (`pidfd_getfd` duplication), which is the only path the transport is actually built for; the cache tests substitute synthetic open/close ops.
