### svc-nvidia-pr-review · 2026-09-03


PR scope/size (blocker): REVIEW.md enforces a hard limit — PRs over 500 added lines are not allowed, and feature PRs must not bundle unrelated changes. This PR combines at least six independent, separable changes: (1) netlink relaxed vs. best route matching; (2) CUDA Blackwell RTX generation + bandwidth; (3) CUDA IPC close_handles on driver-deinit shutdown; (4) IB AH_CACHE_TTL config + uct_ib_iface_release_ah wiring across dc/ud/rc/srd; (5) IB multiplane XDR bandwidth / num-paths; (6) ROCm IPC per-peer cache refactor to khash. Each has its own risk profile and test needs; please split into separate PRs so each can be reviewed and reverted independently.


Note (no blocker): The SRD path switch from uct_ib_iface_create_ah to uct_ib_device_create_ah_cached correctly forces caching (SRD keeps the AH for the ep lifetime and never destroys it), so it must bypass AH_CACHE_TTL=0. This looks intentional and correct.


Note (no blocker): UCT_CUDA_BASE_GEN_BRTX = 12 skipping 11 is correct — the values are CUDA compute-capability majors and Blackwell RTX is CC 12.


Note (no blocker): Test coverage for the AH cache TTL (test_dc.cc, test_ib.cc) and multiplane bandwidth (test_uct_ib_perf) is present and focused, which is good — but it reinforces that these are distinct features that belong in their own PRs.


Note: I could not fully assess the netlink relaxed-route change and the multiplane bandwidth ratio math without hardware; those paths rely on the added gtests and CI.
