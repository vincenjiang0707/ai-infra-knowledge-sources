## 正文

## What?
Implement GPU to NIC assignment logic as part of the effort to allow more tailored assignments on certain types of hardware (e.g. Vera Rubin).
This implementation assumed exclusive assignments for now (only 1 GPU assigned to each NIC), and only `FLIP` and `ROUND_ROBIN` policies.

## How?
The groups data structure is built outside of this module, and each group represents equally distant GPUs and NICs.
The assignment logic pairs every NIC with a GPU to spread out the bandwidth within the group.
The devices are assumed to be sorted by BDF within the arrays.

<details><summary>Full analysis</summary>

**Summary:** Compilation of `core/ucp_gpu_nic_assignment.c` with `nvc` (HPC SDK 21.2) aborted with `error #186: pointless comparison of unsigned integer with zero`, failing `make` (`make[2]: *** [core/libucp_la-ucp_gpu_nic_assignment.lo] Error 1`).

**Root cause:** `ucp_gpu_nic_policy_t` (src/ucp/core/ucp_gpu_nic_assignment.h:36-40) contains no negative enumerators, so `nvc` gives it an unsigned underlying type. The assertion at line 145 of `ucp_gpu_nic_assignment.c`:

```c
ucs_assertv((policy >= 0) && (policy < UCP_GPU_NIC_POLICY_LAST),
            "invalid gpu-nic assignment policy %d", policy);
```

makes `policy >= 0` tautologically true. `nvc` diagnoses this as #186; the build uses `-Wall -Werror --display_error_number` and the suppression list in `contrib/configure-*` (`--diag_suppress 1 68 111 167 181 188 381 1215 1626 1901 1902`) does not include 186, so it becomes a hard error. GCC/Clang jobs pass because `-Wtype-limits`/`-Wtautological-compare` isn't fatal there, so this is compiler-specific and only shows up in the ICC/PGI pipeline.

**Implicated commit:** `218a96ad` — "UCP/CORE: Add GPU to NIC assignment logic based on groups", Guy Ealey Morag (file introduced; `[REDACTED:Hex High Entropy String]` by the same author is the follow-up on this file)

**File:** src/ucp/core/ucp_gpu_nic_assignment.c:145

**Suggested fix:** Remove the redundant lower-bound comparison, since the enum type cannot hold a negative value:

```c
ucs_assertv(policy < UCP_GPU_NIC_POLICY_LAST,
            "invalid gpu-nic assignment policy %d", policy);
```

If a defensive lower bound is desired for callers passing raw ints, cast explicitly instead (e.g. `ucs_assertv((unsigned)policy < UCP_GPU_NIC_POLICY_LAST, ...)`), which is portable across gcc/clang/icc/nvc. Also consider changing the `%d` format specifier accordingly. Prefer this over adding `--diag_suppress 186` to `contrib/configure-*`, which would mask genuine tautological comparisons elsewhere.

**Related:** PR #11868 (branch `topo-gpu-nic-assign`); no pre-existing issue found for error #186 in this repo.
