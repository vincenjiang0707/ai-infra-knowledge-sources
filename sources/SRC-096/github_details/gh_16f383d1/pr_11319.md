# [PR #11319] UCT/CUDA/COPY: Qualify cuda_copy for RNDV with peer-failure EH

source: https://github.com/openucx/ucx/pull/11319
state: open | updated: 2026-09-17T01:38:29Z
labels: 

## 正文

## What?

Allow same-UUID endpoints using `UCP_ERR_HANDLING_MODE_PEER` to select transports that do not support peer-failure handling or RMA invalidation, such as `cuda_copy`.

Changes:

1. `ucp_ep_err_mode_init_flags()` omits `UCP_EP_INIT_ERR_MODE_PEER_FAILURE` for same-UUID endpoints in `PEER`
   mode.
2. Wireup applies these effective flags only for lane selection, while the endpoint configuration retains `UCP_ERR_HANDLING_MODE_PEER`.
3. Recovery auxiliary transport selection uses the same effective flags.
4. Same-process endpoint configurations skip RMA-key invalidation, since their RMA-BW lanes may not support `UCT_MD_FLAG_INVALIDATE_RMA`.
5. Tests cover same-process peer-error wireup and optional RMA invalidation.

`UCP_ERR_HANDLING_MODE_FAILOVER` intentionally retains its full peer-failure requirements.

## Why?

With peer error handling and rendezvous enabled, wireup normally requires `UCT_IFACE_FLAG_ERRHANDLE_PEER_FAILURE` and `UCT_MD_FLAG_INVALIDATE_RMA`. `cuda_copy` does not provide these capabilities, so it cannot be selected as an RMA-BW lane even when the remote address has the same UUID as the local worker.

For same-UUID endpoints, there is no independent remote process whose failure requires cross-process RMA-key invalidation. Relaxing these transport-selection requirements allows the local copy path to be selected while preserving the
endpoint's requested `PEER` error-handling mode.

`FAILOVER` is not relaxed: its PSN-based recovery protocols require the full peer-failure behavior.

Cross-UUID endpoints are unchanged and retain the existing peer-failure and RMA-invalidation requirements.

Closes #11318
