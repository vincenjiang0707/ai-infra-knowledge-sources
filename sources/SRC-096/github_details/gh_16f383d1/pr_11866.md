🤖 **CI Triage Agent** — `UCX PR (Tests BlueField on worker 1)` · commit `174dcfdf`

**TL;DR:** The new gtest `rc_mlx5/test_rc_purge_outstanding.get_zcopy` fails because it issues a 64-byte `uct_ep_get_zcopy()`, which RC/mlx5 rejects with `UCS_ERR_INVALID_PARAM` (minimum GET-zcopy length is `max_inl_cqe[TX]+1` = 65, since RC defaults `IB_TX_INLINE_RESP=64`); fix the test to use `cap.get.min_zcopy` (e.g. ≥65) instead of a hard-coded 64.

<details><summary>Full analysis</summary>

**Summary:** Azure job "BlueField on worker 1" failed in `make test` (gtest): `[ FAILED ] rc_mlx5/test_rc_purge_outstanding.get_zcopy/0, where GetParam() = rc_mlx5/mlx5_0:1` → `make: *** [Makefile:4713: test] Error 1` → `Bash exited with code '2'`. 8667/8668 tests passed; only this newly added test failed.

**Root cause:** The test added by this PR calls `test_get(UCT_EP_OP_GET_ZCOPY, 64)` and asserts `ASSERT_EQ(UCS_INPROGRESS, uct_ep_get_zcopy(...))`. For RC/mlx5, `uct_rc_mlx5_base_ep_get_zcopy()` enforces a *minimum* length:
- `src/uct/ib/mlx5/rc/rc_mlx5_ep.c:385` — `UCT_CHECK_LENGTH(total_length, iface->super.super.config.max_inl_cqe[UCT_IB_DIR_TX] + 1, iface->super.config.max_get_zcopy, "get_zcopy")`
- `src/uct/ib/rc/base/rc_iface.c:31` — RC overrides the IB defaults with `TX_INLINE_RESP=64`, so `max_inl_cqe[UCT_IB_DIR_TX]` is 64 and, per `src/uct/ib/rc/base/rc_iface.c:234`, `cap.get.min_zcopy = 65` (reads ≤64B are scattered inline into the CQE and therefore cannot be zcopy).

So a 64-byte `get_zcopy` returns `UCS_ERR_INVALID_PARAM` (plus an unexpected `ucs_error` from `UCT_CHECK_LENGTH`, which gtest also flags), and the `ASSERT_EQ` aborts the test. The sibling `get_bcopy` case (8 bytes) has no such minimum, which is why only the zcopy variant failed. The WQE-parsing code itself (`uct_rc_mlx5_op_info_fill_get_zcopy`) is never reached. Note `test_gga_get_zcopy_purge` can use 64 bytes because gga_mlx5 uses the MMO path with no inline-CQE minimum — likely where the constant was copied from.

**Implicated commit:** `8e578f4d` "GTEST/UCT/IB: test get" (Zihao Zhao), later refactored in `eed21d92`; branch `failover_uct_rcx_get`, HEAD `174dcfdf`.

**File:** `test/gtest/uct/ib/test_rc.cc:1735` (and the assert it triggers at `test/gtest/uct/ib/test_rc.cc:1707`)

**Suggested fix:** Derive the zcopy length from the interface attributes instead of hard-coding it, e.g.:

```c
UCS_TEST_SKIP_COND_P(test_rc_purge_outstanding, get_zcopy,
                     !check_caps(UCT_IFACE_FLAG_GET_ZCOPY))
{
    test_get(UCT_EP_OP_GET_ZCOPY,
             ucs_max(64ul, m_e1->iface_attr().cap.get.min_zcopy));
}
```
(any length > `max_inl_cqe[UCT_IB_DIR_TX]`, e.g. 4096, works; alternatively add `"IB_TX_INLINE_RESP=0"` to the test's config). Optionally add an `EXPECT_GE(length, iface_attr().cap.get.min_zcopy)` guard in `test_get()` so the constraint is explicit.

**Related:** PR #11866 (this change); sibling PRs #11836 (put parser) and #11844 (flush parser) use the same helper and may need the same length guard.

</details>
