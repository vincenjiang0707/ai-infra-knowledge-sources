# [PR #11970] UCS/DATASTRUCT: Add interval map

## 正文

## What?
Add ucs_interval_map_t, a map of half-open intervals to caller-owned objects. Unlike ucs_interval_tree_t, which coalesces, it keeps overlapping intervals distinct: inserting [0,4) and [2,6) yields two entries, both findable.

It is a ucs_rbtree_t ordered by interval start and augmented with each subtree's maximum end, so finding an interval that contains a given range costs O(log n). Nodes are intrusive and caller-allocated, and removal never relocates one, so removal by a held pointer needs no search.

## Why?
Usable as a cache for regions of vmm backed by multiple allocations in a future cuda_ipc change.

## How?
Reusing the rbtree struct, adding an augment function pointer to maintain the max end in the subtree.

### tomerg-nvidia · 2026-09-21

> > Usable as a cache for regions of vmm backed by multiple allocations in a future cuda_ipc change.
> 
> What is the reason the existing interval tree is not suitable for VMM case?

@yosefe The purposed use is for the multi-allocation vmm cuda_ipc cache.
interval_tree is not suitable for two reasons:
1. It merges intervals. With the multi-allocation vmm case we can have two intervals mapped to overlapping remote addresses, but because they are imported to two different local addresses they can't be merged.
2. It doesn't map to a value. This map allows us to map remote address to a local address with the mapped region.

Also note the ucs_pgtable used in the existing single allocation cache can't be used because it rejects overlapping regions.
