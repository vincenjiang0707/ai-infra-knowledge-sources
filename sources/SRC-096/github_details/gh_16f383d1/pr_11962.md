## What?
Fully initialize `nvmlFieldValue_t` objects in the CUDA-IPC NVLink query and its focused NVML test.

## Why?
UCX set `fieldId` but left `scopeId` and other stack bytes indeterminate before calling `nvmlDeviceGetFieldValues`. NVML 580.126.20 branched on those input bytes, producing the reported Valgrind conditional-jump context.

## How?
Initialize the production object with `{0}` and the test object with `{}`. A fresh build at commit `fe133e476b8c19e25590704c488abe258fd96b89` succeeded, both focused tests passed, and the reported NVML signature was absent from all 6 fixed Memcheck logs. The Memcheck processes still returned 99 because of unrelated GDR ioctl errors; no globally clean Valgrind result is claimed.
