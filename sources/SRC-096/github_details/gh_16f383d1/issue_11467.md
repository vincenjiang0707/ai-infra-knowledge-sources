# [Issue #11467] SIGSEGV in ucs_rcache_region_invalidate when rcache is unavailable during RNDV abort

source: https://github.com/openucx/ucx/issues/11467
state: closed | updated: 2026-05-28T08:16:21Z
labels: Bug

## 正文

## Summary

UCX can crash with SIGSEGV in `ucs_rcache_region_invalidate()` when the UCP registration cache is unavailable and a rendezvous request is aborted during peer error handling.

This looks like a UCX bug: the RNDV abort path assumes `context->rcache != NULL`, but `ucp_init()` can successfully continue with `context->rcache == NULL` when rcache initialization fails and `RCACHE_ENABLE=try` is used.

## Environment

- UCX version: `1.18.0`
- Architecture: `x86_64`
- Relevant UCX configuration:

```text
UCX_MEM_EVENTS=n
UCX_MEM_MALLOC_HOOKS=n
UCX_MEM_MALLOC_RELOC=n
UCX_MEM_MMAP_HOOK_MODE=none
UCX_RNDV_THRESH=32k
```

With the memory event / hook settings above, rcache initialization fails. Since UCP's default `RCACHE_ENABLE` is `try`, initialization is tolerated and the UCP context continues with `context->rcache == NULL`.

## Trigger

The issue is intermittent and was observed when a network interface flap caused a connection reset while there were in-flight RNDV requests.

A minimal trigger pattern should be:

1. Start a UCP application with the UCX config above so `context->rcache == NULL`.
2. Use peer error handling.
3. Send messages large enough to use RNDV.
4. Trigger a network failure / connection reset while an RNDV request is in flight.
5. Progress the worker so the endpoint discard / request purge path runs.

## Source-level analysis

`ucp_request_memh_invalidate()` only filters out NULL memh and user memh. It does not check whether `context->rcache` is available:

```c
/* src/ucp/core/ucp_request.c */
if ((*memh_p == NULL) || ucp_memh_is_user_memh(*memh_p)) {
    return 0;
}

ucp_memh_invalidate(context, *memh_p, ucp_request_mem_invalidate_completion,
                    req, invalidate_map);
```

`ucp_memh_invalidate()` then unconditionally uses `context->rcache`:

```c
/* src/ucp/core/ucp_mm.c */
ucs_rcache_region_invalidate(context->rcache, &memh->super, cb, arg);
```

`ucs_rcache_region_invalidate()` immediately dereferences the rcache pointer:

```c
/* src/ucs/memory/rcache.c */
ucs_spin_lock(&rcache->lock);
```

So when rcache initialization was tolerated and `context->rcache == NULL`, an RNDV abort caused by `UCS_ERR_CONNECTION_RESET` can crash in the invalidate path.

## Expected behavior

UCX should not crash when rcache initialization is unavailable but tolerated. The RNDV abort path should handle `context->rcache == NULL` and clean up the request using the non-rcache deregistration path.

## Suggested fix direction

One possible fix is to guard `context->rcache == NULL` in `ucp_request_memh_invalidate()`:

```c
if ((context->rcache == NULL) ||
    (*memh_p == NULL) ||
    ucp_memh_is_user_memh(*memh_p)) {
    return 0;
}
```

Returning `0` lets `ucp_proto_rndv_rts_abort()` continue through the existing reset/completion path, where zcopy cleanup can deregister the memory without using rcache.

It may also be worth adding a defensive assertion or guard in `ucp_memh_invalidate()` to prevent future callers from passing a NULL rcache.
