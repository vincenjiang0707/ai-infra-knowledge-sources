# [PR #11682] UCT/MM: Determine ep flush completion without peer memory access

source: https://github.com/openucx/ucx/pull/11682
state: open | updated: 2026-09-23T13:55:06Z
labels: 

## 正文

## What
Change `uct_mm_ep_flush` to determine completion from local arbiter state
(`ucs_arbiter_group_is_scheduled`) rather than reading the peer's FIFO control
structure. Add four regression gtests that mprotect the peer fifo_ctl page
and verify no page fault occurs on any flush or purge path.

## Why
Shared-memory sends in the MM transport write directly into the peer's receive
FIFO inside `uct_mm_ep_am_common_send` and complete synchronously before the
call returns. There is no outstanding send work after that point; the only
locally pending operations are those queued on the endpoint's pending arbiter
group. Remote FIFO occupancy is therefore a resource-availability signal, not
a completion signal, and flush should not depend on it.

The previous `uct_mm_ep_flush` read `fifo_ctl->head` and `fifo_ctl->tail`
from the peer's shared memory page regardless. Whether that read can fault
depends on the mm mapper's remote-mapping lifetime, which differs by backend:
POSIX and SysV segments are kernel-refcounted and remain valid for an
attached consumer even after the owning peer process exits, so this read is
safe for those mappers. XPMEM does not have that property: an XPMEM
attachment's validity is tied to the exporting process's address space and is
invalidated once that process tears down. This was root-caused as the SIGBUS
seen at `MPI_Finalize` in field runs of the ICON climate model.

Reproducer (no fault injection, forces mm EP wire-up + peer-segment attach to
every rank via an all-to-all one-sided window, frees it, then finalizes
immediately with no barrier, so a fast rank can be inside `uct_mm_ep_flush`
while a peer has already exited):

```c
#include <mpi.h>
#include <stdlib.h>
#include <string.h>

int main(int argc, char **argv)
{
    int rank, size, i, peer;
    const size_t win_bytes = 4096;

    MPI_Init(&argc, &argv);
    MPI_Comm_rank(MPI_COMM_WORLD, &rank);
    MPI_Comm_size(MPI_COMM_WORLD, &size);

    for (int iter = 0; iter < 4; iter++) {
        void *base;
        MPI_Win win;
        char *sendbuf = malloc(win_bytes);
        char *recvbuf = malloc(win_bytes);
        memset(sendbuf, rank + iter, win_bytes);

        MPI_Win_allocate(win_bytes, 1, MPI_INFO_NULL, MPI_COMM_WORLD, &base, &win);
        MPI_Win_lock_all(0, win);
        for (i = 0; i < size; i++) {
            peer = (rank + 1 + i) % size;
            if (peer == rank) continue;
            MPI_Put(sendbuf, win_bytes, MPI_BYTE, peer, 0, win_bytes, MPI_BYTE, win);
            MPI_Win_flush(peer, win);
            MPI_Get(recvbuf, win_bytes, MPI_BYTE, peer, 0, win_bytes, MPI_BYTE, win);
            MPI_Win_flush(peer, win);
        }
        MPI_Win_unlock_all(win);
        MPI_Win_free(&win);
        free(sendbuf);
        free(recvbuf);
    }

    /* No barrier here on purpose: maximizes the teardown interleave. */
    MPI_Finalize();
    return 0;
}
```

Run forced to each mapper, oversubscribed, looped many times (a single run is
not guaranteed to hit the race):
```sh
UCX_TLS=xpmem,self mpirun -np 24 --oversubscribe \
  --mca opal_common_ucx_tls any --mca opal_common_ucx_devices any \
  --mca pml ucx --mca osc ucx ./repro
```

Result on this branch's base (before the fix), looped 200x:
- `xpmem,self`: 200/200 SIGBUS in `uct_mm_ep_flush`
- `posix,self`, `sysv,self`: 0/200

With the fix applied, `xpmem,self` is clean under the same loop.

There is a secondary correctness issue: when a flush request is dispatched
from the endpoint's own arbiter group, the group is transiently non-empty but
not scheduled. The previous code treated non-empty as "outstanding work" and
rescheduled the flush, deadlocking. Checking `is_scheduled` (not `is_empty`)
handles both the normal flush path and this in-flight case correctly. This
part of the fix is independent of mapper: it corrects a real state-modeling
bug in the common mm endpoint code.

## How
Replace the `uct_mm_ep_update_cached_tail` block with a single
`ucs_arbiter_group_is_scheduled` check. The four gtests cover: (1) empty
arbiter returns UCS_OK without touching the protected page; (2) non-empty
arbiter returns UCS_ERR_NO_RESOURCE without touching the page; (3) pending
purge does not access the page; (4) a flush queued as a pending op eventually
completes and does not deadlock. These tests model "peer memory
inaccessible" generically (via mprotect) rather than reproducing the XPMEM
teardown mechanism specifically, so they protect the common-code correctness
property across all mm mappers, not just the one that can fault.

the right order in MPI_Finalize should be:
1. all endpoints doing communication
2. ucp_ep_flush - optional
3. ucp_ep_destroy
4. modex_barrier
5. ucp_worker_destroy

In particular, all communication operations (including flush) and ep_destroy must be done before modex barrier at finalize. and worker_destroy is after the modex.
this guarantees no access to released shared FIFO .
