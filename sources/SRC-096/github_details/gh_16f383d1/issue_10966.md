# [Issue #10966] AWS EFA GPUDirect RDMA validation

source: https://github.com/openucx/ucx/issues/10966
state: open | updated: 2026-07-08T15:37:16Z
labels: 

## 正文

UCX on AWS EFA instances validate the presence of `efa_nv_peermem` module to detect if GPUDirect RDMA is supported.
The `efa_nv_peermem` module might not always be available (depends on OS/AMI), yet the instance does support GPUDirect RDMA.

1. It looks like UCX doesn't make use of this module but uses dmabuf
2. If 1 is true, can we please remove this dependency and find other ways to detect if GPUDirect RDMA is supported? we can make this configurable via environment variable if needed for now.

### erezzarum · 2025-10-22

I have tested on two different instances that supports GPUDirect RDMA dmabuf, p5.48xlarge and p5en.48xlarge, without loading the `efa_nv_peermem` module, UCX fallback to "software emulation", after loading the `efa_nv_peermem`, UCX was using cuda correctly.
I have tested libfabric and it works correct with dmabuf without having the `efa_nv_peermem` loaded, so something with UCX either not able to use dmabuf with EFA or this validation requires `efa_nv_peermem` always even though it uses dmabuf.
