**Summary:** gtest run on "roce on worker 3" ended with `1 FAILED TEST` — `rcx/test_ucp_proto_mock_rcx.rndv_remote_sys_dev_namespace/0` (`make: *** [Makefile:4713: test] Error 1`, Bash exit code 2). All 8718 other tests passed; no hang, timeout or crash (run completed normally with per-test timings printed).

**Root cause:** The test asserts that a remote peer's process-local `sys_dev` value must not leak into the locally-computed remote protocol selection parameters:

```
EXPECT_EQ(remote_sys_dev, rkey_config->key.sys_dev);
EXPECT_EQ(UCS_SYS_DEVICE_ID_UNKNOWN,
          rpriv->remote_proto_config.select_param.sys_dev);
```
(`test/gtest/ucp/test_ucp_proto_mock.cc:930-932`)

But the current production code copies the rkey's sys_dev straight into the remote select param:

```
mem_info.sys_dev = init_params->rkey_config_key->sys_dev;   /* proto_rndv.c:346 */
```

so `remote_proto_config.select_param.sys_dev` equals `remote_sys_dev` (the mocked `mock_0:1` device), not `UCS_SYS_DEVICE_ID_UNKNOWN`, and the second `EXPECT_EQ` fails. Git history shows why: the sys_dev namespace isolation was introduced in `5fa905a7` "UCP/PROTO/RNDV: Isolate remote system device namespace" (PR #11685) and then reverted on this branch by `6c7abeee` "TEST: Restore base RNDV production code for control" (jeffnvidia, 2026-08-31T17:50Z, ~2h before this build), while the test added in `8e90a98b` / touched by `0555af15` remained. The test is therefore correctly detecting that the production fix is missing — a self-inflicted branch inconsistency, not a flake or an infra problem.

**Implicated commit:** `6c7abeee` — jeffnvidia, "TEST: Restore base RNDV production code for control" (reverts `5fa905a7` by Jeffrey Mahou)

**File:** `src/ucp/rndv/proto_rndv.c:346` (assertion in `test/gtest/ucp/test_ucp_proto_mock.cc:931`)

**Suggested fix:** Re-apply the `5fa905a7` production change on this branch: in `ucp_proto_rndv_remote_select_param_init()`, when `rkey_config_key != NULL`, do not propagate the peer's sys_dev — set `mem_info.sys_dev = UCS_SYS_DEVICE_ID_UNKNOWN` (keeping `mem_info.type`/`flags` as-is), since `rkey_config_key->sys_dev` is only meaningful in the remote process's device namespace. If commit `6c7abeee` was intentionally a temporary control experiment, then drop `6c7abeee` before pushing, or gate `rndv_remote_sys_dev_namespace` so it isn't run without the fix — otherwise this job will keep failing deterministically on every rerun.
