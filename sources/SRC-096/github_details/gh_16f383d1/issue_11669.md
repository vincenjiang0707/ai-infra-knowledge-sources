### Describe the bug
We recently upgraded to ucx 1.21.0.20260504-1.65a1a71af.2604085 from DOCA 3.4.0. We have a fortran code that crashes with this version of ucx in ucp_worker_iface_port_speed due to division by zero.

### Root cause
The crash happens in `src/ucp/core/ucp_worker.c`, line 810:
```ratio = perf_attr.bandwidth.shared / wiface->attr.bandwidth.shared;```
when initializing/creating "self iface". Last debug line before crash is
```
[1784338416.935623] [della8:564978:0]            self.c:245  UCX  DEBUG created self iface id 0xd2800b920b351974 send_size 8192
```
So init of "self" interface is failing.

The problem is due to
```
attr->bandwidth.shared        = 0;
```
in `src/uct/sm/self/self.c` which triggers a division by zero. Any code that catches SIGFPE will fail. I did verify that indeed ratio ends up being NaaN (the next line `ratio = ucs_min(ucs_max(ratio, 0.0), 0.99);` will then force it to 0 which is why everything works fine when not catching SIGFPE).

A possible fix would be to check if `wiface->attr.bandwidth.shared > 0` before any division or alternatively in self.c bandwith.shared could be set to a non zero value.
