# [PR #11942] UCP/RMA: Fall back to RMA lanes in SGL put when no RMA_BW lane fits

source: https://github.com/openucx/ucx/pull/11942
state: closed | updated: 2026-09-13T21:03:34Z
labels: 

## 正文

## What?
Let `put/sgl/offload_sw` fall back to plain `RMA` lanes when no `RMA_BW` lane can reach both the local and remote memory types, and re-enable the SGL CUDA gtests.

## Why?
SGL put has only `RMA_BW` protocols, so when a NIC is filtered out of the `RMA_BW` lane set by `MULTI_LANE_MAX_RATIO` (e.g. a cross-socket HCA competing with cma/cuda_ipc), the transfer fails with "cannot find remote protocol". Unlike contig and IOV, which fall back to AM-based emulation.

## How?
`ucp_proto_multi_probe` now returns a status, so the SGL software-emulation probe can retry with `UCP_LANE_TYPE_RMA` after the `UCP_LANE_TYPE_RMA_BW` probe finds no lane, all of this is protocol-selection time only, with no data-path change.
