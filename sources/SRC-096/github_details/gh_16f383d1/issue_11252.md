# [Issue #11252] mlx5: ZTR-RTT CC is not enabled by default

source: https://github.com/openucx/ucx/issues/11252
state: closed | updated: 2026-03-31T09:38:18Z
labels: Bug

## 正文

### Describe the bug

According to `ucx_info -f`, setting `UCX_RC_VERBS_ECE=0` means "Use default ECE".

```
# config Enhanced Connection Establishment to establish connection.
#   0         : Use default ECE.
#   auto      : Use maximal supported ECE.
#   otherwise : Set the ECE to the given numeric 32-bit value.
#               This value is used as best-effort and can be adjusted by
#               the transport implementation.
#
#
#
# syntax:    unsigned long: <number>, "inf", or "auto"
# inherits:  UCX_RC_ECE
#
UCX_RC_VERBS_ECE=0
```

On my mlx5 machine, Programmable Congestion Control (PCC) is enabled, and the default ECE options value is 0x30000002.(ZTR-RTT CC: see other <https://developer.nvidia.com/blog/scaling-zero-touch-roce-technology-with-round-trip-time-congestion-control/>)

```
$ sudo mlxconfig -d mlx5_0 query | grep -i DCQCN
ROCE_CC_DCQCN_COMPATIBILITY_MODE            DEVICE_DEFAULT(0)
ROCE_CC_LEGACY_DCQCN_SW                     False(0)
ROCE_CC_LEGACY_DCQCN                        False(0)
```

However, ZTR-RTT CC is not enabled by default. When I ran the following command, no ZTR-RTT CC packets (VENDOR SPECIFIC) were found in the packet capture.
```
$ UCX_IB_MLX5_DEVX=no UCX_NET_DEVICES=mlx5_0:1 ./install-debug/bin/ucx_perftest  -s 33179419
$ UCX_IB_MLX5_DEVX=no UCX_NET_DEVICES=mlx5_0:1  ./install-debug/bin/ucx_perftest -s 33179419  -t ucp_am_lat 172.1.1.66

$ tshark -r dump.pcap | grep VENDOR
(none)
```
