## 正文

## What?
Build a device inventory from all of the discovered devices.
The inventory devices are grouped by type (net/acc device), sorted by bdf.
Devices under the same physical device (e.g. NIC ports, GPU sub-devices like with MPS MLOPart) are kept together.
Some filters may be also applied, such as keeping only CX9 NICs when the setup is detected as Vera Rubin.
This inventory will be used to group the devices into GPU-NIC groups, to later be used for GPU-NIC assignments.

## How?
- Collect all devices into arrays by type
- Sort by BDF
- Filter out unwanted devices
- Group acc devices of the same physical GPU (BDF is equal)
- Group net devices of the same physical NIC together (BDF is the same except of the function)

<details><summary>Full analysis</summary>

**Summary:** Azure job "Coverity release on coverity_rh7" (build 133620) exited non-zero: `##[error]Coverity found 4 issues:` — all four are `FORWARD_NULL` (Explicit null dereferenced) in `topo_groups.c` at lines 405, 412, 415, 420.

**Root cause:** In `ucs_topo_groups_inventory_build()` the two arrays are declared with `UCS_ARRAY_DYNAMIC_INITIALIZER` (lines 389–390), which sets `buffer = NULL, length = 0`. They are then populated by `ucs_topo_groups_devices_collect()` via `ucs_array_append()`. Coverity's inter-procedural summary for `devices_collect()` does not record the write to `->buffer` (the append goes through the conditionally-chosen `target_array` pointer, and the `num_devices == 0` path returns `UCS_OK` with the buffer untouched), so on the `status == UCS_OK` path it still considers `buffer == NULL`. It then applies its derived models for the callees, which dereference the buffer inside `ucs_array_for_each` / `ucs_qsort_r`:
- 405 → `ucs_topo_groups_sys_dev_sort()` → `ucs_qsort_r` → `ucs_topo_groups_sys_dev_cmp` deref of `elem1` (topo_groups.c:40)
- 412 → `ucs_topo_groups_cx9_filter()` deref at :207
- 415 → `ucs_topo_groups_gpus_build()` deref at :309
- 420 → `ucs_topo_groups_nics_build()` deref at :347

These are false positives in practice (`length == 0` whenever `buffer == NULL`, so `ucs_carray_for_each` never enters and the sort returns early at the `ucs_array_is_empty()` check on line 65). But Coverity does not derive the `length != 0 ⇒ buffer != NULL` correlation — note defect #1 explicitly shows it taking the "`sys_devs->length == 0` false" branch with a NULL buffer, which is impossible. The Coverity build compiles asserts in (`__COVERITY__` enables `ucs_assert` → `ucs_assert_always`, see `src/ucs/debug/assert.h:54`), so a `ucs_assert` is an effective and idiomatic way to teach the checker this invariant. The CI script gates on `nerrors > 0`, so any new defect fails the job.

**Implicated commit:** 5ce1fca4 "UCS/TOPO: Add asserts" (Guy Ealey Morag) — head of PR #11869 branch `topo-build-inventory`; the flagged code was introduced earlier in the same branch (57f4bc2b / 7712e2fd "UCS/TOPO: Use array for each").

**File:** src/ucs/sys/topo/base/topo_groups.c:389-420 (defects reported at :405, :412, :415, :420; callee derefs at :40, :207, :309, :347)

**Suggested fix:** Add the explicit buffer/length invariant right after the successful `devices_collect()` call in `ucs_topo_groups_inventory_build()` (topo_groups.c, after line 403), which covers all four call sites at once:

```c
    status = ucs_topo_groups_devices_collect(devices, num_devices, &acc_devices,
                                             &net_devices);
    if (status != UCS_OK) {
        goto err_free_arrays;
    }

    /* Non-empty arrays always have an allocated backing buffer; makes the
     * invariant explicit for static analyzers (Coverity FORWARD_NULL). */
    ucs_assert(ucs_array_is_empty(&acc_devices) ||
               (ucs_array_begin(&acc_devices) != NULL));
    ucs_assert(ucs_array_is_empty(&net_devices) ||
               (ucs_array_begin(&net_devices) != NULL));
```

Since `ucs_fatal_error_format()` is `UCS_F_NORETURN`, Coverity will prune the `buffer == NULL && length != 0` path and the four FORWARD_NULL reports disappear. Equivalent alternative: add the same assert at the top of `ucs_topo_groups_sys_dev_sort()`, `_cx9_filter()`, `_gpus_build()` and `_nics_build()` next to the existing NULL asserts, so the models are fixed at the callee side. Note that an `ucs_array_is_empty()` early-return alone is *not* sufficient — `sys_dev_sort()` already has one and was still flagged. Do not simply add a Coverity suppression comment; the assert also documents a real invariant.
