# [PR #11969] UCT/IB/MLX5: fix psn track for sgl

source: https://github.com/openucx/ucx/pull/11969
state: closed | updated: 2026-09-22T08:15:57Z

## 正文

## What?
Fix the PSN track for SGL.

## Why?
The PSN track is currently incorrect when SGL contains a 0-length element.

## How?
Increment PSN by 1 when gets a 0-length element.

### svc-ucx · 2026-09-18

🤖 **CI Triage Agent** — `UCX PR (Tests roce on worker 3)` · commit `24cc7353`

**TL;DR:** The new `test_rc_mlx5_token_query.put_sgl_zcopy` gtest segfaults in its skip condition because `check_caps_v2()`/`max_put_sgl_zcopy_count()` dereference `m_e1` while gtest evaluates `check_skip_test()` *before* `init()` creates the entities; guard those helpers on `m_entities` being non-empty (the condition is re-evaluated from `test_rc::init()` once `m_e1` exists).

<details><summary>Full analysis</summary>

**Summary:** `roce on worker 3` gtest run crashed with SIGSEGV (address 0x690) in `test_rc_mlx5_token_query::check_caps_v2()` while setting up `rc_mlx5/test_rc_mlx5_token_query.put_sgl_zcopy/0`, aborting `make test` (`make: *** [Makefile:4711: test] Segmentation fault (core dumped)` → `Bash exited with code '2'`).

**Root cause:** The backtrace shows the crash path is
`test_base::SetUpProxy() (test/gtest/common/test.cc:410) → check_skip_test() → test_rc_mlx5_token_query::check_caps_v2() (test_rc.cc:1505) → uct_test::entity::iface() (uct_test.cc:1168) → ucs::handle::get() (test_helpers.h:790)`.
`SetUpProxy()` calls `check_skip_test()` at test.cc:410 *before* `init()` at line 412. The entities `m_e1`/`m_e2` are raw, uninitialized pointers (`test/gtest/uct/ib/test_rc.h:59`) and are only created in `test_rc::init()` (test_rc.cc:25), which then re-invokes `check_skip_test()` at test_rc.cc:28. So on the first, pre-init evaluation `m_e1` is NULL/garbage and `m_e1->iface()` faults reading the `m_iface` handle at offset 0x690 of a null object — exactly the reported "address not mapped to object at address 0x690".
The v1 helper `uct_test::check_caps()` is safe in this context because it iterates `m_entities` (uct_test.cc:500-507) and trivially returns `true` when the vector is empty; the new v2 helpers added for this test do not have that protection. The skip condition at test_rc.cc:1556-1559 (`!check_caps(PUT_ZCOPY) || !check_caps_v2(...) || max_put_sgl_zcopy_count() < NUM_SGL_ELEMENTS`) therefore short-circuits past the safe check and crashes. This is not a hang or timeout — the ~60s gap between the signal line and the backtrace is just core-dump/backtrace generation.

**Implicated commit:** `[REDACTED:Hex High Entropy String]` — "GTEST/UCT/IB: verify psn for sgl", Zihao Zhao (PR #11969); the same latent pattern was introduced for `am_short` in `0826e0b1` "UCT: add token query support in ucx (#11804)".

**File:** `test/gtest/uct/ib/test_rc.cc:1505` (called from the skip condition at `test/gtest/uct/ib/test_rc.cc:1556-1559`); related: `test/gtest/uct/ib/test_rc.h:59`, `test/gtest/common/test.cc:410`

**Suggested fix:** Make the v2 helpers safe when entities don't exist yet, since `test_rc::init()` re-runs `check_skip_test()` after `m_e1` is created:
```cpp
bool check_caps_v2(uint64_t flags)
{
    if (m_entities.empty()) {
        return true;  /* re-checked from test_rc::init() after m_e1 exists */
    }
    ...
}

size_t max_put_sgl_zcopy_count()
{
    if (m_entities.empty()) {
        return SIZE_MAX;
    }
    ...
}
```
Alternatively move the capability checks into the test body with `UCS_TEST_SKIP_R("unsupported")` instead of the `UCS_TEST_SKIP_COND_P` condition. Additionally, initialize `m_e1`/`m_e2` to `NULL` in a `test_rc` constructor (test_rc.h:59) so this class of bug fails deterministically instead of relying on uninitialized memory, and apply the same guard to the existing `am_short` skip condition (test_rc.cc:1535-1537).

**Related:** PR #11969 (this change); PR #11804 (introduced `check_caps_v2` skip-condition pattern); PR #11866 touches the same test area.

### svc-nvidia-pr-review · 2026-09-20


Residual coverage note: the new test covers PSN accounting on rc_mlx5 only. Data correctness for a zero-length element (and `UCT_MEM_HANDLE_NULL` memh) in a mixed SGL is not covered by the generic `test_uct_sgl` fixture, which currently only uses non-zero lengths — adding such a case there would also cover `cuda_ipc` and any plugin implementation. Also, `uct_ep_put_sgl_zcopy()` in `uct_v2.h` does not document that zero-length elements are allowed and that `buffers[i]`/`memhs[i]` are then ignored, which is what the new test relies on.

**TL;DR:** The aarch64 build failed compiling `test/gtest/uct/ib/test_rc.cc` because the new `max_put_sgl_zcopy_count()` helper calls `m_entities.empty()`, but `ucs::ptr_vector<uct_test::entity>` has no `empty()` member — use `m_entities.size() == 0` (or add `empty()` to `ptr_vector_base`).

<details><summary>Full analysis</summary>

**Summary:** `make` failed in `test/gtest` with a hard compile error (`-Werror`): `'class ucs::ptr_vector<uct_test::entity>' has no member named 'empty'`, aborting the `build_aarch64 sles15sp7_aarch64` job.

**Root cause:** Commit `b2c8530c` ("GTEST/UCT/IB: check caps v2", the HEAD of this PR branch) added a skip-guard in `test_rc_mlx5_token_query::max_put_sgl_zcopy_count()`:

```
if (m_entities.empty()) {
```

`m_entities` is a `ucs::ptr_vector<uct_test::entity>`, which derives from `ptr_vector_base` (test/gtest/common/test_helpers.h:603-660). That class intentionally exposes only a minimal API — `push_back`, `push_front`, `clear`, `begin`, `end`, `front`, `back`, and `size()` — and does **not** define `empty()`. The `operator const std::vector<T*>&()` conversion is not applied for member access, so `.empty()` does not resolve. This is a pure source error, not arch- or SLES-specific; the exact log lines are:

```
2026-09-20T04:02:11.8205270Z /test/gtest/uct/ib/test_rc.cc: In member function 'size_t test_rc_mlx5_token_query::max_put_sgl_zcopy_count()':
2026-09-20T04:02:11.8206774Z /test/gtest/uct/ib/test_rc.cc:1503:24: error: 'class ucs::ptr_vector<uct_test::entity>' has no member named 'empty'
2026-09-20T04:02:12.9755780Z make[3]: *** [Makefile:3670: uct/ib/gtest-test_rc.o] Error 1
```

**Implicated commit:** [REDACTED:Hex High Entropy String] — Zihao Zhao, "GTEST/UCT/IB: check caps v2" (PR #11969)

**File:** test/gtest/uct/ib/test_rc.cc:1503 (class definition at test/gtest/common/test_helpers.h:603-656)

**Suggested fix:** Change line 1503 to use the API that exists:

```c++
if (m_entities.size() == 0) {
```

Alternatively, if `empty()` is wanted generally, add it to `ptr_vector_base` next to `size()` in test/gtest/common/test_helpers.h:654:

```c++
bool empty() const {
    return m_vec.empty();
}
```

Adding the accessor is the cleaner option if other new code in this PR also expects `empty()`. Note this will fail on *every* build job, not just aarch64, so a local `make -C test/gtest` before re-pushing will confirm the fix.
