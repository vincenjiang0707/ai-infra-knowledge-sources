# [PR #11683] UCT/MM,BASE: Fail cleanly when an MM MD cannot provide a memory handle

source: https://github.com/openucx/ucx/pull/11683
state: open | updated: 2026-09-11T17:58:04Z
labels: 

## 正文

## What
Fail cleanly when an MM memory allocation does not produce a memory handle,
instead of dereferencing NULL later.

## Why
The POSIX MM MD re-evaluates `/dev/shm` on every `uct_md_query()` via `statvfs`.
If the free space drops below `UCX_POSIX_SHM_MIN_SIZE` after device enumeration
but before the iface is opened, the MD stops reporting `UCT_MD_FLAG_ALLOC`. The
receive FIFO is then allocated from the heap and `uct_iface_mem_alloc()` leaves
`memh` as `UCT_MEM_HANDLE_NULL`, which `uct_mm_iface_get_address()` dereferences
when it reads `seg->seg_id`. The result is a SIGSEGV at `MPI_Init` on nodes that
are temporarily low on shared memory.

The RX descriptor mpool has the same exposure later on. It grows lazily and each
chunk allocation re-queries the md, so a drop below the threshold after the iface
is open gives a chunk with a NULL memh, which `uct_mm_iface_recv_desc_init()`
dereferences when it reads `seg->length`.

## How
Check `recv_fifo_mem.memh` after the FIFO allocation and return
`UCS_ERR_NO_DEVICE`, and turn the existing debug-only assert in
`uct_iface_mp_chunk_alloc()` into a returned error.

The checks are deliberately not in `uct_iface_mem_alloc()`, since a NULL memh is
valid there for MDs that only need an rkey. gdr_copy and cuda_ipc rely on that
for host bounce buffers. `uct_iface_mpool_init()` is used only by mm, ib and
ugni, all of which dereference the handle.

Note the iface open failure is not silently absorbed: `UCS_ERR_NO_DEVICE`
propagates through `ucp_worker_iface_open()`, so `MPI_Init` fails with an error
rather than falling back to another transport. That is still preferable to a
crash.

A regression gtest clears `UCT_MD_FLAG_ALLOC` from the MD query, matching what
`uct_posix_md_query()` does when the file system runs low, and then opens an mm
iface. Without the fix the test segfaults.

**TL;DR:** The four CUDA-transport gtests fail because PR #11683's new "fail cleanly" check in `uct_iface_mem_alloc()` treats `UCT_MD_FLAG_NEED_RKEY` as "needs a memory handle", so gdr_copy/cuda_ipc MDs (which set NEED_RKEY but can only register CUDA memory) now get `UCS_ERR_UNSUPPORTED` when allocating host bounce buffers; restrict the check to `UCT_MD_FLAG_NEED_MEMH` (and drop the new NULL-memh asserts).

<details><summary>Full analysis</summary>

**Summary:** `make test` in the AddressSanitizer GPU job failed with 4 failed gtests: `gdr_copy/uct_cancel_test.am_bcopy/0`, `cuda_ipc/uct_cancel_test.am_bcopy/0`, `gdr_copy/uct_p2p_rma_test.get_short/1`, `gdr_copy/test_uct_loopback_cuda.envelope/0` (10167 passed, 4 failed → `make: *** [Makefile:4713: test] Error 1`).

**Root cause:** The PR's change to `uct_iface_mem_alloc()` computes
`need_mem_reg = !!(md_attr.cap.flags & (UCT_MD_FLAG_NEED_MEMH | UCT_MD_FLAG_NEED_RKEY))` and, when the memory was not allocated by the MD, now aborts the allocation with `UCS_ERR_UNSUPPORTED` if the MD cannot register the requested memory type (`src/uct/base/uct_mem.c:388-433`).

Both CUDA MDs advertise `UCT_MD_FLAG_NEED_RKEY` but can only register CUDA memory and do not advertise `UCT_MD_FLAG_ALLOC`:
- `src/uct/cuda/gdr_copy/gdr_copy_md.c:119-121` — `flags = UCT_MD_FLAG_REG | UCT_MD_FLAG_NEED_RKEY`, `reg_mem_types = UCS_BIT(UCS_MEMORY_TYPE_CUDA)`
- `src/uct/cuda/cuda_ipc/cuda_ipc_md.c:206-215` — same NEED_RKEY, `reg_mem_types = CUDA`

So for these transports: `need_mem_reg == 1`, `support_mem_reg == 0` (HOST not in `reg_mem_types`), no `UCT_MD_FLAG_ALLOC` to force MD allocation → host bounce buffers are allocated via heap/mmap and then rejected by the new branch instead of getting the previously-legal `mem->memh = UCT_MEM_HANDLE_NULL` (line 443). That makes iface descriptor/bounce-buffer mpool creation fail, which is exactly what breaks bcopy/short-path tests (`am_bcopy`, `get_short`, loopback `envelope`). The MM case the PR targets is unaffected because MM MDs do expose `UCT_MD_FLAG_ALLOC` (`src/uct/sm/mm/base/mm_md.c:79-82`) and take the forced-MD-allocation path.

Secondary hazard from the same commit: `ucs_assert(mem.memh != UCT_MEM_HANDLE_NULL)` in `uct_iface_mp_chunk_alloc` (`src/uct/base/uct_mem.c:492`) contradicts line 443, which legitimately leaves `memh == UCT_MEM_HANDLE_NULL` for MDs that don't need a memh (cuda, tcp, cma) — this will abort in assertion-enabled builds once the error path above is relaxed.

**Implicated commit:** d265a19a — "UCT/MM/BASE: Fail cleanly when an MM MD cannot provide a memory handle", Bryce Westheimer (branch `bwestheimer/mm-toctou-null-memh`, PR #11683)

**File:** src/uct/base/uct_mem.c:388-444 (check at 393-433, NULL-memh path at 443); assert at src/uct/base/uct_mem.c:492

**Suggested fix:**
1. Narrow the hard failure to MDs that truly require a local memory handle:
   ```c
   need_mem_reg = !!(md_attr.cap.flags & UCT_MD_FLAG_NEED_MEMH);
   ```
   (or gate the new `UCS_ERR_UNSUPPORTED` branch on `UCT_MD_FLAG_NEED_MEMH` only, keeping NEED_RKEY-only MDs on the old `mem->memh = UCT_MEM_HANDLE_NULL` path).
2. Remove/relax `ucs_assert(mem.memh != UCT_MEM_HANDLE_NULL)` at line 492 (and the one at 441 is fine since it follows a successful `uct_md_mem_reg`), since NULL memh is valid for MDs without NEED_MEMH.
3. Re-run the ASAN GPU job; the gdr_copy/cuda_ipc `am_bcopy`, `get_short` and `envelope` tests should pass again.

<details><summary>Full analysis</summary>

**Summary:** `coverity release on coverity_rh7` failed with `##[error]Coverity found 1 issues:` — FORWARD_NULL "Dereference after null check" at `src/uct/sm/mm/base/mm_iface.c:899`. Build and analysis themselves succeeded (96 defects total, 1 new/unsuppressed).

**Root cause:** Commit `d6a54274` added a new guard in `uct_mm_iface_t` init:
```
822: if (self->recv_fifo_mem.memh == UCT_MEM_HANDLE_NULL) {
826:     goto err_free_fifo;
```
Coverity records at step 23 that comparing `self->recv_fifo_mem.memh` to NULL implies it *may* be NULL, then at step 28 the `err_free_fifo` label passes that same struct to `uct_iface_mem_free(&self->recv_fifo_mem)` (`mm_iface.c:899`). In `uct_iface_mem_free` (`src/uct/base/uct_mem.c:449`) the NULL check only guards the `uct_md_mem_dereg` call; execution still reaches `uct_mem_free()` (`uct_mem.c:333-335`), which for `UCT_ALLOC_METHOD_MD` calls `uct_md_mem_free(mem->md, mem->memh)` → `md->ops->mem_free(memh)` (`uct_md.c:572`), and the modelled callee (`uct_cuda_copy_mem_free`, `cuda_copy_md.c:554-558`) dereferences it.

Coverity cannot correlate `memh` with `method`, so the new goto exposes the modelled path as a defect. Either way, the code as written is not self-evidently safe and the gate is failing.

**Implicated commit:** `[REDACTED:Hex High Entropy String]` — "UCT/MM: Check the FIFO memory handle in iface init", Bryce Westheimer (also related: `d265a19a`, same author/branch)

**File:** `src/uct/sm/mm/base/mm_iface.c:822-826` and `:899`; dereference model via `src/uct/base/uct_mem.c:447-455` and `:331-352`

**Suggested fix:** Break the null path explicitly rather than suppressing it. Preferred, and it also hardens the generic path:

```c
/* src/uct/base/uct_mem.c, uct_mem_free() */
case UCT_ALLOC_METHOD_MD:
    if (mem->memh == UCT_MEM_HANDLE_NULL) {
        return UCS_OK; /* nothing was registered/allocated by the MD */
    }
    return uct_md_mem_free(mem->md, mem->memh);
```

Alternatives if you prefer to keep `uct_mem.c` untouched:
- In `mm_iface.c`, don't reuse `err_free_fifo` for this case; add a dedicated label that frees via a path guarded by the method, e.g. `if (self->recv_fifo_mem.method != UCT_ALLOC_METHOD_MD) { uct_iface_mem_free(...); }`, making the invariant explicit to both readers and Coverity.
- Add `ucs_assert(self->recv_fifo_mem.method != UCT_ALLOC_METHOD_MD);` right after the NULL check to document the invariant — but note assertions are compiled out in release, so Coverity may still flag it; the `uct_mem_free` guard is the robust option.

Do not add a blanket Coverity suppression here — the gate is reporting a genuinely ambiguous ownership contract introduced by the new early-exit.
