# [PR #11949] UCS/TOPO: Mark device class as incomplete on NVML errors

source: https://github.com/openucx/ucx/pull/11949
state: closed | updated: 2026-09-20T05:57:34Z
labels: 

## 正文

## What?
Mark the `ACC` device class as incomplete if any nvml error occurs during initialization.

## Why?
If any part of the nvml initialization flow fails, it means that the device ordinal calculation may results in unexpected result.
Adding a marker for incomplete classes allows returning `INVALID` when asking for a device class ordinal of an incomplete class, leading to legacy behavior instead of usage of a possibly wrong ordinal.

🤖 **CI Triage Agent** — `UCX PR (Coverity coverity release on coverity_rh7)` · commit `6bc729dc`

**TL;DR:** The Coverity `release` job failed because static analysis found 1 new defect — a MISSING_LOCK data-race report on `ucs_topo_global_ctx.device_class_incomplete_mask` written unlocked in `ucs_topo_init()` (topo.c:1545), a field newly introduced by this PR. Fix by taking `ucs_topo_global_ctx.lock` around the initialization (or adding a `/* coverity[missing_lock] */` suppression, since init is single-threaded).

<details><summary>Full analysis</summary>

**Summary:** `coverity release on coverity_rh7` — `cov-analyze` completed successfully but `cov-format-errors` reported `nerrors=1`, so the stage exited non-zero: `##[error]Coverity found 1 issues: /src/ucs/sys/topo/base/topo.c:1545 Type: Data race condition (MISSING_LOCK)`.

**Root cause:** The build itself was clean (551/551 compilation units, `BUILD SUCCESS`, cov-build "completed successfully"). The failure is purely the Coverity gate. PR #11949 adds a new global field `ucs_topo_global_ctx.device_class_incomplete_mask`, which is consistently mutated under the spinlock in the three other places Coverity found:
- `ucs_topo_device_class_mark_incomplete()` — lock at topo.c:1132, access at :1133
- `ucs_topo_extract_state()` — lock at :1482, access at :1486–1490
- `ucs_topo_restore_state()` — lock at :1504, access at :1511

but is assigned *without* the lock in `ucs_topo_init()` at topo.c:1545. Coverity's heuristic ("accessed with lock held 3 out of 4 times") therefore flags the init write as a race. Functionally this is a false positive — `ucs_topo_init()` runs before any other thread can touch the context, and the spinlock is only created one line earlier at :1542 — but it is a *new* finding attributable to this PR, so the gate fails. (Note `num_devices` on the adjacent line :1544 escapes the report only because it is also read unlocked elsewhere, e.g. :1474.)

**Implicated commit:** a361f7a7 "UCS/TOPO: Mark device class as incomplete on NVML errors" by Guy Ealey Morag (follow-up [REDACTED:Hex High Entropy String] "UCS/TOPO: Fix PR comments"), branch `no-ordinal-on-nvml-error`, PR #11949

**File:** src/ucs/sys/topo/base/topo.c:1545 (supporting sites: :1133, :1486–1490, :1511)

**Suggested fix:** Make the initialization consistent with the other accesses so Coverity's lock-consistency heuristic is satisfied. Simplest, in `ucs_topo_init()`:

```c
void ucs_topo_init()
{
    ucs_spinlock_init(&ucs_topo_global_ctx.lock, 0);
    kh_init_inplace(bus_to_sys_dev, &ucs_topo_global_ctx.bus_to_sys_dev_hash);

    ucs_spin_lock(&ucs_topo_global_ctx.lock);
    ucs_topo_global_ctx.num_devices                  = 0;
    ucs_topo_global_ctx.device_class_incomplete_mask = 0;
    ucs_spin_unlock(&ucs_topo_global_ctx.lock);

    ucs_list_add_tail(...);
}
```

The lock/unlock pair costs nothing at init time and removes the finding. If you prefer not to lock during init, add an explicit suppression immediately above line 1545 (`/* coverity[missing_lock] */`) with a comment noting that `ucs_topo_init()` is single-threaded. As a secondary cleanup worth doing in the same PR, `ucs_topo_extract_state()` reads `ucs_topo_global_ctx.num_devices` at :1474–1475 outside the lock before re-reading it under the lock at :1485 — move the `devices_size` computation inside the critical section (or size the allocation for the max) to avoid a genuine TOCTOU on the copy length at :1484.
