### svc-nvidia-pr-review · 2026-09-14


Coverage note (not blocking, property of the existing gdaki test setup): `rc_gda` devices are only enumerated when an active CUDA primary context exists at TL-query time (`uct_gdaki_push_primary_ctx()` -> `uct_cuda_ctx_primary_push_first_active()`, cached via `UCS_INIT_ONCE`), unless `UCX_IB_GDA_RETAIN_INACTIVE_CTX=yes`. In the gtest binary that context comes from the static `test_device_cuda_ctx_guard` in `uct/test_device.cc`, which is only compiled under `HAVE_CUDA && HAVE_NVCC`. In a CUDA-without-nvcc gtest build the new `rc_gda` instantiation will silently enumerate zero resources and the test will not run — worth knowing when judging CI evidence for this PR.
