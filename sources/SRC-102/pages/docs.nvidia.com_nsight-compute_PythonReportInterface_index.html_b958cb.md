# 2. Python Report Interface[#](https://docs.nvidia.com#python-report-interface)

## 2.1. Introduction[#](https://docs.nvidia.com#introduction)

NVIDIA Nsight Compute features a Python-based interface to interact with exported report files.

The module is called [ ncu_report](https://docs.nvidia.com#module-ncu_report) and works on any Python version from 3.7

[[1]](https://docs.nvidia.com#fn1). It can be found in the

`extras/python`

directory of your NVIDIA
Nsight Compute package.In order to use the Python module, you need a report file generated by NVIDIA
Nsight Compute. You can obtain such a file by saving it from the graphical
interface or by using the `--export`

flag of the command line tool.

The types and functions in the [ ncu_report](https://docs.nvidia.com#module-ncu_report) module are a subset of the ones
available in the NvRules API. The documentation in this section serves as a
tutorial. For a more formal description of the exposed API, please refer to the

[NvRules API](https://docs.nvidia.com/NvRulesAPI/index.html)documentation.

## 2.2. Basic Usage[#](https://docs.nvidia.com#basic-usage)

In order to be able to import [ ncu_report](https://docs.nvidia.com#module-ncu_report) you will either have to navigate
to the

`extras/python`

directory, or add its absolute path to the
`PYTHONPATH`

environment variable. Then, the module can be imported like any
Python module:```
>>> import ncu_report
```

**Importing a report**

Once the module is imported, you can load a report file by calling the
[ load_report](https://docs.nvidia.com#ncu_report.load_report) function with the path to the file. This function returns an
object of type

[which holds all the information concerning that report.](https://docs.nvidia.com#ncu_report.IContext)

`IContext`

```
>>> my_context = ncu_report.load_report("my_report.ncu-rep")
```

**Querying ranges**

When working with the Python module, profiling results are grouped into *ranges*
which are represented by [ IRange](https://docs.nvidia.com#ncu_report.IRange) objects. You can inspect the number of

*ranges*contained in the loaded report by calling the

[member function of an](https://docs.nvidia.com#ncu_report.IContext.num_ranges)

`IContext.num_ranges`

[object and retrieve a](https://docs.nvidia.com#ncu_report.IContext)

`IContext`

*range*by its index using

[.](https://docs.nvidia.com#ncu_report.IContext.range_by_idx)

`IContext.range_by_idx`

```
>>> my_context.num_ranges()
1
>>> my_range = my_context.range_by_idx(0)
```

**Querying actions**

Inside a *range*, profiling results are called *actions*. You can query the
number of *actions* contained in a given *range* by using the
[ IRange.num_actions](https://docs.nvidia.com#ncu_report.IRange.num_actions) method of an

[object.](https://docs.nvidia.com#ncu_report.IRange)

`IRange`

```
>>> my_range.num_actions()
2
```

In the same way *ranges* can be obtained from an [ IContext](https://docs.nvidia.com#ncu_report.IContext) object by
using the

[method, individual](https://docs.nvidia.com#ncu_report.IContext.range_by_idx)

`IContext.range_by_idx`

*actions*can be obtained from

[objects by using the](https://docs.nvidia.com#ncu_report.IRange)

`IRange`

[method. The resulting](https://docs.nvidia.com#ncu_report.IRange.action_by_idx)

`IRange.action_by_idx`

*actions*are represented by the

[class.](https://docs.nvidia.com#ncu_report.IAction)

`IAction`

```
>>> my_action = my_range.action_by_idx(0)
```

As mentioned previously, an *action* represents a single profiling result. To
query the workloads’s name you can use the [ IAction.name](https://docs.nvidia.com#ncu_report.IAction.name) member function
of the

[class.](https://docs.nvidia.com#ncu_report.IAction)

`IAction`

```
>>> my_action.name()
MyKernel
```

To query the workload type, you can use the [ IAction.workload_type](https://docs.nvidia.com#ncu_report.IAction.workload_type) member
function of the

[class, which will return an integer among the](https://docs.nvidia.com#ncu_report.IAction)

`IAction`

`IAction.WorkloadType_*`

values.For CUDA kernels, you get the following result:

```
>>> my_action.workload_type()
0
```

All return values of [ IAction.workload_type](https://docs.nvidia.com#ncu_report.IAction.workload_type) are documented in API
documentation for the

[class.](https://docs.nvidia.com#ncu_report.IAction)

`IAction`

**Querying metrics**

To get a tuple of all metric names contained within an *action* you can use the
[ IAction.metric_names](https://docs.nvidia.com#ncu_report.IAction.metric_names) method. It is meant to be combined with the

[method which returns an](https://docs.nvidia.com#ncu_report.IAction.metric_by_name)

`IAction.metric_by_name`

[object. However, for the same task you may also use the subscript operator through the](https://docs.nvidia.com#ncu_report.IMetric)

`IMetric`

[method, as explained in the](https://docs.nvidia.com#ncu_report.IAction.__getitem__)

`IAction.__getitem__`

[High-Level Interface](https://docs.nvidia.com/index.html#python-report-interface-high-level)section below.

The metric names displayed here are the same as the ones you can use with the
`--metrics`

flag of NVIDIA Nsight Compute. Once you have extracted a *metric*
from an *action*, you can obtain its value by using one of the following three
methods:

to obtain its value as a Python`IMetric.as_string`

`str`

to obtain its value as a Python`IMetric.as_uint64`

`int`

to obtain its value as a Python`IMetric.as_double`

`float`


For example, to print the display name of the GPU on which the workload was
profiled you can query the `device__attribute_display_name`

metric.

```
>>> display_name_metric = my_action.metric_by_name('device__attribute_display_name')
>>> display_name_metric.as_string()
'NVIDIA GeForce RTX 3060 Ti'
```

Note that accessing a metric with the wrong type can lead to unexpected (conversion) results.

```
>>> display_name_metric.as_double()
0.0
```

Therefore, it is advisable to directly use the [High-Level](https://docs.nvidia.com/index.html#python-report-interface-high-level) function
[ IMetric.value](https://docs.nvidia.com#ncu_report.IMetric.value), as explained below.

## 2.3. Python Interoperability[#](https://docs.nvidia.com#python-interoperability)

On top of the low-level [NvRules API](https://docs.nvidia.com/NvRulesAPI/index.html) the
Python Report Interface also implements part of the [Python object model](https://docs.python.org/3/reference/datamodel.html). By implementing special
methods, the Python Report Interface’s exposed classes can be used with built-in
Python mechanisms such as iteration, string formatting and length querying.

This allows you to access *metrics* objects via the [ IAction.__getitem__](https://docs.nvidia.com#ncu_report.IAction.__getitem__)
method of the

[class:](https://docs.nvidia.com#ncu_report.IAction)

`IAction`

```
>>> display_name_metric = my_action["device__attribute_display_name"]
```

There is also a convenience method [ IMetric.value](https://docs.nvidia.com#ncu_report.IMetric.value) which allows you to
query the value of a

*metric*object without knowledge of its type:

```
>>> display_name_metric.value()
'NVIDIA GeForce RTX 3060 Ti'
```

All the available methods of a class, as well as their associated Python docstrings, can be looked up interactively via

```
>>> help(ncu_report.IMetric)
```

or similarly for other classes and methods. In your code, you can access the
docstrings via the [ __doc__](https://docs.python.org/3/library/stdtypes.html#definition.__doc__) attribute, i.e.

`ncu_report.IMetric.value.__doc__`

`IMetric.RollupOperation_AVG`

`IMetric.RollupOperation_MAX`

```

## 2.5. NVTX Support[#](https://docs.nvidia.com#nvtx-support)

The [ ncu_report](https://docs.nvidia.com#module-ncu_report) has support for the NVIDIA Tools Extension (NVTX). This
comes through the

[object which represents the NVTX state of a profiled kernel.](https://docs.nvidia.com#ncu_report.INvtxState)

`INvtxState`

An [ INvtxState](https://docs.nvidia.com#ncu_report.INvtxState) object can be obtained from an action by using its

[method. It exposes the](https://docs.nvidia.com#ncu_report.IAction.nvtx_state)

`IAction.nvtx_state`

[method which returns a tuple of integers representing the domains this kernel has state in. These integers can be used with the](https://docs.nvidia.com#ncu_report.INvtxState.domains)

`INvtxState.domains`

[method to get an](https://docs.nvidia.com#ncu_report.INvtxState.domain_by_id)

`INvtxState.domain_by_id`

[object which represents the state of a domain.](https://docs.nvidia.com#ncu_report.INvtxDomainInfo)

`INvtxDomainInfo`

The [ INvtxDomainInfo](https://docs.nvidia.com#ncu_report.INvtxDomainInfo) can be used to obtain a tuple of

*Push-Pop*, or

*Start-End*ranges using the

[and](https://docs.nvidia.com#ncu_report.INvtxDomainInfo.push_pop_ranges)

`INvtxDomainInfo.push_pop_ranges`

[methods.](https://docs.nvidia.com#ncu_report.INvtxDomainInfo.start_end_ranges)

`INvtxDomainInfo.start_end_ranges`

There is also a [ IRange.actions_by_nvtx](https://docs.nvidia.com#ncu_report.IRange.actions_by_nvtx) member function in the

[class which allows you to get a tuple of actions matching the NVTX state described in its parameter.](https://docs.nvidia.com#ncu_report.IRange)

`IRange`

The parameters for the [ IRange.actions_by_nvtx](https://docs.nvidia.com#ncu_report.IRange.actions_by_nvtx) function are two lists of
strings representing the state for which we want to query the actions. The first
parameter describes the NVTX states to include while the second one describes
the NVTX states to exclude. These strings are in the same format as the ones
used with the

`--nvtx-include`

and `--nvtx-exclude`

options.## 2.6. Sample Script[#](https://docs.nvidia.com#sample-script)

**NVTX Push-Pop range filtering**

This is a sample script which loads a report and prints the names of all the
profiled kernels which were wrapped inside `BottomRange`

and `TopRange`

*Push-Pop ranges* of the default NVTX domain.

```
#!/usr/bin/env python3
import sys
import ncu_report
if len(sys.argv) != 2:
print("usage: {} report_file".format(sys.argv[0]), file=sys.stderr)
sys.exit(1)
report = ncu_report.load_report(sys.argv[1])
for range_idx in range(report.num_ranges()):
current_range = report.range_by_idx(range_idx)
for action_idx in current_range.actions_by_nvtx(["BottomRange/*/TopRange"], []):
action = current_range.action_by_idx(action_idx)
print(action.name())
```
