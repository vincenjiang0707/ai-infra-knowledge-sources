## Summary

Vibe-coded POC — putting this up for discussion, not meant to land as-is.

**Problem:** When `update-problems` changes a leaderboard's eval (e.g. reference_kernels updates `eval.py`), all existing submission scores become stale/invalid. There's no way to distinguish "scored with old eval" from "scored with new eval," so stale scores pollute the leaderboard.

**Approach: task versioning**
- `task_version` integer column on both `leaderboard` and `runs` tables (default 1)
- When `update_leaderboard()` detects a task change, it bumps `task_version`
- All ranking queries now filter `r.task_version = l.task_version` — old scores are preserved but hidden from rankings
- New `POST /admin/backfill` endpoint re-runs top N submissions from previous versions against the new eval
- Backfill just queues into the existing `BackgroundSubmissionManager` — no new scheduling infra

**Usage:**
```bash
# After update-problems bumps the version:
curl -X POST "http://host:8000/admin/backfill" \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"leaderboard": "softmax_v2", "gpu": "H100", "top_n": 100}'
```
