## 正文

## Why

The comparison suite runs only on datacenter GPUs, and every case lists `sglang` as the sole framework. That leaves two gaps that matter for how this project is perceived:

- The one public claim a competitor makes about us — that SGLang-Diffusion OOMs on a consumer card — has nothing in the suite that answers it.
- **ComfyUI**, the engine consumer users actually run, was not a framework the runner could drive at all.

## What this adds

A ComfyUI adapter and a single-GPU MiniMax-H3 case sized for a 32 GB RTX 5090, at the parameters an earlier manual comparison established as apple-to-apple: 864×480, 124 frames, 20 steps, cfg 1.0, `euler_ancestral`, sigma shift 12.0 / 3.0, shared seed and prompt.

ComfyUI is a workflow engine rather than an OpenAI-compatible server, so the graph handling lives in `comfyui_adapter.py` and `run_comparison.py` only gains three dispatch entries. It is deliberately **not** in `INSTALLABLE_FRAMEWORKS`: it runs from its own checkout and virtualenv, referenced through `COMFY_ROOT` / `COMFY_PYTHON` so the committed case stays machine-agnostic.

## The three things that decide whether such a number means anything

1. **Weight parity.** ComfyUI's shipped H3 path is pruned + int8 with an NVFP4 text encoder, and it casts the text encoder to fp16 unless told otherwise — none of which is the lossless path SGLang runs. The case points at the unpruned bf16 repack and passes `--bf16-text-enc --bf16-unet`; a config missing those is reported at launch rather than silently benchmarked as if it were lossless.

2. **Schemas are read, not guessed.** Node classes, input names and enum values are checked against the live `/object_info` before submission, so a ComfyUI release that moves an input fails with the authoritative schema instead of an opaque validation error mid-run.

3. **Same host-memory horizon.** ComfyUI sizes its residency from `psutil.virtual_memory()`, so on a host with far more RAM than the deployment under comparison it keeps more resident and looks faster — measuring its circumstances, not its capability. An earlier experiment saw its anonymous footprint fall from 116 GiB to 30 GiB, and its loading strategy change, once it was shown a 32 GiB horizon. The horizon ships as a `sitecustomize` hook beside the harness and is put on `PYTHONPATH` **by the adapter**, not by per-machine configuration: an omitted hook does not fail, it quietly compares against a bigger machine.

## Tests

Four new unit tests in the existing nightly-comparison suite, covering exactly the properties above: the workflow carries the case's sampler parameters and leaks no documentation keys, schema validation names the accepted inputs when a node drifts, the launch environment always carries the hook, and missing bf16 parity flags are reported. `8 passed` locally on an H200 box.

## Not in this PR

No measured numbers yet — the 5090 host is currently out of disk. The harness change and the measurement are separable, and the parity machinery is the part worth reviewing on its own.
