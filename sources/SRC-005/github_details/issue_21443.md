### Motivation

## Problem

On Apple Silicon Macs, GPU and CPU share Unified Memory Architecture (UMA). Several places in SGLang use `psutil.virtual_memory().total` or `.available` to determine how much memory is available for model loading and KV cache allocation on the MPS device:

- **`python/sglang/srt/utils/common.py` – `get_available_gpu_memory()`** (line 604–605):
  ```python
  elif device == "mps":
      free_gpu_memory = psutil.virtual_memory().available
  ```
- **`python/sglang/_mps_stub.py` – `get_device_properties()`** (line 131–132):
  ```python
  _cached_props = _MPSDeviceProperties(
      total_memory=psutil.virtual_memory().total,
  )
  ```
- **`python/sglang/multimodal_gen/runtime/platforms/mps.py` – `MpsPlatform.get_available_gpu_memory()`** (line 86):
  ```python
  free_memory = psutil.virtual_memory().available
  ```

However, **Metal cannot use all of system RAM**. Apple exposes a per-device limit via [`MTLDevice.recommendedMaxWorkingSetSize`](https://developer.apple.com/documentation/metal/mtldevice/2369280-recommendedmaxworkingsetsize), which is typically **~65–75% of total RAM** depending on the chip and macOS version. Allocating beyond this limit causes the system to start paging GPU-resident memory, leading to:

- Severe performance degradation (GPU stalls waiting for page-ins)
- System instability
- **Machine reboots** (I have personally experienced this)

This was also flagged in a code review: *"What is our OOM behavior here? (I don't want you to OOM your Mac haha, but we should have a guardrail around this)"*

## Expected Behavior

Memory reporting for MPS should be capped to Metal's recommended max working set size, not the full system RAM. This ensures SGLang never tries to allocate more memory than the GPU subsystem can safely handle.

## Reference Implementation

The [vllm-metal plugin](https://github.com/vllm-project/vllm-metal) already handles this correctly using MLX's API:

```python
# vllm-metal/vllm_metal/utils.py
device_info = mx.metal.device_info()
max_wired = int(device_info.get("max_recommended_working_set_size", 0))
```

It also sets the wired memory limit to prevent paging:

```python
# vllm-metal/vllm_metal/utils.py
mx.set_wired_limit(max_wired)
```

And uses this value to cap prefix cache and KV cache budgets:

```python
# vllm-metal/vllm_metal/v1/model_runner.py
device_info = mx.metal.device_info()
total = int(device_info.get("max_recommended_working_set_size", 0))
max_bytes = int(total * fraction)
```
