## 正文

## Motivation

`encode_arguments_to_dsml()` in `python/sglang/srt/entrypoints/openai/encoding_dsv4.py` has no test coverage, and the behavior it implements has already been broken once.

When an assistant history message carries `tool_calls`, `normalize_assistant_tool_call_arguments()` (`serving_chat.py`) converts `function.arguments` from a JSON string into a dict *before* the encoder runs. If the encoder then collapses that dict into a single DSML parameter literally named `arguments`:

```
<｜DSML｜parameter name="arguments" string="false">{"path": "/tmp/b.txt"}</｜DSML｜parameter>
```

instead of expanding it per key:

```
<｜DSML｜parameter name="path" string="true">/tmp/b.txt</｜DSML｜parameter>
```

the model imitates that malformed in-context example on the next turn, and the returned tool call comes back double-wrapped:

```
expected: {"path": "/tmp/b.txt"}
actual:   {"arguments": {"path": "/tmp/b.txt"}}
```

Downstream executors then report the real parameter as missing and `arguments` as unexpected. The first turn is always clean, so this only surfaces in multi-turn agent loops.

`main` is **correct** today (fixed in #28035). This PR adds no production change — it only pins the behavior down, because a vendored-encoder branch has since reverted the same hunk (see #39277, #38450), and nothing in the test suite would have caught that.

## Modifications

Adds `TestEncodeArgumentsToDsml` to `test/registered/unit/entrypoints/openai/test_serving_chat.py`, covering:

- dict-valued `arguments` (the post-normalization shape) expand to one parameter per key
- JSON-string `arguments` expand to one parameter per key
- non-string values are marked `string="false"` and JSON-encoded
- empty `arguments` produce no parameters
- non-object `arguments` are rejected with `ValueError`

Every case asserts that `name="arguments"` does **not** appear in the output, which is the specific regression shape.
