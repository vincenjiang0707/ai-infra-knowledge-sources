## 正文

## Summary

This PR adds MiniMax-M3 DSpark speculative decoding support, using MiniMax-M3 as the target model and MiniMax-M3-DSpark as the draft model.

MiniMax-M3-DSpark is a draft-only model and cannot be served standalone. Pairing it with MiniMax-M3 requires integration across auxiliary hidden-state capture, the VL wrapper, TARGET_VERIFY metadata, MiniMax sparse-attention geometry, DP padding, and DFLASH/DSPARK configuration loading.

This PR connects those integration points while preserving the existing MiniMax-M3 EAGLE3 and NPU behavior.

## Modifications

### MiniMax-M3 target model

- Add `set_dspark_layers_to_capture()` to `MiniMaxM3SparseForCausalLM`.
- Reuse the existing EAGLE3 layer-capture implementation so DSpark and EAGLE3 apply the same `L -> L + 1` mapping and `_is_layer_to_capture` marking.
- Require explicit DSpark layer IDs to provide deterministic auxiliary hidden-state capture points.
- Guard tuple unpacking because warmup and idle forwards may return a plain hidden-state tensor rather than `(hidden_states, aux_hidden_states)`.

### MiniMax-M3 VL wrapper

- Add `set_dspark_layers_to_capture()` to `MiniMaxM3SparseForConditionalGeneration`.
- Reuse the same EAGLE3 layer-capture implementation.
- Forward captured auxiliary hidden states to the logits processor.
- Preserve plain-tensor handling for warmup and idle forwards.

### ForwardBatch TARGET_VERIFY metadata

- Add ragged TARGET_VERIFY metadata preparation for MLP synchronization.
- Populate `extend_seq_lens`, `extend_prefix_lens`, and `extend_start_loc` from `RaggedVerifyLayout`.
- Use `qo_indptr_device` as the graph-stable source of per-request start locations.
- Avoid reading replay-time verify lengths back from the GPU when no CPU mirror is available.
- Preserve and restore the original `ForwardBatch` metadata after MLP synchronization.
- Represent DP-padded request rows with zero-length verify geometry instead of treating them as real requests.
- Slice post-forward logits and hidden states using the real ragged token count when host metadata is available.

### MiniMax sparse attention

- Resolve `RaggedVerifyLayout` for TARGET_VERIFY and build sparse-attention geometry with `build_ragged_target_verify_geometry()`.
- Consume `geometry.cu_seqlens_q` and `geometry.cache_seqlens_int32` instead of reconstructing ragged geometry from a fixed request width.
- Continue using the regular `ForwardBatch.extend_*` path when explicit extend geometry is available.
- Restrict the fixed-width fallback to genuinely uniform, non-padded TARGET_VERIFY batches.
- Reject DP-padded or attention-TP sequence-sharded TARGET_VERIFY batches when per-request geometry is unavailable.
- Trim DP-padded `q` and `idx_q` rows before invoking the sparse kernel and restore the graph-sized output shape afterward.
- Use fixed query and context bounds during CUDA Graph capture to avoid deriving graph metadata from synthetic capture-time sequence lengths.
- Preserve the existing NPU sparse-attention paths, lazy GPU sparse-kernel import, index-cache behavior, and EAGLE3 compatibility.

### DFLASH / DSPARK configuration

- Read `sliding_window` from the local raw `config.json` when the loaded Transformers configuration exposes it as `None`.
- Reject `return_logprob` requests explicitly because DFLASH/DSPARK does not support that mode yet.
- Preserve MiniMax-M3-DSpark draft-model loading compatibility.

### Tests

Add unit coverage for:

- Rejecting DP-padded TARGET_VERIFY without per-request geometry.
- Rejecting sequence-sharded TARGET_VERIFY without per-request geometry.
- Building ragged sparse-attention geometry from per-request verify lengths.
- Trimming padded query rows before the sparse kernel and restoring the original output shape with zero padding.
- Handling explicit uniform `ForwardBatch.extend_*` geometry with zero-length padded rows.
- Reusing the EAGLE3 hidden-state capture setup for both the text and VL MiniMax-M3 wrappers.

## Error cases fixed

This PR addresses the following MiniMax-M3 + MiniMax-M3-DSpark serving failures:

```text
ValueError: DFLASH sliding_attention layers require config.sliding_window.
```

```text
ValueError: Model MiniMaxM3SparseForConditionalGeneration implements neither
set_dspark_layers_to_capture nor set_dflash_layers_to_capture, one of which is
required for DFLASH/DSPARK.
```

```text
AttributeError: 'NoneType' object has no attribute 'device'
```

```text
ValueError: DFLASH target_hidden feature dim mismatch. Expected shape
[N, 36864] (num_context_features=6, hidden_size=6144), but got
shape=(..., 6144).
```

```text
RuntimeError: CUDA error: operation failed due to a previous error during capture.
```

It also addresses the TARGET_VERIFY geometry issue raised during review:

- Ragged TARGET_VERIFY now obtains `cu_seqlens_q` from the per-request verify lengths through `build_ragged_target_verify_geometry()`.
- DP-padded batches use explicit per-request extend geometry when available.
- The MiniMax sparse backend fails fast instead of interpreting padded or sequence-sharded rows as uniform real requests.

### Two-node TP16 serving

Validated with MiniMax-M3 as the target model and MiniMax-M3-DSpark as the DSPARK draft model:

```bash
python3 -m sglang.launch_server \
  --model-path /models/MiniMax-M3 \
  --served-model-name MiniMax-M3 \
  --reasoning-parser auto \
  --tool-call-parser auto \
  --trust-remote-code \
  --tp-size 16 \
  --nnodes 2 \
  --node-rank <0-or-1> \
  --dist-init-addr 192.168.1.81:20000 \
  --speculative-algorithm DSPARK \
  --speculative-draft-model-path /models/MiniMax-M3-DSpark \
  --speculative-dspark-block-size 8 \
  --chunked-prefill-size 8192 \
  --mem-fraction-static 0.80 \
  --dtype bfloat16 \
  --host 0.0.0.0 \
  --port 31000
```
