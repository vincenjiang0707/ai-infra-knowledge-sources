## 正文

### Background

[NCCL 2.29–2.30.7](https://docs.nvidia.com/deeplearning/nccl/release-notes/rel_2-30-x.html) introduces NCCL EP (Expert Parallelism), a new communication primitive optimized for MoE workloads. This is part of the broader [Roadmap: Integrate NCCL 2.30 Features into SGLang](https://github.com/sgl-project/sglang/issues/TBD).

This issue tracks the first phase: integrating NCCL EP's low-latency decode path as an optional MoE A2A backend.

### Goals

1. Add optional `nccl4py[cu13]` packaging
2. Runtime capability detection (nccl4py importability, CUDA 13, SM ≥ 90)
3. Implement LL dispatch/combine for decode workloads
4. Correctness parity with Standard/DeepEP backends
5. Graceful fallback when NCCL EP is unavailable

### Scope

- **LL decode path only** (HT prefill is follow-up)
- **w4afp8 models only** (supported MoE compute path)
- **Hopper/Blackwell GPUs** (SM ≥ 90) + CUDA 13 + NCCL ≥ 2.29

### Known Limitations

- `hidden_size` must be in `{2048, 2560, 4096, 5120, 6144, 7168, 8192}`
- `topk ≤ 9` (models like Nemotron Super fall back to DeepEP)
- CUDA 13 only (cu12 falls back to DeepEP)

### Reference

- NCCL EP source: [`contrib/nccl_ep`](https://github.com/NVIDIA/nccl/tree/master/contrib/nccl_ep)
- DeepEP integration (reference pattern): #29402
