## Motivation

Full and sliding-window KV caches share a device byte budget under unified memory, but independently sized host pools cannot redistribute free capacity between them. This PR adds a shared host arena with stable logical page IDs, safe compaction, and coordinated allocation/reclaim. It also enables the supported unified-memory decode offload and host-pool retraction paths.

#39477 is merged. This branch now includes main through `91c329cc866957a4750a929d158978a3ac69f45d`, including #37507's unified-memory HiCache support. Its remaining changes build on that implementation.

## Modifications

- Back compatible Full/SWA page envelopes with one byte arena, growing from opposite ends. Compact physical pages while keeping cache-visible logical IDs stable, and allocate/reclaim related transfers together.
- Hold host-layout leases across asynchronous L2 transfers and synchronous L3 storage access so compaction cannot move pages still in use. Discover UMBP page sizes without dereferencing unallocated logical pages.
- Use #37507's transfer contract: keep Full IDs virtual until L2 submission, retain kernel-facing SWA IDs, wait for the producer event before translation, then resolve host and envelope indices under the layout lease. Preserve main's batched write submission and sparse-layer transfer bounds.
- Preserve main's host capacity and RAM-budget accounting. Use the shared arena only for compatible two-ended Full/SWA pools; retain the existing host implementations for tri-pool/GDN, packed draft, buffer-only, and other layouts.
- Enable unified MHA decode offload with file storage and supported host-pool retraction. Keep unsupported MLA offload, hybrid SWA/Mamba decode offload or retraction, and decode-radix host-pool retraction guarded. Unified hierarchical HiCache support from #37507 remains enabled.
