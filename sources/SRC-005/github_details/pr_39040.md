# [PR #39040] Fix/encdec decode paged alloc row offset

source: https://github.com/sgl-project/sglang/pull/39040
state: open | updated: 2026-09-23T03:17:32Z

## 正文

## Motivation
For encoder-decoder models the encoder KV is prepended to the request's
    req_to_token row, so decoder position L lives at row position
    encoder_len + L. `alloc_for_decode` already accounts for that when writing
    (locs = encoder_lens + seq_lens) but not when computing the paged
    allocation: last_loc was read at `row[seq_len - 1]` and the new-page
    decision used the encoder-stripped seq_len.

At page_size > 1 that makes `last_loc + 1` resolve to `row[L]` -- the slot
    already held by encoder position `L` -- so the row stops satisfying
    `row[j] == page[j // page_size] * page_size + (j % page_size)`. The paged
    free path relies on that invariant: free_segment() samples one page
    representative every page_size row entries, so an aliased row makes it
    name the same physical page twice and `available_size()` grows by one page
    per request until the idle pool-leak invariant aborts the scheduler.


## Modifications
Use the row length (encoder_lens + seq_lens) for last_loc, for the
    seq_lens handed to alloc_decode, and for the CPU mirror feeding
    `get_num_new_pages`. `page_size == 1` takes the non-paged branch before any
    of this runs, so default CUDA behaviour is unchanged, as is every
    non-encoder-decoder model.

## Accuracy Tests
Added: `test/registered/unit/mem_cache/test_encdec_paged_kv_page_accounting.py`

cc @hnyls2002 — this sits directly on machinery you built: free_segment's one-representative-per-page release (#32701, and #38159 most recently) assumes row[j] == P[j // page_size] * page_size + (j % page_size). For encoder-decoder models alloc_for_decode was doing its paged arithmetic on the encoder-stripped seq_lens while writing at encoder_lens + seq_lens, so at page_size > 1 decode slots aliased the encoder region and that invariant broke — free_segment then emitted the same page id twice and available_size() grew a page per request until the idle leak check aborted the scheduler. This fix restores the invariant.
