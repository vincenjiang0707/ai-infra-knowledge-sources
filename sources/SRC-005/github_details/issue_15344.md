# Context
In the previous milestone ([#5973](https://github.com/sgl-project/sglang/issues/5973), [#6460](https://github.com/sgl-project/sglang/pull/6460)), Our community introduced the Scoring API into SGLang with several key implementation and optimization PRs:
1. [Tokenizer] Batch Tokenization —[ #5141](https://github.com/sgl-project/sglang/pull/5141)
2. [Tokenizer] Dynamic Batch Tokenizer —[ #9382](https://github.com/sgl-project/sglang/pull/9382)
3. [ZMQ] Batch Send from Tokenizer Manager —[ #9436](https://github.com/sgl-project/sglang/pull/9436)
4. [Generative Score API] Remove Decode path —[ #8840](https://github.com/sgl-project/sglang/pull/8840)
5. [Generative Score API] Prefill-only optimizations —[ #9748](https://github.com/sgl-project/sglang/pull/9748)
6. [Benchmark] Prefill-only benchmarking scripts —[ #10240](https://github.com/sgl-project/sglang/pull/10240)
7. [Garbage Collection] Memory optimization —[ #9241](https://github.com/sgl-project/sglang/pull/9241)
8. [Generative Score API] Multi-item scoring with custom attention mask —[ #10979](https://github.com/sgl-project/sglang/pull/10979)

# Goal
Our goal is to make Prefill-only inference in SGLang a first-class, production-ready execution path for scoring and other non-generative workloads.
1. Usability – Offer a simple, consistent Scoring API across model types (e.g., CausalLM, SequenceClassification, Bert based).
2. Performance – Deliver predictable, high-throughput, low-latency Prefill-only execution via efficient batching, KV reuse, and cache-aware optimizations, while matching HuggingFace reference correctness.
