## 正文

# Summary

With `SGLANG_ENABLE_METRICS_DEVICE_TIMER=1`, the prefill and decode log lines reuse the `fwd_occupancy` gauge. That gauge is windowed over `decode_log_interval` batches and starts each window at NaN, so an isolated prefill logs `fwd occupancy: nan%`, and sparse decode traffic logs close to 100% even when the cumulative forward counter says the device was busy a small fraction of the wall time.

Add a separate log window that starts before its first forward, includes the idle gap that preceded it, and resets after `decode_log_interval` processed batches or on an active-to-idle transition. Repeated idle polls retain the idle gap for the next request. The log lines now report two values over the entire wall time since the window started:

- `fwd occupancy` = device forward seconds / wall seconds
- `fwd+idle occupancy` = (device forward seconds + scheduler idle seconds) / wall seconds

Both log paths poll completed device events before formatting; no device synchronization is added. Scheduler time accounting now also runs when only the device timer is enabled, so the log values work without `--enable-metrics`; the Prometheus counters and the `process_time_ns` sampling stay gated on `--enable-metrics`. The existing `fwd_occupancy` / `stats.fwd_occupancy` gauge keeps its timing, initialization, and NaN-at-idle behavior, so `sglang:fwd_occupancy` readers such as the sanity kit are unaffected.

The new window is a `msgspec.Struct` rather than a dataclass, per `.claude/rules/no-dataclasses.md`. No production caller changes; the change is one file.
