 The server loads weights successfully and starts serving, but crashes on the first decode batch when DSPARK speculative decoding is enabled. The crash occurs in the accept/verify path when top_k_renorm_prob is called but returns None instead of a callable function.

 The model loads fine and serves correctly without speculative decoding (removing the 4 DSPARK flags).

 Root cause (likely):

 top_k_renorm_prob in sglang/srt/speculative/dflash_utils.py line 784 is None at runtime. This suggests the function is conditionally imported or lazily initialized (possibly from a CUDA-only or Triton-only code path) and is not being set on
 ROCm, despite the Triton-based accept kernel being used.

 Workaround:

 Remove the DSPARK speculative decoding flags:
 - --speculative-algorithm DSPARK
 - --speculative-draft-model-path RadixArk/Kimi-K3-DSpark
 - --speculative-dspark-block-size 7
 - --enable-linear-replayssm-spec

 The server runs correctly without speculative decoding.
