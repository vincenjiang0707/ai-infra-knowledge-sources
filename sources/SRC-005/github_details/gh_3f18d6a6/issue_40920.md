## Open questions

- Rust server boundaries: should the rust frontend only take token ids in and out, leaving everything before and after to the renderer?
- Client or proxy: does the frontend call the renderer, or does the renderer sit in front? In the proxy shape the frontend never knows, it only ever sees rendered `GenerateRequest`s.
- Do we need shared `sglang-protocols` crates for the wire types, or can we just keep them in the renderer crate?
- Stop strings is the only(?) case where the rust frontend needs to be aware of the textual representation of token-ids. In case the rust frontend becomes TITO, where should that component sit, and how the rust server interacts with it every turn?

## Notes

1. HTTP and grpc wire types stay dumb DTOs. Boundary mapping lowers them to protocol structs, where the logic lives (following #36923).
2. New endpoints don't need their own version of chat. They lower to it, the way python's anthropic layer already does.
3. Media crosses as ids and hashes, and the heavy tensors can be built later where they are needed.
