## 正文

## Motivation and scope

The Qwen3 cookbook lacks Ascend NPU deployment recipes. This adds seven selectable combinations: four A3 8B/30B-A3B recipes, A2 TP4 recipes for 32B BF16 and W8A8, and an A2 TP8 candidate for 235B W8A8. Related task: https://github.com/Ascend/sglang/issues/1216.

**Draft:** six recipes have measured performance. Five recipes have verified accuracy: A3 8B low latency, both A3 30B recipes, and both A2 32B recipes. A3 8B TP1 GPQA retesting and 235B hardware validation remain pending.

- Provide editable checkpoint paths, interfaces, service settings, and startup, inference, accuracy, and performance commands; require a draft checkpoint only when EAGLE3 is enabled.
- Label physical cards and logical NPU devices explicitly: one device per A2 card, two per measured A3 card. The shared component supports per-NPU throughput while preserving GPU defaults and hides the disabled Playground submission hint.
- Keep 235B BF16 outside the single-node selector: it requires two interconnected eight-card A2 nodes and storage for approximately 470 GB of weights. The 235B W8A8 recipe remains an untuned eight-card candidate.
- Document the 32B W8A8 source discrepancy: its A2 title says two cards but its command launches TP4; this recipe requires four actual A2 devices.

## Runtime and checkpoints

Documentation and A2 runs use SGLang source `b44e2486824e2fbde9cbcb09adad10bce5593c16`. A3 measurements are from **2026-09-12**, source `c389dd086340878934bf96bc209534f1fbb8440c`; A2 BF16 and the final W8A8 GPQA evaluation completed on **2026-09-23**. A3 results are not measurements on the newer documentation base.

- **A3:** one physical card exposing two 64 GB devices; CANN 9.0.0, PyTorch 2.10.0+cpu, torch-npu 2.10.0, sgl-kernel-npu 2026.9.0, triton-ascend 3.2.1.dev20260530, Transformers 5.8.1.
- **A2:** four 64 GB Ascend 910B3 devices; CANN 9.0.0, torch/torch-npu 2.10.0, official 910B/aarch64 kernel 2026.9.0, Transformers 5.12.1, memfabric-hybrid 1.1.4, memfabric-zbal 1.1.2. BF16 uses `--max-running-requests 8 --cuda-graph-bs-decode 1 2 4 8`, without EAGLE3. No additional host tuning was applied.
- **Checkpoints (main + draft):** 8B: `vllm-ascend/Qwen3-8B-w8a8` + `Zjcxy-SmartAI/Eagle3-Qwen3-8B-zh`; 30B: `Eco-Tech/Qwen3-30B-A3B-w8a8` + `vllm-ascend/Qwen3-a3B_eagle3`; 32B W8A8: `vllm-ascend/Qwen3-32B-W8A8` + `Zjcxy-SmartAI/Eagle3-Qwen3-32B-zh`; 32B BF16: `Qwen/Qwen3-32B`. A2 downloads passed recorded size/SHA-256 checks.

The 30B workloads share one accuracy run. GSM8K excludes five prompt examples from 1,319 rows; all scored responses were nonempty with valid answer extraction. BF16 had no API errors, with 1136 `stop` and 178 `length` outcomes; all truncations remain scored. AIME had 27 `stop` and three actual `max_tokens` truncations, with all 30 requests successful. Recorded A3 GPQA/AIME used EvalScope 1.11.1, seed 42, and client concurrency 64/16.

**GPQA correction:** both historical 40,000-budget attempts rejected index 127 because 2,829 input tokens plus 40,000 requested output tokens exceeded the 40,960 context limit. EvalScope produced a synthetic `model_length` result with `error=null`; this was not an ordinary output truncation. The scores retain all 198 questions, including the failed request. The earlier A3 claim of 198 successful requests is corrected to 197. Public examples now use 38,000; neither historical score validates that revised protocol. The independent full A2 rerun completed with 198 HTTP 200 responses, 198 `stop` outcomes, no rejections, and no empty final answers. Its 132/198 result is reported separately without splicing or selecting the higher historical score. The changed output budget and stochastic sampling do not establish a controlled accuracy regression. A3 requires its own retest when resources are available.
