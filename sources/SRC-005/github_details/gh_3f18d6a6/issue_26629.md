# [Issue #26629] [Bug] FlashInfer MIS silently overflows uint16 item positions for >65k-token items

state: closed | updated: 2026-09-23T20:52:27Z

## 正文

### Summary

FlashInfer Multi-Item Scoring (MIS) appears to silently overflow item-position metadata when any scored item is longer than 65,535 tokens.

In `python/sglang/srt/layers/attention/flashinfer_backend.py`, `_process_multi_item_scoring` casts per-item positions to `torch.uint16`, and `max_item_len_ptr` is also built as `uint16`. For a 70k-token scored item, positions wrapped from `65535` back to `0`, the request still returned HTTP 200, and MIS scores diverged materially from the identical non-MIS scoring run.

If FlashInfer requires uint16 metadata here, this looks like a missing validation/fallback bug in SGLang. If FlashInfer supports wider metadata, this looks like a correctness bug in SGLang's MIS metadata construction.

Below-boundary item did not wrap:

token_pos_prepad dtype=torch.uint16 min=0 max=65000

### Score comparison

Below-boundary MIS roughly matched non-MIS:

```text
non-MIS [item_below]: [8.390536297405524e-10, 4.653219071241521e-08]
MIS     [item_below]: [7.075681511711238e-10, 3.9858220603823486e-08]
max_abs_diff: 6.673970108591723e-09
```

Above-boundary MIS materially diverged, while non-MIS returned normally:

```text
non-MIS [item_long]: [1.1668274457666609e-09, 5.28146429567152e-08]
MIS     [item_long]: [4.873932399926735e-10, 2.2988196753904577e-07]
max_abs_diff: 1.7706732458233056e-07
```

The second label score was about `4.35x` larger in MIS than in non-MIS for the 70k-token item.

The mixed MIS request completed in a separate run and returned scores, while logging the same uint16 truncation:

```text
scores=[[1.3688256846912624e-06, 4.630677602424308e-06], [4.580356498790701e-10, 2.0294656015981385e-07], [1.458230590824044e-06, 4.634247233474888e-06]]
```

### Expected behavior

SGLang should not silently produce wrapped MIS metadata for an item longer than 65,535 tokens.

Possible fixes, depending on the FlashInfer contract:

- If FlashInfer requires uint16 item-position metadata, validate item lengths before MIS metadata construction and reject the request or fall back to non-MIS for any item longer than 65,535 tokens.
- If FlashInfer supports wider metadata, construct `token_pos_in_items_ptr` / `max_item_len_ptr` using a sufficiently wide dtype instead of `uint16`.

### Existing issue/PR search

I searched open and closed issues/PRs for:

- `token_pos_in_items_ptr uint16`
- `max_item_len_ptr uint16`
- `Multi-Item Scoring 65535`
- `enable_mis long context`

I did not find an existing bug report. The only relevant hit I found was the merged MIS implementation PR, https://github.com/sgl-project/sglang/pull/10979, which documents the MIS metadata fields as uint16 but does not cover this overflow case.
