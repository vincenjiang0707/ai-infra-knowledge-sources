### Describe the bug

Enabling `--enable-expert-distribution-metrics` on a MoE model served with EAGLE/MTP speculative decoding and `--speculative-num-steps >= 2` crash-loops the server during startup CUDA-graph capture:

```
torch.AcceleratorError: CUDA error: operation not permitted when stream is capturing   (cudaErrorStreamCaptureUnsupported)
→ CUDA error: operation failed due to a previous error during capture                  (cudaErrorStreamCaptureInvalidated)
→ Exception: Capture cuda graph failed
```

The identical configuration with `--speculative-num-steps 1` starts and serves fine (explanation below). Observed in production on v0.5.15.post1 (GLM-5.2 NVFP4 quant, 8×B200, TP8, EAGLE steps=3 / topk=1 / draft-tokens=4, using GLM's built-in MTP layer as the draft). The involved code is unchanged on `main` @ `108a183f6b` — all permalinks below point there.

#### Root cause

1. `--enable-expert-distribution-metrics` auto-starts recording at recorder construction ([expert_distribution.py#L161-L165](https://github.com/sgl-project/sglang/blob/108a183f6bdd2035e649f6812c17ddb3193ebd65/python/sglang/srt/eplb/expert_distribution.py#L161-L165); the flag alone auto-sets `expert_distribution_recorder_mode="stat"`, [server_args.py#L5454-L5458](https://github.com/sgl-project/sglang/blob/108a183f6bdd2035e649f6812c17ddb3193ebd65/python/sglang/srt/server_args.py#L5454-L5458)). The recorder is created by the target `ModelRunner.initialize()` ([model_runner.py#L677-L683](https://github.com/sgl-project/sglang/blob/108a183f6bdd2035e649f6812c17ddb3193ebd65/python/sglang/srt/model_executor/model_runner.py#L677-L683)) and shared process-globally, so it is already recording when the scheduler later captures the spec-decode graphs (`init_tp_model_worker` → `maybe_init_draft_worker` → `init_all_cuda_graphs`, [scheduler.py#L850-L857](https://github.com/sgl-project/sglang/blob/108a183f6bdd2035e649f6812c17ddb3193ebd65/python/sglang/srt/managers/scheduler.py#L850-L857)).
2. EAGLE draft graph capture drives the **full `ModelRunner.forward`** inside the capture: `EagleDraftCudaGraphRunner.capture_one_shape` → `run_once()` → `eagle_worker.draft_forward` ([eagle_draft_cuda_graph_runner.py#L430-L450](https://github.com/sgl-project/sglang/blob/108a183f6bdd2035e649f6812c17ddb3193ebd65/python/sglang/srt/speculative/eagle_draft_cuda_graph_runner.py#L430-L450)), and `draft_forward` calls `self.draft_runner.forward(forward_batch)` once per draft step, breaking before the forward on the last step ([eagle_worker_v2.py#L654-L694](https://github.com/sgl-project/sglang/blob/108a183f6bdd2035e649f6812c17ddb3193ebd65/python/sglang/srt/speculative/eagle_worker_v2.py#L654-L694)). So `speculative_num_steps >= 2` ⇒ at least one full `ModelRunner.forward` inside the capture (`torch.cuda.graph` context in [full_cuda_graph_backend.py#L89-L114](https://github.com/sgl-project/sglang/blob/108a183f6bdd2035e649f6812c17ddb3193ebd65/python/sglang/srt/model_executor/runner_backend/full_cuda_graph_backend.py#L89-L114)).
3. `ModelRunner.forward` wraps every forward in `with_forward_pass(...)` — its only call site, not gated on `is_draft_worker` ([model_runner.py#L3002-L3024](https://github.com/sgl-project/sglang/blob/108a183f6bdd2035e649f6812c17ddb3193ebd65/python/sglang/srt/model_executor/model_runner.py#L3002-L3024)) — which runs `_on_forward_pass_start` / `_on_forward_pass_end` ([expert_distribution.py#L193-L207](https://github.com/sgl-project/sglang/blob/108a183f6bdd2035e649f6812c17ddb3193ebd65/python/sglang/srt/eplb/expert_distribution.py#L193-L207)).
4. The pass-end bookkeeping is not capture-safe. With metrics enabled, `_UtilizationRateAccumulatorMixin._append_utilization_rate` performs a rank-0 GPU→CPU sync — `utilization_rate_gpu.item()` ([expert_distribution.py#L746](https://github.com/sgl-project/sglang/blob/108a183f6bdd2035e649f6812c17ddb3193ebd65/python/sglang/srt/eplb/expert_distribution.py#L746)) — which raises `cudaErrorStreamCaptureUnsupported` and invalidates the capture. The production traceback below shows this frame exactly. (The `torch.distributed.reduce` at [#L729](https://github.com/sgl-project/sglang/blob/108a183f6bdd2035e649f6812c17ddb3193ebd65/python/sglang/srt/eplb/expert_distribution.py#L729) executed without raising first — but a default-PG collective plus the accumulator buffer writes at the pass boundary would in any case be baked into the draft graph and replayed on every draft step, which is not intended either.)

#### Why `--speculative-num-steps 1` is unaffected

`draft_forward` breaks before the forward on the last step ⇒ zero in-capture `ModelRunner.forward` calls. The draft-extend capture invokes the bare `model.forward` ([eagle_draft_extend_cuda_graph_runner.py#L422](https://github.com/sgl-project/sglang/blob/108a183f6bdd2035e649f6812c17ddb3193ebd65/python/sglang/srt/speculative/eagle_draft_extend_cuda_graph_runner.py#L422)), as do the decode and prefill graph runners — so the recorder pass boundary never runs inside those captures. We ran a steps=1 fleet with metrics enabled for days without issue while the steps=3 fleet crash-looped on every start.

#### Workarounds

- Drop `--enable-expert-distribution-metrics` (the mitigation we run in production), or
- `--speculative-num-steps 1`.

#### Proposed fix

Skip the forward-pass boundary while a stream capture is active, mirroring `_on_hook`, which is already capture-aware by design ([expert_distribution.py#L235-L247](https://github.com/sgl-project/sglang/blob/108a183f6bdd2035e649f6812c17ddb3193ebd65/python/sglang/srt/eplb/expert_distribution.py#L235-L247)): per-layer hooks intentionally stay active during capture so the captured graphs keep accumulating into the gatherer buffers at replay — only the pass-boundary bookkeeping (reset / collect / accumulator append with its collective + host sync) must be skipped. There is same-file precedent for keeping recorder bookkeeping out of draft capture: `disable_routed_experts_capture_for_draft` ([model_runner.py#L707-L710](https://github.com/sgl-project/sglang/blob/108a183f6bdd2035e649f6812c17ddb3193ebd65/python/sglang/srt/model_executor/model_runner.py#L707-L710)). PR incoming.

Alternatives considered: deferring the auto `start_record()` until after startup capture fixes only this instance (any future in-capture `ModelRunner.forward` would regress) and changes when recording starts; wrapping `draft_forward` in `disable_this_region()` would also silence per-layer hooks for EAGLE3 MoE draft models, changing recorded data.

#### Side notes (kept out of the fix PR to stay minimal)

- `_append_utilization_rate` has a stray debug `print(f"hi {self._rank=} {utilization_rate_gpu=}")` on the `SGLANG_ENABLE_EPLB_BALANCEDNESS_METRIC` path ([expert_distribution.py#L740](https://github.com/sgl-project/sglang/blob/108a183f6bdd2035e649f6812c17ddb3193ebd65/python/sglang/srt/eplb/expert_distribution.py#L740)); formatting the device tensor syncs too, so that branch would invalidate the capture the same way.
- Eager (non-captured) draft forwards also run the pass boundary, and for NextN/MTP drafts the per-layer hooks are suppressed via `disable_this_region()` ([glm4_moe_nextn.py#L105](https://github.com/sgl-project/sglang/blob/108a183f6bdd2035e649f6812c17ddb3193ebd65/python/sglang/srt/models/glm4_moe_nextn.py#L105), [deepseek_nextn.py#L232](https://github.com/sgl-project/sglang/blob/108a183f6bdd2035e649f6812c17ddb3193ebd65/python/sglang/srt/models/deepseek_nextn.py#L232)) — so those passes record all-zero data into the balancedness history/windows. Pre-existing data-quality quirk; possibly worth gating `with_forward_pass` on `is_draft_worker` as a follow-up.

### Reproduction

Any MoE model with an MTP/EAGLE draft should reproduce. Observed with GLM-5.2 (NVFP4) on 8×B200:

```
python -m sglang.launch_server \
  --model <GLM-5.2 NVFP4 checkpoint> --tp 8 \
  --speculative-algorithm EAGLE --speculative-num-steps 3 \
  --speculative-eagle-topk 1 --speculative-num-draft-tokens 4 \
  --enable-expert-distribution-metrics --expert-distribution-recorder-mode stat
```

Crash-loops in "Capturing batches (...)" during startup. Dropping `--enable-expert-distribution-metrics` or setting `--speculative-num-steps 1` avoids it.

### Environment

sglang v0.5.15.post1 (cu130 build; code path identical on `main` @ `108a183f6b` by inspection), Python 3.12, 8×NVIDIA B200 (TP8), GLM-5.2 NVFP4 with the built-in MTP layer as EAGLE draft, EAGLE worker v2.
