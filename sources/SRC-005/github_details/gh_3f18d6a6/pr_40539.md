# [PR #40539] [DCP] Add fi_a2a_fused comm backend using FlashInfer's fused A2A + LSE reduce

## 正文

## What

`a2a` and `fi_a2a` exchange DCP head partials and then merge them with a separate
Triton LSE kernel, so every MLA layer round-trips the partials through global memory
between two launches.
[flashinfer#4929](https://github.com/flashinfer-ai/flashinfer/pull/4929) does both in
one cooperative kernel over NCCL LSA symmetric memory. This exposes it as
`--dcp-comm-backend fi_a2a_fused`.

The send layout is unchanged — `fi_a2a` already packs `partial_o` as
`[B, H_per_rank, cp_size, D]`, which is what the fused op consumes — so the
`dcp_lse_combine_triton` call simply goes away.

## Status — draft, blocked upstream

1. flashinfer#4929 is unmerged (targets 0.7.0).
2. It needs two PyTorch-`main`-only APIs, absent from torch 2.13.0:
   `NCCL_HAS_DEVCOMM` (`c10d/symm_mem/nccl_dev_cap.hpp`) and
   `NCCLSymmetricMemory::get_window_offset()`.

Worth knowing: the first failure is silent. `dcp_lse_reduce.cu` guards its whole body
on `#ifdef NCCL_HAS_DEVCOMM`, so without the macro the op compiles, registers, and only
fails at the first call. Defining it by hand moves the failure to nvcc
(`no member "get_window_offset"`). NCCL is not the blocker — the images already ship
2.29.7.

The backend is therefore **explicit-only**: the resolver is untouched, so an unset
`--dcp-comm-backend` still resolves to `fi_a2a`/`a2a`/`ag_rs` and no existing
deployment changes behaviour.

## Notes

- New value rather than changing `fi_a2a` in place, so the validated MNNVL path stays
  byte-identical and the two can be A/B'd.
- The fused op allows one workspace per ordered CUDA stream, and rendezvous is
  collective and not graph-capturable — so workspaces are allocated upfront and handed
  out per stream (eager + the global capture stream). PDMUX needs more and raises.
- fp8 rejected at init: `a2a` tolerates it by shipping partials as opaque bytes; the
  fused kernel reduces in place and has no fp8 path.

## Tests

- `test_dcp_fi_a2a_fused_equivalence.py` (torchrun) — dcp ∈ {2,4,8} × {bf16, fp16} ×
  {base-2, base-e}, fused vs an all-gather + `dcp_lse_combine_triton` reference at
  `rtol=1e-2, atol=1e-3`. Skips when the op is unavailable.
- `test_server_args.py` — the new choice, explicit-only resolution, rejection rules.

## Benchmarks

**TBD** — not measurable until the dependencies land. Planned: 8×B200,
DeepSeek-V2-236B, tp8 = dcp8, ctx 256K; GSM8K at `--parallel 1` before each sweep,
median TPOT at cc 1/2/4, plus 20-step nsys captures.

For calibration: flashinfer#4929's 9.5–14.7× is against *unfused* NCCL a2a (roughly
this repo's `a2a`, which is launch-bound). The honest baseline here is `fi_a2a`, whose
MNNVL kernel is already ~6.85 µs — so the win is just the removed Triton combine.
