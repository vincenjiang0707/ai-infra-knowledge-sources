# [Issue #32200] [Feature] NCCL SYMM: Add one-sided RMA support

## 正文

## Motivation

NCCL 2.29–2.30 adds one-sided RMA on top of symmetric memory: `ncclPutSignal` pushes data into a peer's registered window and signals, `ncclWaitSignal` waits for it — data movement runs on the NCCL proxy, not a collective kernel, reducing SM contention during TP all-reduce / EP all-to-all.

SGLang's SYMM stack only wired the window-registration half (`ncclCommWindowRegister`/`Deregister`, the `SymmetricMemoryContext` allocator, the TP collective fast path). The RMA primitives (`ncclPutSignal`/`ncclSignal`/`ncclWaitSignal`/`ncclWinGetUserPtr`/`ncclGetPeerDevicePointer`) are unbound and registered window handles are discarded, so no code path can issue an RMA op today.

## Proposal

- Bind the RMA primitives + `ncclMemAlloc`/`ncclMemFree` + `ncclCommInitRankConfig` via ctypes, gated on symbol presence + NCCL ≥ 2.30.
- Surface registered window handles from the symmetric-memory allocator so a peer's handle can be passed to `ncclPutSignal`.
- Add `NcclRmaCommunicator` with an all-rank warm-up: symmetric buffer + window register + handle allgather + ring `put_signal`/`wait_signal` handshake with verification. Skip (leave `rma_available=False`) when NCCL returns a NULL handle (no NVLink / vGPU).
