## 正文

### Motivation
Pipeline parallelism is an important feature that can effectively reduce Long Context (e.g., 1M input tokens) TTFT, and it is also a promising optional parallel strategy for improving throughput.

### Pipeline Parallelism Roadmap
 - [x] Long context prefill + PD Disaggregation @ShangmingCai @XucSh @alpha-baby @whybeyoung
   - [x] Achieve almost linear scaling by doing chunked pipeline parallelism with prefill on a long context (e.g., 1M)
   - [x] Compatible with different tp degree on decode (e.g., PP8TP8 on prefill +TP4 on decode, PP8TP1 on prefill + TP8 on decode)
 - [ ] High throughput decoding @ShangmingCai  @bluecoffee8 


***
Currently, SGLang has supported Pipeline parallelism (https://github.com/sgl-project/sglang/pull/5724) in the main branch, and also made it compatible with the PD Disaggregation feature (https://github.com/sgl-project/sglang/pull/8846), but the implementation is not perfect, and there remains a lot of space for performance improvements. In other words, there still exist many pipeline bubbles (e.g., GPU's idle time) in the whole cluster for the current implementation.

To reduce PP bubbles, the refactoring works can be divided into the following sub-tasks:

### Refactoring the PP communication strategy

- [x] Use async send for PP stages communication in the new event loop (proposed by @alpha-baby  in #7979, adapted in the implementation of the new PP event loop by @merrymercy)
- [x] Use async micro batch buffer and async P2P communication to allow overlapping the GPU computation and CPU processing, and avoid the last PP rank staggler (done by @merrymercy)
- [x] Adapting the new event loop in the main branch @XucSh @ShangmingCai  https://github.com/sgl-project/sglang/pull/11852
- [x] Detailed profiling and performance evaluation @whybeyoung @alpha-baby 
- [x] Reduce bubbles by reordering and minimizing the communication-related overhead and CPU stalls  @ShangmingCai @XucSh @alpha-baby 

### Make new disagg prefill event loop compatible with PD Disaggregation

- [x] Adapting the new event loop in the main branch @ShangmingCai @XucSh 
- [x] Reduce bubbles by reordering and minimizing the communication-related overhead and CPU stalls @alpha-baby @ShangmingCai @XucSh 
- [x] Reduce bubbles with Dynamic Chunking @ShangmingCai @XucSh @whybeyoung @bluecoffee8  https://github.com/sgl-project/sglang/pull/11852
- [x] Doc about usage of dynamic chunking https://github.com/sgl-project/sglang/pull/14985 https://github.com/sgl-project/sglang/pull/16630
