## 正文

## Motivation

A selective rerun currently executes all tests sharing a runner/install configuration in one job. The five unified-cache files in [this run](https://github.com/sgl-project/sglang/actions/runs/35306615118/job/105480010351) exhausted the 60-minute test-step timeout after the first four files passed. The same combination also timed out in runs 35108771902 and 34695253228.

## Modifications

Keep one workflow run per dispatch configuration and partition its commands into independent matrix jobs before execution. A lightweight hosted job statically reads test registrations from the requested revision and packs commands into partitions of at most 40 estimated minutes. Unknown-duration and individually oversized tests run alone; multiple registrations use the largest estimate conservatively. No test modules are imported.

CUDA, CPU, and multimodal jobs consume their partition's commands with `fail-fast: false`. The finalizer waits for the matrix jobs and reports their aggregate result through the existing reply marker. Coredump artifact names include the partition ID. The precision-baseline refresh guard continues to validate the original full input.

The reported combination becomes two jobs in one run: four files totaling 2,036 estimated seconds and DSV4 KL totaling 1,865 seconds. Direct workflow dispatches receive the same partitioning. The hard 60-minute test-step limit remains; estimates cannot guarantee that an individual test finishes before it.

## Accuracy Tests

No inference changes. Local checks exercised the actual five-file combination, command preservation, exact budget boundaries, unknown/oversized tests, CPU positional registration, multiple registrations, selectors, empty inputs, the matrix-size limit, and the real CLI output consumed by the workflow. Workflow wiring, actionlint, Ruff, isort, the job-name checker, and `git diff --check` passed. No test files or documentation changes are included. The fork PR runs exercised the test code but used the workflow from main, so they did not validate the matrix partitioning. Validation through `/rerun-group radix_cache/unified_radix_tree` on this upstream branch confirmed that [prepare-partitions succeeds and creates two CUDA matrix jobs](https://github.com/sgl-project/sglang/actions/runs/35751395868): partition 1 contains linker DSV4, HiCache PP, CP, and Mamba; partition 2 contains DSV4 KL alone. GPU execution is still pending/in progress; this confirms partition generation and workflow wiring, not full GPU test success.
