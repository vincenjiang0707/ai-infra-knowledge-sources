## Motivation

On PD prefill workers, the first output reports `completion_tokens=0` while the per-request baseline starts at 1. The resulting negative delta reached `sglang:inter_token_latency_seconds` through the default histogram path, which writes bucket internals directly, and left negative bucket counts and sums. Negative, non-monotonic buckets break `histogram_quantile` and `rate()`. A decrease in reported tokens on decode workers had the same effect. Aborted requests with no output also recorded a TTFT sample.

## Modifications

- `metrics_collector.py`: `observe_inter_token_latency` ignores token weights `<= 0`. This is the single guard; the caller no longer checks too.
- `tokenizer_manager.collect_metrics`:
  - PD prefill workers never observe ITL.
  - TTFT is skipped only when the finish reason is an abort. Embedding, reward, and classify requests, and `max_new_tokens=0` scoring, still record TTFT.
  - The existing baseline reset on a token-count decrease is kept; the comment now describes only that case.

## Tests

Added `TestTokenizerLatencyAccounting` to `test/registered/unit/observability/test_ray_wrappers.py`, reusing its collector fixture on the default (`_histogram_cls = None`) path. 3 methods:
- TTFT is skipped only for aborts (subtests: abort on null and decode roles; embedding and zero-output requests still record);
- prefill never observes ITL (every bucket and the sum stay 0);
- a token-count decrease resets the baseline (all samples non-negative, count 2).

On `main`, all three fail: the abort subtests record TTFT, and the other two produce negative buckets (`-2` and `-8`). The embedding and zero-output subtests failed on the previous `completion_tokens > 0` gate. `test_ray_wrappers.py` passes: 36 tests.
