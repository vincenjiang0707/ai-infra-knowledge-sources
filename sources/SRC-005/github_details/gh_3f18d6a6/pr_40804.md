# [PR #40804] [RL] Keep DSA cuda-graph state and the graph pool intact across TMS pause/resume

source: https://github.com/sgl-project/sglang/pull/40804
state: open | updated: 2026-09-23T04:04:16Z
labels: run-ci

## 正文

## Motivation

In RL colocation the engine releases the `GPU_MEMORY_TYPE_CUDA_GRAPH` torch-memory-saver region while the trainer runs and resumes it before the next rollout. Two things break on main:

1. The full-cuda-graph pool holds capture-time-initialized device state that replays read but never rewrite. Pausing discards it, so the first replay after resume reads garbage.
2. DSA's wide `page_table` (`max_num_tokens x max_ctx_len` int32) and the flashmla metadata stay resident during training even though they are rewritten in full before every replay.

## Modifications

- `FullCudaGraphBackend`: pass `enable_cpu_backup=True` to the memory-saver `cuda_graph` context so the pool is backed up on pause and restored on resume.
- `DeepseekSparseAttnBackend.init_cuda_graph_state`: allocate `page_table` and `flashmla_metadata` inside the pausable cuda-graph region (gated on `--enable-memory-saver` and `SGLANG_MEMORY_SAVER_CUDA_GRAPH`). The other decode metadata is written once at init and stays outside the region.

Squash of sglang-miles #32718, #33479 (authors credited as co-authors).
