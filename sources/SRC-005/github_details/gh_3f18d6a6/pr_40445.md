# [PR #40445] [NPU] Fuse FIA KV-cache K/V writes into one npu_scatter_pa_kv_cache call

source: https://github.com/sgl-project/sglang/pull/40445
state: open | updated: 2026-09-23T06:11:23Z
labels: npu, run-ci

## 正文

## Motivation
On the NPU FIA path ( ASCEND_USE_FIA=1 ), NPUMHATokenToKVPool.set_kv_buffer writes K and V into the paged KV cache with two separate npu_scatter_nd_update_ kernels — one per tensor, indexed by the same out_cache_loc . That is two kernel launches per layer on the decode critical path.

MiMo-V2.5-Pro EP6 decode profiling (msprof, DeepEP LL, 57 MoE layers) shows the two aclnnScatterNdUpdate kernels cost ~11.1us/layer.

torch_npu provides npu_scatter_pa_kv_cache , which writes both K and V in a single kernel .

## Modifications
- environ.py : add SGLANG_NPU_USE_SCATTER_PA_KV_CACHE (default False )
- memory_pool_npu.py : gate the FIA branch of set_kv_buffer on the env var —
  - enabled: single npu_scatter_pa_kv_cache call (K+V in one kernel, cache_mode="Norm" )
  - disabled: the original two npu_scatter_nd_update_ calls, unchanged (fallback for older torch_npu/CANN or explicit opt-out)
- guards: fail loudly when the installed torch_npu lacks the op, and when the store dtype is outside the op's fp16/bf16/int8 contract
- slot_mapping is passed through in its native dtype (int32 or int64): the op accepts both, and the prefill/spec paths deliver int64 out_cache_loc — an unconditional .to(int32) would add a per-layer cast kernel, partially defeating the fusion

## Accuracy Tests
Bit-identical by construction — same flat-slot indexing, and verified at two levels on Ascend:

1. Op level : npu_scatter_pa_kv_cache vs two npu_scatter_nd_update_ writing the same K/V into identical paged buffers, with cross-page slot targets (page_size=4, slots spanning multiple pages) — final buffers torch.equal in both K and V
2. Pool level : full NPUMHATokenToKVPool constructed with ASCEND_USE_FIA=1 , set_kv_buffer executed with the gate off vs on (with an int64 loc , matching the dtype the prefill/spec paths deliver), all layer K/V buffers compared torch.equal — identical
3. int64 slot_mapping : verified the op accepts int64 indices directly and produces identical buffers vs the int32 form

## Speed Tests and Profiling
msprof on the MiMo-V2.5-Pro workload (per-layer kernel averages, same column units):

| | before | after |
|---|---|---|
| KV-cache write | 2× `aclnnScatterNdUpdate` ≈ 12.6 | 1× `aclnnScatterPaKvCache` = 3.5 |

~9us/layer saved on the write path (one launch instead of two, plus a cheaper fused kernel)
