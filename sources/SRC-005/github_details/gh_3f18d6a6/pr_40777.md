# [PR #40777] [RL] Add RL weight-update sessions and support updating spec draft runners

source: https://github.com/sgl-project/sglang/pull/40777
state: open | updated: 2026-09-23T06:38:02Z
labels: documentation, run-ci

## 正文

## Motivation

Port the sglang-miles weight-update core to main as its final state. On main the draft-runner handling in `SchedulerWeightUpdaterManager` guesses the runner layout through `getattr` chains, each weight path enumerates draft runners its own way (tensor through per-worker overrides, disk/IPC through `draft_runners`), `update_weights_from_distributed` never reaches the draft model, and a refit never re-runs `process_weights_after_loading`: `update_weights_from_{tensor,distributed}` only call `model.load_weights`, so any format whose postprocess changes layout (Marlin repack, MXFP8 shuffles, NVFP4 swizzles) is left in checkpoint layout under kernels that expect the processed one. Schemes whose kernel layout also changes parameter shapes (compressed-tensors W4A16 MoE on Marlin) additionally need a restore before the checkpoint-format values can be loaded.

## Modifications

- `begin_weight_update` / `end_weight_update` session RPCs (HTTP, `Engine`, `HttpServerEngineAdapter`, `TokenizerManager` under the pause-aware writer lock). `begin` restores in-place-packed weights to a loadable state; `end` finalizes quantized weights into kernel layout, and runs `post_load_weights` only when no weights were loaded through the engine during the session (P2P/RDMA writes). One session spans many buckets, so finalize runs once per refit.
- **One runner enumeration for every weight op.** `weight_update_runners()` returns `(role, ModelRunner)` pairs; the scheduler's `_select_runners(selector)` concatenates the target's and the draft's, and disk, IPC, tensor, distributed, check and begin/end all iterate it. The worker-level `update_weights_from_*` methods on `BaseTpWorker`, `BaseSpecWorker`, `EAGLEWorkerV2`, `NGRAMWorker` and `UnoWorkerV2` are removed.
  - `BaseSpecWorker.weight_update_runners()` derives from `draft_worker.draft_runners` (#31078), so EAGLE, Standalone and FrozenKV MTP need no override. It is defined on the base rather than abstract: DFlash, DSpark and UNO forward unknown attributes to the target worker via `__getattr__`, so a missing method would silently re-enumerate the target runner.
  - Overrides only where `draft_runners` cannot express the family: multi-layer EAGLE (one `draft_step_{i}` role per step), DFlash and DSpark (draft worker is a plain `TpModelWorker`; DSpark only on the last PP stage). NGRAM and UNO have no draft worker and return `[]`.
  - `_draft_model_runners()` is untouched: it enumerates runners with their own KV pool (hicache), and FrozenKV MTP is deliberately absent there while it does own weights.
- A `{target, draft, all}` selector on tensor, distributed, check and begin replaces `disable_draft_model`. Role `"target"` is unprefixed in checksum keys; draft roles are prefixed.
- `update_weights_from_distributed` receives once on the target runner and loads into each selected runner; draft runners never join the update group.
- `check_weights` merges per-role payloads; `ChecksumInfo` carries one `parallelism_info` entry per role plus an optional `skip_tensor_list`. `role` is a field of the pydantic `ParallelismInfo` in `weight_checker` (the wire struct mirrors it), passed per runner from the scheduler.
- `update_weights_from_{tensor,distributed}` require an open session; calls outside one, a nested `begin`, or an `end` without `begin` return `success=False` (HTTP 400) rather than raising in the scheduler, which would SIGQUIT the server. In-repo callers, tests and `docs/advanced_features/sglang_for_rl.mdx` (new "Weight Update Session" section) are updated.
- Session restore/finalize live on the runner's `WeightUpdater` (`model_runner.py` stays orchestration-only), and every load goes through `WeightUpdater`, keeping the weight-cache and derived-weight-cache guards. The finalize reuses `DefaultModelLoader.postprocess_weights` (#34981) instead of a second copy of the per-module loop, and `restore_weights_before_loading` sits beside it as a staticmethod. The shared module walk skips LoRA wrappers: `FusedMoEWithLoRA` forwards `quant_method` but owns no expert params, so on main `update_weights_from_disk` on a MoE-LoRA model with quantized experts calls `process_weights_after_loading` on the wrapper and raises `AttributeError`. Startup loads run before LoRA wraps the model, so the skip is a no-op there.

Squash of sglang-miles #28001, #28575, #27750, #18565, #29675, #22663 plus the rebase fixups; the later commits are the cleanup pass and the enumeration unification.

### Disk/IPC behavior vs main, per family

- **Target**: `TpModelWorker.update_weights_from_{disk,ipc}` was a one-line forward to `model_runner.weight_updater`; the scheduler now calls the runner directly with the same arguments.
- **EAGLE / Standalone / FrozenKV MTP / multi-layer EAGLE**: same runners as `BaseSpecWorker`'s loop over `draft_runners`, same order (target first), same arguments.
- **UNO**: its disk/IPC methods were no-ops; it now contributes no runners.
- **NGRAM / DFlash / DSpark**: previously `AttributeError` (no `draft_runners` on their draft worker). NGRAM now updates the target only. **DFlash and DSpark gain disk/IPC updates** of their draft runner.
- Cache flush and version recording keep main's semantics: flush once the target runner loaded even if a draft runner fails afterwards; record the version only if every runner succeeded.

## Not supported by this PR

- `CompressedTensorsWNA16TritonMoE` (the SM100 auto default for W4A16 MoE) cannot be refit: its postprocess rebinds the packed params to new uint8 `Parameter`s behind a one-shot `is_triton_converted` flag, so the next load fails on shape (`RuntimeError: The size of tensor a (2048) must match the size of tensor b (1024)`, reproduced on B200 with the test above switched to `--moe-runner-backend triton`). Pin `marlin` for W4A16 RL on Blackwell until that is fixed.
- Formats whose postprocess is not re-runnable after a full reload (MXFP4, compressed-tensors W4A16 linear layers, per-tensor FP8 linear) are not made refit-safe here.

## Breaking changes

- `update_weights_from_tensor` and `update_weights_from_distributed` must run inside `begin_weight_update()` ... `end_weight_update()`; callers without a session get `success=False` and a message naming the call to make. Migration is the three-line pattern in the doc section.
- `UpdateWeightsFromTensorReqInput.disable_draft_model` is removed; use `selector="target"`.
- `ChecksumInfo.parallelism_info` is now a list, one entry per role.

## Testing

Lint via pre-commit (Python hooks clean on all files).

- Unit (CPU): `test/registered/unit/model_loader/test_default_model_loader.py` (`postprocess_weights` must not process a LoRA wrapper; fails without the skip), `test/registered/unit/rl/test_distributed_weight_update_spec_worker.py`, `test/registered/unit/managers/test_scheduler_weight_version_tracking.py`, `test/registered/unit/managers/test_msgpack_ipc_roundtrip.py`.
- Unit (1-gpu-small, real kernels): `test/registered/unit/layers/quantization/test_compressed_tensors_wna16_moe_reload.py` refits a Marlin W4A16 `FusedMoE` (fresh A, refit B, refit A) through `WeightUpdater.begin_weight_update` / `end_weight_update`, the per-runner component the scheduler drives, and requires parameters bitwise equal to fresh loads, unchanged `data_ptr`s, and matching outputs. It is the first caller of `CompressedTensorsWNA16MoE.restore_weights_before_loading` (#15238) on main. Verified on 1x B200: passes on this branch; with the `CompressedTensorsFusedMoEMethod` forwarding removed (main's state) the first refit fails in `_load_w13` with `RuntimeError: The size of tensor a (64) must match the size of tensor b (128)`.
- Unit (1-gpu-small, imports only): `test/registered/unit/spec/test_weight_update_runners.py` pins the runners every spec family exposes, including FrozenKV MTP, both DSpark PP positions, multi-layer step roles, NGRAM and UNO.
- E2E: `test_update_weights_from_distributed.py`, `test_update_weights_from_tensor.py`, `test_weight_checker_e2e.py`, `test_utils_update_weights.py`, `test_multi_instance_release_memory_occupation.py`.

Not executed locally: every test above except the Marlin W4A16 refit relies on CI. MXFP8 and NVFP4 finalize correctness is covered by the existing `test_update_weights_from_disk_blackwell.py`, which runs the same `DefaultModelLoader.postprocess_weights` after a full reload. The MoE-LoRA disk-update `AttributeError` on main is inferred from the code and covered by the unit test above, not reproduced end to end. DFlash and DSpark weight updates (all paths) have no e2e coverage; they are exercised only through the enumeration unit test.
