## Level 1 contract

The initial supported shape is intentionally narrow:

- Apple Silicon with the MLX backend.
- Text-only Gemma 4 E2B target `mlx-community/gemma-4-e2b-it-4bit` at revision `238767527555cb75a05732a84dff5d6ba0dd6809`.
- Matching assistant `mlx-community/gemma-4-E2B-it-assistant-bf16` at revision `a7770799b560135ebdbfae8b7f468947415003bc`, loaded through `mlx-vlm==0.5.0`.
- `FROZEN_KV_MTP`, with compatible `NEXTN` alias resolution.
- Greedy requests with explicit `temperature=0`.
- One proposal, top-k 1, one speculative step, and verify width 2 (`root + draft`).
- Batch size and maximum running requests of one; synchronous scheduling.
- Radix cache, overlap scheduling, and chunked prefill disabled.
- Context length no greater than 2,048. If `max_total_tokens` is explicit, it must be at least the context length.
- No multimodal inputs, distributed execution, sampling penalties, logprobs, constrained decoding, sessions, LoRA, or custom logits processors.

This milestone makes no throughput or speedup claim.

## Acceptance criteria

- MLX never instantiates the Torch/CUDA Frozen-KV worker.
- Unit coverage exercises accept, reject, bonus-token, rollback, and rotating-cache behavior while preserving target-only greedy output.
- Optional hidden-state capture does not change target logits or tokens.
- Assistant target-KV views are read-only and generation checked.
- Scheduler commit accounting and finish/failure cleanup remain single-owner and leak free.
- Fresh pinned target-only and MTP servers return identical IDs, text, and finish reason for a 64-token cross-window `/generate` request.
- Real execution reports nonzero proposal and verification activity; per-request and worker counter deltas agree.
- Completion and cache flush return request/cache/view counts to zero, retain assistant generation, and allow a post-flush request.
- Offline Stage A coverage and the pinned Stage B test pass.
- Documentation labels the feature experimental and lists the exact constraints.

## Follow-up tracks

These are separate gates after Level 1:

- **Concurrency and mixed batches:** request isolation, ragged batches, mixed prefill/decode, and BS=2/4.
- **Heterogeneous paged/radix KV:** per-layer local/global layouts, YOCO ownership, scheduler-managed pages, radix reuse, and read-only assistant views.
- **Performance and overlap:** reduce copies and synchronization, integrate overlap, benchmark larger targets, and publish results only while exact-token parity remains green.

The paged/radix and native-cache performance tracks may proceed in parallel.
