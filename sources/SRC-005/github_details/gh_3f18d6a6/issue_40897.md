# [Issue #40897] [Bug] Inkling multimodal returns HTTP 500 instead of 400 for invalid image input

source: https://github.com/sgl-project/sglang/issues/40897
state: open | updated: 2026-09-23T15:16:34Z
labels: 

## 正文

## Summary

When an Inkling model receives invalid multimodal input via `/v1/chat/completions` - an empty/unreachable `image_url`, or an image in an unsupported/corrupted format - the server responds with HTTP 500 instead of HTTP 400. This makes it impossible for a client to distinguish its own bad request from a genuine server fault, and pollutes server-error monitoring with what are really client input errors.

Root cause: `InklingMultimodalProcessor` overrides `process_mm_data_async()` with its own media-resolution step (`_resolve_media_item()`, in `sglang/srt/multimodal/processors/inkling.py`) and its own image-decode step (`_encode_image_bytes()`, in `sglang/srt/multimodal/inkling/image_processing.py`). Neither goes through `BaseMultimodalProcessor._load_single_item()` / `sglang/srt/utils/common.py::load_image()`, so the `CLIENT_MEDIA_EXCEPTIONS` classification added there by #31417 (which every other VLM processor inherits) never applies to Inkling.

## Reproduction

Two ways to reproduce, below.

### Option 1: Exercised directly

No server or model weights needed -- both functions can be exercised directly.

```python
from sglang.srt.multimodal.processors.inkling import _resolve_media_item
from sglang.srt.multimodal.inkling.image_processing import _encode_image_bytes

# 1. Empty image_url -- should be a client error, raises an unclassified one
_resolve_media_item({"url": ""})

# 2. Unreachable image_url -- requests.exceptions.ConnectionError propagates raw
_resolve_media_item({"url": "https://unreachable.example/x.png"})

# 3. Undecodable image bytes -- PIL.UnidentifiedImageError propagates raw
_encode_image_bytes(
    b"definitely not an image",
    patch_size=14,
    rescale_image_frac=None,
    rescale_image_max_upscaled_long_edge=None,
)
```

Each call raises without being reclassified to `ValueError`.

### Option 2: Deploy Inkling and call the API

```bash
sglang serve \
  --trust-remote-code \
  --model-path thinkingmachines/Inkling-NVFP4 \
  --tp 8 \
  --quantization modelopt_fp4 \
  --attention-backend fa4 \
  --page-size 128 \
  --fp4-gemm-backend flashinfer_trtllm \
  --moe-runner-backend flashinfer_trtllm_routed \
  --enable-torch-symm-mem \
  --mamba-radix-cache-strategy extra_buffer \
  --mem-fraction-static 0.85 \
  --swa-full-tokens-ratio 0.1 \
  --mamba-full-memory-ratio 0.1 \
  --enable-multimodal \
  --reasoning-parser inkling \
  --tool-call-parser inkling \
  --host 0.0.0.0 \
  --port 30000

# 1. Empty image_url
curl -s http://localhost:30000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "thinkingmachines/Inkling-NVFP4",
    "messages": [{"role": "user", "content": [
      {"type": "text", "text": "describe this image"},
      {"type": "image_url", "image_url": {"url": ""}}
    ]}]
  }'
# Expected: 400. Actual: 500.

# 2. Unreachable image_url
curl -s http://localhost:30000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "thinkingmachines/Inkling-NVFP4",
    "messages": [{"role": "user", "content": [
      {"type": "text", "text": "describe this image"},
      {"type": "image_url", "image_url": {"url": "https://unreachable.example/x.png"}}
    ]}]
  }'
# Expected: 400. Actual: 500.

# 3. Unsupported/corrupted image format (base64 of non-image bytes)
curl -s http://localhost:30000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "thinkingmachines/Inkling-NVFP4",
    "messages": [{"role": "user", "content": [
      {"type": "text", "text": "describe this image"},
      {"type": "image_url", "image_url": {"url": "data:image/png;base64,bm90IGFuIGltYWdl"}}
    ]}]
  }'
# Expected: 400. Actual: 500.
```

## 评论 (1)

### apex-mochen · 2026-09-23

Opened a PR for this: #40931. It classifies empty URLs / remote-fetch failures / undecodable image bytes as `ValueError` (the 400 path used by every other VLM processor via `CLIENT_MEDIA_EXCEPTIONS`) rather than letting raw exceptions escape as HTTP 500, plus regression tests.
