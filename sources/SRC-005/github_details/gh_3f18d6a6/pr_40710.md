## Motivation

On HIP, the DSA FP8 indexer writer currently issues a chain of small kernels (K LayerNorm, joint Q/K RoPE, optional Hadamard, Q/K FP8 quant, and the paged index-K cache store). That launch overhead shows up on decode ITL, especially the tail.

CUDA already fuses the analogous indexer writer (`SGLANG_DISABLE_DSA_INDEXER_FUSION`, default on). This PR adds the ROCm counterpart via AITER `indexer_qk_rope_quant_and_cache`, so HIP can fuse RoPE + K LayerNorm + FP8 quant + cache write into one kernel. Hadamard is omitted, matching the CUDA fused writer (pre-quant logits stay aligned).

The path is **default-on** when AITER is available and indexer geometry matches (`head_dim=128`, `rope_dim=64`, `quant_block=128`, index-K LayerNorm). Models that do not match (including RMSNorm index-K) keep the legacy split writer. Set `SGLANG_AITER_FUSED_FP8_DSA_INDEXER=0` to force the split path.

Validated on GLM-5.2-MXFP4 (gfx950). Any DSA indexer with the same geometry can take this path; it is not hardcoded to a model name.

## Modifications

- `python/sglang/kernels/ops/attention/dsa/fp8_fused_writer_hip.py`: AITER adapter (geometry checks, RoPE table reshape, fused Q/K write).
- `python/sglang/srt/layers/attention/dsa/dsa_indexer.py`: enable fused writer when HIP + AITER + geometry match; LayerNorm in fp32 only on the fused path; warn only if the env is explicitly set and unsupported.
- `python/sglang/srt/environ.py`: `SGLANG_AITER_FUSED_FP8_DSA_INDEXER = EnvBool(True)`.
- Tests:
  - `test/registered/unit/layers/attention/test_fp8_fused_writer_hip.py`
  - `test/registered/amd/test_fp8_fused_dsa_writer_gfx950.py`
