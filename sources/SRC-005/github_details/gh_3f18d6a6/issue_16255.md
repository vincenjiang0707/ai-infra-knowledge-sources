## Motivation
After months of development, the file `deepseek_v2.py` has grown to more than 4k lines of codes. As the key part for a series of popular MoE models (DeepSeek V3/V3.1/V3.2 family, Kimi-K2 family, Mistral-Large-3 family), this file deserves careful cleaning and refactoring to ensure its maintainability and extensibility.

## Current Structure of `deepseek_v2.py`

- Importing packages and device flag setting (~150 lines)  
- Definition of different attention forwarding methods (MHA, MLA, Chunked MHA etc...), and how each attention backend gets routed to these forward methods (~200 lines)
- MLP/MoE layer implementation (~800 lines)
- MLA layer implementation (~1500 lines)
    - About 900 lines are implementation of different attention forward methods
- Weight loading logics (~600 lines)
- Decoder Layer/whole model level implementation  (~500 lines)
- Other small functions (~300 lines)

## Parts for Improvement
- Many standalone modules can be extracted from modeling logic, and deserves a single file. Including:
    - Definition/Implementation of different attention methods
    - Routing strategy of different attention backends
    - NSA(V3.2) specific logics
    - Weight loading logics
    - Util functions
- There are too many if-else branches from different hardware platforms (AMD/NPU/CPU)

## Folder structure after Refactoring


```
├── deepseek_common
│   ├── attention_backend_handler.py
│   ├── attention_forward_methods
|   |   ├── forward_methods.py
│   │   ├── forward_mha.py
│   │   ├── forward_mla_cpu.py
│   │   ├── forward_mla.py
│   │   └── forward_mla_rocm.py
│   ├── hardware_backend
│   │   ├── deepseek_v2_amd_mixin.py
│   │   ├── deepseek_v2_cpu_mixin.py
│   │   └── deepseek_v2_npu_mixin.py
│   ├── utils.py
│   ├── v32_mixin.py
│   └── weight_loader_mixin.py
├── deepseek_v2.py
├── deepseek.py
...
```

For refactoring, we need to split the original `deepseek_v2.py` into these files or subfolders for mixin Classes:
-  `attention_backend_handler.py`: MLA routing logic on different attention backends
-  `attention_methods`: implementation of different attention forward methods. Including MHA (forward_normal), MLA (forward_absorb) and variants on other hardware platforms.
-  `hardware_backend`: mixin classes for different hardware platforms (AMD/NPU/CPU)
-  `utils.py`: util functions
-  `weight_loader.py`: weight loading logics
-  `v32_mixin.py`:  V3.2 related logics

In the original `deepseek_v2.py`, we keep the definition of basic blocks, like `DeepseekV2AttentionMLA` or `DeepseekV2MoE`, so the places importing these classes will not be broken.

For refactor of multiple hardware backends, `MultiPlatformOp` might be another way to simplify the codes. We should choose the one working better.


## Further Refactor

After the file has been split and stabilized. We can try to optimize the structure with some carefully designed abstractions. 

For example, we can create a class for attention_forward_method. It might include methods for different hardware, such as `forward_prepare_cuda`, `forward_core_cuda`, `forward_prepare_npu`, etc... So most of the if-else structures inside the forward logics can be replaced.
