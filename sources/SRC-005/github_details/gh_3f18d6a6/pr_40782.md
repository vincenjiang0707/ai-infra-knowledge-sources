# [PR #40782] [HiSparse] Prepare write slots once in attention metadata

source: https://github.com/sgl-project/sglang/pull/40782
state: open | updated: 2026-09-23T02:30:28Z
labels: amd, memory-pool

## 正文

Prepare physical KV write locations when DSA attention metadata is initialized, then reuse them for fused MLA cache writes throughout the batch. HiSparse pools translate logical locations once for gfx95 decode; resident pools retain their locations. Modes without prepared decode metadata resolve locations at the writer. Hybrid and TBO backends delegate lookup to the backend that owns the active metadata.

The new coverage checks decode graph replay, eager execution, padding, resident pools, and fallback behavior. Focused CPU and MI355X GPU validation passed on that source commit.

## C1 steady-state decode

Measured on GLM-5.2 FP8 with BF16 KV, TP4 MI355X, a 32,768-token input and 256-token output, using 64 warmup tokens and the next 192 decode intervals. Measured source commit: `87c1754b5990`. Runtime: stock SGLang v0.5.20 on ROCm 7.2.4. Parent: `c0f7b4d`. Lower is faster.

| Prefetch | Parent median (ms/token) | This PR median (ms/token) | Latency reduction |
|---|---:|---:|---:|
| Off | 20.111 | 19.918 | ~1% |
| On | 18.375 | 18.201 | ~1% |

One trial per source and prefetch mode was run on the same TP4 allocation. These results are descriptive, not independent restart replications.
