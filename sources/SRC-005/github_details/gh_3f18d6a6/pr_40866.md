## 正文

## Motivation

#40818 pointed coding agents at the cookbook, but everything it added lives in `.claude/` rules and docs, and both are excluded from the wheel:

```toml
[tool.setuptools.packages.find]
exclude = ["assets*", "benchmark*", "docs*", "dist*", "playground*", "scripts*", "tests*"]
```

So for anyone who runs `pip install sglang` rather than cloning the repo — the majority of users — there was no path to the cookbook at all. The README had zero mentions of it, `[project.urls]` carried only Homepage and Bug Tracker, and no CLI help mentioned it.

## Modifications

Add the pointer where a pip user actually looks:

- **CLI help.** `sglang --help`, `sglang serve --help` and `sglang generate --help` now end with a one-line pointer. For `serve` it is printed once in the help branch after whichever backend help ran, rather than as each backend parser's epilog — the auto path prints both the LLM and diffusion help, so an epilog per parser would repeat it. This also covers an LLM-only install, where the diffusion parser never runs.
- **`[project.urls]`.** Adds `Documentation` and `Cookbook`, which render in the PyPI sidebar.
- **README.** One line in Getting Started.

The wording stays generic ("its cookbook page carries the recommended command for it: GPU count, parallelism, quantization and the flags that matter for that model") so it does not go stale as the cookbook grows.

## Accuracy Test

Not applicable — no runtime behaviour changes; the CLI additions only affect `--help` output.

Verified on an H200 devbox that every help path prints the pointer exactly once, at the end:

| command | occurrences |
| --- | --- |
| `sglang --help` | 1 |
| `sglang serve --help` (auto) | 1 |
| `sglang serve --model-type llm --help` | 1 |
| `sglang serve --model-type diffusion --help` | 1 |
| `sglang generate --help` | 1 |
