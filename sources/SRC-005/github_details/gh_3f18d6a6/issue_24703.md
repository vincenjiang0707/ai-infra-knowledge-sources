# Weight Loader RFC

Claude assisted, I took a pass, and most of the suggestions seem reaonsable.

This RFC describes a proposal for interfaces and abstractions for the model weight loading layer.

Today, we have 165 model files in `python/sglang/srt/models/`, each carrying its own ~50–150 line `load_weights`. The largest (`deepseek_v2.py`) is 2.4k lines. And `sglang/python/sglang/srt/models/deepseek_common/deepseek_weight_loader.py` is over 700 lines long. 

Every time someone wants to fix a behavior here, they end up touching one model and missing the rest, since the same control flow is copy-pasted across the whole directory. For examples, the following PRs are for simply adding remapping per model for NVFP4 models:

https://github.com/sgl-project/sglang/pull/18224
https://github.com/sgl-project/sglang/pull/18189

But the same happens for supporting PP, etc. 

(There are more, but I cannot find them right now..)

## Motivation

The per-model `load_weights` functions repeat the same boilerplate over and over. Some quick numbers from grep today:

- 116 / 165 model files declare their own `stacked_params_mapping` (almost always the same `qkv_proj` / `gate_up_proj` tuples).
- 83 / 165 files repeat the `rotary_emb.inv_freq` / `cos_cached` / `sin_cached` skip block verbatim.
- 27 / 165 files repeat the `maybe_remap_kv_scale_name(...)` block.
- 28 / 165 files repeat the `tie_word_embeddings` + `lm_head.weight` skip.
- 352 call sites to `is_pp_missing_parameter` / `start_layer` / `end_layer` guards, all sprinkled inside the per-model loops.

So fixes to FP8 kv-scale remapping, fused module support, or PP edge cases tend to land in one or two files and quietly miss the rest. The `DeepseekV2WeightLoaderMixin` extraction is evidence that we already feel this pain — but the pattern stops at one model family.

The control flow inside each `load_weights` is fundamentally the same procedural sweep:

```text
for name, weight in weights:
    skip rotary buffers;
    skip out-of-range PP layers;
    remap kv-scale names;
    skip lm_head if tied;
    walk stacked_params_mapping → maybe load + break;
    walk expert_params_mapping → maybe load + break;
    fall-through default_weight_loader.
```

This isn't really domain logic, it's plumbing — and it would be much nicer to have it living in one place.

For reference, vLLM solved a very similar problem with `AutoWeightsLoader` (`vllm/model_executor/models/utils.py:117`). Their `llama.py:load_weights` is 5 lines. Ours is 74 lines doing essentially the same thing.

## Proposal

### Abstraction

Three pieces, each non-intrusive:

1. **Walker** (`AutoWeightsLoader`). Given a root `nn.Module` and an iterable of `(name, tensor)`, it walks the module tree. For each child it finds, if that child has its own `load_weights`, defer to it; otherwise recurse; at the leaf, look up `param.weight_loader` (already the convention used by sglang's linear / fused MoE layers) and call it. This is where rotary skip, PP skip, kv-scale remap, tie-word-embeddings skip, and "not found" diagnostics all live exactly once.

2. **Name remapper** (`WeightsMapper`). A small declarative dataclass: `{regex|substr|prefix|suffix → new_name | None}`. Replaces the dozens of `name = name.replace("foo", "bar")` lines, plus the "set name to None to drop it" idiom. Composable via `|` so quant remaps and model remaps stack cleanly.

3. **Quirks registry**, parallel to the `OverrideRegistry` in the server-args proposal. Per-architecture hooks for things like DeepSeek's `fused_qkv_a_proj_with_mqa` (currently injected into `packed_modules_mapping` inside `__init__`) or w4afp8's expert-input-scale mapping. Today these are `if quant_config.get_name() == "w4afp8": ...` branches inside the loader; they should be registered, not branched, in the model loading code.

### Interface

After the walker is in place, a typical model's `load_weights` would look like:

```python
class LlamaForCausalLM(nn.Module):
    def load_weights(self, weights):
        loader = AutoWeightsLoader(
            self,
            skip_prefixes=["lm_head."] if self.config.tie_word_embeddings else None,
        )
        return loader.load_weights(weights)
```

That covers the 80% case. Models with real special cases override at the *module* level instead of the top-level model:

```python
class DeepseekV2MoE(nn.Module):
    def load_weights(self, weights):
        # MoE-specific expert sharding — only this submodule, not the whole model
        ...
```

The walker sees `DeepseekV2MoE.load_weights` exists and defers to it; the rest of the model still rides the auto path. This is where most of the win comes from: today, one quirk in one submodule forces you to write the entire top-level loader by hand.

```python
@WeightQuirkRegistry.register(["DeepseekV3ForCausalLM"])
def deepseek_quirks(model, mapper: WeightsMapper) -> WeightsMapper:
    if model.fuse_qkv_a_proj:
        mapper |= WeightsMapper(orig_to_new_substr={
            "q_a_proj": "fused_qkv_a_proj_with_mqa",
            "kv_a_proj_with_mqa": "fused_qkv_a_proj_with_mqa",
        })
    return mapper
```

Subsystem interface: nothing else in the codebase needs to know the walker exists. `model_loader/loader.py` keeps calling `model.load_weights(...)` exactly as today, and the change is local to `srt/models/*`.

## Breaking Changes

Since this is not exactly **public** API, we can maybe keep on making further changes for readability/usability/ease of maintenance. It will only affect those with out of tree models (requires them changing the mdoel code).

- Delete `stacked_params_mapping` and `packed_modules_mapping` from every model class. They move to the layer that owns the fusion. Out-of-tree models that copy-pasted these will need to drop them.
- Standardize the `load_weights` return type to `set[str]` (loaded param names). Today some return `None`, some return nothing. This unblocks "expected but missing" diagnostics in the walker.
- Delete `do_load_weights` / `DeepseekV2WeightLoaderMixin` — the walker subsumes it. Submodule-level `load_weights` overrides replace it cleanly.
- Delete `get_module_name_from_weight_name`, `get_num_params`, `get_weights_by_name` from individual model classes (used mostly by tests and weight-update RPC). These are mechanical and belong on the walker / a single helper, not duplicated per model.
- Drop the per-loop `is_pp_missing_parameter` / `start_layer` / `end_layer` checks. Make `PPMissingLayer` short-circuit traversal in the walker so model code never has to think about PP boundaries again. (~352 call sites go away.)
- Lift the `ThreadPoolExecutor` + `should_async_load` path out of the DeepSeek mixin and make it the default in the walker, so every model gets it for free. Behavior change: load order becomes non-deterministic, but `weight_loader` callers should already not depend on order.
- Standardize on `Iterable[tuple[str, torch.Tensor]]` (drop the legacy `Tuple` typing, drop the variant signatures like `is_nextn=False` kwarg — the NextN distinction can be handled by a quirk that swaps in a different mapper).
- `bitsandbytes_stacked_params_mapping` becomes the same registry mechanism, not a separate per-model attribute.

These are aggressive but each one removes a category of duplication, not just lines.

## Open questions

1. Migration order. first, do the easy and less used models, we can do Deepseek files at the very end.
