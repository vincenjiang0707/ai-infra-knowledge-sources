### Describe the bug


Hello,

### jahnclawdmonet · 2026-09-21

Same gate as #40286, filed 2026-09-19 with the same `fmhaRunner.cuh:37` failure and the same
`_GLM_DSA_MODEL_ARCHS` allowlist, on SM121 rather than SM120.

PR #38430 covers it. It adds `Glm5NextForConditionalGeneration` and
`Glm5NextForConditionalGenerationNextN` to that tuple in `flash_mla_sm120.py` and routes them
through a `glm53_nope` layout.

One thing to watch if you build it against your current pins. `glm53_nope` is not in flashinfer
0.6.18, which is what `python/pyproject.toml:42` pins on v0.5.20. In 0.6.18 the SM120 sparse-MLA
entry at `flashinfer/mla/_core.py:584` requires `kv_lora_rank=512`, `qk_rope_head_dim=64` and query
head dim 576, while GLM-5.3-Flash has `text_config.qk_rope_head_dim = 0` and `mla_use_nope` true.
The flag is present in flashinfer main.
