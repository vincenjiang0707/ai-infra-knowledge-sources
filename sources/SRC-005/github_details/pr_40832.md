# [PR #40832] Modify the mapping relationship between TP and NUMA nodes to many-to-one.

## 正文


## Motivation

The TP cases in SGLang UT needs to remove the hard-coded code to accommodate SPR.

## Modifications

- Added adaptive allocation logic for TPs (Tensor Parallelism) to specific NUMA node CPUs; regardless of TP settings, execution is confined to the CPUs of a single NUMA node.
- Resolved mapping conflicts during concurrent multi-process startup by implementing a locking mechanism, ensuring that nodes allocated to simultaneously starting processes do not overlap.
- Bypassed automatic threshold setting to prevent small models from crashing due to memory exhaustion on a single physical node.

## Accuracy Tests

- When started as a single process, the workload runs on a single NUMA node if TP > 1.
- When multiple processes are started concurrently, the NUMA nodes assigned to the processes do not overlap or conflict.
