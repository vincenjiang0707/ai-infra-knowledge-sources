## Motivation

Adds support for TRT-LLM XQA decode backend for SM90/120 speculative decoding, by building a causal mask it requires for the verify forward pass (more than 1 q token).

Agent generated summary:

Before: pure `--attention-backend trtllm_mha` + NEXTN on SM90/120 died at server startup during decode CUDA-graph capture — verify routes to the XQA decode kernel, which demands a mask for `q_len > 1` that the backend never passed:
```
  File "/SGL/flashinfer/flashinfer/xqa.py", line 332, in xqa                                                       
      assert mask is not None, "Mask is required for speculative decoding"                                         
  AssertionError: Mask is required for speculative decoding 
```

Never caught before because the verify→decode-kernel routing was written for SM100 (trtllm-gen needs no mask); XQA enablement for SM90/120 came later and nobody ran spec decoding on that combo.
                                                                                                                   

## Modifications

Fix/After: precompute XQA's bit-packed causal mask (constant for chain/topk=1 speculation) at init and pass it on verify — flashinfer already plumbed the argument. 

## Accuracy Tests

Validated: boots through capture, GPQA-10 0.70, acceptance 2.20/0.40 matching the FA3-verify reference (see MTP data reported in https://github.com/sgl-project/sglang/pull/23112).

### jpezzulli · 2026-08-20

I reproduced this on current `main` at `b03ac355e7` with DFlash2 on an RTX PRO 6000 (SM120). Target-verify CUDA-graph capture fails in FlashInfer 0.6.17 because `q_len_per_req=8` reaches XQA without a mask.

The existing fix needs a small current-main update because uniform verification now goes through `_run_fixed_q_len_decode()`, including its optional KV-length split path. I prepared a two-file update that:

- precomputes FlashInfer's packed causal mask once at the graph-aligned request bound;
- applies it only to uniform XQA target verification;
- passes a correctly sized prefix view to each split group (the causal mask is identical for every request);
- rejects unexpected query widths and batch-capacity overflow explicitly; and
- adds portable coverage for packing, capacity, split/unsplit forwarding, and unmasked non-target calls.

Validation on the current-main update:

- complete `test_trtllm_mha_graph_metadata.py`: 160 passed;
- CPU-only/FlashInfer-disabled collection: 13 passed, 147 skipped;
- all pre-commit hooks passed;
- target and draft CUDA-graph capture completed on SM120; and
- four simultaneous ordinary 1,024-token thinking requests completed with CUDA graphs active (4,096 completion tokens in 10.119 s; warmed reported samples 399.67–462.66 tok/s; DFlash acceptance length 2.92–4.32).
