# [Issue #30432] [Refactor] Confusing name: `global_num_tokens` collapses to `[local_num_tokens]` in pure DP+EP layout

state: closed | updated: 2026-09-23T00:26:58Z

## 正文

### Summary

The field `global_num_tokens` (and its variants `global_num_tokens_cpu` / `global_num_tokens_gpu` on `ForwardBatch`, plus the accessor `get_dp_global_num_tokens()`) has a misleading name: despite the `global_` prefix, in the pure DP + EP layout it does **not** hold a cross-rank list — it collapses to a length-1 list `[local_num_tokens]` holding only the current rank's count.

This is a documentation/naming issue only. Not requesting an immediate fix, just tracking it.

### Where the overloading happens

`python/sglang/srt/managers/scheduler_components/dp_attn.py` (`_update_gather_batch`):

```python
if not require_mlp_tp_gather:
    batch.global_num_tokens = [mlp_sync_info.num_tokens]          # length 1: only THIS rank's count
else:
    batch.global_num_tokens = mlp_sync_info.global_num_tokens     # full length-dp_size gathered list
```

So the field's length and meaning are context-dependent:
- `require_mlp_tp_gather=True`  → full length-`dp_size` gathered list (the DP MLP-gather buffer packs every rank's tokens).
- `require_mlp_tp_gather=False` → `[local_num_tokens]` (length 1), because there is no shared buffer — each rank is standalone (attention DP + dense TP=1 + EP all-to-all).

Its true role (see `python/sglang/srt/model_executor/forward_batch_info.py` `prepare_mlp_sync_batch`, where `buffer_len` / per-rank slice are derived from it) is a **DP MLP-gather buffer layout descriptor**, not a global token census.

### Why it's confusing

- The name promises "across all ranks," but the value can be the *local* count — the opposite.
- Consumers must guard with `len(dp_global) > 1` to detect whether the gathered list is actually available. For example the FlashInfer A2A dispatcher (`python/sglang/srt/layers/moe/token_dispatcher/flashinfer.py`) does exactly this in its `runtime_max_tokens_per_rank` Case 1. This subtlety was a real trap while debugging #30242.
- Note `MLPSyncBatchInfo.global_num_tokens` (in `dp_attn.py`) is **accurately** named — it is always the true gathered list. Only the `ScheduleBatch` / `ForwardBatch` copies are overloaded.

### Suggested actions (pick one; no rush)

1. **Minimum:** add a precise comment at the field definitions (`schedule_batch.py`, `forward_batch_info.py`) and at the collapse site in `_update_gather_batch`, stating that `len` may be 1 (`[local]`), and that consumers must not assume `len == dp_size`.
2. **Better (invasive):** rename to something that reflects "MLP-gather buffer layout," e.g. `mlp_gather_num_tokens` / `mlp_sync_num_tokens`, and update all call sites including `get_dp_global_num_tokens()`. This touches the scheduler, forward batch, both cuda-graph runners, dp_attention, and spec decoding, so it should be a deliberate standalone change.

### Context

Surfaced while analyzing #30242 (FlashInfer A2A dispatcher `runtime_max_tokens_per_rank` selection). The `len(dp_global) > 1` guard is only correct because of this collapse behavior, which is not documented anywhere.
