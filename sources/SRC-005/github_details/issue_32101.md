## 正文

## Motivation

Add correctness-first Gemma 4 text generation to SGLang's MLX backend on Apple Silicon, then incrementally add scheduler coverage, first-class radix-cache integration, larger variants, multimodal inputs, and MTP.

This tracks a concrete model contribution under the Apple Silicon roadmap in #19137 and cross-links the existing Gemma 4 roadmap in #26596. SGLang's existing Gemma 4 implementation targets the standard GPU model path; the MLX backend instead loads and executes models through `mlx-lm`.

## Why an incremental path is needed

`mlx-lm` already implements Gemma 4, but Gemma 4's cache and attention contracts cannot currently be represented by SGLang's uniform MLX radix pool. The model combines:

- sliding-window and full-attention layers;
- heterogeneous per-layer head dimensions and KV layouts;
- K=V attention variants without `v_proj`;
- Gemma-specific `v_norm`; and
- YOCO layers that reuse earlier K/V and do not own cache entries.

The proposed MVP therefore leaves cache semantics with `mlx-lm` while retaining SGLang's scheduler and HTTP APIs. This is a correctness bridge, not the final optimized cache design.

## Milestones

- [ ] E2B text-only MVP using model-native `mlx-lm` caches, with radix caching, overlap scheduling, and chunked prefill disabled.
- [ ] Scheduler hardening for cancellation, chunked prefill, overlap/chained decode, and multiple concurrent requests.
- [ ] Model-neutral per-layer KV specifications and YOCO cache ownership.
- [ ] First-class heterogeneous full/SWA cache and radix integration, coordinated with #30050, #30091, and #30156.
- [ ] Variant expansion: E4B, then 31B, then 26B MoE with per-checkpoint accuracy gates.
- [ ] Separate follow-ups for multimodal inputs and MTP speculative decoding.

## MVP acceptance criteria

- Cover the public `gemma4.Model` wrapper and text backbone with a tiny real architecture test.
- Match raw `mlx-lm` greedy decoding across a prompt longer than the synthetic sliding window.
- Preserve independent native cache state for multiple requests and release state when requests finish.
- Fail with actionable startup errors for unsupported radix/overlap/chunked configurations.
- Launch `mlx-community/gemma-4-e2b-it-4bit` and serve `/v1/chat/completions` on Apple Silicon.
- Match unmodified `mlx-lm` token-for-token on a real E2B checkpoint.
- Document the conservative 2,048-token validated configuration and all non-goals.

A local prototype currently meets these criteria: the real 4-bit E2B checkpoint loaded as 35 layers with 15 model-owned YOCO caches, matched 8/8 greedy tokens against raw `mlx-lm`, and returned correct OpenAI-compatible chat responses.

## MVP non-goals

Radix/prefix reuse, fused batched attention, long-context claims, Gemma 4 Unified, E4B/31B/26B support, multimodal inputs, MTP, and custom Gemma-specific Metal kernels.
