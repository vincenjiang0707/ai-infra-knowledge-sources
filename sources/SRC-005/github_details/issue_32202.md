### Describe the bug

When a speculative draft model is stored in S3-compatible object storage and `--speculative-draft-load-format auto` is set explicitly, the draft model is loaded with `DefaultModelLoader` instead of `RunaiModelStreamerLoader`.

The target model's `--load-format auto` is resolved from the target model path during `ServerArgs` post-processing. The draft path is not processed independently. During draft worker initialization, the scheduler copies the literal draft value `auto` into the shared `server_args.load_format`. `build_load_config()` therefore creates `LoadConfig(load_format="auto")`, and `get_model_loader()` falls through to `DefaultModelLoader`; it only selects `RunaiModelStreamerLoader` when the format is explicitly `runai_streamer`.

Actual loader selection:

```text
draft S3 path + draft load format auto
  -> LoadFormat.AUTO
  -> DefaultModelLoader
```

Expected loader selection:

```text
draft S3 path + draft load format auto
  -> LoadFormat.RUNAI_STREAMER
  -> RunaiModelStreamerLoader
```

The draft load format should be resolved against the draft model path on draft-specific server arguments. This should not mutate the target model's shared `ServerArgs`. An unspecified draft format should continue to inherit the target format, and explicit non-auto draft formats should remain unchanged.

### Reproduction

Launch speculative decoding with both models in S3-compatible object storage and explicitly request `auto` for the draft:

```bash
python3 -m sglang.launch_server \
  --model-path s3://bucket/target-model \
  --load-format auto \
  --speculative-algorithm EAGLE \
  --speculative-draft-model-path s3://bucket/draft-model \
  --speculative-draft-load-format auto
```

Observe that the target path resolves `auto` to `runai_streamer`, while the draft value remains literal `auto` and reaches `DefaultModelLoader`.

The same mismatch can be verified from the loader-selection path without loading weights:

1. `ServerArgs._handle_load_format()` resolves only `self.model_path`.
2. `Scheduler.maybe_init_draft_worker()` assigns `speculative_draft_load_format` to the shared `load_format`.
3. The draft worker passes that value through `build_load_config()`.
4. `get_model_loader()` selects `RunaiModelStreamerLoader` only for `LoadFormat.RUNAI_STREAMER`; `LoadFormat.AUTO` falls through to `DefaultModelLoader`.

### Environment

- SGLang: latest `origin/main`, commit `a25164bda3`
- Model storage: S3-compatible object storage
- Deployment where observed: 2 nodes, TP=8, PP=2, NVIDIA H20
- The failure occurs deterministically during loader selection, before hardware-specific model execution.

python3 -m sglang.check_env output can be attached from the target deployment environment when filing the issue.
