# [PR #40827] fix(models): guard both format_ue8m0 reads in deepseek weight loader (fixes humming weight-load crash)

source: https://github.com/sgl-project/sglang/pull/40827
state: open | updated: 2026-09-23T02:45:26Z
labels: deepseek

## 正文

## Motivation

Fixes #40393.

On v0.5.20, serving a DeepSeek-family / GLM MLA checkpoint with `--quantization humming` crashes on every TP rank at the end of weight loading:

```
AttributeError: 'BlockQuantScaleParameter' object has no attribute 'format_ue8m0'
```

#38446 hoisted the `format_ue8m0` attribute read out of a short-circuit expression in `DeepseekV2WeightLoaderMixin.post_load_weights`, so it is now evaluated unconditionally. The attribute is only stamped by quant methods that requant scales to UE8M0 (fp8/DeepGEMM, flashinfer_trtllm, mega_moe, NPU methods); quant methods like `humming` never stamp it, so the read genuinely fails there.

## Modifications

`python/sglang/srt/models/deepseek_common/deepseek_weight_loader.py` — guard **both** unguarded reads with `getattr(..., False)`:

1. `is_ue8m0_uint8 = weight_scale.format_ue8m0 and ...` (line 632)
2. the `should_deepgemm_weight_requant_ue8m0(...)` branch (line 656), which is still reachable after (1) is fixed: when DeepGEMM UE8M0 requant is enabled (H100/H20, 128×128 block size) the condition evaluates `weight_scale.format_ue8m0` and raises the same `AttributeError` — fixing site (1) alone only relocates the crash 24 lines down.

The `getattr(..., False)` pattern matches existing defensive usage in `layers/linear.py` and `models/qwen3_5.py`. Behavior for quant methods that DO stamp the attribute is unchanged — the default `False` only applies where the attribute never existed.

### Relation to #40397

PR #40397 fixes the first read (site 1). As described above, the second read (site 2) is evaluated when the `elif should_deepgemm_weight_requant_ue8m0(...)` branch is taken, which is the common case on H100/H20 — so that PR alone still crashes for `--quantization humming`. This PR covers both sites; the audit is straightforward to re-verify: these are the only two non-defensive `format_ue8m0` reads in the repo (all other sites are writes/`getattr`).
