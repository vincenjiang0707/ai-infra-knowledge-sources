## 正文

### Problem Description

Collecting counters with rocprofv3 on the [HIP-Basic](https://github.com/ROCm/rocm-examples/tree/develop/HIP-Basic/) matrix multiplication example yields a .csv file where all counters have a 0 value (even simple counters such as 'MemUnitBusy').

### Operating System

Ubuntu 24

### CPU

i5 13600k

### GPU

7900XTX

### ROCm Version

6.4.0

### ROCm Component

rocprofiler

### Steps to Reproduce

```
amdgpu-install --usecase=rocm

git clone git@github.com:ROCm/rocm-examples.git
cd rocm-examples
cd HIP-Basic

cmake -S . -B build
cmake --build build

rocprofv3 --pmc MemUnitBusy -- ./build/bin/hip_matrix_multiplication

cat counter_collection.csv
>

"Correlation_Id","Dispatch_Id","Agent_Id","Queue_Id","Process_Id","Thread_Id","Grid_Size","Kernel_Id","Kernel_Name","Workgroup_Size","LDS_Block_Size","Scratch_Size","VGPR_Count","Accum_VGPR_Count","SGPR_Count","Counter_Name","Counter_Value","Start_Timestamp","End_Timestamp"
1,1,1,1,15309,15309,256,7,"__amd_rocclr_initHeap",256,0,0,16,0,128,"MemUnitBusy",0.00000000e+00,1203600088247,1203600094327
2,2,1,1,15309,15309,2097152,16,"void matrix_multiplication_kernel<16u>(float const*, float const*, float*, unsigned int)",256,2048,1024,48,0,128,"MemUnitBusy",0.00000000e+00,1203600507426,1203701866465
```

`"MemUnitBusy",0.00000000e+00,1203600507426,1203701866465` is the interesting part of the CSV. 

I would expect a non-zero value just after ``"MemUnitBusy"`?

Pretty much all counters that I have tried (VALUInsts, WRITE_SIZE, WriteUnitStalled, GPUBusy) behave this way, except maybe `'Wavefronts'` which does give `128432.000000` in the CSV output for the `matrix_multiplication` example

## 评论 (2)

### schung-amd · 2025-04-23

Hi @TomClabault, I notice you're on gfx11; have you set the power state to stable? If not, most counters will show as 0. From the README:

```
gfx10, gfx11 and gfx12 requires a stable power state for counter collection. This includes Radeon 7000 GPUs.

# For device <N>. Use 'rocm-smi' or 'amd-smi monitor' to see device number.
sudo amd-smi set -g <N> -l stable_std
# After profiling, set power state back to 'auto'
sudo amd-smi set -g <N> -l auto
```

### TomClabault · 2025-04-23

This was indeed the issue, thanks!
