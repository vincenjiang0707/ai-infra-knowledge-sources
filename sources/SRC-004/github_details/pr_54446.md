# [PR #54446] [torch.compile] Remove dead torch 2.9 Inductor monkeypatches

source: https://github.com/vllm-project/vllm/pull/54446
state: open | updated: 2026-09-23T03:00:56Z
labels: torch.compile, needs-rebase

## 正文

## Summary

`vllm/env_override.py` carries four Inductor monkeypatches plus a `get_raw_stream` workaround that are gated on `is_torch_equal("2.9.0")` / `is_torch_equal("2.9.1")`. No supported install path ships torch 2.9:

- `pyproject.toml` build requires `torch == 2.13.0`; `requirements/cuda.txt`, `cpu.txt` and `xpu.txt` pin `torch==2.13.0`
- ROCm: `requirements/build/rocm.txt` pins `torch==2.11.0`, `docker/Dockerfile.rocm_base` builds ROCm/pytorch `release/2.12`, and `docker/Dockerfile.rocm_base_gfx1250` sets `TORCH_VERSION=2.11.0`
- TPU: `docker/Dockerfile.tpu` starts from the `xla:nightly` image

So both gates are constant-false everywhere vllm pins a version, and the ~380 lines behind them can never execute. This PR removes them.

## What is removed

- `memory_plan_reuse_patched` (pytorch#165514 workaround)
- `get_graph_partition_signature_patched` (pytorch#165815 workaround)
- `should_partition_patched` and `_update_scheduler_patched` (vllm#26678 workaround)
- `_patch_get_raw_stream_if_needed` (vllm#30905 workaround)
- the `if is_torch_equal("2.9.0"):` block that installs them, and the now-unused `is_torch_equal` import
- `tests/compile/test_config.py::test_get_raw_stream_patch`, whose body only asserts under torch 2.9

## What is deliberately NOT touched

The `torch <2.12`, `2.10–2.12` and `>=2.11` gates further down the same file stay exactly as they are. ROCm images ship torch 2.11 and 2.12, so those patches are still live — the comment saying one "can be removed once torch >=2.12 is the minimum supported version" is not yet true for every supported platform.

No behavior change on any version vllm currently pins.

Found while auditing version-gated leftovers in popular open-source projects.
