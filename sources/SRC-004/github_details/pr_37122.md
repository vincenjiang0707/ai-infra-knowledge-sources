## 正文

## Purpose

Fix `StopIteration` crash at server startup when using Qwen3-Omni with `--mm-processor-kwargs '{"use_audio_in_video": true}'`.

## Root Cause

When `use_audio_in_video=True` is set in `--mm-processor-kwargs` for Qwen3-Omni, the server crashes during encoder cache profiling at startup.

`Qwen3OmniMoeThinkerDummyInputsBuilder` (previously just an alias for `Qwen2_5OmniThinkerDummyInputsBuilder`) generates profiling data with separate `<|audio_pad|>` and `<|video_pad|>` tokens. However, with `use_audio_in_video=True`, the HF processor folds audio into the video token — `<|video_pad|>` consumes both `audio_lengths` and `video_grid_thw`. The separate `<|audio_pad|>` token exhausts the `audio_lengths` iterator first, leaving nothing for `<|video_pad|>`, causing `StopIteration`.

## Fix

Override `get_dummy_processor_inputs` in `Qwen3OmniMoeThinkerDummyInputsBuilder` to:

1. Detect when `use_audio_in_video=True` is set and videos are present
2. Include paired audio data for each video (so the HF processor has audio lengths to consume)
3. Remove `<|audio_pad|>` tokens from the prompt (since audio is folded into video)
4. Pass `use_audio_in_video=True` in `hf_processor_mm_kwargs`

When `use_audio_in_video` is not set, behavior is unchanged (delegates to the parent class).

## How to reproduce

```bash
vllm serve Qwen/Qwen3-Omni-30B-A3B-Instruct \
    --mm-processor-kwargs '{"use_audio_in_video": true}' \
    --limit-mm-per-prompt video=4
```

Server crashes during startup profiling with:

```
StopIteration
```
