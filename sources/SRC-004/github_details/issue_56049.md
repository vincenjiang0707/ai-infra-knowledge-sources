## 正文

## Overview

Fast Start reduces vLLM startup time by avoiding repeated checkpoint loading, weight processing, and kernel autotuning during engine restarts and scaling events.

The core design uses a persistent per-GPU weight daemon. The daemon loads and processes model weights once, keeps sharded weights in GPU memory, and exposes them to new vLLM engines through CUDA IPC or a multi-node transport.

When a compatible cache is unavailable, vLLM falls back to the existing checkpoint loader.

## Design Goals

- Reuse processed GPU weights across engine instances.
- Support TP, PP, EP, multi-node deployments, and MTP.
- Support quantized formats including FP8 and FP4.
- Cache autotune results with hardware- and version-aware keys.
- Preserve correctness through strict cache validation.
- Provide a reliable fallback path for cache misses and failures.

## Cache Validation

Cache entries are identified using model and checkpoint identity, quantization configuration, parallelism settings, GPU architecture, vLLM protocol version, and other relevant runtime metadata.

Incompatible entries must never be silently reused. Cache misses, stale daemon connections, and validation failures produce diagnostics and fall back to the normal loading path when enabled.

## Success Criteria

- Warm engine startup avoids repeated checkpoint loading.
- Cached and regular loading produce equivalent model outputs.
- Cache failures do not compromise correctness or availability.
- Startup, cache-hit, fallback, transfer, and autotune timings are observable.
