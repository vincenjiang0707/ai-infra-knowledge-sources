## 正文

## Summary

- accept an explicit `CUDAGraphMode.FULL` request when PCP is enabled
- retain FULL CUDA graphs for rank-local, one-token-per-request decode batches
- route PCP prefill batches eagerly because Triton MLA prefill metadata is data-dependent and is not safe to replay through a decode-shaped FULL graph

## Design

The PCP-specific policy stays in `PCPManager`. `GPUModelRunner` only delegates three decisions:

1. adjust generic attention CUDA-graph support for an explicit PCP FULL request;
2. restrict capture sizes to decode-compatible shapes;
3. select eager execution for PCP prefill batches.

This preserves the persistent-buffer and decode padding work already used by PCP PIECEWISE and FULL_DECODE_ONLY support, while avoiding a broad MLA metadata/backend change.

## Validation

Tested on two RTX 5090 GPUs with `DeepSeek-V2-Lite-Chat`, BF16, max model length 8192, max batched tokens 8192, max sequences 64, and chunked prefill enabled.

Candidate:

- PCP=2, TP=1, EP enabled
- requested and effective CUDA graph mode: `FULL`
- startup captured 11 FULL graphs

Reference:

- PCP disabled, TP=2, EP enabled
- requested mode `FULL`; upstream Triton MLA capability resolution selected `FULL_AND_PIECEWISE`

The managed image used for the TP=2 reference predates the fused vocab
embedding extension in current main, so that reference used the existing
unfused embedding path as a deployment-only workaround. No embedding change is
included in this PR.

GSM8K five-shot completion evaluation, temperature 0, seed 42, max output 4096, concurrency 32:

| Run | Correct | Accuracy | Invalid | Errors |
|---|---:|---:|---:|---:|
| PCP off smoke | 20/32 | 62.50% | 0 | 0 |
| PCP on smoke | 20/32 | 62.50% | 0 | 0 |
| PCP off full | 871/1319 | 66.0349% | 0 | 0 |
| PCP on full | 878/1319 | 66.5656% | 0 | 0 |

The full-run delta is +7 correct answers for PCP. Predictions matched on 1094/1319 rows; PCP was uniquely correct on 56 differing rows and the reference was uniquely correct on 49.

Static checks:

- `ruff check`: passed

Local torch tests were not run because this workspace requires torch-dependent execution on managed GPU hardware. The candidate was validated through real service startup, FULL graph capture, API smoke, and full-dataset accuracy runs.
