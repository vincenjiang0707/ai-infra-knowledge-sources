# [PR #55891] [Bugfix] Set worker runtime threads before profiling and compilation

source: https://github.com/vllm-project/vllm/pull/55891
state: closed | updated: 2026-09-23T02:12:22Z
labels: bug, ready

## 正文

- Move `set_torch_threads_for_runtime()` to the end of `Worker.load_model`, before memory profiling and compilation.
- Preserve parallel weight loading while keeping the PyTorch thread count consistent between warmup and serving.
- Add a regression using real `torch.compile` that verifies graph reuse across the runtime transition; `.venv/bin/python -m pytest tests/v1/worker/test_gpu_worker.py::test_load_model_preserves_compiled_graphs_at_runtime -q` fails before the fix and passes afterward.

This is an independent compilation candidate: [#49919](https://github.com/vllm-project/vllm/pull/49919) (`7635a9002b`) introduced the post-warmup thread-count transition on August 4, 2026, and was already present in the passing [nightly 12674](https://buildkite.com/vllm/amd-ci/builds/12674#01a07b19-ca8d-499f-a279-e15993ff6da9). Investigation of [build 12711's E2E Scheduling failure](https://buildkite.com/vllm/amd-ci/builds/12711#01a08040-53ed-4d18-9de5-61feb19c4848) led to a separate method-level bisect using historical worker methods, current PyTorch dependencies, and stubbed GPU/model operations. That reproducer shows the thread transition can invalidate compiled graphs under the current runtime; it does not establish when this affected production or explain the September 8 CI failure. Both unmodified nightly endpoints and this patch passed the full scheduling test locally, with the relevant configuration still using 16 graph variants, so this candidate should remain outside the confirmed nightly-regression fixes.

@njhill Helpers like `grouped_topk` compile separately inside the MoE op and keep their own guards. In a small repro, changing the thread count recompiled that helper while the outer graph was reused. So I don’t think it’s strictly stock-only, but the current test doesn’t demonstrate that clearly enough.
