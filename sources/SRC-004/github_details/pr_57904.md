## Summary

Fix Qwen3-Omni EC transfer shapes across Mooncake and CPU/NIXL. Its nested `thinker_config` produces 8192-wide visual DeepStack embeddings but 2048-wide audio embeddings. A fixed width causes Mooncake `EC source shape mismatch` errors and CPU/NIXL under-allocation or incorrect reload shapes.

- Share modality-aware shape inference for Mooncake push/store specs and CPU/NIXL transfers.
- Allocate CPU blocks by tensor bytes and restore the original shape on load.
- Bump the NIXL protocol version to 2; producer and consumer must upgrade together.

## Validation

Qwen3-Omni-30B-A3B-Instruct, TP=1, BF16, Model Runner V2, CUDA graphs enabled, proxy `--no-rewrite`: image-only, audio-only and image+audio requests completed on both Mooncake/TCP and NIXL/UCX without shape errors. Exact output matches against colocated baselines were 1/3 and 2/3 respectively; independently restarted baselines also differed. This validates serving, not absence of an accuracy regression. Video and live-store GPU E2E were not run.

### omerpaz95 · 2026-09-22 · COMMENTED

This is an excellent catch. Some items that are worth your fixes (or at least consideration) while you're here:
1. This PR fixes Qwen3-Omni specifically, but leaves other multimodal models that use deepstack untreated. Specifically, MOSS-Audio and Granite4-Vision have different config shapes:
- Granite4-Vision: width is text_config.hidden_size * (len(deepstack_layer_map) + len(spatial_target_layers)).
- MOSS-Audio: language_config.hidden_size * (1 + deepstack_count) on modality audio, so the ("image", "video") gate excludes it by construction.

This may be worth a separate PR, but I think we need to generalize this solution. Not by adding more if/else gates, but maybe adding some optional config in vllm_config, and rejecting any model that doesn't declare it.
2. If you decide not to generalize, we need to, at the bare minimum, think about how to reject unsupported models on startup. Otherwise, this same class of bug will recur in other models.
