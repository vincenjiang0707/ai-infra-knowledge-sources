## 正文

## Purpose

On lazy/XLA device backends (e.g. TPU via vllm-torchtpu), `ExpertMapManager` triggered a device sync and graph compile per MoE layer during model init:

1. `get_compressed_map_string()` called `.item()` on every element of the device-resident expert map. Its result is an `info_once()` argument, so it is evaluated for every MoE layer, and each distinct element index compiled its own slice module: 128 compiles (~5.4 min serialized) at startup for Qwen3.5-397B at EP8.
2. `determine_expert_map` ran under the model-init device context, so all its ops were device ops, and any host reader of the map had to read it back.

This PR builds the expert map and mask on CPU, keeps a host copy (`_expert_map_host`), moves the tensors to the device once, and builds the log string from the host copy. `update()` recomputes the maps, so the host copy stays in sync with it. The result is value-identical; CUDA/ROCm behavior is unchanged apart from skipping per-element `.item()` syncs.

## Test Plan

- `ruff check` / `ruff format --check` on the changed file.
- Qwen3.5 MTP server startup on TPU (vllm-torchtpu, TP8/EP) with and without the change; compare the EP-map log line and the startup compile count.

## Test Result

The EP log line is unchanged. The per-layer expert-map slice compiles are gone from startup.
