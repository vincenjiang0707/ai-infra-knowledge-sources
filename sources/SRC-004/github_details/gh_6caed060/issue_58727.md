# [Issue #58727] [Bug][Frontend]: Anthropic /v1/messages always hoists inline system messages because merge detection checks the CLI --chat-template (None) instead of the model's template

## 正文

### Your current environment

`main` @ 73a78e6f1f. `vllm serve zai-org/GLM-5.3-Flash --reasoning-parser glm47 --enable-auto-tool-choice --tool-call-parser glm47` (no `--chat-template`), with Claude Code 2.1.281 connected via `/v1/messages`.

### 🐛 Describe the bug

This is item 1 of #58647, split out as its own issue.

`AnthropicServingMessages.__init__` decides whether to hoist inline `role: "system"` messages by calling:

```python
self._merge_inline_system = self._detect_merge_inline_system(chat_template)
```

`chat_template` here is the **`--chat-template` CLI value**, which is `None` for almost every deployment, and `_detect_merge_inline_system` short-circuits:

```python
if not chat_template:
    return True
```

As a result, the probe that renders `[system, user, system, user]` never runs against the template that is actually used, which comes from the tokenizer. **Every deployment that relies on the model's own template goes down the merge path**, including models whose templates handle inline system messages correctly (GLM-5.3 is one). The "preserve in place" branch added in #46025 only runs when a user passes `--chat-template` explicitly.

The merge path (`_convert_system_message`) appends every inline system message to the leading system block. Claude Code sends a new inline system message almost every turn (`<total_tokens>N tokens left</total_tokens>`). So the leading block changes on each request, and everything after it, i.e. the whole conversation, misses the prefix cache. It also changes semantics: a mid-conversation instruction becomes part of the global system prompt.

#### Reproducer (offline, tokenizer only)

The script builds Claude Code-shaped consecutive turns, runs each one through `to_chat_completion_request`, renders it with GLM-5.3-Flash's template, and counts how many prompt tokens turn N+1 shares with turn N. That count is the best possible prefix-cache hit.

<details><summary>repro_inline_system.py</summary>

```python
import json
from transformers import AutoTokenizer
from vllm.entrypoints.anthropic.protocol import AnthropicMessagesRequest
from vllm.entrypoints.anthropic.serving import AnthropicServingMessages

MODEL = "zai-org/GLM-5.3-Flash"
SYSTEM = [
    {"type": "text", "text": "x-anthropic-billing-header: cc_version=2.1.281; cch=abc"},
    {"type": "text", "text": "You are Claude Code, Anthropic's official CLI." * 50},
]
TOOLS = [{"name": "Bash", "description": "Run a shell command.",
          "input_schema": {"type": "object",
                           "properties": {"command": {"type": "string"}},
                           "required": ["command"]}}]


def claude_code_turn(n):
    msgs = [{"role": "user", "content": "List the files in the repo and count them."},
            {"role": "system", "content": "# Environment\n - Platform: linux"}]
    left = 15_000_000
    for i in range(n):
        msgs.append({"role": "assistant", "content": [
            {"type": "thinking", "thinking": f"I should run step {i}.", "signature": ""},
            {"type": "tool_use", "id": f"toolu_{i}", "name": "Bash",
             "input": {"command": f"ls | head -{i + 1}"}}]})
        msgs.append({"role": "user", "content": [
            {"type": "tool_result", "tool_use_id": f"toolu_{i}",
             "content": "\n".join(f"file_{j}.py" for j in range(i + 1))}]})
        left -= 173 * (i + 1)
        msgs.append({"role": "system",
                     "content": f"<total_tokens>{left} tokens left</total_tokens>"})
    return {"model": MODEL, "max_tokens": 32000, "system": SYSTEM,
            "tools": TOOLS, "messages": msgs}


def render(tok, body, merge):
    req = AnthropicServingMessages.to_chat_completion_request(
        AnthropicMessagesRequest.model_validate(body), merge_inline_system=merge)
    messages = [m if isinstance(m, dict) else m.model_dump() for m in req.messages]
    for m in messages:  # chat_utils parses tool-call arguments before rendering
        for tc in m.get("tool_calls") or []:
            tc["function"]["arguments"] = json.loads(tc["function"]["arguments"])
    tools = [t.model_dump(exclude_none=True) for t in req.tools or []]
    text = tok.apply_chat_template(messages, tools=tools, tokenize=False,
                                   add_generation_prompt=True)
    return tok.encode(text, add_special_tokens=False)


def shared(a, b):
    n = 0
    while n < min(len(a), len(b)) and a[n] == b[n]:
        n += 1
    return n


tok = AutoTokenizer.from_pretrained(MODEL)
for label, merge in {
    "today: detect(None)": AnthropicServingMessages._detect_merge_inline_system(None),
    "detect(tokenizer template)":
        AnthropicServingMessages._detect_merge_inline_system(tok.chat_template),
}.items():
    print(f"=== {label} -> merge_inline_system={merge}")
    prompts = [render(tok, claude_code_turn(n), merge) for n in range(1, 5)]
    for i in range(1, len(prompts)):
        k = shared(prompts[i - 1], prompts[i])
        print(f"turn {i}->{i + 1}: shared {k}/{len(prompts[i - 1])} "
              f"({k / len(prompts[i - 1]):.1%})")
```

Output:

```
=== today: detect(None) -> merge_inline_system=True
turn 1->2: shared 671/709 (94.6%)
turn 2->3: shared 684/751 (91.1%)
turn 3->4: shared 697/798 (87.3%)
=== detect(tokenizer template) -> merge_inline_system=False
turn 1->2: shared 712/712 (100.0%)
turn 2->3: shared 756/756 (100.0%)
turn 3->4: shared 805/805 (100.0%)
```

In the merged case, the rendered prompt splits right where the `<total_tokens>` messages pile up in the leading system block, before the first `<|user|>`:

```
...<total_tokens>14999481 tokens left</total_tokens><total_tokens>14998962 tokens left</total_tokens ^ ><total_tokens>14998270 tokens left</total_tokens><|user|>List the files...
```

The shared prefix never grows past the tools block plus the base system prompt. Every token after that is recomputed on each turn, so the cost grows with the length of the session.

I ran the same measurement on captured Claude Code 2.1.281 traffic against GLM-5.3-Flash (4 consecutive main-loop requests, about 20k-token prompts). The results match: today the shared prefix stays at about 17.7k tokens (tools + system prompt, 89–90%) on every turn that adds an inline system message. With detection against the tokenizer template it is 100% on every turn.

#### Expected

`_detect_merge_inline_system` should run against the **resolved** chat template (the tokenizer's `chat_template`, or the renderer's resolved template), not the CLI override. Models whose templates accept non-leading system messages should then keep them in place.

#### Notes / related

- The same pattern is used in `vllm/entrypoints/scale_out/render/serving.py:60`.
- `test_anthropic_messages_conversion.py` asserts `_detect_merge_inline_system(None) is True`, which encodes the current behavior.
- Fixing detection alone does not help templates that really do require system-first (e.g. Qwen's `loop.first` guard): they will still merge and still miss the cache. Those need the fold-into-adjacent-turn approach discussed in #53393. Some templates (MiniMax-M3, the DeepSeek-V3.2 encoder, see #46710 / #53737) also mishandle in-place system messages, so they may need their own fallback.
- Related: #53393, #46710, #48874, #41114. Competing PRs listed in #58647: #53501, #56520, #52978, #47681.

the problem is `AnthropicServingMessages` and `ServingRender` pass the raw CLI `chat_template` arg directly into `_detect_merge_inline_system`. since that defaults to `None`, the detection forces `True` and hoists everything, completely destroying prefix caching regardless of the model's actual tokenizer template.

fixed it locally by falling back to `online_renderer.renderer.get_tokenizer().chat_template` if the CLI override is absent.
