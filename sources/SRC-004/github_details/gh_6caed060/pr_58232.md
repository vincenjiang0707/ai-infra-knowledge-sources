## Purpose

Follow-up to #58211, where the (DGX) Spark GPQA eval has been failing with `RuntimeError: Server exited unexpectedly` across several nightlies.

`gpt-oss-20b-sm120.yaml` is the only config in `tests/evals/gpt_oss/configs/` with no `server_args`, so the engine falls back to the default `gpu_memory_utilization` of 0.92. Spark's GPU memory is unified with system RAM, so free memory on startup is never close to the reported total — the OS and page cache hold tens of GiB at all times. The startup check then refuses to allocate, EngineCore exits, and the harness only surfaces its own terse message.

## Test Plan

Run the eval exactly as CI does, on a DGX Spark (GB10, aarch64, CUDA 13.0, sm_121), against a source build of `main`:

```
pytest tests/evals/gpt_oss/test_gpqa_correctness.py --config-list-file=configs/models-spark.txt
```

## Test Result

Before:

```
INFO [model.py:2097] Using max model len 131072
(EngineCore) ValueError: Free memory on device cuda:0 (83.35/121.7 GiB) on startup is less than
  desired GPU memory utilization (0.92, 111.96 GiB).
(EngineCore) EngineCore failed to start.
E   RuntimeError: Server exited unexpectedly.        # tests/utils.py:706
```

After:

```
(EngineCore) Available KV cache memory: 57.69 GiB
(EngineCore) GPU KV cache size: 2,395,438 tokens, Maximum concurrency for 131,072 tokens per request: 18.28x
(APIServer) INFO:     Application startup complete.
```

Server comes up, and 57 GiB of KV cache is far more than this eval needs.

I can't run the GPQA body itself here — my box is missing the `gpt_oss` eval package — so this is verified up to server startup, not to the accuracy number. And I can't read the Buildkite logs, so if the Spark job output does *not* contain `Free memory on device cuda:0`, something else is going on and this should be closed.

0.6 is a conservative pick rather than a tuned one; happy to change it if you'd prefer a different value.
