## 正文

## Purpose

Bump the ROCm base image's pinned AITER version from `v0.1.22.post1` to
[`v0.1.23`](https://github.com/ROCm/aiter/releases/tag/v0.1.23) (released
2026-09-26), AITER's regular bi-weekly release. Follows the same pattern as
prior bumps (#56885, #55968, #52826).

## Duplicate-work check

```bash
gh pr list --repo vllm-project/vllm --state open --search "aiter v0.1.23"
gh pr list --repo vllm-project/vllm --state open --search "AITER_BRANCH"
gh pr list --repo vllm-project/vllm --state open --search "bump aiter"
```
No open PR bumps AITER to v0.1.23. Closest hits (#51728, #51086, #54095) are
either stale (superseded, targeting older versions) or unrelated (gfx1250-
specific pin, a version-specific API-compat fix already merged separately).

## Test Plan & Result

Diffed `v0.1.22.post1...v0.1.23` for every AITER surface vLLM calls into
directly (`GateMode`, `shuffle_weight`/`shuffle_scale`, the private
`_fused_moe_impl`'s `_q_dtype_a` override, `aiter/__init__.py` exports):
no removals or signature changes. The one relevant refactor — the inline
activation-dtype heuristic moved into a new public
`resolve_activation_dtype()` — still applies `_q_dtype_a` with the same
override precedence as before. `aiter/__init__.py` changes are additive only
(a6w4/a4w6 gemm ops, `topk_select`, gfx1250 asm guards).

```bash
pre-commit run --files docker/Dockerfile.rock_base docker/Dockerfile.rocm_base
```
Clean. Full build/test validation happens via this repo's ROCm Buildkite CI
on this PR, consistent with prior AITER bump PRs.
