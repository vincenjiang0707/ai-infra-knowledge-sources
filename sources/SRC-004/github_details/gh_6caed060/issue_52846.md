# [Issue #52846] [Bug]: DeepSeek V4 buffers long string tool arguments until </parameter>

source: https://github.com/vllm-project/vllm/issues/52846
state: open | updated: 2026-09-25T18:16:47Z
labels: tool-calling

## 正文

### Your current environment

This is reproducible in the parser without a model or accelerator.

- Reproduced on vLLM `v0.25.1` (`752a3a504485790a2e8491cacbb35c137339ad34`).
- Confirmed by source inspection on current `main` at `f1178f3a06fa30a0cc282376924210cedad08c44`: `deepseek_v4_config()` still sets `arg_structural_chars=frozenset(">")`, and `_compute_arg_delta()` still skips converter calls when a raw delta does not contain one of those characters.
- Python 3.12.

### 🐛 Describe the bug

DeepSeek V4 tool calls do not incrementally stream the body of a single long string parameter. The stream emits the function name and the opening JSON prefix, then remains silent for the entire parameter body. When the DSML `</parameter>` closing tag arrives, the accumulated body is emitted as one large `delta.tool_calls[0].function.arguments` fragment.

This is the same user-visible failure mode discussed in #43267, but it affects the DeepSeek V4 parser added in #45877 after #43267 was closed. #46351 added schema-aware support for streaming prefix-stable string values in the shared ParserEngine, but the DeepSeek V4 configuration prevents that path from running for ordinary parameter-body deltas.

#### Minimal parser-only reproduction

The following uses no model weights or accelerator:

```python
import json
from unittest.mock import MagicMock

from vllm.entrypoints.openai.chat_completion.protocol import (
    ChatCompletionToolsParam,
    FunctionDefinition,
)
from vllm.tool_parsers.deepseekv4_engine_tool_parser import (
    DeepSeekV4EngineToolParser,
)

tokenizer = MagicMock()
tokenizer.get_vocab.return_value = {}
tool = ChatCompletionToolsParam(
    type="function",
    function=FunctionDefinition(
        name="emit_text",
        parameters={
            "type": "object",
            "properties": {"text": {"type": "string"}},
            "required": ["text"],
        },
    ),
)
request = MagicMock()
request.tools = [tool]
request.tool_choice = "auto"
parser = DeepSeekV4EngineToolParser(tokenizer, tools=[tool])

header = (
    '<｜DSML｜tool_calls>\n'
    '<｜DSML｜invoke name="emit_text">\n'
    '<｜DSML｜parameter name="text" string="true">'
)
body = "A" * 4096
tail = (
    '</｜DSML｜parameter>\n'
    '</｜DSML｜invoke>\n'
    '</｜DSML｜tool_calls>'
)
chunks = [header] + [body[i : i + 32] for i in range(0, len(body), 32)] + [tail]

previous = ""
argument_deltas = []
for index, delta_text in enumerate(chunks):
    current = previous + delta_text
    delta = parser.extract_tool_calls_streaming(
        previous_text=previous,
        current_text=current,
        delta_text=delta_text,
        previous_token_ids=[],
        current_token_ids=[],
        delta_token_ids=[1],
        request=request,
    )
    previous = current
    if delta:
        for tool_call in delta.tool_calls:
            if tool_call.function and tool_call.function.arguments is not None:
                argument_deltas.append((index, tool_call.function.arguments))

print([(index, len(value)) for index, value in argument_deltas])
print("pre-close non-empty deltas:", sum(
    bool(value) for index, value in argument_deltas if index < len(chunks) - 1
))
print("valid reconstruction:", json.loads("".join(
    value for _, value in argument_deltas
)) == {"text": body})
```

Observed output:

```text
[(0, 10), (129, 4104)]
pre-close non-empty deltas: 1
valid reconstruction: True
```

The only pre-close fragment is the JSON prefix `{"text": "`. All 4096 body characters are withheld and emitted with the closing tag.

Expected behavior: multiple non-empty `function.arguments` deltas should contain parameter body text before `</parameter>`, while their concatenation remains valid JSON after the tool call completes.

#### Root cause

`vllm/parser/deepseek_v4.py` configures:

```python
arg_converter=_dsml_arg_converter,
arg_structural_chars=frozenset(">"),
```

`ParserEngine._compute_arg_delta()` then returns early for every body-only delta:

```python
structural = self._arg_structural_chars
if structural is not None and structural.isdisjoint(raw_delta):
    return None
```

The opening parameter tag contains `>`, so the converter emits `{"text": "`. Typical string body deltas contain no `>`, so they are accumulated without conversion. The closing tag contains `>`, which finally triggers conversion of the full accumulated body.

As a diagnostic control, setting `arg_structural_chars=None` for the same parser input produces 130 non-empty argument deltas (maximum 32 characters) before/finally at close, with exact JSON reconstruction. That demonstrates the filtering condition is the immediate cause, although simply removing it may make the regex-based converter repeatedly scan the full accumulated argument and should be evaluated for long-argument complexity.

#### Real endpoint confirmation

A deterministic `stream=true`, `tool_choice="auto"` request to a DeepSeek V4 Flash service produced:

```text
2.433s  function name: emit_text
2.531s  arguments: {"text": "        (10 characters)
12.893s arguments: <entire body>       (861 characters)
12.942s arguments: "}                  (2 characters)
12.992s finish_reason: tool_calls
```

There were no argument-body deltas for 10.36 seconds. The reconstructed arguments were valid JSON. `tool_choice="auto"` is intentional so the request exercises the DeepSeek V4 parser rather than the generic required/named-tool path.

A regression test should specifically assert that a single long schema-typed string parameter emits more than one body delta before `</parameter>`. The existing mixed-parameter incremental test can pass because each subsequent parameter header contains `>` and flushes the preceding value.

### jayzuccarelli · 2026-09-25

Still reproduces on current main. The short circuit is in ParserEngine._compute_arg_delta (vllm/parser/engine/parser_engine.py:1017-1018): DeepSeek V4 and V3.2 set arg_structural_chars=frozenset(">") (deepseek_v4.py:240, deepseek_v32.py:117), so any delta without a ">" returns before the converter runs and the prefix-stable string path from #46351 never gets used. I'd keep that gate as the cheap path for non-string args and bypass it only when the tool slot has streamable string keys, so string bodies stream and everything else behaves as today. For the test I'll turn your parser-only repro into a case in tests/tool_parsers/test_deepseekv4_tool_parser.py that asserts the body arrives in multiple argument deltas before </parameter> and the joined args still round-trip. I'll put up a PR with a regression test.
