# [PR #58840] [Bugfix][Core] Fix negative indexing of KV cache block hash views

## 正文

## Purpose

`BlockHashListWithBlockSize` exposes hashes for complete blocks at the requested block size. If that size is twice the source block size, `[h0, h1, h2, h3, h4]` becomes `[h1, h3]`, but negative indexing gives the wrong results:

| Expression | Before | Expected |
| --- | --- | --- |
| `view[-1]` | `h4` | `h3` |
| `view[-3]` | `h0` | `IndexError` |

Count negative indices from the end of the view and raise `IndexError` when they are out of range. This makes indexing agree with iteration and slicing, including inherited indexing in Mooncake's `_CompactChunkHashList`.

We found no inference code using negative indices on this view and did not reproduce incorrect model output.

No equivalent open PR was found. #51694 fixes multimodal hashing; #54342 addresses HF3FS cache keys.
