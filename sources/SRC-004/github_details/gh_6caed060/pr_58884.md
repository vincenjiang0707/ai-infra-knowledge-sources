# [PR #58884] [Model] Enable LoRA support for RobertaForSequenceClassification

## 正文

## Purpose

Enable LoRA adapter serving for `RobertaForSequenceClassification` (and its
registry alias `XLMRobertaForSequenceClassification`).

These models are widely used as cross-encoder rerankers (e.g.
`cross-encoder/ms-marco-MiniLM-L-6-v2`, `BAAI/bge-reranker-v2-m3`). Adding
LoRA support allows serving a single base model with multiple fine-tuned
adapters via `LoRARequest`, avoiding the need to merge and redeploy full model
copies for each adapter.

The change follows the same pattern as ModernBertModel (#57148):
- Add `SupportsLoRA` to the class bases
- Declare `packed_modules_mapping` for the fused `qkv_proj` layer

The underlying `BertModel` already uses `QKVParallelLinear` for the fused
QKV projection, which is LoRA-compatible. The component names (`query`, `key`,
`value`) match the HuggingFace weight names that PEFT adapters target.

## Test Plan

Tested with a PEFT LoRA adapter (rank 256) trained on
`cross-encoder/mmarco-mMiniLMv2-L12-H384-v1` (RoBERTa-based cross-encoder)
using vLLM's `LLM.score()` API with `LoRARequest`. Verified:
- Engine starts with `enable_lora=True` without errors
- Adapter loads and produces scores
- Scores are numerically equivalent to the merge-and-unload approach
  (max absolute difference < 0.01, cosine similarity > 0.999)

## Test Result

Benchmark on L4 GPU (bf16, eager mode, max_lora_rank=256):
- Base model: p50=76ms, ~422 pairs/s
- Merged model: p50=72ms, ~442 pairs/s
- Native LoRA: scores equivalent to merged within bf16 tolerance
