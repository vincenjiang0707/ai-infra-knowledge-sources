### 🐛 Describe the bug

### Description
When running an FP8 MoE model (`Qwen3.6-35B-A3B-FP8`) on TPU v6e with `--enable-prefix-caching` enabled, the engine crashes during the warmup phase with an `AssertionError` in `shared_experts.py`. 

The root cause appears to be a state leak in the FP8 `shared_experts` module triggered by a failed AOT compilation attempt. 

### Steps to Reproduce
1. Environment: TPU v6e-8
2. Image: `vllm/vllm-tpu:nightly-20260626-c539adc-cc79815`
3. Command:
```bash
vllm serve Qwen/Qwen3.6-35B-A3B-FP8 \
  --tensor-parallel-size 8 \
  --data-parallel-size 1 \
  --max-model-len 131072 \
  --max-num-batched-tokens 16384 \
  --gpu-memory-utilization 0.85 \
  --max-num-seqs 64 \
  --enable-prefix-caching \
  --trust-remote-code
```  

### Relevant Log Output
```(EngineCore pid=602) INFO 06-26 17:58:38 [compilation_manager.py:133] Precompile worker0 backbone --> {'num_tokens': 2048, 'num_reqs': 64}
(EngineCore pid=602) INFO 06-26 17:58:39 [compilation_manager.py:156] AOT lower skipped for worker0 backbone (ValueError('Invalid shape for `swap`... ')); will compile in warmup.
...
(EngineCore pid=602) ERROR 06-26 17:58:42 [core.py:1231]   File "/workspace/vllm/vllm/model_executor/layers/fused_moe/runner/shared_experts.py", line 165, in forward
(EngineCore pid=602) ERROR 06-26 17:58:42 [core.py:1231]     assert self._output[self._output_idx] is None
(EngineCore pid=602) ERROR 06-26 17:58:42 [core.py:1231] AssertionError
``` 

### Root Cause Analysis
1.) The engine attempts AOT compilation for various input shapes. It succeeds up to num_tokens=1024.
2.) When attempting to compile num_tokens=2048, AOT lowering fails due to a shape mismatch in the prefix caching swap logic:
```AOT lower skipped for worker0 backbone (ValueError('Invalid shape for swap. Ref shape: (2, 0, 2048). Expected shape: (0, 32). Value shape: (1, 32)... ')); will compile in warmup.```

3.) The State Leak: The FP8 shared_experts module does not clear its internal state after this aborted AOT pass.

4.) When the engine immediately moves to the warmup phase and attempts to trace the model, it hits the uncleared state and crashes here:
assert self._output[self._output_idx] is None -> AssertionError

### Additional Context
1.) This bug is a regression. The identical configuration runs successfully on an older image (vllm/vllm-tpu:nightly-20260612-c0c56aa-8a91228).

2.) The crash requires the combination of FP8 MoE (requantizing to float8_e4m3fn), AOT compilation, and --enable-prefix-caching.

### matdou · 2026-06-27

@ericehanley Found the root cause and a fix.

**What crashes and why**

`SharedExperts.forward()` (`vllm/model_executor/layers/fused_moe/runner/shared_experts.py:165`) uses a two-slot buffer `_output = [None, None]`. The contract: `forward()` fills a slot, the `output` property reads and clears it. Line 165 asserts the slot is empty before writing.

The assert fires because the slot is never cleared. The sequence:

1. `CompilationManager._run_compilation` attempts AOT lowering via `fn.lower(...)`.
2. This raises a `ValueError` during shape tracing (`"Invalid shape for swap. Ref shape: (2, 0, 2048). Expected shape: (0, 32). Value shape: (1, 32)"`).
3. The except clause in `compilation_manager.py` (lines 150-158) catches any exception and falls back to a warmup run that calls the real model forward pass.
4. That warmup calls `SharedExperts.forward()`, fills `_output[0]`, then returns without ever calling `se.output`. Slot stays occupied.
5. The next shape's warmup calls `forward()` again. Line 165 asserts the slot is empty. It isn't. Crash.

I verified steps 3-5 by reading `compilation_manager.py` directly and writing a unit test that reproduces the crash and confirms the fix.

I don't know the exact cause of the shape error in step 2. Based on the shapes `(2, 0, 2048)` and `(0, 32)`, my best guess is a zero-size block dimension in the KV cache path when prefix caching finds nothing new to write — but I haven't traced that code path. Can you confirm what triggers the `fn.lower()` failure?

**The fix**

In `shared_experts.py`, reset the stale slot before the assert:

```python
if self._output[self._output_idx] is not None:
    logger.warning_once(
        "shared_experts output slot was not consumed before next "
        "forward() call; clearing stale tensor. This is expected "
        "during a failed AOT compilation pass."
    )
    self._output[self._output_idx] = None

assert self._output[self._output_idx] is None
```

The assert still runs immediately after, so a genuine double-write during real inference still trips it.

**Regression**

PR #45793 ("Upgrade tpu-inference to v0.22.1", merged June 16) bumped JAX from 0.9.2 to 0.10.0. The first nightly built after that merge is `nightly-20260617` (commit `25a54f2`, June 17 06:53 UTC). `nightly-20260612` (your working image) ran tpu-inference 0.21.0 / JAX 0.9.2. I can't confirm whether `nightly-20260616` is broken or safe — its build SHA doesn't resolve in the vLLM repo.

**Workaround**

If you can verify that removing `--enable-prefix-caching` stops the crash, that would confirm the trigger is in the prefix caching path.

Can you test the one-liner fix above and confirm it unblocks startup?
