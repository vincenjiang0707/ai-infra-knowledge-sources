## 正文

## Changes

- Adds `vllm:prompt_tokens_cached_by_source_total{source}` with `source` in `device`, `host`, `p2p`, `disk`, `external_unspecified`. All five series initialize at zero.
- Counted at admission. Invariant: `sum(source) == vllm:prefix_cache_hits + vllm:external_prefix_cache_hits`. `device` equals `vllm:prefix_cache_hits`.
- Scheduler change is 10 lines at the existing `connector_prefix_cache_stats.record(...)` call, which already runs after `update_state_after_alloc` with the accepted hit count and already excludes preempted re-admissions. `prefill_stats.set` stays where main has it.
- `PrefixCacheStats` gains a typed `hits_by_source: CachedTokensBySource`. `PrefillStats`, `PromptTokenStats` and their wire format are unchanged from main.
- Connector contract: `get_external_cache_hit_sources(request, n) -> CachedTokensBySource`, unordered counts summing to `n`. A miscount is reported as `external_unspecified` with a one-time warning instead of asserting.
- Connector mappings: NIXL, Mooncake transfer, MoRIIO: `p2p`. Mooncake Store and other uninstrumented connectors: `external_unspecified`. Simple offload: `host` or `disk`. MultiConnector delegates to the connector that served the request.
- Native offloading attributes each token range to the tier of the keys loaded for it. On hybrid models a token needs every KV group, so when groups disagree the outermost tier (farthest from the accelerator) is reported. `CacheHitSource` is declared in offload order and exposes `outermost()`. Tokens no loaded key covers are `external_unspecified`. Promotion origin is kept per request so a disk or P2P hit staged into host memory is not relabeled `host`.
- Secondary tier default derives from `Medium`: CPU is `host`, STORAGE is `disk`; P2P sets its own.
- Rust frontend decodes the new `PrefixCacheStats` field and emits the same counter. Per-source handles are created lazily like the other request metrics.

Closes vllm-project/vllm#53368.

## Changes since the first review

Per @robertgshaw2-redhat's review: single source of truth, one write site, minimal scheduler surface.

- Attribution moved from `PrefillStats` to the scheduler's existing admission-time prefix-cache record. The moved `prefill_stats.set`, the ordered source segments and the `PrefillStats` wire change are gone.
- Dropped the failure-path truncation in `_update_requests_with_invalid_blocks`. It changed `prompt_tokens_cached_total`, `prompt_tokens_by_source_total{external_kv_transfer}` and the OpenAI `cached_tokens` field on partial KV load failure. Parity with main is kept; a fix for all affected counters belongs in its own PR.
- Typed `CachedTokensBySource` instead of a dict; `EXTERNAL_UNSPECIFIED`; enum moved under `kv_connector`.

## Validation

DeepSeek-V4-Pro, 3,600-second AIPerf AgentX sweeps, evaluations disabled. AIPerf scraped Prometheus. Artifacts include JSON/CSV metrics and request logs.

- [B200 — passed](https://github.com/SemiAnalysisAI/InferenceX/actions/runs/34420875287): [DRAM c8](https://github.com/SemiAnalysisAI/InferenceX/actions/runs/34420875287/artifacts/10133753012), [Simple NVMe c14](https://github.com/SemiAnalysisAI/InferenceX/actions/runs/34420875287/artifacts/10133728096), [native DRAM+NVMe c14](https://github.com/SemiAnalysisAI/InferenceX/actions/runs/34420875287/artifacts/10133870624).
- [GB300 — passed](https://github.com/SemiAnalysisAI/InferenceX/actions/runs/34406466616): [NIXL 1P/1D c256](https://github.com/SemiAnalysisAI/InferenceX/actions/runs/34406466616/artifacts/10134452316).

Those sweeps ran the first design and exercised the connector-side attribution paths this PR keeps. In the native DRAM+NVMe run, ranges where KV groups disagreed were about 2% of external hits. Not yet rerun on GPU since the admission-time change.

B200 included separate backend backports [#55712](https://github.com/vllm-project/vllm/pull/55712) and [#50014](https://github.com/vllm-project/vllm/pull/50014). P2P: 1,740 completed requests, zero request errors, 435 drain-deadline cancellations.

Locally: stats, tiering, Mooncake Store, NIXL offload, multi-connector, load-failure recovery and connector-level attribution tests pass; Rust tests across `vllm-engine-core-client`, `vllm-metrics`, `vllm-llm` pass with clippy clean. Scheduler-level tests rely on CI.
