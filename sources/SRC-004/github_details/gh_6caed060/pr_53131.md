# [PR #53131] [Security] Widen int32 pointer arithmetic to int64 in CUDA kernels

## 正文

## Summary

- Widen 32-bit integer pointer offset arithmetic to 64-bit in CUDA kernels to prevent cross-user data disclosure when `num_tokens * stride` overflows `2^32`
- Applies the established fix pattern from `451227cb3f` (activation_kernels.cu): cast `blockIdx.x` to `int64_t` before multiplying by stride/dimension
- Covers LayerNorm, LayerNorm-quant (FP8), MoE routing, and AllSpark W8A16 GEMM kernels

## Affected kernels

| Kernel | File | Risk |
|---|---|---|
| `rms_norm_kernel` | `layernorm_kernels.cu` | High -- confirmed exploitable with PoC |
| `rms_norm_static_fp8_quant_kernel` | `layernorm_quant_kernels.cu` | High -- FP8 quantized path |
| `fused_add_rms_norm_static_fp8_quant_kernel` (both specializations) | `layernorm_quant_kernels.cu` | High |
| `moeSoftmax` / `moeSigmoid` / `moeTopK` | `topk_softmax_kernels.cu` | Moderate |
| AllSpark W8A16 GmemTile / ComputeTile | `allspark_qgemm_w8a16.cu` | Low (defense in depth) |

## Root cause

CUDA built-in `blockIdx.x` is `unsigned int` (32-bit). When multiplied by a 32-bit `hidden_size` or stride, the product wraps at 2^32, causing a kernel block to read/write another user's hidden state within the same batch. With `hidden_size = 8192`, the overflow triggers at ~524,288 tokens.

## Fix pattern

```cpp
// Before (32-bit overflow)
scalar_t* out_row = out + blockIdx.x * hidden_size;

// After (64-bit safe)
const int64_t token_idx = blockIdx.x;
scalar_t* out_row = out + token_idx * hidden_size;
```

For host-side code, `int input_stride` is widened to `int64_t input_stride` to match the kernel parameter change.
