## 正文

get_mrope_input_positions treated PlaceholderRange.offset as the index of the modality-start token (<|vision_start|>/<|audio_start|>), but the prompt replacement machinery only replaces the pad token, so offset points at the first pad token and the start token is already covered by the preceding text segment. The extra bos slot emitted per media item made the assembled positions one slot longer than the token span: prompts ending with a media item always hit the "Position ids length mismatch" RuntimeError (fatal to EngineCore), and prompts with trailing text got silently misaligned M-RoPE positions from the first pad token onward.

## Purpose

`Qwen3OmniMoeThinkerForConditionalGeneration.get_mrope_input_positions` misinterprets `PlaceholderRange.offset`: the prompt replacement machinery only replaces the pad token, so `offset` points at the first pad token and the modality-start token (`<|vision_start|>` / `<|audio_start|>`) is already covered by the preceding text segment. The function instead treats `offset` as the modality-start index and emits an extra bos slot per media item, making the assembled positions one slot longer than the token span:

- Prompts ending with a media item (e.g. custom/transcription-style chat templates) always hit `RuntimeError: Position ids length mismatch with input ids length`, which is fatal to EngineCore.
- Prompts with trailing text (stock chat template) don't crash, but every M-RoPE position from the first pad token onward is silently misaligned by one slot — a correctness bug on all multimodal requests.

This drops the redundant bos slot and fixes the `st` advancement in each media branch (image/audio/video/audio-in-video) so the emitted position count always equals `seq_len`. The audio-in-video value structure (shared bos/eos positions) is preserved, consistent with the Qwen2.5-Omni behavior in HF.

Follow-up to GHSA-328w-h674-qp56 (per maintainer feedback, the crash path requires an operator-chosen chat template; this PR fixes the offset handling itself).

## Test Plan

```
pytest tests/model_executor/test_qwen3_omni_mrope.py -v
```

New unit tests use synthetic input_ids + `MultiModalFeatureSpec` (no GPU/weights needed):
- `test_mrope_positions_{image,audio,video,audio_in_video}_at_prompt_end`: prompt ending exactly at the modality-end token must yield `positions.shape == (3, seq_len)`.
- `test_mrope_positions_image_then_text`: media followed by text must produce the exact expected per-position values.

## Test Result

Before the fix: all 5 tests fail — the 4 media-at-prompt-end cases raise `RuntimeError: Position ids length mismatch` (the engine-death path), and the image-then-text case fails on misaligned position values.

After the fix: all 5 tests pass.
