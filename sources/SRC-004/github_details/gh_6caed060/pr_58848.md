# [PR #58848] [Bugfix][Frontend] Truncate Responses API auto-truncation at item level

source: https://github.com/vllm-project/vllm/pull/58848
state: closed | updated: 2026-09-27T05:03:53Z
labels: bug

## 正文


Fixes #58421

## Purpose

`truncation: "auto"` on `/v1/responses` was mapped to `truncate_prompt_tokens=-1`, which cuts the rendered prompt at the token level. Depending on the tokenizer's truncation side this discards the `instructions` system message first and can split input items mid-message, instead of dropping whole items from the beginning of the conversation as the OpenAI API contract specifies.

This PR resolves it at the item level in `OnlineRenderer.render_responses`: for non-Harmony requests, the derived token-level truncation is disabled and the oldest droppable conversation message is dropped one at a time (re-rendering after each drop) until the prompt fits, keeping the `instructions` system message and the final message intact. When nothing can be dropped, the original length validation error propagates so the client still receives a 400. Subsequent tool-loop turns and the scale-out render endpoint inherit the behavior through the same code path.

## Test Plan

- New regression tests in `tests/entrypoints/openai/responses/test_serving_responses.py`:
  - `test_online_renderer_auto_truncation_drops_oldest_items` — verifies items are dropped oldest-first, `instructions` and the final message survive, and token-level truncation stays disabled
  - `test_online_renderer_auto_truncation_surfaces_error_when_undroppable` — verifies the original 400 error propagates when nothing can be dropped
  - `test_online_renderer_disabled_truncation_uses_default_tok_params` — verifies `truncation="disabled"` behavior is unchanged
- Run with: `pytest tests/entrypoints/openai/responses/test_serving_responses.py -k truncation`

## Test Result

- `ruff check` / `ruff format` (repo-pinned 0.14.0) pass on both changed files.
- Manual verification against the issue's repro script (Qwen3-0.6B + filler messages) is still pending a GPU machine; CI will run the new unit tests.
