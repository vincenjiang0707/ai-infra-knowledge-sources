# [PR #58619] [Bugfix][KV Offload] Enable partial-tail offload for hybrid models under DCP

state: open | updated: 2026-09-27T05:07:10Z

## 正文

## Purpose

Split out of #57216 per @orozery's review (part 2 of 2): the DCP store guard and per-group addressing, with the `-1` squashed in and `alignment_tokens` reused.

`supports_partial_tail` required `len(group_block_sizes) == 1` **and** `decode_context_parallel_size == 1`. Under DCP the full-attention offload block is `dcp ×` the attention block while recurrent blocks stay unsharded (12288 vs 1536 at DCP 8 — attention groups are scaled in `build_offloading_config` / `resolve_dcp_kv_block_size`, `MambaManager.__init__` undoes the scaling for recurrent state). Both conditions fail, so the feature is off for every hybrid model under DCP.

The store path also addressed every group with one shared physical block index (`boundary // self._partial_tail_block_size`), which is wrong once block sizes differ, and read that block size from `kv_group_configs[0]`, which need not be the full-attention group.

Fix:
- Allow mixed block sizes when every recurrent block divides the full-attention block and is hash-aligned, and hash boundaries split evenly across DCP ranks. The window a tail can lie in is the full-attention offload block, which `SchedulerOffloadConfig.alignment_tokens` already holds — no new field.
- Address each group's source block in its own block size, as the block that *ends* at the boundary: `(boundary - 1) // tokens_per_block`. The old `boundary // tokens_per_block` pointed at the *next* block when the boundary lands on a group's block edge (inert today because `block_indices` is unused on the worker at `blocks_per_chunk == 1`, but wrong the moment that stops holding).
- A hand-off drains every `align` manager for the step, so it can carry more than one boundary (e.g. the last full recurrent block next to the prompt tail, `MambaManager.cache_blocks`). At dcp == 1 the extra ones are full-attention multiples and get filtered. Under DCP they are not, and the existing `assert len(boundaries) == 1` would take the engine core down (see the unit reproducer below). Keep only the longest boundary, which is the tail a consumer's descending probe reaches first. Storing every boundary was proposed separately (#58620) and closed: on hardware, boundaries arrived in separate hand-offs, so longest-only already stored each pair and a consumer diverging before the tail still resumed at the earlier boundary.

At `dcp == 1` the scaling factor is 1, so the guard change is a no-op and the store path resolves to the same single block index as before.

## Test Plan

On a DCP-shaped hybrid fixture (full-attention offload block = `dcp x attention block` = 32, unsharded 16-token Mamba block, hash 4 -- the same shape as 12288 vs 1536 at DCP 8):

```
pytest tests/v1/kv_connector/unit/offloading_connector/ -q
```

Fail on `main`, pass here:
- the guard accepts mixed block sizes under DCP (window 32) and still rejects a DCP-indivisible hash, EAGLE, and a recurrent block that does not divide the full-attention block; at `dcp == 1` it is unchanged (window 16)
- the store addresses each group in its own block size, fences both source blocks, and the self-describing event covers only the valid prefix of the partial block
- **crash reproducer**: a two-boundary request-end hand-off `[(1, 24, 48), (1, 25, 56)]` asserts on the previous code; now the aligned path stores the recurrent row at 48 and the partial path exactly one pair, at 56
- block index for a boundary in the first block (28 -> `[0, 1]`), mid-block (44 -> `[1, 2]`) and on a recurrent block edge (48 -> `[1, 2]`, the block that *ends* there)
- lookup + load under DCP: the tail is laid out per group (full-attention chunk + partial block at indices 0-1, recurrent state at index 2 past the nulls)

Pass on both: an aligned (full-attention multiple) boundary still goes to the aligned path only.

- **`main`:** partial tails are off under DCP, so only whole 2048-token chunks restore, and only when the last full recurrent block lands on the chunk grid.
- **This PR alone:** tails are stored and found within one window of the complete-chunk hit.
- **With #58618:** every prompt restores to its last hash boundary.
- **All trials:** replayed greedy output is byte-identical to the cold recompute (32 tokens), with 0 allocation failures and no assertions or errors in the server logs.
- **Caveat:** on this model each retained boundary arrived in its own hand-off, so the multi-boundary crash path is covered by the unit reproducer only.

An earlier run of the combined change on a 2-node GB300 K3 deployment (TP8/DCP8) is in #57216.

## Notes

- Standalone: correct on its own, but the CPU tier only yields hits beyond one window of the complete-chunk hit once #58618 (lookup anchor) also lands. Merges cleanly with it (verified; the merged tree passes the suite).
- Not duplicating: #53889 scales `UniformTypeKVCacheSpecs` groups by DCP in `build_offloading_config` (config side, complementary); #52397 fixes the `max_offload_tokens` cap in this function and is left to that PR — the baseline lines are kept verbatim here so the rebase is trivial.
- `tokens_per_hash % dcp == 0` is conservative: store and load copy whole physical blocks per rank, so the copy path does not need it, but it is the only shape validated on hardware.
- `dcp == 1` was not run on hardware for this PR; the guard change is a no-op there by construction and the existing dcp=1 unit tests cover the store path.
- #58413 (MTP/EAGLE Mamba offload) touches the same file and merges cleanly; EAGLE stays excluded by this PR's guard.
- AI assistance (Claude / Devin) was used to draft code and tests; every changed line was reviewed and the tests were run by the submitter.
