# [PR #58405] [ROCm][DSv4][Perf] Use the shared prefill chunk plan in the ROCm sparse prefill

## 正文

## Purpose

`DeepseekV4ROCMAiterMLAAttention._forward_prefill` splits prefill requests into fixed groups of `PREFILL_CHUNK_SIZE = 4` and sizes the bf16 gather workspace from the static worst case (`N = ceil(max_model_len / compress_ratio)`, `M = N + window_size + max_num_batched_tokens`). The NVIDIA FlashMLA path already uses `DeepseekSparseSWAMetadata.get_prefill_chunk_plan()` (#45061), which packs requests by workspace area and returns each chunk's real widths.

This PR drives the ROCm prefill loop from the same plan. The loop allocates the workspace per chunk as `(chunk_size, chunk_M, head_dim)` and passes `chunk_N` / `chunk_M` to the SWA gather and `combine_topk_swa_indices`, matching the NVIDIA V4 path. Steps with more than 4 prefill requests now run as fewer, larger chunks. Peak memory is unchanged: the plan's area bound equals the worst case that `forward_mqa()` already reserves during warmup. Decode is unchanged, and steps with at most 4 prefills still run as a single chunk.

`vllm/models/deepseek_v41/amd/rocm.py` has the same loop and is not changed here.

## Test Plan

MI355X (gfx950), TP=1, DeepSeek-V4-Flash, `--kv-cache-dtype fp8`, `VLLM_ROCM_USE_AITER=1`, main `4fb767ff0a`.

- Micro: time `_forward_prefill` on live model inputs for main vs. this PR, in interleaved blocks within one process. Each scenario is one prefill step, summed over 43 layers.
- e2e: a fresh server per run, 4 runs per arm per block with the first discarded, one server on the host at a time.

```bash
vllm serve deepseek-ai/DeepSeek-V4-Flash --kv-cache-dtype fp8 --max-model-len 65536 \
```
