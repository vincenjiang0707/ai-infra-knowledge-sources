### 🐛 Describe the bug

Title: INSTALL_KV_CONNECTORS=true in vLLM 0.27.1 Docker image installs LMCache wheel incompatible with shipped PyTorch, causing lmcache.c_ops to fall back to torch baseline
 
Environment
-----------
- vLLM image version: vllm-project/vllm:v0.27.1 (built with INSTALL_KV_CONNECTORS=true)
- Host GPU driver / CUDA runtime: CUDA 13.0
- PyTorch in image: torch==2.13.0+cu130
- LMCache resolved version: lmcache==0.5.3
- Working comparison: vllm-project/vllm:v0.22.0 (torch==2.11.0) loads lmcache.c_ops correctly.
 
Reproduction
------------
Build the official image:
 
    docker build -t vllm:0.27.1-lmcache \
      --build-arg INSTALL_KV_CONNECTORS=true \
      -f docker/Dockerfile .
 
Deploy any model with kv_connector="LMCacheConnectorV1" or LMCacheMPConnector, then inspect the vLLM pod logs.
 
Observed behavior
-----------------
vLLM 0.27.1 logs:
 
    [LMCache WARNING] lmcache.c_ops compiled extension not found; CudaDeviceOps stays on the torch baseline for all ops.
    [LMCache INFO] multi_layer_block_kv_transfer mode: tensor
 
vLLM 0.22.0 logs:
 
    [LMCache INFO] multi_layer_block_kv_transfer mode: ptr
 
Root cause
----------
requirements/kv_connectors.txt currently pins:
 
    lmcache >= 0.3.9
 
and docker/Dockerfile installs it with:
 
    uv pip install --system -r /tmp/kv_connectors.txt --no-build || ( ...source build fallback... )
 
The first --no-build path installs the LMCache wheel from PyPI. That wheel is compiled against torch==2.11.0 (matching LMCache/pyproject.toml's build-system pin), but vLLM 0.27.1 ships torch==2.13.0. The compiled lmcache.c_ops extension fails to import at runtime due to PyTorch C++ ABI mismatch.
 
Because the wheel install itself succeeds, the Dockerfile's source-build fallback is never executed, so the extension is never recompiled against the vLLM image's actual torch version.
 
vLLM 0.22.0 works only because it also ships torch==2.11.0, which happens to match the LMCache wheel's ABI.
 
Suggested fixes
---------------
1. Force source build against the image's torch
   In the connector install step, build LMCache from source so c_ops is compiled against the same PyTorch/CUDA versions vLLM ships, e.g.:
 
       uv pip install --system -r /tmp/kv_connectors.txt --no-build-isolation --no-binary :lmcache:
 
2. Pin a torch-ABI-compatible LMCache version/wheel
   Update requirements/kv_connectors.txt to reference a lmcache wheel or version built against torch==2.13.0.
 
3. Upstream LMCache wheel matrix
   Coordinate with LMCache to publish wheels for each supported PyTorch ABI, similar to other torch extensions.
 
Expected behavior
-----------------
When INSTALL_KV_CONNECTORS=true is used, the resulting image should load lmcache.c_ops successfully and log:
 
    multi_layer_block_kv_transfer mode: ptr
 
regardless of the vLLM release's PyTorch version.
 
Impact
------
Without lmcache.c_ops, LMCache falls back to the torch baseline path for KV cache transfer. This can silently degrade performance for users who expect the optimized native CUDA path, especially with disaggregated prefill / CPU offloading scenarios.
