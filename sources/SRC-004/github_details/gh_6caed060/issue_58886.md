# [Issue #58886] [Bug][ROCm]: GPU memory fault in AITER MLA FP8 prefill under async scheduling (race on persistent PS metadata)

source: https://github.com/vllm-project/vllm/issues/58886
state: open | updated: 2026-09-27T08:46:17Z

## 正文

**Fix:** #58887 plans the FP8 prefill metadata into pinned host staging and copies it on the current stream, so the update is ordered after in-flight prefill kernels. AITER-side follow-up: [ROCm/aiter#5879](https://github.com/ROCm/aiter/issues/5879).

and the AITER ASM kernels are byte-identical between the two images.

## 🐛 Describe the bug

With `ROCM_AITER_MLA`, an FP8 KV cache and async scheduling, serving crashes with a GPU memory
fault while under load. The FP8 MLA prefill path (`mla_prefill_ps_asm_fwd` + `mla_reduce_v1`)
reads its scheduling metadata from one set of persistent device buffers. Those buffers are
rewritten for every batch that contains a new prefill, by host code that is not ordered on the
current stream. With async scheduling, the rewrite for step N+1 can land while step N's
prefill kernels are still queued. Step N then runs with step N+1's work/reduce maps.

### Standalone reproduction (no server, one gfx950 GPU)

The same race, isolated with the same AITER calls vLLM makes. It reproduces on ROCm 7.2 as
well as ROCm 10:

1. Plan batch A (one 8175-token prefill, no partial tiles) into persistent device buffers
   with `aiter.get_ps_metadata_v1`.
2. On a non-blocking `torch.cuda.Stream()` (the stream vLLM uses), queue a GPU delay
   (`torch.cuda._sleep`), then A's `mla_prefill_ps_asm_fwd` + `mla_reduce_v1`.
3. Immediately plan batch B (three prefills: 6992, 6896, 2495 tokens) into the same buffers
   from the host, as step N+1's metadata build does under async scheduling.
4. Synchronize and compare A's output with a reference run.

| Mode | ROCm 7.2 | ROCm 10 |
| --- | --- | --- |
| as above (vLLM's current pattern) | GPU memory fault on the first iteration | GPU memory fault on the first iteration |
| `stream.synchronize()` before planning B | output matches reference | output matches reference |
| plan B into pinned host memory, `copy_(non_blocking=True)` on the stream (proposed fix) | output matches reference | output matches reference |

The fault has the serving signature: `Memory access fault ... on address 0x1d000` / `0x64000`,
`Write access to a read-only page` (or `Unknown`). Script: `aiter_ps_metadata_race.py` ([gist](https://gist.github.com/amd-mghanimi/970e190ceea417467594980b96f3604b), also inlined below).
Run it inside either vLLM ROCm image with `python3 aiter_ps_metadata_race.py`. Add `--streams 12`
for the per-stream table in "Why ROCm 7.2 does not show it end to end".

#!/usr/bin/env python3
"""Standalone reproducer: AITER MLA FP8 prefill plan rewritten while in use (vLLM async scheduling).

Mirrors vLLM's ROCM_AITER_MLA FP8 prefill (rocm_aiter_mla.py @ 29468dde,
_build_fp8_prefill_ps_metadata + _mla_fp8_prefill_attn) on one gfx950 GPU:

  1. Plan batch A (one 8175-token prefill) into persistent device buffers with
     aiter.get_ps_metadata_v1, as vLLM does.
  2. On a non-blocking stream (as vLLM uses), queue a GPU delay standing in for step N's
     earlier layers, then A's mla_prefill_ps_asm_fwd + mla_reduce_v1.
  3. Immediately plan batch B (three prefills) into the same buffers from the host, as step
     N+1's metadata build does under async scheduling.
  4. Synchronize and compare A's output with a reference.

Default run, one stream, three modes (each in its own process, since a GPU fault kills it):
  race    vLLM's current pattern: device outputs, stream-less hipMemcpy inside AITER.
  synced  stream.synchronize() before planning B.
  fixed   plan into pinned host staging, copy_(non_blocking=True) on the stream (the vLLM fix).

  python3 aiter_ps_metadata_race.py

Expected on ROCm 7.2 and ROCm 10 alike: race faults, synced and fixed match the reference.

Why ROCm 7.2 serving can still look fine:
  python3 aiter_ps_metadata_race.py --streams 12

runs the race on each of 12 non-blocking streams. It first probes which streams a stream-less
1 KiB hipMemcpy waits behind, i.e. which share the null stream's in-order hardware queue.
AITER's first plan copy is that small, so it runs as a copy kernel on the null stream's queue.
Only prefill streams on a shared queue are protected. Queue assignment differs between ROCm
versions and runtime settings (try DEBUG_HIP_DYNAMIC_QUEUES=1 or GPU_MAX_HW_QUEUES=16 on
ROCm 7.2).
"""
import argparse
import ctypes
import json
import os
import subprocess
import sys
import time

TILE_Q = 256  # _FP8_PREFILL_TILE_Q
NHEAD = 16  # 12 heads/rank (Kimi-K3 TP8) replicate-padded to 16 for the ASM prefill
QK_DIM, V_DIM = 192, 128  # mla_pfl_qh192_vh128_*
MAX_REQS, MAX_TOKENS = 256, 16384
BATCH_A = [8175]  # the crash batch's prefill
BATCH_B = [6992, 6896, 2495]  # a following multi-prefill batch
PLAN_KW = dict(qhead_granularity=1, qlen_granularity=TILE_Q, kvlen_granularity=128,
               block_size=1, is_causal=True)


def alloc_plan_buffers(torch, device, pin=False):
    from aiter import get_ps_metadata_info_v1

    info = get_ps_metadata_info_v1(batch_size=MAX_REQS, num_head_k=NHEAD,
                                   max_qlen=MAX_TOKENS, qlen_granularity=TILE_Q)
    bufs = []
    for size, dtype in info:
        shape = size if isinstance(size, tuple) else (size,)
        bufs.append(torch.empty(*shape, dtype=dtype, device=device,
                                pin_memory=pin and device == "cpu"))
    return bufs  # work_meta, work_indptr, work_info, reduce_indptr, reduce_final, reduce_partial


def plan(torch, bufs, seq_lens):
    from aiter import get_ps_metadata_v1

    lens = torch.tensor(seq_lens, dtype=torch.int32)
    qo = torch.zeros(len(seq_lens) + 1, dtype=torch.int32)
    qo[1:] = lens.cumsum(0)
    get_ps_metadata_v1(qo, qo.clone(), lens, 1, NHEAD, *bufs, **PLAN_KW)


class PrefillA:
    def __init__(self, torch):
        self.torch = torch
        torch.manual_seed(0)
        total = sum(BATCH_A)
        fp8 = torch.float8_e4m3fn
        self.q = (torch.randn(total, NHEAD, QK_DIM, device="cuda") * 0.5).to(fp8)
        self.k = (torch.randn(total, NHEAD, QK_DIM, device="cuda") * 0.5).to(fp8)
        self.v = (torch.randn(total, NHEAD, V_DIM, device="cuda") * 0.5).to(fp8)
        self.qo = torch.tensor([0, total], dtype=torch.int32, device="cuda")
        self.kv_indices = torch.arange(total, dtype=torch.int32, device="cuda")
        self.total = total
        self.one = torch.ones((), dtype=torch.float32, device="cuda")
        # vLLM carves per-call scratch from a pre-reserved workspace.
        self.workspace = torch.empty(64 << 20, dtype=torch.uint8, device="cuda")

    def launch(self, dev_bufs, num_partial_tiles):
        from aiter import mla_prefill_ps_asm_fwd, mla_reduce_v1

        torch = self.torch
        shapes = [((num_partial_tiles * TILE_Q, NHEAD, V_DIM), torch.float32),
                  ((num_partial_tiles * TILE_Q, NHEAD), torch.float32),
                  ((self.total, NHEAD), torch.float32)]
        scratch, off = [], 0
        for s, d in shapes:
            n = torch.Size(s).numel() * torch.empty((), dtype=d).element_size()
            scratch.append(self.workspace[off:off + n].view(d).view(s))
            off += (n + 255) // 256 * 256
        logits, lse, final_lse = scratch
        _, work_indptr, work_info, reduce_indptr, reduce_final, reduce_partial = dev_bufs
        out = torch.empty(self.total, NHEAD, V_DIM, dtype=torch.bfloat16, device="cuda")
        mla_prefill_ps_asm_fwd(self.q, self.k, self.v, self.qo, self.qo, self.kv_indices,
                               work_indptr, work_info, max(BATCH_A), QK_DIM ** -0.5, True,
                               logits, lse, out, self.one, self.one, self.one)
        mla_reduce_v1(logits, lse, reduce_indptr, reduce_final, reduce_partial, TILE_Q, 0,
                      out, final_lse)
        return out


def child(mode, num_streams, index, iters, delay_ms, probe):
    import numpy as np
    import torch

    print(f"HIPVER {torch.version.hip}", flush=True)
    torch.zeros(1, device="cuda")  # the null stream exists first, as in frameworks
    # Load AITER and allocate before creating streams, as vLLM does (model load, then streams).
    dev_bufs = alloc_plan_buffers(torch, "cuda")
    staging = [alloc_plan_buffers(torch, "cpu", pin=True) for _ in range(2)]
    a = PrefillA(torch)
    plan(torch, dev_bufs, BATCH_A)
    torch.cuda.synchronize()
    streams = [torch.cuda.Stream() for _ in range(num_streams)]
    # HIP binds a stream to a hardware queue at its first launch; launch on every stream once,
    # in order, so the stream-to-queue mapping does not depend on the tested index.
    for s in streams:
        with torch.cuda.stream(s):
            torch.cuda._sleep(1000)
    torch.cuda.synchronize()
    stream = streams[index]

    with torch.cuda.stream(stream):
        torch.cuda._sleep(1_000_000)
        t0, t1 = torch.cuda.Event(True), torch.cuda.Event(True)
        t0.record()
        torch.cuda._sleep(50_000_000)
        t1.record()
    t1.synchronize()
    cycles = int(50_000_000 * delay_ms / t0.elapsed_time(t1))

    if probe:
        hip = ctypes.CDLL("libamdhip64.so")
        hip.hipMemcpy.argtypes = [ctypes.c_void_p, ctypes.c_void_p, ctypes.c_size_t, ctypes.c_int]
        dst = torch.empty(1024, dtype=torch.uint8, device="cuda")
        src = np.zeros(1024, dtype=np.uint8)
        hip.hipMemcpy(dst.data_ptr(), src.ctypes.data, 1024, 1)
        torch.cuda.synchronize()
        shared = []
        for j, s in enumerate(streams):
            with torch.cuda.stream(s):
                torch.cuda._sleep(cycles)
            t = time.perf_counter()
            hip.hipMemcpy(dst.data_ptr(), src.ctypes.data, 1024, 1)
            if (time.perf_counter() - t) * 1000.0 > 0.5 * delay_ms:
                shared.append(j)
            torch.cuda.synchronize()
        print("PROBE " + json.dumps(shared), flush=True)

    with torch.cuda.stream(stream):
        plan(torch, dev_bufs, BATCH_A)
        ref = a.launch(dev_bufs, int(dev_bufs[3][-1].item()))
    torch.cuda.synchronize()

    mismatches, walls = 0, []
    for it in range(iters):
        with torch.cuda.stream(stream):
            if mode == "fixed":
                host = staging[it % 2]
                plan(torch, host, BATCH_A)
                for d, h in zip(dev_bufs[1:], host[1:]):
                    d.copy_(h, non_blocking=True)
                tiles = int(host[3][-1])
            else:
                plan(torch, dev_bufs, BATCH_A)
                tiles = int(dev_bufs[3][-1].item())
            torch.cuda._sleep(cycles)  # step N's earlier layers still running
            out = a.launch(dev_bufs, tiles)  # step N's prefill reads the plan
            if mode == "synced":
                stream.synchronize()
            t = time.perf_counter()
            if mode == "fixed":  # step N+1's plan, stream-ordered
                host = staging[(it + 1) % 2]
                plan(torch, host, BATCH_B)
                for d, h in zip(dev_bufs[1:], host[1:]):
                    d.copy_(h, non_blocking=True)
            else:  # step N+1's plan, stream-less hipMemcpy into the shared buffers
                plan(torch, dev_bufs, BATCH_B)
            walls.append((time.perf_counter() - t) * 1000.0)
        torch.cuda.synchronize()
        mismatches += int((out.float() - ref.float()).abs().max().item() > 0)
    print("RESULT " + json.dumps({"mismatches": mismatches,
                                  "plan_b_ms": round(sum(walls) / len(walls), 1)}), flush=True)


def run_child(args, mode, num_streams, index, probe):
    cmd = [sys.executable, os.path.abspath(__file__), "--child", mode, "--streams",
           str(num_streams), "--index", str(index), "--iters", str(args.iters),
           "--delay-ms", str(args.delay_ms)] + (["--probe"] if probe else [])
    out = subprocess.run(cmd, capture_output=True, text=True)
    text = out.stdout + out.stderr
    info = {"hip": next((l[7:] for l in out.stdout.splitlines() if l.startswith("HIPVER ")), "?"),
            "probe": next((json.loads(l[6:]) for l in out.stdout.splitlines()
                           if l.startswith("PROBE ")), None)}
    res = next((json.loads(l[7:]) for l in out.stdout.splitlines() if l.startswith("RESULT ")), None)
    if res is not None:
        info["verdict"] = "WRONG OUTPUT" if res["mismatches"] else "ok"
        info["detail"] = f"output matches reference; plan B call {res['plan_b_ms']} ms" \
            if not res["mismatches"] else f"{res['mismatches']}/{args.iters} iterations differ"
    elif "Memory access fault" in text or "illegal memory access" in text or out.returncode < 0:
        info["verdict"] = "GPU FAULT"
        fault = next((l.strip() for l in text.splitlines() if "Memory access fault" in l), "")
        info["detail"] = fault or "illegal memory access"
    else:
        info["verdict"] = "error"
        info["detail"] = (text.strip().splitlines() or [f"rc={out.returncode}"])[-1][:100]
    return info


def main():
    p = argparse.ArgumentParser(description=__doc__, formatter_class=argparse.RawDescriptionHelpFormatter)
    p.add_argument("--streams", type=int, default=1,
                   help="create this many non-blocking streams; >1 runs the race on each")
    p.add_argument("--iters", type=int, default=5)
    p.add_argument("--delay-ms", type=float, default=50.0)
    p.add_argument("--child", choices=["race", "synced", "fixed"], help=argparse.SUPPRESS)
    p.add_argument("--index", type=int, default=0, help=argparse.SUPPRESS)
    p.add_argument("--probe", action="store_true", help=argparse.SUPPRESS)
    args = p.parse_args()

    if args.child:
        child(args.child, args.streams, args.index, args.iters, args.delay_ms, args.probe)
        return

    env = " ".join(f"{k}={os.environ[k]}" for k in
                   ("GPU_MAX_HW_QUEUES", "DEBUG_HIP_DYNAMIC_QUEUES", "AMD_SERIALIZE_COPY")
                   if k in os.environ) or "runtime defaults"
    if args.streams == 1:
        rows = [(m, run_child(args, m, 1, 0, False)) for m in ("race", "synced", "fixed")]
        print(f"HIP {rows[0][1]['hip']}, {env}, {args.delay_ms:.0f} ms delay, {args.iters} iterations")
        print(f"{'mode':<7} | {'result':<12} | detail")
        print("-" * 72)
        for m, r in rows:
            print(f"{m:<7} | {r['verdict']:<12} | {r['detail']}")
        return

    rows = [(i, run_child(args, "race", args.streams, i, True)) for i in range(args.streams)]
    hip_ver = rows[0][1]["hip"]
    print(f"HIP {hip_ver}, {env}, race mode, {args.streams} streams, "
          f"{args.delay_ms:.0f} ms delay, {args.iters} iterations")
    print(f"{'prefill stream':>14} | {'shares null-stream queue':>24} | {'result':<12} | detail")
    print("-" * 96)
    for i, r in rows:
        shares = "?" if r["probe"] is None else ("yes" if i in r["probe"] else "no")
        print(f"{i:>14} | {shares:>24} | {r['verdict']:<12} | {r['detail']}")


if __name__ == "__main__":
    main()

### Exact error

On most ranks at once, with the address in 0x6c000-0x6f000:

```text
Warning: Queue error - HSA_STATUS_ERROR_MEMORY_FAULT
Memory access fault by GPU node-4 (Agent handle: ...) on address 0x6c000. Reason: Write access to a read-only page.
terminate called after throwing an instance of 'c10::AcceleratorError'
  what():  CUDA error: an illegal memory access was encountered
```

The batch vLLM dumps at the fault always has the same shape: one new, unchunked ~8.1k-token
prefill plus 29-30 decodes (e.g. `num_scheduled_tokens` sum 8204 = 8175 + 29 x 1). That step
is larger than `max_cudagraph_capture_size`, so it runs without CUDA graphs.

## When the error disappears

Each row changes one thing relative to the reproduction (same stream, seed 4, 1024 prompts):

| Change | Result |
| --- | --- |
| none | fault at request 111 |
| `--enforce-eager` | fault at request 111 (CUDA graphs not involved) |
| FP8 ASM prefill disabled (`_fp8_mla_prefill_supported()` forced to `False`) | 1024/1024 |
| `--no-async-scheduling` | 1024/1024 |
| `torch.cuda.synchronize()` immediately before `get_ps_metadata_v1` | 1024/1024 (x2) |
| real LSE buffer passed to the decode kernel (`final_lse` non-null) | fault at request 78 (decode not involved) |
| instrumentation that synchronizes after every MLA call | 1024/1024 (the race is hidden) |
| ROCm 7.2 image, same code | no fault observed end to end (the standalone reproduction does fault) |
| `AMD_SERIALIZE_COPY=1` (runtime: copies wait for already-queued work) | 1024/1024 (the same stream faulted at request 78 without it) |
| `GPU_MAX_HW_QUEUES=1` (runtime: every stream shares one hardware queue) | 1024/1024 (same stream) |
| proposed fix (stream-ordered metadata update, see below) | 1024/1024 on every stream above |

`VLLM_ROCM_AITER_MLA_ASM_PADDING` makes no difference with an FP8 KV cache. `use_gluon_decode()`
returns `False` for any quantized KV cache before the setting is read, so "asm" and "auto" run
the same kernels.

## Root cause

1. One persistent set of FP8 prefill PS metadata buffers is allocated per builder
   ([`_init_fp8_prefill_ps_buffers`, L785-L804](https://github.com/vllm-project/vllm/blob/29468dde8b515031dc6d4d9d06bf0a2fa0442098/vllm/v1/attention/backends/mla/rocm_aiter_mla.py#L785-L804)).
2. Every batch with an unchunked prefill rewrites them via `aiter.get_ps_metadata_v1`
   ([`_build_fp8_prefill_ps_metadata`, L901-L918](https://github.com/vllm-project/vllm/blob/29468dde8b515031dc6d4d9d06bf0a2fa0442098/vllm/v1/attention/backends/mla/rocm_aiter_mla.py#L901-L918),
   called from [`build()`, L1315-L1320](https://github.com/vllm-project/vllm/blob/29468dde8b515031dc6d4d9d06bf0a2fa0442098/vllm/v1/attention/backends/mla/rocm_aiter_mla.py#L1315-L1320)).
   Each step's metadata only references the shared buffers
   ([L937-L941](https://github.com/vllm-project/vllm/blob/29468dde8b515031dc6d4d9d06bf0a2fa0442098/vllm/v1/attention/backends/mla/rocm_aiter_mla.py#L937-L941)).
3. `get_ps_metadata_v1` plans on the host and copies the result into the caller's device
   tensors with blocking `hipMemcpy` and no stream
   ([aiter `v1_2_host.cuh` L395-L418](https://github.com/ROCm/aiter/blob/v0.1.22.post1/csrc/kernels/mla/metadata/v1_2_host.cuh#L395-L418)).
4. The consumers, `mla_prefill_ps_asm_fwd` and `mla_reduce_v1`, are launched asynchronously
   once per layer
   ([L1799-L1832](https://github.com/vllm-project/vllm/blob/29468dde8b515031dc6d4d9d06bf0a2fa0442098/vllm/v1/attention/backends/mla/rocm_aiter_mla.py#L1799-L1832)).
5. The builder's `.item()` sync on `reduce_indptr[-1]` comes after the rewrite, so it cannot
   prevent it
   ([L930-L931](https://github.com/vllm-project/vllm/blob/29468dde8b515031dc6d4d9d06bf0a2fa0442098/vllm/v1/attention/backends/mla/rocm_aiter_mla.py#L930-L931)).

Decode is not affected: its plan comes from `get_mla_metadata_v1`, a device-side kernel on the
current stream
([L1221](https://github.com/vllm-project/vllm/blob/29468dde8b515031dc6d4d9d06bf0a2fa0442098/vllm/v1/attention/backends/mla/rocm_aiter_mla.py#L1221)).

### Why ROCm 7.2 does not show it end to end

ROCm 7.2 has the same race and hides it by accident: in practice, its plan copy waits behind
GPU work that is already queued.

**Same rules on both versions.**

- vLLM runs these kernels on a non-blocking stream it creates, on both runtimes.
- A stream-less `hipMemcpy` waits only for the null stream and for blocking streams, never for
  non-blocking ones. The code path is the same in the two HIP runtime builds shipped in these
  images (`ROCm/rocm-systems` `af70edc9` for 7.2 and `25e14349` for ROCm 10, per vLLM's
  `Dockerfile.rocm_base` / `Dockerfile.rock_base`).
- In a two-stream test, `get_ps_metadata_v1` returns on both versions while a kernel on a
  vLLM-style stream is still running, and the new bytes are already visible.
- The standalone reproduction above faults on both.

**The window opens equally often.** With a non-synchronizing counter, about 7–11% of prefill
plan updates start while the previous step's prefill is still queued, on both images.

**The difference is how long the copy takes when it overlaps.** We timed `get_ps_metadata_v1`
in the server, with no added synchronization:

| When the previous prefill is still queued | ROCm 10 | ROCm 7.2 |
| --- | --- | --- |
| Mean plan-update time | ~0.8 ms | ~105–133 ms |
| Updates that returned only after that prefill finished | almost none | about two thirds |
| Mean plan-update time with no overlap | ~0.9 ms | ~14.5 ms |

On ROCm 7.2 the copy usually sits behind in-flight work, including the prefill still reading
the plan. On ROCm 10 it lands immediately, which is the fault.

**Why a blocking copy can end up waiting for unrelated work.**

- The first of AITER's five copies, `work_indptr` (1,028 bytes), is below HIP's 16 KiB blit
  threshold (`GPU_FORCE_BLIT_COPY_SIZE`). The runtime therefore runs it as a small copy kernel
  on the null stream's hardware queue. The other four copies use the SDMA engines.
- Hardware queues are in order. A process with more streams than hardware queues (default 4
  per GPU) shares them.
- If the null stream's queue holds in-flight work, that copy waits for it. Because every
  `hipMemcpy` blocks, the whole plan update waits too.

Forcing every stream onto one hardware queue on ROCm 10 (`GPU_MAX_HW_QUEUES=1`) removes the
fault, and so does `AMD_SERIALIZE_COPY=1`. Both are on a stream that faults at request 78
otherwise.

**Changing ROCm 7.2's queue assignment makes it crash.** Unpatched ROCm 7.2, same request
streams:

| ROCm 7.2 | Result |
| --- | --- |
| defaults | 1024/1024, 2048/2048 |
| `DEBUG_HIP_DYNAMIC_QUEUES=1` | crash at request 117 (x3, on 2 machines, including the stock image); plan update now ~0.8 ms |
| `GPU_MAX_HW_QUEUES=16` | crash at request 111 (x2, on 2 machines, stock image) |
| `DEBUG_HIP_DYNAMIC_QUEUES=1` + proposed fix | 1024/1024 |
| `GPU_MAX_HW_QUEUES=16` + proposed fix | 1024/1024 |

Both crashes are `hipErrorIllegalAddress` with the usual crash batch, at the same request
numbers where ROCm 10 faults. A single-GPU version of the standalone reproduction runs the
prefill on each of 12 non-blocking streams. On ROCm 7.2 defaults, only the streams that share
the null stream's hardware queue are protected; with either setting, or on ROCm 10, every
stream faults.

Which stream shares that queue depends on the order in which streams first launch work,
because HIP binds a stream to a hardware queue at first use. That is also why
`DEBUG_HIP_DYNAMIC_QUEUES=0` does not protect ROCm 10 in vLLM: it still faults at request 117,
because its static mapping puts the collision on other streams.

Either way, correctness must not rely on this. The copy has no ordering guarantee on any ROCm
version.

When the stale indices stay in bounds, the prefill attention output would be silently wrong
instead of faulting. We have not linked this to a measured accuracy drop: `niah_single_2`
(4k at concurrency 4/32/64, 64k and 128k at concurrency 32) scored the same with and without
the fix.

## How this was narrowed down

- Reproduced deterministically (fixed stream, same fault request) and checked eager mode:
  still faults, so CUDA graphs are not involved.
- Confirmed from the backend code that FP8 KV routes decode to the padded ASM persistent
  kernel `mla_a8w8_qh16_qseqlen1_gqaratio16_ps`, whatever the ASM padding setting.
- Compared the ROCm 7.2 and ROCm 10 images: identical vLLM/AITER Python and identical ASM
  `.co` files. Kernel-argument layouts match their declared sizes. All compiled AITER modules
  and the HIP runtime differ.
- Toggled one component at a time (table above). Only removing the FP8 prefill path, removing
  async scheduling, or ordering the metadata rewrite made the fault go away.
- Checked AITER's host planner: it writes full output buffers with stream-less `hipMemcpy`
  (`work_info` alone is ~8.9 MB at `batch=256, max_qlen=16384`).
- Verified that `get_ps_metadata_v1` accepts pinned host output tensors and produces
  byte-identical plans to device outputs (5 batch shapes, including the crash batch). This is
  what the fix relies on.
- Checked which stream vLLM uses (non-blocking, on both images) and whether a stream-less
  `hipMemcpy` waits for queued kernels on it (no, on both runtimes). Then isolated the race in
  the standalone reproduction above, which faults on ROCm 7.2 too.

## Proposed fix

vLLM-only: plan into two pinned host staging slots, copy to the device buffers with
`copy_(non_blocking=True)` on the current stream, and reuse a slot only after its previous
copy completes (CUDA event). `num_partial_tiles` then comes from the host plan, which removes
a GPU sync per prefill step. Throughput is unchanged (e.g. 8k/1k concurrency 32: 1083.0 vs
1082.6 output tok/s). PR: #58887.

An AITER-side follow-up (a stream-ordered host planner, or a device-side planner like decode)
would make device outputs safe for all callers:
[ROCm/aiter#5879](https://github.com/ROCm/aiter/issues/5879).
