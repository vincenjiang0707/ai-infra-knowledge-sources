## 正文

## Purpose

When a prefix-cache hash has multiple physical copies, `BlockHashToBlockMap` promotes its value to a dictionary. Eviction currently retains that dictionary even when only one copy remains. Subsequent lookups can repeatedly scan its deleted entries, and its allocation remains live.

Restore the existing direct `KVCacheBlock` representation when eviction leaves one copy. Extend the existing mapping test to cover re-insertion, an unknown block ID and final removal, and update the pool-eviction expectations. Block identity, reference counts, cache contents and KV-event behavior are preserved.

The state is reachable through repeated `prompt_logprobs` requests followed by cache pressure. The benefit applies when the surviving prefix is subsequently reused; ordinary cache hits need not encounter this state. Checked the actual diffs of #55092 and #48933, which change removal-event semantics/counts and retain singleton dictionaries, and #40459, which adds an optional Rust pool without fixing this Python mapping. This follows the compact-representation approach introduced in #24830.

- **649 passed, 2 skipped**; the two skips are the CUDA/ROCm-only simple-offload worker/integration modules on CPU. All applicable pre-commit checks passed. The compact-representation assertion was first shown to fail on the original implementation.
- CPU environment: AMD Ryzen 7 9700X, WSL Ubuntu, Python 3.12.3, torch 2.13.0+cpu. CPU extensions are from nightly `29468dde8`, not an exact current-main binary build.
- Prior GPU validation used base `a4eb3f25` with its exact CUDA wheel and the same production patch: RTX 4090, Qwen3-0.6B revision `c1899de289a04d12100db370d81485cdf75e47ca`, FP16, seed 0, V1/MRV2, eager, single GPU. Four baseline–patch–patch–baseline runs passed. All 211 completed requests per run had identical generated tokens, generated-token logprobs and cache-hit counts. Active-request reset/recomputation and cancellation checks passed; all non-null blocks were released. The model workload reached 16 copies → one and released 5,056 bytes of inner dictionaries for its eight target hashes. This GPU validation has not been rerun on the newer base.

Earlier real-`KVCacheManager` CPU lookup measurements at `a4eb3f25`, for a 4,096-token prefix after duplicate eviction (1,000 queries × 7 repeats, median):

| Original copies → one | Baseline / patch, µs | Inner dictionary storage, baseline / patch |
| --- | --- | --- |
| 1 → 1 control | 84.71 / 85.38 | 0 / 0 bytes |
| 2 → 1 | 102.69 / 83.61 | 57,344 / 0 bytes |
| 32 → 1 | 106.25 / 84.19 | 299,008 / 0 bytes |
| 128 → 1 | 122.26 / 85.49 | 1,200,128 / 0 bytes |

The 128-copy case is a constructed CPU workload, not the GPU workload. These are dictionary allocation sizes, not process RSS or GPU memory savings.

A further CPU comparison on the current base included duplicate creation, pressure eviction and subsequent hot-request query/allocation/free costs in one timed phase. With two copies → one, followed by 8 or 32 normal requests, wall-time medians were 1.844 → 1.489 ms and 5.352 → 4.805 ms respectively. This used a 4,096-token prefix, one CPU, enabled GC, two warmups and 30 alternating repetitions; manager/request construction and model execution were excluded.

There is a tradeoff: continuously cycling one ↔ two copies **without prefix reuse** reallocates dictionaries. The isolated insert/pop pair took 0.369 versus 0.279 µs. In a separate real-manager repeated-scoring workload, the 4,096-token query-entry/allocation/free cycle measured 303.70 versus 276.68 µs, with substantial sample variation. These costs remain relevant; the optimization is workload-dependent.

Production prevalence, long-running RSS/GC behavior and a statistically significant serving-throughput improvement have not been established. Multi-GPU, quantization and speculative decoding were not model-tested. Prefix-query savings must not be multiplied by generated-token count; admission retries/recomputation can add queries, but their real frequency was not measured.

```python
"""CPU cache-manager lifecycle and timing; no simulated GPU/model result."""
import json
import platform
import statistics
import sys
import timeit

import torch
import vllm.v1.core.block_pool as block_pool_module

from vllm.sampling_params import SamplingParams
from vllm.utils.hashing import sha256
from vllm.v1.core.kv_cache_manager import KVCacheManager
from vllm.v1.core.kv_cache_utils import get_request_block_hasher, init_none_hash
from vllm.v1.kv_cache_interface import FullAttentionSpec, KVCacheConfig, KVCacheGroupSpec
from vllm.v1.request import Request


def request(name, tokens, scoring=False):
    return Request(request_id=name, prompt_token_ids=tokens,
                   sampling_params=SamplingParams(max_tokens=1, prompt_logprobs=1 if scoring else None),
                   pooling_params=None, block_hasher=get_request_block_hasher(16, sha256))


def run(copies, num_blocks):
    num_tokens = num_blocks * 16
    tokens = list(range(num_tokens))
    manager = KVCacheManager(
        KVCacheConfig(num_blocks=copies * num_blocks + 1, kv_cache_tensors=[],
                      kv_cache_groups=[KVCacheGroupSpec(["layer"], FullAttentionSpec(
                          block_size=16, num_kv_heads=1, head_size=64, dtype=torch.float16))]),
        max_model_len=num_tokens + 16, scheduler_block_size=16, hash_block_size=16,
        enable_caching=True,
    )
    # Prompt logprobs require recomputation, so distinct physical copies of
    # identical prefixes accumulate even for sequential scoring requests.
    for i in range(copies):
        req = request(str(i), tokens, scoring=True)
        computed, hit_tokens, _ = manager.get_computed_blocks(req)
        assert hit_tokens == 0
        allocated = manager.allocate_slots(req, num_tokens, hit_tokens, computed)
        assert allocated is not None
        manager.free(req)
    # An unrelated request consumes older copies under ordinary cache pressure.
    evicted = manager.block_pool.get_new_blocks((copies - 1) * num_blocks)
    probe = request("probe", tokens)
    computed, hit_tokens, _ = manager.get_computed_blocks(probe)
    assert hit_tokens == num_tokens - 16
    assert len(computed.blocks[0]) == num_blocks - 1
    assert all(b.ref_cnt == 0 for b in computed.blocks[0])
    values = manager.block_pool.cached_block_hash_to_block._cache.values()
    dict_bytes = sum(sys.getsizeof(v) for v in values if isinstance(v, dict))
    lookup = lambda: manager.get_computed_blocks(probe)
    for _ in range(50):
        lookup()
    samples = timeit.repeat(lookup, number=1000, repeat=7)
    # Cache hits remain usable, and releasing requests restores the pool.
    assert manager.allocate_slots(probe, 16, hit_tokens, computed) is not None
    manager.free(probe)
    manager.block_pool.free_blocks(evicted)
    assert manager.block_pool.get_num_free_blocks() == copies * num_blocks
    return dict(copies=copies, prefix_tokens=num_tokens, cached_tokens=hit_tokens,
                retained_dict_bytes=dict_bytes,
                lookup_us_median=statistics.median(samples)*1000,
                lookup_us_samples=[s*1000 for s in samples])


init_none_hash(sha256)
print(json.dumps({"python": sys.version, "platform": platform.platform(),
                  "source": block_pool_module.__file__,
                  "torch": torch.__version__, "warmup": 50, "iterations": 1000,
                  "repeats": 7, "records": [run(c, b) for b in (16, 256) for c in (1, 2, 32, 128)]}, indent=2))
```
