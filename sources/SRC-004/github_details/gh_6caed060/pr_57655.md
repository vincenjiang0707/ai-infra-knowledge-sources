## 正文

## Purpose

Fix Dots3 NOTE dropping video audio with the default MM processor cache. The
first miss stores a video-only result, so later hits also lose the audio track.

`_get_cache_missing_items()` uses `__getitem__()`, which unwraps the
`MediaWithBytes` containing the source video required for audio decoding. Add
`get_item_for_reparse()` to preserve the parser-compatible raw item without
using the hash-only accessor as model input.

The production change is `+13/-4` lines, and the regression test adds 37 lines.

### Duplicate-work check

#56304 changes Dots3 NOTE audio decoding after source bytes reach the model
processor. #54283 changes multimodal hash framing. Neither preserves source
bytes across processor-cache misses.

### Model-input equivalence

Using the official Dots3 NOTE processor configuration and tokenizer, the
complete prompt token IDs, multimodal tensors, hashes, and placeholders were
compared across cache-disabled, first-miss, and cache-hit processing:

| Modality | Cache-disabled prompt tokens | First miss | Cache hit | All model inputs equal |
| --- | ---: | ---: | ---: | --- |
| Image | 66 | 66 | 66 | yes |
| Audio | 15 | 15 | 15 | yes |
| Video | 372 | 372 | 372 | yes |

Generic image and video `MediaWithBytes` inputs also produce identical Hugging
Face processor payloads before and after reparsing. The hasher suite confirms
that the separate `get_item_for_hash()` behavior is unchanged.

The video comparison used the same reproducible 4-second H.264/AAC input:

| Implementation and cache path | Prompt tokens | Frames | Audio segments | Audio samples |
| --- | ---: | ---: | ---: | ---: |
| Unmodified, cache disabled | 372 | 4 | 2 | 64,512 |
| Unmodified, first cache miss | 2,176 | 16 | 0 | 0 |
| Unmodified, cache hit | 2,176 | 16 | 0 | 0 |
| Patched, cache disabled | 372 | 4 | 2 | 64,512 |
| Patched, first cache miss | 372 | 4 | 2 | 64,512 |
| Patched, cache hit | 372 | 4 | 2 | 64,512 |

After the fix, cache-disabled, cache-miss, and cache-hit processing produce the
same measured processor outputs. No documentation update is required because
this restores existing behavior without changing the public API or
configuration.
