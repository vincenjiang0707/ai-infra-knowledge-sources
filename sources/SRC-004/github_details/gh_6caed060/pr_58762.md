## Purpose

With #58207, `--min-kv-cache-group-layers` (default 3) trades KV capacity for fewer KV cache groups, because every group rebuilds its attention metadata each step. For Qwen3.6-35B-A3B + DFlash that's 17 groups instead of 46 and 30% less KV cache (RFC #58638, question 1). GDN groups with the same spec differ only in their state indices. This builds the first group's metadata and derives the others with `update_block_table()`, also at capture, so later groups' FULL graphs read the first group's batch-level buffers.

- `build_attn_metadata` does this for groups with the same `MambaSpec` and builder type, if the builder supports `update_block_table()`. No GDN-specific code in the runner.
- GDN implements `update_block_table()` and takes MRV2's precomputed `mamba_aligned_state_indices`.
- Mamba1/2 builders already support `update_block_table()` without spec decoding, so their metadata is now reused too.

Opened as part of [model runner discussion](https://github.com/vllm-project/vllm/pull/52297#discussion_r4089381401) on #52297. Implements @MarkXCloud's second suggestion there. Same idea as #35166 by @jennyyyyzhen, which was closed as stale.
@xyang16 explicitly added as co author, since the original idea developed in their PR
