## 正文

### Your current environment

- vLLM main (probed 2026-09-20; minimax_m2.py @ 24bfbd5d, deepseek_v4.py @ 39e33db7)
- Parser-only bug: reproduction needs no GPU, no model, no server.

### Describe the bug

#57699 describes a bug class for qwen3: when the model closes the tool call **without closing the last parameter tag**, the trailing value is dropped by the final (partial=False) conversion. #57707 fixes qwen3 only - but the same structure exists in three other converters, none of which are covered by that PR:

**1. minimax_m2 - vllm/parser/minimax_m2.py `_minimax_m2_arg_converter`**

`_PARAM_RE` only ends a value at the closing parameter tag or at the next parameter open tag. The trailing `_PARTIAL_PARAM_RE` extraction runs only under `if partial:`, so the final conversion drops the last parameter. With `stream_arg_deltas=True`, the streamed partial conversions have already emitted the value, and the flush at tool-call end produces a shorter JSON - the same client-visible divergence as #57699.

Model output:

```
<minimax:tool_call><invoke name="get_weather">
<parameter name="city">Seattle</parameter>
<parameter name="unit">celsius
</invoke></minimax:tool_call>
```

non-streaming: `arguments == {"city": "Seattle"}` - `unit` is silently lost.

**2. glm47_moe - vllm/parser/glm47_moe.py `_glm47_arg_converter`**

`_ARG_RE` requires the value close tag; the `_PARTIAL_ARG_RE` extraction is under `if partial:`. `stream_arg_deltas=True` is set. Same divergence: a tool call that omits the last closing arg_value tag yields non-streaming `arguments` without the trailing parameter.

**3. deepseek_v4 (inherited by v32/v41) - vllm/parser/deepseek_v4.py `_dsml_arg_converter`**

Same `if partial:` structure. Additionally, the partial branch swallows JSON failures with `contextlib.suppress` and **drops the value entirely**, while the complete branch falls back to the literal text. So a trailing `string="false"` parameter whose partial value is not yet valid JSON is discarded even mid-stream.

### Reproduction (CPU only)

```python
from vllm.parser.minimax_m2 import _minimax_m2_arg_converter

raw = '<parameter name="city">Seattle</parameter>\n<parameter name="unit">celsius\n'
print(_minimax_m2_arg_converter(raw, partial=True))   # {"city": "Seattle", "unit": "celsius\n"}
print(_minimax_m2_arg_converter(raw, partial=False))  # {"city": "Seattle"}  <- unit dropped
```

Equivalent direct calls to `_glm47_arg_converter` (glm47_moe) and `_dsml_arg_converter` (deepseek_v4) show the same drop.

### Expected behavior

Mirror the qwen3 fix (#57707): the trailing-partial extraction should also run in the final conversion, so a properly closed tool call keeps its last parameter value. For deepseek_v4, the partial branch should also fall back to the literal text like the complete branch does.

I can send PRs (one per parser, following the fix shape of #57707) with regression tests mirroring TestUnclosedLastParameter in tests/parser/engine/test_qwen3.py.

### devtyagi3909 · 2026-09-23

confirmed the root cause across all three converters.

minimax_m2 and glm47_moe: the trailing partial extraction (`_PARTIAL_PARAM_RE` / `_PARTIAL_ARG_RE`) is gated behind `if partial:` so the final flush with `partial=False` never reaches it. any tool call where the model omits the closing tag on the last arg silently discards that value.

deepseek_v4 has the same structure but also a second issue: inside the `if partial:` branch, the json parse is wrapped in `contextlib.suppress`, which eats failures and drops the value entirely instead of falling back to the literal text the way the complete branch does.

the fix shape is identical to #57707 (qwen3): run the partial extraction unconditionally in the final pass too, and for dsml drop the suppress in favor of the same literal-text fallback used in the complete branch.

working on PRs for all three.

### redd34 · 2026-09-26

A small correction to the earlier comment that #45701 already fixed this: on v0.30.0 and on current main (@ 3b4566c), `_glm47_arg_converter` and `_minimax_m2_arg_converter` still gate the trailing extraction on `if partial:`, and the final conversion drops the last value:

```python
from vllm.parser.glm47_moe import _glm47_arg_converter
from vllm.parser.minimax_m2 import _minimax_m2_arg_converter

raw = "<arg_key>city</arg_key><arg_value>Seattle</arg_value><arg_key>unit</arg_key><arg_value>celsius"
print(_glm47_arg_converter(raw, partial=True))    # {"city": "Seattle", "unit": "celsius"}
print(_glm47_arg_converter(raw, partial=False))   # {"city": "Seattle"}
raw = '<parameter name="city">Seattle</parameter>\n<parameter name="unit">celsius\n'
print(_minimax_m2_arg_converter(raw, partial=False))  # {"city": "Seattle"}
```
