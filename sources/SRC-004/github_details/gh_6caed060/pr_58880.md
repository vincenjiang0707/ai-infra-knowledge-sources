## Purpose

`get_routing_method_type` maps sigmoid + correction bias + renormalize routing (no expert groups) to `RoutingMethodType.MiniMax2` only when `routed_scaling_factor` is 1.0 (added in #44347). MiniMax-M3 uses `routed_scaling_factor=2.0`, so its MoE falls back to `Unspecified`. On SM100 with the MXFP8 checkpoint, that means the modular TRT-LLM path: a separate vLLM `topk_sigmoid` launch per MoE layer, then `trtllm_fp8_block_scale_routed_moe`.

The restriction is no longer needed with the pinned FlashInfer 0.7.0:
- FlashInfer's MiniMax2 routing uses `routed_scaling_factor` as its route scale: final weight = `sigmoid(x) * routeScale / sum` (`trtllm_fused_moe_routing_runner.cu`: `routingData.mRouteScale = routedScalingFactor`).
- Every monolithic TRT-LLM caller that accepts MiniMax2 already passes `routed_scaling_factor` through: FP8 block scale / MXFP8, FP8 per-tensor, and NVFP4.
- The scale is not applied twice. When `apply_routed_scale_to_output` is false, which is the M3 case, the scale goes to the router and the runner gets 1.0.

This PR removes the restriction, and with it the now-unused `routed_scaling_factor` argument of `get_routing_method_type`.

The restriction also, by accident, kept zero-expert models (`ZeroExpertRouter`) off kernels with built-in routing whenever their scale was not 1.0. Those kernels cannot reproduce zero-expert handling, and with scale 1.0 such a model was already mapped to MiniMax2. `ZeroExpertRouter.routing_method_type` now returns `Unspecified` explicitly.

Effect: any model with sigmoid + bias + renormalize routing, no expert groups, and a non-unit scale becomes eligible for the monolithic TRT-LLM kernels on Blackwell. MiniMax-M3 is one such model. The routing semantics are the same as vLLM's `fused_topk_bias`: biased scores select the experts, unbiased sigmoid gives the weights, which are renormalized and scaled.

**Not a duplicate:** I searched open PRs for `MiniMax2 routed_scaling_factor`, `MiniMax-M3 routing trtllm`, `minimax m3 moe routing fused` and `RoutingMethodType MiniMax2`. Nothing touches this mapping. The related merged PRs are #39141 and #44347, and #44347 introduced the restriction.
