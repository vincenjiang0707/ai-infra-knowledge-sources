# [Issue #58647] [RFC]: Hardening /v1/messages (Anthropic API) for Claude Code across model families

state: open | updated: 2026-09-25T03:34:30Z

## 正文

### Motivation

Claude Code can run against vLLM through the Anthropic Messages endpoint (`ANTHROPIC_BASE_URL` → `/v1/messages`). Claude Code's agentic loop is a demanding client of that endpoint:

- It sends every request with ~25 tools, many with large nested JSON schemas.
- It uses interleaved thinking with parallel tool calls.
- It sends inline `role: "system"` messages that change every turn.
- It sends side queries (title generation, the auto-mode permission classifier) with `stop_sequences` and small `max_tokens` budgets.
- It recovers from context overflow based on the error it gets back.

This issue audits the current converter (`vllm/entrypoints/anthropic/`) and the HF chat templates of the major open model families against real Claude Code traffic. We found:

- several gaps that affect every model family;
- a set of model-specific breakages, some of which return **400 on Claude Code's default requests**.

Many of the small fixes already have open PRs, often more than one per problem. This issue gathers them so they can be deduplicated and prioritized, and it proposes the pieces that have no owner yet.

**How we checked**

- We captured `/v1/messages` traffic from Claude Code 2.1.281 through a logging proxy (~50 requests covering main-loop turns, title generation and the auto-mode classifier).
- We replayed synthetic Claude Code-shaped conversations through `AnthropicServingMessages.to_chat_completion_request` → `chat_utils` post-processing.
- We rendered the result with the current HF templates, and with `mistral_common` / the DeepSeek Python encoders / Harmony where applicable.

Items marked *(unverified)* were not reproduced at runtime.

**Observed request shape (from captures)**

| Field | Values seen |
|---|---|
| `system` | List of text blocks with `cache_control`. The first is the `x-anthropic-billing-header` line. |
| `messages` | Contains inline `role: "system"` messages at non-leading positions (e.g. a `<total_tokens>` update each turn). |
| `thinking` | `{"type":"adaptive"}`, `{"type":"adaptive","display":"omitted"}`, `{"type":"enabled"}`, `{"type":"disabled"}`, or absent |
| `output_config` | `{"effort":"high"}`; title generation adds `format: json_schema` |
| `context_management` | `{"edits":[{"type":"clear_thinking_20251015","keep":"all"}]}` |
| `max_tokens` | `32000` (main loop), `2112` (classifier, `stop_sequences: ["</block>"]`), `64` (stage-1 classifier, `stop_sequences: ["</severity>"]`) |
| `tool_result` | `is_error` is set on most results. Content is a string or a list of text/image blocks. User turns often carry extra text blocks (system reminders) after the tool results. |

### Part 2: Model / template-specific findings

The common thread: every family uses **different names and values** for thinking and effort. Examples: `enable_thinking`, `thinking`, `thinking_mode`, `low_effort`, `thinking_budget`, and effort sets such as `{low,high}`, `{none,high}` or `{xhigh,medium,low}`. Passing `output_config.effort` straight through as `reasoning_effort` therefore gives inconsistent behavior, and 400s on several families.

| Family | Finding | Status |
|---|---|---|
| **Qwen3.8** (27B, Flash-Next, 2.4T) | The template raises `Unexpected reasoning effort high. Supported types are xhigh (default), medium, and low.` Claude Code sends `high` by default, so **every default Claude Code request returns 400**. 2.4T also raises `Disabling thinking is not supported.` | confirmed |
| **Qwen3.5 / 3.6** | Keep reasoning only after the last user message (item 8). 3.6 supports `preserve_thinking`, which vLLM never sets. The system-first guard is hidden only by item 1. | confirmed |
| **Qwen3.5 / Qwen3-Coder** | Historical arguments rendered with `\| string` produce Python `True`. Qwen3-Coder renders nested `anyOf` lossily. | confirmed (template-side) |
| **GLM-5.2 / 5.3** | Effort is mapped as `'high' if effort == 'high' else 'max'` (5.2), or only `{low,high}` is recognized (5.3), so `low`/`medium` become **Max**. 5.3 cannot disable thinking: the generation prompt is always `<think>`. `glm47_moe` parser switches to content-only when `enable_thinking=False`, so a naive disabled-thinking mapping would leak reasoning into `content`. | confirmed |
| **MiniMax-M3** | The template's `thinking_mode` (`enabled`/`disabled`/`adaptive`) maps 1:1 to Anthropic `thinking.type`, but vLLM never sets it. The template has no branch for non-leading system messages, so they are silently dropped once item 1 is fixed. | confirmed |
| **MiniMax-M2.x** | Reasoning is dropped before the last user message (item 8). | confirmed |
| **DeepSeek-V3.1** | The stock HF template does `'<｜tool▁sep｜>' + arguments`, but `chat_utils` has already turned arguments into a dict, so rendering raises `TypeError` on any history containing a tool call. It also never renders `tools`. Workaround: `examples/tool_chat_template_deepseekv31.jinja`. | confirmed |
| **DeepSeek-V3.2** (encoder) | `drop_thinking = messages[-1]["role"] == "user"` drops the current loop's reasoning (item 8). The strict tool-ordering check breaks on items 6 and 7. A non-merged inline system message has no role token and lands inside `<think>`. | confirmed |
| **DeepSeek-V4 / V4.1** | V4 is fine. V4.1 raises on `effort: "medium"` (accepts low/high/xhigh/max). | confirmed |
| **Kimi K2-Thinking / K2.5 / K2.6** | The template renders only the tool-call **id**, never the tool name (`<\|tool_call_begin\|>{{ id }}`). Any id not generated by Kimi on vLLM (`toolu_…`, `chatcmpl-tool-…`, after `/model` or a resumed session) loses the tool name. Thinking uses `thinking`, not `enable_thinking`. | confirmed |
| **Kimi K3** | Only low/high/max effort are accepted, so `medium` / `xhigh` return 400. Tool-result matching is robust to foreign ids. | confirmed |
| **gpt-oss (Harmony)** | `max` / `xhigh` effort raise. Reasoning cannot be disabled. Images are dropped. Each inline system message becomes a new developer message. JSON Schema → TypeScript is lossy: `anyOf`+enum, `allOf`, `$ref` and `const` become `any`, and `additionalProperties` maps become `{}` (affects Claude Code's `AskUserQuestion` / `Workflow` tools). | confirmed |
| **Mistral / Devstral** | `validate_request_params` allows only `{none, high}` effort, so Claude Code's other values return 400. Devstral-Small-2 and Devstral-2 raise `think tokens are not available for this tokenizer` whenever the history contains a thinking block. `truncate_tool_call_ids` works but logs a WARNING per historical tool call on every request. | confirmed |
| **Gemma 4** | Later tool results are lost when a user message is inserted (item 6). The template renders `anyOf` as an empty type, renders enums only for strings, and renders map-typed objects as fake properties (hits `AskUserQuestion`). | confirmed |
| **Nemotron v3** | The template reads `low_effort`, which vLLM never sets, so effort has no effect. Thinking cannot be disabled via the Anthropic API. | confirmed |
| **Seed-OSS** | Thinking is controlled only by `thinking_budget` (default unlimited). The default tool rendering is Python signatures that drop nested types and enums; `use_json_tooldef` fixes this but is off by default. Historical arguments use Python repr. | confirmed |

### Proposed Change

Suggested priority order:

1. **Per-model thinking/effort mapping layer.** Map Anthropic `thinking.type` (+ `budget_tokens`) and `output_config.effort` onto each model's native switch (`enable_thinking`, `thinking`, `thinking_mode`, `low_effort`, `thinking_budget`) and clamp to the levels that model accepts. Treat absent `thinking` as disabled only where the model can actually disable it. This extends #58613 and #52738, and removes most of the 400s above.
2. **Inline system handling that preserves the prefix.** Keep inline system messages in place, or fold them into the adjacent user turn when the template requires system-first (as proposed in #53393). Never hoist them into the leading system block. Detect the template requirement against the *resolved* tokenizer template, not the CLI flag.
3. **Converter structure fixes.**
   - Keep tool-result images inside the `tool` message.
   - Emit one merged user message per Anthropic user turn, so the trailing text doesn't cut off reasoning.
   - Mark `is_error` (e.g. an `Error:` prefix).
   - Join system blocks with `\n\n`.
   - Emit a single `tool_reference` message.
4. **Error compatibility.**
   - Translate context-overflow errors to Anthropic's messages so Claude Code can auto-compact or reduce `max_tokens`.
   - Degrade unknown content blocks to text instead of failing with 422.
   - Use Anthropic error types and envelopes throughout.
5. **Model-specific fixes.**
   - Rewrite Kimi tool-call ids to `functions.{name}:{idx}`.
   - Drop historical reasoning for Mistral tokenizers without `[THINK]`.
   - Add a schema-normalization pass (flatten `anyOf`/`$ref`) for Harmony, Gemma 4 and Seed-OSS.
   - Evaluate stop strings against content only, not reasoning.
6. **Regression coverage.** Add a small Claude Code-shaped fixture (captured request shapes, no user content) to `tests/entrypoints/anthropic/`, rendered through the converter for each supported template family.
