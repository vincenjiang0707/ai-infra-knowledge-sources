# [PR #57599] [ROCm][CI] Expand single-GPU coverage on MI355 DPX

## 正文

Move single-GPU CI coverage to MI355 DPX, including all main-CI `mi355_1` suites except the suite that failed its first DPX run in [build 90270](https://buildkite.com/vllm/ci/builds/90270/table). Include focused fixes for the observed kernel-reference and cold-cache loading failures. Remove the DPX-specific skips, xfails, tolerance increases, and unused `is_dpx()` / `VLLM_DPX_CI` plumbing originally introduced by this PR.

| Source queue | Main-CI suites moved | Main-CI shards moved |
| --- | ---: | ---: |
| `mi300_1` | 30/51 (58.8%) | 40/79 (50.6%) |
| `mi355_1` | 44/46 (95.7%) | 62/69 (89.9%) |

- Block INT8 MoE's reference now truncates activation quantization like the production C++ and Triton implementations. Preserve round-to-nearest for existing whole-token reference callers and add exact fractional-value regression cases.
- MXFP4 skinny GEMM's independent FP32 reference is rounded to the declared BF16 output type before comparison. Correct BF16 rounding reproduces both old DPX failure counts exactly; tolerances and pass-rate thresholds are unchanged.
- Reduce one large-K skinny-GEMM test's M from 128 to 64 so the raw operation needs 96 CUs rather than 192 on a 128-CU DPX device. It retains the same 24 K-shards and multi-pass LDS readback regression coverage.
- Discover nonstandard root-level safetensors filenames when the Hub's standard metadata API rejects them, reading headers without downloading weights. This fixes TinyLlama GPTQ cold-cache initialization, which otherwise constructs unquantized layers before encountering checkpoint `qweight` tensors. Preserve offline/gated cache fallback.

- Guard native DPX jobs with a nonblocking lock per render device in the shared host-local cache. A second participating job fails before workspace preparation or test execution; CPU-only and non-DPX jobs bypass the guard. This protects cooperating runners while the cluster allocation issue observed in [AMD-CI build 13342](https://buildkite.com/vllm/amd-ci/builds/13342/list) is investigated.
- Use AMD-SMI diagnostic options supported in Linux guests, preserving the existing probe timeouts and failure handling.

Guard validation: 23 local process cases passed, including an eight-process race admitting exactly one workload, device aliases, independent devices, queue bypasses, and lock retention through teardown. A separate check verified inherited lock lifetime after wrapper termination. Six real AMD-SMI probes, guest-parser checks, shell syntax, and pre-commit passed. Lock tests use synthetic device nodes; live cross-pod mount sharing remains unverified.

Investigation, implementation, validation, and this description were AI-assisted.
