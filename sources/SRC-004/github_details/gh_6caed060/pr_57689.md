## Purpose

Fixes #57688, a follow-up gap in #57098.

#57098 gave `extract_reasoning` (non-streaming) the four-shape split, but `extract_reasoning_streaming` still falls through to "everything is reasoning" whenever no think-close marker exists. A completion that opens straight into the response channel (no think markers at all, the real-user shape behind #50258) is content in the non-streaming path, yet streamed entirely as `reasoning_content`, raw XTML markers included, with `content` left empty. Same bytes, opposite classification depending on `stream=`.

Not a duplicate of #57366 / #50291: both cover only the non-streaming truncated-reasoning shape (#50291 even notes streaming already classifies that shape as reasoning). This PR fixes the inverse divergence, the response-only shape, in the streaming path.

Change, all inside the kimi_k3 parser per the directory guide:

- Latch the response-only shape once the response opener completes with no think markers seen, and route the stream through `strip_content_streaming` from then on (the composite `KimiK3Parser.parse_delta` never strips for this shape because `reasoning_ended` stays false, so the reasoning parser has to emit clean content itself).
- Hold back a partial response opener in `_reasoning_text_ready_to_emit` so the first ambiguous chunks are not emitted as reasoning while the marker is still arriving.
- Reasoning already streamed before a mid-stream response opener (think prefix consumed, close never sent) stays reasoning; only the response body switches to content.

Left out on purpose: `is_reasoning_end` / the structured-output gate and the tool-call transition still key off think markers, so grammar-constrained decoding and tool-call parsing for this shape are unchanged (previously they never fired either). Happy to follow up if maintainers want response-open to also end reasoning there.
