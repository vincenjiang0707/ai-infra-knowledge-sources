## Summary

Implements **Gap D** from the elastic EP recovery RFC: same-size DP rank peer-swap after a worker failure, without changing EP size.

RFC comment: https://github.com/vllm-project/vllm/issues/30112#issuecomment-4120362903
Design doc: https://gitlab.com/tzulingk/wideep-ft/-/blob/main/vllm/recovery_gap.md?ref_type=heads

### Changes

- **`vllm/distributed/device_communicators/all2all.py`** — adds `NixlEPAll2AllManager.replace_peer()`: disconnects a dead EP rank and reconnects its replacement in the NIXL buffer, optionally updating the TCPStore group before reconnect.

- **`vllm/distributed/elastic_ep/standby_state.py`** — adds `create_recovery_groups()`: rendezvous on a fresh TCPStore (same DP topology) to avoid stale keys from the original init blocking the new rendezvous. Improves the existing `create_standby_groups` assertion message.

- **`vllm/distributed/elastic_ep/elastic_execute.py`** — adds `ElasticEPScalingExecutor.reconnect_peer()`: orchestrates the surviving-rank side of the peer swap — new process groups → promote standby → reconnect NIXL per EP rank.

- **`vllm/v1/engine/__init__.py`** — adds `dead_data_parallel_rank` field to `ReconfigureDistributedRequest` to carry the dead DP rank index during recovery (`-1` for normal elastic scaling).

- **`tests/distributed/test_recovery_ep.py`** — three-level test suite:
  - **Level 1 (no GPU, CI):** unit test for `replace_peer` using a `FakeNixlEPBuffer`.
  - **Level 2 (2 GPU, no NIXL):** `test_recovery_groups[gloo/nccl]` — verifies fresh TCPStore isolation and live all-reduce after `create_recovery_groups`.
  - **Level 3 (2 SM90+ GPUs + NIXL + RDMA):** `test_recovery_ep` end-to-end — baseline GSM8K verified on B200; recovery trigger pending wiring to an API endpoint.

## Code Review

This pull request introduces distributed data parallel (DP) rank recovery functionality for NIXL-EP. Key changes include adding a `replace_peer` method to `NixlEPAll2AllManager` to handle disconnecting and reconnecting ranks, and a `reconnect_peer` method in `DistributedWorkerManager` to orchestrate the recovery process for surviving ranks. A new `create_recovery_groups` function is added to `standby_state.py` to establish fresh communication groups during recovery, and `ReconfigureDistributedRequest` is updated with a `dead_data_parallel_rank` field. New tests are also added to validate this recovery mechanism. A review comment suggests improving the robustness of TCPStore initialization in the tests by replacing a fixed `time.sleep` with a retry loop to prevent flakiness.
