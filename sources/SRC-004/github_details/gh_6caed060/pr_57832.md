## 正文

## Purpose

Adds **context-parallel decode scoring** for MiniMax-M3's sparse lightning indexer on ROCm (TP>1, opt-in via `VLLM_ROCM_MINIMAX_INDEXER_CP=1`).

### Problem
With TP>1, every rank independently scores the entire KV cache for the sparse indexer — redundant work scaling linearly with world_size.

### Solution
- Each rank scores only its 1/world_size shard of global KV blocks (round-robin: block = local × world + rank)
- Scores scattered into a global-shape `[heads, tokens, max_block]` tensor pre-filled with `-inf`
- MAX allreduce across TP group fills all positions from their owning rank
- `minimax_m3_index_decode(precomputed_score=...)` skips internal re-scoring and runs top-k directly

**Default: OFF** (`VLLM_ROCM_MINIMAX_INDEXER_CP=False`). The per-step allreduce adds latency that only pays off at moderate-to-high concurrency (≥20) and mid-range context (10k–90k ISL). At low concurrency (≤4) or very long context (≥100k) the overhead exceeds the scoring savings — keep CP off in those regimes. At conc=20+ and 20k–90k ISL, CP yields +11–29% throughput and up to −64% p99 TTFT.

**CUDAGraph compatibility:** The forward guard uses both `torch.compiler.is_compiling()` (for `torch.compile` tracing) and `torch.cuda.is_current_stream_capturing()` (for CUDA graph capture) to skip the `dist.all_reduce` during graph recording, matching the pattern in `vllm/model_executor/layers/sparse_attn_indexer.py`. This allows the CP `forward` to be called during graph tracing and stream capture, where `super().forward()` is substituted. In practice this means CP works with `cudagraph_mode=FULL_DECODE_ONLY` when the cudagraph compilation time stays within the vLLM heartbeat window (≤60s). For longer warmup configs or when using EAGLE3 speculative decoding, use `--enforce-eager` to avoid the shm_broadcast timeout. Companion PR #57909 (AITER fp8 indexer) avoids this limit entirely by using AITER custom_all_gather instead of dist.all_reduce.

### MiniMax-M3 sparse attention pipeline

MiniMax-M3 uses a two-stage sparse attention architecture:

1. **Indexer (stage 1)** — scores every KV block, selects top-k blocks per head. This PR accelerates this stage.
2. **Sparse attention (stage 2)** — runs attention only over the selected blocks.

Each stage has independent backend choices:

| Stage | Backend | Index cache dtype | When selected |
|---|---|---|---|
| Indexer | **Triton** (this PR) | `bf16` | `indexer_kv_dtype=bf16` — default; no AITER dependency |
| Indexer | AITER (#57909) | `fp8_e4m3` | `indexer_kv_dtype=fp8` — requires AITER sparse PA extensions |
| Attention | **AITER_SPARSE_PA** | — | `SHUFFLE_KV_CACHE_LAYOUT=1` + `ROCM_AITER_UNIFIED_ATTN` |
| Attention | Triton | — | Fallback when AITER unavailable |

This PR targets the **Triton bf16 indexer** path. The index cache stores a lightweight BF16 copy of KV states for block scoring — separate from the main FP8 KV cache used by the attention kernel. Model weights (BF16 or MXFP4) are independent of both.

## Test Result

### Benchmark A — AgentX QoS (BF16 weights, vLLM 0.28.1)

**Indexer:** Triton bf16 | **Attention:** AITER_SPARSE_PA
**Dataset:** semianalysis_cc_traces_weka_062126_256k, 300s

| Concurrency | Config | TTFT p50 | TTFT p90 | ITL p90 | tput/user |
|---|---|---|---|---|---|
| 20 | Baseline | 519ms | 16,087ms | 116ms | 33.3 tok/s |
| **20** | **CP Indexer** | **478ms** | 16,815ms | 146ms | 29.7 tok/s |
| 32 | Baseline | 2,956ms | 15,280ms | 132ms | 23.8 tok/s |
| **32** | **CP Indexer** | **2,626ms** | **11,964ms** | **114ms** | **24.8 tok/s** |

At concurrency 32: **−22% TTFT p90**, **−14% ITL p90**, +4% throughput/user.
At concurrency 20: TTFT p50 improves (−8%); ITL p90 and tput/user regress (+26% ITL, −11% tput) — allreduce overhead exceeds scoring savings at this load. This is why CP is **default-off**.

### Benchmark D — AgentX Pareto Sweep (MXFP4+EAGLE3, TP=4, vLLM 0.3.1)

**Indexer:** Triton bf16 (`indexer_kv_dtype=bf16`) | **Attention:** AITER_SPARSE_PA
**Server:** `max-num-seqs=64`, `enable-chunked-prefill`, `enable-prefix-caching`, EAGLE3 MTP spec decode (`synthetic_acceptance_length=2.78`)
**Benchmark:** aiperf `inferencex-agentx-mvp`, Weka trace `semianalysis_cc_traces_weka_062126_256k`, 900s per point
**Methodology:** Single server per run (baseline then CP back-to-back without restart), 60s warmup, all concs sequential — eliminates ISL trace variance.

| Concurrency | Baseline (tok/s/GPU) | CP (tok/s/GPU) | Delta | vs ATOM (MI355X) | ISL baseline | ISL CP |
|---|---|---|---|---|---|---|
| 15 | 14,732 | 14,767 | +0.2% | 0.66x | 79,387 | 79,464 |

CP is neutral (0–1%) at all concurrency points with EAGLE3 spec decode. With speculative decoding, the decode step is fast enough that the indexer is not the bottleneck — consistent with Benchmark C (no EAGLE3) showing CP benefit at shorter ISL where indexer is proportionally more expensive.

**Hardware note:** Our MI350X vs ATOM/MI355X gap (0.48–0.66x) is hardware, not config — MI355X has ~2× higher FP8 compute and HBM bandwidth at this workload. The CP overhead is zero in both cases.
