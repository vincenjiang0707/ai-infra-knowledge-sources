## Purpose

Disclaimer: The code was largely assisted by Claude Code but the PR itself is handwritten and well tested.

In general, this PR is a follow-up to #41028.

#41028 tries to allow sm120 to use Triton kernels for GPT-OSS models instead of Marlin kernels. However, current implementation of triton kernels does not work on sm12x out-of-box and this PR fixes this. By testing on an RTX 5090:

- Decode speed is the same.
- Triton prefilling is 10% slower than Marlin kernels.The root cause is that the smem is too small for a larger tile for Triton. 
- Triton kernel earns +8% kvcache pool because Marlin kernel needs more space for alignment.

Therefore, this PR still keeps Marlin kernel as the default implementation, but allows sm12x to use Trition kernels if users would like the kvcache benefits by `--moe-backend triton`.
