## Purpose

Currently, some default triton kernel implementations do not perform correct or well on different platforms, and there is no way to override the default Triton kernel implementation on different platforms.

This PR introduces a new mechanism to dispatch Triton kernel calls to platform-specific implementations.

outdated
> The usage is quite simple. For the target triton kernel, we decorate it with `@pluggable_kernel`, Then in the out-of-tree or non-default platform, we register a platform-specific implementation using `@register_kernel`. The dispatcher will then dispatch the kernel call to the platform-specific implementation if available, otherwise to the default implementation.

This PR also take `expand_kernel` as an example to show that how the dispatcher works in in-tree and out-of-tree platform.
- In-tree: see the change in cpu model runner
- out-of-tree: see https://github.com/vllm-project/vllm-ascend/pull/9265 in vllm-ascend

Related RFC：https://github.com/vllm-project/vllm/issues/45133

## Code Review

This pull request introduces a Triton Kernel Dispatcher to support multi-platform kernel implementations while preserving the standard `kernel[grid](...)` syntax. It includes decorators for automatic registration of default kernels and manual registration of platform-specific overrides. Feedback suggests removing the `lru_cache` from the kernel lookup function to prevent stale results when the registry is updated at runtime. Additionally, the `KernelDispatcher` should be updated to include necessary metadata and a `__call__` method to fully satisfy the `SubscriptableCallable` protocol and act as a transparent wrapper.
