# [PR #58892] [Bugfix] Keep FlashAttention sparse ahead of FlashInfer SM90 for NoPE-512 MLA

source: https://github.com/vllm-project/vllm/pull/58892
state: open | updated: 2026-09-27T09:37:42Z
labels: bug, nvidia

## 正文

## Purpose

Fixes #56564.

`_get_backend_priorities` inserts `FLASHINFER_MLA_SPARSE_SM90` at the **front** of the SM90 sparse list whenever `head_size == 512`:

```python
sparse_tail = [FLASH_ATTN_MLA_SPARSE, FLASHMLA_SPARSE]
if head_size == 512:
    sparse_tail.insert(0, FLASHINFER_MLA_SPARSE_SM90)
```

GLM-5.3-Flash is NoPE MLA (`kv_lora_rank=512`, `qk_rope_head_dim=0`), so `head_size = 512` and the condition fires. The first four non-sparse candidates are rejected (the model requires sparse), which makes the winner whatever leads `sparse_tail`. Once FlashInfer >= 0.6.18 satisfies `has_flashinfer_sm90_nope_mla()` (the `ckv_scale_arr` kwarg check), the SM90 FlashInfer sparse backend is selected by default.

The reported measurements on H100 (#56564) put that backend **36% behind `FLASH_ATTN_MLA_SPARSE` at concurrency 1 and 70% behind at concurrency 8** (output 754 → 230 tok/s), with **identical MTP acceptance length** — so the gap is the per-step attention kernel, not the drafting path. The issue reporter re-confirmed on nightly `7f1a539` / FlashInfer 0.6.18.post1 that the priority is unchanged and the workaround is still an explicit `--attention-backend FLASH_ATTN_MLA_SPARSE`.

## Change

Drop the `head_size == 512` special case: NoPE-512 and DeepSeek-576 now share one SM90 sparse order, with `FLASHINFER_MLA_SPARSE_SM90` kept last as a fallback for hosts where the FlashAttention sparse path is unavailable. No behavior change for 576, for SM100/SM120, or for the non-sparse lists.

Two things that previously argued for keeping FlashInfer first no longer do:

- The `FLASH_ATTN_MLA_SPARSE` TMA-descriptor log spam (#56563) was fixed by #55385.
- There is an open CUDA illegal-memory-access report against the FlashInfer SM90 sparse backend for this exact model (#55626), which is a further argument against making it the default on sm_90.

If the intent behind #53906's `insert(0, ...)` was a specific configuration where the FlashInfer path does win on Hopper (FP8 KV in-kernel dequant halving HBM traffic is a plausible one), a narrower gate on that configuration would be preferable to a blanket head-size rule — happy to rework it that way, but there is currently no published benchmark on sm_90 supporting the inversion while there is one against it.

## Test

`tests/v1/attention/test_flashmla_nope_sm90_backend_selection.py` gains two cases (both pure priority-table logic, no GPU needed):

- `test_sm90_sparse_priority_prefers_flash_attn[nope512|ds576]` — `FLASH_ATTN_MLA_SPARSE` leads the SM90 sparse list for both head sizes, and `FLASHINFER_MLA_SPARSE_SM90` remains present but behind it
- `test_sm90_sparse_priority_identical_across_head_sizes` — `head_size` does not reorder the SM90 sparse list

The existing SM100/576 invariants in that file are untouched and still pass unchanged (they assert `FLASHMLA_SPARSE` leads on SM100, which this diff does not affect).
