# [PR #38156] [Model] Enable batched video encoding for NanoNemotron-VL (RADIO ViT)

## 正文

## Summary

- **Removes the `requires_sequential_video_encoding` hack** from `GPUModelRunner` and the NanoNemotron model class. Videos are no longer processed one-at-a-time in a Python loop; instead, multiple videos are batched together through the ViT encoder in a single forward pass.
- **Adds two video encoding paths in NanoNemotron**: a **same-resolution fast path** that micro-batches up to ~128 frames at a time across multiple videos, and a **varying-resolution dynamic path** that pre-patches frames into the dynamic-resolution ViT format with per-tubelet positional encoding.
- **Refactors `ViTPatchGenerator.forward_video`** to accept `num_frames: list[int]` (multiple videos) instead of a single video tensor, producing all tubelets in one batched call.
- **Adds `forward_video_dynamic`** to `ViTPatchGenerator` for handling videos with heterogeneous spatial resolutions via temporal grouping and dynamic-resolution positional encoding.
- **Sorts multimodal items by modality** in `GPUModelRunner._execute_mm_encoder` so that `group_and_batch_mm_kwargs` sees consecutive same-modality items, enabling cross-request batching.

## Motivation

The previous implementation required sequential (one-video-at-a-time) encoding for NanoNemotron-VL's dynamic-resolution video pipeline because it did not support batch size > 1. This was a significant throughput bottleneck, especially for concurrent video requests. This PR lifts that restriction by:

1. Teaching the RADIO ViT patch generator to process multiple videos (with potentially different frame counts) in a single batched call.
2. Splitting the video embedding logic into a fast path (same H/W across videos) and a dynamic path (varying H/W), each capable of batching.
3. Removing the per-video loop and `requires_sequential_video_encoding` flag from the GPU model runner.

## Changes

| File | What changed |
|---|---|
| `nano_nemotron_vl.py` | Removed `requires_sequential_video_encoding` flag. Split `_extract_video_embeddings_temporal` into `_fast` (micro-batch windows, same-res) and `_dynamic` (pre-patch, varying-res) variants. Updated `_get_video_pixel_inputs` to preserve list form when video frames have different spatial sizes. |
| `radio.py` | Added `_apply_temporal_grouping` for dynamic-res tubelet grouping. Added `forward_video_dynamic` entry point. Refactored `forward_video` to accept `num_frames: list[int]` and batch across videos. Updated `RadioInternVisionModel.forward` with three-way dispatch (dynamic-res video / same-res video / images). Wired `_tubelet_imgs_sizes` into `RadioModel` for correct feature extraction. |
| `gpu_model_runner.py` | Removed `requires_sequential_video_encoding` flag and the sequential per-video fallback loop. Added modality-based sorting before batching so same-modality items are grouped across requests. Simplified encoder execution to always use the batched path. |
