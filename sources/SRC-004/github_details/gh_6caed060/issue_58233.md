### Proposal to improve performance

机器是8张H200，2T内存，本地NVMe放的模型。vLLM用的nightly镜像，部署的DeepSeek-V4.1-Flash。

报错那次完整的启动命令如下：

sudo docker run -d
```bash
--name deepseek-v41-flash
--gpus all
--privileged
--ipc=host
--shm-size=128g
-p 30003:30003
-v /data/3/lyp/models/deepseek_v4_1_flash/:/models/deepseek_v4_1_flash
-e VLLM_ENGINE_READY_TIMEOUT_S=3600
-e HF_HUB_OFFLINE=1
-e VLLM_USE_RUST_FRONTEND=1
vllm/vllm-openai:nightly /models/deepseek_v4_1_flash
--tokenizer-mode deepseek_v41
--enable-expert-parallel
--tensor-parallel-size 8
--tool-call-parser deepseek_v41
--enable-auto-tool-choice
--reasoning-parser deepseek_v41
--trust-remote-code
--no-enable-flashinfer-autotune
--gpu-memory-utilization 0.90
--max-model-len 1048576
--max-num-seqs 64
--enable-prefix-caching
--port 30003
--speculative-config '{"method":"dspark","num_speculative_tokens":5,"draft_sample_method":"probabilistic","rejection_sample_method":"block","enable_adaptive_verification":true}'
--mm-encoder-tp-mode data
--kv-transfer-config '{"kv_connector":"SimpleCPUOffloadConnector","kv_role":"kv_both","kv_connector_extra_config":{"cpu_bytes_to_use_per_rank":171798691840,"lazy_offload":true}}'
```

后来去掉--kv-transfer-config也试过，一样慢。

现在问题是：并发才8个请求，就卡得不行。New API那边看日志全是“首字不适用”，frt=-1000，就是vLLM压根没吐第一个token出来。等个2到15分钟，客户端直接超时断了，completion_tokens=0。

vLLM自己的日志里 Reqs Running: 8，但 Avg generation tput: 0.0 toks/s，GPU KV cache used 才1%左右。Prefix cache hit rate也是抽风，一会98%一会0%。

nvidia-smi看，SM跑满100%，但mem才6%到28%，PCIe接收倒是有2.5到7 GB/s。GPU温度功耗都正常，ECC也全是0。之前有张卡报过Xid 95，重置后没再犯。

请求的prompt都巨长，几万到几十万token，reasoning_effort基本都是high或max。我怀疑是超长上下文把prefill队列堵死了，decode根本排不上，所以generation tput才是0。也可能Engram表放CPU内存，PCIe来回搬数据太慢。

试过去掉KV offload，没用。Rust前端启动时还提示有些参数不生效。CUDA Graph捕获的时候一堆空图警告，但最后显示都100%完成了。

有没有人遇到过类似情况？是不是必须把max-model-len降下来？或者换回Python前端？还是说Engram这块目前就是坑？求指点，感谢！

### Zephyr69 · 2026-09-23

Your pcie speed indicates very poor intercommunication performance, which destroys the throughput including prefill speed. Hence, a very long input's raw prefill can take several hundred seconds and blocks the serving as the engine prefills requests one by one. 

If you are already on pcie gen 4 or 5, the bottleneck could be the communication between the two cpu nodes, but there can be other causes. If inter cpu node communication was the culprit, the simplest solution would be to do DP2 and group the GPUs by cpu node affinity.
