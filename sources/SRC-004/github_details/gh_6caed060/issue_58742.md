# [Issue #58742] [Bug]: MFU/MBU silently drops attention and FFN for GPTQ, AWQ, gpt-oss, DeepSeek-V4 FP8 and online-quantized models

source: https://github.com/vllm-project/vllm/issues/58742
state: open | updated: 2026-09-25T17:38:17Z
labels: deepseek, gpt-oss, quantization, DSv4

## 正文

### Your current environment

`main` at `38cc054fc2` (25/09). Reproduced without a GPU (macOS, vLLM imported from source, `UnspecifiedPlatform`) with real `ModelConfig`s and the real quantization-config resolution (`VllmConfig._get_quantization_config`); `vllm/v1/metrics/perf.py` only needs the configs, no weights or GPU.

### 🐛 Describe the bug

`AttentionQuantizationConfigParser` and `FfnQuantizationConfigParser` look up `quant_config.get_name()` in `_QUANT_WEIGHT_BYTE_SIZE` and raise `InvalidComponent` for any name that is not in the table. `ModelMetrics.__init__` catches that and skips the whole component at `logger.debug` level, so `--enable-mfu-metrics` reports **unembedding only**, with no warning.

The table was last expanded in #37231 (03/2026); later edits (#43841, #39612, #43529) only removed entries. Since then several quantization configs were added or renamed and return names that are not in the table:

| Model / flag | `ModelConfig.quantization` | `get_name()` | Components billed |
|---|---|---|---|
| `openai/gpt-oss-20b`, `openai/gpt-oss-120b` | `gpt_oss_mxfp4` | `gpt_oss_mxfp4` | `unembed` only |
| `deepseek-ai/DeepSeek-V4-Flash`, `deepseek-ai/DeepSeek-V4-Pro` | `deepseek_v4_fp8` | `deepseek_v4_fp8` | `unembed` only |
| any GPTQ checkpoint (`Qwen/Qwen2.5-0.5B-Instruct-GPTQ-Int4`), no flag or `--quantization gptq` / `gptq_marlin` | `auto_gptq` | `auto_gptq` | `unembed` only |
| any AWQ checkpoint (`Qwen/Qwen2.5-0.5B-Instruct-AWQ`), no flag or `--quantization awq_marlin` | `auto_awq` (`awq` on CPU) | `auto_awq` | `unembed` only |
| bf16 checkpoint (`Qwen/Qwen3-0.6B`) with `--quantization fp8`, `fp8_per_tensor`, `fp8_per_block` or `fp8_per_channel` | as given | `online` | `unembed` only |
| control: `Qwen/Qwen3-30B-A3B-FP8` | `fp8` | `fp8` | `attn`, `ffn`, `unembed` |

- `gpt_oss_mxfp4` came in #39604, `auto_gptq` in #38288, `auto_awq` in #42727 and `deepseek_v4_fp8` with the DeepSeek-V4 support. `gptq`, `gptq_marlin`, `awq` and `awq_marlin` now all map to `AutoGPTQConfig` / `AutoAWQConfig`, whose `get_name()` is `auto_gptq` / `auto_awq`, so the four matching entries in the table can no longer be hit.
- Every online shorthand resolves to `OnlineQuantizationConfig` (#38138), whose name is `online`; `--quantization fp8` on an unquantized checkpoint is the deprecated alias of `fp8_per_tensor`.
- `humming` and `modelopt_mixed` are also missing from the table (not measured here).

Magnitude for one decode step (batch 1, context 1024, `per_gpu=True`), current table vs. the same table with the missing name added:

| Model | `main` | with the name added | ratio |
|---|---|---|---|
| gpt-oss-20b (`gpt_oss_mxfp4: 0.5`) | 1.16 GFLOP / 1.16 GB | 7.44 GFLOP / 2.70 GB | ×6.4 FLOPs, ×2.3 bytes |
| gpt-oss-120b (`gpt_oss_mxfp4: 0.5`) | 1.16 GFLOP / 1.16 GB | 10.58 GFLOP / 3.47 GB | ×9.1 FLOPs, ×3.0 bytes |
| DeepSeek-V4-Flash (`deepseek_v4_fp8: 1`) | 1.06 GFLOP / 1.06 GB | 16.21 GFLOP / 8.64 GB | ×15 FLOPs, ×8 bytes |
| DeepSeek-V4-Pro (`deepseek_v4_fp8: 1`) | 1.85 GFLOP / 1.85 GB | 58.27 GFLOP / 30.08 GB | ×31 FLOPs, ×16 bytes |

For DeepSeek-V4 the second column still has no attention: `MLAAttentionMetrics` fails separately with `Missing required attr kv_lora_rank in config` for the `deepseek_v4` / `deepseek_v41` configs (`DeepSeek-V4.1-Flash`, which resolves to `fp8`, is billed `ffn` + `unembed` for the same reason). That looks like a separate gap; noting it so the numbers above are not read as complete.

Repro (no GPU needed):

```python
from types import SimpleNamespace
from vllm.config import LoadConfig, ModelConfig, VllmConfig
from vllm.v1.metrics.perf import ModelMetrics

mc = ModelConfig(model="openai/gpt-oss-20b")
qc = VllmConfig._get_quantization_config(mc, LoadConfig())
cfg = SimpleNamespace(
    model_config=mc, quant_config=qc,
    cache_config=SimpleNamespace(cache_dtype="auto"),
    parallel_config=SimpleNamespace(data_parallel_size=1, tensor_parallel_size=1,
                                    pipeline_parallel_size=1, enable_expert_parallel=False),
)
print(qc.get_name(), [m.component_type() for m in ModelMetrics(cfg).metrics])
# gpt_oss_mxfp4 ['unembed']
```

Possible fix: add the missing names (`gpt_oss_mxfp4`, `deepseek_v4_fp8`, `auto_gptq`, `auto_awq`, `online`, `humming`, `modelopt_mixed`; for `online` the byte size could come from the resolved `QuantizationConfigArgs`), and for an unknown method fall back to the model dtype with a `logger.warning_once` instead of dropping the component, so a future rename degrades the estimate rather than removing most of it. `test_quantization_config_parser_unknown_method` currently asserts the drop and would need to change.

AI assistance (Claude Code) was used for the scripts and this report; I ran the checks and reviewed the results.
