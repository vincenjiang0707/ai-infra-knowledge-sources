## Purpose

`LLM.encode()` writes its internal pooling task into the caller's `PoolingParams`. Reusing `PoolingParams(use_activation=False)` first with an `embed` LLM and later with a separate `token_embed` LLM fails before inference:

```text
You cannot overwrite param.task='embed' with pooling_task='token_embed'!
```

Each instance keeps its own configured task. The problem is the first call leaving that task in the shared parameter object.

Clone each request's parameters before assigning the task in the base offline IO processor, and before calling the plugin's `merge_pooling_params()`. BGE-M3 and ColBERT change the parameters during that merge, before reaching the base processor. The existing check for an explicitly conflicting task stays unchanged.

I checked existing issues and PRs for parameter reuse and task mutation and found no matching fix. #50884 handles `SamplingParams` seeds and does not change this path.
