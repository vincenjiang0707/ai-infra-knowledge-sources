## 正文

### Your current environment

- vllm `0.23.0` (PyPI release) and `vllm-project/vllm@main` (also reproduced on a downstream fork at the same upstream sha)
- transformers: verified on both `4.57.1` and `5.12.1` (latest stable, released 2026-06-15) — same failure
- 1 × NVIDIA H20, CUDA 13.0, torch `2.11.0+cu130`

### 🐛 Describe the bug

`tests/compile/passes/test_mla_rope_kvcache_cat_fusion.py::test_mla_rope_kvcache_cat_fusion` parametrizes over `kv_cache_dtype=["auto", "fp8"]` × `MLA_BACKENDS = [TRITON_MLA, FLASH_ATTN_MLA, ROCM_AITER_MLA]`. On Hopper (where `flash_attn_supports_mla()` is True) two combinations are collected and both fail at backend construction:

```
test_mla_rope_kvcache_cat_fusion[fp8-dtype0-True-16-512-1536-128-64-128-16-True-AttentionBackendEnum.FLASH_ATTN_MLA]
test_mla_rope_kvcache_cat_fusion[fp8-dtype0-False-16-512-1536-128-64-128-16-True-AttentionBackendEnum.FLASH_ATTN_MLA]
```

Stack:
```
E   NotImplementedError: FlashAttnMLA V1 with FP8 KV cache not yet supported
```

raised by `vllm/v1/attention/backends/mla/flashattn_mla.py` when constructing the backend.

### Reproducer

```bash
pytest -v tests/compile/passes/test_mla_rope_kvcache_cat_fusion.py \
       -k "FLASH_ATTN_MLA and fp8"
```

Expected: 2 collected, both either pass or be cleanly skipped.
Actual: 2 failed (after pytest-rerunfailures retries them).

### Where it came from

`tests/compile/passes/test_mla_rope_kvcache_cat_fusion.py` was added in #40392 (merged 2026-05-11) and has not been touched since (only one commit on the file). The parametrize matrix unconditionally crosses `kv_cache_dtype=["auto", "fp8"]` with all `MLA_BACKENDS`. There is no `skipif` for the `(FLASH_ATTN_MLA, fp8)` cell, even though `FlashAttnMLA` explicitly raises `NotImplementedError` for FP8 KV cache.

### Suggested options (no preference, just listing)

1. Implement FP8 KV cache support in `FlashAttnMLA` so the parametrize matrix can stand.
2. Add a `pytest.skip(...)` runtime check in `test_mla_rope_kvcache_cat_fusion` for `(attn_backend == FLASH_ATTN_MLA and kv_cache_dtype == "fp8")`, mirroring the `flashattn_mla.py` capability gate.
3. Filter `MLA_BACKENDS` to drop `FLASH_ATTN_MLA` when `kv_cache_dtype == "fp8"` at test collection time.

Filing this only as a report — happy to put up a PR for any of the three if a maintainer indicates the preferred direction.

### Palaiologos1453 · 2026-06-27

Correction on my earlier PR #46695: I am closing it because the implementation dequantized the FP8 MLA cache before calling the existing FA3 MLA `q_v` kernel. That is not true FP8 KV-cache support and would lose the intended memory-bandwidth benefit.

The correct short-term fix for this issue is to skip/filter the unsupported `(FLASH_ATTN_MLA, fp8)` test matrix cell. True `FLASH_ATTN_MLA` FP8 support would require a fused low-level operator in the FA3/vllm-flash-attention path that consumes FP8 KV cache directly; the currently available fused FP8 MLA decode path is the dedicated FlashMLA backend/extension.
