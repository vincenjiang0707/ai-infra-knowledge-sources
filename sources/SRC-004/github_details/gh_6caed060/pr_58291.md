# [PR #58291] [Bugfix] Attach DeepSeek-V4 request tools to existing system/developer messages

## 正文

## Purpose

Fixes #58280.

DeepSeek-V4 still put request-level `tools` on a synthetic leading system message whenever the conversation started with a **developer** prompt. That renders `## Tools` *before* the instructions, so serving diverges from the reference encoder (`{content}\n\n## Tools`) and from how the same data is packed at train time.

`#51856` already attaches tools to an existing **system** message. This extends that to **developer** as well: attach to the first `system`/`developer` message, and only insert a synthetic system message when neither is present.

Not a duplicate of `#52255` (stale, needs-rebase; would redo the already-landed system case). Smaller nits in the issue (tool-parser newlines, tool-message join) are left alone.

AI assistance was used to implement and test this change. A human reviewed the diff.

No model-eval change: this only reorders the tools block onto an existing developer/system message.
