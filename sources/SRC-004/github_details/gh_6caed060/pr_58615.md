# [PR #58615] [Bugfix][Metrics] Keep per-request records out of the debug wire payload

state: open | updated: 2026-09-27T07:36:21Z

## 正文

Fixes #58596

**What breaks.** With `--enable-mfu-metrics` and `VLLM_DEBUG_MFU_METRICS=1`, the first request returns HTTP 500 and the server shuts down: `msgspec.ValidationError: Expected int, got array` at `debug_stats.context_breakdown`. Since #55624, `ExecutionContext` carries per-request records (`requests: list[tuple[...]]`), and `get_step_perf_stats_per_gpu` passes `asdict(ctx)` into `DebugPerfStats.context_breakdown`, which is typed `dict[str, int]`. The engine core encodes it fine; the frontend's typed `MsgpackDecoder(EngineCoreOutputs)` rejects it and the output handler dies.

**Fix.** Filter the dict to its int counters at the production site. The per-request records stay engine-side (the sliding-window estimator uses them there), the wire type holds, and a future non-int field cannot take the server down the same way.

**Not duplicating.** No open PR touches this path; #55624 introduced the field and this repairs its wire contract rather than reverting it.

**Tests.** New `test_debug_perf_stats_survive_typed_decoder` builds real debug stats through `get_step_perf_stats_per_gpu` with the debug env on and round-trips them through `MsgpackDecoder(PerfStats)`. Red on the unfixed tree (ValidationError), green here. Ran `tests/v1/metrics/` locally: 105 passed; the 2 `test_engine_logger_apis.py` failures and the `test_ray_metrics.py` collection error reproduce identically on the unfixed tree (my minimal macOS venv lacks the engine/ray pieces), unrelated to this diff.

Server-level repro (the 500 + shutdown) needs a GPU host, which I don't have here; the issue's reporter verified the unit round trip 3/3 and the fix is exactly the contract the typed decoder enforces.

AI assistance was used in preparing this PR (Kimi); the analysis, the diff, and the local verification above were reviewed by the committer before submission.
