# [PR #58879] [Bugfix] Use original context length for mRoPE YaRN correction range

source: https://github.com/vllm-project/vllm/pull/58879
state: open | updated: 2026-09-27T05:19:15Z
labels: bug

## 正文

## Purpose

Fixes #58870.

`MRotaryEmbedding` enlarges `max_position_embeddings` 4x as cos/sin cache headroom (for Qwen2.5-VL video positions) and passes the enlarged value to the base class. For YaRN it borrows `YaRNScalingRotaryEmbedding._compute_inv_freq`, which reads `self.max_position_embeddings` as the *original* context length for `yarn_find_correction_range`. So every mRoPE + YaRN model (Qwen2-VL, Qwen2.5-VL, Qwen3-VL, Qwen3.5 with YaRN enabled) computes its correction range from 4x the original length, and the interpolation ramp no longer matches Transformers (`_compute_yarn_parameters` uses `original_max_position_embeddings`).

For the config in the issue, the ramp moves from (14, 22) to (16, 24) and 9 of 32 inverse frequencies differ from HF by up to 37.5%. Plain YaRN (no `mrope_section`) is unaffected and already matches HF exactly.

The fix records the original length as `original_max_position_embeddings`, the name `Phi3LongRoPEScaledRotaryEmbedding` already uses, and has YaRN's correction range read it:

- `YaRNScalingRotaryEmbedding` sets it to `max_position_embeddings`, so plain YaRN behaves exactly as before.
- `MRotaryEmbedding` sets it before applying the 4x headroom.

The cache size is deliberately unchanged. The 4x headroom is documented as intentional for Qwen2.5-VL video positions, and shrinking it is a separate question from the frequency mismatch.

**Not a duplicate:** no open PR references #58870. #53964 (request-static YaRN profiles for mRoPE) also touches `MRotaryEmbedding`, but it keeps taking the correction range from the enlarged length, so it doesn't fix this.

## Test Result

**Regression test:** passes with this change. On `main` both cases fail: 26.7% and 35.6% of the cos/sin cache entries differ from Transformers, by up to 0.197 and 1.62.

**Reproducer from the issue:** on `main`, 9 of 32 inverse frequencies differ from HF. With this change there are none. The cache stays at 2,621,440 rows, and plain YaRN is unchanged (still exact vs. HF, 655,360 rows).

**Suites:** 950 passed, 6 skipped, 20 failed. The same 20 fail on unpatched `main` on this machine: 16 `test_rotary_embedding` bf16 cases with 8,192 tokens hit CUDA OOM on a 6 GB GPU, and 4 config tests need gated `meta-llama` repos. pre-commit and the manual mypy hook pass.

**Model eval:** mean |Δ logprob| vs. Transformers, and top-1 agreement:

| positions | `main` | this PR |
|---|---|---|
| 1–1000 | 0.0389 | 0.0271 |
| 1000–2000 | 0.0497 | 0.0250 |
| 2000–3000 | 0.0596 | 0.0261 |
| 3000–3500 | 0.0680 | 0.0268 |
| **all** | **0.0521** (97.0% top-1) | **0.0262** (98.3% top-1) |

On `main` the gap to Transformers grows with position, as expected from a wrong interpolation ramp. With this change it stays flat at the bf16 noise level. Tokens after position 3,500 were not measured (6 GB GPU).
