# [PR #53011] [Bugfix] Avoid eager torch.compile in Kimi K2.5 vision helper

source: https://github.com/vllm-project/vllm/pull/53011
state: open | updated: 2026-09-27T04:42:23Z
labels: bug, ready, torch.compile, kv-connector, kimi

## 正文

## Problem

`get_rope_shape` in the Kimi K2.5 vision encoder was decorated with bare
`torch.compile`, and an eager wrapper invoked it on the first input key. This
could initialize Triton before vLLM's compilation lifecycle configured its
cache directories, causing warm-cache reload failures.

## Solution

Remove the eager wrapper and bare decorator so compilation remains under
vLLM's compilation lifecycle. This leaves `get_rope_shape` as a regular helper
for the caller's existing compilation path.

Fixes #52965

## Testing

- `.venv/bin/ruff check vllm/model_executor/models/kimi_k25_vit.py`
- `.venv/bin/ruff format --check vllm/model_executor/models/kimi_k25_vit.py`
- `.venv/bin/python -m py_compile vllm/model_executor/models/kimi_k25_vit.py`
- `pre-commit run --files vllm/model_executor/models/kimi_k25_vit.py`
- `git diff --check`

The full model test suite requires the repository's CUDA/PyTorch environment
and was not run on this Apple Silicon host.

AI assistance was used for repository exploration and implementation; the
submitting contributor reviewed the changed lines and owns the validation.
