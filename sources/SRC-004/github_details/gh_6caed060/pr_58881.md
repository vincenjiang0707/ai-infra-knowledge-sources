# [PR #58881] [Bugfix][Core] Publish KV cache reset events while idle

## 正文

## Purpose

An idle engine can clear its prefix cache without sending `AllBlocksCleared` until another inference step. A router using these events may keep cache locations that are no longer valid.

Publish pending KV events immediately after a successful local reset. Preserve pending events when the local reset fails, and still publish a local clear if the connector reset returns `False`.

Related: vllm-project/aibrix#2287. No equivalent open PR was found: #58670 adds Mooncake events; #57789 adds cache snapshot and recovery support.

### Reproduction

Enable automatic prefix caching and ZMQ KV events, with a subscriber already receiving events.

1. Generate the same 129-token prompt twice; the second request reuses 128 tokens.
2. Call `LLM.reset_prefix_cache()` and leave the engine idle for 2 seconds.
3. Generate the same prompt again.

| When | Before | After |
| --- | --- | --- |
| While idle after a successful reset | No event | `AllBlocksCleared` |
| After the next request | `AllBlocksCleared`, `BlockStored` | `BlockStored` |
