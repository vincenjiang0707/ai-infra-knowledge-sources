**Owner:** @mpashkovskii

### Related work

RoPE-to-IR has been attempted before: **#38756** ("Port RoPE ops to IR") tracked it, with **#43199** (@wxsIcey) and its predecessors **#39488 / #41773 / #42264** carrying the implementation. That series is **closed and unmerged** (last state: merge conflicts, `mergeable_state: dirty`), and RoPE is still **not** an IR op on current `main`.

#58838 revives that direction but differs materially:

- rebased on current `main`, conflict-free;
- **keeps `MatcherRotaryEmbedding`** instead of deleting it — current `main` gained the AITER `QkNormRopeKvCacheFusionPass` (#53918) *after* #43199 was written, and that pass depends on the matcher;
- **completes the ROCm/AITER path** (adds an `aiter` IR provider, decouples the AITER dispatch from `RotaryEmbedding.enabled()`);
- scope limited to the base `RotaryEmbedding` (Neox / GPT-J); `DeepseekScalingRotaryEmbedding`, mRoPE, flashinfer, and the `key=None` cross-layer-KV-sharing path are left for follow-ups.

Motivating bug: **#28042** — RoPE only matched the QK-norm+RoPE fusion when registered as a custom op.
