## 正文

## Purpose

MRV2 skipped frontend validation for auto-discovered logits processors, allowing invalid parameters to reach workers. Discover and validate these plugins at admission while preserving pooling's intentional skip.

## Reproducer

A temporary reproducer registers an entry-point-only processor whose `validate_params()` rejects the request, constructs the normal frontend validator, and separately verifies the pooling skip.

```python
from types import SimpleNamespace
from unittest.mock import patch

from vllm.exceptions import VLLMValidationError
from vllm.sampling_params import SamplingParams
from vllm.v1.engine.input_processor import InputProcessor
from vllm.v1.worker.gpu.sample.logits_processor import loader
from vllm.v1.worker.gpu.sample.logits_processor.interface import (
    LogitsProcessor,
)


class RejectingPlugin(LogitsProcessor):
    validation_calls = 0

    @classmethod
    def validate_params(cls, sampling_params):
        cls.validation_calls += 1
        raise ValueError("plugin rejected request")

    def apply(self, logits, ctx):
        return logits


class EntryPoint:
    name = "rejecting"
    value = "reproducer:RejectingPlugin"

    def load(self):
        return RejectingPlugin

    def __str__(self):
        return self.name


def build_validator(runner_type):
    processor = SimpleNamespace(
        model_config=SimpleNamespace(
            logits_processors=None,
            runner_type=runner_type,
        ),
        vllm_config=SimpleNamespace(use_v2_model_runner=True),
    )
    return InputProcessor._build_logits_processors_params_validator(processor)


loader._cached_load_v2_logitsprocs.cache_clear()
with patch.object(loader, "entry_points", return_value=[EntryPoint()]) as discover:
    validator = build_validator("generate")

    try:
        validator(SamplingParams())
    except VLLMValidationError as exc:
        generation_outcome = f"rejected: {exc}"
    else:
        generation_outcome = "accepted invalid request"

    print(f"generation_discovery_calls={discover.call_count}")
    print(
        f"generation_validation_calls="
        f"{RejectingPlugin.validation_calls}"
    )
    print(f"generation_outcome={generation_outcome}")


# Verify that pooling models retain their intentional plugin skip.
loader._cached_load_v2_logitsprocs.cache_clear()
with patch.object(
    loader,
    "entry_points",
    side_effect=AssertionError("pooling unexpectedly loaded plugins"),
) as discover:
    validator = build_validator("pooling")
    validator(SamplingParams())

    print(f"pooling_discovery_calls={discover.call_count}")
    print("pooling_outcome=plugin skipped")
```

Thanks @njhill ! You’re right that the existing code returns a no-op for both pooling and non-pooling models when custom_logitsprocs is empty. The subtle issue is that “empty” only means no processors were explicitly configured.

For a non-pooling model, the worker still calls [_load_v2_logitsprocs()](https://github.com/taneem-ibrahim/vllm/blob/1119518fd18b6d7cf859673460dd6c9837721d3c/vllm/v1/worker/gpu/sample/logits_processor/loader.py#L181-L183), which always includes [installed entrypoint plugins](https://github.com/taneem-ibrahim/vllm/blob/1119518fd18b6d7cf859673460dd6c9837721d3c/vllm/v1/worker/gpu/sample/logits_processor/loader.py#L136-L146). For example, if custom_logitsprocs=[] but a processor is installed through the vllm.logits_processors entrypoint, the worker loads and runs it. 

Pooling is different because the worker [returns before loading any entrypoint plugins](https://github.com/taneem-ibrahim/vllm/blob/1119518fd18b6d7cf859673460dd6c9837721d3c/vllm/v1/worker/gpu/sample/logits_processor/loader.py#L172-L181). That’s why the no-op is still correct for pooling. The goal here is to make the frontend and worker discover the same processors for non-pooling models.

Overall, the probability of hitting this particular issue is **_low_**. For normal set up without entrypoint plugins, the bug cannot occur. But for an entrypoint-only plugin, admission validation is skipped on every request, invalid input will reliably reach the worker.

The worker loads entry point processors even when none are explicitly configured, but the frontend currently returns a no-op and skips their validate_params(). This proposed PR makes the frontend discover and validate those processors, while keeping the existing pooling behavior unchanged since pooling already ignores the entry point processors.
