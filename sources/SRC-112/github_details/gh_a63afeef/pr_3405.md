## 正文

Adds six Kimi-K3 B300 Mooncake EFA AgentX recipes from #2814 on the current `srt-slurm` schema, pinned to `vllm/vllm-openai:nightly-0961bbae2894d574be790d219651824eb199318e`.

The shared setup installs AWS EFA Installer 1.50.0, the Mooncake EFA wheel, and `libhwloc15` for NIXL's LIBFABRIC plugin. Disaggregated recipes select NIXL LIBFABRIC; aggregate recipes use Mooncake Store. FlashInfer autotuning is enabled.

Validation: all six recipes pass `srtctl dry-run`. The DSXE aggregate canary is in progress.

The recipe content itself checks out statically. The three master-config entries match the schema in `infx/matrix/validation.py` (agg entries carry `worker` + `num-nodes`, disagg entries carry `prefill`/`decode` with the `CONFIG_FILE` on prefill, no entry-level `dcp-size`), `model.container` equals `image` in all six recipes, the Docker Hub image path is a public-registry format, `moonshotai/Kimi-K3` resolves through `runners/srt-slurm/b300-dsxe.yaml`, the `probabilistic`/`block` DSpark settings map to the committed golden curve which covers both draft lengths 4 and 7, and the matrix `conc-list` values match each recipe's `concurrencies`. The Mooncake version pinned in the master config (`0.3.13.post1`) matches the wheel installed by the setup script.

Not verified in this environment (the sandbox blocked network access and `python`, and the `utils/srt-slurm` submodule is not checked out): that the `nightly-0961bbae…` tag exists on Docker Hub, that the patch hunk lands on line 173 of upstream `cudagraph_utils.py`, that srt-slurm's `mooncake-master` service accepts `protocol: efa`, and the generator output for the three keys. The PR body reports dry-run and generator success for these, and the queued full sweep will exercise them.
