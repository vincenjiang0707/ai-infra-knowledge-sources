**Stopped before GPU dispatch · baseline-point-mismatch**\
All 9 published 2026-09-01 `lmsysorg/sglang:v0.5.14-cu130` points (producer [33451222974 / attempt 2](https://github.com/SemiAnalysisAI/InferenceX/actions/runs/33451222974/attempts/2), head `0c32f3c2`) were generated before the fixed-sequence SRT-Slurm migration (#3352). Their point identities have no `srt-recipe`, so the current family can't produce them and final baseline coverage would fail: 8k/1k TP4/EP1 c4; TP2/EP1 c4, c8, c16, c32, c64; TP2/EP2 c16, c32, c64.\
Source check: `v0.5.20-cu130` (`sha256:06e4f2ed…d611f`) bundles sglang 0.5.20 at [`94602c9c`](https://github.com/sgl-project/sglang/tree/94602c9c2b7cbdb8efd5c52802dac6a1c180089e). Its parser accepts every recipe flag once `--cuda-graph-max-bs` becomes `--cuda-graph-max-bs-decode`. The alias was removed in v0.5.20; in [v0.5.14](https://github.com/sgl-project/sglang/blob/v0.5.14/python/sglang/srt/server_args.py) it set the same field. Performance compatibility is untested.
