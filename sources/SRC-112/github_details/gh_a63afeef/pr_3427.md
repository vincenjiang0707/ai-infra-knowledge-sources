## Description

CollectiveX's workflow now calls Python directly. Python owns allocation, image/source staging, backend preparation, rank startup, retries, artifact collection, and cleanup; **all seven original CollectiveX Bash files are removed**. Job steps execute through the real `simple-slurm==0.3.6` API. Explicit `salloc --no-shell`, targeted queue queries, and cancellation preserve the existing allocation model.

The benchmark side separates the former monolithic harness (1,662 lines at the initial baseline; 1,774 in current main) into orchestration, measurement, correctness, and results. DeepEP/UCCL share compatible Buffer operations. Small helper modules were folded back into their owners: implementation files fell from **41 in the first refactor to 28**, versus **25 at the original baseline**. There is no shell-to-Python argument protocol or generated shell environment file.

This is intended to preserve behavior: matrix coverage, CLI arguments, workload/timing profiles, event ordering, source/image pins, cache identities, per-pool placement and retries, result schema, failures, and cleanup. All work stays in the worktree created from `origin/main` at `960ff1ffa51e160df422394e0477a4410fa65888`. The final integration merges current main at `4f94801a5` and preserves its concurrently landed CUDA-graph replay and NCCL rank-major/zero-copy changes; those are upstream behavior, not new refactor features.

**The 30% implementation LOC reduction target is not met.** Python plus Bash grows **194 physical lines (+2.1%)**. The final result has fewer files than the first refactor and no repository-owned Bash orchestration, but Python's explicit resource handling, argument lists, and process boundaries do not produce a net line reduction. Tests, error handling, and measurement explanations were not sacrificed to meet a percentage.

### Structure and call flow

`collectivex-sweep.yml → ci.py → runtime/execution.py → simple-slurm srun / Docker torchrun → runtime/node.py → bench/run_ep.py → EPBackend adapter → ep_harness.run_sweep → ep_results`

- `ci.py`: matrix/extraction, execution, independent finalization, and private-workspace cleanup.
- Runtime has **eight substantive modules**, plus its package initializer: `config.py` (pool policies/settings/arguments), `scheduler.py` (Slurm/processes/locks/logs), `probe.py` (hardware/network discovery and selectors), `storage.py` (images and staging), `build.py` (pins/source/build caches), `node.py` (compute-host preparation and rank bootstrap), `execution.py` (shard lifecycle), and `docker.py` (Slurm-less pools).
- `run_ep.py` owns CLI setup and lazy backend dispatch. `ep_backend.py` owns the abstract transport/input contract. `ep_measurement.py` owns `EPTiming`, event timing, reductions, and samples. `ep_harness.py` orders passes, `ep_oracle.py` checks them, and `ep_results.py` owns identity/accounting/publication.
- `BufferOperations` in `ep_buffer.py` shares the active DeepEP/UCCL Buffer operations; vendor constructors, quantizers, and different normal transports remain in their adapters. `EPBackend` inherits `EPTiming`; orchestration mostly uses functions and data classes, with `SlurmAllocation` owning one allocation.
- Swap-blocks uses the same cluster lifecycle with its existing independent benchmark and schema. OperatorX's probe and runtime-directory consumers remain covered.

### Judgment calls

1. **Library choice:** use portable `simple-slurm`, without requiring Slurm-version-matched PySlurm headers/shared libraries on every runner. It really executes each `srun`. Its API internally invokes a shell; all dynamic values are quoted. “No Bash orchestration” does not mean the library never invokes `/bin/sh`.
2. **Allocation semantics:** keep explicit allocations and native lifecycle queries/cancellation because replacing them with `sbatch` changes resource ownership and cancellation behavior. Do not add a Python daemon or cluster service.
3. **Small-file consolidation:** configuration owns pool policies and block-copy arguments; probes own network selectors; scheduler owns process helpers; builds own dependency pins; measurement owns timing; CLI/identity/ladder helpers live with their consumers. Keep genuine process boundaries and numerical responsibilities separate. Name the active shared implementation `ep_buffer.py`/`BufferOperations`; it is not deprecated compatibility code.
4. **No numeric redesign:** retain explicit isolated timing and sibling chain loops, event placement, call depth, source pins, quantizers, and different wire contracts. Combine sharing applies to untimed oracle work.
5. **Worker environments:** install the host dependency with the locked `collectivex` extra, but invoke its interpreter directly so the host venv does not replace the pinned container's `PATH`/Python. Compute-host utilities travel as a stdlib zipapp; vendor imports remain lazy. Node setup publishes a private, allowlisted JSON environment instead of executable shell text.
6. **Recovery:** preserve per-pool allocation/health/image retry policies and cache keys. Persist allocation/container ownership for independent finalization; stop jobs before collection/deletion, retain recovery state when stop is unconfirmed, and preserve signal exit status. AMD Docker block copies retain runner UID/GID, and Python bytecode writes are disabled for container utilities.
7. **Concurrent main changes:** merge the newly landed graph-replay/NCCL changes into their new owners and compare against that main revision. Keep the same graph defaults, capture/replay events, rank-major reduction, and output fields. One existing SRT test double needed to recognize Git global `-c`/`-C` options used by main; this fixes 14 unrelated test failures without changing production launcher code.
8. **Scope/LOC:** favor behavioral equivalence and explicit handling over the 30% target; report the shortfall and test/docs growth honestly. No recipe, image, source pin, workload or timing-profile change is intended, so `perf-changelog.yaml` is untouched. No full serving sweep/eval reuse or merge authorization is claimed.

## 判断与取舍

1. 选择可移植的 simple-slurm，避免各运行器安装与 Slurm 版本严格匹配的 PySlurm 头文件/共享库。库实际执行 srun，内部仍调用 shell，动态值全部转义；“无 Bash 编排”不表示库绝不调用 `/bin/sh`。
2. 保留显式分配和原生查询/取消，因为改成 sbatch 会改变资源归属及取消行为；不引入 Python daemon 或集群服务。
3. 合并细碎模块，但保留真正的进程边界和数值职责：配置持有池策略/块复制参数，probe 持有网络选择器，scheduler 持有进程辅助，build 持有版本，measurement 持有计时，CLI/身份/梯度回归各自使用方。共享模块命名为 `ep_buffer.py`/`BufferOperations`，表达当前使用的 Buffer 操作，避免被误解为已废弃的兼容代码。
4. 不重新设计数值逻辑：保留计时循环、双链、event 位置、调用层次、版本、量化器和不同通信约定；combine 共享仅用于不计时的 oracle 工作。
5. 宿主依赖用锁定 extra 安装，直接调用 venv 解释器，避免污染容器 PATH/Python。计算节点工具通过标准库 zipapp 传输，厂商库按需导入；节点环境用私有白名单 JSON 替代可执行 Shell 文本。
6. 保留各池重试策略和缓存键；记录资源归属供独立清理，确认作业停止后才回收/删除，不能确认时保留恢复状态，并维持信号退出码。AMD Docker 块复制继续使用运行器 UID/GID，容器工具禁写 Python bytecode。
7. 将同期合入的 graph/NCCL 改动迁移到对应职责模块，以最新 main 为对照，保留默认模式、捕获/回放 event、rank-major 归约和产物字段。既有 SRT 测试替身需识别 main 使用的 Git `-c`/`-C` 全局选项，修正 14 项无关测试失败，没有修改生产启动器。
8. 行为等价和清晰处理优先于行数目标，明确披露未达目标及测试/文档增长。无配方、镜像、源码版本、工作负载、计时配置的预期变化，perf-changelog.yaml 未改；不声称全量推理扫描/评估复用或合并授权。
