## Summary

Replace all raw `subprocess.run(["gh", ...])` and `subprocess.run(["git", ...])` calls in `infx/workflows/merge_with_reuse.py` with **PyGithub** (GitHub REST API) and **GitPython** (git operations). Behavior is identical to the prior module: same eligibility checks, comment text, sync/merge order, perf-changelog conflict resolution, head-lag retry, exit codes 0/1/2, and error messages.

## Dependencies

Added to the `workflows` optional extra in `pyproject.toml`:
- `PyGithub>=2.6,<3` (locked 2.10.0)
- `GitPython>=3.1,<4` (locked 3.1.62)

Install: `uv sync --extra workflows` or `uv run --extra workflows python -m infx.workflows.merge_with_reuse <pr>`

## `gh` to PyGithub mapping

| Old `gh` / `infx.github.api()` call | New PyGithub call |
|---|---|
| `gh pr view --json headRefName,isCrossRepository,state,labels` | `Repository.get_pull()` fields: `.state`, `.head.repo.full_name`, `.head.ref`, `.labels` |
| `gh pr comment --body` | `PullRequest.create_issue_comment()` |
| `gh pr view --json headRefOid` | `pull.update(); pull.head.sha` |
| `gh pr view --json mergeCommit` | `merge_status.sha` from merge result |
| `gh pr checks --watch --fail-fast` | Poll `commit.get_check_runs()` + `commit.get_combined_status()` with fail-fast semantics |
| `gh pr merge --squash --admin` | `PullRequest.merge(merge_method="squash", sha=<head>)` -- admin bypass relies on token's ruleset bypass permission; API error surfaced verbatim |
| `infx.github.api("/commits/{sha}/check-runs")` | `gh_repo.get_commit(sha).get_check_runs()` |
| `gh api` (in `sweep_runs.py` via `infx.github`) | Unchanged -- `find_eligible_run` still calls `infx.github.paginate()` for artifact/run listing |

## `git` to GitPython mapping

| Old `subprocess.run(["git", ...])` | New `GitOps` method |
|---|---|
| `git status --porcelain` | `repo.is_dirty(untracked_files=True)` |
| `git symbolic-ref --short HEAD` / `git rev-parse HEAD` | `repo.active_branch.name` / `repo.head.commit.hexsha` |
| `git rev-parse <ref>` | `repo.rev_parse(ref).hexsha` |
| `git fetch origin ...` | `repo.git.fetch(...)` |
| `git checkout ...` | `repo.git.checkout(...)` |
| `git merge origin/main --no-ff --no-edit` | `repo.git.merge(...)` with return code |
| `git diff --name-only --diff-filter=U` | `repo.git.diff("--name-only", "--diff-filter=U")` |
| `git diff --quiet -- <path>` | `repo.git.diff("--quiet", ...)` (exception = non-zero) |
| `git show :<stage>:<path>` | `repo.git.show(..., stdout_as_string=False, strip_newline_in_stdout=False)` -- byte-identical to `git show` |
| `git add / commit / push` | `repo.git.add/commit/push(...)` |
| `git branch -D / merge --abort` | Wrapped in `contextlib.suppress(GitCommandError)` |

The `GitOps` class is a thin wrapper so tests can inject a mock or a temporary-directory `Repo`.

## Auth fallback

Token resolution: `GH_TOKEN` env > `GITHUB_TOKEN` env > `gh auth token` (one bootstrap subprocess, read from stdout only). Respects `GITHUB_API_URL` for GHE. Token is never printed, logged, passed as a CLI argument, or embedded in remote URLs. PyGithub/GitPython/urllib3 debug logging forced to WARNING.
