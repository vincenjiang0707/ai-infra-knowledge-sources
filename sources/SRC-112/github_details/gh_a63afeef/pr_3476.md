## Summary

Migrate 6 SPEED-Bench acceptance-length (AL) collectors from legacy bash-script execution to the native srt-slurm single-node path:

- **Migrated models**: dsr1, dsv4, glm5, glm52, qwen3.5, qwen3.8next (all `*_fp4_b300_vllm.sh`)
- **Legacy models** (unchanged): dsv4dspark, dsv4dsparkprob, kimik3 (both variants), minimaxm3

### Changes

- **6 srt-slurm recipe YAMLs** (`benchmarks/single_node/srt-slurm-recipes/<model>/vllm/b300-fp4-speedbench/speedbench.yaml`): per-model recipes with `zip_override` groups for thinking modes x MTP 1-8
- **Shared client** (`benchmarks/single_node/srt_speedbench.sh`): one script handles all migrated models (per-mode sampling, chat-template kwargs shim, metrics collection, AL computation)
- **Python collector support** (`infx/srt_slurm/single_node.py`): `_is_speedbench()` detection; `validate_recipe()` skips ISL/OSL/RANDOM_RANGE_RATIO/USE_CHAT_TEMPLATE checks for collectors; `runtime_arguments()` binds CATEGORY, SPEEDBENCH_OUTPUT_LEN, CHAT_TEMPLATE_KWARGS_ON
- **Aggregation module** (`infx/workflows/speedbench_matrix.py`): reads per-cell result JSONs and produces golden YAML matrix output
- **Workflow routing** (`.github/workflows/speedbench-al.yml`): conditional case statement routes migrated prefixes through srt-slurm (one submission per cell), keeps draft-model collectors on legacy `BENCH_SCRIPT_OVERRIDE`. `qwen3.8next` binds TP/GPU_COUNT=4 to match its TP4 recipe (plain TP8 is incompatible with its FP8 checkpoint's 128-wide quantization blocks — the legacy collector silently folded TP=8 to 4 the same way)
- **Delete 6 legacy scripts** (`benchmarks/single_node/speedbench/{dsr1,dsv4,glm5,glm52,qwen3.5,qwen3.8next}_fp4_b300_vllm.sh`)
- **Tests**: 7 new collector tests in `utils/test_srt_single_node.py`, 4 matrix aggregation tests in `utils/test_speedbench_matrix.py`
