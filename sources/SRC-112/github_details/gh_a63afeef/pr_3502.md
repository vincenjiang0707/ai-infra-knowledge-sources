## Summary

Audit all git and GitHub usage under `infx/` and refactor into two new shared subpackages:

- **`infx/git/`** -- subprocess-based git helpers (`show_file`, `rev_parse`, `diff_added_lines`, `ls_tree_batch_read`, `run_git`, `show_stage`) plus a `GitRepo` class wrapping GitPython for workflow automation
- **`infx/github/`** -- backward-compatible gh-CLI wrapper (moved from `infx/github.py`) plus `infx/github/client.py` with PyGithub helpers (`resolve_token`, `require_token`, `make_client`, `is_transient_error`, `retry_delay`)

All callers refactored to use shared helpers. Behavior is identical.

## Dependency decision

**GitPython and PyGithub remain in the `workflows` optional extra** (`pyproject.toml` unchanged). The `infx/git/` subprocess-based helpers (`show_file`, `rev_parse`, `diff_added_lines`, `ls_tree_batch_read`) work without GitPython and are safe for `--no-project` CI runs (used by `matrix/plan.py` and `validate_perf_changelog.py`). The `GitRepo` class and `infx/github/client.py` require their respective libraries and are importable only under the `workflows` extra. This avoids adding GitPython to the core install footprint while keeping a clean import boundary.

## Token safety

- Tokens are never passed on the command line, logged, printed, or embedded in URLs
- `resolve_token()` reads from env vars or `gh auth token` captured in memory only
- `require_token()` checks env vars only (no CLI fallback) for CI strictness
- PyGithub/GitPython/urllib3 debug logging suppressed at WARNING level
- Test added asserting tokens do not appear in error message text or repr

## Package shadowing

Python 3 absolute imports ensure `import git` resolves to GitPython and `import github` resolves to PyGithub even from within `infx/git/` and `infx/github/`. Tests verify this.
