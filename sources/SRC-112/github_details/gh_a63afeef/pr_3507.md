## Summary
`benchmarks/multi_node/srt-slurm-recipes/sglang/` was the only engine-first tree in the multi-node recipe directory. Every other recipe follows the layout in [RECIPES.md](benchmarks/multi_node/srt-slurm-recipes/RECIPES.md): `<model-prefix>/<engine>/<gpu>-<precision>/<workload>/<recipe>.yaml`. This moves its four MI355X SGLang disagg recipes into that layout and updates the 22 `CONFIG_FILE` lines in `configs/amd-master.yaml`. The `sglang/` directory is gone.

| Old | New |
|---|---|
| `sglang/dsr1/mi355x/fp4-disagg-fixed-seq.yaml` | `dsr1/sglang/mi355x-fp4/8k1k/disagg-variants.yaml` |
| `sglang/dsr1/mi355x/fp8-disagg-fixed-seq.yaml` | `dsr1/sglang/mi355x-fp8/8k1k/disagg-variants.yaml` |
| `sglang/qwen3.5/mi355x/disagg-1p1d-tp4p-tp8d-fixed-seq.yaml` | `qwen3.5/sglang/mi355x-fp8/8k1k/disagg-1p1d-p-tp4-d-tp8.yaml` |
| `sglang/qwen3.5/mi355x/disagg-1p1d-tp8-mxfp4-fixed-seq.yaml` | `qwen3.5/sglang/mi355x-fp4/8k1k/disagg-1p1d-tp8.yaml` |

The naming follows RECIPES.md:
- Workload is `8k1k`. All four recipes and all seven master-config entries run a single ISL 8192 / OSL 1024 point; `fixed-seq-len` is reserved for bundles spanning several lengths.
- The two DSR1 files are override bundles, so they are named `*-variants.yaml`.
- Filenames don't repeat model, hardware or precision already in the path.
- Role-qualified `p-tp4` / `d-tp8` is used for split TP.

File contents (including the internal `name:` fields) and every `override_*` selector are unchanged. All four moves are 100% renames.

Config keys touched (path only): `qwen3.5-fp8-mi355x-sglang-disagg`, `qwen3.5-fp4-mi355x-sglang-disagg`, `dsr1-fp8-mi355x-sglang-disagg`, `dsr1-fp8-mi355x-sglang-disagg-mtp`, `dsr1-fp4-mi355x-sglang-disagg`, `dsr1-fp4-mi355x-sglang-disagg-mtp`, `dsr1-fp4-mi355x-sglang-disagg-8k1k-mtp`.

No perf-changelog entry and no sweep: benchmark behavior is unchanged. `run-sweep.yml` only triggers on `perf-changelog.yaml`. Historical changelog mentions of the old paths stay (append-only).

## Known effect
The recipe path is part of the generated matrix row. `recipe_fingerprint` and `_matrix_curve_key` in `infx/matrix/plan.py` hash every field except `conc`, `exp-name` and `recipe-fingerprint`. So the 22 affected entries get new fingerprints. The next changelog entry for any of the 7 keys must be a regular, not append-only, entry, and Klaud per-point joins will not match pre-move result rows. App curves are unaffected: `_matrix_visual_series_key` ignores `additional-settings`. This is the same cost earlier recipe moves accepted (e.g. #3086).
