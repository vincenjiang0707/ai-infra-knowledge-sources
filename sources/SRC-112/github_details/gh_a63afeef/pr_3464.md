## Summary
Delete the last legacy single-node benchmark and config archives, and every live pointer to them:

1. **`benchmarks/single_node/fixed_seq_len/`** (110 files, all under `deprecated/`). Since the single-node SRT-only cutover (2026-09-22) every active fixed-sequence config runs as an srt-slurm recipe; nothing executes or sources these scripts.

### Policy change: retired configs are deleted, not archived
- `AGENTS.md` "Deprecating benchmark configs", `docs/configuration-procedures(_zh).md` and the Claude review prompt in `.github/workflows/claude.yml` now say: delete retired entries (or only the retired scenarios); git history and `perf-changelog.yaml` are the record. Unused recipes/setup scripts are deleted rather than moved to a `deprecated/` directory.

### Docs moved to the srt-slurm recipe flow
- `.claude/commands/add-model-hardware.md` (the add-model-hardware skill): produce an srt-slurm recipe + master entry with `srt-recipe:` + changelog; no bash script, no launcher routing (variant selection via `infx/srt_slurm/single_node.py::select_recipe`); `USE_CHAT_TEMPLATE: 'true'` for MTP; dropped the retired in-place MiniMax-M3 ROCm EAGLE3 patch step.
- `docs/configuration-procedures(_zh).md` new-config steps 2/3/6 and sources line likewise.

### Pointers
- `MODELS(_zh).md`: links into `configs/deprecated/` become plain text; present-tense "archived in / live in" statements now say the archive was removed (dated history otherwise unchanged).
- `KLAUD_DEBUG.md` example pointer dropped (identical to the same line in #3463, so the two merge cleanly); `benchmarks/multi_node/amd_utils/deprecated/models_vllm.yaml` comment updated.

Not changed: `SCENARIO_SUBDIR: fixed_seq_len/` in the workflows is a path fragment still consumed by the launchers' generic bash fallback (no active config reaches it); removing that fallback across all launchers is a separate cleanup.
