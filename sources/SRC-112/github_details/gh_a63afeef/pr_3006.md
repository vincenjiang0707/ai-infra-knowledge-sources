> [!NOTE]
> **Medium Risk**
> Changes benchmark serving topology (DCP, KV offload backend, cudagraphs) and cluster node selection, which can affect measured performance and job placement but not application security paths.
> 
> **Overview**
> Retunes the **Kimi-K3 MXFP4 agentic MTP** vLLM benchmark on MI355X and aligns the matrix config with the new serving recipe.
> 
> The benchmark script is reworked around **concurrency bands**: low conc (1–16) keeps **DCP off**, **MTP/DSpark** with golden synthetic acceptance lengths (or live block rejection in eval-only), **Triton KDA prefill**, and tuned batch/seq limits; higher conc turns on **DCP=8** and only applies **SimpleCPUOffloadConnector** when the harness requests DRAM offload—**LMCache** install/server path is removed. Defaults shift to **newer AITER/vLLM env flags**, **gpu-memory-utilization 0.89**, **`FULL_DECODE_ONLY` cudagraphs** with a 1..N capture ladder, **`fastsafetensors`**, and extra serve flags (`--no-async-scheduling`, prompt token details). After startup, workers can be **pinned to CCDs** via NUMA/L3 topology.
> 
> **`amd-master.yaml`** bumps the ROCm vLLM **nightly image**, **dram-utilization to 0.65**, and expands the search space (e.g. conc 16 without offload; high-conc points use **vllm-simple** + DCP8). **`launch_mi355x-amds.sh`** excludes node **`mia1-p01-g09`** from allocations. Changelog records the image update.
