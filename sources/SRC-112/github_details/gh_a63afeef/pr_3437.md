# [PR #3437] CollectiveX: graph-replay every capturable EP backend with rank alignment and the chained period

## 正文

Graph-replays each EP backend where it's that library's fastest configuration that passes every check. It also fixes graph timing, so graphed and eager rows measure the same thing.

## Harness
- **Rank-aligned replay.** Each timed replay starts behind a device-side rank barrier: an all-reduce, then a spin of fixed *wall time*, with no host sync. The spin is converted to cycles per GPU by measuring its spin rate. A fixed cycle count left ~15 µs of skew between differently clocked ranks. Timing events are graph nodes.
- **Graphed fresh-entry tails are withheld.** `roundtrip`, `dispatch`, `combine` and `cross_rank_min` publish only p50 under replay. A rank whose host launches its replay late still stalls the others, and those stalls own p90–p99 (gb200 T=1 roundtrip p99 858 µs vs combine p99 30 µs).
- **The chained family comes back under graphs.** Each chain sibling is one graph of unrolled pairs, the shape of a decode graph. `pair_period` keeps its tails, and the chained oracle runs.
- **Every graphed row is value-checked.** An untimed capture puts `stage()` inside the graph. What dispatch wrote and the combined output are filled with 0xFF bytes (NaN) before its replay, and the result must match an eager drained pair. Previously, FP8 and hoisted-staging rows (e.g. flashinfer) had only a finite-output check.
- **ROCm:** timing events are captured with `hipEventRecordWithFlags(..., hipEventRecordExternal)`, because the image's torch (older than 2.13) rejects `Event(external=True)`.
- Graphed rows get a `-cudagraph` suffix on `kernel_generation`.

## Per-library configuration
| Backend / mode | Default | Notes |
|---|---|---|
| deepep-v2 LL | graph | |
| deepep-v2 normal decode | graph, `do_cpu_sync=False`, receive sized to the next power of two of T | vLLM's graphed `deepep_v2` decode contract; `v2-elastic-buffer-nosync` |
| deepep-v2 normal prefill | eager, host sync | unchanged |
| uccl-ep LL | graph, intranode only; eager on b200 FP8 | scale-out goes through the CPU proxy, never validated under capture |
| uccl-ep normal | eager | capturing it would need `num_worst_tokens` padding (not done) |
| flashinfer-ep | graph for decode, eager for prefill | decode gain is removed host overhead |
| nccl-ep LL | graph, rank-major (TensorRT-LLM's NCCL EP contract) | `COLLX_NCCL_LL_LAYOUT=expert-major` gives the like-for-like row (`nccl-ep-v02-ll-em`) |
| nccl-ep HT | eager, zero-copy, full static combine input (`-zc-static`) | see below |
| MoRI | graph, both modes | new in this revision; see validation |

**The rank-major nccl-ep LL win is mostly contract, not kernel.** Rank-major moves ~27% fewer wire bytes (b200 EP8 T=8: 281 vs 384 copies), and within one scale-up domain it's also the zero-copy variant. Where neither variant is zero-copy (b200 EP16) the gap is ~2%. The artifacts record both bases (`byte_provenance` vs `wire_byte_provenance`).

**nccl-ep HT:**
- The combine input used to be sliced to the received count. The FLAT contract requires the full static `[num_recv_slots, hidden]` plane, and requires it outright under graph capture. The slice broke the contract in both regimes, and it's the prime suspect for the earlier intermittent graphed failures (b200 EP16 T=128, h200 EP16 T=32 and prefill T=1024).
- Now fixed. HT stays eager until repeated graphed runs are clean.
