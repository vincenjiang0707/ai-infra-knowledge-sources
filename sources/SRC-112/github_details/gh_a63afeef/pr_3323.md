## 正文

## Summary

Add BF16 H100 coverage for `Qwen/Qwen3-0.6B` using ModelScope and `nvcr.io/nvidia/tensorrt-llm/release:1.3.0rc27`. The source-matched runtime backport of [TensorRT-LLM #2](https://github.com/SemiAnalysisAI/TensorRT-LLM/pull/2) uses scoped snapshot and path resolution. Both the server and benchmark tokenizer use the ModelScope snapshot.

The image matches `v1.3.0rc27`, commit `6e1cc953c071b8a9055b03ef2ae4ee0bc4c645c4`. Runtime dependencies are pinned to `modelscope==1.40.1` and `modelscope-hub==0.4.3`. The [engine-patch waiver](docs/waiver/3323.md) records provenance and removal when an NGC image includes the integration.

## Evaluation policy

The initial [H100 sweep](https://github.com/SemiAnalysisAI/InferenceX/actions/runs/35534330261) passed all five throughput points. GSM8K completed all 1,319 questions at concurrency 64 with 0.6717 strict / 0.6785 flexible accuracy, then failed the global 0.90 threshold; fail-fast cancelled concurrency 32.

Set `models.qwen3-0.6b.gsm8k` to a conservative **0.60 integration regression floor**. Preserve five-shot chat, deterministic sampling, the 5,376-token budget, and both scored metrics. The [policy and sample audit](docs/eval-agentx-procedures.md#qwen3-06b-gsm8k-floor) document formatting/repetition errors, the 7.17-point strict-score margin, and Qwen's greedy-decoding caveat. Qwen's published 59.59% result is for the base model with four-shot CoT and is scale context only; no directly comparable published chat baseline was established. This floor is not a claim of optimal model quality.

## Validation

- Exact-key and filtered full matrices: 8k/1k, TP1, concurrency 1, 4, 16, 32, 64; evals at 32 and 64.
- Changelog validation, Bash syntax, Python compilation, Ruff checks, and `git diff --check` passed.
- Nine eval-batching tests passed; score validation accepts the recorded full-split result and rejects 0.59.
- The patcher applied twice to exact `v1.3.0rc27` source: first application patched, second was idempotent, and patched modules compiled.
- [Full canary-gated sweep 35538521127](https://github.com/SemiAnalysisAI/InferenceX/actions/runs/35538521127) passed on final head `916278d18`: all five throughput points and both evals. All 1,170 benchmark requests completed with zero failures and valid power data. Tests, lint, and Python CodeQL passed.
- Model weights and inference ran only on H100, never on the local laptop.

Both evals completed all 1,319 questions with no empty responses and the same unchanged deterministic settings. Raw samples, result metadata, score validation, and all seven server logs were inspected. Each server used TensorRT-LLM `1.3.0rc27` and loaded weights from the ModelScope snapshot; the canary job log confirms the benchmark tokenizer used that same snapshot. No server errors or Hugging Face model fallback appeared in the logs.

### Summary

One 🟡 warning posted inline on `runners/patch_trtllm_modelscope.py`: the ModelScope branch forwards Hugging Face glob patterns into `ignore_file_pattern` / `allow_file_pattern`, which ModelScope treats as regexes and silently drops when they fail to compile. That makes the ignore filter a no-op and would make `download_hf_partial` return an empty snapshot for glob allow-lists. It does not affect the full Qwen3-0.6B download this sweep performs, so it is not blocking.

Everything else checked out: the image is public NGC, the entry is single-node on `cluster:h100-dgxc`, `EXP_NAME` resolves to `qwen3-0.6b_8k1k` so the launcher picks `qwen3-0.6b_bf16_h100_trt.sh`, `HF_HUB_CACHE` and `PORT` are supplied by the workflow and launcher, `MODEL_PATH` export feeds `get_native_max_context_length` from the ModelScope snapshot, the changelog entry is appended at the tail without `append-only`, and the waiver satisfies the checklist's patch exception (matching the existing `patch_trtllm_chat_store.py` precedent).

Two non-blocking notes:
- The bench client still resolves the `Qwen/Qwen3-0.6B` tokenizer via Hugging Face (`VLLM_USE_MODELSCOPE` is unset), so the run is not fully HF-independent; pass `--tokenizer "$MODEL_PATH"` if that is the intent.
- The script recomputes `MAX_MODEL_LEN` locally instead of consuming the caller-supplied value like sibling TRT scripts; the values are identical today.
