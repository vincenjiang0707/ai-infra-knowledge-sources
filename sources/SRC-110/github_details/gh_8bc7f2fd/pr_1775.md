# [PR #1775] fix(metrics): stop math_equal matching 100x-off numbers without a % sign

source: https://github.com/modelscope/evalscope/pull/1775
state: open | updated: 2026-09-24T06:01:54Z
labels: 

## 正文

Fixes #1774.

`math_equal` checked every numeric prediction against `reference / 100`, `reference` and `reference * 100`, even when no percent sign was involved. `Accuracy(numeric=True)` and `MathAcc` use the default `include_percentage=True`, so an answer off by exactly 100x scored as correct. On gsm8k, `\boxed{1800}` against the target `18` scored 1.0.

| prediction | reference | before | after |
|---|---|---|---|
| `1800` | `18` | True | False |
| `42` | `4200` | True | False |
| `0.18` | `18` | True | False |
| `18%` | `0.18` | True | True |
| `10` | `10\%` | True | True |

The fix builds the `/100` and `*100` alternatives only when the prediction or the reference contains `%` (this also covers `\%`). `parse_digits` already turns `18%` into `0.18`, so percent answers still match. The signature is unchanged.

One trade-off. On the benchmark path, `strip_answer_string` removes the `%` before `math_equal` runs, so there only answers in the same form still match. Reference `10\%` with `\boxed{10}` or `\boxed{10\%}` still scores 1, but with `\boxed{0.1}` it now scores 0. After stripping, `10` vs `0.1` looks the same as `18` vs `0.18`, so this spot can't keep one without the other. None of the MATH-500 or gsm8k test answers contain `%`. Keeping `%` in `strip_answer_string` would bring those matches back, but it changes the extracted answer for every benchmark that uses `extract_answer`, so I left it out.

Scores can only go down. That applies to benchmarks scored by `Accuracy(numeric=True)` (gsm8k, math_500, competition_math, mgsm and others) and to the direct `math_equal` calls in agieval, hipho and tir_bench. `parser.py` comes from Qwen2.5-Math, whose grader has the same x100 check, so results can differ slightly from that script. I did not bump `evaluation_version`. AGENTS.md asks for it when scoring changes, so tell me if you want it in this PR.

Tests: new `tests/metrics/test_math_equal.py` with 13 cases, 6 of which fail on `main`. `pytest tests/metrics` gives 104 passed (91 on `main`). I also compared old and new results on 58 pairs, called directly and through `Accuracy(numeric=True)` and `MathAcc`, and only the cases described above changed. `test_ci_lite` and `pre-commit` pass.
