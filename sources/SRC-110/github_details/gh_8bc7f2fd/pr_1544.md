## 正文

Closes #1538

Rewrites the ACEBench adapter to follow the official protocol, and validates it
against the upstream repository rather than against our own reading of it.

## Why

The previous implementation approximated ACEBench: hand-written English system
prompts, a lenient call parser, and no rollout at all for the `agent`
categories (it asked the model to emit a final-state JSON blob and graded
that). Reported numbers were not comparable to the official leaderboard.

#1538 is one visible symptom: `score_milestones` returned `1.0` when
milestones existed but failed to parse, so an unscorable sample looked
identical to a perfect one.

## What changed

**Official protocol.** Prompts, output contract, decoding and scoring now
follow upstream. An answer that cannot be decoded scores zero instead of being
rescued by lenient parsing. `normal_multi_turn_*` is scored per dialogue (every
step must be correct). `agent` categories run a real rollout against the
simulated phone / food-delivery / travel APIs and are graded on the resulting
environment state.

**Milestone scoring (#1538).** `milestone_accuracy` compares milestones as raw
strings and always divides by the declared milestone count, so a milestone that
cannot be matched lowers the score instead of disappearing from the
denominator:

```python
milestone_accuracy([], [{'unexpected_schema': 'value'}])   # 1.0 -> 0.0
milestone_accuracy([], ['not a call'])                     # 1.0 -> 0.0
milestone_accuracy([], [])                                 # 1.0 (case (A), left as-is per the issue)
```

**Report.** Adds the official groupings (ATOM, SINGLE_TURN, MULTI_TURN, NORMAL,
SPECIAL, AGENT) and an OVERALL weighted `normal` 0.578 / `special` 0.2676 /
`agent` 0.1545, matching `model_eval/evaluation_helper.py`.

**Safety.** Upstream `eval()`s both reconstructed call strings and argument AST
nodes. Here calls are dispatched with `getattr(instance, name)(**kwargs)` and
arguments resolved with `ast.literal_eval`, so model output is never executed
as code (`test_model_output_is_never_executed` guards this). API instances are
per-rollout instead of module globals, which makes concurrent evaluation safe.

**Vendored code.** The simulated API classes live in
`evalscope/third_party/acebench/{en,zh}/`, byte-identical to upstream, with the
MIT notice reproduced in `evalscope/third_party/acebench/LICENSE`. ACEBench is
not published as a package and the agent categories are graded on the state
these classes reach, so they have to run as-is.

**Observability.** The rollout emits an `AgentTrace` and keeps the model's own
assistant messages, so agent samples render in the dashboard like
AgentLoop-driven benchmarks and `PerfCollector` picks up per-turn latency and
tokens.

## Validation

The scoring logic and the simulated APIs are ports, so the guarantee is a
differential run against the real thing. Point `ACEBENCH_REPO` at a checkout to
enable it:

```bash
ACEBENCH_REPO=/path/to/ACEBench pytest tests/benchmark/test_acebench.py -q
# 62 passed, 0 skipped
```

- `test_checker_matches_upstream[en|zh]` — every verdict on 1000+ perturbations
  per language agrees with upstream `normal_checker`, quirks included
- `test_simulated_apis_match_upstream` — end state matches upstream
  `execute_agent_func_call` field by field
- 22 prompt constants compared verbatim against upstream
- loop structure, execution labels, dispatch semantics, milestone recording and
  policy concatenation checked line by line against `apimodel_inference.py`

Without `ACEBENCH_REPO` those three skip and the remaining 59 run offline (no
network, no live model).

Also run: `make lint`, `pytest tests/cli/test_all.py::TestRun::test_ci_lite`,
and an end-to-end evaluation over all three families with a live model,
including both agent rollout paths and a `use_cache` + `rerun_review` replay.

## Behaviour changes to note in the changelog

- `end_state_acc` is gone from `metric_list`; decoding is stricter. ACEBench
  numbers from before this change are **not comparable**.
- `agent_multi_turn` needs a user simulator (`extra_params.user_model`, the
  official runner uses `gpt-4o`). Without one those rollouts fail and score
  zero, which drags the AGENT group down — configure it before reading OVERALL.
- `extra_params.is_fc_model` was removed. It attached tool schemas while the
  system prompt still demanded a textual `[ApiName(...)]` list, so a compliant
  model scored zero, and the `special`/`agent` paths ignored it entirely.

## Known deviations from upstream

Both are deliberate and documented at the call site:

- **Unknown API.** Upstream leaves `func_call_result` bound from the previous
  iteration and silently reuses the previous observation (or raises `NameError`
  on the first call). We report `Error during execution: name '<api>' is not
  defined` instead. Only reachable when the model calls a non-existent API.
- **`eval()`-only AST nodes.** `BinOp` / `Lambda` / `Subscript` arguments are
  resolved with `literal_eval` and fall back to source text. No ACEBench sample
  carries such an argument.

`agent_multi_step` deliberately keeps upstream's transcript behaviour: only
`user` and `execution` lines are folded in, so the agent never sees its own
previous messages (`get_inference_message` is called solely in the agent branch
of `multi_step_inference`). A model that needs that history will repeat one call
until the step budget runs out. That costs real accuracy but is what the
official numbers measure, so widening it would inflate scores above the
leaderboard. `test_multi_step_transcript_hides_the_agents_own_turns` locks it.

## Out of scope

The dashboard's model-level summary sums `Metric.num` across all subsets,
including the derived groups appended by `_on_generate_report_end`, so a
29-sample run displays `Num=98`. `bfcl_v3`, `bfcl_v4`, `poly_math`,
`needle_haystack`, `gdpval`, `ocr_bench_v2` and `general_arena` use the same
pattern and are affected identically. Worth a separate issue at the framework
level rather than a per-benchmark workaround.
