### Suppressed comments (4)

**evalscope/agent/external/dockerfiles/Dockerfile.deepseek-harness:9**
* The DSH npm package is version-pinned, but `node:22-slim` is a mutable tag. Rebuilding the image tagged `0.1.5-rc.2` can therefore silently change the OS/Node base and make Docker E2E and production runs non-reproducible; pin this `FROM` to a reviewed digest (or explicitly document that only the npm package is pinned).
```
FROM node:22-slim
```
**evalscope/agent/external/runners/deepseek_harness.py:105**
* With the default `home_override=None`, `install_task_skills` rewrites its standard `$HOME/.agents/skills` destination using `home_dir`, but this runner only exports `DSH_HOME` and leaves `HOME` inherited. DSH therefore scans the inherited `$HOME/.agents/skills`, not `<DSH_HOME>/.agents/skills`, so task/configured skills copied by this runner are invisible (and the prompt's `$HOME` path points elsewhere). Export `HOME=home_dir` (or consistently set `DSH_AGENTS_HOME`) whenever `home_dir` is non-`None`, and update the exact environment assertion in the new runner test.
```
        if home_dir is not None:
            env_vars['DSH_HOME'] = home_dir
```
**evalscope/agent/external/runners/deepseek_harness.py:80**
* `ensure_node_via_apt` only checks that `node` and `npm` exist; it does not verify their versions. The pinned `@deepseek-ai/dsh@0.1.5-rc.2` declares Node `^22.19.0 || >=24.0.0`, so an environment with Node 18/20 will skip the NodeSource 22 setup and install/run DSH on an unsupported runtime even with `auto_install=True`. Validate the Node version before accepting it (and cover the incompatible-version path) rather than treating presence alone as sufficient.
```
        await ensure_node_via_apt(
            env,
            node_setup_url=self._node_setup_url,
            timeout_s=self._install_timeout_s,
            runner_name='DeepSeekHarnessRunner',
        )
```
**evalscope/agent/external/runners/deepseek_harness.py:118**
* `dsh --profile headless` parses the task with Commander, so a task beginning with `-` (for example `--help`) is treated as a CLI option rather than the user instruction and the process exits before evaluating it. Terminate option parsing before appending the arbitrary task text (and add a leading-dash regression test).
```
            cmd.append(task.instruction)
```
