# [PR #1410] fix(cache): use persistent jsonl writer to avoid Windows PermissionError

## 正文

## Summary

- **Replace per-record `dump_jsonl_data` (open-write-close) with a persistent `jsonlines.Writer` per file**, fixing Windows `PermissionError` caused by NTFS file-lock release latency during rapid open/close cycles.
- Each writer is flushed (`_flush` + `fsync`) after every write so crash recovery is preserved.
- All open handles are released in `Evaluator.finalize()` via `CacheManager.close()`.

**Root cause:** `evaluator._run_pool` persists each sample result from the main thread as worker futures complete. Under high concurrency (many workers finishing back-to-back), `dump_jsonl_data` opens and closes the same `.jsonl` file dozens of times per second — on Windows, NTFS lock release latency triggers `[Errno 13] Permission denied`. The retry-based fix in #1405 has structural bugs (outer `with` holds the lock while the retry loop tries to re-open the same file).
