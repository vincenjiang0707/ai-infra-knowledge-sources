# [PR #1705] refactor(metrics): give metric semantics one source per decision

## 正文

## Why

`evalscope/metrics/semantics` expressed three decisions twice, and the copies disagreed.

The sharpest consequence, reproduced before the fix:

```
# v1 report: {'dataset_name': 'job_bench', 'metrics': [{'name': 'total_score', ...}]}
v1 path  -> judge_score:identity  quality.judge_score.unbounded  QUALITY   | primary = judge_score
v2 path  -> diagnostic.unspecified                              DIAGNOSTIC | source = BENCHMARK_OVERRIDE
```

`BENCHMARK_METRIC_OVERRIDES` marks `job_bench`'s `judge_score` as a diagnostic because it is the raw sum of passed rubric weights, not a comparable score. The v1 read path consulted the read-old manifest *before* that override, so an archived report promoted exactly the value the override exists to reject — and made it the report's headline.

## What changed

**One source per decision**

| Decision | Before | After |
| --- | --- | --- |
| Resolution priority | `SemanticsResolver.resolve` and `hydrate_report_semantics`, in different orders | `resolve()` only; reading old differs by one optional `legacy_name` argument |
| Primary metric selection | `select_primary_identity` + two layers of `try/except` in the v1 reader; collection reports skipped it | `select_primary` serves all three producers, never raises, reports authoring ambiguity via `authoring_error` |
| Alias knowledge | five separate declarations | `METRIC_ALIASES`, with `AliasScope` encoding each rewrite's obligation |

The alias scopes are deliberately different sets: a `metric_list` rewrite must keep `get_metric()` resolving, which is the constraint the `bertscore` / `bert_score` mismatch broke; a read-old rewrite may reassign an ambiguous name, which a producer rewrite must never do.

**Correctness fixes**

- `Report.score` no longer falls back to `metrics[0]`, which could present a diagnostic such as `no_answer_num` as the run's score. The frontend already read the primary metric strictly (`primaryMetricOf` never guesses), so this aligns the backend with it — no frontend change needed.
- `olmocr_bench` emitted `aggregation='unit_test_pass_rate'`, undeclared in `KNOWN_AGGREGATIONS`, which was already failing the registry alignment gate on main. Its pooled pass rate is a mean weighted by each page's unit-test count (`sum(passed)/sum(total)`), so it is `weighted_mean`; scores are unchanged.
- A stale gdpval test asserted a metadata key (`judge_strategy_note`) that no longer exists and reached `calculate_metrics` through a configuration `validate_judge_strategy` rejects. It now asserts the grading contract the adapter implements.

**Redundancy removed**

- 68 of 189 read-old catalog entries repeated their `METRIC_DEFINITIONS` declaration verbatim, so a display change had to be made in two places. Removed, with a test forbidding re-addition.
- `identity.py` split into `naming.py` (producer path, never infers) and `legacy_identity.py` (read-old path, deliberately infers) — opposite policies that were mixed in one module.

Net `+1224 / -624` across 28 files; three new concepts (`AliasScope`, `Stage`, `PrimarySelection`), each with an existing caller.

## Behaviour changes

Both are corrections, each locked by a test:

1. A v1 `job_bench` report's `total_score` now reads as a diagnostic and no longer becomes the primary metric.
2. `Acc` migrates to `accuracy` instead of the undeclared `acc`. The producer path already did this; the read path did not, because it consulted the alias table only before snake-casing.

## Breaking surface (internal Python API only)

| Removed / renamed | Replacement |
| --- | --- |
| `metrics.semantics.identity` | `metrics.semantics.naming` / `metrics.semantics.legacy_identity` |
| `metrics.semantics.legacy` | `metrics.semantics.aliases` |
| `resolver.select_primary_identity` | `primary.select_primary` |
| `is_known_dynamic_legacy_name` | `is_known_legacy_spelling` |

No `report.json` field changes, so no `contracts:generate` regeneration and no golden-sample edits.

## New gates

- v1/v2 semantic equivalence: every canonical name must mean the same thing however the report was written; the only permitted divergence (`error_rate`) is pinned by name.
- Per-rule `examples` replace a hand-maintained list of benchmark names, so a new legacy rule without pinned cases fails.
- AST scan replaces a regex that could not see an aggregation passed through a variable, plus a new check that a benchmark forwarding `BenchmarkMeta.aggregation` into an `AggScore` declares a known name.

## Known debt, unchanged and recorded

- `api` → `metrics.semantics` reverse dependency (contract layer depending on the data layer) is untouched; a layering gate cannot be added until it is fixed. `meta.py` keeps exactly one import edge, as before.
- Catalog tables remain mutable `Dict`; no production code mutates them.
- `LEGACY_METRIC_MIGRATIONS` could later move to its own module; deferred until `catalog.py` outgrows its current size.

This PR refactors metric semantics so each decision (resolution priority, primary metric selection, and aliasing) has a single authoritative implementation, ensuring v1 (read-old) and v2 (fresh) report reads cannot disagree on what a metric means or which metric is primary.

**Changes:**
- Centralized semantics resolution ordering into `SemanticsResolver.resolve(..., legacy_name=...)` and added explicit source reporting for each resolution step.
- Replaced exception-based primary-metric selection with a non-raising `select_primary()` returning a structured `PrimarySelection`, reused across fresh, collection, and v1-migrated reports.
- Consolidated legacy/producer/metric_list alias handling into `METRIC_ALIASES` with explicit `AliasScope` obligations, plus new tests/gates preventing drift.
