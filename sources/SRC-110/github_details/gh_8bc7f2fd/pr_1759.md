## 正文

## Summary
- add `--max-turn-tokens` for per-turn output limits in multi-turn performance benchmarks
- reuse the final configured value when a conversation has more turns than values
- preserve trace-provided per-turn limits unless the CLI schedule explicitly overrides them
- set protocol-native fields for OpenAI Chat, OpenAI Responses, and DashScope
- document and test that `custom_multi_turn` preserves a system message supplied in JSONL

## Root cause
`--max-tokens` is global, so multi-turn agent simulations cannot model short intermediate tool-call outputs and a longer final answer. The existing trace override also writes a top-level `max_tokens` field directly, which is not correct for protocols such as OpenAI Responses or DashScope.

## Changes
- validate scalar and list forms of `max_turn_tokens`
- select the effective limit in `MultiTurnStrategy`, with CLI values taking precedence over trace values
- add a protocol hook for setting the request's output limit without changing every plugin's `build_request` signature
- add regression coverage for parsing, validation, precedence, last-value reuse, protocol fields, and system-message preservation
- update the English and Chinese stress-test documentation

## Scope
This PR intentionally does not add a CLI option for overriding the system prompt. Custom system prompts remain supported through the leading `system` message in `custom_multi_turn` JSONL input.
