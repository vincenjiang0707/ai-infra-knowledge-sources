## 正文

## Summary

Unifies LLM-judge scoring on a single JSON output contract, replacing hand-rolled, unanchored judge-response parsing (`re.search`, `'yes' in resp`, etc.) that caused false-positive verdicts and silent metric corruption across benchmark adapters.

Adapters now declare judge **cases** and a Pydantic **verdict schema**; they never call the judge model and never parse a reply. `JudgeExecutor` owns retries, position swap, aggregation and fail-closed exclusion — a reply that fails the contract **excludes the sample from the metric**, never scores 0 or full credit.

## Key changes

- **New subsystem** `evalscope/api/judge/` (contracts, executor, types); scoring routed through `LLMJudgeMixin.score_with_judge_contracts`.
- **Default binary-correctness path** in `LLMJudgeMixin` (`judge_prompt` hook + `_CorrectnessVerdict` contract): single-verdict benchmarks migrate by setting only `uses_judge_contracts = True`. Migrated `baby_vision`, `world_vqa`, `zerobench`, `minerva_math`, `imo_answerbench`, `math_verse` onto it with zero duplicated hooks.
- **phyx (MC/OE)** migrated to the contract; deleted the `parse_judge_verdict` / `_VERDICT_RE` parser.
- **Gate cleared**: `PENDING_MIGRATION` is now empty. `job_bench` / `wide_search` remain `PERMANENTLY_EXEMPT` (judge used as a JSON data transformer producing scorecards/tables, not a single verdict).
- **Docs**: added `## Key Features` to `researchrubrics` and `air_bench_chat`, regenerated their `_meta` + en/zh pages; documented the judge-contract authoring flow in `AGENTS.md`.
- **Tests**: structural gate, contract, executor, and per-adapter migration tests.

## Validation

- `make lint` passes; `tests/api/judge` + affected benchmark suites (235 tests) pass; `test_ci_lite` passes.
- Real-API end-to-end (qwen-plus): `simple_qa`, `researchrubrics` (full agent + rubric judge + chunk/synthesis), `minerva_math`, `imo_answerbench` — judge naturally emits the JSON verdict; parse failures / transport errors exclude rather than mis-score.
