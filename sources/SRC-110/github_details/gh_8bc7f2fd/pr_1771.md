## 正文

Fixes #1770

Since #1601, AlpacaEval counts a win as 0.75 and a loss as 0.25. The reported win rate is therefore 0.25 + 0.5 * p, where p is the true win rate. For example, 8 wins out of 10 show up as 0.65.

The reduce step builds PairwisePlacementOutcome and PairwiseOutcome without a strength value, so both use the default "weak". Arena-Hard and GeneralArena read the strength from labels such as A>>B and A>B. The AlpacaEval judge only answers m or M, so it has no slight preference to express.

What I changed:

1. The reduce step in alpaca_eval_adapter.py now marks every outcome as strong. A win scores 1 and a loss scores 0. A split verdict under position swap still scores 0.5.
2. The AlpacaEval evaluation_version goes from v1.0 to v1.1. AGENTS.md asks for a minor bump when a change affects the default scores, and the bump keeps old cached scores apart from new ones.
3. The position swap test now expects 1.0 when the candidate wins both placements. It expected 0.75 before, and that value was the bug.
4. A new test covers the default single pass. A win gives 1.0 and a loss gives 0.0.

I did not change PairwiseOutcome.score. The weak and strong scale is right for Arena-Hard and GeneralArena, so the fix belongs in the AlpacaEval adapter. It also matches the code before #1601, where the adapter returned 1 for M and 0 otherwise.

- pytest tests/api/test_benchmark_registry_contract.py: 27 passed.
