# [PR #1749] refactor(benchmarks): load adapters on demand instead of importing all 238 at package import

source: https://github.com/modelscope/evalscope/pull/1749
state: closed | updated: 2026-09-18T03:30:54Z
labels: 

## 正文

## Problem

`import evalscope` executed **every one of the 238 `*_adapter.py` modules**. Because Python always runs a parent package's `__init__` first, *any* import paid the full cost:

| | before |
|---|---|
| `evalscope --help` (prints 542 bytes) | **16.3 s** |
| `import evalscope.api.registry` (just wants a registry) | **~10 s** |
| modules loaded by `import evalscope` | **3885** |

Adapter module bodies transitively pull `datasets` (4.4 s), `nltk`/`rouge_score` (3.7 s), `openai` (3.4 s) and `pandas`. Every CLI subcommand, the web service, every library-style import and every pytest process paid it. This also contradicted the codebase's own practice — `default_data_adapter.py` and `config.py` already defer imports specifically to keep module load cheap.

## Change

Split **discovery** (which benchmarks exist) from **loading** (executing the adapter module). `evalscope/benchmarks/_index.json` maps benchmark name → adapter module; a new `LazyRegistry` resolves a name by importing only that module.

| | before | after |
|---|---|---|
| `evalscope --help` | 16.3 s | **4.2 s** |
| modules after `import evalscope` | 3885 | **1664** |
| resolving one benchmark | — | 0.06 s, +28 modules |

## Behaviour is preserved, not traded away

- **Batch consumers still see the whole catalog.** `keys()` / `values()` / `items()` / iteration / `len()` load everything — that's what `evalscope benchmark-info --list`, the docs pipeline and several tests rely on. `--list` output is **byte-identical** to before (261 lines).
- **A stale index costs time, not correctness.** A name the index doesn't know falls back to a full load and still resolves. There's a test for exactly this.
- **Registration never triggers resolution.** `register_benchmark` uses a write-path membership check, so importing a custom adapter module directly does not drag in the catalog.
- **Unknown names raise the same `ValueError`**, including the `Did you mean:` suggestions.

## `_index.json` is generated, never hand-edited

`evalscope benchmark-info --update-index` writes it, and `make docs-update` / `docs-update-stats` / `docs-pipeline` now run that step. `tests/api/test_benchmark_registry_contract.py` fails if the committed copy drifts from the registry.

**Scope of that guard:** it is a local/pytest check. CI runs a fixed set of test node IDs (`test_ci_lite`, `test_benchmarks`, the perf sweep, and two frontend files) and does not collect `tests/api/`, so a drifted index will not turn CI red. That is deliberate here: because an unindexed name falls back to a full load, a stale index degrades startup time and never changes results.

Why an index at all instead of deriving the name from the path: **44 of 257 names don't match their module leaf** (`aime24`/`aime25`/`aime26` ← `aime.aime_adapter`, `gpqa_diamond` ← `gpqa.gpqa_adapter`, `chinese_simpleqa` ← `chinese_simple_qa.csimple_qa_adapter`) and **11 modules register several names**. A naming convention cannot express that, so the mapping is read from the registry.

## Adjacent defects this surfaced

- `from evalscope.benchmarks import *` published `os`, `glob`, `time`, `importlib` and loop temporaries (`file_path`, `start_time`, …) as public `evalscope` attributes — `evalscope.os` really was the stdlib `os` module — plus a 238-entry `import_times` list nothing ever read.
- `from evalscope.evaluator import *` **rebound `evalscope.evaluator`** to the inner `evalscope.evaluator.evaluator` module, so `evalscope.evaluator.batch_reviewer` / `.execution_tracker` / `.perf_collector` raised `AttributeError`. Now an explicit import; the four public classes stay exported.
- `metrics/nlp/bert_score/utils.py` imported the **root package** for `__version__`, which only worked because a sibling deferred its import. A probe confirms the module-level form raises `ImportError: cannot import name '__version__' from partially initialized module`.
- `utils/data_utils.py` depended on api + metrics + report from inside the leaf `utils` package → moved to `report/data_frames.py`. Two function-local imports of it were redundant (the same module was already imported at module scope in the same file) and one only guarded a cycle that ran through `evalscope.utils`, which the move removes.

## `.importlinter`

Records the resulting import directions. **`core layers must not import benchmark adapters` passes with zero exemptions** — that is the check that detects eager loading creeping back. The other four contracts carry an explicit, reviewable list of the dependencies that exist today; they are a debt inventory, not an excuse list. Type-checking-only imports are excluded, because most of this package's apparent cycles are type-only and treating them as real produces false positives.

**Not wired into CI.** `lint.yml` runs only `pre-commit`, and the pre-commit config has no import-linter hook, so this is a local check via `make lint-imports`. It documents and detects direction regressions for whoever runs it; it does not block a merge. Wiring it into `lint.yml` was considered and deliberately left out of this PR.
