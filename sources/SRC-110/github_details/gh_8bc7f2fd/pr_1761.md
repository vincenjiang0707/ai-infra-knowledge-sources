# [PR #1761] fix(ifbench): guard StopWordPercentageChecker against word-less responses

## 正文

### Problem

`StopWordPercentageChecker.check_following` (instruction `ratio:stop_words`) divides by the word count without guarding it:

```python
num_words = instructions_util.count_words(value)
num_stopwords = instructions_util.count_stopwords(value)
stopword_percentage = (num_stopwords / num_words) * 100
```

`count_words` uses a `\w+` tokenizer, so any response that contains **no word tokens** — only punctuation, symbols, emoji or whitespace (`"..."`, `"---"`, `"***"`, `"😀"`) — makes `num_words == 0` and raises `ZeroDivisionError`.

This is reachable on real, default runs:

- In both `test_instruction_following_strict` and `test_instruction_following_loose`, the response is only guarded by `response.strip()`. A non-empty but word-less response (e.g. a model that emits only punctuation/emoji) passes that guard and hits the division.
- The loose path additionally evaluates markdown-stripped (`response.replace('*', '')`) and first/last-line-removed variants, so even a normally-formatted response can reduce to a word-less variant and trigger the crash.
- The exception is swallowed in `IFBenchAdapter.match_score`, which sets `score.value = {}`. That discards the results of **every other instruction on that prompt**, not just this checker, and corrupts the aggregate metric.

### Reproduction

```python
from evalscope.benchmarks.ifbench import instructions

c = instructions.StopWordPercentageChecker('ratio:stop_words')
c.build_description(percentage=50)
c.check_following('...')   # ZeroDivisionError: division by zero
c.check_following('😀😀')  # ZeroDivisionError: division by zero
```

### Fix

Restore the guard that upstream [IFBench](https://github.com/allenai/IFBench) has and that evalscope dropped — return `False` when there are no words:

```python
num_words = instructions_util.count_words(value)
if num_words == 0:
    return False
```

This matches upstream verifier behavior exactly and keeps the scoring for the rest of the prompt intact.

### Verification

- Added parametrized regression tests for punctuation/symbol/emoji/whitespace-only responses, plus a normal-response case. Confirmed they raise `ZeroDivisionError` before the fix and pass after it.
- `pytest tests/benchmark/test_ifbench_instructions.py` — 28 passed.
- `ruff check` and `ruff format --check` clean on the changed files.

Not bumping `evaluation_version`: no previously *valid* score changes — word-less responses always errored out (never produced a score), so this only replaces a crash with the upstream-defined `False`, consistent with #1756 which aligned verifiers without a bump.
