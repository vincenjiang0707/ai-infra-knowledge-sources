## 正文

## Problem

`HallusionBenchAdapter.aggregate_scores` computes figure-level (`fAcc`) and question-pair (`qAcc`) accuracy differently from the official HallusionBench evaluation, corrupting both metrics on the default `HallusionBench` dataset.

**1. The grouping key drops `category`.** The current key is:

```python
key = f'{subcategory}_{set_id}_{group_id}'   # group_id = figure_id or question_id
```

HallusionBench has two categories, `VD` and `VS`, and they **reuse the same** `subcategory` / `set_id` / `figure_id` / `question_id` numbering. Omitting `category` merges distinct figures/questions from different categories into a single group. On the official data (1129 records) this collapses **27 figure keys** and **26 question keys** across `VD`/`VS` (e.g. `ocr_0_0` and `chart_0_1` exist under both categories).

**2. `fAcc` counts VS "no-figure" records.** VS entries with `figure_id == 0` are text-only (no supplementary figure). The official eval excludes them from figure-level accuracy. The default data contains **178** such records, all currently counted as spurious figure groups.

## Reference

Both behaviours come straight from the official implementation — [`tianyi-lab/HallusionBench` `utils.py`](https://github.com/tianyi-lab/HallusionBench/blob/main/utils.py):

- `get_eval_fig` (fAcc): key = `"_".join([category, subcategory, set_id, figure_id])`, and it skips records where `category == "VS" and figure_id == "0"`.
- `get_eval_pair_all` (qAcc): key = `"_".join([category, subcategory, set_id, question_id])`.

## Fix

Include `category` in the grouping key, and skip VS `figure_id == 0` records for figure-level accuracy. Question- and answer-level accuracy still see every record.

## Verification

Added `tests/benchmark/test_hallusion_bench.py`, which fails before this change and passes after:

- `test_grouping_key_separates_categories`: two rows sharing `chart_0_1` under `VD` vs `VS` (both `figure_id == 1`, isolating the category effect). Before: one merged group → `fAcc`/`qAcc = 0.0`. After: two groups, one correct → `0.5`.
- `test_figure_accuracy_skips_vs_no_figure_records`: a VS `figure_id == 0` record is dropped from `fAcc` but still counts toward `aAcc`/`qAcc`.

Local run: `tests/benchmark/test_hallusion_bench.py` + `tests/metrics` + `tests/report/semantics/test_complex_aggregations.py` → 97 passed. `ruff check` / `ruff format --check` clean on the changed adapter.
