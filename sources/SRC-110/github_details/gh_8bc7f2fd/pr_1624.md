## 正文

## Summary

Fixes #1619 and hardens the `TaskConfig` layer. Previously a misspelled or
hyphenated config key (e.g. `eval-batch-size` instead of `eval_batch_size`)
was silently dropped by Pydantic's default `extra='ignore'`, leaving the
value at its default with no feedback — the user in #1619 only noticed
because vLLM kept `running=1`.

## What changed

### Unknown-key rejection (#1619 root cause)
- `BaseArgument` now uses `extra='forbid'`. `from_dict` raises with a
  top-level **"did you mean"** suggestion (e.g. `'eval-batch-size' ->
  'eval_batch_size'`) while leaving nested Pydantic errors — which already
  report the full path — untouched.
- Verified against 24 real historical output snapshots: **zero net new
  failures** (the existing `judge_worker_num` removal error already covered
  the same input class).

### eval_batch_size default
- Defaults to **8** for remote API eval types (`openai_api`,
  `openai_responses_api`, `anthropic_api`, `litellm`); local/checkpoint stays
  `1`. CLI `--eval-batch-size` default is `None` so the dynamic default can
  apply, and an explicit value always wins.

### eval_type alias normalization
- Deprecated aliases are normalized at input (`checkpoint` -> `llm_ckpt`,
  `server` -> `openai_api`). This fixes two latent bugs: `checkpoint` was
  missing its default `model_args`, and `server` was missing the concurrent
  default — both because downstream `eval_type ==` checks compared against the
  canonical value only.
- Removes the unused `EvalType.SERVICE` constant; aligns the
  `server`/`checkpoint` model-API deprecation removal to `v2.0.0`.

### Internal cleanup (behavior-preserving)
- Deprecation handling is split by whether it needs the coerced field value:
  a `mode='before'` validator `_migrate_deprecated_input` does **pure key
  renames** (judge keys, eval_type alias) on the raw input, while
  `_apply_typed_config_deprecations` and `_init_default_sandbox_config` run
  **after validation** for anything that must read a coerced value
  (timeout/stream/n forwarding, sandbox legacy-field folding). Keeping the
  sandbox fold in the after-validator lets it read the already-coerced
  `use_sandbox` bool instead of re-implementing Pydantic's coercion.
- Unifies the two divergent serialization paths (`to_dict` for YAML,
  `_to_update_dict` for merge) into a single `_serialize(purpose)` core.
  `agent_config` is now set-only on both paths, so snapshots no longer pin
  default values (was full-dumped by `to_dict` before).

## Compatibility note

`extra='forbid'` is stricter than before. Snapshot round-trip and 24 real
historical configs were checked and behave identically; deprecated keys still
migrate. Any config carrying a truly unknown key will now error instead of
silently ignoring it — this is the intended fix.

## Testing
- New `tests/api/test_task_config_validation.py` (34 cases): unknown-key
  rejection + suggestion, nested-key attribution, alias normalization,
  remote-API default, sandbox legacy folding (incl. falsy string coercion),
  serialization round-trip, and `update()` merge semantics.
- `tests/api`: 274 passed (4 unrelated pre-existing failures).
