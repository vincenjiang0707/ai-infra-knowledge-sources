# [PR #1763] fix(perf): include response body time in embedding and rerank latency

source: https://github.com/modelscope/evalscope/pull/1763
state: open | updated: 2026-09-22T06:52:59Z
labels: 

## 正文

Embedding and rerank benchmarks currently stop their timers as soon as HTTP response headers arrive. Reading the JSON or text body happens afterward, so response transfer time is omitted from request latency and the metrics wall-time window. This can understate latency and inflate QPS, especially for large embedding responses.

Move the existing completion timestamp and latency assignments after the response body has been consumed, for both successful and HTTP error responses. Body-read exceptions still follow the existing failure handling: the plugin marks the request failed, and `AioHttpClient.post` fills in an incomplete failure timestamp. This change does not introduce a new exception-timing policy.

Validation uses a local aiohttp HTTP server that flushes headers, delays the body, and records when the body is sent. All eight cases fail on the unmodified base because the recorded completion time precedes the body; they pass after the fix. The cases cover embedding/rerank, HTTP 200/500, JSON/text fallback, and the metrics accumulator's wall-time window.

Validation:
- Targeted latency and adjacent metrics regression tests: 61 passed on Python 3.12.13 and Python 3.13.13.
- `make lint`: passed, including the new test.
- CI lite smoke: 1 passed with the mock model; the API-key-gated perf sweep was skipped.
- `make lint-imports`: 5 contracts kept, 0 broken.

No external embedding/rerank model service was used.
