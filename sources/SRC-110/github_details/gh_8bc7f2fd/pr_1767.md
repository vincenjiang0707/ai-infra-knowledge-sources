## 正文

## Summary

Multi-turn perf benchmarks (`--multi-turn`) currently have no way to set per-turn `max_tokens` from the CLI. The global `--max-tokens` applies uniformly to every turn, but real-world agent workloads often need different output caps per turn (e.g. 150 tokens for tool-call turns, 1000 for the final answer).

This PR adds `--multi-turn-per-turn-tokens` to fill that gap.

## Changes

- `Arguments.multi_turn_per_turn_tokens`: `List[Optional[int]]` field with JSON validator
- CLI `--multi-turn-per-turn-tokens "[150, 150, 1000]"` argument
- `MultiTurnStrategy._worker`: applies CLI override by turn index (highest priority), falling back to `Turn.max_tokens` (trace replay) then global `--max-tokens`
- 6 new unit tests covering parsing, validation, and fallback behavior

## Usage

```bash
evalscope perf \
  --model qwen-plus \
  --api openai \
  --dataset random_multi_turn \
  --multi-turn \
  --max-turns 10 \
  --multi-turn-per-turn-tokens "[150, 150, 150, 150, 150, 150, 150, 150, 150, 1000]"
```
