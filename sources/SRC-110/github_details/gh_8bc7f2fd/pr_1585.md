# [PR #1585] fix(agent): make AgentLoop own the nudge count and give models an honest reminder

source: https://github.com/modelscope/evalscope/pull/1585
state: closed | updated: 2026-09-10T07:43:23Z

## 正文

Follow-up to #1581 (merged). That PR fixed the one broken marker string in
`swe_bench_toolcall`; this one removes the mechanism that produced the bug, fixes
the same latent defect in `swe_bench_backticks`, and then removes two further
instances of the same pattern found along the way. Thanks @Roovelrz for the
diagnosis and the first fix.

## The pattern, not the instance

The original bug was one instance of *deriving state that another party owns*.
Strategies answered "how many nudges have I injected?" by substring-matching a
reminder in `ctx.messages`, while `AgentLoop` is the only party that injects it.
Any drift between the assumed marker and the injected text silently yields `0`,
which reads as "never nudged" and lets a stuck model nudge on **every** no-tool
turn up to `max_steps` (250 for SWE-bench). The failure mode of the counting
mechanism was exactly the bug it existed to prevent, and it failed silently.

Two of four strategies were broken this way: `swe_bench_toolcall` matched a
string the loop never writes (fixed in #1581); `swe_bench_backticks` matched a
`ParsedAction.error` the loop only records in the trace. `function_calling` /
`react` worked only by luck — their marker is a prefix of `NUDGE_PROMPT`.

## Changes

**1. Authoritative nudge count.** `AgentContext.nudge_count` is owned by
`AgentLoop`, read by a single default `should_nudge`. All four strategies drop
their hand-rolled implementations. Reading a typed field fails loud on
regression instead of silently degrading.

**2. Consecutive, not per-episode.** The counters reset on every tool-calling
turn, so a budget bounds a *consecutive* streak. Without this a single stray
text-only turn late in a long task ends the run early.

**3. Honest reminder text.** `AgentStrategy.nudge_message` returns
`parsed.error` when present, else a strategy-appropriate prompt. The generic
"call the submit tool" misleads for `swe_bench_*` (completion is a bash
sentinel) and for BrowserGym/MiniWoB (`include_submit_tool=False`).

**4. Explicit turn outcome.** `if not parsed.tool_calls` branched on a *symptom*
shared by two unrelated states: a malformed turn that tried to act, and an idle
turn that only produced text. `ParsedAction.outcome` (`TurnOutcome.ACT /
MALFORMED / IDLE`) names them and defines the precedence in one place.

**5. Separate budgets.** A malformed turn is told the exact rule it broke, so it
is strictly more recoverable than a model replying in prose — yet it used to get
the same or fewer retries. `max_parse_error_nudges = 3` /
`ctx.parse_error_nudge_count` are now independent of `max_nudges = 2` /
`ctx.nudge_count`; an ACT turn resets both.

**6. Distinct terminal source.** An exhausted malformed streak was reported as
`implicit_no_nudge` ("the model stopped calling tools") when the model was in
fact calling tools and only breaking the protocol. New
`SubmissionSources.PARSE_ERROR_EXHAUSTED`, and the SUBMIT payload now carries
`outcome` / `error` / `raw_text_preview` instead of a `final_answer` the loop
does not own.

**7. Two score-losing fixes found while validating.** A live SWE-bench run
surfaced these:
- `swe_bench_backticks.extract_final_answer` returned the *nudge reminder text*
  as the patch when a run ended on a nudge (nudges are `ChatMessageUser` too).
  Nudges are now identified from the trace's NUDGE events.
- Both SWE-bench adapters recovered a diff via
  `str(msg.content or '') or msg.text`. For any reasoning model `content` is a
  `list[Content]` whose `str()` is a non-empty Python repr, so `msg.text` was
  dead code and `extract_diff` passed the repr through to the grader — `git
  apply` then fails. Fixed at all four sites that stringified message content.

**8. Trace view surfaces it.** `NudgeRow` shows an idle/malformed badge and the
submit pill shows its source, so a reminder is attributable without reading
JSONL. Three i18n keys added earlier were dead — `trace.loopMessage.*` is only
consulted for `error`-type events — and are replaced by keys the renderers
actually ask for. `keyCoverage.test.ts` gains the reverse check that would have
caught them.

## Behavior changes

- `swe_bench_backticks`: unbounded nudge → at most 2 consecutive.
- `swe_bench_toolcall`: at most 1 **consecutive** (was 1 per episode). Its
  malformed path is unreachable — `parse_output` never sets `error`.
- Malformed retries: previously unbounded (the error text did not match the
  marker) → now 3 consecutive.
- Worst-case consecutive nudges rises from 2 to 5, when a model alternates
  malformed and idle turns and drains both budgets in one streak.
- `nudge_message` is now a **required** member of the strategy contract: the loop
  calls it unconditionally, so an implementation satisfying the Protocol
  structurally rather than by subclassing raises `AttributeError`.
- `TurnOutcome` is exported from `evalscope.api.agent`.
- No benchmark score changes: what gets submitted is untouched except where it
  was previously wrong (point 7).

## Validation

- `tests/agent` + `tests/api`: 334 passed / 8 skipped (was 308 on the base).
- Frontend: `tsc -b`, `eslint`, `drift:locale` clean; vitest 65 files / 491 tests.
- **Mutation-tested**: 17 injected defects each redden a specific guard —
  outcome precedence, collapsing the two counters, dropping either reset,
  reverting the terminal source, widening a budget, dropping the sentinel from a
  reminder, and each of the four `str(content)` sites.
- **Live E2E** (Docker + qwen3-max): `swe_bench_verified_agentic_backticks`
  (exercises the nudge path: 2 nudges then `implicit_no_nudge`), `gaia`
  (`react` + submit, 33.3%, no nudges — confirms the normal path is intact),
  `miniwob` (`function_calling` with `max_tool_calls_per_turn=1`).
- **Trace view verified in a browser** against the real SWE-bench run: both the
  nudge badges and `Submit · no tool call` render as intended.

## Rejected

`AgentTrace.final_prediction` was implemented and then reverted. The live run
showed it holding the repr of a content list where the reported prediction was
`''`: resolution is an adapter-level decision (the SWE-bench overrides layer
their own diff recovery), so the loop cannot own it, and the convergence point
exposed a separate pre-existing defect in assigning `''` to
`ModelOutput.completion` for list content. A field advertised as the single
source of truth while carrying a wrong value is worse than no field.

Refs #1577, #1581

## Pull request overview

This PR fixes unbounded “nudge” retries in the agent loop by moving nudge counting to an authoritative, loop-owned counter (`AgentContext.nudge_count`) and replacing fragile transcript substring-matching with a consistent budgeted policy across strategies. It also improves nudge content so models get accurate feedback (e.g., parse errors vs “no tool call”, and submit-free reminders when no submit tool exists).

**Changes:**
- Add loop-owned `nudge_count` with a default `AgentStrategy.should_nudge()` that enforces a per-strategy `max_nudges` budget and resets the streak on tool-calling turns.
- Introduce strategy-specific `nudge_message()` (parse-error passthrough; SWE-bench bash/sentinel guidance; no-submit variant for function_calling).
- Add regression tests covering all registered strategies’ budgets, streak reset behavior, and nudge message content.
