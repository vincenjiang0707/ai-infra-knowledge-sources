## 正文

## Problem

`OpenaiRerankPlugin.process_request` (`evalscope/perf/plugin/api/openai_rerank_api.py`, used by `evalscope perf --api openai_rerank` / `--api rerank`) summarises a successful response with

```python
score = top_result.get('relevance_score', top_result.get('score', 0))
output.generated_text = f'top_score={score:.4f}, num_results={len(results)}'
```

`dict.get()` only substitutes the default when the key is *absent*. If the server returns the key with `null` (or a stringified number) the f-string raises, and because it runs inside the same `try` whose handler sets `output.success = False`, a genuine HTTP 200 with valid results is recorded as a failed benchmark request. Reproduced against a real local `aiohttp.web` server through the unmodified module:

```
case=null_relevance_score  server answered 200 with results: True   output.success = False
                           output.error = TypeError: unsupported format string passed to NoneType.__format__
case=null_score_key        output.success = False
case=string_score          output.success = False  (ValueError: Unknown format code 'f' for object of type 'str')
case=normal                output.success = True   generated_text='top_score=0.8421, num_results=2'
```

Downstream, `benchmark_util.py` only accumulates `n_success`, latency and token samples when `data.success` is true, so such requests are dropped from the statistics and pull the success rate down (`summary.py` warns below 95 %). The plugin's own `parse_responses()` degrades gracefully on malformed payloads instead of failing the request; this cosmetic summary line is the only place where a payload detail decides success.

Reachability, honestly: the default perf path reaches this as soon as a server puts `null` or a string in the top result's score. I did not find a specific production rerank server that does so (the documented targets declare the score as a float), so this is a robustness fix for non-conforming servers rather than a reproducible failure with a known backend.

## Change

Format the score with `.4f` when it is an `int`/`float`, otherwise fall back to `str(score)` (so a `null` shows as `top_score=None` rather than being disguised as `0.0000`). Nothing else in the request path changes; 18 numeric inputs (ints, floats, bools, ±inf, nan, huge ints) produce byte-identical summaries before and after.

## Tests

`tests/perf/test_rerank_process_request.py` (`IsolatedAsyncioTestCase` + mocked session, same style as `test_perf_streaming.py`): numeric score, `score`-key fallback, `null` score, string score. On `main`: 2 failed (the `null` and string cases, `False is not true` with the `TypeError`/`ValueError` in the log); with this change: 4 passed. The other offline perf tests (`test_openai_api_parse_responses`, metrics/percentile/stream/trace, arguments, request build errors) still pass. `ruff check` / `ruff format --check` clean.
