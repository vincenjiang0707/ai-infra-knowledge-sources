## User problem

Simulating a production Agent under `evalscope perf --multi-turn` is currently impossible without hand-rolled scripts: open models don't emit the 4000-token tool-call system prompt a real deployment uses, `custom_multi_turn` reuses the dataset's own prompts, and `swe_smith` can't take a custom system prompt at all. Users lose EvalScope's RPS / P99 / TTFT / TPOT / KV-cache metrics the moment they step outside the tool.

This completes the remaining ask in #1358 (per-turn `max_tokens` landed in #1767): a CLI system-prompt override for multi-turn benchmarks.

## UX decision

`--multi-turn-system-prompt "..."` applies once per conversation (turn 0), to warmup and measured conversations alike:

- dataset's first message is `system` → its content is **replaced** (explicit user intent wins);
- otherwise → the override is **inserted first**;
- flag omitted → dataset prompts untouched.

```bash
evalscope perf \
  --model qwen-plus --api openai --dataset share_gpt_zh_multi_turn \
  --multi-turn --max-turns 10 \
  --multi-turn-system-prompt "You are a tool-calling agent. ..." \
  --multi-turn-per-turn-tokens "[150, 150, 150, 150, 150, 150, 150, 150, 150, 1000]"
```

## Changes

- `Arguments.multi_turn_system_prompt` + CLI `--multi-turn-system-prompt`
- `apply_system_prompt_override()` in `MultiTurnStrategy` module; hooked on turn 0. It only touches the per-conversation `context` (fresh list of copied messages), never shared dataset state.
- 6 unit tests (replace / insert / empty / no-op / Arguments parsing / default), no network needed.
