## 正文

## What

`BBHAdapter.record_to_sample` removes `(` and `)` from every target (`evalscope/benchmarks/bbh/bbh_adapter.py:124`), so that `(A)` becomes `A` in the multiple-choice subsets. It also runs on the free-form subsets, where brackets can be the answer: `dyck_languages` asks the model to close a bracket sequence, and 119 of its 250 targets contain `(` or `)`:

- `) ]` is stored as `]`: the correct answer `) ]` scores 0 and the wrong answer `]` scores 1;
- `)` is stored as `""`, which `Target` drops (`evalscope/api/evaluator/state.py:16`), so 39 rows have no reference and are excluded from scoring.

This PR strips the brackets only in `MULTIPLE_CHOICE_LIST` subsets.

## Measured effect

I ran the adapter's own `record_to_sample` and `calculate_metrics` over the BBH test rows, with the gold answer as the completion (`... So the answer is <gold>.`). The rows come from `SaylorTwift/bbh`; its 250 `dyck_languages` rows are identical, in input, target and order, to those in `evalscope/bbh`, the dataset the adapter loads.

| | main | this PR |
|---|---|---|
| `dyck_languages` | 131 correct, 80 wrong, 39 excluded | 250 correct |
| other 26 subsets | 6261 / 6261 | 6261 / 6261 |
| wrong dyck answer = gold without its round brackets | scores 1 on 70 rows | 0 |

`evaluation_version` goes to `v1.1`, since the target mapping changes (AGENTS.md). `tests/benchmark/test_bbh_targets.py` adds 7 cases, including a version check in the style of `test_ifbench_instructions.py`. 6 of them fail on main; all pass here, together with the existing `test_bbh_prompts.py`.
