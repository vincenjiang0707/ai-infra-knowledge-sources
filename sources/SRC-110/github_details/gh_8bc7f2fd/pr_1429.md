## 正文

## Summary

Add two new external agent runners (OpenCode, OpenHands) to the agent bridge system, along with pre-built Docker images for all 4 supported agent frameworks.

## Changes

### New Runners
- **OpenCodeRunner** (`evalscope/agent/external/runners/opencode.py`): Drives `opencode-ai` CLI via the OpenAI Responses API route. Supports pre-built image (fast) and `auto_install` fallback (installs Node.js + npm package at runtime).
- **OpenHandsRunner** (`evalscope/agent/external/runners/openhands.py`): Drives `openhands-ai` via a dedicated venv. Uses `RUNTIME=local` with a stub `e2b` package to work around upstream dependency conflicts.

### Dockerfiles (`evalscope/agent/external/dockerfiles/`)
- `Dockerfile.opencode` — node:22-slim + opencode-ai 1.17.9
- `Dockerfile.openhands` — python:3.11-slim + openhands-ai (stub e2b)
- `Dockerfile.claude-code` — node:20-slim + @anthropic-ai/claude-code
- `Dockerfile.codex` — node:20-slim + @openai/codex

All Dockerfiles include Chinese mirror sources (Aliyun apt/pip, npmmirror npm) for faster builds in mainland China.

### Config & Registry
- `ExternalAgentConfig` validator now accepts `opencode` and `openhands` framework names
- Runner auto-discovery via `@register_runner` decorator

## Testing

- All non-Docker unit tests pass (walking skeleton, trace schema, evaluator pipeline, agent loop)
- Docker e2e verified: `evalscope-opencode:latest` image → bridge → MockLLM → trajectory capture (3.3s round-trip)
- Docker images built successfully: opencode (748MB), codex (687MB), claude-code (629MB)

## Usage

```bash
# Build the opencode image
docker build -f evalscope/agent/external/dockerfiles/Dockerfile.opencode -t evalscope-opencode:latest .

# Use in eval config
evalscope eval --datasets swe_bench_pro --agent-config '{"mode": "external", "framework": "opencode", "environment": "enclave"}'
```
