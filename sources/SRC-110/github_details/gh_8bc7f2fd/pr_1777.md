# [PR #1777] fix(models): preserve provider finish reasons in streamed responses

labels: 

## 正文

MiMo can finish a response with `repetition_truncation`, but EvalScope rejects the completed stream before caching its answer. Both sync and async collectors raise:

```text
Input should be 'stop', 'length', 'tool_calls', 'content_filter' or 'function_call' [type=literal_error, input_value='repetition_truncation', input_type=str]
```

Accept provider strings when assembling streaming choices while retaining validation of the other fields. Unrecognized reasons still map to native `unknown`; their exact values persist in prediction metadata by choice index. JSON responses use the same metadata path. Standard stop reasons keep their existing behavior.

Fixes https://github.com/modelscope/evalscope/issues/1776.

## Testing

A loopback HTTP server returns fixture SSE or JSON responses through the real SDK, native model and prediction cache. No live model or API key is needed. The regression runs in CI and checks sync/async generation, packed choice indices, content, reasoning, usage, cache reload and malformed fields.

Setup and command run on Python 3.12:

```bash
uv venv --python 3.12 .venv
uv pip install --python .venv/bin/python -e '.[dev,perf,docs]' \
  'openai==2.54.0' 'httpx==0.28.1'
.venv/bin/python -m pytest tests/models/test_openai_provider_finish_reason.py -q --tb=short
```
