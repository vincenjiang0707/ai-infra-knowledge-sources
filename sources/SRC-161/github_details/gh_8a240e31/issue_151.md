# [Issue #151] [Bug Report] High failure rate with gemini-3-pro-preview due to "SyntaxError" (conversational output) and Signature Mismatches

source: https://github.com/flashinfer-ai/flashinfer-bench/issues/151
state: open | updated: 2026-01-27T22:26:57Z
labels: 

## 正文


### Environment
- **Hardware:** NVIDIA GeForce RTX 4090
- **Model:** `gemini-3-pro-preview`
- **Target Language:** Triton
- **Action:** Running `uv run kernel_generator_example.py`

### Description
I am encountering a very high failure rate when generating kernels using `gemini-3-pro-preview`. The generated solutions are failing mostly due to `SyntaxError` during the build phase, and occasionally due to generated function signature mismatches.

It appears the tool expects raw Python code, but the model is including conversational text (markdown preamble/postscript) which is being saved directly into the `.py` file, causing Python import errors.

### Steps to Reproduce
1. Clone the repository and install dependencies with `uv`.
2. Configure `.env` with Gemini API key.
3. Modify `kernel_generator_example.py`:
   ```python
   model_name = "gemini-3-pro-preview"
   target_gpu = "RTX4090"
   language = "triton"
   ```
4. Run `cd examples && uv run kernel_generator_example.py`.

### Logs & Analysis

**1. SyntaxError (Conversational Text Issue)**
The model output contains text like "Here is the optimized Triton kernel...", which crashes the Python importer.

```text
BuildError: Failed importing module ... from sources: invalid syntax (main.py, line 1)
...
  File ".../main.py", line 1
    Here is the optimized Triton kernel for the RTX 4090...
                ^^^^^^^^^
SyntaxError: invalid syntax

```

**2. Signature Mismatch**
The generated kernel's entry point does not match the parameters expected by the harness.

```text
BuildError: Destination-passing style callable has incorrect number of parameters: 2 != 3

```

**3. Correctness Issues**
In the few rare cases where it compiles (e.g., solution `r6`), the relative error is extremely high (>6000), indicating the generated kernel logic is incorrect.

### Suggested Fix

* **Parser Update:** The `PythonBuilder` or the prompt generator needs to enforce strictly code output or use a parser to strip markdown/text before saving the `.py` file.
* **Prompt Engineering:** The system prompt might need stronger constraints to prevent conversational filler for this specific model.
