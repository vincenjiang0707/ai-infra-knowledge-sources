# [PR #429] fix: handle matching infinities in evaluator

source: https://github.com/flashinfer-ai/flashinfer-bench/pull/429
state: open | updated: 2026-07-23T13:12:42Z

## 正文

## Summary

- treat same-sign infinities as exact matches in `compute_error_stats`
- reject finite/infinite, opposite-infinity, and NaN comparisons
- preserve the existing finite-value `atol`/`rtol` semantics
- keep non-finite mismatches fatal even with a relaxed matched ratio
- remove duplicated solution-only non-finite checks from the default, low-bit, and DSA evaluators
- add CPU regression tests for the comparison rules and DefaultEvaluator behavior

## Motivation

Bottom-right causal attention can produce valid empty rows when `q_len > kv_len`. These rows have zero output and `LSE = -inf`.

The current evaluators reject a correct solution containing `-inf`, even when the reference contains `-inf` at the same position. At the same time, `compute_error_stats` can treat a finite output against an infinite reference as matched because the relative error becomes `NaN`.

## Behavior

| Output | Reference | Result |
| --- | --- | --- |
| `+inf` | `+inf` | match |
| `-inf` | `-inf` | match |
| finite | `+/-inf` | mismatch |
| `+/-inf` | finite | mismatch |
| `+inf` | `-inf` | mismatch |
| `NaN` | any value | mismatch |
