### sunny-infra · 2026-08-22

The root cause of the current issue is that Ascend PTA does not yet support `flex_attentio`n. Therefore, the recommended parameter for running speculators on NPU at present is `--draft-attn-impl sdpa`.
Changes introduced in this PR do not fundamentally resolve the NPU adaptation problem, and the flex_attention‑related error persists. We suggest using the SDPA implementation as a temporary workaround instead of modifying the upstream repository code. We will roll out an update as soon as Ascend adds support for `flex_attention` (expected in mid‑September). cc @shanjiaz 

### fynnsu · 2026-08-26

@sunny-infra would you recommend we get rid of the `conditional_torch_compile` logic then? We can also add a warning/raise an error if the user select flex_attention with npu accelerators. 

As it currently stands, I believe the `conditional_torch_compile` will be disabling `torch.compile` on all NPU training runs, including those that correctly use the `sdpa` backend, which I'd expect to slow down NPU training. 

### sunny-infra · 2026-08-28

@fynnsu This is a good idea. I will first test whether removing conditional_torch_compile works in other scenarios. If it does, I will add an NPU‑related warning for cases where flex_attention is triggered.
Meanwhile, I would like to ask whether I can add usage guidance for NPU to the documentation at [https://docs.vllm.ai/projects/speculators/en/latest/user_guide/tutorials/train/](https://link.wtturl.cn/?target=https%3A%2F%2Fdocs.vllm.ai%2Fprojects%2Fspeculators%2Fen%2Flatest%2Fuser_guide%2Ftutorials%2Ftrain%2F&scene=im&aid=497858&lang=zh).
