## Purpose

Adds a LongBench-v2 dataset so long-context speculative decoding can be benchmarked. 


## UX

```bash
python scripts/evaluate/prepare_longbench_v2.py \
  --data-dir ./longbench_v2_data \
  --download

python evaluate.py throughput \
  --target http://localhost:8000/v1 \
  --dataset longbench-v2 \
  --dataset-dir ./longbench_v2_data
```

Existing Hugging Face IDs and local paths keep working through `--dataset`; SPEED-Bench accepts the shared `--dataset-dir` spelling while retaining its old hidden alias.

## Two fixes ride along:

- `run_guidellm` omitted `load_kwargs.split=train` on its local-file branch, so guidellm 0.7.x receives a `DatasetDict` and dies in its column mapper with `'DatasetDict' object has no attribute 'info'`. This breaks every prepared dataset today, SPEED-Bench included — #861 fixed the HuggingFace branch only. Both branches now assert the split.
- `evaluate.py` never checked how many requests completed. LongBench-v2 prompts routinely exceed the server's context window and are rejected per request, so a run could print an ordinary acceptance report drawn from a fraction of its sample. The per-outcome counts now reach `acceptance.csv`.



## Tests


End to end on one GB10, vLLM serving `Qwen/Qwen3-0.6B` with n-gram speculative decoding at `--max-model-len 40960`:

```bash
python scripts/evaluate/prepare_longbench_v2.py --data-dir ./lbv2 --download

python evaluate.py throughput --target http://localhost:8000/v1 \
    --dataset longbench-v2 --dataset-dir ./lbv2 --max-requests 8
```

All 503 prepared prompts are byte-identical to the official [`prompts/0shot.txt`](https://github.com/THUDM/LongBench/blob/main/prompts/0shot.txt) rendering.

A length-filtered subset ran clean — 8/8 requests, acceptance length 2.51. The full file rejected 7 of 8 prompts for context overflow, as expected at this context size, and recorded `requests_successful=1,requests_errored=7` in `acceptance.csv`.
