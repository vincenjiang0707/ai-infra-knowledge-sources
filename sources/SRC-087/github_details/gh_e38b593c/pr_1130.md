## Purpose

We already support using a combination of loss functions (e.g. `--loss-fn '{"ce": 0.1, "tv": 0.9}'`) which will use both CE and TV losses and weight them based on the float values. This pr adds support for scheduled (based on global step) loss function weighting. You can now specify

```
--loss-fn '{"ce": 0.1, "tv": {"type": "linear", "start": 0.9, "end": 0.1, "start_step": 0, "end_step": 10000}}'
```

Which would use a linear schedule for the tv weight. Note that the format is backwards compatible with the previous implementation.

This doesn't fully solve the issue of shifting loss weights when there are multiple different loss targets (e.g. auxiliary losses for DSpark or DFlash2). I'll add support for that in a future pr.
