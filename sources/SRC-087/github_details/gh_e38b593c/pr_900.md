# [PR #900] Seed resumed LR schedulers with the global step, not the epoch index

source: https://github.com/vllm-project/speculators/pull/900
state: open | updated: 2026-09-22T15:52:11Z
labels: 

## 正文

## Problem

On resume, `setup_optimizer` passes `last_epoch = checkpointer.previous_epoch` (an epoch index) to `get_linear/cosine_schedule_with_warmup`, but these schedulers step once per optimizer step. Whenever `scheduler_state_dict.pt` is missing (e.g. the original run used `scheduler_type="none"`, or an older checkpoint), the resumed schedule sits at step `previous_epoch` of warmup: near-zero LR, then a full re-warmup and re-decay on an already-trained model. Constructing a scheduler with `last_epoch >= 0` can also crash outright with `KeyError: initial_lr` when the loaded optimizer state predates any scheduler.

## Fix

The resume seed is now `self.global_step - 1` (the constructor's initial step advances it by one, matching a fresh scheduler stepped `global_step` times), `initial_lr` is backfilled into param groups that lack it, and a warning is logged when `scheduler_state_dict.pt` is absent, including the caveat that checkpoints without `training_state.json` read `global_step` as 0 and restart warmup.

## Tests

Unit tests assert the resumed scheduler's `last_epoch` and LR exactly match a fresh scheduler advanced by the same number of optimizer steps, and that fresh runs still start at -1. The resume test fails on main (KeyError: initial_lr, and wrong LR position with state loaded).
