# [PR #704] fix(eagle3): handle float masks in extend_dense_mask_for_draft_tokens

## Summary

- `extend_dense_mask_for_draft_tokens` cast a boolean identity matrix to the mask's dtype to build the diagonal block
- With float masks (0/-inf) from `create_float_mask`, this produced 0/1 instead of 0/-inf, breaking the extended attention mask
- Now correctly produces 0/-inf for float masks while preserving boolean behavior

This is a latent bug — the default backend is `simple_flex_attention` which uses the `BlockMask`-based `extend_mask_for_draft_tokens` instead. This path is only hit with `eager` or `sdpa` backends.

Split out from #691 to keep that PR scoped to the confirmed divergence fix.
