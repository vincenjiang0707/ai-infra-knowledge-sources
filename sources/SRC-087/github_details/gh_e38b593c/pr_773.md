## Purpose

Adds the **Domino** causal correction head as a `projector_type` sub-mode of the existing DFlash draft model (closes #664, based on training-side work in PR #685).

Domino (arXiv 2605.29707) extends DFlash's parallel draft backbone with a lightweight GRU + low-rank MLP head (~56M params) that refines base logits using causal state from previous draft tokens — entirely in logit space, without extra forward passes. Architecture verified against the paper and the [SpecForge reference implementation](https://github.com/sgl-project/SpecForge/pull/571).

Corresponding PR https://github.com/vllm-project/vllm/pull/48241

### Architecture

- `DominoHead` module (`prefix_gru` + `embed_proj`) wired into `DFlashDraftModel`
- Dual-branch training objective: `loss = (1 - λ) * final_loss + λ * base_loss` with linear λ decay schedule
- **Accept-Until-Fail (AUF)** loss truncation (`--auf`, arXiv 2607.01893): zeros the loss support after the first prediction error per block, aligning training with the verifier's prefix-acceptance semantics. Works with both plain DFlash and Domino (for Domino, only the base branch is truncated; the final branch keeps the full mask).
- **Decay-weighted loss normalization** (`--normalize-loss-by-decay`): divides the loss by the sum of decay weights instead of the token count, producing a proper weighted average that stabilizes loss magnitude across different gamma values. Matches SGLang's DFlash loss normalization.

### New CLI flags

| Flag | Section | Default | Description |
|------|---------|---------|-------------|
| `--auf` | DFlash | off | Enable AUF truncation (arXiv 2607.01893) — works with both DFlash and Domino |
| `--normalize-loss-by-decay` | DFlash | off | Normalize loss by sum of decay weights instead of token count |
| `--projector-type` | Domino | `dflash` | `domino` to enable the correction head |
| `--domino-gru-hidden-dim` | Domino | `1024` | GRU hidden dimension |
| `--domino-emb-dim` | Domino | `256` | MLP bottleneck dimension |
| `--domino-pure-draft-prefix-len` | Domino | `1` | Positions using pure base logits before GRU correction |
| `--domino-lambda-start` | Domino | `1.0` | Initial base-loss weight λ |
| `--domino-lambda-decay-ratio` | Domino | `1.0` | Fraction of total steps over which λ decays to 0 |

### jianuo-huang · 2026-07-14

Thanks for the implementation. I would like to clarify the intended design and point out an issue in the current `shift_label=False` path.

1. **Why shifted labels are used**

   Shifted labels avoid wasting the anchor position. With unshifted labels, block position 0 contains the known anchor and must be excluded from the loss, so a block of size (B) produces only (B-1) predictions. With shifted labels, position 0 predicts the first draft token, allowing all (B) positions to be used.

2. **Meaning of `pure_draft_prefix_len`**

   `pure_draft_prefix_len` counts draft predictions, not raw block positions. With `pure_draft_prefix_len=1`, the first draft token uses pure DFlash logits because the anchor has already been consumed by the backbone. Domino correction starts from the second draft token, when the first realized draft token provides additional causal information.

3. **Issue in the unshifted path**

   When `shift_label=False`, prediction position (j) targets token (x_{a+j}), but `gru_out[j]` has already consumed that same token. Therefore, the correction head sees the token it is trained to predict, causing label leakage and a train–inference mismatch.

4. **Suggested fix**

   The unshifted path should use:

```python
suffix_start = 1 + pure_draft_prefix_len
domino_loss_mask[:, ::block_size] = 0
correction_state[:, j] = gru_out[:, j - 1]
```

I suggest either requiring `shift_label=True` for Domino, which matches the intended compute-efficient design, or implementing these separate offsets for the unshifted path.

A regression test should also verify that, in unshifted mode, changing token (j) cannot affect the correction logits used to predict token (j).
