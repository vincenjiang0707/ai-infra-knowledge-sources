# [PR #942] fix(loss): normalize training loss by global (cross-rank) token count

## 正文

## Purpose

`loss_function` (`src/speculators/models/metrics.py`) normalizes the masked training loss by the **per-rank** supervised-token count:

```python
denominator = loss_mask.sum(dim=1) + _EPS
batch_loss  = torch.sum(elementwise_loss, dim=1) / denominator
return batch_loss.mean()
```

Under DDP/FSDP the per-rank gradients are then **mean-averaged**, so the effective objective is the rank-local mean of ratios

```
(1/R) · Σ_r ( Σ_t loss_r / Σ_t mask_r )
```

rather than the token-weighted objective

```
( Σ_r Σ_t loss ) / ( Σ_r Σ_t mask )
```

These differ whenever the per-rank supervised-token counts are uneven: a token's weight in the update ends up depending on which rank it landed on.

This is not prevented by packing. `_lpt_packed_batch` balances **total** tokens against a budget (and its docstring notes that "slot 0 always takes the largest sample and the highest slot absorbs the small ones", so sample counts stay skewed), while the loss denominator counts **supervised** tokens — the packer never looks at `loss_mask`. Two ranks can hold the same token budget and still differ substantially in how many positions are unmasked: one rank holding a single long sample has one masked prompt, while a rank absorbing many small samples pays that prompt cost many times over.

For reference, DeepSpec computes its backward loss this way (`_build_loss`): each term is `local_numerator / all_reduced_denominator`, and the sum is scaled by `world_size`; the rank-local denominators are used only for reported metrics.

## Fix

When distributed, all-reduce the denominator to the global token count and scale by `world_size`, so the subsequent gradient mean-average reconstructs the token-weighted objective.

- **Gradient-identical when ranks are token-balanced** (single rank, or balanced supervised-token counts) — a no-op for that case, so it does not shift the effective LR of tuned recipes.
- Only changes behavior — correctly — when per-rank supervised-token counts are imbalanced.
- The all-reduce is on the **detached denominator only**; autograd flows through this rank's numerator exactly as before.
- Uses the default process group, matching `fully_shard`'s gradient reduction; correct under sequence parallelism as well, where summing across shards recovers the full sequence's token count.
- Batch is `[1, seq_len]` after collation, so within-rank semantics are unchanged; only the cross-rank normalization changes.
- Cost is one scalar all-reduce per loss term per step; the call is rank-symmetric, like the collectives the trainer already performs.
- Device-agnostic; no new dependencies.

### zihanlin-ai · 2026-08-22

Two things on this change, from carrying an equivalent fix downstream:

**1. A deterministic unit test for the gradient, not just the loss value.** Two-rank Gloo test with deliberately uneven supervised-token counts: same tiny model on both ranks, rank 0 gets a batch with 1 valid token and rank 1 a batch with 3, run the loss, let DDP average the gradients, compare the resulting `param.grad` against the gradient of the single-process global weighted mean over all 4 tokens. With per-rank normalization the numbers differ by construction (each rank's tokens get weight 1/(2·n_rank) instead of 1/4); with the global denominator they match to fp32 precision. ~40 lines.

The downstream fix is a `distributed_weighted_mean` that all-reduces the denominator and scales by world size so the DDP/FSDP-averaged gradient equals the gradient of the global weighted mean; that test is what caught it: on a two-rank CUDA probe with uneven valid-token counts the DDP-averaged gradient came out 2.999986 where the single-process global reference was 4.0. *(Edited: an earlier version said 8 ranks; the preserved evidence is the two-GPU probe.)*

**2. Same shape in one more place.** `dspark/metrics.py::_masked_decayed_mean` (confidence-head BCE) has the same per-rank `loss_mask.sum()` denominator; routing it through the same helper keeps `loss + conf_alpha * conf_loss` consistently normalized. The confidence term is the one whose per-rank token counts vary most once anchors are sampled.
