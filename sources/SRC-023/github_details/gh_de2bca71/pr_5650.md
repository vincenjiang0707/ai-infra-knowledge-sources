# [PR #5650] [Triton/Gluon] gfx942: dtype-split large-prefill attn_2d entries for head 256/512 (Gemma-4)

## 正文

## Summary

Adds four `attn_2d` entries to the gfx942 unified-attention table so large prefill on head-256/512 layers (Gemma-4-31B: 10 full-attention layers at head 512, sliding layers at head 256) stops running on the decode-era `BLOCK_M=16` configs. Continues and supersedes the config side of #5063, informed by a side-by-side with #5649.

```json
"D_GEQ_512.Q_GEQ_1024.DT_fp8_fp8":  {"BLOCK_M": 128, "num_warps": 8, "num_stages": 2, "waves_per_eu": 2, "TILE_SIZE_MIN": 16, "TILE_SIZE_MAX": 16},
"D_GEQ_512.Q_GEQ_1024.DT_bf16_bf16": {"BLOCK_M": 64, "num_warps": 8, "num_stages": 2, "waves_per_eu": 2, "TILE_SIZE_MIN": 16, "TILE_SIZE_MAX": 16},
"D_GEQ_256.Q_GEQ_1024.DT_fp8_fp8":  {"BLOCK_M": 64, "num_warps": 2, "num_stages": 2, "waves_per_eu": 2, "TILE_SIZE_MIN": 16, "TILE_SIZE_MAX": 16},
"D_GEQ_256.Q_GEQ_1024.DT_bf16_bf16": {"BLOCK_M": 64, "num_warps": 4, "num_stages": 2, "waves_per_eu": 2, "TILE_SIZE_MIN": 16, "TILE_SIZE_MAX": 16}
```

## Why dtype-split

The two prior attempts at this used dtype-agnostic composite keys. Measured on MI325X (isolated kernel bench, same kernel body for every arm — only `select_2d_config`'s return is swapped; Gemma-4 per-rank shapes 32q/4kv, page 64, 16k tokens, median `do_bench`):

**fp8 q+kv (D=512, 16k tokens):**

| arm | ms | regs / spills |
|---|---|---|
| table `D_GEQ_512.DT_fp8_fp8` (M16/T32/w4) | 43.6 | 211 / 0 |
| #5649 `D_GEQ_512.Q_GEQ_256` (M64/T16/w4) | 25.7 | 256 / 0 |
| **new fp8 entry (M128/T16/w8)** | **18.9** | 238 / 0 |

**bf16 (D=512, 16k tokens):**

| arm | ms |
|---|---|
| table `D_GEQ_512` (M16/T16/w4) | 69.9 |
| #5649 entry applied to bf16 (M64/T16/w4) | **93.0 — regression** (CI triton 3.8.0) |
| **new bf16 entry (M64/T16/w8)** | **38.8** |

The fp8-tuned warp count regresses bf16, and BLOCK_M 128 at bf16 overflows the 64KB LDS (compile error, required 131072). So the entries are split on `DT`.

**D=256 sliding-window prefill (SW=1024, 16k tokens):**

| dtype | table (M16/T32/w4) | new entry |
|---|---|---|
| fp8 | 3.32 | **1.21** (M64/T16/w2) |
| bf16 | 4.49 | **1.84** (M64/T16/w4) |

## Why Q_GEQ_1024

Measured crossover vs the D-only entries is between 512 and 1024 tokens (at Q=512 the D-only entries still win on both dtypes; at Q=1024 the composites win). Binding at 256 (as #5649 does) gives the new configs sub-1k-token prefills where they slightly lose; binding at 1024 leaves those on the existing entries.

## Pre-shuffled KV note

The pre-shuffled A8W8 path pins `TILE_SIZE = block_size` after lookup (`unified_attention.py`, `_unified_attention_2d_triton`). With block_size 64 at head 512, M64/T64 needs 69632B of LDS — over the 65536B limit — so this entry must not be used as-is there; measured M16/T64 (the current effective config for that path) compiles and runs. The new keys are dtype-scoped to plain fp8/bf16 KV; the pre-shuffled path should get its own entry after a dedicated tuning pass (not attempted here).

## Verification

- Isolated kernel bench on MI325X, both triton 3.7.1 (vllm-openai-rocm v0.28.0 image) and **3.8.0 (aiter CI pin, installed from pypi.amd.com)**: numbers above are from 3.8.0; 3.7.1 agrees within ~5%.
- Register/spill stats via kernel `n_regs`/`n_spills`: every new entry compiles with 0 spills (M128/w8 fp8: 238 regs, LDS exactly 65536B).
- Lookup regression tests: `op_tests/triton_tests/attention/test_unified_attention_config.py` asserts the matched key and BLOCK_M for all 18 cases (both dtypes × both head tiers × decode controls × Q=1023/1024 boundary), run against the actual `_lookup`/`_axis_values` from this branch — 18/18 pass.
- Output equivalence between arms verified in-bench (max abs diff at fp8 = 1 quant step of the synthetic input scale; 0 at bf16).

## Pre-shuffled KV (follow-up commit)

The SHUF axis was added to the schema so pre-shuffled A8W8 prefill (where the wrapper pins `TILE_SIZE = block_size` post-lookup) gets LDS-safe, separately tuned entries: head 512 `M32/w4/s1` (42.2 → 28.6 ms) and head 256 `M128/w8/s2` (16.6 → 9.1 ms), both fp8, MI325X. Six shuffled lookup cases cover Copilot's ask; 24/24 total pass.
