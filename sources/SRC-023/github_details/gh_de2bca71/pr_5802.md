# [PR #5802] [FlyDSL] [Bugfix] Route a16w4 SiLU MoE to CK-Tile and apply swiglu_limit

## 正文

## Motivation

A bf16-activation x MXFP4-weight SiLU MoE with a `swiglu_limit` has no working route. This is the small-batch path that DeepSeek-V4.1 takes on gfx950 whenever the token count is below `AITER_BF16_FP8_MOE_BOUND` (default 256). `get_2stage_cfgs` only sends SwiGLU to CK-Tile there, so SiLU falls through to CK2stages. CK2stages has no A16W4 SiLU instance and no clamp. In our container the JIT build of `module_moe_ck2stages_b16_fp4x2_preshuffle_on_b16_silu_per_1x32_mulWeightStage2` fails at server start. Where it builds, `swiglu_limit` would be dropped.

Downstream, sgl-project/sglang#39857 carries this change as a Docker patch, and DeepSeek-V4.1 deployments set `AITER_BF16_FP8_MOE_BOUND=0` to stay on the a8w4 route. This PR lets both go.

## Technical Details

- `get_2stage_cfgs`: SiLU with bf16 output on gate/up-interleaved MXFP4 weights takes the CK-Tile split-K post-activation route that SwiGLU already uses. SwiGLU keeps its `standard` post-activation layout; SiLU uses `auto`, which selects the interleaved FlyDSL activation for fp4 weights.
- `fused_moe_2stages`: forwards `swiglu_limit` to `cktile_moe_stage1` for that SiLU case.
- `cktile_moe_stage1` and `flydsl_silu_and_mul_interleaved`: take `swiglu_limit` and pass it to the kernel (`runtime_swiglu_limit`) instead of a fixed `inf`.
- The SiLU route is limited to `GateMode.INTERLEAVE`. On separated gate/up weights the output was about 4.5% (cosine) off the clamped reference, so that layout is left as it was.

## Test Plan

```bash
AITER_BF16_FP8_MOE_BOUND=256 python -m pytest op_tests/test_moe_a16w4_silu_limit.py -q
```

The new test runs a DeepSeek-V4.1-shaped MoE (model_dim 5120, inter_dim 2304, 32 experts, top-6, `swiglu_limit=7`) through `fused_moe` and compares it with the clamped `torch_moe_stage1/2` reference. It also checks that the inputs actually reach the limit.

## Test Result

MI350X VF (gfx950), ROCm 10 Python wheels with torch 2.11. Current main does not JIT-build in this container (`module_moe_asm`), so the change was validated on `acf8fdf93`, where it applies unchanged.

| | token=1 | token=32 |
|---|---|---|
| without this change | JIT build failure | JIT build failure |
| with this change (cosine diff vs clamped ref) | 1.3e-5 | 1.4e-5 |

End to end, DeepSeek-V4.1-Flash TP4 with the default bound serves and scores 0.910 on GSM8K (200 questions); without the change the server fails to start.
