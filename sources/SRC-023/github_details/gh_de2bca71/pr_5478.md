# [PR #5478] [Triton/Gluon] [Attention] Add overflow-guarded per-call int32 varlen strides

state: open | updated: 2026-09-24T14:08:07Z

## 正文

## Summary

AITER's Triton variable-length attention currently selects 32- vs 64-bit stride arithmetic through process-global state. This PR adds a **per-call** opt-in so a caller can request 32-bit addressing when the complete launch is safe, without changing other concurrent attention calls.

`prefer_int32_strides=True` uses the int32 specialization only when the checked tensor layout and launch geometry fit safely in int32. Otherwise the existing int64 path is used or, for unsupported metadata/implementations, the opt-in is rejected explicitly.

Defaults are unchanged.

## Safety boundary

The opt-in is currently limited to BF16 inference, matching the qualified use case. FP16/FP32 keep the existing int64 dispatch, as does training.

The guard covers:

- Q/K/V, output and LSE storage offsets and strides
- production tile sizes
- padded and one-past tile coordinates
- sequence-coordinate and sliding-window arithmetic
- flattened launch-grid bounds
- 1D contiguous cumulative-length metadata

Unsupported implementations such as Gluon/DAO do not silently ignore the request.

## Validation

The current test suite runs the new branch in the normal Triton attention pytest path. On MI300X/gfx942, **307 tests pass** across the bounds/configuration suite and GPU dispatch/parity cases. The GPU cases cover output and LSE, graph replay, causal/windowed attention, GQA, strided views, head padding and independent FP32 references. FP16/FP32 fallback is also checked.

For the long MiniMax H3 attention shape that motivated this work, the isolated primitive improved from **134.90 ms to 84.80 ms (1.59x)**.

With the companion SGLang adapter (#39249), a matched 8x MI300X MiniMax H3 run with Cache-DiT off improved full generation time from **208.17 s to 142.12 s**, or **46.48% more serial clips/hour**. The three measured decoded audio/video outputs were identical between the two arms.

Short attention shapes can regress, so this PR does not enable the option by default or claim a universal speedup.

## Review question

The main maintainer question is whether the per-call API and its safety/fallback boundary are the right abstraction for Triton varlen attention. The implementation does not change the attention algorithm or remove overflow protection.
