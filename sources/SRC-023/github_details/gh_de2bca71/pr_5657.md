## 正文

## Motivation

DeepSeek-V4-Flash-0731 uses three block-scale FP8 pre-shuffled GEMM shapes that are not covered by the current gfx950 tables. This adds tuning data collected from a live SGLang TP2 run on MI355X. Related issue: **[add issue link before submitting]**.

## Technical Details

This adds 398 tuned rows for `(N, K)` shapes `(1536, 4096)`, `(8192, 1024)`, and `(16384, 1024)`, using CK, CKTile, and ASM kernels. Of 399 collected shapes, 398 passed the 2% improvement gate; `M=704, N=1536, K=4096` remains untuned. The 132 accepted rows for `(1536, 4096)` were 40.2% faster at the median, with speedups from 2.0% to 53.6%. A 60-row subset improved end-to-end output throughput by 1.87% and TPOT by 1.82% over a 22-point serving sweep; the completed three-family table stayed around 2% faster in long-context checks.

## Test Plan

- Run the tuning and correctness comparison through the production operator.
- Run `python op_tests/test_pretune.py`.
- Check CSV schemas, shape coverage, duplicate keys, and overlap with current `main`.

## Test Result

All 398 rows have `errRatio=0.0`. The pretune suite passed 84/84 checks, and the CSV validation found no duplicate keys or overlap with current `main`. The runtime collision unit test could not run locally because Ninja is unavailable; the same collision keys were checked directly against the canonical and model-specific tables.
