## 正文

## Motivation

PR #4970 introduced a two-stage int4 quick reduce FlyDS kernel that improved all-reduce throughput over the existing Aiter two-stage/RCCL kernels. Current Aiter all-reduce kernels are written primarily for the xGMI interconnect. This PR optimizes the FlyDSL quick reduce int4 kernel for PCIe interconnects (MI350P) and adds two new kernels: a one-stage lossless and a two-stage ring kernel with int4/int6 codecs. On MI350P, they offer better performance than the existing Aiter production kernels (RCCL/cross-device-reduce)

Category | Speedup TP=2 | Speedup TP=4 | Speedup TP=8
-- | -- | -- | --
Decode (new kernels are exact) | 1.40x-2.27x (avg: 1.62x) | 1.45x-5.60x (avg: 2.25x) | 2.36x-4.60x (avg: 3.18x)
Prefill (new kernels use quantization) | 2.42x-3.54x (avg: 2.94x) | 2.50x-3.89x (avg: 3.08x) | 2.43x-4.84x (avg: 3.57x)

## Technical Details

**Kernels** (`aiter/ops/flydsl/kernels/`)
- `one_shot_allreduce.py`: exact one-stage push all-reduce. bf16 in and out, fp32 accumulation in a fixed rank order. The IPC inbox is double-buffered by color parity.
- `quick_allreduce_int4_ring.py`: two-stage ring schedule, 2(N-1) single-destination hops, with a wire format (int4/int6) chosen separately for each lap. At TP8 the reduce-scatter lap defaults to INT6 so the ring holds the 18 dB SQNR floor.
- `quick_allreduce_codec.py` and `quick_allreduce_shared.py`: the INT4, INT6 and fp16 wire formats and the transport shared by the mesh and ring schedules. The #4970 mesh kernel is refactored onto them.

**Host wrappers** (`aiter/ops/flydsl/`)
- `QuickAllReduceInt4` gains an `algorithm="mesh"|"ring"` choice, per-lap codecs, inbox memory modes, and payload-size super-tile ladders.
- `OneShotAllReduce` is a new host wrapper for the one-stage kernel. It picks a per-fabric rung (`ONESHOT_LADDER`) by payload size.
- Fabric detection (`has_xgmi_peer_links`) reads KFD link types. PCIe hosts get a fine-grained inbox, because uncached peer writes serialize per destination on PCIe. On xGMI we use un-cached IPC memory.

**Production dispatch**, opt-in with `AITER_FLY_AR=1` - the existing behavior is unchanged when the env variable is unset/disabled.
- The custom-all-reduce slot is fronted by the exact one-shot for plain bf16 up to the policy ceiling.
- The quick-reduce slot, under `AITER_QUICK_REDUCE_QUANTIZATION=INT4`, dispatches bf16 payloads in the policy window to the FlyDSL mesh or ring instance.
- The windows come from `allreduce_policy.FAMILY_POLICY`, keyed on (fabric, world size). They can be overridden with `AITER_FLY_AR_ONESHOT_MAX_BYTES` and `AITER_FLY_AR_MESH_MAX_BYTES`.
- `CudaCommunicator.destroy()` now closes the all-reduce slots it owns. That releases the IPC handles before the process group goes away.
- Fabric detection is per host. The assumption that a node is uniformly either xGMI or PCIe.

## Test Plan

Added option to use fp16 codec over the wire. This ensures lossless transport and allows to verify the transport correctness using a bitwise equality/all close against a reference implementation. The new one-stage kernel is exact by construction. Added/modified the following test suites that run under the CI
-  `test_flydsl_quick_allreduce_int4.py`: Added tests for the ring algorithm, added transport correctness tests for both mesh and ring algorithm.
- `test_reuse_identical_rank_groups.py`: Added tests to ensure that `CudaCommunicator.destroy()` now closes the all-reduce slots it owns.
- `test_flydsl_one_shot_allreduce.py`: New test suite for the one-stage exact all-reduce kernel.

All tests should pass on CI to verify the code changes form this PR.

Created a separate benchmarking suite for communication collective under `op_tests/op_benchmarks/flydsl`
- `bench_comm_allreduce.py`: Comprehensive benchmarking suite for Aiter's all-reduce collectives. Can be extended to include the fused all-reduce variants.
- `transferbench_roofline.py`: Optional roofloine analysis using TransferBench. Used in the benchmarking script with additional `--roofline` flag to provide wire-efficiency estimate of the different all-reduce implementations.

The benchmarking suite is used to tune the instance selection as well to produce performance claims in this PR. The suite can be used to tune any all-reduce implementations, not just the FlyDSL ones.   ‎

## Findings

Findings are ordered by severity. Each finding has a location, a trigger, a reason, and a proposed fix.

### P1 — The production selector accepts layouts that both engines reject

**Where:** `aiter/dist/device_communicators/flydsl_all_reduce.py` lines 208-225, `FlyDSLAllReduce.should_fly_all_reduce` (weak-contiguity eligibility); lines 227-232, `fly_all_reduce` (unconditional selected-engine call); `aiter/ops/flydsl/one_shot_allreduce.py` lines 211-245, `OneShotAllReduce._check_payload` (strict contiguity); `aiter/ops/flydsl/quick_allreduce_int4.py` lines 795-828, `QuickAllReduceInt4._check_payload` (strict contiguity)

**Trigger:** Enable the new production path and pass a non-contiguous tensor whose view consumes the full remaining storage. A transpose of a contiguous allocation is one example. The payload must otherwise be in the selected family window and meet the dtype and 16-byte-size checks.

**Reason:** The selector imports `is_weak_contiguous`. That helper returns true when the storage tail equals the logical byte count, even when `Tensor.is_contiguous()` is false. Both selected engines then require `inp.is_contiguous()` and `out.is_contiguous()`. A local probe with a bf16 transpose reported `should_fly_all_reduce=True`; both `_check_payload` methods raised `ValueError`. `CudaCommunicator.all_reduce` has already committed to this path, so the exception replaces the intended fallback.

**Proposed fix:** Make the selector and engine contract identical. One sufficient approach is to require strict contiguity in `should_fly_all_reduce`. Another sufficient approach is to support the accepted weak-contiguous mapping in both engines and in output allocation. Add a production-dispatch test with a full-storage transpose and assert either a successful result or a clean fallback.

**Trigger:** Run the repository's standard single-GPU and multi-GPU test jobs with no `AITER_TEST` override.

**Reason:** Four separate problems share one root cause: the new tests were designed as a pytest estate, while AITER's CI runs `python3 <file>` over a fixed, shallow file list.

1. *A new script makes the multi-GPU job fail.* The multi-GPU runner executes every `*.py` under `op_tests/multigpu_tests/`, recursively, as a script. `fit_allreduce_policy.py` takes a required positional `csv` argument, so a bare `python3` invocation exits with status 2 and the job reports a failed file. I confirmed the argparse contract directly: a parser with `add_argument("csv", nargs="+")` raises `SystemExit(2)` on an empty argument list. `transferbench_roofline.py` already documents this exact runner behavior at lines 768-772 and self-skips; `fit_allreduce_policy.py` does not, and neither is in `skip_tests`.
2. *A 2405-line benchmark becomes a CI test.* The same runner executes `bench_comm_allreduce.py`. Its only guard is the architecture allow-list, so on a supported runner it sweeps 13 shapes at TP4 across every applicable candidate at 101 timed iterations, after JIT-building each FlyDSL ladder engine. It also asserts an SQNR floor per candidate inside the timed loop, which turns a tuning tool into a correctness gate whose failure message points at a benchmark rather than at an operation. These three scripts are tooling, not tests, and `op_tests/multigpu_tests/` is a directory where everything is executed.
3. *The behavioral coverage is not reachable from CI.* Neither `aiter_test.sh` nor `split_tests.sh` descends into `op_tests/flydsl_tests/`, so the 32 policy cases and the 36 codec cases never run; the FlyDSL tests CI does run are the top-level `op_tests/test_flydsl_*.py` files listed in `split_tests.sh` lines 89-172. The two multi-GPU files do run, but as scripts: the quick-allreduce `main()` sweeps `mesh` only at TP8 over three shapes, and the one-shot `main()` runs TP2 only. None of the 46 quick-allreduce pytest cases and none of the 36 one-shot pytest cases execute. The principal new ring protocol, the TP8 INT6 reduce-scatter default, and every codec edge case can regress while CI stays green.
4. *The suites themselves depart from the op-test contract.* `test_flydsl_one_shot_allreduce.py` has no `@benchmark` function, no `run_perftest`, no `checkAllclose`, no TFLOPS or TB-s columns, and no markdown summary; its `-tp` flag is a single behavior selector instead of a swept list, so `itertools.product` never applies. `test_flydsl_allreduce_policy.py` is a CPU-only structural suite with no kernel and no oracle, and it couples to shipped tuned values: line 211 asserts `oneshot_max == (48 << 10)`, and lines 62-71 assert that the xGMI rows are flat with a comment stating the test is meant to fail once a real fit replaces them. Retuning is a normal event and must not turn a suite red. `test_flydsl_quick_allreduce_codec.py` builds a second FlyDSL kernel inside the test file to drive private codec helpers, which makes the wire format a product under test rather than checking the operation through its public wrapper.

On volume: the estate is disproportionate. About 150 collected cases and about 31 multi-process spawns cover an operation family whose distinct behaviors are the two schedules, three wire formats, three world sizes, the partial-tile and super-tile paths, and a handful of E4M3 edge cases. Much of the count is the same case restated. The `allclose` family at lines 781-808 reruns the shapes of the `bit_exact` family at lines 743-779 with a weaker gate. The E4M3 edge cases appear twice, as codec cases at lines 336-420 and as `_FILLS` cases at lines 647-674. `mesh` and `ring` are crossed with every world size in three separate families, although the ring is the schedule this PR introduces and the mesh is already covered at base. A smaller estate that CI actually executes would protect more behavior than this one does.

Two minor items belong with this finding. `bench_comm_allreduce.py` line 131 refers to `op_tests/multigpu_tests/shapes/README.md`, which the PR does not add. The one-shot suite writes rank logs to fixed `/tmp/flydsl_one_shot_allreduce_tp{N}_rank{R}.log` paths (lines 260-263), which collide between concurrent runs on a shared runner.

**Proposed fix:** The outcome to reach is one canonical, CI-executed suite per new operation, with the tooling moved out of the executed directory. One sufficient approach:

- Move `bench_comm_allreduce.py`, `fit_allreduce_policy.py`, and `transferbench_roofline.py` out of `op_tests/multigpu_tests/` into a location the runner does not execute. If they must stay, add all three to `skip_tests` in `aiter_test.sh` and give each a no-argument path that exits 0, as `transferbench_roofline.py` already does.
- Keep `test_flydsl_quick_allreduce_int4.py` as the canonical suite for the quantized all-reduce and reshape `test_flydsl_one_shot_allreduce.py` into the standard form: a module-level reference, a `@benchmark` function timed with `run_perftest` and checked with `checkAllclose`, swept argparse lists, the `get_gfx()` allow-list in `main()`, and a markdown summary table.
- Fold the parts of the two `op_tests/flydsl_tests/` suites that protect real behavior into those canonical files, and delete the rest. Worth keeping: the codec sub-floor, ceiling-saturation, and zero-group cases, expressed through the public wrapper against the fp32 oracle, where the `_FILLS` mechanism already reaches them; and a policy check for family selection, precedence, and fallback built on a small synthetic policy map. Worth dropping: assertions on shipped threshold constants, the xGMI flatness tripwire, the structural checks that restate `FamilyPolicy.__post_init__`, the in-test FlyDSL codec kernel and its private-symbol imports, and the codec-resolution unit tests once the same resolution is observed through the wrapper.
- Reduce the remaining matrices to distinct behaviors: one gate per transport shape rather than a bit-exact and an allclose pass over the same shapes, and the full `mesh` cross-product only where the mesh path actually changed.
- Make the default script sweep of each canonical file small enough to finish inside the 60-minute per-file budget while still touching each supported world size, both schedules, and the partial-tile and super-tile paths.

### P3 — Residual: fabric detection is host-global, not group-specific

**Where:** `aiter/ops/flydsl/quick_allreduce_int4.py` lines 295-333, `has_xgmi_peer_links` (scans every KFD link on the host); lines 336-350, `_resolve_inbox_flags` (selects one memory mode from that result); `aiter/dist/device_communicators/flydsl_all_reduce.py` lines 118-123, `FlyDSLAllReduce.__init__` (selects the policy from the same result)

**Trigger:** A host that mixes PCIe-connected and xGMI-connected GPU pairs, where the process group uses only the PCIe-connected devices.

**Reason:** The detector returns true after it finds any xGMI link on the host. It does not receive the selected device or the process group, so a PCIe-only group on such a host would select the xGMI policy and an uncached inbox, and the source documents that uncached peer writes collapse on PCIe. This is recorded as an accepted assumption rather than a defect: deployed single-node hosts are uniformly PCIe or uniformly xGMI, so the mixed topology this depends on is outside the expected deployment.

**Proposed fix:** No change is required for merge. If the assumption is ever in doubt, classify only the links between the devices in the process group, for example by gathering each rank's device identity over the CPU group, mapping those devices to KFD nodes, and inspecting the peer links the collective uses. Recording the assumption near `has_xgmi_peer_links` would make it visible to the next reader.
