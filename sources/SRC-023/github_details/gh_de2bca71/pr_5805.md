# [PR #5805] [OPUS] Speed up the gfx1250 32mx1 MLA sparse-prefill kernels

source: https://github.com/ROCm/aiter/pull/5805
state: open | updated: 2026-09-24T11:32:18Z
labels: ASM

## 正文

## Summary

Rebuilds the two prebuilt gfx1250 code objects that serve `16 < H_Q <= 32` on the DSv4 sparse-prefill path, and reworks the op test so its inputs match how the kernel is actually used in a DSA deployment.

## Kernels

`opus_mla_v4_prefill_a8w8_32mx1_16nx4` now fits two workgroups per CU: LDS drops from 224256 to 157696 bytes (154 KiB, under the 160 KiB half-budget) and the VGPR count from 734 to 512. `opus_mla_v4_prefill_a16w16_32mx1_16nx4` prefetches V one tile ahead in the round loop, trading VGPRs (742 -> 826) for a shorter dependency chain.

Measured with `op_tests/test_pa_sparse_prefill.py --backend opus --h_q 32` across `prec x {1024, 4096} tokens x {1024, 2048} topk x {64Ki, 1Mi} pages`, 16 points per precision:

| precision | min | max | mean |
| --- | --- | --- | --- |
| bf16 | 1.005x | 1.029x | 1.022x |
| fp8 | 1.077x | 1.300x | 1.207x |

The fp8 gain narrows as the prefix pool grows (1.23-1.30x at 64Ki pages, 1.08-1.19x at 1Mi), which is what an occupancy win looks like once the gather starts missing cache. Accuracy is unchanged: every point reports a 0.0 mismatch ratio against the PyTorch reference.

## Test

The page table now models a DeepSeek Sparse Attention top-k selection instead of uniform-random CSR rows. Each token draws `topk` rows from each range, the extend range is causal (token `i` only sees `[0, i]`, since those rows are the chunk's own K/V), and indices stay scattered so the gather does not degenerate into a near-sequential read. This replaces the `sparse` / `dense` / `empty` modes; `--topk` and `--total_pages` become the sweep axes, with `total_pages` defaulting to `[65536, 1048576]` so the gather is measured outside the caches rather than partly served by L2.

Two hardening changes come with it. Pool rows the page table never names are filled with NaN (0xFF for fp8 NoPE, which is NaN as both e4m3 and E8M0), so a gather that walks off its index list cannot return plausible numbers. The fp8 row pad past the block scales is 0xFF for the same reason. All three backends (`opus`, `triton`, `asm`) pass with both in place.

`_PYTEST_CASES` folds `topk` into each case rather than crossing it as an axis, which kept most combinations from collapsing onto the same whole-pool budget. The seven cases cover every wave layout, both cluster widths, two partial head blocks, a ragged KV tile tail, a whole-pool budget, and empty pools.
