## 正文

The M3 sequence-parallel path needs contiguous reduction shards, attention outputs in token-major head layout, and faster sorting of large prefill batches. This adds the AITER kernels used by [ROCm/ATOM#2364](https://github.com/ROCm/ATOM/pull/2364) to reduce communication and layout-processing overhead.

- Add four-rank INT4 QuickReduce reduce-scatter for contiguous FP16/BF16 tensors. It reuses the existing codec and communicator state, sends one data phase, and protects IPC-buffer reuse with a consumption barrier. Calls sharing a communicator must remain serialized on its current stream.
- Add four-rank head exchange that writes the final token-major head layout directly, using CustomAllreduce registered pointers and synchronization. It supports staged inputs and already-registered graph inputs.
- Add opt-in tiled MoE sorting with stable packed token IDs, expert padding, and optional auxiliary mappings. `use_tiled_sort` defaults to `False`; the dispatch guard targets gfx950 M3 MXFP4 prefill with 32,768 tokens, top-k 5, 129 experts, hidden size 6,144, intermediate size 768, and block size 64. Unsupported contracts, including caller-provided output buffers, use the existing dispatcher. Launch settings use the shared JSON config loader, and kernels include config-aware trace names.

This reuses the existing norm/quantization kernels and leaves existing QuickAllReduce entry points unchanged. The sorting implementation is a separate histogram/prefix/stable-scatter algorithm; the original four sorting phases remain valid.

### Validation

Rebased onto `11d38524cb12d4ff56fa89c2b03418afcc78c41c`. On four gfx950 GPUs:

- **32/32 GPU sorting tests passed**, including exact packed-route/padding/auxiliary output, changed-input graph replay, fallback behavior, and byte-exact M3 fused-MoE output comparison. The companion ATOM four-rank transport/GQA/graph and MXFP4 prequantization/MoE checks also passed.
- The full SP model ran with `3e3a168a8e3476e7fd5731e48c32341540d98c07`; all four workers loaded the fresh QuickRS and head-exchange extensions. A clean-build failure caused by include ordering was fixed before this run.
- M3 **131072 input / 100 output / C16**, 16 warmups and 160 measured requests: optimized SP4 **43.221 output tok/s**, compared with **41.072** for TP4 QuickReduce all-reduce INT4 with BF16-to-FP16 cast (**+5.23%**). Both completed 160/160 requests with exact requested lengths and no errors. One measured run per configuration; this is combined system performance, not an isolated attribution to each kernel. Decode median ITL remains slower: **14.626 ms** versus **10.390 ms**.
- Full GSM8K, 1,319 samples, 5-shot: strict and flexible exact match **0.93783169**, above the requested **0.93** threshold. INT4 reduction is lossy; this is empirical model-quality acceptance.
- Python/C++ formatting, Ruff, Python compilation, JSON parsing, and 10 isolated CPU dispatcher/signature/config checks passed.

The TP4 run used `f2bd394f7`; the only subsequent AITER change restores required include ordering in the new QuickRS translation unit, which TP4 does not use. Both full-model runs used ATOM `cc7558ac` and the same benchmark client from ATOM `3a2df1d3`. The final ATOM branch was then rebased onto newer main with its M3 server runtime verified byte-identical; these numbers do not measure the new CI telemetry harness. The companion ATOM PR contains the full model settings and opt-in environment recipe.

The final CI follow-up only regroups imports in the benchmark script. Production kernel bodies and launch settings match the full-model run. Ruff 0.16.8 was rechecked without its cache.
