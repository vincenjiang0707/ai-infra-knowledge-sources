## 正文

## Motivation

The gated-delta-rule (GDN / KDA) prefill pipeline runs as six stages, K1–K6. Two of them
dominate the tail: **K5**, the inter-chunk hidden-state scan, and **K6**, the inter/intra-chunk
output projection.

There is no fused K5+K6 kernel for `gfx942` today. The `gfx942` path runs K5 and K6 as two separate
kernels, which forces the entire K5→K6 handoff through HBM: the per-chunk `h` snapshots
(`BV·K` per chunk) and the gated `v_new` (`BT·BV` per chunk) are written out by K5 and
immediately read back by K6. On a kernel that is already memory-bound, that round-trip is the
single largest avoidable cost.

This PR adds that fused kernel, and in the process makes the standalone K5 kernel faster than
existing `gfx942` backends (Triton, HIP, FlyDSL) for most shapes measured. Both improvements are
independently useful: the fused kernel wins where the grid is large enough to fill the device,
and the improved standalone K5 carries the shapes where it is not.

Benchmarked 31 production shapes on MI325X and MI300X (Kimi-K3 KDA at TP8/TP4, Qwen3-Next GDN at TP8/TP4, Qwen3.5-MoE GDN at TP1/TP8, Qwen3 GDN at TP1):

**K5 standalone** — geomean speedup vs Triton (31 shapes):

| Kernel | vs Triton | vs HIP |
|---|---|---|
| FlyDSL (`flydsl_opt`, PR #4732) — unsafe conv | 1.86× | 1.08× |
| FlyDSL VK (this PR) — safe conv, shipped default | 1.96× | 1.15× |
| FlyDSL VK (this PR) — unsafe conv (`AITER_FAST_FP32_TO_FP16=1`) | 2.24× | 1.32× |

**K5+K6** — geomean speedup vs Triton K5+K6 (31 shapes, `fused_auto` routing):

| Kernel | vs Triton+Triton | vs HIP+Triton |
|---|---|---|
| `flydsl_opt`+Triton K6 (PR #4732) — unsafe conv | 1.39× | 1.05× |
| Fused FlyDSL VK (this PR) — safe conv, shipped default | 2.03× | 1.53× |
| Fused FlyDSL VK (this PR) — unsafe conv (`AITER_FAST_FP32_TO_FP16=1`) | 2.24× | 1.70× |

## Technical Details

**One kernel, two modes.** `chunk_gated_delta_h_gfx942.py` builds both the K5-only and the fused
kernel from one source, switched by a `COMPUTE_OUTPUT` compile-time flag. The fused build pairs
with `STORE_H=False` / `SAVE_NEW_VALUE=False`, which is what elides the two HBM drains.

The fusion is possible because K6's operands are already in LDS at the end of K5's chunk body:

| LDS buffer | Holds | K6 consumer |
|---|---|---|
| `lds_h` | the `h` snapshot (state *before* this chunk's update) | GEMM3 B-operand |
| `lds_kt` | `k` | GEMM4a B-operand |
| `lds_vnt` | the gated `v_new`, `[BV, BT]` | GEMM4b B-operand |
| `lds_w` | dead after GEMM1 → restaged as `q` | GEMM3 / GEMM4a A-operand |

The subtlety worth reviewing: GEMM3 needs the *pre-update* snapshot, which works only because
`lds_h` still holds it while GEMM2's result lives in registers and is never written back within
the iteration.

**LDS is the binding constraint.** Five buffers at `BT=64, K=128, BV=64` total exactly 64 KiB —
the gfx942 limit — which pins the kernel to one workgroup per CU. `q` reuses `lds_w` rather than
taking its own buffer; an `lds_A`-onto-`lds_h` aliasing path exists for configurations that would
otherwise overflow.

**Kernel instance selection is two closed-form rules.**

- *Which K5/K5+K6 instance* — This is driven by `H*N` (number of heads `x` number of sequences): 
`H*N <= 32 → bv16`, `H*N<= 80 → bv32`, `H*N> 80 → bv64w8`.
- *Fused vs separate* — fuse iff `ceil(V/BV)·N·H / CU >= 0.45`, where `BV` is the V-axis tile size of the instance 
that the heuristics selected.  In other words, used fused instance when it fills the device sufficiently.

**MI308 path is unchanged.** gfx942 covers MI300A, MI300X, MI308X, and MI325X . 
The CU count (`_device_cu_count()`) is used to discriminate between different chips: MI300X/MI325X have 304 CUs
while other chips have less. The `elif use_chunk_flydsl` branch in `chunk.py` routes to `chunk_gated_delta_rule_fwd_h_flydsl`
(VK kernel, this PR) only when `_device_cu_count() >= 304` and no flydsl_opt-only features are in use
(indexed state pool via `initial_state_indices`, `inplace_final_state`, or non-default `snapshot_dtype`).
All other callers (including every MI308 call path) fall back to `chunk_gated_delta_rule_fwd_h_flydsl_opt`,
preserving existing behavior.

**Bounds handling — reads and writes.** Every token-indexed read (`k`, `q`, `w`, `u`, `g`, `gk`)
uses a buffer descriptor rooted at the CTA's `(sequence, head)` with an exact `T_local` extent, so
a row past the sequence end is out of range of the descriptor and the hardware returns zero. 

The `v_new` and `o` **stores** are bounded by the same construction: a write past `num_records` is
discarded by the hardware, so the padding rows of a partial last chunk store nowhere and the
per-element tail guards on both stores are gone as well. 

**f32 → bf16 conversion.** `arith.truncf` (IEEE round-to-nearest-even), which preserves NaN and
Inf classification by construction. A faster non-NaN version is available as an
explicit opt-in, `AITER_FAST_FP32_TO_FP16=1`, which is ~15% faster on K5 and ~11% on the fused kernel,
but does **not** preserve NaN. Both are covered by a direct converter unit test.

**Other kernel work in this PR:** 
- tiled copy / tiled MMA throughout
- XCD chiplet remapping so CTAs sharing `k`/`w`/`gate` land on the same die (L2 hit rate improvement)
- cheap `f32→bf16` rounding path (gfx942 lacks `v_cvt_pk_bf16_f32`)

 ## Architectural changes (items 5 and 6)

The gfx942-fused-specific assets — compile cache, capability + speed predicates, BV/wave selector, launch, the two public entry points, and the fused-vs-separate router are now in a new file `gdn_fused_gfx942_kernels.py`.

- The old module keeps the separate-K5 pipeline and the shared shape/BV
  machinery and the new module imports those.
- Device/arch reads in the new module go through the old module.

### Benchmarks / helpers split from the test file (item 6c)

The original test + benchmark script is now split into:

- `op_tests/op_benchmarks/flydsl/bench_gdn_fused_k5k6.py`: the sweep + CLI (new
  `flydsl/` bench dir, matching sibling `triton/` and `hip/` dirs).
- `op_tests/gdn_common.py` — shared input builders and the PyTorch reference.
  `ref_chunk_gated_delta_rule_fwd_h` moved here out of the K5 test module.
- the test file keeps only correctness + routing tests.

### `ALWAYS` routing restructured (item 5)

Introduced one capability predicate `fused_gfx942_unsupported_reason()` (human-readable reason or `None`). `should_use_fused_gfx942` is now purely the speed question on top of it. `ALWAYS` tests capability and raises an error with a reason when unsupported. It no longer bypasses the `>=304 CU` (MI308) device guard.

## Correctness fixes (items 2, 3, 4)

### Item 2 — dense multi-batch `gk` view

The view was undersized (`T_flat*H*K`, one batch). Fixed.

However, `gk` (and `g`, `k`, `q`, `w`, `u`) now go through `_seq_view`, which roots the descriptor at this CTA's `(sequence, head)` and gives it an exact `T_local` extent. The descriptor no longer spans the whole tensor, so there is no batch term left
to get wrong. This makes the tail reads return hardware zero.

Another bug fixed in the process. The FlyDSL compile caches key on shape params only,  but the compiled kernel's C ABI is
   packed per tensor *rank*. The docstrings advertise `g` as `[B,H,T]` **or**   `[H,T]`; calling both spellings for one shape in a process crashes the second with `IndexError: tuple index out of range` in `<flydsl-cabi-fill>`. Fixed with `_canonical_gate_rank` (metadata-only reshape) in both wrappers.

Also added `_check_gk_shape`, the host-side guard. It is called in both the K5 VK entry point (`chunk_gated_delta_rule_fwd_h_flydsl`) and the fused launch (`_run_fused_gfx942`). It validates that `gk` spans all B batches, i.e., rejects `[T, H, K]` when `B=2`, forcing the caller to pass the full `[B, T, H, K]` tensor.

New tests: `test_fused_dense_multibatch`, `test_fused_gate_rank_spellings_interop`, `test_fused_rejects_undersized_gk`.

### Item 3 — NaN-safe masking

Every token-indexed read descriptor (`k`, `q`, `w`, `u`, `g`, `gk`) is now rooted at this CTA's `(sequence, head)` and bounded to `T_local` rows (`_seq_view`), so a row past the sequence end is out of range of the buffer descriptor and the
hardware returns zero. The out-of-bounds read is gone, not masked:

- the `k` address clamp and its value mask is deleted: a tail row can no longer
  address another sequence, and a hardware zero cannot be Inf or NaN.
- the `v_new` tail row mask is deleted: `w` and `u` read hardware zeros, so
  `v_new = u - w @ h` is already exactly zero on padding rows.
- the causal mask's two in-bounds terms is deleted: `q` and `k` read hardware
  zeros, so `A = q @ k^T` is already exactly zero there. Only the triangle
  comparison remains.

The stores are bounded the same way. `v_new` and `o` are written through descriptors rooted at this CTA's `(sequence, head)` with the same `T_local` extent, so a padding row addresses past `num_records` and the hardware
discards the write.

**gfx950 note:** the sibling `chunk_gated_delta_h.py` still carries the original `select`-based fix, not the structural one.

### Item 4 — f32 -> bf16 NaN conversion

`(bits + 0x8000) >> 16` carries into the exponent for any NaN with payload below bit 16, so `0x7F800001` -> `0x7F80` = +Inf.

Fix: `arith.truncf`. The conversion is now plain IEEE round-to-nearest-even. It preserves NaN and Inf classification by construction and  rounding is unbiased.  The old fast path survives as an opt-in behind `AITER_FAST_FP32_TO_FP16=1`.

All five candidates now pass `output_final_state=True`. Full sweep re-run on MI325X after all code changes landed. PR description updated with new numbers.

### yiijin · 2026-08-26 · CHANGES_REQUESTED

Thank you for adding the gfx942-native GDN K5 and fused K5+K6 support for MI300X/MI325X. The performance work and detailed analysis are appreciated.
Before merging, I think the following issues should be addressed:

#### 1. Benchmark mismatch

The baselines use `output_final_state=True`, while the fused candidates use `False`. Please align the workloads and rerun the benchmarks.

#### 2. Dense multi-batch `gk`

The `gk` view only covers `T_flat * H * K`, but dense `B > 1` addressing includes a batch offset.

- Size the view from the actual tensor.
- Add a `B=2, USE_GK=True` correctness test.

#### 3. NaN-safe masking

Tail and causal masks use multiplication by zero, which does not suppress NaN/Inf.

- Replace it with `select(valid, value, 0)`.
- Explicitly zero invalid tail `k` rows instead of redirecting them to row 0.

#### 4. Potential NaN conversion risk

`_to_bf16_fast()` can convert low-payload FP32 NaNs into BF16 infinity. Combined with multiplicative masking, this may hide or later reintroduce NaNs through `Inf * 0`.

Please preserve NaN classification and add VK/fused coverage for:

- Low-payload NaNs
- Signaling and quiet NaNs
- Positive and negative infinity

#### 5. Inconsistent `ALWAYS` behavior

`K5K6Fusion.ALWAYS` may be silently ignored after fallback, but it can also bypass the MI308 CU guard.

It should either:

- Guarantee that the fused path is used, or
- Fail explicitly when fusion is unsupported

#### 6. Code organization

The architecture-specific kernel and variant files are justified, but some responsibilities should be separated more clearly:

- `K5K6Fusion` is backend-neutral and should not live under Triton-private utilities, as this creates a FlyDSL → Triton-internals dependency.
- `test_flydsl_gdn_fused_k5k6.py` mixes correctness tests, routing tests, benchmarks, CLI handling, and input generation. Benchmarks should live under `op_tests/op_benchmarks/flydsl/`, with shared test helpers separated.
- `linear_attention_prefill_kernels.py` now owns architecture detection, heuristics, compilation, launch, validation, and routing. Consider moving the gfx942 fused compile/launch/heuristic logic into a dedicated host-side module.
