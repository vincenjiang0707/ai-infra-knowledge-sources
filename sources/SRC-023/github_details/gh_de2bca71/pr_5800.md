## 正文

## Motivation

On `gfx950`, `fused_clamp_act_mul` regression on Triton 3.8 at large-M prefill shapes up to 7.2%

| M | N (n_half) | Triton 3.4 | Triton 3.8 | delta |
|---|---|---|---|---|
| 16384 | 2048 | 34.02 us | 36.47 us | **+7.18%** |
| 8192 | 4096 | 34.44 us | 36.00 us | **+4.52%** |
| 16384 | 4096 | 62.26 us | 64.88 us | **+4.21%** |

The kernel was not tuned at M, as it was only tuned previously on row width (N). Essentially, `M=1` and `M=16384` at the same N received the same launch config. The triton path launches `grid=(M,)`, meaning one program per row, and `BLOCK_SIZE_N` is the whole row. In this case, `num_warps` is the only knob to be tuned, and past a few thousand rows, the grid alone fills the GPU. The shipped width-keyed value is tuned for small M and is too high for prefill. Decode (M <= 128) is unaffected and measures identically on both compilers.

Also, the benchmark for this kernel was not usable on main. It fails to import `_is_gluon_available()` and it crashes `rocprofv3` runs for shapes due to `rep` being hardcoded. Both issues are fixed here. 

## Technical Details

The kernel now checks the N-specialized `FUSED_CLAMP_ACT_MUL-N={N}.json` for the largest `M_GEQ_<x> <= M` before falling back to the existing `DEFAULT.json`, which is unchanged.

```
aiter/ops/triton/fusions/fused_clamp_act_mul.py                     +32 -8
op_tests/op_benchmarks/triton/bench_fused_clamp_act_mul.py          +10 -2
configs/gfx950/triton/fusions/fused_clamp_act_mul/FUSED_CLAMP_ACT_MUL-N=2048.json  (new)
configs/gfx950/triton/fusions/fused_clamp_act_mul/FUSED_CLAMP_ACT_MUL-N=4096.json  (new)
```

Tuned values (gfx950, from a `num_warps` sweep of 1/2/4/8/16 per shape):

| N | shipped | M >= 4096 | M >= 16384 |
|---|---|---|---|
| 2048 | 4 | **2** | **1** |
| 4096 | 8 | **4** | 4 |
| 512, 8192 | 1, 8 | unchanged (optimal) | |

### Benchmark fixes

- `is_gluon_available()` restored, as the benchmark didn't import properly. The guard now asserts properly.
- `--rep` made configurable, because the default 100 crashes `rocprofv3`. Make it an argument so that one can define the number of reps desired.
