## 正文

## Motivation

aiter has no Windows support: `__init__.py` force-enables `AITER_TRITON_ONLY` on `win32`, and the JIT layer assumes Linux-only tooling (`rocminfo`, `libamdhip64.so`, `/dev/null`, `rm -rf`, ELF linker flags). This wires the JIT and Python layers up to the Windows ROCm stack so CK- and HIP-based ops compile and run there.

## Technical Details

Toolchain discovery - ROCm tools ship as `.exe`/`.bat` wrappers on Windows, so executable lookup goes through a suffix-aware `_find_executable`, and `_find_rocm_home` falls back to `HIP_PATH`. `get_cxx_compiler` returns hipcc, the only compiler on Windows that can build both the .cpp and .hip sources.

GPU info - `chip_info` uses `hipinfo` in place of `rocminfo`, with a parser per output format, and loads the version-suffixed `amdhip64*.dll`. `--offload-arch=native` shells out to offload-arch, which cannot detect the GPU on Windows, so `native` resolves via `_detect_native()` instead.

Build system - ELF/GNU-ld-only flags (`-fPIC`, `-mcmodel=large`, `--gc-sections`, `-fvisibility=*`, `_GLIBCXX_USE_CXX11_ABI`) are excluded on Windows; `_ninja_path` escapes drive-letter colons, which ninja otherwise reads as rule separators; PE links against `pythonXYZ.lib`; `-D_USE_MATH_DEFINES` is added since the UCRT only declares `M_SQRT2` & friends under it. `compile_lib` drives hipcc with ninja instead of make.

Stale-lock fix - `FileBaton._pid_alive` no longer probes with `os.kill(pid, 0)` on Windows: CPython maps that onto `TerminateProcess`, so the liveness check would kill the very builder it was checking on.

Several shell idioms are also replaced with portable equivalents that are more robust on Linux too: `os.system("rm -rf")`, `os.popen("cat /proc/sys/kernel/numa_balancing")`, `echo ... | hipcc -`, and the shelled-out `hipcc` and `hipconfig` calls in `csrc/cpp_itfs/utils.py`.

`check_LLVM_MAIN_REVISION` needed more than the shell change. Its probe relies on CTAD, and at hipcc's default standard on Windows it failed on a template-argument error rather than on the `__host__ __device__` rule it is meant to measure, so the function returned the same value whatever the toolchain did. The probe is now pinned to `-std=c++20`, the standard the modules are built with. On Linux clang already defaults to `gnu++17`, so the answer there is unchanged.

`arch_info.get_arch()` now probes Triton on first call instead of at import. Since #5590 the flash-attention Triton backend imports `tuned_config_utils`, which imports `arch_info`, so importing it on a host with no GPU driver raised and then fell through to the `jax` fallback. This is what fails the Windows Smoke Test on `main`.
