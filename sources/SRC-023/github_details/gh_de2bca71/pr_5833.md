## 正文

## Motivation

VLLM can sometimes have poisoned kv cache where page index 0 contains NaNs. This PR addresses this by using an index valid for a request and using that as placeholder.

Besides that some tuning for models using triton 3.8.0+gitc0a142ff from vllm/vllm-openai-rocm:nightly-rocm100

# Sparse MLA per forward step: branch vs aiter main

aiter main `a75ba53de` vs `cagri/gluon_sparse_mla_invalid_tail_lanes` at `14ab4a706` · Triton 3.8.0 (`gitc0a142ff`) · MI355X (gfx950) · 16 heads per GPU (TP4)

Each cell is the attention kernel time for one forward step, summed over the model's sparse-attention layers: `main → branch (speedup)`, where speedup = main time ÷ branch time, so above 1.00× the branch is faster. C is the number of query rows in the step; C ≤ 1,024 is decode, C = 4,096 and 16,384 are prefill.

## Headline

64-bit loads (cache pool over 2 GiB, as in vLLM) with has_invalid on:

| Model | Decode, C = 1 | Prefill, C = 16,384 |
|---|---|---|
| DeepSeek-V4.1-Flash | 0.98× | 1.45× |
| DeepSeek-V4-Flash, 1M | 1.37× | 1.39× |
| GLM-5.2 · fp8 | 0.99× | 1.00× |

NaN-filled cache test (every cache row no valid index points at holds NaN): branch **40 / 40** correct, aiter main **20 / 40** (every has_invalid-on case fails: 16 return NaN, 4 return wrong values).
