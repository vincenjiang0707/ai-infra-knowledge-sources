# [PR #5648] [Triton/Gluon] [Bugfix][MLA] Mask the >2GB global_load path in mla_gluon decode (fixes gfx950 IMA)

source: https://github.com/ROCm/aiter/pull/5648
state: open | updated: 2026-09-24T22:25:04Z
labels: Triton/Gluon

## 正文

## Problem
On gfx950, serving **Kimi-K2.6** (8 heads/rank @ TP8, `kv_lora_rank=512`, bf16 KV) with vLLM crashes at decode warmup with a GPU **illegal memory access** inside the Gluon MLA decode kernel (`mla_gluon`). Its paged KV cache is far larger than 2 GB, so the wrapper sets `within_2gb=False` and KV is loaded via `global_load_to_shared` (64-bit offsets) instead of `buffer_load_to_shared`.

## Root cause
The `>2GB` `global_load_to_shared` calls (the `else` of each `if WITHIN_2GB:`) dropped the bounds `mask` that their `buffer_load_to_shared` siblings carry. A partial split block then dereferences out-of-bounds KV rows -> IMA. Additionally, `buffer_load` returns `0` for masked lanes while `global_load` leaves them undefined, so a mask alone yields **NaNs** on partial blocks -- `other=0.0` is required to match `buffer_load` semantics.

Introduced by #4474 (which added the int64 `>2GB` global_load path); still present on current `main`.

## Fix
Add `mask=<same predicate as the buffer_load sibling>, other=0.0` to all 8 `global_load_to_shared` calls in `_mla_gluon`.

## Test
Adds `test_mla_gluon_decode_over_2gb` to `op_tests/triton_tests/attention/test_mla.py`: it drives a >2 GB cache through the `global_load` path and asserts finiteness + bit-parity against the `<2GB` `buffer_load` reference on identical KV.

The two configs are chosen so that **every one of the 8 masked loads is executed**, keyed on `num_iter = cdiv(per_split, BLOCK_N=64)` with `per_split = max(64, ctx // NUM_KV_SPLITS)` and `NUM_KV_SPLITS = min(256 // batch, cdiv(ctx, 64))` (bh16bn64 regime):

| config | NUM_KV_SPLITS | per_split | num_iter | loads exercised |
|---|---|---|---|---|
| `(batch=8, ctx=777)` | 13 | 64 | 1 | prologue loads, last split is a **partial** block (mask + `other=0.0`) |
| `(batch=4, ctx=33000)` | 64 | 515 | 9 | prologue + **loop-body** loads + **epilogue** load (partial tail = 3) |

So `(4, 33000)` reaches `for i in range(num_iter - 2)` and the `if num_iter >= 2` epilogue — the paths a `num_iter == 1` config never touches.

```
pytest op_tests/triton_tests/attention/test_mla.py -k test_mla_gluon_decode_over_2gb
```

The fix itself was validated on MI350 (gfx950): the >2 GB path output matches the `buffer_load` reference (`max_abs_diff=0.0`), the standalone repro goes from memory-access-fault -> clean, and **Kimi-K2.6 `-tp 8` serves** on upstream vLLM.

AI assistance was used; changes were human-reviewed.
