## 正文

## Motivation

Prefill and decode send tokens to very different experts. On DeepSeek-V4 EP8, decode concentrates on a few hot experts, while prefill spreads almost evenly. The same MoE shape therefore wants different kernels in each case.

A single tuned table can't express that. The tuned key uses only the padded token count, and prefill and decode fall into the same buckets. Whichever resolves a bucket first fixes the kernel for both through `get_2stage_cfgs`' `lru_cache`. With CUDA graphs that is always decode, because every bucket is resolved during decode graph capture. The only way to tune decode today is to force the same kernels onto prefill.

This PR lets the caller say whether each call is prefill or decode (the "regime"), and gives each regime its own optional table.

## Summary of changes

- **`aiter/fused_moe.py`**
  - Adds `AITER_CONFIG_FMOE_PREFILL` and `AITER_CONFIG_FMOE_DECODE`, which name a tuned table per regime.
  - Adds `set_moe_regime()`, `get_moe_regime()` and the `moe_regime()` context manager for the host to select the active regime.
  - `get_2stage_cfgs` takes `moe_regime` as an argument, so it becomes part of the cache key. The two regimes get separate cache entries instead of overwriting each other. Both runtime callers (`fused_moe_` and `fused_moe_2stages`) pass the active regime.
  - A regime table replaces the default table but keeps the normal lookup behaviour: activation and tier fallbacks, and the heuristic when a shape is missing. It deliberately does not go through the `config_file=` path, which errors when a shape is missing.
  - When neither env var is set, or the host never sets a regime, behaviour is unchanged and the single `AITER_CONFIG_FMOE` table is used.
- **`aiter/configs/model_configs/moe_regime/dsv4_fp8fp4_ep8_tuned_fmoe_decode.csv`**
  - The decode table for DSV4-Pro FP4 on gfx950 with EP8 and shared-expert fusion (expert=49), token buckets 512 to 16384.
  - Stage1 is tuned against decode's real routing. Stage2 is left on the default geometry.
  - It lives in a subdirectory on purpose. aiter merges every top-level `model_configs/*tuned_fmoe*.csv` into the default table, which would apply the decode kernels to prefill too.
- **`aiter/configs/model_configs/moe_regime/README.md`**
  - Explains that tables in this directory are not merged into the default table, and which env var selects each one.

The host-side change, which sets the regime on each forward pass and pins decode during CUDA graph capture, is in a separate sglang PR.
