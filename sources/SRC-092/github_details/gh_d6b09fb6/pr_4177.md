## Description

Implements the platform split proposed in #4176.

- Keep the existing TONE entry and introduce an independent ROCm entry/configuration/lifecycle.
- Share cases, Python helpers, assets and orchestration under `scripts/e2e/` without duplicating suite logic.
- Preserve local `/test_run` paths through links and a read-only shared mount; materialize links on workers via `rsync -L`.
- Refresh environment/wheels on setup and run cases in isolated subshells. Preserve ROCm allocation isolation, pinned SSH, reset/postflight and stop-on-unhealthy protections.
- Update workflow/release verification paths, ownership, labels, docs and regression tests.

TONE uses the full inventory; ROCm uses core-4gpu. Suites require a complete checkout rather than copying an individual suite directory.

Related work: #4175 only extracts PR/nightly composite actions and explicitly excludes E2E splitting. #3600 adds a parallel TENT TONE job and overlaps some script paths, but this PR does not add TENT coverage. #3970 changes wheel build implementation rather than E2E lifecycle policy. Open issues/PRs were checked before filing this change.

Draft pending human line-by-line review and actual two-node TONE/ROCm E2E validation.
