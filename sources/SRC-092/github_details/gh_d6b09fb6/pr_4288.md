## Description

 Adds observability for the DFS space allocator by exposing three new master metrics: total capacity, allocated bytes, and backing-file count. Previously the DFS allocator had no metrics — `GetTotalCapacity()`/`GetUsedBytes()` were effectively dead code and shard count was only reachable via an ad-hoc admin HTTP endpoint. These metrics support both allocator modes:
- **shard mode** (`DfsGlobalAllocator`, default)
- **bucket mode** (`ImmutableBucketAllocator`)

New metrics:

| Metric | Meaning |
| --- | --- |
| `master_dfs_total_capacity_bytes` | Total DFS allocator capacity |
| `master_dfs_allocated_bytes` | Bytes currently allocated by the DFS allocator |
| `master_dfs_file_count` | Number of DFS backing files — shard files in shard mode, immutable bucket files in bucket mode |

Implementation notes:
- Added a mode-agnostic `GetFileCount()` to `DfsAllocatorInterface` so both allocators report through the same interface pointer. The name is deliberately generic ("file count") rather than "shard count" to stay accurate in bucket mode.
- Extended `TieredStorageUsageSnapshot` with a `DfsUsageSnapshot`, populated in`MasterService::GetStorageUsageSnapshot()` and projected into gauges via the existing `project_storage_usage()` path — no new threads or polling.
- Metrics are emitted both on the Prometheus `/metrics` endpoint (`serialize_metrics()`) and in the periodic human-readable admin log (`get_summary_string()`), where a `DFS: <allocated> / <capacity> (pct%) files=N` segment is appended after `SSD Storage`. The segment is omitted when DFS is disabled, so existing deployments' logs are unchanged.

These are distinct from the pre-existing `master_total_file_capacity_bytes` / `master_allocated_file_size_bytes` gauges, which track the 3fs/nfs disk-replica subsystem, not the DFS allocator.
