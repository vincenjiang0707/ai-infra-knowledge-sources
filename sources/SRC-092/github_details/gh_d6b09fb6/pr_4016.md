## 正文

## Description

Fixes #3926.

The Store build included Linux-only hugepage headers from a public header. That breaks macOS compilation for every translation unit including client_buffer_allocation.h.

The original revision also moved get_hugepage_size_from_env() into the header, which introduced missing declaration dependencies and left a second definition in the .cpp; this caused the Linux CTest, wheel, CUDA/ROCm/EFA, and TENT CI failures.

## Fix

- Guard Linux hugepage headers and fallback constants with __linux__.
- Keep get_hugepage_size_from_env() declared in the header and implemented once in the .cpp.
- On non-Linux platforms, preserve the requested allocation size, leave hugepage flags unchanged, and log a warning.
- Add the Transfer Engine include directory before Store targets are created when WITH_STORE=ON and WITH_TE=OFF.

The earlier #3894 TCP header change has been removed. Current Apple SDKs include infiniband/verbs.h, and a complete macOS TCP-only Transfer Engine wheel requires broader CMake, linking, and packaging work outside this focused Store fix.

## Why macOS

The goal is to restore the Mooncake Store build and local Store development path reported in #3926. This PR does not claim full macOS support for every Transfer Engine transport.

## Testing

- clang-format-20 --dry-run --Werror passes for the changed C++ files.
- git diff --check passes.
- A header smoke compile passes through both Linux and non-Linux preprocessor paths; only the unrelated CacheLib Slab type is stubbed.
- On a B200 GPU pod, a default WITH_TE=ON, WITH_STORE=ON, USE_CUDA=OFF production build completes 226/226 targets.
- A WITH_TE=OFF Store build compiles the Store source objects past the prior common.h failure; final linking in that mode requires the external libtransfer_engine that WITH_TE=OFF is designed to consume.
- Full GitHub CI was re-triggered for final head 2743980 and is pending runner capacity.
