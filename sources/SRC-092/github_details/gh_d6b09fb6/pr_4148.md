## 正文

## Summary
Fixes Master retaining SpdkWrapper heartbeat probe resources after NoF segment unmount (`ns_seg` qpairs, `probe_buffers_`, and unused `connected_ctrlrs`).

- Add `SpdkWrapper::CloseNofSegment()` to free the namespace qpair / probe DMA buffer and detach the controller when no other namespaces remain on it.
- Serialize `ProbeNofSegment` and `CloseNofSegment` with `probe_lifecycle_mutex_` so concurrent unmount cannot free resources mid-probe.
- Call release from both `UnmountNoFSegment` and `TryUnmountNoFSegmentByHeartbeat` (Mount already rejects duplicate `te_endpoint`s, so still-mounted namespaces on the same controller are preserved).
- Extend `nof_heartbeat_test` to assert the release hook runs for heartbeat unmount, selective unmount, and explicit unmount.

Fixes #4038

### Suppressed comments (4)

**mooncake-store/src/master_service.cpp:11273**
* This release uses the endpoint from a pre-unmount heartbeat snapshot rather than the segment actually found by `PrepareUnmountSegment`. If the snapshot races with an explicit unmount and a remount using the same UUID, the prepare/commit can remove the new segment while this call frees the old endpoint's resources, leaving the new endpoint cached. Capture the endpoint through `PrepareUnmountSegment(..., &te_endpoint)` and release that value, while revalidating the snapshot identity before committing.
```
    ReleaseNoFProbeResources(snapshot.segment.te_endpoint);
```
**mooncake-store/src/master_service.cpp:2808**
* The heartbeat thread takes a segment snapshot, releases its state/segment locks, and only then calls `ProbeNoFSegment`. An explicit unmount can therefore run this release first; the stale heartbeat iteration then reopens the endpoint through `OpenNofSegment` after `CloseNofSegment`, leaving a new qpair and probe buffer cached with no later unmount to remove them. Coordinate probe admission with unmount, or revalidate that the segment is still mounted immediately before opening it.
```
    ReleaseNoFProbeResources(te_endpoint);
```
**mooncake-store/src/spdk/spdk_wrapper.cpp:392**
* `ProbeNofSegment` can return `completion_timeout` while the submitted read is still outstanding, but this path frees the qpair immediately. Releasing a qpair with an in-flight SPDK request can fail or leave a completion using the released qpair, so heartbeat-triggered cleanup after a timeout may crash or corrupt the probe state. Cancel/drain the request before freeing the qpair, or defer qpair/controller cleanup until no I/O remains.
```
                        spdk_nvme_ctrlr_free_io_qpair(ns_it->second->qpair);
```
**mooncake-store/tests/nof_heartbeat_test.cpp:145**
* These tests replace the default release callback with a recorder, so they verify only that the Master path invokes a hook; they never exercise `CloseNofSegment` or its qpair, DMA-buffer, and shared-controller cleanup. A regression in the default callback or wrapper cleanup would still pass. Add a focused USE_NOF/SPDK test using the new state helpers that covers final release, retention with another namespace, and timeout cleanup.
```
    service->SetNoFProbeReleaseFnForTesting(
        [&release_mutex, &released_endpoints](const std::string& endpoint) {
            std::lock_guard<std::mutex> lock(release_mutex);
            released_endpoints.push_back(endpoint);
        });
```
