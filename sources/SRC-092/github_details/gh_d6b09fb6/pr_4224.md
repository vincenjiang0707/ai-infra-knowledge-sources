## Description

Follow-up to #3946 (defect A + log rate-limiting). #3946 capped burst-escalation (cooldown 30s vs 300s) and rate-limited the failure-storm logs, but left `available()` as a mutating admit used as a predicate and dropped Half-Open/probing to this follow-up. A reviewer's prerequisite: split admit vs query and track in-flight probes.

## State machine: Closed → Open → Half-Open → Closed/Open

| State | `isAvailable()` | `admit()` | On success | On failure |
|---|---|---|---|---|
| **Closed** (`!paused()`) | true | true (no-op) | — | `markFailed` arms Open (defect A: fresh pause only) |
| **Open** (`paused()`, `now < resume_time`) | false | one probe per `probe_interval_` (in-flight gated) | `markRecovered` → Closed | `markFailed` no-op (was paused) |
| **expired-Open** (`paused()`, `now >= resume_time`) | false | transition to Half-Open, one trial | `markRecovered` → Closed | `markFailed` escalates `*= 2`, re-arms Open |
| **Half-Open** (`paused()`, `half_open`) | false | false (trial in flight) | `markRecovered` → Closed, backoff reset | `markFailed` escalates `*= 2`, re-arms Open |

`resume_time` stays armed through Half-Open so `paused()` stays true. **Escalation happens only on a probe/trial failure, never on clock expiry** — this removes the "expiry fully reopens" path that slammed a still-dead peer with every slice and re-triggered the storm at 30s/60s/120s.

## The split

`available()` conflated query and admit. Split:
- `isAvailable(l, r) const` — pure predicate (`!paused()`). No mutation, no `updateBestMapping` → recursion gone. Used by `updateBestMapping` and queries.
- `admit(l, r)` — the only mutating admit. Closed → true; Open → one probe per `probe_interval_` (in-flight gated); expired-Open → Half-Open trial; Half-Open → false.
- `cancelProbe(l, r)` — clears an armed probe/trial on a pre-wire failure (see below).

## In-flight tracking

`admit()` arms `probe_in_flight` at selection, but selection ≠ posting. A slice that arms a probe then never reaches the wire orphans the flag and strands the rail. Three paths, all handled:

1. **GDR-exclusion after admit** (`selectFallbackDevice`): GDR check moved **before** `admit`, so a probe is never armed on a GDR-excluded pair.
2. **getEndpoint-null re-queue** (`asyncPostSend`): `cancelProbe` before `submitFromTick`.
3. **HW-reject re-queue** (`asyncPostSend`): `cancelProbe` before `submitFromTick`.

`cancelProbe` clears `probe_in_flight` and reverts `half_open` to expired-Open. No-op when no probe is in flight (normal transfers), so callers invoke it unconditionally on re-queue. Single-threaded per-worker ownership (`WorkerContext::rails[machine_id]` is one `RailMonitor` on one worker thread) makes a `bool` sufficient.

## Out of scope

- **Store-kill**: a probe still hits the dead old port until master drops the old segment (~51s). That is master-side `unmount_expired_mem_segment` / stable segment names, not RailMonitor backoff. Half-Open only stops expiry from re-flooding the dead port; a fresh replica is reached within one `probe_interval` of a successful trial.

## Tests (`tent/tests/rail_monitor_test.cpp`):
- `BurstFailuresDoNotEscalateCooldown` (probing disabled): 8× `markFailed`; `admit()`=true at 1.5s (cooldown stayed 1s), false if escalated to 256s.
- `TrialFailureEscalatesCooldown` (probing disabled): trial fail → 1→2s; 2s expires → trial.
- `TrialSuccessResetsBackoff` (probing disabled): trial success → Closed; next pause uses 1s, not 2s.
- `ExpiryAdmitsOneTrialNotFullReopen` (probing disabled): expiry `admit()`=true, next `admit()`=false (in-flight).
- `InFlightProbeBlocksSecondAdmit` (**default** `probe_interval=1s`): `admit()`=true (probe), `admit()`=false (in-flight), `markRecovered` clears → new probe arms. Exercises in-flight directly, not hidden by `probe_interval=60`.
- `CancelProbeRevertsArmedTrial`: trial armed → `cancelProbe` → re-admits; no-op on Closed.

10 baseline tests renamed `available()`→`isAvailable()`; `CooldownDoesNotCarryOverAfterRecovery` adapted (final expiry assertion → `admit()` with probing disabled).

Probing-disabled tests use `probe_interval=60` so a *cooling* rail's `admit()`=false while an *expired* rail's `admit()`=true — discriminating cooldown **duration**. `InFlightProbeBlocksSecondAdmit` uses the default 1s to test in-flight directly.

### he-yufeng · 2026-09-19 · COMMENTED

Mechanism read of the state machine plus a local build and test run on this head.

The split is the right call: `isAvailable()` as a pure predicate (never mutates, never calls `updateBestMapping`) closes the recursion the old mutating `available()` had through the mapping rebuild, and `admit()` owning all transitions makes the four states legible. The invariant set holds where I probed:

- Open-phase probes admit at most one per `probe_interval_` and `probe_in_flight` blocks the race; a probe failure during Open is a no-op for escalation, so defect A stays fixed, and a probe success closes the rail early, which is the transient-fault win.
- Expired-Open admits exactly one trial and Half-Open blocks everything else until it resolves; trial failure is the only escalation point for a paused rail, which is the correct reading of "elapsed time does not prove health".
- `markFailed` arming `last_probe_time = now` at pause start is a nice catch; without it the epoch default would fire a probe immediately and defeat the throttle.
- The workers wiring is careful in both directions: the two pre-wire failure paths call `cancelProbe` so an armed probe is never orphaned by a slice that never reached the rail, and the GDR exclusion check moved ahead of `admit()` so a probe is never armed on a rail GDR would reject. Those two orderings are what keep the in-flight flag total.

Tests are real and discriminating: the cooldown suites pin probing off so `admit()` distinguishes cooling from expired, the escalation test measures the 1s to 2s doubling on the trial result rather than the clock, and the in-flight test runs the default interval so the probe path itself is exercised.

Two non-blocking notes:

1. `admit()`'s check-then-set on `probe_in_flight` is not atomic, and the rail map is shared across worker threads, so two workers can both arm a probe in the same window. The blast radius is bounded (one extra probe on the wire, and the second failure lands in the no-op error-count path), and the pre-existing code had the same racy shape, so this is not a regression; worth a comment or a future lock if probe cost ever matters.
2. `cancelProbe` leaving `last_probe_time` untouched means a cancelled Open-phase probe still holds the interval, delaying the next probe by up to `probe_interval_`. At the 1s default that is fine; if an operator raises the interval, a pre-wire failure strand plus a cancelled probe delays recovery probing by that much. Deliberate enough, just worth knowing.

Verified locally: configured the tent-only build (`USE_TENT=ON`, Release) on this head in the project's build container and ran `tent_rail_monitor_test`: 16/16 pass. I did not exercise the RDMA path on hardware.


### alogfans · 2026-09-20 · COMMENTED

`cancelProbe()` handles the retry paths below, but `admit()` can also arm a probe/trial before `generatePostPath()` finishes.

For example, a later post-path validation failure—or cancellation after path generation but before `submitSlices()`—means the slice never reaches the wire, so neither completion callback clears `probe_in_flight`. In the Half-Open case, this leaves the rail permanently blocked.

Please ensure every pre-wire exit after a successful `admit()` rolls the admission back, and add a regression test for an aborted Half-Open trial.
