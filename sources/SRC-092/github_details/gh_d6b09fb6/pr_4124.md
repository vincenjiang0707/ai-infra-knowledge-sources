## Description

This PR implements the DFS immutable Bucket allocator proposed in:

- RFC: https://github.com/kvcache-ai/Mooncake/issues/3641

It introduces a pluggable `GlobalAllocatorInterface` for DFS replica allocation while preserving the existing `DfsGlobalAllocator` as the default `shard` implementation.

A new `ImmutableBucketAllocator` can be selected with:

```bash
MOONCAKE_DFS_ALLOCATOR=bucket
```

The Bucket allocator stores objects as aligned, append-only immutable entries in fixed-capacity Bucket files. Buckets are created on demand and reclaimed in LRU order.

The existing `DistributedFSDescriptor` wire format is unchanged. In Bucket mode, the existing `shard_idx` field carries the Bucket ID, preserving serialization compatibility.

### Main changes

#### Pluggable DFS allocator

- Extract `GlobalAllocatorInterface` as the Master-facing DFS allocation contract.
- Adapt `DfsGlobalAllocator` to implement the interface.
- Keep `shard` as the default allocator with unchanged behavior.
- Add configuration parsing and validation for `shard` and `bucket`.

#### Immutable Bucket allocation

- Create fixed-capacity Bucket files on demand.
- Store values as aligned, append-only entries:

  ```text
  [value bytes][zero alignment padding]
  ```

- Track entries through `PENDING`, `COMMITTED`, and `TOMBSTONE` states.
- Never overwrite entries or reuse tombstoned or rolled-back ranges.
- Assign monotonically increasing Bucket IDs.
- Allow ordered batch allocation across multiple Buckets.
- Roll back all reservations if any allocation in a batch fails.
- Match complete descriptors when committing, freeing, or updating entries.
- Seal full Buckets and create new ones up to the configured limit.

#### Bucket-level LRU eviction

- Track access and reclaim complete Buckets in LRU order.
- Exclude the active Bucket and Buckets containing pending or protected entries.
- Lock affected metadata shards in a stable order and validate every live entry against its exact DFS descriptor.
- Abort the entire eviction if any entry is processing, leased, pinned, or otherwise invalid.
- Remove replicas from metadata before deleting the Bucket file. Failed file deletion keeps the Bucket charged against capacity for a later retry.
- Trigger reclamation at configured watermarks and when allocation is exhausted.

#### Synchronous buffered Bucket I/O

- Extend the filesystem adapter to open existing files without creating them.
- Use synchronous buffered positional I/O with short-lived descriptors for Bucket requests, while retaining cached descriptors for shard files.
- Handle interrupted and partial POSIX operations, treating zero progress, premature EOF, and incomplete transfers as errors.
- Validate Bucket paths, IDs, descriptor alignment, object sizes, and ranges before I/O.
- Never create a file implicitly for an invalid or missing Bucket descriptor.

#### Master and Client integration

- Select the configured allocator during Master initialization and allocate DFS replicas through the common interface.
- Keep Bucket entries pending while replicas are `PROCESSING`, then commit them in `PutEnd` before publication.
- Tombstone reservations when writes are revoked, removed, or replaced.
- Keep DFS writes synchronous and revoke failed writes so incomplete data is never published.
- Attempt one validated whole-Bucket eviction when Bucket capacity is exhausted.
- Preserve existing shard expansion and eviction behavior in `shard` mode.

#### Configuration

The following settings are introduced:

```bash
MOONCAKE_DFS_ALLOCATOR=shard | bucket
MOONCAKE_DFS_BUCKET_CAPACITY=1073741824
MOONCAKE_DFS_MAX_BUCKET_COUNT=64
```

The existing DFS settings continue to configure common filesystem and eviction behavior:

```bash
MOONCAKE_DFS_ROOT_DIR
MOONCAKE_DFS_FS_ADAPTER
MOONCAKE_DFS_ALIGNMENT
MOONCAKE_DFS_EVICTION_ENABLED
MOONCAKE_DFS_EVICTION_HIGH_WATERMARK
MOONCAKE_DFS_EVICTION_LOW_WATERMARK
MOONCAKE_DFS_EVICTION_CHECK_INTERVAL
```

`MOONCAKE_DFS_BUCKET_CAPACITY` must be nonzero, aligned to `MOONCAKE_DFS_ALIGNMENT`, and representable by the filesystem interface. `MOONCAKE_DFS_MAX_BUCKET_COUNT` must be positive.

#### Documentation

- Document the immutable Bucket layout and lifecycle.
- Document allocator selection and Bucket-specific environment variables.
- Describe allocation, rollback, commit, and whole-Bucket eviction.
- Document current operational and recovery limitations.

### Compatibility

- `shard` remains the default allocator with unchanged allocation, eviction, and I/O behavior.
- `DistributedFSDescriptor` serialization remains unchanged, so existing clients can continue using shard descriptors without configuration changes.
- Bucket capacity settings affect only `bucket` mode.
- Shard count and capacity settings do not control Bucket allocation.

  -DUSE_CUDA=OFF \
  -DUSE_HIP=OFF \
  -DUSE_HYGON=OFF \
  -DUSE_3FS=OFF \
  -DUSE_TCP=ON

cmake --build build --target \
  dfs_immutable_bucket_allocator_test \
  dfs_immutable_bucket_backend_test \
  dfs_immutable_bucket_client_test \
