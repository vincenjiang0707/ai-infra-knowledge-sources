## Why is this change needed?

Fix CUDA suballocation registration in the Transfer Engine's Data Direct path introduced by #4267. Data Direct requires a system-page-aligned IOVA, but a tensor inside a CUDA allocation can start between page boundaries, causing registration to fail with `EOPNOTSUPP`.

For an 8 MiB + 1 KiB tensor at a page-aligned allocation base + 1 KiB, on a system with 64 KiB pages:

```diff
- IOVA=base+1024, DMA-BUF offset=1024, length=8389632
+ IOVA=base,      DMA-BUF offset=0,    length=8390656
```

The logical buffer bounds stay unchanged. Chunking accounts for the alignment prefix so the expanded MR stays within `max_mr_size`; deregistration restores fork state over that same expanded range. Ordinary registration and host-memory behavior are unchanged. No new configuration is needed.

## Test Plan

- On Data Direct hardware with 64 KiB pages, the same GPU tests produce three registration failures (`EOPNOTSUPP`) against the pre-fix implementation; all four cases pass with the fix.
- Preserve aligned and unaligned loopback RDMA WRITE payload checks, including a write across the final chunk boundary under a 64 MiB MR limit. Interior-buffer cases also cover unaligned lengths and offsets.
- Pass `dmabuf_export_test`, `rdma_context_reprobe_test`, and `rdma_buffer_range_index_test`.
