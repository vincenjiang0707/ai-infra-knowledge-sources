## Description

RDMA `submitPostSend` currently concatenates `server@nic` into a per-slice
`std::string` on every descriptor. Mapping, batched enqueue, CQ drain, and
redispatch then copy or hash that owned string again.

This change interns those paths in a process-lifetime pool and points
`Slice` at the interned string. Pointers outlive a COW `SegmentDesc`
replacement. Interned paths are rebuilt from `devices` / `name` /
`rdma_server_name` in `addLocalSegment` and `decodeSegmentDesc`, not from
`rebuildBufferRangeIndex()`. `internedNicPath()` falls back to the intern
pool without mutating the snapshot when sizes differ, and logs
`LOG_FIRST_N(WARNING, 8)` on that path. `addLocalSegment` requires exclusive
ownership of `desc`; `allocateLocalSegmentID` copies before mutating. Local
buffer COW publishes only after rebuild. `peerNicPath()` returns the interned path
when set, and falls back to `peer_nic_path` for transports that still
fill the owned string. Batched enqueue uses `peerNicPath()` so an empty
owned string does not send every slice to the same worker.

Measured `submitTransfer` p50 on same-host H20 / `mlx5_bond_0` RDMA (classic
tebench, VRAM, GPU0→GPU1 READ, 4 KiB blocks). First two iterations skipped.
Wait / bandwidth is completion time and is not claimed. Baseline is current
`origin/main` (already includes #4259, #4273, and #4279).

| batch | origin/main | this PR | change |
|---:|---:|---:|---|
| 4,096 | 1.318 ms | 0.529 ms | −60% |
| 65,536 | 11.973 ms | 8.997 ms | −25% |
| 207,360 | 40.331 ms | 30.089 ms | −25% |
