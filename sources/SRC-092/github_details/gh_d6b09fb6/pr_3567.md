## Description

Add partial matrix reads for dense two-dimensional DataProto `batch` fields.

The public `batch_slices` mapping selects a column slice per field and composes
with the existing `rows` selection. A single M x N implementation covers row
batches, column batches, and general submatrices without separate code paths.

The implementation:

- plans byte ranges from matrix shape, dtype, selected rows, and column slice;
- coalesces consecutive full-width rows;
- uses one BufferPool lease and one `get_into_ranges` call across selected
  fields, DataProto stages, and payload chunks;
- keeps NumPy results writable and rewrites native tensor metadata for the
  sliced shape;
- commits caller destinations only after every selected field and the final
  DataProto result have been constructed successfully;
- falls back to regular materialization when ranged reads are unavailable or
  the request exceeds the range or physical-fragment limits.

The fast path guarantees one batched ranged call. The fallback is intentionally
whole-request and does not guarantee a single backend call; this keeps the
destination commit semantics and the hot path small. Logical ranges are capped
per field, while physical fragments are capped at 4096 across the entire
batched request before BufferPool allocation.

The append write path is unchanged. Dense matrix fields added through
`append_dataproto_fields()` are resolved from their existing stage refs and can
participate in the same batched partial read.
