## Description

Avoid mandatory CPU staging when the selected remote memory replica can be
read directly into a GPU destination through Transfer Engine.

## Stack

This is **[3/3]** of the RFC implementation stack:

1. #2966 — HOST_NUMA/Fabric Transfer Engine prerequisite (merged).
2. #3335 — Provider-owned EGM Store pool.
3. #3431 — direct remote-memory reads into GPU destinations (this PR).

The head branch is a strict child of #3335. With #2966 merged, GitHub now
shows the two remaining Store commits against `main`. The logical review
increment for this PR is still the four-file direct-read change. It will be
rebased onto `main` after #3335 merges.

## Problem

Remote memory reads into GPU buffers fall back to CPU staging even when
Transfer Engine can write directly to the destination. Direct-read eligibility
must follow the selected replica's transport, which can differ from the
protocol requested at client setup.

The staging path adds a CPU allocation and host-to-device copy, which can
become the throughput bottleneck for cross-node paths such as EGM to HBM.

## Fix

The private direct-read predicate now receives the selected
`Replica::Descriptor` and uses the memory replica's actual
`buffer_descriptor.protocol_`:

| Selected replica | Destination behavior |
| --- | --- |
| `nvlink` | Ordinary CUDA destination is passed directly to Transfer Engine |
| `rdma` | Direct only when the full destination range is Store-registered |
| Other protocols | Existing CPU staging fallback |

The affected full, ranged, and batched GPU-read paths pass the selected replica.
The newer snapshot APIs retain their existing registration and lease contracts.
There is no new Transfer Engine introspection API, public C++/Python API, wire
schema, or configuration change.

## Relationship to existing work

- #3197 removed staging for same-process GPU reads but intentionally retained
  the remote path.
- RFC #2479 proposes broader zero-copy read/write work. This PR only fixes the
  remote memory-read decision and does not add the broader lifecycle changes.
- RFC #2914 and #3335 expose the performance impact through cross-node
  EGM-to-HBM reads.
