# [PR #4335] [Bugfix][Store] Avoid placing multiple replicas on the same hosts

## 正文

## Description

  `RandomAllocationStrategy` placed an object's replicas on **distinct segments** but not on **distinct hosts**. When one machine contributes several segments (a large mount split at `max_mr_size`,
  or multiple NICs), two replicas could land on that machine's two segments — so losing one host lost both copies and defeated the fault tolerance `replica_num >= 2` is meant to provide. The only
  host-aware placement was `LOCAL_FIRST` / `prefer_alloc_in_same_node`, i.e. single-replica *affinity*, not spreading.

  **Fix — make placement host-aware:**
  - `AllocatorManager` gains an optional `segment -> host` map (built in snapshots by inverting the existing `segments_by_host_` index) and a `GetHost()` accessor. The new `Snapshot` argument is
  optional, so existing callers are unchanged.
  - `RandomAllocationStrategy::Allocate` runs two passes: **pass 1** places replicas on different hosts; **pass 2** runs only if pass 1 fell short *and* the same-host check was actually applied,
  dropping the check so the replica count is never lower than before (best-effort preserved).
  - With no host info (empty map — e.g. the NoF live manager), behaviour is identical to the previous single pass.

  **Effect:** with hosts A (segments A1, A2) and B (B1), a 2-replica put now lands on {A, B} instead of possibly {A1, A2}.

  **Scope:** memory path only (allocates on a snapshot). NoF (live manager) and `RankedAllocationStrategy` (`FreeRatioFirst`) are follow-ups — there `GetHost()` returns `""`, so the check is safely
  skipped.
