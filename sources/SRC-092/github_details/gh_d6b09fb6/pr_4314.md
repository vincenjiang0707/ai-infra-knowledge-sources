## Description

Implements the Store-side portion of [RFC #4255](https://github.com/kvcache-ai/Mooncake/issues/4255).
K3 prefix lookups may inspect multiple KDA checkpoints while restoring only one. This PR adds `GrantLeasePolicy` to `BatchProbeKey` to support selective lease acquisition:
- `None`: preserves the existing lease-free probe behavior.
- `LastHitOnly`: selects the last complete candidate in caller order, leases all its keys, and returns a selected-only mask.
`candidate_size` defines how many consecutive keys form a candidate. Completeness checks and lease grants run under ordered metadata-shard locks, preventing normal eviction between validation and leasing.
The policy is exposed through the C++ client/RPC layers and Python binding. Existing existence APIs, single-key probes, soft-pin behavior, and shared-group lease semantics remain unchanged. Inference-engine integration is left to follow-up PRs.

**Compatibility:** batch-probe RPC signatures change. Master, client daemon, and clients must be upgraded together; mixed-version batch-probe calls are not supported.
