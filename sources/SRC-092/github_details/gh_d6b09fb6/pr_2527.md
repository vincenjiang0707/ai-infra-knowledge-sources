# [PR #2527] fix(metadata): make rpc_meta republish idempotent in the Python server

## 正文

## What

The Python HTTP metadata server (`mooncake-wheel/mooncake/http_metadata_server.py`) rejected **every** duplicate `rpc_meta` key:

```python
if key.find("rpc_meta") != -1 and key in self.store:
    return web.Response(text='Duplicate rpc_meta key not allowed', status=400, ...)
```

So a node that re-publishes its own unchanged metadata (a normal occurrence on reconnect/retry) gets a `400` instead of a no-op success.

The C++ metadata server already handles this as idempotent — #2311 made it compare the stored value against the request body, returning `200 metadata unchanged` for an identical value and only rejecting a genuinely conflicting one. This PR mirrors that logic in the Python server:

```python
if key.find("rpc_meta") != -1 and key in self.store:
    if self.store[key] == data:
        return web.Response(text='metadata unchanged', status=200, ...)
    return web.Response(text='Duplicate rpc_meta key not allowed', status=400, ...)
```

## Test plan

Added `mooncake-wheel/tests/test_http_metadata_server.py`, which exercises `_handle_put` directly — no compiled engine, server, or network required (it only imports the pure-Python module and mocks the request). It covers the first write, an idempotent re-publish (the regression), a conflicting value (still rejected), and a non-`rpc_meta` overwrite.

```
python -m unittest mooncake-wheel.tests.test_http_metadata_server
# Ran 4 tests — OK
```

The idempotent-republish case fails on `main` (`400 != 200`) and passes with this change. The test is engine-free and could be wired into CI alongside `test_safetensor_functions` if desired.
