## Description

Fix classic RDMA auto-GID recovery when a GID can reach RTR but repeatedly
fails on the data path with `IBV_WC_RETRY_EXC_ERR`.

The existing retry path could rebuild an endpoint while selecting the same
ranked GID again. This change tracks failures by peer connection identity and
uses a bounded recovery sequence:

1. Retry the current GID once with a fresh endpoint/QP.
2. If a distinct fresh endpoint also fails, coordinate the next ranked GID
   with the peer and rebuild the connection.
3. Continue through the ranked candidates (for example, GID 5 -> 7 -> 3)
   until the configured limit is reached.

Any successful data completion clears the failure streak, so a temporarily
unavailable GID is retained when the fresh-QP retry succeeds. After a fallback
connection succeeds, the selected GID remains in use; no background probing of
earlier GIDs is scheduled.

The negotiated `auto_gid_rank` handshake field keeps both peers on the same
candidate. Its presence is optional for compatibility with older peers, and an
explicit `MC_GID_INDEX` continues to bypass automatic selection. The maximum
fallback rank is controlled by `MC_AUTO_GID_MAX_RETRIES` (default: 2; set to 0
to disable auto-GID fallback).

The focused Linux suite passed on the final commit. It covers ranked candidate
selection, GID 5 -> 7 -> 3 traversal, duplicate-CQE suppression, fresh-QP
retry, success reset, monotonic rank synchronization, candidate exhaustion,
optional handshake-field compatibility, and coordinated endpoint state.

A two-host physical RDMA test started both peers on rank 0/GID 5, injected
data-path retry exhaustion across fresh endpoint generations, and observed both
peers advance to rank 1/GID 7. A 4 MiB write followed by a 4 MiB read completed
with byte-for-byte comparison success.

The complete `transfer_metadata_test` binary has an unrelated existing
fixed-port reuse failure in `TransferMetadataTest.RpcMetaEntryTest` when all
cases run sequentially. The production serialization round-trip that covers
the new handshake field passes independently, as shown above.
