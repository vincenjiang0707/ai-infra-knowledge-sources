## Description

Fifth slice of the Mooncake Conductor upstreaming series, on top of the zmq subscriber. Wires the ingest path into the prefix index and exposes the query surface, and produces the mooncake_conductor binary:

- kvevent/event_manager.{h,cpp}: EventManager owns the indexer, the per-service ZMQ subscribers and the coroutine HTTP server. Start subscribes to every configured service concurrently and reports individual failures through the log rather than failing as a whole, so one unreachable publisher cannot block startup. Stop is idempotent. UnsubscribeFromService stops its ZMQ client outside the manager lock, because the client's loop thread can still be dispatching a batch that needs the manager. Registers five routes: /query, /register, /unregister, /services and /global_view.
- kvevent/event_handler.cpp: KVEventHandler implements the zmq EventHandler interface for the three publisher protocols, dispatching each batch to per-event handlers that translate into indexer mutations. Mooncake Store publishes one logical hash as several physical objects, such as separate key and value components, so pool_bindings_ tracks the physical set per logical key and only removes the index entry once the last component is gone.
- Handler lifecycle: MarkUnavailable stops admitting new callbacks and WaitForIdle waits for the ones already admitted, with DispatchLease releasing the in-flight count on every exit path. This is what lets a service be unsubscribed while its subscriber thread is mid-batch.
- kvevent/config.{h,cpp}: reads the static service list from CONDUCTOR_CONFIG_PATH. A missing file warns and yields an empty list; a malformed file is fatal, since silently serving no cache would be worse than failing to start.
src/main.cpp: resolves the log level, parses the config, starts the manager and HTTP server, then waits for SIGINT/SIGTERM.
Two adaptations were needed against the merged common layer, both beyond the mechanical namespace nesting:
  main.cpp consumed a LogLevel enum that no longer exists. https://github.com/kvcache-ai/Mooncake/pull/3825 replaced it with LogLevelConfig, which already reports glog's own values, so the four-case switch collapses to two assignments.
  Parsing helpers come from mooncake-common rather than being reimplemented: medium normalization uses AsciiToLower (ascii_string.h) instead of a local std::tolower transform, which also drops a locale-sensitive path from a comparison against ASCII literals, and the cache-group check uses TryParseInteger<int64_t> (integer_parser.h). Both substitutions were checked against the previous local implementations over 6470 inputs, including every single byte, the medium spellings the call sites compare against, signed and unsigned int64 boundaries and overflow, embedded NULs, and padded and whitespace-wrapped forms.
  yalantinglibs is guarded with if(NOT TARGET yalantinglibs::yalantinglibs): the top-level build already provides it through mooncake-common, and its config.cmake mutates an imported target owned by the parent scope, so it cannot run twice.

Verified: builds standalone and under the top-level configuration, and conductor_test passes (169 tests across 34 suites, up from 113 across 25).
