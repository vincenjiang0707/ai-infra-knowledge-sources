# [PR #4311] [CI] Write the sccache GHA cache only from push and scheduled builds

## Description

Make PR builds read the sccache GitHub Actions cache without writing to it. Only `push` and `schedule` runs write.

**Why.** GitHub lets a PR run read caches from its own ref and from its base branch (`main`), but not from other PRs. So a PR run's sccache writes only help that same PR's later runs. They still count toward the repo's 10 GB Actions cache limit, though.

Snapshot on 2026-09-24 08:05 UTC:

- The cache held 7351 entries (11.0 GB), all of them `sccache/*`. That is over the limit, so least-recently-used eviction is running.
- 2700 entries (5.46 GB) belonged to just 7 open PRs.
- The least-recently-used entry left in the cache was last read at 06:49. In other words, any entry that goes about 75 minutes without a read gets evicted, and that includes `main`'s.

The effect shows up in CI logs:

- **Main's cache works.** A fork PR's first run (`vin/gid-fix`, run 35947527377) hit 243 of 252 compiles in `build-wheel (3.10)`. Those hits could only have come from `main`'s entries.
- **A PR's own entries rarely survive long enough to matter.** For `tent-diagnostic-core`, two pushes 48 minutes apart took tent-ci hits from about 60% to about 98%. Two pushes about 4 hours apart stayed near 60%, because the earlier entries had been evicted.
- **PR writes push out main configurations that run less often.** In PR 4305's runs, the new arm64 EFA jobs hit 0 of 230 compiles on two pushes 66 minutes apart.

With PRs read-only, the whole cache goes to `main` and `release/**` entries, which every PR can read.

The E2E workflow (`e2e-ci.yml`) is also affected. Its `pull_request_target` and `workflow_dispatch` triggers build PR code through `ci_rocm.yml` under `main`'s cache scope. Those builds now read the cache but no longer write into `main`'s.

**How.** Set `SCCACHE_GHA_RW_MODE` (supported since sccache 0.18, the version the action installs) wherever `SCCACHE_GHA_ENABLED` is set for a workflow that PR code can reach:

- `ci.yml`
- `ci_rocm.yml`
- `_build-wheel.yaml`
- `_build-efa-wheel.yaml`

In reusable workflows, `github.event_name` is the caller's event, so the rule follows the trigger that started the run. `nightly.yml` only runs on schedule or manual dispatch and is unchanged.

**Trade-off.** A PR no longer reuses its own objects from its previous push. Under the current ~75-minute eviction window, that reuse was already unreliable.
