## Description

#4289 added support for building `mooncake_master` on macOS, but no CI job covers it, so Linux-only changes can silently break it again. This PR adds a separate `Build (macOS)` workflow (`.github/workflows/ci-macos.yml`) that:

- runs on the GitHub-hosted `macos-15` (arm64) runner, triggered on push/PR to `main` / `release/**` when `mooncake-*/**`, `extern/**`, `cmake/**`, `CMakeLists.txt` or the workflow itself changes, plus `workflow_dispatch`;
- checks out submodules (`extern/pybind11` is needed at configure time; Linux CI gets it from `dependencies.sh`);
- installs dependencies via Homebrew (`ninja boost fmt gflags glog jsoncpp msgpack-cxx yaml-cpp xxhash zstd openssl@3`, derived from ninja's recorded header deps and the linked libraries) and caches only the downloaded bottles (key includes the runner `ImageVersion`; `HOMEBREW_NO_AUTO_UPDATE=1` keeps formula versions pinned to the image);
- configures with defaults plus `-DBUILD_UNIT_TESTS=OFF -DBUILD_EXAMPLES=OFF`, builds only the `mooncake_master` target, and smoke-tests `mooncake_master --version`.

It also includes one small source fix found by the first run: `UdsAcceptor` used `std::jthread`, which is not available in the libc++ shipped with Xcode 16 (AppleClang 17, the runner's default toolchain). The acceptor never uses a `stop_token`, and `stop()` (also called by the destructor) always joins the thread; `running_` is only cleared in `stop()`. So switching to `std::thread` keeps the same behavior. `uds_transport_test` in the Linux CTest job covers it.

It is intentionally a separate workflow and not wired into `CI Gate`, so it is non-blocking for now. It can be made required once it has proven stable.

On the hosted runner the job passes in about 6 minutes: about 17s to install deps and about 5m12s to build `mooncake_master`.

## How Has This Been Tested?

Reproduced the job's steps locally on Apple Silicon macOS with a fresh build directory:

**Test commands:**
```bash
cmake -S . -B build-ci -G Ninja -DCMAKE_BUILD_TYPE=Release -DBUILD_UNIT_TESTS=OFF -DBUILD_EXAMPLES=OFF
cmake --build build-ci --target mooncake_master -j3
./build-ci/mooncake-store/src/mooncake_master --version
```

**Test results:**
- [ ] Unit tests pass
- [ ] Integration tests pass (if applicable)
- [x] Manual testing done (describe below)

Local configure + build succeeded (~61s wall time at `-j3`); `--version` exits 0 (`--help` exits 1 under gflags, so it is not used). The Homebrew dependency list was derived from the linked libraries (`otool -L`) and `CMakeCache.txt`. Hosted runner: https://github.com/kvcache-ai/Mooncake/actions/runs/35975013398 passes.
