## Description

On rail-isolated RDMA fabrics, a local HCA cannot reach a different-name peer HCA. The existing path pins one local device for a whole request and treats same-name pairing as a preference: if that peer is missing, it falls back to another device. That fallback shows up as retry exceeded / `IBV_WC_RETRY_EXC_ERR` (see #35 and #1450).

This adds an opt-in switch, `MC_ENABLE_STRICT_DEST_DEVICE_AFFINITY`. It defaults to off, so full-mesh mlx5 and the soft `MC_ENABLE_DEST_DEVICE_AFFINITY` preference are unchanged.

When the switch is on:

1. Each slice picks its own local HCA instead of pinning one HCA for the whole request.
2. The peer HCA must have the same name. There is no fallback, including when the matched rail is paused.
3. `retry_count == 0` round-robins `preferred_hca` and `avail_hca` together, so every listed rail can be used.

It is mutually exclusive with `MC_ENABLE_HCA_PEER_AFFINITY`. If both are set, peer selection falls back to the default.
