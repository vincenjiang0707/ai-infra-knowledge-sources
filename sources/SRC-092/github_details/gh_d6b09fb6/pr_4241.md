## Description

When TENT reports `CANCELED`, Python `transferSync` and `batchTransferSync` keep polling until `MC_TRANSFER_TIMEOUT` expires.

Handle `CANCELED` as a terminal result: release the batch and return `-1` immediately. Add regression coverage for scalar and batch READ/WRITE, register the test in the CPU-only TENT CI job, and document the behavior.

Refs #3995. This covers cancellation handling; the synchronous retry-policy change is tracked separately in #4228.

## How Has This Been Tested?

Built with `USE_TENT=ON`, `USE_CUDA=OFF`, `WITH_STORE=OFF`, and `BUILD_UNIT_TESTS=ON`.

The regression uses a test-only ELF interposer to submit real TENT tasks and cancel them through the native API. It checks the return value, elapsed time, submission count, and batch release count.

**Test commands:**

```bash
cmake --build build --target engine tent_sync_cancel_injector -j12
ctest --test-dir build --output-on-failure --no-tests=error \
  -R '^tent_python_(send_probe|first_buffer|sync_canceled)_test$'
```

- Cancellation regression fails on baseline and passes after the fix; all three selected CTests pass.
- Eight cross-host READ/WRITE cases pass across classic TCP and TENT HP TCP.
