## Description

Refactor `MasterService` to delegate all metadata operations to a backend abstraction layer, enabling future support for alternative metadata stores (e.g., Redis) without modifying the RPC interface.

This is **Phase 1 of 4** in the Redis backend implementation plan — a pure refactor with zero behavior change. MasterService still provides the same RPC interface; it just delegates to `NativeMetadataBackend` internally.

### Changes
- Add `MetadataBackend` abstract interface with 67 pure virtual methods mirroring the MasterService RPC surface (ExistKey, GetReplicaList, Put, MountSegment, Ping, etc.)
- Create `NativeMetadataBackend` class containing the original in-memory metadata logic extracted from MasterService
- Refactor `MasterService` to delegate all operations to an injected `backend_` member
- Extract `SegmentDetailInfo` struct to `segment.h` and add `UUIDHash` to `types.h` for cleaner interface boundaries
- Update CMakeLists.txt to include the new source file

### Next phases
- **Phase 2**: Redis backend MVP (core operations, basic config, unit tests)
- **Phase 3**: Redis backend production readiness (Sentinel HA, observability, performance tuning, chaos tests)
- **Phase 4**: Migration tool and documentation
