## Summary
Build and publish aarch64 variants of the AWS EFA wheels (`mooncake-transfer-engine-efa`, `-efa-cuda13`, `-efa-non-cuda`) alongside the existing x86_64 wheels. The default wheels already ship aarch64; the EFA ones were x86_64 only. aws-efa-installer supports aarch64, so this unblocks EFA on Graviton and GB200 (p6e-gb200).

## Changes
- `_build-efa-wheel.yaml`: new `architecture` input (`x86_64` | `arm64`, default `x86_64`).
  - arm64 runs on `ubuntu-22.04-arm`, same as `_build-wheel.yaml`.
  - The libfabric library path is resolved with `uname -m` instead of hardcoding `x86_64-linux-gnu`.
  - New step checks that the wheel platform tag matches the target architecture.
  - arm64 artifact names get a `-arm64` suffix. x86_64 names are unchanged, so the existing publish patterns (`mooncake-wheel-efa-py*`, `-cuda13-py*`, `-non-cuda-py*`) collect both architectures without matching other variants.
- `release-efa*.yaml`: each workflow now builds an `[x86_64, arm64]` matrix with `fail-fast: false`. The PyPI package names are unchanged, and pip picks the wheel by platform tag.
- `ci_efa.yml`: adds one cuda13 / py3.12 / arm64 build to PR CI.
