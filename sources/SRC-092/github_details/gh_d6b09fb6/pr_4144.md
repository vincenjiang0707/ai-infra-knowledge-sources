## Description

A failed existence probe after remove currently looks like an absent key: `isExist(key) == 1` is false for negative error codes too. The benchmark can then report success despite a failed check.

Require an explicit zero (absent) result before accepting the removal, and preserve a negative probe error in the result. Already-absent keys retain their existing idempotent removal behavior.

Follow-up to #3938, which handled worker exceptions. This change handles negative return codes from a completed existence call.
