## Description

Fixes #3658.

After #3903, get sessions already support MEMORY (zero-copy) and DFS (staging + scatter). SSD-only / file-backed keys still failed session start with `702 INVALID_REPLICA` because `SelectSessionReplica` and the classify/execute pipeline only handled MEMORY and DFS.

This PR extends that same prepare → classify → execute pipeline (no separate packing layer):

1. **`SelectSessionReplica`**: after MEMORY / DFS, also accept a complete `LOCAL_DISK` or `DISK` replica. NOF-only keys still return `INVALID_REPLICA`.
2. **`classify_session_range_read_requests`**: route `LOCAL_DISK` → `local_disk_requests`, `DISK` → `disk_requests`.
3. **LOCAL_DISK** (`execute_session_local_disk_range_reads`): group by owner endpoint; restore each unique key once via shared `restore_offload_objects(..., allow_pinned=false)` (RPC into the owner's TE-registered client buffer — never the unregistered pinned arena); then `Client::BatchTransferReadOffloadRanges` from restored pointer + `src_offset` into already `register_buffer`'d destinations. The reader does **not** need a setup local buffer (`local_buffer_size=0` works). Same-node GPU destinations also go through TE (no offload `kLocalAddress` memcpy on the session path).
4. **DISK** (`execute_session_disk_range_reads`): one `Client::BatchGet` into a temp host buffer, then scatter by `src_offset`. Keys fail if the client has no allocator.
5. **Shared restore helper**: sequential `batch_get_into_offload_object_internal` now uses the same `restore_offload_objects` / `OffloadRestoreLease` (default `allow_pinned=true` so memcpy into the pinned arena remains available).

Duplicate keys restore once and scatter many times. Invalid ranges do not block valid entries. Lease is checked locally after transfer. Offload GC TTL rewrites only successful scatters to `OBJECT_HAS_LEASE`. No session-level object pin.

## Relation to #3903

#3903 landed the DFS session path and the shared pipeline. This branch was rebased onto main: redundant DFS / `MultiBufferRangeRequest` work from earlier revisions was dropped; only LOCAL_DISK / DISK session reads and the shared offload restore helper remain.

### fcczzz · 2026-09-18

I missed this while reviewing #3903 — flagging the overlap now, since neither has landed.

The two PRs both rewrite `batch_get_session_start` and the ranged-session read path. They touch four of the same files, with substantive overlapping edits in `real_client.cpp`, `real_client.h`, and `docs/source/api-reference/python/mooncake-store.md`.

Proposal: land #3903 first, then rebase this on top and preserve its DFS session path while adding the LOCAL_DISK/DISK coverage here. The LOCAL_DISK path in this PR is the part that directly addresses the SSD-offload failure in #3658, so please keep that coverage.

One correctness issue before merge: at this PR's base, `SelectBestReplica` returns immediately on the first local MEMORY or local NoF replica. That means `[local NoF, local MEMORY]` selects the NoF replica. Since `batch_get_session_start` now uses `SelectBestReplica`, it can cache that NoF replica; the ranged-read path later accepts only MEMORY, LOCAL_DISK, DISK, or DFS, so it returns `INVALID_REPLICA` even though a usable local MEMORY replica exists.

#3662 fixes the selection ordering so local MEMORY wins regardless of replica order and adds a regression test. Please either rebase on that fix before merge or carry the equivalent ordering fix and regression coverage here.
