## Description

Add an advisory per-request local RNIC hint to the classic RDMA transport.

Mooncake already had `Topology::selectDevice(location, hint, retry_count)`, but
classic RDMA requests could not pass a non-empty hint to it. This change wires a
new `TransferRequest::nic_hint` through the request-level and per-slice fallback
selection paths.

The hint is intentionally advisory:

- empty hint preserves the existing topology-based selection behavior;
- unknown or disabled devices fall back to normal selection;
- only the initial attempt is pinned, so retries can fail over to another RNIC.

The Python transfer APIs expose the same option as a trailing `nic_hint=""`
keyword argument, without changing existing positional calls. The
`transfer_engine_bench` example exposes `--nic_hint` for hardware validation.

This enables callers that know more than the transport about workload placement
to isolate KV traffic from NCCL/EP traffic or enforce a known GPU–NIC affinity.

Tested branch: `feature/rdma-nic-hint` at `1bcf2429` (the final amend after the
hardware run only completed the C++ API documentation snippet).

Hardware environment: two H20 nodes, six active ConnectX-7 400G NDR RNICs per
node (`mlx5_0..5`), RoCEv2/GID index 3. The test used host DRAM only, one-sided
RDMA READ, 8 submit threads, batch size 64, and 1 MiB requests. Initiator RX was
measured from the RNIC hardware counters over a five-second steady-state window.

| case | bench GB/s | hardware RX GB/s | top RX RNIC | top share |
|---|---:|---:|---|---:|
| baseline A | 90.123 | 92.325 | mlx5_1 | 16.82% |
| `nic_hint=mlx5_3` A | 46.049 | 47.439 | **mlx5_3** | **100.00%** |
| `nic_hint=mlx5_5` A | 48.408 | 49.252 | **mlx5_5** | **100.00%** |
| invalid hint | 90.624 | 92.882 | mlx5_1 | 16.71% |
| `nic_hint=mlx5_5` B | 48.338 | 49.027 | **mlx5_5** | **100.00%** |
| `nic_hint=mlx5_3` B | 47.189 | 47.977 | **mlx5_3** | **100.00%** |
| baseline B | 90.525 | 92.610 | mlx5_2 | 16.70% |

Both run orders reproduced the result. Valid hints put all measured payload
bytes on the requested RNIC at its expected 400G effective line rate. The
unknown hint completed successfully and reproduced the baseline's even six-RNIC
distribution. The lower aggregate throughput in a valid-hint cell is expected:
the test validates pinning semantics, not whether constraining traffic to one
rail improves throughput.
