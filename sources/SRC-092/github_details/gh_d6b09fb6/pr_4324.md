## Description

With the CUDA build, the TCP transport staged device memory through a synchronous `cudaMemcpy` on the legacy default stream, so any transfer of GPU buffers waited behind every kernel the process already had queued — the reporter sees streamed tokens reaching the client two at a time. The `USE_MACA` build already went through `copyTcpCudaMemory` (a private non-blocking stream, `cudaMemcpyAsync`, then a sync of that stream); the CUDA build didn't.

This lifts `copyTcpCudaMemory` out of the `USE_MACA` guard so every GPU build has it, and routes all four staging sites (`ServerSession`/`ClientSession` x `readBody`/`writeBody`) through it. The trailing stream sync keeps the copy's completion contract identical for callers.

Neighbor note: #4233 pipelines CUDA TCP staging with pinned buffers but deliberately keeps `cudaStreamDefault` (legacy-stream semantics) for its session stream, so the stall this fixes survives that PR. The two are complementary; whichever lands second rebases.

Fixes #4323
