## Description

Contributes to #3809 and #2694 by giving the Master CXL startup settings one internal owner, `CxlBootstrapConfig`.

- Resolve the existing flat YAML/JSON keys (`enable_cxl`, `cxl_path`, `cxl_size`) and explicitly supplied CLI flags in one loader, preserving `defaults < flat file keys < explicit CLI flags`.
- Keep the existing HA and non-HA serving fields as compatibility views; CXL allocation and device behavior are unchanged.
- Check that an effective `cxl_size` fits the service's `size_t` before conversion.

No grouped public keys or environment-variable changes are introduced; valid CXL runtime behavior is unchanged. This is independent of the metrics, admin HTTP, runtime-identity, and tenant-quota bootstrap PRs, which own different settings.
