## Description

**Depends on #4016.** This branch is stacked on #4016; only the last commit
(`[Build] Support building mooncake_master on macOS`)
belongs to this PR. The #4016 commits will drop out of the diff once it merges.

#4016 fixes the `linux/memfd.h` error from #3926, but the Store build still
fails on macOS after it. This PR makes `mooncake_master` build, link, and run
on macOS arm64 (Apple Clang 21) with `-DWITH_STORE=ON -DWITH_TE=OFF`.

### Decouple the master from the TE metadata plugin

The master linked `transfer_metadata_plugin` for a single reason: it used
`MetadataStoragePlugin` to DELETE a timed-out client's `ram/` and `rpc_meta/`
keys on a separately deployed HTTP metadata server. Without TE, that target
does not exist and the link fails.

- Add `httpDelete()` next to the existing `httpGet()` in `common/network`
  (ylt `coro_http_client`), and use it for the remote cleanup. The key
  encoding (`?key=<url-encoded>`), the 3 s timeout, and the "200 only" success
  rule match the old plugin.
- `mooncake_store_master` no longer links `transfer_metadata_plugin`, and the
  cleanup path no longer depends on the TE `USE_HTTP` option.
- Remote cleanup now accepts only `http://` endpoints, because the ylt HTTP
  client is built without TLS. A `https://` endpoint logs a warning and
  disables remote cleanup, the same way etcd/redis endpoints are handled.

### Portability fixes hit by the master build

- ibverbs: disable yalantinglibs ibverbs RPC on macOS (`FindYLT.cmake`). Guard
  `init_ibv()` and `ib_socket_t` uses with `YLT_ENABLE_IBV`. If
  `MC_RPC_PROTOCOL=rdma` is set in a build without it, log a warning and fall
  back to TCP. `ClientRequester` now reuses `detail::MaybeEnableRdmaSocketConfig`.
- NUMA: link `numa` only on Linux; `bindToSocket()` in TE `common.h` returns
  `ERR_NUMA` on non-Linux platforms, like the existing "NUMA unavailable" path.
- Bundled fmt 8.0.1: newer Clang rejects `FMT_STRING` with format specs in
  the bigint formatter as a non-constant expression; use plain literals there.
- Missing `#include <shared_mutex>` in `master_snapshot_manager.h`. libc++
  does not pull it in transitively, and Clang silently typo-corrected it to
  `std::timed_mutex`.
- `lease.h`: explicit `duration_cast`, since `system_clock` is microseconds on
  libc++.
- `size_t` vs `uint64_t` mismatches (`std::max` in `allocator.cpp`,
  `GetUInt64` for `cxl_size`).
- `uds_transport.cpp`: set `FD_CLOEXEC` via `fcntl` when `SOCK_CLOEXEC` is
  unavailable; cast `timeval` fields explicitly.
- `local_ssd`: add the Boost include directory via `find_path` (Homebrew
  headers are not on the default search path).

### Out of scope

- The Store client side (`mooncake_store_client_objects`) and the unit tests
  that link it still do not build on macOS (TE headers, mmap/NVMe ioctl, ...).
- `uds_transport` compiles but uses Linux abstract-namespace sockets, so it
  does not work at runtime on macOS. Only the client uses it.

## How Has This Been Tested?

**Test commands:**
```bash
# macOS 27 arm64, Apple Clang 21, Homebrew deps
cmake -S . -B build -G Ninja -DWITH_STORE=ON -DWITH_TE=OFF \
      -DBUILD_UNIT_TESTS=ON -DCMAKE_BUILD_TYPE=Release
ninja -C build mooncake_master

# default WITH_TE=ON still configures
cmake -S . -B build-te -G Ninja -DWITH_STORE=ON -DWITH_TE=ON

./scripts/code_format.sh --check --changed-lines --base upstream/main
```

**Test results:**
- [ ] Unit tests pass
- [ ] Integration tests pass (if applicable)
- [x] Manual testing done (describe below)

- `mooncake_master` links with no TE symbols (`nm` finds no `MetadataStoragePlugin` / `TransferEngine`) and no libcurl, numa, or ibverbs dependency.
- Started `mooncake_master --enable_http_metadata_server=true`: the RPC port
  accepts connections, `/metrics` returns 200, the HTTP metadata server serves
  requests, and shutdown is clean.
- Called `httpDelete` with the master's key encoding against that server:
  - a key containing `/ : space &` is deleted, and a GET afterwards returns 404
  - a missing key returns `http=404 body: metadata not found`
  - an unreachable host returns `network error: Request timeout` after the configured timeout
- **Not yet verified on Linux**; relying on CI for the Linux builds.
