## Summary

Add an opt-in bitwise repeatability check for nccl-tests collectives.

`-B,--bitwise <repeat count>` captures one collective output as a reference, reinitializes the same generated input, and compares each of the requested repeat outputs against the reference without floating-point tolerance.

The check is implemented in the common harness, so it applies to all collective test binaries. AllReduce and ReduceScatter are the primary target use cases.

## Details

- Compare raw 8-, 16-, 32-, and 64-bit element representations with XOR.
- Report aggregate differing element and bit counts.
- Report the first zero-based repeat, rank, element, and bit that differs.
- Keep mathematical correctness checks under `-c,--check` independent from repeatability checks.
- Support out-of-place, in-place, multi-GPU, multi-thread, MPI, and CUDA Graph validation paths.
- Allocate the additional reference buffer only when bitwise checking is enabled.
- Add text and JSON output while preserving the default `-B 0` output path.
- Return a failing test status when any repeat differs from its reference.

The current nccl-tests verifiable input generator is reused intentionally. This mode verifies repeatability for that generated input and does not claim repeatability for arbitrary application tensors.

## Example

```bash
NCCL_ALGO=Ring NCCL_PROTO=Simple \
./build/all_reduce_perf \
  -b 1M -e 1M -g 2 -d float -o sum \
  -c 1 -B 100
```

## Validation

- `git diff --check`
- `make -n BUILDDIR=/tmp/nccl-tests-build`
- Added CUDA self-tests for identical buffers, single- and multi-bit changes, 8/16/32/64-bit elements, signed zero, and distinct NaN payloads.

CUDA compilation and GPU execution have not been run locally because the development host is ARM64 macOS without `nvcc` or an NVIDIA GPU. This PR is intentionally opened as a draft until Linux CUDA compilation and multi-GPU AllReduce/ReduceScatter validation are complete.
