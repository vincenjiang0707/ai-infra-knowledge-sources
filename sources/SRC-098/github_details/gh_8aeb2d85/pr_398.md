# [PR #398] alltoall: preserve exact per-rank element counts

source: https://github.com/NVIDIA/nccl-tests/pull/398
state: open | updated: 2026-09-25T09:20:30Z
labels: 

## 正文

`alltoall_perf` rounds each peer's element count down to a 16-byte multiple. For example, `-g 2 -d float -b 40` currently reports and checks only 32 bytes. Keep every complete per-peer element instead; the device implementation already has a scalar fallback and tail.

On two RTX 5090s with NCCL 2.32.3 and CUDA 13.0, the host AllToAll path completed with zero wrong values:

| Requested (B) | Before: tested (B) | After: tested (B) | After: wrong |
| ---: | ---: | ---: | ---: |
| 40 | 32 | 40 | 0 |
| 72 | 64 | 72 | 0 |
| 104 | 96 | 104 | 0 |
| 136 | 128 | 136 | 0 |

The same cases passed with `-u 1`; int8 counts of 34, 38, and 42 bytes also passed. The modified `alltoall_perf` built with SM120 device kernels. Device implementations 1 and 2 could not run on this host: NCCL reports that the communicator does not support symmetric memory.

Equal-payload host-path timing control (`-g 2 -d float`, 20 warmup and 100 timed iterations per process, A/B/B/A order; mean of two runs per variant):

| Tested (B) | Before (µs) | After (µs) | Speedup, before/after |
| ---: | ---: | ---: | ---: |
| 32 | 37.25 | 37.15 | 1.003× |
| 64 | 33.69 | 33.96 | 0.992× |
| 96 | 31.10 | 31.34 | 0.992× |
| 128 | 28.91 | 29.10 | 0.993× |

These small differences are within run-to-run variation; this change fixes test coverage, with no measured speedup claim.
