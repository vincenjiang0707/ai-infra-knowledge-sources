## 正文

## Summary

- Normalize KV-cache metadata before crossing the native extension boundary.
- Fully materialize rotary tables because the native kernels require full contiguity, not only a contiguous last dimension.
- Reject unpaired `k`/`v` and `rotary_cos`/`rotary_sin` inputs with clear errors.
- Add an end-to-end CUDA regression covering row-strided metadata and cache mutation parity.
- Correct the malformed `cache_seqlens` type annotation.

## Why

The FA2 native API applies `CHECK_CONTIGUOUS` to `seqlens_k`, `leftpad_k`, `cache_batch_idx`, and rotary tables. The Python wrapper previously normalized tensor `cache_seqlens` only inside the integer conversion branch, did not normalize `cache_leftpad`, and used a last-dimension-only helper for rotary tables. A row-strided rotary table can therefore have `stride(-1) == 1` while still failing the native full-contiguity contract.

FA3 has the same full-contiguity requirement for rotary tables, so the corresponding boundary is normalized there as well.

## Validation

- `python3 -m py_compile flash_attn/flash_attn_interface.py hopper/flash_attn_interface.py tests/test_flash_attn.py`
- `git diff --check`
- CPU boundary probe with a stub native module verified every affected argument reaches `fwd_kvcache` in the required layout and all four unpaired-input cases raise the intended `ValueError`.
- Added `test_flash_attn_kvcache_noncontiguous_metadata` to compare outputs and mutated caches against contiguous inputs.

I could not execute the CUDA regression locally because this machine has neither CUDA nor a built `flash_attn_2_cuda` extension; the test is included for a GPU-capable environment.
