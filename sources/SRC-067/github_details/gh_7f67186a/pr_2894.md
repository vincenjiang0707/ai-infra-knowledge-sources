## 正文

Two CI infra fixes that interact, in one PR.

## Registry-free GPU job

The job logged in to Docker Hub on every run to pull a private image. With the credentials rotated, the
unconditional login step fails before any test runs, although the SIF is cached and the pull is skipped.
The image is just Ubuntu + Python + torch; `run_fa4_ci.py` installs cutlass-dsl / quack / FA4 at job time.

- `gpu-test`: new input `fa4_local_sif` — use that SIF, skip pull and prune, fail if the file is missing.
- `ci.yml`: Docker Hub login only when `vars.FA4_LOCAL_SIF` is empty. Unset = unchanged behaviour.
- `tools/ci/docker/build_local_sif.sh`: `docker build` the existing Dockerfile on the runner and
  `apptainer build` a SIF into `CI_WORK_DIR/local-sif/` (registry mode prunes `*.sif` directly under
  `CI_WORK_DIR`, hence the subdirectory).

## Verify the provisioned overlay from a fresh session

All 8 tests failed with `JIT session error: Symbols not found: [ CuteDSLRT_TVMFFISetRaisedCudaError ]`
after a passing floor check. The test session saw the SIF-baked cutlass-dsl 4.6.0 runtime (`lib/`) next to
the installed 4.8.0 (`cu13/lib/`): `apptainer exec` returns before its fuse2fs child has flushed the overlay
image, so the next session can read a stale view, and DSL discovery tries `lib/` first. Intermittent and
load-dependent; latent since #2685, fatal once #2798 moved the pin off the SIF's layout. The floor check
runs in the same session as the install, so it cannot see this.

`tools/ci/run_fa4_ci.py`: wait until nothing holds the overlay image between sessions; verify from a fresh
session (one distribution per package, `flash_attn.cute` from the checkout, runtime owned by the installed
cutlass-dsl), re-provision once, then fail with `OVERLAY VERIFY FAILED: ...`; pin the verified runtime via
`CUTE_DSL_LIBS`.

## Validation

- Action pull step run locally in all three states (local SIF selected / missing file → exit 1 / variable
  unset → old cached-SIF path).
- Verification fails on an `--overlay img:ro` mount (whiteouts ignored, i.e. the leaked state), passes on RW.
- End-to-end with the `ci.yml` filter on the current CI SIF (DSL 4.6.0 baked) and on a
  `build_local_sif.sh` image (4.8.0 baked): verify OK, Pass 1 8/8, Pass 2 8/8 on both.

Related: #2685, #2798. Supersedes #2895.
