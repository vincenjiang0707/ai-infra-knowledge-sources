## Summary

Native 64-Q-head training kernels for the SM100 sparse top-k MLA (DSA) path. With exactly 64 Q heads per KV head (latent 512 + rope 64, top-k 2048) the existing kernels pay for a 128-row tile: the 2-CTA forward pads half its rows and, because the CTA pair N-splits its two B operands differently, gathers every key's latent twice; the dQ/dQv gather-GEMM pads to 128 rows; a separate scalar-atomic kernel produces the 64 rope columns of dK; and the main backward serializes its dV scatter behind the MMA warp. This PR adds compile-time specializations for that head count, selected on the head tile as before: no API change, no new knobs or env vars, 128-head / load-P / dense kernels bitwise untouched.

- **Backward main** (`flash_bwd_mla_sm100.py`): the dV accumulator hand-off is pipelined (third TMEM dV stage, the staging guard compiled out when the staging does not alias the operands), and dK_rope is fused in (one `cta_group::2` 128x64x16 UMMA per group over the resident dS^T and a 4 KiB dims-split Q_rope tile, scattered with the dV epilogue); the dK kernel is no longer launched at 64 heads with recompute-P.
- **Forward** (new `flash_fwd_mla_sm100_h64.py`): one token per CTA, `cta_group::1`, each key's 1152-B row gathered once and re-viewed MN-major for P.V, `tcgen05.mma.ws` GEMMs (S as a TS dual GEMM with Q in TMEM via `tcgen05.cp`, O += P.V as SS), three latent stages; the existing softmax / correction / epilogue code (exact running max, o_lo residual, LSE, sink) is reused. Serves 64-head forwards that do not write P (`gather_bwd_recompute_p` or no grad); load-P keeps the 2-CTA kernel.
- **dQ/dQv** (new `flash_bwd_mla_dq_dqv_sm100_h64.py`): one token per CTA, 64-row M tile, whole-row 2-stage gather, bitwise-identical dq/dqv to the padded kernel.
- Design record `AI/SPARSE_MLA_64H.md` (one section per change: mechanism, byte-exact smem/TMEM maps, measured effect, invariants, validation); `interface.py` comments are one line each pointing at it.

One commit per change, in the order they were built and measured (each commit message carries its design summary and effect).

## Validation (GB200, CuTe DSL 4.7.1)

- Sparse-MLA subset (`-k "mla_sparse or mla_sink or topk_order_invariance or precise_dpsum or preprocess_tile_tail"`): 182 passed / 40 skipped, fake-tensor compile and GPU. Six tests that hard-coded 128 heads now also run at 64 heads (`fully_masked_rows`, `token_chunk_rect`, `token_chunk_varlen`, `learnable_sink`, `topk_order_invariance`, `sentinel_varlen`), and the sentinel canaries run with recompute-P. `test_flash_attn_mla_absorbed`: 1040 passed on the GPU (64-head sparse cases now exercise the new forward).
- Test contract change: at 64 heads the recompute-P and load-P forwards run different kernels, so `recompute_p[64]` and `learnable_sink[64]` certify agreement up to bf16 output rounding (out rel-L2 < 5e-3, lse < 1e-4, dsink < 1e-2; measured ~1e-3 / ~2e-6 / ~3e-3) instead of bitwise; 128-head assertions unchanged. No tolerance changes elsewhere.
- Dense / varlen slices: per-id outcomes and compile-key SASS identical to main (505 common keys).
- ncu on the new kernels: forward 1152 B gathered per (token, key) (was 2220), tensor pipe 48 %; dQ/dQv tensor pipe 75 % (was 46 %); backward main reduction bytes 2304 B per (token, key) as before plus the fused rope columns. `setmaxnreg` budgets are honoured in the new kernels (launched with `min_blocks_per_mp=1`; the existing MLA launches drop them silently, see below).

## Not included / known limits

- The new forward is ~8 % slower per (token, key) than FlashMLA's head-64 kernel: this kernel family (gather once, two GEMMs over the same stage, lane-half exchange) is bound by the shared-memory port (~264 KiB per 64-key block); scheduling variants were measured and rejected.
- For 1-2 very long sequences per rank (kv >= 128k per sequence, CP tails) the cuDNN backward is 9-14 % faster (DRAM-regime chunks); key-range passes over the chunk loop would address it and are not part of this PR.
- The existing MLA kernel launches omit `min_blocks_per_mp=1`, so ptxas deletes their `setmaxnreg` (all warp roles run at 128 registers; the 2-CTA forward's softmax spills). Adding the attribute to the fwd / bwd-main launches is bitwise-neutral and -1.5 % at 128 heads but changes the 128-head register allocation, and the padded dQ/dQv kernel traps when its budgets are honoured; left out of this PR deliberately.
