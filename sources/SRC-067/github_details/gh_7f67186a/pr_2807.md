## 正文

## Summary

- Bound dedicated SM100/SM110 HD256 varlen forward, dQ, and dK/dV grids by runtime maximum sequence lengths instead of packed total-token extents.
- Preserve packed output alignment for vector stores.
- Use TMA stores for complete 128-row dQ tiles while retaining predicate stores for ragged tails.
- Add targeted MQA correctness coverage for complete and ragged tiles under causal and noncausal masking.

This closes #2521. Thanks to @horakka5 for the original root-cause analysis and reproducer.

## Why

The dedicated HD256 kernels used the packed `total_q` / `total_k` extents to size each batch's grid. For a packed input with `B` equal-length sequences this launches approximately `B` times more M tiles than necessary, with most CTAs exiting after reading `cu_seqlens`.

After fixing the grid, packed-varlen epilogues become visible in short-sequence profiles:

- Forward used `domain_offset` for the runtime packed-row offset, which discarded the alignment proof needed by `autovec_copy`.
- Backward constructed a dQ TMA destination only for fixed-length inputs. Every varlen dQ tile therefore used the predicate global-store path, including complete tiles that cannot cross a sequence boundary.

The change keeps the physical packed tensor extents unchanged. Runtime maximum sequence lengths are used only for grid sizing. Within a sequence, complete dQ tiles use TMA; the final partial tile keeps the bounds-checked path.

## Benchmark protocol

- GPU: NVIDIA GB200, SM100
- PyTorch: `2.11.0+cu130`
- CUDA: 13.0
- CUTLASS DSL: 4.5.2
- dtype: BF16
- packed-varlen layout: `Q=[B*S,Hq,256]`, `K/V=[B*S,1,256]`
- `Hkv=1`, dropout disabled, softcap disabled
- seed: `20260814`
- `CUDA_DEVICE_MAX_CONNECTIONS=16`
- 20 warmups per phase
- 5 retained trials; reported latency is the median
- 50 timed iterations per trial for `S <= 8K`, otherwise 20
- FA4 HD256 backward uses `deterministic=False` because the current upstream kernel rejects deterministic mode

The baseline is upstream main before this PR. Commit `0251105` only changes dependency requirements; its HD256 kernels are identical to the measured `145b101` baseline.

MFU uses the repository's historical GB200 roofline:

- compute peak: 2.5 PFLOP/s
- HBM peak: 8 TB/s
- BWD useful FLOPs: `2.5 * FWD FLOPs`
- BWD `exec` is the useful MFU multiplied by 1.4 to reflect the split dQ + dK/dV kernel work

The shape dependence matches the expected mechanism:

- Many short sequences benefit strongly because the old grid multiplies packed totals by batch size.
- At `B=1`, grid sizing is unchanged and attention computation dominates, so differences are within normal run-to-run variation.
- Complete dQ tiles benefit from TMA; only sequence tails retain predicate stores.

## Correctness

The regression test covers:

- sequence lengths `(128, 256)`: complete 128-row tiles
- sequence lengths `(129, 257)`: ragged tails
- causal and noncausal masks
- MQA with `Hq/Hkv=4/1`
- forward output and backward `dQ/dK/dV` against PyTorch SDPA
