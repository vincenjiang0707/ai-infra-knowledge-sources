## Summary

This PR takes the CuTe SM90 backward at head_dim 256 from 373 to 530 TFLOP/s (dense bf16, S=16k, H200), 1.42x, past the C++ FA3 kernel (480 TFLOP/s on the same GPU), with unchanged numerics. It is the follow-up to #2888, which fixed the swapped postprocess layout and moved hdim 256 to a 2-stage 64x48 config (302 → 373 TFLOP/s). The two optimization commits are independently useful:

1. **C++ FA3's hdim256 dQ path** (`BwdConfig.dQacc_use_TMA=False`). No smem staging of dQ: the MMA warp groups reduce the dQ accumulator straight into `dQaccum` with `red.global.add.v4.f32`, partitioned by the same R2S tiled copy as the smem path, so the gmem layout and the postprocess are unchanged. dQ is computed in two hdim halves into the same registers (C++ `Slice_dQKV_Mma`; with two accumulators ptxas hoists the second WGMMA above the atomics and dV spills at tile_n=80). The freed 64 KB is what lets the C++ tile (64x80, 2-stage Q) fit. 373 → 471 TFLOP/s, C++ FA3 is 480 on the same GPU.
2. **FA4's 2-CTA dS exchange, on Hopper via DSMEM** (`BwdConfig.cluster_size=2`). With the atomics compiled out the 1-CTA kernel runs at 747 TFLOP/s, so what remains is the fp32 reduce traffic into dQaccum (`S² · d · 4 B / tile_n` per head; a single SM sustains only ~30 GB/s of `red.add`). The two CTAs of a cluster take KV blocks n and n^1 of one head, walk the union of their m-block ranges in lockstep and exchange their dS tiles through distributed shared memory (`cp.async.bulk.shared::cluster`, mbarrier full/empty handshake with remote arrive/expect_tx). CTA r then computes `dQ[:, 128r:128r+128] = dS_own @ K_own[:, half] + dS_peer @ K_peer[:, half]` (K = 2·tile_n) and reduces only its half: half the atomics and half the dQ registers at the same tile_n. Splitting by head-dim halves rather than query rows (FA4's Blackwell variant) needs only the peer's K half (20 KB) in smem, which is what makes 64x80 fit exactly (232,448 B). Q and dO are TMA-multicast to the pair. Odd block counts use a "ghost" partner that participates in every barrier with fully masked columns (dS = 0), flushes its dQ half, and skips the dK/dV epilogue. 471 → 530 TFLOP/s.

The pair's fixed cost only pays off once the m-block loop is long enough, so `_tile_size_bwd_sm90` selects the 2-CTA kernel for `seqlen_q >= 2048` (max_seqlen_q for varlen) and keeps the 1-CTA 64x80 config below (measured crossover, table below). Deterministic and block-sparse backward keep the semaphore-ordered smem-staged path, matching the C++ restriction `Deterministic && kHeadDim < 256`. Forward and hdim ≤ 192 are untouched.

A third commit rounds `seqlen_k_rounded` straight to `n_block_size * cluster_size` instead of fixing up the parity of the n-block count. The old form branched on `max_seqlen_k`, which callers may pass as a device tensor (HF/TE varlen): that synced, and raised `DataDependentOutputException` in the FakeTensorMode compile pass. The rounding is the same value and does not branch. The SM100 2-CTA backward has the same issue; the SM90 cluster config added here reaches it from the varlen path.

New surface: two `BwdConfig` fields (`dQacc_use_TMA`, `cluster_size`) and two `FlashAttentionBackwardSm90` constructor arguments of the same names, both selected in `_tile_size_bwd_sm90` (which gains `deterministic` and `seqlen_q` keyword arguments). No public API change.

## Correctness

- Max error vs an fp32 reference is unchanged from `main` on every path (S=2048: dq/dk/dv 1.33e-3 / 1.16e-3 / 9.14e-4 non-causal, 1.20e-2 / 1.21e-2 / 1.58e-2 causal). dQ stays fp32-accumulated; only the reduction order changes, as in the C++ kernel.
- Checked vs the fp32 reference on both the 1-CTA and the 2-CTA kernel: dense, causal, GQA 16/4 and 16/2, MQA, local (200,0)/(100,50)/(256,0)/(1024,1024), softcap, deterministic (bitwise-identical repeat, MHA and GQA; smem path), hdim_v=128, hdim 200/224/240 (MHA and GQA, per kv head), odd n-block counts (ghost CTA), ragged S=1000, S=4096, varlen S=86000.
- Varlen with the 2-CTA kernel, per batch vs the fp32 reference (`bench/varlen_gqa_cluster.py`): GQA/MQA/MHA with batches of 0, 1, odd and many KV blocks, causal and not, identical errors to the 1-CTA kernel (this caught a padded-offset mismatch between the kernel and the dK/dV accumulator layout during review; fixed in commit 2).
- Varlen callers that pass `max_seqlen` as a device tensor: same gradients as the host-int call, and the FakeTensorMode compile pass goes through (commit 3).
- `tests/cute/test_flash_attn.py::test_flash_attn_output -k -256-` (8560 ids: every head_dim 256 case and every seqlen 256 case, mha/mqa/gqa × causal × local × softcap × deterministic × sink): 5246 passed, 3312 skipped, 2 failed. Both failures are the `dSink` tolerance check at `[256-256-128-...-mqa]` (diff 0.0018 vs tolerance 0.0011, head_dim 128) and fail identically with `main`'s `flash_bwd_sm90.py` / `interface.py` on this GPU. `test_flash_attn_varlen_output` d=256 random sample (320 ids): 196 passed, 124 skipped, 0 failed. `test_flash_attn_sm90_hdim_padding*` and the empty-workload backward tests: 170 passed.
- `ruff check` / `ruff format --check` (0.11.13) clean on `flash_bwd_sm90.py`.
