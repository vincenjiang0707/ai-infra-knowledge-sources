## 正文

Add symmetric head dimension 512 (`d_qk = d_v = 512`) to the SM100 CuTe attention path, including FP16/BF16 forward and backward.

### Implementation and scope

- Fused two-CTA dense forward shares QK and online softmax across all 512 output columns, reusing the SM100 MLA pipeline. Generic forward uses two V256 slices for varlen, paged KV, FP8, local masks, softcap and SplitKV; each slice uses the complete D512 QK dot product.
- Separate TCGEN05 dQ/dK/dV kernels keep the working set within shared-memory/TMEM limits. Accumulation and grouped-query partial reduction use FP32, with head grouping and long noncausal tile ordering for reuse.
- Compact layouts keep batch/token extents dynamic, with runtime maximum lengths and scheduling-aware cache keys. Noncompact layouts retain static specialization. Forward, backward and GQA reduction have disk-cache reload regressions.
- Large GQA reduction counts and indices use Int64 from the first multiplication, avoiding overflow at 2^31 output elements.
- Signed window bounds retain their literal meaning. The latest fix also initializes gradients when a negative bound can exclude an entire output tile: for square sequences, those tiles previously skipped their stores and could leave stale gradients. Added tests use nonzero supplied output buffers so allocator reuse cannot hide missing writes.

FP16/BF16: dense/varlen forward and backward, MHA/GQA/MQA, causal/local masks, softcap, LSE gradients and training with SplitKV forward. FP8 E4M3/E5M2 and paged KV are **forward only**. Deterministic backward, learnable sinks, custom score/mask callbacks, block sparsity and sparse gather/scheduler metadata are outside this implementation. Callers must translate external `-1`-means-unbounded conventions to FA4's `None` convention. Validation is on B200; full-graph `torch.compile` integration is not claimed.

Latest follow-up: `71ff336`, retaining the dynamic-cache contribution in `313d646` and the subsequent fixes in `f502aea` and `bed49db`. The diff contains implementation, regression tests and necessary CI wiring; no reports or binary artifacts.

### Performance

Fresh measurements from this source on one B200: BF16, B1, Hq8/Hkv2, fixed sequence/mask, changing only D. D128/D256 are the upstream implementations at base `1bda8f9`. Changing D changes the workload; these are not identical-workload regression ratios.

Three interleaved rounds, four independent inputs rotated in a CUDA Graph, median of round medians; each pattern receives at least 150 ms warmup followed by 10 groups of 10 replays. Forward uses `num_splits=1` and `return_lse=True`; complete backward includes preprocessing and required reduction. Compilation and input creation are excluded. No clock settings were changed. ### dawnop · 2026-09-21

Both D512 paths convert their tensors with a plain `from_dlpack`, so every extent is baked into the compiled kernel and the cache key has to carry the full `(shape, stride, dtype)`: `_forward_cache` in `flash_fwd_sm100_hd512.py`, `_native_cache` in `flash_bwd_sm100_hd512.py`, which keys on `max_seqlen` as well. Fixed shapes pay that once. Packed varlen training hands over a new token count on nearly every micro-batch and recompiles each time — about 1.7 s per new forward shape, 3.9 s per new dq/dk/dv trio. It cost 20% of step time in an 8xB200 SFT run, and per-kernel timings show nothing, because a shape that has been seen once runs in 42 ms.

313d646 marks the batch and sequence modes dynamic where the layout is compact, passes `max_seqlen` to the backward as a runtime `Int32` instead of constructor state, and keys both caches on the head shape alone. In the kernel `maxsq` was only used for `tile = ceil_div(maxsq, 128) - 1 - tile`, which takes a dynamic value fine. Non-compact layouts keep the static path, and the GQA reduction judges its own tensors, since the caller's `dk`/`dv` arrive over-strided in `test_large_gradient_stride`.

One fwd+bwd per shape, one B200, bf16, 16q/2kv, d512, causal, varlen (ms; the first call compiles in both):
