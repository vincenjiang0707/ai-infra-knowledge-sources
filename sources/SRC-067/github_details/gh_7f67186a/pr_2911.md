## 正文

## Summary

`gather_bwd_recompute_p` (#2816) was restricted to exactly 128 Q heads when #2883 introduced in-kernel head padding. The restriction is wider than it needs to be: the backward tile is 64 or 128 rows, and with exactly 64 Q heads per KV head nothing is padded (`tile_m = 64`, `pad_qheads = False`), so the recompute path runs on the same shapes #2883 already validated for load-P. This PR relaxes the check to "the head count must fill the backward tile" (64 or 128 heads) and adds 64-head coverage to the recompute-P tests.

64-head MLA models can now train with the low-memory backward instead of choosing between load-P (P saved in bf16, ~20 GiB of activations at 64k tokens) or zero-padding Q to 128 heads (2x the work).

## Changes

- `interface.py`: the two `ValueError` gates now allow 64 or 128 heads. The backward-side check is expressed as `recompute_p and pad_qheads`, so it stays aligned with the tile rule. Docstring updated.
- `tests/cute/test_flash_attn.py`: `test_flash_attn_mla_sparse_bwd_recompute_p` is parametrized over 128 and 64 heads; `test_flash_attn_mla_sparse_bwd_precise_dpsum` gains `(64, recompute_p=True)`; the sentinel test expects the `ValueError` only for padded counts (96, 24, 1).
- `AI/SPARSE_MLA_RECOMPUTE_P.md`: new "Head counts" section explaining the rule, why padded counts stay unsupported in this mode, and 64-head numbers.

Padded head counts (e.g. 24 -> 64, 96 -> 128) remain rejected. Supporting them in recompute mode would need `+inf` padding in the padded rows of the tile-width `lse_log2` buffer (so the recomputed P is exactly 0), a head-sliced `lse_log2` view for the preprocess (today it is passed unsliced and the preprocess launch fails on a shape mismatch), and a padded TMA view for `q` (rope) in the main backward kernel, which currently only gets the packed layout.

## Validation (GB200, CuTe DSL 4.7.1)

- `test_flash_attn_mla_sparse_bwd_recompute_p`: 8/8 (128 and 64 heads x shared_kv x causal; includes bitwise chunked-vs-unchunked dq/dqv and retain_graph).
- `test_flash_attn_mla_sparse_bwd_precise_dpsum`: 20/20, including `(64, recompute_p=True)` in batch and varlen mode with `gather_bwd_token_chunk`.
- `test_flash_attn_mla_sparse_bwd_sentinel` (128/64/96/24/1 heads x shared_kv x causal x 3 lengths): all pass; the `ValueError` fires exactly for 96/24/1.

## 64-head train step

B=1, one causal document, 64 Q heads, head_dim 64 (rope) + 512 (latent), gather width 2048, varlen API, `gather_bwd_token_chunk=4096` in recompute mode. Times are per fwd+bwd step; memory is the CUDA peak / saved activations between forward and backward.

Gradient rel-L2 vs an fp64 reference is identical (to three digits) to the 128-head recompute path and slightly lower than load-P on the same commit (e.g. dq_latent 0.222% vs 0.247% at 8k, iid inputs).
