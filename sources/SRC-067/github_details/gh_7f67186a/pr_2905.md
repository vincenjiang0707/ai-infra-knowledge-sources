## 正文

Dense E4M3 attention with `head_dim = head_dim_v = 256` on Blackwell runs the generic hd256 2-CTA forward kernel, whose BF16-shaped schedule leaves the FP8 tensor cores waiting on softmax and TMEM traffic. This PR adds a dedicated persistent 2-CTA FP8 forward kernel (`flash_attn/cute/sm100_hd256_2cta_fmha_forward_fp8.py`) and dispatches to it from `flash_attn_func` for dense `float8_e4m3fn` inputs on SM100 (B200) and SM103 (B300 / GB300). Its BF16 output and FP32 LSE are **bitwise identical** to the generic kernel.

## What the kernel does differently

- persistent static scheduling; causal tiles are ordered longest-first with alternate waves reversed so trip counts balance across the grid;
- separate three-deep K and V TMA rings, one full-D QK^T MMA per KV block, QK^T issued one KV block ahead of PV;
- SM103: `tcgen05.ld.red` returns the row max together with the score tile; SM100 uses a plain TMEM load and a software max (same result, max is exact);
- the online-softmax correction factor is handed to the correction warps through SMEM, and the accumulator rescale is skipped when every factor in the warp is exactly 1.0.

FP32 accumulation, the softmax reduction order, the EX2 emulation settings and the FP8 P conversion are unchanged from the generic kernel, which is why the outputs are bitwise identical.

## Dispatch

`_hd256_fp8_dispatch()` in `interface.py`: dense inputs only (no varlen, paged KV, local window, descales, qv), `float8_e4m3fn`, `head_dim = head_dim_v = 256`, compute capability 10.x. `ld.red` is used when the DSL compile target is the SM103 family. E5M2 and every other configuration keep the existing kernels. Both choices are part of the JIT cache key. There are no shape-dependent tuning knobs: half-D QK^T tiles and a 2-deep KV ring were measured on both parts and were not better.

## Tests (`tests/cute/test_flash_attn.py`)

- `test_flash_attn_fp8_hd256_output`: reference comparison on 8 shapes (unaligned tails, aligned diagonal, `seqlen_q <= 128`, several persistent rounds, rows without valid keys, E5M2 fallback);
- `test_flash_attn_fp8_hd256_matches_generic`: bitwise equality with the generic kernel on 4 shapes x `return_lse`;
- `test_flash_attn_fp8_hd256_dispatch_rule` (CPU), `..._uniform_scores` (analytic output/LSE), `..._preallocated_graph` (strided output, CUDA graph replay with changed inputs).

`test_flash_attn_fp8_hd256*` is added to the GPU CI filter; the B200 CI runner now exercises the new kernel (SM100 path).

## Performance

Method: for each shape, both arms (upstream generic kernel and this PR) run in one process with separate JIT caches; outputs are checked bitwise; each arm is captured as a CUDA graph of N back-to-back `flash_attn_func` calls (N sized to ~20 ms), warmed up, and replayed in interleaved order for 6 rounds; the table reports the median per-call time. FLOPs = `2 * B * Hq * (Dqk + Dv) * pairs` with `pairs = Q * KV` (non-causal) or the bottom-right causal count. Default clocks. GB300: 152 SMs, PyTorch 2.10.0+cu130, CUTLASS DSL 4.7.1. B200: 148 SMs, PyTorch 2.14 (NGC 26.08), CUTLASS DSL 4.7.1.
