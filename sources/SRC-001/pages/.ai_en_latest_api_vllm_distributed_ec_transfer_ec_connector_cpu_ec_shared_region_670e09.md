##

`ECSharedRegion`

[¶](https://docs.vllm.ai#vllm.distributed.ec_transfer.ec_connector.cpu.ec_shared_region.ECSharedRegion)

Flat mmap-backed memory region shared across TP workers for encoder cache blocks.

Layout: (num_blocks, block_size_bytes) — contiguous, no per-worker interleaving. All workers map the same file and see identical data.

File path: /dev/shm/vllm_ec_{engine_id}.mmap

This class owns only the shared memory substrate (mmap lifecycle, the `blocks`

view, CUDA host registration). Block allocation and eviction are tracked by `EmbeddingCache`

in the scheduler process.

Methods:

-
–[cleanup](https://docs.vllm.ai#vllm.distributed.ec_transfer.ec_connector.cpu.ec_shared_region.ECSharedRegion.cleanup)Tear down the region. Lifecycle method; no concurrent access.

-
–[pin_memory](https://docs.vllm.ai#vllm.distributed.ec_transfer.ec_connector.cpu.ec_shared_region.ECSharedRegion.pin_memory)Register the entire mmap as CUDA pinned memory for fast DMA.

`pin_memory()`

[¶](https://docs.vllm.ai#vllm.distributed.ec_transfer.ec_connector.cpu.ec_shared_region.ECSharedRegion.pin_memory)

Register the entire mmap as CUDA pinned memory for fast DMA.

Each TP worker process owns its own virtual address for the same shared physical pages, so every process must register independently. No-op when CUDA is not available or already pinned.
