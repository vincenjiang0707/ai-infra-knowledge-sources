# [PR #20409] [Fix][S-TIR] Add a block-aware ForceNarrowIndexToInt32

source: https://github.com/apache/tvm/pull/20409
state: closed | updated: 2026-09-22T23:28:37Z
labels: 

## 正文

#20378 moved block iterator, access region, and match buffer rewriting into `s_tir::IndexDataTypeNormalizer`, so `tirx.transform.ForceNarrowIndexToInt32` only handles functions whose blocks have been lowered. Callers that narrow scheduled TIR, such as MLC's compilation pipeline, get tensorized blocks with int64 iterators and int32 domains, which later fail in `CompactBufferAllocation` with a `mismatched types. int64 vs. int32` error. Every q4f16_1 Metal build in MLC currently hits this. Add `s_tir.transform.ForceNarrowIndexToInt32` for functions that still contain blocks, sharing the narrowing rules with the TIRx pass and restoring the check on int64 block allocations. The TIRx pass now rejects S-TIR blocks instead of producing inconsistent IR, and the scan dispatch tests that narrow dispatched TIR use the new pass.
