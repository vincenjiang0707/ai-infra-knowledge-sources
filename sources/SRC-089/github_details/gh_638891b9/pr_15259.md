# [PR #15259] fix(vllm): allow sparse KV totals in explicit prefill rows

## Summary

Schema-v3 prefill manifests reject valid explicit rows when their positive KV-token total is smaller than the batch size. For example, `[[1, 0], [1, 1]]` conserves both totals but fails the aggregate lower bound inherited from generated splits.

Apply that lower bound only when explicit rows are absent. Keep per-row validation, exact totals, schema-version checks, partition exclusion, and downstream runtime alignment checks unchanged.
