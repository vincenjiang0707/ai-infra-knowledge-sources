# [Issue #14128] webhook validation test pins encoding/json's incidental struct name, fails under Go 1.27

source: https://github.com/ai-dynamo/dynamo/issues/14128
state: open | updated: 2026-09-22T21:47:27Z
labels: deployment::k8s, test, go, operator

## 正文

## Describe the Bug

`internal/webhook/validation` has one table test whose expected error string
embeds an `encoding/json` implementation detail — the outermost Go struct
type name that `json.UnmarshalTypeError` prints ahead of the field path
(e.g. `Go struct field PodCliqueSet.spec.template.topologyConstraint.pack`).
That name is not a function of `deploy/operator/internal/provideroverride`'s
code; it comes straight from `encoding/json`, and Go 1.27 changed which
unqualified type name lands there for a pointer-typed nested field. The
webhook's own behavior (reject the malformed value, don't echo it) is
unchanged either way.

`deploy/operator/go.mod` declares `go 1.26.6` — a minimum, not a pin — so any
`make test` / `make envtest` run outside the operator's Docker image (which
does pin `golang:1.26.6` in `deploy/operator/Dockerfile`) already reproduces
this under a Go 1.27 toolchain, even on an unrelated change.

## Steps to Reproduce

1. Install a Go 1.27.x toolchain (verified with 1.27.0).
2. `cd deploy/operator && make envtest` (or `go test
   ./internal/webhook/validation/...` with `KUBEBUILDER_ASSETS` set).

## Expected Behavior

`TestDynamoGraphDeploymentValidator_Validate` passes, matching CI (which
pins Go 1.26.5/1.26.6 via `actions/setup-go` and the Docker base image).

## Actual Behavior

```
--- FAIL: TestDynamoGraphDeploymentValidator_Validate/malformed_provider_override_field_is_invalid_without_echoing_its_value
    admission errors = [... Go struct field PodCliqueSet.spec.template.topologyConstraint.pack ...],
    want [... Go struct field TopologyConstraint.spec.template.topologyConstraint.pack ...]
```

Verified against the exact pinned `github.com/ai-dynamo/grove/operator/api`
version in `go.sum`: `go1.26.6` produces `TopologyConstraint.`, `go1.27.0`
produces `PodCliqueSet.` for the identical input and dependency graph.

## Environment

Linux amd64, Go 1.26.6 vs Go 1.27.0 (both from go.dev/dl), operator module
at `go.mod`'s pinned `github.com/ai-dynamo/grove/operator/api
v0.1.0-alpha.12-rc1`.

### atchernych · 2026-09-22

Correction to this reporting:
  
  The issue says CI "pins Go 1.26.5/1.26.6 via actions/setup-go." That is not what the workflow does. .github/workflows/pr.yaml:830 uses:
  
`  go-version-file: deploy/operator/go.mod`
  
  CI's Go version is not a separate pin. It tracks go.mod.


Recommended fix:
Follow the pattern the harness already uses. At `suite_envtest_test.go:549-550` it already normalizes incidental text out of messages:
  
```
  message := strings.Replace(cause.Message, `Invalid value: "object": `, "Invalid value: ", 1)
  message = strings.Replace(message, `Invalid value: "array": `, "Invalid value: ", 1)

```
Adding one more normalization that strips the <TypeName>. prefix before the field path fits right in, and it fixes the whole class rather than this one case. The field path and the type name are both stable across toolchains, as my run shows, so the test keeps its real assertion.
