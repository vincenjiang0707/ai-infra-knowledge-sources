# [PR #14349] feat(sidecar): speak TensorRT-LLM's OpenEngine gRPC API

## 正文

## Summary

TensorRT-LLM is adding OpenEngine (`openengine.v1`) as its gRPC surface. This migrates `lib/sidecar/trtllm` off the bespoke `TrtllmService` protocol and adds disaggregated serving, which the old protocol had no representation for.

**Vendored protos, not the BSR.** The Buf Schema Registry Rust SDK needs a per-developer token to build — a bad first-run experience — and it pinned this crate to a different tonic version than the rest of the workspace. The protos are vendored instead, with `proto/README.md` recording the upstream commit and a SHA-256 per file so the copies stay verifiable.

**Disaggregation follows the protocol's own shape.** A prefill worker marks its request `context_only` through `extra` and terminates with `PrefillReady` instead of `finished`; the decode worker replays the returned `KvSessionRef` verbatim. The handoff is opaque JSON, so `disagg.rs` owns the codec and refuses anything it cannot round-trip — non-finite numbers, integers past 2^53, a missing endpoint port.

**Shared JSON codec.** `json.rs` moves from the vLLM sidecar into `dynamo-sidecar-common`, since both sidecars now need Struct↔JSON conversion. Behaviour and error text are unchanged.

## Notable details

- The prefill leg's synthesized terminal chunk uses `FinishReason::Length`. The frontend's prefill router treats any other terminal reason as "already complete" and never runs the decode leg.
- `Control.GetModelInfo` is called once at startup for the model's context length; `--context-length` supplies it when the engine reports none, which is what an engine started without `--max_seq_len` does.
- Cancellation closes the stream and issues `Control.Abort`.

- Concurrent requests (6/6) and client-cancellation paths exercised by hand.

- `openengine-target-dp-rank` is rejected with `UNIMPLEMENTED` at every rank, including 0, as is `openengine-priority`; a request carrying neither succeeds. The sidecar now refuses a rank hint in `validate_request` rather than letting the engine fail it.

- `RESOURCE_EXHAUSTED` is emitted nowhere in the installed `tensorrt_llm`; `ERROR_CODE_OVERLOADED` has a single emitter, the consumer-stall watchdog. Both mappings changed to match.

Re-validated on the published release `nvcr.io/nvidia/tensorrt-llm/release:1.3.0rc27.dev202609170000`, the first public tag carrying the OpenEngine servicer (TinyLlama-1.1B, RTX 5880 Ada, through the Dynamo frontend).

- **Aggregated:** non-streaming chat, 25-chunk SSE stream, `/v1/completions` with `logprobs=2` (`token_logprobs` and `top_logprobs` both populated), and a request omitting `max_tokens` served from the registered context window.
- **Disaggregated:** the same four requests over the NIXL cache transceiver, with `KvCacheTransceiverV2 ... TransferWorker ready` on both engines and the prefill and decode sidecars each logging all four — zero warnings on either.
- **The three contract claims reproduce exactly.** `openengine-target-dp-rank` (ranks 0 and 3) and `openengine-priority` both return `UNIMPLEMENTED`, while the same request without metadata succeeds; `GetModelInfo` reports `max_context_length` unset for an engine started without `--max_seq_len`, whose own args log `max_input_len=1024 max_seq_len=None`; and statically, `ERROR_CODE_OVERLOADED` has one emitter (`servicer.py:241`), `RESPONSE_STALL_TIMEOUT_SECONDS = 30.0` (`streaming.py:27`), the rank/priority rejection sits at `request_mapping.py:189`, and `RESOURCE_EXHAUSTED` appears in zero files. `control.py:258` now states it outright: `supports_priority = False  # Generate rejects openengine-priority`.
- A dp-rank hint reaches the sidecar's guard and fails as `InvalidRequest: data-parallel rank targeting is not supported by the TensorRT-LLM sidecar` instead of a 5xx out of the engine.
- The release ships the servicer but **not** the `openengine.v1` bindings it imports, so a stock image exits with `Failed to import OpenEngine support: No module named 'openengine'`. The docs, launch script, and manifest now name the release as the floor and keep the pinned pip step (the pins resolve cleanly against its protobuf 6.33.6).
