# [Issue #15255] [BUG]: usage.prompt_tokens includes replayed tokens after request migration

source: https://github.com/ai-dynamo/dynamo/issues/15255
state: open | updated: 2026-09-24T13:51:38Z
labels: bug, language::rust, dynamo-llm, backend::vllm, frontend

## 正文

### Describe the Bug

when a worker dies mid-stream and the frontend migrates the request, the final `usage.prompt_tokens` counts the tokens that were already generated before the migration as prompt tokens. they're also in `completion_tokens`, so they get counted twice and `total_tokens` goes up by the same amount. nothing errors, so if you bill on usage you just silently overcharge.

what i think is happening:
1. `RetryManager::track_response` appends the delivered tokens to the request for the retry (https://github.com/ai dynamo/dynamo/blob/9979c32f53f607b18b61617db60ac17d2de636c7/lib/llm/src/migration.rs#L753)
2. the new worker reports usage for that longer prompt (for vllm, `_build_completion_usage` sets `prompt_tokens = len(request_output.prompt_token_ids)`)
3. `update_usage_from_backend_output` overwrites the frontend's `prompt_tokens` with that (https://github.com/ai-dynamo/dynamo/blob/9979c32f53f607b18b61617db60ac17d2de636c7/lib/llm/src/protocols/openai/delta_common.rs#L154), so the isl from `update_isl` gets lost

### Steps to Reproduce

dynamo 1.5.0 (`ai-dynamo==1.5.0`), frontend with `--migration-limit 3`, three mocker workers (`python -m dynamo.mocker --model-path HuggingFaceTB/SmolLM2-135M-Instruct`), file discovery.

1. stream a completion with a 6 token prompt and `max_tokens: 40`
2. sigkill the worker serving it after 12 tokens
3. look at the final usage chunk

standalone script, stdlib only, prints BUG REPRODUCED and exits 1: https://github.com/iemAnshuman/baton/blob/main/deploy/dynamo-mocker/repro_usage.py

### Expected Behavior

`prompt_tokens: 6, completion_tokens: 40, total_tokens: 46`

### Actual Behavior

the stream finishes fine with all 40 tokens and `finish_reason: "length"`, but usage says `prompt_tokens: 18, completion_tokens: 40, total_tokens: 58`.

ran it 30 times on the mocker with random kill points. 30 of 30 migrated, all 30 over-reported, always by the `tokens_completed` of the last migration in the frontend log. with real `dynamo.vllm` workers (vllm 0.28.0) on a100s, 56 of 66 requests migrated and 54 of those 56 over-reported. the 2 that came out right both ended on a stop string the frontend matched itself, which cuts the stream before the backend's final usage chunk shows up.

### Environment

dynamo 1.5.0 (ai-dynamo wheel). mocker runs: frontend + three mocker workers in one container, cpu only. real worker runs: three dynamo.vllm workers, vllm 0.28.0, SmolLM2-135M-Instruct, float32, 4x a100 40gb, linux, slurm.

### Additional Context

possible fix: keep the client-facing `prompt_tokens` pinned to the isl from `update_isl` for a migrated request, or have `RetryManager` track how many tokens it replayed and subtract them from what the backend reports.

also, maybe intended: `nvext.worker_id` keeps showing the original worker for the whole stream after a migration, and the frontend logs `Conflicting request tracker write field="decode_worker_id"` on every migration. happy to open a separate issue if that's not supposed to happen.
