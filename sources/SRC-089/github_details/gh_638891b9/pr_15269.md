## Overview:

### Summary

When NATS is unavailable during startup, the frontend and workers exit after one connection attempt. Kubernetes restart backoff can then delay recovery after NATS becomes reachable.

This change retries temporary NATS connection failures for up to 120 seconds by default and lets initialization continue after connection succeeds. A version-gated frontend startup probe keeps liveness checks from interrupting the dependency waits.

## Details:

- Add `NATS_STARTUP_CONNECT_TIMEOUT_SECONDS`. Retry DNS, I/O, and timeout failures with exponential backoff capped at 5 seconds, and bound each attempt to 5 seconds or the remaining startup budget. Authentication, authorization, TLS, and other permanent connection errors fail immediately.
- Cancel startup attempts and backoff when the runtime shuts down. Release the dedicated transport runtime when initialization fails or its caller disappears, while preserving the successful connection lifetime.
- Add a five-minute `/live` startup probe for frontends on runtime 1.6.0 and later, including colocated frontends. Preserve complete user probe overrides and existing defaults for older or unresolved runtime versions.
- Document the timeout, readiness behavior, and probe allowance. Regenerate the Kubernetes API references from the operator documentation source.

### Validation

- Targeted `dynamo-runtime` tests passed for NATS retries, cancellation, deadlines, fatal errors, recovery, transport cleanup, and environment names. `cargo fmt --all --check` and `cargo clippy -p dynamo-runtime --no-default-features --all-targets` passed; Clippy reported existing warnings.
- Operator `make test` passed with Go 1.26.6.
- Built ARM64 planner and operator images from this branch and passed the full `make integration` target, including the existing profiler Job scenarios.
- `TestClusterDynamoGraphDeploymentToleratesLateNATS` passed both independently and in the full suite. With NATS unavailable for 60 seconds, both original pods stayed unready with zero restarts. After NATS started, both became Ready and `/v1/models` listed `mock-llama`. Retry and recovery log assertions passed without exposing the NATS address.
- Pre-commit checks, documentation lint, API documentation generation, and `fern check` passed. The separate broken-link check reported one existing link in the unchanged DeepSeek recipe page.
