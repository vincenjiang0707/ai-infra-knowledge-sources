## 正文

Implements DEP #14282 (https://github.com/ai-dynamo/dynamo/issues/14282) 

This replaces the standalone `python -m dynamo.profiler.sweeper` CLI from #13765 

DGD generation now goes through `aisimulate recommend --output dgd` (this adapter) with Dynamo Replay reached via `--stack dynamo` (this stack provider). 

Removed:
- __main__.py (324 lines): the standalone CLI's argument parsing, candidate-to-DGD orchestration, and output writing. This logic is fully superseded by dgd_output_adapter.py (already confirmed against the real AISimulate output-adapter ABI in the prior commit on this branch)
- runner.py (70 lines): load_sweep_config/run_sweep duplicated exactly what `aisimulate recommend` owns directly (loading a SmartSearchConfig, running Sweeper). _load_runner_factory/DynamoReplayRunnerFactory -- the actual, real, reusable Dynamo Replay wiring -- survives, moved to stack_provider.py.
- test_main.py, test_runner.py: tested the removed CLI/wrapper functions directly; no equivalent behavior remains to test at this layer.

Added:
- stack_provider.py: registers Dynamo Replay as `--stack dynamo`. SPECULATIVE -- unlike dgd_output_adapter.py's confirmed ABI, no real aisimulate `stack.py` diff has been reviewed; the entry-point group name and factory shape are modeled on the one CONFIRMED registration pattern in this codebase (aisimulate.sweep_config_providers / dynamo.planner.simulation:create_provider), flagged explicitly in the module docstring as needing rework once the real interface is found.
- test_stack_provider.py: replaces test_runner.py's coverage for the surviving _load_runner_factory logic only.

pyproject.toml: added "aisimulate.stacks" (speculative, see above) alongside the already-confirmed "aisimulate.output_adapters" entry point from the prior commit.
