# [PR #15228] fix(vllm): honor managed ports in the disagg multimodal E+PD launcher

## 正文

Closes [DYN-4427](https://linear.app/nvidia/issue/DYN-4427).

## Summary

`disagg_multimodal_e_pd.sh` is the last multimodal vLLM launcher still off the `dyn_port` managed-port contract from #14751. Its workers read `DYN_SYSTEM_PORT{1,2}` directly and ignored the injected `DYN_VLLM_NIXL_SIDE_CHANNEL_PORT{N}` and `DYN_VLLM_KV_EVENT_PORT{N}` vectors, so a missing or invalid injected port fell back to a fixed default silently.

## Details:

- Each worker's system, NIXL side-channel, and KV-event port now resolves through `dyn_port`, as in `disagg_multimodal_epd.sh`. The old literals remain the fallback, so a hand-run is unchanged; under `DYN_MANAGED_PORTS` a missing or invalid value fails the launch. `--kv-events-config` only pins the ZMQ endpoint — `enable_kv_cache_events` stays false, so engine behaviour is unchanged.
- The frontend starts without the worker system-port variables, matching the sibling launcher — defence in depth, since `dynamo.frontend` already discards `DYN_SYSTEM_PORT`.
- `health_check_workers=True` on `e_pd`, as `epd`, `epd_video`, and `p_d` already set, names a worker that dies at startup rather than surfacing only as the launch script exiting 1.
- Launcher regression cases cover worker port isolation, missing managed ports, JSON option aliases, decoded endpoints, and standalone passthrough. Managed mode rejects dotted KV-event options; use a whole JSON configuration with the reserved endpoint instead.
- Update the SGLang metrics test stub to the renamed `_guided_output_requires_reasoning` helper, matching `main`, to repair the two runtime CI import failures.

This closes a contract gap, but does not establish the flake's cause: neither worker opens a NIXL or KV-event port in this topology today.

## Where should the reviewer start?

`examples/backends/vllm/launch/disagg_multimodal_e_pd.sh`, against its sibling `disagg_multimodal_epd.sh`.
