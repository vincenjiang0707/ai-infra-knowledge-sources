Add tier-specific agent guides for the Rust workspace, runtime crate, Python components, and Kubernetes deployment, and link them from the root guide.

Agents descending into each tier get its source map, local development conventions, and links to canonical architecture documentation.

# Plan — component/crate-level agent markdown for Dynamo

Route: implementation

Template: debug-investigation

Engine: vllm

## User intent

A Slack thread asked for "a good agent.md context which explains key Dynamo
concepts (e.g. request/event planes, router, disagg) and summary of codebase
structure — for warming up a new agent with Dynamo context." The reply pointed
at the root `AGENTS.md` and immediately conceded "we probably should fix it in
so far as it doesn't do a good job." A second participant supplied the concrete
idea the caller told us to implement: "Instead of complex root one I wonder if
we should really get component/crate level mds… As soon as agent descends down
to a dir it'll read it in."

So the ask is not "rewrite the root file." It is to move orientation *down* the
tree, to where an agent lands, and let the root stop trying to be the whole
map. Agent harnesses read every `AGENTS.md` on the path they descend, so a file
at `lib/` and a file at `lib/runtime/` compose: the tier file frames the
neighbourhood, the crate file names the local rules. That composition is the
whole point of the idea, and it is what this change builds.

There is no runtime behaviour change here, no performance claim, and no
hypothesis about a defect in shipped code. The `debug-investigation` overlay is
retained because it is the only template that authorizes a *documentation*
correction while still insisting on a real, reviewable diff, and because it
cites `learnings/discovery-survey-before-planning.md` first — which is exactly
what saved this work item from writing the wrong change (see Discovery). Its
"reproduce the symptom" framing maps to establishing, concretely and from the
tree, what the root guide actually fails to do for a cold agent.

## Non-goals

- Not rewriting the root `AGENTS.md`. It is a competent *contributor* guide —
  build, test, lint, PR conventions, DCO, CODEOWNERS. Those sections stay. The
  root gains two small things and loses nothing.
- Not authoring new architecture prose. Dynamo already has canonical concept
  pages under `docs/fern/pages/developer-guide/knowledge-base/concepts/`. The
  new files summarize in a couple of lines and link; they do not re-explain,
  because re-explained architecture rots and then lies to agents.
- Not covering every crate and package. The workspace has 39 members and
  `components/src/dynamo/` has 17 packages. A 30-file dump is not reviewable.
  The deferred set is named explicitly below.
- Not converting the existing `CLAUDE.md`-canonical files, and not relocating
  content other teams authored (the `lib/llm` N-2 compatibility policy from
  #12800/#12894, the operator semantics from #13244). Churn on those files buys
  nothing and costs reviewer goodwill.
- Not touching `.github/codeowners/areas.yaml`. Discovery proved no edit is
  needed (below).
- No GPU work, no engine smoke test, no benchmark. Nothing in this change can
  be defended by running a model.

## Discovery

Everything in this section was read from the checkout at commit `bce85e29a` on
`main`, or from the GitHub API. Paths are repo-relative.

### The premise was wrong, and that changed the plan

The work item is phrased as if Dynamo has no component-level agent files. It
has 64 of them. `git ls-files | grep -iE 'agents?\.md|claude\.md'` returns
`AGENTS.md`/`CLAUDE.md` pairs across `lib/backend-common/`, `lib/bench/`,
`lib/data-gen/`, `lib/kv-router/` (plus five nested `src/` subdirectories),
`lib/kvbm-engine/`, `lib/kvbm-kernels/`, `lib/kvbm-logical/`, `lib/llm/src/`
(four subdirectories), `components/src/dynamo/{common/backend,router,sglang}/`,
`deploy/operator/` (six files), `docs/fern/`, `recipes/`, `tests/`,
`examples/router/custom-policy-example/`, and `aisimulate/`.

So the correct change is not "invent a pattern." It is "extend an established
pattern into the gaps that matter, and make the root point at it." Writing this
plan from the work item's wording alone would have produced a duplicate
convention layered on top of a working one.

### What the existing files actually are

Reading them showed they are not orientation documents. `lib/llm/CLAUDE.md` is
a 56-line N-2 worker/frontend wire-compatibility policy.
`components/src/dynamo/frontend/CLAUDE.md` is a 16-line rule that
`FrontendConfig` must not be written back to `os.environ`.
`deploy/operator/internal/controller/AGENTS.md` is a list of reconciliation
invariants. These are *guardrails* — "do not do X here" — authored as a
by-product of feature PRs. Not one of them tells a cold agent what the
component is or how it fits.

That is the real shape of the gap, and it is why the new files are additive
rather than replacements: leaf files constrain, and nothing exists yet to
orient. The new tier files orient. The two roles compose on the descent path
instead of competing.

### Three conventions are in play, and the newest one wins

`git ls-files -s` on the mode bits separates them cleanly:

- **Symlink twins** (24 files, mode `120000`): `CLAUDE.md` is the real file and
  `AGENTS.md` is a symlink to it. This is the dominant `lib/` and
  `components/` pattern, established wholesale by merged PR #10984
  ("docs(agents): add missing AGENTS symlinks", merged 2026-06-29), which added
  18 such symlinks in one go.
- **`AGENTS.md`-canonical, no twin**: `deploy/operator/` (six files),
  `docs/fern/`, `recipes/`. This is what recent merges do — #13244
  ("docs(operator): codify implementation semantics", merged 2026-08-14) added
  `AGENTS.md` only.
- **`AGENTS.md`-canonical with an import pointer**: the repository root, whose
  `CLAUDE.md` is the single line `@AGENTS.md`; and
  `deploy/operator/internal/controller/CLAUDE.md`, which is `@"AGENTS.md"`.

New files in this change follow the root's convention: `AGENTS.md` is the real
file and no `CLAUDE.md` twin is created. That matches the most recent merged
precedent, makes the cross-agent open filename canonical, and adds the fewest
files. The older symlink direction is left exactly as it is — flipping 24 files
would be pure churn.

### PR #10984's invariant has silently regressed

#10984 existed to guarantee that every `CLAUDE.md` has an `AGENTS.md` sibling,
so harnesses that read only the open filename are not blind. Its own Validation
section records the check it used — a `find`-based sweep for `CLAUDE.md`
directories lacking `AGENTS.md`. Running the same sweep today returns four
directories where the invariant has since broken:

- `lib/llm/` — the largest crate in the tree
- `components/src/dynamo/frontend/`
- `lib/mocker/src/replay/online/`
- `aisimulate/crates/core/src/replay/`

An agent that reads `AGENTS.md` and descends into `lib/llm/` currently gets
nothing, while an agent that reads `CLAUDE.md` gets a compatibility policy. That
is a concrete, verifiable defect in exactly the mechanism this work item is
about, and closing it costs four symlinks.

### What the root guide does badly — named, not asserted

Reading `AGENTS.md` (159 lines) against the Slack ask:

1. **It never explains a single concept the thread asked for.** "Request plane"
   and "event plane" do not appear. The Overview names disaggregation and
   KV-aware routing in one sentence each and moves on. Roughly 100 of its 159
   lines are process: the skills index, ecosystem table, build/test/lint
   commands, PR and DCO conventions.
2. **The concepts are already written down, and the root does not link them.**
   `docs/fern/pages/developer-guide/knowledge-base/concepts/communication-planes/`
   contains `request-plane.md`, `event-plane.md`, and `discovery-plane.md`;
   `.../concepts/system-architecture/` contains `architecture-flow.md`,
   `distributed-runtime.md`, and `disaggregated-serving.md`. The root guide
   references none of them. The person in the thread was told to read a file
   that pointed away from the material they wanted.
3. **Two links are labelled wrong.** Lines 83 and 84 render as
   `` `docs/AGENTS.md` `` while targeting `docs/fern/AGENTS.md`. `ls
   docs/AGENTS.md` confirms no such file exists. An agent that trusts the
   label and tries to open the path fails. (Open PR #12405, "docs: remove stale
   agent guide paths", fixes two *different* stale references — in

### Conventions any new markdown must satisfy

- `.pre-commit-config.yaml` applies `codespell`, `end-of-file-fixer`,
  `trailing-whitespace`, `mixed-line-ending`, and `check-case-conflict` to all
  files. Markdown is not excluded by the top-level `exclude:` regex.
- The `validate-skills` hook has `files: ^(\.agents/skills/|AGENTS\.md$)`.
  pre-commit matches with `re.search`, so **every nested `AGENTS.md` triggers
  this hook** — adding files under `lib/` will run it. Reading
  `scripts/validate_skills.py` shows it is invoked with `pass_filenames: false`
  and only ever reads the repository-root `AGENTS.md`, checking that its
  `## Skills` section matches `.agents/skills/` exactly. Consequence: the new
  nested files cannot break it, but the root edit must not disturb the Skills
  index. Any `## Skills` heading inside a nested file is ignored; even so, the
  new files will not use that heading.
- `docs/fern/AGENTS.md` scopes itself in its own first line to "files under
  `docs/`, `examples/`, or `recipes/`". New files under `lib/`,
  `components/`, and `deploy/` are therefore **not** bound by Fern frontmatter
  or the documentation style guide's page rules. The house conventions that do
  carry over and will be honoured: the `<!-- SPDX -->` comment header (as on the
  root `AGENTS.md`, `recipes/AGENTS.md`, and the `deploy/operator/` set),
  GitHub-style `> [!NOTE]` admonitions in `.md`, language-tagged code fences,
  and backend casing vLLM / SGLang / TensorRT-LLM.
- CODEOWNERS: `.github/workflows/codeowners.yml` runs
  `pytest .github/codeowners/test_codeowners.py` plus a diff-aware `--strict`
  coverage gate and a drift check. Reading `CODEOWNERS` shows the agent-file
  rules are **root-anchored** — `/AGENTS.md` and `/CLAUDE.md` at lines 311-312
  — so nested files do not get pulled to the process team. Running
  `.github/codeowners/who_owns.py --codeowners CODEOWNERS --repo .` over the
  proposed paths resolves every one to a real team:
  `lib/AGENTS.md`, `components/src/dynamo/AGENTS.md`, `deploy/AGENTS.md`,
  `lib/runtime/AGENTS.md`, `lib/llm/AGENTS.md` → `dynamo-runtime-codeowners`;
  `components/src/dynamo/frontend/AGENTS.md` → `dynamo-frontend-codeowners`.
  `areas.yaml` also carries `meta.catch_all`. No `areas.yaml` edit is required
  and the coverage gate will not red-X.

### Naming

every one of the 64 in-tree files is `AGENTS.md` or `CLAUDE.md`,

`AGENTS.md`, and `AGENTS.md` is the cross-harness open convention. Introducing
`agent.md` would create a third filename that no tooling reads.

## Chosen approach

Add tier-level orientation where an agent descends, close the four regressed
symlink gaps, and turn the root from a wall into an index. Nine paths, eight of
them new files.

**Tier and crate orientation — four new `AGENTS.md`:**

1. **`lib/AGENTS.md`** — the Rust workspace tier. A crate map grouped by role
   rather than alphabetically: runtime and transport (`runtime`, `memory`,
   `tokens`, `truthy`); LLM serving (`llm`, `backend-common`, `sidecar`,
   `router-plugins`); routing (`kv-router`, `kv-hashing`); KV block management
   (the `kvbm-*` family); simulation and benchmarking (`mocker`, `bench`,
   `data-gen`); bindings (`bindings/python`, `bindings/c`). Plus the
   per-crate build and test invocation, and the note that
   `lib/bindings/python` is deliberately outside the workspace and built with

   is what makes the scoped subset defensible.
2. **`lib/runtime/AGENTS.md`** — the concept file the thread asked for, sited on
   the crate that owns the concepts. Request plane, event plane, and discovery

   `.../system-architecture/distributed-runtime.md`; and a pointer to
   `lib/runtime/src/transports/` as where the vocabulary is realized in code.
3. **`components/src/dynamo/AGENTS.md`** — the Python tier. Package map, the

4. **`deploy/AGENTS.md`** — the Kubernetes tier. What `operator`, `helm`,
   `inference-gateway`, `observability`, `snapshot`, and `pre-deployment` each
   are, and a hand-off to the existing `deploy/operator/AGENTS.md` set rather

**Restore the #10984 invariant — four `AGENTS.md` symlinks** at `lib/llm/`,
`components/src/dynamo/frontend/`, `lib/mocker/src/replay/online/`, and
`aisimulate/crates/core/src/replay/`, each pointing at the `CLAUDE.md` already

## Rejected alternatives

**Rewrite the root `AGENTS.md` to explain everything.** This is what the thread
explicitly rejected ("Instead of complex root one…"), and it is what #11231
already did once to produce today's file. A single root file cannot be both
short enough to read on every invocation and complete enough to orient in
`kvbm-physical`. It also concentrates every future edit into one file the
process team owns, whereas nested files route to the team that owns the code —
proven above with `who_owns.py`.

**One `AGENTS.md` per workspace member (39 files).** Faithful to a literal
reading of "crate level mds", and the reason it loses is reviewability: a
39-file markdown PR gets skimmed and rubber-stamped or stalls. It would also
require inventing prose for crates like `truthy` and `kvbm-config` with no
owner to check it, producing exactly the confidently-wrong context that makes
agent guides harmful. The tier files give every crate coverage at a fraction of
the surface.

**Name the files `agent.md`, as the thread's wording suggests.** Rejected on
tooling grounds: `scripts/validate_skills.py`, `areas.yaml`, and every one of
the 64 existing files key on `AGENTS.md`/`CLAUDE.md`. A third name would be read
by nothing.

**Create `CLAUDE.md` twins alongside each new `AGENTS.md`.** Doubles the file
count for no gain. Claude Code reads `AGENTS.md`, and the newest merged
precedent (#13244, `deploy/operator/`) ships `AGENTS.md` alone. Adding twins
would also create four more pairs that can drift.

**Convert `lib/llm/CLAUDE.md` and `frontend/CLAUDE.md` into real `AGENTS.md`
files carrying both orientation and the existing rules.** Considered, and it is
the tidier end state. Rejected for this PR because it relocates content other
teams authored (#12800, #12894) into a file they did not write, which invites a
review objection orthogonal to the change's purpose. Since agents read every
`AGENTS.md` on the descent path, `lib/AGENTS.md` is read on the way into
`lib/llm/` anyway — the orientation lands without moving anyone's text. The
symlink gets the parity fix at zero content risk.

**Add a pre-commit hook enforcing the `CLAUDE.md` ⇒ `AGENTS.md` invariant.**
Genuinely tempting, since the invariant regressed once already and would
otherwise regress again. Rejected as scope: it is a `.pre-commit-config.yaml`
plus a new script plus a CODEOWNERS-routing change to the process team, and it
would bury a docs PR in tooling review. Worth its own follow-up; called out in
the PR description as a known follow-up rather than smuggled in here.

**`02-rust-cargo-check`.** No Rust source, manifest, or feature changes —
`lib/AGENTS.md` and `lib/runtime/AGENTS.md` are inert to the build. The
"optional vs required parameter" reasoning in the planner brief does not apply:
this change adds no parameter and no caller anywhere needs updating, so there is
no caller-discovery claim for `cargo check --workspace` to defend.

## Validation strategy

Markdown-only on a single-A100 sandbox with no Docker daemon (per
