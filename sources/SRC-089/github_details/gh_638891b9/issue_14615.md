## Summary

The **SGLang Snapshot Deploy Test** is consistently failing in Dynamo's trusted PR CI while capturing the initial automatic checkpoint.

The failure reproduces across unrelated pull requests and persists after the job's rerun bootstrap successfully recreates the vCluster and reinstalls snapshot-agent. This points to a shared CI infrastructure / snapshot integration problem rather than a PR regression.

## Evidence

### PR #14256 — three consecutive failures

Workflow run: https://github.com/ai-dynamo/dynamo/actions/runs/34403167850

- Attempt 1: https://github.com/ai-dynamo/dynamo/actions/runs/34403167850/job/102644799904
- Attempt 2: https://github.com/ai-dynamo/dynamo/actions/runs/34403167850/job/102658783093
- Attempt 3: https://github.com/ai-dynamo/dynamo/actions/runs/34403167850/job/102881575006

Attempt 3 ran on September 10, 2026. Its rerun-specific setup completed successfully:

- Self-bootstrap vCluster
- Connect to vCluster
- Install snapshot-agent

The test then failed after approximately 15 minutes.

### Unrelated PR #14553 — same failure

https://github.com/ai-dynamo/dynamo/actions/runs/34415312996/job/102683370170

This job reported the same `SourceCompletedWithoutCapture` condition.

### Known earlier pass

The exact job passed on PR #14249 on September 4:

https://github.com/ai-dynamo/dynamo/actions/runs/33833006178/job/100902386907

Newer green workflows inspected generally skipped this path-filtered job, so they are not pass evidence.

## Failure signature

The DGD condition reports:

```
failed to reconcile checkpoints: failed to resolve checkpoint for component decode:
automatic SnapshotJob ... failed: SourceCompletedWithoutCapture:
source pod ... completed before PodSnapshotContent ... reported capture success or failure
```

The same attempt also reports a PVC access failure from the host node:

```
FailedMount ... failed to fetch PVC from API server:
persistentvolumeclaims ... is forbidden:
User "system:node:..." cannot get resource "persistentvolumeclaims" ...
no relationship found between node ... and this object
```

Additional events include repeated vCluster `SyncError` messages while patching snapshot-agent/operator pods and `FailedToRetrieveImagePullSecret` warnings.

## Expected behavior

The snapshot agent captures the source pod before it completes, reports success or failure through `PodSnapshotContent`, and the SGLang checkpoint/restore deployment test completes.

## Actual behavior

The source pod completes without a capture status. The DGD remains not ready and the deploy test times out.

## Suggested investigation

1. Check vCluster host/virtual namespace synchronization and node authorization for the snapshot PVC.
2. Determine whether the PVC mount/access failure prevents snapshot-agent from reporting `PodSnapshotContent` status.
3. Verify whether the source pod lifecycle needs fencing until capture reaches a terminal state.
4. Stabilize the shared snapshot deploy-test environment, then rerun the affected PR jobs.

No matching report was found in open GitHub issues or in the Dynamo development Slack channel before filing.
