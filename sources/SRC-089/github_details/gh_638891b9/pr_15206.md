## 正文

## Summary

Moves the in-tree FFmpeg to the official **9.0.2** release to fix the RGB-to-VP9 color corruption in #15198. With the current 8.1.2 build (`--disable-x86asm`, x86), red comes back magenta. 9.x includes upstream swscale fix [62285be0](https://github.com/FFmpeg/FFmpeg/commit/62285be0096319310d7012bbab1739db79926c4d); 8.1.3 does not.

> [!IMPORTANT]
> **This PR stacks on #14925.** The first four commits are #14925's commits, cherry-picked unchanged with `-x`: the PyNvVideoCodec 2.2.3 pin and FFmpeg 9.0.1 built with `--build-suffix=_dynamo`, pkg-config aliases, auditwheel exclusions, and `ffmpeg-next` 9.0.0 with `video-rs` 0.12.0. **Only the last commit is new.** This PR is a draft so CI can qualify the full stack at 9.0.2. It should land after #14925, or be folded into it.

## Details

The new commit `fix(container): move the in-tree FFmpeg to 9.0.2 and assert VP9 colors`:

- **Pin and verify the release.** `container/context.yaml` sets `ffmpeg_version: "9.0.2"` and adds `ffmpeg_sha256`. The tarball's detached signature verifies against the FFmpeg release key `FCF986EA15E6E293A5644F10B4322F04D67658D8`. `wheel_builder.Dockerfile` runs `sha256sum -c` and fails if the digest is wrong or unset. `native_packages.yaml` and the `deny_components` floor in `codec_policy.yaml` move to 9.0.2, which keeps `test_ffmpeg_version_consistency.py` green.
- **Make the codec guard fail closed.** `ffmpeg -parsers` is not a CLI option: it exits 8 with "Unrecognized option", so the existing parser check never checked anything. The build guard now:
  - reads parsers from the `libavcodec/parser_list.c` registry that configure generates;
  - requires every surface to list vp9 before its absence check counts.

  `tests/dependencies/test_no_software_video_codecs.py` now reads the shipped libavcodec's parsers through `av_parser_iterate`, and fails on any empty or failed listing. Codec restrictions are unchanged: no H.264/H.265/AAC and no NVENC. The two Annex-B bitstream filters stay.
- **Assert colors, not codec names.**
  - `tests/utils/video_color.py` is an RGB-quadrant oracle. It decodes with the shipped ffmpeg, measures YUV with `crop,signalstats`, so no libswscale runs on the way back, and inverts BT.601 in Python.
  - `tests/dependencies/test_video_color_roundtrip.py` covers the CLI and `encode_to_video_bytes`, each with MP4 and WebM. It carries every framework marker plus `framework_agnostic`.
  - The vLLM-Omni, SGLang and TRT-LLM `test_video_encode_real.py` tests now encode colored frames and assert the decoded colors.
- **No further Rust or runtime changes.** 9.0.2 keeps 9.0.1's library majors (`avcodec`/`avformat`/`avdevice` 63, `avutil` 61, `avfilter` 12, `swscale` 10, `swresample` 7), and its `configure` and `ffbuild/` are byte-identical to 9.0.1's. So the bindings, both lockfiles and the runtime copy globs from #14925 apply as-is.
