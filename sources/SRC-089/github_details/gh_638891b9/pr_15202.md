## Summary

Follow-up to the merged #14785. Replaces #15183, which closed when its base branch was deleted; this PR targets `main`.

Move routing configuration into `--router-policy-config`:

- Default-policy scoring knobs use `worker_selection.instances[].parameters`. The builtin owns the shared-cache multiplier default: `0.5` when shared cache is enabled. Policy parameters override explicit deprecated CLI/env values, including zero. This also fixes native startup giving YAML-enabled HiCache zero credit while env-enabled HiCache got `0.5`.
- Shared cache and tracking settings use a new process-wide `router` section. Python validation and Rust startup apply these settings before constructing policies and trackers. Explicit YAML values override legacy flags; omitted values keep their existing settings.
- Deprecate the six scoring flags, `--load-aware`, and the redundant prefill/decode selection and queue threshold/policy flags, including their environment variables. Their existing behavior and precedence remain available during migration.

All Python flag deprecations use one reusable `Deprecated(replacement, remove_in)` declaration through the argument helpers. It supplies the same warning format for CLI/env use and help text, including aliases and boolean negative forms. Defaults do not warn. Native Rust env reads use one matching deprecation mapping. Removal comments target v1.7, after the v1.6 YAML migration release; wire compatibility fields keep their separate lifetime.

The overlap-query response reports raw cache hits and removes `router_credit_blocks`, which was calculated from global weights and could disagree with the active policy.

During mixed-version rollouts, workers advertising HiCache routing settings must keep an explicit legacy shared-cache multiplier (normally `0.5`) until all frontends support policy-owned defaults. Older readers otherwise interpret the omitted multiplier as zero; the migration guide documents this limitation.

Shared infrastructure flags remain supported, including host/disk cache weights because they also affect load accounting. Conditional-disaggregation settings remain separate. The migration guide replaces the load-aware preset with policy parameters and a `router` section in one YAML file.

Related: ai-dynamo/dynamo#14778.
