# [PR #14799] fix(request-trace): emit pre-stream cancellations

## 正文

## Overview

Today, Dynamo can miss the final `request_end` trace when a client cancels a request before Dynamo sends the first response item. The request is counted as cancelled by the frontend, but its trace has no ending record.

This change writes the same existing `request_end` record for that cancellation path. It does not add a new event type or change the trace schema.

## What changes

- Keep the information needed for the final trace until the request finishes or is cancelled.
- If the engine marks the request as killed before the first response item, write one `request_end` record.
- Keep the current behavior for normal stream completion and cancellation after streaming begins.
- Prevent duplicate ending records if normal completion and cleanup both run.
- Leave other early errors unchanged.

A stream that is merely cleaned up is not enough to create a trace. The engine must have marked the request as killed.

## Validation

- All 70 focused request-trace tests passed.
- `cargo fmt` and `cargo check` passed.
- We deployed the patch on ARM64 under mirrored production traffic.
- During one complete hour, all 715 trace-eligible frontend completions had exactly one `request_end` trace: **715 / 715 (100%)**.
- All four cancelled requests in that hour had exactly one matching `request_end` trace.
- A direct cancellation before the first response produced `request_payload`, then `request_end` 456 ms later.
- An unpatched control during the same period had 816 traces for 817 eligible completions (99.88%).

## Where should the reviewer start?

Start in `lib/llm/src/request_trace/integration.rs` with `RequestEndTraceState::drop`, the one-time `emit` helper, and the cancellation tests.

Minor — the `request_id` threaded through `wrap_request_end_stream` (and its two wrappers) looks redundant now. `build_request_end_trace_state_for_policy` already stores `request_id.to_string()` from `context.id()`, and it also stores that same `context` as `request_context`. Since the state carries the id from construction, you can drop the `request_id: String` param on `wrap_request_end_stream` + the two wrappers and the reassignment — removes a per-request `String` alloc and trims the diff surface.
