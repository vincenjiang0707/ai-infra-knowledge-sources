## 正文

_Based on #13293._

## Why

Unary endpoint adapters are generic runtime building blocks, not component-only experiments. Keeping their implementations in the components wheel prevents runtime-only consumers from using them and makes examples depend on an internal namespace. Give each helper a stable home matching its responsibility without changing request, streaming, cancellation, or cleanup behavior.

## Effect

Before:
```python
from dynamo.experimental.endpoint import UnaryClient, serve_unary_endpoint
from dynamo.experimental.llm import LLMUnaryClient, with_engine_data
```

After:
```python
from dynamo.runtime import UnaryClient, serve_unary_endpoint
from dynamo.llm import LLMUnaryClient, with_engine_data
```

## What Change

- Export generic unary endpoint helpers from `dynamo.runtime`.
- Export Generate aggregation helpers from `dynamo.llm`.
- Move implementation and coverage; retain only the empty experimental package marker.

## Test Plan

- Passed 27 unary behavior tests.
- Passed pre-commit, compileall, and strict CODEOWNERS coverage.
