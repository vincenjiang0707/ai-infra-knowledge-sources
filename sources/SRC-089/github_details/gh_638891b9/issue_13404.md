# [Issue #13404] feat(vllm): add NIXL handoff adapter to the standalone decode sidecar

## 正文

## Outcome

Make the standalone decode sidecar execute the supported raw-vLLM NIXL prefill-to-decode handoff after EPP selects a disaggregated plan.

The adapter sends the prefill leg to the selected prefill worker, passes the resulting vLLM handoff parameters to its local decode worker, and returns the decode response stream to Gateway. KV bytes transfer directly between vLLM workers; neither EPP nor the sidecar carries them.

## Scope

* Establish the exact supported raw-vLLM release, launch configuration, and NIXL request/response contract.
* Implement the prefill request, extraction of the vLLM handoff parameters, and local decode request through the sidecar.
* Preserve the original OpenAI request semantics and prevent EPP orchestration metadata from reaching vLLM.
* Propagate prefill/decode errors, cancellation, and stream termination through the sidecar contract.
* Add focused protocol coverage using the supported vLLM contract.

## Out of scope

* A generic adapter for other vLLM KV connector families or backends.
* KV-byte proxying through EPP or the sidecar.
* Paired EPP admission, worker discovery, manifests, benchmarks, or end-to-end deployment validation.

## Dependencies

* Decode-sidecar request contract for standalone disaggregated routing.

### bzsuni · 2026-08-21

The proposed design:

- Add a vLLM-specific NIXL P/D adapter behind the backend-neutral decode-sidecar interface from #13405.
- Keep the adapter independent of EPP/Gateway metadata. Its inputs should be the original request body and the selected prefill endpoint; sidecar-owned configuration provides access to the local decode worker.
- Use Dynamo’s current pinned vLLM/NIXL stack as the initial protocol baseline (`vLLM 0.27.1`, `NIXL 1.3.2`).

The adapter flow would be:

1. Derive a prefill request from the original OpenAI request using the vLLM disaggregated-prefill contract.
2. Send it to the selected prefiller.
3. Validate and extract the returned `kv_transfer_params`.
4. Derive the decode request from the original request, attaching only the returned handoff parameters.
5. Send it to the local decode worker and expose the decode response stream through the sidecar interface.

A few design constraints I’d keep:

- The original request remains immutable; prefill and decode requests are derived independently from it.
- The adapter treats `kv_transfer_params` as a vLLM handoff object. It validates the expected contract but does not own NIXL transport.
- EPP-only metadata is handled by the sidecar contract and is never forwarded to either vLLM worker.
- Backend-specific failures are surfaced through the adapter contract; HTTP error mapping and the external response lifecycle remain owned by the sidecar layer.
- The adapter propagates cancellation and stream termination to its prefill/decode operations according to the sidecar contract.
- Protocol tests use mocked prefill/decode upstreams and cover request derivation, handoff validation, error propagation, cancellation, and streaming behavior.
