# [Issue #15168] [BUG]: DeepSeek V4.1 image inputs rejected by pinned frontend renderer

## 正文

## Describe the Bug

Dynamo main at `843d92a7e4170ef6daf8a27aac906af6917bc376` pins `dynamo-renderer = 5.3.1`, whose native DeepSeek V4.1 formatter rejects image content. The published image-input fix in `dynamo-renderer 5.3.2` has not been consumed at that revision. This affects the shared frontend preprocessing path used by the inference gateway, before inference reaches the backend.

## Steps to Reproduce

Select the native `DeepSeekV41Formatter` with the pinned renderer and render an OpenAI chat request containing text and an image:

```json
{
  "model": "deepseek-v4.1",
  "messages": [{
    "role": "user",
    "content": [
      {"type": "text", "text": "Describe this image"},
      {"type": "image_url", "image_url": {"url": "https://example.com/image.png"}}
    ]
  }]
}
```

The example URL is illustrative; no image download or GPU is required to exercise the formatter. PR #15165 adds typed Dynamo integration tests covering this boundary, data URLs, and UUID-only cache references.

## Expected Behavior

Render an ordered `<｜deepseek_image｜>` placeholder for each image, preserve surrounding text and the selected reasoning mode, and retain the original image inputs for downstream media collection.

## Actual Behavior

The pinned text-only V4.1 renderer rejects image content instead of producing a prompt. The dependency/source mismatch is confirmed; no fresh deployed-GPU reproduction is claimed in this issue.

## Environment

- Dynamo base: `843d92a7e4170ef6daf8a27aac906af6917bc376` (1.6.0 development line).
- Baseline dependencies: `dynamo-renderer 5.3.1`, `dynamo-protocols 6.0.1`.
- Patch validation: macOS ARM64, Rust 1.96.1; CPU-only renderer integration tests.
- The deployment operator confirms that the container build has been tested in production. The image digest and exact source-commit mapping are not recorded here.
