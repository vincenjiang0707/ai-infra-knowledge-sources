## 正文

### Feature request

Add the harmony vocab files to the dynamo images

### Describe the problem you're encountering

For gpt-oss reasoning and tool parsing, you need to manually add the harmony vocab files to the frontend, which isn't mentioned in the recepies, and if they are missing, the frontend can't process the reasoning and tool calls.
I use dynamo 1.4.0 in an air-gapped environment 

### Describe alternatives you've tried

Adding them as configmaps isn't possible because they are too large.
Currently I'm using an init container to copy the files.
At the very least I'd say, fix the recepie, but adding the tiktoken files to the image is easy and would make the usage simpler

### atchernych · 2026-09-22

The issues with baking this into the image:
  - Redistribution. The openai-harmony package is MIT. The vocab file is a separate artifact on an OpenAI blob endpoint with no license stated there. Putting it inside an NVIDIA-distributed image is a legal question, not an engineering one. Let me ask the ops
  - Precedent. This could grow unmanageable when next model family with an out-of-band artifact gets the same request. There is no natural stopping point. 
  - It hides the real problem. The frontend silently downloads from a hardcoded public URL at request time. Baking in a copy papers over that instead of making it configurable. I will create a complimentary PR

Please try the following approach:
  The harmony library checks `TIKTOKEN_ENCODINGS_BASE` before it tries the network. If that variable points at a folder, it reads the vocab file straight from disk. It also checks the file's hash, so a wrong or damaged file fails loudly instead of quietly.
  
  Steps
  
  1. Get the file once, from a machine with internet:
  https://openaipublic.blob.core.windows.net/encodings/o200k_base.tiktoken
     It is 3,613,922 bytes. SHA256 is 446a9538cb6c348e3516120d7c08b09f57c36495e2acfffe59a5bf8b0cfb1a2d.
  2. Copy it into the cluster the same way you copy model weights.
  3. Keep the filename exactly o200k_base.tiktoken. The library builds the path itself. A different name will not be found.
  4. Mount that folder into the Frontend pod and set the variable. The Frontend is the pod that needs it, not the worker.
  
  The patch
  
```
      - name: Frontend
        type: frontend
        podTemplate:
          spec:
            containers:
              - name: main
                env:
                  - name: TIKTOKEN_ENCODINGS_BASE
                    value: /model-cache/tiktoken
                volumeMounts:
                  - name: model-cache
                    mountPath: /model-cache
                    readOnly: true
            volumes:
              - name: model-cache
                persistentVolumeClaim:
                  claimName: model-cache
                  readOnly: true
```
 With the file at /model-cache/tiktoken/o200k_base.tiktoken.
