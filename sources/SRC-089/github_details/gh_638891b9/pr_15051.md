# [PR #15051] fix(sidecar): expose health probes before engine discovery

## 正文

## Summary

Fixes the native sidecar startup probe dependency cycle.

- HTTP listener binds before any runtime connection or engine discovery
- `/live` returns 200 immediately; `/health` = NATS + discovery connectivity, not engine registration
- Readiness withdraws on shutdown before unregistering
- Scope: vLLM, SGLang, TRT-LLM; DEP #14897 items 1–2; companion #14927

## Changes

| Path | What changed |
|------|-------------|
| `lib/sidecar/common/` | New sidecar runner: probes active before engine discovery; SIGTERM cancels bootstrap; passes connected `DistributedRuntime` to `Worker.run_with_drt` |
| `lib/runtime/src/system_status_server/sidecar.rs` | `SidecarStatusServer` binds HTTP before DRT connects; decoupled from `DistributedRuntime` constructor via health closure; `attach()` / `info()` made public |
| `lib/runtime/src/distributed.rs` | Removes `new_with_sidecar_status`; adds `discovery_metadata()` and `set_system_status_server_info()`; wiring moved to call site |
| `lib/runtime/src/storage/kv{.rs,/etcd.rs,/nats.rs}` | `Store::check_connection` trait method: etcd uses maintenance RPC + leader guard (quorum loss → 503), NATS uses reactive connection state; `kv_store.rs` simplified |
| `lib/runtime/src/transports/etcd.rs` | `check_connection` rejects `leader == 0` — follower can answer `status()` even after quorum loss |
| `lib/backend-common/src/worker.rs` | `Worker.run_with_drt` entry point for pre-built `DistributedRuntime` |
| `lib/bindings/python/` | Probe lifecycle wired to sidecar runner; startup test simplified |
