# [PR #15271] fix(container): bake DYNAMO_COMMIT_SHA into the frontend image

## 正文

## Summary
- `frontend.Dockerfile` never declared `ARG DYNAMO_COMMIT_SHA` / `ENV DYNAMO_COMMIT_SHA=$DYNAMO_COMMIT_SHA`, unlike every other runtime image built from this tree (`dynamo_runtime.Dockerfile`, `vllm_runtime.Dockerfile`, `sglang_runtime.Dockerfile`, `trtllm_runtime.Dockerfile`, `planner.Dockerfile` all do).
- A CI that passes `--build-arg DYNAMO_COMMIT_SHA=<sha>` to every image build (so the exact source commit is recoverable from the pushed image's config alone, with no git needed inside the image) had that build-arg silently dropped for `dynamo-frontend` specifically, because nothing in the Dockerfile declared a matching `ARG` to receive it.
- Found downstream: a CI that inspects each deployed image's config env to (a) sync a host-side `dynamo/` checkout to the exact commit an image was built from, and (b) verify every image used in one deployment shares a commit, could never resolve one for the frontend image — 100% reproducible, since there was genuinely nothing to find.

## Fix
Add the same two-line `ARG`/`ENV` block every other runtime Dockerfile already has, right before the final `ENTRYPOINT`/`CMD` in `frontend.Dockerfile`'s `pre_frontend` stage. The final `frontend` stage (`FROM pre_frontend AS frontend`) inherits the `ENV` automatically, so no second declaration is needed there.

## Test plan
- [x] Diffed `frontend.Dockerfile` against `dynamo_runtime.Dockerfile`/`planner.Dockerfile` to confirm the two-line pattern matches exactly.
- [ ] CI image build + a registry inspection of the resulting `dynamo-frontend` image's config env for `DYNAMO_COMMIT_SHA` (not run here — no local Docker registry push access from this environment).
