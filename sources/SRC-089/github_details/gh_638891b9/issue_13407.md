## 正文

## Outcome

Add the EPP-owned plan ledger and paired reservation lifecycle for standalone disaggregated routing.

For each client request, EPP selects and reserves a compatible prefill worker and decode worker concurrently. It publishes a routing plan only after both reservations succeed, then translates request lifecycle events to the correct role-scoped selector.

## Scope

* Mint one logical plan ID with role-qualified prefill and decode reservation IDs.
* Start both `select_and_reserve` calls concurrently and persist the plan only after both succeed.
* Compensate any completed reservation when the peer selection fails, times out, loses eligibility, or the client request is cancelled before dispatch.
* Free the prefill reservation at the disaggregated handoff boundary; for the MVP, conservatively use the first decode response body.
* Keep the decode reservation until completion, cancellation, stream teardown, or upstream error.
* Bound orphaned reservations through the existing reservation expiry/cleanup mechanisms.
* Add focused coverage for successful paired admission, each partial-failure path, cancellation before dispatch, and role-correct lifecycle cleanup.

## Out of scope

* Cross-selector transactional commit or distributed consensus.
* Decode-sidecar execution and vLLM NIXL protocol handling.
* Multi-EPP disaggregated state replication, manifests, benchmarks, or end-to-end deployment validation.

## Dependencies

* Role-scoped worker catalogs for standalone disaggregated routing.
