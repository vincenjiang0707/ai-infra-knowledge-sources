# [Issue #14604] [BUG]: Invalid multimodal URIs return opaque 500 instead of a 4xx validation error

source: https://github.com/ai-dynamo/dynamo/issues/14604
state: closed | updated: 2026-09-22T05:35:32Z
labels: bug, backend::vllm, frontend, multimodal

## 正文

### Describe the Bug

When a chat completion request embeds an image via a malformed `data:` URI, the Dynamo worker raises a plain `ValueError` during image decoding. This exception is not preserved as a client error, so it propagates as a generic backend exception and the client receives an opaque **500 "Failed to generate completions"**.

Malformed client input should produce a **4xx with a clear diagnostic message**. A 500 signals a server fault and causes clients to retry requests that can never succeed.


### Steps to Reproduce

**Variant A — invalid base64 payload:**

```bash
curl -s http://<frontend>:8000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"<model>","messages":[{"role":"user","content":[{"type":"image_url","image_url":{"url":"data:image/png;base64,not!!!base64!!!"}},{"type":"text","text":"What is in this image?"}]}],"max_tokens":10}'
```

**Variant B — missing `;base64` marker:**

```bash
curl -s http://<frontend>:8000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"<model>","messages":[{"role":"user","content":[{"type":"image_url","image_url":{"url":"data:image/png,iVBORw0KGgoAAAANSUhEUgAAAAEAAAABCAYAAAAfFcSJAAAADUlEQVR42mP8z8BQDwAEhQGAhKmMIQAAAABJRU5ErkJggg=="}},{"type":"text","text":"What is in this image?"}]}],"max_tokens":10}'
```

**Variant C — non-image MIME type:**

```bash
curl -s http://<frontend>:8000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"<model>","messages":[{"role":"user","content":[{"type":"image_url","image_url":{"url":"data:text/plain;base64,aGVsbG8gd29ybGQ="}},{"type":"text","text":"What is in this image?"}]}],"max_tokens":10}'
```

### Expected Behavior

All malformed `data:` URI inputs → 400 Bad Request with a clear message.


### Actual Behavior

All three variants return HTTP 500 with an opaque body:

```json
{"message":"Failed to generate completions","type":"Internal Server Error","code":500}
```


### Environment

- Dynamo: latest main (nightly image, deployed 2026-08-30)
- Backend: vLLM 0.27.1, disaggregated (1 prefill + 1 decode)
- Model: Qwen3-VL-2B-Instruct
- Deployment: DynamoGraphDeployment on Kubernetes
