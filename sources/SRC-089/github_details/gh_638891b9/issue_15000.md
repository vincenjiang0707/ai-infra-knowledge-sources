# [Issue #15000] [FEATURE]: support non-streaming requests on the SGLang engine-native /generate endpoint

source: https://github.com/ai-dynamo/dynamo/issues/15000
state: open | updated: 2026-09-22T03:58:39Z
labels: enhancement, backend::sglang

## 正文

### Feature request

Let `POST /generate` accept `stream: false` and return a single JSON object instead of SSE.

The endpoint rejects requests without `stream: true` — including those that omit it, since it defaults to false. SGLang's own `/generate` already returns a single JSON when `stream` is false.

### Why

We run SGLang behind Dynamo for RL rollout. Streaming forces the client to reassemble every field: `output_ids` and `output_token_logprobs` arrive as fragments to be concatenated, and `routed_experts` only lands on the final event. We're not asking the engine to stop streaming — only for the endpoint to return one response.

### Where we are today

We serve that workload through the OpenAI-compatible `/v1/completions` endpoint today, non-streaming. We want to move to `/generate` because it accepts a client-supplied `routed_experts_start_len`, which `/v1/completions` fixes at 0 — so it cannot express "return routing for the completion only", and the routing payload scales with prompt length. The streaming-only restriction is what blocks that move.
