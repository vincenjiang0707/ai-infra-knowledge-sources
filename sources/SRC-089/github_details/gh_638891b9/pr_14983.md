## Summary

SGLang counts reasoning tokens internally when a request declares reasoning, but three unconnected layers dropped that count before it reached OpenAI clients, so `usage.completion_tokens_details.reasoning_tokens` was missing or always `0` even while `reasoning_content` streamed normally.

Fixes #13329. The decode-bridge layer below carries the same intent as #14409 for an earlier symptom of the same issue; this PR covers the full chain, and the bridge commit can be dropped if #14409 lands first.

**1. Frontend never asked the engine to count (origin of the zeros)**

The SGLang chat processor set the per-request `require_reasoning` engine argument only for guided tool choices (`_guided_tool_choice_requires_reasoning`). SGLang's scheduler only accounts reasoning tokens when `req.require_reasoning` **and** the worker's reasoning parser (scheduler `think_end_ids`) both hold, so `meta_info.reasoning_tokens` always stayed `0` for ordinary thinking chat requests.

`require_reasoning` now mirrors what SGLang's own `serving_chat` feeds the engine from its resolved thinking decision: `force_reasoning` is Dynamo's port of that per-request thinking decision, already resolved against template defaults and client opt-outs. A thinking request declares reasoning; `enable_thinking=false` on an opt-out family leaves the gate off (the engine counter would otherwise attribute plain output to reasoning).

**2. Standalone routers silently drop newer request fields**

`dynamo.router` — and its duplicated copy in `dynamo.thunderagent_router` — rebuilt every request from a hardcoded 13-field allow-list before calling `kv_router.generate_from_request`, so every `PreprocessedRequest` field added after those lists were written was silently dropped: `require_reasoning`, `kv_hint`, `router` (nvext params), `agent_context`, `media_io_kwargs`, `is_probe`, `migration_link`... With layer 1 sending `require_reasoning`, these routers would have eaten it on the way to the workers.

Both routers now forward the inbound request dict wholesale and overlay only the fields they synthesize (model fallback, `token_ids`, routing synthesized from legacy top-level `dp_rank`). Keys the struct does not declare are ignored by depythonize, so stale or legacy extra keys remain harmless.

**3. Decode bridge never forwarded the count**

The SGLang decode handler built `completion_usage` from prompt/completion/cached tokens only and never read `meta_info["reasoning_tokens"]`. It now forwards the engine's count into `completion_tokens_details`, per choice: a reported `0` stays `0`, and an unreported count keeps the field absent. Both the disaggregated and non-disagg paths force `stream=True` on the engine and the HTTP service folds non-streaming client requests from the same terminal chunk, so this covers streaming and non-streaming responses alike.

Note: the engine still only counts when the worker runs with a reasoning parser (scheduler `think_end_ids`), which remains a deployment prerequisite.

## Validation

- 4 new frontend tests: a plain thinking request sets the engine gate on the inline and pool paths; `enable_thinking=false` leaves it off on both paths.
- 3 new standalone-router tests: fields added after the allow-list survive the hop (`require_reasoning`, `kv_hint`, `router`, `agent_context`, `media_io_kwargs`, `is_probe`, `request_timestamp_ms`, `migration_link`); legacy `dp_rank` routing synthesis; model fallback.
- 2 new decode-handler tests: reasoning count passed through per choice; reported zeros preserved; unreported stays absent.
- The streaming metrics test now pins the bridge-shaped usage (including `completion_tokens_details`) passing through verbatim.
- The aggregator fold test asserts the non-streaming aggregation keeps the backend reasoning count (`cargo test -p dynamo-llm`).
- Python suites on top of this branch: frontend sglang processor, frontend sglang metrics, sglang decode handler, standalone router, thunderagent router — **470 passed, 1 optional skip**.
