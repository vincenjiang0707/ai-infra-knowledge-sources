# [Issue #11919] Disaggregated prefill worker does not populate KV gauges (total_blocks / gpu_cache_usage_percent)

source: https://github.com/ai-dynamo/dynamo/issues/11919
state: closed | updated: 2026-09-21T16:13:33Z
labels: bug, backend::vllm, Stale, metrics, observability, kvbm

## 正文

### Summary

On a disaggregated deployment, the **prefill** worker (`python -m dynamo.vllm --disaggregation-mode prefill`) never wires the dynamo stat-logger that emits `dynamo_component_total_blocks` and `dynamo_component_gpu_cache_usage_percent`, so those two gauges have **no samples** on its `/metrics` endpoint (only `# HELP`/`# TYPE`). The decode and aggregated workers populate them correctly.

Note: the prefill worker does have a GPU KV cache — this is a missing metric-emission wiring on the prefill path, not an absent cache.

### Ask

Wire the dynamo stat-logger on the prefill worker so `total_blocks` / `gpu_cache_usage_percent` render as real values (or an explicit seeded 0), matching agg/decode.

### Related

Surfaced by the `disaggregated_lmcache` serve test in PR #11439.
