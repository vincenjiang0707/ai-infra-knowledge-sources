## Summary
 
Implements "select bounded scalar/Pareto results" — [tracking issue #13545](https://github.com/ai-dynamo/dynamo/issues/13545), item 5. 
Given the current selection and one newly-scored `Candidate`, returns the updated selection. Maintaining state across a stream of candidates is the caller's job — same design as `compute_actions` in the DGDC reconcile-diff work (`#14931`).
 
## What's confirmed, not assumed
 
- `Candidate.objectives` is a dict keyed by `OptimizationTarget` value.
- Each objective's maximize/minimize direction is a **search-level** property (`[(t.value, t.maximize) for t in resolved_pareto_objectives]`), not a per-candidate field — callers supply it via `ObjectiveSpec`, one per objective, at the goal level.
- Scalar goals break score ties by fewer GPUs: *"rank (best score, ties → fewer GPUs) for every scalar goal."* Implemented exactly, with dedicated tests for both the tie-break firing and *not* firing when it shouldn't.
- Pareto results are *"only non-dominated candidates."*
- `ParetoGoal.max_candidates` defaults to `5`, matching the real, confirmed `RecommendationSpec.MaxCandidates` default on the `v1beta2` DGDR type (fetched directly from the `#13603` PR branch).
## Eviction policy
 
NSGA-II crowding distance when the front exceeds `max_candidates` — the standard algorithm for this exact problem, not an arbitrary rule. Boundary candidates (best on any single objective) get infinite distance by construction and are never evicted; eviction thins dense interior clusters instead of trimming the front's own extremes.
