## 正文

 ## Summary

  - Add Phase 1 protected-model loading for Dynamo/vLLM.
  - Preserve the existing plain-model path: plain Hugging Face models bypass key, license, TPM, crypto, and tmpfs handling.
  - Add protected-package verification, signed manifest/license validation, TPM-bound key recovery, AES-256-GCM shard decryption, and tmpfs-only plaintext materialization.
  - Integrate the resolved protected model path with the vLLM backend and clean up decrypted files after use.
  - Add a protected image build profile, packaging/issuance tools, deployment examples, and English operator documentation.

  ## Security properties

  - No encryption key or signing private key is committed to source, image, or runtime configuration.
  - Protected packages fail closed on invalid signatures, invalid license, machine mismatch, missing key material, integrity failure, or unsafe tmpfs/runtime policy.
  - A copied protected package cannot run on a different machine without its TPM-bound key material and valid license.
  - Plaintext model shards are materialized only in the configured tmpfs workspace.

  ## Validation

  - `components/src/dynamo/vllm/tests/test_model_protection_bootstrap.py`
    - 18 passed, 2 skipped.
    - The skipped cases require vLLM 0.29; the local environment has vLLM 0.28.
  - `git diff --check` passed.
  - Rust packager tests passed before the final main update; the current local offline cache cannot resolve a locked `aisimulate-core` dependency, so full Rust validation should run in CI.

  ## Follow-up validation before production enablement

  - Build and test the protected image with vLLM 0.29.
  - Run an end-to-end protected LFM model load through TPM → tmpfs → vLLM → GPU.
  - Validate failure paths: copied package, invalid license, TPM/machine mismatch, tampered shard, and tmpfs cleanup.
