## 正文

### Type of Change

New feature

### Problem Statement

Speculative decoding on the SGLang backend is largely implemented, but it is not validated end to end or documented. As a result, the feature matrix marks it as unsupported/WIP (🚧).

The [SGLang backend overview](https://docs.nvidia.com/dynamo/dev/knowledge-base/modular-components/backends/sg-lang/overview) currently shows 🚧 for Speculative Decoding against every other feature.

**Comparison with vLLM**

| Capability | vLLM | SGLang | Gap |
|---|---|---|---|
| Disaggregated P/D speculation | ✅ Supported | ✅ EAGLE state-transfer path exists | Not validated or documented |
| KV-aware routing with EAGLE | N/A (Block Hashing) | ✅ Supported in #6872, #10982, #11764 | No E2E coverage |
| Examples / E2E validation | ✅ `agg_spec_decoding.sh` + nightly `aggregated_spec_decoding` test | ❌ No launch script and no test | **Main gap** |
| Documentation | ✅ `speculative-decoding-with-vllm.md` | ❌ "Not yet documented" | Missing document |




### Proposed Solution

Close the gap with mostly tests and documentation. No runtime changes are expected. The work is planned to split into three PRs.

**PR 1: Aggregated EAGLE3 E2E**
- #15251 
- Add `examples/backends/sglang/launch/agg_spec_decoding.sh`, mirroring the vLLM script. It runs Qwen3-8B with the `Tengyunw/qwen3_8b_eagle3` draft model (both ungated) and `--enable-metrics`.
- Add a nightly `aggregated_spec_decoding` config to `tests/serve/test_sglang.py`, mirroring the vLLM case.

**PR 2: EAGLE + disaggregated P/D + KV-aware routing E2E**
- #15261
- Add an EAGLE variant of `test_router_decisions_sglang_disagg`, with speculation enabled on both the prefill and decode workers.
- Validate the full chain:
  1. Prefill runs with EAGLE.
  2. KV and speculative state transfer to decode.
  3. Decode continues speculating.
  4. The worker's KV event hashes match the router's hashes: on a shared prefix, the overlap is greater than 0 and the request goes to the same worker.

**PR 3: Documentation**

- #15268
- Add `speculative-decoding-with-sglang.md` covering aggregated, disaggregated, and KV-router launch, plus how to read the `sglang:spec_*` metrics.
- Update the backend table in `speculative-decoding/overview.md`.
- Update the SGLang feature matrix: mark the validated cells as ✅ and note.

**Out of scope**

- DSpark and other algorithm related coverage
- Speculative decoding combined with KVBM, LoRA, or request migration
