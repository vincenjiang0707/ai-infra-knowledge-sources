## 正文

## Summary

- add explicit CPU, memory, and ephemeral-storage requests to the DGDR CI `profiler` and `output-copier` containers so they are no longer `BestEffort`
- bound profiler ephemeral storage with container limits and `profiling-output.emptyDir.sizeLimit`
- set `backoffLimit: 1` so an evicted profiling Pod gets one clean retry that can be scheduled away from a node under `DiskPressure`
- preserve explicit per-test overrides and the existing Hugging Face token injection

The selected values are intentionally conservative for the mocker-based CPU suite: the profiler requests `250m` CPU, `512Mi` memory, and `1Gi` ephemeral storage with a `4Gi` ephemeral-storage limit; the output copier requests `25m` CPU, `64Mi` memory, and `128Mi` ephemeral storage with a `256Mi` limit. The shared output volume is capped at `1Gi`. CPU and memory limits remain unset to avoid adding throttling or OOM failure modes.

`backoffLimit: 1` recreates the Pod after an eviction; it is not live migration. A node carrying the `DiskPressure` taint should be avoided by the replacement Pod, although Kubernetes does not guarantee that every retry lands on a different node.

The `4Gi` container limit covers the writable layer and the logs of the profiler. Default kubelet log rotation bounds a container log at `containerLogMaxSize` times `containerLogMaxFiles`, which is 10Mi times 5 by default.

If a bound is exceeded anyway, the kubelet evicts the Pod. With `backoffLimit: 1` that costs one retry, and then the Job sets its terminal condition. The test does see it. `_wait_for_phase` in `dgdr_utils.py` raises `AssertionError` with the DGDR conditions as soon as the phase turns `Failed`, and the controller only sets `Failed` from the `JobFailed` condition at `dynamographdeploymentrequest_controller.go:1892`. The failure is visible in the request status, not only in events.

One consequence is worth stating out loud, because it is a deliberate trade. `backoffLimit: 1` doubles the time before the Job reaches `JobFailed`, so a real profiling failure takes two attempts to surface. On the mocker CPU lane, where profiling takes minutes against a `profiling_timeout` of 3600, that is cheap. `tests/deploy/test_dgdr_h100.py` also calls `build_dgdr`, and no workflow runs that file today, so the second attempt does not cost GPU time in CI.
