# [PR #14355] refactor(replay): delegate Weka ingestion to AISimulate

## 正文

#### Summary

Replace Dynamo's duplicate Weka parser and converter with AISimulate's graph loader. Keep `trace_format="weka"` as a compatibility adapter and execute the resulting graph through the existing typed agentic replay path.

- Remove the Dynamo Weka parser, lowering code, converter binary, and their build targets.
- Preserve source block sizes, explicit nested timestamp overrides, and the resolved timestamp basis in offline/online summaries and runner metadata.
- Retain source-model provenance and the configured execution target; adapt to the required AISimulate API changes.
- Keep the router implementation unchanged apart from the new protocol field required by AISimulate.

#### Weka behavior changes

- `auto` selects one nested timestamp basis for the whole corpus. Adding a relative-timestamp witness can change other files' interpretation. The resolved basis is reported; explicit `absolute` retains before-marker rejection.
- `out: 0` remains zero, replacing the former `max(1, out)` normalization; output totals and timing/throughput metrics can change.
- Missing/null `api_time` remains absent in provenance; dependency classification uses a zero-duration interval instead of rejecting the input.

These differences are documented in the CLI reference.

#### AISimulate nightly migration

Pin Python/benchmarks/containers to `aisimulate==0.13.0.dev202609230000000054` and both Cargo manifests plus all three lockfiles to `aisimulate-core = "=0.13.0-dev.202609230000000054"`. Both are published; NVIDIA wheel staging also lists this release. No Git source overrides are required.

This release removes the old AIC import namespaces. Update planner, profiler, runtime helpers, tests and collection stubs to `aisimulate` / `aisimulate_core`, including `aisimulate.capacity` and `aisimulate.legacy_cli`. Adapt planner construction to the canonical forward-pass configuration API while preserving regression-only operation and native-to-regression fallback.

Lower resolved canonical op-level timing through Dynamo's existing AIC callback, retaining materialized KV capacity. Reject unsupported non-default timing controls explicitly. Initialize the new synthetic cached-prefix field to zero. The nightly now samples vLLM's first token at prefill completion, so both vLLM and SGLang parity checks compare TTFT to context latency without an extra decode step; the 5% tolerance is unchanged. The decode-worker midpass test now uses decode latency to establish its in-flight boundary.

#### Prediction changes beyond Weka

The dependency upgrade also changes AIC and replay predictions for non-Weka workloads. In the reviewer's comparison of `0.12.0` with the previous September 17 nightly, Qwen/Qwen3-32B on h200_sxm showed roughly 1.69 ms higher AIC TPOT (8.0–9.2% across measured ISLs), unchanged context latency, and SGLang TTFT without the extra decode step. These are historical measurements of that earlier nightly, not measurements of the current September 23 pin or a guarantee for other models/systems. The current nightly also emits vLLM's first token at prefill completion; both backend parity oracles now reflect that behavior. Prediction baselines may therefore change outside Weka as well.
