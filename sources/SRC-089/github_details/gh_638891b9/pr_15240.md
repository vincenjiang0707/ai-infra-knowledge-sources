## Summary

Extend Dynamo’s existing `ai-dynamo` replay runner, `dynamo.router` provider and native `KvReplayComposition` so AISimulate users can configure KV-aware placement with independent conversation affinity:

```yaml
router:
  policy: kv_router
  affinity:
    mode: sibling_group  # or session
    ttl_seconds: 3600
```

The existing `aisimulate predict --config agentx.yaml` entry point executes the native policy and reports actual worker/attention-DP placement and physical cache reuse. No new Python distribution or alternate policy implementation is introduced. AISimulate remains the engine/round-robin package; installing existing `ai-dynamo` supplies routing through its existing entry points. This follows [the installation-boundary review in AISimulate #306](https://github.com/ai-dynamo/aisimulate/pull/306#discussion_r4087684968).

- Reuse current-main `DefaultWorkerSelector` from `dynamo-custom-policy-builtin`, `PolicyQueue`, `SessionAffinity`, the existing replay indexer and physical KV-event bridge. Add group-key mapping, simulated time and Hold/Lease ownership around accepted dispatch; the selector, affinity table and eviction algorithms remain native.
- Reuse AISimulate’s existing Python runner and shared serialized executor for snapshots, warmup, duration, timing and reports, passing the existing Dynamo composition. Supported conversation/profile paths are static offline vLLM/SGLang aggregated and P/D with attention DP. Reject incompatible Planner/backend/config combinations explicitly. Retain legacy explicit runner and replay paths.
- Pin actual AISimulate source **60fd1bb74a78339e7090161866c5e93d299dc65f**, exact version 0.13.0, in both Rust manifests and three existing lockfiles. Python/container dependencies use the same version; the container builds the existing AISimulate wheel from that immutable source. Strict runtime version/API and dependency checks remain; no local override or new lockfile is used.
- Update existing AISimulate 0.12 Python import paths to 0.13 namespaces across Replay, Planner, Profiler and native timing helpers, including their existing test/marker configuration. These are required by the package-wide dependency upgrade, not additional integration layers.
- Correct an existing mid-pass test fixture that deadlocked on a zero-duration decode pass. The failure reproduces on unmodified Dynamo/core 0.12; the fixture now establishes an actual 100ms decode window without changing production timing or scheduler behavior.

## Dependency and installation boundary

This draft targets current Dynamo main, using interfaces already merged there. **Dynamo #15149 is not required and remains independent.** Source dependency is one-way: this Dynamo consumer depends on the neutral hooks from AISimulate #306 (stacked on #307). AISimulate’s core/wheel does not depend on Dynamo. Merge/publish the matching AISimulate source before finalizing the downstream release dependency; do not confuse a buildable source pair with a published package.

Only the existing `aisimulate`, `ai-dynamo` and `ai-dynamo-runtime` packages are used. The [AISimulate quickstart](https://github.com/ai-dynamo/aisimulate/blob/harrli/aic-1817-routing/docs/agentx-quickstart.md) records source-build prerequisites and complete YAML; its Dynamo revision is pinned to the tested source build. No GPU or running Dynamo service is required for offline replay.
