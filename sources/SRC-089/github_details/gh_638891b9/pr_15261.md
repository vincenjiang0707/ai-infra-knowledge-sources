## Summary

Second PR for #15250: EAGLE3 speculative decoding with disaggregated prefill/decode behind the KV router.

- New nightly `test_router_decisions_sglang_disagg_eagle` in `tests/router/test_router_e2e_with_sglang.py`: 2 prefill workers on GPU 0, 1 decode worker on GPU 1, EAGLE3 on both sides. It uses the Qwen3-8B + `Tengyunw/qwen3_8b_eagle3` pair.
- On top of the existing checks (all requests go to the same prefill worker, and that worker is not a decode worker), it asserts the chain from the issue:
  - **Worker and router KV hashes match.** Requests 2 to 4 share a prefix with the previous request, so the test requires `nvext.timing.kv_hit_rate > 0`. With EAGLE, SGLang keys its radix cache by token bigrams, and the router has to align its hashes the same way. If they don't match, the overlap stays 0 while requests can still land on the same worker by chance, so we need to explicity use hit rate to verify the path works.
  - **Decode keeps speculating after the KV and EAGLE state transfer.** After the requests, the test scrapes the decode worker's `/metrics` with `SGLangSpecDecodeMetricsPayload`: `spec_verify_calls_total > 0`, and more than 1.2 tokens per verify step. 
- Harness changes (backend-agnostic parts go in `common.py` / `e2e_harness.py`, per `tests/router/AGENTS.md`):
  - `SGLangProcess` accepts `extra_args`.
  - `_test_router_decisions_disagg` takes a `require_kv_hit` flag, off by default.
  - `run_disagg_router_decisions_test` takes a `post_check(prefill_workers, decode_workers)` hook that runs while the workers are still up.

### Fixes that also re-enable `test_router_decisions_sglang_disagg`

The EAGLE variant first failed the same way as the skipped non-EAGLE disagg test. Two causes, both in the test setup:

1. **Bootstrap server bound to loopback.** SGLang 0.5.19 binds the KV bootstrap server to `--host` (default `127.0.0.1`), but `dynamo.sglang` advertises the auto-detected local IP to decode workers. Decode got `Connection refused`. Fixed now by using `0.0.0.0`. 
2. **`kv_transfer_estimated_latency_ms` can legitimately be 0.** Since #14968, SGLang prefill completion is recorded when the prefill stream ends. On the bootstrap path, decode runs in parallel and can emit its first token first, so the saturating difference is 0. The harness already has `enable_bootstrap=True` to skip this check. SGLang always takes the bootstrap path, so both SGLang disagg tests now pass it.

## Where should the reviewer start?

`test_router_decisions_sglang_disagg_eagle` and the `--host 0.0.0.0` line in `SGLangProcess`.
