# [PR #15094] fix(backend): Preserve worker errors when local stop conditions trigger

## 正文

### Summary

When serving glm-5.3 with vLLM, we found that requests sometimes returned malformed JSON with HTTP 200 and `finish_reason: "stop"`, even though vLLM logged a grammar rejection and terminated the request with an error

We found the cause is in `Backend`’s finish-reason handling: when the failed worker’s final token batch also contains EOS, local stop detection overwrites `FinishReason::Error` with `Stop`. A token limit or user-defined stop can overwrite it too.

This pr adds a guard that preserves the worker error which fixes error reporting; the underlying grammar failure is being addressed in xGrammar [pr905](https://github.com/mlc-ai/xgrammar/pull/905)
