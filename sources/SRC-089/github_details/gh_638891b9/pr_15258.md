# [PR #15258] fix(kv-router): break request-lease observer ownership cycle

## 正文

## Overview:

`KvRouter::new` hands the scheduler a strong `Arc` to the `RequestLeaseManager` as its replica observer, and the manager holds the scheduler's `SchedulerBookingCleanup` handle that it receives from `set_scheduler`. Both edges are strong, so neither side can drop once construction has wired them. A router that fails to construct after that point, or one that is dropped, leaks its scheduler actor and lease state. This PR replaces the strong observer with a weak one so the cycle is broken while callbacks still reach the manager for as long as it is alive.

This is the first of three independent PRs split out of #14965. That PR's Mooncake Store test for failed router construction depends on `RequestLeaseManager::replica_observer` from this change. The leak itself exists on `main` today and is not specific to Mooncake Store.

## Details:

- Add `RequestLeaseManager::replica_observer`, which returns an `Arc<dyn ReplicaRequestLeaseObserver>` backed by a `Weak<RequestLeaseManagerInner>`.
- Replace the `impl ReplicaRequestLeaseObserver for RequestLeaseManager` with a private `WeakRequestLeaseObserver`. Each of `admitted`, `progressed`, and `completed` upgrades the weak reference and forwards to the existing `register_remote`, `touch_booking`, and `complete_remote` methods, or becomes a no-op once the manager is gone.
- `KvRouter::new` passes `request_leases.replica_observer()` to the scheduler instead of `Some(Arc::new(request_leases.clone()))`.
- Add the regression test `replica_observer_forwards_live_callbacks_without_retaining_manager`. It admits a booking on a tracked router, drives the three callbacks through the observer and checks the lease record at each step, drops the router, and asserts the manager is released. It then calls the callbacks again on the dangling observer to confirm they are no-ops.
- Make the `tracked_router` test helper in `kv_router.rs` `pub(super)` so the `request_lease` test module can reuse it.

## Where should the reviewer start?

- `lib/llm/src/kv_router/request_lease.rs`: `replica_observer` and `WeakRequestLeaseObserver`, then the new test at the top of the `tests` module.
- `lib/llm/src/kv_router.rs`: the one-line change in `KvRouter::new` where the observer is handed to the scheduler.

## Validation

Both tests in the module pass. The regression test was also run against the previous strong observer in a throwaway worktree, where the `manager.upgrade().is_none()` assertion fails, so the test does detect the cycle. `cargo fmt --all --check` is clean.
