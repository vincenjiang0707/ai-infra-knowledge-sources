## Description

The example profiler only ever records the first `NCCL_PROFILE_GROUP_API_POOL_SIZE` (8 by default) groups of a run. Every group API event owns its CollApi, P2pApi and KernelLaunch children and each child takes a reference on it. The KernelLaunch child takes its reference in `exampleProfilerStartEvent` but nothing releases it: `exampleProfilerStopEvent` returns early for that type and the `updateEvent` branch that would do it is never reached. Since 2.31 a pool slot is only reused once its refCount is 0, so every group that launched a kernel keeps its slot forever. After 8 such groups the pool is full, later group API events are dropped, and since NCCL passes the (now NULL) group handle as the parent of the CollApi/P2pApi/KernelLaunch events, those are dropped too. That is what #1910 asks about.

#1908 is the other half of the same lifecycle. When a group slot is recycled the plugin drains the group's child queues, calls `resetTaskEvents` on the CollApi/P2pApi children and advances `collApiPoolBase`/`p2pApiPoolBase` once more, although those children already advanced them when they retired in `updateEvent`. Today that code never runs (no group is ever recycled once a kernel was launched); with #1910 fixed it would run on every recycle, double count the bases and reset the task queue of a CollApi/P2pApi slot that a newer group may already be using.

This change makes every child kind retire itself exactly once and the group retire exactly once:

- the KernelLaunch stop falls through to `updateEvent`, which stamps `stopTs`, returns the slot to the kernelLaunch pool and releases the group, the same way the CollApi and P2pApi cascades do;
- the group holds a reference on itself from start to its API stop, so a group whose API children were all dropped (child pool full) does not retire once per kernel plan, and a childless group retires at all;
- `updateEvent` reads a CollApi/P2pApi event's parent before releasing its slot, since the application thread can reuse the slot right after the release;
- the GroupApi reuse path only empties the child queues.

## Changes & Impact

- `plugins/profiler/example/plugin.cc`: the changes above, 18 lines added, 27 removed. No change to NCCL core or to the plugin API.

Tested on one node (RTX 5070 Ti + RTX 2070) with a small program that issues one AllReduce group and one Send/Recv group per iteration under the example profiler with all event bits set, one channel, a stream sync per iteration, and checks the last `groupApiId` in the trace. On master 40 groups leave groupApiId 0..7 in the trace; with the change the last 8 groups are there, also with 3 ranks, with one rank per GPU, with 400 groups, with `NCCL_PROFILE_GROUP_API_POOL_SIZE=4`, with 12 communicators per group (more CollApi events per group than the CollApi pool holds), with `NCCL_PROFILE_P2P_API_POOL_SIZE=2` (P2pApi children dropped), and without the per-iteration sync. An instrumented build showed every pool base equal to its index at finalize and no refCount going negative in all of those. `git clang-format` clean, `-Wall -Wextra` warning count unchanged.

Things this does not change, so nobody reads it as "the pools now always recycle": the pools still drop groups when the application runs more than `NCCL_PROFILE_GROUP_API_POOL_SIZE` groups ahead of the GPU; with an event mask that has only the API bits, or a Coll/P2p task pool smaller than the tasks in flight, the CollApi/P2pApi children never get their completion cascade and the group pool stalls the same way as before; CUDA graph replays re-run the task cascade on the capture-time CollApi event and break the counts (same on master); the CE path decrements the CollApi refCount directly. And with more than one channel per collective the Coll/P2p task refCount is not primed with the channel count, so a task can retire early; on master this is hidden by the KernelCh type width bug (#1961, PR #2391). All of these are pre-existing and separate.

Not tested: network transports (ProxyOp/NetPlugin events), PXN detached proxy ops and CE collectives; their branches are untouched.

## Performance Impact

None on NCCL. In the plugin, one fewer loop body per group reuse.
