## 正文

## Description

A process holding live CUDA multicast objects cannot be checkpointed today: `cuCheckpointProcessCheckpoint` hangs even on an unbound multicast group.
This makes any NVLS-enabled communicator incompatible with `cuda-checkpoint`,
blocking checkpoint/restore of training jobs on NVLink SHARP systems, which are arguably one of the highest value use-case for us at Modal.

This PR extends `ncclCommSuspend`/`ncclCommResume` to cover the NVLS
multicast layer (`ncclNvlsSuspend`/`ncclNvlsResume` in `transport/nvls.cc`), which resolve VA accounting issues making the suspend / resume API compatible with memory snapshots. 

## Related Issues

- https://github.com/NVIDIA/nccl/issues/2337

## Changes & Impact

No public API changes and no breaking changes. `ncclCommSuspend`/`ncclCommResume`
keep their existing signature and the NVLS suspend / resume additions happen internally as steps for that flow. 

## Performance Impact

Given that all new work happens only inside suspend/resume routines, this change should not have performance impact in any other part of NCCL.

I am opening this PR for guidance. I'd be happy to do more testing and benchmarking as needed. Feedback would be very much appreciated.
