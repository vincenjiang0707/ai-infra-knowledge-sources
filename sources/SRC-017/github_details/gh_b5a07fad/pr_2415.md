# [PR #2415] Drop misplaced const from ncclComm_t API parameters

## 正文

## Description

Five functions in `nccl.h` take `const ncclComm_t comm`: `ncclCommCount`, `ncclCommCuDevice`, `ncclCommUserRank`, `ncclCommRegister` and `ncclCommDeregister`. Since `ncclComm_t` is `struct ncclComm*`, that spells `struct ncclComm* const`, so the const is on the parameter variable and not on the communicator. It isn't part of the function type, a caller holding a `const struct ncclComm*` still can't pass it, and it reads like a read-only promise the code doesn't keep: the three query functions go through `ncclCommEnsureReady` and `ncclCommGetAsyncError`, which stores to `comm->groupJob`, and register/deregister update `comm->regCache`.

This just removes the qualifier so these five look like every other entry point (`ncclCommGetAsyncError`, `ncclGetLastError`, ... all take `ncclComm_t`). I went with dropping it rather than `const struct ncclComm*`: the latter changes the function types (code that takes these functions' addresses into `ncclResult_t (*)(ncclComm_t, int*)` stops compiling in C++, and in C with GCC 14's default `-Werror=incompatible-pointer-types`), needs a `const_cast` in front of `ncclCommEnsureReady` and `ncclRegister`, and would be untrue for register/deregister anyway.

## Changes & Impact

- `src/nccl.h.in`: the five declarations and their `pncclXxx` twins.
- `src/init.cc`, `src/register/register.cc`: matching definitions and `NCCL_API` lines, plus the `NCCL_API` line of `ncclGetLastError`, which had the same const while the header and the definition didn't.
- `src/include/register.h`, `src/register/register.cc`: the internal `ncclCommGraphRegister`/`ncclCommGraphDeregister` declarations copied the spelling.
- `docs/userguide/source/api/comms.rst`: signatures updated to match.
- `contrib/nccl_checkpoint/shim.cc`, `shim_checkpoint.cc`: the hand-written interposers of `ncclCommRegister`/`ncclCommDeregister` copied the signature and had `const_cast<ncclComm_t>(comm)` all over because of it; both go. The generated part of the shim picks the new header up on its own.

No API or ABI change: top-level const on a parameter is ignored for type compatibility in C and C++, so existing callers, function-pointer wrappers and the `pnccl` aliases compile and link unchanged. Checked that `nm -D` on `libnccl.so` lists the same symbols before and after. The generated nccl4py Cython files still say `const ncclComm_t`; they declare their own `ncclComm_t` and never include `nccl.h`, so they are unaffected and I left them for the generator.

Tested on one node with two GPUs (RTX 5070 Ti + RTX 2070): `make src.build WERROR=1` clean, `git clang-format` clean, a small program that creates a 2-rank communicator with `ncclCommInitAll`, calls the five functions, registers and deregisters a buffer and runs an allreduce with a data check (both GPUs, each GPU alone, and with P2P and SHM disabled), nccl-tests `all_reduce_perf` and `sendrecv_perf` with `-g 2` rebuilt against the new header, and the checkpoint shim rebuilt with its pytest harness (`--checkpoint-mode=shim`). A C11 file that redeclares the five functions without the const next to `nccl.h` compiles with `-Wall -Wextra`, and a C++ `static_assert` that the function types equal the unqualified ones passes with both the old and the new header.

## Performance Impact

None, declarations only.
