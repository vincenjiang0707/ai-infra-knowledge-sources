## 正文

## Description

GDAKI creates send-only RC QPs, so a GPU-side application cannot use RDMA Write with Immediate notifications: the receiver has neither receive credits nor a GPU-visible receive CQ. This PR adds opt-in receive-queue resources for connected remote main GDAKI QPs.

`NCCL_GIN_GDAKI_RECV_DEPTH` defaults to zero and preserves the existing send-only behavior. When enabled, the backend allocates an RQ and a non-collapsed receive CQ, pre-posts receive WQEs using the existing sink MR, and exports RQ/CQ state for GPU-side progress. Self and companion QPs remain send-only.

The application owns the immediate-data protocol, CQ polling, and credit replenishment. This PR does not add a public NCCL WImm API or a cross-backend protocol.

## Related Issues

Addresses the implementation proposed in #2417.

## Changes & Impact

- Adds an optional `NCCL_GIN_GDAKI_RECV_DEPTH` parameter, defaulting to zero.
- Retains the device-QP size and existing key offsets by using reserved descriptor space for RQ/CQ state.
- Rejects CPU-proxy and software-emulated DBR modes when an RQ is requested because receive credit replenishment requires a GPU-addressable RQ DBR.
- Contains a small preceding cleanup commit for CQ resource-error paths.
- Does not change public NCCL APIs or default-path behavior.
