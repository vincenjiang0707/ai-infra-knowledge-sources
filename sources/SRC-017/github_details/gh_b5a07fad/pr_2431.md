# [PR #2431] [Fix] nvls: wire NVLS buffers per channel so a shared parent is not left unset

## 正文

## Problem

Fixes #2430.

With `splitShare`, a child communicator reuses its parent's NVLS resources and per-channel NVLS peers but can use fewer NVLS channels (e.g. `config.nvlsCTAs`). `ncclNvlsBufferSetup()` runs lazily on the first comm to launch an NVLS collective. It wired only that comm's channels, with that comm's channel count as the buffer stride and allocation size, and then marked the **shared** resources `inited`. If the child ran first, the parent's remaining channels kept NULL buffer pointers, and the parent's next NVLS collective faulted with an illegal memory access.

## Fix

- Size and lay out the NVLS data buffers by the owning comm's channel count (`resources->nChannels`), the same way the credit buffers are already laid out in `ncclNvlsSetup()`. The layout no longer depends on which comm calls setup first.
- Replace `bool inited` with `int nChannelsInited`. Each call wires only the channels in `[nChannelsInited, comm->nvlsChannels)`, so channels that are already in use by another comm are not touched again.

When the parent runs first, the behavior is identical to before: same layout, all channels wired once, and later calls from the child return early.

Tradeoff: if a child runs NVLS first, the shared data buffer is now allocated at the owner's full size (the size the parent would allocate anyway), not the child's smaller size. The MC partition was already reserved at that size.

## Testing

H200 x3 (NVSwitch), CUDA 12.8, driver 580.159.03. Reproducer: one thread per GPU; the child is split with `splitShare=1, nvlsCTAs=N`; 256 MB AllReduce with `NCCL_ALGO=NVLS`; results checked on the host.

| Scenario | master (2.32.3-1) | this PR |
|---|---|---|
| child nvlsCTAs=1/2/4/8 first, then parent | illegal memory access (4/4) | PASS (4/4) |
| parent first, then child nvlsCTAs=1/2/4/8/16 | PASS | PASS |
| child nvlsCTAs=16 first | PASS | PASS |
| child(2) → sibling(8) → parent → child | illegal memory access | PASS: wiring grows 0→2→8→16 |
| same matrix with `splitShare=0` | — | PASS (10/10) |

Also ran nccl-tests `all_reduce_perf`, `reduce_scatter_perf` and `all_gather_perf` with `NCCL_ALGO=NVLS -c 1` (8 B – 256 MB): all 0 errors. The change touches only one-time setup, not the data path.

The reproducer source is attached to #2430.
