# [PR #2448] Fix symmetric AllReduce avg kernel selection

## 正文

### Description

`ncclAllReduce` with `ncclAvg` on buffers registered as symmetric windows fails with `ncclUnhandledCudaError` for every float type (float, half, bf16, fp8 e4m3 and e5m2). With `NCCL_DEBUG=WARN` you get `ncclSymkGetKernelIndex: unknown red op 4 for id 0` and then `Cuda failure 'invalid device function'`.

What happens: since 2.30 (8df9d244) `ncclSymkImplemented()` says AllReduce supports `ncclDevSumPostDiv`, same as ReduceScatter, but `generate.py` only generates avg kernels for ReduceScatter (the AllReduce loop still has `if red == "avg": continue`). So the symmetric scheduler takes the task, `ncclSymkGetKernelIndex()` returns -1 with a warning, and `ncclSymmetricTaskScheduler()` uses that -1 to index `ncclSymkKernelList` and `ncclSymkKernelMaxDynamicSmem`. The launch then fails on a garbage function pointer.

Before 2.30 an avg AllReduce was rejected by the symmetric path and ran on the regular kernels. This PR restores that: `ncclSymkImplemented()` only accepts `ncclDevSum` for AllReduce, so avg goes back to the regular scheduler, which handles symmetric-window buffers fine (same as every integer reduction today). It also checks the -1 from `ncclSymkGetKernelIndex()` in the scheduler and returns `ncclInternalError` with a warning instead of reading out of bounds, so a future kernel table mismatch shows up as a clear NCCL error.

If you would rather add avg AllReduce symmetric kernels, that is a bigger device code change and I did not attempt it; this PR just makes the call work again.

Fixes #2447

### Changes & Impact

- `src/sym_kernels.cc`: `ncclSymkImplemented()` splits the AllReduce and ReduceScatter cases; AllReduce only accepts `ncclDevSum`, ReduceScatter keeps `ncclDevSum` and `ncclDevSumPostDiv`.
- `src/scheduler/symmetric_sched.cc`: return `ncclInternalError` when `ncclSymkGetKernelIndex()` returns -1.

Tested on an RTX 5070 Ti (sm_120) with two ranks on the same GPU (`NCCL_MULTI_RANK_GPU_ENABLE=1`), CUDA 12.9, driver 595.84, nccl-tests 2.20 MPI build: `all_reduce_perf -R 2 -c 1 -o avg` fails before and passes after for all five float types; `-o sum -R 2` still uses the symmetric kernel (`AllReduce_AGxLL_R`) and `reduce_scatter_perf -R 2 -o avg` still passes on its symmetric avg kernel. `NCCL_DEBUG=INFO` shows the avg AllReduce now scheduled as `Algo RING proto LL`. Also ran all nccl-tests collectives with `-d all -o all -R 2`, with and without CUDA graphs, on that GPU, and `all_reduce_perf -g 2 -c 1` on a two-GPU PCIe box. I could not test real NVLink/NVSwitch, NVLS multicast, or GIN, but the change is only in the host side decision of which kernel family to use.

### Performance Impact

None for anything that worked before. Symmetric avg AllReduce goes from failing to running on the regular kernels; there was never a symmetric avg AllReduce kernel to lose.
