## 正文

## Summary

Improve NCCL P2P diagnostics for peers on the same host that cannot use P2P because they see different shared-memory devices.

This update keeps the change local to `src/diagnostics/p2p.cc`:

- keeps same-`hostHash` peers in the diagnostics candidate set, including peers separated by `/dev/shm` isolation
- preserves ownership tracking for dynamically constructed rank sets
- wraps the existing `ncclTopoCheckP2p` call in a diagnostics-local helper
- identifies `same hostHash + different shmDev` locally as `shmIsolation`
- logs these topology-skipped edges through `INFO(NCCL_INIT, ...)`
- does not treat shared-memory isolation as a diagnostic test failure
- does not modify the shared topology API or transport-selection behavior

Related to #1781.

## Motivation

Peers on the same physical host can see different `shmDev` values when running in isolated `/dev/shm` namespaces.

`ncclTopoCheckP2p` already rejects P2P for this case. However, these peers can be separated from the topology-local rank group before P2P diagnostics inspect them, so the reason for the skipped edge is not visible.

The diagnostics candidate set therefore includes peers sharing the local rank's `hostHash`. A helper local to P2P diagnostics calls the existing `ncclTopoCheckP2p` and, when P2P is rejected for a same-`hostHash` pair with different `shmDev` values, records the skipped edge as:

    reason=shmIsolation

This only improves diagnostic visibility; it does not make the pair eligible for P2P.

## Expected diagnostic output

For same-host peers with different shared-memory devices:

    Diagnostics P2P skipped srcRank=0 dstRank=1 reason=shmIsolation srcShmDev=87 dstShmDev=88

The edge is skipped rather than counted as a failed P2P diagnostic.

## Validation

The PR now targets the latest `dev` branch and contains one change:

    src/diagnostics/p2p.cc

`git diff --check` passes.

A local macOS `src.build` cannot complete because NCCL's generated device-header build requires the supported CUDA/Linux build environment; the failure occurs while generating `build/include/nccl_device/*`, before compiling this P2P diagnostics change.

DCO passes.

## Notes

The candidate-set expansion remains restricted to peers with the same `hostHash`. MNNVL and cross-clique behavior are preserved.

No changes are made to `ncclTopoCheckP2p` or the shared topology API.

### teojgo · 2026-09-03

@namtran1812 After a second review pass, I think it may be cleaner to keep this additional check local to the P2P diagnostics without expanding the normal diagnostic rank set.

`comm->peerInfo` already contains the hostHash and `shmDev` for every rank. Each rank could scan this information directly and identify peers with the same hostHash but different `shmDev` values. Peers with different hostHash values are already handled by the existing topology and MNNVL logic.

The isolated pair can still be logged through `ncclDiagP2pLogEdge()` to follow the existing P2P debug-record convention. A zero-initialized diagnostic record with pathType set to `PATH_DIS` would report `path=DIS`, `handle=NONE`, and `topoRead=0`, correctly indicating that no handle or read mode was selected before the pair was rejected. The shared-memory device information can be included as:

`reason=shmIsolation srcShmDev=<srcDev> dstShmDev=<dstDev>`

The resulting message would remain an `INFO(NCCL_INIT)` debug record:

`NCCL INFO Diagnostics P2P skip ...`

rather than being reported as an active NCCL DIAG failure.

This approach would leave `localRankToRank`, MNNVL grouping, allocation ownership, synchronization, and `ncclTopoCheckP2p()` unchanged.
