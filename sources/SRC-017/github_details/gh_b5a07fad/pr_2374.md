# [PR #2374] bootstrap: close accepted sockets on error and abort paths

state: open | updated: 2026-09-11T10:05:42Z

## 正文

## Summary

Closes accepted / listening sockets that were leaked on error and abort paths in
the bootstrap layer. All changes are in `src/bootstrap.cc`.

## Bugs and fixes

### 1. `bootstrapRoot`: accepted socket leaked on `socketRecv` failure

In the root's receive loop the code accepts a connection into a local `sock` and
then does `socketRecv(&sock, &info, ...)`. On failure the `goto out` left the
just-accepted socket open, leaking its fd for every rank whose `extInfo` recv
fails. Now the socket is closed before bailing:

```c
if ((res = socketRecv(&sock, &info, sizeof(info))) != ncclSuccess) {
  (void)ncclSocketClose(&sock);
  goto out;
}
```

### 2. `bootstrapInit`: accepted socket and root listen socket leaked on `socketRecv` failure

When receiving the ring "next peer" info from the root, the code accepts into
`sock` and receives into it with `NCCLCHECK`, which `return`s on error without
closing either `sock` (accepted) or `listenSockRoot` (the root listen socket).
Both are now closed on failure. Note it jumps to `exit`, not `fail`: at this
point `proxySocket` is not yet allocated, and the `fail` label does
`free(proxySocket)` on that uninitialized pointer.

### 3. `unexpectedFree`: pending unexpected-connection sockets leaked on abort/destroy

`unexpectedFree` walked the `unexpectedConnections` list freeing each element but
never closed the socket embedded in it, leaking one fd per pending unexpected
connection whenever a comm is aborted/destroyed with connections still queued.
Each element's `sock` is now closed before the element is freed, and the list
head is set to `NULL` afterwards.

`ncclSocketClose` is a safe no-op on an already-closed / invalid socket, so these
additions are safe on every path that reaches them.

## Verification

Verified by static analysis against master (`7b83616d`, v2.31.2-1). I don't have
multi-GPU/NVSwitch hardware or a full NCCL build on my dev box, so these paths
were not runtime-tested; the changes are self-contained cleanup-path edits.

Disclosure: this contribution was authored with an AI coding assistant (Claude) and reviewed before submission.

### EylonKrause · 2026-09-11

Thanks — reworked along the lines you suggested, and rebased onto `dev` (retargeted the PR) since the mirror to dev would otherwise conflict:

- **bootstrapRoot:** `sock` is hoisted out of the receive loop and initialized before it, and `out:` now closes it — a no-op unless we bailed out with an accepted connection open. The per-iteration `ncclSocketInit` stays so each accept starts clean.
- **bootstrapInit:** the cleanup moved to `fail:`, which now closes the accepted socket and the root listen socket before freeing `proxySocket`. To make that safe on every path I initialize both sockets up front, NULL-initialize `proxySocket`, and converted the function's `NCCLCHECK`s to `NCCLCHECKGOTO(..., result, fail)`. The three locals those earlier jumps would have crossed (`offset`, `curr_root`, `nRankRoot`) are declared at the top, otherwise the gotos would not compile.
- **unexpectedFree:** you're right, `dev`/`staging` already close the socket there — dropped.

Caveat as before: I can't build or run NCCL here, so this was checked by inspection (plus an independent review pass for goto/initialization and ownership issues), not by a compile. Happy to adjust if the build or your tests flag anything.
