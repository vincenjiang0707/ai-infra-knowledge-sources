# [PR #2450] Return ncclInvalidArgument for bad init arguments

source: https://github.com/NVIDIA/nccl/pull/2450
state: open | updated: 2026-09-26T15:28:41Z
labels: 

## 正文

### Description

A few argument errors in the init calls crash instead of returning ncclInvalidArgument:

- `ncclCommInitRankConfig(&comm, 0, id, 0, cfg)` (nranks = 0) and `ncclCommInitRankScalable` with nId <= 0 or nId > nranks: the nId check at the top of `ncclCommInitRankDev()` returns before `*newcomm = NULL` is set, and the callers' fail path then dereferences `*newcomm`, which is whatever the user had in the variable (usually uninitialized).
- `ncclCommInitRankScalable` with a NULL `commIds` array: no check, crashes in memcpy.
- `ncclCommInitAll(comms, 0, devlist)`: `ndev < 0` is rejected but `0` is not, and the NVTX payload then reads `comms[0]`, which was never written.
- `ncclCommSplit(NULL, ...)` inside a user group: `ncclCommInitChildComm()` exits on the argument checks before `*newcomm = NCCL_COMM_NULL`, and `ncclCommSplit`'s exit path reads `*newcomm` and `comm` (outside a group the group error short-circuits that; `ncclCommShrink` with `excludeRanksCount == 0` leaves `*newcomm` uninitialized the same way).

The patch moves the nId check after the existing pointer and rank checks so it goes through the fail label, adds a `PtrCheck` for `commId`, makes the device-count check `ndev <= 0`, and sets `*newcomm = NCCL_COMM_NULL` right after the `newcomm` pointer check in `ncclCommInitChildComm()`. WARN texts and return codes are the ones the existing checks already use.

### Related Issues

Fixes #2449

### Changes & Impact

src/init.cc only, +11/-8, in `ncclCommInitRankDev()`, `ncclCommInitAll()` and `ncclCommInitChildComm()`. No API or behavior change for valid arguments. A bad nId is now rejected after `ncclInit()` and `cudaFree(NULL)` ran, like every other argument error in that function. `ncclCommInitAll` with `ndev == 0` returns ncclInvalidArgument instead of crashing (or, before the NVTX payload existed, silently returning success).

Independent of open PR #2373, which changes the fail blocks of the same functions (different hunks). Tested on a 2-GPU box (RTX 5070 Ti + RTX 2070, CUDA 12.9): a small program with the eight bad calls crashes or leaks the uninitialized pointer 8/8 before and returns ncclInvalidArgument with `*newcomm == NULL` 8/8 after (plus the control); nccl-tests all_reduce with -g 2, mpirun -np 2, -t 2 and single GPU pass with -c 1; WERROR=1 build clean.

### Performance Impact

None.
