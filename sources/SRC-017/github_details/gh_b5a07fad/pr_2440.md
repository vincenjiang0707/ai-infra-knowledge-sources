## 正文

## Description

The hybrid-EP (HT) dispatch/combine JIT kernels in `contrib/nccl_ep/device/hybrid_ep.cuh` compute buffer offsets as `slot_index * stride` with both operands `int32`, then add the product to a typed pointer. The receiver slot space is partitioned by source rank at `max_tokens_per_rank` granularity, so the offset for high sender ranks scales with `rank * max_tokens_per_rank * HIDDEN_DIM` and crosses 2³¹ well within supported configurations:

- With 32 LSA ranks × `max_tokens_per_rank=32768` × `hidden_dim=4096`, the dispatch destination offset goes negative for sender ranks ≥ 16 → deterministic `CUDA_ERROR_ILLEGAL_ADDRESS` in `dispatch_nodes1_lsa32_*` on the upper half of the ranks.
- Observed on a 397B-parameter MoE at TP4/EP32: ranks 20–31 fault, the fault follows the rank index (not the hosts), and is independent of the capacity factor. `max_tokens_per_rank=16384` runs clean with zero margin — `524287 * 4096` is 4 KiB below 2³¹.
- The combine-side read at `slot * HIDDEN_DIM * size_u16<kTokenDtype>()` is in **bytes**, so it overflows at half the token count.
- The local-dup zone write offset scales with the full receive capacity and overflows similarly under large capacity factors.

This PR casts the slot index to `size_t` at every slot-scale multiply: the `dispatch_s2g_issue_token` token/prob/scaling-factor destination pointers, the combine g2s source reads, and the local-dup pad writes.

## Changes & Impact

No API or behavior change for configurations that previously worked; configurations that previously faulted now address correctly. Header-only changes to the runtime-JIT'd device source — no library binary is affected and the JIT cache re-keys on the new source automatically. Only the slot-scale multiplies that can exceed 2³¹ under currently supported configurations are widened; index arithmetic bounded by per-chunk or per-warp extents remains `int32`.

## Performance Impact

None expected: the widened multiplies are address arithmetic on values already feeding 64-bit pointer additions. Validated in production MoE training (397B parameters, TP4/EP32, GB300) at `max_tokens_per_rank=32768`, where unpatched kernels deterministically fault; throughput at previously-working sizes is unchanged.
