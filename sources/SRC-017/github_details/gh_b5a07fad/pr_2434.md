# [PR #2434] [Fix] net/ib: use ID-based matching whenever receives are pre-posted

state: open | updated: 2026-09-22T03:27:52Z

## 正文

## Problem

Pre-posted IB receive work requests all carry `NCCL_IB_RECV_WR_ID_DUMMY` (`UINT64_MAX`) as `wr_id`, so with pre-posting the receiver can only find the request from the ID carried in the immediate data (`BY_ID` matching). The conditions that turn these on are out of sync:

- `ncclIbRecvCommInit()` pre-posts when `NCCL_IB_PREPOST_RECEIVE_WORK_REQUESTS=1`, when OOO RQ is enabled, or when the resiliency context exists. `ncclIbResiliencyInit()` creates it for any non-zero `NCCL_IB_RESILIENCY_PORT_FAILOVER`.
- `ncclIbBaseCommInit()` forces `BY_ID` only for OOO RQ and `NCCL_IB_RESILIENCY_PORT_FAILOVER == 1`.

With `NCCL_IB_PREPOST_RECEIVE_WORK_REQUESTS=1`, or `NCCL_IB_RESILIENCY_PORT_FAILOVER=2`, the receiver stays on index matching and indexes `recvReqs[wc->wr_id]`, i.e. `recvReqs[-1]`. The first receive then fails:

```
NET/IB: Recv comm could not retreive a request found for a successful completion (comm=0x..., wc.wr_id=-1, opcode=129, ...)
... internal error - please report this issue to the NCCL developers
```

## Fix

Force ID-based matching in `ncclIbBaseCommInit()` for every condition that makes the receiver pre-post: OOO RQ, an enabled resiliency context (`baseComm->resiliency`, set just above by `ncclIbResiliencyInit()`), or explicit pre-posting. This runs for both send and recv comms, so the sender switches its immediate data to the request ID as well. The now-unused `extern ncclParamIbResiliencyPortFailover()` declaration is removed.

## Testing

2x H200 on one node, forced onto IB loopback (`NCCL_P2P_DISABLE=1 NCCL_SHM_DISABLE=1`, 1x HDR port). `all_reduce_perf -c 1`, 8 B – 64 MB:

| Setting | master (2.32.3-1) | this PR |
|---|---|---|
| `NCCL_IB_PREPOST_RECEIVE_WORK_REQUESTS=1` | internal error on first receive | 0 errors |
| `NCCL_IB_RESILIENCY_PORT_FAILOVER=2` | internal error on first receive | 0 errors |
| `NCCL_IB_RESILIENCY_PORT_FAILOVER=1` | 0 errors | 0 errors |
| `NCCL_IB_PREPOST_RECEIVE_WORK_REQUESTS=0` | 0 errors | 0 errors |
| `NCCL_IB_OOO_RQ=0` | 0 errors | 0 errors |

`sendrecv_perf -c 1` with `NCCL_IB_PREPOST_RECEIVE_WORK_REQUESTS=1`: 0 errors with this PR.
