## 正文

## Summary
- Adds optional `NCCL_P2P_VALIDATE=1` in `p2pCanConnect`: **enable peer access**, perform a **device-side peer store** (SM kernel with `__threadfence_system`, matching the #2335 discriminator), then verify with an **owner-local** read. Failed pairs disable P2P and fall back.
- Results are cached per CUDA device pair under a **mutex** (safe for concurrent communicator init).
- When validation is requested but a peer is **invisible** (`CUDA_VISIBLE_DEVICES` / `busIdToCudaDev == -1`) so the SM probe cannot run, **fail closed** and disable P2P for that pair instead of allowing the unvalidated IPC/VMM P2P path. Out-of-range device ids likewise fail closed.
- Documents the false peer-access / private-mirror failure class and warns that `NCCL_P2P_USE_CUDA_MEMCPY` can complete with wrong data on this class.
- Addresses https://github.com/NVIDIA/nccl/issues/2335

This does not fix driver/GSP aperture programming; it fails closed when the direct peer visibility contract is broken, and also when validation was requested but cannot be performed. The probe intentionally avoids `cudaMemcpyPeer` without peer access, which CUDA may stage through host memory and pass even when NCCL’s SM peer aperture is a private mirror.

Default remains off (`NCCL_P2P_VALIDATE=0`) per CONTRIBUTING guidance on workarounds for external components.

### aarav1109s · 2026-08-10

Addressed the remaining invisible-device blocker on `7cfb5757`:

**Fail closed when the probe cannot run.** On CUDA 10.1+, NCCL still allows P2P with devices hidden by `CUDA_VISIBLE_DEVICES` via IPC/VMM. The SM-store/owner-read probe needs visible `cudaDev` indices, so with `NCCL_P2P_VALIDATE=1` that path now sets `*ret = 0` instead of returning success unvalidated. Out-of-range device ids in the validate cache likewise fail closed. Docs updated accordingly.

**Builds / functional tests.** This contributor environment has no CUDA toolkit / GPUs (`nvcc` / `nvidia-smi` unavailable), so Makefile/CMake builds and the healthy multi-GPU / #2335 verification items in the test plan remain unchecked and need a GPU host (or maintainer CI) before merge. Happy to iterate further if you prefer moving validation onto the IPC/VMM import path instead of fail-closed at `p2pCanConnect`.

### xiaofanl-nvidia · 2026-08-21

As per the discussion on https://github.com/NVIDIA/nccl/issues/2335, closing this PR since we believe it's better to address the driver issue directly. 

BTW from NCCL side, we have released some new tools such as NCCL diagnostics which could be helpful to find this kind of lower level issues in the future. We would like to introduce these systems in a way that is isolated to the RAS subsystem so that we don't impact performance for users with healthy systems, and keep the NCCL code modular and maintainable.
