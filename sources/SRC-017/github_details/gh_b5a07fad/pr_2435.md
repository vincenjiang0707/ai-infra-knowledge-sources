## 正文

## Problem

Fixes #1598.

`ncclTopoComputeP2pChannels()` derives `p2pnChannels` from `nChannels`, which is already capped by `config.maxCTAs` / `NCCL_MAX_CTAS`. It then rounds the value up to a power of 2, which p2p peer-to-channel mapping relies on. When maxCTAs is not a power of 2, the rounded value exceeds it. P2P work is spread over all `p2pnChannels`, and the kernel grid is the number of channels used, so send/recv and all-to-all kernels launch more CTAs than the user allowed. This defeats `maxCTAs` both for reserving SMs for overlapped compute and for limiting per-rank resources with multiple ranks per GPU, which env.rst recommends it for.

As @sjeaugey noted in #1598, `NCCL_MAX_CTAS` should cap the number of channels for all use cases.

## Fix

After the round-up, clamp `p2pnChannels` to `pow2Down(config.maxCTAs)`, so it stays a power of 2 and does not exceed the cap. Also remove the stale comment saying max/minCTAs were already honored there. The default maxCTAs (`MAXCHANNELS`) is a power of 2, so default behavior is unchanged. A p2p channel count below the collective channel count is already a supported state (e.g. `NCCL_MAX_P2P_NCHANNELS=4`).

Tradeoff: with a non-power-of-2 cap, p2p now uses the next lower power of 2 (e.g. 4 channels for `maxCTAs=5`), where master used the next higher one and exceeded the cap. If `minCTAs == maxCTAs` and the value is not a power of 2, p2p ends up below minCTAs; honoring the upper bound seemed the right priority.

This fixes the communicator-level cap. The per-call `ncclAlltoAllConfig` maxCTAs issue (#2421) is separate.

## Testing

4x H200, `alltoall_perf -b 16M -e 16M -t 4 -g 1`. Channel counts are from the INIT log; SendRecv kernel grid sizes are from `nsys` (`cuda_gpu_trace`, GrdX):

| `NCCL_MAX_CTAS` | master: coll / p2p channels, SendRecv grid | this PR |
|---|---|---|
| unset | 24 / 32, grid 24–32 | 24 / 32, grid 24–32 (unchanged) |
| 16 | 16 / 16, grid 12–16 | unchanged |
| 6 | 6 / 8, **grid 6–8** | 6 / 4, grid 3–4 |
| 5 | 5 / 8, **grid 6–8** | 5 / 4, grid 3–4 |
| 3 | 3 / 4, **grid 3–4** | 3 / 2, grid 2 |

`alltoall_perf` and `sendrecv_perf -c 1` (8 B – 128 MB) with `NCCL_MAX_CTAS=5` and `3`: 0 errors on master and with this PR.
