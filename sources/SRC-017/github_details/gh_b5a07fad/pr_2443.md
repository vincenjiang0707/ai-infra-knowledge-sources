# [PR #2443] Fix C++20 build of the fp8 pack casts in reduce_kernel.h

state: open | updated: 2026-09-23T20:18:18Z

## 正文

## Description

Building with `CXXSTD=-std=c++20` fails in `src/device/reduce_kernel.h`. The `EASY_CAST` specializations turn a packed fp8 vector (`__nv_fp8x2_e5m2` etc.) into a `float2`/`float4` with a functional cast, `VecB(...)`. In C++20 mode nvcc's front end reads `float2(x)` as parenthesized aggregate initialization (P0960) and tries to put the whole fp8 vector into `float2::x`, so every device file fails with `no suitable conversion function from "__nv_fp8x2_e5m2" to "float" exists`. gcc accepts the same line in C++20, so this is nvcc being stricter than the standard, but we have to build with nvcc.

The change spells the conversion as `static_cast<VecB>(...)`, which goes through the vector type's explicit `operator float2()`/`operator float4()` under every standard. Only that direction is changed: the reverse line builds the fp8 vector through its explicit constructor, which is not an aggregate, and compiles fine in C++20.

## Related Issues

Fixes #1770. Same fix as #1771 but limited to the one line that fails, with the reasoning and a standalone reproducer written up.

## Changes & Impact

One line in `src/device/reduce_kernel.h`. No API or ABI change, no behavior change: under the default standard the same conversion operator is picked as before, and `cuobjdump -sass` of the symmetric fp8 kernel objects that contain this code (`symmetric/all_reduce_sum_f8e4m3`, `symmetric/all_reduce_sum_f8e5m2`, `symmetric/reduce_scatter_sum_f8e4m3`, `symmetric/reduce_scatter_sum_f8e5m2`, the `RSxLDMC_AGxSTMC` variant) is byte-identical before and after.

Tested on 2.32.3-1 with CUDA 12.9 / gcc 13.3: full `make src.build CXXSTD=-std=c++20` now links `libnccl.so` (before: 4 errors in each of the 202 device units); default build with `WERROR=1` is warning-free; nccl-tests pass with both the default and the C++20-built library: `all_reduce_perf -g 2 -c 1` (float) across an RTX 5070 Ti + RTX 2070, and fp8 all_reduce / reduce_scatter / reduce (`-d f8e4m3`, `-d f8e5m2`, also `-o avg` and with CUDA graphs) with two ranks on the 5070 Ti (`NCCL_MULTI_RANK_GPU_ENABLE=1`; the 2070 is sm_75 and NCCL rejects fp8 reductions there). The symmetric kernels that contain this code need NVLink/P2P between GPUs and could not be executed here, only compiled and compared at the SASS level.

Not in scope: a C++20 build still prints deprecation warnings (implicit `this` capture in `all_gather.h`/`reduce_scatter.h`, `-Wvolatile` in `proxy.cc`/`enqueue.cc`/`symmetric_sched.cc`, enum arithmetic in `symmetric_sched.cc` and the vendored doca code). They are warnings only.

## Performance Impact

None, generated code is unchanged.
