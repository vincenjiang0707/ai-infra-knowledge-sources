# [PR #2427] net/ib: stop each Qp profiler event exactly once

source: https://github.com/NVIDIA/nccl/pull/2427
state: open | updated: 2026-09-21T06:48:37Z

## 正文

## Description

net_ib stops a request's Qp profiler events from two paths, so in the common success path the same event is stopped twice. The profiler API requires each event to be stopped exactly once. The profilers in this repo happen to tolerate the extra stop, so the bug is silent here. But a custom profiler that does real work on stop — free/recycle the handle, decrement a refcount, close a span — will double-free or crash. This PR makes the stop idempotent.

**Problem:** `ncclIbCompletionEventProcess` stops a Qp when its successful CQE is
reaped; `ncclIbRequestComplete` then unconditionally stops all of the request's
Qp events (a safety net for error/resiliency completions never stopped by the
per-completion path). In the success path both run, so each reaped Qp is stopped
twice.

**Solution:** add `ncclIbStopQpEvent()`, which stops an event only if its handle
is non-NULL and then clears the handle, making any later stop a no-op. Route all
four stop sites through it, keeping the request-complete safety net.

## Reproduction

1. Build with net profiling: `make NET_PROFILER=1`.
2. In a profiler plugin, enable the `ncclProfileNetPlugin` bit and count each
   NetPlugin `startEvent`/`stopEvent`.
3. Run over the in-tree IB transport: `NCCL_NET_PLUGIN=none NCCL_NET=IB`.

Without the fix, stops exceed starts (double-stopped Qps); with the fix they are
balanced 1:1.

## Changes & Impact

Single file `src/transport/net_ib/p2p.cc`: adds a `static inline` helper and
routes the four Qp `stopEvent` sites through it. No public API/ABI or data-path
change; all new code is under `#ifdef NCCL_ENABLE_NET_PROFILING`, so default
builds are unaffected.

## Performance Impact

None — only a NULL check and pointer clear per Qp `stopEvent`, and only when
built with `NET_PROFILER=1`.
