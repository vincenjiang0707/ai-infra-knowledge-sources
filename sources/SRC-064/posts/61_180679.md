Hi. I think this is much easier to disentangle than before:


My read of the current results is: **yes, there seems to be a real persistent path dependence in the protocol you are testing, not just “the model wrote two different answers once.”** The interesting question has shifted from *“does any difference survive?”* to *“which memory layer is carrying the surviving difference?”*

I would still keep the claim narrow. The current experiments seem to support persistence in the **book/state**, and in some conditions persistence into later **behavior** after the original event has left the last-k window. They do not yet show that *reconstruction itself* is necessary for that persistence, or that deliberate distortion is necessarily beneficial.

- make the current persist/ruminate fixtures replayable from a clean checkout;
- emit retrieval telemetry
**per probe/reply**, rather than only the folded summary;
- pick one late/far probe and intervene on it:
- if normal retrieval selects T0/the marked trace, try
`DropMarked`

`DropMarked`

##
What I think the current experiments already separate

I find the new **book / retrieval / behavior** split much more useful than treating “memory worked” as one variable.

I would distinguish four claims:

**Book persistence:** did the differing event or a descendant of it remain in persistent state?
**Retrieval persistence:** was that state actually selected for this particular probe?
**Behavioral influence:** did access to that state change the reply?
**Evolution benefit:** did mutable/reconstructive processing do something that a matched frozen selective memory would not?

The current report looks fairly strong on the first question in the tested protocol.

The last-k experiment is particularly useful because once T0 is outside the `k=8`

window, a later difference cannot simply be “the original text is still sitting in the prompt.” Your reported C1/C2 split after eviction therefore seems like a meaningful step beyond the original demonstration.

The later ablations also suggest that there may be **more than one route** from history to behavior.

For the five distinct same-schema hours, your report suggests that the distant late effect depends on the ladder/sleep path more than on direct episodic recall.

For the repeated pinned meeting, the no-sleep condition can apparently still bind the distant probe back to the repeated event, which looks more like a retrieval-driven route.

I would not collapse those into one mechanism. If both survive further testing, that is actually more informative:

```
history
|
+--> episodic trace --> retrieval --------------------> reply
|
`--> several related traces --> motif/belief --------> reply
|
`--> later traits ...
```


So “path dependence survives” can be true while the carrier differs by protocol.

What still seems open to me is the stronger question: **does the reconstructive/mutable part itself add something over selective persistent storage?**

That is a different claim from persistence.

##
The smallest causal test I would run next

I would choose **one** late/far probe first rather than rerunning every condition.

Something like:

```
Choose one late/far reply
|
|-- Did Observed select T0 / the marked support trace
| for THIS exact probe?
| |
| |-- yes --> DropMarked
| | |
| | |-- late effect disappears
| | | -> direct episodic retrieval is
| | | a strong mediator for this reply
| | |
| | `-- late effect survives
| | -> remove lineage-derived axioms next
| | |
| | |-- effect disappears
| | | -> motif/belief/trait is
| | | a strong carrier candidate
| | |
| | `-- effect survives
| | -> inspect mood/global state,
| | then correlated traces/variance
| |
| `-- no --> ForceMarked
| |
| |-- behavior changes
| | -> direct access is sufficient to affect
| | this probe even though normal retrieval
| | did not choose it
| |
| `-- behavior does not change
| -> retrieval alone is insufficient;
| inspect readout/probe sensitivity
```


The nice part is that most of this machinery already exists.

`Observed`

, `DropMarked`

, and `ForceMarked`

are already present in `retrieve.rs`

, so this does not require inventing another memory system.

There is also a useful conceptual connection to [Causal Intervention-Based Memory Selection](https://arxiv.org/abs/2605.17641). That work is not doing the same experiment, but I like the principle here: a memory being semantically related is weaker evidence than showing that adding/removing/changing it causally changes the downstream answer.

After the carrier is localized, a nice next extension would be a **matched semantic substitution** rather than only present/absent:

```
original memory
vs
no memory
vs
same-shape memory with a changed meaning
```


For example:

```
unfair cancellation
vs
no cancellation memory
vs
a cancellation that was expected/fair/resolved
```


If later behavior tracks the changed meaning, that is considerably harder to explain as just “some extra text was retrieved.”

##
One telemetry detail I would change before interpreting individual replies

There is one small thing in the current P1 reporting that I think is worth separating before reading `rank=1 / selected=true`

as the retrieval path for a particular late answer.

In the current `fold_sides`

, the folded `RetrievalSide`

uses:

- the
**best/minimum** T0 rank across the probes;
`t0_selected = true`

if **any** probe selected T0;
`selected_ids`

and `top`

from the **last** probe.

Those values are individually useful, but they describe different aggregations.

So it is possible for a folded row to say something equivalent to:

```
T0 rank = 1
T0 selected = true
selected_ids for the final probe = [... no T0 ...]
```


without any contradiction: an earlier probe selected it, while the final probe did not.

For the causal question, I think the cleanest output would simply be one `RetrievalDump`

beside each probe/reply:

```
probe
reply
T0 rank
T0 selected?
selected trace IDs
top candidates/scores
behavior marker / semantic score
```


That should cost essentially no extra LLM calls, and then a statement like “this late behavior occurred while T0 was selected” becomes directly inspectable rather than inferred from the folded row.

I would still keep the aggregate summary; I just would not use the aggregate rank as evidence about one specific reply.

##
If DropMarked does not remove the late effect

This branch seems especially interesting in the current architecture.

`DropMarked`

is an intervention on **episodic retrieval**. It is not an intervention on every state that may already have been produced from the marked episode.

In `engine.rs`

, an isolated probe sends both:

- recalled memories;
- living axioms;

to the narrator, together with current mood.

And in `ladder.rs`

, an `IdentityAxiom`

keeps its `support_trace_ids`

.

So this route is possible:

```
T0 / related episodes
|
v
sleep
|
v
motif / belief axiom
|
v
late reply
```


even if T0 itself is subsequently excluded from episodic retrieval.

I tried a very small synthetic check against the public API for exactly this architectural question — not a reproduction of the Grok P1 result.

I inserted two negative events under the same schema, ran `sleep()`

, and got a living axiom. I then marked both supporting traces and queried with `DropMarked`

.

The marked episodes were absent from selected retrieval, but the living axiom still reached the reply.

So if the live P1 result survives `DropMarked`

, I would not read that as “T0 did not matter.” A more precise interpretation would be:

direct episodic retrieval was not necessary at read time; a descendant state may be carrying the history instead.


Because the lineage is already stored in `support_trace_ids`

, the next control seems relatively cheap:

```
DropMarked
+
withhold any living axiom whose support_trace_ids intersect
the marked episode lineage
```


If the effect then disappears, the ladder-derived motif/belief becomes a much stronger mediator candidate.

If the effect still survives, **then** I would test mood/global affect before adding more machinery.

This also makes the ablations easier to interpret: “drop the episode” and “drop the consequences of the episode” are different interventions.

##
Scoring the quieter effects

I would keep the strict lexical marker.

It has very useful properties: it is simple, transparent, reproducible, and hard to move after seeing the outputs.

But I would treat it as one channel rather than the complete definition of influence.

For reconstructive memory, the most interesting far effect may be precisely a case where the original words disappear while a constraint on behavior remains.

A useful neighboring benchmark here is [LoCoMo-Plus](https://aclanthology.org/2026.acl-long.1150/). Its “cognitive memory” setting explicitly tests **cue–trigger semantic disconnect**: earlier interaction establishes a latent constraint such as a state, goal, value, or causal relation, while the later query does not simply ask for the original fact. The paper also points out that ordinary string-matching metrics can be poorly aligned with that setting.

That seems close to the measurement problem in your distant probes.

I would therefore keep something like:

```
A. strict lexical callback
- existing marker
- remains untouched
B. semantic/constraint outcome
- small rubric fixed before looking at the new outputs
- asks whether the response behaves consistently with the earlier experience
- does not require repeating the original wording
```


For example, if the earlier history establishes mistrust of unexplained institutional decisions, the semantic test should not be “did the reply contain the word injustice?” It should be a precommitted question such as whether the later answer becomes more guarded, asks for evidence, preserves optionality, etc.

The important part is to lock that rubric **before** evaluating the intervention outputs, rather than replacing the lexical metric after it becomes inconvenient.

##
Separating persistence from the reconstructive part

I think this is the next larger question after the causal carrier is localized.

There are at least two hypotheses that can both explain persistent divergence:

```
H1:
selective persistent storage is enough
H2:
selective storage + reconstruction / reconsolidation / abstraction
adds something important
```


To distinguish them, I would make the frozen comparator as strong as possible rather than treating it as a weak baseline:

- same admission/gating;
- same initial episodes;
- same retrieval budget;
- same downstream model;
- but the retained memory representation stops evolving.

Then compare it with full SelMem.

The result is informative in every direction:

**Frozen ≈ evolving**

The path dependence is still real, but reconstruction may not be load-bearing.

**Evolving > frozen, especially on distant/implicit probes**

Then abstraction or memory evolution becomes a much stronger candidate for what is carrying useful transfer.

**Evolving < frozen**

Also interesting: the mutation process may be introducing drift faster than it creates useful abstraction.

There is a useful warning/example in [Useful Memories Become Faulty When Continuously Updated by LLMs](https://arxiv.org/abs/2605.12978). Different task and different memory systems, so I would not transfer its result directly to SelMem, but it shows why an episodic/frozen comparator is worth taking seriously: repeated consolidation can eventually make a memory *less* useful, and an episodic-only control can remain competitive.

So I would treat “imperfection/reconstruction” as the thing to test, not as something already implied by the persistence result.

##
After persistence: can the path change when it should?

If the system really develops history-dependent state, eventually I think the more important test becomes not just:

can a path survive?


but:

can it revise without either forgetting everything or becoming locked into its old interpretation?


A small matched pair could be enough.

Should-change

Later evidence genuinely changes the meaning of the earlier event.

Example shape:

```
T0:
a project is cancelled in a way interpreted as unfair
later:
credible evidence shows why it happened,
or the responsible party corrects/repairs the situation
```


A useful memory should probably update something.

Stasis

Give equally substantial new information that is unrelated to the earlier interpretation.

The path should not disappear just because more text arrived.

Then measure the same layers separately:

```
book/state
retrieval
behavior
```


[STALE](https://arxiv.org/abs/2605.06527) is useful background for this distinction. Its setting is different, but one result is very relevant conceptually: an agent can have access to updated evidence and still fail to update its downstream behavior. So “the memory was corrected” and “the agent now acts as if it was corrected” should be separate measurements.

For SelMem this would also help distinguish adaptive path dependence from a self-reinforcing attractor/rumination effect.

##
A small reporting checklist for future runs

Since the project is moving quickly, I think future readers would benefit if every experimental result could be tied to a small immutable bundle:

```
exact SelMem commit
exact frozen stimulus file
raw model outputs
model/provider/version
sampling/reasoning settings
strict marker/scorer version
semantic rubric version, if any
per-probe retrieval dumps
intervention flags
which derived states remained visible at readout
```


That would make later comparisons much easier, especially once several pathways exist.

There is a related evaluation lesson in [HaluMem](https://arxiv.org/abs/2511.03506): end-to-end QA alone makes it difficult to identify where a memory error entered the pipeline, so they separate extraction, updating, and QA.

For SelMem I would use a slightly different decomposition:

```
admission/book
->
mutation/evolution
->
retrieval
->
derived state
->
behavior
```


The important part is not the terminology; it is making sure a successful or failed final reply is not silently attributed to the wrong stage.

So at this point I would not add much more machinery.

The current implementation already seems close to answering the more interesting version of the question: not merely **whether two identical agents can diverge after one history difference**, but **which persistent representation carries that divergence after the original context is gone**.

If the per-probe telemetry + one `DropMarked`

branch + one lineage-aware axiom cut can localize that path, I think that would strengthen the experiment more than a much larger set of unconstrained examples.
