## 正文

Hi,

Thank you for the great work and the useful tool you are developing. I am trying to profile a VLM using `genai_perf`. My triton package includes an ensemble for the VLM that was generated following the steps mentioned here for Qwen2-VL: https://github.com/triton-inference-server/tensorrtllm_backend/blob/main/docs/multimodal.md
I launched Triton server following the instructions provided on the link above and the image I am using is `nvcr.io/nvidia/tritonserver:25.01-trtllm-python-py3` with tensorrt_llm version `0.17.0.post1`.

I am running my profiling commands from a virtualenv that has `genai-perf==0.0.13` and `tritonclient==2.57.0` installed, where `perf_analyzer` was installed upon `tritonclient`'s installation.

My model is not OpenAI-Compatible by default, so I used Triton's OpenAI-Compatible frontend to launch the Triton server by following the instructions here for TensorRT-LLM models: https://github.com/triton-inference-server/server/tree/main/python/openai

The `genai-perf` command I used looks like this:
```bash
genai-perf profile -m my_ensemble_vlm \
    --tokenizer Qwen/Qwen2-VL-7B-Instruct \
    --endpoint-type vision \
    --image-width-mean 640 \
    --image-height-mean 424 \
    --image-width-stddev 0 \
    --image-height-stddev 0 \
    --endpoint v1/chat/completions \
    --url 0.0.0.0:9000 \
    --streaming --concurrency 16 \
    --num-dataset-entries 64 \
    --warmup-request-count 32 \
    --request-count 32 \
    --synthetic-input-tokens-mean 3000 \
    --synthetic-input-tokens-stddev 0 \
    --output-tokens-mean 150 \
    --output-tokens-stddev 0 \
    --extra-inputs max_tokens:150 \
    --random-seed 0 \
    -- --max-threads 64
```
I get an error when `genai-perf` tries to call `perf_analyzer`:
```Running Perf Analyzer : 'perf_analyzer -m my_ensemble_vlm --async \
    --stability-percentage 999 --warmup-request-count 32 --request-count 32 -i http -u \
    0.0.0.0:9000 --concurrency-range 16 --service-kind openai --endpoint v1/chat/completions \
    --max-threads 64 --input-data \
    artifacts/my_ensemble_vlm-openai-vision-concurrency16/inputs.json \
    --profile-export-file \
    artifacts/my_ensemble_vlm-openai-vision-concurrency16/profile_export.json'
Failed to retrieve results from inference request.
Thread [0] had error: OpenAI response returns HTTP code 400: {"detail":"only text message is supported, but got image_url"}
```
I suspect this error occurs because the [OpenAI-Compatible frontend](https://github.com/triton-inference-server/server/tree/main/python/openai) does not fully support multimodal input in the way `genai-perf` is constructing the requests.

Therefore, I tried launching the model without the OpenAI-Compatible frontend, using Triton directly as stated [here](https://github.com/triton-inference-server/tensorrtllm_backend/blob/main/docs/multimodal.md). In this scenario, I launched the Triton server on port 8000 and I get the following error:

```
Running Perf Analyzer : 'perf_analyzer -m my_ensemble_vlm --async \
    --stability-percentage 999 --warmup-request-count 32 --request-count 32 -i http -u \
    0.0.0.0:8000 --concurrency-range 16 --service-kind triton --endpoint v2/models/my_ensemble_vlm/generate \
    --max-threads 64 --input-data \
    artifacts/vlm-openai-vision-concurrency16/inputs.json \
    --profile-export-file \
    artifacts/vlm-openai-vision-concurrency16/profile_export.json'
Failed to retrieve results from inference request.
Thread [0] had error:
```

Can you please advise on the best way to profile a multimodal model that isn't strictly OpenAI API compatible and uses the trtllm-backend? Should I create a custom `input.json` file following the [examples here](https://github.com/triton-inference-server/perf_analyzer/blob/main/docs/input_data.md#real-input-data) and feed that directly to `perf_analyzer`, bypassing `genai-perf` for this specific use case? If so, what would a minimal working `input.json` look like for my my_ensemble_vlm model with text_input (string) and image_input (image data as base64)?

Thank you for your time and assistance.

Hi,
**An update:** I was able to profile my VLM using a custom `input.json` file, instead of the json file generated by `genai-perf`. Apparently the `input.json` genai-perf geenrates for `--endpoint-type vision` or `--endpoint-type multimodal` can only be used for OpenAI API compatible models. I was able to use perf_analyzer with my model by creating a custom `input.json` using the instructions [here](https://github.com/triton-inference-server/perf_analyzer/blob/main/docs/input_data.md#real-input-data). My input.json looks something like this:
```
data": [
    {
      "prompt": ["MY_PROMPT"],
      "image": {
        "b64": "MY_BASE64_IMG"
      },
      "max_tokens": {
        "content": [64]
      }
    },
]
```
