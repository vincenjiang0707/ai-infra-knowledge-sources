## 正文

# Description

Adds two custom mesh and rule sets for running DeepSeek-V3 671B at **`per_device_batch_size=0.5`** on **16k TPU v7x chips (32768 devices)**, with eval at **`eval_per_device_batch_size=1/64`**:

- **`fsdp-as-dp-for-attn-cp-as-ep-for-moe`** (train): `fsdp-as-dp-for-attn` plus a `context` axis that the MoE borrows, as in `cp-as-ep`.
- **`fsdp-as-dp-for-attn-cp-as-ep-for-moe-eval`** (eval, via `custom_mesh_and_rule_for_eval`): same mesh and weight rules; only moves `expert` from the batch to the sequence.

## Train rule

| | attention | MoE (between EP all2all) |
|---|---|---|
| `fsdp` / `fsdp_transpose` | DP (attention weights replicated) | FSDP (`embed_moe` / `mlp_moe`) |
| `expert` | DP for activations, FSDP for attention weights | EP |
| `context` | CP (sequence halves), FSDP for attention weights | EP |

- `context` is laid over the **two TensorCores of a chip**. Each chip holds one sequence split in half.
- `exp` → `['context', 'expert']`, so EP = context × expert. `RoutedMoE` now uses the `("context", "expert")` EP axes for this rule, as it already does for `cp-as-ep`. Without this the MoE would run EP over `expert` only while the weights are sharded on both axes.
- Attention weights (`q_lora`, `kv_lora`, `embed_attn`) → `['context', 'expert']`. The `context` half of their all-gather stays on-chip. Their gradient needs a reduction over `context` anyway, so sharding them there turns that all-reduce into a reduce-scatter and all-gather, and halves their HBM.
- **`context` is deliberately the last mesh axis.** jax's v7x mesh builder assigns logical axes last-first and offers the core axis first. With `expert` last, a 32-wide expert axis claims `(16, core)` on a 16x16x32 slice, and `context` can then no longer be placed.

## Eval rule

Only the logical rules are swapped at eval (the mesh is built once from the train rule), so `mesh_axes` is identical. Every weight rule is identical too, so the train state is consumed without re-layout. The only change:

- `activation_batch*` / `activation_kv_batch` / `activation_embed_and_logits_batch` drop `expert` → `['data', 'fsdp', 'fsdp_transpose']`
- `activation_length` / `activation_norm_length` / `activation_length_attn` / `activation_q_length` → `['context', 'expert']`

This enables `eval_per_device_batch_size = 1 / (context × expert)`. For 1/64 that means `ici_context_parallelism=2`, `ici_expert_parallelism=32`. The MoE is unchanged: tokens are still sharded over context × expert, which is the EP group.

## Usage (16k chips)

```
per_device_batch_size=0.5 eval_per_device_batch_size=0.015625
custom_mesh_and_rule=fsdp-as-dp-for-attn-cp-as-ep-for-moe
custom_mesh_and_rule_for_eval=fsdp-as-dp-for-attn-cp-as-ep-for-moe-eval
ici_context_parallelism=2 ici_expert_parallelism=32
context_parallel_load_balance=false
eval_sa_block_q=64
# 16 x 4x16x16 slices: ici_fsdp_parallelism=32  allow_split_physical_axes=true
#  2 x 16x16x32 slices: ici_fsdp_parallelism=256 allow_split_physical_axes=false
```

## Things to know

- **`eval_sa_block_q` must be ≤ 64** at 1/64 (4096 / 64 query tokens per device). With 256 the eval compile fails: `q_block_size=256 should divide q_seq_len_per_shard=64`.
- **`expert=32` on 1024-chip slices needs `allow_split_physical_axes=true`**, because 32 is not a product of {4, 16, 16}. `expert` then becomes a 2×16 sub-plane (half of x × y) instead of a single ring. On 16x16x32 slices it maps cleanly onto the 32-long ring.
- **EP=64 doubles ring-of-experts traffic.** With `use_ring_of_experts=true`, each device gathers 64 × 2048 tokens per MoE layer, about 2× the current EP=16 / pdb=1 recipe. All-to-all volume does not grow with EP, so `use_ring_of_experts=false` is worth profiling.
- **Keep `context_parallel_load_balance=false`.** The input pipeline reorders for the train CP size (2) only, while eval splits the sequence 64 ways. The cost is causal imbalance across the core pair during training: the second half does about 3/4 of the attention work.

# Tests

**AOT** of both the train step and the eval step (under `logical_axis_rules_for_eval`) on 32768 tpu7x devices. The config is the DeepSeek-V3 671B MLPerf fp8 recipe (qwix `fp8_full`, ring of experts, tokamax splash/GMM, MTP, custom remat with decoder-input offload) at `per_device_batch_size=0.5`, `eval_per_device_batch_size=1/64`.

| layout | mesh | physical placement | train | eval (1/64) |
|---|---|---|---|---|
| 2 × `tpu7x:16x16x32` | data 2, fsdp 256, expert 32, context 2 | expert = z ring of 32, fsdp = x×y, context = cores | 45.0 GB/device | 9.1 GB/device |
| 16 × `tpu7x:4x16x16` | data 16, fsdp 32, expert 32, context 2 | expert = half of x × y, fsdp = half of x × z, context = cores | 55.3 GB/device | 7.4 GB/device |

Global batch: 16384 (train), 512 (eval). Input sharding: `P(('data','fsdp','expert'), 'context')` (train), `P(('data','fsdp'), ('context','expert'))` (eval).

Mesh axes spanned by each collective in the optimized HLO (static op counts, same on both layouts unless noted; DCN collectives lower to megascale send/recv and are not listed):

| | train | eval |
|---|---|---|
| all-gather `context` | 29 (CP key/value gather) | — |
| all-gather `expert+context` | 145 (attention weights, ring-of-experts tokens) | 57 (CP over 64, attention weights, ring-of-experts) |
| all-gather `fsdp` | 109 (MoE / dense weights) | 28 |
| reduce-scatter `context` | 14 | — |
| reduce-scatter `expert+context` | 59 | 6 |
| reduce-scatter `fsdp` | 59 on 4x16x16; 22 on 16x16x32 (XLA all-reduces the rest over the 256-wide fsdp) | — |

No weight re-layout between train and eval, and no gather over `data`.

`train_compile.py` does not compile the eval step. I used a local driver that reuses `train_compile.get_shaped_inputs` / `jit_and_compile` and compiles `train.eval_step` with the eval data sharding under `axis_rules(config.logical_axis_rules_for_eval)`, the same way `train.py` warms up the eval executable. The driver builds the mesh from `get_topology_desc` so that 4x16x16 can be targeted, because `tpu7x-2048` maps to 8x8x16. The AOT used local libtpu 0.0.46, synthetic data and no checkpointing, and dropped `--xla_tpu_rerun_latency_hiding_scheduler_post_sc_assignment`, which crashes the local compiler.

**Sharding dump test**
- New `TEST_CASES` entry in `tests/utils/sharding_dump.py`: `deepseek2-16b`, `tpu7x-8`, 1 slice, fsdp=2 / context=2 / expert=2, ring of experts on. Its golden in `tests/utils/sharding_info/` was dumped by `tests.utils.sharding_dump`. The golden records:
  - attention weights (`query`, `wkv_a`, `wkv_b`, `out`) on `['context', 'expert']`;
  - routed-expert weights on `['context', 'expert']` (expert dim) × `fsdp` (embed);
  - dense, shared-expert and embedding weights on `fsdp`;
  - activations on `P(('fsdp', 'expert'), 'context', None)`.
- **The golden comparison in `tests/unit/sharding_compare_test.py` is restored, on the NNX state.** The NNX-only migration (71d5c4751) removed it along with the Linen driver, so nothing had been checking these goldens since.
  - The test uses the same arguments as `run_sharding_dump` and compares the physical, logical and input (activation) shardings. On mismatch it prints a per-key diff.
  - The other 11 goldens are Linen-era (`.params/['params']/...` keys). Regenerating the existing `cp-as-ep` one gives a ~1100-line diff. The test skips them with a pointer to `run_sharding_dump`, and they are compared again once regenerated. Regenerating them is out of scope here.
- `pytest tests/unit/sharding_compare_test.py` (CPU, TPU plugin): 1 passed, 11 skipped.
- Checked that it catches regressions: changing `kv_lora` to `['expert']` in the rule fails the test with `changed: ...wkv_b...: expected [['context', 'expert'], ...] actual ['expert', ...]`.

**Unit tests**
- New `test_fsdp_as_dp_for_attn_cp_as_ep_for_moe_rules` in `tests/unit/pyconfig_test.py`. It loads both rules through `pyconfig` and pins the invariants the design relies on. It also covers the eval rule, which the sharding dump does not see:
  - `context` is the last mesh axis and `context_sharding == "context"`.
  - EP axes are `("context", "expert")`.
  - The eval rule shards the sequence over `("context", "expert")` and drops `expert` from the batch.
  - Every weight rule is shared between train and eval.
- `pytest tests/unit/pyconfig_test.py` (CPU): 46 passed.
- `pre-commit run --files <changed>`: codespell, pylint, pyink, mdformat, yamllint pass.
