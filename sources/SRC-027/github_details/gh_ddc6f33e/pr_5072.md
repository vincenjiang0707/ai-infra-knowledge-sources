## 正文

Integrate Lineage DeepSeek-V3 model (dsv3.py) into MaxText.

Adds a `use_lineage` option that runs MaxText's DeepSeek-V3 decoder stack (dense layers followed by MoE layers) through Lineage's `dsv3.dsv3` entry point. All Lineage-specific logic lives in a new Google-internal `experimental/lineage/lineage_adapter.py`, which is excluded from the open-source export; changes to shared MaxText files are limited to wiring.

`experimental/lineage/lineage_adapter.py`:
* Weights: translates MaxText dense/MoE parameter trees into Lineage's `DSv3WeightsPytree` (moving `param_scan_axis` to 0, fusing `wi_0`/`wi_1`) and reshards them to Lineage's layout. Routed experts are sharded `P(None, "expert", "fsdp_moe", None)` / `P(None, "expert", None, "fsdp_moe")` to match MaxText's native `fsdp_moe` placement, removing four step-boundary all-to-all reshards (256 chips: 5,410.3 -> 5,150.0 ms/step synthetic, 7,944.9 -> 7,701.2 ms/step on C4 + `ckpt0424`).
* RoPE: converts the trailing `qk_rope_head_dim` channels of `wq_b` / `wkv_a` from MaxText's interleaved layout to Lineage's split-half layout (`Lineage_yarn(P x) == MaxText_yarn(x)`), closing 62% of the step-0 loss gap (6.585 -> 5.707 nats).
* Segment IDs: reshards `decoder_segment_ids` to match Splash Attention in explicit mode so packed documents stay isolated, closing the remaining loss gap (5.707 -> 5.165 nats).
* Mesh: `build_axis_mapping` derives Lineage's logical axes from `logical_axis_rules`; `create_device_mesh` maps the `['dcn', 'x', 'y', 'z', 'core']` mesh 1:1 onto the physical Ghostfish torus per slice (-2,320.5 ms / -22.6% step time at 256 chips, xid/290538307), falling back to `mesh_utils` otherwise.
* Rounds the capacity factor up to the Pallas GMM tile size and computes a Switch-style MoE load-balance loss from router outputs when `load_balance_loss_weight > 0`.

MaxText wiring:
* `nnx_decoders.py`: new `elif cfg.use_lineage` branch in the scanned DeepSeek path that calls `lineage_adapter.run_lineage_dsv3` and sows `moe_lb_loss`; `_build_linen_params` also returns the dense `mlp` subtree.
* `maxtext_utils.py`: uses `lineage_adapter.create_device_mesh` when `use_lineage=true`.
* `types.py` / `base.yml`: `use_lineage` flag and validation (requires scanned `deepseek` decoder, MLA, YaRN and `capacity_factor > 0`); per-axis parallelism lists are kept as configured for custom physical mesh axes.
* `train.py`: skips the aux-loss-free bias update when no `moe_bias_updates` were produced (the Lineage path does not emit them).
* `deepseek3-671b-lineage.yml`: DeepSeek-V3 671B config on the physical `['dcn', 'x', 'y', 'z', 'core']` mesh.
* `copy.bara.sky`: excludes the adapter, its tests and the lineage config from export.
* `mllog_utils.py`: tolerates `mlperf_logging` versions that lack `DEEPSEEKV3_671B`.

Lineage:
* `learning/performance/lineage/BUILD`: grants `:dsv3`, `:dsv3_mla`, `:dsv3_types` and `:ops` visibility to the adapter package and MaxText tests.
* `learning/performance/lineage/dsv3_router.py`: wraps the SparseCore-pinned coefficient gather in a `@jax.custom_vjp` (forward `_sc_gather` in logits dtype, backward `_sc_scatter_add_f32` in f32) so XLA's `OffloadGatherToSparseCore` does not fuse an implicit `convert` into `gather_custom_fusion`.
* `scripts/launch_dsv3_batchsplit_maxtext.sh`, `scripts/launch_dsv3_perf_test.sh`: XManager launchers for MaxText + Lineage DSv3 runs.

Tests: `lineage_adapter_test` (CPU) and `lineage_adapter_tpu_test` (Ghostfish forward/backward).

Tested:
Unit tests above; 256-chip Ghostfish runs (xid/290319547, xid/290538307, xid/292152200 synthetic, xid/292153498 C4 + `ckpt0424`); 512- and 1,024-chip multi-slice runs (`dan-syn512-0006` 9.64 s/step, `dan-mlpev-1520` reached eval_loss 3.595 <= 3.60 at step 52, `dan-syn1k-1550` 11.38 s/step); 64-chip parity runs (xid/291362265: 363.5 ms vs 371.5 ms pure Lineage; xid/292193282).
