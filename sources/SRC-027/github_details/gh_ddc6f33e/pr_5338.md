# Description

Follow-up to the discussion on the last round of test fixes: turn `cpu-unit` into the job that catches multi-device sharding bugs, instead of letting them reach accelerator runners.

- `tests/conftest.py` auto-marks any test without an explicit hardware marker as `cpu_only`, and the accelerator jobs deselect `cpu_only` -- so **`cpu-unit` is the only job that runs that bulk**.
- It runs on a single device, where two whole classes of bug pass for the wrong reason:
  - a test whose batch is smaller than its mesh (1 row "divides" 1 device), and
  - a test that relies on ambient flax `axis_rules` it never entered (everything resolves to unsharded, so context-parallel code paths are silently skipped).
- Both only fail once 2+ devices are visible. Four rounds have now reached `main` this way: #5133, #5134, #5286, #5287 -- all authored after the failures were found on a 4-device runner rather than in the PR that introduced them.
- This sets `XLA_FLAGS=--xla_force_host_platform_device_count=4` for the `cpu-unit` flavor only. No new job, no new runner, no accelerators: the CPU backend simply exposes 4 virtual devices in one process.

# Tests

Tested on recent main branch, running the exact `cpu-unit` selection (`-m "cpu_only and not post_training and not integration_test" --ignore=tests/post_training`):

| | failed | passed | skipped | time |
| --- | --- | --- | --- | --- |
| 4 devices | 25 | 2003 | 1393 | 15m08s |
| 1 device (today) | 25 | 1965 | 1431 | 13m14s |

- **The two failure sets are identical** - nothing fails at 4 devices that does not already fail at 1.
- **38 tests that currently skip themselves now execute** - the ones guarded by `if len(devices) < 2: self.skipTest(...)`. That is the point of the change, and worth knowing: a few of those have never run anywhere.
- Cost is ~2 minutes of wall time. `linux-x86-n2-32` (32 vCPU / 128 GB) has plenty of headroom; the 4 devices share host RAM.

Reproduce either column locally with:

    JAX_PLATFORMS=cpu XLA_FLAGS=--xla_force_host_platform_device_count=4 python -m pytest \
      -m "cpu_only and not post_training and not integration_test" --ignore=tests/post_training tests/

If you would rather keep a single-device signal as well, I am happy to respin this as a separate `cpu-unit-multidevice` flavor instead of changing `cpu-unit` in place - that needs entries in the coordinator's per-flavor maps plus a job in `ci_pipeline.yml`, so I went with the smaller change first.
