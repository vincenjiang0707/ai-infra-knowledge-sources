## 正文

## Problem

Under vLLM's mamba prefix caching (`mamba_cache_mode="align"`), a Qwen3.5 rollout on the MaxText-native path dies on the first decode step:

```
File "maxtext/models/qwen3.py", line 913, in __call__
  recurrent_state, conv_state = active_cache.get_gdn_states()
AttributeError: 'tuple' object has no attribute 'get_gdn_states'
```

`Qwen3NextGatedDeltaNet` decides whether vLLM is driving paged state by sniffing for one field:

```python
use_paged_state = (
    ... and getattr(attention_metadata, "mamba_state_indices", None) is not None and ...
)
```

But align mode is precisely the mode where tpu-inference stops populating it (`tpu_inference/runner/tpu_runner.py:3220-3246`):

```python
# In align mode (prefix caching), mamba state indices are derived on-device
# from the block tables, so mamba_state_indices is None.
if (self.kv_cache_config.has_mamba_layers and getattr(
        self.cache_config, "mamba_cache_mode", "none") != "align"):
    ...  # build mamba_state_indices
else:
    mamba_state_indices = None
```

So `use_paged_state` goes False and the layer falls through to the MaxEngine branch, calling `get_gdn_states()` on the 2-tuple of paged state arrays vLLM handed it.

## Change

Resolve the slots from the mamba block table when `mamba_state_indices` is absent.

Align mode needs the read and write slots to **differ**: a request resumes from the block covering its last already-computed token and writes to the block covering its last token, so a later request hitting that cached prefix can pick up the checkpoint. `run_jax_gdn_attention` already takes `read_state_indices` for exactly this (`tpu_inference/layers/common/gdn_attention.py:50`) — the vLLM path passes it, MaxText did not, so read == write. New `_mamba_block_table_slots` computes both and the call now forwards `read_state_indices=`.

`mamba_block_size` lives on vLLM's `cache_config`, which the layer has no handle on, so the adapter passes it down as a new `gdn_mamba_block_size` config key (0 when not in align mode). `generate_maxtext_config` already does this kind of vLLM→MaxText translation for sharding and MoE padding.

Non-align behaviour is unchanged: the `mamba_state_indices` branch is the same code as before, and `gdn_mamba_block_size` defaults to 0.

## Testing

`tests/unit/qwen3_gdn_mamba_slots_test.py`, 3 passed (CPU backend). Covers the read/write split across a block boundary, clamping into the rank-local range, and per-DP-rank slicing of the block table. The first case is inherently a regression test for the old behaviour — it expects read block 11 and write block 12 for the same request.
