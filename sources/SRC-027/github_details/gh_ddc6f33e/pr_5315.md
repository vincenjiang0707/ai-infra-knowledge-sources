# Description

`train_loop()`'s initialization retry can use the results of a setup attempt it has already abandoned, leaving the run with a mesh from one topology and batch sizes from another. `pw-snp-4x1k-0827-3` hit this and died before its first step with

```
IndivisibleError: ... Mesh('data': 3, 'fsdp': 2048, ...), spec=P(('data', 'fsdp'), None) ...
array axis 0 is partitioned 6144 times, but the dimension size is 8192
```

It started on 3 slices, the fourth returned mid-setup, and the retry re-sized the config to 4 slices (batch 8192) while the first attempt kept running. That attempt finished first, and because `run_setup` was defined inside the loop and captured `setup_results`, `init_complete_event` and `devices` — all rebound on each retry — its late result landed in the new attempt's dict and set the new attempt's event. The main thread compiled the 3-slice mesh against the 4-slice batch.

- **Each attempt gets its own state.** `run_setup` is defined once and takes its results dict, events and devices as thread arguments, so a late result lands in a dict nobody reads.
- **The abandoned attempt is cancelled.** The retry sets its `cancel_event`; `setup_train_loop()` checks it before creating the data iterator and before restoring state. An attempt already inside the restore still finishes it — an in-flight Orbax restore cannot be stopped from here.
- **The mesh must match the config.** After setup, `train_loop()` retries if the mesh does not have `config.num_target_devices` devices.

## Code Review

This pull request introduces a cancellation mechanism for setup attempts in the training loop to prevent abandoned attempts from leaking into newer ones. It defines a `SetupCancelledError` and checks a `cancel_event` at stage boundaries within `setup_train_loop` to abort early. Additionally, it adds a check to retry setup if the mesh size does not match the expected target devices, and includes unit tests to verify these behaviors. A review comment suggests refreshing the active slice indices of the `elastic_manager` before retrying on a topology mismatch to prevent an infinite retry loop.
