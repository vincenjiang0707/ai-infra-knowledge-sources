# [PR #5363] guard GDN backward norm on zero tokens and duplicate MoE replay slots

### Summary
Two small numerical stability guards for Qwen3.5-35B / 397B RL training:

1. **Zero-norm backward gradient guard in Gated DeltaNet (`pallas_mosaic_tpu_bwd.py`)**:
   - In `_bwd_gdn_pipeline_body`, `inv_r_q = rsqrt(||q||^2 + 1e-6)` evaluates to `1 / sqrt(1e-6) = 1000.0` on zero/padded tokens (`q_orig == 0`). Because GDN is stateful (`d_q_g = do_h @ state_prev^T` is non-zero from prior active tokens), multiplying by `inv_r_q = 1000.0` at line 331 (`d_q = (d_q_scaled - ...) * inv_r_q`) amplifies gradients on zero tokens by `1000x` per layer.
   - Using the double-`jnp.where` check (`q_is_zero = q_norm_sq == 0.0`) sets `inv_r_q = 0.0` (and `inv_r_k = 0.0`) on zero-norm tokens, cleanly zeroing `d_q` and `d_k`.

2. **Duplicate expert ID guard in MoE Router Replay (`moe.py`)**:
   - `slot_valid` checks `0 <= expert_id < num_experts`, which treats a zero-initialized buffer (`[0, 0, 0, 0, 0, 0, 0, 0]`) as valid and routes all 8 top-k slots of the token into Expert 0.
   - Since genuine top-k routing (`k=8`) always selects distinct experts, checking `has_duplicate` after sorting along `axis=-1` falls back to `auto_indices` whenever duplicate slots are present.
