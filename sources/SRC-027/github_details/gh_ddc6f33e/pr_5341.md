# Description

Adds `m3/core/sharding.py`: logical-axis to `PartitionSpec` translation, plus
mesh creation over ICI and DCN.

Models never name a physical mesh axis. They name logical ones — `"embed"`,
`"heads"`, `"mlp"` — and a `Sharding` instance supplied at construction
translates them, so changing parallelism strategy means changing one class
rather than every model. Legacy instead carries 12 mesh axes and a ~105-entry
`logical_axis_rules` table; m3 starts with `dp`/`fsdp`/`tp`/`ep` and adds axes
as models need them.

Notes:

- `create_mesh(ici=..., dcn=...)` takes mappings rather than one keyword per
  axis, since the axis list is expected to grow. Unnamed axes are 1. Each
  mapping may carry one `-1`, because they resolve against different totals —
  devices-per-slice and slices.
- The single-slice path deliberately avoids `create_hybrid_device_mesh` with an
  all-ones DCN shape: that function requires every device to expose
  `slice_index`, which single-slice TPU and CPU devices lack, so it raises
  rather than degrading. A test pins the branch.
- `Sharding.__call__` rejects two dimensions of one tensor claiming the same
  mesh axis. Legacy tolerates this via Flax fallback rules (hence the duplicate
  keys in `logical_axis_rules`); m3 has no fallback, so it reports the conflict
  instead of emitting an invalid spec.
- `constrain` is activations-only — re-constraining a parameter after init
  collides with the training engine's deferred all-reduce and Zero-1 resharding.

Shortcomings:

- Sizes are passed directly; m3 config comes later.
- "Raise on an unknown logical axis" is a convention on the ABC, not enforced.
- Multi-slice tests stub the slice count and jax's placement function, as no
  testbed here spans slices. The arithmetic underneath is tested unmocked.
- `sharding.py` omits `__all__` (there are no star-imports in the repo);
  `rope.py` still has one, removed in a follow-up.

# Tests

`tests/unit/m3/sharding_test.py`, 54 tests. Multi-device cases are marked
`tpu_only` — without that marker the repo conftest treats them as `cpu_only`
and skips them on accelerator testbeds.

```
# CPU: 77 passed, 8 skipped
JAX_PLATFORMS=cpu python3 -m pytest tests/unit/m3/ -q

# TPU v6e-8: 8 passed
python3 -m pytest tests/unit/m3/sharding_test.py -q -m tpu_only
```
