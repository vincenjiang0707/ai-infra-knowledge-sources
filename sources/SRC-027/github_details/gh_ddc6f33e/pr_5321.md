# Description

Enabling `retry_when_tokens_dropped` currently costs **+2.669 GiB/device of peak HBM (+4.9%)** and **+59 full-mesh all-reduces per step**, measured by AOT `train_compile` A/B on DeepSeek-v3-671B at `tpu7x-1024` (MLPerf flag set, only this flag differing). Neither cost is inherent to the feature. This PR removes both, bringing the flag's overhead down to **+10.6 MiB (+0.019%)** and **one** all-reduce.

| per-device | baseline | `retry_when_tokens_dropped=true` | delta |
|---|---|---|---|
| generated_code | 0.4262 G | 0.4296 G | +3.5 MiB |
| argument | 7.3327 G | 7.3327 G | 0 |
| output | 7.3326 G | 7.3326 G | 0 |
| alias | 7.3326 G | 7.3326 G | **0** |
| temp | 46.8720 G | 46.8790 G | +7.1 MiB |
| **peak HBM** | **54.6309 G** | **54.6412 G** | **+10.6 MiB (+0.019%)** |

`may-alias` entries: 182 in both. Collectives: all-reduce 44 → 45, all-gather 141 → 141, reduce-scatter 24 → 24. The 58-trip MoE forward scan gains 18 instructions and **zero** collectives.

## 1. Keep the state donated by rolling the step back in-graph

The replay needs the pre-step state to still be live, which `get_functional_train_with_signature` arranged by setting `donate_argnums=()` whenever the flag was on. That dropped all 182 `input_output_alias` entries and paid for an un-aliased copy of the whole train state on *every* step to cover a rare event — the entire 2.669 GiB.

Instead the step always runs and discards its own update when an overflow is detected (`_rollback_on_overflow`): an elementwise `jnp.where(has_moe_overflow, old, new)` over the state leaves, which XLA folds into the existing optimizer-update fusions (+154 selects, no new buffers). The donated buffers are still written in place, and the returned state is bit-identical to the input whenever an overflow occurred, so `training_loop_iteration` replays straight from it — no second copy of the state is ever live, and the explicit `x.delete()` / `gc.collect()` dance it used to need is gone.

Two details:
- The dropless replay model sows a compile-time-constant `False`, so the select folds away entirely in the replay executable — that path pays nothing.
- Typed PRNG keys are skipped by the select (`jax.dtypes.extended` values aren't selectable). Leaving them advanced is harmless: the replay needs *a* valid key, not the original one.

## 2. Reduce the overflow flag once per model, not once per layer

`permute()` did `jax.lax.psum(local_overflow, tuple(mesh.axis_names))` — one `replica_groups=(1,1024)` all-reduce inside the 58-trip forward MoE scan, plus one for MTP, for a flag nothing in the layer consumes. It is only sown for the host-side retry decision. XLA cannot combine these with the pre-existing in-loop psum, which is only over `fsdp`.

`permute()` now returns the unreduced per-device flag, `sparse_matmul`'s `shard_map` emits it with `out_specs=P(tuple(mesh.axis_names))` (one element per device), and `loss_fn` does a single `jnp.any` for the whole model. `collect_intermediates_by_suffix` grows a `ravel` argument because flattening the mesh-sharded flag array would otherwise force a reshard.

The one new all-reduce is a `u32[] reduce_or` in `main._spmd`, outside every scan.

## 3. Reject `retry_when_tokens_dropped` with `enable_diloco`

The dropless replay executable is only built off the plain NNX train state. Under DiLoCo there is nothing to replay with, so with the in-graph rollback the step would discard its update on every overflow and silently make no progress. Now a config error.

# Tests

- **AOT A/B** (the numbers above): `train_compile` on `deepseek3-671b`, `compile_topology=tpu7x-1024`, MLPerf flag set, with and without `retry_when_tokens_dropped=true`. Peak HBM = `generated_code + argument + output - alias + temp` from `CompiledMemoryStats`; collective and `may-alias` counts from the optimized HLO.
- **New unit tests** in `tests/unit/train_nnx_test.py`: `test_state_is_rolled_back_on_overflow` asserts every returned state leaf is bit-identical to the input when the flag is set, and `test_state_advances_without_overflow` guards it from passing vacuously.
- `tests/unit/maxtext_utils_test.py::TestGetFunctionalTrainWithSignature` updated — donation now stays on with the flag.
- `pytest tests/unit/train_nnx_test.py tests/unit/maxtext_utils_test.py` (CPU): 136 passed, 9 skipped.
- `pytest tests/unit/moe_test.py -k "retry or force_dropless or overflow_detection"` (TPU v5, 4 chips): 4 passed.
- Full `pytest tests/unit/moe_test.py` (TPU v5): 6 failed, 34 passed, 53 skipped. All 6 failures are pre-existing — verified by re-running those node ids at `c8f300c7e` with this diff stashed, identical result. They all raise `AssertionError: lhs_scale requires lhs quantization to engage ... hardware supports fp8/int8 matmul`, i.e. the fp8/tokamax tests can't run on this TPU generation.
- `pre-commit run --files <changed>`: codespell, pylint, pyink, mdformat all pass.

**Not run:** an end-to-end training workload. The claim here is about compiled memory and collective counts, which the AOT A/B measures directly; a convergence/throughput run on the 671B config would be worth doing before this goes out for review.

## Code Review

This pull request optimizes the retry_when_tokens_dropped mechanism by keeping MoE overflow flags unreduced per device to avoid per-layer all-reduces, and rolling back step updates in-graph on overflow to allow state donation to remain enabled, saving significant memory. The reviewer feedback suggests further optimizing the overflow reduction by locally reducing non-device dimensions first, and refactoring the rollback mechanism to use jax.tree_util.tree_map on the full PyTree state instead of manually flattening and zipping leaves for a safer, structure-preserving implementation.
