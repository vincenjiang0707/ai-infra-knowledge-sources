# [PR #5362] Fix dropless-replay remat override: match the NNX decoder

source: https://github.com/AI-Hypercomputer/maxtext/pull/5362
state: closed | updated: 2026-09-25T02:23:47Z
labels: pull ready

## 正文

The dropless replay program (retry_when_tokens_dropped) is built by reconstructing the model with force_dropless on the MoE modules and remat_policy_override="full" on the decoder, so the worst-case replay recomputes instead of saving activations. The override was applied to modules whose class name is "Decoder", but the decoder class is NNXDecoder, so it never matched and the replay kept the run's remat policy.

With remat_policy=custom and large device-saved tensors this makes the replay program much larger than the training step: on DeepSeek-V3 671B at 1024 chips (EP16 x FSDP128, moe_x_sorted=device) the replay compile needed 253.9 GiB of HLO temporaries (the routed expert input saved at dropless capacity for all 58 layers) and failed, while the training step itself compiles at 42.6 GiB. Matching the decoder by its get_remat_policy attribute lets the override apply; the same replay then compiles at 62.1 GiB, identical to a full-remat replay. The training step is unchanged.

Related: #5348 (moe_x_sorted remat location), which is where this surfaced.
Receipts: AOT compiles on a virtual tpu7x-2048 topology with the team's recipe: replay before 253.89 GiB (RESOURCE_EXHAUSTED), after 62,125,417,504 B; training step 42,556,076,960 B in both.
