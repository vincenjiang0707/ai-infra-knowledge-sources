# Description

Expose the `enable_continuous_profiling` CLI configuration flag in MaxText to support saving trace profiles larger than 2GB as `.xplane.riegeli`.

### Context & Solution:
When profiling large model workloads or multi-step training runs, monolithic `.xplane.pb` trace files can exceed Protocol Buffer's 2GB wire format limit, leading to serialization and file upload failures.

Setting `enable_continuous_profiling=True` configures the profiler to stream smaller trace chunks into compressed Riegeli record containers (`.xplane.riegeli`), bypassing the 2GB single-protobuf size limitation. Because Riegeli applies high-ratio block compression, an uncompressed trace that exceeds 2GB typically compresses down to a `.xplane.riegeli` file of only a few hundred MBs on disk/GCS.

### Specific Changes:
- Added `enable_continuous_profiling` (boolean, default `False`) to `src/maxtext/configs/base.yml` and `src/maxtext/configs/types.py`.
- Updated `src/maxtext/common/profiler.py` to populate `advanced_config["enable_continuous_profiling"] = True` in `jax.profiler.ProfileOptions().advanced_configuration` when `profiler="xplane"` and `enable_continuous_profiling=True`.
- Updated post-training trainers (`src/maxtext/trainers/post_train/rl/train_rl.py`, `src/maxtext/trainers/post_train/sft/train_sft.py`, `src/maxtext/trainers/post_train/dpo/train_dpo.py`, and `src/maxtext/trainers/post_train/distillation/train_distill.py`) to forward `enable_continuous_profiling` to Tunix's `profiler.ProfilerOptions`. Related Tunix PR: https://github.com/google/tunix/pull/2036
- Added documentation notes in `base.yml` clarifying that continuous profiling requires JAX >= 0.11.2.

# Tests
