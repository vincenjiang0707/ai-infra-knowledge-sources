```python
AttributeError: 'CheckpointManager' object has no attribute 'latest_step'
# Occurs when training engine's CheckpointManager is passed to:
# maxtext.common.checkpointing.latest_step(checkpoint_manager)
#   -> return checkpoint_manager.latest_step()
```

#### 💡 Root Cause Analysis & Context
**Confidence:** high (confirmed cause)

The failure is a **codebase regression** introduced in commit `e50e394` ("Use helper functions for CheckpointManager operations."). 

This commit refactored MaxText's checkpointing logic to interact with the checkpoint manager through dedicated helper functions (`latest_step`, `wait_until_finished`, `reached_preemption` in `src/maxtext/common/checkpointing.py`) instead of direct method calls. This was designed to isolate the core logic from specific Orbax CheckpointManager version (v1 vs v0) semantics.

However, the training engine's `CheckpointManager` wrapper class (defined in `src/maxtext/training_engine/checkpointing.py`) was not updated to support these methods (it only defined `get_latest_step()`). Consequently, passing the training engine's wrapper manager into any of these common checkpoint helper functions results in an `AttributeError` or missing method failure.

#### 🛠️ Recommended Fix
We have resolved this issue by implementing the standard `latest_step`, `wait_until_finished`, and `reached_preemption` compatibility methods directly on the training engine's `CheckpointManager` wrapper class in `src/maxtext/training_engine/checkpointing.py`, forwarding the operations to the underlying Orbax `CheckpointManager` instance:

```python
  def latest_step(self) -> int | None:
    """Returns the latest checkpoint step."""
    return self.get_latest_step()

  def wait_until_finished(self) -> None:
    """Blocks until pending saves finish."""
    if self._checkpoint_manager:
      self._checkpoint_manager.wait_until_finished()

  def reached_preemption(self, step: int) -> bool:
    """Returns whether preemption has been reached."""
    if self._checkpoint_manager:
      return self._checkpoint_manager.reached_preemption(step)
    return False
```

Additionally, comprehensive unit tests have been added to `src/maxtext/training_engine/maxtext_engine_test.py` to assert the correct behavior of these wrapper methods.
