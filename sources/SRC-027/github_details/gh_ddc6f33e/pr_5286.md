# Description

- `per_device_batch_size` is **per device**: the real batch is that number times the device count, and the mesh shards the batch axis across every device.
- These tests use it as if it were the whole batch, building 1 or 2 rows. On a 4-device host the fsdp axis then tries to split 1 row four ways and the test dies with `IndivisibleError: array axis 0 is partitioned 4 times, but the dimension size is 1`.
- Batch size is incidental to what they assert (which experts the router replays), so the batch just needs to fit the mesh.
- CI has never caught this: these tests are auto-marked `cpu_only`, so only the single-device `cpu-unit` job runs them, where 1 row divides by 1 device fine.
- Fix: derive the row count from the config (`per_device_batch_size * jax.device_count()`) instead of reusing the per-device number, in the two batch-building helpers and the tests that build `forced_routed_experts`. Single-device behaviour is unchanged.

The seven tests affected are `test_loss_fn_with_forced_routed_experts`, ..._gemma4`, `..._scanned_qwen3_5`, `..._scanned_mixtral`, `test_different_replays_give_different_losses_unscanned`, and `test_per_layer_routing_is_not_broadcast_{scanned,unscanned}`.

# Tests

Reproduce the failure on `main` and the fix on this branch with:

    XLA_FLAGS=--xla_force_host_platform_device_count=4 python -m pytest tests/unit/router_replay_test.py

Verified on 4x AMD Instinct MI355X (ROCm 10, jax 0.11.1): the seven tests fail on `main` with the `IndivisibleError` above and pass on this branch. Full file passes in both environments that matter -- 4 devices (35 passed, 1 skipped) and a single CPU device (35 passed, 1 skipped), the latter being what `cpu-unit` runs today.
