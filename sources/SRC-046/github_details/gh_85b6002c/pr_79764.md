### Description

#### 问题背景

修复 `RestrictedUnpickler` 中由 NumPy wildcard 白名单和 pickle dotted name 属性遍历共同导致的白名单绕过问题。

此前以下模块使用了 wildcard 白名单：

* `numpy.core.numeric`
* `numpy._core.numeric`

对于 protocol 4/5 的 `STACK_GLOBAL`，pickle 的 `name` 可以包含 `.`。原实现只校验 `module` 是否位于白名单中，并在 wildcard 命中后直接调用：

```python
super().find_class(module, name)
```

当 `name` 为 dotted name 时，Python 可能继续按照属性链进行解析，从受信任的 NumPy 模块访问白名单之外的对象，从而绕过 `RestrictedUnpickler` 的白名单限制。

#### 修复内容

* 将 `numpy.core.numeric` 的 wildcard 白名单由 `'*'` 收紧为仅允许 `_frombuffer`
* 将 `numpy._core.numeric` 的 wildcard 白名单由 `'*'` 收紧为仅允许 `_frombuffer`
* 对命中 `_ALLOWED_CLASSES` 的模块，拒绝包含 `.` 的 dotted name，避免通过 `super().find_class()` 继续进行属性链遍历
* 未全局禁止 dotted name，保留安全用户自定义类 fallback 对嵌套 qualified name 的兼容性
* 审查 `_ALLOWED_CLASSES`，确认当前已不存在其他 `'*'` wildcard

#### 测试覆盖

新增并完善 RestrictedUnpickler 相关测试，覆盖以下场景：

* protocol 5 NumPy ndarray 可通过 `safe_loads_pickle()` 正常反序列化
* `numpy.core.numeric._frombuffer` 仍可正常解析
* `numpy._core.numeric._frombuffer` 仍可正常解析
* `numpy.core.numeric.builtins.eval` 被正确拒绝
* `numpy._core.numeric.builtins.eval` 被正确拒绝
* 其他 dotted name，例如 `foo.bar`，被正确拒绝
* 普通 NumPy ndarray、dtype、multiarray reconstruction、字典及文件加载路径保持正常
* 安全用户自定义嵌套类的 dotted qualified name 仍可通过 fallback 正常加载

#### 验证结果

* RestrictedUnpickler 完整测试：`48 passed, 1 skipped`
* 跳过项原因：当前测试环境的 NumPy 不提供 `numpy._core.numeric`
* `py_compile` 检查通过
* 相关 pre-commit 检查全部通过
* `git diff --check` 通过

#### 影响范围

本次修改仅涉及：

* `python/paddle/framework/restricted_unpickler.py`
* `test/legacy_test/test_restricted_unpickler.py`

未修改 CIFAR、Flowers、下载或 tar 解压相关代码。
