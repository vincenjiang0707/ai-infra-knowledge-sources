# [PR #79745] Harden Fleet CI yq download path in H-Coverage workflow

state: closed | updated: 2026-09-17T16:34:34Z

## 正文

`Fleet Unit test (single card)` was failing before tests ran because `yq` download intermittently failed with proxy tunneling errors in the `Install PaddleFleet` step. This change makes that external fetch resilient without altering test logic or package selection.

- **Root-cause path addressed**
  - `H-Coverage.yml` failed on a single-shot `wget` to GitHub release assets (`yq_linux_amd64`), causing job exit on transient proxy/network failure.

- **Workflow hardening (minimal scope)**
  - Updated `Install PaddleFleet` in both Fleet jobs:
    - `Fleet Unit test (single card)`
    - `Fleet Unit test (multi-card)`
  - Replaced one-shot download with retry/timeout flags and a `--no-proxy` fallback attempt.

- **Representative change**
  ```bash
  wget --tries=5 --retry-connrefused --waitretry=2 --timeout=30 --read-timeout=30 \
    https://github.com/mikefarah/yq/releases/latest/download/yq_linux_amd64 \
    -O /usr/local/bin/yq || \
  wget --no-proxy --tries=5 --retry-connrefused --waitretry=2 --timeout=30 --read-timeout=30 \
    https://github.com/mikefarah/yq/releases/latest/download/yq_linux_amd64 \
    -O /usr/local/bin/yq
  chmod +x /usr/local/bin/yq
  ```
