### Description
<!-- Describe what you’ve done -->
新增`Conv2dEpilogueFusion`，初步支持 conv2d + trivial_fusion 的子图匹配，打通子图匹配和`ap_variadic` 算子替换流程。
本 PR 提交的单测主要测试 pattern 能否成功匹配和替换成 ap_variadic 算子，后端计算直接调用 cutlass 的 conv2d+relu 接口，自动生成 varidic epilogue 由后续 PR 支持。

当前生成的代码如下：
```cpp

// auto generated codes
#include "kernels.h"
#include <vector>

namespace ap {

template <typename T>
struct VariadicEpilogueFunctor {
  struct Arguments {
    // Extents of the output spatial dimensions. The epilogue of an implicit
    // GEMM only knows the GEMM_M index `coord.row`, these are what let the
    // generated statements decompose it back into (n, p, q).
    int P;
    int Q;
    int64_t input0_dim1;
    int64_t input0_dim3;
    const half* in_ptr_0;
  };

  // Note: need to support vectorized operation
  __forceinline__ __host__ __device__
  T operator()(T x, const Arguments& args, const MatrixCoord& coord) const {
    T out;
    float op2_out0 = static_cast<float>(args.in_ptr_0[((coord.row / (args.P * args.Q)) * args.input0_dim1 * args.input0_dim1 * args.input0_dim3 + ((coord.row / args.Q) % args.P) * args.input0_dim1 * args.input0_dim3 + (coord.row % args.Q) * args.input0_dim3 + coord.column)]);
    float op3_out0 = static_cast<float>(x + op2_out0);
    float op4_out0 = static_cast<float>((op3_out0 > 0 ? op3_out0 : 0) );
    out = op4_out0;
    return out;
  }
};

template <int TuningConfigId>
static void RunConv2dWithVariadicKernel(const Conv2dEpilogueParams &params, const half* input0, const half* input1, half* output, int64_t input0_dim0, int64_t input0_dim1, int64_t input0_dim3, int64_t input1_dim1, const half* in_ptr_0) {
  using ElementT = half;
  using ElementComputeT = float;

  typename VariadicEpilogueFunctor<ElementComputeT>::Arguments epilogue_args;
  epilogue_args.P = params.P;
  epilogue_args.Q = params.Q;

  epilogue_args.input0_dim1 = input0_dim1;
  epilogue_args.input0_dim3 = input0_dim3;
  epilogue_args.in_ptr_0 = in_ptr_0;

  // The activation and the filter are both indexed along the channel dimension,
  // while the output is indexed along the output channel dimension.
  constexpr int AlignA = Alignment<ElementT, 16>::kValue;
  constexpr int AlignB = AlignA;
  constexpr int AlignC = Alignment<ElementT, 16>::kValue;

  Conv2dVariadicFusion<ElementT, ElementComputeT, VariadicEpilogueFunctor,
                       AlignA, AlignB, AlignC, TuningConfigId>(params,
                                                              epilogue_args);
}

} // namespace ap

extern "C" {

void Conv2dVariadicKernel(void* stream_ptr, const half* input0, const half* input1, half* output, int64_t input0_dim0, int64_t input0_dim1, int64_t input0_dim3, int64_t input1_dim1, const half* in_ptr_0) {
  // The activation is NHWC (data_format) and the filter is KRSC.
  std::vector<int64_t> input0_shape;
  input0_shape.resize(4);
  input0_shape[0] = input0_dim0;
  input0_shape[1] = input0_dim1;
  input0_shape[2] = input0_dim1;
  input0_shape[3] = input0_dim3;

  std::vector<int64_t> input1_shape;
  input1_shape.resize(4);
  input1_shape[0] = input0_dim3;
  input1_shape[1] = input1_dim1;
  input1_shape[2] = input1_dim1;
  input1_shape[3] = input0_dim3;

  ap::Conv2dEpilogueParams params(stream_ptr,
                                  input0,
                                  input1,
                                  /*bias=*/nullptr,
                                  output,
                                  input0_shape,
                                  input1_shape,
                                  std::vector<int64_t>{},
                                  std::vector<int>{1, 1},
                                  std::vector<int>{1, 1},
                                  std::vector<int>{1, 1},
                                  1);

  ap::RunConv2dWithVariadicKernel<ap::DefaultConfig::kConfigId>(params, input0, input1, output, input0_dim0, input0_dim1, input0_dim3, input1_dim1, in_ptr_0);
}
}

```

#### 支持范围
| 维度 | 首版支持 | 拦截位置 |
|---|---|---|
| 算子 | pd_op.conv2d fprop | source_pattern |
| 设备 | CUDA（`-arch=sm_80`）；DCU/HIP 不支持 | `constraint()` → `compile_command_util.supports("conv2d")` |
| dtype | fp16（已验证）；bf16 代码路径存在但未验证 | 无检查 |
| activation 布局 | `data_format == "NHWC"` | `constraint()` |
| filter 布局 | `KRSC`，依赖 `FLAGS_manually_trans_conv_filter=1` | 运行期 `Conv2dEpilogueParams` 断言（见已知限制）|
| groups | `== 1` | `constraint()` |
| padding | `padding_algorithm == "EXPLICIT"` 且上下/左右对称 | `constraint()` |
| kernel / stride / dilation | 任意（走 `IteratorAlgorithm::kOptimized` + `StrideSupport::kStrided`，`R/S ≤ 32` 时最优） | — |                                            
| epilogue | `ap_trivial_fusion_op`，输入 2 ~ 11、输出；1 ~ 10（`register_conv2d_epilogue_class` 注册），可融性由 `constraint()` 的访存拓扑化简判定 | `constraint()` |

实现上固定的选择：`split_k_slices = 1`；tile 固定 `DefaultConfig::kConfigId`，autotune 未开启；epilogue functor为标量版本，未向量化；AlignA/AlignB 按输入通道 C 取、AlignC 按输出通道 K 取。

#### 验证环境
- GPU / 工具链：A100（sm_80）、CUDA 12.8 + nvcc、gcc 12.3.0、Python 3.10；构建需开启 CINN。
- 端到端单测：`test/ap/test_conv2d_epilogue.py`，NHWC fp16、3×3、padding=1、groups=1，子图为 `conv2d + add + relu`。断言融合发生（PIR 中出现`pd_op.ap_variadic`）并与 Eager 对数值（atol=1e-1）。已覆盖 add 的两种索引形态：per-channel bias（沿 N/P/Q 广播，索引化简为coord.column）和与输出同形的逐元素加（coord.row 反解为 (n,p,q) 后线性化）。
- 运行前置：`FLAGS_manually_trans_conv_filter=True`（filter 走 KRSC）、`FLAGS_deny_cinn_ops="transpose"`（transpose 留在 phi kernel）。

未验证 / 不在本 PR 声明范围：
- DCU/HIP（无环境，已在 pass 层拒绝并有单测）；
- sm_80 以外架构；
- fp32；
- 性能对比与 autotune。
