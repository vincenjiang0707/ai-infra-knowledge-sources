### Description
<!-- Describe what you’ve done -->
**What**

Add the **Hyperball** constraint to the `Muon` optimizer so each parameter can be trained in one of four modes, plus a decoupled `muon_epsilon`.

- **`MuonParamInfo.use_hyperball`** (new field, default `False`): combined with `use_muon`, selects the per-parameter mode — **MuonH** (Muon direction + sphere projection), **AdamH** (Adam direction + sphere projection), plain **Muon**,
  plain **AdamW**.
- **`Muon._hyperball_apply`** (new): the shared projection `W_{t+1} = R·Normalize(W_t − η·R·Normalize(u))`, with `R = ‖W‖_F` recomputed every step (per-matrix for 2D, per-expert for 3D). No weight decay; `R` is not stored in the checkpoint.
- **`Muon._adamw_hyperball_update`** (new): the AdamH path — Adam-preconditioned direction fed into `_hyperball_apply`.
- **`muon_epsilon`** (new ctor arg, default `None`): the Newton–Schulz normalization epsilon, decoupled from `adam_epsilon`. When unset it falls back to `adam_epsilon`, so existing behavior is unchanged.
- **`MuonShardingOptimizer`**: classification changed to `keep_whole = use_muon or use_hyperball`. Hyperball params are kept whole on an owner rank (V1) so the global Frobenius norm is computable locally with no extra collective; plain AdamW stays element-wise sharded (V2).

**Why**

Hyperball fixes each weight matrix on a Frobenius-norm sphere (replacing weight decay), which needs the full matrix to compute `‖W‖_F`. Decoupling `muon_epsilon` lets the NS orthogonalization use a sensible eps (~1e-7) independent of Adam's much smaller `epsilon`.

**Backward compatibility**

Fully backward compatible: `use_hyperball` defaults to `False` (sharding reads it via `getattr(..., False)`), and `muon_epsilon` defaults to `adam_epsilon`. Existing configs produce identical behavior.
