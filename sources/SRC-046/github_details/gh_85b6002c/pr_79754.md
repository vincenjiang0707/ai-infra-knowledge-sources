### Description
<!-- Describe what you’ve done -->
背景：`gather_grad` 的 GPU 反向在 `axis != 0` 时走 `funcs::GatherV2GradCUDAFunction`，其 `GatherGradGPUKernel` 对每个元素调用`CudaAtomicAdd`。当 index 含重复值时（gather 反向即 scatter-add），原子加的累加顺序受线程调度影响，导致同一份输入会出现多次梯度不逐位一致。

在 `FLAGS_cudnn_deterministic`=true时，为 `axis != 0` 增加一条确定性反向路径，保持累加顺序的一致以及结果的稳定可复现，用于在PaddleAPITest中实现和torch的逐位对齐
- 新增`gather_grad_deterministic_cuda_kernel`：每个线程独占一个 `(inner_dim_index, outer_dim_index)` 列，在列内顺序遍历index完成梯度累加，因此同一元素的多次累加顺序固定
- 新增host 侧 `GatherGradDeterministicCUDAFunction`，索引映射与既有`GatherGradGPUKernel` 保持一致，支持 int32/int64 index

p.s 另外修复了gather_grad在处理0-D index时outer_dim计算错误的问题：0-D index下前向将在output中删除axis维，output仅有`input.dims()-1`维，所以gather_grad中计算outer_dim时要从axis维开始而不是axis+1维
