### Description

devPR:https://github.com/PaddlePaddle/Paddle/pull/79756

Cherry-pick of the `moe_permute` optimisation and bug fix from develop.

Two rewrites make `moe_permute` 1.9x faster for bfloat16 and 3.3x for float8
at the production shape, and no shape measured is slower (30 shapes tested,
1.03x to 12.55x). A third change fixes two pre-existing misaligned 16 B
accesses that abort the kernel outright.

The limiter was parallelism, not bandwidth: bfloat16 and float8 move 2x
different byte counts in 1297.3 vs 1295.8 us (0.1% apart), and turning the
token movement off entirely saves only 18%.

1. Replace the cross-block serial spin chain in phase 1 with two independent
   kernels (count + scan). Phase 1: 1068.6 -> 61.6 us.

2. Move token rows with one warp per row through registers instead of one row
   at a time through shared-memory ping/pong buffers via cp_async_bulk. This
   also removes the TMA store path (unreachable once the gather is
   unconditional) and returns 2 * token_dim * sizeof(dtype) of shared memory
   per block. bfloat16: 797.7 -> 246.8 us, float8: 814.2 -> 192.9 us.

3. Fix two places that touch token rows with 16 B vectors without checking the
   address (phase-2 fallback copy and padding-row fill). Reachable from the
   public API for any token_dim not a multiple of 16 B.

Neither rewrite performs arithmetic on token data, so the output is
bit-identical. Verified over 46 shapes against an independently computed
reference and over every shape the old path can run against the old path itself;
test/legacy_test/test_moe_permute_unpermute.py 11/11 passing.
