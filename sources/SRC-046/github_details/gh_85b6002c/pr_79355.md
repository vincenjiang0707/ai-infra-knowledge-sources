# [PR #79355] CI: avoid hard-fail in Linux-CPU tests when quick-disable list fetch is unavailable

source: https://github.com/PaddlePaddle/Paddle/pull/79355
state: closed | updated: 2026-09-17T16:35:15Z
labels: contributor

## 正文

`Linux-CPU / Build and test` was failing in the test stage with exit code `102` before running `ctest`. The failure path came from quick-disable list retrieval, where transient fetch errors terminated the job instead of using the existing fallback pattern.

- **Root cause**
  - `ci/utils.sh:get_quickly_disable_ut` called `exit 102` on fetch failure, aborting the whole test script.

- **Change**
  - Replace hard exit with graceful fallback in `get_quickly_disable_ut`:
    - keep `disable_ut_quickly='disable_ut'`
    - return non-zero (`return 1`) instead of exiting the process
    - emit explicit fallback log message

- **Why this aligns with current call sites**
  - Callers already use short-circuit fallback style, e.g.:
    ```bash
    get_quickly_disable_ut || disable_ut_quickly='disable_ut'
    ```

- **Example patch shape**
  ```bash
  else
      echo "Failed to fetch quickly disabled unittests, fallback to local default."
      disable_ut_quickly='disable_ut'
      return 1
  fi
  ```
