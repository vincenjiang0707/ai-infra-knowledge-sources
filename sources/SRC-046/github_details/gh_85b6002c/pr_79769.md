#### 修复内容与范围

修复 CUDA bilinear 插值在开启 `FLAGS_use_accuracy_compatible_kernel` 后，前向及输入梯度仍无法与 Torch 2.12 确定性路径逐位一致的问题。

兼容分支限定 CUDA、FP32、NCHW、`align_corners=False`、`align_mode=0`，且按输出尺寸计算插值坐标：

| 调用方式 | 开启兼容标志后的路径 |
|---|---|
| 显式 `size` | 兼容路径 |
| `scale_factor` + `recompute_scale_factor=True` | 兼容路径 |
| `scale_factor` + `recompute_scale_factor=False/None` | 原有路径 |

重算缩放先转换为输出尺寸，与对应显式 `size` 语义一致，无需新增算子来源属性。未开启标志，以及其他 dtype/layout、1D linear、抗锯齿入口保持原实现。

前向保留各步 FP32 舍入，避免 FMA 改变结果；反向复现四个 gather 分支的梯度及固定累加顺序，利用坐标单调性确定贡献区间，避免排序索引和原子累加。

#### 原 PR 性能结论

同一张 H800、相同输入与随机梯度，复用前向图单独测反向；预热 20 次，计时 100 次，5 轮中位数。同步墙钟耗时包含 Python 调用开销，单位 μs：

| 输出尺寸 | Paddle 原路径 | Torch 非确定性 | Paddle 兼容路径 | Torch 确定性 |
|---|---:|---:|---:|---:|
| 31×68 | 33.8 | 39.9 | 368.0 | 1844.1 |
| 20×35 | 26.5 | 39.9 | 307.8 | 981.7 |
| 19×37 | 28.2 | 39.6 | 306.6 | 987.1 |
| 30×45 | 28.2 | 39.5 | 326.5 | 1416.0 |

兼容前向约 21 μs，与 Paddle 原路径基本一致。兼容反向约 0.30–0.37 ms，比 Paddle 原路径慢约 11 倍，但比对齐目标 Torch 2.12 确定性路径快约 3.2–5.0 倍。

独立 Torch 进程及 CUDA Event 复核得到相近结果。31×68 的单独 Profiler 采样中，4 次索引梯度 kernel 合计约 1.36 ms、占 GPU kernel 时间约 80%；排序仅约 0.03 ms，主要瓶颈是通用确定性索引梯度归约。这些结论仅适用于该版本、硬件、形状与 eager 路径，不外推到 Torch 整体或 `torch.compile`。
