### Description

本 PR 简化 #79723 引入的模块化 AOA 生成接口，收敛命名协议、去掉两处过度设计。

**1. `checkpoint_name_mapping` 两侧改为绝对路径**

原来 key/value 都是相对根前缀的模板，命中后再拼 checkpoint 根前缀。改为 key 从 model 根写起、value 是完整的 checkpoint 名。

**2. `validate_checkpoint_name_mapping` 相应调整**

- key 侧保留根前缀校验：key 是拿去和 single 名比对的，single 名必带 model 根，所以无根 key 永远匹配不上，会静默退化成 identity 兜底产出一个看似合理的错名字，必须在入口拒掉。
- value 侧去掉同类校验：value 被原样当作最终 checkpoint 名使用，落在共享根之外是合法布局而非错误。
- 去掉「重复 checkpoint 目标」校验：mapping 要覆盖模型可能构建的全部布局，而两个互斥的输出头只会实例化一个，两个 key 共享一个 value 是合法声明。

**3. 去掉 dtype cast 机制与 `should_skip`**

删除 `DtypeCastRule`、`resolve_dtype_cast_rule`、`format_dtype_cast_attr`、`format_inv_dtype_cast_attr`、`should_skip`，以及 `AOAContext` 的 `dtype_cast_rules` / `excluded_names` 两个字段。需要 cast 的组件改为直接覆写最小范围类的 AOA 方法；`Layer` 基类递归改为两侧解析结果同名时省略该条语句。

**4. 用 `checkpoint_lookup_drop_segment` 取代 `AOANameScope`**

有的子树在真实模块树里比 checkpoint 里多嵌一层（MTP block 把 transformer layer 当子模块持有，而 checkpoint 把该层的张量直接挂在层下）。原来用一个四字段的 `AOANameScope` 加一条独立的 scoped 解析路径描述这件事，现在改为在查 checkpoint 名之前把这一个多出来的路径段从 single 名里去掉：去掉后子树的名字和普通层同形，`checkpoint_name_mapping` 里为普通层写的模板与 identity 兜底都直接适用，model 侧的名字保留该段。

删除 `AOANameScope`、`_scoped_checkpoint_name`、`_resolve_scoped_names`；`gen_aoa_statements` / `gen_inv_aoa_statements` 的关键字参数由 `aoa_name_scope` 改为 `checkpoint_lookup_drop_segment`。段不存在时按 no-op 处理，这样子树的持有者可以把同一个值无条件传给所有子模块；出现多次则报错，因为该丢哪一个无从判断。
