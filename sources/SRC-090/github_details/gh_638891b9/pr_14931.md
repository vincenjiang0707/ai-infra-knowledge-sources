## Summary

Adds the reconcile-diff algorithm for DGDC lifecycle management — [tracking issue #13545](https://github.com/ai-dynamo/dynamo/issues/13545), item 5 ("materialize DGDCs, and reconcile their lifecycle"). Given a desired set of candidates and the current set of DGDCs, decides what to create, delete, and update.

## Key design decision

Identity is a **content hash** of the rendered spec + evaluation-context fields, not `Status.Rank`. Rank changes over time as better candidates are found and worse ones evicted, often with no change to the candidate's own content — using it as identity would force unnecessary delete+recreate churn. Using a content hash instead means a real content change and an identity change are the same event, which lines up naturally with `DynamoGraphDeploymentCandidate.Spec`'s real, confirmed CEL immutability rule (`"spec is immutable"`) — there's no "update spec" code path in this module at all.

Confirmed against the real `v1beta2` Go types (fetched directly from the `#13603` PR branch)
