# [PR #15246] fix(sglang): pass the prefill dp rank to sglang decode

## 正文

## Overview:

In SGLang disaggregated serving with a data-parallel prefill, the decode engine has to know which prefill DP rank owns a request's KV before it can create its KV receiver. SGLang's own router sends that rank in the decode request (`disagg_prefill_dp_rank`). Dynamo chooses the rank in the frontend but never forwarded it to the decode leg, so SGLang's decode fell back to resolving the rank over HTTP against the prefill's bootstrap server. The prefill cannot start its forward until the decode receiver has registered, so that round trip is serial in front of every prefill.

Measured with SGLang's per-request time statistics (`--enable-request-time-stats-logging`) on a GLM-5.2 PD deployment with a 4-way DP prefill, per request:

| | without this change | with this change |
|---|---|---|
| decode `bootstrap_duration` | 150 ms to 650 ms depending on load (p90 up to 1.1 s) | 0.3 ms to 0.6 ms |
| prefill `bootstrap_duration` | 170 ms to 860 ms | 0.4 ms to 53 ms |
| requests parked in the decode pre-allocation queue | 3.7 to 6.8 per DP rank | 0 |
| client TTFT minus prefill `forward_duration` | 0.22 s to 0.64 s | 0.04 s to 0.06 s |

The native SGLang router reads 0.25 ms on the same decode metric.

## Details:

- `lib/llm/src/kv_router/prefill_router/mod.rs`: `PrefillOutcome::Bootstrap` and `PreparedPrefill` carry the prefill DP rank the router selected, and `into_decode_request` writes it to the decode leg's `routing.prefill_dp_rank`. The prefill leg already had it (`prepare_prefill_dispatch`); the decode leg is a clone taken before dispatch and only received `prefill_worker_id`.
- `components/src/dynamo/sglang/_compat.py`: `prefill_dp_rank_kwargs` builds `{"disagg_prefill_dp_rank": rank}` filtered through `filter_supported_async_generate_kwargs`, so an SGLang release without the argument receives nothing.
- `components/src/dynamo/sglang/request_handlers/llm/decode_handler.py`: passes it on the disaggregated `async_generate` call and on the native-payload builder.
- `components/src/dynamo/sglang/engine_generate.py`: `build_native_generate_request` accepts `prefill_dp_rank` and sets `disagg_prefill_dp_rank` when the installed `GenerateReqInput` has the field.
- Tests: the Rust decode-leg test asserts the rank is carried; Python tests cover the helper against engines with and without the argument, the disaggregated decode path forwarding the rank, and the native builder.

Every existing reader of `routing.prefill_dp_rank` is phase-gated (KV selector pinned-worker hint, session-affinity explicit target, SGLang and vLLM sidecar converters) and uses `dp_rank` alone for Decode and Aggregated, so setting the field on the decode leg does not change decode routing. The bootstrap room already encoded the rank (`compute_bootstrap_room`), but SGLang only trusts that encoding when the prefill runs `--load-balance-method follow_bootstrap_room`; sending the rank explicitly works for every load-balance method.

Not covered here: the multimodal decode handler (its request model has no routing block) and the Rust SGLang sidecar's decode request builder, which has the same gap and can now read the rank from the decode leg. Both are follow-ups.

## Where should the reviewer start?

`into_decode_request` in `lib/llm/src/kv_router/prefill_router/mod.rs`, then `_compat.prefill_dp_rank_kwargs` and its two call sites in `decode_handler.py`.
