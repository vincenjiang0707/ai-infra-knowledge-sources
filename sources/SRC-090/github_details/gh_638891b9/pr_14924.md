# [PR #14924] build(planner): move dynamo-planner image to CPython 3.13

## 正文

## Overview:

Move only the standalone `dynamo-planner` container image to CPython 3.13 by introducing a planner-scoped interpreter key. Everything else stays on the global `python_version: "3.12"`.

Moving the planner keeps its interpreter line on a supported CPython release without disturbing the frontend or the framework runtime images.

## Details:

- `container/context.yaml`
  - `planner_build_image_tag: 3.12-slim` → `3.13-slim`
  - `planner_runtime_image_tag: 3.12-v4.0.9` → `3.13-v4.1.4`
  - `planner_baseline_sbom: python@ec133be9` → `python@eb5be985` (new self-baseline stem for `nvcr.io/nvidia/distroless/python:3.13-v4.1.4`)
  - New key `planner_python_version: "3.13"` with a comment explaining why the planner does not follow the global `python_version`.
- `container/templates/args.Dockerfile`: adds `ARG PLANNER_PYTHON_VERSION={{ context.dynamo.planner_python_version }}` inside the existing `target == "planner"` block, following the local `PLANNER_*` args style.
- `container/templates/planner.Dockerfile`: every planner use of `PYTHON_VERSION` moves to the planner-scoped arg - the `ARG` declaration, the two comment references to `/usr/local/include/python${...}` and `python${...}-dev`, and the `uv venv ${VIRTUAL_ENV} --python ${...}` line. Nothing in this template is on the global arg any more.
- `container/compliance/policy/licenses.toml`: single header-comment tweak, `python:3.12-slim = Debian 13` → `python:3.13-slim = Debian 13`. Both images are Debian Trixie so the surrounding dpkg exceptions still apply.
- `container/compliance/base_sboms/`: re-captured the self-baseline SBOMs for `nvcr.io/nvidia/distroless/python:3.13-v4.1.4` on `linux/amd64` and `linux/arm64` with `capture_baseline_sbom.py`, updated `manifest.json`, and dropped the stale `3.12-v4.0.9` entries and files so `check_drift.py` stays green.

The global `python_version: "3.12"` is deliberately untouched. It flows through `args.Dockerfile` to eight templates (`args`, `dev`, `dynamo_runtime`, `frontend`, `planner`, `sglang_xpu_framework`, `vllm_runtime`, `wheel_builder`), and moving it is out of scope for two independent reasons already verified locally:

1. `frontend.Dockerfile` apt-installs `python${PYTHON_VERSION}-dev` on `nvcr.io/nvidia/base/ubuntu:noble-20250619`. Ubuntu 24.04 noble ships python3.12 with no python3.13 in its archive.
2. The framework runtime images (`vllm/vllm-openai`, `lmsysorg/sglang`, `nvcr.io/nvidia/tensorrt-llm/release`) ship python3.12 with cp312 ABI wheels for torch, vLLM, SGLang, and TensorRT-LLM.
