## 正文

## Summary

Validate supplied function parameter schemas with explicit `strict: true` before inference on `/v1/chat/completions` and `/v1/responses`. Invalid schemas return HTTP 400 with the existing error envelope and a diagnostic that names the function and schema location.

Responses validates all submitted functions before `allowed_tools` filtering, including namespace members. Validation also applies when `tool_choice` is `none`. Omitted, `null`, or `false` strictness and omitted or `null` parameters retain existing behavior. Submitted schemas are not normalized.

Fixes https://github.com/ai-dynamo/frontend-crates/issues/209

## Changes

- Add a shared iterative schema walker with deterministic diagnostics, object constraints, recognized keyword shape checks, and per-schema size budgets.
- Support bounded document-local references and recursive object schemas without expanding schemas or counting reference targets twice.
- Preserve Chat validation order and classify Responses conversion failures as `ResponsesConversionError::InvalidArgument`.
- Add HTTP regression and acceptance coverage, conversion compatibility tests, and walker tests for malformed schemas, references, and budget boundaries.
- Update the structural-tag and agent-harness guides with the behavior change and support limits.

Passing preflight does not establish complete OpenAI compatibility or guarantee backend enforcement of every constraint. Preflight runs independently of structural-tag activation.
