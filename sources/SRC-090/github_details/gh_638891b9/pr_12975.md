## Summary

The nvext page told readers to set `DYN_ENABLE_FRONTEND_NVEXT=false`. That variable does not exist. The real switch is `DYN_DISABLE_FRONTEND_NVEXT` (`lib/runtime/src/config/environment_names.rs:336`), so following the documentation was a silent no-op: `nvext` and the routing-override headers stayed in effect while the reader believed they were off.

Four other user-visible surfaces shipped with no documentation at all.

## Changes

| Area | Change |
|---|---|
| nvext | Replace the flag and describe the behavior from the code contract: enabled by default, truthy `1`/`true`/`yes`/`on`, drops `request.nvext` at handler entry, ignores the four `x-dynamo-*` routing overrides and the response-side `extra_fields` opt-in |
| router-examples | Document the `kv_state_endpoint` `WorkerConfig` parameter (`lib/bindings/python/rust/backend.rs:386`) and its compatibility default of the serving endpoint |
| metrics-catalog | Add `dynamo_kvrouter_ckf_mutation_total` |
| metric-labels | Add the `allocation_failed` and `ownership_degree_overflow` `status` values (the list carried 6 of the 8 in `lib/kv-router/src/indexer/metrics.rs`), plus the CKF `outcome` label |
| router-guide | Cross-link Multi-DC KV Routing, whose entry point was lost in the docs restructure |

## Verification

Every claim was checked against the source tree before editing: the env var name and its doc comment, `kv_state_endpoint` in the Python bindings and its `effective_kv_state_endpoint` fallback, the `CKF_MUTATION_NAME` and `METRIC_STATUS_*` constants, and the multi-DC page's presence in `index.yml` without a guide cross-link.

Documentation only, no behavior change.
