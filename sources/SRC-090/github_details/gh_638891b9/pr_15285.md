# [PR #15285] fix(sglang): return sidecar request refusals to the client

## 正文

## Overview:

The SGLang sidecar refuses some requests before it calls the engine, for example an image request or `n=2`. The client then gets `400 {"message":"Invalid request"}`, and the real reason is only in the worker log. Since #14396, the HTTP body shows `DynamoError::public_message()` and falls back to "Invalid request" when the error has no public message. The sidecar sets only the private message. This PR gives the fixed request-validation texts of the sidecar gRPC request builder a public message.

Repro (stock SGLang, one SGLang sidecar worker):

```bash
curl -s localhost:8000/v1/chat/completions -H 'Content-Type: application/json' -d '{
  "model": "Qwen/Qwen3-VL-2B-Instruct", "max_tokens": 16,
  "messages": [{"role": "user", "content": [
    {"type": "image_url", "image_url": {"url": "data:image/jpeg;base64,<JPEG>"}},
    {"type": "text", "text": "Describe this image."}]}]}'
```

Before:

```json
{"message":"Invalid request","type":"Bad Request","code":400}
```

After:

```json
{"message":"multimodal payloads are not supported by SGLang's native Generate RPC","type":"Bad Request","code":400}
```

The same change applies to `n=2` ("n must be 1 for the SGLang sidecar") and to the other request checks.

## Details:

`lib/sidecar/sglang/src/client.rs` adds `invalid_request(&'static str)`. The helper sets the same fixed text as the message and as the public message. The parameter type is `&'static str`, so client input and runtime values cannot become public through this helper.

`lib/sidecar/sglang/src/protocol.rs` uses the helper for its fixed request-validation texts. These are the checks in `validate_request` and the range checks for `max_tokens`, `min_tokens`, `logprobs`, the data-parallel rank, token ids, and stop-token ids. The token-id texts no longer include the client value. Errors that carry endpoints, bootstrap ports and rooms, engine state, or engine text stay private.

The `prompt_embeds` check now runs before the empty-token check. A `prompt_embeds` request arrives with empty `token_ids`, so the old order gave the wrong reason. The thinking-budget text now names the client field `thinking_token_budget`. This PR does not add or remove a refusal.

The tests check the public text for three refusals. They also check that a disaggregation handoff error has no public message.

Out of scope: the vLLM and TRT-LLM sidecars have the same gap through `invalid_argument` in `lib/sidecar/common/src/error.rs`. The refusals on the native HTTP path of the SGLang sidecar (`native_http.rs`) also keep a private message.
