## Overview

### Summary

DeepSeek V4.1 requests containing `image_url` blocks fail in Dynamo's pinned text-only renderer. This combines the published image-input renderer fix with media collection ordering: when assistant calls A then B but results arrive B then A, images and UUID cache references must follow the rendered A-then-B placeholders.

## Details

- Include Ace Eldeib's original commit `95f5434` from #15097, preserving its author and commit identity. It aligns tool-result media collection with the renderer, including model-name fallback and interleaved user images.
- Upgrade `dynamo-renderer` from 5.3.1 to 5.3.2 and its required shared `dynamo-protocols` dependency from 6.0.1 to 6.1.0.
- Regenerate the workspace, Python binding, and KVBM binding lockfiles with Cargo.
- Extend the existing DeepSeek V4.1 integration tests to cover interleaved text/images, URL and data-URL inputs, reasoning enabled/disabled, and UUID-only cached images in user/tool messages. Check that rendering preserves the original message content.
