## 正文

## Overview

With a Python chat processor, `DYN_REQUEST_TRACE_RECORDS=request_end` currently produces no request-end rows. The native Rust chat path installs a request tracker, but the Python processor sends its preprocessed request through `RoutedEngine` without that trace state.

## Details

- Attach a tracker at the Python-to-Rust routing bridge only when request-end capture is active. Reuse an existing tracker if the request has one.
- Emit one request-end row after the raw engine stream closes or is canceled, using the router's worker, queue, cache, token, and timing observations. Replay hashing runs off the response path.
- Include replay hashes for eligible single-choice text requests. Multimodal and other non-replayable inputs still produce a metadata row without `request.replay`; no media or request payload is captured by this change.
- Document the distinction between request-end metadata and replayable traces.

The Python path does not yet enrich these rows with session or parsed finish-reason metadata.

## Where should the reviewer start?

`lib/bindings/python/rust/llm/routed_engine.rs` owns the stream lifetime and tracker. `lib/llm/src/request_trace/record.rs` preserves the existing request-end schema while allowing absent replay hashes.
