## Summary

The opt-in Chat Completions `tool_call_dispatch` extension cannot safely consume fragmented OpenAI tool-call deltas. It currently treats one chunk containing `id`, `function.name`, and `Some(function.arguments)` as a complete call, emits that chunk as `event: tool_call_dispatch`, and immediately deduplicates the call by `(choice_index, id)`.

That same-chunk assumption is contradicted by Dynamo's own stream aggregation code and becomes operationally important when #13821 restores immediate publication of Python vLLM tool-call fragments.

The Rust dispatcher must accumulate each call by outer choice index and inner tool-call index, preserve identity fields across chunks, append argument fragments, and emit exactly once only at a defined JSON completion boundary.

## Current behavior and failure modes

The current predicate is in [`streaming_tool_dispatch_events`](<https://github.com/ai-dynamo/dynamo/blob/ff18f7210d9909d824b41193e1a58bb77e87d1c8/lib/llm/src/http/service/openai.rs#L2635-L2681>):

```rust
let has_name_and_args = chunk
    .function
    .as_ref()
    .is_some_and(|f| f.name.is_some() && f.arguments.is_some());

if let (true, Some(id)) = (has_name_and_args, &chunk.id) {
    if !dispatched_ids.insert((choice.index, id.clone())) {
        continue;
    }
    // emit the current chunk
}
```

OpenAI tool-call chunks require the inner `index`, but `id`, `type`, `function`, `function.name`, and `function.arguments` may arrive independently. Dynamo already documents and handles the common shape elsewhere:

```text
delta 1: index + id + type + function.name
delta 2: index + first function.arguments fragment
delta N: index + final function.arguments fragment
```

The current dispatcher therefore has three distinct failures:

1. If the identity opener contains `arguments: Some("")`, the existing intentional empty-argument rule dispatches an empty call immediately. Later fragments cannot correct it because the ID is already in the dedup set.
2. If the opener contains ID/name with `arguments: None` and continuation chunks contain arguments without repeating ID/name, no event is ever emitted because no individual chunk contains all three fields.
3. If one chunk contains ID/name and a non-empty but incomplete prefix such as `{"path":"/a/very`, that invalid prefix is dispatched immediately and later completion is suppressed.

This is not only hypothetical backend behavior. [`DeltaAggregator::merge_tool_call_chunk`](<https://github.com/ai-dynamo/dynamo/blob/ff18f7210d9909d824b41193e1a58bb77e87d1c8/lib/llm/src/protocols/openai/chat_completions/aggregator.rs#L209-L254>), added by ai-dynamo/dynamo#8582 for #8640, already corrects the same same-chunk assumption for non-streaming aggregation: ID/type/name are first-wins and argument fragments concatenate by inner tool-call index. Its split and interleaved regression cases are at [lines 1259-1423](<https://github.com/ai-dynamo/dynamo/blob/ff18f7210d9909d824b41193e1a58bb77e87d1c8/lib/llm/src/protocols/openai/chat_completions/aggregator.rs#L1259-L1423>).

## Required behavior

The ordinary OpenAI `data:` chunks must pass through unchanged. With `--enable-streaming-tool-dispatch`, Dynamo must additionally emit one `tool_call_dispatch` event containing the fully assembled call as soon as the completion policy below is satisfied.

The event remains a Dynamo extension with its current payload:

```json
{
  "choice_index": 0,
  "tool_call": {
    "index": 0,
    "id": "call_1",
    "type": "function",
    "function": {
      "name": "create_file",
      "arguments": "{\"path\":\"/a/very/long/file\"}"
    }
  }
}
```

It must not be converted into a synthetic ordinary `ChatCompletionChunk`, and it must not be enabled by default on `/v1/chat/completions`.

### 1. Request-local assembly state

Replace the HashSet-only detector with request-local state keyed by:

```rust
(choice.index, tool_call_chunk.index)
```

This state belongs beside the current reasoning and dispatch state in the per-request streaming branch at [`openai.rs:2935-2941`](<https://github.com/ai-dynamo/dynamo/blob/ff18f7210d9909d824b41193e1a58bb77e87d1c8/lib/llm/src/http/service/openai.rs#L2935-L2941>). Create or update an entry for every tool-call chunk; do not require ID and name to coexist in the chunk that creates the entry.

For normal fragments, use the same merge semantics as `DeltaAggregator`:

* Preserve the first non-`None` ID, type, and function name.
* Append every `Some(arguments)` fragment in arrival order, including empty fragments.
* Allow arguments to arrive before identity and dispatch later when both identity and completion are available.
* If a later non-empty identity field conflicts with an earlier value for the same key, mark the entry invalid, log the producer violation, and do not assemble a call from conflicting identities.

Retain a completed-key tombstone after emission so a replayed complete chunk cannot emit twice. Isolation must remain correct when two choices use the same call ID and the same inner index.

The existing merge helper should be extracted for shared use, or the dispatcher should have parity tests against it. Do not introduce a third, subtly different field-merge policy.

### 2. Early-completion policy

Chat Completions has no per-tool-call `done` bit. `finish_reason` terminates the choice, not each individual call. Consequently, JSON closure is a Dynamo early-dispatch convention rather than proof supplied by the OpenAI protocol.

For early dispatch before `finish_reason`:

* Maintain an incremental JSON structural scanner with container, string, and escape state that survives fragment boundaries.
* At minimum, recognize self-delimiting top-level objects and arrays, including nested mixed containers.
* Ignore braces/brackets inside strings and handle an escape split across chunks.
* Consume the entire current fragment before declaring a candidate, so `{}junk` cannot dispatch at the first closing brace.
* When the root container closes, validate the complete accumulated string once with `serde_json`, allowing only trailing whitespace.
* Emit only when JSON syntax is valid and ID/name are available.

The scanner should be O(total argument bytes). Calling `serde_json::from_str` on the whole buffer after every token would become quadratic for the long arguments that motivated #13821. Structural scanning identifies candidate boundaries; `serde_json` confirms them.

Top-level scalar values do not need speculative early dispatch. They can wait for the terminal policy below, because a number such as `1` may legally receive another fragment such as `2`.

Successful JSON parsing proves syntax only. It does not validate arguments against the requested tool schema or authorize execution; extension clients must continue to perform those checks.

Once a valid root value has been dispatched, a later non-whitespace continuation for that key is a backend/protocol violation. Log and suppress it; an already emitted event cannot be retracted. Preserve the existing behavior for an exact replay of an already completed call without emitting a duplicate.

### 3. Terminal, empty, and malformed state

`Some("")` is ambiguous during streaming: it may mean a parameterless backend call, or it may be an empty opener followed by real argument fragments. It must not dispatch early merely because the field is present.

* Canonical parameterless arguments (`"{}"`) can dispatch early.
* On `finish_reason: "tool_calls"`, make one final completion pass. This is the only point where the existing empty-string parameterless compatibility may be preserved safely, because the choice has definitively stopped producing arguments.
* Preserve the exact accumulated argument string in the event; do not silently rewrite model output.
* Do not dispatch incomplete or malformed non-empty JSON on `length`, backend error, disconnect, or raw EOF.
* Clear unfinished state for each choice when that choice terminates. Request-local state naturally disappears when the HTTP stream is dropped.

### 4. Pipeline placement and ordering

Keep dispatch at its current observational boundary in the HTTP stream:

1. Apply `parallel_tool_calls=false` filtering.
2. Update dispatch state from the surviving ordinary chunk.
3. Emit `tool_call_dispatch` before the ordinary `data:` event for the fragment that completes the call, matching current ordering.
4. Pass the original response once through `EventConverter`, metrics, and response collection.

The relevant loop is [`openai.rs:2947-3024`](<https://github.com/ai-dynamo/dynamo/blob/ff18f7210d9909d824b41193e1a58bb77e87d1c8/lib/llm/src/http/service/openai.rs#L2947-L3024>). The tracker may clone or accumulate metadata for its own payload, but it must not consume, rewrite, duplicate, or re-aggregate the standard deltas.

## Prior art from [#6845](<https://github.com/ai-dynamo/dynamo/issues/6845>)

[#6845](<https://github.com/ai-dynamo/dynamo/issues/6845>) is useful design material, not a patch to cherry-pick. Its final implementation provided:

* Request-local `(choice_index, tool_call_index)` state.
* Accumulated arguments.
* String and escape state across fragment boundaries.
* Exactly-once emission.
* Tests for quoted braces, split escapes, multi-fragment ordering, and interleaved calls.

Do not restore its old stream adapter or `event: tool_call.complete`; the current `tool_call_dispatch` event boundary is the correct integration point. Do not copy its scanner unchanged either: it initialized state only when ID and name appeared together, recognized only object braces, did not parse the resulting JSON, and considered `}{"x":1}` structurally complete after clamping the leading brace. The new regressions should reject that input.

## Regression coverage

Add focused tests that establish both the state machine and its placement in the SSE pipeline:

 1. A valid single-chunk object still emits exactly once with the existing payload.
 2. An identity opener followed by two argument-only fragments emits nothing until the final fragment, then contains the preserved index/ID/type/name and complete arguments.
 3. `arguments: Some("")` followed by later fragments does not dispatch the empty opener.
 4. ID, name, and arguments arriving in different chunks still assemble correctly; conflicting repeated identity fails closed.
 5. Quoted braces, escaped quotes, a backslash split across fragments, nested objects, and arrays do not create false boundaries.
 6. Leading junk, trailing junk in the completing fragment, mismatched containers, and truncated JSON never dispatch.
 7. Two same-choice calls at inner indexes 0 and 1 can interleave and complete in reverse order.
 8. Two outer choices can both use inner index 0 and the same call ID without state collision.
 9. `parallel_tool_calls=false` never accumulates or emits a filtered higher-index call.
10. Terminal cases cover valid JSON, `{}`, absent/empty arguments under the compatibility rule, invalid JSON, and `finish_reason: "length"`.
11. A repeated complete backend chunk remains deduplicated.
12. A stream-level test proves that every #13821-style ordinary fragment remains an ordinary SSE `data:` event and that exactly one dispatch event precedes the ordinary fragment that completes the JSON.

The existing `make_choice_with_tool_call` helper hardcodes inner index 0 and should accept an explicit tool-call index. The current `extract_sse_data_json` test helper also finds JSON boundaries with a brace-only, string-unaware scan; quoted-brace cases should exercise typed state/payloads or the actual SSE serialization rather than failing inside that test helper.

## Documentation

Update the streaming-dispatch documentation to state the actual completion convention: Dynamo assembles fragments and JSON-syntax validates the complete argument string before emitting the extension event, while the client remains responsible for tool-schema validation and execution policy. The existing claim that the harness receives a ready-to-execute call with no assembly should remain true after this change.

## Scope

This issue covers only the Rust Chat Completions `tool_call_dispatch` extension.

* #13821 separately restores normal OpenAI delta cadence in the Python vLLM postprocessor.
* Parser-v2 Qwen streaming is separate because its scanner currently waits for a complete `</function>` block.
* Responses and Anthropic converters use their own protocol completion events and are not changed here.
* The custom Chat Completions event remains opt-in; this issue does not make it part of the standard OpenAI stream.
