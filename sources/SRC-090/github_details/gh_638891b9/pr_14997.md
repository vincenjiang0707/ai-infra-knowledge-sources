## 正文

## Summary

`spec.backendFramework` — a real, validated field on `v1beta1.DynamoGraphDeploymentSpec` — is never set anywhere in the direct-renderer materialization pipeline producing DGD/DGDC which misses the field.

## Fix

New `set_config_backend_framework(config, backend)`, added once in `protocol.py`'s `BaseConfigModifier`:

- **Spec-level, not per-component** — unlike `set_config_model`/`set_config_replicas`, `backendFramework` is a single top-level field, not something set per worker.
- **No CLI flag involved**, so no per-backend duplication needed — one shared implementation, not three.
- `Config.spec` uses `extra="allow"` (confirmed in `config.py`), so setting `backendFramework` directly is a legitimate, permissive field assignment, not a schema violation.

Called once in `materialize_dgd_from_candidate`, right after `update_image` and **before** the agg/disagg branch — deliberately *not* inside `_materialize_worker`, since that function runs twice for disagg (once per role) and `backendFramework` is set once per DGD, not once per role.

## Files changed

- `components/src/dynamo/profiler/utils/config_modifiers/protocol.py` — new `set_config_backend_framework`
- `components/src/dynamo/profiler/sweeper/renderers/direct/materializer.py` — one new call site
- `components/src/dynamo/profiler/tests/unit/sweeper/test_renderer_direct.py` — two new tests
