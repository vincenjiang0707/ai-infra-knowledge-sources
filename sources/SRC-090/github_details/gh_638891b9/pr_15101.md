# [PR #15101] fix(multimodal): preserve URL path case in ImageLoader cache key

source: https://github.com/ai-dynamo/dynamo/pull/15101
state: open | updated: 2026-09-25T13:24:05Z
labels: external-contribution, size/L, fix, multimodal

## 正文

## Overview:

`ImageLoader.load_image` built its HTTP(S) cache key by lowercasing the entire URL:

```python
key = normalized_url.lower()
```

Per RFC 3986, only the scheme and host are case-insensitive. Paths, queries, userinfo and fragments are not, and case-sensitive object stores such as S3 and GCS serve different objects for `/Cat.png` and `/cat.png`. Those two URLs collapsed onto one cache entry, so the second request was served the first request's decoded image with no origin fetch, no error, and no log line at the collision. The same key feeds `self._inflight`, so concurrent requests for case-differing URLs also deduped onto a single fetch.

`ImageLoader` is a process-wide instance in the vLLM encode worker, so within the LRU window one request's image bytes could be returned for another request's URL.

## Details:

The key is now rebuilt from parsed components, lowercasing only the host and port and dropping the fragment:

```python
parsed_url = urlsplit(normalized_url)
...
userinfo, at, hostport = parsed_url.netloc.rpartition("@")
key = parsed_url._replace(
    netloc=f"{userinfo}{at}{hostport.lower()}", fragment=""
).geturl()
```

Three things this gets right, each of which was a separate round of review:

- **Host only, not the whole authority.** `netloc` carries userinfo, so `rpartition("@")` keeps `User:Token@` verbatim and lowercases only `host:port`. Case-distinct HTTP Basic credentials no longer share an entry.
- **Parsed components, not string slicing.** The parser strips leading control characters, so a byte-offset slice into the raw string could put the case-folding boundary in the wrong place and let `\nhttps://example.com/A` collide with `https://example.comm/A`.
- **`urlsplit`, not `urlparse`.** See below.

The cache is in-memory and rebuilt on every boot, so the key format change needs no migration.

## Trailing semicolons (review round 3)

`urlparse` peels a trailing `;params` off the last path segment into a separate field, and `geturl()` cannot put an *empty* one back:

```
urlparse('https://example.com/img.png;').geturl()  ->  'https://example.com/img.png'
urlsplit('https://example.com/img.png;').geturl()  ->  'https://example.com/img.png;'
```

So `/img.png;` round-tripped to `/img.png` and shared its cache and in-flight entry, while yarl puts both on the wire unchanged as distinct request targets. What a local origin actually receives:

```
requested '/i.png?'  -> origin saw '/i.png'
requested '/i.png'   -> origin saw '/i.png'
requested '/i.png;'  -> origin saw '/i.png;'
requested '/i.png;;' -> origin saw '/i.png;;'
requested '/i.png#A' -> origin saw '/i.png'
```

This one was self-inflicted: it did not exist on `main` (which lowercased the raw string and so kept the semicolon), and arrived with the rewrite onto parsed components. `urlsplit` does no params splitting, so the path reaches the key verbatim. Nothing in the module read `.params`, and `data:` is not in `urllib.parse.uses_params`, so the `data:` branch parses identically either way.
