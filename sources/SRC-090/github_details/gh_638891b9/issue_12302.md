# [Issue #12302] Pass through thinking_token_budget from OpenAI-compatible requests

source: https://github.com/ai-dynamo/dynamo/issues/12302
state: closed | updated: 2026-09-19T21:51:57Z
labels: enhancement, language::rust, dynamo-llm, frontend

## 正文

## Summary

Allow OpenAI-compatible chat/Responses requests to pass a root-level `thinking_token_budget` through preprocessing into backend sampling parameters when the backend supports it.

## Motivation

Some reasoning models expose a per-request budget for generated reasoning tokens. Dynamo already has lower-level support for a `thinking_token_budget`-style sampling field in some paths, but OpenAI-compatible chat/Responses ingress should be able to carry the same request-level control without the frontend validator stripping it as unsupported.

This is useful for generic reasoning-model deployments where operators need to bound runaway reasoning without changing the model's default configuration.

## Proposed API shape

Accept a root-level optional integer on OpenAI-compatible chat requests, for example:

```json
{
  "model": "dummy-reasoning-model",
  "messages": [
    {"role": "user", "content": "Return a short answer for this synthetic prompt."}
  ],
  "max_completion_tokens": 128,
  "thinking_token_budget": 32
}
```

Equivalent Responses API ingress should preserve the field if the request is converted through chat-completion internals.

## Expected behavior

- Omitted field remains `None` / unset, so existing defaults still apply.
- Present field is validated as a non-negative integer within backend-supported bounds.
- The value is forwarded through preprocessing to `SamplingParams.thinking_token_budget` or the equivalent backend request field.
- Unsupported backends should either ignore it explicitly according to existing backend-option policy or return a clear validation error; it should not be silently dropped before backend selection.

## Reproduction scenario

1. Send the dummy request above to a synthetic reasoning-model setup.
2. Inspect the preprocessed/backend request object.
3. Verify `thinking_token_budget: 32` reaches the sampling parameters.
4. Repeat with the field omitted and verify no budget override is set.

The payload is intentionally synthetic. Do not include real prompts, customer names, internal request IDs, URLs, credentials, or proprietary model names in reproductions.
