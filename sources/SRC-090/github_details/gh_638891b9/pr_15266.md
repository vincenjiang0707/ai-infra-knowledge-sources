## 正文

## Overview

An etcd member can stop responding while its TCP connection remains open. The watch then receives neither events nor an error, so discovery stays stale. This combines the watch retry, HTTP/2 keepalive, and lease-budget warning in **one signed commit**. It supersedes #15263 and closes #15262.

## Changes

- Retry watch stream creation with backoff after a reconnect failure while a receiver still exists. Watch creation and retry sleep exit on runtime cancellation or receiver closure.
- Enable etcd HTTP/2 keepalive by default: 15s ping interval and 10s acknowledgment timeout. `ETCD_KEEPALIVE_INTERVAL_SECONDS=0` disables it; both values remain configurable. Builder-created clients receive the default when no explicit connection options are supplied.
- Disable pings when the channel has no active streams, as required by etcd's default enforcement policy. Active watch and lease streams still receive pings.
- Change the default primary lease TTL from 10s to 30s. The 25s keepalive detection budget is below that TTL. An explicit `ETCD_LEASE_TTL` still takes precedence.
- Warn when a configured interval plus timeout reaches or exceeds the configured lease TTL. This warns of a tight or impossible recovery budget without changing operator settings. A PING timeout detects a transport stall; it cannot detect an application-level stalled watch if the HTTP/2 connection remains healthy.

These changes correspond to basetenlabs/dynamo#905, #917, and #935. The standalone paused-member reproduction is in #15262.
