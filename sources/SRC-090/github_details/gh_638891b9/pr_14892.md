## Summary

Add live `paused` state to the Python vLLM worker's `get_weight_version` response, queried under `_pause_lock`. Controllers can distinguish a serving worker from one left paused after a weight update. A downstream replay failure left a paused worker receiving traffic and hanging requests, motivating this observation.

Pause query succeeds (`true` means paused; `false` means unpaused):

```json
{"status": "ok", "version": "checkpoint-1", "paused": false}
```

Pause query fails or returns an invalid value:

```json
{"status": "ok", "version": "checkpoint-1", "paused": null}
```

Failures are logged; version retrieval still succeeds. `null` means unknown, not unpaused. No error-detail field is added. `EngineDeadError` retains the existing shutdown behavior. The original `getattr(self, "_weight_version", "initial")` is preserved, including its missing-attribute fallback.

`paused` is unconditional so callers use one response shape; clients with closed schemas must accept the added boolean-or-null field. The query still waits for the engine and lock, and follows vLLM's pause semantics, without an all-DP-rank guarantee. Readiness and routing are unchanged.
