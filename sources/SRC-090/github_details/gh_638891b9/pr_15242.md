## Summary

Make the runtime's NVTX ranges shippable.

### Compile NVTX ranges into runtime wheels

The Rust runtime annotates the frontend hot path (`preprocess.*`, `route.*`, `transport.*`, `detokenize`) behind the `nvtx` Cargo feature and the `DYN_ENABLE_RUST_NVTX` runtime gate. The feature was absent from the wheel builds, so in every published wheel the macros expand to nothing and the runtime gate has no effect. It could not simply be enabled: the ranges went through `cudarc::nvtx`, whose build links `libnvToolsExt.so`, the NVTX v2 shared library that CUDA 12.9 removed. The CUDA 13 base images ship only the `nvtx3/*.h` headers, so a wheel built with the feature either fails to link or fails to import.

- `lib/runtime/src/nvtx.rs` now delegates to the `nvtx` crate, which compiles the header-only NVTX v3 shim into the binary. No shared library at build or run time; Nsight attaches through its injection library at launch as before. The macros and the `DYN_ENABLE_RUST_NVTX` gate are unchanged. The crate is already a workspace dependency through kvbm.
- `nvtx` is added to the maturin feature lists in the wheel builder. With the feature compiled in and the gate unset, each range site costs one relaxed atomic load.
- `dynamo.common.utils.nvtx_utils` degrades to its existing no-op path with a warning when `DYN_NVTX=1` is set but the `nvtx` Python package is absent, instead of failing at import. Profiling presets set that variable on every launch, and not every serving image ships the package.

## Validation

- `cargo check` and `cargo clippy -D warnings` on `dynamo-runtime` with and without the `nvtx` feature; `cargo check -p dynamo-llm --features nvtx`; `cargo fmt --check`.
- A runtime wheel built with the feature on a CUDA 13 aarch64 SGLang image: `ldd` on `_core.abi3.so` shows no `libnvToolsExt` dependency, the NVTX symbols are present, `from dynamo.runtime import DistributedRuntime` and the `dynamo.frontend` and `dynamo.sglang` entry points work.
- Serving with that wheel under `DYN_ENABLE_RUST_NVTX=1`: the frontend and workers log "NVTX annotations enabled", and the frontend's Nsight report contains the `preprocess.*`, `route.*`, `transport.*`, and `detokenize` ranges.
- `nvtx_utils` import guard checked by importing the module with the package made unavailable.
- `pre-commit` passes on every changed file.

## Known limitations

- The CI multi-arch wheel builds are the remaining check for the x86 and CUDA 12 variants.
