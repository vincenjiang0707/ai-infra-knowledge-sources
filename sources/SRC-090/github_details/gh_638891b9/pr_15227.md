# [PR #15227] fix(sglang): gate auto tool-call grammars on reasoning

source: https://github.com/ai-dynamo/dynamo/pull/15227
state: closed | updated: 2026-09-24T02:59:15Z
labels: external-contribution, size/M, fix, frontend

## 正文

With thinking enabled and `tool_choice="auto"`, Kimi K3 can return only reasoning: no answer and no tool call.

## Example

```json
{
  "model": "<your-served-kimi-k3-model>",
  "messages": [
    {"role": "user", "content": "What is the weather in San Francisco? Use the weather tool."}
  ],
  "chat_template_kwargs": {"thinking": true},
  "tool_choice": "auto",
  "tools": [{
    "type": "function",
    "function": {
      "name": "get_weather",
      "parameters": {
        "type": "object",
        "properties": {"city": {"type": "string"}},
        "required": ["city"]
      }
    }
  }],
  "stream": true,
  "stream_options": {"include_usage": true}
}
```

**Before:** the client gets `reasoning_content` chunks until the token budget runs out, then `finish_reason: "length"`. It gets no `content` and no `tool_calls`.

**After:** the model finishes thinking, then calls `get_weather({"city": "San Francisco"})`. `tool_choice="auto"` still allows a plain answer instead.

## Why it happens

For `auto`, the frontend sends a tool-call grammar (a structural tag) to the worker. Kimi K3's grammar forbids the end-of-thinking marker `<|close|>think<|sep|>`. The frontend also sent `require_reasoning=False`, so the grammar applied from the first token, while the model was still thinking. The model could not close its thinking block. It escaped only occasionally, by jumping straight into a tools block.

## Fix

`_guided_output_requires_reasoning` now returns `True` for an auto request whose guided decoding is a tool-call structural tag. SGLang then holds the grammar back until thinking ends. This matches SGLang's `serving_chat.py`, which sets `require_reasoning = thinking_mode` for every `tool_choice`.

Unchanged:
- `required`/named tool choices.
- An explicit `response_format`, including the gpt-oss exception.

Note: the SGLang worker must run with SGLang's own `--reasoning-parser`. `--dyn-reasoning-parser` alone does not enable the backend that holds the grammar back. The same already applies to `required`/named tool choices.

## Testing

`test_sglang_processor_unit.py`:
- gate cases for an auto structural tag, including `response_format: text` and the gpt-oss `structural_tag` exception;
- a Kimi K3 pool-worker test using the example above: `thinking=true` gives `require_reasoning=True`, `thinking=false` gives `False`. The `thinking=true` case fails without the fix.

291 passed. The two `kimi_k2` auto failures also fail on `main` with this SGLang checkout (`get_model_structural_tag` rejects `parallel_tool_calls`). Not yet verified against a live Kimi K3 worker.
