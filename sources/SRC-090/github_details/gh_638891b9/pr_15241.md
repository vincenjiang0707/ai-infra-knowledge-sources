# [PR #15241] fix(anthropic): open a fresh text block for text arriving after streamed tools

## 正文

## Problem

When a chat-completions stream interleaves text and tool calls (e.g. text before and after a tool header, as produced by several backends such as Nemotron), the Anthropic stream converter dropped or malformed the trailing text:

- The tool-call path correctly closes the current text block (`content_block_stop`), per the Anthropic streaming spec (each block must be closed before the next starts).
- But text arriving *after* the tool chunk still emitted `content_block_delta` into the **closed** block's index, because the converter only ever opened a text block once (`text_block_started` was never reset after `text_block_closed = true`).

Anthropic SDK consumers discard deltas on stopped blocks, so the trailing text fragment was silently lost; strict clients treat it as a protocol violation.

## Fix

Open a **fresh** text block (new `content_block_index`) whenever text arrives after the previous text block was closed, instead of resuming the closed one:

```rust
if !self.text_block_started || self.text_block_closed {
    self.text_block_started = true;
    self.text_block_closed = false;
    self.text_block_index = self.next_block_index;
    self.next_block_index += 1;
    // emit content_block_start ...
}
```

This composes with the existing lazy tool-block flush: block indices stay strictly monotonic (text blocks inline, tool blocks at flush), and no `content_block_delta` is ever emitted into a block that already received `content_block_stop`.

## Testing

`test_text_after_tool_opens_fresh_text_block`: text -> tool chunk -> text -> `tool_calls` finish, asserting:
- two distinct, consecutive text block indexes;
- each fragment's `text_delta` lands in its own block;
- the first text block's `content_block_stop` precedes the second block's `content_block_start`, and the closed block is never resumed.

Verified the test fails without the production change. All 40 pre-existing `anthropic::stream_converter` tests pass unchanged (`cargo test -p dynamo-llm --lib anthropic::stream_converter`).
