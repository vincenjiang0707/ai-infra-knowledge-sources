# [PR #15249] fix(frontend): Flush buffered byte-fallback decoding

## 正文

## Overview:

Prevent frontend response failures caused by incremental byte-fallback decoding while preserving the tokenizer’s full-decode output.

A later malformed byte can cause Hugging Face’s ByteFallback decoder to reinterpret an entire byte-token run, including a prefix Dynamo has already emitted. The companion tokenizer change buffers that unstable suffix. This PR integrates terminal flushing into Dynamo so buffered text is not lost when generation ends.

## Details:

- Consume the companion tokenizer fix, which buffers unfinished byte-fallback runs while retaining the append-only guard for other unexpected rewrites.
- Flush buffered text at EOS, terminal chunks, bare end-of-stream, and engine-decoded terminal responses.
- Preserve stop-sequence buffering, output ordering, error propagation, and per-token metadata.
- Add self-contained Rust regression coverage for byte-fallback boundaries and terminal/stop handling. The tests require no running frontend, model weights, GPUs, or Kubernetes.
- Pin the companion tokenizer commit in both the root and Python-binding Cargo workspaces so direct and transitive consumers resolve the same patched implementation.

Companion tokenizer change:
https://github.com/ai-dynamo/frontend-crates/compare/main...alexeldeib:ace/stable-byte-fallback-decode

The tokenizer fix should be published first; I'll replace both temporary review pins with the published release before publishing this PR.

Validation against current upstream main (beyond some offline e2e, because this issue came from our prod env):

- Tokenizer: 88 unit tests and 8 integration tests passed.
- Dynamo: 15 backend-filtered tests and 15 stop-behavior integration tests passed.
- Formatting, applicable pre-commit checks, and tokenizer Clippy passed.

Then review the companion tokenizer change in `tokenizers/src/lib.rs` and `tokenizers/src/hf.rs`. Finally, check `Cargo.toml` and `lib/bindings/python/Cargo.toml` to confirm both workspaces resolve the same patched tokenizer source.
