## 正文

## Summary

- Map CODEOWNERS areas to pytest feature markers for selective CPU test routing.
- Keep GPU, multi-GPU, and vLLM CPU-E2E stages on full expressions until empty-stage gates exist.
- Add deterministic shadow reporting for matched areas, marker expressions, and selected node IDs.
- Validate marker coverage across tests, components, Python bindings, and GPU memory service tests.

## Changes from #13845

- Rebased the implementation onto current `main`.
- Preserve current sidecar exclusions, Triton coverage, and the vLLM CPU-E2E split.
- Treat `.txt` dependency files as test-affecting paths instead of documentation.
- Avoid empty GPU selections that would fail with pytest exit code 5.
- Expand the marker audit to Python bindings and GPU memory service suites.
- Make optional dependency stubs deterministic for the expanded audit.
- Correct the CODEOWNERS filter comment and cover all selector inputs in filter tests.
- Regenerate CODEOWNERS from the updated ownership source.

## Rollout

Shadow mode remains fail-open. Selective mode remains fail-closed. In selective mode, only backend CPU smoke lanes use the generated feature expressions. GPU stages retain their current full expressions.

- Strict CODEOWNERS coverage passed for 5,908 tracked files.
- Changed-file filter suite passed 75/75 cases.
