## 正文

<!-- codex-pr-description:start -->
Dynamo replay now exposes optional, policy-neutral telemetry at a configurable simulated-time cadence through in-memory capture, a Python callback, and buffered JSONL. This lets consumers such as Planner Gym persist queue, traffic, fleet, cache, and latency timelines without changing the scaling-policy callback or default report shape.

CLOSES: LLM-193

### How This Was Implemented

- Added a dedicated `ReplayTelemetryObserver`, composed independently with scaling observers.
- Emit baseline, periodic, and final snapshots while keeping live gauges separate from interval counters, including counters from retired workers until the next sample.
- Grouped high-level controls in optional `TelemetryOptions`; omitting it constructs no telemetry observer, capture buffer, or sink.
- Support in-memory capture, Python callbacks, and a lazy buffered JSONL sink; callback-only and JSONL-only runs do not retain a telemetry vector.
- Preserve Python callback exceptions and flush buffered telemetry after replay, including failure paths.
- Use ordinary file creation with direct checks that configured output paths do not exactly equal each other or an input trace.

<details>
<summary>Walkthrough</summary>

- Mocker propagates scaling and telemetry observers independently through aggregated, disaggregated, concurrency, and agentic replay paths.
- The high-level Python wrapper translates `TelemetryOptions` into the private native arguments and materializes typed telemetry only when capture is requested.
- Samples are emitted serially; shared writer ownership exists only so the binding can flush after AISimulate consumes the observer, not to coordinate concurrent writers.
- The JSONL sink creates parent directories, opens lazily on the first successful sample, writes newline-delimited JSON, and flushes at replay completion.

</details>

### Validation

- Native replay telemetry suite: 19 passed.
- High-level replay API and simulation suite: 17 passed.
- `cargo check`, `cargo fmt --check`, Black, Ruff, Python compileall, and `git diff --check` passed.

### Benchmark Results

- Exact commit `708442176b`, 60 paired release-mode runs: telemetry omitted was `+0.504%` median elapsed versus baseline revision `373bc9f`, with a one-sided 95% upper bound of `+0.920%` against the `+5%` gate.
- Five-second JSONL sampling versus the same candidate with telemetry omitted was `+0.260%` median overhead, with a one-sided 95% upper bound of `+0.787%`.
- A 100,000-sample JSONL-only soak wrote 169,974,059 bytes without a captured telemetry vector. Peak RSS was 278,020,096 bytes, within the 274-293 MB range and essentially equal to the 278,118,400-byte median of ordinary disabled runs.
