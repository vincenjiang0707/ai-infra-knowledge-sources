# [PR #15236] fix(tests): arm the vLLM worker's startup VRAM guard in the frontend test

source: https://github.com/ai-dynamo/dynamo/pull/15236

## 正文

Closes [DYN-4247](https://linear.app/nvidia/issue/DYN-4247).

## Summary:

The fixture launches its vLLM worker with both `--kv-cache-memory-bytes` and `--gpu-memory-utilization 0.01`. With the byte count set, vLLM sizes the KV cache from it and skips memory profiling, so the utilization value decides no allocation. Its one remaining job is vLLM's startup guard, which refuses to start when free VRAM is below `total * utilization`. At `0.01` that guard asks an 80 GiB card for 0.8 GiB and passes on a nearly full card. The worker then loads weights it cannot fit and dies out of memory, which the fixture reports as `Main server process exited with code 1 while waiting for health check`.

## Details:

The fraction is now derived from the test's own `@pytest.mark.profiled_vram_gib` budget and the total memory of the GPU the pytest child was pinned to — the budget the GPU-parallel scheduler packs the card against. When the card cannot be queried (no `pynvml`, or a UUID in `CUDA_VISIBLE_DEVICES`), the previous `0.01` is kept.

Allocation on a free card is unchanged: profiling is still skipped and the KV cache is still sized from the byte count. Under contention the test still fails — no fixture change fits a worker onto a full card — but it refuses at the startup memory snapshot with a named error instead of first taking 12.82 GiB that co-scheduled tests need. No flake-rate improvement is claimed, and VRAM contention is not shown to be the only cause of this error string.

The SGLang metrics test stub also uses the current `_guided_output_requires_reasoning` helper name so its processor import succeeds.

## Validation:

On a free card `test_reasoning` passes and reserves the same memory as before. The reported error was reproduced on unchanged `main` under held VRAM, and the same conditions with this change produce the named refusal instead. `pre-commit run --files tests/frontend/test_vllm.py` passes. Two other tests in this file fail identically with and without the change on this host.

## Where should the reviewer start?

`WorkerProcess._gpu_memory_utilization` in `tests/frontend/test_vllm.py`, and its helper `_visible_gpu_total_memory_gib`.
