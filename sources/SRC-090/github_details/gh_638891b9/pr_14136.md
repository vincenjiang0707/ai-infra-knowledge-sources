## 正文

## Overview

The ownership contract check catches an owner lost to last-match-wins precedence while its declaration survives. Nothing catches the inverse: deleting the declaration removes its own enforcement, so a `shared` grant can be dropped and no check has anything left to assert.

This closes that gap, and adds a way to record a hand-off that is genuinely intended.

## What Changed

Enforceable grants in `areas.yaml` are compared against the merge-base, and owners that stop owning tracked files are reported.

A removed declaration is the trigger, not the verdict. Each candidate is confirmed against resolved ownership, so three legitimate shapes pass: a reassignment that moves ownership to a more specific claim, a prune whose files are gone, and a grant that merely restates what an area rule already gives. Resolution runs over the paths under candidate globs alone, never the whole tree.

`ownership_transfers` records a deliberate hand-off. Each entry names the glob, the teams dropped, and why. The gate blocks a removal that is not recorded, and blocks an entry that no longer matches a removal, so the list cannot accumulate into something nobody reads and everyone appends to. It feeds validation only and does not affect emission.

When the merge-base policy cannot be read or no longer resolves under the current schema, the check skips and says so. A gate that quietly stops gating reads as green, and a bug in this one must never block the change that removes it.

## Validation

Backtested against every commit on `main` that touched `areas.yaml`: no findings across 34 commits, with pre-schema revisions skipping rather than misfiring.

On its first run against the real tree it found a live case, `components/src/dynamo/vllm/handlers.py` dropping `rl` co-ownership held since CODEOWNERS became generated. That narrowing is deliberate and pinned by an existing routing test, but nothing in the repository said so. It was recorded as a transfer, landed with #11869, and the stale-entry rule then required pruning the entry, so the list ships empty. The mechanism cleaned up after itself on its first use.

Seven new tests cover a removed shared grant, a removed required owner, a prune whose files are gone, a reassignment, a redundant grant, a missing base policy, a recorded hand-off, and an inert entry. 166 tests pass, the strict gate exits 0, and emission is unchanged.
