## Summary

- accept version-matched preprocessed multimodal feature envelopes at the vLLM sidecar boundary
- forward bounded MessagePack kwargs through the native vLLM gRPC media contract
- derive execution identifiers with vLLM Rust's domain-separated SHA-256 algorithm instead of trusting producer hashes
- validate modality alignment, placeholder ranges, inline kwargs, unknown fields, feature count, decoded bytes, and raw/preprocessed exclusion
- preserve expanded multimodal prompt tokens across prefill/decode handoff
- keep this feature independent from routed-expert request and response behavior

## Required dependency order

- direct Dynamo parent: #13532
- protocol dependency: #13527 plus the composite protocol-only sync in this branch
- runtime receiver dependency: vllm-project/vllm#52722
- exact composite source pin: `biswapanda/vllm@f0250a93161bac650fd7df7fb61017a25edd5888`

The vendored inference protocol is byte-for-byte identical to the composite source and has SHA-256 `55dcc2413caba3bd45f78dbe60c7b2578f3e0860083c26f2173f31e1d4820a93`. The composite contains the independent routed-output and multimodal protocol fields, while the sidecar behavior in this PR is multimodal-only.

This draft must not be deployed with an older multimodal vLLM server: `supports_multimodal` is a model capability, not negotiation for the preprocessed-feature oneof. Exact routing from #11588 is intentionally not a dependency.
