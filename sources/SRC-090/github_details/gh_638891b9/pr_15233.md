# [PR #15233] fix(vllm): name the worker that ends a disaggregated multimodal launch

## 正文

Closes [DYN-4428](https://linear.app/nvidia/issue/DYN-4428).

## Summary

Four disaggregated multimodal vLLM parameterizations fail on every nightly attempt. The deployment log never recorded which worker left first — `wait_any_exit` printed only `A background process exited with code 1`, and the cleanup trap then killed the rest. This PR makes that message name the worker. It does not turn those parameterizations green.

## Details:

`dyn_track_worker <label>` in `examples/common/launch_utils.sh` labels the process just backgrounded. `wait_any_exit` first checks saved worker PIDs for exits during startup and retrieves their status with `wait <pid>`. Otherwise, on Bash 5.1+ it uses `wait -n -p` to learn which child was reaped, and prints `Worker 'prefill' (pid 406179) exited with code 1`. Labelling is opt-in, so unlabelled processes and older bash keep the existing message and the other launch scripts are unaffected. `disagg_multimodal_epd.sh` and `disagg_multimodal_p_d.sh`, the two scripts behind the failing parameterizations, label their workers; `tests/serve/test_launch_utils.py` covers both messages and the labels themselves.

The nightly log points at an `IndexError` inside vLLM 0.29.0 when a worker's engine is built with a NIXL `kv_transfer_config` for Qwen3-VL. Upstream fixed that call site in vllm-project/vllm#43272, which is absent from `v0.29.0` and present in later tags, so the repair is raising the pin in `pyproject.toml` and `container/context.yaml`. That bump is untested here and needs a maintainer's choice of tag, proven on `vllm-runtime / H100 Test cuda13.0, amd64`.

The SGLang metrics-test stub also uses the current reasoning helper name, correcting the import error exposed by full CI.

## Where should the reviewer start?

`examples/common/launch_utils.sh`: `dyn_track_worker`, and the `wait -n -p` branch of `wait_any_exit`.
