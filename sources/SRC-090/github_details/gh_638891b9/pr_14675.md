# [PR #14675] feat(backend): unify graceful shutdown behind one budget and ordered stages

## 正文

## Summary

PR 2 of 3: #14674 → #14675 → #15145. This PR targets `stack/1-runtime-teardown`.

- Give native workers one SIGTERM-origin deadline covering discovery withdrawal, router grace, admission closure, request drain, KV-transfer drain, engine cleanup, and runtime teardown.
- Reserve cleanup time inside the total; cleanup and runtime share that allowance rather than extending the deadline.
- Propagate cleanup failures, record failed/timed-out outcomes, and retain the native watchdog until successful teardown.
- Keep typed draining rejections compatible with supported older readers by using the established worker-unavailable wire identity.
- Expose stage duration/reason, remaining budget, in-flight count, and KV state metrics.
- Require the final operator pod grace period to cover explicit literal worker budgets plus the required margin.
- Remove unused engine-route method scaffolding and correct budget documentation.

## Validation

- All 180 backend-common tests passed again on this PR's isolated, rebased tree.
- Combined-stack runtime compatibility and deadline regressions passed.
- Seven operator shutdown-budget table cases passed in `golang:1.26.6`.
- Rust formatting and targeted docs lint passed (zero errors; five unrelated navigation warnings). Fern CLI was unavailable.
- Real transport/process and GPU validation of the combined stack is described in PR 3.

## Limitations

- Static operator checks cannot resolve image defaults, envFrom, shell expressions, or SDK-only settings.
- Unsupported KV-state fallback is not proof of transfer quiescence.
- Latest review fixes have not been rerun on native-sidecar GPU deployments or Kubernetes deletion.

Relates to #13286.
