# [PR #2069] fix(optim): fall back to non-paged state on all devices without managed memory

source: https://github.com/bitsandbytes-foundation/bitsandbytes/pull/2069
state: open | updated: 2026-09-04T00:10:24Z
labels: Low Priority, Cross Platform, Optimizers

## 正文

## Summary

Paged optimizers (`PagedAdamW`, `PagedAdam`, `PagedLion`, `PagedAdEMAMix`, and their 8-bit variants) only fell back to regular state buffers on `cpu`. On any other device without managed-memory support they reached `F.get_paged`, which calls `lib.cget_managed_ptr`, and failed with a misleading error:

```
RuntimeError: Method 'cget_managed_ptr' not available in CPU-only version of bitsandbytes.
Reinstall with GPU support or use CUDA-enabled hardware.
```

On MPS this affects every `paged_*` optimizer in `test_optim.py::test_optimizer32bit` (45 cases with `BNB_TEST_DEVICE=mps`), and any user who picks e.g. `optim="paged_adamw_32bit"` in a Transformers `TrainingArguments` on Apple Silicon.

This PR generalizes the existing CPU fallback in `Optimizer8bit.get_state_buffer` to any device type whose native library does not provide `cget_managed_ptr`. Managed memory is implemented for CUDA/ROCm (`cudaMallocManaged`) and XPU (`sycl::malloc_shared`), so those keep the paged path; everything else gets a plain tensor plus a one-time warning naming the device.

## Changes

- `bitsandbytes/optim/optimizer.py`: fallback condition is now `device.type not in ("cuda", "xpu")`; warning text names the device; the once-only flag is renamed from `_cpu_paged_warned` to `_paged_fallback_warned`.
- `tests/test_optim.py`: the `paged_*` skip in `test_optimizer32bit` now applies to all non-paging devices instead of only CPU.

## Testing

Apple M5, macOS 26, torch 2.12.1:

- `BNB_TEST_DEVICE=mps pytest tests/test_optim.py -k "paged or test_optimizer32bit"`: 72 passed, 72 skipped (the 45 paged cases previously errored).
- `BNB_TEST_DEVICE=cpu pytest tests/test_optim.py -k "paged or test_optimizer32bit"`: 72 passed, 72 skipped.
- `pre-commit run --all-files`: clean.

Not tested on CUDA/XPU hardware; the paged path there is unchanged apart from the condition being expressed as an allow-list of device types.

Ref #2011 (MPS backend work). The 8-bit optimizer op itself is still unimplemented on MPS; that is a separate item planned for v0.51.0 and is not touched here.
