## 正文

This fixes https://github.com/ROCm/rocprofiler-compute/issues/777 and https://github.com/ROCm/rocprofiler-compute/issues/786 for me.

My guess for the `1704` -> `1705` change is that a new section was added but the following section numbers were not correctly updated in `gui.py`

I hope that the rest of the ids in https://github.com/ROCm/rocprofiler-compute/blob/61a9381edfd781cdbef83aa8837d77531bbb661f/src/rocprof_compute_analyze/analysis_webui.py#L54-L59 are correct, especially the id `1701` for which I was hitting the `HBM Bandwidth` key error https://github.com/ROCm/rocprofiler-compute/issues/786. It seems `HBM Bandwidth` was introduced in https://github.com/ROCm/rocprofiler-compute/pull/632 (not clear why), so I am not sure whether this fix is correct - or whether 1701 should be now 1702 for example.

Also `determine_chart_type` was trying to build a table chart using an empty dataframe which yielded errors.

# Before: Output before the fix and what is wrong here

`ROCPROFCOMPUTE_LOGLEVEL=debug rocprof-compute analyze -p workloads/mykernel/MI355/ --gui` crashing when selecting a kernel, with several crashes fixed in this PR.

# After: Output after this fix and how is it fixed

rocprof-compute GUI works.

# Explanation of fix

* Table id `1704` is wrong in the code and should be `1705`.
* A section for `HBM Bandwidth` is missing in https://github.com/ROCm/rocprofiler-compute/blob/develop/src/rocprof_compute_soc/analysis_configs/gfx950/1700_L2_cache.yaml
* A table is empty and there is no check for empty tables yield later crashes (see https://github.com/ROCm/rocprofiler-compute/pull/787#discussion_r2222294101)

### xuchen-amd · 2025-07-04

> @xuchen-amd Thank you! `HBM Bandwidth -> Bandwidth` change looks correct to you?

@fxmarty-amd, no, I was mistaken.

The df access using key `HBM Bandwidth` was introduced in [f9aa7be97cbcd5d96546b9fcbc634210a7e22906](https://github.com/ROCm/rocprofiler-compute/commit/f9aa7be97cbcd5d96546b9fcbc634210a7e22906) to read `HBM Bandwidth` from df directly, instead of `base_data[base_run].sys_info["hbm_bw"][0]` (removed in the same commit).

`HBM Bandwidth` is calculated with [`"hbmBandwidth": "($max_mclk / 1000 * 32 * $num_hbm_channels)"`](https://github.com/ROCm/rocprofiler-compute/blob/61a9381edfd781cdbef83aa8837d77531bbb661f/src/utils/parser.py#L89). With this, please check if you are seeing the warning message:
"WARNING max_mclk is not available in sysinfo.csv, please provide the correct value using --specs-correction".

With a `max_mclk` value, you should see `HBM Bandwidth` correctly calculated and displayed:
<img width="467" alt="image" src="https://github.com/user-attachments/assets/f5e4cbe0-d6d1-45f9-af5c-604129fb03e1" />

Usage for --specs-correction is at: [argparser.py#L678](https://github.com/ROCm/rocprofiler-compute/blob/61a9381edfd781cdbef83aa8837d77531bbb661f/src/argparser.py#L678)
