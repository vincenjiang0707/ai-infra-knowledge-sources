# [PR #11928] [triton_kernels] Fix gathered activation scale indexing

## 正文

When a ragged matmul gathers activation rows, the values can use a dense
TMA descriptor while their scales are stored in padded, per-slice blocks.
Selecting scale offsets from the values' descriptor mode uses a dense row
count that is undefined for ragged inputs, causing compilation to fail.

Select scale offsets using the matmul's ragged dimension. Require the
scale layout and matmul to share the same `RaggedTensorMetadata` instance
so their row boundaries and padding agree, without synchronizing device
data on each call. Document this contract and the required scale row order
for gathered inputs.

## Validation

- Added four cases to `test_gathered_ragged_act_scale_indexing` in
  `python/triton_kernels/tests/test_matmul.py`: shared metadata, different
  block offsets, different row boundaries with identical block offsets,
  and separately created metadata with equal contents.
- Reproduced the original compilation failure and the missing metadata
  validation before the fixes. All four cases pass with the fixes on
  NVIDIA GB200.
- 56 additional GB200 checks passed, covering gathered inputs, uneven and
  empty slices, strided scales, and dense, batched, and ragged layouts.
