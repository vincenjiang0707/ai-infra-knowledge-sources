## Summary

- recognize SM110 as an MMA v5 target in `test_dot` opcode checks
- keep the tcgen05 INT8 expectation restricted to SM100, matching the compiler capability check
- continue to exclude SM120 from the MMA v5 path

## Motivation

On NVIDIA Thor (`sm_110a`), the numerical checks pass, but 165 `test_dot` cases fail their PTX opcode assertions. The tests classify only SM10x as tcgen05 targets even though Triton selects MMA v5 for supported dot types from SM100 through SM119.

Thor emits `tcgen05.mma` for FP16, TF32, and BF16-based dot operations. INT8 is an exception: tcgen05 INT8 is supported only on SM100, so Thor correctly falls back to `mma.sync`.

## Testing

- representative TF32 and INT8 cases: `2 passed`
