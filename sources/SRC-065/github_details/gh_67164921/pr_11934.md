## 正文

## Summary

Lower pairs of same-thread FP32 multiplies to LLVM vector operations on SM100+ (PTX 8.6+), allowing LLVM to select [`mul.f32x2`](https://docs.nvidia.com/cuda/parallel-thread-execution/index.html#floating-point-instructions-mul). Keeping ordinary LLVM arithmetic preserves constant folding and fused multiply-add selection.

## Desired features

- Automatically pack ordinary FP32 multiplication, without kernel changes or a new API.
- Preserve FP32 arithmetic and fusion controls; retain scalar fallbacks.

## Validation

NVIDIA GB300; rebuilt with `make`.

```sh
python -m pytest -s --tb=short python/test/unit/language/test_core.py -k 'fp32_mul_packed or enable_fp_fusion or force_disable_fp_fusion'
PYTHONPATH=python:python/triton_kernels python -m pytest -s --tb=short python/triton_kernels/tests/test_mxfp.py
```

Unmodified NVIDIA FP4 (NVFP4) quantizer, synthetic 4096×16384 input, identical 32×64 tiles and 8 warps, no tuning. Outputs and scale bytes match the saved baseline. Median kernel time using `do_bench_cudagraph_proton(rep=20, quantiles=[.2,.5,.8])`; L2 cleared before every invocation, eviction excluded.

| Input | Before | After | Latency reduction |
|---|---:|---:|---:|
| BF16 | 64.13 µs | 61.45 µs | 4.2% |
| FP16 | 62.66 µs | 61.42 µs | 2.0% |
| FP32 | 79.18 µs | 79.10 µs | Within noise |
