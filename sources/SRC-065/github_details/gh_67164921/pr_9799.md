# [PR #9799] [Testing] do_bench: add fixed iteration count option for distributed workloads

state: closed | updated: 2026-09-22T21:06:52Z

## 正文

Fixes #9683

## Problem

`do_bench` computes `n_warmup` and `n_repeat` by dividing a target duration (e.g. warmup=25ms) by a per-rank timing estimate. In distributed workloads that use collectives such as `all_reduce` or `all_gather`, this produces different iteration counts across ranks due to small timing differences. The rank with more iterations calls the collective one extra time with no matching call on the other side, causing a hang or crash.

## Solution

Add optional `n_warmup` and `n_repeat` parameters so callers can pin the iteration counts directly. When both are provided, the estimation phase is skipped entirely, guaranteeing that every rank executes `fn` the same number of times.

The new parameters default to `None`, preserving the existing time-based behavior for all current callers.

## Example Usage
```python
triton.testing.do_bench(fn, n_warmup=10, n_repeat=50)
```
