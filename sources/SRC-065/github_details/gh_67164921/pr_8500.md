### zhanglx13 · 2025-10-23 · CHANGES_REQUESTED

I can see this PR is trying to reduce inter-warp data exchange for reduceOp.  I have some questions regarding the design and impl.
1. When the warplayout is [2, 4] we know reduceOp will incur inter-warp data exchange. Then about overhead
  1.1 What is the overhead? like LDS traffic?
  1.2 How much is the overhead? how many ds_xxx instructions will be used? is this a function of the warp layout? and how much latency we will suffer?
2.  Then about strategy. Say the reduction dim is 1, i.e. row reduction. Does it make a difference between warplayout [1, 8], [2, 4], and [4,2]? If there is a difference, how much is the diff?
3. Say we figure a new warp layout for reduceOp and you need to insert a convert_layout before reduceOp. What is the overhead of this inserted convert_layout? Will it be removed later by the removeLayoutConversion pass?
4. Do you have any example kernel that shows improvements by this optimize-warp-layout pass?
5. The impl is anchored on blockedLayout and row reduction. Can we generalized it with linear layout and both reduction dims?
