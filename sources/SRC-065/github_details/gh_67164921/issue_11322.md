### Describe the bug

  `make_ttgir`. The failure is triggered by a dynamic `tl.range` loop containing a
  runtime `if` that selects one of two B-matrix pointer expressions before a masked
  `tl.load`, followed by `tl.dot`.

  while executing `TritonAMDGPUBlockPingpong`:

### Reprocuder
Run this on an AMD machine.
```
import torch
import triton
import triton.language as tl


@triton.jit
def repro_dot_dominance(
    switch_ptr,
    a,
    b,
    c,
    M,
    N,
    K,
    stride_am,
    stride_bn,
    BLOCK_M: tl.constexpr,
    BLOCK_N: tl.constexpr,
    BLOCK_K: tl.constexpr,
):
    values = tl.load(switch_ptr + tl.arange(0, 2))
    zero, one = tl.split(values)
    cond = zero > one
    m_offsets = tl.arange(0, BLOCK_M)
    k_offsets = tl.arange(0, BLOCK_K)
    acc = tl.zeros((BLOCK_M, BLOCK_K), tl.float32)

    for n in tl.range(tl.cdiv(N, BLOCK_N)):
        n_offsets = n * BLOCK_N + tl.arange(0, BLOCK_N)
        a_mask = (m_offsets[:, None] < M) & (n_offsets[None, :] < N)
        a_ptrs = a + m_offsets[:, None] * stride_am + n_offsets[None, :]
        a_block = tl.load(a_ptrs, mask=a_mask, other=0.0)

        b_mask = (n_offsets[:, None] < N) & (k_offsets[None, :] < K)
        if cond:
            b_ptrs = b + n_offsets[:, None] * stride_bn + (one * k_offsets)[None, :]
        else:
            b_ptrs = b + n_offsets[:, None] * stride_bn + k_offsets[None, :]
        b_block = tl.load(b_ptrs, mask=b_mask, other=0.0)

        acc = tl.dot(a_block, b_block, acc, allow_tf32=False)

    c_mask = (m_offsets[:, None] < M) & (k_offsets[None, :] < K)
    c_ptrs = c + m_offsets[:, None] * K + k_offsets[None, :]
    tl.store(c_ptrs, acc, mask=c_mask)


def solve(a, b, c, M: int, N: int, K: int):
    switch = torch.tensor([0, 1], dtype=torch.int32, device=a.device)
    grid = (1, 1)
    repro_dot_dominance[grid](
        switch, a, b, c, M, N, K, N, K, 32, 32, 32, num_stages=2
    )
```

## 评论 (1)

### alexxony · 2026-09-24

Confirmed the crash on 3.7.1:

```
error: operand #0 does not dominate this use
note: operand defined here (op in a parent region)
error: Failures have been detected while processing an MLIR pass pipeline
note: Pipeline failed while executing [`TritonAMDGPUBlockPingpong` on 'builtin.module' operation]
```

The non-dominating operand traces back to `b_mask` (computed once per loop iteration, before the `if cond: ... else: ...` pointer selection) being used inside the if-region.

It does not reproduce on 3.8.0 or current `main` — both compile successfully. This is at least partly explained by #10585 (`isLoopVariant` check in `BlockPingpong.cpp`'s `getDotPingponged()`): both `a_mask` and `b_mask` here depend on the loop induction variable `n`, so the pass should bail before reaching the pingpong rewrite at all on 3.8.0/main.

To sanity-check that `BlockPingpong` itself is still active for this kernel shape (`BLOCK_M=32`, `num_warps=4`, gfx942) on both versions, I removed the masks from both loads (keeping the `if/else` pointer selection) — this compiles with `setprio`/`sched.barrier` present in the TTGIR on **both 3.7.1 and 3.8.0**. So the pass is active and doesn't crash on this reduced case either way; this variant doesn't share a mask value across the if-region the way the original repro does, so it doesn't isolate whether the dominance issue itself is fixed on 3.8.0/main or just gated out by #10585 for masked loads specifically.

I don't have AMD hardware to trace further into `BlockPingpong.cpp`'s rewrite logic to determine which of the two it is.
