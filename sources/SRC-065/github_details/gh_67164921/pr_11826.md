# [PR #11826] [Gluon] Add linear asynchronous bulk loads to shared memory

## 正文

PR description written by Codex

Gluon currently needs inline PTX for linear global-to-shared bulk copies, hiding their memory dependencies from the compiler and sanitizers. Add `hopper.bulk.async_load(smem, pointer, num_bytes, barrier, pred=True, multicast=False)`, also exported from Blackwell and Rubin, with native IR and `cp.async.bulk` lowering.

Production changes support partitioned and replicated CTA clusters, multicast, and shared layouts validated through their canonical LinearLayout. Copies preserve physical byte order and use full per-CTA capacity strides between source tiles, including partial copies. The byte count is a positive compile-time multiple of 16 within a contiguous destination view; addresses must be 16-byte aligned, with a separate completion barrier in each CTA. Requires SM90+/PTX8.6+. ConSan tracks transaction counts and shared-memory completion, GSan tracks exact predicated source ranges, and IISan checks source alignment.

Other changes add documentation and regression coverage for layouts, partial copies, predication, 2/4-CTA partitioning and replication, multicast destinations, arrival routing, phase reuse, warp-specialized handoff, and sanitizer diagnostics. After rebuilding, all 24 affected compiler tests and 147 focused frontend/GPU/sanitizer cases passed on GB300, including code generation for SM90/100/103. The three GSan ordering cases also passed with line information disabled.

ConSan conservatively covers the entire destination view. GSan records source reads at issue time; its pre-existing gap in tracking asynchronous global-memory lifetime through completion remains unchanged.
