# [PR #11978] [NVIDIA] Diagnose tmem_wait lowering on targets without tensor memory

source: https://github.com/triton-lang/triton/pull/11978
state: open | updated: 2026-09-26T15:34:31Z
labels: 

## 正文

Fixes #11747.

Compiling a ConSan-instrumented TMEM kernel for SM 12.x can abort in NVPTX when selecting `llvm.nvvm.tcgen05.wait.st`, killing the pytest-xdist worker.

Reject `ttng.tmem_wait` during LLVM conversion unless `100 <= cc < 120` (SM 10.x/11.x), producing a compilation error before instruction selection. The check uses the configured compute capability; PTX versions, architecture variants, and other TMEM operations remain outside its scope.

## Tests

- New diagnostic test: `tmem_wait_sm120_rejected.mlir` rejects cc=90/120.
- Existing `lower_tensor_memory_to_llvm.mlir` and `tritongpu_to_llvm_blackwell.mlir` cover successful lowering at cc=100/103.

## Reported validation

On RTX 5090 (sm_120), the reproducer changed from SIGABRT (exit 134) to a compilation error (exit 1). The diagnostic test and existing positive lit tests were reported to pass.
