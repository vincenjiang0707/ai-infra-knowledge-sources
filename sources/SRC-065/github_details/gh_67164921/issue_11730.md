# [Issue #11730] 3.8.0 on sm_120: a multi-CTA kernel that reads a peer CTA's shared memory fails at exit with "unspecified launch failure"

source: https://github.com/triton-lang/triton/issues/11730
state: open | updated: 2026-09-12T08:47:02Z
labels: 

## 正文

On an RTX PRO 6000 Blackwell (sm_120, driver 610.57.04) with the 3.8.0 wheel (torch 2.11.0+cu128), `test_scalar_atomic_cas_multicta_result` and the five `test_tensor_atomic_cas_multicta_result` cases fail with `CUDA error: unspecified launch failure`. The error is sticky: in a full `test_core.py` run on this card, 932 of the tests that follow fail with the same message (937 failed, 8071 passed, 349 skipped).

The kernel is the test's own:

```python
@triton.jit
def kernel(lock, output, BLOCK_SIZE: tl.constexpr):
    old = tl.atomic_cas(lock, 0, 1)
    offsets = tl.arange(0, BLOCK_SIZE)
    tl.store(output + offsets, old)

lock = torch.full((1,), 7, device="cuda", dtype=torch.int32)
output = torch.empty((512,), device="cuda", dtype=torch.int32)
kernel[(1,)](lock, output, BLOCK_SIZE=512, num_ctas=4)
```

The scalar atomic is issued by CTA 0 and the other CTAs read its result from CTA 0's shared memory (`mapa.shared::cluster` followed by `ld.shared::cluster` in the PTX). In the 3.8.0 PTX nothing keeps CTA 0 resident until the peers have read: there is no cluster barrier before `ret`. `main` emits one (`barrier.cluster.arrive.aligned; barrier.cluster.wait.aligned;` before `ret`, from #10656, which made the exit barrier in `ClusterBarrierInsertion` unconditional). The release still has the conditional form, and `hasUnresolvedCrossClusterDependency` cannot see a read that the lowering itself introduces.

Confirmed at the PTX level on the same card: with `TRITON_KERNEL_OVERRIDE=1`, the wheel's own PTX plus those two instructions before `ret` launches fine and `output` is all 7; the unmodified PTX fails every time. A plain kernel launched with `num_ctas=4` and no cross-CTA shared read runs fine here, so clusters themselves work on this card.

I have the cherry-pick of the `ClusterBarrierInsertion.cpp` part of #10656 onto `release/3.8.x` building now and will open it as a PR; would you take it for a 3.8.1?
