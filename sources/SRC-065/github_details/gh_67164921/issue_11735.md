# [Issue #11735] 3.8.0 lacks eleven fixes that main's own tests catch on the wheel (wrong results, a device fault, crashes); cherry-picks built and verified

## 正文

This is a follow-up to #11730 and #11733, with the method turned around: instead of running the release's tests on the wheel, I ran main's `python/test/unit/language` tests (main at 42c5e89c3) against the 3.8.0 wheel on an RTX PRO 6000 (sm_120), one process per failing test, and kept the failures whose test was added by a fix and whose symptom a user of the wheel can hit through the public API. `release/3.8.x` is one commit above its merge base with main (3bb23dde7, 23 Jun), so every fix below is simply absent from 3.8.0. All of these reproduce on the pure wheel; the ones marked with a cherry-pick apply to `release/3.8.x` without conflicts; I built the branch with all of them (on top of #11731 and #11734) on the same board and main's tests for each pass there.

Wrong results:

- `tl.dot_scaled` with an E8M0 scale byte of 0 or a scale that is subnormal in bf16: every element wrong (`test_scaled_dot_minimum_scale`, `test_scaled_dot_zero_scale`, 16384 of 16384 elements). Fixed by #11624 (10 Sep); the core part (`DecomposeScaledBlocked`, the interpreter, `tools/mxfp.py`, plus the AMD caller of the changed helper) applies with a 3-way merge and passes the whole `test_scaled_dot` family (1728 cases) on the board; the AMD upcast, fpsan and triton_kernels parts are separate.
- `OptimizeThreadLocality` reorders a reduction incorrectly: `test_optimize_thread_locality_preserves_rows`, 256 of 256 elements wrong. Fixed by #11186 (5 Aug), clean cherry-pick.
- `tl.range(..., flatten=True)` with an inner loop that can be empty: the flattened loop drops iterations (`test_tl_range_fuse_empty_inner_bounds`, 352 instead of 337). Fixed by #11607 and its reland #11688 (10 Sep); #11607 is clean, #11688 conflicts only in the lit file.
- `tl.softmax` normalizes along the wrong axis for `dim != -1` (`test_softmax`, 4 of 4 elements). Fixed by #11409 (24 Aug), clean.
- A list comprehension with an `if` filter in a `constexpr` context ignores the filter: `[x for x in (10, 20, 30, 40) if x >= 30]` has four elements on the wheel, two on main (`test_list_comprehension_if_filter`). Fixed by #10888 (15 Jul), clean.
- `tl.full(shape, -0.0, tl.float32)` produces +0.0 on the wheel (sign bit clear), -0.0 on main (`test_scalar_constant_preserves_signed_zero`). Fixed by #11426 (24 Aug), clean.

Crashes and device faults:

- A pipelined TMA load whose stage size is not 16-byte aligned faults on the device: `test_tma_load_unaligned_stage_size` ends in `CUDA error: misaligned address`, and the error is sticky for the process. Fixed by #10898 (17 Jul), clean cherry-pick (7 files).
- `tl.gather` with a [4096, 4] index tensor over a [4, 4] source: `PassManager::run failed` (`test_gather[src_shape2-indices_shape2-0]`). This is the class of #11600; fixed by #10838 (13 Jul), clean.
- `tl.dot_scaled` with an unscaled bf16 lhs and an MN-packed fp4 rhs: `PassManager::run failed` (`test_dot_scaled_unscaled_lhs_fp4_rhs`). Fixed by #11613 (6 Sep), clean.
- A `while` loop whose condition is an integer rather than a bool: `error encountered during parsing` (`test_while_integer_condition`). Fixed by #11234 (19 Aug), clean.
- `tl.histogram` on a non-32-bit input fails inside the pass manager instead of with a frontend error (`test_err_histogram_non_32bit_int`). #10891 (9 Aug), clean.

Not included, for the record: the rest of the 443 failures are new APIs (`atomic_poll`, `atomic_load/store`, CLC, keyword-only arguments, `topk` checks, tuple targets in comprehensions), the BC-breaking promotion changes (#11472, #11473, #10883), and test-side changes.

I can open the cherry-pick PRs the same way as #11731 and #11734 if a 3.8.1 is on the table; the device fault and the dot_scaled results would be my first two.
