# [PR #11896] [AMD] Do not insert barriers between mbarrier-synchronized TDM copies

source: https://github.com/triton-lang/triton/pull/11896
state: open | updated: 2026-09-23T08:59:50Z
labels: 

## 正文

An async copy that carries an mbarrier operand sends an LDS atomic arrive when it completes, so it takes part in mbarrier synchronization exactly like AsyncCopyMbarrierArriveOp, which membarFilter already recognizes. The mbarrier orders those accesses across the whole workgroup, so a ttg.barrier between two such ops synchronizes nothing.

Copies without a barrier operand are deliberately not covered here. Those are ordered by their async wait instead, and an async wait counter is per wave, so it cannot order accesses between waves.

Without this, a TDM collective expressed with mbarrier completion emits more barriers than the async_tdm_wait formulation it replaces, which makes mbarrier unusable as an alternative.
