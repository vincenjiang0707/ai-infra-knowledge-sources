## 正文

I'm a contributor to FlagGems (GPU kernel library built on Triton) and have been systematically closing the libdevice parity gap between CUDA and HIP. This is Part 2, following #10377.

## What does this PR do?

Adds 9 bit manipulation and integer functions to the HIP backend. Unlike Part 1 which only required Python changes (OCML mappings), these functions needed changes in two files — a Python binding and a new LLVM lowering for each.

**Files modified:**
- `third_party/amd/language/hip/libdevice.py` — Python bindings
- `third_party/amd/lib/TritonAMDGPUToLLVM/BuiltinFuncToLLVM.cpp` — LLVM lowerings

## Functions Added

| Function | LLVM Implementation | Types |
|---|---|---|
| `clz` | `CountLeadingZerosOp` | i32, i64 |
| `popc` | `CtPopOp` | i32, i64 |
| `ffs` | `CountTrailingZerosOp` + zero select | i32 |
| `brev` | `BitReverseOp` | i32, i64 |
| `mul24` | 24-bit masked multiply via `MulOp` | i32, u32 |
| `mulhi` | Upper 32 bits of 64-bit product | i32, u32 |
| `hadd` | `(a+b)>>1` overflow-safe via i64 extend | i32, u32 |
| `rhadd` | `(a+b+1)>>1` overflow-safe via i64 extend | i32, u32 |
| `sad` | `\|a-b\|+c` sum of absolute difference | i32, u32 |
