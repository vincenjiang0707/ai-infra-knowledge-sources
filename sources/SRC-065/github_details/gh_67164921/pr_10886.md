# [PR #10886] [AMD] Emit actionable errors when a direct-to-LDS copy cannot be lowered

source: https://github.com/triton-lang/triton/pull/10886
state: open | updated: 2026-09-25T12:45:49Z
labels: 

## 正文

## Problem

On CDNA, `ttg.async_copy_global_to_local` and `amdg.buffer_load_to_local` lower
to a direct-to-LDS copy only when `canLoadDirectToLDS` succeeds. When it doesn't,
the failure was surfaced in two unhelpful ways:

- `amdg.buffer_load_to_local` is not marked illegal in the AMD ConvertToLLVM
  target, so a failed lowering silently survived the pass and surfaced
  much later, during LLVM-IR translation, as a bare
  `error: LLVM Translation failed for operation: builtin.unrealized_conversion_cast`
  with no hint at the real cause.
- `ttg.async_copy_global_to_local` failed at legalization but only with the
  generic `failed to legalize operation ... marked illegal`, again with no
  explanation.

In both cases the underlying reason is almost always one of two things, neither
of which the diagnostics named:

1. the source pointer/offsets can't be proven aligned to a supported vector
   width, or
2. a predication mask isn't aligned to the vector boundary. Since a direct-to-LDS
   copy transfers each lane's whole vector in one transaction, every
   vector-width group of mask values must be identical.

This is painful to debug, especially the buffer path, where the error appears
far from where the decision was made.

## What changes

Failures are now reported at legalization where the decision happens, with
a message that states the achievable vector width and distinguishes the two
causes, as well as concrete guidance (raise provable alignment with `tl.multiple_of`,
align the mask to the vector width, or peel the ragged remainder into a separate
load). `amdg.buffer_load_to_local` is made illegal in the AMD ConvertToLLVM
target so an unlowerable one fails here instead of continuing IR translation.
The mask vector-alignment requirement is also documented in the Gluon
`buffer_load_to_shared` / `global_load_to_shared` docstrings.

### Notes

Marking `amdg.buffer_load_to_local` illegal means an unlowerable one is now a
hard error at legalization rather than passing through conversion. Three
existing test cases in `buffer_load_to_local_to_llvm.mlir` previously asserted
that behavior (the op surviving on gfx942, where 128-bit direct-to-LDS is
unsupported). They now assert the early, actionable error instead.

## Tests

- Updated `async_ops_to_llvm_errors.mlir`, `async_ops_to_llvm_invalid.mlir`,
  `invalid_async_ops_to_lllvm.mlir`, and `buffer_load_to_local_to_llvm.mlir`.
- Added `direct_to_lds_mask_errors.mlir` covering the mask-alignment cause for
  both ops.
- `test/Conversion/amd` and `test/TritonGPU/amd` pass.
