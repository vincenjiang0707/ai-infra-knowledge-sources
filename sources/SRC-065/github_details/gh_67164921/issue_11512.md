## 正文

## Summary

When several processes JIT-compile the same kernels concurrently into one shared
`TRITON_CACHE_DIR` on a network/distributed filesystem, individual compilations
crash with one of two signatures:

1. `OSError: [Errno 16] Device or resource busy` raised from
   `FileCacheManager.put` -> `os.removedirs(temp_dir)` — the staged file has already
   been renamed to its final name when this cleanup step runs, so the exception aborts
   a `put` whose real work had completed;
2. `FileNotFoundError` in `CompiledKernel.__init__` reading back files the process
   itself just published.

Both reproduce with the stock 3.4.0 wheel and the script below. Both code paths are
unchanged on current `main`
([cache.py L103-L127](https://github.com/triton-lang/triton/blob/5f2ca3a88c52b80b601e3e243fb3d6079de0f61f/python/triton/runtime/cache.py#L103-L127),
[compiler.py L407-L432](https://github.com/triton-lang/triton/blob/5f2ca3a88c52b80b601e3e243fb3d6079de0f61f/python/triton/compiler/compiler.py#L407-L432)).
We first hit both in real 8-rank torchrun jobs (four EBUSY occurrences across three
distinct `put` call sites — IR-stage put, metadata put, `put_group` — plus several
FileNotFoundError ones); there a single crashed rank left the remaining ranks blocked
in collectives, so the whole job hung.

## Environment

- Triton 3.4.0 (pip wheel), Python 3.12.3, Linux 5.15 (Ubuntu), x86_64, single node
- Shared `TRITON_CACHE_DIR` on a Kubernetes PVC backed by a vendor distributed NVMe
  filesystem (`findmnt` fstype `storage`, mounted `rw,noatime`); proprietary — we do
  not have visibility into its client/server internals or documented POSIX guarantees
- Control run on local overlayfs on the same machine: zero failures
- The reproducer does not touch a GPU (explicit `GPUTarget("cuda", 90, 32)`, ptxas
  from the wheel); the original crashes were in GPU jobs on the same mount

## Signature 1: EBUSY in `put` cleanup

```
  File ".../triton/compiler/compiler.py", line 383, in compile
    metadata_group[metadata_filename] = fn_cache_manager.put(json.dumps(metadata, default=vars), metadata_filename,
  File ".../triton/runtime/cache.py", line 119, in put
    os.removedirs(temp_dir)
  File "<frozen os>", line 243, in removedirs
OSError: [Errno 16] Device or resource busy: '/path/to/cache/7CDGTACI.../tmp.pid_2958216_a306aa55-5495-45ce-8a85-cf7f77b01ead'
```

In the reproducer this fires both at the metadata `put` (as above) and at `put_group`; in our real jobs also at IR-stage `put`s.

`put()` writes to a per-writer temp dir (unique: pid + uuid4), atomically
`os.replace`s the file to its final name, then removes the temp dir. `os.removedirs`
only propagates an error from the leaf `rmdir` (parent-pruning errors are swallowed),
so the filesystem is refusing to remove the writer's own just-emptied temp dir. We
have not traced the fs internals; empirically it happens only while sibling processes
are hammering the same key dir with their own staged writes and renames. Whatever the
fs-side reason, the failing operation is pure cleanup of a private directory whose
only file was already renamed out — aborting the compilation at that point turns an
ignorable condition into a crash.

Two incidental observations on this line: `os.removedirs` also tries to prune the
*shared* key directory and its ancestors after removing the temp dir (normally stopped
by `ENOTEMPTY`, but clearly unintended), and #4295 — which introduced the temp-dir
scheme — did not discuss the cleanup step's failure modes.

## Signature 2: FileNotFoundError reading back just-published files

```
  File ".../triton/compiler/compiler.py", line 403, in compile
    return CompiledKernel(src, metadata_group, hash)
  File ".../triton/compiler/compiler.py", line 448, in __init__
    metadata = json.loads(metadata_path.read_text())
  File "/usr/lib/python3.12/pathlib.py", line 1030, in read_text
    return f.read()
FileNotFoundError: [Errno 2] No such file or directory
```

(an earlier run of the same reproducer, and our real jobs, also hit the same
failure in the `read_bytes` loop over the other group files a few lines down)

Note where it fails: `open()` succeeded — the ENOENT comes out of the `read()` of an
already-open file. `metadata_group` holds final paths this process itself just
published. Nothing in the workload deletes published files; the only concurrent
mutation of those names is other writers `os.replace`-ing their own copies of the
same content over them. On a fully POSIX filesystem an open file survives its name
being replaced; the failures are consistent with the open handle being invalidated
by a concurrent same-name replace (we did not capture a syscall trace tying an
individual failing read to an individual competing rename). #4295 fixed
an earlier FileNotFoundError in this loop (glob picking up other writers' temp
files); this is a distinct remaining window in which the reader loses to a same-name
replace rather than to temp-file listing.

## Reproducer

<details><summary>repro_cache_race.py</summary>

```python
#!/usr/bin/env python3
"""Reproducer for Triton JIT cache crashes under multi-process compilation
with a shared TRITON_CACHE_DIR on a network filesystem.

Per round: N fresh processes compile the same 8 kernel variants (same cache
keys) into one fresh shared cache dir, barrier-aligned per variant. No GPU is
used: compilation targets are given explicitly and ptxas comes from the wheel.

Expected failure signatures (both fail the compilation; the harness catches
and records them — in real jobs they crash the process):
  (a) OSError [Errno 16] Device or resource busy
      from FileCacheManager.put -> os.removedirs(temp_dir)
  (b) FileNotFoundError
      from CompiledKernel.__init__ reading back just-published group files

Rounds where a failure occurred are preserved on disk for inspection; clean
rounds are deleted. Each round validates that all N workers reported back and
exited 0, so the failure counts have a trustworthy denominator.

Usage: python repro_cache_race.py <cache_base_dir> [rounds] [nproc]
"""
import json
import multiprocessing as mp
import os
import shutil
import sys
import traceback

ROUNDS = int(sys.argv[2]) if len(sys.argv) > 2 else 50
NPROC = int(sys.argv[3]) if len(sys.argv) > 3 else 16
BLOCKS = [16, 32, 64, 128, 256, 512, 1024, 2048]  # 8 cache keys per round


def worker(cache_dir, barrier, q, widx):
    os.environ["TRITON_CACHE_DIR"] = cache_dir
    failures = []
    done = 0
    try:
        import triton
        import triton.language as tl
        from triton.compiler import ASTSource, compile as tri_compile
        from triton.backends.compiler import GPUTarget

        @triton.jit
        def add_one(x_ptr, y_ptr, n, BLOCK: tl.constexpr):
            pid = tl.program_id(0)
            offs = pid * BLOCK + tl.arange(0, BLOCK)
            m = offs < n
            tl.store(y_ptr + offs, tl.load(x_ptr + offs, mask=m) + 1, mask=m)

        for blk in BLOCKS:
            barrier.wait(timeout=600)  # align all processes on each compilation
            try:
                src = ASTSource(
                    fn=add_one,
                    signature={"x_ptr": "*fp32", "y_ptr": "*fp32", "n": "i32", "BLOCK": "constexpr"},
                    constexprs={"BLOCK": blk},
                )
                tri_compile(src, target=GPUTarget("cuda", 90, 32))
                done += 1
            except Exception:
                failures.append(traceback.format_exc())
    except Exception:  # import error / broken barrier: report, don't hang the round
        failures.append(traceback.format_exc())
    q.put((widx, done, failures))


def main():
    base = sys.argv[1]
    os.makedirs(base, exist_ok=True)
    ctx = mp.get_context("spawn")
    hits = []
    anomalies = []
    for rnd in range(ROUNDS):
        cache_dir = os.path.join(base, f"round_{rnd}")
        shutil.rmtree(cache_dir, ignore_errors=True)
        os.makedirs(cache_dir)
        barrier = ctx.Barrier(NPROC)
        q = ctx.Queue()
        procs = [ctx.Process(target=worker, args=(cache_dir, barrier, q, i)) for i in range(NPROC)]
        for p in procs:
            p.start()
        results = []
        for _ in procs:
            try:
                results.append(q.get(timeout=900))
            except Exception:
                break
        for p in procs:
            p.join(timeout=60)
            if p.is_alive():
                p.terminate()
        # denominator validation
        n_ok = sum(done for _, done, _ in results)
        nfail = sum(len(f) for _, _, f in results)
        if len(results) != NPROC or any(p.exitcode != 0 for p in procs) \
                or n_ok + nfail != NPROC * len(BLOCKS):
            anomalies.append(rnd)
            print(f"round {rnd}: ANOMALY reports={len(results)}/{NPROC} "
                  f"exitcodes={[p.exitcode for p in procs]} ok={n_ok} fail={nfail}", flush=True)
        for widx, _, failures in results:
            for tb in failures:
                sig = "EBUSY" if "Errno 16" in tb else ("FNF" if "FileNotFoundError" in tb else "OTHER")
                hits.append({"round": rnd, "worker": widx, "sig": sig, "tb": tb})
                print(f"=== round {rnd} worker {widx} [{sig}] ===\n{tb}", flush=True)
        print(f"round {rnd}: {nfail} failed / {n_ok} ok compilations, "
              f"{len(results)}/{NPROC} workers reported (total hits: {len(hits)})", flush=True)
        if nfail == 0 and rnd not in anomalies:
            shutil.rmtree(cache_dir, ignore_errors=True)  # keep failing rounds for forensics
        with open(os.path.join(base, "hits.json"), "w") as f:
            json.dump({"hits": hits, "anomalous_rounds": anomalies}, f, indent=1)
    ebusy = sum(1 for h in hits if h["sig"] == "EBUSY")
    fnf = sum(1 for h in hits if h["sig"] == "FNF")
    print(f"\nDONE: {len(hits)} failing compilations in {ROUNDS} rounds x {NPROC} procs "
          f"x {len(BLOCKS)} compiles (EBUSY={ebusy}, FileNotFoundError={fnf}, "
          f"anomalous rounds: {anomalies})")


if __name__ == "__main__":
    main()
```

python repro_cache_race.py /path/on/network/fs/cache_race 60 16

Each round spawns 16 fresh processes that barrier-align 8 compilations of the same
kernel into a fresh shared cache dir, and validates that all 16 workers report back
with exit code 0 so the totals below have a sound denominator. Failing rounds'
cache dirs are preserved.

Results on our system:

- network fs: 27 crashed compilations out of 7680 (60 rounds x 16 procs x 8 compiles): 21 FileNotFoundError, 6 EBUSY. 21 of 60 rounds had at least one crash; every round reported 16/16 workers and a consistent ok+fail total
- local overlayfs control (same machine, same script): 0 crashed compilations out of 5120 (40 rounds x 16 procs x 8 compiles)

## Workarounds

Pre-warming the cache with a single process before the job, or giving each rank its
own `TRITON_CACHE_DIR`, avoids the concurrent same-key writes; we have not seen
either signature since adopting them.

## Suggested fix

For signature 1 the cleanup should not be able to kill a compilation:
`os.rmdir(temp_dir)` (the parent pruning of `os.removedirs` looks unintended anyway)
wrapped best-effort, e.g. ignoring/logging `EBUSY`-class `OSError`s — the staged file
is already published when it runs. Happy to send a PR.

Signature 2 is less local — the read-back in `CompiledKernel.__init__` would need to
tolerate or retry a lost race against a same-name replace (close and reopen the
path — the observed error comes from `read()` on the already-open handle), or the compile path could
avoid re-reading files it just wrote. We can help test a chosen direction.
