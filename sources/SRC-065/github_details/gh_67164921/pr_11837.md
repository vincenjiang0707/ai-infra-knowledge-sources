# [PR #11837] [TensorDescriptor] Allow backends to specialize descriptor arguments

source: https://github.com/triton-lang/triton/pull/11837
state: open | updated: 2026-09-25T07:16:28Z
labels: 

## 正文

`specialize_tensordesc` returns no specialization key for any backend, so a descriptor is the only kernel argument a backend cannot key on, despite carrying a base pointer plus per-dimension shapes and strides.

Mirror what tensors already have (`supports_native_tensor_specialization` and `get_tensor_specialization`) with `supports_native_tensordesc_specialization` and `get_tensordesc_specialization`, same opt-out semantics.

Both in-tree backends inherit the flag as set, so the key stays `None` and the hook is never called. 
It is meant for backends that do need to key on descriptor properties, including ones shipped out of tree as an extension.

> can you maintain this patch downstream?

Yes, Intel downstream fork can carry it.

It mirrors the tensor hook AMD already uses (`get_tensor_specialization`), so it's the same seam with one argument kind left out.

The reason to have it upstream is **the out-of-tree extension case**: a backend shipped as its own package against a released Triton has nothing to patch, and ends up replacing `specialize_impl` - a Python call on every argument of every launch, including kernels with no descriptors, which is launch overhead #7771 went out of its way to remove.
