# [PR #11844] [NVIDIA] Fix unhandled OSError crash in NvidiaTool.from_path triggered on macOS

source: https://github.com/triton-lang/triton/pull/11844
state: open | updated: 2026-09-24T06:45:07Z
labels: 

## 正文

## Summary

Fix `NvidiaTool.from_path` to handle `OSError` (e.g., `Exec format error`) 
when the bundled NVIDIA binaries are not executable on the current platform.

This fixes a `make test-nogpu` regression on macOS introduced by #11806.

## Problem

On macOS, Triton's build system downloads Linux ARM64 (sbsa) NVIDIA binaries 
(ptxas, cuobjdump, etc.) because NVIDIA does not provide macOS-native CUDA 
toolchain. These Linux ELF binaries exist on disk but cannot be executed on 
macOS, raising `OSError: [Errno 8] Exec format error`.

`NvidiaTool.from_path` only caught `FileNotFoundError` (file missing) and 
`CalledProcessError` (non-zero exit), but not the more general `OSError` that 
covers format errors. Since `FileNotFoundError` is a subclass of `OSError`, 
replacing it with `OSError` is backward-compatible and also covers other 
potential OS-level errors like `PermissionError` on any platform.

This caused `test_gluon_ast_source_without_driver[target0-cubin]` to crash 
instead of being gracefully skipped.

## Changes

1. **`python/triton/knobs.py`**: Change `except (CalledProcessError, FileNotFoundError)` 
   to `except (CalledProcessError, OSError)` in `NvidiaTool.from_path`, so it 
   correctly returns `None` when the binary exists but is not executable.

2. **`python/test/gluon/test_frontend.py`**: Skip the CUDA parameterization of 
   `test_gluon_ast_source_without_driver` when `ptxas` is not available, using 
   the now-correct `RuntimeError` from `get_ptxas()`.

## Testing

Verified on macOS (Apple Silicon)
