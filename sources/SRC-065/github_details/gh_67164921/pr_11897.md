# [PR #11897] [BACKEND] Support fp8 <=> fp64 casts by going through fp32

## 正文

## Background
`x.to(tl.float8e4nv)` on an fp64 tensor (and `fp8.to(tl.float64)`) cannot compile on any target: the frontend emits `tt.fp_to_fp` between fp8 and f64, but neither backend lowers it.
- NVIDIA: `getConversionFunc` has no f64 entries and calls `report_fatal_error("Unsupported rounding mode for conversion.")`, which aborts the Python process.
- AMD: `failed to legalize operation 'tt.fp_to_fp'`.

Inductor emits exactly this for `x_fp64.to(torch.float8_e4m3fn)`.

```python
@triton.jit
def kernel(X, Z):
    offs = tl.arange(0, 128)
    tl.store(Z + offs, tl.load(X + offs).to(tl.float8e4nv))   # X: *fp64
```

## Summary
- NVIDIA and AMD `FpToFp` lowerings: an f64 source is truncated to f32 before the f32 -> fp8 conversion, and an fp8 -> f64 cast converts to f32 and extends. Only RTNE is supported for f64 -> fp8, as before for other rounding modes.
- Interpreter: `_convert_float`'s downcast rounded ties away from zero, dropped the carry when rounding overflowed the mantissa (126.24 -> fp8e4nv gave 64 instead of 128) and rounded subnormal results twice. It now rounds the mantissa once to nearest even, carries into the exponent, and keeps NaN as NaN. Two shifts also needed unsigned shift amounts for 64-bit types, so fp8 <=> fp64 works in the interpreter too.

## Tests
- Lit: `tritongpu_to_llvm_hopper.mlir` and `amd/fp_to_fp.mlir` check the f32 step in both directions (fail before, pass after).
- `test_core.py::test_cast`: fp8 <=> float64 added to the fp8 cast matrix.
- `test_core.py::test_cast_fp64_to_fp8_rounding`: a few doubles covering ties, rounding into the next binade and subnormals, compared bitwise with `torch.Tensor.to`; also runs in the interpreter.
- Interpreter downcasts checked exhaustively over all fp16/bf16 inputs and ~1.3M fp32 values against an exact reference for every fp8/fp16/bf16 target (RTNE and RTZ).
- H200 (sm90): the raw kernel and `torch.compile` (fp64 -> fp8e4nv, fp8 -> fp64) compile and match eager bit-for-bit; `test_core.py -k "test_cast or test_convert_float16_to_float32"` 170 passed, `test_conversions.py` 57 passed. A800 (sm80): fp64 <=> fp8e5 cases pass. The CI interpreter suite passes on Linux.
