# [PR #11901] [NVIDIA] Canonicalize constant fdiv through an approximate reciprocal

state: closed | updated: 2026-09-22T23:13:36Z

## 正文

Canonicalize FP32 `arith.divf(a, b)` with constant denominator magnitudes in `[2^-126, 2^126]` to `a * tt.approx_divf(1.0, b)` on NVIDIA. Scalar and splat denominators use one scalar reciprocal; dense constants are checked elementwise. Use `TargetInfoBase` to restrict the rewrite to CUDA and register it in both the standard and Gluon canonicalizers.

The randomized regression compares raw result bits against `div.full.f32` with the same constant denominator. This checks preservation of the original constant-division behavior; PTXAS can use different reciprocal approximations when the denominator is a runtime value.

## Stack

Depends on #11900. This PR targets `codex/approx-fdiv-op` so its diff contains only the constant-division rewrite and its regression coverage.

## Validation

Validated on a Brix GB300 devbox after a native rebuild and source-hash verification:

- All repository pre-commit checks passed.
- 9 focused lit files passed, covering standard and Gluon canonicalization, AMD exclusions, NVIDIA and AMD lowering, and FPSan.
- 22 division GPU cases passed.
- The randomized regression passed all 2,359,296 raw-bit comparisons: 65,536 numerator encodings across 36 signed in-range constant denominators, including both range endpoints.

AMD was validated through IR tests; no AMD GPU runtime was used.
