## Summary

Running `test_nested2_change` before `test_nochange` can fail because `apply_src_change` restores a dependency's source while leaving its callers' hashes cached for the modified source. This reproduces the exact hash mismatch in [the GB200 CI failure](https://github.com/triton-lang/triton/actions/runs/36076855353/job/107889912179).

Restore the original source and invalidate all affected hashes when leaving the helper, including on exceptions. Include the requested target in invalidation, and strengthen the existing mutation tests to check that the original cache key is restored.
