## Summary

- expose the CUDA fabric-handle capability through the GSan allocator extension
- skip fabric export/import tests when the device reports no fabric-handle support
- preserve the existing runtime skip for supported devices without access to an IMEX channel

## Motivation

NVIDIA Thor supports CUDA virtual memory management but reports `CU_DEVICE_ATTRIBUTE_HANDLE_TYPE_FABRIC_SUPPORTED = 0`. Requesting `CU_MEM_HANDLE_TYPE_FABRIC` on this device causes `cuMemCreate` to return `CUDA_ERROR_INVALID_VALUE`.
