## 正文

FA kernels can spend time rescaling register accumulators when their runtime scale is exactly one. A block-wide branch cannot skip work independently for warps owning different rows, and elementwise selection does not express the execution boundary needed to avoid that arithmetic. This adds `gl.warp_if` to request warp-level skipping while preserving the result of unconditional block-level evaluation.

```python
@gluon.jit
def rescale(acc, total, alpha):
    return acc * alpha[:, None], total * alpha

acc, total = gl.warp_if(alpha != 1, (acc, total), rescale, args=(alpha,))
```

A warp executes the complete body when any of its conditions is true; otherwise it retains its inputs. The compiler verifies that false-condition elements are identities. Thus layout changes can change the amount of skipped work, but cannot change the logical result. Conditions can describe rows, columns, or individual elements. No warp-varying source scalar or elementwise select is introduced.

The initial verifier accepts f32/f64 rescaling by the scale tested with `scale != 1`, identity returns, register-only broadcasts/expansions, and their supported canonicalized forms. It rejects effects, memory access, collectives, nested control flow, uninlined calls, incompatible layouts, and identities it cannot prove. All-true constant masks have no identity obligation but retain the body/layout restrictions. AMD flush-to-zero mode is rejected.

AMD and NVIDIA share a ballot/branch/phi lowering. The region remains visible through layout inference and GPU scheduling. LLVM may if-convert small bodies; final instruction selection is not an API guarantee. GSan and ConSan compilation are covered. FPSan validates the original body and evaluates it unconditionally before replacing arithmetic with hashes. Proton scopes can surround the operation; scopes inside its body are rejected.

## Performance evidence

The measurements below predate the latest rebase onto upstream `2cfa16702`.
Post-rebase regression checks and an FA correctness smoke test pass; performance
has not been remeasured on the new base.

On one gfx950 GPU, tutorial FA v4, BF16, B=32, H=8, N=8192, D=128, BM=256, BN=64, eight warps:

| Compiler | Unconditional MFMA efficiency | warp_if MFMA efficiency | Gain |
|---|---:|---:|---:|
| Stock LLVM | 62.10% | 69.91% | +7.81 pp |
| Tutorial scheduler | 71.59% | 84.62% | +13.03 pp |

These are medians of three interleaved ATT captures per variant. The tutorial metric is `4096 / measured main-loop cycles * 100`, accounting for two resident waves per SIMD, over 62 paired iterations. These measurements establish the use case, not a universal performance benefit.

The tuned measurements use the tutorial scheduler and its supporting hook, which are not included in this PR. The clean upstream branch also passes the full-size FA comparison against unconditional rescaling and an independent FP32 reference, with identical register/shared-memory use and no spills. A final clean-branch run measured 10.277 ms with `warp_if` versus 10.991 ms unconditionally, a 6.95% throughput gain (median of seven rounds of 40 prepared launches).
