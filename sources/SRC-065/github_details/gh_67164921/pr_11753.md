## 正文

Fix two NVIDIA paths that round FP8 conversions incorrectly: software E5M2 conversion before Ada, and FP32 conversion on Ada.

```python
# x.to(tl.float8e5, fp_downcast_rounding="rtne")
# FP16/BF16 input on the software path:
# x = 1.125:       main -> 1.25; this PR -> 1.0 (ties to even)

# x.to(tl.float8e4nv, fp_downcast_rounding="rtne")
# FP32 input on Ada:
# x = 1.0625001:   main -> 1.0;  this PR -> 1.125
```

The software path shares one nearest-even FP16 encoder. FP32 first uses round-to-odd, which keeps a bit recording discarded precision so the final round can distinguish an exact tie from either neighbor. BF16 can use the same encoder without changing the E5M2 rounding decision. Finite overflow saturates. Rounding and clamping before extracting the FP8 byte lets the compiler emit fewer shifts.

Ada converts directly from FP32: the old FP16 intermediate lost the bits that distinguish the second example from an exact tie. Tests cover ties and neighbors, subnormals, signed zero, overflow and NaNs.

The fix also enables existing E5M2 conversion, MXFP, reduction-gradient and matmul tests on A100. Remove their obsolete skips while keeping the actual E4M3 hardware requirements.

Independent fix, based on [main](https://github.com/triton-lang/triton/tree/main).
