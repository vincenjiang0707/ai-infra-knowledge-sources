# [PR #11938] [BACKEND] Lower float % to libdevice fmod on NVIDIA

source: https://github.com/triton-lang/triton/pull/11938
state: open | updated: 2026-09-24T17:10:15Z
labels: 

## 正文

On NVIDIA, `%` on floating-point tensors is lowered to `llvm.frem`, and NVPTX expands that to `x - trunc(x / y) * y`. Once `x / y` cannot be represented exactly the result is wrong, even though `%` follows C `fmod` semantics: e.g. `1e10 % 3` returns 256 instead of 1 in fp32, `3e7 % 0.7` returns -0.289 instead of 0.411, and fp64 is affected the same way. `torch.fmod` on the same device gives the correct results.

This lowers `arith.remf` on NVIDIA to libdevice's `__nv_fmodf`/`__nv_fmod` (fp16/bf16 go through fp32), and adds `test_fmod_large_quotient`, which fails on main for fp32 and fp64.
