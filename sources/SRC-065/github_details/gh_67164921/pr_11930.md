## Summary

Support unswizzled padded FP4 Tensor Memory Accelerator (TMA) loads and reject unsupported 32- and 64-byte swizzles during descriptor selection.

Unswizzled loads preserve the eight padding bytes after each eight packed data bytes and use 64-byte packed transfer boxes, including when a larger tile requires multiple copies.

[NVIDIA's PTX specification](https://docs.nvidia.com/cuda/archive/13.0.0/parallel-thread-execution/index.html), section 9.7.9.25.5.1, permits no swizzle or 128-byte swizzling for `.b4x16_p64`, subject to its other restrictions.

## Desired features

- Support no swizzle and 128-byte swizzling for padded FP4; reject 32- and 64-byte swizzles.
- Preserve the consumer's local shared-memory layout.
- Preserve FP4 padding and transfer-box sizing for unswizzled copies.

Descriptor selection before and after this change (other descriptor requirements still apply; padded FP4 requires Blackwell or newer):

| Layout | Swizzle width | Before | Now |
| --- | --- | --- | --- |
| Unpadded | None (0 B) | Accepted | Accepted |
| Unpadded | 32 B | Accepted | Accepted |
| Unpadded | 64 B | Accepted | Accepted |
| Unpadded | 128 B | Accepted | Accepted |
| FP4 padded | None (0 B) | Rejected | **Accepted** |
| FP4 padded | 32 B | Selected, then rejected | **Filtered out during selection** |
| FP4 padded | 64 B | Selected, then rejected | **Filtered out during selection** |
| FP4 padded | 128 B | Accepted | Accepted |
