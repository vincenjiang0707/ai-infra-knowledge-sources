## Summary

Use physical storage width for Tensor Memory Accelerator (TMA) stride alignment. Packed FP4 uses `uint8` storage; using its logical 4-bit width incorrectly rejects a 16-byte row stride. Preserve gathered row indices for activation scales so values and scales use the same source rows.

Without preserving those indices, the H100 pointer-gather path pairs `X[gather[i]]` with `X_scale[i]`, producing numerical mismatches rather than a TMA error (maximum relative error 0.9443 versus 0.02 allowed in one case).

[NVIDIA specifies `globalStrides` in bytes, with 16-byte alignment for ordinary TMA.](https://docs.nvidia.com/cuda/cuda-driver-api/cuda_driver_api/group__CUDA__TENSOR__MEMORY.html)

## Desired features

- Accept packed FP4 tensors whose physical storage strides satisfy ordinary TMA alignment.
- Keep gathered activation values and their block/tensor scales on the same source rows.

## Validation

Tested on NVIDIA GB300 (copy below) and NVIDIA H100 (gathered-scale path) with Triton 3.8.0. The copy below is byte-exact and uses ordinary UINT8 TMA (`fp4_padded=False`). The old alignment expression returned `False`; the patched helper returned `True`. This copy does not validate padded FP4 or matmul.

Run with `triton_kernels` from the checkout:

```python
import torch
import triton
import triton.language as tl
from triton_kernels.tensor import FP4, is_tma_compliant, make_tma, wrap_torch_tensor


@triton.jit
def copy_packed(src, out):
    tl.store(out + tl.arange(0, 32), src.load([0, 0]).reshape(32))


storage = torch.arange(32, dtype=torch.uint8, device="cuda").reshape(2, 16)
packed = wrap_torch_tensor(storage, dtype=FP4)
out = torch.empty_like(storage)
kernel = copy_packed[(1,)](make_tma(packed, [2, 32], "dense"), out)

# checks
assert torch.equal(out, storage)
assert "cp.async.bulk.tensor" in kernel.asm["ptx"]
assert is_tma_compliant(packed)  # Fails before this change.
```
