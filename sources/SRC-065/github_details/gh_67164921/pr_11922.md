# [PR #11922] [AMD] Fix RDNA DRAM bandwidth estimates

## 正文

## Summary

`get_dram_gbps()` computes peak bandwidth as memory clock × bus width × 2,
which assumes two data transfers per clock.

The HIP driver reports the DRAM clock and bus width correctly, but current RDNA
products use GDDR6 or LPDDR5X. Their effective memory data rates require larger
transfer multipliers:

- gfx1100, gfx1101, gfx1102, gfx1200 and gfx1201 use GDDR6: 16 transfers per clock
- gfx1151 uses LPDDR5X: 8 transfers per clock

Use the normalized Triton target architecture to select the RDNA multiplier.
CUDA, CDNA and unknown HIP architectures retain the existing ×2 behavior.

gfx1150 and gfx1152 are intentionally excluded because their platforms may use
either DDR5 or LPDDR5X, which cannot be distinguished from the properties
currently exposed to this helper.

## Validation

Runtime properties and resulting peak bandwidth:

| Architecture| Current formula | With this change | Published value |
| --- | ---: | ---: | ---: |
| gfx1100 | 107.904 GB/s | 863.232 GB/s | 864 GB/s |
| gfx1151 | 64 GB/s | 256 GB/s | 256 GB/s |
| gfx1200 | 40.256 GB/s | 322.048 GB/s | up to 320 GB/s |

Runtime validation covers gfx1100, gfx1151 and gfx1200. The gfx1101, gfx1102
and gfx1201 cases are based on current AMD product documentation and synthetic
driver properties rather than local hardware.

gfx1200 reports a 1258 MHz memory clock at runtime rather than the nominal
1250 MHz used by the public specification, accounting for the 0.64% difference.

A new table-driven unit test covers every mapped architecture, both documented
gfx1151 bus widths, and unchanged CUDA behavior. Seven HIP cases fail with the
old ×2 formula while the CUDA control passes; all eight pass with this change.
The test uses synthetic driver properties and runs without GPU hardware.
