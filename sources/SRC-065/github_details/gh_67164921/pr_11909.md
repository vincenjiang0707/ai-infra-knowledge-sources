## 正文

**This is still work in progress**

## Description

`amdgpu.scaled_upcast` requires a layout which has `groupSize` (min 4) elements along `axis` held by a thread. When doing software emulation for scaled_dot we currently emit a blocked layout invalidating this requirement and rely on RemoveLayoutConversation to fix this for us. 
With https://github.com/triton-lang/triton/pull/11760 this no longer reliably works and this PR emits an legal packed initial layout. We also treat it as a layout anchor to avoid invalidating the layouts with RemoveLayoutConversions.

This also allows us to have a proper verifier to ensure the layouts are compatible and we no longer trigger late asserts when lowering to llvm. The other option would be to implement a software path were we lower via unpacked instructions, but it would silently regress performance if we mess up the layouts, especially in Gluon.

## Known issues
This will break if the axis dimension is too small so we do not have enough unique elements along `axis`. This is a latent bug and would trigger an assert in the lowering before this PR (it's now a verifier fail). This will be fixed in a follow up PR.
