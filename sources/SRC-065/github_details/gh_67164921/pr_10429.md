# [PR #10429] [BC-Breaking] Reject too many tensor slice indices

## 正文

## Summary

- Reject full-slice indexing after all dimensions of the source tensor have been consumed.
- Treat None/newaxis as adding an output dimension without adding a source dimension that a later full slice can consume.
- Guard semantic.expand_dims against out-of-range axes instead of silently appending.
- Add regressions for valid scalar newaxis-only indexing and for too many full slices before or after newaxis.

Fixes #6122.

## Validation

- Compared the supported indexing subset against NumPy: scalar[None] and scalar[None, None] are valid, while scalar[None, :] and scalar[:, None] both raise too-many-indices errors; vector[None, :] and vector[:, None] remain valid.
- Executed a dependency-free model of the source-dimension accounting for those cases.
- python3 -m py_compile passed for all three changed files.
- git diff --check passed.
- The GPU-backed pytest target cannot run on this macOS host because triton._C.libtriton is not built; CI remains the authoritative integration run.

I used AI assistance for repository inspection and validation, then reviewed the focused production and test changes and confirmed the indexing semantics before submission.

### yinli-systems · 2026-06-17

Pushed 26b40cfa8 to fix the integration-test failures from the previous run.

Root cause: the new too-many-slice-indices check counted full slices against the original tensor rank even after preceding `None`/newaxis indices. That made existing valid patterns like `scalar[None, :]` and `scalar[None, None, :]` fail, which showed up in `language/test_core.py::test_reduce` with `keep_dims=True` and `axis=None`.

Fix: validate full slices against the current effective rank after any prior newaxis expansion, while still rejecting genuinely too many slices such as `scalar[:, None]` and `vector[:, :]`. I also updated the slice tests to cover the valid scalar newaxis+slice cases.
