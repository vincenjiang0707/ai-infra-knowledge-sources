# [Issue #11406] `tl.softmax` produces incorrect, non-row-wise results

source: https://github.com/triton-lang/triton/issues/11406
state: closed | updated: 2026-09-07T10:16:14Z
labels: bug

## 正文

### Describe the bug

Hi,

I found what appears to be a shape/broadcasting issue in `tl.softmax` when the reduction dimension is dropped (`keep_dims=False`).


**Reproducer** (`triton_softmax_axis1_min.py`):

```python
import torch
import triton
import triton.language as tl


@triton.jit
def kernel(x_ptr, out_ptr):
    r = tl.arange(0, 2)
    c = tl.arange(0, 2)
    x = tl.load(x_ptr + r[:, None] * 2 + c[None, :])
    y = tl.softmax(x, dim=1, keep_dims=False)
    tl.store(out_ptr + r[:, None] * 2 + c[None, :], y)


x = torch.tensor([[0.0, 2.0], [3.0, 1.0]], device="cuda", dtype=torch.float32)
out = torch.empty_like(x)
kernel[(1,)](x, out)
torch.cuda.synchronize()

expected = torch.softmax(x.cpu(), dim=1)
assert torch.allclose(out.cpu(), expected, rtol=2e-3, atol=2e-3)
```

**Steps to reproduce**

```bash
python3 triton_softmax_axis1_min.py               # assertion fails
TRITON_INTERPRET=1 python3 triton_cdiv_signed_min.py  # interpreter: same failure
```

**Observed behavior**

Both the compiled and interpreter paths return non-row-wise results. For the 2×2 input above, the kernel output row sums are:

```text
actual:   [0.3979, 5.4493]
expected: [1.0, 1.0]
```

The exact output is:

```text
[[0.2689, 0.1289], [5.4018, 0.0474]]
```

The same kernel with `keep_dims=True` produces the correct row-wise result.

- GPU: NVIDIA V100
