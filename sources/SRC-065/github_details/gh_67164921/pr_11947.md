## Summary

The NVIDIA cache-policy lowering prints a full `f32` fraction (`1.0`) as `1` inside inline Parallel Thread Execution (PTX) assembly. The assembler rejects that integer-looking operand for `createpolicy.fractional`.

Add a `newConstantOperand(double)` overload to the PTX builder using `std::to_chars` for the shortest round-tripping decimal representation. Append `.0` when the representation has neither a decimal point nor an exponent, and use the formatter for cache-policy fractions. This applies to integral-valued floats generally, including `2.0`; it does not special-case `1.0`. Round trips preserve binary64 precision, as in Python. The f32 cache-policy fraction widens exactly to double before formatting: `0.1f` therefore prints as `0.10000000149011612`, while `0.1` prints as `0.1`. An integral forwarding overload preserves existing integer calls without ambiguity.

This is an investigation draft and must not be merged yet. The source audit found one direct `APFloat::toString` call in NVIDIA PTX lowering; this is not a claim that all inline-assembly constants have been audited.

## Desired features

- Finite double constants retain their value when parsed back as double; float inputs widen exactly.
- Integral-valued constants remain unmistakably floating point, including signed zero.
- Cache-policy fraction `1.0` compiles successfully, preserving the existing behavior of fractional and legacy policies.
