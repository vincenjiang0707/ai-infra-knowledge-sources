# [PR #11970] [TRITONGPU] Guard toLinearLayout against unencoded RankedTensorType

source: https://github.com/triton-lang/triton/pull/11970
state: closed | updated: 2026-09-25T19:08:36Z
labels: 

## 正文

Fixes #11795.

### Motivation and Root Cause
`mlir::triton::gpu::toLinearLayout(RankedTensorType type)` delegates directly to `toLinearLayout(type.getShape(), type.getEncoding())`. When an unencoded `RankedTensorType` (i.e. where `type.getEncoding() == nullptr`) is encountered during lowering (e.g. inside `LocalLoadOpConversion` or `LocalStoreOpConversion` in `ConvertTritonGPUToLLVM` / `ConvertTritonAMDGPUToLLVM`), the downstream overload executes:
```cpp
auto *ctx = layout.getContext();
return ctx->getLoadedDialect<TritonGPUDialect>()->toLinearLayout(shape, layout);
```
Dereferencing `layout.getContext()` on a null `Attribute` triggers an immediate SIGSEGV / segmentation fault in `mlir::Attribute::getContext()`.

### Proposed Changes
1. **`lib/Dialect/TritonGPU/IR/LinearLayoutConversions.cpp`**:
   - Added an explicit guard in `toLinearLayout(RankedTensorType)`: if `type.getEncoding()` is null, report an informative fatal error (`llvm::report_fatal_error(...)`) rather than crashing with an unchecked null pointer dereference.
2. **`test/TritonGPU/unencoded-tensor-linearlayout.mlir`**:
   - Added lit regression test using `not --crash triton-opt ... 2>&1 | FileCheck` to verify that an unencoded tensor on `ttg.local_load` produces the explicit error message instead of segfaulting.

### Validation
- Ran the regression test via `FileCheck`: confirmed that the compiler cleanly catches the missing encoding and terminates with `LLVM ERROR: toLinearLayout: RankedTensorType must have a layout encoding, got none`.
- Ran the full `TritonGPU` lit test suite (137/138 passing, no regressions introduced).
