# [PR #11251] Emit scheduling DAG as a (bb, position) edge list from translate_to_mir

source: https://github.com/triton-lang/triton/pull/11251
state: open | updated: 2026-09-25T06:43:44Z
labels: 

## 正文

Replaces the old `dump_sched_dag` path with a scheduling DAG emitted directly from the MIR that `translate_to_mir` already dumps. The old path ran a second, independently-scheduled compilation and printed `-misched-print-dags` text that keyed instructions by register name, which is fragile across virtual-register
  renumbering. The new path appends a per-region edge list after the `SCHEDULING DAG` marker in the MIR dump:

```
  region <bb>
  node <pos> <def-reg|-> <opcode>
  edge <src-pos> <dst-pos> <Type> <latency> [<reg>]
```

Instruction identity is `(bb, position)`, so the MIR dump and the DAG stay correlatable regardless of how vregs are numbered. Data/Anti/Output/Memory/Barrier edges are kept; Artificial/Cluster are dropped.

`DAGBuilder` is a thin wrapper over LLVM's `ScheduleDAGInstrs`. It runs as a `MachineFunctionPass` so `LiveIntervals` is available; that lets `buildSchedGraph` track lane masks and produce **subregister-precise** dependencies that match LLVM's own scheduler (without LI, subregister defs/uses are over-approximated and the DAG gains spurious WAW/WAR edges).

The DAG is currently built by re-parsing the dumped MIR text. A subsequent commit will build it from the live pipeline `MachineFunction` instead, avoiding the re-parse round-trip and reusing the pipeline's `LiveIntervals`.
