# [PR #11720] [TUTORIALS] Avoid per-case streams in fused-softmax benchmark

source: https://github.com/triton-lang/triton/pull/11720
state: closed | updated: 2026-09-24T20:19:00Z
labels: 

## 正文

Fixes #11661

The fused-softmax tutorial created and selected a new PyTorch device stream in every `benchmark()` call. This made each case use a different stream while the caching allocator retained memory from earlier cases, causing reserved memory to grow through the sweep.

Remove the two per-case stream calls so the benchmark uses the current stream. On an 8 GiB RTX 2000 Ada running Windows, the full 294-case sweep completed with this change alone. Reserved memory still grew (to 23,016 MiB under WDDM), so this does not establish that the original 6 GiB OOM is fixed on that card.
