# [Issue #11601] [FuseNestedLoops] flatten=True hoists the inner bound load above a zero-trip outer loop and dereferences a pointer the source never reads

source: https://github.com/triton-lang/triton/issues/11601
state: open | updated: 2026-09-05T14:17:49Z
labels: 

## 正文

`tritongpu-fuse-nested-loops` with `flatten=True` moves the inner loop's bound computation above the outer loop, and when that computation is a scalar `tt.load` the load runs even when the outer loop has zero trips. A kernel whose source never touches `q` at `m = 0` then dereferences `q`: with `q` pointing at unmapped memory the launch fails with an illegal memory access, and the same kernel with `flatten=False` is clean.

```
triton 3.7.1  torch 2.13.0+cu130  NVIDIA RTX PRO 6000 Blackwell Max-Q Workstation Edition
flatten=True  exit=3 CUDA error: an illegal memory access was encountered
flatten=False exit=0 clean
```

Before and after the pass, `flatten=True` (the load moves from the inner loop to function scope, no mask):

```

      %bound = tt.load %q : !tt.ptr<i32>
      %acc_2 = scf.for %j = %c0_i32 to %bound step %c1_i32 iter_args(%acc_3 = %acc_1) -> (tensor<128xf32, #blocked>)  : i32 {

// IR Dump Before Canonicalizer, i.e. immediately after the pass
    %offs = tt.make_range {end = 128 : i32, start = 0 : i32} : tensor<128xi32, #blocked>
    %bound = tt.load %q : !tt.ptr<i32>
    %acc_0 = arith.subi %bound, %c0_i32 : i32
```

The site is `FuseNestedLoops.cpp:246-253` at `c98f87649e5b`, which hoists any `isMemoryEffectFree() || hasSingleEffect<Read>` op; a read is speculated without the guard the loop provided. Distinct from #11519 (that one is `matchPositiveTripCount` accepting a non-dominating `llvm.assume`; this kernel has no assume).

With `flatten=False` the same load is put at function scope by `triton-licm` one pass later, as `%bound = tt.load %q, %acc_0` with `%acc_0 = arith.cmpi sgt, %m, %c0_i32`.

Self-contained script (two subprocesses, since the error is sticky; the pointer is passed as a raw integer because the launcher validates tensor pointers with `cuPointerGetAttribute`):

```python
"""Self-contained reproducer: tritongpu-fuse-nested-loops hoists a scalar tt.load out of a
loop that may not run, without the mask triton-licm synthesises for the identical load.

`canHoistLoopBoundComputation` (FuseNestedLoops.cpp:246-253) admits an operation with a single
read effect, so the `tl.load(q)` that supplies the inner loop's bound travels above the outer
loop. Nothing re-establishes the premise that the outer loop runs. At `m = 0` the source
program never reads `q`; the compiled program reads it before the loop.

`triton-licm`, one pass later, hoists the same load out of the same loop and strengthens its
mask with the trip test (LoopInvariantCodeMotion.cpp:55-77), which is what `flatten=False`
below gets. So the two rows are two lowerings of one source program, and `flatten` is a
scheduling hint absent from that program's semantics.

Distinct from #11519: no `llvm.assume` anywhere, a different predicate in the same pass, and
the observable is a read of an address the source never reads rather than a wrong value.

    python repro_fuse_hoist.py

`q` is given an address 1 TiB past a live allocation, which is unmapped. Only the arm that
dereferences it faults; the same arm at `m = 1`, where the source does read `q`, faults too,
so the fault is a fact about the address and not about the arm.
"""

import os
import subprocess
import sys

import triton
import triton.language as tl

BLOCK = 128
# 1 TiB past a live allocation: an address in the device VA space that nothing maps.
UNMAPPED_OFFSET = 1 << 40


@triton.jit
def kload(p, out, q, m, BLOCK: tl.constexpr, FLAT: tl.constexpr):
    offs = tl.arange(0, BLOCK)
    acc = tl.zeros([BLOCK], dtype=tl.float32)
    for _i in tl.range(0, m, flatten=FLAT):
        bound = tl.load(q)  # `q` need only be dereferenceable when m > 0
        for j in range(0, bound):
            acc += tl.load(p + j * BLOCK + offs)
    tl.store(out + offs, acc)


class RawPtr(int):
    """A device address handed to the kernel as a raw uint64.

    Triton's launcher validates a `data_ptr()` argument with `cuPointerGetAttribute` and
    refuses an address the driver does not recognise; the uint64 road that the same function
    documents (`backends/nvidia/driver.c`, `extractPointer`) passes the value through as given.
    """

    def __new__(cls, address, dtype):
        self = super().__new__(cls, address)
        self.dtype = dtype
        return self

    def data_ptr(self):
        return int(self)


def arm(flat):
    """One launch at m = 0 with an unmapped `q`. Never returns: the error is sticky."""
    import torch

    p = torch.ones(2 * BLOCK, dtype=torch.float32, device="cuda")
    out = torch.zeros(BLOCK, dtype=torch.float32, device="cuda")
    q = torch.full((1,), 2, dtype=torch.int32, device="cuda")
    unmapped = RawPtr(q.data_ptr() + UNMAPPED_OFFSET, torch.int32)
    try:
        kload[(1,)](p, out, unmapped, 0, BLOCK=BLOCK, FLAT=flat, num_warps=4)
        torch.cuda.synchronize()
    except RuntimeError as exc:
        print(str(exc).strip().splitlines()[0], flush=True)
        os._exit(3)
    print("clean", flush=True)
    os._exit(0)


def run():
    """Each arm in its own process: an illegal access poisons the context it happens in."""
    for flat in (1, 0):
        done = subprocess.run([sys.executable, __file__, str(flat)], capture_output=True, text=True)
        detail = done.stdout.strip().splitlines()[-1] if done.stdout.strip() else "?"
        print(f"flatten={bool(flat)!s:5s} exit={done.returncode} {detail}")


if __name__ == "__main__":
    if len(sys.argv) > 1:
        arm(int(sys.argv[1]))
    import torch

    device = torch.cuda.get_device_name(0)
    print(f"triton {triton.__version__}  torch {torch.__version__}  {device}")
    run()
```

A minimal witness, 15 lines, no store at all. Run it with `triton-opt --tritongpu-fuse-nested-loops`: after the pass the `tt.load %arg2` is the first op of the function, above the `scf.if` that tests `%arg3 == 0`, so `q` is dereferenced even when the outer loop never runs.
