## Summary
This PR is to extend  `TestStandaloneInductor.test_aoti_cuda_cmake_uses_multi_arch_gencode_flags` and `TestStandaloneInductor.test_aoti_cuda_save_kernel_recompiles_for_target_arch` so they run on both CUDA and ROCm instead of skipping HIP.


- `test_aoti_cuda_cmake_uses_multi_arch_gencode_flags `:
  - **CUDA** behavior is unchanged: TORCH_CUDA_ARCH_LIST=7.0;8.0;8.6;9.0 with compile target sm_80 emits -gencode for 80/86/90 and drops 70 and the mocked live 100a.
  - **ROCm**: PYTORCH_ROCM_ARCH=gfx900,gfx90a,gfx942 emits --offload-arch for those gfx targets and does not emit nvcc -gencode.
  
- `test_aoti_cuda_save_kernel_recompiles_for_target_arch`:
  - **CUDA** behavior is unchanged: with `aot_inductor.emit_multi_arch_kernel=True`, a mismatched `cuda.arch` triggers Triton recompile (`cc_override`) and packages target cubin/PTX and an unset `cuda.arch` keeps the current-device binary.
  - **ROCm** has no `cuda.arch` / `cc_override` path. The HIP branch asserts what `save_gpu_kernel` actually does: 
     - multi-arch **on**: cache `hsaco` + LLVM IR (`llir`, `asm_type="ll"`), no recompile
     - multi-arch **off**: cache `hsaco` + `amdgcn`, no recompile

- save_compile_cmd_to_cmake: on HIP, write HIP_OFFLOAD_ARCH_FLAGS from get_rocm_target_archs() and an embed_gpu_kernel that objcopies hsaco. CUDA fatbin/-gencode cmake is unchanged. This runs only for aot_inductor.package_cpp_only, not normal torch.compile.
