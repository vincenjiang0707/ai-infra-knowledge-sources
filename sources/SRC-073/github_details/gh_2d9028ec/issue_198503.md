## 正文


## Bug description

AOTInductor compilation of an nnUNetv2 model hangs indefinitely on Windows after successful export. The same model compiles successfully in a Linux environment.

`torch.export.export()` completes successfully and the exported model passes correctness validation. However, `torch._inductor.aoti_compile_and_package()` never returns.

Using `py-spy` after more than 30 minutes of runtime consistently shows the main thread inside `torch._inductor.codecache.format_consts_to_cpp()`.


---

## Reproduction script

```python
import json, torch
from nnunetv2.utilities.plans_handling.plans_handler import PlansManager
from nnunetv2.utilities.get_network_from_plans import get_network_from_plans

MODEL_DIR = r"Path\to\SPACEtomo_lamella_segmentation_Yeast\model"
CONFIG = "2d"

plans = json.load(open(f"{MODEL_DIR}\\plans.json"))
dataset_json = json.load(open(f"{MODEL_DIR}\\dataset.json"))
pm = PlansManager(plans)
cfg = pm.get_configuration(CONFIG)

ckpt = torch.load(
    f"{MODEL_DIR}\\fold_0\\checkpoint_final.pth",
    map_location="cpu",
    weights_only=False,
)

num_in = len(dataset_json["channel_names"])
num_out = pm.get_label_manager(dataset_json).num_segmentation_heads

model = get_network_from_plans(
    cfg.network_arch_class_name,
    cfg.network_arch_init_kwargs,
    cfg.network_arch_init_kwargs_req_import,
    num_in,
    num_out,
    allow_init=True,
    deep_supervision=True,
)

model.load_state_dict(ckpt["network_weights"])
model = model.cuda().eval()

example_input = torch.randn(1, 1, 1024, 1024, device="cuda")

total_params = sum(p.numel() for p in model.parameters())
total_mb = sum(
    p.numel() * p.element_size()
    for p in model.parameters()
) / (1024 ** 2)

print("Total params:", total_params)
print("Parameter size (MB):", total_mb)

with torch.no_grad():
    exported = torch.export.export(model, (example_input,))

torch.testing.assert_close(
    exported.module()(example_input),
    model(example_input)
)

print("export done")

pt2_path = torch._inductor.aoti_compile_and_package(
    exported,
    package_path=r"Path\to\nnunet_gpu.pt2",
)

print("compiled:", pt2_path)
```

3. Download the model from: zenodo model-> record 10360540
4. Run:

```cmd
venv\Scripts\activate.bat
```

## Observed behavior

Export succeeds.

Total params: 33494470
Parameter size (MB): 127.7712631225586

After export, execution hangs inside:

```python
torch._inductor.aoti_compile_and_package(...)
```

The process remains stuck at aoti_compile_and_package(...) and remaind stuck there for more thatn 30 mins before Ctrl+c. During this time memory use continued to grow.

Repeated py-spy dumps show execution in `format_consts_to_cpp()`.


## Additional notes

- Reproduces consistently on Windows.
- Same model successfully compiles with AOTInductor on Linux.
- The issue reproduces with both nnUNetv2 configurations tested (2d and 3d_fullres) on Windows. In both cases, torch.export.export() succeeds, but torch._inductor.aoti_compile_and_package() hangs.
- Stack traces repeatedly point to `torch._inductor.codecache.format_consts_to_cpp()` with no observable forward progress.
