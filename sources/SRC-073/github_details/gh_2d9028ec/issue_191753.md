## the problem

By default it looks like Dynamo cache lookup and pre-graph bytecode take ~2ms. This happens on every forward pass of the model:

<img width="692" height="329" alt="Image" src="https://github.com/user-attachments/assets/8f7bc6e8-eabc-49a1-b9b4-523f533e62e6" />

It's possible that this runtime overhead can matter depending on everything else the user does. The prefill in this profile is 41ms, which is a bit larger than 2ms, but a decode of this is probably going to be closer to 2ms than 41ms. Usually people use cudagraphs (on the outside of torch.compile) and/or make sure their gpu is fully utilized via other strategies, so it's plausible that the Dynamo CPU overhead can be hidden, but 2ms seems like a lot.

We should try to bring down the 2ms as much as possible and/or document how to do it if we haven't already.

## some workarounds that bring the times down

some noisy codex analysis:
```

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━  ━━━━━━━━━━━━━━  ━━━━━━━━━━  ━━━━━━━━━━━━━━━━━━━
 Baseline                                     0.761 ms    0.131 ms             0.892 ms
───────────────────────────────────────  ──────────────  ──────────  ───────────────────
 + install_free_tensors=True                  2.000 ms    0.006 ms             2.006 ms
───────────────────────────────────────  ──────────────  ──────────  ───────────────────
 + skip_guard_eval_unsafe=True                0.105 ms    0.007 ms             0.112 ms
───────────────────────────────────────  ──────────────  ──────────  ───────────────────
 + skip_guard_on_all_nn_modules_unsafe        0.038 ms    0.006 ms             0.044 ms
───────────────────────────────────────  ──────────────  ──────────  ───────────────────
 + skip_all_guards_unsafe                         0 ms    0.006 ms             0.006 ms
```


I'm surprised that skip_guard_eval_unsafe=True doesn't just skip all the guards, since I'm just compiling for one specialization.

Unrelated but interesting: Inductor freezing mode is highly profitable because it combine the qkv weights all into one big buffer. codex tells me the forward pass latency goes from 20-26ms down to 10ms with freezing on.
