# [PR #198435] [dynamo] Leave plain functions unbound when super() is bound to a class

source: https://github.com/pytorch/pytorch/pull/198435
state: closed | updated: 2026-09-25T12:54:53Z

## 正文

When `super()` is bound to a class (e.g. zero-arg `super()` in a classmethod), CPython calls the descriptor with `obj=NULL`, so a plain function from the MRO stays unbound ([typeobject.c](https://github.com/python/cpython/blob/v3.13.0/Objects/typeobject.c#L11162-L11166)). Dynamo always passed `objvar` as the first argument, which can silently change the result:

```python
class Parent:
    def greet(*args):
        return len(args)

class Child(Parent):
    @classmethod
    def greet(cls):
        return super().greet()  # eager: 0, compiled: 1
```

`SuperVariable.call_method` now leaves the function unbound when `objvar` is a class. This enables `test_super.py::TestSuper::test_reassigned_new` and `test_mixed_staticmethod_hierarchy` and removes their expected-failure markers.

In a metaclass method, `super(Meta, A)` binds to `A` even though `A` is a class. That case goes through the real `super()` fallback in `_resolved_getattr_and_source`, which already applies the descriptor, so it never reaches the new branch unbound. `test_super_metaclass_method` covers it, including a staticmethod on the parent metaclass that was previously called with `A` prepended.

Towards #195901.
