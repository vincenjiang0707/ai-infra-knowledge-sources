## 正文

Fixes #198197

Description

In TorchDynamo, accessing a missing attribute on builtin types/functions via getattr(builtin_type, missing_attr) or inside try...except getattr(...) fell through to construct a fallback GetAttrVariable(self, name, py_type=None, ...).

Because Dynamo treated this as an unmodeled or deferred attribute access rather than raising an observed exception, control flow checking attribute existence (try: getattr(...) except AttributeError:) bypassed the except block and took the wrong branch under torch.compile.

Solution
In BaseBuiltinVariable.tp_getattro_impl, check hasattr(fn, name). If not present, call raise_observed_exception(AttributeError, tx) and return None early.
In BuiltinVariable.tp_getattro_impl:
Return None early under self.fn is object when getattr raises AttributeError.
Check hasattr(self.fn, name). If not present, call raise_observed_exception(AttributeError, tx) and return None early instead of falling through to GetAttrVariable.
Add regression test test_builtin_type_getattr_missing_attr_issue_198197 to test/dynamo/test_tp_getattro.py exercising int, str, list, dict, type, object, float, bool, tuple, and set.

## PR Review: #198330

### Summary
The PR makes `BaseBuiltinVariable.tp_getattro_impl` and `BuiltinVariable.tp_getattro_impl` raise an observed `AttributeError` when the attribute doesn't exist on the real builtin. Previously they built a `GetAttrVariable`, so `try: getattr(...) except AttributeError:` took the wrong branch. The approach is sound. The problems below are code quality and test adequacy.

### Code Quality
- **Dead `return None` after `raise_observed_exception`** (`torch/_dynamo/variables/builtin.py:472`, `:2879`, `:2884`). `raise_observed_exception` is annotated `-> NoReturn` (`torch/_dynamo/exc.py:556`), so these lines never run. They also contradict the `-> VariableTracker` return annotation. Most call sites in `variables/` don't add a `return` after it, including the original `object` branch this PR edits. Remove all three.
- **`hasattr` followed by `getattr` does the lookup twice** (`builtin.py:470-473`, `:2882-2885`). The `object` branch just above (`:2875-2878`) already uses `try: getattr(...) except AttributeError: raise_observed_exception(...)`. Use that same form in both new sites: one lookup, and it matches the file's existing pattern.
- **The two sites now build `py_type` differently.** `BaseBuiltinVariable` now passes `py_type=type(attr)`, so an attribute whose value is `None` gets `NoneType`. `BuiltinVariable` (`:2886-2888`) still has `py_type=type(attr) if attr is not None else None`. Now that `attr` is known to exist, `type(attr)` is correct in both places. Drop the conditional in `BuiltinVariable` so the two overrides agree.

### Testing
- **The test collapses 10 results into one bool** (`test/dynamo/test_tp_getattro.py:1858-1887`). A failure only shows "sin vs cos", not which type broke. Return the `results` list, or use `@parametrize` over the types, and compare with `assertEqual`. Also replace `assertTrue(torch.allclose(...))` with `assertEqual(actual, expected)`, per the repo testing guidelines.
- **Coverage is missing for:**
  - Builtin functions (`len`, `print`, `abs`). These go through `BuiltinVariable.tp_getattro_impl` too, and the PR description says the fix covers "builtin types/functions".
  - Direct attribute access (`int.__nonexistent__` via `LOAD_ATTR`), not only `getattr(...)`.
  - `hasattr(int, "__nonexistent__")`. `call_obj_hasattr` routes through `tp_getattro_impl` and catches `ObservedAttributeError` (`variables/base.py:2306-2311`).
  - A positive case (e.g. `getattr(int, "from_bytes")`, `getattr(len, "__name__")`) in the same compiled function. This guards against the new check wrongly rejecting attributes that exist.
- Nit: the other tests in the file don't put the issue number in the test name. Put `#198197` in a comment instead.

### Recommendation
**Request Changes.** The semantics are correct. Remove the dead code, use the `try/except` form in both sites, and broaden the test (per-type assertions, builtin functions, `LOAD_ATTR`, `hasattr`, a positive case) before merging.

Note: I couldn't run the tests in this environment (no approval to run Python), so this review is based on reading the code only.
