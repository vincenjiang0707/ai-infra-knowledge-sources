## 正文

### 🐛 Describe the bug

This is detected by our fuzzer, and the reproducible code is:

```
import torch
import torch.nn as nn
import torch.nn.functional as F


class Model(nn.Module):
    def __init__(self):
        super().__init__()
        self.scale = 1.0/300.0

    def forward(self, x):
        y = F.interpolate(x, scale_factor=self.scale, mode='linear', align_corners=False)
        padded = F.pad(y, pad=(1, 0))
        out = torch.gt(padded, y)
        return out


torch.manual_seed(0)
x1 = torch.randn(1, 8, 396)
torch.manual_seed(0)
x2 = torch.randn(1, 8, 396)

model = Model()
cmodel = torch.compile(Model(), dynamic=True)
out1 = model(x1)
out2 = cmodel(x2)
torch.testing.assert_close(out1, out2)

```

Error:

```
AssertionError: Tensor-likes are not equal!

Mismatched elements: 6 / 16 (37.5%)
Greatest absolute difference: 1 at index (0, 0, 1)
Greatest relative difference: 1.0 at index (0, 0, 1)
```

Additional information:

The issue is specifically triggered by dynamic=True combined with align_corners=False.
The F.pad → torch.gt sequence is required to reproduce the final output mismatch; without it, no error occurs.

### JingHao-Leon · 2026-09-23

Reproduced on **torch 2.14.0, CPU-only, Apple Silicon arm64 (macOS 26.5)** — the issue repro gives the same `6/16` mismatched elements, so this is not CUDA-specific.

Also checked the two stated specificity conditions:

| variant | result |
|---|---|
| issue repro (`dynamic=True`, interpolate → pad → gt) | mismatch **6/16** (same count as reported) |
| `dynamic=False`, same ops | match (confirms the `dynamic=True` claim) |
| `dynamic=True`, interpolate **only** (no pad/gt) | mismatch **3/8** |

The second specificity claim doesn't hold: `F.pad → torch.gt` is **not** required. With `dynamic=True`, the plain `F.interpolate(x, scale_factor=1/300, mode='linear', align_corners=False)` output already differs from eager on 3 of 8 elements, so the root cause appears to live in the dynamic-shape linear interpolation itself (the 396 → 1 downscale with a float `scale_factor`), and the pad/gt sequence only amplifies it into the issue's 6/16.

Repro script is the issue's module with the pad/gt branch made conditional; happy to paste a single runnable file if useful.
