# [PR #198627] [dynamo] Apply __index__ to constant str and bytes subscripts

source: https://github.com/pytorch/pytorch/pull/198627
state: open | updated: 2026-09-25T12:34:35Z
labels: open source, module: dynamo, ciflow/inductor, ciflow/torchtitan

## 正文

I reproduced this myself with a small script. An object with `__index__` can be used as an index or a slice bound: `"abcdef"[Index(2)]` gives `'c'` and `"abcdef"[Index(1):Index(4)]` gives `'bcd'`. Under `torch.compile` normal mode gave the same results, but `fullgraph=True` failed with `Unsupported`, so these are graph breaks: Dynamo could not call `__index__` here. The same happened for an object without `__index__`, where plain Python raises `TypeError: string indices must be integers, not '...'`; that case is like an empty `functools.partial()`, a user error that should just be the `TypeError`. With this PR all of these match eager under `fullgraph=True`.

> **AI-generated technical summary (Claude), reviewed by me:**
>
> Part of #195901 (apply `__index__` when subscripting constant strings and bytes; apply `__index__` to constant string and bytes slice bounds).
>
> `ConstantVariable.mp_subscript_impl` only constant-folded `str`/`bytes` subscripts whose key was already a Python constant, so any other key graph-broke. For `str` and `bytes` it now converts a tracked index with `pynumber_index` and slice bounds with `SliceVariable.as_index_slice` before the existing fold; both paths trace `__index__` and validate its result, which reusing `getitem_const` would miss. A tracked key without `__index__` raises CPython's `TypeError` (`string indices must be integers, not '...'` / `byte indices must be integers or slices, not ...`); these messages are the same in Python 3.12, 3.13 and 3.14. Constant keys go through the existing path unchanged. A tensor index still graph-breaks (on `Tensor.item()`) and gives the same result as before.
>
> **Tests** (all under `fullgraph=True`, each fails without the fix)
>
> - `test_getitem.py::test_str_bytes_subscript_index_object`: `__index__` objects as `str` and `bytes` indices, including a negative index.
> - `test_getitem.py::test_str_bytes_subscript_slice_index_object`: `__index__` objects as slice bounds and step.
> - `test_getitem.py::test_str_bytes_subscript_index_object_errors`: `__index__` returning a non-int (`TypeError`) or an out-of-range value (`IndexError`).
> - `test_getitem.py::test_str_bytes_subscript_invalid_object`: an object without `__index__` raises the `str` and `bytes` `TypeError` messages.
>
> CPython tests under Dynamo: 11 tests go from error to passing (`test_index` `StringTestCase` and `BytesTestCase`: `test_error`, `test_index`, `test_slice`, `test_slice_bug7532`, `test_wrappers`; `test_userstring` `UserStringTest.test_subscript`), and no test goes from passing to failing in `test_index`, `test_userstring`, `test_str` or `test_bytes`; the 11 expected-failure markers are removed. The other tests in `test/dynamo/test_getitem.py` show the same results with and without the change.
