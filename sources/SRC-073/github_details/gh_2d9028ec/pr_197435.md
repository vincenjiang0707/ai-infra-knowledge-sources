# [PR #197435] Skip TestCompositeCompliance.test_cow_input tests with ACL

source: https://github.com/pytorch/pytorch/pull/197435
state: closed | updated: 2026-09-25T11:54:34Z
labels: open source, ciflow/trunk, mergedog, mergedX1

## 正文

When ACL is used addmm_impl_cpu_ on ARM may call `mkldnn_matmul`. When the (unsqueezed) matrices are `is_mkldnn_optimized_format` then they will be aliased instead of copied and `itensor_view_from_dense` will then materialize the CoW tensors as `from_const_data_ptr=false`.

Mark the relevant tests as XFAIL until this is otherwise adressed.

The following reproduces the failures:
```
    PYTORCH_OPINFO_SAMPLE_INPUT_INDEX=0 python test/test_ops.py TestCompositeComplianceCPU.test_cow_input_addmm_cpu_float32
    PYTORCH_OPINFO_SAMPLE_INPUT_INDEX=0 python test/test_ops.py TestCompositeComplianceCPU.test_cow_input_addmm_decomposed_cpu_float32
    PYTORCH_OPINFO_SAMPLE_INPUT_INDEX=2 python test/test_ops.py TestCompositeComplianceCPU.test_cow_input___rmatmul___cpu_float32
    PYTORCH_OPINFO_SAMPLE_INPUT_INDEX=6 python test/test_ops.py TestCompositeComplianceCPU.test_cow_input_cholesky_inverse_cpu_float32
    PYTORCH_OPINFO_SAMPLE_INPUT_INDEX=6 python test/test_ops.py TestCompositeComplianceCPU.test_cow_input_cholesky_solve_cpu_float32
```

@robert-hardwick fixed a similar issue with https://github.com/pytorch/pytorch/pull/142366

I wasn't able find exact documentation on whether iDEEP actually leaves the memory of those inputs untouched for this operation.
If that was the case we can simply pass `from_const_data_ptr = true`
