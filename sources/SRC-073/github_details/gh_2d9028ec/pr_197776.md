# [PR #197776] [Feature Refactoring]Switch memory calls in CUDA to device_interface calls.

source: https://github.com/pytorch/pytorch/pull/197776
state: open | updated: 2026-09-25T11:31:48Z

## 正文

Summary：
1. Add four new interfaces to device_interface: get_mempool_type, begin_allocate_to_pool, end_allocate_to_pool, and release_pool.
2. Modify the torch.cuda.memory._cuda invocation in function begin_mempool to use device_interface.
3. Modify the torch.cuda.memory._cuda invocation in function end_mempool to use device_interface.
4. Remove function _get_mempool_by_index.
5. Change torch.cuda.MemPool for CUDAMemPoolVariable to use device_interface calls.

### Spacexcx · 2026-09-20

In torch/_dynamo/device_interface.py:
get_mempool_type = staticmethod(torch.cuda.MemPool) does not return the MemPool class when called; instead, calling iface.get_mempool_type() will attempt to invoke the torch.cuda.MemPool() constructor.
When used in torch/_dynamo/variables/memory.py:
if not isinstance(mempool, iface.get_mempool_type()):
This will either raise a TypeError due to constructor arguments or instantiate an object, causing isinstance() to fail with:
TypeError: isinstance() arg 2 must be a type, a tuple of types, or a union
To return the class object itself, this should be defined as:
@staticmethod
def get_mempool_type() -> type:
return torch.cuda.MemPool
