# [Issue #198507] torch.topk returns different values on CPU and CUDA for a 0-D input with k=0

## 正文

### 🐛 Describe the bug

`torch.topk` returns different values on CPU and CUDA for the same 0-D input when `k=0`.

For example, with a float32 scalar containing `3.5`, the CPU result contains `3.5`, while the CUDA result contains `0.0`. Both `values` and `indices` are 0-D tensors, and both devices return index `0`.


### To reproduce

```python
import torch

print("PyTorch:", torch.__version__)

for device in ("cpu", "cuda"):
    for dtype, value in ((torch.float32, 3.5), (torch.int64, 7)):
        x = torch.tensor(value, dtype=dtype, device=device)
        values, indices = torch.topk(x, k=0)

        if device == "cuda":
            torch.cuda.synchronize()

        print(
            device,
            dtype,
            values.cpu(),
            indices.cpu(),
            values.shape,
            indices.shape,
        )
```
On PyTorch 2.13.0+cu130, the float32 case prints a value of 3.5 on CPU and 0.0 on CUDA. The int64 case also returns different values on CPU and CUDA.
Expected: CPU and CUDA should return consistent results for the same input and arguments. Please clarify the intended behavior for a 0-D input when k=0.
A related but different issue is #49205, which concerns a CUDA assertion for a 1-D input with k=0. This report concerns a 0-D input and a CPU/CUDA result mismatch.

### Versions

CPU arm: PyTorch 2.14.0+cu130, Python 3.10.12, Ubuntu 22.04 (x86_64)
CUDA arm: PyTorch 2.14.0+cu130, CUDA 13.0, cuDNN 9.24.0, RTX 5090, driver 580.76.05
