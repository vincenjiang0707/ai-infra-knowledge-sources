## 正文

Fix Dynamo support for automatically deleting exception variables after an `except X as e` block exits.

> **Codex-generated summary:** `DELETE_FAST` previously removed the local from Dynamo's symbolic locals, so a later `LOAD_FAST_CHECK` graph-broke instead of raising `UnboundLocalError`. This change preserves a `NullVariable` tombstone and raises the observed exception on a later read. It also removes the expected-failure markers for the two CPython 3.13 tests.
>
> **Verification:** `test_exception_cleanup_names` and `test_exception_cleanup_names2` passed in Dynamo mode. The full `test_exceptions.py` run had no failures: 102 tests ran, 69 skipped. Python 3.13.1 required a process-local compatibility shim for a missing test-support decorator.
>

## PR Review: #198380

### Summary
`DELETE_FAST` now leaves a `NullVariable` tombstone in `symbolic_locals` instead of removing the entry. `LOAD_FAST_CHECK` then raises an observed `UnboundLocalError` instead of graph-breaking. On 3.12+ this is correct, since `LOAD_FAST_CHECK` exists there and `output_graph` already treats NULL locals via `locals_null_keys`. On 3.10/3.11 the change regresses behavior, because there the tombstone is never checked and hits a hard assertion. It also comes without a Dynamo-native test.

### Code Quality
- **`torch/_dynamo/symbolic_convert.py:2293`: the tombstone is only handled on 3.12+, but it is written on every version.** Python 3.10/3.11 have no `LOAD_FAST_CHECK`; a read after `except E as e:` cleanup compiles to plain `LOAD_FAST`. Two problems follow:
  1. **Silent bad value.** `LOAD_FAST` (`symbolic_convert.py:2211`) now pushes the `NullVariable` itself (`.unwrap()` is identity) onto the stack. The user should get `UnboundLocalError`. Before this PR, the `KeyError` branch graph-broke cleanly. Example:
     ```python
     def f(x):
         try:
             raise ValueError
         except ValueError as e:
             pass
         return x + 1, e
     ```
     On 3.11 this reconstructs a `NullVariable` as `PUSH_NULL` into a return value. On 3.10 it graph-breaks with a `DYNAMO_BUG` "cannot reconstruct NullVariable" hint.
  2. **Internal assertion on graph break.** Suppose a graph break happens while the deleted name is still live, meaning it is read later on some path, e.g. `if cond: e = 1` after the handler, then `graph_break()`, then `print(e)`. Then `output_graph.py:1995-1999` raises `AssertionError("variable should never be NULL in Python < 3.12")`. Previously the name was just absent and the resume function saw it as unbound.

  Fix: write the tombstone only on `sys.version_info >= (3, 12)` and keep the `del` otherwise. Alternatively, also raise `UnboundLocalError` from `LOAD_FAST` on `< 3.12` when it sees a `NullVariable`, and relax the `< 3.12` assertion in `output_graph.py` to treat NULL locals as unbound. Don't add the check to `LOAD_FAST` unconditionally: `LOAD_FAST_AND_CLEAR` (`symbolic_convert.py:4976`) routes through `LOAD_FAST` and may legitimately load a `NullVariable`. Low-confidence caveat: I could not run the 3.10/3.11 bytecode here to confirm. The analysis is based on CPython's `except ... as` cleanup sequence (`LOAD_CONST None; STORE_FAST e; DELETE_FAST e`) and Dynamo's current handling.

  [Fix this →](https://claude.ai/code?q=In%20torch%2F_dynamo%2Fsymbolic_convert.py%20on%20branch%20codex%2Ffix-dynamo-exception-cleanup-names%2C%20DELETE_FAST%20now%20stores%20a%20NullVariable%20tombstone%20in%20symbolic_locals%20on%20all%20Python%20versions%2C%20but%20on%203.10%2F3.11%20there%20is%20no%20LOAD_FAST_CHECK%20so%20LOAD_FAST%20pushes%20the%20NullVariable%20and%20output_graph.py%20asserts%20NULL%20locals%20never%20occur%20before%203.12.%20Gate%20the%20tombstone%20to%20sys.version_info%20%3E%3D%20(3%2C%2012)%20(keep%20del%20otherwise)%20or%20make%20LOAD_FAST%20raise%20UnboundLocalError%20on%20NullVariable%20for%20%3C3.12.&repo=pytorch/pytorch)

### Testing
- **No Dynamo-native regression test.** The only coverage is removing the two `CPython313-*` expected-failure markers, and those tests run only on the 3.13 CI shard. Please add a test to `test/dynamo/test_exceptions.py` using `torch.compile(..., backend="eager", fullgraph=True)`, parametrized where it makes sense, that covers:
  - reading `e` after the `except E as e:` block (expects `UnboundLocalError`);
  - `del x` on an already-deleted local;
  - a graph break between the handler exit and a conditional later read of `e` (covers the resume path and the `< 3.12` assertion above);
  - deleting a tensor local, so the `_maybe_emit_sync_dealloc` path still runs before the tombstone is written.

  Running this on the 3.10 CI shard would have caught the issue above.

### Recommendation
**Request Changes**

The tombstone needs to be version-gated or handled on 3.10/3.11, and the fix needs a regression test in `test/dynamo/`.
