# [PR #198629] [dynamo] Fold literal boolean expressions passed to eval

## 正文

I reproduced this myself with a small script. Dynamo computes `eval()` of a constant string while tracing, but only if every piece of the expression is on an allowlist. `eval("2 + 3")` already worked, but `eval("1, 2 + 3")` and `eval("1 or (1 / 0)")` failed under `fullgraph=True` with `Unsupported` because the tuple and `or` were not on the list, so these were graph breaks. This PR adds only those pieces. Names and function calls must stay off the list: names can change, so the wrong result would be baked in. With this PR these expressions match eager under `fullgraph=True`.

> **AI-generated technical summary (Claude), reviewed by me:**
>
> Part of #195901 (fold literal Boolean expressions passed to `eval`).
>
> `BuiltinVariable.call_eval` evaluates constant strings at trace time: first with `ast.literal_eval`, then, when that fails, with a guarded evaluator whose AST allowlist (`_constant_eval_numeric_expr`) admits only numeric constants and arithmetic. Tuple and boolean-operation nodes were missing, so an expression like `1, 2 + 3` or `0 and 1, 2 or 3` graph-broke. This adds `ast.Tuple` (with its `ast.Load` context) and `ast.BoolOp`/`ast.And`/`ast.Or`. Names, calls and non-numeric constants remain excluded, and the evaluator still runs with empty `__builtins__`, so short-circuiting and errors behave as in CPython. A separate evaluator would duplicate the guarded path without improving its semantics. Results are the same in Python 3.12, 3.13 and 3.14.
>
> **Tests**
>
> - `test_misc.py::test_builtin_eval_literal_bool_expr`: under `fullgraph=True`, `eval("1, 0 or 1")`, `eval("0 and 1, 2 or 3")`, `eval("1 or (1 / 0)")` and `eval("0 and (1 / 0)")` match eager, including short-circuiting past `1 / 0`. Fails without the fix.
>
> CPython `test_grammar` under Dynamo: `GrammarTests.test_eval_input` goes from error to passing and no test goes from passing to failing; its expected-failure marker is removed. The other tests in `test/dynamo/test_misc.py` show the same results with and without the change.
