# [Issue #198579] torch.distributions.Normal.log_prob returns NaN for very large or very small scale because scale**2 overflows/underflows

source: https://github.com/pytorch/pytorch/issues/198579
state: open | updated: 2026-09-25T03:50:03Z
labels: module: distributions, triaged, module: edge cases, bot-triaged, release triage

## 正文

Description

`Normal.log_prob` squares `scale` (and `value - loc`) before dividing, so the intermediates overflow or
underflow long before the result does. In float32, `scale >= 2**64` (or `<= ~1e-23`) gives NaN for
ordinary points, and between about 1.3e19 and 2**64 the result is silently wrong (the `-0.5*z**2` term is
lost). In float64 the same happens beyond about 1e154 / below 1e-155.

### Steps to reproduce

```python
import torch
from torch.distributions import Normal
d = Normal(torch.tensor(0.0), torch.tensor(1.8446744073709552e19))
print(d.log_prob(d.loc + d.scale))                               # nan  (exact: -45.780)
print(Normal(torch.tensor(0.0), torch.tensor(1e-23)).log_prob(torch.tensor(0.0)))  # nan (exact: 52.04)
```

### Expected

A finite result equal to `-0.5*z**2 - log(scale) - 0.5*log(2*pi)`.

### Versions

Environment

PyTorch 2.14.0 (the latest release, CPU wheel) and 2.12.0, Python 3.12, Ubuntu 24.04, x86_64
