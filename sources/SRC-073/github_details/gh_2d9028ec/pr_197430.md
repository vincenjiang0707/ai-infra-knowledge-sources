## 正文

Summary:

Resolve AOTI constants by exact or unique wrapper-normalized FQN for compatibility with existing snapshots whose generated _run_on_acc/_run_on_gpu wrapper changed.

The `_run_on_acc_<n>` and `_run_on_gpu_<n>` components are generated by lowering partitioning, so wrappers may be added, removed, or renumbered when graph partitioning or ordering changes between otherwise compatible snapshot publishes. In the observed `1140807405/4 -> /17` transition, the cold-loaded AOTI delegate retained `merge.submod_0._run_on_acc_0...ln.weight`, while the replacement archive exposed the same tensor as `merge.submod_0...ln.weight`. The prior exact lookup therefore raised `<wrapper-qualified FQN> not found in Weights` and aborted the update before snapshot 17 became ready.

Also index each packed parameter, buffer, and tensor constant by its namespaced archive storage key. AOTI delegates retain that compatible-snapshot identity from the source snapshot and prefer it during inplace updates, so lowering-wrapper renames do not control weight matching. Storage-key ambiguity is derived directly from the multimap, and canonical ambiguity is derived directly from the current weight set, eliminating separately maintained ambiguity state.

Every update logs an exhaustive resolution breakdown: storage key, exact FQN, canonical FQN fallback, and optional constants retained. Constant metadata is read for both cold-loaded and cached-weight executors, so buffers, tensor constants, and empty parameters retain AOTI optional-update semantics in the child process while missing required parameters still fail.

This is runtime-only and requires no model input or publishing-config change.
