# [PR #198628] [dynamo] Constant-fold str and bytes maketrans

## 正文

I reproduced this myself with a small script. `str.maketrans("abc", "xyz")` builds a translation table that depends only on its arguments, so Dynamo can compute it once while tracing. Under `torch.compile` normal mode gave the right result, but `fullgraph=True` failed with `Unsupported`, so this is a graph break; a `ValueError` for arguments of different lengths also could not reach its `except`. Adding it to the table of methods that are computed while tracing is safe because the same input always gives the same table. A function whose result changes on every call, like reading the clock, must not go in that table: the wrong result would be baked in. With this PR both cases match eager under `fullgraph=True`.

> **AI-generated technical summary (Claude), reviewed by me:**
>
> Part of #195901 (`str.maketrans` and `bytes.maketrans`).
>
> `_BUILTIN_CONSTANT_FOLDABLE_METHODS` in `builtin.py` lists builtin methods that `BuiltinVariable` may evaluate at trace time when all arguments are constants. `str.maketrans` and `bytes.maketrans` were missing, so they graph-broke. Both are pure functions of their arguments, so they are added to the table; the existing constant conversion and observed-exception path then handles their results (a `dict` for `str`, a 256-byte `bytes` table for `bytes`) and their errors. A method-specific handler would duplicate that path without adding needed behavior. The error messages are the same in Python 3.12, 3.13 and 3.14.
>
> **Tests** (under `fullgraph=True`, each fails without the fix)
>
> - `test_misc.py::test_builtin_maketrans_constant_fold`: `str.maketrans` with a dict and with three strings, and `bytes.maketrans`, match eager.
> - `test_misc.py::test_builtin_maketrans_errors` (`str`, `bytes`): unequal-length arguments raise the same error as eager.
>
> CPython tests under Dynamo: `test_str` `StrTest.test_maketrans_translate` and `test_bytes` `BytesTest.test_maketrans` go from error to passing and no test goes from passing to failing in either file; the two expected-failure markers are removed. The other tests in `test/dynamo/test_misc.py` show the same results with and without the change.
