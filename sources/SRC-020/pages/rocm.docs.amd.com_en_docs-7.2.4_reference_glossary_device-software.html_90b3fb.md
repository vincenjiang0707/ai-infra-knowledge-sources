# Device software glossary[#](https://rocm.docs.amd.com#device-software-glossary)

2026-02-20

2 min read time

This section provides brief definitions of software abstractions and programming models that run on AMD GPUs.

- AMDGPU assembly
[#](https://rocm.docs.amd.com#term-AMDGPU-assembly) AMDGPU assembly (GFX ISA) is the low-level assembly format for programs running on AMD GPUs, generated by the

[ROCm compiler toolchain](https://rocm.docs.amd.com/host-software.html#term-HIP-compiler). See[AMDGPU assembly](https://rocm.docs.amd.com/projects/HIP/en/docs-7.2.4/understand/compilers.html#amdgpu-assembly)for instruction set details.- AMDGPU intermediate representation
[#](https://rocm.docs.amd.com#term-AMDGPU-intermediate-representation) AMDGPU IR is an intermediate representation for GPU code, serving as a virtual instruction set between high-level languages and

[architecture-specific assembly](https://rocm.docs.amd.com#term-AMDGPU-assembly). See[AMDGPU intermediate representation](https://rocm.docs.amd.com/projects/HIP/en/docs-7.2.4/understand/compilers.html#amdgpu-ir)for compilation details.- Global memory
[#](https://rocm.docs.amd.com#term-Global-memory) Global memory is the

[device-wide memory](https://rocm.docs.amd.com/device-hardware.html#term-GPU-RAM-VRAM)accessible to all[threads](https://rocm.docs.amd.com/device-hardware.html#term-Work-item-Thread), physically implemented as HBM or GDDR. See[Memory model](https://rocm.docs.amd.com/projects/HIP/en/docs-7.2.4/understand/programming_model.html#memory-hierarchy)for global memory details.- Grid
[#](https://rocm.docs.amd.com#term-Grid) A grid represents the collection of all

[work-groups](https://rocm.docs.amd.com/device-hardware.html#term-Work-group-Block)executing a single[kernel](https://rocm.docs.amd.com#term-HIP-kernel)across the entire GPU. See[Grid](https://rocm.docs.amd.com/projects/HIP/en/docs-7.2.4/understand/programming_model.html#inherent-thread-hierarchy-grid)for grid execution details.- HIP kernel
[#](https://rocm.docs.amd.com#term-HIP-kernel) A HIP kernel is the unit of GPU code that executes in parallel across many

[threads](https://rocm.docs.amd.com/device-hardware.html#term-Work-item-Thread), distributed across the GPU’s[compute units](https://rocm.docs.amd.com/device-hardware.html#term-Compute-units). See[Device programming](https://rocm.docs.amd.com/projects/HIP/en/docs-7.2.4/understand/programming_model.html#device-program)for kernel programming details.- HIP memory hierarchy
[#](https://rocm.docs.amd.com#term-HIP-memory-hierarchy) The memory hierarchy pairs each

[thread hierarchy](https://rocm.docs.amd.com#term-HIP-thread-hierarchy)level with corresponding memory scopes, from[private registers](https://rocm.docs.amd.com/projects/composable_kernel/en/docs-7.2.4/reference/Composable-Kernel-Glossary.html#term-register)to[LDS](https://rocm.docs.amd.com/device-hardware.html#term-Local-data-share)to[GPU RAM](https://rocm.docs.amd.com/device-hardware.html#term-GPU-RAM-VRAM). See[Memory model](https://rocm.docs.amd.com/projects/HIP/en/docs-7.2.4/understand/programming_model.html#memory-hierarchy)for memory architecture details.- HIP thread hierarchy
[#](https://rocm.docs.amd.com#term-HIP-thread-hierarchy) The thread hierarchy structures parallel work from individual

[threads](https://rocm.docs.amd.com/device-hardware.html#term-Work-item-Thread)to[blocks](https://rocm.docs.amd.com/device-hardware.html#term-Work-group-Block)to[grids](https://rocm.docs.amd.com#term-Grid), mapping onto hardware from[SIMD lanes](https://rocm.docs.amd.com/device-hardware.html#term-SIMD-core)to[compute units](https://rocm.docs.amd.com/device-hardware.html#term-Compute-units)to the entire GPU. See[Hierarchical thread model](https://rocm.docs.amd.com/projects/HIP/en/docs-7.2.4/understand/programming_model.html#inherent-thread-model)for complete details.- LLVM target name
[#](https://rocm.docs.amd.com#term-LLVM-target-name) The LLVM target name is a string identifier corresponding to a specific

[GFX IP](https://rocm.docs.amd.com/device-hardware.html#term-GFX-IP)version that is passed to the[HIP compiler](https://rocm.docs.amd.com/host-software.html#term-HIP-compiler)toolchain to specify the target GPU architecture for code generation. See[ROCm compiler reference](https://rocm.docs.amd.com/projects/llvm-project/en/docs-7.2.4/reference/rocmcc.html)for details.- ROCm programming model
[#](https://rocm.docs.amd.com#term-ROCm-programming-model) The ROCm programming model defines how AMD GPUs execute massively parallel programs using hierarchical

[work-groups](https://rocm.docs.amd.com/device-hardware.html#term-Work-group-Block), memory scopes, and barrier synchronization. See[Introduction to the HIP programming model](https://rocm.docs.amd.com/projects/HIP/en/docs-7.2.4/understand/programming_model.html#programming-model)for complete details.
