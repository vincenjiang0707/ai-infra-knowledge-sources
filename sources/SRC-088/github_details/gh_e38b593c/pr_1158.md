# [PR #1158] fix(loading): resolve Mamba-backbone verifier embedding key

source: https://github.com/vllm-project/speculators/pull/1158
state: closed | updated: 2026-09-23T21:12:52Z

## 正文

Fixes #1156.

## Problem
HF-format Mamba-backbone verifiers name the input embedding `backbone.embeddings.weight` (NemotronH — verified on the published Nano/Super/Ultra checkpoints; Mamba/Mamba2/FalconMamba per their transformers `modeling_*.py`). None of the current `embed_tokens.weight` candidates is a suffix of that key, so `_resolve_key` returns `None` and `SpeculatorModelBase._load_verifier_weights` raises `KeyError: 'embed_tokens.weight'`. Every algorithm loads the verifier embedding through that base method (eagle3/peagle, dflash/dflash2/dspark, mtp), so all are affected; reproduced end-to-end with eagle3 and dflash.

## Fix
Add `backbone.embeddings.weight` to `_WEIGHT_ALIASES["embed_tokens.weight"]`, following the per-architecture alias pattern of #989, #719, #1038. Kept specific (not a bare `embeddings.weight`) so the resolver's `endswith` scan can't misresolve unrelated tensors such as `position_embeddings.weight`. Standard `model.embed_tokens.weight` verifiers (llama/qwen/gemma, and llama-style hybrids Bamba/Jamba/Zamba2) are byte-unchanged — they match the primary candidate before the alias is consulted. Scope: HF/transformers-format checkpoints (original `mamba_ssm` exports use singular `backbone.embedding.weight`, out of scope).

## Tests
Adds resolver unit tests: the backbone key resolves, standard verifiers are unaffected, and boundary decoys (`position_embeddings.weight`/`word_embeddings.weight`) don't misresolve. `make quality` and `pytest tests/unit/utils/test_loading.py` pass locally.

Note: the open pretraining RFC (#1127) also reads the verifier embedding for the DFlash family, so it would hit the same gap once it lands.
