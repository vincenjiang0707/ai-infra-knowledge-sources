# [PR #1129] fix(train): resolve per-layer config attrs for heterogeneous verifiers

## 正文

## Purpose

Fixes #1118.

`speculators train` crashes at config-build time on a **heterogeneous per-layer verifier config** (transformers ≥5.15, e.g. `google/gemma-4-31B-it`). `create_transformer_layer_config` reads `head_dim` / `num_key_value_heads` off the **global** verifier config; on heterogeneous configs transformers raises `AmbiguousGlobalPerLayerAttributeError`, which subclasses `RuntimeError` (not `AttributeError`), so `getattr(config, "head_dim", None)` does **not** swallow it. Fixing only `head_dim` just moves the crash to `num_key_value_heads`.

These reads only seed the draft's *own* default attention block (this branch is skipped under `--draft-config` / `--from-pretrained`), so there is no ground-truth per-layer value to recover — just a default to pick. When the verifier `is_heterogeneous`, this resolves the affected attributes — driven off `verifier_config.per_layer_attributes`, not a hardcoded list — from the single **modal** (most common) layer. That gives a leaner/faster draft (draft latency is on the spec-decoding critical path) and matches the published `RedHatAI/gemma-4-31B-it-speculator.dflash` draft geometry (`head_dim=256`, `num_key_value_heads=16`). A scoped `num_attention_heads % num_key_value_heads == 0` check guards a future config that also varies query-head count. Homogeneous configs are unchanged.

Only `train/cli.py` is affected — the other `head_dim` reads (`models/dflash`, `models/eagle3`, `convert/eagle`) operate on the drafter's own homogeneous config or a plain dict.

## Tests

Added unit tests in `tests/unit/train/test_draft_config_init.py` with a fake heterogeneous config: modal resolution, a no-global-read guarantee, and the divisibility invariant.

```
$ python -m pytest tests/unit/train/test_draft_config_init.py -q
55 passed

$ make quality
ruff check / ruff format / mdformat / mypy / sync_provenance  -> all pass
```

Full `tests/unit` run: **1005 passed, 5 failed** — the 5 are pre-existing `@requires_multi_gpu` distributed tests failing with an environment-specific NCCL/CUDA error, unrelated to this change (they never call `create_transformer_layer_config`).

Also verified end-to-end that `create_transformer_layer_config(verifier_name_or_path="google/gemma-4-31B-it", draft_arch="llama", ...)` now builds a draft config (`head_dim=256`, `num_key_value_heads=16`, `num_attention_heads=32`, `hidden_size=5376`) where mainline raises.
