# [PR #1141] Treat layer_types and sliding_window as optional in DFlash

## 正文

## Purpose

Fixes #1138.

`DFlashSpeculatorModel.__init__` reads `tl_config.layer_types` and `tl_config.sliding_window` unconditionally. Both are optional in `transformers` — declared only when attention alternates, or when there is a window — so DFlash raises `AttributeError` in its constructor for verifiers with uniform global attention, before any draft layer is built.

Behaviour is unchanged for configs that declare them; `uses_sliding_window_attn` stays `False` for those that don't.

## Tests

```python
from transformers import AutoConfig

for model_type in ("mistral", "olmo2", "starcoder2"):
    config = AutoConfig.for_model(model_type)
    print(model_type, hasattr(config, "layer_types"), hasattr(config, "sliding_window"))
```

All three report `False False`. Constructing a `DFlashSpeculatorModel` with any of them as `transformer_layer_config` raises `AttributeError: 'MistralConfig' object has no attribute 'layer_types'` before this change, and succeeds after it.

### Hyungkeun-Park · 2026-09-18

Adding a tighter reproduction, since the one above reaches for Mistral and this is simpler: a plain `LlamaConfig` draft hits it too, on `main`.

```python
from transformers import AutoConfig
from speculators.models.dflash.core import DFlashDraftModel
from speculators.models.dflash.config import DFlashSpeculatorConfig
from speculators.config import SpeculatorsConfig, VerifierConfig
from speculators.proposals.greedy import GreedyTokenProposalConfig

c = AutoConfig.for_model("llama", num_hidden_layers=1, hidden_size=64, intermediate_size=128,
                         num_attention_heads=4, num_key_value_heads=2, vocab_size=256)
c._attn_implementation = "eager"
DFlashDraftModel(config=DFlashSpeculatorConfig(
    transformer_layer_config=c, draft_vocab_size=256, block_size=4,
    aux_hidden_state_layer_ids=[0], mask_token_id=3,
    speculators_config=SpeculatorsConfig(
        algorithm="dflash", proposal_methods=[GreedyTokenProposalConfig(speculative_tokens=3)],
        default_proposal_method="greedy",
        verifier=VerifierConfig(name_or_path=None, architectures=["T"]))))
# AttributeError: 'LlamaConfig' object has no attribute 'sliding_window'
```

`AutoConfig.for_model("llama")` declares neither `layer_types` nor `sliding_window`; `qwen3` declares both, which is why `--draft-arch qwen3` never shows it. `create_transformer_layer_config` sets both explicitly, so the synthesized path is fine — `--draft-config` pointing at an ordinary Llama config is the one that fails.
