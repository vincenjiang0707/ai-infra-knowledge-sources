# [PR #1165] fix(loading): resolve Mamba-backbone verifier final-norm key

source: https://github.com/vllm-project/speculators/pull/1165
state: open | updated: 2026-09-25T00:45:17Z
labels: 

## 正文

**Purpose.** DFlash/DFlash2/DSpark carry a frozen `verifier_norm` and load the verifier's final
norm as `model.norm.weight`. HF Mamba-backbone verifiers (NemotronH — Nano/Super/Ultra —,
Mamba/Mamba2, FalconMamba) name it `backbone.norm_f.weight`, which the alias map doesn't resolve. On
a real checkpoint the bare `norm.weight` alias then suffix-matches a per-layer
`backbone.layers.N.norm.weight` and loads it as the final norm — silently, no warning (the quieter
secondary case, a checkpoint with only `backbone.norm_f.weight`, falls back to identity `weight=1.0`).
Either mis-scales the reconstructed targets (cf. #1090). Measured on Nemotron-3-Nano: the tensor
`main` actually loads reconstructs the verifier's top-1 target correctly only **65.0%** of the time,
vs a **99.6%** sanity gate for the correct norm. Fixes #1164.

**Fix.** Add `backbone.norm_f.weight` to `_WEIGHT_ALIASES["model.norm.weight"]`, ordered before the
bare `norm.weight` suffix so the specific final-norm key wins over per-layer norms. Follows the
per-architecture alias pattern of #1158 (embedding), #719, #989. Standard verifiers are byte-unchanged.

**Tests.** Resolver unit tests: final norm resolves; not confused with per-layer norms; standard
`model.norm.weight` unaffected. `ruff` clean; `pytest tests/unit/utils/test_loading.py` green.
