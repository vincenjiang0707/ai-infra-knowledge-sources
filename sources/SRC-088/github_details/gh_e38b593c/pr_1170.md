## 正文

## Purpose



Remove named raw-dataset presets from `prepare-data`, **because it's legacy off-policy path (this is wrong!), and we should not support it**. 

This applies to all registered names, including `sharegpt`, `ultrachat`, and `gsm8k`: loading them directly uses the source dataset's answers instead of responses regenerated by the target model.

**`regenerate-responses` keeps its existing preset support and normalizers.** Pass its generated JSONL to `prepare-data`. Explicit files and Hugging Face sources remain accepted; callers are responsible for supplying target-model responses.

Start the review in `preprocessing.py` (**+12 / −33**): delete the preset-loading branch and the normalization callback. Keep the existing `(dataset, None)` return shape so callers need no API migration.

The remaining edits keep existing consumers working:

- The existing multimodal tests used `load_raw_dataset("sharegpt4v_coco")` ([upstream call](https://github.com/vllm-project/speculators/blob/ca13206b7399cc54ee1fecf7a4c233741121289d/tests/e2e/utils.py#L318)). Their setup now loads the same fixture explicitly and passes a JSONL file to preparation. No new dataset support or test cases are added here; multimodal regeneration remains unsupported.
- The preset-loading test becomes a rejection test for every registered name.
- Two training examples run the existing regeneration helper first, then prepare its generated JSONL. Correct the documentation and error message that recommended passing presets to preparation.

1/n of #893.

## Tests

- **142 passed** across preparation, source loading, regeneration, CLI, and render-boundary suites.
- `make quality` passed.
- **4 GPU E2E smoke tests passed** in 11m 55s: online/offline training for Qwen3-0.6B and Qwen3-VL-2B-Instruct, followed by vLLM inference from each trained checkpoint. Run on one B300 with PyTorch 2.13.0+cu130 and vLLM 0.30.0.
- These are 50-sample, one-epoch smoke tests. Nightly acceptance-threshold regressions were not run.

### Security Architecture Review

**Security architecture risk:** _🟡 Moderate_ · up to `ba169`

Rejecting raw presets closes an off-policy preparation path. The new example workflows can nevertheless reuse earlier generated responses or continue after some responses fail, without confirming that the data prepared for training belongs to the current run.

**Retained concerns**
- **Medium · architecture · inferred:** The newly automated training workflows can treat a reused JSONL as regenerated for the current target model, or proceed with successful rows after other conversations fail, without validating the artifact's provenance or completion before preparation.

<details>
<summary>Security review details</summary>

**Security Blast Radius**
- _inferred_ — The identified exposure is integrity of the generated training artifact and its downstream consumers in these example runs. The evidence does not establish new tenant, credential, IAM, or externally reachable network exposure.

**Security Findings and Attack Paths**
- _inferred_ — If an earlier JSONL remains at an example's output path, source-ID-only resume can carry its rows into the current run without establishing that they came from the current target model. No lower-privilege attacker path to that file was established.

**Trust Boundaries and Controls**
- _observed_ — The producer specifies the requested model in generation requests and records endpoint and sampling metadata, while the preparation consumer does not bind tokenized rows to a model identity. Its acceptance of explicit input files predates this change.

**Resilience and Maintainability Implications**
- _inferred_ — Per-conversation failure isolation protects the training file from ordinary failed conversations, but the new examples can proceed after such errors because the wrapper gates on process exit rather than an error-free generation result.

**Hardening Proposals**
- _proposed_ — Bind reusable generation output to the source and target-model configuration, require an acceptable completion result before preparation, and invalidate prepared output when its input changes.
