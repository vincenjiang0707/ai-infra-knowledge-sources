# [PR #1131] fix(eagle3): fail conversion on unmatched checkpoint keys instead of saving random weights

## 正文

## Description

Eagle3 conversion silently persisted randomly initialized weights whenever a checkpoint key did not match the model: `Eagle3Converter._save_converted_checkpoint` logged missing and unexpected `load_state_dict` keys as warnings and saved anyway, so any weight the checkpoint failed to provide remained at its random initialization on disk. This is the failure mode behind #358 and #360, where a lost remap produced a checkpoint that converted cleanly and only surfaced as zero acceptance during evaluation.

This change mirrors the MTP and DFlash converters by raising `ValueError` on unexpected keys and on missing keys, since the detached conversion flow fills no weights after load and every model-owned key must come from the checkpoint; the issue reporter verified that all 48 valid flag combinations load with zero missing and unexpected keys, so valid conversions are unaffected. Unit tests cover a renamed checkpoint key, a missing draft layer weight, and a happy path asserting saved tensors equal the source weights.

Fixes #1114
