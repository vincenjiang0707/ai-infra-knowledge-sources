## Summary

- Implement JetSpec (arxiv 2606.18394), a causal parallel draft head that predicts all block positions in a single forward pass using causal attention within blocks
- Unlike DFlash's bidirectional blocks, JetSpec conditions each position on earlier positions in the block, enabling tree-structured candidate generation at inference time
- Reuses DFlash's decoder layers and utilities but with causal attention masking, actual token inputs (instead of mask tokens), and standard next-token prediction alignment

## Key differences from DFlash

| Aspect | DFlash | JetSpec |
|--------|--------|---------|
| Block attention | Bidirectional | Causal |
| Block input | Mask tokens | Actual tokens (teacher forcing) |
| Target alignment | Roll-shifted | Standard next-token |
| Position 0 loss | Excluded | Included |
| Default block_size | 8 | 16 |

## Design-level assessment

The JetSpec model is well-structured and correctly captures the key architectural differences from DFlash: causal (not bidirectional) attention within blocks, actual-token inputs (teacher forcing) instead of mask tokens, standard next-token target alignment (no roll-shift), and position-0 inclusion in loss. Code is clean, reuses DFlash infrastructure appropriately, and follows the repo's existing patterns.

However, there is **one crash bug** that will prevent training from running, plus a few other issues.

### Missing tests

This PR adds 543 lines of new model code — attention masking, forward pass, loss computation — with zero new tests. The causal block mask is the architectural novelty and needs dedicated tests (e.g., verify a position can attend to earlier positions in its block but not later ones). The target alignment difference from DFlash (no roll-shift) should be tested. The loss computation with position-0 included should be tested. At minimum:

- `test_causal_block_mask`: verify causal vs bidirectional attention pattern
- `test_target_alignment`: verify `anchored_block_indices` produces correct targets without roll-shift
- `test_jetspec_loss_decay`: verify decay weights, including edge cases (gamma=0)
- `test_forward_smoke`: basic forward pass shape/dtype checks

### vLLM integration note

The PR description says "Maps to DFlash inference pathway via `algos.py` registration" but no `algos.py` is modified. It also says "Full tree-aware proposer deferred to future work." These are contradictory — worth clarifying the description to avoid confusion during review.
