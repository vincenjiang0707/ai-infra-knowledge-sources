## 正文

## What

`_build_hierarchy_info` recursively walks `group_subtasks` to build the result table's display hierarchy, with no cycle detection. A cycle reachable from a root recurses until Python raises `RecursionError` — potentially *after* an evaluation has already completed, losing the results display at the last step. A cycle with no distinct root is never visited by the root-based traversal at all, so its members are silently flattened in as unrelated top-level entries instead of surfacing the malformed config.

## Fix

Track the current recursion stack during the walk and raise a descriptive `ValueError` as soon as a back-edge is detected — before any recursive display ordering begins. After the root-based walk, any `group_subtasks` key never reached is provably part of a cycle with no distinct root (every group is either a root or a descendant of one), so that case is rejected too instead of silently flattening. Uses a plain `ValueError` with a clear message rather than a new exception class, matching this codebase's existing convention (no custom exception types exist elsewhere in `lm_eval`). Valid non-cyclic hierarchies are unaffected.

## Testing

Added 3 tests to `tests/test_evaluator.py`: the exact reachable-cycle repro from the issue, the no-root-cycle variant, and a valid non-cyclic hierarchy (parent/child/standalone) proving no regression. `python -m pytest tests/test_evaluator.py -v -k "hierarchy or make_table"` → 5 passed (3 new + 2 pre-existing `make_table` regression tests unchanged). `ruff check` / `ruff format --check` clean on both changed files (diffed against unmodified `main` to confirm zero new findings).
