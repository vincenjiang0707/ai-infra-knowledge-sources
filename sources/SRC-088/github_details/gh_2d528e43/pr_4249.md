## Summary

**Advances #2682** (reasoning-model support), **addresses the extraction half of #3129**.

Reasoning-style models emit a `<think>...</think>` trace before the answer. Two failure modes follow:

1. Task stop sequences (often the fewshot delimiter `\n\n`) occur *inside* the trace and truncate the generation before any answer is produced. The vLLM and TRT-LLM backends already accept a `think_end_token` model argument for this (stops are withheld from the engine; the trace is stripped afterwards).
2. Extraction filters downstream must not have to match through the trace — and until now there was **no backend-independent equivalent** at the task/filter layer, so `hf`-backend and API users (the default path for both linked issues) had no supported route.

This PR adds that portable layer.

## The filter

```yaml
filter_list:
  - name: "strip-thinking"
    filter:
      - function: "strip_think"
      - function: "regex"
        regex_pattern: "#### (-?[0-9.,]+)"
```

Semantics:

- complete `<think>...</think>` blocks: everything up to and including the **first** end token is discarded
- **unclosed leading** `<think>` (generation truncated mid-trace): the block is stripped, yielding an empty answer — visible, not silently scored against trace text
- applied **per draw** under `repeats > 1`
- configurable end token (`</reasoning>`-style variants)
- registered at the filter layer, so behavior is identical across `hf`, `vllm`, `trtllm`, and API backends

## For #3129 specifically

The reporter's setup (Qwen3-32B, `hf` backend, GSM8K CoT, harness score 0.63–0.71 vs 0.92 published) combines both failure modes: the trace trips stop sequences and buries the answer from the strict-match regex. With this filter plus the documented settings (raised `max_gen_toks`, careful stops, flexible extract for paper comparison), the extraction half is solved at the task layer on the default backend. The remaining gap is generation-side truncation, which the `think_end_token` backend argument addresses where available.

## Testing

11 tests in `tests/test_think_filter.py`: closed blocks, multiline traces, unclosed leading blocks, no-block passthrough, per-draw application under repeats, custom end tokens, first-block split semantics, defensive passthrough, chaining into regex extraction, and registry resolution via package import. All pass; `test_metrics.py`, the repeats suite, and the mmlu_generative filter suite pass unchanged.
