# [PR #4239] fix(gguf): forward per-request temperature to llama.cpp

## 正文

`GGUFLM._generate_one` normalizes the request's `gen_kwargs` but reads only `max_gen_toks` out of the result, so `gguf_completion` always sends `self.temperature`, the `model_args` value fixed in `__init__` (default `0.0`). A task whose `gen_kwargs` ask for sampling, e.g. `{temperature: 0.7, do_sample: true}` on the math and self-consistency tasks that use `repeats > 1`, is decoded greedily on the `gguf`/`ggml` backend with no warning, so repeated samples come back identical and majority-vote/pass@k numbers understate the model's real variance. The `hf`, `vllm` and `openai_completions` backends all read the `temperature` that `normalize_gen_kwargs` returns; gguf is the outlier that drops it.

What changed:

- `gguf_completion` takes an optional `temperature` and falls back to the constructor value when the caller passes none, so behaviour with no task `gen_kwargs` is identical to today.
- `_generate_one` forwards the normalized `temperature` along with `max_gen_toks`.

Loglikelihood scoring is untouched: `_score_position` still sends `temperature: 0` for exact teacher forcing.

Testing:

- New `test_generate_until_forwards_temperature` checks the temperature that reaches the request payload for three requests: `{temperature: 0.8, do_sample: true}` -> `0.8`, `{temperature: 0.8, do_sample: false}` -> `0.0`, and `{}` -> the `model_args` value. It fails on main (`[0.3, 0.3, 0.3]`) and passes with this change.
- `python -m pytest tests/models/test_gguf.py` (13 passed), plus `ruff check` and `ruff format --check` on both files.

AI assistance (Claude) was used to draft this change; the tests listed above were run locally on this branch.
