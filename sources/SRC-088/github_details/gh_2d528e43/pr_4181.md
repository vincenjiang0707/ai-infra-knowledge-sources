## PR Title
fix(cli): strip whitespace from keys in `key_val_to_dict` (#4147)

## PR Body
## Summary
- `key_val_to_dict()` in `lm_eval/_cli/utils.py` did not strip whitespace from keys, so a CLI argument like `--model_args "do_sample=false, temperature=1.0"` produced a key `" temperature"` (with leading space) instead of `"temperature"`.
- This affected all seven flags using `MergeDictAction`: `--model_args`, `--gen_kwargs`, `--metadata`, `--wandb_args`, `--wandb_config_args`, `--trackio_args`, `--hf_hub_log_args`.
- The bug was silent: downstream consumers received the wrong keyword name, causing valid arguments to be ignored or rejected depending on the consumer.

## Fix
Added `k = k.strip()` after splitting the key/value pair, plus validation to reject empty keys after stripping (e.g., `"=1"` or `"a=1, =2"`).

```python
k, v = item.split("=", 1)
k = k.strip()
if not k:
    raise ValueError(f"empty key in {item!r}")
v = handle_cli_value_string(v)
```

Value whitespace is preserved (unchanged behavior) — only keys are stripped.

## Testing
- Added 7 new test cases in `tests/test_cli_utils.py`:
  - Basic whitespace stripping: `"do_sample=false, temperature=1.0"`
  - Multiple spaces: `"a=1,  b=2,   c=3"`
  - Tab whitespace: `"a=1,\tb=2"`
  - Empty key rejection: `"=1"` and `"a=1, =2"`
  - Value whitespace preservation: `"key = value with spaces"`
  - Quoted values with spaces: `'a="hello world", b=2'`
  - Signed integers still work (existing test)
