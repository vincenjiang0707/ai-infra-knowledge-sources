## 正文

## Summary

Makes `repeats` usable for sampling-based evaluation (self-consency / pass@k) from the Python API, and fixes the silent config bug that broke it.

**Fixes #3297** (repeats from the Python API: now a first-class `simple_evaluate` kwarg). **Addresses #3339** (see scoping note below).

- **`simple_evaluate(repeats=N)`** — a new kwarg that overrides `TaskConfig.repeats` for all tasks, mirroring the existing `num_fewshot` override.
- **Fixes silent `TaskConfig` field loss** — `ConfigurableTask.__init__` unpacked a passed `TaskConfig` object as `**kwargs`, which reads only its *dict items*; every dataclass field (including `repeats`) silently reset to its default before reaching the evaluator. `TaskConfig` instances are now copied with `copy.copy`; plain-dict configs are unchanged.
- **New `pass_at_k` metric** — the fraction of documents where *any* of the k sampled responses exactly matches the target; pairs with the existing `take_first_k` filter for any-correct scoring.
- **Loud warning when repeats are discarded** — with `repeats > 1` on a `generate_until` task and no custom `filter_list`, the default `take_first` filter throws away all but the first of the sampled responses. This was previously logged at debug level; it now warns with actionable guidance.
- **Docs** — a self-consency recipe (majority voting and pass@k filter pipelines) in `docs/config_files.md`.

## Scoping note for #3339

The reporter's route — passing `repeats` inside the `Instance` metadata tuple — is a separate path the harness does not act upon (nothing reads repeats from metadata; the count is taken from `TaskConfig.repeats` at request-build time). This PR does not change metadata handling; instead it provides the supported route (`simple_evaluate(repeats=N)` or `TaskConfig(repeats=N)`) and fixes the config-object path that silently dropped it. If maintainers prefer, the metadata route could raise or warn instead of being silently ignored — happy to add that here if wanted.

## Root-cause demonstration

```python
from lm_eval.config.task import TaskConfig
cfg = TaskConfig(repeats=8)
cfg.repeats                   # 8
TaskConfig({**cfg}).repeats   # 1  <- every field lost in the dict unpack
```

## Testing

22 new tests in `tests/test_repeats_aggregation.py`:

- `pass_at_k` metric: any-correct, one-of-k, none, k=1 degenerate, bare-string (take_first path), mixed docs, non-string gold coercion
- `majority_vote`: modal selection, first-encountered tie-break, unanimous, single response
- `take_first_k`: keeps first k, raises with actionable message on insufficient repeats
- extraction-then-vote chaining (the documented recipe)
- `take_first` regression at repeats=1
- config roundtrip regression: a `TaskConfig` object preserves `repeats` through construction; dict configs unchanged
- discard warning: fires at repeats=4 naming `majority_vote`/`pass_at_k`; silent at repeats=1
- `simple_evaluate` signature exposes `repeats`

All 22 pass; `tests/test_metrics.py` and `tests/test_evaluator_utils.py` (102 tests) pass unchanged.

## Notes for reviewers

- The `filter_list` key already supports `majority_vote` and `take_first_k`; this PR makes them *reachable* (config loss fix), *scoreable* (`pass_at_k`), and *safe* (the warning).
- The config-copy change is behavior-preserving for dict configs and for `TaskConfig` objects that set fields via constructor or attribute; the only observable change is that fields previously lost now survive — which is the fix.
