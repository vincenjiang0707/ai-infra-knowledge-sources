## What

Adds `tests/models/test_utils_hf.py`, covering `lm_eval/models/utils_hf.py`, which previously had no direct tests.

`utils_hf` is imported by six HuggingFace backends — `huggingface.py`, `hf_vlms.py`, `hf_audiolm.py`, `mamba_lm.py`, `neuron_optimum.py`, `optimum_ipex.py` — so a regression in its padding or dtype handling would otherwise only surface through slow, GPU-dependent model runs.

## Coverage

`pad_and_concat`
- right padding and left padding produce the expected `(batch, max_length)` layout
- a tensor already at `max_length` is returned unpadded
- a `[1, seq]` shaped tensor is squeezed before padding, as the backends pass
- an unrecognized `padding_side` raises

`get_dtype`
- `"float16"` / `"bfloat16"` / `"float32"` convert to the matching `torch.dtype`
- `"auto"` passes through untouched (it is resolved later against an instantiated HF `AutoConfig`)
- a `torch.dtype` argument passes through untouched

`MultiTokenEOSCriteria` / `stop_sequences_criteria`
- stays `False` until every row in the batch has matched, and flips to `True` once they all have
- `done_tracker` is updated per row
- `sequence_id_len` keeps the documented `len(sequence) + 2` lookback
- `stop_sequences_criteria` builds one criteria per stop sequence

## Notes

- `MultiTokenEOSCriteria` is exercised through a small one-token-per-character stub tokenizer rather than a real one, so the tests stay offline and deterministic in CI. The criteria only depends on `encode` and `batch_decode`.
- `clear_torch_cache` is deliberately not covered — it calls `torch.cuda.empty_cache()` and needs a GPU.
- Everything else runs on CPU.
