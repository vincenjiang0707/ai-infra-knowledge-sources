## 正文

Fixes #4243

`MODEL_MAPPING` advertised `lm_eval.models.hf_audiolm:HFAudioLM`, but the class in that module is `HFAUDIOLMQWEN`. Since #4013 the registry rejects a placeholder whose path differs from the real object's path, so merely importing the module now raises:

```
ValueError: 'model' alias 'hf-audiolm-qwen' already registered
  (existing=lm_eval.models.hf_audiolm:HFAudioLM,
   new=<class 'lm_eval.models.hf_audiolm.HFAUDIOLMQWEN'>)
```

### Change

```diff
-    "hf-audiolm-qwen": "lm_eval.models.hf_audiolm:HFAudioLM",
+    "hf-audiolm-qwen": "lm_eval.models.hf_audiolm:HFAUDIOLMQWEN",
```

### Verification

Before / after on `main` (d6de8164), Python 3.12, same interpreter, no accelerator involved:

```
# before
$ python -c "import lm_eval.models.hf_audiolm"
ValueError: 'model' alias 'hf-audiolm-qwen' already registered (...)
$ python -c "from lm_eval.api.registry import get_model; get_model('hf-audiolm-qwen')"
ValueError: 'model' alias 'hf-audiolm-qwen' already registered (...)

# after
$ python -c "import lm_eval.models.hf_audiolm as m; print(m.HFAUDIOLMQWEN)"
<class 'lm_eval.models.hf_audiolm.HFAUDIOLMQWEN'>
$ python -c "from lm_eval.api.registry import get_model; print(get_model('hf-audiolm-qwen'))"
<class 'lm_eval.models.hf_audiolm.HFAUDIOLMQWEN'>
```

### Not tested

No Qwen2-Audio weights were downloaded — this change is only about the registry/import path.

(While reproducing this I also noticed that `HFAUDIOLMQWEN.generate_until()` hard-codes `.to("cuda")` for the input ids, which breaks the model on non-CUDA accelerators such as Ascend NPU. That is a separate defect, so I will send it as its own PR rather than widen this diff.)
