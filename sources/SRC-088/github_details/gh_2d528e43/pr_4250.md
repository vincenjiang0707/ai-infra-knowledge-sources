## Summary

**Fixes #3196.** Backends that post-process generated text — vLLM and TRT-LLM stripping `<think>` traces via `think_end_token` — discarded the raw generation, so `--log_samples` output could not show reasoning traces even for analysis. The reporter's use cases (studying reasoning processes, chain-of-thought quality, prompt debugging) need exactly what was being thrown away.

## The change

- `Instance` gains a `raw_resps` list alongside `resps`
- vLLM's `generate_until` captures the unmodified generation **before** `postprocess_generated_text` strips it, reorders it with the same `Collator` index map as the processed results, and attaches it to the request instances
- The evaluator's logged samples include `raw_resps` when any instance carries one — absent otherwise, so runs without post-processing backends see no change in their logs
- `result_schema` marks the field optional
- Docs: a short section on the field

No scoring behavior changes: `resps` and `filtered_resps` are byte-identical; this only adds the raw text alongside.

## Testing

8 tests in `tests/test_raw_resps.py`:

- `Instance` default/append semantics for `raw_resps`
- raw survival through `postprocess_generated_text` (the stripped vs. unmodified outputs shown side by side)
- parallel `Collator` reordering preserving index-wise pairing — the mechanism the capture relies on (raw[i] is the unmodified generation of the request whose processed output is resps[i])
- instance attachment in original order
- the logged-sample dict includes `raw_resps` when present, omits it when absent
- a vllm-free static source contract asserting the capture happens **before** the stripping call and the attachment before return

All pass; `test_metrics.py` unchanged.

## Complements

- #4249 (the `strip_think` filter) makes trace-stripping available at the task layer for every backend; this PR makes the raw trace *recoverable from logs* when backends strip. Together they close the loop for reasoning-model analysis.
