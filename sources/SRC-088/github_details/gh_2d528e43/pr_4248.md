## Summary

**Fixes #2279.** The `mmlu_generative` `get_response` filter chain kept the whole first line of each generation, so any answer format other than a bare letter scored `exact_match = 0` even when the model's choice was correct:

| generation (first line) | filtered (before) | scores (before) | filtered (now) | scores (now) |
|---|---|---|---|---|
| `A` / `a` | the letter | ✅ | the letter (unchanged) | ✅ |
| `A.` `A)` `(A)` `a)` | whole line | ❌ 0 | the letter | ✅ |
| `Answer: A` `answer is B` `option: D` | whole line | ❌ 0 | the letter | ✅ |
| `The answer is B` | whole line | ❌ 0 | the letter | ✅ |
| `A. foo` `Because Paris` `""` | whole line | ❌ 0 | `[invalid]` fallback | ❌ 0 (score-equivalent) |

This is the mechanism behind the reporter's all-zero run: the template defaults to zero-shot, base models answering zero-shot almost never emit a bare letter (they continue the passage), and every such response scored exactly 0 across all 57 subtasks.

## The change

One added step in the filter chain (`lm_eval/tasks/mmlu/generative/_default_template_yaml`):

```yaml
- function: "regex"
  regex_pattern: "(?i)(?:^\\W*|answer\\s*(?:is)?\\s*[:\\-]?\\s*|option\\s*[:\\-]?\\s*)\\(?([A-D])\\)?\\W*$"
```

Design properties, each asserted by tests:

- **Bare-letter behavior is byte-identical** — well-formed responses filter to exactly what they did before.
- **Fallback lines are score-equivalent** — every line the regex does not match was already scoring 0 under whole-line comparison against a bare-letter target; it now scores 0 via the `[invalid]` fallback (verified per-case with `exact_match_hf_evaluate` itself).
- **Ambiguity is refused, not guessed** — `A. foo` does not silently become `A`; only an isolated A-D letter (optionally decorated or behind an answer lead-in) is extracted.

## Testing

26 tests in `tests/test_mmlu_generative_filter.py`:

- the 13-case extraction matrix (bare, decorated, lead-ins, lowercase)
- 6 fallback cases (elaborations, continuations, multi-token, empty)
- multiline generations take the first line, then extract
- bare-letter invariance
- score equivalence for fallback lines against the pre-fix comparison
- a yaml-sync guard that fails if the template and the test chain drift

All 26 pass; `tests/test_metrics.py` and the repeats suite pass unchanged.

## Notes

- No code changes — the fix is a task-template filter step plus tests.
- The `[invalid]` fallback also makes unparseable responses visible in `log_samples` output instead of hiding inside a full-line mismatch.
