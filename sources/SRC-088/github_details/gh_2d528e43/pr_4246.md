# [PR #4246] Keep the stderr of a nanmean metric from collapsing to NaN

source: https://github.com/EleutherAI/lm-evaluation-harness/pull/4246
state: open | updated: 2026-09-27T01:25:30Z
labels: 

## 正文

A task that aggregates with `nanmean` gets a bootstrap standard error, because `nanmean` is on the bootstrappable list in `stderr_for_metric`. Resampling the raw per-sample values can draw a replicate that holds no usable value at all, and `nanmean` reports NaN for that replicate — a single one of them makes the entire standard error NaN, silently, while the point estimate of the same run is a perfectly good number.

It is reachable in normal use, not just in theory. `nanmean` was added for the healthcare tasks (7c9fbcf8) precisely because their per-sample scores come back NaN, and eight task configs use `aggregation: nanmean` today (`medtext`, `olaph`, `meqsum`, `careqa_open`, `mts_dialog`, `mimic_repsum`, `mediqa_qa2019`, `meddialog`). How often it bites depends on the NaN share and the sample count:

| NaN share | samples | replicates that are NaN | stderr |
|---|---|---|---|
| 0.5 | 100 | 0 / 1000 | 1.61 |
| 0.7 | 20 | 1 / 1000 | `nan` |
| 0.9 | 20 | 111 / 1000 | `nan` |

With eighteen of twenty samples NaN the point estimate is `1.5` and the reported stderr is `nan` — the number a reader would use to judge whether `1.5` means anything is exactly the number that got lost.

The fix resamples the usable values for `nanmean` only. When there are none, `nanmean([])` is NaN and the standard error stays NaN as before, so an all-NaN run is unchanged; no other bootstrappable metric is touched.

Test: `pytest tests/test_metrics.py` fails on `main` with `assert not math.isnan(...)` → `nan` for `test_bootstrap_stderr_drops_replicates_the_statistic_could_not_evaluate`, and passes on this branch (10 passed). A second test pins that `mean` still reports NaN here, i.e. the change is scoped to `nanmean`; it passes on both sides. Also ran `pytest tests/test_aggregation_pipeline.py tests/test_evaluator_utils.py tests/test_misc.py` (85 passed), and `ruff check` / `ruff format --check` on the two changed files — no new findings versus `main`, and both files are already formatted.

Related but separate: #4221 speeds up the bootstrap for binary `f1`/`mcc` and adds a separate `_binary_count_bootstrap`; it does not touch `stderr_for_metric` or the NaN handling.
