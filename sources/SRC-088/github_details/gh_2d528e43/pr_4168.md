# [PR #4168] fix(task): exclude the evaluated doc when the few-shot pool falls back to its split

## 正文

Fixes #4145.

## What was wrong
`fewshot_context()` passes the evaluated document to the sampler for exclusion only when `fewshot_cfg.split == config.test_split`. When a task sets no `fewshot_split`, `fewshot_docs()` falls back to train, then validation, then test — but `fewshot_cfg.split` stays `None`. For a test-only task the pool is the test split, the comparison is `None == "test"`, and the sampler gets `eval_doc=None`. The evaluated document can then appear as its own demonstration, gold answer included.

Reproduced on `main` (`d6de8164`) with a real `ConfigurableTask` (3 test-only docs, `num_fewshot=2`): 3 of 3 prompts contained their own question and answer among the demonstrations.

## Fix
A small helper, `_fewshot_pool_is_eval_split(config, fewshot_cfg)`, resolves the split `fewshot_docs()` actually draws from (same fallback order) and compares it with the split being evaluated (test, else validation). The existing condition is kept and OR-ed with it, so every task that already passed `eval_doc` keeps doing so and its sampling stream is unchanged; only the cases that leaked change:
- no `fewshot_split`, no train/validation split, test split set (the #4145 case);
- explicit `fewshot_split` equal to `validation_split` on a task with no test split (follows from the helper's logic; not covered by a dedicated test).

The helper takes `config` and `fewshot_cfg` rather than `self` so the existing mock-based `test_sampler_no_exclusion_when_different_split` keeps passing (a method version broke it, because `self` is a `Mock` there).

## Scope
A static scan of the task YAMLs (includes resolved, `!function` samples treated as present) finds ~3,336 of 13,125 task YAMLs that are test-only with no few-shot pool. None of the scanned YAML tasks sets `num_fewshot > 0` by default (Python-defined task subclasses were not scanned); the leak appears when a user passes `--num_fewshot` to one of them. A pool no larger than `num_fewshot` already raised `ValueError` from `random.sample` on the explicit same-split path and now does on the fallback path too.

## Tests
Added to `tests/test_fewshot_context.py`, using real `ConfigurableTask` objects built from in-memory `datasets`:
- `test_fewshot_never_shows_the_evaluated_doc` — 5 docs, `num_fewshot=4`, three cases: fallback to test (fails on `main`), explicit same split, fallback to validation (guards, pass on `main` too);
- `test_fewshot_from_a_different_split_is_not_filtered` — train pool stays a train pool.

`pytest tests/test_fewshot_context.py tests/test_samplers.py`: 91 passed. `ruff check` / `ruff format` (0.16.3) are clean on the changed lines; the remaining findings in `task.py` exist on `main`.

Thanks to @sdivyanshu90 for the precise report and root cause. Prepared with AI assistance; I ran and read every test above.
