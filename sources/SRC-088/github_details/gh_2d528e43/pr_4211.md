# [PR #4211] fix(tmmluplus): pin ikala/tmmluplus to v1.0 (main moved to v1.1; 5-shot now fails on 12 subjects)

## 正文

`tmmluplus` loads `ikala/tmmluplus` without a revision, so it always follows the dataset's `main` branch. On 2026-09-07 iKala moved `main` to v1.1 (tags `v1.0` and `v1.1` both exist on the Hub). Compared with v1.0, v1.1 has 19,680 instead of 20,160 test questions, question counts changed in 63 of 67 subjects, and 167 answer keys changed. So the same model and command now give a different `tmmluplus` score while the task still reports version 2.

It also breaks few-shot runs. In v1.1, 12 subjects have fewer than 5 `train` rows (organic_chemistry has 3, the other 11 have 4), so `--num_fewshot 5` stops at the first of them:

AssertionError: Error: number of fewshot samples requested exceeds the 4 that are available.

I noticed the dataset change because my own TMMLU+ evaluation code picked up v1.1 and the numbers moved. I then checked lm-eval's task config and found it isn't pinned either.

**Change**

- `_tmmluplus_template_yaml`: add `dataset_kwargs.revision` pinned to the commit of tag `v1.0` (`02a54a3953cd17a31b894f1d88fe98d923be2d37`). This is the data #3950 verified against the old `ZoneTwelve/tmmluplus` copy.
- `tmmluplus_linear_algebra.yaml`: its own `dataset_kwargs` replaces the template's (includes are merged shallowly), so I pinned its two `hf://` paths with `@<sha>`. I checked that the revision is really applied: linear_algebra test has 42 rows at the pin and 34 on `main`, and a bogus revision raises "revision not found".
- README: changelog entry.

No version bump, following #3350 (MMLU-SR revision pin): this restores the data version 2 was built on.

**Before / after** (`lm_eval --model dummy --tasks tmmluplus --num_fewshot 5 --limit 1`, CPU, datasets 5.0.1)

- before (main d6de8164): fails at `tmmluplus_agriculture` with the AssertionError above
- after: exit 0, all 67 subjects build 5-shot contexts; group table reports version 2

Test rows loaded through `TaskManager` for all 67 subjects: 19,680 before, 20,160 after. Subjects with fewer than 5 few-shot examples: 12 before, 0 after.

Also ran `pre-commit run --files` on the changed files, plus `pytest tests/test_tasks.py` with `tmmluplus_linear_algebra` and `tmmluplus_agriculture` selected the way CI selects changed tasks (29 passed).

**Alternative**

If you'd rather move to v1.1, I'm happy to change this PR instead. That would mean bumping the task version to 3 (or adding a separate v1.1 variant), and deciding what to do about 5-shot on the 12 subjects that no longer have 5 `train` rows. I went with the pin because it's the smaller change and keeps existing version 2 results comparable.
