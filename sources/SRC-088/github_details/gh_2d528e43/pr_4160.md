# [PR #4160] fix(leaderboard/math): strip unit words on word boundaries

state: open | updated: 2026-09-16T18:29:53Z

## 正文

## What

`leaderboard/math`'s `normalize_final_answer` strips `REMOVED_EXPRESSIONS`
entries with a plain `str.replace`, so the unit word `"ft"` also matches
inside LaTeX command names:

- `\left` → `\le`
- `\infty` → `\iny`
- `\leftarrow` → `\learrow`

This corrupts the **gold target** before any comparison happens, so a model
that answers correctly still scores 0.

## Measured impact

On `HuggingFaceH4/MATH-500` (500 rows), **8 gold answers** are affected — all
of them interval or ordered-pair spellings:

| gold | before | after |
|---|---|---|
| `\left( 3, \frac{\pi}{2} \right)` | `\le(3,\frac{\pi}{2}\right)` | `\left(3,\frac{\pi}{2}\right)` |
| `(2,\infty)` | `(2,\iny)` | `(2,\infty)` |
| `\left( \frac{3}{2}, -13 \right)` | `\le(\frac{3}{2},-13\right)` | `\left(\frac{3}{2},-13\right)` |
| `(-\infty, 0]` | `(-\iny,0]` | `(-\infty,0]` |
| `(5,\infty)` | `(5,\iny)` | `(5,\infty)` |

I also audited the other 25 alphabetic entries against LaTeX command names:
`"ft"` is the only one that collides.

## Why this shape

`minerva_math` and `putnam_axiom` already guard against this. This PR ports
their existing two-pass approach to the `leaderboard/math` copy rather than
inventing a third variant:

1. strip alphabetic units on word boundaries **before** `SUBSTITUTIONS`
   removes the whitespace that delimits them;
2. after `SUBSTITUTIONS`, strip again but skip `\[a-zA-Z]+` command spans.

## Tests

Added to `tests/test_minerva_math.py`, parametrized over all three
implementations through the existing `NORMS` tuple. They fail on `main` and
pass here. The 7 interval cases are real MATH-500 golds.

Note: 3 failures already present in this file on `main`
(`test_bare_digit_tuple_is_not_fused`,
`test_malformed_grouping_is_left_untouched`,
`test_negative_thousands_grouping_is_stripped`) are unrelated to this change
and fail identically before it.

## Out of scope

The same list contains `"meters"`, `"sue"`, `"ways"`, `"square"`, which eat
the tails of `centimeters`, `issue`, `always`, `squares`. That affects all
three implementations (including the already-guarded ones) and is a separate
concern, so it is not addressed here. Happy to follow up if you'd like it
fixed.
