# [PR #4179] fix(cli): stop an in-word apostrophe from swallowing later key=value args

## 正文

## Summary

- `split_top_level` treated any quote character as opening a quoted span, so an in-word apostrophe (`until=Bob's`) left the parser inside a quote and silently folded every following `key=value` pair into that one value
- a quote now opens a span only when it begins a token — at the start of the string or right after a separator — so an apostrophe inside a word is a literal character
- the quote must also have a partner later in the string, so an unterminated quote degrades to a literal instead of consuming the rest of the input
- genuinely quoted values (`a='x,y'`, `desc=say "hi"`) and bracket/brace protection are unchanged

Affects all seven flags parsed by `MergeDictAction`, including `--model_args`, `--gen_kwargs` and `--metadata`. The failure is silent: a run proceeds with different generation settings than requested, so reported numbers are wrong and unreproducible.

### Evihut · 2026-09-18

While checking that this fix was complete, I found the same class of bug on the other
entry point, and I would rather flag it than quietly widen this PR.

`gen_kwargs` and `model_args` reach two different parsers. The CLI goes through
`MergeDictAction` -> `key_val_to_dict` -> `split_top_level`, which this PR fixes.
`simple_evaluate()` and several model backends (`nemo_lm`, `ibm_watsonx_ai`) instead call
`lm_eval.utils.simple_parse_args_string`, which splits on a bare `,` with no bracket or
quote handling. The two disagree on the same input:

| input | CLI path | `simple_parse_args_string` |
|---|---|---|
| `max_seq_lengths=[4096,8192],tokenizer=gpt2` | `{'max_seq_lengths': [4096, 8192], 'tokenizer': 'gpt2'}` | `{'max_seq_lengths': '[4096', '8192]': '', 'tokenizer': 'gpt2'}` |
| `until=['\n\n','###'],temperature=0` | `{'until': ['\n\n', '###'], 'temperature': 0}` | `{'until': "['\\n\\n'", "'###']": '', 'temperature': 0}` |
| `a='x,y',b=2` | `{'a': 'x,y', 'b': 2}` | `{'a': "'x", "y'": '', 'b': 2}` |

The API path does not raise — it fabricates an extra key (`'8192]'`, `"'###']"`) with an
empty value, which then travels on to the model constructor as an unknown keyword.

This is the root cause behind #1677, which is assigned, so I have deliberately left
`simple_parse_args_string` alone here. The dict escape hatch mentioned there does exist
now (`if isinstance(gen_kwargs, str)` in `evaluator.py`), but the string form is still
what the docs and most callers use.

Happy to either extend this PR so both paths share the bracket/quote-aware splitter, or
leave it for #1677 — whichever you prefer.

One unrelated heads-up: #4181 also touches `tests/test_cli_utils.py`, appending at the
end as this PR does. The source changes are in different functions and do not overlap,
but whichever lands second will need a trivial rebase on the test file.
