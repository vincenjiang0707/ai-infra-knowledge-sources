# [PR #4216] fix(utils): stop make_table from repeating shared subtasks

## 正文

## Problem

`_build_hierarchy_info` (which drives `make_table`) walks `group_subtasks` as a tree, but it is a DAG — a group can be reachable from more than one parent. Each path that reached a key appended it again, so a key reachable *k* ways produced *k* identical rows (one per metric) in both the Markdown and LaTeX tables.

Minimal repro:

```python
result_dict = {
    "results": {n: {"alias": n, "acc,none": 0.5} for n in
                ["root", "a", "b", "shared"]},
    "versions": {}, "n-shot": {}, "higher_is_better": {},
    "group_subtasks": {"root": ["a", "b"], "a": ["shared"], "b": ["shared"]},
}
make_table(result_dict)
```

Before — `shared` printed twice:

```
root
 - a
  - shared
 - b
  - shared
```

After:

```
root
 - a
  - shared
 - b
```

## Reachability

This is not only a synthetic shape. Walking every group config in `lm_eval/tasks`, exactly one shipped root group contains a multiply-reachable node: **`flan_held_out`**.

- `mmlu` is a direct child of `flan_held_out` (and of `pythia` / `openllm`).
- `stem` is a child of both `mmlu` and `mmlu_flan_cot_zeroshot`.

So a run over `flan_held_out` repeats `stem` and the 57 MMLU tasks beneath it for each path that reaches them. `agieval` has the same shape internally (`agieval_aqua_rat` is a child of `agieval`, `agieval_en` and `agieval_nous`).

## Fix

Track the keys already placed and skip them on later paths. The first path to reach a key still wins, so order and indentation are unchanged for every other key.

## Tests

`test_make_table_regression_no_duplicate_rows_for_shared_subtasks` builds the `flan_held_out` → `mmlu` / `mmlu_flan_cot_zeroshot` → `stem` shape and asserts the row list has no repeats. It fails on `main` and passes with the change; the two existing `make_table` regression tests still pass.

```
python -m pytest tests/test_evaluator.py -k make_table -q
# 3 passed
```

## Scope

This is the **display** side of the DAG walk. #4171 / #4172 cover the **aggregation** side (`Group.get_all_tasks` / `Group.aggregate` in `lm_eval/api/group.py`) — different function, different symptom, no overlap with this diff.
