## Summary

**Advances #2682** — the reporter's exact request: ready-to-run eval support for R1-style models on their named benchmarks (GPQA, BBH; MuSR left as noted follow-up).

Two task families, thirty tasks, ready to run:

```
lm_eval --model hf --model_args pretrained=deepseek-ai/DeepSeek-R1-Distill-Qwen-7B,... \
        --tasks gpqa_diamond_reasoning --apply_chat_template
lm_eval --model hf ... --tasks bbh_boolean_expressions_reasoning --apply_chat_template
```

## What each variant changes (vs. the base CoT template)

| Setting | base CoT | reasoning variant |
|---|---|---|
| filter chain | regex extraction directly | **strip_think →** regex extraction |
| max_gen_toks | 1024 | 32768 |
| until | includes `\n\n`, `Q:` | **EOS only** (those delimiters occur inside traces) |
| everything else | — | unchanged (prompt, target, metrics) |

The last row is the design principle: **scores are comparable across model families** — the same benchmark scored with and without the reasoning variant isolates the trace effect. Reasoning and non-reasoning models can share a leaderboard row.

## Tasks added

- `gpqa_main_reasoning`, `gpqa_extended_reasoning`, `gpqa_diamond_reasoning` — both extraction chains (strict-match, flexible-extract) prefixed with `strip_think`
- `bbh_{all 27 subtasks}_reasoning` — the `the answer is` extraction prefixed with `strip_think`

Generated by the same `_generate_configs.py` pattern as the existing variants.

## Testing

11 tests in `tests/test_reasoning_tasks.py`:

- yaml structure: strip_think placement (before extraction, before take_first), generation kwargs reasoning-safe (max_gen_toks ≥ 16384, no `\n\n`/`Q:` stops), metrics preserved, all 3 GPQA subsets and all 27 BBH subtasks generated
- end-to-end: R1-format responses through the real filter chains — BBH's `the answer is` and GPQA's multi-choice both scoring correctly; truncated traces (unclosed `<think>`, no answer) never scoring against trace content
