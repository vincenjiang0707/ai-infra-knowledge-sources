## 正文

Closes #3900.

`.github/workflows` runs `pre-commit` with `--from-ref`, so a PR that touches
`anthropic_llms.py`, `sglang_causallms.py`, or the `global_piqa` files inherits
lint failures it did not introduce. This makes those files clean so the trap
stops firing.

### What changed

Autofixed by `ruff check --fix` + `ruff format` (pinned `v0.16.3`, same as
`.pre-commit-config.yaml`): PEP 585/604 annotations, an empty `TYPE_CHECKING`
block, one redundant conditional.

Applied by hand:

| rule | where | fix |
|---|---|---|
| `B904` ×4 | `anthropic_llms.py` | chain the re-raised `ModuleNotFoundError` with `from exception` |
| `B905` ×10 | `sglang_causallms.py` | pass `strict=` explicitly (see below) |
| `B020` | `sglang_causallms.py:269` | `for output, context in zip(cont, context)` rebound the iterable it walks — loop variable renamed to `ctx` |
| `B007`, `PIE790` ×2, `RUF013` ×4 | both | unused loop variable, `pass` after a docstring, implicit `Optional` |
| `TRY004` | `sglang_causallms.py:240` | suppressed, not fixed — see below |

### Two judgement calls worth a look

**`strict=` values.** I used `strict=True` at every site where `huggingface.py`
or `vllm_causallms.py` already passes `strict=True` at the structurally
identical line (`zip(*batch)`, `zip(*chunk)`, `zip(*(req.args ...))`, and the
generate/loglikelihood batch zips). The one exception is `_parse_logprobs`,
where `tokens[ctxlen:]` and `top_logprobs_lists[ctxlen:]` are not guaranteed to
be the same length — that one keeps the current truncating behaviour with
`strict=False`. Happy to flip any of these if you'd rather have the opposite
default.

**`TRY004`.** `hf_vlms.py`, `hf_audiolm.py`, and `neuron_optimum.py` raise
`ValueError` at the same "gen_kwargs is not a dict" check, so changing
sglang's to `TypeError` would be a behaviour change *and* would split the
convention across backends. I added `# noqa: TRY004` instead. If you'd rather
move all four to `TypeError`, say the word and I'll do that in a separate PR.

### Scope

Only the files named in #3900. The wider repo still has pre-existing
violations under the current ruff config, but since CI only lints changed
files those are not blocking anyone today.

No behaviour change is intended.
