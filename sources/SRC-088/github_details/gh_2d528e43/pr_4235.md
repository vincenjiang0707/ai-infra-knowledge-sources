## 正文

## Summary

- initialize built-in model, filter, metric, and aggregation registrations before resolving registry lookups, even when custom entries registered first
- preserve lazy model implementation loading because the built-in model module continues to register placeholder paths
- add a fresh-process regression test covering custom-first registration and coexistence with built-ins

Fixes #4234.

## Why

The lookup functions previously used registry emptiness as a proxy for whether built-ins had been initialized. Importing a custom plugin first made the registry non-empty and caused all built-in registrations for that component type to be skipped.

Python caches module imports, so performing the initialization import at lookup time is idempotent while removing the incorrect dependency on registry contents.
