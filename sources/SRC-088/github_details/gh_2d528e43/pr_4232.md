## 正文

Fixes #3226

The mis-scoring described in the original report did not reproduce: @nata2627's sweep over the full `All` test split found 0 rows where a correct unknown answer falls outside the target set. This PR fixes the two real bugs that sweep turned up in `lm_eval/tasks/bbq/utils.py`.

## What changed

`doc_to_choice` always returns the two non-unknown answers followed by the ten `UNKNOWN_RESPONSES`, so the unknown choices sit at indices 2..11. For rows whose gold answer is an unknown, `doc_to_targets`:

- built `range(2, 2 + len(UNKNOWN_RESPONSES) + 1)`, i.e. 2..12. Index 12 is past the end of the 12-entry choice list. Now 2..11.
- always started the list at 2 (`"Unknown"`), so `doc_to_target` returned 2 on every ambiguous row whatever phrasing the dataset uses. The logged target then disagreed with the dataset label. The row's own unknown phrasing is now first.

A second commit clears nine pre-existing ruff violations in the same file (`zip(..., strict=False)`, one `any()`, one collapsed `elif`). The Linters job runs pre-commit on changed files, so the fix cannot go green without it, same as #4125. No behaviour change.

## Scoring impact

- `acc` is unchanged. The target set is the same apart from the unreachable index 12, and `acc` only checks membership.
- Few-shot prompts change. `doc_to_target` is used for few-shot examples, so with `num_fewshot > 0` an ambiguous example now shows its own phrasing (for example "Can't be determined") instead of always "Unknown". Zero-shot prompts are identical. I did not bump `metadata.version` in `bbq_multiple_choice.yaml` / `bbq_generate.yaml`; happy to if you consider this a prompt change that warrants it.

## Tests

New `tests/test_bbq.py` with hand-built docs, no dataset download: every one of the 10 unknown phrasings at each of the 3 gold positions (30 cases), checking all targets are in range, the unknown targets are exactly 2..11, and `doc_to_target` points at the row's own phrasing; plus one case with a non-unknown gold answer.

```
python -m pytest tests/test_bbq.py
```

- on main: 30 failed, 1 passed
- with this fix: 31 passed

`pre-commit run --files lm_eval/tasks/bbq/utils.py tests/test_bbq.py` passes all hooks.
