## 正文

Calling `exact_match_fn` with `regexes_to_ignore=[]` compares Python lists or tuples as whole sequences. A batch with one correct answer out of two therefore returns `0.0` instead of `0.5`:

```python
from lm_eval.api.metrics import exact_match_fn

print(exact_match_fn(
    predictions=["alpha", "wrong"],
    references=["alpha", "beta"],
    regexes_to_ignore=[],
))
# Before: {"exact_match": 0.0}; after: {"exact_match": 0.5}
```

An empty list enters the regex branch but never executes its loop, and also skips the `else` that converts inputs to arrays. This patch makes array conversion unconditional after regex processing. It adds 23 parameterized cases covering list/tuple/array inputs, no/partial/full matches, ignored patterns, and the existing normalization flags.

The fix and tests are in the first commit. A separate second commit resolves pre-existing lint findings in the two touched files so the pinned pre-commit hooks pass. The unmodified base reports 46 findings. That cleanup keeps `zip` truncation explicit and retains materialization and indexing for the checked empty-input errors.
