## 正文

## What was wrong

`SteeredModel.clamp()` in `lm_eval/models/hf_steered.py` crashes whenever a `clamp`-action steering vector targets a specific attention head (`head_index` set) -- the per-head steering feature added in #3279.

The `head_index is not None` branch contained a leftover/incorrect debug assertion:

```python
x = acts[:, :, head_index, :]
proj = (x * direction).sum(dim=-1, keepdim=True)
assert proj == acts @ direction
```

`acts` has shape `[batch, pos, heads, features]` and `direction` has shape `[features]`. `proj` is the projection of the *single selected head*, shape `[batch, pos, 1]`. But `acts @ direction` is a matmul over the *whole* tensor -- every head -- shape `[batch, pos, heads]`. The two are neither the same shape nor the same quantity. Comparing them with `==` broadcasts to `[batch, pos, heads]`, and `assert` then calls `bool()` on that multi-element tensor, raising:

```
RuntimeError: Boolean value of Tensor with more than one element is ambiguous
```

(Newer PyTorch phrases it "...with more than one value is ambiguous".)

This is not a valid invariant even mathematically -- the two sides only coincide when the broadcast collapses to a single element (`heads == pos == batch == 1`). There is no equivalent check in `add()` or in the `head_index is None` branch, confirming it is spurious debug code.

## Trigger

Run `lm_eval --model steered` with a `steer_path` whose config has a hookpoint entry with `"action": "clamp"` and a non-None `"head_index"` (the documented dict schema in `SteeredModel.__init__`, and exactly what #3279 added the feature for). On the first forward pass the registered hook calls `clamp(...)` and hits the assert; for any layer with more than one attention head (i.e. essentially all real transformer layers) or batch/seq-len > 1, the run aborts before any scoring.

## Fix

Remove the spurious assertion. The surrounding per-head clamp logic is already correct.

## Evidence

RED (current code), calling the real `clamp()` classmethod with `acts` of shape `[2, 5, 8, 16]`, a unit `direction` `[16]`, and `head_index=2`:

```
proj.shape          = (2, 5, 1)     # correct, per selected head
acts @ direction    = (2, 5, 8)     # all heads -- wrong quantity
RuntimeError: Boolean value of Tensor with more than one value is ambiguous
```

GREEN (after removing the assert), same input:

```
returned shape                     = (2, 5, 8, 16)
selected-head matches formula      = True
selected-head projection == value  = True   # clamp target reached
other heads untouched              = True
```

`ruff format --check` reports the file already formatted; the change touches a single line and adds no new lint findings.
