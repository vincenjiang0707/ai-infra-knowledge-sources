## What

Adds **EconLogicQA** ([Quan & Liu, 2024](https://arxiv.org/abs/2405.07938)) as `econ_logic_qa`: 130 test questions that each present four interconnected events from a business or supply-chain narrative and ask the model to order them by **logical rather than chronological** precedence. The 390-question train split supplies the few-shot examples.

Economics is currently represented in the harness only as MMLU-family subject slices (`mmlu_econometrics`, `cmmlu_economics`, `mmlu_pro_economics`, …), which test recall. This tests whether a model can sequence economic cause and effect.

## Evaluation setup

Follows Section 4.1 of the paper: greedy decoding, the permutation extracted from the generation with a regular expression, and accuracy over exact matches against the gold order.

Default is **1-shot**, the paper's best setting. The paper deliberately excludes 0-shot — "the results are unsatisfactory due to the task's complexity" — and recommends few-shot for sorting problems, so the default is 1 rather than 0. `--num_fewshot 5` reproduces the paper's other column.

The paper states it used lm-evaluation-harness with a YAML config for the open models, but neither the config nor any evaluation code was released, and the dataset repo holds only the CSV splits. The prompt template is therefore reconstructed from the dataset's own answer format; absolute numbers should track the paper's ranking rather than match it exactly. This is noted in the task README.

## Metrics

| Metric | Description | Chance |
|---|---|---|
| `exact_match` | Extracted permutation equals the gold order — the paper's accuracy. | 1/24 ≈ 4.2% |
| `pairwise_accuracy` | Fraction of the six event pairs placed in the correct relative order; 0 when no permutation is recoverable. | 50% |

`pairwise_accuracy` is not in the paper. It is reported alongside because `exact_match` cannot distinguish a model that ordered the events wrongly from one that never emitted an ordering. That distinction is load-bearing here: several models in the paper's Table 2 score *below* the 4.2% random-permutation floor (Llama-2-7B 0.77%, Gemma-1.1-7B-IT 0.77%, Gemma-7B-IT 2.31%), which is the signature of a format failure rather than of reasoning. Happy to drop it if you'd rather the task report only the published metric.

## Results

`Qwen/Qwen2.5-0.5B-Instruct`, full 130-question test split, greedy, `dtype=float32`:

| n-shot | `exact_match` | `pairwise_accuracy` | permutation recovered |
|---|---|---|---|
| 1 | 6.92% ± 2.23 | 54.74% ± 2.19 | 128/130 |
| 5 | 4.62% ± 1.85 | 54.87% ± 2.06 | 129/130 |

```bash
lm_eval --model hf --model_args pretrained=Qwen/Qwen2.5-0.5B-Instruct,dtype=float32 \
    --tasks econ_logic_qa --num_fewshot 1 --batch_size 8
```

A 0.5B model sits at roughly the random-permutation floor on `exact_match`, below every model in the paper's table except the Llama-2 and Gemma runs. The two metrics together say why: it emits a well-formed permutation on 98% of questions but orders the pairs barely better than chance — an absence of sequencing ability, not a format failure. I don't have the hardware to run the 7-8B models the paper reports, so I can't offer a direct point comparison; the published numbers are quoted in the task README for whoever can.

For reference, the paper's reported accuracy:

## Tests

`tests/test_econ_logic_qa.py` — 34 cases over the extraction and scoring logic, following the `test_kormedmcqa.py` pattern. Covers the separator forms models actually emit (`,` `;` `->` `→` `>` bare space, unseparated `DACB`, lower case), answers wrapped in prose, reasoning that mentions several orderings before committing (last marker wins), and the cases that must score zero: non-permutations, short runs, and refusals. One guard test pins that a bare `.` is not treated as a separator, so an echoed option list can't be mistaken for an ordering.
