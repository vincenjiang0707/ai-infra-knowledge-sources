## 正文

## Summary

- restore the documented `metadata.num_fewshot` override in collected results
- keep nonzero runtime few-shot counts authoritative for normally sampled examples
- add focused regression tests for both precedence paths

## Problem

Tasks with demonstrations hard-coded into their prompt keep runtime `num_fewshot` at zero so the harness does not prepend another set of examples. They can declare the actual demonstration count in metadata for the printed and serialized `n-shot` result field:

```yaml
num_fewshot: 0
metadata:
  num_fewshot: 5
```

The result collector currently reads only the runtime field, so this configuration is reported as zero-shot.

## Fix

When the runtime count is zero, result collection now uses `metadata.num_fewshot` if present. A nonzero runtime count remains authoritative, matching the original behavior introduced by #1379 and ensuring that the change affects reporting only—not prompt construction or sampling.

Current Ruff rules also required three mechanical cleanups in the touched evaluator module: simplifying a string conversion, removing a redundant numeric union, and removing an unnecessary integer cast. These do not change behavior.

## Tests

- `python -m pytest tests/test_evaluator_utils.py tests/test_num_fewshot_metadata.py -q` — 74 passed
- standalone regression reproduction — reported value changed from `0` to `5`
- `pre-commit run --files lm_eval/evaluator_utils.py tests/test_num_fewshot_metadata.py` — passed

The broader `tests/test_evaluator.py` integration file had 2 passes and 6 model-backed failures because the local environment could not resolve Hugging Face; the failures were model-download setup errors.
