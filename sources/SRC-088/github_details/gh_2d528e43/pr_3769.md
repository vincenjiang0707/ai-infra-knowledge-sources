# [PR #3769] Fix mbpp extract_code_blocks stripping the first identifier of bare-code output

source: https://github.com/EleutherAI/lm-evaluation-harness/pull/3769
state: open | updated: 2026-09-15T03:50:46Z
labels: 

## 正文

`extract_code_blocks` simulates the opening fence injected by `gen_prefix: "\n\`\`\`python\n"` (used by `mbpp_instruct` and `mbpp_plus_instruct`) so a model emitting raw code can still be matched by the `\`\`\`...\`\`\`` regex. The previous prepend was three backticks with no newline, so the regex's optional `(?:\w+)?` language-tag group swallowed the first identifier of any bare-code generation:

```
text     = "def foo(): return 1\n```"
haystack = "```def foo(): return 1\n```"        # bare ``` + text
match    = lang="def", body=" foo(): return 1"
```

Result: the extracted code became ` foo(): return 1`, a `SyntaxError`, and any bare-code generation starting with a Python identifier silently scored 0 even when functionally correct.

Fix: append `\n` to the simulated opening fence so `(?:\w+)?` can only match a real language tag followed by a newline. When the model already emitted its own fence, search the original text — that branch was correct.

### Cases

```
'def foo(): return 1\n```'                       -> 'def foo(): return 1'           # was: stripped "def"
'import heapq\n\ndef bar(x): return x\n```'      -> 'import heapq\n\ndef bar(x): return x'
'```python\ndef baz(): return 2\n```'            -> 'def baz(): return 2'           # unchanged
'```\ndef qux(): return 3\n```'                  -> 'def qux(): return 3'           # unchanged
```

### Impact

`mbpp_instruct` on a 350M-param chat-tuned ONNX model, full 500-sample test split:

| | pass@1 |
|---|---|
| before | 0/500 (0.0%) |
| after  | 67/500 (13.4%) |

Entirely due to `import` / `def` no longer being stripped from extracted candidates; no model or task config change.
