## 正文

## What

Adds unit tests for the built-in filter classes that currently have no direct coverage, plus the `FilterEnsemble` pipeline wiring that chains them:

- `selection.py`: `TakeFirstFilter` (`take_first`), `TakeKFilter` (`take_first_k`, incl. the repeats assertion), `MajorityVoteFilter` (`majority_vote`, incl. tie-breaking by first occurrence)
- `transformation.py`: `LowercaseFilter` / `UppercaseFilter` (incl. Unicode `Ä`->`ä`, `ß`->`SS`), `MapFilter` (`map`, incl. `default_value` and the non-dict assertion)
- `custom.py`: `CustomFilter` (`custom`)
- `lm_eval/api/filter.py` + `lm_eval/filters/__init__.py`: `build_filter_ensemble` -> `FilterEnsemble.apply` end-to-end — chained pipelines over real `Instance` objects, kwargs passing, multiple named pipelines on the same instances, and registry resolution of the filter names used by task configs.

## Why

These registered filters are referenced by string in many task YAML configs, but only `MultiChoiceRegexFilter`, `SPANFilter`, and the BBH filters had tests. `FilterEnsemble` composes filters that return lazy `map` objects (e.g. `take_first`), so the per-instance assignment path was untested; a regression there would be silent. This closes the gap.

## How tested

- `pytest tests/test_filters.py tests/test_bbh_filters.py` -> 36 passed
- Regression sweep of adjacent torch-free suites: `test_registry`, `test_metrics`, `test_misc`, `test_samplers`, `test_serialization`, `test_filters`, `test_bbh_filters` -> 132 passed
- `ruff check` and `ruff format --check` (ruff v0.16.3, the repo's pinned pre-commit version) -> clean

No production code changed.
