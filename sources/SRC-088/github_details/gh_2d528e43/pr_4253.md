## 正文

## Summary

A group's `task:` list is built by looking each member up in the task index. When a member name is not in the index, nothing was reported: the factory invented an empty `ConfigurableTask` named `<group>::<name>` and appended it as a child, and a `{group: name}` member with no inline task list became an empty subgroup.

So the bad name surfaced somewhere else. With a custom task directory (`--include_path`) whose subtask YAML has a syntax error, the index drops that file, the group then builds a task with no `dataset_path`, and the run dies inside `datasets.load_dataset`:

```
File "lm_eval/api/task.py", line 869, in download
  self.dataset = datasets.load_dataset(
TypeError: expected str, bytes or os.PathLike object, not NoneType
```

That names neither the group nor the task. If the group carries shared task-level config, the invented task inherits it and runs, and the group score is then computed over a different set of subtasks than the config lists.

A member that only carries a name is a *reference*, so an unresolvable one is a configuration error. A member that also says where its data comes from is an inline definition and is still built under a namespaced name, which is what `tests/test_configs/group.yaml` relies on. The sibling tag path already reports this case — `TaskFactory._build_tag` warns `references unknown task` and skips — so this aligns the group path with it.

Walking the index over all 855 built-in groups: no group has a dangling reference of either shape. The 93 unregistered group references all carry an inline `task` list, which is the documented inline-subgroup syntax.

## Test

`pytest tests/test_task_manager.py -k dangling` fails on main with `Failed: DID NOT RAISE KeyError` and passes here; the whole file is 73 passed. The end-to-end case above now reports:

```
KeyError: "Group 'mygroup' references unknown task 'gamma'. A group member must
either name a registered task, group or tag, or define a task inline by giving
it a 'dataset_path' or 'class'."
```

`ruff check`, `ruff format` and `codespell` are clean on the changed files (versions pinned by `.pre-commit-config.yaml`).

## Notes

Related to #4242, which raises the log level for a task YAML the index cannot load. That is the same neighbourhood but a different layer: it still builds the group, so the empty child described here is still created. The two changes are independent.

The last hunk moves the closing quotes of one pre-existing docstring in `tests/test_task_manager.py`. Pre-commit only lints the files a branch touches, and that D209 finding would otherwise turn the Linters job red for this PR.
