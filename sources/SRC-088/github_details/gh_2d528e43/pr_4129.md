# [PR #4129] fix: avoid passing None as add_special_tokens in TemplateAPI.tok_encode

source: https://github.com/EleutherAI/lm-evaluation-harness/pull/4129
state: open | updated: 2026-09-14T16:40:28Z
labels: 

## 正文

Motivation:
When a TemplateAPI-based model (e.g. LocalCompletionsAPI/LocalChatCompletion)
is constructed with add_bos_token=None and tok_encode is called without an
explicit add_special_tokens, the fallback expression
`add_special_tokens = False or self.add_bos_token` evaluates to None instead
of a bool. That None is passed straight through to the HuggingFace fast
tokenizer, which requires an actual bool and raises:
  TypeError: argument 'add_special_tokens': 'NoneType' object cannot be
  converted to 'PyBool'
This is the same root cause reported in
https://github.com/EleutherAI/lm-evaluation-harness/issues/3075, whose
originally-reported code path (HFLM) was already fixed elsewhere, but the
TemplateAPI path was not.

Approach:
Swap the fallback to `self.add_bos_token or False`, which normalizes
None/False/True the same way `_add_special_kwargs` (already used by
huggingface.py, trtllm_causallms.py, and vllm_causallms.py) does, without
changing behavior for the already-working True/False cases.

Note: the same buggy pattern also exists in SGLangLM (sglang_causallms.py)
and NeuronOptimumLM (neuron_optimum.py), as flagged in a comment on the
issue. I left those out of this PR: both files currently fail `ruff check`
with dozens of pre-existing, unrelated lint errors (stale typing.List/
Optional[X] annotations, missing zip(strict=), etc.) that predate this
change, and this repo's lint CI job lints the full content of any touched
file. Fixing just the one line there would still leave the PR's lint job
red for reasons unrelated to this fix, so those two are better addressed in
a separate, dedicated cleanup PR.

Validation:
- Added a regression test (test_api_none_does_not_crash_and_matches_false in
  tests/models/test_bos_handling.py) that calls TemplateAPI.tok_encode with
  add_bos_token=None. Confirmed it fails with the exact TypeError above
  against the old code, and passes against the fix.
- Ran: python -m pytest tests/models/test_bos_handling.py tests/models/test_api.py -q
  -> 62 passed.
- Ran: pre-commit run --files lm_eval/models/api_models.py tests/models/test_bos_handling.py
  -> all hooks passed (ruff check, ruff format, codespell, etc).
- Checked base branch CI (gh run list --branch main) is currently green.
