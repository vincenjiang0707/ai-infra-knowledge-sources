## 正文

## Summary

- de-duplicate recursive group leaves by task name while preserving traversal order
- prevent a task shared by sibling subgroups from receiving duplicate metric and sample weight in their parent
- add regression coverage for both leaf discovery and size-weighted aggregation

## Problem

`Group.get_all_tasks()` previously concatenated the leaves returned by every subgroup. If two sibling subgroups referenced the same task, the parent leaf list contained that task twice even though evaluation results contain only one entry per task name.

`Group.aggregate()` consumes that list directly, so the shared task's value and `sample_len` were counted once per hierarchy path. In the regression case, two unique tasks totaling 300 samples were reported as 400 samples, and their correct size-weighted score of `0.6667` became `0.5`.

## Fix

Recursive traversal now tracks task names already visited and returns the first task object for each name. This keeps deterministic traversal order and makes all existing consumers use the same unique set of evaluated tasks:

- TaskManager's flattened task map
- filter discovery
- group sample totals
- metric values, weights, and per-metric sample counts

Overlap between separately requested top-level groups is still rejected by the existing TaskManager validation.

While validating the touched module, the current Ruff hook also required simplifying an existing `sorted(list(set_value))` call to `sorted(set_value)`; this has no behavior change.
