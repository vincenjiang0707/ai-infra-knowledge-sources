## 正文

### What

Removes three invalid escape sequences (`W605`, which is selected in `[tool.ruff.lint] extend-select`):

| file | before | after |
|---|---|---|
| `lm_eval/tasks/aime/utils.py:199` | `string.replace("\%", "")  # noqa: W605` | line dropped |
| `lm_eval/tasks/hendrycks_math/utils.py:199` | same duplicate line | line dropped |
| `scripts/clean_training_data/process_sorted_buckets.py:38` | `re.sub("\D", "", …)` | `re.sub(r"\D", "", …)` |

### Why

Unknown escapes in string literals are deprecated (`DeprecationWarning` up to 3.11, `SyntaxWarning` from 3.12) and are scheduled to become errors. The `# noqa: W605` comments hide that instead of fixing it.

In `aime`/`hendrycks_math` the suppressed line was also **dead code**: the literal `"\%"` is the very same string as `"\\%"` on the preceding line, so the replacement had already been performed — the duplicate only existed to carry the noqa.

### Behaviour

Unchanged, verified with:

- `strip_string` is byte-identical before/after over inputs covering percentages, fractions, decimals and whitespace, e.g. `{"50\\% off": "50off", "a\\%b%c": "ab%c", ".5": "\\frac{1}{2}", "  7  ": "7"}`.
- `re.sub("\D", …)` and `re.sub(r"\D", …)` compile to the same pattern (`"abc123" -> "123"`).
- `ruff check --select W605` → `All checks passed!`; the full `ruff check --statistics` error count for these files is **identical before and after** (16), so no `# noqa` was load-bearing and nothing new was introduced.
- `python -W error::SyntaxWarning -c "compile(...)"` fails on the previous revision and passes now.
- `ruff format --check` → already formatted, so the diff stays at 3 files, −3/+1.

### Not included

`lm_eval/tasks/ifeval/multilingual/instructions/{es,ca}_instructions.py` carry the same class of invalid escape (`` `\*` `` inside a docstring, lines 351 and 349; the one in the `es` file is currently flagged by `W605`).

They are left out on purpose: both files have pre-existing `ruff-format` drift (2-space upstream ifeval style), so touching them makes the `pre-commit` job rewrite ~1,900 lines each. The fix itself is one character (`` `\*` `` → `` `\\*` ``, which leaves the rendered docstring unchanged) — I can send it as a separate PR, or fold it in here if you'd rather have the reformat.
