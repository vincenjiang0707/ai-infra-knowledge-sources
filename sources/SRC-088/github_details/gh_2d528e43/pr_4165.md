# [PR #4165] chore(leaderboard): drop the orphaned ifeval module copies

## 正文

`lm_eval/tasks/leaderboard/ifeval/instructions.py`, `instructions_registry.py` and `instructions_util.py` are dead code. Nothing imports them, and nothing can:

- `ifeval.yaml` resolves its scoring through `!function utils.*` only;
- `leaderboard/ifeval/utils.py` imports `lm_eval.tasks.ifeval.instructions_registry`;
- the orphaned `instructions_registry.py` itself imports `lm_eval.tasks.ifeval.instructions`;
- the orphaned `instructions.py` itself imports `lm_eval.tasks.ifeval.instructions_util`.

Every path leads back to `lm_eval/tasks/ifeval/`. Loading the task and inspecting `sys.modules` confirms it — the only module pulled in from this directory is `utils`, alongside the three canonical ones:

```
process_results: .../lm_eval/tasks/leaderboard/ifeval/utils.py
leaderboard-ifeval modules in sys.modules: ['lm_eval.tasks.leaderboard.ifeval.utils']
ifeval modules in sys.modules: ['lm_eval.tasks.ifeval.instructions_util',
                                'lm_eval.tasks.ifeval.instructions',
                                'lm_eval.tasks.ifeval.instructions_registry']
```

### They were dead on arrival

#2047 created `leaderboard/ifeval/` by copying `ifeval/` — at that commit all four files were byte-identical to their source — and rewired `utils.py` alone:

| file | blob @ #2047 | blob @ `main` |
|---|---|---|
| `instructions.py` | identical | **diverged** |
| `instructions_registry.py` | identical | identical |
| `instructions_util.py` | identical | **diverged** |
| `utils.py` | *differs (rewired)* | identical |

The other three have been unreachable ever since, which is why they then rotted unnoticed for two years:

- `instructions_util.py` still imports `pkg_resources`, exactly what #2471 reported and what #2267 fixed in the live copy. `pkg_resources` is gone from setuptools >= 81, so this file no longer imports at all in a current environment:
  ```
  >>> import lm_eval.tasks.leaderboard.ifeval.instructions_util
  ModuleNotFoundError: No module named 'pkg_resources'
  ```
- #2267 also added the `LOCAL_RANK` guard around `nltk.download`; the copy kept the unguarded call that has every rank race for the same download.
- `instructions.py` has drifted from the live copy on typing and logging.

This is the failure mode of #4125: a copied task module diverging from its source in silence. There the divergence was reachable and cost a crash; here it is unreachable, so deleting the copies is the fix rather than syncing them.

`utils.py` stays — it is the module the YAML actually loads.

### No behaviour change

`process_results` over all 541 `leaderboard_ifeval` docs hashes identically before and after:

```
before: d68eb7b3aa643977e74764a8d7e24113f43e00b6035a6c40c0fe68ff39743d1d
after:  d68eb7b3aa643977e74764a8d7e24113f43e00b6035a6c40c0fe68ff39743d1d
```

(seeding `random` per doc, since ifeval's `build_description` draws from it when a kwarg is absent — without that the digest is unstable run-to-run on 2 of the 541 docs, independent of this change).

No YAML is touched, so no `metadata.version` bump is warranted — same as #4125.

### Test

A module nothing imports is invisible to every other test, so the added test pins the invariant directly. It fails on the pre-change tree, naming all three files:

```
AssertionError: assert {'instructions.py', 'instructions_registry.py', 'instructions_util.py'} == set()
```

and passes after. `ruff check` / `ruff format --check` clean.
