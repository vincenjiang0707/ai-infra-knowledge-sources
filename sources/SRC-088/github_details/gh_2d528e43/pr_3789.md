## 正文

## Summary

This PR adds first-class support for **Rebellions ATOM/REBEL NPU** as a new
model backend for `lm-evaluation-harness`, registered as:

- `rbln`     — causal-LM and seq2seq-LM evaluation via `optimum-rbln`
- `rbln-vlm` — vision-language model evaluation via `optimum-rbln`

It plugs into the existing model registry the same way `hf`, `vllm`,
`habana`, and `neuronx` do — no changes to evaluator logic or task code
are required, and the imports are guarded so users without
`optimum[rbln]` installed are unaffected.

Closes #N/A — initial backend contribution.

## Motivation

Rebellions NPUs (ATOM, REBEL) are commercially available accelerators
used in production inference deployments. Today users who want to
benchmark their compiled RBLN artifacts on standard `lm-eval` tasks
(`hellaswag`, `mmlu`, `lambada_openai`, `gsm8k`, `mmmu`, `chartqa`, …)
have to maintain an out-of-tree fork. Upstreaming the backend gives the
community a reproducible way to compare NPU vs GPU/CPU numbers on the
same harness, and gives Rebellions users access to the full task
catalog without a vendored fork.

The integration mirrors the layering used by the existing
`optimum-habana` (`habana`) and `optimum-intel` (`ipex`) backends:
weights and run-time stay vendor-side in `optimum-rbln`, and only the
`lm_eval` adapter lives here.

## What's in the PR

### New model backends

| Registry name | Class | File | Coverage |
|---|---|---|---|
| `rbln`       | `RBLNLM`  | `lm_eval/models/optimum_rbln.py`     | Causal LM, Seq2Seq LM |
| `rbln-vlm`   | `RBLNVLM` | `lm_eval/models/optimum_rbln_vlm.py` | LLaVA, LLaVA-NeXT, Qwen2-VL / Qwen2.5-VL / Qwen3-VL, Gemma3, IDEFICS3, PaliGemma / PaliGemma2, Pixtral, BLIP-2 |

`RBLNVLM` subclasses `RBLNLM` so the **same compiled VLM artifact** can
serve both multimodal `generate_until` requests (e.g. MMMU, ChartQA) and
text-only `loglikelihood` requests (e.g. `hellaswag`, `mmlu`, `arc_*`,
`winogrande`) — no separate text-only checkpoint required.

### Behavior parity with HFLM

To keep results comparable to the `hf` backend on the same model:

- **Tokenization and logit extraction** are aligned with `HFLM` —
  `add_special_tokens`/BOS handling, `_select_cont_toks`, padding side,
  and continuation slicing all use the same utilities
  (`lm_eval.models.utils`, `lm_eval.models.utils_hf`).
- **Per-token forward pass** for causal models that return only
  last-token logits on RBLN-compiled artifacts: the loop performs N
  individual forward passes and reconstructs the full continuation-token
  logit slice so `loglikelihood` results match HF reference within
  numerical noise.
- **Seq2seq `cache_position` shim** for the RBLN SDK's scalar/tensor
  expectation difference, plus explicit `decoder_input_ids` /
  `decoder_attention_mask` and float32 attention masks.
- **VLM text-only loglikelihood** is implemented through `model.generate(
  ..., max_new_tokens=1, output_scores=True)` with zeroed
  `token_type_ids`, because direct `model(input_ids=…)` is not a stable
  forward API on RBLN-compiled VLM artifacts (state-init constraints).
  This is documented in the module docstring.

### Lazy / soft dependency

`optimum-rbln` is **not** a hard dependency. The model module sets
`RBLN_AVAILABLE = False` and falls back to placeholder objects when the
SDK is missing; the entries in `MODEL_MAPPING` are lazy strings, so
`lm_eval --tasks list` and unrelated backends are unaffected on machines
without the SDK installed. This matches the pattern used by
`vllm_causallms.py` / `optimum_habana.py`.

### Auxiliary additions

- `lm_eval/npu_utils/npu_detection.py` — light wrapper around
  `rbln-stat` so users get a clear error when no NPU is visible, instead
  of an opaque SDK traceback.
- `examples/npu/` — minimal working example
  (`demo_working_rbln_integration.py`) and README with copy-pasteable
  `lm_eval` invocations.
- `RBLN_MODEL_TYPE_EVALUATION_GUIDE.md` — model-type → recommended-task
  matrix and known limitations.
- `tests/npu/test_npu_integration.py` — hardware-gated integration tests
  (skipped automatically when no NPU is present).

## Usage

```bash
pip install lm_eval optimum[rbln]

# Causal LM
lm_eval --model rbln \
  --model_args pretrained=meta-llama/Meta-Llama-3-8B-Instruct \
  --tasks hellaswag

# Seq2Seq LM
lm_eval --model rbln \
  --model_args pretrained=google/flan-t5-base \
  --tasks squadv2

# Multi-NPU tensor parallel
lm_eval --model rbln \
  --model_args pretrained=meta-llama/Meta-Llama-3-8B-Instruct,rbln_tensor_parallel_size=4 \
  --tasks hellaswag

# VLM — multimodal
lm_eval --model rbln-vlm \
  --model_args pretrained=llava-hf/llava-v1.6-mistral-7b-hf \
  --tasks mmmu_val

# VLM — text-only on the same compiled artifact
lm_eval --model rbln-vlm \
  --model_args pretrained=llava-hf/llava-v1.6-mistral-7b-hf \
  --tasks hellaswag
