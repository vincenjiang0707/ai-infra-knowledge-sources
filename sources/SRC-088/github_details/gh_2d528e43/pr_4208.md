## 正文

## What

Guard the flan MMLU `MultiChoiceRegexFilter` against an all-empty capture tuple, so a regex that matches with only-empty groups falls through to the fallback instead of raising `IndexError`.

Fixes #4207.

## Why

`lm_eval/tasks/mmlu/flan_cot_zeroshot/utils.py` and `lm_eval/tasks/mmlu/flan_n_shot/generative/utils.py` both reduced a match tuple with `[m for m in match if m][0]`. When every capture group is empty (a pattern whose groups are all optional), that list is empty and `[0]` raises `IndexError`, aborting the run rather than falling through to the fallback.

This is the same defect #4125 fixed for the bbh filters and `lm_eval/filters/extraction.py`; these two flan copies were missed. The fix mirrors the bbh guard exactly:

```python
if isinstance(match, tuple):
    non_empty = [m for m in match if m]
    if not non_empty:
        return ""
    match = non_empty[0]
```

## Reproduction (no model/download)

```python
from lm_eval.tasks.mmlu.flan_n_shot.generative.utils import MultiChoiceRegexFilter
MultiChoiceRegexFilter(regex_pattern=r"x(foo)?(bar)?").apply([["x"]], [{"choices": ["A", "B"]}])
# before: IndexError: list index out of range
# after:  [['[invalid]']]
```
