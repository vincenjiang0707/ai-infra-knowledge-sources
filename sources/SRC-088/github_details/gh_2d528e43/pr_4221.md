## 正文

Fixes #4220.

## What

When the aggregation is lm-eval's own `f1_score` or `matthews_corrcoef` and every item is a `(gold, pred)` pair of 0/1 labels, `bootstrap_stderr` draws the four confusion counts from a multinomial instead of resampling rows and calling sklearn per replicate. Every other aggregation and label type takes the existing path unchanged.

## Why it is the same statistic

Binary F1 and MCC depend only on TN, FP, FN and TP. Resampling n rows with replacement makes those counts Multinomial(n, observed proportions), so the count draws have the bootstrap distribution the row resampling has. Undefined scores are 0.0, as the sklearn-backed aggregations return.

## Numbers

`bootstrap_stderr` at the default 100,000 replicates, one-core Linux box, 0/1 pairs at the GLUE validation sizes:

| rows | main | this PR |
|---|---:|---:|
| 1,043, mcc (CoLA) | 234.7 s | 0.043 s |
| 408, f1 (MRPC) | about 280 s | 0.050 s |
| 40,430, f1 (QQP) | about 57 min | 0.041 s |

The two "about" figures are main's measured per-replicate cost times 100,000. Main spreads its work over a process pool, so on a multi-core machine divide its column by roughly the core count; this path starts no processes.

## Behaviour changes

- Reported stderr values for these two metrics move within Monte Carlo noise because the random stream is different (CoLA-size example: 0.024466 on main, 0.024649 here). The seed is fixed, so repeated runs give identical values, as before. If you would rather keep the old digits reproducible across versions, I can put this behind an environment variable or a keyword.
- The number of replicates is unchanged, including the whole-thousands rounding the chunked path applies (1,500 requested gives 1,000).
- No progress bar or "bootstrapping for stddev" line for these two metrics.

## Tests

`tests/test_bootstrap_binary_counts.py`, 15 cases:
- every confusion table of 1 to 8 rows scores as the sklearn-backed aggregation does, both metrics
- all 4^4 row resamples of a skewed 4-row sample with one empty cell give the same score distribution as the multinomial over count tables, within 1e-12
- the replicate count matches the row path at 100,000, 1,500 and 250
- labels outside 0/1, string labels, non-pairs, empty input and other aggregations go to the row path
- no process pool is started, and repeated calls give identical values
- the stderr agrees with the row path within Monte Carlo noise, both metrics

`tests/test_metrics.py`, `tests/test_evaluator_utils.py` and `tests/test_aggregation_pipeline.py` still pass.
