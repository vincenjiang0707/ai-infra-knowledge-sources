## 正文

## Summary

Add three CPU-only unit tests for the input-validation paths in `simple_evaluate()` that run *before* any model or dataset is loaded. These tests exercise the validation checks that fire immediately when invalid arguments are passed.

## Tests added

1. **`test_simple_evaluate_rejects_limit_and_samples_both_set`**  
   Asserts `ValueError` with message "both are not None" when both `limit` and `samples` are provided (they are mutually exclusive).

2. **`test_simple_evaluate_rejects_empty_tasks_list`**  
   Asserts `ValueError` with message "No tasks specified" when `tasks` is an empty list or `None`.

3. **`test_simple_evaluate_rejects_unknown_model_name`**  
   Asserts `ValueError` with message "no model for this name found" when the `model` argument does not match any registered model class.

## Verification

- All three tests pass locally.
- Ruff lint passes (no new errors introduced; the 5 reported issues are pre-existing in the file).
- Mutation-style sanity check: temporarily changing the error message strings in the source causes the corresponding test to fail, confirming each test is anchored to the real production code path.

## Related issue

Addresses the "evaluator-level validation" regression-test gap mentioned in #1883 (comment by @aarushi211). These tests are scoped to validation paths only and do not overlap with the CLI wiring or CPU snapshot work already in progress.
