# [PR #2557] fix(mcp): detach launcher subprocesses from the MCP stdio pipe

## 正文

### What does this PR do?

Fixes #2551.

When `modelopt-mcp` runs as a stdio MCP server, its stdin is the JSON-RPC transport pipe. The three `modelopt-launcher` call sites in `tools/mcp/modelopt_mcp/bridge.py` spawned children with stdin inherited (`capture_output=True` redirects stdout/stderr only), so the child contended with the server for the same stdin handle and blocked until its timeout fired (60s for dry-run, 300s for Slurm, indefinite for the detached Docker `Popen`).

Type of change: bug fix.

The fix adds `stdin=subprocess.DEVNULL` at all three launcher call sites:
- `submit_job_impl` — Docker live submit (`subprocess.Popen`)
- `submit_job_impl` — Slurm live submit (`subprocess.run`, timeout=300)
- `_submit_job_dry_run` — dry-run (`subprocess.run`, timeout=60)

Other subprocess call sites in `bridge.py` (verify probes, ssh, git/gh) are untouched: the issue shows they fail fast and are not affected.

### Usage

N/A — bug fix, no API change. After this change, `submit_job(dry_run=True)` over a stdio MCP connection returns in ~2s instead of timing out at 60s (as reported in #2551).

### Testing

- New regression tests in `tools/mcp/tests/test_bridge.py` (`test_submit_job_dry_run_detaches_stdin`, `test_submit_job_slurm_detaches_stdin`, `test_submit_job_docker_detaches_stdin`) assert each launcher call site passes `stdin=subprocess.DEVNULL`. All three **failed before the fix** (`stdin` kwarg absent) and pass after.
- Full `tools/mcp` suite: **69 passed** (`pytest tests/`, baseline before the change was 66 passed).
- Standalone mechanism check: a child doing `sys.stdin.read()` with an inherited never-written pipe hung (killed after 5s); with `stdin=subprocess.DEVNULL` it exited rc=0 in 0.1s.
- `ruff check` and `ruff format --check`: clean on both changed files.
- `mypy` on `bridge.py`: only pre-existing environment errors (missing library stubs for `yaml`, `modelopt_launcher`, `nemo_run`) — unrelated to this change.
- Caveats: this sandbox has no GPU and the repo's `tests/unit` suite (torch etc.) was not installed; only the CPU-runnable `tools/mcp` tests were run.
