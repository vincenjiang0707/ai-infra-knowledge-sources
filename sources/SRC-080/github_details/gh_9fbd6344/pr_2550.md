# [PR #2550] Fix NVFP4 real-quant GEMM availability check for effective_bits

## 正文

### What does this PR do?

Type of change: Bug fix

Fixes #2330. After `mtq.quantize` + `mtq.compress`, the NVFP4 availability check never matched, so `RealQuantLinear` warned "No real-quant GEMM found" and fell back to the default GEMM.

`NVFP4_DEFAULT_CFG` carries `effective_bits: 4.5`, an AutoQuantize cost-model hint that `quantize()` stores on the quantizer as `_effective_bits`. The check compared every cfg key against public attributes via `hasattr`, so it always failed on this key. Skip it like `enable`.

### Testing

- `test_nvfp4_gemm_matches_after_compress`: quantize + compress a linear model, assert `gemm_registry.find_match` returns `Nvfp4Linear.apply` (skipped without FP4-capable GPU / tensorrt_llm).
- Verified on a `TensorQuantizer` built from `NVFP4_DEFAULT_CFG`: `effective_bits` is stored as `_effective_bits`, and the patched key filter no longer rejects it.
