### A write-mask so calibration can be confined to a scope

Calibration algorithms take an optional `should_process` predicate and AND it into their existing `is_enabled` filter, so an algorithm can be restricted to part of the model. `None` means the whole model, which is today's behaviour, so **nothing changes for any existing caller**.

Three properties matter, each with a test:

- **It gates writes only, never enable-state.** Reads are untouched, so the activations a search-based algorithm sees are identical either way.
- **It keys on module identity, not name.** That is what lets it survive `layerwise_calibrate` handing an algorithm a reparented subtree whose module names are relative.
- **It has to reach helper calls *inside* an algorithm**, not just its top-level module loop. `awq_lite` calls `enable_stats_collection(model)` directly and would otherwise calibrate the whole model regardless of scope.

### Reviewing this

One file of library change, and the question is narrow: *is every write site gated?* That is exactly the question the `awq_lite` bug above failed, which is why this is its own PR rather than buried in the plan machinery.

No caller passes a mask yet — the plan that does arrives in PR 4. This is deliberate: the threading is mechanical and error-prone, the plan is neither, and mixing them makes both harder to check.

### A caveat the tests cannot cover

The guards in the `max_calibrate` path are **mutually redundant**. Removing any one of `enable_stats_collection`, `weight_only_quantize` or `finish_stats_collection` leaves the others covering it, so no single-guard mutation is observable. The test detects a real leak — 5 of 7 cases fail when all three are removed — but redundancy is why it cannot pin any one of them individually.

Found while mutation-testing this PR's own test, which also turned up a genuine gap: the first version only snapshotted amax, so removing GPTQ's guard changed nothing detectable, because GPTQ writes *weights*. The test now snapshots amax, weights and `pre_quant_scale`.
