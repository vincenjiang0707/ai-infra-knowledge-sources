## 正文

### What does this PR do?

Type of change: Bug fix

Fixes ModelOpt MCP remote experiment log retrieval when the MCP server runs from an environment whose `PATH` and `NEMORUN_HOME` differ from the launcher subprocess.

The log reader now:

- resolves the installed `nemo` console script from `PATH` or beside the active Python interpreter instead of relying on `uv run` in the caller's workspace;
- derives `NEMORUN_HOME` from the experiment directory already resolved by the MCP; and
- returns both stdout and stderr because NeMo Run emits remote task output on stderr.

### Usage

No API changes. Existing `read_cluster_artifact(experiment_id=..., job_idx=...)` calls now return the remote task log from the correct experiment metadata root.

## Claude review — `tools/mcp` log-retrieval fix

**Scope:** full review. The PR touches 2 files (+30/−10); both were reviewed in full — `tools/mcp/modelopt_mcp/bridge.py` and `tools/mcp/tests/test_bridge.py`. No `modelopt/` or `examples/` paths are affected, so the mode/state, export, and checkpoint-compatibility categories do not apply here.

**Findings: CRITICAL: 0 · IMPORTANT: 1 · SUGGESTION: 2**

### Most impactful

**[IMPORTANT] `read_cluster_artifact_impl` skips `_validate_experiment_id`** (bridge.py:2125-2132). This is a pre-existing omission, but the change makes it load-bearing: `experiment_id` now reaches `_resolve_experiment_dir`, which does `root / experiment_id` and `root.glob(f"*/{experiment_id}")`. The validator at bridge.py:205 exists for exactly this — its docstring reads *"Reject experiment ids that could escape path joins or alter glob matching"* — and both sibling tools (`job_status_impl`, `job_logs_impl`) call it as their first statement. With `experiment_id="*"` the nested lookup matches an arbitrary unrelated experiment and derives `NEMORUN_HOME` from it, reintroducing the wrong-metadata-root failure this PR is fixing. Two added lines at the top of the function close it for both modes.

**[SUGGESTION] `NEMORUN_HOME` derivation duplicates root knowledge and misses `local_experiments`.** Matching a parent named `"experiments"` skips the `Path.cwd() / "local_experiments"` root (bridge.py:1609, written by `tools/launcher/launch.py:155` for `hf_local` runs), so the fix silently doesn't apply there; and when `exp_dir is None` the code proceeds with the stale env instead of returning the `experiment_dir_not_found` + `_experiment_not_found_diagnostic()` that the sibling tools return. Having the resolver return the matched root handles both.

**[SUGGESTION] stdout+stderr share one 8 KB tail budget** (bridge.py:2166), so large stderr console output can evict the task log entirely. Truncating each stream independently keeps the fallback without the regression.

### On the core fix

The direction is right, and the root cause is correctly identified rather than patched around: `uv run nemo` resolved against the *caller's* workspace project, which is wrong for a long-lived MCP server, and deriving `NEMORUN_HOME` from the already-resolved experiment dir is the correct source of truth. `shutil.which("nemo")` with a `sys.executable`-sibling fallback is well-targeted, since `nemo-run>=0.8.0` is a hard dependency of `modelopt-launcher`, itself a hard dependency of `modelopt-mcp` — so the console script is normally beside the interpreter even when `PATH` doesn't include the venv.

I agree with CodeRabbit's inline finding on the unavailable-`nemo` case and won't duplicate it: `server.py` wraps `read_cluster_artifact_impl` with no `except Exception`, so a `FileNotFoundError` from the fallback path escapes as a protocol-level error instead of the `{ok: False, reason, diagnostic}` contract every other failure branch in this function honors. Given the dependency chain above the practical likelihood is low, but the fix is cheap — add `FileNotFoundError` to the existing `except subprocess.TimeoutExpired` handler with a `reason: "nemo_cli_not_found"` branch.

The test rewrite is a real improvement — asserting exact `argv` and the derived `NEMORUN_HOME` against a `tmp_path` layout with a deliberately wrong inherited `NEMORUN_HOME` pins the actual regression, including the nested `experiments/<title>/<id>` shape.

### Risk

**Low.** Confined to a diagnostic read path in a dev tool; no library, export, or checkpoint surface is touched, and no public API changes. The IMPORTANT finding is an input-validation consistency gap rather than a functional break on the happy path.
