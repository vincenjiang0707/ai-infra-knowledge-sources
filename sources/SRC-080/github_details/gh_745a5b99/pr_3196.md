# [PR #3196] Add test that pre-baked datasets produce samples without padding

state: closed | updated: 2026-09-23T19:20:17Z

## 正文

SUMMARY:
Add a unit test that runs `get_processed_dataset` over all pre-baked datasets (the dataset names registered in `src/llmcompressor/transformers/data`) and asserts the generated samples contain no padding.

The processor is obtained via `AutoProcessor` rather than `AutoTokenizer`, which lets the test also cover the multimodal pre-baked datasets by exercising only their text tokenization:
- `flickr` uses a `Qwen/Qwen3-VL-8B-Instruct` processor stub.
- `peoples_speech` uses an `openai/whisper-large-v3` processor stub.

All other pre-baked datasets (`perfectblend`, `open_platypus`, `evolcodealpaca`, `gsm8k`, `ultrachat_200k`, `wikitext`) use the tiny llama processor.

The no-padding check is feature-aware:
- Datasets emitting `input_ids` + `attention_mask` (text and `flickr`) assert every sample's attention mask is all ones.
- `peoples_speech` (whisper) emits `decoder_input_ids` and no attention mask, so it asserts the single, un-padded transcription is non-empty and contains at most one pad terminator.

TEST PLAN:
- `pytest tests/llmcompressor/transformers/data/test_dataset_loading.py::test_prebaked_datasets_generate_no_padding` — all 8 parametrized cases pass.
- `ruff check` and `ruff format` on the modified file pass.
