## 正文

## Summary

Adds block-wise local quantization-aware distillation after a preceding weight quantization method. During the existing calibration forward, QAD hooks cache a decoder block's inputs and unquantized outputs. At `sequential_epoch_end`, the preceding method prepares quantization, QAD reconstructs the cached outputs, and the existing pipeline propagates the final quantized outputs.

- Share one calibration dataset and dataloader. No changes to the pipeline, public lifecycle, Modifier base class, or oneshot entrypoint.
- Compose RTN (`QuantizationModifier`) or `GPTQModifier` followed by `QADModifier`. The tested AWQ composition is `AWQModifier` → `QuantizationModifier` → `QADModifier`; AWQ's transform still needs a weight quantization modifier. Other methods use the same lifecycle contract; QAD does not inspect GPTQ-specific state or quantizer class names.
- Follow the weight re-observation schedule in #3051: before training, after every epoch, and before final materialization. Observe all modules before updating any qparams to preserve fused NVFP4 global scales.
- Retain masked MSE, FP32 optimizer master weights for FP16/BF16 execution, dynamic FP16 loss scaling, gradient accumulation/clipping, deterministic validation, early stopping, and best-checkpoint restoration. Restore matching weight qparams with the best weights. `reobserve_weights=False` retains a fixed-scale option.
- Use one complete target module per subgraph, local teacher targets, single-process calibration, and `propagate_error=True`. Ignore the output LM head. Full teacher streams, separate QAD datasets, and arbitrary multi-target graph reconstruction are outside this version.
- Keep `LayerwiseQADModifier` as an alias. Usage and quantizer composition requirements are documented in `examples/qad/`.

## Validation

- CPU: QAD tests plus `tests/llmcompressor/core/test_session_functions.py` — 39 passed, 4 accelerator cases skipped. Regression cases cover long-sequence FP16 gradient underflow, unscaling before clipping, complete/partial accumulation groups, overflow retries, and persistent nonfinite-gradient failure. The experiment training/export/reload entrypoint also passes a tiny CPU check with source/input provenance validation.
- H200 on the corrected source: 41 passed, 2 CPU-only cases skipped. Covers all QAD tests, including FP16 long-sequence gradients, overflow recovery, exact teacher-input propagation, RTN/GPTQ/AWQ+RTN composition with NVFP4A16/W4A16, and RTN/GPTQ FP16 NVFP4 save/reload/generation.
- Changed Python files pass Ruff lint/format and CUDA portability checks. Full `make quality` reaches two existing import-order errors in unchanged sparsity tests.
- An additional check on main `8ada4c40` with compressed-tensors `698967f` encounters a `weight_global_scale` Tensor/Parameter error in the dependency's post-save offload conversion; the same error reproduces with GPTQ alone. The existing experiment environment passes save/reload.
- Paired Llama-3.1-8B-Instruct experiments use shared UltraChat budgets 512/1024/2048, evaluation seeds 1234/2345/3456, five benchmarks, and WikiText-2 PPL (context 2048, stride 512). All six checkpoints passed quantization, export and reload validation; 18/18 full evaluations are verified, including all nine complete GPTQ/QAD budget/seed pairs. Each condition has one trained checkpoint (training seed 42); the three seeds are evaluation repeats.
- The three GPTQ-only checkpoints and nine baseline evaluations are reused. Comparing archived runtime sources confirms that only QAD training code changed. Model/data revisions, calibration token IDs, hyperparameters and the evaluator are pinned. Accepted corrected QAD evaluations pass the same complete protocol, sample and paired-input checks.

Results are mixed. At 1024 samples, QAD improves MMLU-Pro, IFEval, MATH-500 and PPL means, with small decreases in GSM8K and MMLU CoT. At 512 samples, IFEval improves but MMLU-Pro and MATH-500 decrease; at 2048, MMLU CoT improves while IFEval and PPL worsen. These measurements do not establish a consistent quality improvement or robustness across training seeds.

All eighteen evaluations passed protocol, checkpoint and sample validation: 28,324 unique task documents, 29,533 scoring records and 75 task/filter groups each. All nine GPTQ/QAD budget/seed pairs have identical document, prompt and target hashes for every scoring record. WikiText-2 scores exactly 289,076 target tokens with context 2048 and stride 512; its repeated scores are identical for each checkpoint under this deterministic scoring procedure.

Evaluation tasks are `gsm8k_platinum_cot_llama`, `mmlu_cot_llama`, `mmlu_pro_chat`, `ifeval` (instruction-level strict accuracy), and the documented custom MATH-500 task adaptation. Generation uses the same vLLM 0.25.1 environment, temperature 0.6, top-p 0.9 and maximum 4096 generated tokens for every condition. H100/H200 evaluation workers are mixed.
