# [PR #3144] Fix activation caching for dataclasses that validate their fields

source: https://github.com/vllm-project/llm-compressor/pull/3144
state: open | updated: 2026-09-21T21:19:25Z
labels: 

## 正文

Caching activations containing a strict dataclass currently reconstructs the object with `type(value)(**wrapped_fields)`. Its constructor validates each `IntermediateValue` wrapper against the original field type and rejects it. The concrete Mistral object is `transformers.models.mistral3.configuration_mistral3.Mistral3Config` used by Mistral-Small-3.2; its nested text config is another configuration object.

The fix shallow-copies the dataclass and writes the transient wrapped fields with `object.__setattr__`, then uses the same mechanism to restore fields on load. This bypasses constructor and assignment validation without mutating the original object.

Reproduced on 2026-09-14 with Transformers 5.14.1 and huggingface_hub 1.31.0, without model weights or PyTorch:

```python
from dataclasses import dataclass, fields
from transformers import Mistral3Config

@dataclass
class IntermediateValue:
    value: object
    device: object = None

config = Mistral3Config()
wrapped = {f.name: IntermediateValue(getattr(config, f.name))
           for f in fields(config)}
type(config)(**wrapped)
```

This raises `StrictDataclassFieldValidationError` for `transformers_version`: `IntermediateValue(value=None, device=None)` is neither `str` nor `None`. The exact `_replace_fields` helper from this PR successfully wrapped and restored that same real config, with `restored.to_dict() == config.to_dict()` and the original left unchanged.

The existing regression test exercises a validating dataclass through the actual cache. Its original PR receipt reports the full cache file at 17 passed. The 2026-09-14 revision adds the missing DCO sign-off only; its code tree is byte-identical to cf2ead8127ddbc7ef8855f51e30d156e86c2b769. Fresh hosted checks and maintainer approval remain required.
