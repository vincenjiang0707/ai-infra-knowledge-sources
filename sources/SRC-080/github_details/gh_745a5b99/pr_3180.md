# [PR #3180] [Datasets] Change `pad_to_max_length` default

source: https://github.com/vllm-project/llm-compressor/pull/3180
state: closed | updated: 2026-09-16T02:56:57Z
labels: ready

## 正文

Previously `pad_to_max_length` defaulted to true, since SparseML was focused on fixed-size batched training. However, this is a bad policy now that the library is focused on calibration.

## Why this change revealed a latent bug

Flipping `pad_to_max_length` to `False` surfaced a pre-existing inconsistency in the sequential pipeline.

Sequential subgraphs are traced under **eager** attention (`trace_subgraphs` patches `_attn_implementation="eager"`). Eager attention bakes an *unconditional* causal-mask add into the traced graph:

```python
add_2 = mul_6 + wrapped_4   # wrapped_4 == create_causal_mask(...)
```

At calibration runtime, however, the model ran with its default attention implementation (e.g. `sdpa`). `create_causal_mask` under sdpa returns `None` for a fully-attending (all-ones) mask as an optimization — so the baked-in add becomes `Tensor + None` and raises:

```
TypeError: unsupported operand type(s) for +: 'Tensor' and 'NoneType'
```

With `pad_to_max_length=True`, every calibration batch was padded to a fixed length, so the attention mask always contained padding zeros and `create_causal_mask` always returned a real tensor — accidentally hiding the trace/runtime mismatch. Once padding became dynamic, unpadded batches (all-ones mask) started returning `None`, exposing the bug. This reproduced via `tests/llmcompressor/observers/test_fused_observers.py::test_fused_observers_with_linear_sequential_targets`.

## Fix

Bake the eager-attention config patch into `calibration_forward_context` via a new `use_eager_attention` context manager, so tracing **and** runtime calibration always agree on the attention implementation. The now-redundant explicit patch in `trace_subgraphs` is removed.
