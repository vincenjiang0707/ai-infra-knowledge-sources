# [PR #3224] Centralize fused module mappings

source: https://github.com/vllm-project/llm-compressor/pull/3224
state: open | updated: 2026-09-26T10:07:41Z
labels: ready

## 正文

Closes #3177

## Summary

`FUSED_MODULE_MAPPINGS` in `observers/fused_mappings.py` is now the single
llm-compressor definition of the fused linear-layer groups tracked for
quantization. `oneshot` (`fuse_weight_observers`) and `model_free_ptq`
(`get_fused_names`, `ModelFreePtqConverter.get_dependencies`) both consume it.

The fusion mapping definitions, derived name indexes, and shared resolution
logic live together in `observers/fused_mappings.py`, while
`fuse_weight_observers` remains in `observers/helpers.py`.

This removes the separate `FUSED_LAYER_NAMES`, `DEFAULT_FUSED_MAPPINGS`, and
`_DEFAULT_FUSED_MAPPINGS_LIST` definitions, along with the now-unused
`match_names_set_eager` / `invert_mapping` helpers.

The general same-quantization check for oneshot mentioned in #3177 remains the
follow-up described by the issue.

Each mapping contains required `names` and optional `optional_names`. Names are
relative to the layers' common parent, which lets the same resolver operate on
HF module attributes and checkpoint weight names. Where HF and checkpoint
namings differ, separate naming entries describe the same packed group.

## Resolving architecture-dependent fused groups

A mapping applies to a parent only when all required members are present.
Optional members join when present, and larger applicable groups take
precedence over overlapping smaller groups.

This matters for Kimi `g_proj`, which can belong to different packed groups:

- KDA / delta-attention layers: `in_proj_qkvgfab`
- output-gated MLA layers: `fused_qkv_a_g_proj`

The resolver determines the group from the sibling layers present on that
specific parent rather than from the layer name alone.

For model-free PTQ, `model_free_ptq` reads the checkpoint weight map and passes
its tensor names into `ModelFreePtqConverter` before delegating to
`convert_checkpoint`. Fused groups are resolved once from that checkpoint
context, and only the primary member returns the other members as dependencies.

This avoids a compressed-tensors `Converter` protocol change. For microscale
schemes, constructing `ModelFreePtqConverter` without `weight_names` raises
instead of silently resolving fusion from incomplete context.

## Mappings added / updated

- Kimi KDA:
  - `in_proj_qkvgfab` = q/k/v/b/f_a
  - optional `g_proj` for full-rank gating
  - Transformers naming with nested `forget_gate.f_a_proj`
- Kimi MLA:
  - q_a/kv_a with optional output-gate `g_proj`
- DeepSeek V4 attention:
  - `fused_wqa_wkv`, under both HF and checkpoint naming
- DeepSeek V4 compressor:
  - `fused_wkv_wgate`, under both naming layouts
- DSA indexer:
  - `wk_weights_proj`
- Gemma 4:
  - `v_proj` is optional in the q/k/v mapping because
    `attention_k_eq_v` layers contain q/k but no separate v projection
- Existing gate/up, w1/w3, q/k/v, and MLA mappings move into the same SSOT.

Kimi's q/k/v `ShortConvolution` -> `conv1d` packing is not included: those are
convolution modules rather than the linear layers handled by this mapping. In
the current NVIDIA Kimi KDA implementation, vLLM constructs the packed conv1d
separately in float32 without a quantization config.

Current vLLM also constructs DeepSeek V4 `fused_wkv_wgate` and DSA
`wk_weights_proj` with `quant_config=None`. They are still represented here
because they are fusion relationships requested by #3177 and the resolver
should describe them consistently if their source linear layers are encountered
by llm-compressor.

## Behavior changes vs main

- Model-free fusion resolution no longer assumes parent names such as `attn` or
  `mlp`; sibling structure determines the group.
- Gemma 4 q/k layers without a separate `v_proj` no longer produce a missing-v
  dependency.
- MLA layouts without a q/k/v projection group no longer acquire a false qkv
  dependency.
- DeepSeek V4 checkpoint `wq_a` resolves against `wkv` instead of the older MLA
  `wkv_a_with_mqa` expectation.
- HF-named MLA and expert/shared-expert gate/up groups now participate in
  shared-scale resolution.
- Kimi KDA/MLA groups now include their additional packed projections.
- The existing requirement that members of a resolved packed group use
  compatible quantization now applies to these larger groups as well.

The previous q/k-without-v missing-dependency test is replaced by an optional
partner case because q/k without a separate v projection is a valid Gemma 4
layout.

## Interaction with related work

- #3206 has merged. This PR is rebased on it and integrates with the
  `convert_checkpoint` pipeline by passing checkpoint `weight_names` when
  constructing `ModelFreePtqConverter`.
- #3162 is still open and overlaps the observer-fusion path. It currently builds
  on `FUSED_LAYER_NAMES`; if it lands after this PR, that logic should use the
  centralized resolver instead.

## Tests

`tests/llmcompressor/observers/test_fused_mappings.py` covers:

- each supported fused-layer shape
- Kimi `g_proj` resolution on KDA vs MLA parents
- nested Transformers Kimi naming
- agreement between oneshot/module resolution and checkpoint/model-free
  resolution for the Kimi-K3 model definition
- both full-rank and low-rank Kimi gate configurations

`tests/llmcompressor/entrypoints/model_free/test_fused_names.py` covers:

- checkpoint-name resolution, including nested `forget_gate.f_a_proj`
- optional fused partners such as Gemma 4 `v_proj`
- precedence of larger overlapping groups such as Kimi KDA over generic qkv
- keeping identically named projections under different parent modules separate
- exactly one dependency-owning job per fused group
- tensors loaded exactly once across shards
- end-to-end model-free PTQ over mixed KDA, gated MLA, Gemma 4, MoE, and
  DeepSeek V4 groups
- one global scale across every resolved fused group

## H100 validation: main vs this branch

Using NVFP4A16 on `inference-optimization/Kimi-K3-0.40B-MXFP4` with the
attention projections targeted:

### `model_free_ptq`

- main: all 8 targeted packed attention groups had mismatched global scales
- this branch: 0 / 8 mismatched

### `oneshot`

- main: 7 / 8 targeted packed attention groups had mismatched global scales
- this branch: 0 / 8 mismatched

As a regression control, `Qwen/Qwen3-0.6B` produced byte-identical output on
main and this branch. Both checkpoints loaded and generated successfully with
vLLM 0.30.0, with the same measured perplexity.

The reduced Kimi checkpoint could not provide an end-to-end vLLM serving
validation. The generated NVFP4 checkpoints fail in vLLM 0.30.0 while
constructing the KDA layer, before checkpoint weights are loaded, at the
`in_proj_qkvgfab.weight` padding path. The untouched source fixture also cannot
serve with this setup for a separate reason: its MLA dimensions have no
supported prefill backend.

Therefore the Kimi comparison above does not claim an end-to-end vLLM pass; it
checks the saved global scales directly against the projection groups vLLM
packs together.
