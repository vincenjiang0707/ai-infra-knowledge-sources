# [PR #2944] [GPTQ] Avoid implicit CUDA sync when logging calibration sample count

source: https://github.com/vllm-project/llm-compressor/pull/2944
state: open | updated: 2026-09-22T15:58:16Z
labels: bug, gptq, needs-rebase, two-reviews

## 正文

## Summary

`GPTQModifier.compress_module_list` formatted the per-module `num_samples`
CUDA scalar tensor directly for a debug log:

```python
logger.info(f"Quantizing {name} using {int(num_samples)} samples")
```

`int(num_samples)` calls `Tensor.item()`, which forces an implicit
`cudaStreamSynchronize` on **every** Linear being quantized. Two problems:

1. **Hang (the filed bug):** under multi-rank DDP with sharded/divergent
   module sets across ranks (e.g. decoupled MoE experts), this sync directly
   follows a `dist.reduce` on the NCCL stream and can block indefinitely
   waiting on a kernel that is no longer pending from NCCL's perspective.
2. **Wasted syncs:** even in the happy path it is a synchronous host stall per
   Linear — tens of thousands of unnecessary `cudaStreamSynchronize` calls on
   a large MoE calibration run, purely to format a log message.

## Change

Materialize the sample count on the host once, explicitly, before logging:

```python
if isinstance(num_samples, torch.Tensor):
    num_samples = int(num_samples.detach().cpu().item())
logger.info(f"Quantizing {name} using {num_samples} samples")
```

The averaged-hessian division is untouched — it still divides by the
on-device tensor via `self._num_samples.pop(module)`, so quantization
numerics are unchanged.

## Scope

This addresses the **log-path host sync** identified in #2736 (the issue's
option (b)). The deeper NCCL-event registration in `wait_for_comms`
(option (a)) requires a multi-rank environment to reproduce and verify and is
left as a follow-up.

## Testing

- `ruff check src/llmcompressor/modifiers/gptq/base.py` passes.
- Logic change is behavior-preserving for the log (same integer value) and
  does not touch the quantization math. No local GPU/multi-rank environment
  was available to reproduce the original hang.

Fixes #2736
