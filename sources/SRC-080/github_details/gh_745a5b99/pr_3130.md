# [PR #3130] fix(autoround): pre-seed fp_ref from IntermediatesCache to skip collect_reference

source: https://github.com/vllm-project/llm-compressor/pull/3130
state: open | updated: 2026-09-24T11:19:21Z
labels: ready, autoround

## 正文

## Summary

AutoRound's \`collect_reference\` runs a full FP16 forward pass over all
calibration inputs at the start of every \`quantize_block\` call to obtain
reference outputs for SignSGD optimization. With \`propagate_error=False\`
(the default), \`SequentialPipeline\` already holds the identical tensors
in \`IntermediatesCache[k+1]\` — \`collect_reference\` is a duplicate that
exhausts CPU RAM for large N on big models (~39 GB/rank at N=8192,
seq=6144, hidden=3072, 8-GPU DDP).

Fix: before \`sequential_epoch_end\` fires, extract the next subgraph's
hidden states from \`IntermediatesCache\` and deliver them to the modifier
via \`set_fp_ref_outputs()\`. \`apply_autoround\` passes them to
\`quantize_block(reference_output=...)\`, skipping \`collect_reference\`
entirely. Falls back to the existing path when absent (last subgraph, or
\`propagate_error=True\`).

Two files changed in llm-compressor, ~45 lines.

> **Companion PR to intel/auto-round merged** — intel/auto-round#2289 (merged 2026-09-04)
> added \`reference_output\` to \`CompressionOrchestrator.quantize_block\`.
> The parameter is guarded with \`inspect.signature\` so existing installs
> (auto-round <=0.15.0, the current PyPI max) silently fall back to \`collect_reference\`
> as before. The optimized path activates automatically once auto-round 0.16.0 is
> released on PyPI; a follow-up PR will bump the \`setup.py\` pin to \`>=0.16.0\` at
> that point.

Also adds a docstring note to \`AutoRoundModifier.enable_torch_compile\` recommending
\`False\` for multi-GPU DDP with large models (per-rank compilation time can exceed the
NCCL watchdog timeout).

Closes #3129
Depends on: #3055 (merged)

## Test Plan

- Ran N=8192, seq=6144, iters=200, \`enable_torch_compile=False\` on 122B MoE
  (8 × H20 140 GB, 8-GPU DDP):
  - v1-2 model: before fix → CPU RAM OOM + NCCL watchdog timeout at layer 44;
    after fix → ✅ 49/49 blocks completed, ~10 h, peak system RAM ~310 GB
  - v1-3 model: after fix → ✅ all 8 ranks SUCCESS, 31291 s (~8h42m)
- \`make quality\` passes
- See linked Issue for quantization quality evaluation results
