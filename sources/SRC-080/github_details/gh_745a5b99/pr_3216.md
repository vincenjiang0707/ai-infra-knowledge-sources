## Summary

This is a **discussion Draft PR** for the streaming subgraph prefetch described in Issue #3132, extended to MoE models. The `pipeline.py` file is a `NotImplementedError` placeholder — the goal is to share the `checkpoint.py` implementation and benchmark results for review before writing the full `StreamingPipeline.__call__`.

Benchmark discussion (3 comments): https://github.com/vllm-project/llm-compressor/issues/3132#issuecomment-5776372775

## What's in this PR

`src/llmcompressor/pipelines/streaming/`

- **`checkpoint.py`** — Core utilities for the meta-device pipeline:
  - `CheckpointMap`: lightweight param_fqn → (shard_file, key, dtype, shape) index built from safetensors headers only (~7ms for 0.6B, <1s for 72B; no weights read at construction)
  - `stage_modules`: disk→CPU staging grouped by shard (background-thread safe; safetensors releases GIL during I/O)
  - `commit_staged_async`: H2D transfer queued on a dedicated CUDA stream — the sole addition over PR #3111's blocking `commit_staged`
  - `release_modules`: replace GPU params with meta tensors in <1ms (no disk write)
  - `MetaSubgraphPrefetcher`: wraps `stage_modules` in a background thread

- **`pipeline.py`** — `StreamingPipeline(CalibrationPipeline)` skeleton (`NotImplementedError` placeholder)

- **`__init__.py`** — Public exports

## Three-layer pipeline

```
Disk bg:    [read sg_N+1 ──────────]
H2D stream:                   [DMA sg_N+1 ──]
GPU:        [compute sg_N          ]  [wait≈0ms]  [compute sg_N+1 ────]
```

`inject_wait_s ≈ 0ms` validated across all 48 configurations tested (dense 27B/72B × 4 configs; MoE 30B × 6; MoE 235B × 6).

## Benchmark highlights

| Model | Best speedup | Key driver |
|-------|-------------|-----------|
| MoE 30B-A3B (N=16–128) | **15.1×** | `load_s` elimination (430–670s → 0.2s) |
| MoE 235B-A22B | **1.74×** | `load_s` elimination (2400–3200s → 26s) |
| Dense 72B (N=128, sl=2048) | **1.52×** | GPTQ compute dominates; sync overhead amortized |

A 235B model (~447 GB bf16) can be fully GPTQ-calibrated end-to-end on a **single L20 (48 GB)** — no model sharding, no multi-GPU coordination. This mirrors vLLM's deployment-time weight loading pattern applied to calibration.

## Code Review

This pull request introduces checkpoint utilities and a placeholder for a streaming (meta-device) pipeline to enable async subgraph prefetching and offloading. Key components include CheckpointMap for indexing safetensors headers, stage_modules for disk-to-CPU staging, and MetaSubgraphPrefetcher for background prefetching. Feedback on these changes highlights three critical improvements: first, dynamic fallback remapping should be implemented in CheckpointMap's lookup methods instead of unconditionally modifying keys during initialization; second, staged CPU tensors must be pinned using .pin_memory() to ensure truly non-blocking host-to-device transfers; and third, the background prefetch thread should catch BaseException instead of Exception to avoid silent failures and hangs.
