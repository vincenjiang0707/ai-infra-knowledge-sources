# [PR #2990] [Bugfix] Do not recurse into container modules in observe/update_qparams

source: https://github.com/vllm-project/llm-compressor/pull/2990
state: closed | updated: 2026-09-16T10:57:47Z
labels: ready

## 正文

SUMMARY:

`observe()` and `update_qparams()` in `modifiers/quantization/calibration.py` decide whether their `module` argument is one module or a collection of modules with `isinstance(module, collections.abc.Iterable)`. Container modules are both: `nn.ModuleDict` is a `Module` *and* is `Iterable`, and iterating it yields its keys, which are strings. From there `observe("weight", ...)` iterates the string, `observe("w", ...)` iterates `"w"` back into `"w"`, and the recursion never terminates:

```
  File ".../llmcompressor/modifiers/quantization/calibration.py", line 99, in observe
    observe(m, base_name)
  [Previous line repeated 992 more times]
  File ".../llmcompressor/modifiers/quantization/calibration.py", line 97, in observe
    if isinstance(module, Iterable):
       ^^^^^^^^^^^^^^^^^^^^^^^^^^^^
  File "<frozen abc>", line 119, in __instancecheck__
RecursionError: maximum recursion depth exceeded in comparison
```

Any model using `torch.nn.utils.parametrize` has such a `ModuleDict`, because torch stores parametrizations at `<module>.parametrizations`. The wav2vec2 family all do: wav2vec2, HuBERT, WavLM and UniSpeech-SAT weight-norm `encoder.pos_conv_embed.conv`.

Reproducer on `main` (28c9c76b), no downloads:

```python
import torch
from llmcompressor.modifiers.quantization.calibration import observe

model = torch.nn.Sequential(
    torch.nn.utils.parametrizations.weight_norm(torch.nn.Conv1d(4, 4, 1)),
    torch.nn.Linear(4, 4),
)
observe(list(model.modules()), "weight")  # RecursionError
```

**Scope, honestly.** On `main` neither in-tree caller trips this. `QuantizationModifier.on_sequential_epoch_end` and `GPTQModifier.on_sequential_epoch_end` both filter with `is_module_quantized` first, and a `parametrizations` `ModuleDict` has no `quantization_scheme`, so it never reaches `observe`. That filter arrived with #2784. On 0.12.0.x, where `on_event` passed `get_modules(parents)` straight through, it is a hard crash: `oneshot` on `microsoft/wavlm-large` with `QuantizationModifier(scheme="W8A16", targets=["Linear"], ignore=["classifier"])` dies with the traceback above (verified on 0.12.0.1). So on `main` this is a latent defect rather than a live crash — but the helpers are public and `QuantizationMixin` tells modifier authors to call them directly ("Modifier must explicitly call `observe(modules, base_name="weight")` then `update_qparams(modules, base_name="weight")`"), and the failure mode is a blown stack rather than an error message. The guard that hides it today lives in the callers, not in the helpers.

**Fix.** Check `Module` before `Iterable` so a container module is treated as a single module. `update_qparams` has the same dispatch and the same defect, so it gets the same treatment.

Two things worth calling out:

- This is a behaviour change for one case: passing an `nn.ModuleList`/`nn.Sequential` of quantized modules used to iterate it and now treats it as a single module, which is a no-op since containers carry no observers. No in-tree caller does that — callers pass a `list`, `dict_values`, or a single module — and the pipelines flatten with `.modules()`, so a container's children already arrive in the same list as separate entries.
- I fixed the helpers rather than filtering containers where the module lists are built (`Subgraph.submodules`, `list(model.modules())` in the basic/data-free pipelines), because there are several producers and only two consumers.

I did not add a `not isinstance(module, str)` guard: with the `Module` check in place nothing in-tree can produce a string here. Happy to add it if you would rather have the recursion hard-stopped regardless of caller.

Found while quantizing speech emotion classifiers (WavLM/HuBERT encoders with a classification head) to INT8/FP8/INT4. Our workaround on the released version is to fold the weight-norm parametrization away before `oneshot` and reapply it before saving.

### Ar4ikov · 2026-08-03

Hi @brian-dellabetta. A normal flow, not a synthetic case.

 I hit it quantizing speech emotion classifiers (WavLM/HuBERT/wav2vec2/UniSpeech-SAT encoders + a classification head) to INT8/FP8/INT4 with `llmcompressor==0.12.0.1`. Every wav2vec2-family model on the Hub weight-norms `encoder.pos_conv_embed.conv`, so `torch` keeps a `parametrizations` ModuleDict on it. On 0.12.0.x `QuantizationModifier.on_event` passed `get_modules(parents)` straight into `observe`, that ModuleDict reached it, and `oneshot` died with the traceback in the description. Public reproducer, verified on 0.12.0.1:

 ```python
 from llmcompressor import oneshot
 from llmcompressor.modifiers.quantization import QuantizationModifier
 from transformers import AutoModelForAudioClassification

 model = AutoModelForAudioClassification.from_pretrained("microsoft/wavlm-large")
 oneshot(model=model, recipe=[QuantizationModifier(
     scheme="W8A16", targets=["Linear"], ignore=["classifier"])])
 ```

 The `weight_norm(Conv1d(4, 4, 1))` in the test is just that reduced to something that runs in milliseconds — it's the same shape torch produces for the real model, not an unusual API use.

 Your example passes because it has no parametrizations at all, so no ModuleDict ever enters `observe`. Add weight norm and it recurses on `main` too:

 ```python
 import torch
 from llmcompressor.modifiers.quantization.calibration import observe

 model = torch.nn.Sequential(
     torch.nn.utils.parametrizations.weight_norm(torch.nn.Conv1d(4, 4, 1)),
     torch.nn.Linear(4, 4),
 )
 observe(list(model.modules()), "weight")  # RecursionError
 ```

 To restate the scope from the description: on `main` no in-tree caller trips this, because `on_sequential_epoch_end` filters with `is_module_quantized` since #2784 and a `parametrizations` ModuleDict has no `quantization_scheme`. So `main` has a latent defect in two public helpers rather than a live crash — the guard lives in the callers, `QuantizationMixin`'s docstring tells modifier authors to call `observe`/`update_qparams` directly, and the failure mode is a blown stack. Happy to close this if you'd rather keep the invariant in the callers; I'd just note the released version does hard-crash on this whole model family.
