# [PR #3186] [Tests] Lower w4a4_nvfp4 recovery threshold to 0.94

source: https://github.com/vllm-project/llm-compressor/pull/3186
state: closed | updated: 2026-09-17T18:43:31Z
labels: ready

## 正文

SUMMARY:
The `tests/lmeval/configs/w4a4_nvfp4.yaml` test was failing recovery validation because it relied on the default `recovery_threshold` of 0.95, while the observed recovery rates were ~0.94 for both exact_match metrics:

```
Recovery testing failed: exact_match,flexible-extract: 94.00% < 95.00% (base=0.7810, compressed=0.7360); exact_match,strict-match: 94.00% < 95.00% (base=0.7090, compressed=0.6670)
```

This PR adds an explicit per-metric `recovery_threshold` of 0.94, matching the pattern already used in the sibling `awq_nvfp4.yaml` config.

TEST PLAN:
- Confirmed the new thresholds parse through the `LmEvalConfig` pydantic model and that both metrics now pass: recovery rounds to 0.94 for each metric, which is `>= 0.94`.
- The actual GPU lm-eval run is gated behind `@requires_gpu(1)` and CI cadence, so it will run in the nightly/weekly lmeval jobs.
