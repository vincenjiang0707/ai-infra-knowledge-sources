# [PR #4286] [Fix][NIXL] Report failed static loads correctly

## 正文

**What this PR does / why we need it**:

The static NIXL L2 load path previously marked present keys as successfully loaded before executing the batched transfer. If transfer preparation or execution failed, the adapter still returned successful bitmap bits and emitted L2 access notifications even though destination memory could remain unchanged or stale. A transfer failure could also leak its handle because cleanup only occurred on the success path.

- Defer load bitmap and access-notification bookkeeping until the batched NIXL transfer completes successfully.
- Release created transfer handles in a `finally` block.
- Return an all-zero bitmap and emit no access notification when batch preparation or transfer fails.
- Continue treating missing keys as individual misses without failing an otherwise successful batch.
- Add failure-injection coverage for the result bitmap, destination memory, access notification, handle release, and load completion event.
