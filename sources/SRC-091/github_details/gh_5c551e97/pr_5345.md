## Summary

`lmcache server --trace-level events` (#5312) records the cache-event stream a server emits for the coordinator, one `.lct` file per server process. This adds the other half: replaying those files into a coordinator.

- **`lmcache/v1/mp_coordinator/events_replay.py`**: `EventsTrace.load(paths)` reads one or more `events`-level files with `TraceReader`, refuses another level or an unknown `cache_event_schema_version`, and merges the records by wall-clock time (a stable sort, so a server's own `seq` order is never disturbed). `replay(trace, target, speed)` hands each record to a `CoordinatorTarget`, logging each one; batches are passed exactly as recorded. The target does what a live server would: `POST /instances` at a `start` mark (through `registrar.register`, at the recorded address or loopback), a heartbeat per registered server on a timer, one `POST /events` per batch, `DELETE /instances/{id}` at `stop`. `speed` paces by the recorded clock; `0` (default) delivers as fast as the coordinator takes batches, which is safe because the coordinator orders per emitter by `seq`.
- **Crashes.** A file that ends without a `stop` mark is a killed server or a cut recording. The replayer calls the target's `end(instance_id)` after that server's last record, which only cancels its heartbeat, so the coordinator's own `instance_timeout` retires it the way it learns of a real crash. The summary counts such streams.
- **`lmcache trace replay-events FILE... --coordinator-url URL [--speed N] [--heartbeat-interval S]`**, a new sub-command beside `replay`, which stays storage-only and untouched. A replay always registers, heartbeats and deregisters like a real fleet; the docs say not to replay into a coordinator that has the same fleet live.
- **Recorder:** the `stop` lifecycle mark now carries `instance_id` like the `start` mark does, so a file's marks stay attributable once several files are merged. Additive; the cache-event schema is unchanged.
- Docs: `docs/source/cli/trace.rst` (the `replay-events` section) and the design doc's §8, §9.8, the lifecycle record table and a §12 "Replay" subsection.
