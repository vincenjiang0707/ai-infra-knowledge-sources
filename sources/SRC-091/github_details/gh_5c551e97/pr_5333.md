## 正文

Fixes #5190

## What changed

Converted the remaining logging f-strings in these four files to lazy `%`-style
logging arguments, so the message is only formatted when the record is actually
emitted:

- `lmcache/v1/cache_engine.py` — `logger.debug` in `move_kv_between_locations`
  now logs `"Trying to send %d memory objects to %s"`.
- `lmcache/v1/config.py` — the env-parse failure warning in
  `_update_config_from_env` now logs `"Failed to parse %s=%r: %s"`, preserving
  the `!r` rendering of the raw value.
- `lmcache/v1/config_base.py` — the singleton hint about the config-file env var
  now logs `"the environment variable: %s"`.
- `lmcache/v1/memory_management.py` — the ref-count/pin-count underflow warnings
  in `TensorMemoryObj` and `BytesBufferMemoryObj` now pass the address and count
  as `%s` arguments.

The rendered log text is unchanged in every case; only non-logging f-strings
(such as the `ValueError` in `set_used_size`) were left alone. I also removed
the four matching `G004` entries from `per-file-ignores` in `pyproject.toml`
since those paths are now clean.

Refs #5118, refs #3372. Follow-up for #5125 as described in #5190.
