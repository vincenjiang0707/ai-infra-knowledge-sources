## Summary
Addresses the documentation request in #5326. Confirmed by grepping the whole repo: `kv_load_failure_policy` does not appear anywhere in LMCache's Python or C++ source — it's a vLLM connector setting that LMCache's config passthrough carries but never reads or branches on. This isn't obvious from the docs, which show the flag in example configs without saying which connector actually enforces it.

- **`p2p.rst`**: adds a note after the first `LMCacheMPConnector` example clarifying the setting is passed through but not enforced, and that a genuine L2 load failure and an ordinary cache miss are currently indistinguishable (both recompute).
- **`disaggregated_prefill.rst`**: the config table there actually reveals the real distinction — in that example, `kv_load_failure_policy=fail` is set on the **`NixlConnector`** entry (vLLM's own connector, for the prefill→decode handoff), not on `LMCacheMPConnector` at all. Clarified this in the table so it's clear setting it under `LMCacheMPConnector` would have no effect.

This is documentation only — it doesn't change any enforcement behavior, since I don't have enough context on the intended design to know whether/how that should change (see the discussion I left on #5326 with the same findings).
