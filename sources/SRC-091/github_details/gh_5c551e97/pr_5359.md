## 正文

Splits the MP-mode portion out of #4864, per @maobaolong's review there. In-process mode is excluded, since that mode is marked deprecated and the review asked for it not to be submitted. The benchmark is a separate stacked PR (link added once opened).

### What this adds

A Neuron device backend so vLLM + LMCache caches KV on Trainium through the multiprocess (engine-driven) connector.

### Verification

trn2.48xlarge, vLLM 0.24.0, vllm-neuron 0.24.0.1.1.0, torch 2.11.0, Python 3.13, `meta-llama/Llama-3.2-1B-Instruct`, `chunk_size=256`.

Two engines run in sequence against one persistent LMCache MP server, sharing a 1022-token prefix. The first writes; the second is a fresh process, so anything it reads came from LMCache rather than vLLM's own prefix cache, which died with the first process.

Server counters after both runs (`GET /metrics`):

```
lmcache_mp_l1_write_chunks_total          4.0
lmcache_mp_l1_read_chunks_total           4.0
lmcache_mp_lookups_requests_total         2.0
lmcache_mp_lookup_requested_tokens_total  2048.0
lmcache_mp_lookup_hit_tokens_total        1024.0
lmcache_mp_lookup_hit_l1_tokens_total     1024.0
```

Both engines requested 1024 tokens. The first lookup hit nothing on a cold cache; the second hit all 1024, served entirely from L1. Four chunks written and four read matches 1024 tokens at `chunk_size=256`, and `GET /status` reports `total_object_count: 4`. Both engines produced identical output, so the KV that came back is usable rather than corrupt.

### Serving config

```bash
vllm serve meta-llama/Llama-3.2-1B-Instruct \
  --max-model-len 2048 \
  --max-num-batched-tokens 1024 \
  --enable-prefix-caching \
  --kv-transfer-config '{
    "kv_connector": "LMCacheMPConnector",
    "kv_role": "kv_both",
    "kv_connector_extra_config": {
      "lmcache.mp.host": "tcp://localhost",
      "lmcache.mp.port": 5555,
      "lmcache.mp.autostart": true,
      "lmcache.mp.autostart.server_args":
        "--l1-size-gb 4 --eviction-policy LRU --supported-transfer-mode engine_driven"
    }
  }'
```
