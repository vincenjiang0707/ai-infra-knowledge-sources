## Functional validation

The request sequence below was exercised on both model families.

| Step | DeepSeek-V4-Flash | Qwen-3.5-27B | Purpose |
|---|---:|---:|---|
| Initial request | 716 input / 512 output tokens | 726 input / 512 output tokens | Populate the cache |
| Longer request sharing the same prefix | 1,021 input / 474 output tokens | 1,025 input / 512 output tokens | Verify prefix reuse |
| Repeat the longer request | Tested | Tested | Verify the warm path |
| Flush radix cache and repeat | Tested | Tested | Verify flush and cold fallback |

## Accuracy

Evaluation configuration:

- 200 examples;
- 32 threads;
- 5-shot prompting;
- temperature `0`;
- maximum output length `2,048` tokens.

| Model | Evaluation | Baseline | LMCache cold | LMCache warm |
|---|---|---:|---:|---:|
| DeepSeek-V4-Flash | GSM8K | 0.975 | 0.96 | 0.97 |
| DeepSeek-V4-Flash | Mixed-prefix GSM8K | 0.985 | 0.985 | 0.975 |
| Qwen-3.5-27B | GSM8K | 0.745 | 0.73 | 0.75 |
| Qwen-3.5-27B | Mixed-prefix GSM8K | 0.86 | 0.865 | 0.85 |

The observed score variation is at most 1.5 percentage points across the sampled runs, with no consistent degradation between cold and warm LMCache paths.

## Serving benchmark

Benchmark configuration:

| Parameter | Value |
|---|---:|
| Dataset | Random |
| Requests | 256 |
| Input length | 10,000 tokens |
| Output length | 128 tokens |
| Request rate | Unlimited |
| Maximum concurrency | 32 |
| Seed | 42 |
| Warm-up requests | 0 |

`LMCache write` is first-run measurements with zero cache hits. `LMCache FS hit` restore reusable prompt KV from filesystem storage. The reported overall hit rate is lower than 100% because not every processed token is reusable prompt KV; all cached tokens in the hit runs came from the corresponding storage backend.

## Key observations

- LMCache filesystem hits increased total token throughput by **50.5%** on DeepSeek-V4-Flash and **64.0%** on Qwen-3.5-27B relative to baseline.
- LMCache filesystem hits reduced mean end-to-end latency by **33.8%** and **39.6%**, respectively.
- Mean TPOT improved by **33.5%** on DeepSeek-V4-Flash and **42.4%** on Qwen-3.5-27B with LMCache filesystem hits.
- The zero-hit write path introduces measurable overhead. The impact is model-dependent: total throughput decreased by **6.5%** on DeepSeek-V4-Flash and **19.1%** on Qwen-3.5-27B.


## Reproduction commands

<details>
<summary>start commands</summary>

- start sglang only with radix cache
```bash
sglang serve \
  --model-path <model-path> \
  --host 0.0.0.0 \
  --port 8021 \
  --served-model-name sglang_test \
  --tp-size 8 \
  --page-size 256 \
  --mem-fraction-static 0.80
```

- start sglang with lmcache
```bash
sglang serve \
  --model-path <model-path> \
  --host 0.0.0.0 \
  --port 8021 \
  --served-model-name sglang_test \
  --tp-size 8 \
  --page-size 256 \
  --mem-fraction-static 0.80 \
  --enable-unified-lmcache \
  --lmcache-config-file lmcache.yaml
```

- lmcache config
```yaml
# lmcache.yaml

mp_host: 127.0.0.1
mp_port: 15555

extra_config:
  lmcache.mp.mq_timeout: 300
  lmcache.mp.heartbeat_interval: 10
```

- start lmcache mp server
```bash
lmcache server \
  --host localhost \
  --port 15555 \
  --l1-size-gb 300 \
  --max-gpu-workers 8 \
  --max-cpu-workers 8 \
  --eviction-policy LRU \
  --chunk-size 256 \
  --separate-object-groups \
  --l2-adapter '{
    "type": "fs_native",
    "base_path": "<path>",
    "num_workers": 16,
    "use_odirect": false,
    "max_capacity_gb": 800,
    "eviction": {
      "eviction_policy": "LRU",
      "trigger_watermark": 0.9,
      "eviction_ratio": 0.1
    }
  }'
```

</details>
