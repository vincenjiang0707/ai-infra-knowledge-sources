# [PR #5170] feat(nixl): add IBM_SCALE backend support and fix NIXL transfer performance

source: https://github.com/LMCache/LMCache/pull/5170
state: open | updated: 2026-09-24T14:32:14Z
labels: High Prio

## 正文

Add IBM Storage Scale (`IBM_SCALE`) to all NIXL backend allowlists and fix
several performance bugs in the NIXL transfer path that are exposed by
`io_uring`-backed backends (IBM_SCALE, GDS).

1. Add IBM_SCALE to allowlists
   - `nixl_store_dynamic_l2_adapter.py`: `_VALID_DYNAMIC_BACKENDS` (via `FILE_DYNAMIC_BACKENDS`)
   - `nixl_store_l2_adapter.py`: `_VALID_NIXL_BACKENDS`, `_FILE_BACKENDS`

2. Fix 10 ms polling floor in `post_non_blocking` / `_post_non_blocking`
   Add a 20-iteration spin-check before falling back to a 1 ms cooperative
   sleep. Move the sleep before `check_xfer_state` so a transfer completing
   on the first poll exits immediately without paying an extra sleep.
   Eliminates the ~10 ms floor that dominated latency for `io_uring` backends.

3. Concurrent store via `asyncio.gather` in `_execute_store_in_the_loop`
   Reserve all keys under the lock first, then launch all
   `dynamic_store_file` coroutines concurrently. Per-key failure isolation
   via `return_exceptions=True`. Matches the existing concurrent load path.

4. Fix `_open_flags()`: `O_RDWR` → `O_WRONLY` (store) / `O_RDONLY` (load)
   `O_RDWR` is ambiguous for backends that infer write intent from the fd
   access mode (IBM_SCALE uses this to select the right GPFS prefetch
   hint). `O_WRONLY`/`O_RDONLY` is also better POSIX practice.

5. Move `os.stat` outside the lock in secondary lookup
   `_secondary_lookup_locked` called `os.stat` while holding `_lock`,
   blocking concurrent store/load on slow/remote filesystems. Refactored
   to a two-lock, one-stat pattern: collect missing keys under lock, stat
   them unlocked, then commit found entries under lock. Removes
   `_secondary_lookup_locked` entirely.

Refs: ai-dynamo/nixl#2134

**What this PR does / why we need it**:

Enables `IBM_SCALE` as a valid backend in LMCache's static and dynamic NIXL
adapters. Without this, LMCache raises a `ValueError` at config validation
time even when the IBM_SCALE plugin is installed. The accompanying
performance fixes (items 2–5) benefit all fast `io_uring` backends — GDS
users also see reduced TTFT.

**Special notes for your reviewers**:

- Items 2–5 are independent of IBM_SCALE and improve the general NIXL transfer
  path. They can be reviewed/merged separately if preferred.
- The companion upstream NIXL plugin PR is ai-dynamo/nixl#2265.
