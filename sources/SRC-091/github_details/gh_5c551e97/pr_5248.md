> [!NOTE]
> **High Risk**
> Changes KV load/store semantics on the preemption and resume path; incorrect behavior would corrupt cached prefixes across requests, though the new ShareGPT differential CI is meant to catch that.
> 
> **Overview**
> Adds **MP connector support when vLLM preempts requests**: resumed work can **reload KV from LMCache** instead of always recomputing, and the **LMCache-driven transfer path** now **waits on in-flight stores** before freed blocks can be reused so preempted keys are not written with another request’s KV.
> 
> Connector changes remove the `PREEMPTED` early exit in `get_num_new_matched_tokens`, **assign** (don’t accumulate) `num_stored_tokens` when the scheduler polls repeatedly under memory pressure, and emit **`<resume-load>`** logs for CI to prove the resume path ran.
> 
> **Buildkite** gains a **`preemption_correctness`** job (2-GPU baseline vs LMCache, pinned `NUM_GPU_BLOCKS_OVERRIDE`, ShareGPT answer agreement, preemption metrics, optional debug ladder) with **sync vs async scheduling** matrix wiring in `vllm.sh`. A design doc describes behavior and the test ladder.
