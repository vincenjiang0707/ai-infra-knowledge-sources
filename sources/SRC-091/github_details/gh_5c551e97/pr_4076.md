**What this PR does / why we need it**:

Under chunked prefill, connector metadata flows scheduler → worker only.
`DisaggSpec.num_transferred_tokens` is advanced on the worker after a
successful PD store, but that mutation is not written back to the
scheduler's `RequestTracker`. The next chunk rebuilds `ReqMeta` with
`num_transferred_tokens=0`, so:

```python
skip = min(save_spec.skip_leading_tokens, disagg_spec.num_transferred_tokens)
```

becomes `min(N, 0) = 0` and the already-transferred prefix is stored/PD'd
again (or relies on decoder-side key dedup).

This PR keeps a worker-local `req_id → transferred` watermark, restores it
before the skip gate, and records it after a real store (last PP rank only,
same as today's progress advance). LocalCPU `skip_leading_tokens` is never
used to seed PD progress: a full local hit with zero peer progress must
still transfer.
