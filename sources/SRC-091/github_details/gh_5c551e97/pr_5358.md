## Summary

[#5308](https://github.com/LMCache/LMCache/pull/5308) added the LMCache-driven direct copy-engine transfer (`execute_direct_copy_transfer` / `cudaMemcpyBatchAsync`) but gated it to CUDA, on the premise that *"HIP has no equivalent."* That premise is outdated for **ROCm 7.x (HIP 7.15)**, which ships `hipMemcpyBatchAsync` with the **identical 9-arg (`failIdx`) signature**, plus `hipMemcpyAttributes` and `hipMemcpySrcAccessOrderStream`. This PR enables the same path on ROCm.

## Changes

- **`csrc/cuda/mp_mem_kernels.cu`**
  - Enable `LMC_HAS_BATCH_MEMCPY` under `USE_ROCM && HIP_VERSION >= 71500000` (include `<hip/hip_version.h>`).
  - In `batch_memcpy_supported()`, skip the CUDA-versioned `>= 12080` runtime/driver comparison on ROCm — HIP versions its runtime/driver on a different scale and the compile-time `HIP_VERSION` guard already ensures the API is present.
  - The existing CUDA 12.8/12.9 (`#else`) call site is a byte-for-byte match to the HIP signature, so no call-site change is needed.
- **`setup_extensions/build_profiles/rocm.py`** — torch's *bundled* hipify map predates the batched-copy API, so it leaves a few tokens untranslated. Patch the hipified output for: `cudaMemcpyBatchAsync`, `cudaMemcpyAttributes`, `cudaMemcpySrcAccessOrderStream`, `cudaStreamPerThread`.
- **Docs** — `lmcache_driven_transfer_copy_paths.md` requirements now note ROCm/HIP ≥ 7.15.
- **Tests** — GPU test skip reasons updated; the skip predicate is unchanged and already keys on `torch_device_type == "cuda"` (true on ROCm) and `batch_memcpy_supported()`, so the existing parity tests now run on ROCm.

## Isolation to ROCm (no CUDA behavior change)

Every executable change is `USE_ROCM`-guarded, and `rocm.py` is the ROCm-only build profile. Verified concretely: preprocessing `mp_mem_kernels.cu` with a **CUDA build config** (`USE_ROCM` undefined, `CUDART_VERSION=12080`) yields **byte-identical** source selection before vs. after this PR, and `LMC_HAS_BATCH_MEMCPY` still resolves to `1` on CUDA ≥ 12.8.
