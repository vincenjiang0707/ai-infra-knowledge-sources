**What this PR does / why we need it**:

Add SmartIO muFile backend for MP GDS L1

**Special notes for your reviewers**:
1. Why modify the common file gds_context.py:
lmcache/v1/gpu_connector/gds_context.py is the common MP GDS lifecycle owner. It currently contained CUDA-specific assumptions:
- It directly accessed torch_dev.current_stream().cuda_stream.
- It used constants named _CUFILE_ALIGNMENT and _MAX_CUFILE_REGION.
- It did not explicitly close the selected backend driver during GDSContext.close().
Those assumptions prevent a MUSA backend from integrating cleanly. 

2.  The changes:
- Add get_raw_stream_handle(stream), which resolves handles in this order:musa_stream,cuda_stream,ptr
- Replace direct .cuda_stream access in registration, deregistration, read, write, and submission-checkpoint paths with the helper.
- Move alignment and registration-region limits behind "_gds_async" capability queries: get_io_alignment(),
get_max_registered_region_bytes().
- Call the selected backend’s close_driver() during context teardown.

## E2E test methodology

**Architecture (MP-only, production shape):**

```text
Engine worker (client)                     LMCache MP server
┌───────────────────────────┐              ┌──────────────────────────────┐
│ SGLang MHA paged KV (musa)│  ZMQ + IPC   │ GDS L1: GDSContext (mufile)  │
│ lmcache_driven: exports   │ ───────────► │  slab files, libmufile DMA   │
│ K/V as MUSA IPC handles   │ ◄─────────── │  reads/writes worker memory  │
│ no local GDS storage      │  completion  │  via imported IPC handles    │
└───────────────────────────┘              └──────────────────────────────┘
                                           GET /status → gds_l1_mufile_stats
```

**Workload:** two identical requests with the same 1024-token prefix (Qwen3-8B geometry: 32 layers × 8 KV heads × 128 head dim, bf16, SGLang MHA paged layout, 16-token blocks).

**Request lifecycle exercised :**

```text
store(prefix)                    # round 1: worker GPU → server slab via DMA
lookup(request_id)               # round 2: submit prefetch (async)
wait_prefetch_status(request_id) # block until read-locks are held
retrieve(request_id)             # server slab → worker GPU via DMA
free_lookup_locks + end_session  # release locks, close session
```

**Server config:**

```bash
lmcache server --port 5580 --http-port 6580 --max-workers 4 \
  --supported-transfer-mode lmcache_driven \
  --l1-size-gb 5 --gds-l1-path /data/lmcache-business \
  --gds-l1-backend mufile --gds-l1-use-direct-io \
  --eviction-policy LRU --disable-observability
# env: LMCACHE_MUSA_HANDLE_TRANSFER=1 LMCACHE_MUFILE_STATS=1 MUFILE_ALLOW_COMPAT_MODE=FALSE
```
