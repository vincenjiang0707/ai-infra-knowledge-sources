# [PR #3766] Fix KeyError on lookup_cache re-query after async lookup timeout

## 正文

Fixes #3685.

When an async lookup times out, lookup_cache() returns 0 and pops the request's
first_lookup_time entry, but leaves reqs_status[lookup_id] as None (still
pending). If vLLM calls lookup_cache() again for the same id (which happens with
nixl + enable_async_loading), it re-enters the `req_status is None` branch and
indexes self.first_lookup_time[lookup_id] directly, raising KeyError at
lmcache_async_lookup_client.py:175 and taking the vLLM worker down.

This treats a missing first_lookup_time the same as an expired one: the request
reports a cache miss (0) so vLLM recomputes, instead of crashing.

Added a regression test that drives the timeout then re-query sequence through
the public lookup_cache interface (no server, so the request stays pending). It
reproduces the KeyError on current main and passes with the fix.
