## 正文

**What this PR does / why we need it**:

Add an explicit Buildkite runtime selector so an MP-focused PR can skip the audited in-process integration suites, including comprehensive tests.

| Selection | PR label | Manual build environment |
| --- | --- | --- |
| In-process | `ci-inprocess` | `LMCACHE_CI_MODE=inprocess` |
| Multiprocess | `ci-mp` | `LMCACHE_CI_MODE=mp` |
| Both modes | Neither label, or both | `LMCACHE_CI_MODE=all` |

A nonempty environment setting overrides the labels. 
Unknown values warn and keep both modes eligible. 
Scheduled builds and `force-ci` bypass mode selection. Eligible jobs retain their existing path and `full` trigger conditions.

The shared selector is applied before K3 pipeline upload and before setup in older Buildkite entry points:

- **In-process:** K3 integration, correctness, and comprehensive; older comprehensive, vLLM integration, correctness, and MMLU pipelines.
- **MP:** K3 multiprocess, SGLang MP, CacheBlend plugin compatibility, XPU multiprocess, the older multiprocessing pipeline, and the AMD MP benchmark step.
- **Existing selection retained:** unit tests, shared/mixed and unclassified suites, MUSA hardware smoke, MetaX, the external legacy E2E harness, and GitHub Actions. The AMD unit step remains eligible when its MP benchmark is skipped.
