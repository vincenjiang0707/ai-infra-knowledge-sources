## 正文

**What this PR does / why we need it**:

The legacy documentation already marks in-process mode deprecated, but runtime startup provides no migration notice and some onboarding instructions still promote or incorrectly select that mode. 
This PR makes the existing soft deprecation consistent while retaining working legacy deployments.

- Log one actionable WARNING per operating-system process when the legacy KV engine or vLLM connector is constructed. Both entry points share a PID-aware guard, covering scheduler-only vLLM startup and allowing forked children to emit their own warning. Imports and shared configuration/metadata remain silent.
- Make MP the primary quickstart path where the integration and required features are supported. Preserve vLLM connector-version requirements, correct SGLang mode-selection guidance, use separate MP/legacy configuration files, and qualify TensorRT-LLM connector-preset requirements.
- Add `legacy/migration_to_mp` with configuration mappings, server pool sizing, cache-format precautions, store/retrieval verification, feature gaps, and rollback instructions that preserve existing configuration and cache data.
- Label legacy tutorial/example sections explicitly without deprecating shared tools or their MP functionality. Clarify that the separate encoder-cache engine is outside this KV-cache deprecation.
- Add regression coverage for legacy startup and deduplication, scheduler-only warnings, isolated fork behavior, silent shared imports, and actual MP server startup over ZMQ and gRPC. Negative checks include a logging positive control so disabled capture cannot produce a false pass.

**Special notes for your reviewers**:

Production changes are limited to `lmcache/deprecation.py` and calls from `LMCacheEngine.__init__` and `LMCacheConnectorV1Impl.__init__`. Legacy SGLang and TensorRT-LLM engine construction reaches the same engine boundary. The warning uses the existing logger and is independent of the startup banner.

No existing files are deleted or renamed. Legacy APIs, configuration defaults, request handling, and shutdown behavior remain intact. MP implementations, shared config/metadata types, dedicated MP documentation/examples, and `AGENTS.md` are unchanged. There is no automatic mode switch, server launch, configuration translation, removal date, or new maintenance guarantee.

Migration does not imply feature parity: the guide records MP CacheGen and encoder-cache gaps, unverified hidden-state parity, platform-specific SGLang restrictions, and version-dependent TensorRT-LLM support. CacheBlend has an MP implementation with different configuration.
