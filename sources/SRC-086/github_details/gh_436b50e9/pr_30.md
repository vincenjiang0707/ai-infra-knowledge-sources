## 正文

### Background
Medusa heads learn to predict multiple tokens into the future as a function of the base model's final hidden states. Each Medusa head is a linear layer that maps each token's final hidden state to produce its output of a token prediction for a specific position in the future (e.g. 2 tokens in the future).

Considering a sequence length of 512, this means that tokens 501, 502, and 503 generated in parallel (i.e. 3 tokens by 3 Medusa heads) are a linear transformation of the same final hidden state stored in the token 500 of the sequence.

Beyond this single token hidden state, can we also take advantage of the information stored in the final hidden states of all previous tokens to predict 501, 502, and 503?

### Method
When fine tuning the Medusa architecture, we can give Medusa heads a lightweight attention mechanism (e.g. two decoder layers) to "move" information into the hidden state of the last token before applying each Medusa head's linear transformation. This gives the Medusa heads "access" to the information in all previous token hidden states because we fine tune two attention layers (shared by all Medusa heads) jointly with the Medusa LM heads.

Concretely, we
1) create two new LlamaDecoderLayers and a single LlamaRMSNorm,
2) initialize their weights to the weights of the base model's last two LlamaDecoderLayers and post decoder layers LlamaRMSNorm,
3) fork the computation path of the hidden states during the forward pass to get original and medusa logits

#### Why two decoder layers?
Anthropic has found that, compared to single layer attention models, two layer (and up) attention models can predict tokens later in the sequence significantly better than tokens earlier in the sequence ([Olsson et al. 2022](https://transformer-circuits.pub/2022/in-context-learning-and-induction-heads/index.html); [Elhage et al. 2021](https://transformer-circuits.pub/2021/framework/index.html)).

i.e., a minimum two attention layers allows the model to learn compositions of query/key/value operations that execute more general patterns of communication between subspaces of token residual streams (e.g. induction heads searching for and retrieving information that completes a local pattern).

#### Why should we expect there to be valuable information in previous token residual streams?
The loss function encourages it: In a sequence window of size 512, the final hidden states of token 500 are mapped by the linear LM head layer to predict token 501. As a secondary objective however, the hidden states before the last decoder attention layer can be attended to by future token positions--thus, in this layer there is an optimal capacity tradeoff point where the value of allocating information to predict the **next** token intersects with the value of allocating information to predict the _**next**_ **next** token (or any other future token). Once the value of preparing for future tokens outweighs allocating more information to predict the next token, we should expect the model to do so.

By fine tuning the last two decoder layers with 3 Medusa heads, we're training the attention mechanism to move information from tokens[:500] into tokens[500] that is useful for predicting tokens 501, 502, and 503. The secondary objective above indicates the likelihood of information existing in tokens[:500] that is valuable for predicting token 502, but in the original Transformer architecture the attention heads wouldn't be rewarded for moving that information into token 500, since 500 only predicts 501. But now that 500 is predicting 501, 502, and 503, we can tune a few of the final attention heads to move all relevant information into 500.

Intuitively, this should allow the model to decode tokens later in the sequence window faster than tokens earlier in the sequence window because it has had more space to prepare.

#### But this adds more parameters to the inference
The two decoder layers are shared among all Medusa heads, but it still may be the case the extra information gained via attention is not worth the added weight memory and flops--a side by side profiling of decoding will test this.

1) conversations with 2 or more entries
