## 正文

## Summary

Add a standalone native MLX path for EXL3 fallback quantization when no usable Hessian/LDL decomposition is available. It composes the merged tensor-core tile transform, native Viterbi quantizer, and inverse transform while preserving the existing EXL3 output layout.

This PR covers the fallback branch only. LDLQ compensation, processor integration, regularization, and packing changes are intentionally out of scope.

## What Changed

- Added `exl3_fallback_quantize_mlx(...)` for regularized EXL3 float32 weights.
- Returns the reconstructed float32 matrix plus unpacked int16 trellis states in the same shapes as the Torch/CUDA path.
- Preserves EXL3's input/output divisibility requirements and forwards bit-width, codebook, and bounded-workspace validation.
- Added independent Torch-oracle coverage for bits 2/4/8, all three codebooks, true half-rounding ties and adjacent values, signed zero, codebook endpoints, invalid inputs, and all nine pinned Qwen3.8-27B projection shapes.
- Added a reproducible full-shape benchmark with exact output-drift columns.

EXL3 quantization is canonically float32, so checkpoint bfloat16 is not applicable to this stage.

## Accuracy

Environment: Apple M5 Ultra (256 GB), MLX 0.32.2, Torch 2.14.0. Full Qwen matrix dimensions use a deterministic four-tile pattern bank. The independent Torch oracle performs its own tile transform and Viterbi search, expands the independently quantized patterns across every output tile, and compares the complete reconstructed matrix and every int16 state.

## Performance

Inputs were resident. MLX timings are median of 3 measured full-matrix runs after 1 warmup.

The corresponding `main` implementation requires the EXL3 CUDA extension and cannot execute on Apple silicon. The Torch column is explicitly an estimate: median-of-3 independent CPU-oracle time per tile, measured through an eight-tile minimum matrix and multiplied by the full tile count. It is not a measured CUDA comparison.
