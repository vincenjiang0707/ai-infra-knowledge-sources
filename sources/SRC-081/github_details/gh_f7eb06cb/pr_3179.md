## 正文

## Summary

- correct the vendored GGUF Q8_1 block size from 40 bytes to 36 bytes
- match llama.cpp's `block_q8_1` C ABI: two FP16 values plus 32 int8 quants
- add a minimal GGUF reader regression fixture that verifies the 36-byte payload exactly
- add SPDX and llama.cpp GGUF credit headers to every changed file

## Upstream audit

Latest stable Python package: `gguf==0.19.0` (May 6, 2026).

GPTQModel already vendors the 0.19.0 reader API and supplies its own quantizers, so this PR does not add an external `gguf` dependency. Adding one would make packing behavior depend on whether the optional package is installed.

The 0.19.0 Python size table still describes Q8_1 as 40 bytes, while the llama.cpp C ABI at that release is 36 bytes. Current llama.cpp `master` corrects the Python table to `2 + 2 + 32`. Its only new quantization enum since 0.19.0 is Q2_0, which GPTQModel already supports. Stable 0.19.0 also added NVFP4 dequantization, which GPTQModel already supports.

Sources:

- https://pypi.org/project/gguf/
- https://github.com/ggml-org/llama.cpp/blob/gguf-v0.19.0/ggml/src/ggml-common.h
- https://github.com/ggml-org/llama.cpp/blob/master/gguf-py/gguf/constants.py

## Compatibility impact

| Item | Before | After |
|---|---:|---:|
| Q8_1 logical block | 32 values | 32 values |
| Reader bytes per block | 40 | 36 |
| llama.cpp C ABI match | No | Yes |

This is a reader metadata correction. It does not change inference, quantization, or MLX kernels, so kernel speed metrics are not applicable.
