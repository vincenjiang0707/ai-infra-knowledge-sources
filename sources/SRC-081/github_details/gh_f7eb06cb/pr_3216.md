## 正文

## Summary

Accelerate the MLX BitsAndBytes NF4/FP4 inference kernel by decoding four consecutive values per lane instead of two. This halves loop/control work and reuses each block scale across two packed bytes.

The complete layer path is faster for every tested Qwen3.8-27B projection, activation dtype, and NF4/FP4 combination:

- Decode (1 row): 1.014–1.152×
- Prefill (16 rows): 1.075–1.283×

## What Changed

- Add a four-code path when the input width and block size are divisible by four.
- Retain the existing two-code and scalar paths for other layouts.
- Preserve codebook lookup, FP16 weight rounding, bias handling, output dtype, and public API.
- Add a dependency-free Torch-oracle boundary regression covering all codebook regions, block transitions, signed zero, and neighboring FP values.
- Extend the Qwen-shape regression to check the FP32 kernel output separately from the visible FP16/BF16 output.
- Add a reproducible main-versus-candidate benchmark.
- INT8 and other quantization methods are intentionally out of scope.

The nonzero main differences are expected floating-point reduction regrouping: each lane now accumulates four consecutive products rather than two. Packed codes, codebook values, FP16 dequantized weights, and term order within each four-value group are unchanged. All observed raw and rounded drifts are more than 65× below the 2e-3 inference limit.
