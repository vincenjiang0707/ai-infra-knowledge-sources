## 正文

## Summary

Route large BitsAndBytes NF4/FP4 weights through the existing native MLX quantizer from the standard `BitsAndBytesLinear.pack_original` processor on Apple silicon.

The dominant weight quantization runs on MLX. Compressed nested statistics stay on the much smaller CPU scale vector, which preserves the exact bitsandbytes reduction and serialized state. Weights below 4,194,304 elements remain on the existing Torch/bitsandbytes path because MLX does not win below that measured crossover.

## What Changed

- Added an Apple-silicon MLX bridge for standard BitsAndBytes NF4/FP4 processor packing.
- Preserved exact bitsandbytes `QuantState` layouts for compressed and uncompressed statistics.
- Added a measured crossover guard so small weights retain the faster existing path.
- Added processor boundary/oracle tests for NF4/FP4, FP16/BF16, and both statistics modes.
- Added a reproducible Qwen3.8-27B benchmark covering every projection shape.
- INT8 is intentionally unchanged: end-to-end screening did not beat Torch on the smallest Qwen projections.

## Notes

- No checkpoint schema or public API changes.
- Non-Apple platforms, unavailable MLX installs, and small matrices retain the existing bitsandbytes implementation.
- The quantization-stage output is byte-for-byte identical to bitsandbytes across every benchmark row; no tolerance was consumed.


### Crossover guard validation

The exact 4,194,304-element dispatch threshold was separately measured with the same 10-warmup/301-interleaved-sample protocol. All eight FP16/BF16 × NF4/FP4 × compressed/uncompressed cases won; the minimum was **1.649×** and the maximum was **2.615×**.
