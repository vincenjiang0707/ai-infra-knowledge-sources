## Summary

Add an opt-in MLX/Metal kernel for FOEM's default alpha-zero quantization update. It computes per-group FOEM scales and zero points in MLX, fuses the sequential column and beta correction into one Metal dispatch per group, and applies cross-group Hessian updates with the existing accurate MLX matmul. It returns the pseudo-quantized weight, scales, and zero points in MLX arrays. The existing FOEM processor still uses Torch.

## What Changed

- Add `foem_quantize_weight_mlx(weight, inverse_hessian, bits=4, group_size=128, beta=0.2, sym=True)`.
- Match the existing Torch `Quantizer.find_params` and FOEM `alpha=0` arithmetic for 2–8 bits, symmetric or asymmetric groups, and beta in [0, 1].
- Validate nonempty shapes, supported dtypes, Hessian dimensions, finite values, and a positive Hessian diagonal.
- Add an independent Torch oracle, full packed-code reconstruction checks, one-input-step rounding boundary tests, and nine [Qwen3.8-27B projection](https://huggingface.co/Qwen/Qwen3.8-27B/blob/1d4bf0f2ff6012fd82039f2fa52739d0dd7c60c0/config.json) tests.
- Add a reproducible per-projection performance benchmark against the corresponding Torch group-update arithmetic.

This is a standalone native API. Alpha-enhanced FOEM/GPTAQ, MSE parameter search, activation-order permutation, and static groups remain on the existing Torch path; those configurations are outside this API. The native path uses `blocksize=group_size` and accepts group sizes 16, 32, 64, and 128.

## Performance vs main Torch arithmetic

M5 Ultra, group size 128, 4-bit symmetric, beta 0.2. BF16 source weights and diagonal inverse Hessians were resident in each backend before timing. The benchmark reproduces main's alpha-zero Torch per-channel parameter calculation and sequential FOEM group-update loop, and compares it with the native MLX API. Both timings exclude Hessian construction, input transfer, and the FOEM processor lifecycle. One warmup followed by median of three complete calls, with MLX outputs evaluated.
