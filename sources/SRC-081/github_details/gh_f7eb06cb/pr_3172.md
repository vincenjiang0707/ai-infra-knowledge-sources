## Summary

- add an opt-in native MLX implementation of EXL3's Hessian-compensated LDLQ stage
- preserve EXL3's descending 16-row block order and buffered error-feedback semantics
- reuse the existing native MLX EXL3 tile-layout and Viterbi kernels
- add a dedicated Metal float32-FMA reduction for `factor.T @ error`
- retain compensation only for the unquantized prefix to avoid writes that cannot be consumed
- keep this PR limited to LDLQ; it does not integrate unrelated EXL3 stages

The generic MLX matmul path was not accepted blindly: on a dense feedback fixture its normalized correction drift was `5.9159965e-6`, it crossed 69 float16 input boundaries, and it ultimately changed 57 trellis states. The dedicated reduction removes that regression.

## Accuracy

Target: Mac Studio, M5 Ultra, 256 GB. EXL3 matrix layout is `(input_features, output_features)`. Qwen tests use 4-bit MCG and a nonzero `2^-16` block-subdiagonal LDL coupling. Every complete reconstructed weight and every unpacked trellis state is compared with an independent Torch oracle.

Additional numerical checks:

- dense nonzero LDL feedback: exact states and reconstructed weights for 2/4/8-bit, with 16- and 32-row buffers
- rounding thresholds: exact agreement below, at, and above ties for all three EXL3 codebooks, plus signed zero and codebook extrema
- Metal reduction versus float64 Torch oracle: normalized drift `2.01891458581e-7`, max absolute drift `2.14741856908e-7`, no nonfinite values

## Performance

Main's EXL3 LDLQ implementation is CUDA-only and calls `torch.cuda` streams/synchronization, so **main has no runnable M-chip latency**. The closest runnable reference is the independent Torch CPU oracle. Its full-shape time below is extrapolated per tile; MLX is measured end-to-end on the complete projection with resident weight/factor inputs, one warmup, and median of 3 runs.
