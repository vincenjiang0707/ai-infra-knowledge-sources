## Summary

Reduce the native MLX GGUF MXFP4 nearest-code search from all 16 signed codebook entries to the eight nonnegative magnitudes. The kernel applies the source sign after selecting the magnitude, preserving the existing lower-magnitude tie rule and packed bytes while removing seven impossible opposite-sign comparisons per weight.

## What Changed

- Search the eight unique MXFP4 magnitudes instead of both signed halves of the codebook.
- Reapply the sign bit only for nonzero selected magnitudes, preserving the existing unsigned-zero behavior.
- Add a focused positive/negative code-pair regression against the independent Torch oracle.
- Update the resident-input Qwen benchmark to compare directly with the current `main` signed search.
- No public API or packed-layout changes. Other GGUF methods are intentionally out of scope.

## Notes

For a negative finite value, the absolute error to a negative codebook entry is exactly the same arithmetic as the corresponding positive magnitude comparison. The optimized search therefore keeps the original candidate ordering among magnitudes and reconstructs the sign only after the winning nonzero magnitude is known.
