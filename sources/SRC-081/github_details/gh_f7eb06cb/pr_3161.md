## 正文

## Summary

- Fix MLX conversion routing for ParoQuant layers. `ParoLinear` inherits the AWQ holder and was also entered in `awq_dtype`, so merged `main` replaced it with `MlxAWQLinear` before the Paro wrapper could be selected.
- Apply all learned ParoQuant rotation stages in one Metal dispatch with threadgroup memory for group sizes 16, 32, 64, and 128.
- Keep the merged one-stage FP16 path where it is already optimal and retain the existing fallback for full-width groups larger than 128.
- Preserve FP16 and BF16 projection output dtype.
- Keep `ParoMlxQuantLinear` as the GPTQModel `BaseQuantLinear` holder for method, format, bit, group-size, shape, platform, and dtype validation.

## Supported ParoQuant matrix

| Property | Covered values |
|---|---|
| Weight format | ParoQuant packed AWQ codes |
| Bits | 4 |
| Group size | `-1`, 16, 32, 64, 128 |
| Rotation stages | 1 and 8 |
| Activation output | FP16 and BF16 |
| `desc_act` | false and true |

## Accuracy and performance vs main

Apple M5 Ultra, 256 GB, MLX 0.32.2. The baseline invokes the exact merged-main `MlxParoLinear` runtime directly because main’s converter currently misroutes ParoQuant layers to the AWQ wrapper. Each timing is the median of 21 alternating measurements after 3 paired warmups. `Speedup = main / PR`; values above 1.0 favor this PR. Accuracy uses an independent FP64 Torch oracle over the exact patterned packed 4-bit checkpoint.

- Faster in **61/72** cases; median **1.095x**; range **0.90x–1.80x**.
- All 36 eight-stage cases are faster: FP16 median **1.110x**, BF16 median **1.450x**.
- One-stage FP16 selects the merged-main kernel, so its measured ratios around 1.0 are timing noise.
- Maximum PR vs main absolute difference: **2.441406e-04**.
- Maximum PR vs FP64 oracle: **1.873140e-03**.
