## 正文

## Summary

Fix a BF16 accuracy regression in the merged native MLX GPTQ quantizer. At Qwen3.8-27B scale, MLX's built-in affine parameter selection rounded exact `-8.5` zero-point ties away from zero while the independent Torch oracle rounded to even. For the full K projection, 61 of 81,920 group scales and 488 of 655,360 packed words differed. The new MLX parameter calculation uses ties-to-even selection before the existing fused group-update kernel.

## What Changed

- Replace only the group affine parameter selection with an MLX-native calculation matching the Torch oracle's min/max, scale, signed edge, zero-point rounding, scale adjustment, and bias.
- Add a direct BF16 zero-point tie test at the threshold and its neighboring representable inputs, for both signs.
- Pin the [Qwen/Qwen3.8-27B config](https://huggingface.co/Qwen/Qwen3.8-27B/blob/1d4bf0f2ff6012fd82039f2fa52739d0dd7c60c0/config.json) and compare complete packed 4-bit words plus all affine scales/biases across all nine projection roles.
- Compare Hessian accumulation at each distinct projection input width (5120, 6144, 17408) with a float64 Torch oracle.

The original main-branch implementation failed the K projection with 61/81,920 scale mismatches and 488/655,360 packed-word mismatches. The corrected implementation matched the Torch oracle exactly for all packed words, with scales and biases within `rtol=atol=1e-6`. Hessian normalized error met `1e-6`.

## Performance vs main

M5 Ultra; synthetic BF16 weights resident in MLX; 4 bits, group size 64; diagonal inverse Hessian resident in MLX; complete quantizer call with outputs evaluated. Main and fixed implementations were loaded from separate worktrees in one process. The 17408-wide Hessian accumulation test uses 16 calibration vectors.
