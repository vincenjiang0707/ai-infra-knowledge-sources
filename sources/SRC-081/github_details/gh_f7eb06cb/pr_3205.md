## 正文

## Summary

Pack ParoQuant's already-rounded floating code tensor directly in the Metal kernel. The kernel converts each integral code to `uint` at the point of bit insertion, eliminating the full-matrix `codes.astype(mx.uint32)` allocation and pass.

This PR is limited to the ParoQuant export packer. Quantization arithmetic, AWQ word ordering, qzeros, stored scales, and public APIs are unchanged.

## What Changed

- accept FP16, BF16, or FP32 integral codes directly in the packing kernel
- convert each code to `uint` immediately before its four-bit shift
- add a fast direct-kernel regression for all three floating dtypes
- add a synchronized current-main A/B benchmark over all nine Qwen3.8-27B projections

## Accuracy

The independent Torch and existing AWQ export-layout suite passes all 34 tests. Coverage includes:

- every supported input dtype and group size
- complete Qwen3.8-27B BF16 projection packs
- exact code-boundary neighbors and saturation values
- signed zero
- FP32-to-FP16 stored-scale boundaries
- invalid codes, shapes, and scales
- direct FP16/BF16/FP32 integral-code kernel inputs

Across the 18 Qwen performance cases, comparison with current `main` found:

- packed-byte mismatches: **0**
- qzero mismatches: **0**
- stored-scale mismatches: **0**
- maximum stored-scale drift: **0**
