## 正文

## Summary

- replaces EXL3's decoded FP16 MLX fallback with native packed-trellis inference
- adds a dedicated single-token Metal kernel and a 16-row SIMD-group matrix kernel
- transfers trellis/sign/bias tensors directly, including legacy `su`/`sv` sign bitfields
- supports every EXL3 bit width (1–8) and all three codebooks (`3inst`, `mcg`, `mul1`)
- preserves FP16/BF16 activation output dtype

The kernels extract each 16-bit cyclic trellis state directly from its packed bit window, decode the EXL3 codebook in Metal, and apply the existing native normalized Hadamard transforms. No dense weight is materialized.

## Qwen3.8-27B performance vs main

Apple M5 Ultra, MLX 0.32.2, 4-bit MCG, 31 paired alternating samples per case. Main is commit `6a4379e40` and uses the existing decoded FP16 `nn.Linear` fallback. Speedup is main latency / PR latency, so values above 1 are faster.

The principal end-to-end gain is capacity: 4-bit EXL3 now uses 4x less runtime weight memory than main and avoids model-wide FP16 expansion. The packed path is faster for the important wide BF16 Q/KV/MLP input projections, but narrow outputs and FP16 remain slower than dense MLX. The committed benchmark emits every raw projection/dtype/row result.

## Accuracy

All outputs retain their input activation dtype.

| Coverage | FP16 max abs error | BF16 max abs error |
| --- | ---: | ---: |
| 1–8 bits × 3 codebooks vs dtype-rounded Torch dense decode | 0.0078125 | 0.0625 |
| All 9 Qwen3.8-27B shapes, rows 1/16 vs dtype-rounded Torch oracle | 0.00006103515625 | 0.0000152587890625 |

The all-format maxima are dtype-ULP-scale on random high-magnitude outputs. The Qwen-shape suite validates the packed token and SIMD prefill kernels independently with repeated 128-channel tiles.
