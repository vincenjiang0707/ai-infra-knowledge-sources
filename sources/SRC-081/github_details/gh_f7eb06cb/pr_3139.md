## 正文

## Summary

Add opt-in native MLX weight quantization for bitsandbytes NF4, FP4, and LLM.int8 formats on Apple Silicon. The 4-bit path supports plain and nested statistics. This PR covers one quantization method; processor wiring and inference kernels are separate work.

## What Changed

- Add Metal packers for bitsandbytes 4-bit storage and int8 row codes, plus MLX block maxima and nested-scale reduction.
- Preserve the bitsandbytes 4-bit codebooks and nested 8-bit lookup table without a Torch dependency in the MLX path. The file header credits the MIT-licensed bitsandbytes format tables.
- Add independent bitsandbytes CPU-oracle tests for float16, bfloat16, float32, zeros, signed zeros, subnormals, odd lengths, threshold neighbors, and every Qwen3.8-27B projection.
- Add a reproducible per-projection benchmark. Both APIs are opt-in; checkpoint processor integration remains separate.

## Accuracy against bitsandbytes CPU oracle

M5 Ultra; MLX 0.32.2; Torch 2.14.0; bitsandbytes 0.50.2. Complete Qwen3.8-27B BF16 weight projections, with the model's BF16-to-FP16 cast for int8. The table uses MLX-generated weights; `4-bit nested` is the number of scale **code** differences for each of NF4 and FP4. `Scale drift` is the maximum absolute difference across nested block maxima and offset. All 4-bit packed weight bytes match exactly. All int8 differences are one code at an independently verified exact half step; non-tie differences are zero and int8 row-stat drift is zero.

Nested totals: 21 code differences for NF4 and 21 for FP4 across the nine projections, seven on each MLP projection. The regression test reconstructs block maxima and the mean in float64 from the source weights; each differing lookup decision is within one float32 ULP of a lookup boundary. The largest measured float drift is 2.38418579e-7, below the 1e-6 quantization limit. Int8 totals 51,729 exact-half-step one-code differences and zero differences away from those ties. No packed NF4/FP4 weight-byte differences occur.

## Performance versus `main`

Inputs are already resident in both backends. Each call finishes evaluation before timing ends; one warmup and median of seven calls, excluding input transfer and first compilation. The baseline is `main`'s bitsandbytes CPU quantizer with `compress_statistics=True`, 64-element 4-bit blocks, and `threshold=0` for int8. Times are MLX / CPU milliseconds (speedup).
