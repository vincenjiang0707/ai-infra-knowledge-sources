## 正文

## Summary

Use 512 threads for QQQ dynamic activation quantization at the Qwen3.8-27B `mlp.down_proj` input width of 17408. All other widths retain the existing 256-thread kernel source and kernel name.

Across both QQQ packing modes, FP16/BF16, and decode/prefill, the changed path is 1.016–1.066× faster than current main. Quantized codes, input scales, and visible outputs are exact versus main.

## What Changed

- Specialize the QQQ dynamic-quant reduction for 256 or 512 threads.
- Dispatch 512 threads only when the input width is 17408.
- Preserve the exact 256-thread source constants and kernel name for every unchanged width.
- Add Qwen down-projection regression tests against the previous 256-thread path and an independent Torch FP64 oracle.
- Add a failing all-nine-shape benchmark covering both QQQ packing modes and activation dtypes.
- No API, checkpoint, or serialization changes.
- Other QQQ tuning is intentionally out of scope.
