## Scope

GGUF only. Preserve activation dtype at the MLX linear boundary for GGUF affine formats that use MLX `nn.QuantizedLinear`. Its affine matmul may return FP32 because of scale and bias dtypes; `MlxGGUFLinear` keeps that internal math and casts once to the input dtype. Q6_K continues through the existing group-16 kernel. FP16 and BF16 are both covered, including wrapper behavior around MLX native float4 matmul modes.

This PR is stacked on #3150 so the diff against its base contains only the GGUF change.

## Accuracy vs independent Torch oracle

Apple M5 Ultra, MLX 0.32.2. Nine Qwen3.8-27B projection shapes, three activation rows, and both FP16 and BF16 (18 cases). Each accuracy case starts from actual packed GGUF Q4_0 blocks, runs the production GGUF-to-MLX repacker, then compares against an independent Torch float64 decode and matmul. The output dtype is asserted; internal FP32 output is checked against the unrounded oracle, and visible output against the oracle rounded to the same dtype. All cases pass at `rtol=atol=2e-3`.

## Inference latency

Paired alternating measurements compare plain MLX `nn.QuantizedLinear` with `MlxGGUFLinear`, using the same resident weights and inputs. Nine projections × 1/16 rows × FP16/BF16 = 36 cases; five warmups and 21 synchronized `mx.eval` samples per path; medians in milliseconds. 12/36 cases were faster; ratios range 0.895×–1.096×.
