## Summary

WIP implementation of GPTQ W4AFP8 for NVIDIA GB10 (SM121), with per-token E4M3 activation scaling and native INT32-packed GPTQ INT4 checkpoint weights.

- Stage centered INT4 weight codes losslessly into a nonpersistent E4M3 cache during post-init; reuse it during inference.
- Use native FP8 GEMM operands with FP32 accumulation, applying each original GPTQ group scale before summing groups.
- Add versioned activation configuration, backend selection, calibration replay, packing, save/load, and post-init lifecycle support.
- Carry encoded activations and token scales between selected Llama decoder layers, share inputs across Q/K/V and gate/up, and reject plain tensors at selected Linear inputs.
- Add GB10 fused kernels, full-model coverage audits, paired full-row quality tooling, and a memory guard with a 2 GiB reserve and swap disabled.

This PR contains only W4AFP8. W4A4/NVFP4 experiments are excluded.

## Activation contract and current scope

Version 3 carries FP8 codes plus FP32 token scales across decoder layers and into all selected GEMMs. RMSNorm and residual arithmetic decode internally to FP32 and encode their outputs. Linear outputs feeding attention, nonlinear functions, or residual arithmetic use model dtype. RoPE, attention, KV cache, and the output head retain wider precision. This is not a claim of FP8 arithmetic throughout every decoder operation.

Initial support: Llama, Linux, GB10/SM121, symmetric INT4 with group size 128, contiguous groups, `desc_act=False`, INT32 packing, and an unquantized output head. Runtime memory includes the derived FP8 weight cache. No end-to-end speedup claim is made.

## Validation

Tested the extracted FP8 branch after rebasing onto upstream `6d3232c`:

| Check | Result |
| --- | --- |
| FP8 kernel/config tests | 14 passed |
| Encoded activation stream tests | 6 passed |
| Calibration replay tests | 12 passed |
| Tiny Llama quantize/save/reload, with and without rotation | 2 passed |
| Saved Llama 3.2 1B reload | 1 passed |
| Stage and rotation tests | 40 passed, 1 optional checkpoint test skipped |
| Full-model activation audit | All 16 layers and 112 projections passed, including shared carrier pointers and cached generation |

Total: **75 passed, 1 skipped**. Compile checks, shell syntax checks, and `git diff --check` passed. Guarded runs stayed above the 2 GiB reserve with zero swap.

Independent Torch oracles cover FP16/BF16 GEMM inputs, group-specific and per-column scales, zero inputs, outliers, and partial tiles. GEMM cases include K=256, N=64/96/128 and M=1/3/7/16/33; encoding cases include widths 128/256 and up to 129 rows. FP8 threshold and neighboring-value checks cover FP16, BF16, and FP32, including signed zero. Complete encoded bytes match exactly in those tests; floating checks use quantization tolerances of 1e-6 and inference tolerances of at most 2e-3. Per-test maximum floating errors were not separately recorded. The optional microbenchmark uses CUDA graph replay; it is not an end-to-end performance result.

### Existing full-row GSM8K Platinum evidence

The fresh version-3 checkpoint used 512 calibration records, 188,256 nonpadding tokens, and concatenation size 2,048. Both evaluation lanes use the same packed weights.

| Metric | Result |
| --- | --- |
| W4A16 baseline | 432 / 1,209 = 35.7320% |
| W4AFP8 | 441 / 1,209 = 36.4764% |
| Paired difference | +0.7444 percentage points |
| Paired 95% confidence interval | [-1.5431, +3.0319] percentage points |
| Baseline-only / FP8-only correct | 95 / 104 |
| Provisional 2-point regression budget | Within budget |

These full-row results predate the FP8-only extraction and were **not rerun for this PR**. The focused tests and full-model activation audit above were rerun on the extracted branch. The score difference does not establish a statistically significant improvement. GSM8K Platinum is the acceptance benchmark; ARC is diagnostic.
