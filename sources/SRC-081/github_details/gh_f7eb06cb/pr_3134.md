## 正文

## Changes

- Add BaseQuantLinear validated MLX checkpoint holders for ParoQuant, QQQ, GGUF, FP8, bitsandbytes, AWQ GEMV, AWQ GEMV_FAST, and LLM_AWQ.
- Transfer packed ParoQuant/AWQ/GGUF codes and run ParoQuant rotations and QQQ dynamic input quantization with native MLX operations. Fix the GEMV_FAST group-16 buffer width.
- Decode FP8, bitsandbytes, and EXL3 once into MLX FP16 dense layers when explicitly selected. AUTO selects the supported compressed paths on Apple Silicon; it retains the existing bitsandbytes and EXL3 paths after their faster 1024×1024 decode measurements on this host. Dense FP16 conversion increases weight memory versus FP8/4-bit storage.
- Add source credit and SPDX notes to the new files.
- Review follow-up: dense FP8/bitsandbytes holders call BaseQuantLinear validation directly, preserving support for non-affine shapes; a 96-feature regression covers both.

## Accuracy and regression coverage

- Use every projection from the pinned [Qwen3.8-27B config](https://huggingface.co/Qwen/Qwen3.8-27B/blob/1d4bf0f2ff6012fd82039f2fa52739d0dd7c60c0/config.json): full-attention Q/K/V/O, fused linear-attention QKV/O, and MLP gate/up/down.
- Check the previously merged GPTQ and AWQ GEMM MLX kernels on all nine shapes; all GPTQ bit widths (2–8) on the K projection; and the new AWQ GEMV, shared GEMV_FAST/LLM_AWQ, QQQ, and GGUF Q4_0 inference paths on all nine shapes. Include a full-width GEMV group case. Small-shape tests cover the other supported groups and GGUF qtypes with independent Torch arithmetic and packed-code checks. The latest main also contributes full-shape random BF16 audits for merged GPTQ/AWQ and GGUF packers.
- Nonidentity ParoQuant Qwen outputs agree with main's Torch fallback across 27 measurements; maximum absolute error **0.000871**. The Qwen test matrix uses rtol/atol **0.002**.
- **621 MLX tests passed** on the rebased branch. Ruff and `git diff --check` pass. The separate `tests/test_mlx.py` integration test requires a model under `/monster/data/model/...` and could not run here.

## Performance versus main

Apple M5 Ultra, MLX 0.32.2, Torch 2.14.0, FP16 inputs, group size 128. Each value is the median of 11 timed forwards after one warmup with inputs resident on device; Torch MPS and MLX are synchronized. The baseline classes are the unchanged Torch fallbacks from main. Weights and inputs are deterministic synthetic data. These are isolated projection latencies, excluding checkpoint conversion and end-to-end generation.

| Method | 1 row speedup (min / median / max) | 16 rows | 128 rows | Max absolute error |
|---|---:|---:|---:|---:|
| ParoQuant, identity stage | 3.06 / 15.64 / 20.91× | 3.97 / 8.67 / 14.61× | 3.23 / 7.41 / 10.71× | 0.000778 |
| ParoQuant, eight nonidentity stages | 93.22 / 104.14 / 266.40× | 61.62 / 73.62 / 112.22× | 32.58 / 50.57 / 68.19× | 0.000871 |
| QQQ | 10.42 / 60.63 / 104.80× | 10.63 / 47.00 / 73.19× | 8.73 / 30.41 / 40.34× | 0 |
| GGUF Q4_0 | 2.92 / 14.07 / 24.54× | 3.33 / 11.06 / 19.10× | 2.65 / 8.04 / 11.52× | 0.00003 |

ParoQuant's nonidentity case uses eight valid pairwise rotation stages with angle 0.01 and channel scale 1.01. The QQQ benchmark uses uniform packed codes, while the independent Qwen QQQ tests use a varied pattern. GGUF uses Q4_0 blocks; other supported qtypes have separate small-shape numerical tests.
