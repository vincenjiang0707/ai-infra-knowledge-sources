## Summary

- add an MLX-native EXL3 codebook reconstruction kernel for the `3inst`, `mcg`, and `mul1` codebooks
- preserve signed `int16` state bit patterns and reproduce EXL3 half-precision arithmetic before returning FP32 values
- add an independent Torch oracle, exhaustive state-space coverage, Qwen3.8-27B projection-shape regression tests, and a reproducible benchmark

This PR is intentionally limited to EXL3 codebook reconstruction. It does not add or modify the Viterbi/path-search stage.

## Accuracy

The independent Torch oracle does not import or call the MLX implementation.

- all 65,536 encoded states checked for each of the three codebooks
- signed-state boundaries checked explicitly
- all nine Qwen3.8-27B projection outputs checked element-by-element
- exact agreement: zero mismatched values and zero absolute drift

## Performance

Apple M5 Ultra 256 GB, MLX 0.32.2, Torch 2.14.0. Median of 3 timed runs after warmup; inputs are already resident in each framework.

| Projection | Shape | Torch oracle (ms) | MLX (ms) | Speedup |
|---|---:|---:|---:|---:|
| full_attn.q_proj | 12288×5120 | 11.947 | 0.855 | 13.97× |
| full_attn.k_proj | 1024×5120 | 1.068 | 0.224 | 4.76× |
| full_attn.v_proj | 1024×5120 | 1.049 | 0.245 | 4.28× |
| full_attn.o_proj | 5120×6144 | 6.097 | 0.528 | 11.54× |
| linear_attn.in_proj_qkv | 10240×5120 | 9.948 | 0.783 | 12.71× |
| linear_attn.out_proj | 5120×6144 | 6.020 | 0.513 | 11.74× |
| mlp.gate_proj | 17408×5120 | 16.607 | 1.185 | 14.02× |
| mlp.up_proj | 17408×5120 | 17.159 | 1.214 | 14.13× |
| mlp.down_proj | 5120×17408 | 17.223 | 1.244 | 13.85× |

Observed speedup: **4.28×–14.13×**.

The existing production EXL3 reconstruction path is inside the CUDA quantizer and cannot run on Apple Silicon. These timings therefore compare the resident MLX kernel with the exact resident Torch format oracle; they are not CUDA or cross-device timing claims.

Reproduce with:

```bash
python tests/benchmark_mlx_qwen38_exl3_codebook.py
```
