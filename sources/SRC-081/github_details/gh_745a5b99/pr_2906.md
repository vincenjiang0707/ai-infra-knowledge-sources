## Summary

The PR adds [MoNE](https://arxiv.org/pdf/2507.00390) (Mixture of Experts and Novices) pruning support for MoE models. MoNe has an original codebase https://github.com/zxgx/mode-pd from paper authors, we rely on it in our integration and provide a benchmark comparison. 

The MoNe method is close to [REAP](https://arxiv.org/html/2510.13999v1) but instead of removing redundant experts it replaces them with constant vectors that are their unbiased estimators. In our extensive experiments MoNE outperforms REAP on a wide range of benchmarks.

The implementation is tested on `allenai/OLMoE-1B-7B-0924` following the paper experiments and achieves comparable average score across 9 benchmarks from the paper. We also add support for a larger model, particularly minimax-m2.5.

Details:

- Adds a `MoNEPruningModifier` that collects calibration statistics, ranks experts, preserves the top experts, and replaces pruned experts with approximate constant experts.
- Adds generic MoNE model support/registry utilities plus MiniMax-M2 support including native FP8 expert handling.
- Wires MoNE into the pruning modifier registry, pipeline registry, and model loading path for saved MoNE checkpoints.
- Adds checkpoint export validation and fixes cross-device embedding re-tying during save.
- Adds unit coverage for MoNE modifier behavior, MiniMax MoNE layout/export logic, linearized loading, pipeline registry integration, and save utilities.

## Example command

Run 25% pruning of OlMoE model using zyda2 dataset and 100 calibration steps.

```
from llmcompressor import oneshot
from llmcompressor.modifiers.pruning.mone import MoNEPruningModifier

recipe = MoNEPruningModifier(
    preserve_n_experts=48,      # OLMoE has 64 experts/layer; prune 25%
    ranking_metric="fusion",
    ranking_scope="layer",
    fusion_io_weight=0.5,
    stats_device="cpu",
)

oneshot(
    model="allenai/OLMoE-1B-7B-0125",
    recipe=recipe,
    dataset="Zyphra/Zyda-2",
    dataset_config_name="sample-100BT",
    splits="train[:512]",
    text_column="text",
    concatenate_data=True,
    max_seq_length=4096,
    num_calibration_samples=100,
    shuffle_calibration_samples=False,
    batch_size=1,
    moe_calibrate_all_experts=False,
    pipeline="basic",
    precision="bfloat16",
    save_compressed=False,
    output_dir="./OLMoE-1B-7B-0125-mone-pruned-48",
)
```

### ieBoytsov · 2026-07-13

> is MoNe supported in vllm? how are you running these models?

FYI @HDCharles  @Ryfernandes  it is not supported in vllm. We implement it by ourselves in vllm (will be happy to upstream and provide recipes too). 

The key detail is that MoNe modifies model architecture by replacing pruned expert's MLP layers with constant vectors, so in order to support it in vllm one needs to write custom kernels (v0 for minimax m2.5 was quite easy though).

The original paper code shows a way to run it via transformers which we also did and compared with our vllm implementation.
