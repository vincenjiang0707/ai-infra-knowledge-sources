# [PR #3222] [REAP] Refactor pruning report to per-expert saliency scores

## 正文

## Summary

Refactors the report produced by `REAPPruningModifier` and adds a report-only mode.

- **Report data is now `list[list[float]]` serialized with `pickle`.** One inner list of per-expert saliency scores per MoE layer, ordered by layer. Replaces the previous JSON map of retained expert indices per layer.
- **The report no longer stores which experts were retained.** Instead it stores the `saliency` score of each expert (`tracker.mean_saliency`), recorded on the source rank after the distributed reduction.
- **New top-level attribute `prune: bool = Field(default=True)`.** When `prune=False`, the model weights and config are never modified — pruning is skipped in both `on_sequential_epoch_end` and `on_finalize` — while saliency is still computed via the calibration hooks so a report can be written.
- **Validation:** at least one of `report_path` or `prune` must be set (otherwise REAP would do nothing). `report_path` must now end with `.pkl` (was `.json`).

## Testing

- `test_base.py`: extended `test_reap_validation` (`.pkl` extension + `report_path`/`prune` mutual requirement) and added `test_reap_report_only_does_not_modify_model`, verifying the model is untouched under `prune=False` and the pickled report has the expected `list[list[float]]` shape.
- `test_ddp.py`: loads the report via `pickle`, uses `.pkl` paths, and compares per-layer saliency with `torch.testing.assert_close`.
- `make style` / `make quality` pass; REAP unit tests pass.
