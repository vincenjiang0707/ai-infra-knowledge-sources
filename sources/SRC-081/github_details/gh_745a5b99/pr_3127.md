# [PR #3127] [Datatsets] Respect num_calibration_samples when loading calibration data

source: https://github.com/vllm-project/llm-compressor/pull/3127
state: open | updated: 2026-09-23T21:48:04Z
labels: ready

## 正文

Previously num_calibration_samples was only applied in the DataLoader sampler, after the entire split had been loaded and tokenized. And with no split specified, all splits were loaded as a DatasetDict and a downstream fallback only knew how to pick a "train" split (breaking ultrachat_200k, which has train_sft/test_sft).

- Add TextGenerationDataset.DEFAULT_SPLIT so each dataset resolves its own default split (ultrachat_200k -> train_sft, flickr30k/peoples_speech -> test, custom -> None); base defaults to "train".
- Collapse a multi-split DatasetDict to a single split before processing.
- Trim to num_calibration_samples before the preprocess/tokenize maps so we don't tokenize samples the sampler would only discard.
- Simplify get_processed_dataset's split handling accordingly.

## Calibration data resolution

| Config | Calibration samples come from |
|---|---|
| `splits` + `num_calibration_samples` | `num` samples **from your split** (shuffled → seed-42 subset; unshuffled → the `num` longest in the split) |
| `splits` only | Same, with the implicit default 512 (split < 512 → whole split + warning) |
| `num_calibration_samples` only | 512 from the class `DEFAULT_SPLIT` (`train`, `train_sft`, `test`, …) |
| neither | `DEFAULT_SPLIT`, trimmed to the default 512 |
| `num_calibration_samples=None` | The whole split (no trimming) |
| `concatenate_data=True` | `num` *packed chunks* selected by the sampler (packing may yield fewer) |

The trim is only applied where it doesn't change the sampled set: it is skipped when `concatenate_data=True` (the sampler must count packed chunks, not rows) and when `shuffle_calibration_samples=False` (`LengthAwareSampler` must see the whole split to pick the longest sequences). The multi-split `DatasetDict` fallback picks the lexicographically first split so the choice is deterministic.
