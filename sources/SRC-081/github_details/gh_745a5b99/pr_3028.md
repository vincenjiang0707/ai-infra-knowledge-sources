## Overview

HIGGS is a technique from [this](https://arxiv.org/pdf/2411.17525) paper which can be used to determine the theory-based optimal mixed-precision quantization configuration to use to quantize a model given a constraint on the average quantization bitwidth the user wants. Note in the paper there are 2 methods for calculating how sensitive each layer is to quantization, this PR only implements the heuristic method.

HIGGS has 2 phases, it first collects a bunch of MSE data and layer location information to estimate layer sensitivity to quantization, it then converts this information to an ILP and then uses PuLP to solve the ILP and generate an optimal quantization config. This config can then be passed into oneshot or model_free_ptq to actually quantize the model.

All the above functionality lives in the HiggsMSECollectorConverter which is supported by the get_higgs_config entrypoint since our converter architecture makes a number of assumptions about the converter actually applying quantization to the model. In the future we could get rid of get_higgs_config. 

## Results

| Target Bits | NVFP4A16 Layers | FP8_DYNAMIC Layers | word_perplexity |
|-------------|-----------------|---------------------|-----------------|
| 4.0 | 224 | 0 | 9.9381 |
| 4.5 | 124 | 100 | 9.8493 |
| 5.0 | 92 | 132 | 9.7695 |
| 5.5 | 75 | 149 | 9.7209 |
| 6.0 | 61 | 163 | 9.6805 |
| 6.5 | 46 | 178 | 9.6384 |
| 7.0 | 30 | 194 | 9.5992 |
| 7.5 | 15 | 209 | 9.5674 |
| 8.0 | 0 | 224 | 9.4934 |
| 16.0 (base) | 0 | 0 | 9.4236 |

As you can see, a straightforward bitwidth sweep from 4-8 yields consistently monotonic  PPL improvement as the target bitwidth grows. While such a growth is not strictly guaranteed given that after all HIGGS doesn't take into account activation quantization accuracy and only has a local estimate of weight quantization accuracy, it performs extremely well (especially for such a fast technique). These results were generated using the higgs_nvfp4a16_fp8_model_free.py example. Note we use the nvfp4_expanded_mse observer to get a better than RTN quantized model both for error estimates for HIGGS and the final quantization.

As mentioned above though HIGGS can compose with oneshot for quantization schemes that require calibration:

| Example | Schemes | Method | HIGGS Time | Quant Time | PPL |
|---------|---------|--------|------------|------------|-----|
| `higgs_nvfp4_fp8_qmod` | NVFP4 + FP8_DYNAMIC | QuantizationModifier | 8.05s | 1:21 | 9.7502 |
| `higgs_nvfp4_fp8_gptq` | NVFP4 + FP8_DYNAMIC | GPTQModifier | 7.64s | 3:24 | 9.7486 |

As you can see we're able to apply GPTQ or just use a normal QuantizationModifier after HIGGS, you can do things like AWQ as well though that may invalidate the HIGGS scheme's theoretical optimality.

Also note the speed of this HIGGS implementation, since we use a model_free method to collect MSE values without writing anything, we are able to do this incredibly quickly, for all the models i've tested HIGGS takes up a minority of the time compared to the actual application of quantization. This massively outperforms other designs in terms of speed even if you were to pre-quantize the model to each candidate scheme. The process of reading N different model weights into memory in order to calculate MSE is much slower than just calculating it all from scratch, even though some work is duplicated due to weights needing to be quantized both to calculate MSE and to save the final quantized model.

these results were generated using the /home/HDCharles/repos/llm-compressor/examples/quantization_higgs/higgs_nvfp4_fp8_gptq.py example.
