## 正文

SUMMARY:
Adds dense Qwen3-VL to the tracing model enumeration in
`tests/llmcompressor/transformers/tracing/test_models.py`, the configuration
reported broken in #3071 (AWQ/GPTQ W4A16 calibration with `visual.*` in the
quantization ignore list and `sequential_targets=["Qwen3VLTextDecoderLayer"]`).

Investigation of #3071 found the report does not reproduce on main or on the
reporter's versions (llmcompressor 0.11.0 + transformers 4.57.6): the
autowrapper wraps the `if pixel_values is not None:` branch of
`Qwen3VLModel.forward` (it cannot statically evaluate the condition), so
`get_image_features` and the vision tower run eagerly inside a
`torch.fx.wrap`ped function and never enter the fx graph. The new row pins
that behavior so future autowrapper or transformers changes cannot silently
regress it: dense Qwen3-VL traces to `num_hidden_layers + 1` subgraphs with
the vision tower opaque.

The row mirrors the Qwen2-VL and Qwen2.5-VL entries:
`Qwen3VLForConditionalGeneration`, `["Qwen3VLTextDecoderLayer"]`, vision
modality, torchvision backend, default `tracing_ignore`. Per review, this
replaces the standalone tiny-config CPU test from the first revision.

Related to #3071 (not reproducible on main; test guards the working behavior)

TEST PLAN:
* `pytest --collect-only tests/llmcompressor/transformers/tracing/test_models.py`:
  19 tests collected (18 existing + the new row); the row is
  `@requires_hf_token`, so it runs in the token-enabled suite
* `ruff check`, `ruff format --check`, `tools/lint_cuda.py` clean on the file
* VALIDATION (GPU pod, first revision): real `Qwen/Qwen3-VL-2B-Instruct`
  AWQ W4A16 end-to-end oneshot on an L40S (46GB) against main @ 50d0a1c75,
  llmcompressor 0.13.1.dev51+g50d0a1c75, transformers 5.16.1,
  compressed-tensors 0.18.1.a20260826, torch 2.11.0+cu128,
  `CUDA_LAUNCH_BLOCKING=1`, 256 flickr30k calibration samples: traces to
  29 subgraphs with the vision tower opaque, which is exactly the
  `len(target_modules) + 1` the row asserts; oneshot completes,
  save_compressed + reload clean (905M params), 6m35s wall, 5.4 GiB peak
  allocated VRAM.
* The first revision's tiny-config CPU test (2 passed in 0.23s on the same
  pod; full `tests/llmcompressor/pipelines/sequential/` 45 passed) covered
  the same trace on random weights; dropped here in favor of the enumeration.
