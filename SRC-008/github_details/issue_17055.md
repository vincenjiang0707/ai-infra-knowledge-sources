## 正文

### Purpose

This issue records the package set and install order used for our Atlas A3 MegaMoe validation on CANN 9.2.0. It is an environment-reproduction note, not a bug report. The related ABI investigation is in #17030.

### Artifact availability

The CANN 9.2.0 and MegaMoe custom artifacts used in this validation are not distributed through this public issue. For reproducibility, request the exact artifacts from Huawei/Ascend and compare their SHA256 values with the table below.

### Validated baseline

- Platform: Atlas A3 / Ascend910_93
- OS/architecture: Linux aarch64
- Python: 3.12.13
- PyTorch: 2.10.0+cpu
- torch_npu: 2.10.0.post4
- vLLM: `v0.27.1`, commit `6e448d0ea9bf3d88d898b65449ca6dc2aec170ac`
- vLLM-Ascend: 0.27.1, commit `5a9de65760563f7d17c19627b647a5106235e057`
- CANN version directory: `/usr/local/Ascend/cann-9.2.0`

The original local wheel filename ended in `_1.whl`. If copying the artifact, remove the `_1` suffix before `pip install`; otherwise pip interprets the platform tag as `any_1` and reports that the wheel is unsupported.

### 1. Install CANN 9.2.0

Use the recommended clean order below. If a previous CANN installation exists, clean it first and avoid mixing versions.

```bash
PKG_DIR=${PKG_DIR:-/path/to/cann-9.2.0-packages}

"$PKG_DIR/Ascend-cann-toolkit_9.2.0_linux-aarch64.run" --install
"$PKG_DIR/Ascend-cann-nnal_9.2.0_linux-aarch64.run" --install
"$PKG_DIR/Ascend-cann-A3-ops_9.2.0_linux-aarch64.run" --install

source /usr/local/Ascend/cann/set_env.sh
```

After installation:

```bash
readlink -f /usr/local/Ascend/cann
# expected: /usr/local/Ascend/cann-9.2.0

python3 -c "import cann_ops_transformer; print(cann_ops_transformer.__file__)"
# expected under /usr/local/Ascend/cann-9.2.0/python/site-packages
```

### 2. Install the MegaMoe custom vendor package

```bash
PKG_DIR=${PKG_DIR:-/path/to/cann-9.2.0-packages}
source /usr/local/Ascend/cann/set_env.sh

"$PKG_DIR/cann-ops-transformer-custom_linux-aarch64_1.run" --force
```

The validated installation has:

```text
/usr/local/Ascend/cann-9.2.0/opp/vendors/custom_transformer
load_priority=custom_transformer
```

The vendor `version.info` in the supplied artifact reports:

```text
custom_opp_compiler_version=9.1.0
```

This is the version string of the supplied custom vendor artifact; the validation was run with CANN 9.2.0 and the matching custom wheel described below.

### 3. Install and repair the custom MegaMoe wheel

Install the wheel:

```bash
python3 -m pip install cann_ops_transformer_custom-1.0.0-py3-none-any.whl \
  --force-reinstall --no-deps
```

The wheel is not self-contained. Copy the missing Python common package and C++ source from the CANN-installed `cann_ops_transformer` package:

```bash
CANN_HOME=${CANN_HOME:-/usr/local/Ascend/cann}
SITE=/usr/local/python3.12.13/lib/python3.12/site-packages
CUSTOM="$SITE/cann_ops_transformer_custom"
ORIG="$CANN_HOME/python/site-packages/cann_ops_transformer"

# Missing Python module.
rm -rf "$CUSTOM/ops/mc2/common"
cp -a "$ORIG/ops/mc2/common" "$CUSTOM/ops/mc2/common"

# Re-point the copied common module to the custom namespace.
grep -RIl "from cann_ops_transformer\." "$CUSTOM/ops/mc2/common" \
  | xargs -r sed -i 's/from cann_ops_transformer\./from cann_ops_transformer_custom./g'

# Missing C++ source used by CommContextManager.
mkdir -p "$CUSTOM/csrc/mc2"
cp -an "$ORIG/csrc/mc2/comm_context.cpp" "$CUSTOM/csrc/mc2/comm_context.cpp"
cp -an "$ORIG/csrc/mc2/comm_channel_builder_manager.cpp" \
  "$CUSTOM/csrc/mc2/comm_channel_builder_manager.cpp" 2>/dev/null || true

# Prevent common from being treated as an op by auto-discovery.
sed -i 's/_skip = frozenset(("graph_convert",))/_skip = frozenset(("graph_convert", "common"))/' \
  "$CUSTOM/ops/__init__.py"

# Point the custom builder to the custom utils module.
sed -i 's/from cann_ops_transformer.utils.arg_check import wrap_op_module/from cann_ops_transformer_custom.utils.arg_check import wrap_op_module/' \
  "$CUSTOM/op_builder/builder.py"
```

More background on the wheel packaging gap is in #17030.

### 4. vLLM / vLLM-Ascend notes

For the validated setup:

```text
vLLM          = v0.27.1
vLLM-Ascend   = 5a9de65760563f7d17c19627b647a5106235e057
```

No vLLM rebuild is needed. No vLLM-Ascend rebuild is needed for the current validation changes because they are Python-only.

The temporary vLLM-Ascend validation changes are:

1. Prefer the CANN-installed `custom_transformer` vendor over the repo-embedded vendor.
2. Load MegaMoe directly from `cann_ops_transformer_custom.ops.mc2.mega_moe`.

### 5. Minimal smoke result
