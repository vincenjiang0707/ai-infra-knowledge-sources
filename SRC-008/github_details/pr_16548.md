## **1. 背景**

Fixes #16552

Large-EP PD (Flash / Pro / GLM and similar). Construct used to scan
~820k quant keys per RMSNorm; warmup JIT'd 16 RMS `BLOCK_M` values;
first NZ format-cast and Triton compile sat after I/O.

## **2. 设计**

Same Flash-best optimizations as the 0.26 PR, ported to the main package
layout. `is_layer_skipped_ascend` is already O(1) on main (#16051), so that
index is not in this PR. Main already maps a missing
`quant_description[prefix + ".weight"]` to unquantized, so the Pro MTP
`mtp.0.head.weight` KeyError on 0.26 does not apply here.

Dropped the old CPU-then-NPU expert path (it hit `Expected NPU tensor` on
Prefill dummy_run). Kept main's current hash-router `tid2eid` table.

Two opt-in prewarm threads, switched in `additional_config.ascend_warmup_config`
and both default to false (review feedback from @yiz-liu and @kunpengW-code):
- `enable_early_nz_warmup`: pays the first NZ format-cast lazy init during I/O.
  It is independent of the quantization scheme, so it is a standalone utility
  in `vllm_ascend/utils.py`, not in a quant method
- `enable_early_kernel_warmup`: compiles the Triton warmup kernels during I/O

```json
"additional_config": {
    "ascend_warmup_config": {
        "enable_early_kernel_warmup": true,
        "enable_early_nz_warmup": true
    }
}
```

`NPUWorker.load_model` joins both threads before it returns, so neither
overlaps memory profiling or KV cache allocation.

The MTP embed-table skip from the 0.26 PR is not included. DeepSeek V4 always
has `compress_ratios`, so that branch never ran (review feedback from
@Angazenn).

No loader default is changed. The netloader disk fallback used to drop the
whole `model_loader_extra_config`, which silently disabled the user's
multithread load; it now carries the keys `DefaultModelLoader` accepts and
drops only the netloader-only ones. Thread-count defaults stay with vLLM
(review feedback from @nu11ptr7).

## **4. 自验证**

Ran on the 0.27.1rc image
`mindie-motor:3.2.0b3-vllm_ascendnightly-releases-0.27.1rc-a2-openeuler24.03-py3.12-aarch64`,
image Motor 3.2.0b3, no wheel. Overlay is the 0.27 layout of this change set
plus `modelslim_config.py` (that file is not in this PR: main no longer has
`is_layer_skipped_ascend`). Same Motor both sides. Triton cache hot both
sides. HTTP 200. That overlay still read the two prewarm switches from env
vars; the prewarm logic is the same. The join before profiling should not
add wall time on these scenes: the NZ lazy init is 15~19 s and the Triton JIT
hits the hot cache, against 42 s (Flash) / 98 s (Pro) of weight I/O.

A = first `Available plugins` to the last `Model runner load_model total
time`; B = `init engine (profile, create kv cache, warmup model)`. A+B is
taken on the slowest decode pod.

Flash W8A8, A2 4-node, one P and one D instance of two pods each, dp16
(`17-17-06` vs `18-29-36`):

| | baseline | this change set |
| --- | --- | --- |
| slowest decode A+B | 318 s | **206 s** |
| `load_model total` | 151~161 s | **58~68 s** |
| construct | 77 s | **3~4 s** |

Pro W4A8, A2 8-node, one P and one D instance of four pods each
(`18-58-22` vs `19-26-10`):

| | baseline | this change set |
| --- | --- | --- |
| slowest decode A+B | 811 s | **461 s** |
| `load_model total` | 463~529 s | **135~161 s** |
| construct | 308~318 s | **4~5 s** |

Weight I/O is unchanged (Pro 83~98 s both sides). Warmup did not move: both
runs reuse a hot Triton cache, the only B-stage item in this change set is
the Triton kernel warmup and it was already 0.33~0.47 s on the baseline, and
the bulk of B is `torch.compile` plus graph capture (Pro 43 s + 59 s, equal on
both sides), which this PR does not touch. Construct on 0.27.1rc still needs
the `modelslim_config.py` index; that lands in the 0.27 backport, not here.

### yanganYNU · 2026-09-22

Pushed an update addressing the review and CI:

- **@nu11ptr7's point on `num_threads=128`**: dropped. The PR no longer sets
  any loader default. `apply_default_multithread_weight_load` is gone and the
  `platform.py` hook with it, so no behaviour changes for models that do not
  configure it. What remains in `netloader/utils.py` is only the disk-fallback
  bug fix: the fallback used to reset `model_loader_extra_config` to `{}`,
  which silently dropped a user-configured multithread load; it now keeps the
  keys `DefaultModelLoader` accepts and drops only `SOURCE`/`LISTEN_PORT`.
  Thread-count defaults stay with vLLM.
- **`early_kernel_warmup.start_early_kernel_warmup`**: `_STATE["started"]` was
  set before the `get_current_vllm_config() is None` check, so a call made
  before the config context would permanently disable the warmup. Moved the
  flag after the check, with a regression test.
- **`platform.py` removed from the PR.** Its only hunk keyed off
  `MOTOR_VLLM_FORK_PARENT`, which no upstream code sets. The corresponding
  Motor-side change has been withdrawn, so the branch is now pure vllm-ascend.
- **pre-commit**: fixed (`ruff` wanted an import-group blank line in
  `early_kernel_warmup.py`). `ruff check`, `ruff format`, `codespell` and the
  repo's local hooks are clean on the full tree.
- **DCO**: commit is signed off and squashed to one.
- **UT added**: 8 files, covering the early-warmup module, `BLOCK_M`
  flooring, the EPLB map cache, the `norm.bias` cache, the NZ warm thread and
  the loader fallback. `tests/ut/model_executor/warmup/test_rms_triton_warmup.py`
  also had a stale assertion (16 compiles) that this change set makes wrong; it
