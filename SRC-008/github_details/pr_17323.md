# [PR #17323] [v0.26.0rc][BugFix][Proxy] Avoid retrying side-effectful prefill requests

## 正文

### What this PR does / why we need it?

Backport of #17272 for `releases/v0.26.0rc`.

The layerwise proxy currently retries every HTTP and transport failure. A P notification may already have admitted the request before a response error or post-send failure, so replaying it can create duplicate admissions and KV transfer rounds.

Retry only failures that occur before delivery: `ConnectError`, `ConnectTimeout`, and `PoolTimeout`. Propagate HTTP errors and ambiguous post-send transport failures without replaying the request.

### Does this PR introduce any user-facing change?

Yes. Side-effectful prefill notifications are no longer re-POSTed after HTTP, read, or write failures.

### How was this patch tested?

- Added four focused async tests covering connection errors, pool timeout, HTTP errors, and read timeout.
- `ruff check`, `ruff format --check`, `py_compile`, and `git diff --check` pass.
- Full pytest was not run locally because the available macOS environment does not provide `torch`; CI is expected to run the added tests.

```markdown
### What this PR does / why we need it?

This PR refines the retry logic in `send_request_to_service` within the layerwise proxy server example. Previously, all `httpx.RequestError` and `httpx.HTTPStatusError` exceptions were retried. The updated logic ensures that:
- HTTP status errors (`httpx.HTTPStatusError`) are not retried and are raised immediately.
- Transport errors (`httpx.RequestError`) are only retried if they represent pre-send connection issues (specifically `httpx.ConnectError`, `httpx.ConnectTimeout`, or `httpx.PoolTimeout`). Other transport errors (such as `ReadTimeout` after a request has been sent) are raised immediately to prevent duplicate processing.
- Logging is enhanced to include `request_id` and specific error details for better observability.

### Does this PR introduce _any_ user-facing change?

No.

### How was this patch tested?

Added new unit tests in `tests/ut/proxy/test_layerwise_proxy_retry.py` covering:
- Retrying on connection errors and pool timeouts.
- Not retrying on HTTP status errors.
- Not retrying on post-connection transport errors (e.g., read timeouts).
```
