### ChenlingXie · 2026-09-18

We reproduced the exact same issue on another A2 dual-node setup, with two control experiments that may help narrow it down:

**Environment**: 2× Atlas 800 A2 (8×910B4 64GB per node), openEuler 24.03 LTS-SP4, driver 26.1.1, CANN 9.2.0-beta2. **NPU built-in (direct-out) RoCE ports** — not visible in host `ip link`, configured via `hccn.conf`; two nodes directly interconnected via RoCE (all 8 NPU links UP, LLDP peer verified).

**Symptom**: GLM5.3-flash-w8a8 + 0day image, dual-node DP2/TP8/EP16 — hangs at profile_run: repeated `shm_broadcast` 60s warnings → ALLREDUCE/ALLGATHER dispatch timeout → EngineCore crash. Identical to the reporter's.

**Control 1 (rules out image/model specifics)**: same hardware switched to Qwen3.5-122B-A10B + `quay.io/ascend/vllm-ascend:v0.23.0` (this image runs stably in single-node TP8 production) — dual-node, same topology → **same failure at `aclnnMoeDistributeDispatchV4`**.

**Control 2 (rules out physical network / underlying HCCL)**: same machines, `mpirun + hccl_test`, 16-rank all_reduce (8K..64M) all success, 47.9 GB/s @ 64M — underlying HCCL/network is fine.

**Config note**: with direct-out NICs, setting `HCCL_IF_IP` fails to init; only `HCCL_SOCKET_IFNAME` (without `HCCL_IF_IP`) gets past communicator setup.

**Hypothesis**: the vllm-ascend plugin's HCCL usage differs from the native mpirun path in the "multi-node + built-in direct-out NIC" scenario. Community success cases appear to be on servers with PCIE RDMA NICs (visible in the OS). Maintainers may want to compare communicator initialization between the two paths.

我们在另一套 A2 双机环境复现了完全相同的现象，并做了两组对照实验，供定位参考：

**环境**：2× Atlas 800 A2（每台 8×910B4 64G），openEuler 24.03 LTS-SP4，驱动 26.1.1，CANN 9.2.0-beta2。**NPU 直出 RoCE 网口**（宿主 `ip link` 不可见，配置在 `hccn.conf`），两机 RoCE 直连（8 卡 link 全 UP、LLDP 对端正确）。

**现象**：GLM5.3-flash-w8a8 + 0day 镜像，双机 DP2/TP8/EP16，profile_run 阶段卡死（`shm_broadcast` 连续 60s 告警 → ALLREDUCE/ALLGATHER dispatch timeout → EngineCore 崩溃），与楼主现象一致。

**对照 1（排除镜像/模型特有性）**：同硬件换 Qwen3.5-122B-A10B + `quay.io/ascend/vllm-ascend:v0.23.0`（该镜像单机 TP8 生产稳定运行），双机同拓扑，**同款失败**，死在 `aclnnMoeDistributeDispatchV4`。

**对照 2（排除物理网络）**：同机 `mpirun + hccl_test`，16 rank all_reduce（8K~64M）全部 success，64M 达 47.9 GB/s —— 底层 HCCL/网络本身正常。

**配置注记**：直出网口场景下配 `HCCL_IF_IP` 会初始化失败，仅配 `HCCL_SOCKET_IFNAME`（不配 IF_IP）才能进入建域阶段。

**推测**：vllm-ascend 插件在"多机 + NPU 直出网口"场景下对 HCCL 的调用与原生 mpirun 路径存在差异。社区成功案例疑似均为 PCIE RDMA 网卡（系统可见）的服务器，建议维护者对比两条路径的通信域初始化差异。
