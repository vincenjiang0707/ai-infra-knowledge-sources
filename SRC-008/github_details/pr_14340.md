# [PR #14340] [Feature][KV Cache] Support non-contiguous KV cache in hybrid models like Qwen3.5 and GQA models

## 正文

### What this PR does / why we need it?

This PR adds non-contiguous KV cache support for hybrid Attention/Mamba models on Ascend, including Qwen3.5 and GQA-based models.

The current Ascend implementation requires Attention and Mamba cache pages to use the same page size and materializes contiguous cache views. This wastes memory and prevents hybrid models from using independent logical page layouts.

This PR:

- Supports independent Attention and Mamba KV cache page sizes.
- Creates stride-based cache views for hybrid layouts instead of materializing padded cache regions.
- Preserves existing legacy paths for pure Mamba/SSM models, separate K/V allocations, KV-transfer layouts, shared-backing layouts, and legacy MLA paths.
- Adds optimized `gather_ssm_states` and `scatter_ssm_states_` Triton kernels for non-contiguous Mamba state access.
- Documents and validates the supported state layout contract:
  - Only the first state stride may contain physical page padding.
  - Inner state dimensions must remain contiguous.
  - State indices select physical rows and may be unsorted or non-contiguous.
  - `has_initial_state=False` produces a zero initial state without reading the cache.

Generic advanced indexing is inefficient and unsafe for padded non-contiguous state storage when used with the fused recurrent GDN path.

### Does this PR introduce any user-facing change?

No new user-facing CLI option is introduced.

The change is internal to Ascend KV cache allocation, layout construction, and hybrid GDN state access.

### How was this patch tested?

#### Unit tests

- State gather/scatter correctness tests: 18 cases passed.
- MRV2 cache layout tests: 49 cases passed.
- Covered dense and padded layouts, block boundaries, multi-block tails, `int32`/`int64` indices, real GDN state shapes, unselected rows, padding preservation, empty-cache validation, and non-contiguous Attention K/V views.

#### End-to-end model tests

- Qwen3.5-35B-A3B W8A8:
  - V1 engine.
  - ModelRunner V2.
  - FULL_DECODE_ONLY graph mode.
  - Short, long-context, repeated, and concurrent requests.
- Qwen2.5-7B GQA:
  - 28 attention heads and 4 KV heads.
  - Runtime logs confirmed non-contiguous K/V views.
  - Short, long-context, repeated, and 32-way concurrent requests passed.
- All request matrix tests completed successfully with zero failed requests.

#### Performance before and after this PR

The pre-PR baseline used vLLM-Ascend commit `af277b2681443089e4d29684b1101707e2eb6426` with Custom GDN operators.

The post-PR configuration used vLLM-Ascend commit `fc4f6ffd97aafd7ad897c387031a46da05ce1d91` with FLA PR #559 operators and non-contiguous KV cache.

Both configurations used:

- Qwen3.5-35B-A3B W8A8.
- TP=2 and EP.
- MTP=3.
- FULL_DECODE_ONLY graph mode.
- `fused_mc2=0`.
- `gpu_memory_utilization=0.90`.
- GSM8K full dataset: 1319 requests.
- Concurrency: 64.
- Maximum output length: 512 tokens.

Two opposite-order runs were completed:

| Run | Configuration | TTFT | TPOT | Output throughput | Total throughput | Duration |
|---|---|---:|---:|---:|---:|---:|
| 1 | Pre-PR Custom | 627.1 ms | 35.8 ms | 1715.13 tok/s | 1954.16 tok/s | 393.008 s |
| 2 | Post-PR FLA | 612.3 ms | 36.0 ms | 1702.93 tok/s | 1940.23 tok/s | 395.881 s |

#### State I/O ablation

Under the same FLA, model, graph mode, and non-contiguous layout:
| Run | Configuration | TTFT | TPOT | Output throughput | Total throughput | Duration |
|---|---|---:|---:|---:|---:|---:|
| 1 | Old advanced-indexing path | 1491.2 ms | 87.8ms | 692.26 tok/s | 788.72 tok/s | 973.891 s |
| 2 | New gather/scatter path| 612.3 ms | 36.0 ms | 1702.93 tok/s | 1940.23 tok/s | 395.881 s |

The old advanced-indexing path caused both severe performance degradation and abnormal early termination under the non-contiguous layout.
