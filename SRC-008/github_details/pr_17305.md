## 正文

### What this PR does / why we need it?

Backports #17289 to `releases/v0.27.1rc`.

- Synchronizes successful eager MemCache initialization across DP workers through the DP CPU process group before NPU work continues.
- Adds the `memcache_dp_init_barrier` boolean option, enabled by default, and documents its behavior.
- Preserves the release branch's existing `local_rank`-based MemCache backend API while resolving the main-to-release conflicts.
- Adds unit coverage for configuration propagation, barrier participation, skip conditions, invalid configuration, initialization failures, and lazy initialization.

### Does this PR introduce _any_ user-facing change?

Yes. MemCache with DP size greater than one now synchronizes eager store initialization by default. Users can disable it with `memcache_dp_init_barrier: false` in `kv_connector_extra_config`.

### How was this patch tested?

- `git diff --check` passed.
- Unit tests were added but were not run locally because the local Windows environment does not provide the required Ascend NPU `torch`/`torch_npu` runtime. CI validation is required.
- vLLM main: https://github.com/vllm-project/vllm/commit/ba07e4a48fc951300d97eb506217dd530583dea3
