### Report of performance regression

In the ModelRunner V2 full-feature text sampling scenario,
_topk_topp_kernel is a device-side hotspot on Ascend.

### Misc discussion on performance

### Scenario

- Model: Qwen3-8B
- Requests: 64
- Prompt length: 256
- Output length: 16
- `temperature`: 0.8
- `top_p`: 0.9
- `top_k`: 50
- Execution mode: eager
- Tensor parallel size: 1
- Profile rounds: 3

### Profiling result

The following result is collected from
`ASCEND_PROFILER_OUTPUT/op_statistic.csv`:

Device_id | OP Type | Core Type | Count | Total Time(us) | Min Time(us) | Avg Time(us) | Max Time(us) | Ratio(%)
-- | -- | -- | -- | -- | -- | -- | -- | --
10 | _topk_topp_kernel | AI_VECTOR_CORE | 51 | 757379.6 | 4344.28 | 14850.58 | 40799.68 | 6.864

`_topk_topp_kernel` accounts for 5.543% of the accumulated device
operator time, so it is worth optimizing.

### Expected work

- Optimize `_topk_topp_kernel` on Ascend.
- Preserve correctness for top-k and top-p sampling.
- Add a single-operator benchmark using production shapes.
- Compare performance before and after the optimization.
- Verify the improvement in the full-model scenario.
