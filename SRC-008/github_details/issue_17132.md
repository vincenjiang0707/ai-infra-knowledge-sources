# vllm-ascend nightly-main 镜像版本不一致、测试依赖缺失、CPU 测试指南不完整

**Labels:** `bug`, `testing`, `documentation`

---

## 🐛 Bug 描述

在使用 `quay.io/ascend/vllm-ascend:nightly-main` 预构建镜像执行 UT 验证时，发现三类问题：
1. 镜像内 vLLM 版本与 vllm-ascend 期望版本不一致（差距 19 个 commit），导致 `import vllm_ascend` 失败，UT 完全无法启动
2. `requirements-dev.txt` 中的测试依赖未预装，部分用例无法运行
3. 测试指南声称「所有 UT 均可在 CPU 运行」，但实际有 5 个测试必须依赖 NPU 设备

---

## 🔍 问题详情

### 问题一：镜像版本不一致（核心阻塞问题）

#### 环境信息

| 项目 | 内容 |
|------|------|
| 镜像 | `quay.io/ascend/vllm-ascend:nightly-main` |
| 镜像构建时间 | 11 天前 |
| 镜像内 vLLM commit | `752a3a504` |
| vllm-ascend verified commit（`.github/vllm-main-verified.commit`）| `b2f685834` |
| commit 差距 | **19 个 commit** |

#### 报错信息


### Suggest a potential alternative/fix


#### 复现步骤

```bash
docker run --rm -it quay.io/ascend/vllm-ascend:nightly-main bash
# 容器内
python -c "import vllm_ascend"
# 报错：ImportError / ModuleNotFoundError
```

#### 期望行为

nightly-main 镜像内的 vLLM 版本应与 vllm-ascend 仓库 `.github/vllm-main-verified.commit` 指定的 commit 保持同步，确保 `import vllm_ascend` 可正常执行。

#### 修复建议

nightly-main 镜像构建流程应：
1. 读取 vllm-ascend 仓库的 `.github/vllm-main-verified.commit`，按该 commit 精确拉取并安装 vLLM
2. 构建后校验 `vllm.__git_commit__ == verified_commit` 通过后才发布镜像
3. 镜像 tag 增加构建日期或 vLLM commit 后缀（如 `nightly-main-20260910-b2f6858`），便于版本追溯

---

### 问题二：缺失 Python 测试依赖

#### 现象

镜像预装了运行时依赖，但 `requirements-dev.txt` 中的测试依赖缺失或版本不匹配，导致 pytest 收集阶段报 warning，部分测试无法运行。

#### 详情

| 包 | 镜像现状 | 期望 |
|----|---------|------|
| `pytest` | 8.3.2（由 triton-ascend 锁定） | 8.3.2（保持） |
| `pytest-asyncio` | 缺失（手动 `pip install` 装到 1.4.0，与 pytest 8.3.2 不兼容） | 预装，且 `<0.24` |
| `pytest-mock` | 缺失 | 预装 |
| `pytest-cov` | 缺失 | 预装 |
| `coverage` | 缺失 | 预装 |

#### 修复建议

1. 镜像构建时预装 `requirements-dev.txt` 全部依赖
2. 锁定 `pytest-asyncio<0.24` 以兼容 `pytest==8.3.2`
3. 在镜像 README 或 OCI label 中列出预装的测试依赖版本

---

### 问题三：测试指南「UT 可在 CPU 运行」说法不完整

#### 现象

测试指南原文：

> All unit tests can be run on CPUs, so you must mock the device-related functions on the host.

但实际有 **5 个测试在纯 CPU 环境下会失败**（失败而非跳过）。

#### 失败测试清单

| 测试用例 | 失败原因 |
|---------|---------|
| `test_gdn_mixed_batch::test_mixed_non_spec_reuses_rearranged_qkv` | 依赖 NPU 设备 |
| `test_gdn_layerwise_kv::test_connector_observes_updated_gdn_state_for_each_compiled_call` | 依赖 NPU 设备 |
| `test_eagle_proposer::test_set_inputs_first_pass_parallel_drafting` | 依赖 NPU 设备 |
| `test_eagle_proposer::test_set_inputs_first_pass_draft_model` | 依赖 NPU 设备 |
| `test_patch_balance_schedule::test_schedule_body_matches_pinned_release_tag` | 依赖 NPU 设备或环境配置 |

#### 修复建议

1. 为上述 5 个测试添加 NPU 标记，CPU 环境自动跳过：
   ```python
   @pytest.mark.npu_test
   # 或
   @pytest.mark.skipif(not HAS_NPU, reason="requires NPU device")
   ```
2. 更新测试指南原文为：
   > All unit tests can be run on CPUs, **except a small subset that requires NPU hardware** (marked with `@pytest.mark.npu_test`). For those tests, run on an NPU-equipped machine.
