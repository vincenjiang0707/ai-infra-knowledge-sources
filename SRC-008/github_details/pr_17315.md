# [PR #17315] [Bugfix][Worker] Re-adapt routed-experts (routing replay) to vLLM's AuxOutput connector

## 正文

### What this PR does / why we need it?
vLLM #45635 replaced the slot-indexed RoutedExpertsManager with a block-hash
keyed AuxOutput connector: the R3 data plane moved into the worker, and
ModelConfig.enable_return_routed_experts / RoutedExpertsLists /
RoutedExpertsTensors / RoutedExpertsCapturer.get_routed_experts /
GPUModelRunner.init_routed_experts_capturer were all removed.

- utils: add routing_replay_enabled() to read the switch across vLLM lanes.
- MRv1: drop imports/usages of the removed symbols (the module-level import
  broke MRv2 startup as well) and remove the now-dead R3 data plane.
- MRv2: let upstream's AuxOutput connector own R3; assert the connector was
  built instead of calling the deleted init_routed_experts_capturer().
- test: update the stale expectation and cover the new MRv2 branch.

### Does this PR introduce _any_ user-facing change?
Yes. Since vLLM #45635 removed the slot-indexed R3 data plane, R3 is no longer available in MRv1 and has been removed here, while MRv2 still works with upstream's AuxOutput connector owning R3. MRv1 users must migrate to MRv2 to keep using it.

### How was this patch tested?

- vLLM main: https://github.com/vllm-project/vllm/commit/84030bbe3d74d99bad477a3d2e37a973ccd8865c
