# [PR #17322] [v0.26.0rc][BugFix][KV Transfer] Suppress PD send after pool load failure

## 正文

### What this PR does / why we need it?

Backport of #17291 for `releases/v0.26.0rc`.

When a layerwise MemCache load loses its GVA/lease, queued SFA producer tasks can still advertise `READ_READY_BATCH`, including a success marker, for KV that was never loaded. This change records failed request IDs in a process-local, TTL-bounded registry and filters them before building PD notifications.

This is complementary to the release save-fence backport: save fencing prevents publishing bad KV to the shared pool, while this change prevents forwarding the failed local prefix to D.

### Does this PR introduce any user-facing change?

Yes. A request whose layerwise MemCache load fails is no longer advertised as a successful PD transfer.

### How was this patch tested?

- Added focused tests for failure registration, producer filtering, and registry expiry.
- `ruff check`, `ruff format --check`, `py_compile`, and `git diff --check` pass.
- Full CPU pytest was not run locally because the available macOS environment does not provide `torch`/`vllm`; CI is expected to run the added tests.
