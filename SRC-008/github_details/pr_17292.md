## 正文

### What this PR does / why we need it?

FlashComm1 was still enabled by the `VLLM_ASCEND_ENABLE_FLASHCOMM1` environment variable, which was kept only as a compatibility path. This PR removes that path so FlashComm1 is enabled only through `additional_config.enable_flashcomm1` (`--additional-config '{"enable_flashcomm1": true}'`). `enable_dsa_cp` still auto-enables FlashComm1.

- `vllm_ascend/ascend_config.py` no longer reads `VLLM_ASCEND_ENABLE_FLASHCOMM1`.
- Docs, tutorial templates, translations, and the model-adapter skill are updated to the `additional_config` switch.
- Weekly and nightly e2e configs that set the env var are converted in place: `1` / `true` becomes `"enable_flashcomm1": true`, `0` becomes `false`, and commented-out env lines are deleted without turning the feature on.
- For PD configs, the flag is added only on the nodes that previously set the env var. Prefill-on / decode-off cases stay that way, including the GLM-5.2 Memcache PD case.

### Does this PR introduce _any_ user-facing change?

Yes. `VLLM_ASCEND_ENABLE_FLASHCOMM1` no longer enables FlashComm1. Use `--additional-config '{"enable_flashcomm1": true}'` instead.

### How was this patch tested?

- Updated the existing FlashComm1 unit tests in `tests/ut/test_ascend_config.py` so they no longer mock the removed env var.
- Migrated weekly and nightly e2e YAML configs to `additional_config.enable_flashcomm1` and checked that each node's previous on/off state is unchanged.
