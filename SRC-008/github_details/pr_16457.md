# [PR #16457] [BugFix] fix lora in graph-mode on 310P and open MRV2 lora

## 正文

### What this PR does / why we need it?
When running model with lora on 310P and using graph-mode, error occurs that a torch operator "torch.repeat_interleave" in sgmv need stream synchronize but graph-mode not support. This PR will check device type and graph mode and then use bgmv to compute lora. 

### Does this PR introduce _any_ user-facing change?
Yes, LoRA is now supported on Ascend 310P with model runner v2.

### How was this patch tested?
start vllm server with command like: 
vllm serve $MODEL_PATH \
    --host 127.0.0.1 \
    --port 8080 \
    --tensor-parallel-size 1 \
    --served-model-name qwen3.5 \
    --max-num-seqs 32 \
    --max-model-len 16384 \
    --gpu-memory-utilization 0.90 \
    --dtype float16 \
    --enable-lora \
    --lora-modules '{"name": "your-lora-name", "path": "/path/to/lora", "base_model_name": "Qwen/Qwen3.5-4B"}' \
    --compilation-config '{"cudagraph_mode": "FULL_DECODE_ONLY", "cudagraph_capture_sizes": [2,16]}'
The server will run success and be able to take requests to lora adapter.
