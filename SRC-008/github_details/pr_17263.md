# [PR #17263] [Performance][DSpark] Stack DeepSeek V4 context WKV projections

## 正文

### What this PR does / why we need it?

This PR ports the DeepSeek V4 DSpark context WKV stacking optimization from upstream vLLM:

* Upstream PR: vllm-project/vllm#54674

In the current vLLM Ascend DSpark implementation, each draft layer independently applies its WKV projection to the same `context_states`.

This PR stacks the per-layer WKV projections into a single `MergedColumnParallelLinear` projection and splits the result back into per-layer KV states before the existing per-layer KV normalization, RoPE, and KV-cache insertion logic.

Conceptually, this changes the context WKV path from multiple small projections:

```text
X -> WKV_0
X -> WKV_1
X -> WKV_2
```

to one stacked projection:

```text
X -> [WKV_0 | WKV_1 | WKV_2]
```

The goal is to reduce projection launches and improve GEMM utilization on Ascend while preserving the existing DSpark KV-cache semantics.

Compared with the upstream NVIDIA implementation, vLLM Ascend already uses an independent `wkv` projection rather than a fused Q/KV projection, so this PR only ports the cross-layer WKV stacking optimization.

### Does this PR introduce any user-facing change?

No.

This is an internal DSpark performance optimization and is intended to preserve model outputs and speculative decoding behavior.

### How was this patch tested?

Current status:

* [ ] Unit tests
* [ ] DeepSeek V4 DSpark model loading on Ascend
* [ ] Functional / correctness verification
* [ ] Performance benchmark on Ascend 910B

A unit test is included to verify that:

1. Per-layer WKV checkpoint parameters are duplicated into the corresponding shards of the stacked projection.
2. Context WKV projection is executed once and its output is split correctly for individual DSpark layers.

Performance and full Ascend verification results will be added to this PR before it is marked ready for review.
