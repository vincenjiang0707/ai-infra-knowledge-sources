# [PR #16246] [Performance][GDN] Share group-invariant metadata across kv-cache groups

state: open | updated: 2026-09-23T03:32:00Z
labels: module:ops, ready-precise

## 正文

### What this PR does / why we need it?

**Background**

Hybrid models such as Qwen3.8 / Qwen4-Exp (e.g. Qwen3.8-27B) interleave
GDN (linear-attention) layers and full-attention layers at 3:1. The hybrid KV cache
manager aligns kv-cache group sizes to the least-numerous layer type, which splits
the GDN layers across **3 kv-cache groups**. As a result, `_build_attn_group_metadata`
invokes the GDN metadata builder's `build()` once per group on **every step**.

Within a single `_build_attention_metadata` call, every GDN group receives an
identical `common_attn_metadata` **except its own `block_table_tensor` /
`slot_mapping`**. However, the full metadata pipeline is executed 3x per step:

- spec sequence classification + fold (1 `.item()` host sync per group)
- batch statistics (4 `.item()` host syncs per group)
- stable argsort + `repeat_interleave` token reorder
- spec / non-spec `query_start_loc` cumsums and accepted-token reorder
- chunked-prefill chunk indices/offsets (6 CPU `prepare_*` calls + H2D per group)
- causal conv1d metadata and `has_initial_state`

**What this PR changes**

- Add `GDNGroupInvariantCache` to `gdn_attn_builder.py`.
- `AscendGDNAttentionMetadataBuilder.build()` accepts an optional
  `group_invariant_cache` argument.
- The model runner creates one cache before the kv-cache-group loop and passes it
  to every GDN group's build. The **first group (fingerprint miss) performs the
  full build and fills the cache**; subsequent groups **reuse the group-invariant
  intermediates and only recompute the state-index tensors derived from their own
  block table**.

Effect per step: host-device syncs drop from 3x5 to 5; the argsort,
chunked-prefill metadata and conv1d metadata drop from 3x to 1x.

**Safety properties**

- Only block-table-independent results are cached. `spec_state_indices_tensor`,
  `non_spec_state_indices_tensor` and `prefill_state_indices` are always
  recomputed from each group's own block table.
- Cached tensors are shared read-only; per-group full-graph padding still writes
  each builder's own persistent buffers, so captured graph addresses are unchanged.
- An O(1) shape-level fingerprint falls back to a full build on any mismatch.
- Callers that pass no cache (drafting, cudagraph capture, external callers)
  keep the original path unchanged.
- Guarded to non-ubatched calls (`ubid is None`): the shape-level fingerprint
  cannot distinguish same-shaped ubatches, so ubatched GDN builds fall back to
  full computation instead of silently reusing stale entries.

This mirrors the existing DSA precedent (`shared_dsa_draft_cache`).

### Benchmark

**GDN metadata `build()` per-step cost** (single forward):
- **Before**: all 3 kv-cache groups each run the full build, ~`2.1 ms/group`, total `6.3 ms`.
- **After**: the first group still builds fully (`2.1 ms`); the 2nd and 3rd groups
  reuse the cache (`1.2 ms` each), total `4.5 ms`.
- Saves **~1.8 ms / step (≈28.6%)** per forward. With speculative decoding
  (MTP, k=3) this is another forward per step, so the wall-clock benefit compounds.

**End-to-end benchmark** — Qwen3.6-35B-A3B, TP=2, 8k-token random input, 350 output tokens:

| Metric                | Before   | After    | Δ        |
|-----------------------|----------|----------|----------|
| Throughput (tokens/s) | 222.28   | 227.36   | +2.29%   |
| TTFT (ms)             | 1162.65  | 1156.24  | -0.55%   |
| TPOT (ms)             | 23.21    | 22.74    | -2.03%   |
| E2E Latency (ms)      | 9262.48  | 9094.04  | -1.82%   |

Throughput improves by **+2.29%**, and TTFT / TPOT / E2E latency all drop
(by roughly 0.6% ~ 2%). The win comes entirely from removing the redundant
host-device syncs (`.item()`), the repeated NPU argsort, and the duplicated
chunked-prefill / conv1d metadata across the 3 GDN groups.

**Accuracy regression check** — GPQA-diamond benchmark:

| Dataset       | Before | After |
|--------------|--------|-------|
| GPQA-diamond | 0.8622 | 0.868 |

Accuracy is preserved (0.8622 → 0.868), confirming the metadata reuse does not
degrade output quality.

### Does this PR introduce _any_ user-facing change?

No. This is a pure internal optimization of attention metadata construction.
No API, configuration or behavior change. The produced metadata is field-by-field
identical to the original full build (verified by UTs).
