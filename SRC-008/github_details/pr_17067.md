## 正文

### What this PR does / why we need it?

This PR removes redundant DeepSeek V4 RoPE table indexing that remains on current main.

- adds an optional layer filter to `get_cos_and_sin_dsa` so draft attention queries only the RoPE config consumed by its layers
- resolves draft `*.swa_cache` layer names to their registered `*.attn` RoPE layer
- computes the ordinary RoPE cos/sin pair once before the DSpark context-KV layer loop and reuses it across all draft layers
- preserves existing target common/decode caching already present on current main

Current main has already absorbed part of the older optimization design, so this PR deliberately excludes that existing logic. It is independent of the block-table dirty-copy PR.

An earlier DSV4 DP16 decode profile showed that eliminating 26 redundant Index/IndexCheck pairs saved approximately 1.19 ms/step. On current main, only the draft config filtering and cross-layer context-KV reuse remain applicable, so a fresh profile is required before making a current-main performance claim.

### Does this PR introduce _any_ user-facing change?

No API or output change. RoPE values are queried for the same positions and config; the result is reused by layers that share that config.

### How was this patch tested?

- Added unit coverage verifying layer-based config filtering and `swa_cache` to `attn` resolution.
- Repository pre-commit checks passed: Ruff check/format, codespell, typos, gitleaks, import and policy checks, and DCO sign-off.
- `python3 -m compileall` and `git diff --check` passed for the changed files.

NPU execution was not run locally. Required follow-up coverage on Ascend is: DSV4/DSpark eager correctness, affected attention backend smoke with real weights, graph-mode coverage, and a fresh Index/IndexCheck profile.
