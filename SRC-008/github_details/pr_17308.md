## 正文

### What this PR does / why we need it?

Backport of #17289 to `releases/v0.27.1rc` (source commit `97731337d9480bcc1dba95fd298d2652686b1880`).

Synchronize eager MemCache initialization across DP workers with a CPU process-group barrier after successful `store.init()`. This coordinates workers leaving the initialization phase; it does not guarantee readiness of all dynamically created transport channels. Skip the barrier for DP size 1, metadata-only clients, and actual lazy initialization, where ranks can initialize independently in response to requests.

Adapted to the release branch local_rank API and backend construction; unrelated main-branch QoS/device-binding changes are excluded.

### Does this PR introduce _any_ user-facing change?

Adds `kv_connector_extra_config.memcache_dp_init_barrier`, defaulting to `true`, for the MemCache backend. Read it in `AscendStoreConnector` and pass it through the worker to the backend. Set it to `false` to opt out. With `MultiConnector`, put it on the AscendStoreConnector child. Eager DP workers must use consistent values.
