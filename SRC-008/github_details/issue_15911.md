### 🐛 Describe the bug

### Summary

The official v0.23.0 Ascend image bundles the legacy Qwen3XMLToolParser from upstream vLLM v0.23.0. When the model finishes thinking and starts a tool call with a whitespace separator, the streaming parser emits a whitespace-only buffer as normal assistant content.

This causes the frontend to receive an extra Markdown/content delta containing "\\n\\n" before the tool call.

### Minimal reproduction

Model output:

~~~xml
<think>
...
</think>

<tool_call>
<function=get_weather>
<parameter=city>Tokyo</parameter>
</function>
</tool_call>
~~~

The relevant stream boundary is:

~~~text
1. "\\n\\n"
2. "<tool_call>"
3. "<function=get_weather>..."
~~~

Actual streaming result:

~~~text
reasoning_content: "..."
content: "\\n\\n"
tool_calls: [...]
~~~

Expected result:

~~~text
reasoning_content: "..."
content: null / no content delta for the separator
tool_calls: [...]
~~~

### Affected logic

There are two flush paths in qwen3xml_tool_parser.py:

1. In parse_single_streaming_chunks(), a non-empty text_content_buffer is emitted as content whenever tool_call_index == 0. A whitespace-only buffer is therefore emitted before the first tool call.
2. In _process_complete_xml_elements(), the first <tool_call> unconditionally flushes a non-empty text_content_buffer, including when it contains only whitespace.

### Proposed minimal fix

Only suppress the buffer when the complete buffered value is whitespace. Preserve real text before a tool call, for example "I will query this first:\\n\\n".

~~~diff
- if self.text_content_buffer and self.tool_call_index == 0:
+ if (
+     self.text_content_buffer
+     and self.text_content_buffer.strip()
+     and self.tool_call_index == 0
+ ):
      text_delta = DeltaMessage(content=self.text_content_buffer)
      self._emit_delta(text_delta)
      self.text_content_buffer = ""
      return text_delta
~~~

At the first-tool-call flush path, apply the same check before emitting and always clear the buffer afterward:

~~~python
if (...) and self.text_content_buffer:
    if self.text_content_buffer.strip():
        text_delta = DeltaMessage(content=self.text_content_buffer)
        self._emit_delta(text_delta)
    self.text_content_buffer = ""
~~~

The intended behavior is not to discard whitespace globally: non-whitespace content before a tool call must remain content, while a whitespace-only separator should not create a content delta.

### Source/provenance

The vllm-ascend v0.23.0 release Dockerfile clones upstream vLLM with VLLM_TAG=v0.23.0 and then copies the vLLM Ascend plugin into the image:

- https://github.com/vllm-project/vllm-ascend/blob/v0.23.0/Dockerfile
- The affected file in upstream vLLM v0.23.0: https://github.com/vllm-project/vllm/blob/v0.23.0/vllm/tool_parsers/qwen3xml_tool_parser.py
- The upstream Qwen3 XML tests mark multiple streaming cases as having systematic/known streaming issues: https://github.com/vllm-project/vllm/blob/v0.23.0/tests/tool_parsers/test_qwen3xml_tool_parser.py

I first reported this to upstream vLLM in https://github.com/vllm-project/vllm/issues/55633. The upstream maintainer confirmed that this legacy parser is no longer present on current main and suggested reporting the issue against the release/downstream artifact carrying it.

Could you please confirm whether this should be fixed/backported for the v0.23.0 release image, or documented as a known limitation?

### QwertyJack · 2026-09-11

Thanks for the detailed report. The behavior and proposed fix make sense: when the separator between </think> and the first <tool_call> is whitespace-only, the legacy parser should not emit it as an assistant content delta. Real non-whitespace text before the tool call must still be preserved.

This parser is bundled from upstream vLLM v0.23.0 rather than implemented in the vLLM-Ascend plugin, so the fix needs to be applied to the vLLM source used by the release image (or backported in the image build). We will confirm whether a v0.23.0 image backport is still appropriate; otherwise we will document this as a known limitation and recommend a release containing the newer parser.
